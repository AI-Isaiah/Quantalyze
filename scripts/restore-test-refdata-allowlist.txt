#
# ── WHAT AN ENTRY IS ───────────────────────────────────────────────────────
# One line = one (migration file, target table, pinned top-level statement
# count) triple, plus the consumer that reads the row.
#
#     <basename>.sql <TAB> <schema.table> <TAB> <n> <TAB> # <anchor + consumer>
#
# ⛔ NEVER A BARE TABLE (decision L-02). Reference-ness is a property of a
#    STATEMENT, not of a table. `public.strategies` is a DO-block fixture in
#    many migrations and a required application singleton in exactly ONE
#    (20260515095804_teaser_anchor_strategy.sql:78-90). A per-table allowlist
#    would either replay fixture rows — including encrypted `api_keys` blobs —
#    into shared TEST, or lose that sentinel. Neither is acceptable, so the key
#    is (file, table, count) and the extractor refuses anything else.
#
# ── WHY THIS FILE EXISTS ───────────────────────────────────────────────────
# ⛔ LEDGER PRESENCE IS NOT EFFECT PRESENCE, and for DML-bearing migrations it is
#    FALSE BY CONSTRUCTION. baseline.sql carries 562 GRANT/REVOKE statements and
#    ZERO INSERT/COPY, so a ledger row here evidences a migration's DDL and ACLs,
#    NEVER its DML.
#    (The same sentence, in the same words, is at scripts/vac08-ledger-baseline.txt:22-25
#    and in CLAUDE.md. The three must stay in agreement; they describe one fact.)
#    The TEST restore drops `public`, reloads a schema-only dump, and SEEDS the
#    migration ledger from the repo file list — so every migration reads as
#    applied while every row it INSERTed is gone. This file names the rows that
#    have to come back.
#
# ── THE CRITERION (C1-C4). A statement is reference data iff ALL FOUR hold ──
# C1  TOP-LEVEL — not inside a `DO $$…$$`, a `CREATE FUNCTION … AS $$…$$`, or a
#     `cron.schedule($cron$…$cron$)` body. Every fixture, probe and backfill in
#     this corpus lives in a body; every reference seed is bare.
# C2  LITERALS ONLY — `INSERT INTO t (cols) VALUES (…)` with no SELECT/FROM and
#     no identifier in the tuple beyond a cast, NULL/TRUE/FALSE, now() or
#     gen_random_uuid(). An `INSERT … SELECT` is a backfill of existing data by
#     construction: on an empty table it inserts nothing.
# C3  TARGET IN `public` — the restore drops ONLY `public`
#     (scripts/restore-test-from-baseline.sh:861), so rows in other schemas
#     survive and need no replay. `storage.buckets` is OUT for this reason.
#     ⚠️ ONE NAMED EXCEPTION, and only one: `auth.users` in
#     20260515095804_teaser_anchor_strategy.sql. That row is the FK head of the
#     teaser trio and it SURVIVES the restore, so replaying it is a no-op via its
#     own `ON CONFLICT (id) DO NOTHING`. It is kept because `public.profiles` and
#     `public.strategies` below it do NOT survive, and keeping the head makes the
#     trio FK-self-contained on a lane that starts empty. The extractor accepts
#     `auth.users` and NO other non-public target; any other schema is refused by
#     name. A reviewer who reads C3 and then finds this line has not found a
#     contradiction — this paragraph IS the exception.
# C4  A CONSUMER READS THE ROW BY KEY — an FK, a CHECK, a slug lookup, or a
#     constant in application code. Human judgement; cite it in the entry.
#     Idempotence (`ON CONFLICT DO NOTHING`) is a strong SIGNAL and NOT a
#     criterion: `discovery_categories` has none and is unquestionably reference,
#     while a backfill in 20260408113028_disclosure_and_tenancy.sql:152-156
#     carries one and is not.
#
# ── DIRECTION ──────────────────────────────────────────────────────────────
# ⛔ THIS FILE GROWS when a new reference statement is AUTHORED, and SHRINKS only
#    when the CONSUMER that reads the row is gone — never to make something go
#    green. State which consumer went away in the commit message.
# ⛔ A PINNED COUNT MOVES ONLY WHEN AN APPLIED MIGRATION IS EDITED. Migrations are
#    immutable once applied, so a count never drifts on its own; a count that
#    stopped matching means someone edited applied SQL, which is precisely the
#    event that should fail loud. Clear it by understanding the edit, not by
#    re-pinning the number.
# ⛔ DO NOT HAND-SEED SHARED TEST TO SHORTEN THIS FILE. TEST is shared with other
#    people's CI. A missing reference row is a NAMED failure of the restore's own
#    gate; it is never fixed by a hand-run INSERT (CONTEXT, out of scope).
# ⛔ A RED `--audit` IS CLEARED BY ADDING THE ALLOWLIST LINE WITH ITS CONSUMER,
#    never by relaxing the classifier.
#
# ── KNOWN LIMITATIONS, STATED RATHER THAN HIDDEN ───────────────────────────
# 1. `--audit` sees ONLY the tables this file already names. It closes "a new
#    `*_kind.sql` migration merged with no allowlist line". It CANNOT see a
#    brand-new reference TABLE (a future `foo_kinds`) — that remains a human
#    call, made against C1-C4 above, at review time.
# 2. `--audit` classifies with C1+C2. A future top-level `INSERT … SELECT` into
#    an allowlisted table is therefore SKIPPED, not flagged. That is deliberate
#    (it is a backfill by C2), and it is the second thing a reviewer must decide
#    by hand rather than expect the gate to raise.
# 3. This file says nothing about whether the rows are on TEST right now. It says
#    which statements the restore replays. The restore's own in-transaction gate
#    and its `refdata:` census rows are what report presence.
#
