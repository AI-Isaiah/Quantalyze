### C6 — the Q2 scoping argument: **I could not build a counterexample to the argument as scoped, but it is NOT airtight — it rests on an unpinned numeric coincidence, and it leaves one shape uncovered that the plans' "fix the families" language implies is covered.**

The argument itself survives every attack I tried:
- `''` collapsing: the token is a whitespace-split piece of the same collapsed `content`, so
  `token ≤ content` always. Holds.
- boundary-straddling literals: `closingParen` walks **masked**, where both single-quote contents and
  dollar-region contents are blanked, so a `)` inside a literal can never end a region. Holds.
- an unparseable region swallowing a literal: reachable only for text that does not balance, i.e. text
  that would not run in PROD — and it is loud (`header-unparseable` → measure-fail). Holds, but see W7.

**W3 — what it actually rests on.** `HEADERS_LITERAL_MAX` is `32` `[MEASURED: cron-drift.mjs:189]`
and plan 04 hard-codes the token threshold as a separate literal `32`. The partition is airtight
*if and only if* `TOKEN_MIN >= HEADERS_LITERAL_MAX`. Nothing states that, nothing pins it, and the
`header_region_only` `expect_not` row pins **today's values**, not the invariant. Raise
`HEADERS_LITERAL_MAX` to 40 in a later phase and a 32–39-char token inside a header region is caught
by nobody, silently.

**W4 — the shape I could not get either rule to catch.** The derived-length sum is anchored to three
header NAMES (`X-Service-Key`, `Authorization`, `apikey`). Under any other name:

```sql
jsonb_build_object('X-Auth', 'FAKE-key-01234' || '56789abcdef0123')
```

`long-literal-in-headers` is silent (each literal is < 32); the derived sum never runs (name not in
the three); `long-token-anywhere` is excluded (header region), and would be silent anyway (no ≥32
token). **Nothing fires.** In fairness this is *not* created by the Q2 decision — the token rule
would not have caught it outside a header region either — so Q2 is not the wrong call. But the
phase's own language is "fix the families, not the cases", and this is a live member of family (2).
Remedy, and it does not touch a D4-protected value: run the derived sum for
`long-literal-in-headers` too, at `HEADERS_LITERAL_MAX`. D4 forbids **lowering** the thresholds; it
does not forbid improving the *measurement* fed to them. Otherwise record it as an explicit residual
beside A2, so it is a decision rather than a gap.

### B3 — Plan 03, Task 2, `<verify>`: the gitleaks leg cannot fail

```sh
(command -v gitleaks >/dev/null && gitleaks detect … --exit-code 1 >/dev/null 2>&1 \

```

Trace it: gitleaks **finds a leak** → exits 1 → control falls to `||` → the inner group runs
`command -v gitleaks`, which **succeeds** → the group exits 0 → the subshell exits 0 → **the verify
passes on a finding.** The leg exists to catch a credential-shaped fixture string in a PUBLIC repo
(T-164.8.5-14) and it cannot report one. Same class as the reverted repair's controls.

**Fix:**
```sh
if command -v gitleaks >/dev/null; then \
  gitleaks detect --no-git -c .gitleaks.toml --source scripts/prod-prober/fixtures/cron-drift; \
else echo "gitleaks absent locally — CI (8.30.1) is the first run"; fi
```
(no `--exit-code 1`, no `>/dev/null` swallow, failure propagates through the `&&` chain).
