`.github/workflows/prod-prober.yml`. The step sets `set -uo pipefail`, deliberately omitting `-e` —
but GitHub's default shell for a `run:` block is `/usr/bin/bash -e {0}`, and `set` cannot turn off
what the invocation already set.

**SHA-bound evidence, run `34565978460` (schedule), step "Probe production" → `failure`:**

```

…
2026-09-11T05:27:10.3046416Z ##[endgroup]
2026-09-11T05:27:16.1356146Z ##[error]Process completed with exit code 1.
```

Zero stdout between `##[endgroup]` and the error — the `cat "$RUNNER_LOG"` never ran.

**Scheduled-run conclusions, measured 2026-09-11:** 10 of the last 12 are `failure`
(`34565978460`, `34547561958`, `34535743944`, `34519955526`, `34477143827`, `34451054069`,
`34428590952`, … ; `34504092497` and `34500455961` succeeded). An hourly red check on main's HEAD is
precisely the Railway wait-for-CI deadlock the 25-line POSTURE LINE comment above it exists to
prevent (incident 2026-06-21). That comment is careful, correct, and had never once been reached.

**Reproduced locally**, the step block extracted from the YAML and executed under a real
`bash -e` (GNU bash 5.3.9) against a stub runner that exits 1:

```
BEFORE  (bare call, `status=$?` on the next line)
  STEP EXIT=1
```

⛔ **The old wiring test PINNED THE BUG.** `liveCommandCapturesItsOwnStatus` asserted `status=$?` on
