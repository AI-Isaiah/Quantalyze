## §1 — "A red fixture that proves a rule can fire": which of the three idioms?

The prompt is right that this repo has three. **They are not interchangeable, and the answer for a
new cron-drift hygiene rule is neither of the two the question makes salient.**

### The three idioms, and what each one is actually for

| Idiom | Registry | Unit of isolation | Where it lives |
|---|---|---|---|
| **A. `ARM_FIXTURE_TABLE` red map** (`scripts/prod-prober/run.mjs`, `ARM_FIXTURE_TABLE` at `:815`) | fixture filename → **DEFECT KIND** | one whole `runProber` run producing **exactly one defect** | `fixtures/<arm>/<name>.json` |
| **B. `lint-sql-gates` / `lint-app-guc` red+green pairs** (`RULES` at `lint-sql-gates.mjs:120`, `selfTest` at `:1307`; `FINDING_KINDS` at `lint-app-guc.mjs:111`, `selfTest` at `:631`) | rule id → `.red.sql` / `.green.sql` | one **finding kind** per file | `scripts/lint-*-fixtures/` |
| **C. `RED-UNDER` mutation annotations** (`scripts/mutation-runner/run.mjs`) | a SQL gate arm ← a production mutation that must make it RED | one **gate arm**, proven by executing a mutant on a throwaway PG lane | `supabase/tests/*.sql` annotations |

**C is out of scope by construction** — its corpus is `supabase/tests/**` and its mechanism is
mutating SQL on a `pg-lane` cluster. This phase writes no SQL and touches no gate file.

### ⭐ The answer: a new cron-drift hygiene rule belongs to a **FOURTH** idiom that already exists

`HYGIENE_RULE_IDS` (`cron-drift.mjs:167`) is its own registry, and it is scanned by a **standalone
counted scenario**, not by `ARM_FIXTURE_TABLE`. It is idiom **B's discipline** (rule id ↔ red row,
one-rule isolation, plus a green false-positive calibration) implemented over a **JSON array of rows**
rather than a directory of `.sql` files.

**Walk the full registration path for `long-literal-in-headers`, end to end — all five sites:**

1. **The rule id is declared** in `HYGIENE_RULE_IDS` (`scripts/prod-prober/arms/cron-drift.mjs:167`,
   entry `"long-literal-in-headers"` at `:177`). The docblock states the contract verbatim:
   *"EXPORTED so the self-test can assert the red-fixture set equals this list member for member. A
   rule added without a red row, or a red row whose rule never fires, is a SELF-TEST FAIL rather
   than a quiet gap."*
2. **The rule fires** inside `hygieneViolations` (`:310`), through the local `say(id, sentence)`
   helper — `say` prefixes `[${id}]`, which is the stable token every downstream reader parses:
   ```js
   for (const [from, to] of headerRegions(text)) {
     const long = singleQuotedLiterals(text, from, to).find((l) => l.content.length >= HEADERS_LITERAL_MAX);
     if (long) { say("long-literal-in-headers", `job ${name} passes a quoted literal of …`); break; }
   }
   ```
   ⛔ **The sentence NEVER quotes the offending text** (docblock above `hygieneViolations`). The RED
   scenario machine-enforces it: `if (v.some((x) => x.includes(row.command))) missed.push(...)`.
3. **A red row is added** to `scripts/prod-prober/fixtures/cron-drift/hygiene-red.json` — an array of
   `{ rule, jobname, command }`. The existing row:
   ```json
   { "rule": "long-literal-in-headers", "jobname": "fixture_longlit_job",
     "command": "SELECT net.http_post(url := 'https://x.invalid/a', headers := jsonb_build_object('X-Trace', 'FAKE-0123456789-0123456789-0123456789'), body := '{}'::jsonb)" }
   ```
   Note the credential-shaped values are all spelled `FAKE…` / `.invalid`.
4. **The RED scenario asserts four things at once** — `scenario("hygiene RED: all ten rules fire on
   their own fixture row, and the id sets match exactly")`, `run.mjs:1660`:
   - every red row fires the rule **it names**;
   - `ids.length !== 1` → **ISOLATION**, explicitly called *"the lint-sql-gates idiom"* in the message;
   - `red.data.length === 10` — a **hand-pinned count** that must move with the rule set;
   - `JSON.stringify(fixtureIds) === JSON.stringify(armIds)` — **SET EQUALITY against
     `HYGIENE_RULE_IDS`**, which is the anti-vacuity device: a rule with no red row, or a red row for
     a deleted rule, fails here.
5. **A green calibration row** goes in `fixtures/cron-drift/hygiene-green.json`, asserted by
   `scenario("hygiene GREEN: every ACHIEVABLE Vault-backed shape produces ZERO violations")`
   (`run.mjs:1694`). That scenario pins `green.data.length >= 5`, requires the Vault-backed
   `match_engine_cron` body by name, requires the `'Bearer ' ||` concatenation by substring, and
   requires `flagged.length === 0`.

**What the plan must therefore do for each of the nine bypass shapes (a)–(i) in CONTEXT:**

- If the shape is caught by an **existing** rule id once that rule is strengthened → add a row to
  `hygiene-red.json` naming that rule id, and **raise the `red.data.length === 10` literal at
  `run.mjs:1673`**. ⚠️ That literal is currently `10` and equals the rule count *by coincidence of
  one-row-per-rule*; adding a second row for an existing rule breaks that coincidence. The honest
  edit is `red.data.length === <new row count>` with the set-equality leg unchanged — **the set
  equality is the control, the count is the display**, exactly as `printed === SELF_TEST_SCENARIOS`
  is the control and the `k/N` header is the display (`run.mjs:1002-1010`).
- If the shape needs a **new rule id** (CONTEXT's third fix — "a long literal ANYWHERE in the command
  with the Vault-read shape as its only exemption") → append to `HYGIENE_RULE_IDS`, `say()` it, add
  its red row, add a green row, and the set-equality leg passes automatically.

### §1b — When idiom A (`ARM_FIXTURE_TABLE`) is the right home instead

Only when the thing being proven is a **whole-run defect kind**, not a rule id. The registration path
there is four sites and is materially different:

1. an entry's `red` map gains `"<fixture>.json": "<defect-kind>"` (`ARM_FIXTURE_TABLE`, `:815`);
2. that kind must be in the entry's `kinds` array or match the `<arm>-` prefix (`entryKinds`, `:914`);
3. a **literal** `KIND_ASSERTIONS` entry spelled `(d) => d.kind === "<k>"` (`selfTest`, `:971`) —
   ⛔ mandatory, and the loop hard-fails without it (`run.mjs:1099-1108`);
4. the fixture file exists on disk (`loadFixture`, `:617` — *"a missing fixture is a FAIL, never a
   skip"*).

The green leg then asserts `declared` set == `covered` set (`run.mjs:1073-1083`), so a red fixture
naming an undeclared kind reds the run.

## §3 — Two independent tallies that must agree (this repo's signature anti-vacuity device)

## §4 — The dated-lineage-annotation idiom, and how the annotation/allowlist pair stays honest

**Source:** `scripts/lint-app-guc.mjs`. The mechanism is stated in the file header at `:32-45`:
*"A file is exempt only when BOTH hold: 1. it carries a dated lineage header naming an EXACT
occurrence count, and 2. `LINEAGE_ALLOWLIST` below pins the same file with the same count and the same
successor."*

**Six enforcement legs, all of which criterion 7 must leave intact:**

| Leg | Symbol / anchor | What it makes impossible |
|---|---|---|
| The marker must sit in the masthead | `HEADER_SCAN_LINES = 40` `:81`; `parseLineageHeader` `:331` | an exemption buried mid-file |
| The header must fully parse or it exempts nothing | `parseLineageHeader` returns `{line, malformed}`; `scanFile` `:415-436` still reports every read as `unannotated-reader` | a broken header acting as a wildcard |
| The count is a **two-directional** ratchet | `header.occurrences !== reads.length` → `header-count-mismatch` `:439`, with different prose for MORE vs FEWER | a new reader smuggled into an annotated file |
| The allowlist must agree with the header on **both** fields | `:459-468`, *"Two independent edits must agree, or the exemption is not the one that was reviewed."* | a self-signed permission slip |
| A stale entry is an error, not a courtesy | `allowlist-stale` pushed in `scanPaths` `:538-551` | an exemption quietly disarmed |
| The successor must exist **and** be clean | `:471-503` | *"the lineage points at another copy of the same defect"* |

**The header's own self-reference trap — copy this exactly.** `lineage.green.sql`'s comment:
*"the header itself says 'app-GUC read' in prose and never spells the call out; a header that spelled
it out would match the detector and count as a site of its own."* `parseLineageHeader`'s docblock
repeats it at `:329`. ⚠️ **Criterion 7 widens `DETECT_RE` to four more spellings. Every widening is a
new way for the gate's OWN prose to become a site.** Re-read `lint-app-guc.mjs`'s header block at
`:86-96` (the `v_guc_needle` blind-spot note) and `cron-drift.mjs`'s `app-guc` rule sentence at
`:325-329` before widening — both are prose that mentions `current_setting('app.…')`-adjacent text.

**⛔ The forbidden remedy is machine-visible.** `LINEAGE_ALLOWLIST`'s docblock at `:171-190` pins
*"The five `occurrences` below SUM TO 12"* and `src/__tests__/lint-app-guc.test.ts:363` re-measures
each count against `countReads()` of the real file. So widening `DETECT_RE` **will** change one or
more of the five counts unless the widening genuinely matches nothing new — which is precisely
CONTEXT D4's *"the corpus is 0 findings by design; a fix that MOVES that number is matching something
else."* **The plan must state, per new spelling, what it expects the five allowlist counts to be
after the change, and treat a move as evidence the regex is wrong** — not as a count to update.

**The `DETECT_RE` cross-file identity pin.** `src/__tests__/lint-app-guc.test.ts:98-103`:

⛔ **Criterion 7 changes `DETECT_RE`, therefore it changes `cron-drift.mjs`'s `app-guc` rule regex in
the same commit or this test reds.** The current cron-drift spelling is
`/current_setting\s*\(\s*'app\./i` at `cron-drift.mjs:325`. This is a **cross-file two-independent-
spellings** guard of the §3 family and must be preserved, not deleted to make the edit easier.

**The successor fix (criterion 7 / T-164.7-02 / `[164.7-APPGUC-SUCCESSOR-VACUOUS]`).** The current
check at `:471-503` has exactly two arms: `existsSync(successorAbs)` and `countReads(...) !== 0`.
Everything else — extension, file type, `..` traversal — is unchecked. The red fixture that already
exists is `scripts/lint-app-guc-fixtures/successor-invalid.red.sql`, whose header names
`successor: does-not-exist.sql` and whose `FIXTURE_ALLOWLIST` entry (`lint-app-guc.mjs:267-275`)
agrees on both fields *"so the paperwork is complete and the only defect left is the successor that

4. **A separate `it()` proving the constant cannot be a dead control** (`> 0`, integer).

   value (exit 0) and one at value+1 (the exact defect string). See `ARMS_FLOOR`'s block at

## §7 — Existing consumers of `scanSql`, and the index-preserving idiom to copy

**Complete consumer census (2026-09-10):**

| Consumer | Uses | Notes |
|---|---|---|
| `stripSqlComments` (`sql-body-normalize.mjs:211`) | `stripped` | one-liner re-export |
| `extractFunctionDefs` (`sql-body-normalize.mjs:319`) | **`masked` + `dollarRegions`** | ⭐ the only worked index-preserving idiom in the repo |
| `src/__tests__/sql-statement-tokenizer.test.ts:341-360` | `masked` + `dollarRegions` | cross-checks the tokenizer against the lexer character by character |
| `scripts/mutation-runner/parse.mjs:766` (comment only) | — | *references* `scanSql` as the model; does not import it |
| `scripts/extract-reference-inserts.mjs:441,467` | a **different** `.masked` | from `lint-sql-gates.mjs`'s `statements()`, **not** this module. Do not mistake it for a `scanSql` consumer. |

**⭐ THE IDIOM — `extractFunctionDefs`, `scripts/sql-body-normalize.mjs:319-400.` Copy this exactly.**

```js
export function extractFunctionDefs(sql) {
  const { masked, dollarRegions } = scanSql(sql);      // ← ONE call, destructured once
  …
  // 1. MATCH on `masked` — a hit here can never be inside a comment or a literal
  for (let m = FN_RE.exec(masked); m !== null; m = FN_RE.exec(masked)) {
    starts.push({ stmtStart: m.index, afterKeyword: m.index + m[0].length });
  }
  …
  // 2. SLICE from `sql` at the offsets `masked` produced — same indices, real text
  const { end: afterName, name, schema } = readQualifiedName(sql, afterKeyword);

  // 3. SCAN character-by-character on `masked`, never on `sql`
  let j = afterName;
  while (j < sql.length && /\s/.test(masked[j])) j++;
  …
  if (masked[j] !== "(") continue;
  for (let k = j; k < sql.length; k++) {
    if (masked[k] === "(") depth++;
    else if (masked[k] === ")") { depth--; if (depth === 0) { close = k; break; } }
  }
  const nargs = countArgs(masked.slice(j + 1, close));

  // 4. Dollar bodies come from `dollarRegions`, and the body text from `sql`
  const region = dollarRegions.find((r) => r.start > close && r.start < nextStart);
  const semi = masked.indexOf(";", searchFrom);
  const body = region ? sql.slice(region.contentStart, region.contentEnd) : …;
}
```

**Five rules the idiom encodes, all directly applicable to `hygieneViolations`:**

1. **One `scanSql` call, one destructuring.** The in-file comment at `:335` records the fix:
   *"R2-I05: one call, one destructuring. This parsed the same input twice to pick different fields
   off it."*
2. **Every regex, `indexOf`, bracket walk and whitespace skip runs on `masked`.** Only the final
   *value extraction* touches `sql`.
3. **Bracket matching is a manual depth loop over `masked`, not a regex.** This directly replaces
   `matchingParen` (`cron-drift.mjs:192`), whose hand-rolled `'`-skipping loop is exactly what
   CONTEXT's bypass (a) — `$q$…$q$` — walks straight through.
4. **⛔ REFUSE RATHER THAN DROP** when the lexer's assumption is violated (`:340-388`). The comment
   is worth quoting into the plan verbatim: *"`readQualifiedName`'s ident loop is `/[A-Za-z0-9_]/`,
   so it stops at the first byte outside that set and the `(` test below then DROPS the whole
   definition — silently, exit 0."* That is criterion 6's defect class, one directory over.
5. **`dollarRegions` entries are `{start, tag, contentStart, contentEnd, end}`** and nested tags are
   part of the body (`scanSql` docblock `:76-78` and the CONTEXT measurement table). Use
   `contentStart`/`contentEnd` for the value, `start`/`end` for the whole token.

**How this maps onto the two functions being rewritten:**

- `singleQuotedLiterals(text, from, to)` (`cron-drift.mjs:223`) — the hand-rolled `''`-escape walker.
  Replace with a `masked`-driven scan: a literal is a run between `masked[i] === "'"` delimiters; its
  **content** is `sql.slice(start+1, end)`. `scanSql` already handles `E'…\\…'` (measured in CONTEXT)
  and `""` quoted identifiers, which this function does not.
- `headerRegions(text)` (`cron-drift.mjs:274`) — the `jsonb_build_object\s*\(` / `headers\s*:=`
  matcher plus `matchingParen`. Run **both regexes on `masked`** and the paren walk as the depth loop
  above; the returned `[from, to]` offsets stay valid against `sql` because `masked` is
  index-preserving.
- `headerCarriesLiteral(text, headerName)` (`cron-drift.mjs:263`) — `new RegExp(...'gi')` then
  `matchAll`. Run on `masked`; note that `masked` **keeps the delimiters** (`'`) and blanks only
  contents, so `'X-Service-Key'` becomes `'             '` — **the header NAME is invisible in
  `masked`.** ⚠️ This is the one place where the idiom does not transfer unchanged: header names are
  themselves string literals. Use `stripped` (literals verbatim, comments gone) for the **name**
  anchor and `masked`/`dollarRegions` for the **value** boundaries, or read the name back out of
  `sql` at the offsets `masked` gives. **The plan must state which, and prove it with a fixture in
  both spellings** (criterion 4's `$q$don't$q$` vs `$q$dont$q$` pair is precisely this test).

**No established idiom exists for "sum the lengths of `||`-joined operands"** (CONTEXT fix 2). That
is a **new pattern**; the closest structural precedent is `countArgs(maskedArgs)`
(`sql-body-normalize.mjs:300`), a depth-aware comma splitter over masked text — same shape (walk
`masked`, track depth, split on a top-level operator), different operator. **Cite it as the shape,
not as an analog for the semantics.**
