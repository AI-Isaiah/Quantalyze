## ⭐ THE LOAD-BEARING DISCOVERY — do not write a lexer

**`scripts/sql-body-normalize.mjs` already exports `scanSql(sql)`, and it is exactly the tool this
phase needs.** MEASURED 2026-09-10:

| input | `masked` output | `dollarRegions` |
|---|---|---|
| `a := 'sk_live_AAAA';` | `a := '            ';` | 0 |
| `a := $q$sk_live_AAAA$q$;` | `a := $q$            $q$;` | 1 |
| `a := $q$don't$q$;` | `a := $q$     $q$;` | 1 |
| `a := E'sk\\_live';` | `a := E'         ';` | 0 |
| `DO $a$ x := $b$inner$b$; $a$` | `DO $a$                   $a$` | 1 (nested tag absorbed) |

It returns three things, and the docstring is worth reading in full:
- **`masked`** — SAME LENGTH as the input, comment bodies and string CONTENTS replaced by spaces,
  delimiters kept. **Index-preserving**, so a regex match on `masked` points at real code in the
  original.
- **`stripped`** — comments removed, string literals kept VERBATIM.
- **`dollarRegions`** — every top-level dollar-quoted string with content offsets; nested tags are
  part of the body.

It is already unit-tested (`src/__tests__/sql-body-normalize.test.ts`), including
`stripSqlComments("SELECT 'a -- b';")` returning the string unchanged.

⛔ **The reverted repair's worst single decision was writing a NAIVE duplicate of this**, named
identically (`stripSqlComments`), one import away from the correct implementation. Do not repeat it.
**Import from `sql-body-normalize.mjs`.** If the prober must not depend on that module, say why in
the plan and extract the lexer to a shared home — do not fork it.

## The nine-member bypass family — MEASURED, inherit rather than re-derive

Each returns **zero violations from all ten rules**:

| # | shape | note |
|---|---|---|
| a | `jsonb_build_object('X-Service-Key',$q$sk_live_…$q$)` | dollar-quoted value — **one token, no splitting** |
| b | `chr(115)||chr(107)||…` | zero literals at all |
| c | `concat('sk_live_','AAAABBBB','CCCCDDDD')` | |
| d | `format('%s%s','sk_live_AAAA','BBBBCCCC')` | |
| e | `convert_from(decode('…','base64'),'utf8')||…` | |
| f | `U&'\0073\006b'||…` | unicode escapes |
| g | `quote_literal('sk_live_…')||'…'` | |
| h | `k := '<key>'` then `jsonb_build_object('X-Service-Key', k)` | ⚠️ **variable indirection — no obfuscation** |
| i | `h := '{"X-Service-Key":"<key>"}'::jsonb; … headers := h` | ⚠️ **whole-header JSON — the anchor never matches** |

⛔ **(h) and (i) are what a normal developer writes.** Outside `match_engine_cron` nothing looks for
a long literal at all, because `long-literal-in-headers` is scoped to header regions only.
Header-name CASING is not a bypass (the regex carries `gi`); splitting the NAME is not one either.

**Fix the families, not the cases:** (1) recognise `$tag$…$tag$`, `E''` and `U&''` as literals —
`scanSql` already does; (2) length-test the DERIVED value by summing operands joined by `||` or
passed to `concat`/`format`/`chr`/`decode`; (3) add a rule firing on a long literal ANYWHERE in the
command with the Vault-read shape as its only exemption — **that third one is the only thing that
catches (h)**.
