## 2. Class A — PYAPIFIX-02: venue-transient fault answered with a caller-fault verdict

### Predicate (behavioural, in words)

> `services/exchange.py:validate_key_permissions` sets `read_only=False` **for two disjoint
> reasons**: a real write-scope verdict, and a *failure to establish any verdict*. Any code path
> that converts a `ValidationResult` into a caller-facing outcome — HTTP status, a `recoverable`/
> `retryable` body field, or a terminal-vs-transient job disposition — must separate the five

Ordered by the size of the hole they blow in the plan.

1. **`isProcessKeyOnboardResponse` is not exported, and `route.ts` cannot be imported cleanly from a
   test — RESOLVED, with a cost.** (§6.) The predicate is pure, so extraction to
   `src/lib/process-key-onboard-contract.ts` drags nothing. But this means **PYAPIFIX-01 necessarily
   edits a TypeScript source file**, which collides with CONTEXT's *"Out of scope: everything
   TypeScript beyond the one contract test"*. CONTEXT's own *"Decide deliberately WHICH side
   changes"* clause sanctions it. **The plan must state the reconciliation explicitly** rather than
   let the plan-checker find it. Bounded: one 37-line move + one import line + (if the TS side is
   chosen as the changing side) one branch condition.

2. **`frontend-coverage` is a blocking gate and the extraction's coverage delta is unmeasured.**
   `ci.yml:308` (`needs: frontend-test`), thresholds lines 82 / stmts 80 / fn 74 / branches 72. Both
   the old and new homes are inside `src/**`, and the parity test covers the new module, so the net
   should be ≥ 0 — but one `npm run test:coverage` after extraction is the only thing that settles it.

   pins `0.1.10`; the review's mutation evidence is from `0.1.9`. Survivors #3/#4 depend on
   `__evaluate_limits`' `if all(args)` empty-key skip; #5 depends on
