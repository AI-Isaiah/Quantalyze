# Phase 140.1.1 Plan 05: PYAPIFIX-01 — the consumer's model corrected, both directions proven — Summary

The TypeScript guard asserted a mutual exclusion the domain does not have. It is gone, and
the same edit paid for it three times over. The `/process-key` duplicate reply and its
consumer are now bound to **one committed artifact**, each side running its **own real
implementation** against it — and **neutering either side alone reddens the other's suite**,
observed first-hand in both directions rather than asserted.

## The defect, restated at source

Post-PYAPI-09 the reply carries two **independent** facts:

| Field | Asserts | Produced by |
|---|---|---|
| `queued` / `job_state` | a compute job is now enqueued or running | `_resume_duplicate_job` |
| `code:"WIZARD_DUPLICATE"` + `idempotent:true` | this submission was a duplicate | the duplicate pre-check |

Neither implies the other, and `_resume_duplicate_job` **exists to produce the state where
both are true**. The guard encoded them as one discriminant. Its comment called the
combination "a backbone bug"; it is a supported recovery outcome — **a defect in the
consumer's model, not the producer's.**

### The three invariants — what was actually enforced

| # | Invariant | Kills | Note |
|---|---|---|---|
| 1 | `code`, when present on **either** arm, must be a **non-empty string** | N2 | new — the `queued:false` arm only type-checked it |
| 2 | `idempotent`, when present, must be exactly `true` **and** paired with `code === "WIZARD_DUPLICATE"` | N3 | new — this is what stops the widening degrading to `() => true` |
| 3 | `verification_id` remains **required as a string** on the `queued:true` arm | `{queued:true}` alone | retained, not weakened |

**Invariant 2 is enforced in one direction only, deliberately.** `code === "WIZARD_DUPLICATE"`
does **not** require `idempotent` — that shape was legal before 140.1 and nothing in the
contract retired it. Enforcing the "iff" symmetrically would reject a body the service may
still emit. The code comment says so at the site, so a later reader does not "complete" it.

## M-11 — RECORDED DECISION (the record IS the deliverable; implementation is NOT)

**Finding, sharpened:** onboard's double-submit protection is **not broken — it is UNWIRED.**
Protection is job-level only (`enqueue_compute_job` dedupe + the
`compute_jobs_one_inflight_per_kind_strategy` partial unique index), and that mechanism is
currently **unreachable**: `process_key.py:977-979` gates `idempotent_by_session` on a
caller-supplied `wizard_session_id`, and `grep -n "wizard_session_id"` in
`finalize-wizard/route.ts` and `keys/sync/route.ts` returns **zero hits**. This is also the
reason H-5 was latent rather than live.

**CHOSEN — record and defer: wire the mechanism that already exists.** One payload field at
`finalize-wizard/route.ts:840-851`. Now ledger row **TS-33**.

**REJECTED — port `Idempotency-Key` from `allocator/scenario/commit/route.ts`.** It is real,
in-repo, and well-tested, so the cost is knowable rather than speculative — but it needs a TS
client change **plus** a Python read **plus a migration**, and M-19 records that migrations
auto-apply to PROD with **no branch protection** (`rulesets: []`). Building a second
idempotency mechanism before wiring the first is the point-fix-a-class antipattern this
programme exists to stop.

**REJECTED — harden the Python dedupe as dead code.** Inside the Python fence and cheap, but it
fixes nothing real: hardening an unreachable path leaves the actual gap open while producing a
green diff, which is how a finding gets marked closed without being closed.

**ORDERING (binding): STRICTLY AFTER PYAPIFIX-01.** Adding `wizard_session_id` before the
widened predicate lands converts H-5 from latent into a **live 502 + Sentry on every duplicate
resume**. This is the one sequencing argument that survives the deleted rollout argument — it
is a **phase** ordering, not a deploy ordering. **TS-01 is now DONE, so the constraint is
satisfied and the field is safe to add.**

**NOT IMPLEMENTED HERE, deliberately.** The payload field is 140.2/140.3's TS surface, outside
this phase's fence.
