### Neuter 2 — break the braced-before-pipe grouping (the detail flagged as easy to lose)

Two changes to the count computation, together reproducing the exact hazard: (a) restructured so the `|| echo '?'` fallback sits **outside the command-substitution assignment** entirely (`missing_err_lines="$( wc -l < … | tr -d '[:space:]' )" || echo '?'` — the fallback fires but its output goes to stdout, never into `missing_err_lines`), and (b) pointed the read at an unreadable path (`"${missing_err}-neuterUNREADABLE"`, which never exists). Note: a same-line reordering of `||`/`|` alone did **not** reproduce a blank in this script, because `set -euo pipefail` (active at file scope) already propagates `wc`'s failure through a same-line pipe — the failure mode that actually reproduces the historical hazard is the fallback landing outside the substitution, which is what "the fallback sits outside the grouping" describes.

**Observed (verbatim):**
```
AssertionError: the control did not print a countable stderr, so breaking `wc` below proves nothing: expected 'Repo migrations: 1\n?\n::error::VAC-0…' to contain '1 line(s) of stderr captured'
+ Repo migrations: 1
+ ?
+ ::error::VAC-08 repo-vs-TEST ledger and body drift gate: the ledger presence query failed (exited 3;  line(s) of stderr captured and WITHHELD — it can carry connection detail).
```
The count renders as a blank (`exited 3;  line(s)` — two spaces, no digit and no `?`) exactly where the number belongs, confirming the braces are load-bearing.

**Restore:** `cp` from backup; `cmp` reported byte-identical.
