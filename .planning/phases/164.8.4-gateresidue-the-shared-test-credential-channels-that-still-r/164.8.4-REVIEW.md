## Critical Issues

### CR-01: Two tests in `test-restore-workflow-wiring.test.ts` are stale against the shipped YAML and fail at HEAD — the phase's own fail-closed/leak-ordering proofs no longer execute

**File:** `src/__tests__/test-restore-workflow-wiring.test.ts:1270-1273` and `src/__tests__/test-restore-workflow-wiring.test.ts:6420-6429`

**Issue:** Reproduced by running `npx vitest run src/__tests__/test-restore-workflow-wiring.test.ts` at HEAD: 2 of 752 tests fail.

Root cause: commit `d04bb210` ("fix(164.8.4): portable in-place redaction, and retire an
exemption this phase earned") rewrote the shipped `sed -i -E -f "${GITHUB_WORKSPACE}/…"`
single-line form in both `.github/workflows/ci.yml` (the `sql-tests` per-file loop and
NOTICE-channel probe) and `.github/workflows/test-restore-from-baseline.yml` (the
"Redact connection metadata from the backup directory" step) into the portable
`sed -E -f … > "$x.redacted" && mv "$x.redacted" "$x"` form — correctly, per the
portability analysis above — but did not update the two tests in
`test-restore-workflow-wiring.test.ts` that hard-anchor on the old `-i` shape:

1. `it("a FAILED substitution DESTROYS the channels and exits 1 — EXECUTED, forced to
   fail")` (line ~1255) asserts `script.includes("if sed -i -E -f ")` — this string no
   longer appears anywhere in the step's body (the shipped text is now
   `if { sed -E -f "${GITHUB_WORKSPACE}/scripts/redact-psql-stderr.sed" "${f}" >
   "${f}.redacted" && mv "${f}.redacted" "${f}"; }; then`). The assertion fails
   outright before the mutation-and-execute proof ever runs.
2. `it("every capture is redacted before its echo, and a deleted redaction line is
   caught")` (line ~6419) drives `calibrate()` with a mutation string
   `'sed -i -E -f "${GITHUB_WORKSPACE}/scripts/redact-psql-stderr.sed" "$out"; then'`
   against `CI` — this string also no longer appears in `ci.yml` (same portability
   rewrite, ci.yml's two `sql-tests` sites). `calibrate()`'s own "mutation produced an
   identical string, so the twin proves nothing" guard correctly catches this and
   fails the test loudly rather than passing vacuously — but the test still fails.

Both failures are reproducible right now:

```
Test Files  1 failed | 4 passed (5)
     Tests  2 failed | 750 passed (752)
```

This is exactly the class this repo's own memory notes warn about ("a FIX ROUND IS
WHERE REGRESSIONS ENTER … a NEW code path is outside every existing gate BY DEFAULT
and the suite stays green"): `d04bb210` was an ad-hoc, unplanned follow-up commit (no
plan number, landed after Plan 05 merged) that changed production YAML shape without
re-running the specific tests anchored to the old shape's literal text. The commit
message's own verification claim ("Verified: 312/312 across the three byte-identity
suites; all 15 workflows parse; 0 bare relative references; check:planning-hygiene
clean") is true as far as it goes but did not include `test-restore-workflow-wiring.test.ts`,
which is the file most directly entangled with the exact code shape `d04bb210` changed.

I independently re-derived the underlying *production* behavior by hand (traced every
branch of the `if { sed … && mv …; }` / `else` / `trap … ERR` construct in both
workflow files) and confirmed the shipped YAML is correctly fail-closed — this is not
a production security regression. But the two broken tests are exactly the tests this
phase wrote to *prove* that property by execution rather than by static reading, and
right now neither one reaches its own assertions. Per this phase's own stated
anti-vacuity stance ("a credential reaching a public log is DATA-INTEGRITY, not
hygiene. A gate that cannot fail is a BLOCKER in this phase") — a gate that cannot
even *run* is the same failure mode, and the suite is presently red, which would fail
this branch's CI aggregator on push.

**Fix:**
```diff
- expect(
-   script.includes("if sed -i -E -f "),
-   "the redaction step's substitution is no longer the `if sed -i -E -f` form this twin forces to fail — re-anchor the mutation rather than deleting the twin",
- ).toBe(true);
- const forced = script.replace("if sed -i -E -f ", "if false -i -E -f ");
+ expect(
+   script.includes('if { sed -E -f "${GITHUB_WORKSPACE}/scripts/redact-psql-stderr.sed" "${f}" > "${f}.redacted"'),
+   "the redaction step's substitution is no longer the redirect+mv form this twin forces to fail — re-anchor the mutation rather than deleting the twin",
+ ).toBe(true);
+ const forced = script.replace(
+   'sed -E -f "${GITHUB_WORKSPACE}/scripts/redact-psql-stderr.sed" "${f}" > "${f}.redacted"',
+   'false',
+ );
```
and, for the `calibrate()` call around line 6420-6429, re-anchor the mutation string on
the current shape (e.g. the literal `sed -E -f "${GITHUB_WORKSPACE}/scripts/redact-psql-stderr.sed" "$out" > "$out.redacted"`
substring shared by both ci.yml sites this arm targets), verifying with
`console.log`/a throwaway run that the replace actually changes `CI` before trusting
the calibration again. Re-run the full file after the fix and confirm 752/752 (or
whatever the new total is) pass before this ships.

### IN-02: The channel-derivation regex requires a literal filename segment, so a dynamically-named write target would silently under-derive (safe direction, but worth noting)

**File:** `scripts/derive-restore-channels.sh:52` (`WRITE_TARGET_RE`)

**Issue:** `WRITE_TARGET_RE='\b(RESTORE_OUT_DIR|outdir)\}?/[A-Za-z0-9_.-]+\.(err|log|out)'`
requires the filename component to be a literal string. A producer that wrote
`"${outdir}/${dynamic_name}.err"` (variable-interpolated basename) would not be picked
up by this derivation — the channel would never be staged. This fails in the safe
direction (default-DENY: a channel that can't be derived is simply never published,
which is the correct failure mode for this control) so it is not a defect, but it is a
real blind spot if a future producer ever needs a dynamically-named diagnostic channel;
worth a one-line comment noting the limitation so a future author doesn't assume the
derivation is fully general.

**Fix:** No action required now; consider a header-comment note recording the
literal-filename assumption for future producers.
