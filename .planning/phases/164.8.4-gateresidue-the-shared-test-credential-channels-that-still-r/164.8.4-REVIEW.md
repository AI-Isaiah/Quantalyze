### IN-02: The channel-derivation regex requires a literal filename segment, so a dynamically-named write target would silently under-derive (safe direction, but worth noting)

**File:** `scripts/derive-restore-channels.sh:52` (`WRITE_TARGET_RE`)

**Issue:** `WRITE_TARGET_RE='\b(RESTORE_OUT_DIR|outdir)\}?/[A-Za-z0-9_.-]+\.(err|log|out)'`
requires the filename component to be a literal string. A producer that wrote
`"${outdir}/${dynamic_name}.err"` (variable-interpolated basename) would not be picked
up by this derivation — the channel would never be staged. This fails in the safe
direction (default-DENY: a channel that can't be derived is simply never published,
which is the correct failure mode for this control) so it is not a defect, but it is a
real blind spot if a future producer ever needs a dynamically-named diagnostic channel;
worth a one-line comment noting the limitation so a future author doesn't assume the
derivation is fully general.

**Fix:** No action required now; consider a header-comment note recording the
literal-filename assumption for future producers.
