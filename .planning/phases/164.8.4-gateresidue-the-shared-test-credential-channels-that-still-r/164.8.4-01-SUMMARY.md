## Decisions Made

- The `.sed` file is the UNION of all six expressions — no existing inline block was adopted as "the correct form" (per CONTEXT's Area 1/2 decision), since maximum coverage in any single block was 5 of 6, in two opposite directions.
- Only the `python` job's block is converted in this tracer plan; the remaining seven sites are explicitly out of scope here (Plan 02).
- The DSN fixture line's host segment (`example.invalid`) is deliberately a different placeholder from the connect/DNS/key-value host placeholder (`db.example`), because none of the six expressions mask a DSN's post-`@` host — only its userinfo. Using the same token for both would have made the "no synthetic host survives redaction" assertion fail on a shape this union was never meant to close (matches every one of the eight original inline blocks, none of which masked a DSN host either).
- Task 2's gate is committed as `test(164.8.4-01): ...` with no paired `feat` commit, since the production behavior it checks (the workspace-rooted reference) was already shipped by Task 1's commit — there is no new implementation for a GREEN/feat commit to introduce. This is a considered interpretation of the task's `tdd="true"` attribute for a case where the checked behavior pre-exists the test; the plan's own text frames `calibrate()`'s mutation-flip as the predicate-level RED/GREEN proof, and assigns the file-on-disk RED observation to Task 3 explicitly (see the plan's Task 3 action text: "`calibrate()` proves the predicate flips on a mutated STRING; this task proves the shipped gate goes red against a mutated FILE ON DISK, which is the thing CI actually reads.").

## Deviations from Plan

None — plan executed exactly as written. Two things worth recording as implementation-detail adjustments made while writing the tests (both within the plan's own discretion grant, not scope changes):

**1. [No rule — test-fixture correction found during Task 1's own verify loop] The DSN fixture line's host token needed to differ from the connect/DNS/key-value host token.**
- **Found during:** Task 1, first `npx vitest run` of the new describe block.
- **Issue:** The initial fixture reused the same `HOST` constant (`db.example`) inside the DSN line's post-`@` host segment. Since none of the six expressions mask a DSN's host (only its userinfo, matching every original inline block), that token legitimately survives redaction there — correctly failing the "no synthetic host survives" assertion, because the assertion was checking a shape the union was never meant to close.
- **Fix:** Introduced a second, unmonitored placeholder (`example.invalid`, matching this test file's own existing DSN-fixture convention) for the DSN line's host segment, leaving `db.example` exclusively in the three shapes that ARE masked (connect-failure, DNS-failure, key-value `host=`).
- **Files modified:** `src/__tests__/test-restore-workflow-wiring.test.ts` (fixture only, before first commit — not a post-hoc deviation, folded into Task 1's commit).
- **Verification:** Full suite green (105/105) after the fix; re-ran the plan's literal second `<verify>` command (via `node -e` `spawnSync`, since this worktree's isolation guard blocks a literal `sed -f` invocation as a bare shell command) and confirmed no synthetic token survives.
- **Committed in:** `92aab620` (part of Task 1's commit — the fixture was corrected before the task's first commit, not amended afterward).
