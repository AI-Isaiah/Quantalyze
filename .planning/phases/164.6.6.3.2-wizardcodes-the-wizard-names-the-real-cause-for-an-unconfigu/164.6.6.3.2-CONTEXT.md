## Implementation Decisions (founder 2026-10-07, AskUserQuestion)

- **D-01 (item 7, env gap):** One NEW env-gap wire code and one NEW wizard code cover every "gateway not
  configured" emitter: the three env gaps in `routers/exchange.py`, the port-malformed case, AND the
  fifth emitter added by 164.6.6.3 plan 05 (empty `MT5_KNOWN_SERVERS` and `MT5_SERVER`). Copy: the
  problem is on our side (the connection is not set up), we have been alerted, and the contact form is
  the way to reach us. `SEAM_INTERNAL_FAULT` stays only for the true D-31 `undetermined` arm.
- **D-02 (item 10, busy):** One NEW recoverable wire code and wizard code for both `scrub_owed` and
  `lease_busy` (today both raise 424 `NETWORK_UNAVAILABLE`, shown as `KEY_NETWORK_TIMEOUT`). Copy: the
  MetaTrader terminal is briefly busy; retry in a minute. Pinned by a test per emitter.
- **D-03 (item 0, history not settled):** Copy only, no auto-retry. The wizard says the broker is still
  sending the account's history, nothing is wrong with the key, and to retry shortly. It replaces
  `GATE_ANALYTICS_FAILED`'s "the fault is in our pipeline" for this cause. The carrier is the existing
  `error_kind="transient"` plus the fixed messages `_MT5_HISTORY_UNSETTLED_MESSAGE` (derive) and
  `_MT5_BACKFILL_MESSAGES["history_unsettled"]` (backfill); no new DB `error_kind` (164.6.6.3 D-13).
- **D-04:** Every wire-code roster and census pin moves together, re-based on the counts after
  164.6.6.3 added `MT5_SERVER_UNKNOWN` / `KEY_MT5_SERVER_UNKNOWN`. Grep the pins; never count by hand.
- **D-05:** No contact email anywhere (164.6.6.3.5 DOMAINONE): pointers say "the contact form".

- **D-06 (founder 2026-10-07, after research OQ-1 — the D-03 carrier):** The history-not-settled cause
  reaches the wizard through a cause stamp on the job's FINAL failed attempt, written into the existing
  Phase 164.2 provenance columns (no migration, no new `error_kind`; research option C2). The wizard shows
  the D-03 copy only when that stamp names this cause; every other transient failure keeps today's
  handling. This reverses 164.6.6.3's "no stamp" choice for this one cause only.
- **D-07 (orchestrator, from research):** the new env-gap wizard code joins `OUR_DEFECT_KEY_ERROR_CODES`
  so the key routes keep paging for it (clone the `[164.6.5 WR-06]` route tests). D-01's "we have been
  alerted" must be true at every env-gap emitter: add a capture at the log-only site (research E3) with a
  source-reading pin, rather than dropping the claim.
