## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| PR author → CI runner | A pull request's files (gate SQL, migrations, changed-path names) drive the `sql-mutation` subset and the lane's migration replay. | Untrusted file names and SQL text |
| CI runner → public log | Every lane, probe and gate prints into a public Actions log. | DSNs, hosts and roles must never appear |
| Lane → shared TEST | Only `test-db-drift`, `python` and `e2e-seeded` hold the shared-TEST secret and mutex. `sql-tests` runs on a private loopback lane. | TEST DSN (secret) |
| Runner → GHCR | Supabase CLI image pulls authenticate with the job's `GITHUB_TOKEN` over stdin, `packages: read`. | Short-lived token |
| Migrations → lane (superuser) | The non-public object load (auth trigger, cron jobs) runs as the lane superuser, derived only from the lane's own loopback DSN. | SQL from committed migrations |

## Advisories (non-blocking)

1. **T-28:** the recorded commit-to-bullet table covers 89 commits. The 36 review-round, docs and release commits were mapped by hand to the 0.87.0.0 "Fixed — code review, two rounds" bullets, and none is unrepresented.
2. **T-31 residual:** a setting name built at run time (concatenation, `chr()`, dynamic EXECUTE) is not detected. This is recorded as a known limit in the CHANGELOG and in the `psqlMetaCommandLines` header. The root-cause fix, replaying each file without psql script parsing, changes transaction semantics and is left as a decision. Separately, the dump load (`load_baseline`) and `load_reference_data` call psql without `-X`. Neither runs a replayed migration, and `sql-tests` holds no secret.
3. **T-29:** the AFTER measurement is pending by design. It needs merge-push runs.
4. **T-06 and T-09** are closed on the mechanisms that replaced the declared ones (DECISION F and plan 08).
