# Phase 164.4.2 Plan 03: the ephemeral lane refuses a stale baseline, and CI can tell Summary

**`scripts/local-stack/run.sh` now calls the shared currency gate inside `load_baseline()`
before psql touches the dump, and aborts if the gate refuses. A new `--check-currency` seam
runs the same call. Both lane-booting CI jobs check out with `fetch-depth: 0` so the guard
reads real commit times, and `frontend-local-stack` runs the seam as its own named step.
The refusal was observed in both directions, and 8 neuters each turned a pin RED by name.**

## The refusal, observed in both directions through the lane's own seam

The plan asks for this message verbatim. It is verbatim except for one change: the gate prints
the lane's ABSOLUTE `BASELINE_FILE`/`MIGRATIONS_DIR`, and on a developer box that path includes
the home directory and username. This repository is public, so the checkout root is replaced
with `<REPO_ROOT>`. No other character was changed.

**Stale stub** (baseline reported at epoch 1000000000, migrations at 2000000000):

::error::baseline-stale — the baseline dump is STALE: <REPO_ROOT>/supabase/schema/baseline.sql last changed at epoch 1000000000, <REPO_ROOT>/supabase/migrations at epoch 2000000000. A migration landed after the last dump regeneration, so this dump does not describe PROD. Regenerate the baseline first.

**Fresh stub** (baseline at 2000000000, migrations at 1000000000) → **exit 0**

baseline-currency: baseline=2000000000 migrations=1000000000 defects=0

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] The CI half of the guard had no pin**
- **Found during:** Task 3
- **Issue:** The plan pinned the boot path in vitest (Task 2) but not the CI conditions that
  make the guard meaningful. Removing `fetch-depth: 0` from either job, or dropping the
  `--check-currency` step, would have made the guard pass vacuously and no test would notice.
  That is the defect class this phase exists to remove.
- **Fix:** A second arm in `src/__tests__/local-stack-lane-wiring.test.ts`. It checks that both
  jobs carry a live (non-comment) `fetch-depth: 0` line, and that `frontend-local-stack` runs
  the seam before `run.sh up`. Proven by neuters 6–8.
- **Files modified:** `src/__tests__/local-stack-lane-wiring.test.ts` (already in this plan's `files_modified`)
- **Commit:** `1e568033`

**Total deviations:** 1 auto-fixed (Rule 2). **Impact:** one extra test arm in a file this plan
already owned. No scope creep.

## Recommendation (not done, out of this plan's scope)

The guard's reading on a shallow clone is protected only by CI configuration. The deeper fix
is for `scripts/check-baseline-currency.mjs` itself to refuse by name when it runs on a shallow
repository (`git rev-parse --is-shallow-repository` returns `true`) and `FRESHNESS_TS_CMD` is
the git default. Then no caller could get a vacuous pass. That file belongs to plan 02 and is
also used by the restore path, so the change was not made here.
