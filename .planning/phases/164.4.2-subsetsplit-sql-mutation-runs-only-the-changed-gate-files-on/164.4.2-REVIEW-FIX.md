### WR-04: The replay's meta-command refusal only catches a line-start backslash (plus the widening)

**Status:** fixed (requires human verification: logic)
**Files modified:** `scripts/check-baseline-currency.mjs`
**Commits:** f65279066, then 1e40a7fa7 (style: two eslint `no-unused-expressions` warnings in the new code)
**Applied fix:** A new `psqlMetaCommandLines` lexer refuses any backslash outside a `--` comment, a nested block comment, a `'…'`/`E'…'` literal, a `"…"` identifier or a `$tag$` body. That matches how psql's own lexer decides what is a meta-command. A file whose quoting never closes is refused as unprovable. An unreadable replay file gets a new named kind, `replay-file-unreadable`, and is no longer scanned as empty.

`maskSql` was deliberately **not** reused. It scans dollar-body interiors as code, which is right for the SQL linter and wrong for psql. Measured over all 273 migrations (52 contain a backslash): 0 flagged.

Self-test R10 gained 5 arms: mid-line, two per file by line number, a comments/literals/dollar-body control, unterminated quoting, and an unreadable file. `EXPECTED_ASSERTIONS` went from 31 to 36. Both guards were observed RED when neutered.
