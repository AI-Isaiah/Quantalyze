## Task 2: the assert-step arms

The new arms, in the order the step runs them:
1. Count the `scope:` lines (the `set +e … rc … set -e; [ rc -le 1 ]` idiom). Zero lines is a
   MEASURE_FAIL, and more than one is a MEASURE_FAIL.
2. The form must be `FULL … annotated files` (optionally `(subset fallback: …)`) or
   `SUBSET k/N annotated files: …`. Anything else, including DIAGNOSTIC, is a MEASURE_FAIL.
3. A SUBSET on an event other than `pull_request` is a MEASURE_FAIL that names the scope line and
   the event.
4. For a SUBSET, the claimed k must equal the `*.sql` names printed. k must not be 0, N must equal
   the coverage numerator, and k must not exceed N. The per-file row count must then equal k
   instead of N.
5. For a SUBSET, the runner's `ARMS_FLOOR: NOT compared — this SUBSET run …` line is required. The
   step prints its own closing sentence and exits 0 before the ARMS_FLOOR comparison, and that
   sentence never claims both floors held.
6. A FULL run, including the fallback form, goes through every existing arm unchanged, ARMS_FLOOR
   included.
