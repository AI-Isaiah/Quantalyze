## What was built

- **`sql-corpus-report.mjs` (Task 0).** A diagnostic, not a gate. It runs each `supabase/tests/test_*.sql` file the way CI's `sql-tests` step does (`psql -X -v ON_ERROR_STOP=1 -f`, the LANE-ONLY exclusion, NET 1, NET 2) and continues past failures.
  - `--file` narrows the run and may name files outside the corpus. The scope line says `NARROWED` and counts inside and outside files.
  - `files` counts LANE-ONLY files too. An error after a SKIP marker is labelled FAIL.
  - psql is handed a repo-relative path, or the bare name of a file outside the repo, so its messages never carry a home path.
- **`nonpublic-objects.mjs` (Tasks 1-2).**
  - `--emit` folds the CARRIED migrations only, in filename order.
    - The auth.users trigger class uses `maskSql` + `statements`, with dollar bodies excluded via `dollarBodyRanges`/`insideBody`.
    - The cron class finds call sites in code positions, and each call's arguments are parsed locally from its own `(`.
    - It writes `nonpublic-auth-triggers.sql` and `nonpublic-cron.sql` from the original bytes.
  - `--check` re-derives the fold and never reads the emitted SQL.
    - Triggers: name, `tgtype` (every bit decoded), `tgenabled = 'O'` and the schema-qualified function are compared.
    - Cron jobs: name, schedule and command are compared byte-exact, plus `active`, `username = --cron-owner` and `database`.
    - Output: MISSING, EXTRA, DIFFERS and DUPLICATE are DRIFT (exit 1). An unprovable shape, an empty or meta-less catalogue, a non-superuser reader, or declared jobs without pg_cron is MEASURE_FAIL (exit 2).
- **`nonpublic-catalogue.sql`.** Meta rows (superuser, database, pg_cron), every non-internal `auth.users` trigger, and every `cron.job` row with its free text hex-encoded. An unnamed job gets a visible placeholder name, so it cannot collapse into a skipped blank line.
- **`run.sh`.** `load_nonpublic_objects`: the trigger goes through the superuser DSN in `-1`, and the cron file goes through `"$db_url"` in `-1` with no fallback role. `check_nonpublic_fidelity`: the catalogue is read through the superuser DSN, with `--cron-owner` set to the loading role. Both are called in `load_baseline()` after `load_reference_data` and before `replay_migrations`, with the reason written beside them. A D-G paragraph was added to the header.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The corpus report printed an absolute home path**
- **Found during:** Task 0 (d)
- **Issue:** psql prefixes every message with its `-f` argument as given, so each FAIL's first `ERROR:` line carried the worktree's absolute path. The repo is public.
- **Fix:** psql gets a repo-relative path, or the bare name run from the file's own directory for files outside the repo, and those are labelled `(outside the repo) <name>`.
- **Commit:** `6273c940a` (fixed before the commit)

**2. [Rule 1 - Bug] The catalogue failed on `text || "char"`**
- **Found during:** Task 1 (c), the first boot. It FATALed loudly, as designed, and the stack tore down.
- **Fix:** `t.tgenabled::text`.
- **Commit:** `326a51109`

**3. [Rule 2 - Missing critical] An unnamed cron job could vanish from the catalogue**
- **Issue:** A NULL `jobname` nulls the whole concatenated row, and psql prints it as a blank line that the gate skips. An EXTRA job would have gone unseen.
- **Fix:** `coalesce(jobname, '(unnamed jobid N)')`, so such a job surfaces as EXTRA.
- **Commit:** `ba287553f`

**4. [Rule 2] A `never-scheduled=` census field**
- A no-op unschedule is usually the guard before a job's first schedule: 15 of the 16 on the real corpus are that guard. The census now names only names no carried call ever schedules. The Task 2 fold arm's expectation was updated to match after the RED run.
- **Commit:** `ba287553f`

**5. Scope notes, recorded as deviations and not silent choices**
- The two-lexer agreement check also covers the auth-trigger class. The plan required it for cron.
- The trigger file is applied with `-1` as well. The plan listed `-X -v ON_ERROR_STOP=1 -q`.
