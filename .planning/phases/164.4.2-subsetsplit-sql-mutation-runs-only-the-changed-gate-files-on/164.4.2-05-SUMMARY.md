## The 13 failures — each classified

All 13 were **(a) pins encoding the design DECISION B deliberately changed**. None was a defect
plan 05's ci.yml edit introduced, so ci.yml is unchanged by this continuation. No guard was
deleted, no tolerance or allowlist was widened, nothing was skipped.

### `critical-regressions.test.ts` — 7 tests, `[CRITICAL-C0293] … shared-test-db serialization`

**Cause:** `DB_JOBS` was `["sql-tests", "python", "e2e-seeded"]`; `sql-tests` no longer holds
the key, so every per-job mutex arm failed on it. **(a)** — the D-05 intent (one writer of
shared TEST at a time) is unchanged; the set of writers changed.
**Fix:** `DB_JOBS` = `python`, `e2e-seeded`, `test-db-drift`, counted from ci.yml (the three
jobs that carry an acquire step and the only three that name the key). All seven arms now run
over the real holders, including the byte-identity arm, which proves `test-db-drift`'s acquire
step is byte-identical to `python`'s. **Strengthened, not loosened:** a new arm measures the
holder set from ci.yml and compares it with `DB_JOBS` as an exact set in both directions, and
asserts `sql-tests` is not a holder; and a new `test-db-drift` needs:+result-loop pair mirrors
the retained `sql-tests` pair.

### `ci-anti-skip-gate.contract.test.ts` — whole file (collection error)

**Cause:** the file extracts the corpus step by NAME at module load; plan 05 renamed it from
"Run SQL self-tests against test Supabase project" to "Run SQL self-tests against the
local-stack lane", so extraction threw and no test ran. **(a).**
**Fix:** `STEP_NAME` follows the rename; the stub env feeds a loopback lane handoff through
`LANE_ENV_FILE` instead of the retired secret; the LANE-ONLY notice assertion names the lane;
the psql `-X` pin reads the lane DSN variable. **Added (Rule 2):** two EXECUTED arms for the new
DSN guard — an absent handoff fails loud, and a non-loopback `DB_URL` is refused before any
file reaches psql. Neither refusal was pinned before.

### `ci-docs-path-filter.contract.test.ts` — "the FILTERED set equals its roster of seventeen"

**Cause:** `test-db-drift` is a new job carrying the docs-only conjunct; the roster did not list
it. **(a).** **Fix:** roster gains `test-db-drift` (seventeen -> eighteen, title and count
updated). S7 (docs-only FORK PR composes with the per-row arms) now exercises `e2e-seeded` and
`test-db-drift`, because `sql-tests` no longer has a fork-PR tolerance arm.

### `lint-sql-gates.test.ts` — 5 tests under "the CI invocation (mode identity)"

**Cause:** `EVENT_TOLERANT_JOBS` named `sql-tests`; the tolerant arm moved to `test-db-drift`.
The MW02 green fixture still modelled the old loop, so both fidelity arms failed. **(a).**
**Fix:** `EVENT_TOLERANT_JOBS` swaps `sql-tests` for `test-db-drift` (still three — a one-for-one
swap the exact-set pins see and a count would not); `DOCS_ONLY_TOLERANT_JOBS` gains
`test-db-drift` (12 -> 13); the green fixture is re-quoted from ci.yml with the new row and the
re-homed arm, and dated. Executed posture measured after the fix: on a code PR `sql-tests` is
tolerated in **0 of 8** combinations (strict), `test-db-drift` in **6 of 8** (fork PR or
dispatch); on a docs-only PR both in 8 of 8.
