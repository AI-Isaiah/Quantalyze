## Accomplishments

- **Demand is derived from the corpus, never pinned.** It is re-counted every run
  from `supabase/tests/test_*.sql`, with LANE-ONLY files excluded by the same
  predicate `sql-tests` uses. No floor, no census pin, no stored comparison.
- **Supply is read from the lane, and "could not ask" is never "absent".** Any class
  missing from the answer, answered twice, non-integer, or an answer carrying a line
  that is not ours, reads as UNREADABLE. That gives MEASURE_FAIL, exit 1, even for a
  class nothing demands.
- **The lane's DSN stays local and private.** It is read from the mode-600
  `.stack-env` handoff and refused before connecting unless it is a loopback postgres
  URL with a port and no query string. psql receives it as an argv element, with PG*
  stripped from its environment. It is never printed: execFileSync's message embeds
  the argv and is never printed, and psql's stderr is redacted before printing.
- **The CI step is fatal about measurement.** An absent line, a MEASURE_FAIL verdict,
  an unreadable count or state, an unrecognised token, no class tokens, or an exit
  status that contradicts the verdict each fail with a named `::error::MEASURE_FAIL`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Correctness of the measurement] Demand excludes LANE-ONLY files**
- **Found during:** Task 1
- **Issue:** The plan says demand is detected "over `supabase/tests/test_*.sql`".
  Taken literally, that counts `test_prod_prober_cadence.sql`, which carries
  `-- LANE-ONLY:` and never runs under `sql-tests`. It mentions pg_net, vault and
  cron, so counting it inflates exactly the classes most likely to be absent. The
  result could be an INSUFFICIENT caused by a file that would never run on the lane,
  which would open DECISION C's fallback on a false refutation.
- **Fix:** Excluded by `sql-tests`'s own line-start predicate, and printed on the line
  as `lane-only-excluded=<M>`, so the exclusion is visible on every run. Measured
  locally: pg_net 1 (not 2), vault 1 (not 2), pg_cron 10 (not 11).
- **Files modified:** `scripts/local-stack/capability-probe.mjs`
- **Verification:** self-test section 11 plus neuter N10.
- **Committed in:** `e4b5e77a`

**2. [Rule 2 - Security, threat T-164.4.2-10/-12] Stricter DSN handling than run.sh's glob**
- **Found during:** Task 1
- **Issue:** "Matching the lane's own local-only refusal" read literally is
  `*@127.0.0.1:*`. That glob accepts `@127.0.0.1:` smuggled into the userinfo, and a
  `?host=` query string that libpq would follow. PG* environment variables would also
  fill in anything the DSN leaves unset.
- **Fix:** URL-parsed host check, a port required (as run.sh requires), query
  strings/fragments refused, PG* stripped from psql's environment, and psql's stderr
  redacted before printing.
- **Verification:** self-test section 14 plus neuters N7–N9, and the end-to-end refusal table above.
- **Committed in:** `e4b5e77a`

**Total deviations:** 2 auto-fixed (1 Rule 1, 1 Rule 2). **Impact:** both make the
measurement more trustworthy. Neither widens scope beyond the two files the plan names.
