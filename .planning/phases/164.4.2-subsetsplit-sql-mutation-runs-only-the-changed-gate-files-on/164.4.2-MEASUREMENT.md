## Recipe

Run verbatim, reproducible at any later head with different run ids substituted.

**Step 1 — enumerate merge-push runs of `ci.yml`:**
```bash
gh run list --workflow=ci.yml --branch main --event push --json databaseId,headSha,createdAt,conclusion --limit 12
```
Take the most recent runs that CONCLUDED (`conclusion` non-empty; skip cancelled and in-progress
— an in-progress run reports `conclusion: ""`, not `null`). Use at least 5.

**Step 2 — per run id, pull per-step timings for the three mutex-holding jobs:**
```bash
gh api "repos/AI-Isaiah/Quantalyze/actions/runs/<run_id>/jobs?per_page=100" \
  -q '.jobs[] | select(.name=="sql-tests" or .name=="python" or .name=="e2e-seeded") | {name, started_at, completed_at, steps: [.steps[] | {name, started_at, completed_at}]}'
```

**Step 3 — per run id, pull the run's own wall-clock:**
```bash
gh api "repos/AI-Isaiah/Quantalyze/actions/runs/<run_id>" -q '{run_started_at, updated_at, status, conclusion}'
```

**Per run, per job, four quantities are derived from the step timestamps returned by Step 2:**
- **acquire-wait** — duration of the step whose name begins `Acquire shared-test-db mutex`
- **useful work** — duration of the job's own work step (`sql-tests`: `Run SQL self-tests against
  test Supabase project`; `python`: `Run pytest --cov=...`; `e2e-seeded`: `Run seed-gated specs
  (MA-8 / BLOCK-3)`)
- **job-total** — the job's own `started_at` → `completed_at` (top-level object from Step 2, not a
  step)
- **run-total** — the workflow run's own `run_started_at` → `updated_at` (Step 3)

Durations were computed with a small Node script (`new Date(b) - new Date(a)`, rounded to the
nearest second) rather than by hand, to avoid transcription arithmetic errors in a document that
stays in the repo.

If a job is absent from a run (a skip), it is recorded as ABSENT with the reason from its `if:` —
never as a zero. **No job was absent from any of the 6 runs captured below.**
