<objective>
D-D's wiring (DECISION D): select the subset on a pull request, the full corpus on a push, and make
the vacuity fence a property of the JOB rather than of the runner alone.

Purpose: plan 07 gave the runner the mode and nothing calls it yet. This plan calls it, and adds the
out-of-process half of the fence: `sql-mutation`'s assert step reads numbers out of a log it did not
produce, and a subset run changes which of those numbers are comparable.

⭐ It also answers the ROADMAP's question about the full-corpus run's attribution: D-D puts the full
corpus on the PUSH to main rather than on a schedule, so its red lands on the merge commit, on the
board Railway already reads, with an author and a diff. A scheduled run's red lands on nobody.

Output: a PR that touches three gate files mutates three gate files; a merge mutates all of them.
</objective>

**The `scope:` forms plan 07 fixed:** `scope: FULL <N>/<N> annotated files`, the same with
`(subset fallback: <reason>)`, `scope: SUBSET <k>/<N> annotated files: <names>`, `scope: DIAGNOSTIC …`.
Read them from `164.4.2-07-SUMMARY.md` and the runner, not from this plan, if they differ.

**Which assertions change in a subset run, and which must not:**
| assertion | subset run |
|---|---|
| `coverage: files N/M` present, N >= FILES_FLOOR | UNCHANGED — N comes from the full scan |
| `unreachable:` / `lane-blocked:` / `lane-probe:` present, claim equals names | UNCHANGED — derived from the full scan |
| `arms: E/A/W` present, E > 0, W <= ceiling | UNCHANGED |
| `biting: N` present, N <= E, `lane-invocations` equals E | UNCHANGED |
| per-file rows present, rows sum to `biting` | UNCHANGED |
| per-file row COUNT equals the coverage numerator | CHANGED — equals the narrowed count |
| `biting >= ARMS_FLOOR` | NOT COMPARED — the run says so, and says where it IS compared |
