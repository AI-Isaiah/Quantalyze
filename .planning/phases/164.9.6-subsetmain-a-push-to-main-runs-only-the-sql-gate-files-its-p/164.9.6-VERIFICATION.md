### WR-03 vacuity analysis (the brief's specific question)

**No vacuous pass was found at the code level:**
- **Only two exits narrow.** `judgePush` returns `subset` or `none` only through `narrowed()`, at the D-09 exit and the final SUBSET exit. Every other exit is `full(...)`.
- **The first call cannot narrow.** `derivePush`'s first `judge` call passes no predecessor, so `narrowed()` returns FULL with `predecessorOwed: true`. Only the second call, with `predecessorVerdict(pushRange.sha, readPredecessor)` supplied, can narrow.
- **The check is strict.** It requires `predecessor?.ok !== true`, so a falsy, malformed or missing verdict is FULL. `derivePush` also has a catch-all that returns FULL.
- **The proof is not trivially satisfiable.** `predecessorVerdict` requires all of these:
  - both bodies well-formed and untruncated (`total_count` no larger than what was returned);
  - no foreign `head_sha`;
  - every GitHub Actions run, deduplicated within a suite, completed and in {success, skipped, neutral};
  - every Actions suite completed and non-red;
  - a successful `frontend` run.
  `frontend` is ci.yml's strict aggregator, which has `sql-mutation` in `needs:` and in its result loop. So a red SUBSET on push A makes A's `frontend` red, and push B is FULL. The masking chain is broken by induction, and every narrowed push sits on a green run.
- **A red nightly blocks the next narrowing.** It leaves a red Actions run on main's head SHA, so the next push is FULL. The same holds for a cancelled CI run on `before` (`cancelled` is not OK).
- **No API call is made on a FULL push.** The self-test asserts `ghArgv === null`. My `5552bf977` dry run, a machinery push, confirmed 0 `gh` calls.

**Caveats:**
- **Real-`gh` runs read today's state.** My dry runs used the real `gh` read, which sees each predecessor's checks as they are TODAY, not at push time. Only the fake-`gh` pending row covers timing. That row gives FULL, which is the safe direction.
- **Nightly linkage is post-merge.** A red nightly forces the next push to FULL only if the nightly's check suite lands on main's head SHA. That linkage can only be seen after merge (human item 4).
