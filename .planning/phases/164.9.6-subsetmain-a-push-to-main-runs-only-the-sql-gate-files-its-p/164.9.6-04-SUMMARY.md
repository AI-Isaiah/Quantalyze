# Phase 164.9.6 Plan 04: the D-09 scope step Summary

`sql-mutation` now has a scope step directly after `actions/setup-node`. When the derivation says `sql_gate_mode=none` on a push to `refs/heads/main`, with a non-blank reason and no gate files, the step prints `scope: NONE 0 gate files — no mutation input changed` and `scope-reason: <reason>`, then writes `skip_lane=true`. The job ends green without booting a lane. Every other input boots the lane, and that includes a missing or garbled output. The phase trigger `98f04db16`, run through the real derivation and the real step, takes this path.

## What changed

**ci.yml `sql-mutation`**
- **The scope step.** Its name matches the plan byte for byte, which plan 05 needs because it excludes the step by name. It has `id: scope`, and its `env:` takes `SQL_GATE_MODE` / `SQL_GATE_REASON` / `SQL_GATE_FILES` from `needs.changed-paths.outputs.*`. The body runs under `set -euo pipefail`, and every read uses `${VAR:-}`, so an unset mode boots the lane instead of crashing.
  - `none` + push + main + reason + no files: print both lines, then write `skip_lane=true`, then exit 0.
  - `none` on any other event or ref: a `::warning::` naming the event and ref, then `skip_lane=false`.
  - `none` + push + main with a blank reason, or with gate files named: `MEASURE_FAIL`, exit 1.
  - Every other mode: `scope verdict from changed-paths: sql_gate_mode=<mode>; the lane boots.`, then `skip_lane=false`.
- **The gating.** Exactly `if: steps.scope.outputs.skip_lane != 'true'` sits on the line after `- name:` on all eight later steps: pg_cron, dblink probe, binaries probe, dead-holder drill, meta-command preflight, runner self-test, mutate, assert. Checkout, setup-node and the scope step carry no `if:`.
- A dated comment above the step covers D-09 and its founder-override status, the fail-safe direction, and why the condition is step-level rather than job-level.
- A dated `⚠️ CORRECTED 2026-10-03, Phase 164.9.6 D-09` note sits in the job header's "no `if:`" paragraph.
- There is still exactly one job-level `if:`, `timeout-minutes: 20` is unchanged, and the aggregator tolerance is unchanged.

**src/__tests__/sql-mutation-scope-step.test.ts (new, 20 tests)**
- It extracts the real `run: |` body by step name, using a throwing anchor helper, and runs it under bash with an explicit env and a temp `GITHUB_OUTPUT`.
- It covers every `<behavior>` row, plus a whitespace-only reason and a garbled mode (`None`).
- Calibration A (event test removed) makes the pull_request row write `skip_lane=true`. Calibration B (ref test removed) does the same for the feature-x row. Each sits beside a control row run on the real body.
- **The gating pin** is `gatingViolations(ciText)`. Calibration C deletes the `if:` from the self-test step, and the pin names that step with `has: none`. Calibration D flips the mutate step to `== 'false'`, and the pin names it.
- **End to end.** The block copies the checkout's `sql-gate-subset.mjs` and `classify-changed-paths.mjs` into a detached scratch worktree at each sha. It runs the derivation as a push to main, with `PUSH_BEFORE_SHA=<sha>^1`, and feeds the three parsed outputs into the scope body.
  - Worktrees are removed in `finally`.
  - The leftover check builds its prefix with `realpathSync(tmpdir())`. On macOS `tmpdir()` is a symlink, so a prefix built without the realpath could never match. The check is calibrated by asserting that the live worktree IS visible under that prefix.

## Deviations from Plan

1. **[Rule 3] HOME was dropped from the spawn env.** The first draft passed `PATH` and `HOME`. The env-manifest contract (`every literal process.env read in src/ is documented or allowlisted`) went red on `HOME`, and the plan forbids a new key read. bash needs neither key, so `PATH` alone is passed. The derivation spawn copies `process.env` by iteration and drops every `GITHUB_*`, `SQL_GATE_*` and `PUSH_*` key, so it reads no new literal key.
2. **[Rule 2] Extra rows** beyond `<behavior>`: a whitespace-only reason, a garbled mode, an ordering check that `scope: NONE` prints before `scope-reason:`, and a control row inside each of calibrations A and B.
