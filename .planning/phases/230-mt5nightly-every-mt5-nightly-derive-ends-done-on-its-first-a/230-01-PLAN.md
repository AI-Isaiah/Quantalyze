## Interface contract (plans 02, 04 and 07 build against exactly this)

- Table `public.mt5_terminal_leases`: `terminal_digest text PRIMARY KEY`, `owner_token uuid NULL`,
  `holder text NOT NULL`, `site text NOT NULL`, `acquired_at timestamptz NOT NULL`,
  `expires_at timestamptz NOT NULL`. No foreign key, no user column. Free means
  `owner_token IS NULL OR expires_at <= now()`.
- `public.acquire_mt5_terminal_lease(p_terminal_digest text, p_owner_token uuid, p_holder text, p_site text, p_ttl_s integer) RETURNS boolean`
- `public.renew_mt5_terminal_lease(p_terminal_digest text, p_owner_token uuid, p_ttl_s integer) RETURNS boolean`
- `public.release_mt5_terminal_lease(p_terminal_digest text, p_owner_token uuid) RETURNS boolean`
- Bad input raises SQLSTATE 22023 (`invalid_parameter_value`). The expiry clock is the database's
  `now()`; no client clock is ever written.

## Decisions this plan records

- **DEC-01-A Release kills the token.** Release sets `owner_token = NULL, expires_at = now()` and keeps
  the row, so the last holder stays readable and cardinality stays one row per terminal. A renew that
  lands after the release can never match (RESEARCH Pitfall 1).
- **DEC-01-B Same-token acquire is idempotent.** A retried acquire whose answer was lost succeeds, which
  is what lets plan 02 retry and clean up a late-landing grant (RESEARCH Pitfall 2).
- **DEC-01-C One statement under the row lock.** Acquire is one `INSERT ... ON CONFLICT (terminal_digest)
  DO UPDATE ... WHERE <free or same token>` with `GET DIAGNOSTICS` row count = 1; a concurrent first
  insert blocks on the unique index and re-evaluates the WHERE on the committed row.
- **DEC-01-D Rejected:** a session advisory lock (PostgREST gives no session that spans a hold); moving
  MT5 holdings polls onto the backfill worker and moving the holdings cron (both rejected by the founder
  in D-01); a `cron` schedule for pruning (the table holds one row per terminal and needs none).
