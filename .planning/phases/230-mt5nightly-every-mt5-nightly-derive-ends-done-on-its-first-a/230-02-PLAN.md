## Interface contract (from plan 01; build the backend against exactly this)

`acquire_mt5_terminal_lease(p_terminal_digest text, p_owner_token uuid, p_holder text, p_site text, p_ttl_s integer)`,
`renew_mt5_terminal_lease(p_terminal_digest text, p_owner_token uuid, p_ttl_s integer)`,
`release_mt5_terminal_lease(p_terminal_digest text, p_owner_token uuid)`, all `RETURNS boolean`. Free means
the owner token is NULL or expired on the database clock; a same-token acquire is idempotent; release clears
the token; renew matches the token regardless of expiry. `FakeXLeaseBackend` implements exactly these rules.

## Decisions this plan records

- **DEC-02-A The database release runs INSIDE the local hold, in a nested try/finally.** Order in the
  `finally`: stop renewing (synchronous `task.cancel()`), bump the epoch, end the holder stamp, end occupancy,
  then `try: await hold.release()` / `finally: lock.release()`, then the holder read with no `await` between
  it and `lock.release()`, then the handover record. ⚠️ Rule 7: RESEARCH Pattern 1 releases the database row
  AFTER the local lock to avoid stranding the lock on cancellation. The nested `finally` already guarantees
  `lock.release()` on cancellation, and releasing the row first means an in-process successor never meets
  its own predecessor's row. That keeps `mt5_xlease_waited` a clean cross-process signal, which the seven
  nights rely on (plan 09). Research's order would log false cross-process waits on every in-process
  handover. The cost is at most one bounded RPC added to the local hold.
- **DEC-02-B `mt5_xlease` is a leaf with its own exceptions.** It raises `XLeaseBoundExpired` and
  `XLeaseUnavailable` (plain `Exception`, fixed text). `mt5_terminal_lease` translates them into
  `Mt5TerminalBusyError` and the new `Mt5TerminalLeaseUnavailableError(Mt5TerminalBusyError)`, because
  `mt5_concurrency` imports `mt5_xlease` and the reverse import would be a cycle.
- **DEC-02-C The self-fence is a callback.** `mt5_terminal_lease` passes `on_lost` (a closure calling
  `bump_mt5_terminal_epoch(terminal_key)`), so `mt5_xlease` never imports or re-exports the epoch registry
  (`test_the_epoch_registry_is_not_re_exported_anywhere` stays green).
- **DEC-02-D Digest.** `sha256("mt5-terminal-lease/v1\x00" + terminal_key.strip().lower())`, hex, 64 chars.
  Lower-casing applies to the digest only, never to the in-process registry key.
- **DEC-02-E Timing constants** (plain `Final`, no env override, the 227 pattern):
  `_MT5_XLEASE_TTL_S = 90.0`, `_MT5_XLEASE_RENEW_INTERVAL_S = 20.0`, `_MT5_XLEASE_RPC_TIMEOUT_S = 15.0`,
  `_MT5_XLEASE_POLL_S = 0.5`, `_MT5_XLEASE_POLL_JITTER_S = 0.25`, and the derived
  `_MT5_XLEASE_LOST_AFTER_S = TTL - RENEW_INTERVAL` (70 s). They are validated at import:
  `0 < poll < renew < ttl`, `rpc_timeout < renew`, `ttl >= 2 * renew + rpc_timeout`.
