<domain>
## Phase Boundary

A shared-TEST restore rebuilds its reference rows in the state PROD holds them. The reference-data
replay (`scripts/extract-reference-inserts.mjs`, allowlist `scripts/restore-test-refdata-allowlist.txt`)
also replays a migration's top-level literal `UPDATE` when it targets a `public` table the replay has
just filled. Those tables are empty after `DROP SCHEMA public CASCADE`, so such an UPDATE can reach
only rows the replay itself wrote.

Locked by the ROADMAP `### Phase 164.9.2` block (founder decision 2026-09-24, "Yes, new phase"):
1. A new, separately pinned extractor class for top-level UPDATEs on a `public` table already in the
   replay; never `auth.*`. Own criterion id, pinned counts, audit census, red+green self-test arms.
2. Replayed statements interleave in migration filename order, inside the same transaction as the
   INSERTs.
3. The wrong-state check and its `verified` default stay exactly as they are: no waiver, no relaxed
   default, no widened allowlist.
4. A green `mode=preflight` run, then a green `mode=restore` run on shared TEST, both recorded by
   run id. That closes Phase 164.9 criterion 8.

Rejected (locked): hand-seeding the value after the replay; editing the applied teaser migration.
</domain>

<decisions>
## Implementation Decisions

### Orchestrator decisions on the research's open questions (2026-09-24)

- **D-01: the wrong-state RAISE keeps its check and its `verified` expectation unchanged.** The
  `v_wrong_state` predicate, the four `REFDATA_WRONGSTATE_*` seams and their defaults, and arms 31/32
  stay byte-identical. ONLY the explanatory clause of the RAISE message that becomes false once
  UPDATEs replay ("The replay reproduces INSERT effects only … an UPDATE is not a literal INSERT (C2)")
  is corrected, as a dated correction naming C5. Every substring arm 31 greps for
  (`WRONG STATE after the replay`, and the `public.fx_keep.status for id=2` detail the leg prints) is
  kept.
  **Why:** criterion 3 forbids weakening the check. A message that tells the next reader the gap is
  "not closable by editing the allowlist" after C5 has closed it is a false sentence inside a gate,
  which this repo treats as a defect. Correcting prose is not relaxing a predicate, and keeping the
  greps' substrings keeps arm 31's evidence intact.

- **D-02: the two non-literal UPDATEs (`20260521190243_canonicalize_supported_exchanges.sql` and
  `20260530120000_admin_role_mutate.sql`) are `decline:<n>` lines, each named with a written reason,
  never silently skipped.**
  **Why:** a hard refusal would turn `--audit` red on today's corpus, and a silent skip would carry
  over the INSERT side's known limitation (an unlisted non-literal is invisible). A named decline is
  counted in the C5 census every run and refused if the statement ever turns literal.

- **D-03: both workflows (`ci.yml` job `sql-gate-lint`, and `test-restore-from-baseline.yml`) assert
  the new C5 census line beside the existing audit OK line, which stays byte-stable.**
  **Why:** "could not measure is never a pass" is the idiom both workflows already use for the first
  census line. A C5 class whose census no workflow reads is a class nothing notices disappearing.

### Recorded assumption

- **D-A1 (research assumption A1): shared TEST's restore session runs as `postgres`**, so
  `prevent_profile_privileged_change` (trigger `profiles_lock_privileged_cols`) admits the replayed
  `manager_status` UPDATE. This is not measurable from the repo. It is measured by the post-merge
  `mode=preflight` run: a `42501` there aborts and rolls back (safe), and turns the follow-up into a
  role question, not a classifier question.

### Claude's Discretion (choices made at planning)

- **Criterion id `C5`** ("TOP-LEVEL LITERAL UPDATE ON A REPLAYED PUBLIC TABLE"), in the same
  allowlist file and the same classifier module as C1-C4 (RESEARCH Pattern 1). No second allowlist.
- **Line shape:** 4 TAB fields unchanged; field 3 is `<n>` (INSERT, unchanged), `update:<n>` (C5
  replay) or `decline:<n>` (C5 accounted-for, not replayed).
- **Trailers:** UPDATE blocks carry `-- refdata-update: <file>:<line> <table>`. They never emit
  `-- refdata:` or `-- refdata-expect:` trailers, so the restore's count floor stays INSERT-only
  (RESEARCH Pitfall 2).
- **Emit order:** every block sorted by (migration basename, byte offset of its first token).
- **Census line (exact text, pinned by both workflows):**
  `extract-reference-inserts audit C5 OK: <u> update statement(s) over <uf> file(s) and <ut> table(s) replayed; <d> declined over <df> file(s); 0 unaccounted.`
- **`ENTRY_COUNT` split in two:** `ENTRY_COUNT` keeps its meaning (INSERT entries, 22) and a new
  `C5_ENTRY_COUNT` pins the C5 lines (6 = 4 `update:` + 2 `decline:`).
- **Membership** ("an `update:`/`decline:` line must name a table some INSERT entry fills") is
  enforced in `--audit` only, never in emit (RESEARCH Pitfall 6).
- **Criterion 4 is an orchestrator post-merge step**, never an executor task. The founder authorized
  that dispatch for this occasion.
- **Added 2026-09-25 after the plan-checker's first pass:**
  - **`REFDATA_ENTRY_N` counts INSERT-class lines only** (W6). Its restore note ("… allowlist
    line(s) …, each with a pinned statement count") stays true and keeps reading 22 (fixture 1). The
    ZERO-entries refusal also fires on an allowlist holding only C5 lines, because such a file
    replays no row the count floor can measure.
  - **Zero C5 statements on `auth.*` is by design** (I1). Parse refuses any non-`public` C5 line,
    and the audit's accounting covers `auth.users` because an INSERT entry fills it. So a future
    UPDATE there has no line that can account for it, and is refused.
  - **Duplicate C5 lines are refused** (I2): at most one `update:` and one `decline:` line per
    (file, table). One of each is legal, because a file can hold a literal and a joined UPDATE on
    the same table.
  - **The vitest pins stay in plan 01** (W7 considered and declined). Adding C5 lines turns today's
    `refdata-allowlist.test.ts` red, so the class and its pins must land in the same wave.
  - **Record landing path** (W5): `[164.8.1-REPLAY-INSERT-ONLY-SCOPE]` closes in the phase PR. The
    criterion-4 run ids, the ROADMAP criterion-8 block, `164.9-11-SUMMARY.md` and the CLAUDE.md
    currency correction land in a follow-up docs PR after the dispatch, with a VERSION patch bump
    and a CHANGELOG entry.
