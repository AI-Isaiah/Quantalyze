Method: `grep -ar` over the named trees (excluding `__pycache__`, which holds git-ignored bytecode), each hit read and classified. Branch taken: **`census: no-reader`**.

Why no hit is a `screen-reader`:

1. The only `src` code that returns or renders a snapshot is `src/app/api/verify-strategy/[id]/status/route.ts` (returns `metrics_snapshot` as `results` only when `resolved.public_token` matches the `token` parameter by `safeCompare`), the teaser POST `src/app/api/verify-strategy/route.ts` (which passes the upstream snapshot through `sanitizeMetricsSnapshot`), and `VerificationSection.tsx` / `VerificationResults.tsx` (which render `results.twr` / `results.sharpe` of that status response).
2. `public_token` has exactly one minting site: `src/app/api/verify-strategy/route.ts` (the `public_token: publicToken` write, flow `teaser`). No migration sets it; the `verification_requests` view is `WHERE flow_type = teaser`.
3. The long-fetch flows are `onboard` and `resync` (`_is_long_fetch` in `routers/process_key.py`); `teaser` runs inline, where `enriched_metrics_snapshot` pre-nulls the four keys (Phase 105.1-01 D1). 4. `process_key`'s `.select("*")` duplicate-session replies (`_wizard_duplicate_reply`) return only `verification_id`, `status`, `trust_tier`; the admin CSV status page selects named columns without `metrics_snapshot`; the public trust-signal reads select `trust_tier` and `status` only.
