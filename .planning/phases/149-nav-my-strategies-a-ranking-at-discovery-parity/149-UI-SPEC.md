# Phase 149 — UI Design Contract

> Visual and interaction contract for NAV-01: the "My Strategies" ranking at discovery
> parity. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PARITY IS THE CONTRACT.** The surface is the EXISTING `StrategyTable`
> (`src/components/strategy/StrategyTable.tsx`, 915 lines) rendered the way
> `src/app/(dashboard)/discovery/[slug]/page.tsx` renders it. This spec cites the
> inherited anatomy once, then specs ONLY the four deltas. Anything not listed as a
> delta is inherited byte-unchanged — a redesigned column, a new sort affordance, or a
> re-derived rank presentation is a spec violation, not initiative.

**Props recipe for this surface** (parity minus watchlist):
pass `strategies` (own set via the parameterized predicate), `categorySlug` (page-scope
key), `portfolioId` (Simulate Impact parity), `percentiles` (from unchanged
`getPercentiles()`). **Omit `userId`/`initialWatchedSet`** → the table renders the
`/browse` variant: no star column, no watchlist scope tabs (`StrategyTable.tsx:122-128`).
Rationale: watchlisting is a third-party-discovery affordance; starring your own upload
is meaningless. Everything else renders identically.

**⚠️ `#n` is positional, NOT re-derived.** The leading `#n` is the component's row index
within the displayed set under the active sort — on this page that is rank *among your
own rows*. Do NOT build a second "#n within the published universe" computation; the
published-universe comparison is carried by the percentile suffix + the labeled
comparison-set line (Delta 2). Locked by CONTEXT ("no second percentile mechanism") and
SC-3 (no second ranking implementation).

## The four deltas

### Delta 1 — Sidebar entry (MY WORKSPACE)

`src/components/layout/Sidebar.tsx` — inside the `showsAllocatorWorkspace` branch
(`Sidebar.tsx:103-142`), so it never leaks to a manager-only session (T-110-16 class).

| Property | Value |
|----------|-------|
| Label | `My Strategies` — title case, matching siblings "My Allocation" / "Add a Strategy" |
| Position | Directly ABOVE the "Add a Strategy" action item — read-your-strategies sits beside the write CTA the founder pointed at; "Add a Strategy" stays last in the group |
| Icon | `BarChartIcon` (existing, used by the manager "Strategies" entry — different label, different branch; collision for `role='both'` accounts is acceptable and disambiguated by label) |
| Href | The new route (recommended `/my-strategies` under `(dashboard)/` — final path is planner discretion per CONTEXT). A real `href`, NOT an `action` — this is a page, not an overlay |
| Type/active state | Standard light-rail conventions, inherited from the existing `NavItem` renderer: DM Sans medium label, `text-accent` on active route, no new styling |

Section heading "MY WORKSPACE" (uppercase Geist Mono, tracked) — untouched.

### Delta 2 — Page shell: title + labeled comparison-set line

Route is auth-gated exactly as discovery (`discovery/[slug]/page.tsx:20-22` — no user →
`redirect("/login")`), and role-gated to the allocator workspace the sidebar entry lives in.

Structure, top to bottom, inside `mx-auto max-w-[1920px]`:

1. **`PageHeader` title:** `My Strategies` (existing `PageHeader` component — Instrument
   Serif `--text-page-title`, unchanged primitive). No Breadcrumb (this is a top-level
   workspace page, not a category under Discovery).
2. **Comparison-set line** — the honest-set label, REQUIRED by CONTEXT. Directly below
   the header, `mb-6` (24px) before the table.
   - Anatomy: `<p data-testid="comparison-set-note" className="mb-6 text-small text-text-secondary">`.
     DM Sans regular — this is reading prose, not a data eyebrow; no mono, no accent, no
     semantic color.
   - Copy when `getPercentiles()` returned a map (N = the actual size of the published
     population the map was computed over — the real number, never hardcoded):
     > `Ranked against {N} published strategies. # is the row's position in this list; Pnn compares the row against those {N} published strategies. Private and draft rows are visible only to you and do not affect public rankings.`

   **Focal point:** the ranking TABLE is the page's visual anchor — title and comparison-set line are subordinate; nothing else on the page may compete with the table for visual weight.
   - Copy when `getPercentiles()` returned null (population < 5 — its min-5 rule):
     > `Percentile ranks appear once 5 strategies are published in the comparison set. Private and draft rows are visible only to you.`
     (States the limitation with the threshold attached — DESIGN.md Voice rule. No
     suffixes render in this state, which is the component's inherited behavior.)
3. **The `StrategyTable`** per the props recipe above — or the page-level empty state
   (Copywriting Contract) when the own set has zero rows.

### Delta 3 — Status marker on non-published own rows

`withPublishedOrOwner` admits ALL own statuses (`draft | pending_review | private |
archived` + published). Absence of publication is a fact, not an error — **muted, never
red, never amber** (DESIGN.md semantic-color gates; same reasoning as 148's banner:
publication is admin-gated, the owner has no one-click remedy, so amber would falsely
promise one).

| Property | Value |
|----------|-------|
| Primitive | Existing `Badge type="status"` (`src/components/ui/Badge.tsx`) — `inline-flex items-center rounded-md px-2 py-0.5 text-caption font-medium`. Do NOT invent a new chip |
| Required token delta | Add `private` to `statusMap` → `bg-badge-other/10 text-text-muted` (the `archived` muted-ink pairing) and to `statusLabelMap` → `Private`. Today an unmapped `private` silently falls back to draft styling with a raw lowercase label (`Badge.tsx:46,49`) — that fallback rendering is a defect, not acceptable output |
| Existing mappings reused | `draft` → "Draft", `pending_review` → "Pending Review", `archived` → "Archived" — unchanged |
| Placement | Name cell, first line, after the strategy name link (the same slot the api-verified check occupies at `StrategyTable.tsx:734`; the exact idiom of `StrategyGrid.tsx:84`'s "Example" chip) |
| Render rule | `status !== 'published'` only. **Published own rows carry NO marker** — they render byte-identical to their discovery presentation. Absence of a marker = published; a "Published" chip would be noise |

### Delta 4 — Honest pending state (never zeros)

Family precedent: Phase 147's two-state `series_state` idiom (147-UI-SPEC §chips;
mapping helper `deriveEmptySeriesState`, `src/lib/closed-sets.ts:491`). A fresh key
syncs ~10–15 min before analytics exist — those rows appear immediately, honestly.

| State (from `computation_status` via the 147 mapping) | Chip label | Chip classes (exact 147 chips) | Metric cells |
|---|---|---|---|
| `pending` / `computing` / no analytics row (bounded per closed-sets rule) | `Syncing` | `text-warning bg-warning-bg border border-warning-border` | em-dash `—`, untinted (inherited formatter behavior) |
| terminal (`complete*` / `failed`) with no usable series | `No data` | `text-text-muted bg-track` | em-dash `—`, untinted |

- Chip anatomy matches 147 BASE VERBATIM: `inline-flex items-center rounded-sm px-2
  py-0.5 text-fixed-11 font-medium uppercase tracking-wide` (rounded-sm = 4px, the 147
  literal). DELIBERATE: the adjacent status Badge is `rounded-md` (6px) — the 4px/6px
  difference between the two chip families is accepted; they encode different semantics
  (publication status vs data state) and both radii are established members of the
  DESIGN.md ladder. Do NOT harmonize.
- The `Syncing` chip carries the note via BOTH `title="First metrics arrive in ~10–15 min"`
  AND `aria-label="Syncing — first metrics arrive in ~10–15 min"` (not title-only — AT
  reads the full copy). A visible per-row note line is deliberately omitted: it would break
  row-height parity with the discovery table (the parity contract outranks the 147
  scenario-composer precedent, whose rows are not height-locked).
- Placement: name cell, second line, in the `SyncBadge` slot — `SyncBadge` already
  returns null for a null `computed_at` (`SyncBadge.tsx:28`), so the chip occupies the
  empty slot with no collision. Rows with computed analytics keep `SyncBadge` and get no chip.
- Amber is correct for `Syncing` (transient, the system recovers it on its own —
  DESIGN.md 2026-04-11/2026-07-02); muted for terminal `No data`; **red is forbidden**
  for both (absence ≠ error).
- Percentile suffix: naturally absent — an uncomputed/unpublished row is not in the
  `getPercentiles()` map, and the component renders no suffix for a missing entry
  (`StrategyTable.tsx:473-481`). Zero code needed; assert it, don't reimplement it.
- **Never render `0`, `0.00`, or `+0.0%` for an uncomputed metric** — the em-dash rule
  is load-bearing (Numbers Contract; no-invented-data / SC-4).
