## Deviations from Plan

1. **[Measured, not a gap] `no_house_credentials` cannot be reached through the heal.**
   - `_read_credentials` returns `None` when `MT5_LOGIN` or `MT5_PASSWORD` is unset, and the heal returns before the lease or any client. `_heal_blocking` types `login` and `password` as non-optional.
   - The gate therefore asserts the heal-level fact (no construction, nothing crosses) and drives `_escalate_ipc_fault` directly for the kind.
   - The kind is defence in depth for a direct caller, such as plan 05's reuse. It is not dead code.
2. **[Measured] Row hygiene on `ipc_fault` paths is an empty-store assertion.**
   - The first reading is `ipc_fault`, which classifies `not_measured`. `record_mt5_session_reading` writes nothing for it, and the escalation kind never reaches a row.
   - A first draft asserted the rows were non-empty, and that vacuity guard bit.
   - So the gates run the REAL recorder (`_capture_and_record_outcomes`) and assert `sink.rows == []`, after a field-by-field scan. A future write path on this tick would be named, not silently passed.
3. **[Rule 2, scope] Extra arms and gates beyond the bullets:**
   - a rotation-only arm, so the `saved_password` knob is load-bearing rather than masked by `saved_house_password_stale`;
   - a disconnected degraded arm;
   - the still-faulted-after-settle arm, read from the bullet "not authorized when the settle window passes";
   - the ledger-reader self-test, so the pin cannot pass forever on a regex that never matches.
4. **[Process]** Task 1's `<verify>` command (`.venv/bin/python` relative to `analytics-service`) was run with the main checkout's interpreter, as the dispatch instructed. The worktree has no venv.

No production file changed. `TODOS.md` was not changed (the 0 branch). STATE.md and ROADMAP.md were not touched.
