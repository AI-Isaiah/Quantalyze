<objective>
Close the two windows in which the jobs terminal could be left account-less with nothing acting on it.
(1) Inside this process: a scrub whose credentialed relaunch did not verify leaves relaunch debt, and
the next tick pays it before anything else. (2) Across a process restart: the in-process debt is gone,
and the founder's D-09 widens the boot heal to relaunch with credentials on the account-less
signature.

Purpose: criterion 3 ("no scrub path can leave the jobs terminal logged out") and the boot half of
criterion 4.

Decision 4 (stated): D-09 is a SEPARATE boot-only branch for code `0`. Its `-10005` half needs no
code, because S-10 measured that the account-less signature with the client's 20 s timeout is
`-10005`, which already escalates, and the escalation is now scrub plus credentialed relaunch (plan 03).
The escalation code gate and its pin test stay byte-identical.

Decision 5 (stated): a debt relaunch does not count against `IPC_FAULT_RECYCLE_CAP`. It ends no
process; the cap exists to stop repeated terminates of the shared terminal.

Founder decision (stated): the debt branch sends a credential on a reading that used to send
none, including from the session monitor. That widening of 164.6.2's "credentials only on -6" rule
is CONTEXT D-10, decided by the founder on 2026-10-04 ("Yes, pay debt on any tick"), beside D-09's
boot case. Task 1 asserts the D-10 line before it runs.

Test-double discipline: this plan appends test functions to `tests/test_mt5_relogin.py` and changes
no existing double knob or default, because plan 05 imports those doubles in the same wave. A new
knob, if one is needed, is a new keyword whose default keeps the current behaviour.

Spec-less probe: no requirement IDs, so no edge probe ran. The edges come from RESEARCH Pitfall 1 and
CONTEXT D-09 / S-10.
