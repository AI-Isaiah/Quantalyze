<objective>
DBACC-01 half (a), builder side: the factsheet payload builder reads `strategy_analytics.metrics_json_by_basis` as a pinned set of 21 named aliases instead of the whole column, and a test fails when the projection grows a key.

**Ships in PR-A.** TypeScript only; no database object is created or required. Plan 04 moves the OG route onto the same fragment. Plan 09 (PR-B) then revokes anon's SELECT on the column.

Decisions implemented (CONTEXT cited by heading and date; it has no D-NN ids):
- CONTEXT `### DBACC-01: anon metric reads` (2026-11-26), half (a): "The payload builder's embed projects `metrics_json_by_basis` as a pinned set of named `->` aliases, and a test FAILS when a key outside the pinned alias set appears in the projection." This is ROADMAP SC-1's wording.
- CONTEXT `### Decided autonomously` [DBACC-01]: "named aliases in the existing embed, matching how `metrics_json` is already projected", and "an exact-set test over the parsed select string that fails on an extra or missing key, beside the existing bare-`metrics_json` ban".
- Same section: "The alias shape follows the column's real nesting". RESEARCH `### Minimal alias set and rebuild rule` derived 3 bases x 7 `BASIS_KPI_MAP` server keys = 21 from the writer and every TS consumer. The orchestrator's PROD read Q5 confirmed the keys; Q6 found 0 rows on the one divergent edge.
- `### Claude's Discretion`: module and alias names. Alias form: `by_basis_<basis>_<serverKey>:metrics_json_by_basis-><basis>-><serverKey>`.

Deviation from RESEARCH and PATTERNS, recorded: they prescribe tightening the bare-column ban to a regex that also matches every correct alias, because the `_by_basis->` suffix is not `->`. A node check at plan time confirmed it rejects `by_basis_cash_settlement_sharpe:metrics_json_by_basis->cash_settlement->sharpe`. This plan uses `/metrics_json(?!->|_by_basis->)/` instead. It refuses a bare `metrics_json` and a bare `metrics_json_by_basis`, and accepts every `->` path of either column.

Purpose: SC-1. Whatever the analytics writer adds to a basis object (whole series arrays today) never reaches a reader of this payload without a reviewed edit to the pinned list.
Output: the projection module, its pin and parity tests, a test-side seeding helper, the builder on the fragment, and every builder-fake test seeding the alias shape.
</objective>
