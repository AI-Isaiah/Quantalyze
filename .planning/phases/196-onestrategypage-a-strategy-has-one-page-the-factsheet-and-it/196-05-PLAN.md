<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session cookie → `getUser()` | server-validated identity; never a URL value |
| per-request viewer → shared `unstable_cache` payload | a viewer field crossing here would be served to every later reader |
| `profiles` read → action set | role and approval decide which affordances render |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-196-10 | Information disclosure | `page.tsx` viewer resolution vs `unstable_cache` | high | mitigate | viewer resolved after the probe and passed as render props; tests assert cache args and payload carry no user, role or owner; the public-cache-key and owner-lane suites stay green; neuter evidence on lane order |
| T-196-11 | Elevation of privilege | `ViewerBar` actions | low | mitigate | affordance only: `/api/intro` and `/allocations` keep their own server checks; the bar fails closed on a profile read error |
| T-196-13 | Information disclosure | note read in `page.tsx` | medium | mitigate | read filtered by the server-validated `user.id`, RLS on `user_notes` unchanged; card omitted on read error so no empty card can overwrite a saved note |
| T-196-14 | Spoofing | owner check | medium | mitigate | `isOwner` compares the server-validated user id to the strategy's `user_id` from the server read; no client value is consulted |
| T-196-SC | Tampering | npm/pip/cargo installs | low | accept | no package installs in this plan |
