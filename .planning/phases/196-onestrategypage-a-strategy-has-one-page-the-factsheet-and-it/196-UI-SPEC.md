## Route Contract (LEAN-02, D-03)

One page: `/factsheet/[id]`. Every other strategy detail route leads to it.

| Old route | Behaviour | Destination |
|-----------|-----------|-------------|
| `/strategy/[id]` | permanent redirect (308) | `/factsheet/[id]` (origin unknown) |
| `/strategy/[id]/v2` | permanent redirect (308) | `/factsheet/[id]` (origin unknown) |
| `/discovery/[slug]/[strategyId]` | permanent redirect (308) | `/factsheet/[strategyId]?from=discovery&cat=[slug]` |
| `/browse/[slug]/[strategyId]` | permanent redirect (308) | `/factsheet/[strategyId]?from=browse&cat=[slug]` |
| `/factsheet/[id]/tearsheet` | stays; becomes the factsheet's print view (below) | — |
| `/factsheet-share/[token]` | stays its own route (D-05) | — |
| `/factsheet/[id]/v2` | **[derived]** unchanged (it IS the factsheet; `/factsheet/[id]` re-exports it) | — |

Redirect rules:
- **Unconditional and DB-free.** A redirect never reads the strategy, so it reveals nothing about whether an id exists or is published. The destination decides visibility (published → render; unpublished → owner lane or not-found, unchanged).
- **Query string preserved.** An old shared URL with `?share=1` lands on `/factsheet/[id]?share=1&…`.
- **[derived] Mechanism:** config-level `redirects()` in `next.config.ts` with `permanent: true`, the same mechanism Phase 195 used for `/portfolios/:path*`. It runs before the proxy session gate, so an anonymous visitor on an old `/discovery/...` link reaches the public factsheet instead of the login bounce. Planner verifies both facts (308 status, ordering before `src/proxy.ts`, destination-query param mapping) against `node_modules/next/dist/docs/` before relying on them.
- `src/lib/routing/route-contract-manifest.ts` rows for the four old routes are updated in the same change.
- Every in-app link that today targets an old route (e.g. `OutcomesWidget`, admin `csv-status`, `VerificationResults` linking `/strategy/<id>`) is repointed to `/factsheet/<id>` with its origin (table below), so no in-app click pays a redirect.

## Back Link Contract (D-01)

The origin travels as **query parameters on the link into the factsheet** **[derived]**: `from`
from a closed set, plus `cat` for the category surfaces. The back link's label and `href` are looked
up from that closed set. **The raw parameter value is never used as an `href`** (no open redirect);
an unknown `from`, or a `cat` outside `DISCOVERY_CATEGORIES`, is treated as no origin.

| `from` | Label | `href` | Set by (link sites, re-resolve by symbol) |
|--------|-------|--------|-------------------------------------------|
| `discovery` (+ `cat`) | Back to Discovery | `/discovery/[cat]` (no valid `cat` → default authenticated route) | `StrategyTable` on `/discovery/[slug]`; the discovery redirect |
| `browse` (+ `cat`) | Back to Browse | `/browse/[cat]` (no valid `cat` → `/browse`) | `StrategyTable` on `/browse/[slug]`; the browse redirect |
| `allocations` | Back to My allocation | `/allocations` | `HoldingsTable`, `WatchlistPanel`, `ScenarioComposer`, `OutcomesWidget`, `PortfolioOptimizer` |
| `my-strategies` | Back to My Strategies | `/my-strategies` | `MyStrategiesSection` table; the wizard's `SyncPreviewStep` / `CsvSubmitStep` factsheet links |
| `strategies` | Back to Strategies | `/strategies` | `StrategyTable` on `/strategies` |
| `recommendations` | Back to Recommendations | `/recommendations` | recommendations page "view" link |
| `admin` | Back to Admin | `/admin` | `AdminTabs`, admin `csv-status` |

- `StrategyTable` is shared by four surfaces, so it takes the origin from its mount (a prop), never by sniffing the path.
- Labels mirror the current sidebar names (`Sidebar.tsx`). They live in ONE map, so Phase 201 renames change one place.
- **No origin** (bookmark, pasted URL, external link, the two `/strategy/...` redirects): the link reads **"Back"** and calls `history.back()` when the document has a same-origin referrer. - The `from` / `cat` parameters stay in the URL; "Copy share link" builds its URL from the path, so they never ride into a shared link.

removed.
