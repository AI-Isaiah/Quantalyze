# Phase 167.2.1.1.2.1 Plan 03: Bybit 729-day window and the midnight-edge refusal Summary

**An account holding a Bybit key now starts its rebuild window at the first whole UTC day Bybit still serves (729 days back, `window_days` still 730), and a Bybit crawl that would ask for a start older than two years because the UTC day rolled over mid-job is refused before any trade request, never clamped, with no new refusal token.**

## What changed

- `services/equity_reconstruction.py`: `BYBIT_TRADE_TERMINUS_DAYS = 730` beside `OKX_TRADE_TERMINUS_DAYS`; `_bybit_window_start(end_date)` (`end_date - 729 days`, docstring carries the RESEARCH Q3 arithmetic); `_account_rebuild_window` returns `(_bybit_window_start(end), 730)` when any selected key is Bybit and no key is OKX (OKX's 89-day window still wins; mt5, binance and the rest keep 730 back); the unforced branch of `run_reconstruct_allocator_history_job` uses `_bybit_window_start` for `venue == "bybit"`. `BACKFILL_CAP_DAYS` stays 730 and the `reconstruct_started` audit field is untouched. `_fetch_bybit_trades` refuses (one static WARNING with venue and the start's age in whole days, then `ccxt.BadRequest`) when `since_ms < now_ms - 730 days`, before its first request.
- `tests/_trade_pages.py`: `VenueTradeBook(..., two_year_limit_now=)` (zero-argument callable returning the current UTC instant in ms); a Bybit request whose start is older than that minus 730 days raises `ccxt.BadRequest` and is not recorded. Default off, so plan 01 and 02 tests are unchanged.
- `tests/test_bybit_two_year_window.py` (new, 9 tests): the pure window rule (six venue combinations), the constants, the mid-morning tracer, the unforced start (parametrized bybit 729, binance 730), the forced midnight crossing, the unforced midnight crossing, the in-day crawl, and the 15-token pin.

## Deviations from Plan

None that change scope. Choices made inside the plan:

1. **Rejected requests are not recorded on `VenueTradeBook.calls`.** A request the fake rejects with `BadRequest` returns no rows; the "zero trade requests" assertions use the `AsyncMock` `await_count`, which counts the attempt, and the tracer's start check reads the recorded (accepted) requests.
2. **Limit-enforcing books reuse the existing trades.** `_enforce_two_year_limit` in the new test file swaps an exchange's `fetch_my_trades` for a new `VenueTradeBook` over the same trade list (read from the existing book's `.trades`) and the frozen clock, so `_bybit_exchange` and `_sibling_bybit_exchange` stay the shared fixtures.
3. **Constants sentinel test added** (`test_the_window_constants_are_the_ones_the_rule_names`) beyond the plan's list: pins `BACKFILL_CAP_DAYS == 730`, `BYBIT_TRADE_TERMINUS_DAYS == 730` and the helper's arithmetic.
4. **Guard comparison is strict (`<`)**: a start exactly 730 days before `now_ms` is allowed, matching the fake. How Bybit itself measures the boundary remains RESEARCH A4 (assumed); 729 back from UTC midnight is inside both readings, and plan 06 re-checks live.
5. **Branch namespace.** The worktree branch is `feat/167.2.1.1.2.1-p03`, not `agent-*`; treated as the orchestrator-assigned sequential case, as in plans 01 and 02. It is not a protected branch.
