## Narrative Findings (AI reviewer)

No CRITICAL, HIGH or MEDIUM finding.

### LOW-01: when the BOOK's own join is short, every candidate's admin line blames the candidate-vs-book overlap

**File:** `analytics-service/services/match_engine.py:684-723`; `src/components/admin/CandidateDetail.tsx:124-131`
**Evidence:** `port_df` is the book's own `.dropna()` join, and `overlap_days` is that join
intersected with the candidate. Take a book whose join is, for example, 12 days (D-22's
`book_join_too_short`). Every candidate then gets `fit_unavailable_reason: "overlap_below_min"`
with `fit_overlap_days <= 12`, and CandidateDetail reads "only 12 shared days with the book".
The sentence is literally true. But the real cause is the book, which is named only in
`match_batches.holding_flags`, and CandidateDetail does not read that. An admin could take it
for a short candidate history.
**Fix (optional; booking is enough):** have the router (which already computes `shared_days`
for `book_join_marker`) or CandidateDetail's parent pass a book-short flag, and render
"the book's own holdings share only N days" when the book marker is present. Alternatively, in
the engine, set a different reason (`book_join_below_min`) when `len(port_df) < PORTFOLIO_FIT_MIN_OVERLAP_DAYS`.

### LOW-02: the no-returns candidate path still nulls the fit silently (out of GAP-01 scope)

**File:** `analytics-service/services/match_engine.py:1056-1065`, `:681-682`
**Evidence:** a candidate whose `daily_returns_from_row` is None never enters `returns_by_id`.
`cand_returns is None` then sends it to the bare `_empty_pf_components()`: null fit, portfolio
bar at 0, no reason key. An empty candidate series does the same at `:681`. GAP-01's wording and
its PROD reading cover only the short-overlap branch, so this is not a gap in plan 10. It is the
same "null with no reason" class, though.
**Fix:** book it rather than fix it here. When it is taken up, the fix is the same pattern: in
the `else` at `:1065`, set `fit_unavailable_reason = "candidate_returns_absent"` when
`mode == "personalized"` and the book series is non-empty, and add one TS sentence.

### LOW-03: arm A's "reasons stay clean" oracle is a substring check

**File:** `analytics-service/tests/test_match_candidate_fit_overlap_marker.py:104-107`
**Evidence:** the assertion rejects only `"shared day"` and `"overlap"`. A future reason that
leaks the cause in other words (for example "only 8 days alongside your book") would pass.
**Fix:** compare the reasons against the computed path directly. For example, assert
`_generate_reasons(cand, prefs, breakdown_without_fit_keys, mode) == reasons`, or assert that
no reason contains `str(raw["fit_overlap_days"])`.

### INFO-01: `feedback_engine.py:88` restates another module's version

`# match_engine.ENGINE_VERSION's convention (currently "v2.4.0")` has to move on every engine
bump. That is the restated-constant drift class CLAUDE.md warns about. Consider dropping the
"currently" value.

### INFO-02: `_empty_pf_components` / `_compute_portfolio_fit_components` now return `dict[str, float | int | str | None]`

The wider union means `sharpe_lift` etc. are now typed as possibly `str`. The values reach
`raw_components: list[dict[str, Any]]`, which hides this from mypy. A `TypedDict(total=False)`
for the components would keep the numeric keys typed as `Optional[float]`.

### INFO-03: CHANGELOG / VERSION still describe the v2.3.0 ship

This is correct for a plan (the ship step owns them). The release entry for this gap-closure
must name `ENGINE_VERSION v2.3.0 -> v2.4.0`, and the PROD rescore it triggers for every allocator
on the first cron tick.
