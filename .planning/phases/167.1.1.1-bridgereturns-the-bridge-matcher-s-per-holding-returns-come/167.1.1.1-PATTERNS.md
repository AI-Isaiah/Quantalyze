`written_at_micros` (lines 410-447) is the integer-micros instant parser. Never use `datetime.fromisoformat` (more lenient than the TS twin, would diverge on the shared fixture).

**Per-day pick (copy this logic from TS `dailyMarkPrices`, lines 261-287):**

```ts
const best = new Map<string, { price: number; at: number; keyId: string }>();
for (const r of rows) {
  const m = r.mark_price as number;
  if (!(m > 0)) continue;                       // non-positive mark is a GAP, skipped BEFORE the pick
  const at = writtenAtMicros(r.updated_at);
  const cur = best.get(r.asof);
  if (cur === undefined || at > cur.at ||
      (at === cur.at && r.api_key_id.toLowerCase() < cur.keyId.toLowerCase())) {
    best.set(r.asof, { price: m, at, keyId: r.api_key_id });
  }
}
```

Python equivalent uses `(-written_at_micros(updated_at), api_key_id.lower())` as the sort key, the same trick as `one_key_per_account_day` (lines 486-489):

```python
winner[holding_type] = min(
    (key_id for type_, key_id in instants if type_ == holding_type),
    key=lambda k: (-instants[(holding_type, k)], k.lower()),
)
```

**Contract check (copy from `HoldingMarkContractError`, TS lines 229-268):** every row is checked first. A `mark_price` that is not a finite number (reject `bool` explicitly, since `isinstance(True, int)` is True), or an `asof` not `YYYY-MM-DD`, or a derivative `side` outside {long, short, flat} raises a contract error carrying COUNTS only, never a row value. A non-positive finite mark is a gap, not an error. ISO day regex: `^\d{4}-\d{2}-\d{2}$` (TS line 240).

**Adjacency (copy from TS `isNextDay`, lines 289-292):** a return exists only between exactly adjacent UTC calendar days. Use `date.fromisoformat(b) - date.fromisoformat(a) == timedelta(days=1)` (the module already imports `date, timedelta` in `allocator_equity_derive.py`, line 80).

**Series contract (do not violate):** returns are a `pd.Series` indexed by bare `YYYY-MM-DD` strings keyed by the LATER day of each interval, named with the pseudo id. NEVER a `DatetimeIndex`. The repo guard is `allocator_equity_derive._assert_iso_day_index` (line 213); `analytics-service/tests/e2_fixtures.py` shows the string index convention.

**Withheld ladder (RESEARCH Pattern 2; order matters, mirror `fetchHoldingCompareItem`):**
1. Spot only: `account_balance` (venue not in `CRYPTO_VENUES`), then `fixed_price` (venue `sfox` or `symbol.upper() in STABLECOINS`), without reading marks. Mirrors TS `holdingWithheldReason` lines 150-162.
2. Derivative option (`classify_instrument(symbol) == "option"`): `option_premium` (D-10).
3. No day with a finite mark `> 0`: `no_price`.
4. Derivative with priced days but none with an established direction: `no_direction`.
5. Usable days `< MIN_PRICED_DAYS (30)`: `too_few_priced_days`.
6. Otherwise eligible.

**Signed return (RESEARCH Q4; D-12):** `r_i = s_{i-1} * (p_i / p_{i-1} - 1)`, `s` = +1 long, -1 short, floored at `-1.0`. Day i-1's direction governs the interval. Spot uses `s = +1` always, and a `flat` spot row is NOT a gap. A derivative day whose rows carry `flat` or both sides is a gap. Direction on day d = the single value in {long, short} shared by ALL rows of that day (all keys, including rows whose mark is a gap). Direction comes only from `side`, never from `quantity` or `value_usd`.

**Census warning:** the census test (`src/__tests__/holding-scope-key-census.test.ts`, matchers M4/M8/M11) walks `analytics-service/**/*.py` outside tests. Do NOT build `f"holding:{...}"`, `(venue, symbol, ...)` tuples, or a `venue:symbol` f-string in this module; take the already-built key as a parameter. If one is unavoidable, add a `CLASSIFICATION` entry in the same commit.
