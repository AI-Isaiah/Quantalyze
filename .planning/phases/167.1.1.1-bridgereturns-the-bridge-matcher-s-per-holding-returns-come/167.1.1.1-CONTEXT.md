<domain>
## Phase Boundary

The Bridge matcher's per-holding returns (`_load_holding_portfolio_context` in
`analytics-service/routers/match.py`, today fed by `reconstruct_symbol_returns` in
`analytics-service/services/equity_reconstruction.py`) come from each holding's daily mark
price, so buying, selling or moving an asset never reads as a gain or loss. A holding the price
rule cannot price is withheld from the per-holding returns signal by name, never zero-filled. The
TypeScript rule (`src/app/(dashboard)/compare/lib/holding-compare-adapter.ts`) and the Python rule
agree on one shared fixture.

Founder decision Q2 widens the boundary. Derivatives get a signed mark-price return, negated for
shorts by each day's stored direction. This applies on both sides: the matcher, and `/compare`'s
derivative path, which moves from "rebuilding" to the same signed rule.

Owns TODOS `[167.1.1-BRIDGE-DOLLAR-RATIO-RETURNS]`. Booked by founder decision 167.1.1 D-06.

## Implementation Decisions

### Withheld holdings in the book (founder, 2026-10-15, AskUserQuestion: "Stays in AUM/weights (Recommended)")
- **D-01:** A withheld holding stays in AUM, weights and the max-weight test. Only its returns
  leave the correlation-ceiling test and the portfolio-return context, and its holding_flags entry
  names the reason.
  - Evidence (PROD, read-only, marker = PRODUCTION, 2026-10-15): the latest
    `match_batches.holding_flags` per allocator holds 7 entries, 6 of them stablecoins and none
    flagged. Dropping withheld holdings from the AUM would raise every other holding's weight.

### Derivatives: signed basis (founder, 2026-10-15, AskUserQuestion: "Build long/short now")
- **D-02:** The founder's words: "Build long/short now: flip the price series for shorts, using
  each position's direction per day. This is the correct end state, but /compare must change to
  match, which roughly doubles this phase."
  - Derivatives use the signed mark-price return, negated for shorts by each day's direction.
  - `/compare`'s derivative path moves from "rebuilding" to the same signed rule.
  - Both sides stay under the SC3 shared fixture.
  - Any derivative day whose direction cannot be established from stored data is withheld by
    name. Never guess a sign, and never zero-fill.
  - ⛔ **SUPERSEDES 167.1.1 D-03's "Derivative holdings stay `"rebuilding"` until a signed basis is
    defined"** for `/compare`. The signed basis is defined here. 167.1.1's CONTEXT is kept as
    lineage and is not edited.
- **Direction source, measured on PROD 2026-10-15 (read-only, marker = PRODUCTION, last 730 days),
  before planning, as the coordinator required:**
  - `allocator_holdings.side` is `text NOT NULL`, CHECK in (`long`, `short`, `flat`), one value
    per row, and a row is one (allocator, venue, symbol, asof, api_key_id). Derivative rows carry
    only `long` and `short`: bybit 4996 / 7551, deribit 1378 / 2486, okx 192 / 168. No
    derivative row is `flat`. Spot rows are all `flat`.
  - `quantity` is never negative (all derivative rows have `quantity > 0`), and `value_usd` is
    never negative. So `side` is the ONLY stored direction: a sign must come from `side`, never
    from the quantity or the value.
  - Of 16 771 derivative holding-days, 0 carry both sides on one day, whether across keys or
    within one key. Of 1503 derivative holdings, 471 changed side at some point in the window, so
    the direction must be read per day and not once per holding.
  - Deribit derivative marks contain 109 rows with `mark_price <= 0`. These are gaps under D-03.
  - ⚠️ For the researcher, NOT decided here: 384 of the derivative symbols are Deribit options
    (`BTC-10OCT26-81000-P` shape, 3693 rows). Their mark is an option premium, and the premium's
    unit (USD or the coin) is not measured. The researcher must establish the unit, and whether a
    signed premium-return is what D-02 intends for options, before planning. If it is unclear,
    this goes back to the founder as a question. It is not something to decide silently.

### The shared rule (founder, 2026-10-15, AskUserQuestion: "Adopt the TS rule (Recommended)")
- **D-03:** Python adopts the TypeScript rule as written:
  - One mark per day, from the row with the latest `updated_at`, ties to the smallest lowercase
    `api_key_id`.
  - A non-positive mark is a gap.
  - Returns are taken only between adjacent calendar days.
  - A holding needs at least 30 priced days, or it is withheld as `too_few_priced_days`.
  - One JSON fixture is replayed by vitest and pytest.

### Where "named" lands and the PROD reading (founder, 2026-10-15, AskUserQuestion: "In holding_flags, cron read (Recommended)")
- **D-04:** Each withheld holding gets a `holding_flags` JSONB entry with `withheld_reason` and
  `flagged: false`. No migration and no UI change.
  - The before reading is taken before merge. The after reading is taken after the first
    scheduled cron recompute after deploy. There is no forced recompute.
  - Both readings are read-only and run the marker query first.
