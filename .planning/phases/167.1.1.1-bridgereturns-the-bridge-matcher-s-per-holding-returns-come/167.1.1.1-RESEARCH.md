## Summary

The Bridge matcher's per-holding return series today comes from `reconstruct_symbol_returns` (`analytics-service/services/equity_reconstruction.py:4439`), a `pct_change` over `allocator_equity_snapshots.breakdown[symbol]` dollars, keyed by bare symbol. That is the defect: a purchase reads as a gain. Its only production caller is `routers/match.py:786` inside `_load_holding_portfolio_context`; everything else is tests. The fix is a pure Python twin of the TypeScript price rule (`dailyMarkPrices` / adjacent-day returns in `holding-compare-adapter.ts`) fed by ONE paginated, capped history read of `allocator_holdings` per allocator, grouped by `(venue, symbol, holding_type)` (D-08). `services/allocator_equity_derive.py` already has the Python twins the rule needs (`written_at_micros`, `one_key_per_account_day`, `account_identity_tokens`), and a precedent for cross-runtime shared JSON exists (`analytics-service/tests/fixtures/*.json`, read by vitest through `process.cwd()` and by pytest through `Path(__file__).parent`).

**Three findings change the plan, and one of them is a founder question the orchestrator must take before the matcher half of D-02 is planned:**

1. **Window collapse (BLOCKING for the matcher half of D-02).** `score_candidates`, `_compute_portfolio_fit_components` and `compute_holding_flags` all inner-join the holdings' return series with `pd.DataFrame(...).dropna()`. Admitting derivative series under D-02 shrinks the common window: a PROD simulation (current book, any-row positive mark, no direction filter) gives allocators with 25-26 eligible holdings a **common adjacent-day window of 0-2 days**, against 141-171 days for the spot-only book today (and the engine needs 30, `min_overlap_days=30`). Four of seven PROD allocators would lose the portfolio-fit axis. The spot half of the phase is safe on the same data. See Open founder question OQ-2.
2. **Options are not settleable by code+data alone, but the evidence points one way.** The option `mark_price` IS a USD price of one contract (premium, converted coin to USD at the index by the writer), so the unit question is settled; whether a signed premium return is "the holding's return" is a modelling intent question. PROD premium series have daily sd of 11-65% with a +376% day, only 9 of 384 option symbols ever reach 30 priced days, and a short's signed return would fall below -100%. Recommendation: withhold as `option_premium` (the UI-SPEC default). See OQ-1.
3. **D-01 + D-02 together put derivative NOTIONAL into the matcher AUM.** Today derivatives are dropped by the accident of the breakdown lookup (PROD `holding_flags` holds 7 entries, all spot), so AUM excludes them. After this phase every collapsed holding is in AUM (D-01) at `value_usd`, which for derivatives is notional. Measured scale (per-key newest-day sums, order of magnitude): derivative notional is about 50-390% of spot value per allocator. This moves `add_weight = ticket / portfolio_aum` and every weight. See OQ-3 (acknowledgement, not a blocker).

**Primary recommendation:** Build a pure `analytics-service/services/holding_marks.py` (daily mark pick, direction per day, adjacent signed returns, withheld classifier), replay one shared fixture `analytics-service/tests/fixtures/holding_mark_returns_cases.json` from vitest and pytest, replace Step 3-4 of `_load_holding_portfolio_context` with one `paginated_select` history read that raises `HoldingsReadTruncated`, keep withheld holdings out of `portfolio_strategies`/`portfolio_returns` but in AUM/weights and in `holding_flags` (`flagged: false`), and bump `ENGINE_VERSION` so the next hourly cron tick produces the SC4 "after" batch. Take OQ-1, OQ-2 and OQ-3 to the founder before planning the derivative-in-book wave.

### Pattern 1: one pure rule, two runtimes, one oracle
Both runtimes expose the same pure core over raw rows `{asof, mark_price, side, updated_at, api_key_id}` plus `(venue, symbol, holding_type)`; I/O (paging, RLS vs service role) stays outside. The fixture asserts the core's outputs: `withheld` reason or null, `priced_days`, and the **adjacent-day signed return list** `[[asof, r], ...]`. TS additionally asserts its four metrics from the same rows. Spot is the special case "direction = long on every day".

### Pattern 2: the withheld ladder (order matters, mirrors `fetchHoldingCompareItem`)
1. `holding_type` neither spot nor derivative: TS returns null (unchanged); Python cannot see it (DB CHECK `allocator_holdings_holding_type_check`).
2. **Spot only**: `account_balance` (venue not a crypto exchange) then `fixed_price` (sfox or stablecoin symbol), without reading marks. A derivative must never be routed through this function (UI-SPEC State F note).
3. Derivative option (if OQ-1 = withhold): `option_premium`.
4. No day with a finite mark `> 0`: `no_price`.
5. Derivative, priced days exist but none has an established direction: `no_direction`.
6. Usable days `< 30`: `too_few_priced_days` (Python: withheld entry; TS: `"ready"` with four null metrics and `priced_days`, per UI-SPEC State R0/RD0).
7. Otherwise eligible.

The strings `fixed_price`, `account_balance`, `no_price` exist today; `too_few_priced_days` is D-03's name; `no_direction` and `option_premium` are the UI-SPEC's recommended strings. [CITED: 167.1.1.1-CONTEXT.md D-03; 167.1.1.1-UI-SPEC.md State ND / OP]

### Anti-Patterns to Avoid
- **Reading direction from `quantity` or `value_usd`.** Both are never negative (CONTEXT D-02 measurement); only `side` carries direction.
- **Zero-filling a gap or a withheld holding's returns** into the book (D-02/D-03). Absent is absent.
- **Putting withheld holdings into `portfolio_strategies`.** It flips `mode` to `"personalized"` with an empty returns book (`match_engine.score_candidates:878`) and changes the rescore preflight gate (`job_worker.py` `if ctx.get("portfolio_strategies")`). Keep them out; put them in weights/AUM only.
- **Keying anything by bare symbol** (the old `breakdown` merge). D-08.
- **Using a `DatetimeIndex`.** The repo's series contract is bare `YYYY-MM-DD` string labels (`allocator_equity_derive._assert_iso_day_index`, `tests/e2_fixtures.py`).

### Q1. Deribit options and instrument classes (BLOCKING for D-02 scope: answered, with one residual founder question)

**What the writer stores for a Deribit option** [VERIFIED: analytics-service/services/positions.py:181-193]:
```
    if option_style:
        # Options: `size` is the base-ccy contract count; mark/average are the
        # per-contract PREMIUM (in the coin for inverse, in USDC for linear).
        ...
        px_to_usd = rate if coin_settled else 1.0
        entry_price = average_price * px_to_usd
        mark_price_usd = mark_price * px_to_usd
        size_base = abs(size)
        size_usd = abs(size) * mark_price_usd
```

`_fetch_derivative_rows` stores `quantity = size_base`, `value_usd = size_usd`, `mark_price = mark_price` [VERIFIED: allocator_positions.py:709-727, `"quantity": qty,` `"value_usd": float(s.get("size_usd") or 0),` `"mark_price": float(s.get("mark_price") or 0),`]. So for an option: `mark_price` is **USD per contract** (coin premium x index for coin-settled, USDC premium for linear), `quantity` is the contract count, `value_usd = quantity x mark_price`. Measured on PROD: the longest-lived option holding's rows (quantity 1.0, `side` long) show `value_usd / quantity == mark_price` on every day, with marks in the hundreds of USD that fall steadily towards expiry. The unit question is therefore **settled: USD per contract**.

**Is a signed premium return "the holding's return"? Not settleable from code + data; evidence for withholding:**
- A premium is not a notional. For a short option the capital at risk is margin, not premium; `-(p_t/p_{t-1} - 1)` has no denominator that is the position's capital. For a long option it is the return on the premium paid (meaningful).
- The USD premium of a coin-settled option = coin premium x index, so the series carries the underlying's move on top of the option's own repricing.
- PROD (all allocators, last 730 days), Deribit options: 3693 rows, 384 symbols, **109 rows with `mark_price <= 0` (all of the 109 are options)**. Only **9 of 384 option symbols have >= 30 priced days** (max 56). For those 9 the adjacent-day premium return has daily sd 0.109-0.651, worst day -0.938, best day +3.759. A short's signed return on a +376% day is -376%.
- Therefore: withhold options as `option_premium`. 375 of 384 would be `too_few_priced_days` anyway; the 9 survivors would produce series where compounding is meaningless (NAV below zero for a short). This is the UI-SPEC default. **OQ-1 asks the founder to confirm or override.** Detection is by name (`classify_instrument(symbol) == "option"`, i.e. ends `-C`/`-P`) on both sides; the TS twin must be added and pinned by the fixture.

### Q4. The signed-return rule

**Recommended rule (planner states and tests it; founder's "by each day's direction" governs):** the return of the interval (i-1 -> i) carries **day i-1's direction**.
- Rationale: the row on day i-1 is the position the account carried into the interval. Day i's rule would credit a position opened on day i with the move it did not hold (the exact "trading reads as return" defect); a position closed on day i (no row, no mark) drops that last interval (conservative, nothing invented).
- Interval exists only when both endpoints are adjacent calendar days AND both are usable (positive mark; for a derivative also an established direction). This is the UI-SPEC rule "a priced day with no established direction is a gap like a missing day".
- `r_i = s_{i-1} x (p_i / p_{i-1} - 1)`, `s` = +1 long, -1 short. Spot uses `s = +1` always (its rows are all `flat`; a `flat` spot row is NOT a gap).
- **Cumulative return and max drawdown for a derivative:** compound the signed adjacent-day returns into an NAV path starting at 1 (`NAV_k = prod(1 + r_i)`), cumulative = `NAV_last - 1`, max drawdown = most negative `(NAV - peak) / peak`. Vol and Sharpe use the same return list (`dispersion(returns, 0).sd x sqrt(365)`, `returnStatsSharpe` with `ddof: 0`), exactly as spot does.
- **Relation to spot's form:** spot keeps `last/first - 1` and a running-peak drawdown over the PRICE LEVEL (spans gaps; shipped, unchanged per UI-SPEC). For a long-only derivative with no gaps the compounded form telescopes to the level form, so a fixture case asserts **long-only, gap-free derivative metrics == spot level metrics** (an independent invariant). With gaps they differ: the compounded form drops a move across a missing day, so **the UI-SPEC gap sentence ("A price move across a missing day is not counted.") must render for derivatives**, and the plan must record that it chose this rule.
- **A short is not the negation of the long's cumulative return.** Worked example (hand-checkable): prices 100, 110, 100 -> long returns +0.10 and -1/11 (NAV 1.10 x 0.90909 = 1.0, cumulative 0); short returns -0.10 and +1/11 (NAV 0.9 x 1.09091 = 0.98182, cumulative -1.818%). The caption claims only "gain while long, loss while short", which stays true.
- **Wipe-out edge (real on PROD):** 6 non-option adjacent-day moves of +100% or more exist (e.g. a one-day spike 0.0796 -> 0.4503 -> 0.1293 on a small-cap perp). A short over such an interval has `1 + r <= 0`: NAV <= 0. The plan must pin a rule; recommended: floor each signed interval return at -1 (a daily-rebalanced short loses at most its notional; NAV 0 is a liquidation), keep the returns list as floored, and add a fixture case. Longs cannot reach -100% (the mark is `> 0`).

## Common Pitfalls

### Pitfall 1: the inner-join window collapse (measured)
**What goes wrong:** Every derivative with its own lifetime and gaps shrinks `pd.DataFrame(portfolio_returns).dropna()` to the days ALL series share. **Measured (PROD, current book approximated by each key's newest day, positive-mark day = any row with mark `> 0`, adjacency from those days, direction ignored, options/stablecoins/MT5 excluded, eligible = >= 30 priced days):**

| Allocator (rank) | Book holdings | Eligible (all types) | Common adjacent-day window | Eligible spot only | Spot-only common window |
|---|---|---|---|---|---|
| 1 | 3 | 2 | 69 | 1 | 141 |
| 2 | 61 | 25 | **0** | 1 | 25 |
| 3 | 52 | 0 | 0 | 0 | 0 |
| 4 | 48 | 26 | **2** | 1 | 169 |
| 5 | 48 | 25 | **2** | 1 | 141 |
| 6 | 55 | 26 | **2** | 1 | 171 |
| 7 | 13 | 1 | 68 | 0 | 0 |

Derivative holdings that reach 30 priced days still have large gaps (up to 75 missing days inside their span; no eligible derivative is contiguous), and even spot holdings miss up to 4 days. **Why it matters:** `align_current_and_proposed(..., min_overlap_days=30)` then reports insufficient overlap, so the portfolio-fit axis (the comment in `match_engine` calls it 40% of the score) is None for those allocators, and `compute_holding_flags`'s `rest_df = pd.concat(...).dropna()` empties, so no correlation-ceiling breach can fire. **How to avoid:** needs a founder decision (OQ-2); do not "fix" it by zero-filling. **Warning sign:** `common window < 30` in a unit test fed with a PROD-shaped book.

### Pitfall 2: derivative notional enters AUM
`value_usd` is notional for derivatives (`size_usd = abs(size)` or `positionValue`), not equity. Per-key newest-day sums (before the account rule; order of magnitude only): allocator ranks 1-7 derivative / spot value ≈ 0.7, 0.6, 1.2, 0.6, 0.5, 0.6, 3.9. With D-01 all of it is in `portfolio_aum`, `weights`, and `add_weight`. Acknowledge via OQ-3.

### Pitfall 3: `bool` is an `int` in Python
`isinstance(True, int)` is True; the TS contract check rejects non-numbers. Reject `bool` explicitly in the mark contract check.

### Pitfall 4: tie-break on a lowercase key, instants in integer micros
Use `written_at_micros` (not float seconds, not `fromisoformat`) and `api_key_id.lower()` for the tie; otherwise the shared fixture diverges between runtimes.

### Pitfall 5: a pandas series with the wrong index
A `DatetimeIndex` stringifies to `'YYYY-MM-DD 00:00:00'` and silently misaligns against strategy series; use bare ISO-day strings and a name of the pseudo id.

### Pitfall 6: wipe-out interval for a short
See Q4. Without a floor, NAV goes negative, max drawdown passes -100%, and the compounded cumulative return is meaningless.

### Pitfall 7: tests that stub `get_supabase` have no `.range()` / `.gte()` and one `.order()` slot
`tests/test_match_portfolio_aum_per_key.py` `_Query` supports `select/eq/in_/order/limit` only and `order` overwrites the previous call. Extend the fake (range, gte, multi-order, `max_rows`) or build one shared fake; the existing autouse `_warm_series` shortcut is replaced by history rows.

### Pitfall 8: service-role read without the tenant filter
The Python read uses the service role. Omitting `.eq("allocator_id", ...)` reads every tenant. Pin with a test that inspects the recorded filters (the `_Db.reads` pattern in the existing fake).

### Pitfall 9: a cap that quietly truncates
`paginated_select` returns partial data only below its page cap; the new wrapper must convert `PaginatedSelectTruncated` to `HoldingsReadTruncated`, and a test must feed `alwaysFullPage`-style infinite pages to prove it raises (the TS stub already has `alwaysFullPage`).

### Pitfall 10: counting `holding:` shapes
The census (see Project Constraints) fails on a new f-string or tuple; classify in the same commit.
