- `_load_holding_portfolio_context` Step 3 is ONE `paginated_select` of `allocator_holdings` (`asof, venue, symbol, holding_type, side, mark_price, updated_at, api_key_id`), `.eq("allocator_id", ...)`, `.gte("asof", _holdings_history_window_start())` (730 days), ordered `(asof, id)`, 1000-row pages, 50-page ceiling. - Step 4: rows are grouped per `(venue, symbol, holding_type)` (D-08) for the holdings that survived the account rule; each spot holding goes through `classify_spot_marks`. A priced holding gets a float `pd.Series` indexed by the bare later-day strings and named by its pseudo id. A withheld one is appended (with `withheld_reason`) to `holdings_rows_withheld`, counted in one INFO line per allocator (counts per reason only), and keeps its value in the AUM and weights (D-01).
- `_load_allocator_context` adds withheld spot to the combined renormalisation and the equal-weight fallback and returns `_holdings_rows_withheld`.
- `HoldingMarkContractError` and `HoldingsUpdatedAtError` are not caught anywhere in the matcher. They reach the recompute handler: 500 `SCORING_FAILED` with a correlation id, proved once through the real route with the real scorer.
- Neighbours moved to the new read inside this plan: the AUM per-key file (history in the fixture helper, no assertion edited), the router warm-up arm (D-01 meaning), the phase09 integration file and the score golden (both onto `FakeDb`).

## Deviations from Plan

- **[Rule 3 - fixture mechanism]** The plan says the per-key file's `_holding` / `_ctx` builder expands each holding into 41 days. `_holding` returns one dict that tests place in lists, so the expansion happens in `_ctx` (`_with_history`), driven by a private `_history_days` key on the row (default 41). The bulk rows in the two 1000-row-cap tests opt out with `history_days=1` so they do not multiply to 49,000 rows. No assertion in that file changed except the one the plan named (`test_every_holdings_read_is_owner_filtered_and_scoped_to_one_key`, rewritten on `db.read_log`). The dead `_warm_series` autouse patch stays in that file and in the native-unpriced file for plan 09 to remove.
- `test_match_portfolio_aum_native_unpriced.py` needed no edit: its MT5 and USDT holdings are withheld spot, which D-01 keeps in the AUM and weights, so its existing assertions hold unchanged.
- `test_maybe_single_none_guards.py` and `test_wealth_returns_router_method.py` needed no change (green on the new read).
- The generic worktree branch allow-list (`agent-*` namespace) of the commit protocol was not applied: the dispatch fixed the branch as `feat/167.1.1.1-p04` and asked for that name to be verified before each commit, which was done.
- The census pin for `match.py` M8 moved from 1 to 2 (the `marks_by_ref` grouping tuple), symbols and reason updated in the same commit as the site. M4 stayed at 4: the withheld weights reuse the existing f-string site by looping over eligible plus withheld rows.
