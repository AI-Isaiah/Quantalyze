# 167.1.1.1 BRIDGERETURNS - silent-failure review, round 2

Scope: source diff bdca59921..HEAD excluding .planning, with emphasis on fix commits 5aab1256c,
a82156f8b, 8bef9e2a2, 577ce672d (analytics-service/routers/match.py).

## SFH-01 resolved

- `compute_holding_flags` (match.py, `aum = ... if portfolio_aum and float(portfolio_aum) > 0 else None`)
  writes `weight: None` for every spot entry, priced and withheld, when the AUM is not positive. No
  0.0 remains on that path. `breach_skipped: ["aum_not_positive"]` is added to each spot entry when a
  `max_weight` preference made the test due (`max_weight_skipped`). A NaN AUM also lands on None.
- `_load_allocator_context` logs the WARNING `aum_not_positive` (allocator id) when
  `combined_aum <= 0` and any holding row exists, and passes `portfolio_aum=None`.
- The equal-weight invention from a non-positive AUM is gone: the scoring denominator no longer
  depends on the AUM sign. The only equal-weight path left is a scoring set whose values sum to
  nothing, and it logs `scoring_weights_equal_fallback`. It predates the phase.
- Derivative entries keep `weight: None` and a null contribution when no P&L exists; no 0.0.

## New-failure sweep of the fixes, no MEDIUM or above

- **Marker skip paths.** `book_join_marker` is appended in `_score_one_allocator` after
  `compute_holding_flags`, on the same code path every caller uses (cron, recompute route, job worker
  rescore). It returns None only for an empty `portfolio_returns` (no join exists) or a join of 30
  days or more. It joins the same converted dict and the same `pd.DataFrame(...).dropna()` the engine
  joins (match_engine.py), so marker and engine agree, including the all-empty-series case, which
  gives `shared_days` 0 and a marker. A pandas error in the join would also fail the engine call
  before it, loudly.
- **No exception swallowed** in the new code. The read-contract errors still propagate.
- **No holding vanishes unnamed.** The marker withholds nothing. Eligible, withheld and derivative
  holdings each get exactly one entry, and the book entry is extra.
- **Consumers of `holding_flags`.** Grep across src, analytics-service, supabase and docs: the only
  reader is `src/lib/queries.ts` (`rawFlags`, filtered by `f.flagged && f.top_candidate_strategy_id`
  before `holding_ref.split`). The book entry has `flagged: false` and a null `holding_ref`, so it is
  dropped before the split, and `weight` (now nullable at runtime, typed `number`) is never read.
  `src/lib/admin/match.ts` selects explicit columns without `holding_flags`. The demo route and
  recommendations page do not touch it. No Python or SQL function reads the column.
- **Scoring weights vs AUM share.** Scoring weights use strategy raw values plus priced holdings
  only. The AUM share (withheld spot and derivative P&L in the denominator) feeds only the
  max-weight test and the persisted `weight`. D-21 (tiny positive AUM flags everything, real
  numbers, not null) is pinned by test and accepted.
