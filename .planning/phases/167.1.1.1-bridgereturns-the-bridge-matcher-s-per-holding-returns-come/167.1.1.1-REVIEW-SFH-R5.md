## MEDIUM

### M1. A candidate with NO returns series still gets a null portfolio fit with no named reason

- File: `analytics-service/services/match_engine.py:1056-1065` (the `else: pf_components = _empty_pf_components()`
  branch), also the early returns at `:681-687` (empty candidate series, empty book join).
- Evidence: the branch condition requires `cand_returns is not None`. `routers/match.py:1844-1853` documents that a
  series that cannot be converted (no BTC price source) "is left out, exactly like a strategy with no returns_series",
  so such a candidate reaches `score_candidates` with no entry in `candidate_returns` and is scored (it is eligible).
  Measured at HEAD with one non-flat book and `candidate_returns={}`: `portfolio_fit = 0.0`,
  `sharpe_lift/dd_improvement = None`, `data_completeness = None`, and NO `fit_unavailable_reason` key in `raw`.
- Why it matters: this is the same shape GAP-01 was booked for (null fit, no reason). The admin sees a Portfolio fit bar
  at 0 and no line (`CandidateDetail.tsx:120-132` renders only for `overlap_below_min`), so "candidate has no usable
  returns" is indistinguishable from "scored and fit badly". GAP-01's own comment claims the cause "is persisted", but
  only one of the null-fit causes is named. The `book_join_marker` covers a short BOOK join only, not this candidate-side
  cause.
- Hidden errors: universe load skipped the strategy's series (`routers/match.py:563` writes only when daily returns exist);
  USD conversion dropped an unconvertible native-unit series; an empty `pd.Series` in `candidate_returns`.
- Fix: in `score_candidates`, when personalized and `cand_returns` is None or empty, set
  `fit_unavailable_reason = "no_candidate_returns"` (and the early returns at `:681`/`:687` a matching reason such as
  `"no_book_join"`), persist it via the same conditional write, and widen the UI condition to render a sentence per known
  reason (still nothing for an unknown one). Add a test arm using the already-present `_raw_of(None)` parameter, which no
  test calls today. If the founder scopes GAP-01 to the short-overlap cause only, record the other causes in TODOS.md as an
  explicit deferral instead of leaving the comment's wording implying completeness.
- User impact: admin-only (not allocator-facing), data-integrity of the diagnosis; ranking is unchanged.
