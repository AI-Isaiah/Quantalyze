## Deviations from Plan

### 1. [Rule 1 — bug] Arms D and R as the plan specified them COULD NOT FAIL, and were re-fixtured

- **Found during:** Task 2, designing the twins.
- **Issue:** The plan specifies, for both arms, "writer sentence + markers, then the RPC",
  with a twin that deletes the branch's own unconditional marker clears. Plan 06's
  three-reviewer fix pass — written AFTER this plan — added
  `strategy_analytics_drop_stale_error_provenance_trigger`, a `BEFORE UPDATE` trigger whose
  guard is "the statement CHANGED `computation_error` and did NOT restate the markers".
  Under the twin, branches (a) and (c) blank a NON-NULL sentence with the markers no longer
  in the SET list — which is EXACTLY the trigger's guard. The trigger fires, clears both
  markers, and the arm passes over a deleted fix. Two arms proof-shaped and proof-free.
- **Fix:** Both arms now run over a row **INSERTed** with both markers above a **NULL**
  sentence — the one state the UPDATE-only trigger cannot reach, and a state the pairing
  CHECK admits (both markers present). On such a row the branch writes NULL over NULL, the
  trigger's first conjunct is FALSE, and the branch's own clears are the only mechanism
  left. Measured: both arms now RED under their twins, naming themselves first.
  The reasoning is written into the gate header (`⭐⭐ THE TRIGGER MASKS TWO ARMS`) so the
  fixture cannot be "simplified" back.
- **Files modified:** `supabase/tests/test_sync_status_curated_sentence_survives.sql`
- **Commit:** `19d9de8f`

### 2. [Rule 1 — bug] Six SETUP guards were their own un-twinned SECTIONS

- **Found during:** Task 3, by the full vitest run — `164.4-02: every SECTION an annotated
  file raises for also carries a twin` named all six.
- **Issue:** `sectionOfIdentity` (`run.mjs:2548`,
  `id.replace(/(\d)[a-z]*(-[A-Za-z]+)?$/, "$1")`) collapses a trailing `-SUFFIX` into its
  parent section ONLY when a digit precedes it. Spelled `S-SETUP`, each guard was its own
  section raising `TEST FAILED (…)` with nothing proving it could fail.
- **Fix:** identities carry a digit — `S1` / `S1-SETUP` — so each guard is a SUB-ARM of its
  arm's section, exactly as the sibling gate's `0b`/`0c` are sub-arms of its section `0`.
  The guards stay deliberately un-twinned and the header now says why: they are VACUITY
  guards ("this fixture reached the branch"), not claims about the bridge, and a twin for
  one would have to break PRODUCTION in order to break a FIXTURE. Sections 14 → 8; all
  eight twins re-observed biting under the new identities.
- **Files modified:** `supabase/tests/test_sync_status_curated_sentence_survives.sql`
- **Commit:** `feaaa1a3`
