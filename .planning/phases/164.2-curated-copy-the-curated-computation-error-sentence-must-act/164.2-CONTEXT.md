## Phase Boundary

Every failure sentence a user reads is the true, specific one, addressed to the reader who
actually sees it.

IN scope — two mechanisms, one thesis:

- **(a) The curated sentence survives the write.** `sync_strategy_analytics_status` overwrites
  `strategy_analytics.computation_error` on BOTH branches, so a writer's curated sentence
  ("Insufficient CSV history. At least 2 data points required.") is replaced by a generic
  per-kind sentence seconds later, on every path where a `compute_jobs` row transitions.
  Closing this needs writer/generation PROVENANCE on the column — a SQL-only fix is explicitly
  not accepted, because the column cannot today tell a curated sentence from a stale one. The
  debt is recorded as owed in `20260826120000`'s header and no later migration adds it.
- **(b) Rendered copy stops misattributing.** Four wizard-copy falsehoods, the `code: UNKNOWN`
  class (WIZFORM-02), the raw-code prefix (161-ERRPREFIX), the two freshness bucketers
  (WR-06-UTC), the unproven sync arm (HONEST-08-RESIDUAL), and the developer-facing sentence on
  the anonymous factsheet placeholder.

OUT of scope, named rather than silently dropped:

- The stale-`wizardSessionId` ROOT CAUSE (old criterion 6) is DROPPED by the 2026-09-05
  re-partition: already satisfied. Verify by READING the preselect path; do not re-plan it.
- Whether `Fibonacci Ghost` should be published-but-uncomputed at all. Criterion 9 is COPY only.
- Composite-failure member attribution (Phase 162's open item) — different mechanism.

<decisions>
## Implementation Decisions

### Area 1 — Provenance on `computation_error` (criteria 1, 2)

- **Provenance lives in its own column, not inside the sentence.** Add a dedicated marker column
  to `strategy_analytics` (writer identity + a monotonic generation/job reference). Rejected:
  embedding a JSON envelope in `computation_error` itself — that column renders VERBATIM to the
  account surface (`test_stitch_composite_job.py:558` pins this), so any envelope leaks to users
  the moment one reader forgets to unwrap it.
- **The bridge becomes conditional, not unconditional.** `sync_strategy_analytics_status` may
  write `computation_error` only when the existing value is NULL or carries bridge provenance.
  A writer-provenanced sentence is never overwritten by a per-kind generic.
- **Every Python writer stamps it.** All paths that set `computation_error` — the job worker,
  the derive path, stitch-composite, and the portfolio router — set the marker in the same
  statement. A writer that sets the sentence without the marker is the failure mode to test for.
- **No backfill.** A NULL marker is treated as bridge-provenanced, which reproduces today's
  behaviour exactly for the ~103 legacy PROD rows. Migrating historical rows would be asserting
  provenance we do not have.
- **Criterion 1's proof performs the transition.** The test drives a real `compute_jobs` row
  through the transition and asserts the curated sentence survives. Inspecting the bridge body
  is explicitly not evidence.

### Area 2 — Wizard refusals stop blaming the wrong party (criteria 3, 4, 5)

- **`KEY_MISSING_REQUIRED_FIELD` is fixed at the EMITTER, and a new code is minted.** The fix
  goes in `src/app/api/strategies/create-with-key/route.ts`, whose own guard comment already
  says that arm "may not wear a `KEY_*` verdict that blames a credential". Minting moves
  `EXPECTED_TABLE_SIZE` plus three roster/coverage laws — done deliberately, in the same change,
  not worked around by re-wording the shared member (which is TRUE on the credential arm).
- **`KEY_RATE_LIMIT` splits by SOURCE.** `userActionLimiter`'s 429 gets copy naming our own
  per-user limit; a genuine exchange-side throttle keeps the existing exchange copy. `fix[1]`
  ("try a different exchange account") is removed from the our-limiter arm — it cannot clear a
  per-USER bucket. `route.ts:891` already records this as "our outage, blamed on their exchange".
- **`DRAFT_ALREADY_EXISTS`'s cause is SPLIT, not replaced.** "with the same API key" stays on the
  TOCTOU and credential arms where it is true, and the stale-session path gets a cause naming
  the real collision, `(user_id, wizard_session_id, source)`.
- **WIZFORM-02 closes by a roster-driven test.** One table-driven test over EVERY
  server-classified code the wizard can surface asserts the rendered surface shows THAT code and
  never `code: UNKNOWN`, and is SHOWN to fail when the classification is neutered. Phase 153's
  span verification failed on 2026-08-13 precisely because inspection was accepted; the
  `GATED ON WIZFORM-02 CLOSING` marker in TODOS comes down only when this test exists and has
  been observed red.

### Area 3 — Rendered surfaces (criteria 6, 7, 9)

- **161-ERRPREFIX: prose renders, the code is logged.** `KeyPermissionBadge.tsx` stops
  prefixing the rendered string with `err.code`, and routes the structured code to
  `console.error` and a Sentry breadcrumb, preserving the support-ticket greppability the
  prefix existed for (`:137-138`). This is a CLASS branch — the same site emits
  `PROBE_BACKEND_UNAVAILABLE` and others, so it covers every code, not one string. Two tests:
  one fails when the prefix returns to the render, one fails when the code stops reaching the log.
- **WR-06-UTC: one named constant, imported by both bucketers.** `bucketSeriesAge` in
  `src/lib/freshness.ts` (today: a 5-MINUTE clock-skew allowance) and `bucketByAge` in
  `src/app/factsheet/[id]/v2/FactsheetView.tsx` (today: none) both take a DAY-granularity
  allowance from the same exported constant, imported rather than re-typed — the convention
  `freshness.ts` already states for `CLOCK_SKEW_TOLERANCE_MINUTES`. Both proven, each by a test
  that fails with the allowance removed, plus the single test TODOS asks for: render BOTH
  surfaces from ONE row and assert they agree. Fixing one bucketer manufactures a new
  two-surface contradiction, which is the class this work exists to close.
- **The anonymous factsheet placeholder speaks to its actual reader.** On the anonymous path,
  drop the dev-only instruction ("See the dev-server console for the exact gate…") and the
  internal gate detail (the bundled-benchmark-window sentence). The replacement says the
  factsheet has not been computed yet, without inventing a promise about when. The test binds to
  the ANONYMOUS render — that is the surface where it was measured on PROD at
  `/factsheet/8581f739-1a7b-42a4-a209-3acfa327e259` — and FAILS when the developer-facing
  sentence is restored.

### Area 4 — Proof discipline (criterion 8, and the phase's standard)

- **HONEST-08-RESIDUAL is closed by a rendering test AND a live observation.** The durable proof
  is a test that renders `FreshnessChip` from a row with a FRESH series and a staler sync, and
  asserts the SYNC copy binds — that is what distinguishes correct staler-of-two from "always
  binds to series". A single live PROD observation of such a published row (one exists off the
  `crypto-sma` cohort) is recorded alongside it as the measurement the criterion names, not
  instead of the test.
- **Every anti-vacuity claim in this phase is a NEUTER-AND-OBSERVE, not an inspection.** Each
  test named above is shown RED with its subject neutered and GREEN with it restored, restored
  byte-identically. `git checkout --` is not used for restore in any harness.
- **No criterion is reported closed on the strength of reading the code.** Criteria 1, 3, 6, 7,
  8 and 9 each say so explicitly, and criterion 3 says why: this was believed closed once
  already.

### ⚠️ CORRECTIONS from RESEARCH, 2026-09-06 — these SUPERSEDE the decisions above

The research pass measured the code and refuted four things I asserted while writing this
file. Recorded as corrections rather than silently rewritten, so the planner can see which
decisions were reasoned and which were measured.

1. **The bridge citation above is WRONG.** The latest `sync_strategy_analytics_status` is
   `20260826120000_computation_error_curated_copy.sql:336-905`. `20260826140000` never
   defines the bridge at all. The two overwriting writes are branch (b) `:804-813` and
   (b-prime) `:874-880`.
2. **Branches (a) and (c) write `computation_error` to NULL.** So a conditional bridge must
   CLEAR the provenance marker on those branches too — "only write when NULL or
   bridge-provenanced" is necessary but not sufficient. A marker left standing over a NULLed

3. **There is no trigger.** The bridge is `PERFORM`ed inside `mark_compute_job_failed`
   (`20260529180000:137`) and `mark_compute_job_done` (`20260603120000:439`), plus a Python
   call on DEFERRED. ⭐ So criterion 1's test must call the RPC on the pg-lane —
   `test_sync_status_marked_refresh_protected.sql` is the template. A direct table poke is
   NOT the transition the criterion demands.
4. **`routers/portfolio.py:722-734` must NOT be stamped.** It writes `portfolio_analytics`,
   which has NO bridge (`20260826120000:240`). Stamping it fixes nothing and adds a marker
   no reader consults. The real census is ELEVEN Python `strategy_analytics` failure writers
   (all dict literals, as the JOB-01 AST census requires) plus FOUR TypeScript writers this
   file omitted (`finalize-wizard` ×2, `csv-finalize`, `keys/sync`) — all four pre-enqueue
   and CORRECTLY overwritten by branch (a) when a job starts, so they need no marker either.
   `run_csv_strategy_analytics`, which owns the "Insufficient CSV history" sentence, has no
   `job_id` in scope and needs a keyword-only parameter.
5. **`KEY_RATE_LIMIT` needs no new copy.** `RATE_LIMITED` ALREADY carries honest our-limiter
   copy ("the cap is ours, not your exchange's", `wizardErrors.ts:3326`), pinned by
   `SubmitStep.test.tsx:867`. It simply is not in `KNOWN_CREATE_WITH_KEY_CODES`. The fix is
   WIRING, not authoring — and the class spans FOUR routes behind `userActionLimiter`, not
   one. Fix all four (research's recommendation, adopted).
6. **Minting the preselect code moves FIVE laws, not three** — the union,
   `EXPECTED_TABLE_SIZE` twice in a file carrying a deliberate NUL byte that plain `grep`
   skips silently (use `grep -a`), the divergence test, the roster, and a 400-only derived
   scanner at `expectedSites: 13`.
7. **Two existing tests are load-bearing and must be INVERTED, not deleted.**
   `KeyPermissionBadge.test.tsx:121` PINS the prefix 161-ERRPREFIX removes.
   `SyncBadge.staler-of-two.test.tsx:269` ("an hour ahead is still future") goes RED under a
   day allowance and must become the CONTROL. And `:62` already proves the sync arm binds
   over a fresh series — so HONEST-08-RESIDUAL's missing piece is only the `FreshnessChip`
   twin, which is smaller than this file assumed.
8. **No `addBreadcrumb` exists anywhere in `src/`.** `sentry-capture.ts` is the pattern to
   extend for 161-ERRPREFIX's log half.

⛔ **Mutation-runner coupling is the phase's biggest hazard and is not optional reading.**
