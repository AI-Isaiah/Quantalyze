- `KeyPermissionBadge` throws `new RouteResponseError(message)` with no prefix. A founder with a broken key now reads *"This stored key can no longer be decrypted. Reconnect the key — retrying will not help."* instead of that sentence wearing `KEY_UNDECRYPTABLE: ` in front of it.

## Decisions Made

1. **The class is the route's real six codes, at their real statuses.** The plan named three (`PROBE_BACKEND_UNAVAILABLE @502`, `PROBE_FAILED @503`, `KEY_UNDECRYPTABLE @409`). `must_haves.truths[0]` demands *"EVERY code the route can answer (class, not one string)"*, and `src/lib/probe-vocabulary.invariant.test.ts` already derives that population from the route source and pins it at `EXPECTED_TOTAL_CODES = 6`. So the table covers `CIRCUIT_OPEN @503`, `PROBE_RATE_LIMITED @429`, `KEY_UNDECRYPTABLE @500`, `PROBE_BACKEND_UNAVAILABLE @502`, `PROBE_TIMEOUT @502`, `PROBE_FAILED @502`, with sentences transcribed from that roster.
2. **The breadcrumb takes no per-request `secrets`.** A breadcrumb carries a code and a status, never a credential; `scrubRecord(data, [])` still applies the env-secret list, matching what `captureToSentry` does for its `extra`.
3. **The guard is `typeof err.code === "string" && err.code.length > 0`, not `err.code ?`.** An empty-string code would otherwise fire a breadcrumb whose message is `""` — and `"anything".includes("")` is `true`, the exact vacuity hole `probe-vocabulary.invariant.test.ts` documents one file over. Pinned by the negative-control test.
