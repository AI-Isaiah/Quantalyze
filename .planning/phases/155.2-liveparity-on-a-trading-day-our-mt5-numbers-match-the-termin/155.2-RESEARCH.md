## Summary

Three results shape the whole plan. (1) The parser fix in CONTEXT is a small, local, three-edit change in one module; only one existing test file pins header/footer behaviour (`tests/test_mt5_report_parser.py`, 34 tests, green now) and its `_mutate` helper is hard-wired to the `th`-header line, so the new real-shape test needs its own builder, not a reuse of `_mutate`. (2) **Gate A will not measure on real USD accounts even after the parser is fixed.** `_native_unit_present` in `services/mt5_parity.py` returns true for any mark whose `native_unit` is not NULL, but the marks migration documents that a USD-unit MT5 account stores `native_unit 'USD'`. Every Gate A level, cum_return and day_placement leg then reads `not_measurable:unit_mismatch`. This is exactly what the Phase 155 dress rehearsal printed for all three real accounts, and that record blamed the synthetic oracle, which is wrong (the unit check reads only the capture). The synthetic capture has `native_unit: null`, so no test ever exercised the USD case. Fixing it is an engine edit with a red test, and it must land before the real-file Gate A run. (3) The 29 findings collapse to four root-cause groups, three of which are code-located: a stale `asset_class: "crypto"` literal on every per-key blend leg (the `isCryptoExchange` docstring says "the 'when a non-crypto venue is ever added' future-note is NOW: mt5 is that venue"), an exact-float `===` in the harness's own `cross_store` check against a curve-differenced series, and engine-vs-persisted convention differences (ddof, day basis, 3-decimal rounding, cumulative method). `last_return_date` gaps are a freshness window between two independent pipelines and need a founder named-bucket ruling unless a post-155.1 recapture closes them.

Real-data caveat: nothing under `/.mt5-parity/` was read. Root-cause statements for findings are code-derived hypotheses with a concrete decomposition diagnostic for each; they become facts only when the executor runs that diagnostic on the sealed capture.

## Common Pitfalls

### Pitfall 1: Real Gate A reads `not_measurable` and gets recorded as a finding about the product
**What goes wrong:** the `unit_mismatch` artefact (sec. 2) makes four of five legs unmeasurable on a USD account, and an executor may book it as a parity miss or loosen a rule to make it go away.
**How to avoid:** fix `_native_unit_present` first with a USD/BTC test pair shown RED; then run. A leg that stays unmeasurable after the fix is a named finding, never a pass.
**Warning signs:** `not_measurable:unit_mismatch` on an account whose census unit is USD.

### Pitfall 2: `final_green` read from a Gate-A-only run
**What goes wrong:** treating a green Gate A as parity. **How to avoid:** `Verdict.final_green` needs Gate A and Gate B per label; the record must say "Gate A only, Gate B unjudged".

### Pitfall 3: Wrong clock per account
**What goes wrong:** the scratch script uses the CLI default `us` for an account whose derive used another rule (Phase 217 per-server map), producing a false `clock_mismatch`. **How to avoid:** take the clock from that key's server-clock reading, per account.

### Pitfall 4: Real values leak into tracked text
**What goes wrong:** deal counts are fine, amounts/logins/server names are not; the real Reports and capture stay in `/.mt5-parity/2026-11-19-founder/`. **How to avoid:** every tracked artifact passes `records scan --profile record`; verdict text comes only from `render_verdict_markdown` (typed to carry no amount).

### Pitfall 5: Fix does not show until deploy + recompute + recapture
**What goes wrong:** a TS fix is merged and the finding "persists" because `strategy_analytics` is unchanged until recomputed. **How to avoid:** the plan with "finding cleared" acceptance is the post-deploy recapture plan, bound to `computed_at`.

### Pitfall 6: Parser fix leaks into the `th` path
**How to avoid:** `visible == width` when no hidden cell; all 34 existing parser tests stay unchanged and green.

### Pitfall 7: Planning-tree side effects
**What goes wrong:** `gsd-tools` handlers clobber STATE/ROADMAP; a ship branch that touches `.planning` is refused. **How to avoid:** `git diff` after every handler run; never write a SUMMARY for a deferred founder plan.

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | no | Not touched; investor credentials are never read or recorded |
| V4 Access Control | yes | PROD access only via orchestrator MCP; executors never use CLI/Keychain; read-only SQL gate over `docs/runbooks/mt5-parity` |
| V5 Input Validation | yes | The Report is untrusted founder-side input: closed header/type/direction vocabularies, size cap `MAX_REPORT_BYTES`, strict money/time regexes, named refusals; no external entity fetch |
| V8 Data Protection | yes | No logins, servers, account numbers, amounts or home paths in tracked text; `scan_tracked_text` backstop; capture dir gitignored (a test pins the line) |
| V6 Cryptography | no | sha256 binding only (`bind_report`), stdlib `hashlib` |

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Report edited or swapped after the reading | Tampering | `bind_report` sha256 against the worksheet reading |
| Real data committed to the public repo | Information disclosure | `records scan --profile record`, typed verdict renderers, no-amount types |
| Oracle replaced by our own pipeline's number | Spoofing | `require_provenance` closed to three labels |
| Hidden column silently dropped | Tampering | Known-header set; unknown header refused by name |
| Placeholder readings faking a Gate B | Repudiation | Intake refuses incomplete worksheets; no synthetic marking of a real worksheet |
