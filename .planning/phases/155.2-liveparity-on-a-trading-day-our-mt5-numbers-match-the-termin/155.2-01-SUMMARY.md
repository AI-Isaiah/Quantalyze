# Phase 155.2 Plan 01: Real-shape Report parser Summary

The MT5 Report parser now reads the terminal's real build 5830 All-History Report (bold td header cells, a hidden Cost column before Commission, footer spanning only the visible columns) to the same deals as the th-header synthetic Report, and refuses every other header shape by name.

## What changed

`analytics-service/services/mt5_parity_report.py`:
1. `_Cell.hidden: bool = False`, set by `_RowCollector` when the cell's `class` tokens contain `hidden`.
2. `_canonical_headers` accepts a header row of exactly one tag kind (all th or all td) with every colspan 1; a mix or a spanned cell raises `RowShapeRefused` (same message as before). The `UnknownHeader` refusal that follows is untouched.
3. `"Cost"` added to `REPORT_KNOWN_HEADERS` only. `REPORT_REQUIRED_HEADERS`, `_DEAL_KEYS`, `_MONEY_KEYS`, `_parse_row` and `BALANCE_CONTINUITY_ABS_TOL` are unchanged.
4. `parse_report` computes `visible` (header cells not hidden). The footer / next-marker condition compares span to `visible`. The deal-row condition and the deal-shaped-row-after-footer scan keep the full `width`.

Tests (7 new, 41 total in the file, all 34 pre-existing tests unedited): `test_a_realshape_report_parses_to_the_ledger`, `test_a_mixed_th_td_header_row_is_refused`, `test_a_spanned_header_cell_is_refused`, `test_a_hidden_header_not_named_cost_is_refused_by_name`, `test_a_nonzero_cost_never_enters_the_money_math`, `test_a_visible_width_footer_ends_deals_but_a_full_width_row_does_not`, `test_the_realshape_utf16le_twin_parses_like_the_utf8_one`. A local `_realshape` helper does the string edits (never `_mutate`) and fails loudly if an edit target is absent.

Fixtures: the real-shape pair is generated from the existing synthetic utf8 fixture (synthetic values only); the twin is the UTF-16-LE-with-BOM encoding (`fffe`).
