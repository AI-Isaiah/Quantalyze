# Phase 155.2 Plan 15: Day-0 read of a stored curve (G3-1 (a)) Summary

A stored `strategy_analytics` curve now reads as n daily returns, not n-1, in TypeScript (`resolveDailyReturnSeries`) and in Python (`daily_returns_from_row`) for every venue: the first level is read against the curve's implicit 1.0 base (`w0 - 1`, geometric and simple). The composer returns route therefore serves the same n observations the persisted factsheet Sharpe runs on, pinned by a hand-computed n = 4 (11.619) versus n - 1 = 3 (7.937) Sharpe literal.

## What changed

- `equityCurveToDailyReturns(points, method, keepAbsent, fromBase = false)` and `curve_to_daily_returns(levels, method, *, keep_absent, from_base=False)`: with the option on, row 0 is paired with an implicit 1.0 predecessor on the same usability rule as every other day (geometric needs w0 finite and > 0; simple needs w0 finite). With `keep_absent`, an unusable day 0 is a NaN placeholder at its own date. One-point curves yield one return.
- `resolveDailyReturnSeries(..., fromBase = true)` and `daily_returns_from_row(..., from_base=True)` turn it on. `STORED_CURVE_MAX_POINTS = 5000` in both runtimes, named after `cap_data_points`.
- Shared oracle: top-level `stored_curve_max_points: 5000`; hand-computed day-0 literals on every curve-derived case; four new cases (4-day geometric and simple, geometric non-positive w0 absent, simple negative w0 legal); `native_leg_loses_first_two_days` became `native_leg_loses_only_day_zero` (a close for day 0 was added so day 1 prices: 1.1 * (100 / 80) - 1 = 0.375); `one_point_series_is_empty` became `one_point_series_is_its_day_zero` (level 1.07 -> 0.07).
- Verify-strategy trim site (`routers/portfolio.py`): `from_base=not cut`, `cut` measured from input and output lengths only when the raw curve is a list; one local binds the raw curve so the census site count stays 2.
- `countedSeriesColumn`: N stored curve points count as N returns (N - 1 at or above `STORED_CURVE_MAX_POINTS`).
- Cache key `factsheet-v2-payload-v25` to `-v26` with its dated ladder entry; the two tests that pin the prefix moved with it.

## Capped-curve note

A curve of `STORED_CURVE_MAX_POINTS` (5000) points or more never emits day 0 in either runtime, and that includes a 5000-point curve that was never cut. This is the conservative direction: a record longer than about 13.7 years of daily points keeps the n - 1 reading. Both runtimes are tested at 4999 (emits), 5000 and 5001 (do not). The Python test also asserts `cap_data_points`'s default `max_points` equals the constant and the oracle's `stored_curve_max_points`.

## Deviations from Plan

**1. [Rule 1 - Plan arithmetic] The `short_series` boundary.** The plan says a row of exactly `MIN_FACTSHEET_SERIES_POINTS - 1` stored curve points "now builds". With `MIN_FACTSHEET_SERIES_POINTS = 2`, one stored point is one return and stays short. The real boundary moved by one point: two stored points (they were one return before) now build. I pinned both sides in `fetch-and-build-payload.test.ts`: one wealth point -> `too_few_points`, two wealth points -> buildable.

**2. [Rule 3 - Fixture shape] Stored-curve fixtures carried a 1.0 base point the writer never writes.** `_stored_curve` and `_c6_supabase` (`test_correlation_residue_sites.py`) prepended a base day, and the compare-matrix test seeded curves at 1. Under the new reader that base point is read as an extra 0.0 day. I moved those fixtures to the writer shape (first level `1 + r_0`, no base) instead of editing dozens of expectations, and rewrote the compare-matrix "scaled copy" case (a rescaled copy of an anchored curve is no longer a valid stored curve) as a proportional-returns case with a hand invariant.

**3. [Rule 1 - Expected values moved by day 0] Test files touched beyond `files_modified`** (all with hand arithmetic in comments, never derived by calling a reader): `tests/test_c19_portfolio_fixes.py`, `test_correlation_residue_sites.py`, `test_match_integration_phase09.py`, `test_match_router.py`, `test_portfolio_compute_integration.py`, `test_portfolio_router_logic.py`, `test_simulator_router.py`, `test_wealth_returns_router_method.py`; `src/lib/factsheet/fetch-and-build-payload.test.ts`, `src/app/factsheet/[id]/v2/page.public-cache-key.test.tsx`, `src/app/factsheet-share/[token]/page.cache-isolation.test.tsx`, `src/app/api/og/factsheet/[id]/route.test.tsx`, `src/app/scenario-share/[token]/page.test.tsx`, `share-resolve.test.ts`, `src/components/strategy/CompareCorrelationMatrix.curve-levels.test.tsx`, `src/lib/queries.my-allocation.test.ts`, `src/__tests__/figure-parity-pages.test.tsx`.
