# Phase 155.2 Plan 02: Gate A unit predicate Summary

A Gate A account whose marks carry `native_unit` USD is now measured on start_level, end_level, cum_return and day_placement; a BTC mark unit or a non-USD worksheet `account_currency` still reads `not_measurable:unit_mismatch`.

## What changed

`analytics-service/services/mt5_parity.py`:
1. `WRITER_BASIS_UNIT: Final = "USD"` with a comment that the key_inputs books and the marks' `*_usd` columns are written in USD.
2. `_native_unit_present` is gone. `_unit_mismatch(capture, ordinal, account_currency)` returns True when any mark row's `native_unit` is set and differs from the writer basis (strip and upper-case), or when the account currency reading is not the writer basis. NULL native_unit with no currency reading is measured as before. A small `_is_writer_unit` helper owns the normalisation.
3. `_account_currency(readings)` returns the `account_currency` reading as text, or None when absent; disagreeing readings return a non-USD value.
4. `gate_a_legs(..., *, account_currency: str | None = None)`; both internal uses call `_unit_mismatch`. `evaluate_account` and `_legs_under` pass `_account_currency(readings)` / `_account_currency(ctx.readings)`.

Nothing keys on exchange, venue or the mt5 string. `MT5_PARITY_TOLERANCE` and `MT5_INCEPTION_IDENTITY_BAND` are untouched.

Tests (3 new, added before the fix): `test_a_usd_native_unit_account_is_measured`, `test_a_non_usd_report_currency_is_never_compared_to_usd_books`, `test_a_gate_a_only_verdict_is_never_final_green`. `test_a_native_unit_account_is_never_compared_across_units` is unedited and still passes (the test diff removes no line). At HEAD before the fix the USD and EUR tests failed; the final_green test already passed and is kept as a pin.
