- **Found during:** Task 2 verify
- **Issue:** `allocator-portfolio-payload.test.ts` "sorts by date and drops non-finite / non-positive values defensively" asserted that `equityCurveToDailyReturns` filters bad levels first and pairs the survivors (a bridged ratio across a dropped level), which is exactly what D-01 removes. ### Notes (not deviations)

- `curveMethodFromFlags` warns once without echoing the value (the test asserts the value is absent from the warning).
- The Python parity gaps recorded in plan 01 still hold: a numeric string level is coerced in Python and is a bad level (NaN, absent days) in TypeScript, and duplicate dates are deduped in Python only. Neither is in the oracle.
- Not changed, flagged for a reader of the portfolio page: `buildWealthPoints` plots a persisted `returns_series` as stored when it is non-empty (it does not derive). For a `simple` strategy that is a `1 + cumsum` line on an axis the chart treats as cumprod wealth. That path draws a curve rather than deriving returns from it, so it is outside this plan's scope.
