## Deviations from Plan

None - plan executed as written. Two notes that are not deviations:

- The plan said "recompute the 0.21 personalized test by hand on curve-shaped storage". The existing 0.21 test (`test_portfolio_and_candidate_btc_series_arrive_converted`) hands series straight to `_score_one_allocator` via `precomputed_ctx`, so it never reads storage and stays as is. Its arithmetic: native daily returns `[0.0, 0.0, 0.10, 0.04]` on 02-01..04 store as levels 1.0, 1.0, 1.1, 1.144; the boundary reads days 1..3 (0.0, 0.10, 0.04); the converter drops its first day; 02-03 is `(1 + 0.10) * (66000 / 60000) - 1 = 0.21` and 02-04 is `(1 + 0.04) * (72600 / 66000) - 1 = 0.144`.
- The old router warning said "dropped N/M malformed record(s)"; the shared parser says "skipped N malformed records". The M-0604 test's wording assertion was moved to the new wording, with a comment (the contract, a WARNING naming the series, is unchanged).

## Known behaviour change worth knowing

A BTC leg's first scored day is now day 2 of its stored curve: the boundary drops day 0 (no stored predecessor) and the USD conversion drops the next day (no prior priced value). This is the same two-day loss plan 01's shared oracle pins (`native_leg_loses_first_two_days`).
