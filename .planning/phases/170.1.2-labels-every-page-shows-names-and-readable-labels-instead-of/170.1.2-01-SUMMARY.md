# Phase 170.1.2 Plan 01: Shared label module Summary

One module, `src/lib/display-labels.ts`, now holds every new label vocabulary with a per-vocabulary fallback and an own-key lookup. Each vocabulary is census-tested against its `supabase/schema/baseline.sql` CHECK set. ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] ROLE_META moved to `src/lib/auth-types.ts`, not exported from UserRolesPanel**
- **Found during:** Task 2
- **Issue:** The plan says to `export const ROLE_META` from `UserRolesPanel.tsx` and import it into `display-labels.ts`. `UserRolesPanel.tsx` starts with `"use client"`. A server component (the `/admin/users` page is one, and it renders app-role badges) that imports a non-component export from a `"use client"` module receives a client reference, and reading `ROLE_META[role]` on the server throws. `appRoleLabel` would have crashed on the page it exists for, and vitest cannot see that boundary.
- **Fix:** `ROLE_META` now lives in `src/lib/auth-types.ts`, the existing server-only-free home of `AppRole` and `APP_ROLES`. `UserRolesPanel.tsx` imports it from there and renders identically. Still one definition, never copied.
- **Consequence for the plan's acceptance grep:** `grep -ac 'export const ROLE_META' src/components/admin/UserRolesPanel.tsx` prints 0 (the plan expected 1); `grep -ac 'export const ROLE_META' src/lib/auth-types.ts` prints 1.
- **Files modified:** `src/lib/auth-types.ts`, `src/components/admin/UserRolesPanel.tsx`
- **Commit:** `11c6e1ca3`

**2. [Rule 1 - premise drift] The compute-job kind set now has 17 values, not 16**
- **Found during:** Task 1
- **Issue:** `supabase/schema/baseline.sql` (re-dumped after the plan was written) carries `okx_archive_rebuild` in `compute_jobs_kind_check` (migration `20261026120000_okx_archive_rebuild.sql`). The UI-SPEC table lists 16. The census requires set equality, so a 16-key map would be RED.
- **Fix:** added `okx_archive_rebuild: "OKX history rebuild"` (sentence case, parallel to "Allocator history rebuild"). The UI-SPEC does not lock a label for it. The plan's "16 values" wording and its "Allocator equity derivation is the 16th" reading are superseded; the map has 17 entries.
- **Files modified:** `src/lib/display-labels.ts`
- **Commit:** `110181062`

"Unknown status"`, so a prototype key such as `constructor` also reads "Unknown status" (pinned by a Badge test). Badge now imports `display-labels`, which imports `@/lib/types`, `@/lib/closed-sets` and `@/lib/auth-types`.
