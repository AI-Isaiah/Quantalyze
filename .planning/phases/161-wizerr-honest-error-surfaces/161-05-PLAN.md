## ⛔ MEASURED TOOLING HAZARD — `grep` is BLIND to `src/lib/wizardErrors.test.ts`

Measured first-hand at plan time, 2026-08-24, and it silently invalidates count-based
verification on the exact file this plan edits:

- `src/lib/wizardErrors.test.ts:1572` contains a deliberate NUL byte inside a string literal
  (`.join(" \0 ")` — a phrase-boundary delimiter in the banned-claims scan). It is
  load-bearing. **Do NOT "fix" it.**
- The project's `grep` is a shell function wrapping **ugrep 7.5.0**, which classifies a
  NUL-bearing file as binary and **skips it silently**: `grep -c EXPECTED_TABLE_SIZE
  src/lib/wizardErrors.test.ts` returns **no output, exit 1** — while `sed` shows the constant
  plainly at `:1888`. It is the ONLY non-binary file under `src/` carrying a NUL byte.
- Consequence: any `grep`-based measurement or negative gate over this file returns **zero,
  always** — a vacuous pass of exactly the class the phase's anti-vacuity rule exists to kill.

**Binding rule for every task in this plan** (and any later plan touching this file): measure
and verify inside `wizardErrors.test.ts` with `grep -a` / `--binary-files=text`, or with
`awk` / `sed` / Node `readFileSync` — never bare `grep`. All four were confirmed to return the
correct count of **10** occurrences. The invariant laws themselves are unaffected (they read
source through Node `readFileSync`).
