> gsd-ui-researcher, verified by gsd-ui-checker.

## Copywriting Contract

### Template summary rows

| Element | Copy |
|---------|------|
| Primary CTA | Per-surface remedy verbs (see § Copy Spec): "Try another key" (now non-destructive), "Reconnect the key", "Start a new strategy" (`START_NEW_STRATEGY_LABEL`, existing constant) |
| Empty state heading | not applicable — this phase introduces no new empty states |

### Copy Principles (binding on every string in this phase)

1. **Name the actual blocker.** No `code: UNKNOWN` where the server already classified the
   failure. No sentence that is false about the user's situation.
2. **The remedy must be able to succeed.** "Try again" only where trying again can work. Where
   it can't, name the real action ("Reconnect the key", "This needs an operator, not a retry").
   Mechanically: recoverability is DERIVED from `actions` membership in `RECOVERABLE_ACTIONS`
   (`envelope.ts:54` — `clear_and_retry`, `try_another_key`); to suppress the Retry control you
   omit both, you never add a flag.
3. **Public copy never leaks internals.** No venue internals, key ids, uids, flag names,
   tracebacks. On every 5xx the `error` message stays STATIC (H-1062 / F5b / T-140-11) — forward
   the CODE, never `err.message`. The anon `verify-strategy` surface must not name venues
   outside `UI_EXCHANGE_CODES` (F3 disclosure).
4. **Correlation id only on terminal / non-actionable arms** (`STALE_CLIENT` precedent,
   Phase 160). On an actionable error it is noise competing with the remedy.
5. **Never invent a number.** Retry-After renders only when a wait was advertised; absence means
   "no wait was advertised", never "zero" (TRAP-3). Thresholds are stated with the number
   attached (DESIGN.md Voice: "A minimum of 7 days is required").
6. **DESIGN.md voice throughout:** declarative sentence case, active voice, no adjectives where
   a number exists, no exclamation, no cheerful filler.

### Fence 1 — MT5 curated-message fence (VERIFIED first-hand at HEAD)

Scope: `MT5_GATEWAY_MISCONFIGURED_DETAIL` and ANY new curated MT5 constant entering
`test_mt5_validate_parity.py` (`:380-403`), `test_job_worker.py` (`:137+`, also `len > 40`),
`test_ingestion_mt5.py` (`:310+`). The test lowercases the constant and rejects any SUBSTRING
from:

- `_WRONG_SERVER_TOKENS` (`mt5_validation.py:79-86`): `server`, `connect`, `ipc`, `network`, `terminal`, `not found`
- `_AUTH_TOKENS` (`mt5_validation.py:90-96`): `authoriz`, `account`, `invalid`, `password`, `login`
- credential words: `password`, `investor`, `master`, `secret`

⛔ CONTEXT's example wordings ("…disabled in the **terminal**", "…for this **account**") are
FENCE-ILLEGAL and must not ship (RESEARCH already flagged this; the intent — cause, not sensor
reading — survives). ⚠️ Watch for substring traps: "reconnect" contains `connect`;
"unaccountable" contains `account`. Every candidate sentence is checked against the token lists
BEFORE the test runs. The fence itself must not be relaxed. New constants must keep the
default-argument property (`Mt5GatewayMisconfigured()` never carries raw remote text by
omission). **This fence covers ONLY the MT5 curated constants** — "Reconnect the key" is legal
in TS wizard copy, which the Python fence does not scan.

### Fence 2 — 4xx-curated / 5xx-static rule (VERIFIED first-hand at `simulator/route.ts:202-214`)

A 4xx `detail` is operator-curated copy → forward it with `code: err.seamCode ?? "UNKNOWN"`.
A 5xx `message` may carry FastAPI detail / contract-drift strings / the service base URL → the
body stays STATIC; only the recognized CODE is forwarded. Restated at
`admin/match/eval/route.ts:244-256`. Every WIZERR-06 edit obeys this: widen the code forward,
keep every existing static 5xx sentence byte-identical.

### Copy Spec — per requirement

contract). Each new `WizardErrorCode` member moves `EXPECTED_TABLE_SIZE` (81 → N) at BOTH pins
(`wizardErrors.test.ts:1888`, `:2275`) plus the divergence guard, plus affected `KNOWN_*`

Copy entries use the `WizardErrorCopy` shape: `title` / `cause` / `fix[]` / `docsHref` /

#### WIZERR-01 — MT5 gateway-misconfigured cause variants (Python curated constants)

defensively — absent key ⇒ generic fallback, never KeyError; flag names never reach user copy):

   > cannot be proven. The gateway switches it off again whenever it changes users, so turning
   > it back on needs an operator, not a retry — see docs/runbooks/mt5-go-live.md."

   Fence-checked by hand against all three token lists: clean. Length > 40: yes.
2. **`tradeapi_disabled` true (the case today's constant actually describes):** keep today's
   constant's structure —

   > the external Python API' option is in force), so read-only capability cannot be proven.
   > This needs an operator, not a retry — see docs/runbooks/mt5-go-live.md."

   Fence-checked: clean (today's near-identical constant already passes the fence live).
3. **Flags absent/ambiguous:** today's generic constant, unchanged (honest fallback — never
   guess a cause).

Delivery: a shared flag→cause builder beside `terminal_trade_permission_off` in
`mt5_validation.py`/`mt5_probe.py`, consumed by BOTH raise sites (`ingestion/mt5.py:315`,
`routers/exchange.py:851`) so the next carrier inherits it — that is the "fixed as a CLASS"

extends to every constant the builder can emit. All comment-prose carriers repeating the false
