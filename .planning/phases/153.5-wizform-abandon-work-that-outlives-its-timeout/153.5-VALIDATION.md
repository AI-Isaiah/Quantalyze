## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest + pytest-asyncio (`asyncio_mode = auto`), pytest-xdist (`-n auto --dist loadgroup` in CI) |
| **Config file** | `analytics-service/pytest.ini` (+ `pyproject.toml` `[tool.mypy]`) |
| **Quick run command** | `cd analytics-service && .venv/bin/pytest tests/test_mt5_client_contract.py tests/test_mt5_concurrency.py -x -q` |
| **Full suite command** | `cd analytics-service && make test` (pytest + `--cov-fail-under=80`) |
| **Type gate** | `cd analytics-service && make typecheck` (== CI's `mypy --strict --follow-imports=silent services/ routers/ models/`) |

⛔ **Run pytest from `analytics-service/`, never the repo root.** `tests/conftest_vcr.py:149`
sets `cassette_library_dir="tests/cassettes"` — a RELATIVE path. A root run misses the
cassettes and makes LIVE broker calls.
⚠️ **`mypy --strict` before shipping.** The GSD path runs pytest only, so type errors stay
latent until PR CI. Fix with `cast()`, never `# type: ignore`.
⚠️ **`pandera` may be missing locally** — `pip install 'pandera==0.32.1' --break-system-packages`.
It is a declared dep and CI has it.
⚠️ **Every test in this phase is offline by construction** — no live gateway, no `mt5linux`,
no rpyc import; all clients are built over the `_connect=` seam.

- **Max feedback latency:** 30 seconds (per-task quick run)

  times** in plan 05's verify block. A guard that is green once and red on the third run is a
  fifth flake mechanism, not a pass.

## Oracle Independence

> The failure this catches: assertions that read their expected value out of the module under
> test, so the test passes for any implementation. This project has already paid for it —
> three money bugs survived six review passes behind self-referential oracles.

| Oracle | What it pins | INVARIANT, not the impl's own formula — how we know |
|--------|--------------|------------------------------------------------------|
| Fake-session **call log** (plan 01 T2, plan 05 T2) | "No session touch landed after the lease released" | The oracle is the **absence of an effect on a test-owned double**, not the exception type the production code chose to raise. It stays true if `Mt5SessionAbandoned` is renamed, re-typed, or replaced — and it goes false the moment a touch lands, which is the economic harm itself |
| Ordered log **index** (plan 05 T2) | Post-release ordering | Index into a recorded list, ⛔ never `at_time` / wall clock. A wall-clock comparison is a sleep-ordered race wearing a different hat and would pass or fail on scheduler luck rather than on the property |
| Epoch **exact delta** (plan 03 T2) | "One lease release ⇒ exactly one bump" | The expected delta is a **hand-typed integer** matching the scenario's known hold count — not `len(holds)` and not a counter the production path increments. A "changed / non-zero" assertion would pass for a double-bump, which would fence a legitimate successor |
| `_WRONG_SERVER_TOKENS` / `_AUTH_TOKENS` sweep (plan 01 T2, plan 04) | "The refusal message and the classifier's tables are disjoint" | ⚠️ **Deliberate cross-module import** — the test imports the LIVE tables from `services/mt5_validation.py`. Justified: the invariant is disjointness from *whatever the classifier actually matches on today*; a hand-copied table would go stale and pass while the real classifier gained a token. It is not self-referential, because the table lives in a **different** module from the one under test (`mt5_client.py`) |
| `GUARDED_METHOD_FLOOR = 7` (plan 05 T1) | Roster non-vacuity | A **hand-typed literal**, asserted `>=` so a newly fenced method passes. ⛔ Never `len(EXPECTED_METHODS)` — a list compared to its own length cannot fail |
| `SESSION_TOUCH_FLOOR` (plan 05 T1) | Walk non-collapse | ⭐ Must be **measured once while writing the test and hand-typed as `(measured − 1)`** — see the plan's own wording. A floor derived at execution time from the same walk it guards is the unfailable self-referential floor `test_mt5_shutdown_roster.py:33-37` forbids |
| ast walk **file-count floor ≥ 40** (plan 03 T2) | Class-pin non-vacuity | Hand-typed, with the measured HEAD number in the failure message. A pin over zero files passes silently |
| Roster **self-tests** (plan 05 T1) | The predicate itself | ⭐ The unguarded synthetic is load-bearing: without it, a predicate returning "guarded" unconditionally is indistinguishable from a correct one. Plus the prose-ignored flavour (the thing grep cannot do) and the aliased `stale = self._mt5` flavour |
| Embedded `neuter=True` control (plan 05 T2) | The positive assertion can fail | Both directions live permanently in one file — the positive is never trusted without its negative |
| **Real lease** in the live-path proof (plan 02 T2) | Mutual exclusion, not the fence's logic | The test drives the shipped `mt5_terminal_lease`, so the oracle is "an exclusive lock means the epoch cannot move while held" — a property of the lock, independent of anything `_assert_live` computes |
| Open/close **balance** (plan 02 T3) | "No conn remains open" | Balance, not "the post-connect arm fired". Which arm the zombie takes depends on where its thread was when the bump landed; a per-arm oracle would flake on a run where the leak property genuinely held |
| Response **body** (plan 04) | The user-facing contract | Status + `code` + retry semantics asserted from the response, never from the arm's source. A source-level assertion would pass for an arm that raises but never reaches the serializer |

Checklist:

- [ ] No test imports a **constant** from the module it tests — expected values are **literals** in the test
- [ ] No assertion compares a value to itself via a re-export, fixture, or table under test
- [ ] Roster/registry sizes are pinned to a **hand-typed literal**, never `len(THE_TABLE)`
- [ ] `SESSION_TOUCH_FLOOR` is hand-typed `(measured − 1)`, with the measured number in the failure message
- [ ] `_FakeMt5` and the new spy double are pinned against the real contract they stand in for
      (`test_public_surface_is_exactly_the_contract` must stay green **unchanged** — if it reds,
      the production shape is wrong; ⛔ do not re-cut the pin)
- [ ] Every fence assertion has an **effect-based** oracle (the fake's log), not merely "the
      exception type was raised"
- [ ] The epoch-registry read in tests goes through `services.mt5_client` (the OWNER), never a
      re-export — the E2 silent-no-op trap

*Deliberate self-referential oracles, and what independently covers them:*
1. The **token-table import** (above) — deliberate, because the live table IS the mechanism.
   Independently covered by `mt5_validation`'s own classifier tests.
2. The **ast rosters** derive their expected set from the same source file they guard — that is
   the mechanism, not a bug. Protected from vacuity by the hand-typed floors, the exact-equality
   exempt set, and the unguarded-synthetic self-test. All three must move together or the
   derivation can silently match nothing.
