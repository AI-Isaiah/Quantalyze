### W-153.5-3 — an undocumented, unguarded latent constraint of the lazy bind

`self._epoch` binds on first touch and never rebinds. A single `Mt5Client` instance used under **two** lease acquisitions would therefore be refused on the second — a false positive that would classify as a permanent-looking transient loop.

I checked whether any production path does this and **none does**: ast-derived, the five lease blocks are `job_worker.py:388-391`, `job_worker.py:3610-3802`, `allocator_positions.py:677-741`, `ingestion/mt5.py:200-414`, `exchange.py:846-1017`; each holds exactly one lease per client instance, the `sync_trades` mt5 arm touches the session only through `_fetch_mt5_account_balance` (one lease) before `aclose_exchange` (an exempt verb), and both `_mt5_bounded_restart` sites in each module are inside their own lease. So the constraint is satisfied today by accident of structure, not by any assertion.
