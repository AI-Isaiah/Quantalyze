## Decisions Made

- **Two exemption pins rather than one.** `_teardown_transport` is on D-41's list but is structurally invisible to the touch predicate (it takes `mt5_obj` as a parameter — `restart()` disposes the STALE object after the fresh one is swapped in, so reading `self._mt5` there would close the wrong socket). `EXEMPT_TOUCHING` is asserted with `==` against the derivation; `EXEMPT_BY_PARAMETER` is asserted disjoint from it; `D41_EXEMPT` is their union, derived rather than typed twice (the `_TEARDOWN_NAMES` mechanism). If `_teardown_transport` ever starts reading the attribute, the equality reds and the exemption must be re-cut deliberately — which is the intended outcome, since it must still stay unfenced.
- **The guard must be the FIRST executable statement, not merely present.** All seven fenced methods already satisfy this, so the stronger property is free — and it is the property that matters: a check after the round-trip refuses nothing, and can be rewritten into a scrubbed `Mt5ClientError` by `_guarded_read` (the absorption D-42 forbids) or timed into the D-32 population.
- **The client is built OUTSIDE the lease in the runtime harness.** That is the preflight shape, it carries no occupancy token, and it keeps the case about the METHOD fence alone. The construction fence is a different mechanism with its own cases in `test_mt5_client_contract.py` — one control, one variable.
- **Nothing is monkeypatched except `_assert_live` in the control arm.** The abandonment bound is a LOCAL literal handed straight to `asyncio.wait_for`, so the E2 patch-target trap (patching a merely re-exported name is a silent no-op) has no surface here at all.
- **`asyncio.ensure_future` before the bound, rather than `wait_for(to_thread(...))` inline.** The bound is still a real `wait_for` on a real `to_thread` future; creating the task first is what lets the harness wait — bounded — for the worker to reach the barrier before the clock that decides the ordering starts mattering. Documented at the site with the failure mode it prevents.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 — Test defect] The ledger's loop-liveness oracle (`ticks > 0`) cannot see its own mutation**

- **Found during:** Task 2, while designing falsification H.
- **Issue:** `153.5-VALIDATION.md` row *SC-05-2 (WEDGE-01)* states the oracle as "`ticks > 0` fails" when the lease's `finally` is made to join the worker. It does not: the 10ms ticker starts before the harness and has already accumulated ticks during the abandonment bound's own 50ms, so `ticks > 0` is satisfied long before the release is reached. Asserting it would have shipped a guard that stays green under the exact design D-36 ⛔ REJECTED — the same "a guard that cannot see its own mutation is not a guard" defect plan 02 hit and had to restructure a test to fix.
- **Fix:** the load-bearing assertion is the **release window** specifically — the wall-clock elapsed across the `async with` exit and the tick delta measured across the same window: `release_ticks > 0 or release_elapsed_s < _ABANDON_BOUND_S`. Under the accepted design the release is instantaneous (passes on the second disjunct); under the rejected design it is a bounded deadlock (the test cannot release the barrier until the `async with` has returned) that blocks the loop and accumulates zero ticks. The bare `ticks > 0` is KEPT as a separate, weaker assertion (it proves the session work runs off the loop at all) with its own message, and the docstring states in full why it is not the discriminator.
- **Verified:** falsification H reds with `releasing the lease blocked the event loop for 0.303s and the 10ms ticker advanced 0 times across it`.
- **Files modified:** `analytics-service/tests/test_mt5_abandon_fence.py`
- **Commit:** `e47ad0b1`

**2. [Rule 1 — Plan/source mismatch] `_teardown_transport` cannot be a member of the exact-equality exempt set**

- **Found during:** Task 1, measuring the derivation before writing any assertion.
- **Issue:** the plan specifies `EXEMPT: frozenset = {"__init__", "close", "release", "_teardown_transport"}` "asserted with EXACT equality against (touching − guarded)". Measured against source, `_teardown_transport` contains **zero** `self._mt5` nodes — its only mention is inside its own docstring, which is structurally absent from an AST. The derived difference is `{__init__, close, release}`, so the plan's set could never be equal to it and the assertion would have redded immediately. - **Fix:** two pins, split by KIND, with `D41_EXEMPT` derived as their union so D-41's four names still appear in the file as one roster and cannot be typed twice. Both halves carry the Pitfall-6 warning and the "if this changes, re-cut deliberately" instruction.
