Chiefly `src/components/strategy/ShareableLink.tsx`; `SyncBadge.tsx` placeholder also read.

## SFH2-01 MEDIUM (confidence 8) published-lane failure message points at a URL it does not show

`ShareableLink.tsx:275-287` and label at `:325`. When both copy paths fail, `copyFailed` renders
"Copy failed — copy the URL manually" for 4 s. Only `mint-token` mode opens the dialog with the
URL (`:283`). The published lane (`public-url`) shows nothing to copy: the page is `/strategies`
or the discovery detail, whose address bar is not the shared URL. This message predates the
round, but the new 3 s bound makes it newly reachable on a hang that used to be silent.
Scenario: published strategy, Safari with an unanswered clipboard permission prompt. After 3 s
the label says to copy a URL that is nowhere on screen; the user has no recoverable path and
the message disappears at 4 s. The agent's recorded note is correct and it is a real defect, not
cosmetic.
Fix: on the published lane also surface the URL (small inline readonly Input, or the same
dialog pattern), or change the label to a truthful one ("Couldn't copy — open the factsheet
and copy its address") that names a place the URL actually is.

## SFH2-02 MEDIUM (confidence 6) mint and clipboard failures are swallowed with no log and no cause

`ShareableLink.tsx:231-240` (`catch {` on `mintShareUrl`), `:256-258` (bare catch on
`writeClipboardBounded`), `:266-267` (bare catch on `execCommand`). Nothing is logged, so a
401/403/404/500 mint, a network drop, a 3 s timeout and a permission denial are
indistinguishable, in the UI ("try again" for all) and in the console. The sibling control in
`FactsheetView.tsx` (`mintAndCopy`, ~line 2310) logs `console.warn("[factsheet] share
mint/copy failed", { strategyId, err })` and FINDING-9 logs denials; this component was changed
this round and still does not. Scenario: owner loses ownership or is signed out; mint returns
401/403; label says "Couldn't create the link — try again" forever, retrying cannot succeed,
and support has no trace. The mint error text (`share mint failed: <status>`) is built and then
discarded. Failure feedback is also only a 4 s button label with no live region, so a user who
looks away or uses a screen reader sees or hears nothing.
Fix: `catch (err) { console.warn("[share] mint failed", { strategyId, err }); ... }` in all three
places; add `role="status"` or `aria-live="polite"` to the failure text; for 401/403 prefer a
message that is not "try again".

## Considered and not raised (below MEDIUM)

- Late `writeText` after the 3 s timeout: `Promise.race` keeps handlers on both promises, so no
  unhandled rejection, and a late resolve changes no state and triggers no second action. It can
  leave the dialog saying "would not copy it" after the clipboard did get the link. LOW.
- The button is not disabled during the up-to-3 s clipboard wait (`minting` is already false),
  so a second click runs a concurrent `handleCopy`; the first 2 s timer can cut the second
  "Link copied!" short. Cosmetic. LOW.
- `mintedUrl` stays after a later successful copy, so Manage reopens with the "would not copy"
  banner; and after a revoke made in another tab the banner says the link is live until the
  panel's own revoke 404 converges. LOW.
- The panel's own Copy button (`FactsheetView.tsx` ~2307) still awaits `writeText` unbounded, so
  it can stay in "Copying…" forever; not in these commits. Worth routing with SFH2-02.
