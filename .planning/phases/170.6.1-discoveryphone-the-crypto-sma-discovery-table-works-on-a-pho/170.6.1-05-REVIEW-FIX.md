## Fixed Issues

### WR-01 / SFH-2: a failed venue RPC put the SC-2 defect back as a confident label

**Files modified:** `src/lib/queries.ts`, `src/components/strategy/SyncBadge.tsx`, `src/components/strategy/StrategyTable.tsx`, `src/components/strategy/StrategyGrid.tsx` (tests: `src/lib/queries.trade-venues.test.ts`, `src/components/strategy/SyncBadge.venue.test.tsx`, `src/components/strategy/StrategyTable.trade-venue.test.tsx`, `src/components/strategy/StrategyGrid.test.tsx`)
**Commit:** `3e5a2e050`
**Applied fix:** `readPublishedTradeVenues` now returns `null` ("unavailable") on an RPC error or a throw, distinct from an empty map ("read fine, no key"). `getStrategiesByCategory` tags every row `tradeVenuesUnavailable: true` when it gets `null`. `SyncBadge` takes a `tradeVenuesUnavailable` prop (forwarded by StrategyTable and StrategyGrid) and, when it is true and no venue is known, renders NO label (not the listed exchange), drops the `from the exchange` clause from the fresh and stale tooltips, and shows no mismatch cue. It stays fail-soft (no error boundary for a display label); the console error and the Sentry capture at `error` are kept. A row with venues read and none found keeps the listed exchange (D-05). The flag never reaches `resolveTradeFetch`, so the dot, the sentence and the render gate are unchanged (D-07), pinned by an invariance test over 4 stamps x 2 series states.

**Status:** fixed: requires human verification (a display-logic decision: the founder should confirm that a blank label, rather than the listed exchange, is the wanted degraded state during an outage).

### SFH-1: a malformed 200 response was dropped with no log and no capture

**Files modified:** `src/lib/queries.ts` (tests as above)
**Commit:** `3e5a2e050`
**Applied fix:** Inside the reader, a non-null non-array `data` logs and captures once and returns `null` (every row unavailable). Rows without `strategy_id` or a string `exchange` are counted, then logged and captured ONCE per call (not per row) with `droppedRows` and `totalRows` in the Sentry extras. If no row survives the shape check (a renamed column) the whole payload is unavailable; if only some are bad, the good rows still label and the bad ones are skipped. A successful read with zero rows is legitimate (CSV and demo strategies) and raises no alarm.
