<objective>
Close the D-10 gap (founder 2026-10-14, quoted from 170.6.1-CONTEXT.md): "**When the venue read is unavailable, a Discovery row shows a muted "Venue unavailable" placeholder instead of a blank label.** It never falls back to the listed exchange, which was the SC-2 defect. The WR-01 fail-soft stays (no error boundary, one Sentry capture per call); only the rendered state changes. Ships as a follow-up plan in this phase."

Today `SyncBadge` computes `venueUnknown = !venueNames && tradeVenuesUnavailable === true`, sets `exchangeLabel` to null, and renders NOTHING in the label slot. This plan renders a muted `Venue unavailable` placeholder in that slot, keeps every other output of the badge (tooltip, dot, sentence, render gate per D-07) unchanged, and pins WR-01's one-Sentry-capture-per-call in `queries.ts` without editing `queries.ts`.

Purpose: SC-2 says a Discovery row names the venue its trades come from. When that cannot be known, a blank label reads as a layout bug; the placeholder says the truth, and must never regress into showing the listed exchange.
Output: one changed component, four test files with hand-typed assertions (no generated snapshot), each new behaviour seen RED on today's code before GREEN.
</objective>
