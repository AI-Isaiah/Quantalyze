## Warnings

### WR-01 (MEDIUM, confidence 6): the placeholder runs into the sentence, both on screen and for a screen reader

**File:** `src/components/strategy/SyncBadge.tsx:363-369`

**Issue:** The real label is told apart from the sentence only by its style: `font-medium
text-text-secondary`. Nothing in the markup separates them. "Bybit Trades fetched 2h ago" still
reads correctly because a one-word proper noun stands out. The placeholder is deliberately not
`font-medium` and has the same `text-text-muted` colour as the sentence (the badge's root is already
`text-text-muted`). Visually the badge now shows one undifferentiated muted string at 10 px:

- "Venue unavailable Trades fetched 9d ago · stale"
- "Venue unavailable No trade fetch recorded yet"
- "Venue unavailable Track record ends 20d ago"

The accessible text has the same problem. The dot is `aria-hidden` and there is no separator node,
so the badge is announced as "Venue unavailable Trades fetched 9 d ago, stale". "Venue unavailable
trades" can be heard as a single noun phrase, as if the trades were unavailable. The badge has no
`role`, `aria-label` or other grouping that would mark the first phrase as a label. A muted colour
was the right call under DESIGN.md, but it also removed the only cue that separated label from
sentence. No test pins any separation: every assertion checks the placeholder's own `textContent`
or strips it out (`sentenceOf`).

**Fix:** Put an explicit boundary after the placeholder, and only there, so the D-05 label path
stays byte-identical. The file's own `Separator` is the obvious choice: it gives a visible ` · `
and an sr-only comma.

```tsx
) : venueUnknown ? (
  <span data-venue-unavailable="" className="text-text-muted">
    Venue unavailable
    <Separator />
  </span>
) : null}
```

Alternatively, render the placeholder as `Venue unavailable:` and add an sr-only ", ". Add an
assertion that the badge's full `textContent`, including `.sr-only`, contains `"Venue unavailable,"`.
This makes the test fail if the boundary is removed. If the separator sits inside the
`[data-venue-unavailable]` span, update the exact `textContent === "Venue unavailable"` assertions
in the three test files, or move the `Separator` out as a sibling.

### WR-02 (MEDIUM, confidence 5): on a phone, the two-word placeholder can break across lines inside the pinned name cell

**File:** `src/components/strategy/SyncBadge.tsx:366`. Layout context:
`src/components/strategy/StrategyTable.tsx:1432` (`sticky left-0 ... max-w-[60cqw]`, not
`whitespace-nowrap`).

**Issue:** This phase is about the phone layout. Below `@3xl` the name cell is pinned at
`max-w-[60cqw]`, about 225 px on a 375 px phone. The badge is an `inline-flex` with no wrap, so each
child span is a flex item that shrinks and wraps its own text. Before this plan the label was a
single word ("Bybit", "OKX"), which flexbox cannot split. "Venue unavailable" is the first label
that can break, and at 10 px it competes for width with "Trades fetched 9d ago · stale". With
about 45 characters at about 5.5 px each, roughly 250 px, the likely result is "Venue" and
"unavailable" stacked in a narrow column next to a wrapped sentence. That makes the pinned row
taller and harder to read than any badge state before it. No test measures the badge at phone
width with the flag set: no e2e or default-mounts fixture carries `tradeVenuesUnavailable`. This
finding comes from reading the layout. I did not render it.

**Fix:** Add `whitespace-nowrap` to the placeholder span, so it breaks as a unit and never in the
middle. Then let the badge wrap between the label and the sentence instead of inside the label: add
`flex-wrap` to the SyncBadge root, or `@max-3xl:flex-wrap` if the D-05 path must stay byte-identical
above `@3xl`. Measure one crypto-sma row with `tradeVenuesUnavailable: true` at 375 px, the way the
phase's other phone checks are measured, and record the row height before and after.
