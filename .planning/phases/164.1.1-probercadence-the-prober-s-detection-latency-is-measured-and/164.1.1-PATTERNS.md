## Pattern Assignments

### `supabase/migrations/<ts>_prod_prober_cadence.sql` (migration, event-driven)

**Analog:** `supabase/migrations/20260911120000_vault_tick_hardening.sql` (canonical current body snapshotted at `supabase/schema/functions/match_engine_cron_tick.sql`)

**Core Vault+system_settings+pg_net pattern** (copy this shape verbatim, substituting the destination route and adding the staleness predicate):
```sql
CREATE OR REPLACE FUNCTION public.match_engine_cron_tick()
RETURNS BIGINT
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_catalog
AS $tick$
DECLARE
  v_key TEXT;
  v_cnt INTEGER;
  v_url TEXT;
  v_req BIGINT;
  c_url_allowed CONSTANT TEXT :=
    '^(https://[a-z0-9][a-z0-9.-]*\.up\.railway\.app|http://127\.0\.0\.1:9)$';
BEGIN
  SELECT count(*), max(decrypted_secret) INTO v_cnt, v_key
    FROM vault.decrypted_secrets
   WHERE name = 'analytics_service_key';
  IF v_cnt > 1 THEN
    RAISE EXCEPTION 'analytics_service_key is not unique in vault (% rows) — refusing to pick one', v_cnt;
  END IF;
  IF v_key IS NULL OR btrim(v_key) = '' THEN
    RAISE EXCEPTION 'analytics_service_key missing from vault — refusing to send a null header';
  END IF;

  SELECT s.value INTO v_url
    FROM public.system_settings s
   WHERE s.key = 'analytics_service_url';
  IF v_url IS NULL OR v_url = '' THEN
    RAISE EXCEPTION 'analytics_service_url missing from system_settings — refusing to post to a null url';
  END IF;

  IF v_url !~ c_url_allowed THEN
    RAISE EXCEPTION 'analytics_service_url in system_settings is not an allowed destination — refusing to post the analytics service key. The offending value is deliberately NOT echoed here; read it with an admin session. Allowed: an https host under .up.railway.app';
  END IF;

  SELECT net.http_post(
           url := v_url || '/api/match/cron-recompute',   -- swap for the new route
           headers := jsonb_build_object(
                        'Content-Type', 'application/json',
                        'X-Service-Key', v_key
                      ),
           body := '{}'::jsonb,
           timeout_milliseconds := 60000
         ) INTO v_req;
  RETURN v_req;
END
$tick$;
```

**What the new function must ADD beyond this template:**
1. A `SELECT MAX(completed_at) FROM public.cron_runs WHERE cron_name = 'prod_prober'` gap check
   (⛔ narrow by `cron_name`, never an unfiltered scan — see Anti-Pattern below), comparing against
   CTX-04's committed, dated ceiling constant.
2. Its OWN `cron_runs` self-observability write (self-liveness row), modeled on the "dormant tick"
   pattern in `enqueue_ledger_refresh_for_strategies.sql:215-241` — write a row only on the
   check/alarm tick, not unconditionally, to avoid unbounded table growth.
3. Only call `net.http_post` when the gap exceeds the ceiling — the Vault+system_settings+regex
   guard sequence above stays identical either way.

**RLS / GRANT pattern to copy** (`supabase/migrations/20260408113029_cron_heartbeat.sql`, lines ~62-90):
```sql
ALTER TABLE cron_runs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "cron_runs_admin_read" ON cron_runs
  FOR SELECT USING (
    EXISTS (SELECT 1 FROM profiles p WHERE p.id = auth.uid() AND p.is_admin = true)
  );
CREATE POLICY "cron_runs_service_role" ON cron_runs
  FOR ALL USING (auth.role() = 'service_role')
  WITH CHECK (auth.role() = 'service_role');
```
`prod_prober_cadence_check()` needs the SAME `SECURITY DEFINER` + restricted-`EXECUTE` treatment
`latest_cron_success` and `match_engine_cron_tick` already carry (service_role/admin EXECUTE only).

**Error-message discipline (copy exactly):** name the SETTING that is missing/invalid, never its
value — `RAISE` text lands in `cron.job_run_details`, Postgres logs, and downstream shippers, and
this repo is public.
