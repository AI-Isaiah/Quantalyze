<objective>
PR-2b-2, the SQL twin. CR-01 named `commit_scenario_batch`'s `owner_keys` / `account_edges` / `reach` as the third twin. It joins on `venue_norm` alone, so after migration B one owner's same login on two servers is one account here while the browser (plan 15) counts two. The precondition then refuses every book-mode commit by that owner as `portfolio_fingerprint_stale`. CONTEXT Q6 item 1 requires all three twins to move together.

The rule is the one plan 14's objective states. In SQL, over `owner_keys` (every key of p_allocator_id, no liveness filter, the same set as the other twins):
- `server_norm` = NULLIF(venue_server, ''), with no trim or case-fold (the CHECK refuses blank and every writer stores the normalised form).
- `login_servers` = per (exchange_norm, venue_norm), count(DISTINCT server_norm) and the single server when the count is one.
- `identity_server` = server_norm when set; '' when the login carries no server; the single server when it carries one; NULL when it carries two or more (ambiguous).
- The first `account_edges` arm joins on exchange_norm, venue_norm AND identity_server, all non-null.
- `known_account` takes keys with venue_norm and identity_server both non-null, plus the marker edges.
An ambiguous key falls through to `'key:' || id`, which is what `keyAccountOf` and the scorer give.
