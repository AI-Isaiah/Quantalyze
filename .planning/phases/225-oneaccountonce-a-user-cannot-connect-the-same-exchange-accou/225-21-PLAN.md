Q2, the except chains, read at HEAD 6a1a0adfc by symbol (the review's line numbers are stale). `Mt5ServerMismatchError` subclasses `Mt5AccountMismatchError`, a plain `Exception`, and `classify_exception` answers `('unknown', <fixed text>)` for it (measured with a one-line import at planning time). The three sites differ, and each disposes of it as no-stamp, no-persist, transient:
- Derive (`run_derive_broker_dailies_job`, the MT5 branch): PRE and POST raise inside the one `try` around `asyncio.wait_for(asyncio.to_thread(read_mt5_deal_ledger, ...))`. - Balance (`_fetch_mt5_account_balance._read`): the swallow-all `except (asyncio.TimeoutError, Exception)` logs `exc_class=Mt5ServerMismatchError` and returns None, so the sync completes without a balance snapshot (`advance_sync_cursor` gets a NULL balance and its COALESCE keeps the stored value). That status write is what a login mismatch already does, and the booked scope keeps every disposition unchanged; note that D-18 counts `sync_status='error'` as not working, which is why Task 3 reads the cycle after deploy.
