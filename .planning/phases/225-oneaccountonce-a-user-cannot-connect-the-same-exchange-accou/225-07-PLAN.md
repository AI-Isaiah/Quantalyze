<objective>
The wizard connect route enforces one account per owner with the server in the identity and the failing-holder carve-out. Per D-01 the refusal still rides the one partial index (no second index); per CONTEXT Q1 (founder: "Admit working key") a non-working holder gives up its slot to a validated new key; per D-25 / MT5D-08 a failing key never keeps the slot; per Q2 (CONN-03) the server is written and compared with the null wildcard; per Q3 (ONCE-02) the refusal is per owner.

OQ-2, the minimal correct behaviour, stated (RESEARCH recommends logging it for the founder, not deciding it in code): a demoted key that later recovers STAYS marked duplicate of the working holder while that holder works. The only automatic move back is MT5D-08 itself: if the holder later fails while the demoted key works, the stamper moves the slot back (plan 09). If a demoted key still carries its own strategy, the executor lists that shape under "For the founder" in the SUMMARY. This is the shape Q1 accepts.
