<objective>
Migration A2: the one SQL function that lets a working key take an account's holder slot from a failing same-owner key (founder ruling Q1 "Admit working key", D-25 / MT5D-08). The connect routes (plans 07, 08, 11) and the poll stamper (plan 09) both call it; neither PostgREST client can write the slot and the marker in one transaction, and a sequence of separate calls leaves a window where a marked sibling's poll steals the freed slot (RESEARCH "Pattern: one shared swap function").

The SQL surface is frozen here because PR-2 carries no migration: the signature is `swap_account_slot(p_new_key uuid, p_old_holder uuid, p_venue_account_id text, p_venue_server text DEFAULT NULL) RETURNS void`. The caller passes the login and server explicitly (the function does not read them off the new row), the function refuses with a stable token, and the caller audits and enqueues the recompose itself.
