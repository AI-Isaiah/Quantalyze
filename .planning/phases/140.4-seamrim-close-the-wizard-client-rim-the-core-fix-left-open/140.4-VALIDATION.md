  rule, no tuning, **the first honest mutation is the recorded result**.

## Falsifiability Ledger

> **Coverage answers "is it verified?". This section answers "CAN the verification FAIL?"**

**Rules (binding).** The mutation is a **semantic** edit to **PRODUCTION** source — a value, a
boundary, a branch direction. **Never a syntax error. Never a type error. Never a test edit.** Each row
must be OBSERVED red first-hand and reverted, with the failing test name and assertion text pasted.
**"Asserted — not observed" is not acceptable.** Where a class has more than one member, **mutate the
SECOND** — that is what detects an instance-fix masquerading as a class-fix.

*Why this is not ceremony:* Phase 140 certified "5/5 mutation-tested" while **ten simultaneous
semantic mutations** produced a byte-identical `8859 passed | 287 skipped`.

⚠️ **ONLY A POSITIVE CASE CAN FALSIFY A CARRY.** A deleted carry and a correct absence both produce
`null`; an inert guard and a clean codebase both produce *"no violation"*. Where a row's subject is an
**absence**, the mutation must make the guard **present but unreachable** rather than deleting it —
that is the shape that distinguishes LIVE from INERT. Rows **M90, M94, M97, M98, M103** use this form
by design; each says so in its own plan.

**Rows are recorded in each plan's own SUMMARY**, under a `## Falsifiability Ledger — row(s) Mxx`
heading — **not** in this file. Four wave-1 plans run in parallel and a shared ledger file would race.
This file is the **assignment table and the completeness contract**; the gate collects the receipts.

**Numbering.** The highest pre-existing row in the programme is **M89** (`140.3-G2`). This phase takes
**M90–M108 plus M95b** — **20 rows**, one owner each, zero collisions. M107 and M108 were added at
re-check, when two entries in the no-row table below were shown to be falsifiable after all.

## Oracle Independence

- [ ] No test imports a **constant** from the module it tests — expected values are **literals** in the test
- [ ] No assertion compares a value to itself via a re-export, fixture, or table under test
- [ ] Table/registry sizes are pinned to a **literal count**, never to `len(THE_TABLE)`
- [ ] Any fake/double is pinned against the real contract it stands in for
- [ ] **`vi.spyOn` + `vi.restoreAllMocks()` in every new file that stubs; NEVER `vi.stubGlobal`** (DEF-16-1)
- [ ] **Every set equality has a vacuity fence beside it** — a scanner that matches nothing reports
      agreement forever, which is how a source guard becomes worse than none
- [ ] **Every acceptance grep in every plan was measured on the UNTOUCHED tree before it was written**

**Named hazards for this phase:**

1. **`EXPECTED_TABLE_SIZE = 55`, hand-typed at TWO sites in `src/lib/wizardErrors.test.ts`.** It must
   stay a literal. Replacing it with `Object.keys(WIZARD_ERROR_COPY).length` is hazard #3 in its
   classic form and is forbidden by `140.3-10` and `140.3-12`.
   ⚠️ **This phase's plan set nearly deleted both guards.** A draft criterion in `140.4-03` read
   `grep -cE "Object\.keys\([A-Za-z_]*\)\.length" src/lib/wizardErrors.test.ts` → 0. Measured on the
   untouched tree it is **3**: one is the file's own comment *"Deliberately NOT
   `Object.keys(WIZARD_ERROR_COPY).length`"* (the rule matching its own grep), and **two are the
   correct assertions**. The criterion exited 1 on correct code and was satisfiable only by deleting
   the oracle. **Corrected before execution; recorded here because the near-miss is the lesson.**
2. **`CONTRACT_GUARDS`' floor must be hand-typed** — `toBeGreaterThanOrEqual(CONTRACT_GUARDS.length)`
   is an assertion that can never fail (plan `140.4-10`).
3. **The eslint-plugin expected rule set must be hand-typed** — never `Object.keys(plugin.rules)`
   (plan `140.4-14`).
4. **The 5xx `QUARANTINE` must be hand-typed, then re-derived and diffed** before commit. Copying the
   tree's answer into the roster makes the roster a copy of the thing it measures (plan `140.4-04`).
5. **The derived-roster equality must compare a from-disk derivation to a HAND-TYPED roster**, never
   derivation-to-derivation. Two scanners agreeing with each other is not evidence (plan `140.4-10`).
6. **Wizard copy assertions must hand-type the expected sentence** — reading `WIZARD_ERROR_COPY[code].title`
   on the expected side of an `expect` is the defect (plans `140.4-11`, `140.4-12`).
7. **Sixteen route test files `vi.mock` the seam clients wholesale**, and **six** mock
   `@/lib/ratelimit`. Anything reached through such a module evaluates to `undefined` and throws from
   inside a catch block. Plan `140.4-13` **extends** those factories; it must not delete them.
8. **`vi.mock` factories do NOT re-run on `vi.resetModules()`** (measured, vitest 4.1.10). No negative
   control in this phase may rest on the opposite premise.
9. **⚠️ NEW, and it is this phase's own lesson: an acceptance value is a claim about the untouched
   tree, and a bare integer without its predicate is unowned by construction.** **Four** criteria in
   drafts of this plan set were wrong in exactly this way — one had a pre-value of **24** where **3**
   was claimed, with a post-condition (`≥ 10`) an untouched tree **already satisfied**; one exited 1 on
   correct code and was satisfiable only by deleting the oracle; one counted a file's own docblock; and
   **M108's own blind-spot constant read `3` while its description read as `4`** — a row written to fix
   the previous instance, carrying the next one.
   ⇒ **Every numeric assertion in this phase must be published WITH the predicate that produced it**,
   and re-measured under that predicate rather than a paraphrase of it. CONTEXT §5c states the rule;
   the fourth instance is why it is repeated here as a hazard rather than a principle.
   **Ask of every criterion: could a broken or untouched implementation return this same value — and
   could an honest executor, reading my description, measure something different from what I measured?**
10. **grep is LINE-BASED** (DEF-16-2) and **`grep -h` with a downstream filename filter is a NAMED
    PROHIBITION** (it produced three wrong counts). Comment-strip before counting; use `grep -F` for
    paths containing `[id]`.
