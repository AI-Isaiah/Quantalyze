## 2. Every measured value, WITH the predicate that produced it

> A bare integer is unowned by construction. This is the phase's own lesson (Oracle Independence
> hazard #9), so nothing below is published without its definition.

**THE SCANNER'S PREDICATE (strict), the definition every count is measured under:**

> An `ast.Call` whose `func` is an **`ast.Name`** with `id ∈ {"HTTPException", "JSONResponse"}` — a
> **direct constructor call by that bare name** — found by walking `routers/**/*.py`,
> `services/**/*.py` and `main.py`, skipping any path containing a `tests` segment. Status is
> resolved from a `status_code=` keyword, else the first positional argument, and accepted only when
> it is an `ast.Constant` integer (`bool` excluded).

| Value | Predicate | Measured | Where pinned |
|---|---|---|---|
| **12** | above, literal status `>= 500` | 12 | `EXPECTED_SITE_COUNT` |
| **9** | distinct `(module, function, status)` triples of the above | 9 | `EXPECTED_TRIPLE_COUNT` |
| **3** | of those triples having count > 1 | 3 | `EXPECTED_DUPLICATED_TRIPLES` |
| **88** | files matched by the three roots, minus any `tests` path segment | 88 | vacuity fence, floor 30 |
| **72** | matched constructions where `constructor == "HTTPException"`, **any** status | 72 | vacuity fence, floor 1 |
| **84** | all matched constructions = 81 literal + 3 non-literal + **0** absent | 84 | `test_the_scan_sees_far_more_than_the_5xx_it_reports` (84 > 12) |
| **3** | matched constructions carrying a `status_code=` keyword whose value is **not** an integer literal — **STRICT** | 3 | `EXPECTED_NON_LITERAL_STATUS_SITES` |
| **4** | any `status_code=` keyword, **any callee** — **LOOSE** | 4 | `EXPECTED_NON_LITERAL_STATUS_SITES_UNDER_LOOSE_READING` |
| **1** | `ast.ClassDef` with an `HTTPException` base in the scanned roots | 1 (`VenueTransientHTTPException`) | `EXPECTED_HTTPEXCEPTION_SUBCLASSES` |
| **7** | `ast.Call` with an `ast.Name` func naming that subclass | 7, **all 424** | `EXPECTED_SUBCLASS_CONSTRUCTION_SITES` |

**The strict/loose gap is exactly one site**, and it is the reason the predicate says `ast.Name`:
`services/error_contract.py`'s `VenueTransientHTTPException.__init__` calls
`super().__init__(status_code=status_code, detail=detail)`. Its `func` is an `ast.Attribute`, so it
is **not a matched construction**. Both numbers are honest; they measure different things. **I did
not "fix" the constant and did not report a disagreement.** The `+1` relationship is itself asserted,
so if the gap ever stops being that single `super().__init__`, both must be re-measured.

The **0 absent** bucket matters: every matched construction resolves to either a literal or a
non-literal status, so the three-way classification is exhaustive and there is no unclassified
remainder hiding a site.

## 3. The four non-500 members, each with a recorded reason

`_validate`: *"the only permanent 5xx in this contract is 500, got {status}; a transient fault is
503, an exchange fault is 424."* All four survivors are 503, and each is listed in `NON_500_REASONS`
so it reads as a **decision** rather than an exemption. `test_no_reason_is_recorded_for_a_site_that_no_longer_exists`
forces the mapping to shrink with the tree.

| member | reason |
|---|---|
| `main.py` / `health` / 503 | Worker heartbeat is STALE while the web process is alive. 503 is the transient status uptime probes and load balancers act on; a 500 would read as a crashed app. Degraded, not broken. |
| `debug_key_flow.py` / `_verify_internal_token` / 503 | `INTERNAL_API_TOKEN` unset. A missing platform secret is an operator **configuration** fault fixed by setting the variable — transient by the contract's definition. Testnet-only debug router, not on any user path. |
| `debug_key_flow.py` / `_read_test_creds` / 503 | `DEBUG_KEY_FLOW_<BROKER>_{KEY,SECRET}` unset. Same class as its sibling. |
| `exchange.py` / `fetch_trades` / 503 | `get_kek()` raised — KEK not configured, so no stored key decrypts. Transient in the same configuration sense. |

### ⚠️ One genuine inconsistency found and RECORDED, not silently normalised

`cron.py`'s `cron_sync` raises **500** for the *identical* KEK-missing condition that
`exchange.py`'s `fetch_trades` answers **503** for — and `cron.py` states its reasoning in a comment
(*"the cron runner only alarms on non-2xx; a 200 body with `error:` is silently treated as
success"*). Two statuses for one fault. This is a real wrinkle to settle when these sites are
re-homed onto `service_error()`; **re-homing is explicitly out of this plan's scope (TRAP-8)**, so it
is written into `NON_500_REASONS` where the next author cannot miss it, rather than changed here.

## 4. The needle self-test — 7 assertions, both polarities

All exercise the **same** `scan_source` the census uses; a needle testing a second copy of the logic
would prove nothing about the scanner that produces the census.

**Positive (3):**
1. `test_positive_a_single_line_keyword_raise_is_detected`
2. `test_positive_a_status_on_a_CONTINUATION_LINE_is_detected` — **the shape a line-based grep
   misses**, and the shape that produced this programme's earlier census of 9 instead of 12. Two real
   sites are written this way (`cron.py:630`, `debug_key_flow.py:99`).
3. `test_positive_a_POSITIONAL_status_is_detected` — `HTTPException(503)`

**Negative (4):**
4. `test_negative_a_COMMENTED_OUT_raise_is_NOT_detected` — a `# raise HTTPException(500)` comment.
   `services/job_worker.py` carries exactly this shape; a grep counts it, the parser cannot see it.
5. `test_negative_a_legitimate_4xx_is_NOT_detected` — and it asserts the 404 **is still seen as a
   construction**, so a scanner that broke would not be mistaken for a filter working.
6. `test_negative_a_super_init_status_code_is_NOT_a_matched_construction` — the `ast.Name` vs
   `ast.Attribute` line made concrete; this is the whole strict-3 / loose-4 difference.
7. `test_negative_a_string_mentioning_the_constructor_is_NOT_detected`

The negative half is the load-bearing one: a scan that flagged a comment or a legitimate 4xx would be
"fixed" by weakening it, and the weakened version would then miss the real thing.

## 5. Vacuity fence

A scanner that matched nothing would report agreement with the quarantine forever.

| Bound | Constant | Actual |
|---|---|---|
| files scanned | `MIN_FILES_SCANNED = 30` | **88** |
| `HTTPException` calls found at **any** status | `MIN_HTTPEXCEPTION_CALLS_ANY_STATUS = 1` | **72** |

Floors are deliberately loose: their job is to catch *"matched nothing"*, not to pin a tree size that
churns and turns the guard into a maintenance tax. A second, tighter fence
(`test_the_scan_sees_far_more_than_the_5xx_it_reports`) asserts total constructions (**84**) strictly
exceed the census (**12**), so the `>= 500` filter is provably doing work.

## Coverage-law classification (CONTEXT §2 — binding)

- **ROW 1 for the population.** It is derived from source by an `ast` walk, so a raw 5xx added
  tomorrow in a file nobody thought of is inside the census **by construction**.
- **ROW 2 for the quarantine mapping — and it is therefore PARTIAL BY CONSTRUCTION.** Stated in those
  words, as §2 requires. It is acceptable here, and only here, because it is a roster of **known
  offenders** (which can only shrink) rather than of **protected sites** (which could silently omit
  one), and because the comparison is `==` rather than containment, so a repair cannot leave a stale
  exemption behind.
