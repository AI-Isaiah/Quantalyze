verdict*) pins this green, and it is the case that stops every absence assertion in the receipt

## An oracle near-miss in my OWN receipt, caught by the pre-fix run

The receipt first used the envelope **title** — "We could not verify this strategy" — as the
needle for the escalation case. Run against the **unfixed** tree it reported that case
**GREEN**, because `ErrorEnvelope` renders that identical title for `SYNC_FAILED`,
`GATE_INSUFFICIENT_TRADES` **and** `GATE_NO_DATA_SOURCE` alike. A needle matching three
different states cannot testify about any one of them; it would have certified an escalation
that was not happening.

Fixed before the RED commit by moving the needle to the rendered diagnostics line
(`code: SYNC_FAILED`, `code: GATE_NO_DATA_SOURCE`), which is unique per state, hand-typed, and
never read off `WIZARD_ERROR_COPY`. The reasoning is recorded in the file beside the constant.

**This is only visible because the receipt was run on the pre-fix tree first.** A receipt
written after the fix would have been green on the first run and the bad needle would have
shipped. That is the argument for the inverted task order, made concrete.
