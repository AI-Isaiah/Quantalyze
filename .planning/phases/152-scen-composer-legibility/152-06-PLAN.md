Binding rules for this plan:
- NO new fetches (CONTEXT lock): the panel renders only what is in memory. Null
  metrics → honest "not available"; no loading state exists by construction.
- Keyboard criteria are phrased "Enter/Space on the focused strategy-name
  button" — NEVER "on the focused row" (UI-SPEC acceptance-phrasing rule; the
  row container is deliberately not focusable).
- Do NOT mirror HoldingsTable's a11y (`<tr onClick>` + aria-expanded on a bare
  tr is pointer-only and invalid ARIA — Pitfall 5). Mirror only the host idiom:
  parent-owned `useState<string | null>`, `prev === id ? null : id` toggle.
- Do NOT put `role="button"`/`tabIndex` on the row li (nests interactive
  controls — UI-SPEC forbids).
- Factsheet-link honesty bound (Pitfall 6): the link resolves for the viewer's
  own strategies and currently-published third-party ones (OWN-02 two-lane). A
  stale persisted draft pointing at a since-archived/deleted third-party
  strategy CAN 404 — detecting it would need a fetch, which is locked out.
  Acceptance is scoped accordingly; on completion, log the stale-draft residual
  to TODOS.md as a deferred item (one line, non-blocking).
- Pinned interaction decisions (record in code comments):
  a) li onClick = pointer amplification (UI-SPEC Contract 2 as amended
     2026-08-07). The exclusion set has THREE parts, because the row's LEFT
     cluster (:6250) sits OUTSIDE the control-cluster wrapper:
       (1) ONE stopPropagation wrapper on the control-cluster div (:6279);
       (2) `e.stopPropagation()` inside the name button's own onClick, BEFORE
           its toggle (checker B-1): the name button lives in the left cluster,
           so its click bubbles into the li amplification — both handlers run
           the same functional toggle and one click nets to a no-op; the panel
           would never open by pointer OR keyboard (native button Enter/Space
           dispatch click). stopPropagation on the button is preferred over
           gating the li handler;
       (3) stopPropagation on the include/exclude `role="switch"` toggle
           (:6252) (checker B-2): it is an excluded control per CONTEXT/UI-SPEC
           but also lives in the left cluster, outside the wrapper;
     PLUS stopPropagation on the detail-panel container itself — a deliberate
     addition beyond UI-SPEC's enumeration: the panel is new DOM inside the
     clickable li, and a panel that collapses when you click its own content
     (e.g. selecting a metric) defeats its purpose; the factsheet link stays
     clickable.
  b) Clicking the series-state notes / solve-state line (also inside the li)
     toggles the detail — accepted (non-interactive prose; Pitfall 5 pin).
  c) Null provenance in the panel renders an explicit `—` (TrustTierLabel
     renders nothing for null — a labelled empty space is not honest absence).
