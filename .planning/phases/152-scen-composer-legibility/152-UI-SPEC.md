# Phase 152 — UI Design Contract

> Visual and interaction contract for Phase 152 (SCEN — Composer legibility).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope of UI surface: `ScenarioComposer.tsx` added-strategy rows (ownership chip,
> click-to-detail, header label row, honest notional), a row-detail expansion
> mirroring the `HoldingsTable` → `HoldingDetail` idiom, and
> `StrategyBrowseDrawer.tsx` (duplicate disambiguation secondary line).
> Sources: 152-CONTEXT.md (locked decisions), DESIGN.md (binding token system),
> ROADMAP Phase 152 SCs, REQUIREMENTS SCEN-02..05, 151-UI-SPEC.md (prior approved
> contract on the SAME component), live post-151 composer/browse/holdings code.
>
> ⚠️ Phase 151 reshaped this component (AUM input, per-row dollar input,
> partial-book note). Every contract below COMPOSES with 151's shipped elements —
> nothing here restyles, moves, or relabels a 151 element. All REQUIREMENTS line
> anchors predate 151; locate by symbol.

string (`inline-flex items-center rounded-md px-2 py-0.5 text-caption
font-medium`, `OwnershipTag.tsx:35`) reused for the "Yours" chip. This
consciously supersedes 151's "no new 500-weight text" rule for this one element,
because CONTEXT locks visual consistency with the Phase-150 mark tag — forking a
400-weight near-duplicate of an existing badge family would be the worse
deviation. No other new element may use 500, and nothing new uses 600.

**Size note:** the chip's `text-caption` was evaluated against `text-xs` to keep
the surface at 4 sizes — but the ANATOMY string pins `text-caption`, so
byte-verbatim reuse wins: the 5th size arrives via the locked anatomy, not as a
new sizing decision. Any future change to the chip size must go through
`OwnershipTag`, not a fork.

Raw-px lint: `no-raw-font-px` is repo-wide `error` — tier classes and
`--text-fixed-*` tokens only.

**Honesty invariants (acceptance-greppable):**
- A row with `isOwn` absent/undefined renders NO chip — absence is honest; never
  fabricate ownership for pre-existing persisted drafts (CONTEXT lock).
- The disambiguation line renders ONLY on rows in a detected own-row name
  collision — never on every own row (it is a tiebreaker, not a metadata dump).
  Rows missing the disambiguation fields (older wire shape) render no line.
- The detail panel never invents a metric: null → `—`, both-null → the
  metrics-absent note. No spinner, no "loading" — there is nothing to load.
- The factsheet link always resolves (OWN-02 shipped in 148: owner sees own
  factsheet, published resolves for everyone) — never a `notFound()` dead end.

**Acceptance-phrasing rule (binding on planner):** keyboard-activation criteria
must be phrased "Enter/Space on the focused strategy-name button" — never "on
the focused row". The row container is not focusable (see Component Contract 2);
a row-focus criterion would test an affordance the contract forbids.

## Component Contracts (phase-specific)

### 1. "Yours" ownership chip (SCEN-02)

- **Placement:** in the added-strategy row's name cluster, after `TrustTierLabel`
  and before `CoverageStateChip` (name → provenance → ownership → coverage:
  identity facts before derived state), `shrink-0`.
- **Anatomy (byte-verbatim from `OwnershipTag.tsx`):**
  `inline-flex items-center rounded-md px-2 py-0.5 text-caption font-medium`
  + ink `bg-badge-other/10 text-text-muted`. The `rounded-md` badge family is
  the persistent-fact family (Phase-150 reasoning: identity carried by ink, not
  shape); the uppercase `rounded-sm` family is for derived state and is wrong here.
- **Component decision:** a small dedicated render (inline span or tiny sibling
  component) — do NOT widen `OwnershipTag`'s closed switch (its T-150-08
  spoofing rationale depends on the switch staying closed over
  `CapitalOwnership`), and do NOT route through `Badge` (its unrecognized-label
  fallback renders a trusted-looking Draft badge).
- **Render rule:** iff `isOwn === true` on the `AddedStrategy`. `false`,
  `null`, `undefined` (legacy draft) → nothing.
- **Browse overlay parity:** the same chip may render on own rows in
  `StrategyBrowseDrawer` next to the name (same anatomy) — planner's call; if
  rendered there it must be identical, not a second recipe. It is NOT a
  substitute for the SCEN-05 disambiguation line (both duplicate rows are own
  rows — a chip cannot disambiguate them).
- **Wire (recorded for the planner, per CONTEXT locks):** additive optional
  `isOwn` on the browse route's named-key row fence AND on `AddedStrategy`
  (zod optional/nullish, NO `SCENARIO_SCHEMA_VERSION` bump — 151-06
  `manualAumUsd` precedent; a v4 blob without the field must never reset the
  draft).

### 2. Row click → detail expansion (SCEN-03)

- **Pattern:** the `HoldingsTable` → `HoldingDetail` idiom — an INLINE expansion
  panel, not a modal and not a right-edge slide-out. One open at a time, parent
  owns the open id (`HoldingDetail` "one-open-at-a-time is owned by the parent"
  precedent). Do not fork a second drawer idiom.
- **Host anatomy:** expansion renders inside the row `<li>`, below the main row
  line, behind an interior hairline: `mt-2 border-t border-border pt-3`
  (mirrors HoldingDetail's `bg-surface p-3` host; the li already carries
  `bg-surface` context and `p-3`). Square interior — no nested card, no shadow
  (data panel, not a card).
- **Click target + a11y (CONTEXT locks, mechanism pinned here):**
  - The strategy NAME renders as a `<button type="button">` carrying
    `aria-expanded` + `aria-controls="scenario-detail-{id}"` — this is the
    keyboard-reachable affordance (Enter/Space activate the focused
    strategy-name button natively, because it is a real button).
    Do NOT put `role="button"` + `tabIndex` on the row container: it would nest
    the toggle/inputs/remove button inside an interactive role (a11y violation).
  - The row SURFACE additionally toggles on pointer click (`onClick` on the
    li) as pointer amplification. AMENDED 2026-08-07 (post-approval, checker
    B-1/B-2): the original "one `stopPropagation` wrapper on the cluster
    container" premise was wrong — the row's LEFT cluster holds two controls
    OUTSIDE that wrapper. The exclusion set is THREE parts:
    (1) ONE `stopPropagation` wrapper on the control cluster (weight, dollar,
    mode, target, leverage inputs, remove button) — still not per-control;
    (2) `e.stopPropagation()` inside the strategy-name button's own onClick,
    before its toggle — otherwise the li amplification re-runs the same
    functional toggle and one click nets to a no-op (the panel could never
    open by pointer or keyboard, since native button Enter/Space dispatch
    click);
    (3) `stopPropagation` on the include/exclude `role="switch"` toggle, which
    also sits in the left cluster and is an excluded control.
  - Name hover affordance: `hover:text-accent transition-colors` (StrategyTable
    factsheet-link precedent) so the row reads clickable; row surface may add
    the existing table-row `hover:bg-page/50` tenant. No cursor-only affordance.
- **Detail content (ONLY in-memory data — NO new fetches, locked):**
  - Mono eyebrow labels (`font-mono text-fixed-10 uppercase tracking-[0.18em]
    text-text-muted`): `PROVENANCE`, `MARKETS`, `TYPES`, `CAGR`, `SHARPE`.
  - Values: provenance via the existing `TrustTierLabel`; markets /
    strategy_types as `·`-joined DM Sans `text-xs`; CAGR signed 1dp percentage,
    Sharpe 2dp ratio, both `font-mono` right of their eyebrows, via the
    surface's formatter module: `formatPercent` (already imported in
    `ScenarioComposer.tsx`) and `formatNumber` (NEW import from `@/lib/utils` —
    exists at `utils.ts:27`, already used by `HoldingDetail`) — never an inline
    `toFixed`; one formatter module per surface.
  - Metrics source: `addedStrategyMetadataLookup` (book strategies carry
    cagr/sharpe; drawer-added carry null → `—` / metrics-absent note).
  - "View factsheet →" link: `href={`/factsheet/${id}`}` (StrategyTable:974
    convention), `text-accent hover:text-accent-hover text-sm`, rendered last.
    The link is the FOCAL POINT of the expanded state — the panel's single
    accent element and its only action; everything above it is muted context
    leading to it.
- **Not in the detail:** no tabs (HoldingDetail's 3 tabs serve holdings-specific
  jobs — Record outcome / Notes have no composer analog; mirroring the HOST
  idiom, not the tab chrome, is the reuse), no close button beyond re-clicking
  the name (aria-expanded toggle), no duplicate of the row's weight controls.

### 3. Header label row (SCEN-04)

- **Placement:** exactly ONE instance, mounted directly above the
  ADDED-STRATEGIES group — i.e. immediately below the `Strategies added · N`
  separator li (`ScenarioComposer.tsx`, locate by that string) and above the
  first added-strategy row. Never repeated per sub-group.
- **Deliberate scope call:** book-holdings (per-key) rows carry NO column
  labels. Post-151 code has diverged the two row shapes: per-key rows have no
  dollar input and no remove (`×`) button, added-strategy rows have both — a
  single header above the first constituent row would drift ~104px off its
  columns over every book-holdings row. All four SCEN-02..05 elements live on
  added rows; the header labels the group it actually aligns with.
- **Anatomy:** the composer mono-eyebrow recipe byte-verbatim:
  `font-mono text-fixed-10 uppercase tracking-[0.18em] text-text-muted`.
- **Labels + alignment:** `WEIGHT` `USD` `MODE` `LEV` `NOTIONAL`, each label
  sized to its column's fixed width and right-aligned over it, laid out with the
  SAME `gap-2` flex as the added-row control cluster plus a trailing spacer
  matching the remove (`×`) button — widths mirror the live inputs: `w-20`
  (weight), `w-24` (dollar), mode-toggle width, `w-16` (leverage), `w-20`
  (notional). Alignment is the contract: a header that drifts off its columns
  is worse than no header.
- **Why five labels, not CONTEXT's four:** CONTEXT pinned the set
  WEIGHT · MODE · LEV · NOTIONAL but delegated exact copy to this spec, and
  Phase 151 shipped a per-row USD allocation input BETWEEN weight and mode. A
  four-label header would sit misaligned over five columns and silently label
  the dollar input as part of WEIGHT — fighting 151 instead of composing with
  it. `USD` is the honest fifth label. (Target-mode's conditional drawdown
  input is a sub-control of MODE and gets no column label.)
- **A11y:** the header row is presentational — `aria-hidden="true"`. Every
  control already carries its own accessible name (`sr-only` labels /
  `aria-label`s); announcing the eyebrow strip would duplicate them.
- **Render rule:** renders whenever ≥1 added-strategy row renders (i.e.
  whenever the `Strategies added · N` separator renders); hidden when no
  strategies are added.

### 4. Honest non-derivable notional (SCEN-04)

- The existing derived notional span keeps its recipe and its derived-state
  `title` verbatim. ONLY the non-derivable state changes: when `notionalText`
  yields `—`, the span's `title` becomes `"Set portfolio AUM to size in
  dollars"` and an `sr-only` span carries the same sentence — 151's exact
  em-dash pattern (`title` alone is unreachable by keyboard/touch). The dash
  stays colorless. Result: the em-dash reads "not applicable, here is the
  remedy", never "broken".

### 5. Browse duplicate disambiguation line (SCEN-05)

- **Trigger:** two or more OWN rows in the same browse result whose rendered
  names match (normalized: trim + case-insensitive). ALL rows in the collision
  set get the line. Third-party rows never trigger it (pseudonymised labels are
  synthetic; and the founder's case — two private "Alpha Centauri" rows — is
  own-vs-own).
- **Placement:** a second secondary line directly below the existing
  codename/markets line inside the row's `min-w-0` text block.
- **Anatomy:** the sibling line's recipe verbatim — `mt-1 text-xs
  text-text-muted`, `·` separators. `data-testid="browse-dedup-{id}"` (outside
  the `browse-add-` namespace — the PR #620 automation-contract lesson).
- **Copy:** `Created {Mon D, YYYY} · {Status}` (see copy table — AMENDED
  2026-08-07, D-1: the key-count segment is omitted entirely; `key_count`
  never reaches the wire). `created_at` and status always render (both always
  exist on an own row); rows missing the fields (older wire shape) render no
  line.
- **DISAMBIGUATE, never hide (locked):** no collapsing, no destructive merge,
  no "(2)" suffix on names. Both rows stay; the line makes the choice
  resolvable at a glance.
- **Wire (recorded for the planner):** additive optional fields on the browse
  row fence, emitted for OWN rows only (owner's own metadata — no disclosure
  widening): `created_at` (ISO date), `key_count` (number), `status`
  (product-cased by the client, raw enum on the wire). Named-key fence stays a
  named-key fence — no `...row` spread.
