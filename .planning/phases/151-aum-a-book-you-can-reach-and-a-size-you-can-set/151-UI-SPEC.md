# Phase 151 — UI Design Contract

> Visual and interaction contract for Phase 151 (AUM — a book you can reach and a size you can set).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope of UI surface: `ScenarioComposer.tsx` (direct AUM input, per-strategy dollar
> input, refusal copy, "From my book" segment + partial-book note) and the
> user-visible `sync_error` column rendered by `AllocatorSyncStatus.tsx`
> (human-readable sync copy — never a raw Python exception).
> Sources: 151-CONTEXT.md (locked decisions), DESIGN.md (binding token system),
> ROADMAP Phase 151 SCs, REQUIREMENTS AUM-01..05, live composer code.
>
> Focal point: the Portfolio AUM input is the primary anchor of the composer summary
> region; the per-strategy dollar inputs are secondary and read as a column. This is a
> surgical change to an existing dense screen — conform to its existing hierarchy.

  rule; the dollar input inherits it when AUM is unset).
- No new colors. No gradients. No icons-in-circles.

## Copywriting Contract

Voice (DESIGN.md): declarative, sentence case, active, states the limitation with the
remedy attached, no adjectives where a number exists. Em-dash `—` (U+2014) is the
permitted separator glyph.

| Element | Copy |
|---------|------|
| Primary CTA | "Commit scenario" (existing footer button — unchanged) |
| AUM input label (mono eyebrow) | `PORTFOLIO AUM (USD)` |
| AUM input helper, blank mode + empty | "Required to size and commit." (muted, `text-xs`) |
| AUM override note, book mode + edited away from live sum | "Overrides live-holdings total {formatUsd(liveSum)}." (muted, `text-xs`) |
| AUM-zero refusal — book NOT reachable | "Can't record a scenario commit: portfolio AUM is not set. Set portfolio AUM before submitting." |
| AUM-zero refusal — book reachable (`canEnterBook`) | "Can't record a scenario commit: portfolio AUM is not set. Set portfolio AUM, or switch to \"From my book\", before submitting." |
| Partial-book note (book mode, ≥1 eligible key without per-key dailies) | "{N} of {M} keys not yet contributing — no per-key history yet." |
| Dollar input, AUM unset (read-only state) | value renders `—`; `title="Set portfolio AUM to size in dollars"` |
| Weight-clamp banner (reused verbatim, existing) | "Weight clamped to 1 — the maximum allocation is 100% of portfolio AUM." |
| Empty state | No new empty state — the existing blank-slate composition list and the AUM helper line cover it. |
| Destructive confirmation | None this phase (Reset confirmation pre-exists, unchanged). |

**Refusal-copy invariants (AUM-03, ROADMAP SC-4 — acceptance-greppable):**
- The refusal names ONLY real affordances: the AUM input this phase adds, and the
  "From my book" segment (only in the variant where it actually renders).
- The strings "toggle on a live holding" and "Connect an exchange API key" MUST NOT
  appear in the commit-refusal copy — the live-holding toggle was deliberately never
  built (CONSTIT-03), and the founder hit this refusal with four venues already
  connected.

**Partial-book note invariants (AUM-04):**
- Counts cover **eligible allocator keys** only. MANAGER-side keys (strategy-linked
  series) are excluded from the gate AND from the note's counts — "not yet
  contributing" must never describe a key that will never contribute.
- Rendered in book mode directly above the per-key data-sources list. Plain static
  text; no `role="alert"` (it is steady-state disclosure, not an event).
- Never silent: whenever book mode is active and ≥1 eligible key lacks per-key
  dailies, the note renders.

**`sync_error` copy class (AUM-02 / AUM-05, ROADMAP SC-2):**
`AllocatorSyncStatus` renders the DB `sync_error` string verbatim as the aria-live
helper under the pill (states `error` / `complete_with_warnings`, sanitized ≤500
chars). Every worker-written `sync_error` is therefore end-user copy and follows the
pattern **"{what happened} — {what happens next or what to do}"**:

| Situation | `sync_error` copy (worker-written) |
|-----------|-------------------------------------|
| Unknown non-ccxt venue (honest skip) | "Holdings sync isn't supported for {venue} yet — this key was skipped." |
| Non-USD MT5 account currency (honest skip, no invented FX) | "MT5 account currency is {CCY} — USD conversion isn't supported yet, so this account was skipped." |
| MT5 terminal unreachable / genuine MT5 failure | "MT5 terminal unreachable — sync will retry automatically." |
| sFOX fetch failure | "Couldn't fetch balances from sFOX — sync will retry automatically." |

Invariants (acceptance-greppable): a `sync_error` value never contains `Traceback`,
`AttributeError`, `object has no attribute`, a Python class name, or any code
identifier. Venue names render in product casing ("MT5", "sFOX"), never internal
ids. Which `sync_status` each skip lands on (`complete_with_warnings` vs `error`) is
a planner decision — the copy above is fixed either way; note that
`complete_with_warnings` renders the "Synced (warnings)" pill and also surfaces the
helper, which suits honest skips better than a red "Sync failed".

## Component Contracts (phase-specific)

### 1. Portfolio AUM input (AUM-01)

- **Placement:** composer summary/header region, one instance, both entry modes.
- **Anatomy:** mono eyebrow label `PORTFOLIO AUM (USD)` (Geist Mono uppercase,
  micro tier, 0.18em tracking, `text-text-muted`) above/beside a numeric input in
  the existing composer input recipe (6px radius via `rounded`, 1px `border-border`,
  `bg-surface`, `px-2 py-1`, right-aligned, `font-mono text-xs`, accent focus
  border). Width ~`w-32`.
- **Value semantics:** whole USD dollars; validated with `isValidDollar`
  (`@/lib/dollar-validation`, bound [0, 1e12)); read-only adjacent renderings use
  `formatUsd` — the ONE money formatter (150-UI-SPEC rule; a second formatter on
  this surface is forbidden). Never fabricate cents.
- **Blank mode:** starts empty (never pre-filled `0` — a zero is a claim). Helper
  line "Required to size and commit."
- **Book mode:** pre-filled from the live-holdings sum, editable as an override.
  When the value diverges from the live sum, the override note renders (see copy
  table). Switching entry modes re-seeds per the mode's rule; a dirty-draft switch
  keeps routing through the existing reset confirmation.
- **Interaction:** weights remain the single source of truth. Editing AUM keeps
  weights fixed and rescales all dollar figures live. Manual AUM persists on the
  draft and is recorded in the scenario commit payload (threaded through
  `ScenarioCommitDrawer`'s existing `scenarioAum` prop).
- **Disclosure interplay (recorded decision):** the existing
  "Illustrative shape only — no live capital connected" chart note keys off
  `scenarioAum <= 0` and naturally disappears once manual AUM is set; the
  persistent `PROJECTED — hypothetical, not your live book` pill continues to carry
  the hypothetical disclosure. No new chart disclosure is added.

### 2. Per-strategy dollar input (AUM-01, "allocate $500k to this strategy")

- **Placement:** in each added-strategy row's input cluster, alongside the existing
  weight input. The derived read-only **notional** span (equity × share × leverage)
  is a DIFFERENT number and stays exactly as it is — do not merge or remove it.
- **Anatomy:** same input recipe as the weight input; ~`w-24`; sr-only label
  "{name} allocation (USD)"; right-aligned mono, whole dollars, tabular.
- **Behavior:** displays `weight × AUM` (whole dollars) at rest; editing
  back-computes `weight = amount / AUM` and routes through the EXISTING
  `setWeightOverride` path so the clamp + clamp banner ("Weight clamped to 1 — …")
  are reused verbatim, not duplicated.
- **AUM unset (≤ 0):** the field renders as a read-only `—` with
  `title="Set portfolio AUM to size in dollars"` PLUS an `sr-only` span carrying the
  same sentence (`title` alone is unreachable by keyboard/touch and not announced by
  all screen readers) — an honest non-derivable state,
  never a silently disabled input and never `$0`.
- **⚠️ v1.11 weight-basis landmines (binding):** a sole-unit weight edit REFUSES,
  never renormalizes — the dollar input inherits that refusal because it routes
  through the same weight path; per-key refs are invisible to naive diffing. Do not
  fork a second weight-write path for dollars.

### 3. "From my book" segment + gate (AUM-04)

- **Visuals unchanged:** the existing radiogroup recipe (active =
  `border-accent text-accent`, NO accent fill; arrow-key nav; accent focus ring)
  stays byte-identical. This phase changes the GATE, not the control.
- **Gate semantics:** "From my book" renders when a live book exists and ≥1
  eligible key has per-key dailies (partial book satisfies), with MANAGER-side keys
  excluded from eligibility (role-based, not venue-based — an
  `exchange === 'mt5'` predicate is the wrong fix class).
- **No forced blank:** when the book is reachable the composer never
  force-initializes to blank; entry mode is the user's choice (the existing
  `useState(canEnterBook ? "book" : "blank")` default carries this once the gate
  is fixed).
- **Partial-book display:** book mode shows contributing keys as today;
  non-contributing eligible keys get the partial-book note (copy table above) —
  never silent.

### 4. Sync status surface (AUM-02 / AUM-05)

- **No new component.** `AllocatorSyncStatus` renders whatever the worker writes;
  the UI contract is carried entirely by the `sync_error` copy class above plus the
  planner's `sync_status` choice per skip case. No frontend changes required unless
  the planner picks a status outside the existing
  `idle | syncing | complete | complete_with_warnings | rate_limited | revoked | error`
  set — do not widen that set.
