## Critical Issues

### CR-01: `tokenMeasure` fires the CREDENTIAL rule on ordinary credential-free PROSE, because the concatenation branch — unlike the single-operand branch — never splits on whitespace and has had its digit guard removed

**Files:**
- `scripts/prod-prober/arms/cron-drift.mjs:1267` (the `fromConcat` branch returns `c.text` WHOLE)
- `scripts/prod-prober/arms/cron-drift.mjs:1270` (the single-operand branch, which DOES split on whitespace)
- `scripts/prod-prober/arms/cron-drift.mjs:1789` (`if (!fromConcat && !/\d/.test(token)) return false;`)
- `scripts/prod-prober/arms/cron-drift.mjs:1969-1971` (the sentence printed into a public Actions log)

**Issue.** The design rests on one asserted premise, stated at `tokenMeasure`'s docstring and again
in the printed defect sentence:

> *"nobody writes prose by concatenating two 16-character fragments: `fromConcat` is itself the
> evidence of assembly the digit was standing in for"* … *"No prose is written that way."*

That premise is false for `format`, `concat_ws`, `replace`, `regexp_replace` and `quote_literal` —
callees that are in `BUILDERS` (`:714`) precisely **because their job is to assemble prose** — and
false for a plain `||` of two message fragments, which is the house spelling of a `RAISE` message.

The mechanism: the single-operand branch at `:1270` splits the value on `/\s+/` "because a lone
literal is a sentence as often as a value, and splitting it is the measured difference between zero
false positives and six" (its own docstring). The `fromConcat` branch at `:1267` does **not** split.
It then reaches `credentialShaped` at `:1789`, where `fromConcat` **also** waives the digit guard —
the one remaining filter that had been keeping prose out. A whole sentence therefore arrives as a
single ≥32-character "token" with nothing left to reject it.

**MEASURED — `main` vs this branch, same inputs, same function:**

```
format() two prose args        | main: [] | branch: ["long-token-anywhere"]
replace() prose || suffix      | main: [] | branch: ["long-token-anywhere"]
concat_ws prose                | main: [] | branch: ["long-token-anywhere"]
RAISE prose || prose (in DO)   | main: [] | branch: ["long-token-anywhere"]
quote_literal + concat msg     | main: [] | branch: ["long-token-anywhere"]
```

The last row is verbatim this repository's own vocabulary:

```sql
SELECT 'retention sweep for ' || quote_literal('compute_jobs_done') || ' completed';
-- branch: ["long-token-anywhere"]  ->  kind cron-secret-in-command
```

**Concrete failure scenario.** A migration adds a `RAISE NOTICE`/`format()` status message to any
cron command — the most ordinary edit possible in this codebase, and one no reviewer would question.
The next hourly `prod-prober` run emits `cron-secret-in-command` for that job, whose remedy
(`REMEDIES["cron-secret-in-command"]`, `:220`) is *"Treat the named secret as EXPOSED and rotate it
first"*. The prober log is `cat`ed into a **public** Actions log and copied into an auto-filed
issue. The result is a mandatory credential rotation demanded hourly on a command that contains no
credential — which is exactly the outcome the file itself names as fatal: *"An hourly prober that
cries wolf on real configuration is how a true positive gets ignored."*

This is the phase's own governing constraint violated in the direction the brief flagged: *"a rule
widened to catch a shape must not start reporting credential-free production text."*

**Fix — cheap, and MEASURED to cost nothing.** A credential never contains whitespace. Every real
detection in the entire corpus (29 red rows, 9 green rows, 14 committed manifest commands) is
whitespace-free:

```
red:fixture_unbalanced_headers_job      ws:false len:37
red:fixture_nonanchored_split_job       ws:false len:35
red:fixture_split_outside_header_job    ws:false len:39
red:fixture_nonbuilder_wrapper_job      ws:false len:39
red:fixture_concat_alpha_job            ws:false len:33
```

So the concatenation branch should treat its derived value the way the single-operand branch already
treats a literal — split it, and judge the pieces:

```js
// cron-drift.mjs:1266-1268
if (c.parts.length > 1) {
  // ⛔ SPLIT LIKE THE SINGLE-OPERAND BRANCH BELOW. `format`, `concat_ws`,
  // `replace` and `||` exist to assemble PROSE, so "assembled" is not by itself
  // evidence of a value — but a credential never contains whitespace, and every
  // detection in the corpus (red 37/35/39/39/33) is whitespace-free.
  for (const raw of c.text.split(/\s+/)) {
    if (raw.length === 0) continue;
    out.push({ token: raw, derivedLength: raw.length, fromConcat: true, literalOperands, start, end });
  }
  continue;
}
```

Then add the green calibration row WR-02 asks for, so the fix is falsifiable.

### CR-02: the hoisted manifest-side loop crashes on a `null` element in `manifest.jobs`, and the crash DISCARDS every PROD-side credential finding section (0) already collected

**File:** `scripts/prod-prober/arms/cron-drift.mjs:2642-2643`

```js
for (const row of Array.isArray(manifest?.jobs) ? manifest.jobs : []) {
  if (typeof row.command !== "string") continue;   // <-- throws when row is null
```

**Issue.** Plan 07 hoisted this loop above every early return, and added a *container*-level guard
(`Array.isArray(manifest?.jobs) ? … : []`) while omitting the *element*-level one. The very
validation loop this code now runs ahead of knows better — thirty lines down at `:2724` it opens
with `if (!row || typeof row.jobname !== "string" …)`. Before the hoist, the shape checks had
already rejected such a manifest; after the hoist nothing has run, and `null.command` throws a
`TypeError` from a position **outside** `judgeRow`'s try/catch.

`compareManifest` collects into a local `defects` array that is only returned at the end, so the
throw takes everything with it. It unwinds out of `run()` into `run.mjs:444`, which converts it into
a single arm-level `measure-fail` ("cron-drift threw: …").

**MEASURED** — identical live PROD row carrying a split inline `X-Service-Key`, three manifests:

```
jobs=[]      (valid array) -> cron-secret-in-command:prod:leaky_job | manifest-invalid:cron-manifest.json
jobs=[null]                -> THROW TypeError: Cannot read properties of null (reading 'command')
jobs=[7]                   -> cron-secret-in-command:prod:leaky_job | manifest-invalid:cron-manifest.json
```

**Concrete failure scenario.** One `null` element in the committed `cron-manifest.json` — a
hand-edit, a truncated capture, a merge artefact, or a `jq` filter that dropped a row — deletes the
PROD-side `cron-secret-in-command` finding for **every** job from the output and replaces it with
one generic "the arm threw". `null` is trivially expressible in JSON, and this arm's declared
adversary is *"someone hand-cleaning the committed text."*

This is byte-for-byte the F3 measurement the same file records as closed:

> *"MEASURED with two rows, one leaking: an absent `functionsDir` turned
> `["cron-secret-in-command:prod:leaky_job", "manifest-invalid:…"]` into a THROW, i.e. into ONE
> generic arm-level measure-fail."*

It is loud (non-zero exit), so it is a downgrade rather than a false green — but it is a **refusal
that is substitutive**, which is the one thing this phase's governing invariant forbids, and the
finding it eats is a live production credential report.

**Fix — mirror the guard that already exists at `:2724`:**

```js
for (const row of Array.isArray(manifest?.jobs) ? manifest.jobs : []) {
  // ⛔ ELEMENT-LEVEL, NOT JUST CONTAINER-LEVEL. At this position the eight shape
  // checks have NOT run, so `jobs` may hold anything JSON can express — and
  // `null.command` throws OUTSIDE judgeRow's try, unwinding compareManifest and
  // discarding section (0)'s PROD findings. Same guard as :2724.
  if (!row || typeof row !== "object" || typeof row.command !== "string") continue;
```

Pin it with a case asserting that `compareManifest({…, jobs:[null]}, [leakyRow], …)` still reports
`cron-secret-in-command:prod:<job>` — that case goes RED against the current bytes.

## Warnings

### WR-01: the new value walk is UNBOUNDED over adversary-controlled command text — superlinear, then a stack overflow that silences all 14 rules for the row

**Files:** `scripts/prod-prober/arms/cron-drift.mjs:1023` (`operandAt`), `:1131` (`chainAt`),
`:1186` (`scanValueChains`), `:1244` (`tokenMeasure` over the whole span)

**Issue.** `tokenMeasure` now walks the **entire** span unconditionally, and the walk descends into
any `(` — including a non-`BUILDERS` callee, which is new. There is no analogue of
`MAX_DOLLAR_DEPTH`. The same file's docstring on that constant refuses exactly this trade:

> *"Raising the cap buys deeper lexing at the price of an **unbounded walk over adversary-controlled
> text**."*

**MEASURED,** `SELECT f(f(f(…'x'…)))`, `hygieneViolations` end to end:

| paren depth | command length | `main` | this branch |
|---|---|---|---|
| 800 | 2.4 KB | 2 ms | 1 304 ms |
| 1 000 | 3.0 KB | — | 2 567 ms |
| 1 500 | 4.5 KB | 0 ms | 8 836 ms |
| 1 600 | 4.8 KB | — | **RangeError: Maximum call stack size exceeded** |
| 20 000 | 60 KB | 6 ms | RangeError |

A second, independent superlinearity is in `operandAt:1029` —
`masked.slice(i, to)` allocates the whole remaining string once per operand, so a long `||` chain is
quadratic: 50 000 operands → 1.1 s, 150 000 → 10.0 s.

**Concrete failure scenarios, both real:**

1. **Substitutive refusal, one syntactic wrapper.** Anyone who can write `cron.job.command` wraps a
   credential-carrying command in 1 600 parentheses. The `RangeError` is caught by `judgeRow`
   (`:2521`) and becomes a per-row `measure-fail` with `violations: null` — so **all fourteen rules
   are silenced for that row** and the row is downgraded from `cron-secret-in-command` (rotation
   remedy, names the job) to a generic refusal. Nothing about the credential changed; only the
   parentheses did. That is the WR-R1-03 shape this phase closed for **dollar** nesting, re-opened
   with **paren** nesting.
2. **Availability.** Sibling subtrees just under the stack limit multiply: at ~9 s per subtree,
   a command carrying a few dozen of them pushes the arm past any workflow timeout, and arms run
   sequentially, so the whole prober produces no report at all.

**Fix.** Give the new walk the cap the rest of the file already has. Carry an explicit `depth`
through `operandAt`/`operandValue`/`derivedValue`/`chainAt`/`scanValueChains`, stop at a
`MAX_VALUE_DEPTH` (4 matches `MAX_DOLLAR_DEPTH`'s reasoning), and — critically — record the
give-up in the `refusals` out-parameter so it reports **beside** the other rules rather than
instead of them, exactly as `codeSpans` was changed to do in WR-R2-05. Also replace
`masked.slice(i, to)` at `:1029` with a sticky `/y`-anchored regex (`re.lastIndex = i`) so a long
chain is linear.

### WR-02: the zero-false-positive controls CANNOT FAIL for the mechanism they are cited as protecting

**Files:** `src/__tests__/prod-prober-wiring.test.ts` (`THE BUDGET`, `THE INVARIANT`),
`scripts/prod-prober/fixtures/cron-drift/hygiene-green.json`,
`scripts/prod-prober/cron-manifest.json`

capability: *"the committed manifest's 14 commands remain at zero violations"* and *"every
hygiene-green row still produces ZERO violations."* **Measured:**

- **Zero** of the 14 committed manifest commands contain `||`, and **zero** contain any `BUILDERS`
  callee (`format|concat|concat_ws|replace|regexp_replace|quote_literal|…`). The committed oracle
  cannot exercise the concatenation path at all.
- The green corpus's three `||` rows (`match_engine_cron`, `fixture_bearer_concat_job`,
  `fixture_short_split_headers_job`) all derive **under** `TOKEN_MIN` or are blocked by the

So both controls are **vacuous with respect to `tokenMeasure`**: they return the same answer whether

not close this either — L4 and L6 redden the budget through the *literal* producer and the
*comma-summing* bug respectively, never through a `fromConcat` prose value. CR-01 is the defect this

### WR-03: the "split AND unbalanced" residual is real but its SCOPE is understated — one stray `(` disables the derived measure for the WHOLE REST OF THE SPAN, including values nowhere near a header

**Files:** `scripts/prod-prober/arms/cron-drift.mjs:1943` (`regions.find` — first match wins),
`:1960` (`if (region && region.unparseable) continue;`),
`scripts/prod-prober/fixtures/cron-drift/hygiene-bypass.json` (`bypass_split_after_unparseable_job`)

**Issue.** The residual is documented — in the bypass row's `note`, in `headerRegions`' docstring
and in the SUMMARY — as *"exactly `split AND unbalanced`"*, i.e. a value left **inside** an
unbalanced header argument list. That is not what the code does. `headerRegions` gives an
unparseable region `to: masked.length`, and `regions.find` returns the **first** overlapping region,
so the skip applies to every derived value positioned after the stray `(` anywhere in the span —
including one in a plain plpgsql assignment that is not in, or near, a header expression.

**MEASURED** — same command, one character apart:

```
stray ( then far-away chain: [ 'header-unparseable' ]
same command, balanced     : [ 'long-token-anywhere' ]
```

The credential (`k := 'FAKE-0123456789-01234' || '56789-0123456789ab'`, two statements later, passed
to `public.send`) is not named in the first reading.

**Why it is a WARNING and not a BLOCKER.** I verified the no-false-green half of the claim
structurally and it holds: `header-unparseable` is `say`n from the `for (const region of regions)`
loop that runs in the *same* span iteration, *before* the `tokenMeasure` loop, over the *same*
`regions` array — there is no path that skips and stays silent. So this is a downgrade to
`measure-fail` (exit 1), not a pass. But it is the F2 shape the file itself calls *"an off-switch an
adversary holds with ONE CHARACTER, on the one rule that exists to catch bypasses"* and deliberately
closed for the literal producer — re-opened for the new producer, and recorded under a description
that makes it sound an order of magnitude narrower than it is.

**Fix.** Two options, both small:
1. Restrict the skip to the region the value is actually *inside* by requiring full containment
   (`m.start >= r.from && m.end <= r.to`) for unparseable regions, or at minimum prefer the
   narrowest overlapping region rather than the first one found; or
2. Keep the skip and correct the three prose sites to state the true scope: *"any derived value
   positioned after an unbalanced header `(` anywhere in the span."* Prose that understates a gap is
   the class `[164.7-CITATION-DRIFT-01]` is about.

Either way, add a bypass row for the far-away spelling so the scope is pinned rather than described.

### WR-04: `derivedLiteralLength` and `operandValue` are now two divergent answers to one question, with no control pinning the divergence

**Files:** `scripts/prod-prober/arms/cron-drift.mjs:938` (`derivedLiteralLength`), `:1080`
(`operandValue`)

**Issue.** The file now carries two independent implementations of "how much text can this
expression put on the wire," and they disagree by construction:

| | `derivedLiteralLength` | `operandValue` |
|---|---|---|
| comma inside a `BUILDERS` call | sums the arguments | sums the arguments |
| comma outside one | **sums** (it walks to `,` or `)`) | never joins |
| non-`BUILDERS` callee | **skips whole** (residual, → 0) | **descends**, takes longest arg |
| `chr()` | 1 | `"?"` (1) |
| `(SELECT …)` | skipped | skipped |

`long-literal-in-headers` is decided by the first (`:1702`-`:1707`) while the new concat path can `say` the
**same rule id** from the second (`:1963`). Two measurements, one verdict, no test asserting the
relationship. The comma behaviour is the divergence that already bit once this wave — the
`reconcile_dropped_enqueue_sweep` false positive came from importing `derivedLiteralLength`'s
comma rule into the new walk — and nothing stops the next editor from "unifying" them back.

**Fix.** Either express one in terms of the other, or add a wiring case asserting the specific
divergence with a title that states why (`derivedLiteralLength` sums a callee's arguments because
the caller has already bounded the range to ONE argument; `operandValue` must not, because a
black-box callee's arguments are alternatives). At minimum leave a cross-reference on each
docstring naming the other by symbol.
