### CR2-01: the `fromConcat` digit-guard waiver is inherited PER CHAIN by every whitespace token, so a single long identifier inside assembled PROSE still demands an hourly credential rotation

**Files:**
- `scripts/prod-prober/arms/cron-drift.mjs:1406` — `const fromConcat = c.parts.length > 1;` (a
  property of the CHAIN)
- `scripts/prod-prober/arms/cron-drift.mjs:1430-1433` — every whitespace token of that chain is
  pushed carrying the chain's flag
- `scripts/prod-prober/arms/cron-drift.mjs:1991` — `if (!fromConcat && !/\d/.test(token)) return false;`
- `scripts/prod-prober/arms/cron-drift.mjs:2142-2184` — the producer and the `long-token-anywhere` `say`

**Issue.** The CR-01 fix removed *sentences* from the rule by splitting on whitespace. It did not
remove the thing that made the sentence fire: the digit guard is still waived for **every token of
an assembled chain**, including a token that came WHOLLY FROM ONE OPERAND and therefore carries no
evidence of assembly at all. Any ordinary message that names a long identifier now fires.

The file's own docstring names the counter-example it fails to survive:

> *"A single literal is prose far more often than it is a value —
> `'retention_notification_dispatches:'` is THIRTY-FOUR characters of committed job name — so the
> digit test is what buys the zero-FP reading on the real corpus, and it stays."*

That reasoning does not survive concatenation, and nothing in the fix re-establishes it.

**MEASURED at HEAD, ordinary credential-free commands:**

```

[]                       SELECT public.log_cron_event('retention_notification_dispatches: sweep completed')   <- the control
["long-token-anywhere"]  SELECT public.log_cron_event(format('%s finished', 'strategy_analytics_recompute_dispatcher'))
["long-token-anywhere"]  SELECT public.log_cron_event(concat_ws(' ', 'public.strategy_analytics_recompute_all', 'done'))

`retention_notification_dispatches` job already contains

```

`REMEDIES["cron-secret-in-command"]` then demands, hourly, into a **public** Actions log and an
auto-filed issue: *"Treat the named secret as EXPOSED and rotate it first."* There is no secret.

**This is not a narrow shape.** **Eight of the fourteen** committed manifest commands already carry

those tokens sit in single literals, where the digit guard still applies.

**Fix — make `fromConcat` a property of the TOKEN, not of the chain.** The waiver's stated
justification is "assembly from fragments is the evidence a digit would have supplied"; that

fixture_nonbuilder_wrapper_job    token(39) from operands [21,18]   <- straddles

// cron-drift.mjs:1406, 1430

// licence is "this token was ASSEMBLED"; a token that lies wholly inside ONE

### CR2-02: `BUILDERS` join their arguments with NO separator, fusing the last word of one operand to the first word of the next — so the whitespace split is BLIND to the token it creates, by construction

**File:** `scripts/prod-prober/arms/cron-drift.mjs:1199-1206` (`operandValue`'s BUILDERS branch —
`text += g.text` across `op.args` with nothing between)

**Issue.** `format('%s %s', a, b)` and `concat_ws(' ', a, b)` do not emit `a` and `b` adjacent —
`format` substitutes and `concat_ws` inserts the separator. The measure concatenates them raw, so
the seam produces a whitespace-free token that exists in NO real output and that the CR-01 split
cannot split, because there is no whitespace in it. Whether it fires is decided by the length of
the two words that happen to meet at the seam.

**MEASURED at HEAD:**

```
[]                      concat_ws(' ', 'the retention sweep found orphaned rows', 'and refused to delete them')
                        derived tokens: [... "orphaned", "rowsand", "refused" ...]        <- seam token 7 chars
["long-token-anywhere"] concat_ws(' ', 'the retention sweep found orphaned strategy_rows',
                                       'reconciliation_pass_two refused to delete them')
                        derived tokens: [... "strategy_rowsreconciliation_pass_two" ...]  <- seam token 36 chars

[]                      format('%s for %s', 'nightly reconciliation', 'every archived strategy')
["long-token-anywhere"] format('%s %s', 'nightly reconciliation_sweep', 'for_every_archived_strategy today')
                        derived tokens: ["%s", "%snightly", "reconciliation_sweepfor_every_archived_strategy", "today"]
```

The first line is the SHIPPED green calibration row `fixture_concat_ws_prose_job`. It is green
because `"rows" + "and"` is seven characters. **The control passes by word-length accident, not by
mechanism** — which is the same vacuity WR-02 was raised about, reproduced one level down inside
its own remedy.

**Concrete failure scenario.** Any cron command whose status message is assembled by `format` or
`concat_ws` and whose seam happens to join two long words. `format('%s %s', …)` is the single most
common shape in PostgreSQL status messages, and nothing warns the author.

**Fix.** Join builder arguments with a separator that the split will honour, so a fused token
cannot be manufactured:

```js
// cron-drift.mjs:1201-1206
// ⛔ A SEPARATOR BETWEEN ARGUMENTS (164.8.6-REVIEW-ROUND2 CR2-02). `format`
// SUBSTITUTES and `concat_ws` INSERTS its separator — neither ever emits two
// arguments adjacent. Joining them raw manufactures a whitespace-free token
// that exists in no real output and that the CR-01 split cannot see.
// A credential assembled by a BUILDER is still caught: `fixture_format_key_job`
// and `fixture_concat_key_job` are RED through `derivedLiteralLength`, which
// this walk does not replace.
let text = "";
for (const [a, b] of op.args) { const g = derivedValue(...); text += (text ? " " : "") + g.text; ... }
```

Re-measure the whole corpus after the change: the red rows that rely on a BUILDER joining a SPLIT
credential (`fixture_format_key_job`, `fixture_concat_key_job`, `bypass_format_job`,
`bypass_base64_job`) must be re-confirmed RED, and if any depends on raw adjacency the separator
must be applied to `format`/`concat_ws` only.

### WR2-01: WR-02's new per-row precondition measures a quantity that is NOT the one governing whether the row can fire, and inflates it by the number of whitespace tokens

**File:** `src/__tests__/prod-prober-wiring.test.ts:2314-2317`

```ts
expect(
  assembled.reduce((n, m) => n + m.literalOperands.join("").length, 0),
  `${jobname}'s assembled value must be at least TOKEN_MIN long — a short one could not fire even if the rule were broken`,
).toBeGreaterThanOrEqual(TOKEN_MIN);
```

**Issue.** After CR-01's split, `tokenMeasure` emits ONE RESULT PER WHITESPACE TOKEN, each carrying
the SAME `literalOperands` array for the whole chain. The `reduce` therefore adds the chain's
derived length once per token. MEASURED on the four shipped rows:

| row | true derived length | what the precondition reports | inflation |
|---|---|---|---|
| `fixture_format_prose_job` | 75 | **900** | 12× |
| `fixture_concat_ws_prose_job` | 66 | **660** | 10× |
| `fixture_raise_concat_prose_job` | 72 | **864** | 12× |
| `fixture_quote_literal_prose_job` | 47 | **235** | 5× |

**Concrete failure scenario — the precondition passes on a row that could not fire even against the
broken producer, which is exactly what it claims to exclude.** MEASURED:

```
SELECT public.log_cron_event(concat_ws(' ', 'a b c', 'd e f'))
  assembled measures = 5 (> 0 ✔)   precondition sum = 55  >= TOKEN_MIN(32): TRUE
  BUT the derived value is 11 characters — under TOKEN_MIN, so the row is GREEN
  whether tokenMeasure is correct or not.
```

If any of the four rows is later edited into a short-derived shape, the guard stays green and the
budget silently goes vacuous again. The `assembled.length > 0` half IS live; the length half is not.

**Fix.** Assert the MAXIMUM over distinct chains, not the sum over tokens:

```ts
const chains = new Map(assembled.map((m) => [`${m.start}:${m.end}`, m.literalOperands.join("")]));
expect(
  Math.max(...[...chains.values()].map((v) => v.length)),
  `${jobname}'s assembled value must itself be at least TOKEN_MIN — the SUM over whitespace tokens is the chain length times the word count and says nothing about whether the row could fire`,
).toBeGreaterThanOrEqual(TOKEN_MIN);
```
