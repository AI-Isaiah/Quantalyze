> Holdings allocate) and OWN-05 (owner rename). Generated by gsd-ui-researcher,

## The third chip family — decision and rationale (constraint from orchestrator)

Two chip families exist:

1. **Publication Badge** (`Badge type="status"`, `rounded-md` 6px, `text-caption
   font-medium`) — persistent lifecycle states the owner/system declared
   (Published / Draft / Private / …).
2. **Data-state chip** (147/149 family, `rounded-sm` 4px, `text-fixed-11` uppercase
   tracked) — transient/derived pipeline states (Syncing / No data / No strategy yet).

**The ownership mark joins family 1 (Badge, `rounded-md`).** Why, consciously:

- The mark is a **persistent, owner-declared attribute** — exactly the nature of
  publication status, and nothing like a derived pipeline state. The `rounded-sm`
  uppercase family encodes "the system computed this and it may change on its own";
  the mark never changes on its own.
- It renders **in the same name-cell line as the status Badge** on /my-strategies.
  Two persistent attributes side-by-side with two different radii would read as
  inconsistency, not semantics; the 4px/6px split stays reserved for the
  persistent-vs-derived distinction 149 established ("Do NOT harmonize" cuts both
  ways — do not blur it either).
- Identity within the family is carried by **ink**, not shape:

| Mark | Label | Classes (exact) | Rationale |
|------|-------|-----------------|-----------|
| own-capital | `Own capital` | `inline-flex items-center rounded-md px-2 py-0.5 text-caption font-medium bg-accent/10 text-accent` | Accent means "verified / action" (DESIGN.md). The own-capital mark is precisely the fact that UNLOCKS the money action — it defines the allocatable set. Existing in-family precedent: `statusMap.intro_made` uses the identical accent-tint pairing |
| team-review | `Team review` | same anatomy, `bg-badge-other/10 text-text-muted` | The DEFAULT and a neutral fact — never red, never amber, never "less than". Same muted ink as `Private` (semantic-color gates: absence of allocatability is not an error) |
| unmarked (legacy rows) | **no tag** | — | Absence is honest. The remedy is the row action (retro path, D-11), not a fabricated default |

Implementation hint (planner discretion on mechanics, not on tokens): a distinct
ownership variant/component reusing the Badge class string verbatim — do NOT overload
`statusMap` string keys with non-status values.

## Surface 2 — /my-strategies row (mark tag + row actions + rename)

Extends the Phase-149 `StrategyTable` owner surface. 149's parity contract stands:
these are owner-surface-only deltas, prop-gated; **zero change renders on
/discovery, /browse, or any public surface.**

### Mark tag placement

Name cell, first line, AFTER the Phase-149 status marker (order: name link →
verified check → status Badge → ownership tag). Both tags are Badge-family
(`rounded-md`) so the line reads as one family. Unmarked rows: no tag (see family
table). Row-height parity holds (chips are `py-0.5` within the ~44px row).

### Row actions (action cell — the existing Simulate Impact cell)

The action cell on the owner surface renders a compact text-action cluster,
DM Sans `text-caption font-medium`, ghost treatment (`text-text-muted
hover:text-text-primary transition-colors`, focus ring `focus-visible:ring-2
focus-visible:ring-accent/20` — the `MandateSegmentedRadio` Reset idiom). Trailing
`…` on each label signals a dialog.

| Row state | Actions rendered (in order) |
|-----------|----------------------------|
| unmarked, private/draft | `Mark ownership…` · `Rename…` |
| marked, private/draft | `Change mark…` · `Rename…` |
| unmarked, published | `Mark ownership…` · Simulate Impact (inherited) |
| marked, published | `Change mark…` · Simulate Impact (inherited) |
| any status, non-owner surface | inherited behavior only — none of these actions exist |

- **Rename renders on private/draft rows ONLY** (D-17). On published own rows the
  affordance is ABSENT, not disabled — published rename is a deferred trust-surface
  decision, so there is no honest remedy popup to offer; rendering nothing follows
  the established SimulateImpactButton precedent ("rendering nothing beats
  rendering a button that cannot work").
- `Mark ownership…` / `Change mark…` open the **Mark dialog** (below).
- `Rename…` opens the **Rename dialog** (below).
- Placeholder rows (149 Delta 5, keys with no strategy) get NO mark/rename actions —
  there is no strategy to mark.

### Dialogs (dialog vs inline — decided: dialog)

Inline row editing was rejected: the mark needs its invariant helper line and the
rename needs validation copy; neither fits a 44px-parity row. All three dialogs use
the existing `Modal` primitive (`max-w-lg`, `p-6`, `text-h3 font-semibold` title —
inherited unchanged).

**Mark dialog** — title `Mark ownership`; body = the SAME two-option radiogroup
component as the wizard question (ONE component, two mounts — copy stays
single-sourced), group label variant `Whose capital is this?`, strategy name shown
as the first body line (`text-body font-medium text-text-primary`); same helper
line. Footer: `Save mark` (`Button` primary — accent) + `Cancel` (`Button`
secondary). Initial selection = current mark; unmarked rows open with **(b)
team-review preselected** (same safe default — an accidental save must not mint
allocatability). This dialog IS the retro path (D-09/D-11): Black Swan, Alpha
Centauri, Arctic Fox become markable here with zero re-onboarding.

**Flip with a live allocation (D-03 hole, closed):** when the strategy has a live
`portfolio_strategies` position and the selection flips own-capital → team-review,
`Save mark` does NOT write immediately. The dialog shows a two-step inline confirm
(same in-dialog idiom as Remove allocation; no nested modal): heading
`Remove allocation?`, body `{name} has a ${amount} allocation. A team-review
strategy cannot hold an allocation — changing the mark removes it.`, primary
`Change mark and remove allocation` (`Button` primary styled `bg-negative`),
secondary `Keep own capital` (dismisses the confirm; the mark and position are
unchanged). The mark flip and the position removal are ONE confirmed write — the
flip never leaves a position behind (the invariant holds by construction), and a
position is never removed silently.

**Rename dialog** — title `Rename strategy`; body: `Field` + `Input`, label `Name`,
prefilled with the current name; helper `text-caption text-text-muted`: `Only you
see this name. Public surfaces keep showing the codename.` (D-18 — the C-0112
redaction contract stated as a fact, byte-untouched). Validation, inline at the
field (this phase's forms must not re-introduce the terminal-envelope class —
ROADMAP 153 note): non-empty after trim → `Enter a name.`; length cap 80 chars
(planner confirms against the column) → `Keep it under 80 characters.` Footer:
`Save name` primary + `Cancel`. On save, every owner surface renders the new name
coherently (SC 1c: my-strategies row, Browse own rows, owner factsheet lane,
holdings alias).

**Write-failure state (all dialogs):** the canonical `buildEnvelope()` →
`ErrorEnvelope` machinery renders inside the dialog body below the form — never an
invented inline error string (DESIGN.md authoring rule). Dialog stays open; the
user's input is preserved.

## Surface 4 — Holdings STRATEGIES panel (allocate / edit / honest empty)

Files: `src/app/(dashboard)/allocations/HoldingsTabPanel.tsx` → `HoldingsTable`
`strategyRows` section (+ `lib/strategies-row-adapter.ts`).

**Focal point:** the strategies table — rows plus their per-row actions; the
empty-state arms replace it wholesale, never sit beside it.

### Row population — the D-03 invariant expressed as data

The STRATEGIES panel lists **own-capital-marked strategies** (allocated or not) —
widened from "portfolio strategies only" so unallocated marked rows appear (D-12,
D-15). Team-review-marked and unmarked strategies **never enter the panel's row
set**: no row, no affordance, nothing to disable. The structural phase gate
(D-03, phase-149-parity-test shape) pins that no code path renders an allocate
affordance or creates a position for a non-own-capital strategy. A mark flip on an
allocated strategy cannot strand a row here either — the flip removes the position
in the same confirmed write (Surface 2, Mark dialog), so the panel's population
rule never silently orphans or hides a live position.

### Row anatomy (approved mock, made precise)

Inherited columns unchanged (Strategy / Weight / Allocation / MTD / Sharpe /
Max DD / …). Deltas:

| Row state | Ownership tag | Allocation cell | Weight cell | Action |
|-----------|--------------|-----------------|-------------|--------|
| marked, not allocated | `Own capital` tag in the Strategy cell (after the name — restates why the row is here and allocatable) | `— not allocated` → em-dash in `font-metric`, then `not allocated` in `text-caption text-text-muted` DM Sans | `—` (Numbers Contract; untinted) | `Allocate…` — `Button` secondary `size="sm"` |
| marked, allocated | same tag | `$120,000` — `font-metric tabular-nums`, thousands separators (via the allocations surface-family formatter — never inline `toFixed`) | `24.00%` — unsigned, 2dp, matching the inherited column formatter (`formatPercent(w, 2, { signed: false })`, `HoldingsTable.tsx:739`); a weight is a share, not a gain — no sign prefix | `Edit allocation…` — `Button` secondary `size="sm"` |

- Per-row buttons are SECONDARY (border, transparent) — accent primary lives inside
  the dialog; a column of accent-filled buttons would break the 10% accent budget.
- **Duplicate-add impossible by construction (D-13 / SC 4):** one row per strategy;
  an allocated strategy shows ONLY `Edit allocation…` — there is no path that shows
  `Allocate…` on an already-allocated row, so a second position can never be minted
  from this surface. The write itself must also be upsert-shaped on (portfolio,
  strategy) — planner/money-path review territory, but the UI never offers the
  duplicate.
- Metric cells (MTD/Sharpe/…) follow the existing rows' contract unchanged;
  uncomputed → `—`, never 0.

### Allocate / Edit dialog

`Modal` primitive. Money-path reviewed write to the existing
`portfolio_strategies` path (D-14); UI contract:

| Property | Value |
|----------|-------|
| Title | `Allocate — {name}` / `Edit allocation — {name}` |
| Field | `Field` + `Input type="number"`, label `Allocation (USD)`; Edit prefills current amount |
| Live weight preview | Below the field, `text-caption text-text-secondary`: when book equity is known and > 0 → `≈ {w}% of your book (${bookEquity})` (weight unsigned 2dp, matching the column; equity via the surface formatter); otherwise → `Weight appears once your book equity is known.` (limitation with its condition attached — Voice rule; never a fabricated weight) |
| Validation (inline at field, red border + caption — never a post-submit terminal envelope; ROADMAP 153 note makes this form IN SCOPE for the inline class) | not a finite number > 0 → `Enter an amount above $0.` · amount > $1,000,000,000 sanity cap → `That's above the $1B sanity cap — check the amount.` |
| Over-book amounts | NOT blocked (a book can be forward-sized; Phase 151 owns AUM mechanics) — no warning copy in this phase |
| Primary CTA | `Allocate` / `Save allocation` — `Button` primary (accent), disabled-free: the button stays clickable and submit surfaces the inline field error + focuses the field (no-disabled-buttons direction) |
| Secondary | `Cancel` |
| Remove (Edit dialog only) | `Remove allocation…` text action in `text-negative`, below the footer row. Required: without it, a mistaken position has no exit (amount 0 is refused by validation → dead end otherwise). Two-step inline confirm INSIDE the dialog (no nested modal): confirm copy `Remove this allocation? {name} leaves your allocation. The own-capital mark stays.` with `Remove` (`Button` primary styled `bg-negative`) + `Keep` (secondary). One of two destructive actions in this phase (the other: the Mark dialog's flip-with-live-allocation confirm, Surface 2) |
| Write failure | canonical `ErrorEnvelope` in dialog body, input preserved (same as Surface 2 dialogs) |

### Empty states (D-15 — the dead end dies)

Three arms, in priority order:

| Condition | Rendering |
|-----------|-----------|
| ≥1 own-capital-marked strategy exists | The LIST renders (the not-allocated rows ARE the honest state — this replaces "No strategies onboarded yet" whenever marked strategies exist) |
| zero marked, but the user HAS strategies | Panel empty state, `rounded-lg border border-border bg-surface px-6 py-8` (149 empty-state anatomy; no icon, no illustration): heading `text-body font-medium text-text-primary` → `No strategies marked as own capital.` body `text-small text-text-secondary` → `Set the mark from My Strategies, or when you connect a new key.` + text link `Go to My Strategies →` (accent, persistent underline — inline-prose link rule) |
| zero strategies at all | heading → `No strategies yet.` body → `Connect an exchange API key or upload a CSV to see your strategies here.` (149 voice; no fabricated promise about allocation) |
