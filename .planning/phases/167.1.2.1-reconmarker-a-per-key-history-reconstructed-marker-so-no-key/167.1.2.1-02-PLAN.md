<objective>
PR 1, part 2 (D-07, SC-3). A sole-key replace must never delete history while another key of the same allocator exists, connected or not.

Purpose: `allocator_equity_snapshots` rows are allocator totals, not per key (D-07). Today `_allocator_has_other_api_keys` counts only connected siblings, so a reconstruct for key B wipes the rows that disconnected key A contributed (R-13-1). D-07 counts every non-deleted sibling; this schema has no soft delete, so "non-deleted" means any other row with the same `user_id`.
Output: the predicate change, three inverted tests, and a new end-to-end test file. Python only, no schema change.

Known consequence, carried and stated (research Q5, D-07 is locked): this reverses the v0.15.3.3 / H-1162 / H-1164 stale-curve fix. A user who disconnects key A and adds key B now gets first-writer-wins persist rather than a replace.
</objective>
