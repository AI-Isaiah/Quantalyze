<decisions>
## Implementation Decisions

### Scope and split
- **D-01:** split the phase. RECONMARKER keeps SC-1 to SC-7. The writer residuals (SFH-05 writer half, the single failing key with a known account id, SFH-R3-02, SFH-08, R2-CR-02, item (6)) go to a new phase inserted after 167.1.2.1. The reader/UI items ((1), (2), (3), (7) including undated spot rows) go to a second new phase. Both are booked with `/gsd-phase --insert`, never by hand.
- **D-02:** the two closed items (SFH-R3-07, item (4) WR-02) are recorded as CLOSED in the ROADMAP via `/gsd-phase --edit`, citing #903 and #1006.
- **D-03:** the founder calls inside the moved items (SFH-09 carry-age cap, the SFH-08 hold-or-not, item (7) card order) are asked in those phases' own discuss, not here.

### The per-key marker
- **D-04:** the marker is columns on `public.api_keys`: `history_reconstructed_at timestamptz` (NULL means the key still owes its reconstruct) and `history_reconstruct_attempts int` (not null, default 0). The completion path of `run_reconstruct_allocator_history_job` sets it, and every decider reads it. Today those deciders are `_api_key_already_reconstructed`, the `v_prior_reconstruct` check in `request_allocator_holdings_sync`, the `enqueue_refresh_allocator_equity_for_all` bootstrap predicate and `_inflight_reconstructs_for_zero_snapshot_book`.
- **D-05:** backfill is a plain UPDATE from each key's newest retained `done` `reconstruct_allocator_history` job. Every other key starts owed and is retried by the daily fan-out. No data-reading `DO` block that raises, because TEST holds schema without data (CLAUDE.md `[164.8-DATA-DEPENDENT-MIGRATION-ESCAPE]`).
- **D-06:** the daily fan-out enqueues a reconstruct for every owed key. This replaces the allocator-wide "zero snapshots" bootstrap and covers SC-2, SC-4 and SC-7. Retries are capped (D-09), and a capped key is flagged loudly, never given up silently.
- **D-07 (SC-3):** `allocator_equity_snapshots` rows are allocator totals, not per key. The sole-key replace path is taken only when no other non-deleted key (connected or disconnected) exists on the allocator. `_allocator_has_other_api_keys` counts every non-deleted sibling. Python only, no schema change.

### Landing and failure surfacing
- **D-08:** two PRs. PR 1 carries the marker migration and backfill, the `request_allocator_holdings_sync` status lists (SC-5, re-based on `20260924233749`) and D-07. PR 2 switches the fan-out (`enqueue_refresh_allocator_equity_for_all`, re-based on `20260928140000`) and the refresh hold to the marker, with the retry cap (SC-2, SC-4, SC-7). Every migration is reviewed by migration-reviewer, rls-policy-auditor and silent-failure-hunter before merge (SC-6): a merge auto-applies to PROD with no human stop.
- **D-09:** a cap of 5 attempts. After that the key raises a Sentry **event** (not a breadcrumb), and it is surfaced as "history could not be rebuilt" wherever the book's history state is read today.
- **D-10:** tests first. Every SC gets a test written first that fails on today's code (pytest, or a SQL gate arm with a `RED-UNDER` annotation that moves the mutation census), proven RED by a neuter-and-restore from a byte backup.
- **D-11:** after PR 2, run a read-only PROD census of owed keys (counts only, marker query first). Then let the next 05:00 fan-out retry them, and read the result the following day. No forced mass reconstruct.

### Decisions after research (2026-10-13)
- **D-12 (founder, AskUserQuestion, research Open Question 1: "Add audit-log evidence (Recommended)"). Amends D-05.** `retention_compute_jobs_done` reaps `done` jobs at 30 days, so D-05 alone would mark almost every PROD key older than a month as owed. PR 2's fan-out would then re-reconstruct them, and for a sole key `replace_allocator_equity_snapshots` replaces live-written refresh rows with replayed ones. The backfill therefore ALSO marks a key reconstructed when `audit_log` holds an `allocator.equity.reconstruct_*` success event for it, which survives retention. Before PR 2 merges, a counts-only PROD census (marker query first) reports how many keys would still be owed, and it is brought to the founder before the merge. This moves the D-11 census ahead of PR 2.
- **D-13 (orchestrator, research OQ2):** SC-5 adds `failed_retry` to the RECONSTRUCT gate of `request_allocator_holdings_sync` only, not to the poll-prefetch list. Adding it there would make "Sync now" return `already_inflight` for up to an hour during a poll backoff. The RPC's copy-check DO block (`c_pre_re`) keeps its poll-prefetch pin.
- **D-14 (orchestrator, research OQ3):** D-09's "history could not be rebuilt" is a NON-gating note mirroring `departedHistoryUnavailable` (research Route B), so it never blanks a trustworthy v2 curve. It excludes Deribit and strategy-linked keys, which are never counted or reconstructed.
- **D-15 (orchestrator, research OQ4):** the marker is NOT set on a sole-key DONE that wrote 0 rows from a non-empty payload (`reconstruct_unexpected_noop`); that key stays owed.
- **D-16 (orchestrator, research OQ5):** resetting `history_reconstruct_attempts` on reconnect is out of scope (not required by SC-1..7).
- **D-17 (orchestrator, research finding):** attempts are incremented in the fan-out SQL, in the same transaction as the enqueue, not in a Python hook. A hook misses preflight exceptions, reaped jobs and orphan-terminalized jobs, so the cap would never fire. The Python marker writer ships in PR 2 (research A5), so no window exists in which code writes a missing column.

- **D-18 (founder, 2026-10-13, AskUserQuestion, plan 01 forgery review: "Deny worker-only actions (Recommended)").** `public.log_audit_event` is SECURITY DEFINER, granted to `authenticated`, and has no allow-list. A signed-in user could therefore write an `allocator.equity.reconstruct_*` row for their own key and skip their own reconstruct. Cross-tenant forgery is already closed by arm B8, which requires the evidence row's `user_id` to equal the key owner's. PR 1 re-bases `log_audit_event` on its latest definition so that an `authenticated` caller cannot write the worker-only action prefixes, with a RED-first gate arm. The worker writes through `log_audit_event_service` and is unaffected. Migration-reviewer and the RLS auditor review it before merge (SC-6).

### Orchestrator calls, PR 1 review round (2026-10-13)
