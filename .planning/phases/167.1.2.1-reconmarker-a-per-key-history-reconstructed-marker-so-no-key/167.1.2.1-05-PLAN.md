<objective>
PR 2, worker (D-04, D-08, D-09, D-15, D-17). The analytics worker writes the marker, reads it, holds a book's first row on it, and raises the cap event.

Purpose: SC-1 needs the completion path to SET the marker and every Python decider to READ it. SC-7 needs the refresh hold to depend on "a key the fan-out would still retry, or one in flight", not on job timing. D-09 needs a Sentry event, which SQL cannot raise. The marker writer ships in PR 2, not PR 1, so no code ever writes a column PROD lacks (D-17, research A5).
Output: the worker changes, the hold switch, the event hook and their tests.

Revision 1 (plan-checker B1, orchestrator decision): the decider reads the marker only. An earlier draft let a retained `done` job heal the marker; that marked `reconstruct_unexpected_noop` keys (a noop ends DONE and leaves a `done` row), which D-15 forbids. The accepted cost is one redundant crawl for a key whose reconstruct completed under the old worker after M2's backfill re-run and before this code deployed.
The Python cap constant is pinned against the SQL constant and the TS constant by plan 07 Task 3 (revision 1, B3), so this plan does not read M2's text and stays in wave 3.
</objective>
