## Decisions Made
- Marker DETECTION (does this file carry a `-- LANE-ONLY:` line at all) is decoupled from JSON
  VALIDITY, matching ci.yml's own `grep -a -m1 '^-- LANE-ONLY:'` predicate exactly. A file with
  a malformed payload is still recognised as marker-bearing and throws by name — it never falls
  through to "no marker here" and silently drops out of the register.
- FORWARD and REVERSE both consume `deriveLaneOnlySites(testsDir)` — the live corpus read — not
  the hardcoded `LANE_ONLY_SITES` pin, so the cross-checks stay tied to what the corpus actually
  declares today; Task 1's own SET-pin assertion is what keeps that live derivation from drifting
  from the pinned intent unnoticed.
- Did not implement the fixture-cross-check CONTEXT.md defers, and did not widen the detector to
  "any pg-lane fixture reference" — both are explicitly named as decided-against in the new
  describe block's own comments, so the omission reads as a decision rather than an oversight.
