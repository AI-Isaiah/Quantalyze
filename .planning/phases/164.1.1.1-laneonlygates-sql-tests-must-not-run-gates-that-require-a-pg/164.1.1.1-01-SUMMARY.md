# Phase 164.1.1.1 Plan 01: LANEONLYGATES Summary

**File-level LANE-ONLY exclusion stops `sql-tests` from running `test_prod_prober_cadence.sql` against shared TEST, proven by a stub-psql invocation log rather than inspection, with neither anti-skip floor moved and all three new contract-test properties calibrated RED then restored.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 3
- **Files modified:** 3 (plus one new `deferred-items.md`)

## Accomplishments
- `supabase/tests/test_prod_prober_cadence.sql` declares itself LANE-ONLY via a single structured
  comment line (`-- LANE-ONLY: {json}`), naming the object (`net._lane_posts`), the fixture, the
  owning job (`sql-mutation`), and the reason — no executable change to the gate file at all.
- `ci.yml`'s "Run SQL self-tests" step now reads that marker pre-execution via one
  `lane_only_marker()` predicate, censuses and prints every exclusion before the loop, skips only
  the `psql` invocation and the three `"$out"`-derived checks for a marked file inside the loop,
  and keeps the entire static-analysis half (sentinel declaration, roster-vs-count coherence,
  `n_arms` ≤ RAISE-EXCEPTION-sites) running unconditionally for every file including the excluded
  one. `SENTINEL_FLOOR` (11), `ARMS_FLOOR` (213), and the per-file derivation table are
  byte-unchanged.
- The closing summary no longer overclaims a pass for a file that never ran: it now reports
  executed/found, excluded count, and sentinels verified-this-run vs. declared, plus a fifth
  standing limit documenting exactly what the exclusion does and does not prove.
- `ci-anti-skip-gate.contract.test.ts` gained a real measurement instrument
  (`STUB_INVOCATION_LOG`), a defect-injection capability (`STUB_FAIL_BASENAME`) reproducing the
  shipped CI failure verbatim, and three new scenarios plus one honest rename — 21/21 passing.
- All three new contract-test properties were individually neutered, observed to redden for the
  predicted reason, and restored byte-identically (`shasum -a 256` equal pre/post every cycle).

## Decisions Made
- Implemented the no-floor-move design exactly as the CONTEXT.md/RESEARCH.md ORCHESTRATOR
  CORRECTION specifies — skip execution plus the three `"$out"`-derived checks only, never the
  static accounting. Confirmed via `mutation-runner --parse-only` (prober file still 7 prose / 7
  twin(s) / 0 waiver(s)) and a whitespace-blind `git diff -w` over `ci.yml` showing no content
  change inside the region moved into the `else` branch.
- Gave the one `"$out"`-derived check inside the static block (the completion-sentinel-printed
  check) a third arm — LANE-ONLY / found / not-found — rather than moving it into the execution
  branch, since it needs to run per-file inside the static block that already iterates every file.
- Chose an occurrence-count assertion (not presence/absence) for the static-accounting scenario's
  guard-the-guard check, because `test_sync_status_curated_sentence_survives.sql` independently
  declares the same `"ALL 7 ARMS EXECUTED"` text as the excluded file — a bare `.toContain()` could
  not distinguish "the excluded file's line printed" from "a different file's identical-looking
  line printed."

## Calibration Log (Task 3)

Protocol followed for all three: `cp` a byte backup to the session scratchpad, record
`shasum -a 256` of the original, mutate, run
`npx vitest run src/__tests__/contracts/ci-anti-skip-gate.contract.test.ts`, observe, restore by
copying the backup back (never `git checkout --`), re-take `shasum -a 256` and confirm equality.

1. **Calibration 1 — the exclusion is never silent.** Deleted the `::notice file=…::` emission
   from the pre-loop census, leaving the `lane_only_count` increment intact. Result: the
   never-executed scenario reddened on its missing-`::notice::`-annotation assertion
   (`AssertionError` at the `toContain('::notice file=supabase/tests/...')` line); the calibration
   pair stayed green (`Tests 1 failed | 20 passed (21)`) — proving the two scenarios measure
   different properties. Restored; post-restore digest
   `1d4ecbdb96eaa07abdfdb7b0c99511edd60e14d2573505e30d3115ed5514aa69` equals pre-mutation.

2. **Calibration 2 — the static accounting really does survive.** Wrapped the
   `sentinels_declared=$((sentinels_declared + 1))` increment in `if [ -z "$lane_marker" ]; then …
   fi`, so it is skipped for the lane-only file. Result: `sentinels_declared` fell to 10 against a
   floor of 11, the step self-inflicted a red (`exit 1`), and that cascaded into every default-run
   assertion (`Tests 4 failed | 17 passed (21)`), the static-accounting scenario named among them —
   exactly the rejected `continue`-at-top design's signature the RESEARCH ORCHESTRATOR CORRECTION
   predicted. Restored; post-restore digest equals pre-mutation
   (`1d4ecbdb96eaa07abdfdb7b0c99511edd60e14d2573505e30d3115ed5514aa69`).

3. **Calibration 3 — the marker is what does the work.** Deleted the `-- LANE-ONLY:` line from
   `test_prod_prober_cadence.sql` (line 182). Result: the never-executed scenario reddened (the
   basename now appears in the invocation log; `logged.length` became 74 including the target,
   failing `not.toContain(target)`), and the calibration pair's second arm reddened
   (`spared.code` became `3`, the injected defect now reaching the un-excluded file) —
   `Tests 3 failed | 18 passed (21)`. The static-accounting scenario also reddened as an expected
   side effect (`verified` moved from 10 to 11, since the file now executes and its own sentinel
   gets checked normally) — consistent with, not contradicting, the calibration's purpose. Restored
   both files; post-restore digests
   (`.github/workflows/ci.yml`: `1d4ecbdb96eaa07abdfdb7b0c99511edd60e14d2573505e30d3115ed5514aa69`,
   `supabase/tests/test_prod_prober_cadence.sql`:
   `5a324ff9976c87e54546516dcc9aabf301d0849a816d09a4f533a38fffa5c1a7`) both equal pre-mutation.
