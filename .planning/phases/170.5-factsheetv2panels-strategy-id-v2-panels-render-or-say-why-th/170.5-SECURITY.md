## Review-round check: `fetchStrategyLazyMetricsClient` (src/lib/queries-client.ts)

The review rounds changed the failure behaviour from "resolve `{}`" to "throw" on RPC error, null/undefined payload and non-object payload. No mitigation was weakened:

1. Invisible strategy: the RPC (`20260428120919_strategy_analytics_series.sql:132-160`, SECURITY DEFINER, `SET search_path`) checks `status = 'published' OR user_id = auth.uid()` and returns `jsonb_build_object()` otherwise. That `{}` still resolves (`queries-client.test.ts` "valid EMPTY object resolves {}"). It is the only data an invisible strategy yields, so panels render their say-why or empty state and no series from an invisible strategy can render. Only that one migration defines the function (no later redefinition). The v2 page also 404s for any non-published strategy before any panel mounts (`getStrategyDetailV2` uses `withPublishedOnly`).
2. Anon JWT only: the client uses `@/lib/supabase/client` (browser client); no service-role path. The visibility gate stays inside the RPC, not in client code.
3. Error-path leakage: the thrown `Error` messages (RPC error message, panel id, payload shape type) are consumed by `useLazyPanelMetrics`'s `.catch` and `HeadlineMetricsPanel`'s `.catch`, which only `console.error` and set `status = "error"`. The message is never stored in component state or rendered; the visible copy is fixed strings ("Couldn't load this section", "Log returns didn't load. Retry, or refresh the page."). It does not go to Sentry from the client path. No row, id or SQL detail reaches the DOM.
4. Fail-closed direction: a null/array/primitive payload used to be treated as valid empty; it now throws, which strengthens the shape guard.
5. R2-01 retry in `HeadlineMetricsPanel` refetches from `error` through the same fetcher and visibility gate; it adds no new endpoint.
6. Tests run at HEAD: 12 files, 139 tests pass (queries-client, v2-trust-tier, queries.v2-joint, v2-joint, benchmark-why, `src/app/strategy/[id]/v2`, phase-148 isolation, lazy-panel-fetch-failure, axis-unit, panel7-series).

## Notes (informational, not findings)

1. T-170.5-15 wording: the PLAN says the panel "no longer charts `turnover_series` at all". The code still charts `turnover_series` rows that carry a finite `value` (the `TurnoverChart` contract), while every stored legacy `{date, turnover}` row is withheld. The analytics worker writes no `value` rows today, so the max-exposure-scaled figures are never displayed. The threat's intent holds. If a writer ever emits `{date, value}` rows, re-audit this row.
2. T-170.5-05: `RollingMetricsPanel` guards on the finite-point count but still passes the raw series to `RollingAlphaBetaChart`; non-finite points beyond the guarded pair can reach Recharts, which draws gaps. This is display-only and does not meet the high/critical bar.
