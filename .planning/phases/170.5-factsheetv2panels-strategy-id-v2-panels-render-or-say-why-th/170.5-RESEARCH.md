[VERIFIED: src/app/strategy/[id]/v2/page.tsx:4 `import { StrategyV2Shell } from "@/components/strategy-v2/StrategyV2Shell";`]

Four of the five root causes are on the v2 side and none needs Python, SQL or a migration: (1) the Rolling alpha and beta section is rendered with `gated={false}` and no reason, over one window-independent 90-interval series that is empty for all three published strategies; (2) the IR cell reads a JSONB key the Python never writes, the correlation strip cannot tell "under 90 days" from "unavailable", and one published strategy has no stored greeks at all because the benchmark was unavailable at its last compute; (3) exposure is stored as **USD notional**, and the chart multiplies it by 100 and prints a percent; (4) the stored `turnover_series` rows are keyed `turnover` where the chart reads `value`, **and** their values are price-scaled (244 to 4,210), so there is no honest chart to draw; (5) `getStrategyDetailV2` projects no `trust_tier`, so `Disclaimer` defaults to "self-reported" and `VerifiedBadge` fails closed.

One locked decision rests on a false premise and needs the founder: **D-02 says the factsheet reads a stored source for alpha, beta, IR and Treynor. It does not.** The factsheet computes all four in TypeScript at build time from daily returns and the `benchmark_prices` table; v2 reads the values the Python worker stored at its last run. The two use different IR (sample vs population standard deviation) and different Treynor definitions (CAGR vs annualized arithmetic mean), so they cannot agree to display precision. See Open Question Q1; the plan below defaults to reading the stored source (the literal D-02 wording) and fixing everything that makes it dishonest.

**Primary recommendation:** fix all five in `src/components/strategy-v2/*`, `src/components/charts/{NetGrossExposure,Turnover,RollingAlphaBeta,CorrelationWithBenchmark}*` and `getStrategyDetailV2`; add no Python and no migration; write the five failing-first tests (all verified RED against today's code, see Code Examples); keep every "why" message deterministic from stored flags and history counts.

| | v2 `/strategy/[id]/v2` | Factsheet `/factsheet/[id]` |
|---|---|---|
| Source | `strategy_analytics.metrics_json` keys written by `compute_all_metrics` at the last analytics run | daily returns + `benchmark_prices` read at payload build, then `jointMetrics` in TypeScript |

**Three independent causes found:**

(a) **Key mismatch, IR is always em-dash on v2.** Python writes `metrics_json["info_ratio"] = _safe_float(_info_ratio)` (metrics.py:2569, only when `te > 0` at :2568). TypeScript reads `information_ratio` then `ir` (queries.ts:1760-1763). The test fixture invents the long key (`queries.test.ts:918` `information_ratio: 0.42`), which is why it never failed. `src/lib/types.ts:289` names `info_ratio` as canonical. PROD: A and C store `info_ratio` -1.8457 and -0.3821 and v2 prints "—" for both. Treynor survives only through the `treynor` fallback (queries.ts:1768; Python writes `metrics_json["treynor"]` at :2572). [VERIFIED: metrics.py:2569, 2572; queries.ts:1760-1769]

(b) **Strategy B has no stored greeks at all.** Its row carries `data_quality_flags` `benchmark_unavailable`, `benchmark_note`, `csv_source`; `alpha`, `beta`, `info_ratio`, `treynor`, `correlation` and `btc_rolling_correlation_90d` are all absent. So the factsheet has numbers where v2 has none. [VERIFIED by PROD read: counts and values only; the factsheet render itself was not opened, see A3]

(c) **"Benchmark correlation unavailable." names no cause.** `resolveBenchmarkCorrelation` returns it for any absent key (CorrelationWithBenchmark.tsx:134-137), and the panel passes no `computation_status`, history or flags. The key is absent for A (73 days) and C (25 days) because Python writes it only when `len(aligned_returns) >= 90` (metrics.py:2573), and for B because there was no benchmark. All three published strategies therefore print the same bare sentence for three different reasons. `CORRELATION_90D_MIN_DAYS = 250` (min-history.ts:20) is a different floor from the 90 Python computes at; it only fires for an empty array, which the 90-pair gate means Python does not write. [VERIFIED]

**Agreement is impossible for IR and Treynor even with the key fixed** (definitions, not data):
- alpha and beta: same formula (`_greeks_no_guess` vs `jointMetrics`), both arithmetic annualized, same interval pair (166.4 D-A). They agree to rounding.
- IR: Python uses pandas `std()` (ddof 1), `_annualized_vol_sharpe` docstring "pandas ddof=1" [VERIFIED: metrics.py:598]; TypeScript uses `sharpe(active, { periodsPerYear, ddof: 0 })` [VERIFIED: joint.ts:72]. Ratio sqrt(n/(n-1)), about 0.7% at n=72 and 2% at n=24, enough to change the second decimal the factsheet prints.
- Treynor: Python `cagr / beta` [VERIFIED: metrics.py:2572 `metrics_json["treynor"] = _safe_float(cagr / beta)`]; TypeScript `((m - rf / periodsPerYear) * periodsPerYear) / beta` with `m` the arithmetic mean [VERIFIED: joint.ts:73-74]. PROD A: stored treynor -2.8659 equals stored cagr 0.0157 divided by stored beta -0.0055.

**Fix (default plan = stored source, Q1 open).**
1. Read `info_ratio` first, then `information_ratio`, then `ir` (queries.ts:1759-1764). Keep the existing fallbacks so old fixtures hold.
2. Apply the factsheet's floor: when `history_days < MIN_PAIRED_OBSERVATIONS` withhold all four and print `pairedFloorReason("BTC", history_days, "record")`. v2 must never print a number the factsheet withholds. (`history_days` is an upper bound on the paired count; accepted, see A6.)
3. Flat leg (FACTSHEETTRUTH D-04): when the stored headline `volatility === 0` withhold alpha, beta, IR and Treynor with "No dispersion in this record." The persisted flat signal is `0.0`: [VERIFIED: metrics.py:1939-1943 `0.0` / `if _dispersion_is_residue(float(stat_returns.std()), float(stat_returns.mean()))`]. Python stores beta `0.0` for a flat strategy leg (metrics.py:1542-1548 docstring), which would print "0.000" beside the factsheet's "—".
4. Otherwise a null greek prints "—" with the reason ladder above plus per-cell causes: Treynor needs a non-zero beta, IR needs a tracking error above zero (Python's `te > 0` guard).
5. `CorrelationWithBenchmark`: add an optional context (`history_days`, flags) to the resolver; the absent-key case then returns the ladder's message, with the 90-day floor, instead of the bare sentence. Do not touch the `[]` branch or the 250 constant.

### Pattern: one reason ladder
**What:** a pure function `benchmarkWhy({ flags, historyDays, floor, flatLeg })` returning `{ kind, message } | null`, used by the rolling section, the correlation strip and the greeks table.

### Anti-Patterns to Avoid
- **Renaming `turnover` to `value`** to make the chart draw: prints price-scaled values as percents.
- **Hand-typing fixtures** with the keys you wish the producer wrote (`information_ratio`, `gross: 0.8`, `value`): every one of the four mismatches here was invisible to its own tests. Use the producer's literal shape, cited to its writer line.
- **A "—" with no reason** where the reason is derivable from stored flags and `history_days`.
- **Deriving the paired count from the toggle.** Alpha/beta is one 90-interval series; the toggle must not appear to change it.

## Common Pitfalls

### Pitfall 1: the toggle label implies a window the data does not have
**What goes wrong:** 3M/6M/12M gates use 90/180/365 calendar days, but the Python windows are 63/126/252 rows (metrics.py:2677-2691), and the "3M" Sharpe is `sharpe_30d`. A 130-day strategy is told "need >=180 days" while 5 six-month points exist.
**How to avoid:** not in the five defects; do not widen scope. Say alpha/beta is fixed at 90 and leave the other gates. Booked as Q7.
**Warning signs:** a say-why N that differs from the stored series length.

### Pitfall 2: one-point series
**What goes wrong:** exactly 90 paired intervals yields one alpha/beta point; a `dot={false}` line chart draws nothing, so the panel is "rendered but empty".
**How to avoid:** gate on at least 2 finite points, not on `length > 0`.

### Pitfall 3: stale series presented as current
**What goes wrong:** exposure ends 2026-06-01 on a page computed 2026-10-09.
**How to avoid:** caption the last point's date; never imply currency.

### Pitfall 4: asserting numeric equality with the factsheet for IR/Treynor
**What goes wrong:** the definitions differ (Defect 2), so a test comparing the two pages' IR to 2dp fails or, worse, passes on a fixture where n is large.
**How to avoid:** assert key mapping, reasons and floors, not cross-page numeric equality, unless Q1 picks the computed source.

### Pitfall 5: a shared `Disclaimer` edit
**What goes wrong:** changing the null-tier sentence also changes `/strategy/[id]` and `/browse/...`, and `Disclaimer.test.tsx:30` pins "missing trustTier defaults to self_reported".
**How to avoid:** fix the data (project the tier), leave `Disclaimer` alone. Residual null case is Q5.

### Pitfall 6: the worktree has no `node_modules`
**How to avoid:** `npm ci` in the worktree before the first vitest run (see Environment Availability).
