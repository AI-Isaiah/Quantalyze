<objective>
Give anonymous `/process-key` traffic a per-IP bucket behind a signed pseudonym, put an aggregate anonymous ceiling on top, and fix the stack order so a refused request spends no shared token (RLIM-01, Python half).

CONTEXT ruling, verbatim: "Per-IP anonymous tier. The TS teaser route (`src/app/api/verify-strategy/route.ts`) mints the anonymous tenant claim with a hash of the client IP, read at Vercel from `getClientIp`, never Railway's proxy IP. Python keys `process_key:anon:<iphash>` at 30/hour per IP." and "An aggregate anonymous ceiling sits on top, kept well below the shared 500/hour `/process-key` ceiling, so anonymous traffic as a whole cannot starve tenants."

Purpose: today every anonymous visitor shares ONE 30/hour bucket, and the platform ceiling is evaluated BEFORE the per-identity limit (slowapi evaluates the bottom decorator first), so a refused anonymous call has already burned a ceiling token (RESEARCH Pattern 2, probe-proven). This plan accepts both claim grammars (bare `public` and `public:<hex>`) so it can ship before or with the TS mint (plan 06).

Output: one claim classifier in `services/rate_limit.py`, the three-limit stack in `routers/process_key.py`, the alert re-key, the widened proxy-IP pin, corrected docblocks, and a new behaviour test file.

TODOS this plan closes jointly with plan 06 (deleted at ship, not here): "verify-strategy teaser: per-IP front door cannot see the shared anon bucket".

Budget: the estimate (110,000 tokens, uncalibrated, confidence low) is over the 100,000 smart-zone budget; the orchestrator accepted that knowingly at revision round 1, and the plan is not split.
</objective>
