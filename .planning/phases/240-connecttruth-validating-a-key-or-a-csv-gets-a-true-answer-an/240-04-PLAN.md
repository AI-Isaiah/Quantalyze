<objective>
Give CSV validation its own per-user upstream tier, exempt from the platform ceiling, so a signed-in user inside the edge limit never gets an upstream 429 (RLIM-02, Python half).

CONTEXT ruling, verbatim: "CSV-scoped upstream tier. csv-validate sends a signed scope signal (carried by the signed claim or an HMAC-covered header — never an unsigned header). Python gives CSV validation its own per-tenant bucket sized at or above the edge limit (20/minute), exempt from the shared 500/hour ceiling or given its own slice of it, so a CSV user inside the edge limit is never refused upstream." Discretion resolutions, verbatim: "CSV tier and the ceiling: EXEMPT from the 500/hour ceiling (the only reading under which \"never gets an upstream 429\" holds); CSV per-tenant tier 60/minute (three times the edge bucket, covering bucket straddle and latency)."

Purpose: the edge admits 20 per 60 s per user (1,200/hour) while `/process-key` gives that user 100/hour shared with keys/sync and finalize-wizard, a 12x mismatch (TODOS). The scope rides the signed claim as `csv:<uuid>` (plan 06 mints it inside `postProcessKey` from `flow_type`).

Output: the `csv` kind in the classifier from plan 02, the 60/minute tier, the ceiling exemption, a new behaviour test file and the moved literal pins.

TODOS this plan closes jointly with plans 06 and 07 (deleted at ship, not here): "csv-validate: 12× over the shared `/process-key` tenant tier + stale docblock citation".
</objective>
