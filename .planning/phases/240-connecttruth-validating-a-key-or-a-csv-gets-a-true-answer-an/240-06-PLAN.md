<objective>
Mint the two new claim payloads in the one chokepoint: the per-IP anonymous pseudonym for the teaser and the csv scope for CSV validation (RLIM-01 and RLIM-02, TS half), and bind both languages to the grammar through the committed fixture.

CONTEXT rulings, verbatim: "The TS teaser route (`src/app/api/verify-strategy/route.ts`) mints the anonymous tenant claim with a hash of the client IP, read at Vercel from `getClientIp`, never Railway's proxy IP." and "csv-validate sends a signed scope signal (carried by the signed claim or an HMAC-covered header — never an unsigned header)."

Purpose: plans 02 and 04 made Python classify `public:<hex>` and `csv:<uuid>`; nothing sends them yet. Deriving both inside `postProcessKey` means no route can forget them: all four call sites pass `flow_type` as a literal (`csv-validate` csv, `finalize-wizard` onboard, `keys/sync` resync, `verify-strategy` teaser).

Output: `anonymousClaimPayload` in `tenant-claim.ts`, the derivation in `postProcessKey`, `clientIp` on the teaser call, new fixture cases and the Python parity bucket assertions.

Deploy window that actually happens: Vercel deploys on merge and Railway only after main CI is green, so for that gap the new TS (plan 06) runs against the old Python. Old Python buckets any payload other than bare `public` as a tenant key, so a per-IP anonymous claim lands in `process_key:t:public:<hex>` and a `csv:` claim in `process_key:t:csv:<uuid>`, each at the 100/hour tenant tier under the 500/hour ceiling. That is benign and not an outage: no caller gets less than HEAD gives them today (an anonymous visitor gets a per-IP 100/hour instead of one shared 30/hour, and CSV validation gets its own 100/hour instead of sharing the user's tenant bucket), and the window closes when Railway deploys.
