<objective>
Make a month-name date cell in a numeric-date CSV column parse instead of failing (CONN-06). CONTEXT ruling, verbatim: "Parse the month-name cell (e.g. `12 Mar 2024` in a `DD/MM/YYYY` column). A month name carries no day/month ambiguity, so the reading cannot land in the wrong calendar. Flag it through the existing date-normalization info flag. Closes TODOS `[170.1-CSV-ODD-SPELLING-REJECTED]` with a test."

Purpose: today pandas infers ONE format from the first cell of the date column, so a `12 Mar 2024` cell in a `DD/MM/YYYY` column becomes NaT under both readings and is rejected as `coerce_dtype` at its row (and a month-name FIRST cell makes every other row fail). The fix masks month-name cells out of both readings, parses them with a strict locale-free reader, and merges them back into both readings, the same technique the function already uses for year-first cells.

Output: the month-name reader and merge in `services/csv_validator.py` (date-detection symbols only) and the acceptance, rejection and flag-text pins in the existing date-format test file.

TODOS this plan closes (deleted at ship, not here): `[170.1-CSV-ODD-SPELLING-REJECTED]`.
</objective>
