<objective>
Close the validate-and-encrypt bare-parse entry under TODOS "Two guard gaps on `keys/validate-and-encrypt`" (ROADMAP SC4). Malformed JSON, a literal `null` body or any non-object JSON value returns the route's coded 400 envelope, `{ code: "KEY_MISSING_REQUIRED_FIELD", error: "Invalid request body" }` with `NO_STORE_HEADERS`. The guard is copied exactly from the `strategies/create-with-key` sibling (D-13), and both censuses that count this route's emissions move on purpose (D-14).

Purpose: today the first statement of `POST` awaits `req.json()` with no catch, and `withAuth` has no catch either, so the caller gets a Next.js default 500 with no machine code. That contradicts the route's own invariant, "a machine code on every error arm". The parse error must also be swallowed rather than logged, because a V8 `SyntaxError` message can quote a fragment of a body that carries raw exchange credentials.

Output: the guard in `route.ts`; a `[209 SC4]` describe and the moved count in `route.test.ts`; the moved `expectedSites` and its lineage comment in `wizardErrors.invariant.test.ts`; neuter-to-RED proofs in the SUMMARY (SC5).
</objective>
