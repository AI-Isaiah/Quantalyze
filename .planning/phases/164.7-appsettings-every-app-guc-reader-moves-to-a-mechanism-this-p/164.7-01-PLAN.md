<objective>
Ship the machine that stops the next `app.*` GUC reader from being written into `supabase/migrations/**` (ROADMAP criterion 1, CONTEXT D-05), as a SIBLING of `scripts/lint-sql-gates.mjs` with the identical contract — hermetic, fixture-paired, self-tested first, wired into the existing `sql-gate-lint` job.

**Why a sibling, not an eighth rule (RESEARCH Q3, accepted as measured):** `lint-sql-gates.mjs` has `CORPUS_DIR = supabase/tests` and runs every rule on `maskSql()` output, which blanks `--` comments, block comments AND the contents of string literals — after masking, an app-GUC read is invisible, and D-05 requires the gate to COUNT comments. Its vitest pins the rule set and the mechanism multiset `[1,2,3,4,6,6,6]`; a rule that is not a vacuity mechanism does not belong in that registry.

**The exemption design — RESEARCH's proposal ACCEPTED, with one addition.** RESEARCH recommends a file-level dated header carrying an EXACT occurrence count (the ratchet `lint-sql-gates.mjs`'s ALLOWLIST already uses — more OR fewer is a finding) plus a successor-file zero-check. Accepted: it is falsifiable in both directions on an annotated file (add a reader → count off → fires; remove one → fires). PATTERNS' block-marker alternative (`-- LINEAGE …` / `-- END LINEAGE` around each site) is REJECTED because a block that wraps executable code exempts executable code, and nothing in the block form can tell the two apart — that is "an exemption any comment satisfies", the milestone's named defect. The ADDITION closes the one hole the header alone leaves: a NEW migration that carries a fresh header pinning its own count would exempt itself. So the script carries `LINEAGE_ALLOWLIST` — `{ file, occurrences, successor, reason }` entries, the `lint-sql-gates.mjs` ALLOWLIST shape verbatim — and a header on a file absent from it is the finding `header-not-allowlisted`; an allowlist entry whose file has no header, or whose count disagrees with the header, is an error. Exempting a reader therefore takes two independent edits in two files, both count-pinned, both reviewable. Comparison against the `unreachable:` print in the mutation runner: the annotated files are printed BY NAME on every run, the way `run.mjs` prints its classes.

**The interim this plan creates, stated so nobody debugs it:** at this plan's final commit the corpus step is RED — 12 findings, 5 files — and stays red until plan 05 annotates the five files and fills the allowlist. That is the gate seeing the tree, not a regression. No push and no `workflow_dispatch` before plan 05 lands (same rule as 164.4.1's tripwire interval). Every commit in the interval carries `APP-GUC-INTERVAL:` in its body.

Purpose: SC-1 and D-05 — the machine half of "every reader moves".
Output: the script, its fixtures, its vitest pin, the CI steps, and the neuter evidence log.
