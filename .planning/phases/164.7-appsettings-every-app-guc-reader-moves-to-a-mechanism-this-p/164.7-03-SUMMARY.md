## Decisions Made

1. **A second disjoint timestamp range, never a widen.** MEASURED 2026-09-07: the span `[20260825000000, 20260908000000)` holds ELEVEN migrations, and `20260826140000_compute_jobs_error_kind_orphaned.sql` carries 3 raw `cron.schedule`/`cron.unschedule` hits — a legitimate registration that has nothing to do with this fan-out. A contiguous widen would have made floor 4 report `LEDGER-02 DORMANCY VIOLATION` against a correct file on the very commit that landed this change, and a gate that goes red on correct code gets relaxed. Window 2 is `[20260907130000, 20260907130001)`, one stamp wide, so it cannot silently acquire a neighbour. The failure messages now instruct a future author to ADD a range, never to widen one.

2. **`_PHASE_MIGRATION_NAMES` gains the new file and the selection now EQUALS it** (5 files) — asserted by the verify, so a dropped range or a redating fails by name rather than shrinking the scan quietly.

3. **The retired `app.` setting name is KEPT as a token, and the new key is ADDED.** Floor 2 requires every token to resolve in a scanned migration; the retired one resolves in `20260825130000`/`140000` (MEASURED: those two files and no others carry it, so floor 3's `escaped` check cannot fire on it either). Keeping only the retired one would leave the LIVE surface unguarded the day the last 20260825 reader is redated away.

4. **The normaliser list was retired, and its lesson was not.** With a `BOOLEAN NOT NULL` column there is no string to normalise, so a list of normalisers would be an assertion that cannot fail. The F16 lesson is transposed into an explicit must-not-appear list — `IF NOT <var>` and `IF <var> <> TRUE` — because those are the boolean spellings that read as correct and open the flag on the failure path.

5. ⭐ **The two layers each catch what the other cannot, and this was MEASURED, not assumed.** Neuter N1(a) — the crude `IS DISTINCT FROM TRUE → = FALSE` swap — never reaches the tracer: the migration's OWN verify check (5) aborts the apply first. So N1(b) keeps the token and is still NULL-unsafe (`IF v_enabled IS NOT NULL AND v_enabled IS DISTINCT FROM TRUE`); it passes the migration's text check, the apply goes green, and only the tracer's `(T-a)` arm catches it. N3 is the mirror: a guard moved BELOW the advisory lock satisfies every text check the migration makes about itself (the migration printed its success NOTICE on that file), and only pytest's first-statement assertion sees it.

6. **N-P6 exists for the same reason one level down.** N-P5 (`IF NOT v_enabled`) reddens on the POSITIVE comparison assertion, which on its own would leave the must-not-appear list unproven. N-P6 keeps a correct guard and adds an unsafe spelling beside it, so only that list can fire.
