## Decisions Made

1. **Successor resolution is sibling-relative.** The plan says the successor "must exist under `MIGRATIONS_DIR`", and its own fixture design has the green fixture naming a successor inside the FIXTURE directory. Resolving against `dirname(annotated file)` satisfies both: for every real migration that directory IS `supabase/migrations`, so the corpus behaviour is identical to the literal wording. Documented at the call site.
2. **A directory named `x.sql` is a corpus entry, not a directory to walk.** The recursive walker tests the `.sql` suffix BEFORE `isDirectory()`, so such an entry reaches `scanFile` and MEASURE_FAILs with EISDIR. Walking past it would have let an unreadable corpus entry read as clean, which is threat T-164.7-04 in the shape the plan's own vitest arm (f) was written to catch.
3. **MEASURE_FAIL uses `::error::` with no `file=` field.** So "12 findings" counted by `grep -c '::error file='` can never be inflated by a measurement failure — the two failure classes are distinguishable in the CI log by prefix alone.
4. **`unannotated-comment` is a fixture, not a kind.** A comment read and an executable read are the same finding; making the comment case its own kind would have implied a policy difference the gate does not have.
