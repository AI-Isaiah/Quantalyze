## New trap, measured while executing this plan

⛔ **`gh api …/actions/jobs/<id>/logs` REFUSES a log containing terminal escape sequences** — it
exits **1 with EMPTY stdout**: *"the response contains terminal escape sequences; pass
--allow-escape-sequences to output it anyway."* Measured: without the flag `rc=1, bytes=0`; with it,
`rc=0, 681 lines`. This matters because the plan mandates this path over `gh run view --log`
(which truncates), and an empty log read as "no drift" is a false green of the exact shape this
project books. **Always pass `--allow-escape-sequences` and assert a non-zero line count before
concluding anything.**
