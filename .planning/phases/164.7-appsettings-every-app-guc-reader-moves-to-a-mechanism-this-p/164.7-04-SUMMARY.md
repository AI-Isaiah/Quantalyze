## Decisions Made

1. **`nth`, not a widened needle, and not mutating both bodies.** The plan allowed
   either. `nth` is already in the GRAMMAR, it keeps each twin mutating exactly the
   body its arm names, and — crucially — its failure mode is loud: if the two
   `CREATE OR REPLACE` blocks are ever reordered, the twin mutates the wrong body,
   the gate does not redden and the runner reports `no-red`. Every affected twin
   carries a note saying which body it selects, why, and what happens on a reorder.

2. **Arm A's and K's twins PRESERVE `IS DISTINCT FROM TRUE`.** The plan specified
   `= FALSE` (arm A) and `IS NULL` (arm K). Both delete the token that
   20260907130000's own verify block, check 5, requires **per function** — plan 03
   measured exactly this as neuter N1(a). The migration would abort, the gate would
   never run, and no arm could be the first failure. The shipped twins add a NULL
   guard beside the token instead, which passes the apply-time text check and still
   opens the flag on precisely the path the arm names.

3. **Arm 0's new probe reads a COMMENT-STRIPPED body.** The plan wrote
   `pg_get_functiondef(…) !~ 'FROM public\.system_flags'`. Lint rule R2 fires on
   that, and rightly: the migration's body comments discuss `public.system_flags`
   at length, so the raw match would be satisfied by the prose describing the read.
   `regexp_replace(…, '--[^\n]*', '', 'g')` is the idiom five other gates in this
   corpus already use.

4. **Arm J's twin gained a FOURTH `ALTER TABLE … OWNER TO`, found by measurement.**
   The first lane run of each rewritten gate reported `WRONG-ARM(B)`. The 164.7
   guard adds a read of `public.system_flags`; the drift role is exempt from row
   security by neither route, the RLS-enabled stand-in admits it no rows, the flag
   reads NULL, the fan-out goes dormant and arm B fails ~400 lines before arm J.
   Moving `system_flags` with the other three tables isolates the one property under
   test — the same reasoning, and the same sentence, the arm already carried for the
   other three. (A table owner is not subject to RLS absent `FORCE ROW LEVEL
   SECURITY`, which neither the fixture nor `20260407164606` sets.)

5. ⭐ **The neuter falsified the plan, and the plan lost.** N3 was specified as
   "revert the precondition to a NOTICE … arm A must go RED for the wrong reason
   (this proves the precondition guards A's meaning)". Leg (c) measures that it does
   **not**: with a committed-TRUE row and the precondition downgraded to a NOTICE
   and no mutation at all, the file runs to `ALL 12 ARMS EXECUTED (A-L) and passed`.
   The reason is this plan's own rewrite — the pre-164.7 arm A read a SESSION setting
   it never set, so a session that already had it on made the arm vacuous; the new
   arm A DELETEs the row and arm K UPSERTs it FALSE, so each dormant arm builds the
   state it measures. The precondition was **kept**, because leg (a) shows it firing
   on a condition worth firing on, and its comment and RAISE message were rewritten
   to say what it actually guards (an operator's LIVE row, which this file would
   otherwise lock and overwrite inside its transaction on a shared project).

6. **A literal doubled dollar sign may not appear in a comment inside these gates.**
   Arm L's prose originally wrote out the dollar-quote token; it CLOSED the `DO`
   block, and psql reported `syntax error at or near "…"` against the file's LAST
   line — 660 lines from the cause. Both gates now carry the warning in place of the
   token.
