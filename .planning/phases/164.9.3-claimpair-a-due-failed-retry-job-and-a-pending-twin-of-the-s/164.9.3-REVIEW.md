## Info

### IN-01: Every count arm assumes its rows fall inside `LIMIT 1000`

**File:** `supabase/tests/test_claim_compute_jobs_failed_retry_pending_pair.sql:186` (and each claim call)
**Issue:** The claims are queue-wide and ordered by `next_attempt_at, id`. If the lane carries more than 1000 due, claimable, committed rows older than `now() - 10 minutes` (the header says the sql-tests lane "carries rows other gate files commit"), the arm's twin or unrelated job falls past the LIMIT cut. The arm would then false-red with `n_twin = 0`.
**Fix:** Before each claim, assert that no more than 900 claimable due rows exist outside the arm's ids, and raise a named setup error otherwise. Or push the arm's `next_attempt_at` values into the far past (e.g. `now() - interval '10 years'`) so they sort first.

### IN-02: Three of the four C39 clauses ported into the 2-arg have no behavioural arm

**File:** `supabase/tests/test_claim_compute_jobs_failed_retry_pending_pair.sql:1032-1113`; `supabase/migrations/20260927120000_claim_pair_pre_rank_exclusion.sql:611-636`
**Issue:** P2-C39 exercises only the `api_key_id` clause. If the portfolio, strategy or allocator clause of the port were deleted, only the apply-time `c_c39_re` regex (`:721-722`) would notice, and a self-check is a placement check, not behaviour.
**Fix:** Add P2-C39 variants for the other three partitions, or document that the regex is the accepted sole guard.

### IN-03: No arm covers a cross-kind sibling or a pair that shares only one of two set partition columns

**File:** `supabase/tests/test_claim_compute_jobs_failed_retry_pending_pair.sql` (all partition arms)
**Issue:** The `x.kind = compute_jobs.kind` correlation is pinned only by the self-check regex. If it were dropped, a pending row of a DIFFERENT kind on the same partition would hold the retry back. That is silent over-exclusion, and no arm would redden. Likewise, no arm seeds a retry and a twin that set two partition columns but share only one.
**Fix:** Add a negative arm: a due failed_retry beside a pending row of another kind on the same partition id must be claimed. Add a two-column arm as well.

### IN-05: The 2-arg overload is still maintained dead code with a pre-P97 body

**File:** `supabase/migrations/20260927120000_claim_pair_pre_rank_exclusion.sql:504-656`
**Issue:** Every call to the 2-arg resolves as 42725 while the 5-arg exists. Its body still sets no `claim_token` and clears no `last_error`/`error_kind`. If the 5-arg were ever dropped, this body would become callable, and the claim token of every row it claims would fail the mark-RPC fence. The phase keeps it deliberately (a drop makes VAC-04 report `SNAPSHOT_MISSING`), and the header records this. It is pre-existing and noted here only so the drop path gets an owner.
**Fix:** Book a VAC-04 acknowledgement path for a dropped function, then drop the 2-arg.
