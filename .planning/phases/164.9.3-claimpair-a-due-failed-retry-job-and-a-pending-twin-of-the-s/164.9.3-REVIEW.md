## Warnings

### WR-01: The probe still counts a retry held back by C39 beside a `done_pending_children` row, and the residual prose calls that hold bounded when it is not

**Files:**
- `supabase/migrations/20260927120000_claim_pair_pre_rank_exclusion.sql:42-43`: header residual (i), "What stays: C39 still counts a retry beside a running row in the probe, a hold that ends when that row finishes."
- `supabase/migrations/20260927120000_claim_pair_pre_rank_exclusion.sql:357-386` (5-arg) and `:583-612` (2-arg): the two PROBE EXCLUSION blocks, whose inner sibling test is `p.status = 'pending'` only.
- `CHANGELOG.md` `[0.108.0.0]` `### Notes`, first bullet: "neither the far-future-twin hold nor the low-twin wedge remains". It has no "what stays" sentence.
- `TODOS.md` `[164.9.3-CLAIM-PAIR-23505]` closure: the same sentence, and no "what stays".

**Issue.** WR-01's own principle is stated in the probe block's comment: "is not claimable this tick, so it must not trip the throttle either". The C39 guard in `deduped` also makes a `failed_retry` unclaimable when its `(kind, partition)` holds a `running` or `done_pending_children` row. The probe exclusion covers only a `pending` sibling. So a `normal`/`high` due retry held by C39 still sets `v_high_pending = 1` and throttles every due `low` job queue-wide.

- **Measured, on a throwaway pg-lane with the gate's apply list.** I seeded:
  - D, a `done_pending_children` row (`derive_allocator_equity`, allocator A, `normal`);
  - R, a due `failed_retry` beside it (same kind and allocator, `normal`);
  - U, an unrelated due `low` pending job on allocator A2.

  Three consecutive 5-arg ticks each gave `retry=0 unrelated_low=0`, with no error.
- **Reasoned, not measured: the hold is not "until that row finishes".** A `done_pending_children` row is a fan-in CHILD waiting on its parents. `mark_compute_job_done` (`supabase/schema/functions/mark_compute_job_done.sql:89-99`) releases it to `pending` only when every parent is `done`. So the hold's bound is D's release. If a parent of D is `low`, R's throttle blocks that parent, D is never released, and the result is the same silent permanent wedge that round 1's WR-01 closed, reached through C39 instead of the pre-rank clause. If a parent is `failed_final`, D strands (the Phase 164.9.3.1 FANINGRAPH class), and R throttles every `low` job indefinitely. My harness seeded D with no `parent_job_ids`, so it shows the per-tick behaviour, not permanence.
- **Reachability.** The shape follows the flow this phase unblocks: an enqueue beside an outstanding retry that writes a twin born in `done_pending_children` because its parent is open.
- **Provenance and severity.**
  - This is pre-existing in the 5-arg, because both the C39 guard and the counting probe date from 20260601193000.
  - The 2-arg's C39 port is new in this phase, but that overload is unreachable (42725).
  - It is latent for the same reason round 1's WR-01 was: no writer sets `priority='low'` today.
  - So it does not block the merge. But item 7 of this review ("the residual prose is accurate everywhere") fails: the header understates the hold, and CHANGELOG and TODOS omit it.

**Fix.**
- **(a) Required: correct the prose in all three sites.** The header's "What stays" sentence must name `done_pending_children` as well as `running`. It must say that the hold lasts until that row leaves the in-flight set, which for `done_pending_children` means until every fan-in parent is done, and that the counted retry can itself block a `low` parent. CHANGELOG Notes and the TODOS closure should carry the same sentence, which they currently lack.
- **(b) The complete fix,** consistent with the stated principle and permitted by the amended D-04 because it sits inside the marked block. In each of the eight PROBE EXCLUSION disjuncts, widen the sibling test:

  ```sql
  -- was:  AND p.status       = 'pending'))
  AND p.status IN ('pending', 'running', 'done_pending_children')))
  ```

  Then update `c_probe_re` to match. It needs a red-first arm (the dpc shape above plus a `low` unrelated job), a layered twin, and a census move of ARMS_FLOOR +1 and stepsSeen +2. Whether (b) lands in this phase or is booked is the orchestrator's scope call. If it is booked, it must name a phase, because it is a job-starvation (data-freshness) class.

## Info

### IN-01: Every count arm assumes its rows fall inside `LIMIT 1000` (carried from round 1, still present)

**File:** `supabase/tests/test_claim_compute_jobs_failed_retry_pending_pair.sql` (every claim call; W-LOWTWIN's at `:851-856` too)
**Issue:** The claims are queue-wide, ordered by priority, then `next_attempt_at`, then `id`, and the arms seed rows at `now() - 1..10 minutes`. If a lane carries more than 1000 due claimable committed rows that sort earlier, an arm false-reds with `n_twin = 0`. W-LOWTWIN's `low` twin sorts after every `normal`/`high` row, although its push UPDATE moves the due normal/high rows out.
**Fix:** Seed arm rows at `now() - interval '10 years'`, or assert a bound on foreign claimable due rows before each claim.
