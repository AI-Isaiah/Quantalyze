**Host lane lock (LOCK).** Every lane boot and every lane teardown runs under the host lock, in
the actions AND inside every lane-booting `<automated>` command (`scripts/local-stack/run.sh` uses a
fixed project id, so an unlocked `down` can kill another session's lane). `$LANE_LOCK` is the
`lane.lock` directory inside the scratchpad the orchestrator supplied to this session. Bash-tool
shell state does not persist between calls, so the executor supplies it per command by prefixing
the command with `LANE_LOCK=<scratchpad>/lane.lock`; never paste that path into a tracked file (it
carries a home path). The LOCK prologue that every lane-booting `<automated>` command carries, in
this order: `: "${LANE_LOCK:?set LANE_LOCK to the scratchpad lane.lock dir}"` (refuses to run
unset); `mkdir "$LANE_LOCK" 2>/dev/null || { echo LANE-BUSY; exit 1; }` (acquire, or fail fast);
only THEN `trap 'rmdir "$LANE_LOCK" 2>/dev/null' EXIT` (releases on every exit path; set after the
acquire so the busy path never removes another session's lock). On `LANE-BUSY`, wait in a
BACKGROUND shell (`until test ! -d "$LANE_LOCK"; do sleep 30; done`; the harness blocks a
foreground sleep) and re-run the command. An action that took the lock releases it (`rmdir`) before
running the task's verify, which takes its own. Run lane-booting commands with a long Bash timeout
(600000 ms): a command killed by a timeout never runs its EXIT trap. A `LANE-BUSY` that persists
while no lane runs (`docker ps` shows no local-stack container and `pgrep -fl postgres` no pg-lane
cluster) is a stale directory left by such a kill; remove it with `rmdir` only after that check.

**LS-RUN (local-stack lane, the D-09 substitute for a push).** `WD=$(mktemp -d)`;
`bash scripts/local-stack/run.sh up > "$WD/up.log" 2>&1`; read the DSN with
`sed -n 's/^DB_URL="\{0,1\}\([^"]*\)"\{0,1\}$/\1/p' scripts/local-stack/.stack-env | head -1`
(the file is gitignored, mode 600; never print or paste the DSN); run the gate with
`psql "$DB" -X -v ON_ERROR_STOP=<0|1> -f <gate> > "$WD/gate.log" 2>&1`; always finish with
`bash scripts/local-stack/run.sh down`. `ON_ERROR_STOP=0` is the red-first CENSUS mode (every arm
reports); `ON_ERROR_STOP=1` is the CI mode (`sql-tests`).
