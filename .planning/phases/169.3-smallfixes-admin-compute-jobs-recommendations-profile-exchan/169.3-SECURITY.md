## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| browser → `/api/admin/compute-jobs` | authenticated, possibly non-admin user; query params untrusted | job rows incl. `user_email` (admin only) |
| route → service-role client | the service role bypasses RLS; only an admin may reach it | the `compute_jobs_admin` view |
| allocator browser → `/recommendations` RSC | reads the allocator's own `allocator_preferences` row and own batch (SECURITY DEFINER RPCs) | 11 engine-read preference columns of the viewer's own row |
| page → `strategy_analytics` | second read on the user's own client, bounded to the RPC's ids | status + one date alias, never the series blob |
| match engine → persisted batch | engine output becomes an allocator's visible recommendations | strategy ids, scores, exclusion audit rows |
| allocator browser → `/profile` Exchanges | the allocator's own keys, labels and balances | key labels, balances, venue account ids |
| browser password manager / extension → credential inputs (plan 06) | a saved site login or an extension's stored item can be written into an exchange key field without the user typing it; on submit the browser may offer to save or update a login | site password → exchange key field; exchange secret → the browser's login store |
| clipboard → credential inputs (plan 06) | pasted text carries invisible characters (spreadsheet whitespace, U+200B, U+FEFF) | the credential posted to validate-and-encrypt, create-with-key, add-key, verify-strategy |
| parallel worktrees → merged branch; deployed pages → verdict | plans verified separately ship together; a reading may come from a cache or an older deploy | none (process) |
