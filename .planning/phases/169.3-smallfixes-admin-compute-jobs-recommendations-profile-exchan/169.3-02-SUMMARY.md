# Phase 169.3 Plan 02: /recommendations says one thing about the mandate, dates every record, and never recommends your own strategy — Summary

**/recommendations now reads one `mandateSet` branch for both the header and the list. With no mandate it shows only the set-mandate call to action. Each recommended card carries a SyncBadge fed by the discovery list's one-date `series_end` alias, so a record that ended long ago says so. The match engine hard-excludes a strategy the allocator authored, as `owned` with provenance `authored`.**

## Accomplishments

- **One branch for the header and the list (SC8).**
  - The header `description` is derived from `mandateSet`. With a mandate it reads "Top 3 strategies that fit your mandate. Updated daily." (kept once, inside the true branch). Without one it reads "Strategies matched to your mandate, updated daily. No mandate is set yet."
  - The candidate section is one conditional under the same branch: no mandate → `NoMandateState` only; mandate + candidates → the list; mandate + no batch → `NoBatchState`; mandate + batch + no candidates → `NoCandidatesState`.
  - The predicate is unchanged, `Boolean(preferences?.mandate_archetype)`. Plan 169.3-04 replaces it (D-03).
- **Every recommended record states where its track record ends (SC8).**
  - The bounded `strategy_analytics` status read now selects `strategy_id, computation_status, series_end:returns_series->-1->>date`. It is still `.in("strategy_id", <RPC ids>)` and never projects the `returns_series` array (T-169-10).
  - Each card renders `SyncBadge` with the card's status-gated `computed_at` and a `series_end` that is gated the same way. No new threshold, ladder or copy.
  - A failed status read leaves `computed_at` null, so `SyncBadge` renders nothing. That is fail-closed, the same as the em-dash degrade.
- **No self-recommendation (D-05).**
  - `score_candidates` builds `authored_set` from candidates whose `manager_id` is not None and equals `allocator_id`. It passes the set to both `_eligibility_check` and `_eligibility_check_hard_only` as an optional trailing kwarg.
  - `_eligibility_check_hard_inner` returns `(ExclusionReason.OWNED, "authored")` for such a candidate, after the existing portfolio check.
  - No enum member, SQL CHECK or migration moved; `exclusion_provenance` is free TEXT. Scoring math is untouched.
  - **An already-persisted batch clears on the next daily recompute.**

## Decisions Made

See `key-decisions` above. The one with a user-facing consequence:

- **Withhold, and its interim cost.** Under the current predicate, "mandate set" means `mandate_archetype` is set, and the engine never reads that field (D-03). So an allocator who filled in engine-consumed preferences but left the free-text archetype empty now sees the call to action instead of a list. Before, they saw a list under a contradicting header. Plan 169.3-04 swaps the predicate to `deriveMandateIsSet`, which tests the fields the engine consumes, and that closes the gap. The two plans should ship together, and they do: both are in this phase.
- `NoMandateState` and the header's "Batch" freshness badge are unchanged, as the plan says. The badge still shows the batch time on a no-mandate page even though the list is withheld. Copy polish belongs to Phase 170.

**1. [Rule 1 - Bug] The test mock could not see a dropped projection**
- **Found during:** Task 2 neuter
- **Issue:** The first mock returned `series_end` whatever the select asked for. Dropping the projection therefore failed only AGE4 (the select-string check), not AGE1, and the plan says the 200-days case must go RED.

- **Files modified:** `src/app/(dashboard)/recommendations/page.mandate-gate.test.tsx`
- **Commit:** `9e1ecb693`

**2. [Rule 2 - Simplicity] `computed_at` is not added to the status read**
- **Found during:** Task 2
- **Issue:** The plan's action says to project `computed_at` as well. The card already carries a status-gated `computed_at` from the RPC's `analytics_computed_at`, and the plan's step 3 says to use that one. A second projection would never be read.
- **Fix:** Only the `series_end` alias was added. The status read now projects three columns.
- **Commit:** `9e1ecb693`

**3. [Rule 1 - Bug] Mandate-branch order keeps candidates visible when the batch-meta RPC fails**
- **Found during:** Task 1
- **Issue:** A strict "no batch → NoBatchState" chain would hide candidates the recommendations RPC returned whenever the batch-meta RPC failed. The old page rendered both states in that case.
- **Fix:** Within the mandate branch the list comes first when candidates exist. The first-batch and no-candidates states follow.
- **Commit:** `d08345adc`

**4. [Test addition] Relaxation case for the authored exclusion**
- **Found during:** Task 3
- **Issue:** The relaxation pass calls a separate function (`_eligibility_check_hard_only`), so a fix that reached only the first pass would pass the plan's three cases.
- **Fix:** Added `test_authored_exclusion_survives_relaxation`. It was RED before the fix and under the neuter.
- **Commit:** `b51d4042b`
