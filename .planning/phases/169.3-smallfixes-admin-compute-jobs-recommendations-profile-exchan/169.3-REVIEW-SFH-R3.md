## Recorded for the deferred browser check (not a finding; inferred, not measured)

Before plan 06, neither the masked secret nor the OKX passphrase carried a `new-password` token.
Now both do. That puts two `new-password` fields in the OKX form. Chromium may parse the pair as a
new password plus its confirmation. When a site has exactly one saved login, Chromium can also
offer "Update password?" on a form that has a new-password field but no username. If the user
accepts that prompt on the connect dialog, the saved site login would be overwritten with the
exchange secret. Their next sign-in would then autofill the wrong password and fail with an
invalid-credentials error.

D-76 accepts a save prompt as a cost, but it does not name this overwrite case. None of this was
measured. When the deferred 169.3-05 Task 2 visit runs (Chrome, with a saved site login), it
should note whether the prompt reads "Save" or "Update", and whether the OKX passphrase is filled
along with the secret.
