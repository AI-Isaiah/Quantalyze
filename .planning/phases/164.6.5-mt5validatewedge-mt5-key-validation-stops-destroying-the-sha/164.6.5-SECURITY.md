## Unregistered Flags

None. Plan 02 and plan 05 SUMMARY `## Threat Flags` both read "None beyond the plan's
register". Plans 01, 03, 04, 06 and 07 have no such section.

Two surfaces were added in review rounds after the threat models were written. Both map to
existing threat IDs, so they are recorded here as informational rather than as unregistered
flags:
- **`_REMOTE_SESSION_SNAPSHOT_SRC` / `Mt5Client.session_snapshot`** (R2 WR-03 root cause). This
  is a second remote literal on the T-134-03 channel, and it is covered by T-05, T-06, T-08 and
  T-25. It is an AST constant with no brace, no dunder and no import. Its only `mt5` calls are
  `terminal_info`, `account_info` and `last_error`, and it takes no argument, so the environment's
  login and server never cross. `_parse_session_snapshot` reduces the result to
  `login_matches` / `server_matches` booleans, and
  `test_SESSION_SNAPSHOT_returns_verdicts_never_values` asserts that no account number or server
  name comes back. The pre-recycle and post-relaunch log lines carry
  `session_*_matches_env=<bool>` verdicts only.
- **Sentry paging of `KEY_MT5_TERMINAL_UNRESPONSIVE`** (WR-06/SFH-08, R2-SFH-10). This is
  covered by T-16. `OUR_DEFECT_KEY_ERROR_CODES` gates `captureToSentry` on all three key routes.
  The rotate-secret capture passes `secrets: perRequestSecrets` (the new secret), which
  `captureToSentry` scrubs from the payload, tags and extra (`scrubCaptureInput` / `scrubRecord`).
  The test asserts `options.secrets` contains the synthetic new secret. The `console.error`
  beside it also goes through `scrubSeamError(err, perRequestSecrets)`.
- **`wizard_page_load_id` Sentry tag** (WR-07, IN-03, R2-SFH-11). This is covered by T-34.
  `wizardPageLoadIdTag` returns `null` when the header is absent. A present header that fails
  `/^[A-Za-z0-9._:-]{1,128}$/`, or an array, returns the fixed sentinel `"<malformed>"`, and the
  client value is never echoed. The sentinel's angle brackets sit outside the allowlist, so no
  client value can read as it. `src/instrumentation.test.ts` covers the absent, empty, CR/LF and
  array cases.

⚠️ This one is observed, not in scope, and pre-existing: the neighbouring `correlation_id` tag
in `onRequestError` passes any string `x-correlation-id` header through unshaped. That predates
this phase (Phase 16 / OBSERV-04), and this phase did not widen it. The wizard now sends a
server-conformant `wizard:<uuid>`. It is recorded for visibility only and is not counted.
