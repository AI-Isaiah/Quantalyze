<objective>
Criterion 7 — **the settings landmine is PINNED, not fixed.**

Purpose: the gateway terminal's Experts tab carries *"Disable algorithmic trading when the account
has been changed"*. ⛔ **VALIDATION IS AN ACCOUNT CHANGE**, so ticking that box would SILENTLY
disable algo trading on the shared terminal serving every client — and the failure would be silent
rather than loud. ⛔ **DO NOT TICK THE BOX. Do not add any path that writes a terminal option.**
The deliverable is a CHECK that fails loudly if it ever flips (D-15). It is one-way in the
dangerous direction.

⛔ **THE SETTING IS NOT LIVE-OBSERVABLE, and every remedy must start from that.** It only reaches
disk on a CLEAN terminal exit, so a file read can report a stale value while the running terminal
disagrees — three independent places in this repo say so. Only the CONSEQUENCE is observable.

⭐ **EXTEND THE JUDGE THAT ALREADY EXISTS.** `classify_trade_capability` and
`terminal_trade_permission_off` in `mt5_validation.py` ALREADY judge the consequence post-validate,
with exactly the fail-safe shape this needs: unreadable or disconnected means transient, never a
false alarm; connected with permission off is the real signal. ⛔ Do not mint a competing judge,
and ⛔ do not start judging the prober arm's deliberately unjudged branch — that branch is unjudged
because a probe that logs in would itself re-trip this landmine.

⛔ **AND THERE IS A CONTRADICTION IN THE RECORD THAT THIS PLAN MUST RESOLVE, NOT AVERAGE.** Five
places in this repository state that the gateway re-sets algo trading off on EVERY account change,
founder-measured 2026-08-13. CONTEXT.md D-15 states, measured 2026-09-22, that the box is
UNCHECKED — correct today only by default. Both cannot be true of the same checkbox. Resolving it
is task 1, and it decides what the rest of this plan corrects.

Output: a reconciled and dated record, a loud runtime check on the observable consequence, and
gates that red if either regresses.
</objective>
