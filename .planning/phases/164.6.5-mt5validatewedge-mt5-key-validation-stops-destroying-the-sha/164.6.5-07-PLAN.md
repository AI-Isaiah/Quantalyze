<objective>
Criterion 6 — **`correlation_id` is minted PER REQUEST, not per wizard session.**

Purpose: MEASURED identical across attempts HOURS apart, so two different failures are
indistinguishable in support — which directly undercuts the *"email us with the correlation id"*
instruction printed in that same copy. A support request that arrives with an id matching four
different failures identifies none of them.

⭐ **THE SUBJECT IS NOT WHERE CONTEXT.md AND PATTERNS.md POINTED, and the correction matters.** Both
named `newWizardSessionId()` in the wizard's localStorage module. The id the error envelope actually
renders — and the id the copy tells the user to email — is `getWizardCorrelationId()` in
`src/lib/wizard/wizard-correlation.ts`: a module-level memo, minted once per PAGE LOAD, which
`wizardFetch` also stamps on the correlation header of every request. The localStorage session id is
a different value with a different job.

⛔ **DECIDE DELIBERATELY, AND THE DECISION IS KEEP-ALONGSIDE, NOT REPLACE.** The page-load id keeps
its name and its meaning: funnel telemetry joins on it, and silently changing an existing telemetry
field's cardinality changes the meaning of historical rows (D-14's own stated cost). What changes is
that a FRESH per-request id is minted for each request and is what the server logs and what the user
is shown.

⭐ **THE DEDUPE IS SAFE, and this is verified rather than assumed.** The finalize route's own comment
records that it deliberately does NOT key dedupe off the correlation header, because that header is
memoized per page load and *"a reload … would key the dedupe on a value that changes per request,
which is worse than sending nothing"*. It keys off the draft row's stable session id instead. ⛔ That
sentence is the fence: this plan must not move the dedupe onto a per-request value.

Output: a per-request id on the wire and on the screen, the page-load id preserved, and every
envelope-rendering wizard surface closed as a class.
</objective>

  <action>
Change what the wrapper puts on the wire, and give a caller a way to know what it put there.

**Mint per request.** In the fetch wrapper, mint a FRESH id for every call and stamp it on the
correlation header the server already reads. Mirror the per-call shape used by the analytics client
for entropy and format. ⚠️ This module runs in a BROWSER, so keep whatever fallback the existing
page-load minter already carries for environments without the modern API, and keep the canonical
identifier shape — the existing function's own comment says the only contract that matters is the
shape.

**Preserve the page-load id, under its own name, on its own header.** Add ONE additive header
carrying the page-load id so nothing that wants a stable per-page-load value loses it. ⛔ Do NOT
change `getWizardCorrelationId`'s behaviour, its name, or what it returns: funnel telemetry joins on
it, and redefining an existing telemetry field silently is the cost D-14 explicitly forbids paying.

**Reverse the merge rule, and rewrite the reason.** The wrapper currently sets the session id LAST so
it deterministically wins over a caller-supplied value, with a docblock explaining that a per-call
override would break the log-matching contract. That reasoning is now inverted by measurement: the
per-call value is exactly what makes log matching work across two attempts, and the memoized value
is what broke it. Respect a caller-supplied correlation value, mint one only when the caller supplies
none, and rewrite the docblock to state the new rule and why it changed — dated, with the
measurement. ⛔ Do not leave the old sentence standing beside the new behaviour; a docstring that
went false is the drift class this milestone exists to close.

**Let a caller capture the id.** Add an OPTIONAL way for a caller to learn the value that went on the
wire for the request it just made. ⛔ Keep the wrapper's existing signature and return type
backward-compatible: there are a dozen call sites and only some of them render an envelope, so a
breaking signature change would force edits at sites that have nothing to gain. Additive and optional.

⛔ **THE DEDUPE IS OUT OF SCOPE AND MUST NOT MOVE.** The finalize route keys dedupe off the draft
row's stable session id and its own comment explains why a per-request value there would be worse
than sending nothing. Change nothing about it.

**The gates**, in the module's own test file, following its existing conventions:
  · two calls carry two different correlation values;
  · two calls carry one identical session value, equal to the page-load id;
  · the page-load id function is unchanged — stable within a page load, cleared by the reset helper;
  · a caller-supplied correlation value is respected;
  · the capture path yields exactly the value that went on the wire.
