# Phase 153.7 — Validation Architecture

**Why this file exists.** `workflow.nyquist_validation` is `true` and every sibling phase
(`153-`, `153.5-`, `151-`, `152-`) carries one. It was missing here because the phase was
hand-driven through `gsd-plan-phase` rather than orchestrated, which skips the VALIDATION step.
Caught by `gsd-plan-checker` (BLOCKER-1, 2026-08-14).

⛔ **The stakes are unusually specific.** This phase exists because a previous pass shipped a
mechanism that *worked* and reported it done, while its **reach** was wrong. Every row below is
written to fail if that happens again. A test that cannot fail when the population is wrong is
worse than no test here — it is the fourth instance.

## Oracle Independence checklist

The governing rule: **an oracle must not be derived from the thing it validates.** The 153-span
failure is the canonical violation — the coverage law asserted over a population it also defined.

| # | Oracle | Independent of? | Verdict |
|---|---|---|---|
| O-1 | `EXPECTED_EMITTED_CODES` roster (37 members) | **Hand-typed**, member-for-member. NOT `[...derived]`. | ✅ independent |
| O-2 | `DERIVED_FLOOR` (22) | Hand-typed integer. | ✅ independent |
| O-3 | AST census cross-check (32 sites / 21 codes) | Produced by a **different mechanism** (Python AST, per `test_raw_5xx_census.py`) than the thing under test (TS regex matcher). | ✅ independent — this is the phase's strongest oracle |
| O-4 | `dynamicishByFile` blind-spot map (8 keys) | Hand-typed per-file counts. | ✅ independent |
| O-5 | The 8 Group-A replay tests | Assert against the **real** `classifyKeyValidationError`, recorded RED at 8×UNKNOWN *before* rows land. | ✅ independent |
| O-6 | tmpdir falsifier | Calls the **real** `deriveEmitterSites(root)` over a **synthetic** root. Can genuinely fail if the matcher misses the shape. | ✅ independent |
| O-7 | `EXPECTED_FINALIZE_REJECTION_SITES` (32) | ⚠️ Its **invariance** is the proof. It must STAY 32; a bump would destroy the oracle. | ✅ independent, ⚠️ fragile by design |

⛔ **Forbidden constructions**, each named because it would silently satisfy a row above:
- Any roster written as `[...derived]` or `Array.from(derived)` — that is the self-referential
  oracle in its purest form.
- Reconciling the matcher against a **frozen** census table if `analytics-service/` has drifted.
  Regenerate the census; a stale table agrees with a broken matcher.
- Twelve copies of `CSV_FORMAT_UNSUPPORTED`'s back-referencing one-liner as `WITHOUT_VERDICT`
  reasons — the law would then cover everything and assert nothing.

## Falsifiability Ledger

**One row per success criterion.** Each names the semantic mutation and the test that must red.
⭐ A criterion whose mutation does NOT red is **not validated**, regardless of green CI.

### FL-1 — SC: a code with neither disposition reds CI by name

- **Mutation:** delete the `MT5_GATEWAY_UNREACHABLE` verdict row from `VENUE_WIRE_CODE_TO_VERDICT`.
- **Must red:** the existing disposition assertion in `seam-venue-vocabulary.invariant.test.ts`
  (`EVERY derived code has an explicit disposition …`) **naming the code**, AND the Group-A replay
  test for that code.
- **Where proven:** Plan 02 Task 3 (neuter-proof: delete → both red → restore → record both outputs).
- ⚠️ **Meta-hazard, and the reason this row is first.** The plan-checker found Plan 01 Task 3's
  automated verify was `... | tee ...; test $? -ne 0`, where `$?` is **tee's** status (always 0).
  It exited 1 for both the designed RED and a fully-green run — the check on this phase's central
  property could not fail. **Fixed 2026-08-14** to assert three things: vitest's own exit status
  via `PIPESTATUS[0]`, the failing test matched **by name**, and `Tests 1 failed` (exactly one).
  📌 Lesson to carry: a verify command that pipes to `tee` and then reads `$?` is always vacuous.

### FL-2 — SC: the population covers every user-reachable code (reach, not directory/shape)

- **Mutation:** narrow the call-shape matcher (e.g. revert to `error_code =` only, or drop the
  `routers/` root).
- **Must red:** the roster assertion (37 members, member-for-member), `DERIVED_FLOOR` (≥22), the
  both-shapes-present assertion, and the reach pin.
- **Where proven:** Plan 01 Task 3.
- ⛔ **THE FAIL-OPEN HAZARD — the highest-risk item in the phase.** A too-narrow matcher
  **satisfies every absence assertion in the file**. Absence assertions cannot detect under-reach;
  only the hand-typed roster and floor can. This is why O-1/O-2/O-3 are mandatory and why the AST
  cross-check is acceptance evidence rather than advice.

### FL-3 — SC: a NEW undisposed `service_error(...)` in `routers/` reds the gate

- **Mutation:** the permanent tmpdir falsifier synthesises exactly this condition.
- **Must red:** falsifier asserts exactly `["ZZZ_FALSIFIER_ROUTER_CODE"]`; if the matcher misses
  the shape, the assertion fails.
- **Where proven:** Plan 01 Task 3, plus an optional one-off manual mutation recorded as a SUMMARY
  receipt (revert, then confirm `git status --short` is empty).
- ⛔ **This row IS the phase's definition of done.** A fix that cannot fail this way has not
  closed the class — it has closed instances.

### FL-4 — SC: the mt5-gateway family no longer renders `code: UNKNOWN` to a user

- **Mutation:** remove the shared verdict row.
- **Must red:** the regression tests on **BOTH** `create-with-key/route.test.ts` **and**
  `composite/add-key/route.test.ts`.
- **Where proven:** Plan 03 Task 2, per-route neuter-proof.
- ⚠️ **Twin-path guard.** The fix must live in shared `wizardErrors.ts`. A route-local fix at
  `create-with-key` would green that route's test while the twin stays broken — this milestone's
  single most repeated defect. `finalize-wizard` is NOT the twin; it never calls
  `classifyKeyValidationError`.

### FL-5 — SC: pins re-cut, never deleted; `EXPECTED_FINALIZE_REJECTION_SITES` stays 32

- **Mutation:** bump `EXPECTED_FINALIZE_REJECTION_SITES` from 32.
- **Must red:** the 32 − 32 = 0 arithmetic reconciliation.
- **Where proven:** Plan 03 Task 1. Constraint: **stop and re-measure rather than bump the pin.**
- ⚠️ The ledger collapse is 3 → 0 and the **site count stays 32**. Sites do not disappear; they
  acquire codes. A moved site count means the edit went wrong, not that the pin is stale.
