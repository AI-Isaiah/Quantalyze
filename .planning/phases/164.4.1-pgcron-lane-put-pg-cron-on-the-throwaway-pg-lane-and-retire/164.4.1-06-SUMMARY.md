## The D-07 closure, in one paragraph

`[REDUNDER-LANEBLOCKED-BLIND]` is closed **deliberately, with the classifier
unchanged.** TODOS proposed widening `gateNeedsPgCron` to read a gate's
`RED-UNDER-SETUP` apply list. That fix cannot see its own subject:
`classifyGateIdiom` classifies UNANNOTATED files, and an unannotated gate has no
`RED-UNDER-SETUP` line — the measured instance,
`test_compute_jobs_error_kind_copy_parity.sql`, had none at the moment it was
misclassified. The widened branch would therefore be dead code behind a passing
test, the exact "quietly become unreachable" shape this phase family refuses;
shipping it would have made the ledger look closed while adding an unfalsifiable
branch. What actually closed the exposure was the SUBSTRATE: with pg_cron hosted,
the own-text case and the apply-list case resolve identically (annotatable), so
no verdict is left for a widening to change. The boundary is now (1) documented
in a dated paragraph above `gateNeedsPgCron`, (2) asserted by the hand-built
`D-07 boundary` arm, and (3) cross-referenced from the plan-02 flip so the two
read as one closure. The residual is stated rather than hidden: a future
lane-blocking dependency living only in a migration surfaces as a named
`baseline` defect at annotation time — exit 1 with the file named, not a silent
miscount.

## Deviations from Plan

**1. [Rule 2 — missing critical coverage] A GREEN arm for the EMPTY
`lane-blocked:` line.** Every existing count-recheck arm feeds ci.yml's real
`run:` block a NON-EMPTY line, because that was the only state the corpus could
produce while the deferral was open. The class is now permanently empty, so the
line the gate sees on *every* real run was exercised by nothing — and ci.yml's
own comment predicted the hazard ("an EMPTY deferred set … the state this
phase's successor reaches"): without `|| true` the `grep -o` matches nothing and
aborts the step with no `::error::`. Added, proven able to fail. Commit
`50567f38`.

**2. [Convention conflict, resolved toward the file's own rule] The ubuntu
pg_cron VERSION is not restated in `scripts/pg-lane/README.md`.** The plan asked
for "apt source, package version". The README explicitly refuses to restate
either host's version in prose ("a version in prose is a dated claim and these
two move independently") and directs the reader to each route's own print. The
apt SOURCE (`noble/universe`) is recorded, because it is a structural fact that
answers RESEARCH's open question and does not move; the version is left to the
step's `dpkg -s … Version:` print, with the run id and the evidence log named so
it can be found. CLAUDE.md's currency paragraph does the same.
