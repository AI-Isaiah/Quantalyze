## Summary

**The two comments disagree and the repo's `exchange.py` side is right.** In ccxt 4.5.88 (the pin, `analytics-service/requirements.txt:33` `ccxt==4.5.88` [VERIFIED: requirements.txt:33]), Bybit's `fetch_balance()` calls `GET /v5/account/wallet-balance` and `parse_balance` sets `account['total'] = self.safe_string(coinEntry, 'walletBalance')` (`ccxt/async_support/bybit.py:3546`, sync file `ccxt/bybit.py:3545`). The coin `equity` field and the account `totalEquity` are never read into `total`. Bybit's documentation defines `walletBalance` as "Wallet balance of coin" and `equity` as "Asset Equity = `walletBalance` - `spotBorrow` + `unrealisedPnl` + Asset Option Value". So Bybit `fetch_balance()['total']` is **realized-basis, excluding open-position uPnL**. `equity_reconstruction.py`'s NEW-C01-05 comment ("Bybit V5 reports total as equity-inclusive") is wrong, and the code built on it (`_UNIFIED_MARGIN_VENUES = frozenset({"okx","bybit"})`, line 3069) **drops** the open uPnL from the Bybit reconstruct anchor. The same ccxt code is byte-identical in 4.5.59 (the version the exchange.py comment cites), 4.5.85 (local venv) and 4.5.88 for the balance parse (semantic diff: none; only typing/null-guards changed), so the meaning never changed.

Per-path verdicts: (a) **derive anchor** (`exchange.py` `fetch_account_equity_and_upnl_usd`, wedge 0.0): behaviour is correct and self-consistent (anchor = USDT `walletBalance`, wedge 0.0, `terminal_nav = anchor_nav - 0.0` is the realized basis `nav_twr.py` wants); only its docstrings are wrong (`fetch_account_equity_usd` says "NAV incl. unrealized PnL" and "uPnL settles in USDT ... USDT total equals account equity"). (b) **holdings poll** (`allocator_positions.py`): correct as it stands (spot rows = wallet balances; derivative rows carry `unrealized_pnl_usd`; AUM = spot + derivative uPnL per 167.1.1.2 D-04); no behaviour change, comment only. (c) **reconstruct anchor**: wrong for Bybit. The replay it anchors to is mark-to-market (it adds `pos.mark(px)` for every open perp, `equity_reconstruction.py:1230-1256`), so the correct anchor is wallet + uPnL, exactly what the Binance additive path already computes. Fix: remove `"bybit"` from `_UNIFIED_MARGIN_VENUES` (keep `"okx"`, which is read by the raw `totalEq` call). This is an anchor fix; the derive wedge stays 0.0.

**Binance** is not a double count either. With the repo's construction (no `type` override anywhere; `defaultType` is `'spot'`, `ccxt/async_support/binance.py:1405`), `fetch_balance()` hits the SPOT endpoint (`privateGetAccount`, :4112) and `total` = free + locked, which has no uPnL. Derive wedge 0.0 and reconstruct "balance + position uPnL" are each right for their basis (realized vs MTM). The real Binance defect is different: the USDⓈ-M futures wallet is **never read** (spot only), while `fetch_positions()` reads linear futures (`fetch_positions_risk` defaults subType `'linear'`, :11595ff). A futures-only account anchors at about the spot balance plus futures uPnL. If anyone ever sets `type='future'`, `total` becomes `marginBalance` = wallet + unrealized (:4025) and the reconstruct additive path WOULD double count. D-03 (test only, no keys) is best met by pinning both facts with tests built through ccxt's real `parse_balance_custom`, fixing the comments, and booking the futures-wallet gap.

**Primary recommendation:** Keep the realized-basis derive as is; fix the single wrong path (Bybit reconstruct anchor: add the position uPnL like Binance and OKX-fallthrough logic), correct the three wrong comments/docstrings, and pin everything with one new test module that feeds recorded-shape ccxt payloads through ccxt's REAL `parse_balance`/`parse_balance_custom` and then through each repo path. Flip the existing mock-based test `test_c01_05_bybit_upnl_not_double_counted`, which encodes the wrong reading.

### Anti-Patterns to Avoid
- **Mocking `fetch_balance` as a bare `{"total": ...}`** (the existing C01-05 tests): the mock is whatever the author believed; that is how the wrong reading survived. Parse a payload through ccxt's real parser.
- **Making the derive wedge non-zero for Bybit** to "include" uPnL: the anchor does not embed it; subtracting a wedge from `walletBalance` is the double count.
- **Unifying by "always skip" or "always add"**: the correct rule is per-venue and per-wallet type; encode it as a pinned table with the test, not as prose.

## Common Pitfalls

### Pitfall 1: The reconstruct re-run is gated by a marker
**What goes wrong:** Enqueueing `reconstruct_allocator_history` for an already-reconstructed key does nothing: `run_reconstruct_allocator_history_job` short-circuits to DONE when `api_keys.history_reconstructed_at` is set (`equity_reconstruction.py:3866-3875`, `_api_key_already_reconstructed` :1769).
**How to avoid:** See Open Question 1. Do not hand-null the marker; the plan must pick an explicit, tested, product-path mechanism (e.g. a payload flag honoured by the handler for this recompute) or document the marker reset as a deliberate one-column write with the marker query first. D-02 as worded ("enqueue the existing compute kinds") is not sufficient for the reconstruct half.
**Warning signs:** the audit event `allocator.equity.reconstruct_complete` with `reason: already_reconstructed_for_api_key` after the "recompute".

### Pitfall 2: Local venv ccxt (4.5.85) is not the pin (4.5.88)
**What goes wrong:** A test green locally on 4.5.85 could differ in CI on 4.5.88.
**How to avoid:** The balance functions are byte-identical (diffed), so the behavioural test is valid on both. The test must assert BEHAVIOUR (real parse), not the version string. Add the installed `ccxt.__version__` to the assertion failure message so a future bump that changes `total` is diagnosable. Do not `skip` on version mismatch (a skipped test is "tests pass" lying). Optionally add one cheap guard test that parses `requirements.txt` for `ccxt==` and asserts it equals the version the module-level docstring/constant in the new test names; this goes RED when someone bumps the pin without re-reading these semantics (it fails on local 4.5.85 only if it compares installed vs pin, so compare pin vs the named constant, not installed).

### Pitfall 3: Fixture realism
**What goes wrong:** A synthetic fixture can encode the author's belief. Use field names and shapes copied from ccxt's own response comments (bybit.py:3466-3499; binance.py fapi/papi comments), choose values where `totalEquity != totalWalletBalance`, and compute the expected number from the payload fields in the test (independent oracle), not from the code under test.

### Pitfall 4: A failed positions call re-introduces the drop silently
After the fix Bybit depends on `fetch_positions()` (same as Binance). Today a failure logs a warning and continues with `positions=[]`. Decide whether Bybit/Binance anchors should degrade visibly (e.g. return `None` anchor so the unanchored-series fallback ships and a DQ flag is stamped) rather than ship a low-by-uPnL anchor. Recommend: treat a positions failure on a non-OKX venue as "anchor unavailable" only if the plan also covers its callers' DQ handling; otherwise keep the warning and book it. Surface the choice in the plan.

### Pitfall 5: CONTEXT/ROADMAP line numbers are stale
CONTEXT cites exchange.py ~3108-3133, equity_reconstruction ~3058-3101. In this worktree: docstring :3078, Bybit/Binance note :3111-3118, wedge return :3130; reconstruct skip comment :3060-3070, loop :3093.
