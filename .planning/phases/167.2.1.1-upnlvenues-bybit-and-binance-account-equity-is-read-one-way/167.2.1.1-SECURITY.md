## Verdict: SECURED (0 open, 0 blocking)

## Focus 1 - read-only Bybit probe (`analytics-service/scripts/bybit_upnl_probe.py`)

- No writes. Source holds one `supabase.table("api_keys").select("*").eq("exchange","bybit").eq("is_active",True).order("created_at")` and nothing else against the database. A grep for insert, update, upsert, delete, rpc, create_order, cancel, private_post/put/delete, transfer, withdraw, preflight, load_markets returns no code hits (only docstring prose naming the preflight as never invoked).
- Venue access is the `ReadOnlyBybitProxy`: it defines exactly `private_get_v5_account_wallet_balance` and `private_get_v5_position_list`; `__getattr__` raises `AttributeError` for everything else (`close` included); `_once` refuses a second identical request. The raw ccxt client is never handed to measuring code.
- Output. The only stdout path is `emit_record` -> `validate_record`: exact key whitelist per record kind, per-key validators (labels `k1..k99`, date-only `run_date`, booleans, `field-absent`, 3-significant-figure floats, counts), then `assert_sanitized`. The `ValueError` text names the path, never the value. Account type is collapsed to `UNIFIED`/`CONTRACT`/`other`/`field-absent`. No amount, key id, account number or timestamp finer than a day can pass the validators.
- Errors. `classify_failure` maps to a closed class list and never reads the message; the per-key `except` records by class; `main` disables logging (`logging.disable(CRITICAL)`) and prints `type(exc).__name__` only. Refusal lines print the label and a fixed reason token only. Selection is by SQL filter plus `refusal_reason` per row before any decrypt; the script takes no arguments (`parser.parse_args` on an empty parser), so no id is ever typed.
- Tests that bite: `test_the_probe_cannot_write_and_never_calls_the_breaker_preflight`, `test_emitter_refuses_a_key_or_a_value_outside_the_whitelist`, `test_proxy_serves_each_read_once_per_distinct_request_and_refuses_a_repeat`, `test_one_failed_key_is_recorded_by_class_...`, `test_main_prints_the_exception_type_only_on_a_run_level_failure`.

- Sole reader: `_job_requests_force_rebuild` (`services/equity_reconstruction.py:1795`), `isinstance(metadata, dict)` guard and `is True`. A repo-wide search of `services`, `scripts`, `routers` and the two entrypoints shows no other reference; `src/` has no reference at all.
- Writers: `public.enqueue_compute_job` (9-parameter, latest definition `20260515210300_scoring_weight_overrides_high_hardening.sql`) is `REVOKE ALL ... FROM PUBLIC, anon, authenticated` and `GRANT EXECUTE ... No later migration redefines either grant. `compute_jobs` is RLS deny-all.
- The only authenticated-callable enqueuer of the reconstruct kind, `request_allocator_holdings_sync` (latest definition `20261014120000_api_keys_history_reconstruct_marker.sql:351`), calls `enqueue_compute_job` for it with no `p_metadata` (line 442-447). The refresh fan-out (`20261021120000...:354`) passes none either. No `src/` route enqueues the kind. `test_the_user_callable_reconstruct_enqueue_passes_no_metadata` pins it, reading `supabase/schema/functions/request_allocator_holdings_sync.sql` (no `p_metadata`); I confirmed the migration definition agrees with that file.
- Result: only a service-role (or database-owner) caller can set the flag. Closed.

## Focus 3 - forced replace path refuses and writes nothing on every refusal

Every refusal is a `ForcedRebuildRefusedError` with a reason from the closed 10-token set `FORCED_REBUILD_REFUSAL_REASONS`, caught before the persist half, and returns `FAILED/permanent` with a static message.

| Refusal reason | Raised at | Before any write? |
|---|---|---|
| `sibling_lookup_failed`, `multi_key` | pre-crawl check in `run_reconstruct_allocator_history_job` | yes (before the crawl) |
| `positions_unreadable` | `_fetch_current_equity` (raise, non-list, >=200 rows, open position without numeric uPnL, Bybit `totalPerpUPL` mismatch or unreadable) | yes (inside the crawl; re-raised past the blanket `except` by the dedicated `except ForcedRebuildRefusedError: raise`) |
| `anchor_unreadable`, `anchor_skipped_okx_terminus`, `..._partial_ticker`, `..._unreliable_replay`, `..._implausible` | `_fetch_and_price_window(require_anchor=True)` | yes |
| `replay_empty`, `history_outside_replay` | after the crawl, same `try`, before persist | yes |
| `multi_key` / `sibling_lookup_failed` (round 2) | second sibling lookup directly before the persist branch; returns before `replace_equity_snapshots` and `persist_equity_snapshots` | yes |

The marker writer runs only after a successful persist, so the marker is untouched on refusal. The stored-history guard (`_allocator_snapshot_asofs`) is paged. Refusal text reaches `compute_jobs.error_message` and the `reconstruct_failed` audit as static text plus a closed-set token, and venue errors are raised `from None`. Tests: `test_forced_rebuild_refuses_*` (positions, balance, partial ticker, multi-key, sibling lookup, persist-time sibling disagreement, empty replay, history drop, OKX terminus, inverse perp, implausible offset) and `test_forced_rebuild_refusal_reasons_are_a_closed_set`.

## Accepted risks log

- T-03 / PD-B: an UNFORCED Bybit or Binance reconstruct whose `fetch_positions()` fails anchors at the wallet figure, shifting one day's open uPnL. Logged with venue and class, flagged `anchor_positions_unread` in the completion audit, owned by `TODOS.md` `167.2.1.1-ANCHOR-POSITIONS-READ-FAILURE`. Forced path never does this.
- T-05: Binance futures wallet is not read. No Binance key exists (census); trip-wire test is the trigger.
- T-12 / T-18: repeated or refused forced jobs only affect a service-role-initiated, single-flight job; no automatic retry.
- T-SC: no dependency change.
- Race (code comment in the handler, owner ACCTREBUILD 167.2.1.1.2): the stored-history subset read is outside the replace RPC's transaction, so a row written between the read and the replace by the daily refresh of a sole-key allocator is deleted unseen. Accepted by the phase (no migration allowed); bounded to one daily row on a service-role-initiated, one-off operation.
