<objective>
Stop the OG share card from pinning a not-found or figure-less card at the CDN (CACHE-01). A genuine not-found card and any published card rendered without figures go out `no-store`. A rendered terminal card keeps the long cache.

Purpose: TODOS `170.3-OG-NOTFOUND-CACHE`. Today the not-found card carries `LONG_CACHE_CONTROL` (`s-maxage=86400`, SWR a week), so a strategy published after its card was first unfurled shows "Strategy — — —" for a day.

The ladder, verbatim from phase agent ruling 1 (2026-11-23), which supersedes the SHORT not-found value in 237-RESEARCH.md (Code Examples, Open Questions 1-2, the t0+61 s neuter) and 237-UI-SPEC.md 4.1 and Test Contract item 5: "OG cache ladder: key the header on a `figuresRendered` boolean that defaults to false: `failed` or not-found or no figures rendered -> `no-store`; held re-run with figures -> `public, max-age=60, s-maxage=60`; terminal with figures -> `LONG_CACHE_CONTROL`. Not-found good-after-bad test sees the real card on the very next request." 237-CONTEXT.md "Research follow-ups" says the same.

This plan ships the parts that exist before the hold: no-store for failed, not-found and no figures, and LONG for figures. The held-re-run SHORT branch is added by plan 05 once `analyticsHold` reaches the card.

Constants (ruling 3, verbatim): "Keep `FAILURE_CACHE_CONTROL` (and the other OG cache constants) defined in `src/app/api/og/factsheet/[id]/route.tsx`; do not move them to a shared module (a test reads the definition by regex)." The no-store branch reuses `FAILURE_CACHE_CONTROL` and adds no new header constant.

Output: the header ladder in the route, a new clock-driven good-after-bad test file, and the flipped not-found pins.
