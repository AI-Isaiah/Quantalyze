<objective>
Create the one shared held-re-run verdict, `analyticsHold`, and make the returns API its first consumer, end to end. That means a held row's stored series and scalars plus an `analytics_updating` field (FACT-02 surface S6).

Purpose: every FACT-02 surface asks the factsheet's question ("is this row held, terminal, or neither?") from ONE function. Five surfaces each writing their own status ladder is the drift this phase removes (CONTEXT FACT-02: "Every holding surface follows Phase 190 plan 03's rule: `hasStoredAnalyticsResult` with `isRecomputeOverStoredResult`, plus `hasUnboundDerivePrestamp` where it reads the flags blob. A machine surface (the returns API) carries the state as a field rather than a line of text."). The helper also exports `HELD_RERUN_CACHE_CONTROL`, the short cache a held render may carry, consumed later by the OG route (plan 05) and both PDF routes (plan 06).

Output: `src/lib/analytics-hold.ts` with its unit test, and the returns route holding with the new field.

Where the cache constant lives (phase agent ruling 3, 2026-11-23, verbatim): "Keep `FAILURE_CACHE_CONTROL` (and the other OG cache constants) defined in `src/app/api/og/factsheet/[id]/route.tsx`; do not move them to a shared module (a test reads the definition by regex)." `HELD_RERUN_CACHE_CONTROL` is NEW, not moved. Three routes share it, and a Next route module may export only handler names, so it lives in this lib module. The OG route keeps `LONG_CACHE_CONTROL` and `FAILURE_CACHE_CONTROL` where they are.
</objective>
