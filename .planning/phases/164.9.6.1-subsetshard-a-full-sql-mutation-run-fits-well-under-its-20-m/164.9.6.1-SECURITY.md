# Phase 164.9.6.1 — Security

> Per-phase security contract: threat register, accepted risks and audit trail. The register was authored at plan time: 6 threats in plan 01, 7 in plan 02 and 5 in plan 03. `T-164.9.6.1-SC` is declared in all three plans and counted once, so the register holds 16 threats. `gsd-security-auditor` checked every mitigation against the implementation at the SHA above. `config.json` sets no security keys, so the defaults apply: ASVS 1 and `block_on: high`. ## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| runner → concurrent `pg-lane/run.sh` children | Up to four throwaway clusters share one host's loopback port space and tmp space | Ports, scratch workdirs |
| runner verdict → CI assert step | The summary lines are the only evidence the floor and ratchet verdict reads | `arms:`, `lane-invocations:`, `lane-concurrency:` lines |
| GitHub API (check runs, suites, job log) → predecessor proof | Untrusted text decides whether a push may narrow the SQL gate subset | Check-run JSON, the `sql-gate-lint` job log |
| predecessor reason → `$GITHUB_OUTPUT` / `scope-reason:` | Log-derived tokens reach a workflow output file and a later `run:` script | `sql_gate_reason` |
| `changed-paths` job token | Gains a new Actions read scope | `GITHUB_TOKEN` with `actions: read` |
| ci.yml ⇄ nightly copy | Two copies of one assert block that must not drift | Assert-step text |

## Advisories (non-blocking)

1. **Neuters re-run by the auditor: 2 of the claimed set.** These are T-06 (the findings equality) and T-09 (the docs-only opt-in). Both were run in a scratch copy outside the repo. In those runs, the self-test row "carries git's own stderr reason" also failed, because the scratch directory is not a git repository. That failure is environmental and unrelated to either neuter. The neuter REDs claimed for T-01, -02, -03, -04 and -12 rest on the plan SUMMARYs. The tests themselves pass at HEAD.
2. **SFH-R2-01 (MEDIUM, from the silent-failure re-review).** A lane whose teardown leaks its cluster is judged normally, and its WARNING is discarded. Later lanes on that worker's port then fail as `lane-unrunnable` port-taken MEASURE_FAILs that do not name the leak. This direction is loud, not a false GREEN, so T-02 stays closed. The cause is unnamed, though.
3. **T-07's wording is narrower than the code.** "Only `^[\w.]+/\d+$` tokens enter `why`" holds on the tolerated path. On refusals, `printable()` fragments of a log line, a step header or a malformed token also enter `why`. They are restricted to printable ASCII, capped at 80 chars, and sanitised again by `oneLineReason`. The output-injection vector stays closed.
4. **What a tolerated predecessor did not run.** When the drift step fails, the `sql-gate-lint` steps after it (DRIFT-05 self-test, restore-channel self-check, extractor audit and others) are skipped on that predecessor. The tolerance only narrows `sql-mutation`'s scope, and every push runs `sql-gate-lint` in full itself, so no gate is lost. The predecessor proof just says nothing about those steps.
5. **Signal forwarding on a GitHub job cancel** has no automated test. How it behaves when the runner kills the process tree was not measured here.
