# Phase 164.9.6.1 Plan 02: Drift-tolerant predecessor proof Summary

The SQL gate subset now opts into a tolerant predecessor proof. It reads the `sql-gate-lint` job log through `gh api --allow-escape-sequences` and lets a push narrow only on a positive drift-only reading. A cancelled `sql-mutation`, any other red, or an unreadable or odd log still forces FULL, with the reason named. The docs-only short path keeps the strict rule.

## What was built

- **`predecessorVerdict(sha, fetch, { tolerateBaselineDrift, fetchJobLog })`.** By default no verdict or reason string changes: all 19 pre-existing classifier rows and all 28 pre-existing subset rows pass unchanged. When the caller opts in and a non-OK run exists, `toleratedDriftVerdict` refuses, in this order:
  - any red check other than `sql-gate-lint` or `frontend`, using the strict reason, so the 9c1dc3137 pattern names `sql-mutation`;
  - no red `sql-gate-lint`, or more than one;
  - a `sql-gate-lint` that did not conclude exactly `failure`;
  - no `frontend` run with conclusion `failure` in `sql-gate-lint`'s suite;
  - a red run in another suite;
  - an open suite, an absent lint suite, or a second red suite.

  It reads the log only after all of those pass.
- **`readJobLog`.** The repo must match the owner/name regex and the job id must be a positive safe integer. gh is called with argv elements, never a shell string, with a 60 s timeout and a 16 MiB buffer.
- **`parseBaselineDriftLog`.** It strips the BOM, CRs, ISO timestamps and ANSI CSI, then requires all of these:
  - exactly one exit line;
  - the last `##[group]Run` header before it is exactly the drift step;
  - only DRIFT / SNAPSHOT_MISSING rows, one FAILED line and the exit line as `##[error]` lines;
  - every row token matches `^[\w.]+/\d+$`;
  - exactly one in-step `findings N`, with N equal to the number of tolerated rows.

  `allowlist-*`, `MEASURE_FAIL`, `SNAPSHOT_ONLY` and `UNCOMPARABLE` lines are named in the refusal. Any other `##[error]` line is quoted, cut to 80 printable characters.
- **`derivePush`** (`scripts/sql-gate-subset.mjs`) is the only opt-in caller (D-04). The tolerated reason flows through `judgePush` and `oneLineReason` into `sql_gate_reason`, for example `…; predecessor <sha12> red only with tolerated baseline drift: f_one/1 (sql-gate-lint content-drift DRIFT 1, SNAPSHOT_MISSING 0; frontend aggregator red with it)`.
- **`ci.yml` `changed-paths`** gains `actions: read` and a dated comment. The `git diff` touches only that job's permissions and comment (10 added lines).
