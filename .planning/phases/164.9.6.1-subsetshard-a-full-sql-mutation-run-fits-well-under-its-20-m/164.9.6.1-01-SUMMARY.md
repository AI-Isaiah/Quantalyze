# Phase 164.9.6.1 Plan 01: In-job lane concurrency Summary

The SQL mutation runner now runs up to four gate files at once inside one `runCorpus` call, in one process. Lanes are spawned asynchronously, each worker gets its own port, and output is flushed in corpus order. Runs at concurrency 1 and 4 return identical tallies, exit codes and defect lists, on stub lanes and on real lanes. A full local corpus run at concurrency 4 took 298 s with `arms: 574/574/0`, `biting: 574` and `lane-invocations: 574`.

## What changed (by symbol)

- **`spawnAsync`** (new, private) returns a result shaped like `spawnSync`'s: `{ status, signal, error, stdout, stderr }`.
  - It settles once: on `close`, or on `error` when no pid was ever assigned. This was measured on Node v25.8.1: ENOENT emits `error` and then `close -2`.
  - It emulates `maxBuffer` by counting bytes across both streams. On overflow it kills the child and reports `ENOBUFS`.
  - Each stream is decoded once with `Buffer.concat`.
- **`runLane`** is now `async` and takes a `port` argument.
  - `env.PORT` overrides any `PORT` exported in the shell.
  - `laneTally[leg] += 1` and `laneArmGateTally.set` stay inside `runLane`, under the same `invoked` condition as before.
  - `output` is still stderr, then a newline, then stdout.
- **`LANE_CONCURRENCY_CAP = 4`** carries a dated, measured comment block above it.
- **`defaultLaneConcurrency()`** returns `max(1, min(cap, availableParallelism()))`.
- **`allocateLanePorts(n)`** opens n listeners at the same time, reads their ports and closes them all, so the ports are distinct by construction.
- **`runCorpus`** is now `export async function runCorpus({`, with a new `concurrency` parameter that defaults to `defaultLaneConcurrency()`. A non-integer or `< 1` value throws a usage error.
  - The probe lane is awaited before the pool starts and runs on `ports[0]`.
  - The old per-file `for` body is now `runFile` (nested inside `runCorpus`, every line still indented). It shadows `log` and `addDefect` with a per-file sink. Its three file-level `continue`s became `return`s.
  - `perFileTallies[index] = tally` is assigned by index.
  - Workers claim file indices synchronously (`next++`). `flush` writes a file's buffered lines and defects only after every earlier file has been flushed.
  - Workers are drained with `Promise.allSettled`. A stop flag is set on the first error, and that error is rethrown before the existing `finally` removes `scratchRoot`.
- **`lane-concurrency:`** is printed directly after `log(reasonLine);` and before any lane.
- **`selfTest`, `main` and the entry line** are async: `process.exit(await main(...))`. The `runCorpus({ scopeDir, onlyFile, onlyArm, subsetFiles, scopeReason })` call text in `main` is unchanged, so the CI mutate line and the nightly FULL tail are byte-identical.
- **`git diff` touches only the two `files_modified`.** Nothing under `.github/` changed, and `sql-mutation`'s `timeout-minutes` was not touched.

## Deviations from Plan

1. **[Rule 1 - plan premise] The multi-file corpus is the self-test gate directory, not `FIXTURE_CORPUS`.** The plan called `FIXTURE_CORPUS` "the multi-file corpus". It has one annotated file (`mini-gate.sql`, pinned by the subset AIM test), so it could never satisfy "more than one lane in flight".
   - Task 2 stubs run over all 12 files in `SELFTEST_DIR`.
   - `SELF-TEST (concurrency)` runs a SUBSET of four one-arm gates (`identity-rewrite`, `nonbiting`, `occurrence-mismatch`, `wrong-identity`), chosen for the fewest lanes inside the capped job. Each ends in a different defect, so the defect order has something to compare.
   - The row-1 header text is kept as the plan wrote it.
2. **[Rule 1] The equality comparisons exclude and normalise things that differ by construction.** The `lane-concurrency:` line differs between N=1 and N=4 (Test F asserts it separately). `mutation-runner-*/slot-N` paths and timing figures are normalised before comparing, because defect details carry the slot path.
3. **[Rule 3] `maxBuffer` is kept inline, not as a named constant.** A `LANE_MAX_BUFFER` constant matched the threshold audit's `MAX` name class in `gate-family-meta.test.ts`. The bound is the same literal the old `spawnSync` call carried, now passed to `spawnAsync`.
4. **[Rule 1] The worker rethrows into `allSettled`.** The first implementation swallowed the error inside the worker, which made `allSettled` and `Promise.all` equivalent, so neuter E could not bite. The worker now rethrows (commit `08a812ff2`). The drain is therefore what holds the rejection, and neuter E goes RED.
5. **An extra test, beyond A-F:** the usage refusal of `concurrency` 0, -1, 1.5 and NaN.
