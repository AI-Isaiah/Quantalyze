# Phase 147 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope of this contract

Phase 147 is predominantly a **server-side reader fix** (three bare readers of
`strategy_analytics.daily_returns` widened to resolve through
`resolveDailyReturnSeries`). This contract governs the **only UI surface in
scope**: the honest empty/degraded state on a scenario-composer constituent row
(147-CONTEXT.md → Decisions → "Honest empty state (Area 3)", ROADMAP SC4).

**In scope — exactly three things:**
1. A **syncing** state on an added-strategy composer row (server still computing).
2. A **terminal no-series** state on an added-strategy composer row.
3. The **visible excluded-from-blend note** attached to each.

**Explicitly OUT of scope** (do not spec, do not implement, do not "improve"):
- Composer legibility / layout / density → **Phase 152**.
- AUM input and its zeros-on-screen symptom → **Phase 151**.
- Any factsheet link or "view strategy" affordance from these rows → the owner
  factsheet **404s until Phase 148**; a link shipped here would land on
  `notFound()`.
- **Per-key exchange-source rows** (`data-testid="scenario-constituent-perkey"`)
  — they are fed by the book/dailies path, not the SCEN-01 returns reader. Their
  chip behaviour is byte-unchanged.
- The existing UNIFY-04 "Loading returns…" banner
  (`data-testid="scenario-loading-returns"`, `ScenarioComposer.tsx:4760`) — a
  **third, distinct axis** (client fetch in flight). Keep it verbatim. Do not
  fold it into the two states below; do not delete it.

### Semantic-color gate (normative — derived from DESIGN.md, not invented here)

| State | Tone | Why this tone and not another |
|-------|------|-------------------------------|
| syncing | **amber** `warning` | DESIGN.md 2026-04-11 + 2026-07-02: amber = **transient / recoverable**, whether the system or a one-click action performs the recovery. The server *will* finish computing on its own. Green would claim success; muted would hide that it resolves; red would claim permanence |
| terminal no-series | **muted** | DESIGN.md semantic gates: *"Muted = steady-state, honest-empty."* Absence is a neutral fact, not a failure |
| either | **never red** | DESIGN.md: *"Red = permanent / negative only… **Never for absence**, never for a zero."* A constituent with no series has not failed the allocator's action — the scenario is fine and the other constituents blend normally |

⛔ **`computation_status === "failed"` maps to the terminal *no-series* state
(muted), NOT to a red error.** The user-facing fact on *this* surface is
absence. The remedy for a failed computation lives on that strategy's own
detail page, which this phase does not link to (Phase 148). Recording this
explicitly so a reviewer does not read it as an oversight.

### Deliberate token reuse — read before flagging

`syncing` reuses the **exact** amber trio already used by `auto-excluded`, and
`no-series` reuses the **exact** muted pair already used by
`manually-excluded`. This is deliberate, not a collision:

- DESIGN.md's palette offers exactly three honest tones for a
  not-in-the-blend row (accent / amber / muted). Minting a fourth colour is
  banned by the AI-Slop Ban ("no new colours").
- DESIGN.md and `CoverageStateChip`'s own docstring already require that
  **"the text label always carries the meaning — color is never the sole
  signal" (WCAG-AA 1.4.1)**. The labels differ; the tones agree because the
  *semantics* agree.

## Component Contract

### 1. State vocabulary — extend `CoverageStateChip`, do not mint a second chip

**File:** `src/app/(dashboard)/allocations/components/CoverageStateChip.tsx`

Extend the existing `CoverageState` union **in place** with two members:

| State | Label (chip renders it `uppercase`) | Classes |
|-------|--------------------------------------|---------|
| `in-blend` (existing) | `In blend` | `text-accent bg-accent/10` |
| `manually-excluded` (existing) | `Excluded` | `text-text-muted bg-track` |
| `auto-excluded` (existing) | `Outside window` | `text-warning bg-warning-bg border border-warning-border` |
| **`syncing` (NEW)** | `Syncing` | `text-warning bg-warning-bg border border-warning-border` |
| **`no-series` (NEW)** | `No data` | `text-text-muted bg-track` |

- **Rule 7 — do not mint a second mechanism.** The chip already answers exactly
  one question: *"is this row in the blend, and if not, why?"* Both new states
  are answers to that same question. A parallel `SeriesStateChip` would be a
  second vocabulary for one axis and would risk disagreeing with the divisor
  the way `CoverageStateChip`'s docstring warns about (Pitfall 1).
- **Do NOT rename the file or the type.** Renaming churns three call-site
  files and a test file for zero user-visible gain (Rule 3). Update the
  component docstring's "coverage-window blend" phrasing to name the widened
  axis instead.
- The component stays **presentation-only** — it receives `state` as a prop and
  never re-derives membership or reads the analytics status itself.

### 2. Row anatomy — added-strategy rows only

**File:** `src/app/(dashboard)/allocations/components/ScenarioComposer.tsx`,
the `<li data-testid="scenario-constituent-added">` branch (~`:5587`).

| Property | Value |
|----------|-------|
| Row container | **unchanged**: `flex flex-col gap-2 rounded-md border border-border p-3` |
| `opacity-50 line-through` | ⛔ **NOT applied.** That is the *manual-exclusion* vocabulary; using it here would misread as *"you turned this off"* when the user did nothing |
| Row border | **stays `border-border`.** Do NOT switch to `border-warning-border`. That amber-bordered treatment belongs to the separate `AutoExcludedRow` group; DESIGN.md's AI-Slop Ban also rejects colour-stripe-as-identity. The chip + note carry the identity |
| Include/exclude toggle | **stays ON and interactive.** A no-series strategy stays ADDABLE and stays selected (147-CONTEXT.md locked) |
| Weight / leverage / target inputs | **stay ENABLED and editable.** The typed weight is preserved so it is already correct when the series arrives (the Wave-0 pin (d) preserved-weight precedent). Repo UAT direction: no disabled controls |
| New attributes | `data-series-state={"available" \| "computing" \| "empty"}` on the `<li>` |

**Chip placement:** in the existing identity cluster, immediately after
`<TrustTierLabel …/>`, in the same slot the current `chipState` chip occupies —
`className="shrink-0"`. Exactly **one** chip per row, always.

**Chip precedence (a row is never double-labelled):**

```
!enabled                      → "manually-excluded"   (user intent wins — it is the most recent
                                                       and most explicit signal)
seriesState === "computing"   → "syncing"
seriesState === "empty"       → "no-series"
coverageEligible[id]          → "in-blend"
otherwise                     → null   (the auto-excluded group renders it; unchanged)
```

**The note** renders directly below the identity cluster, inside the row:

| State | Element | Classes | Copy (verbatim) |
|-------|---------|---------|-----------------|
| syncing | `<p role="status" aria-live="polite" data-testid="scenario-series-state-note">` | `text-fixed-11 font-medium text-warning` | `First metrics arrive in ~10–15 min — not in the blend yet` |
| no-series | `<p data-testid="scenario-series-state-note">` | `text-fixed-11 font-medium text-text-muted` | `No return series available — not in the blend` |

Read chip-then-note, each state says exactly what 147-CONTEXT.md locked:
*"Syncing — first metrics arrive in ~10–15 min"* and *"No return series
available"*, with the excluded-from-blend note CONTEXT also requires.

### 3. State derivation — server-side, never inferred from an empty array

⛔ **`daily_returns.length === 0` cannot distinguish computing from
terminal-empty.** Deriving the state client-side from array length would
guarantee one of the two states is a lie.

The returns route (`src/app/api/strategies/[id]/returns/route.ts`) forwards a
discriminator alongside the existing `ReturnsResponse` fields (additive; the
happy-path shape is otherwise byte-identical, so no downstream composer change
is needed when a real series exists):

```
series_state: "available" | "computing" | "empty"
```

Derived server-side from the resolved series + `strategy_analytics.computation_status`
(the closed set at `src/lib/closed-sets.ts:423`):

| Resolved series | `computation_status` | `series_state` | Chip |
|-----------------|----------------------|----------------|------|
| non-empty | any | `available` | falls through to the coverage states — unchanged |
| empty | `pending` / `computing` | `computing` | `Syncing` |
| empty | **no analytics row at all** | `computing` | `Syncing` |
| empty | `complete` / `complete_with_warnings` | `empty` | `No data` |
| empty | `failed` | `empty` | `No data` (muted — see the gate above) |

⚠️ **The missing-row → `computing` mapping is a deliberate honesty call, and it
carries a risk the planner must handle:** a row that never appears would spin
"Syncing" forever — the permanent-spinner class v1.16 Phase 142 exists to kill.
The server-side reaper covers rows stuck at `computing`, **not** missing rows.
Planner: confirm strategy creation always enqueues analytics; if it does not,
the missing-row case must map to `empty`, not `computing`.

Rows fed by the **book** path (`payload.strategies`, `addedStrategyReturnsLookup`)
must derive `series_state` by the **same** table, from the book row's own
`computation_status` — not by a second rule. One mechanism, per SC2.

### 4. Blend-level honesty (SC4 backstop)

When the blend has **zero** contributing constituents, the blend's KPI cells
render **`—`**, never `0.00` (DESIGN.md Numbers Contract: *"Null / non-finite →
em-dash. **Never 0**, never blank, never a fabricated value"*), and a `—` cell
**never** carries a semantic colour. The existing 0/1-constituent
`EmptyStateCard` path (`ScenarioComposer.tsx:4427`) is the renderer — do not add
a second empty-state surface.

## Copywriting Contract

Voice per DESIGN.md: declarative, sentence-case, active, **states the limit with
its threshold attached**, no adjectives where a number exists, no cheerful
empty state, no icon.

| Element | Copy |
|---------|------|
| Primary CTA | **None new.** This phase introduces no CTA. The row's only action stays the existing include/exclude toggle. ⛔ Do not add a "View strategy" / "Open factsheet" link — it would 404 until Phase 148 |
| State chip — syncing | `Syncing` |
| State chip — terminal empty | `No data` |
| Empty state body — syncing | `First metrics arrive in ~10–15 min — not in the blend yet` |
| Empty state body — terminal empty | `No return series available — not in the blend` |
| Error state | **No error state on this surface.** Absence is not an error; the two states above are the entire vocabulary. A 500 from the returns route keeps the existing route-level envelope, unchanged |
| Destructive confirmation | **None.** This phase has no destructive action. Removing a constituent from a draft scenario is existing, reversible, and untouched |
| Existing copy that must NOT change | `Loading returns… {names} not yet in the projection.` (UNIFY-04 banner) · `In blend` · `Excluded` · `Outside window` |

**Copy review notes:**
- `~10–15 min` is the **threshold attached** — the reader learns exactly what
  unlocks the row. It is the founder-verified fresh-key sync window.
- The `—` in both strings is an **en/em dash used as a semantic glyph**, which
  the AI-Slop Ban explicitly permits (`⚠ — · × ✓`). The `–` inside `10–15` is an
  en-dash number range.
- Both strings are sentence-case, ≤ 56 characters, and contain no adjective.
- ⛔ Banned here specifically: "Oops", "Nothing here yet!", "Hang tight", any
  exclamation, any emoji, any icon-first empty state.

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Colour is never the sole signal (WCAG 1.4.1) | Every state carries a text label **and** a text note. Verified by the fact that the two new tones duplicate two existing tones — the label is doing all the differentiating |
| Non-blocking state change announced (DESIGN-05) | The **syncing** note carries `role="status" aria-live="polite"`, so the syncing → in-blend transition is announced. Prefer the existing `<LiveRegion>` primitive (`src/components/ui/LiveRegion.tsx`) if it can be mounted before the message arrives |
| No `role="alert"` | Neither state is a blocking error. `role="alert"` would be a false emergency |
| The terminal note is static | `no-series` does not transition on its own; no live region (an idle live region on every row is announcement spam) |
| Contrast | `#B45309` on `#FEF3C7` and `#64748B` on `#F1F5F9` are both already AA-pinned for the 11px tier by `tests/a11y/chart-contrast.test.ts` / the existing chip tests. No new pair is introduced |
| Motion | **None.** No spinner, no pulse, no skeleton shimmer. DESIGN.md: *"No decorative animation."* The word "Syncing" is the affordance |
| Tap targets | Unchanged — no new interactive element is added |

## Falsifiable Acceptance (for the planner's test tasks)

1. An added strategy whose analytics row is `computing` with an empty resolved
   series renders `data-series-state="computing"`, the chip text `SYNCING`, and
   the note `First metrics arrive in ~10–15 min — not in the blend yet` — and
   the note element has `role="status"`.
2. The same strategy at `complete` with an empty resolved series renders
   `data-series-state="empty"`, chip `NO DATA`, note `No return series
   available — not in the blend`.
3. Neither row renders `opacity-50` / `line-through`, and its include toggle
   reports `aria-checked="true"`.
4. Neither row's weight or leverage input is `disabled`.
5. Neither state renders any `text-negative` / `bg-negative` / `border-negative`
   class, and `computation_status: "failed"` with an empty series produces the
   **muted** `NO DATA` chip, not a red one.
6. No composer row ever renders **two** chips.
7. With zero contributing constituents, no blend KPI cell renders the literal
   `0.00`.
8. The UNIFY-04 `data-testid="scenario-loading-returns"` banner still renders
   while a lazy fetch is in flight (regression guard — it must not be folded
   into or replaced by the new states).
