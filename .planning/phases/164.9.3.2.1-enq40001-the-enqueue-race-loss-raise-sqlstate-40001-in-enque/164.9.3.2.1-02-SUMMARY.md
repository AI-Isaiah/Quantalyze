## Deviations from Plan

**1. [Rule 3 - blocking] `$LANE_LOCK` was not set in the executor's environment.** Same as plan 01: the lock directory was placed in the session scratchpad, set inside each lane script, released on every exit path by an EXIT trap, and never written into a tracked file. `docker ps` showed 0 supabase containers before the local-stack session.

**2. [Mechanics] The Bash tool's shell is zsh, which does not word-split `$APPLY`.** The first LANE CMD invocation therefore passed the whole apply list as one path and failed with `apply file not found` before any SQL ran. The LANE and RUNNER commands were rerun verbatim inside a bash scratch script. That run is not a verdict on the gate.

**3. [Seed] No api key was seeded.** The plan lists an api key in the seed. The gate seeds auth user, profile and strategy exactly as the dedupe gate does, because the enqueue is strategy-scoped and that seed is proven on this apply list and on the local stack.

**4. [Process] The executor's `agent-*` worktree branch allow-list does not fit `feat/164.9.3.2.1-enq40001`.** Every commit was gated instead on the orchestrator's root pin (toplevel and branch equality).
