### Migration: `set_strategy_fills_reread_bound` RPC (SECDEF, claim-token fenced)

**Analog:** `20260602173710_advance_sync_cursor_claim_token_fence.sql`. Copy the shape: `SET LOCAL search_path = public, pg_catalog;`, then:

```sql
CREATE OR REPLACE FUNCTION advance_sync_cursor(
  p_api_key_id UUID, p_job_id UUID, p_claim_token UUID DEFAULT NULL, ...
) RETURNS BOOLEAN LANGUAGE plpgsql SECURITY DEFINER
SET search_path = public, pg_catalog
AS $$
BEGIN
  IF p_api_key_id IS NULL THEN
    RAISE EXCEPTION 'advance_sync_cursor: p_api_key_id is required'
      USING ERRCODE = 'invalid_parameter_value';
  END IF;

  IF p_claim_token IS NOT NULL THEN
    IF p_job_id IS NULL THEN
      RAISE EXCEPTION 'advance_sync_cursor: p_job_id is required when p_claim_token is supplied'
        USING ERRCODE = 'invalid_parameter_value';
    END IF;
    IF NOT EXISTS (
      SELECT 1 FROM compute_jobs
       WHERE id = p_job_id AND status = 'running' AND claim_token = p_claim_token
    ) THEN
      RETURN FALSE;           -- orphan: write nothing
    END IF;
  END IF;
  ... single atomic UPDATE with CASE monotonic guard ...
  RETURN TRUE;
END; $$;

COMMENT ON FUNCTION advance_sync_cursor(UUID, UUID, UUID, TIMESTAMPTZ, TIMESTAMPTZ, NUMERIC) IS '...';

REVOKE ALL ON FUNCTION advance_sync_cursor(UUID, UUID, UUID, TIMESTAMPTZ, TIMESTAMPTZ, NUMERIC)
  FROM PUBLIC, anon, authenticated;
```

**ACL caveat:** the live baseline ACL is `REVOKE ALL ... FROM PUBLIC` plus `GRANT ALL ... TO "service_role"` (RESEARCH, `supabase/schema/baseline.sql`). The migration only states the REVOKE. For the new RPC state BOTH explicitly (`REVOKE ALL ... FROM PUBLIC, anon, authenticated; GRANT EXECUTE ... TO service_role;`). The SQL gate must read the ACL through `aclexplode(proacl)`, not trust the migration text.

**Body semantics** (LEAST on stop, clear only when `p_covers_from <= existing.unread_from`, re-point replaces, key mismatch) are fixed in RESEARCH Pattern 1; the PL/pgSQL state machine has no existing analog. Use a single `INSERT ... ON CONFLICT (strategy_id) DO UPDATE` or a `SELECT ... FOR UPDATE` on the row so concurrent advance-vs-lower is atomic (D-05).

**Verify-block warning:** the analog's `DO $verify$` CALLS the function with dummy UUIDs and checks the return. Do NOT copy that shape if the call reads or writes data tables: `scripts/lint-migration-data-dependence.mjs` refuses data-reading `DO` guards with no opt-out. Keep the new verify block catalog-only (`pg_proc` existence, `prosecdef`, `proconfig` containing `search_path=public, pg_catalog`, `aclexplode(proacl)` grantee set exactly service_role); behaviour is pinned by the SQL gate instead.

if _fills_cursor_ms is None:

    if daily_since_ms is not None:

## Shared Patterns

### Claim-token fence on epilogue writes
**Source:** `advance_sync_cursor` plus its `_advance_cursor` call site. **Apply to:** the new bound RPC and its worker call. `WORKER_FENCE_V2` defaults on; off passes a NULL token and the RPC writes unconditionally.

### Service-role-only table posture
**Source:** `20260919120000_strategy_sync_cursors.sql`. **Apply to:** the new table (deny-all policy plus REVOKE from PUBLIC, anon, authenticated plus GRANT to service_role plus catalog-only verify).

### RED-UNDER / mutation proof
**Source:** `test_strategy_sync_cursors_rls.sql` annotations. **Apply to:** the new SQL gate; PROOF-01 for every gate (neuter from a byte backup with `cp` and `cmp`, never `git checkout/restore/stash`).

### Present-only carry through wholesale rewrites
**Source:** `daily_pnl_malformed_` carry in the runner and prestamp. **Apply to:** all nine `binance_*` sync keys, with the extra list/int validation.

### Over-fetch is safe
The `(strategy_id, exchange, exchange_fill_id)` unique index absorbs a re-read span, so a lowered walk start cannot duplicate fills.
