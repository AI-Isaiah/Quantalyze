<objective>
Make `run_sync_trades_job` keep every run's daily P&L and record its refusal flags truthfully. This plan covers ROADMAP Phase 251 items 1-4 (SC-1 to SC-4), with PROOF-01 (SC-6) for each gate it adds.

Decisions implemented (CONTEXT has no D-NN ids, so they are cited by CONTEXT label):
- "Item 1: store order". The store moves into the ccxt arm, after the read, the drain and the refusal check, and before `fetch_usdt_balance` and the Phase-2 walk. The `phase1_failed` handling is unchanged, and Phase 2 still runs after a persist failure. The flag write stays in its one place at the end of the handler. A run cancelled after the store loses its flag write, and that is accepted.
- "Item 2: no store under a refusal". The reader is the shared `daily_pnl_read_verdict`; no new predicate is written. A deadline flag also refuses. A refusal holds `last_sync_at` and the fills cursor, never touches `phase1_failed`, and reports `trade_count` 0. The balance write, the follow-on enqueue and the DONE outcome are unchanged. On `verdict.rate_limited` the handler raises `ccxt.RateLimitExceeded` into the outer 429 arm.
- "Items 3 and 4: the flag write". The handler owns these keys: the reason keys, `daily_pnl_fetch_error_class` and `daily_pnl_unsupported_venue`. On every run where the ccxt read ran, the stored owned keys are replaced by this run's drained set. `daily_pnl_malformed_*` is merged as drained and never popped. `needs_flag_write` also holds when the ccxt read ran. The upsert site and its payload literal are reused, so the census does not move.
- "Research resolutions":
  - `write_needed` accumulates.
  - A failed flag read with Phase 2 not run skips the write, with a log line.
  - A refused run does not clear a stale `phase1_daily_pnl_persist_failed`.
  - The stored class is the sanitized `verdict.error_class`.
  - A Deribit sync is refused by name every run, pinned by a test.
  - An AST pin covers every `daily_pnl_*` flag.
  - The source-text pins are kept green, never edited.
- "Decided autonomously" [Tests]: mocked-supabase handler tests with `_RAW_TRADE_INGESTION_ENABLED` patched through `unittest.mock.patch`, never `importlib.reload`. [Scope]: `routers/cron.py` is not touched.
- "Claude's Discretion" (owned-key helper shape), the planner's choice: a module-level `_DAILY_PNL_REFUSAL_COMPANIONS` frozenset and a predicate `_is_sync_owned_daily_pnl_key(key)` in `services/job_worker.py`, its only consumer. The predicate returns True for a companion, or when `daily_pnl_read_verdict({key: True}).reasons` contains `key`. It therefore reuses the verdict for the reason set, as CONTEXT requires, and a reason added to the verdict later is owned automatically. This is a deliberate change from RESEARCH Pattern 2's hand-listed set, which could drift from the verdict. Keeping it in `job_worker.py` limits production edits to one file.

Purpose: a run that times out in the fills walk loses no daily P&L. A refused read never overwrites real daily rows with spot fills. The `daily_pnl_*` refusal flags finally reach `data_quality_flags` and are cleared when the read is clean.
Output: the two files above, and `251-01-SUMMARY.md` with the pre-fix RED evidence and the PROOF-01 table.
