## Known limits (recorded, not fixed)

- **B12c, plan 11.** A snapshot frozen before this phase carries no `sharpe_record` and shows its Sharpe as stored (state `"null"`). Nothing was invented for it and no backfill ran. `Date.parse` rolls a calendar-overflow day such as `2026-02-30` forward while Python's `date.fromisoformat` rejects it, so Python freezes that row `unreadable: true` (withheld, the documented failure direction); producers write only real days.
- **Match reason, plan 12.** Reasons frozen in `match_candidates` batches scored before 194.1-12 keep the Sharpe sentence. A short (cleared, under one year) record keeps today's text with no qualifier; the card beside it carries the `<1y` marker. `High-conviction screening pick` prints no figure and is unchanged.
- **B8, plan 09.** The three wire scalars cannot carry the record's `unreadable` flag, so the route serves a fourth wire field, `figure_unreadable` (true only when the run is rankable and the record's dates are present but not dates; R2 WR-01), and reports the record once to Sentry. `cagr`, `sharpe`, span and count keep their rankable gating, so the values reach the composer and `parseConstituentRecord` reads the flag as `unreadable`: both cells render the withheld marker with the reason "Withheld: the record's dates could not be read.", and the "No computed metrics" sentence does not appear (nulling the pair instead made the panel print it, falsely). A deploy older than the route change omits the field and reads as unknown, so it shows the figure as before.
- **Bridge, plan 05.** A response from an analytics deploy older than 194.1-05 shows the Sharpe delta as before until the service redeploys (absent state reads as unknown). The gate does not alter ranking, so a withheld candidate can still rank first (D-15 display rule).
- **B6, plan 08.** A null `strategies` row with no read error passes a null asset class to `recordFromScalars`, which maps to the non-crypto basis through `annualizationPeriods`; it is never turned into crypto. Only a read error throws.
- **B5, plan 07.** A recommended id with no `strategies` row nulls that card's CAGR and Sharpe plainly (no default class) and logs once.
- **B3, plan 06.** `OG_CARD_VERSION` is `"2"`; bump it with any later change to the card's figure rules. The manual check of one short-record card on a preview deploy was not run (no deploy, no database access).
- **196.** If a 196 merge deletes a redirected file, its `EXCLUDED` entry turns stale by name in the census test; delete the entry in whichever PR merges second.
