An unreadable `series_end` or `headline_since` on a rankable run therefore no longer prints a CAGR or Sharpe for a drawer-added leg. A rankable, readable record still serves both values. That matches the executor's recorded RED ("2 failed, expected 0.5 to be null"). All 78 tests in the route, constituent-figure and composer figure-gate files pass at HEAD.

For an unreadable record that sentence is false: the run finished and the metrics exist. They are withheld, and every other 194.1 site renders this state with the withheld idiom.

## Warnings

### WR-01: A drawer leg with an unreadable record now prints "No computed metrics for this strategy", which is false, instead of the withheld idiom (MEDIUM, user-facing)

**File:** `src/app/api/strategies/[id]/returns/route.ts:515, 601-604`; consumer `src/app/(dashboard)/allocations/components/ScenarioComposer.tsx:8203, 8222-8223, 8598-8602`
**Issue:** On a rankable run with `record.unreadable`, the route now sends `cagr: null` and `sharpe: null`, with null span and count. That body reaches the composer as follows:
- `parseConstituentRecord` builds `{ spanDays: null, observations: null, crypto: true|false }` with no `unreadable` flag. `gateAnnualized` returns `"null"` (unknown), not `"withheld"`, so the cells render two bare em-dashes with no withheld marker and no reason.
- `metricsAbsent = metrics.cagr == null && metrics.sharpe == null` is true, and `metrics.state === "settled"`. So `metricsAbsentSettled` renders: "No computed metrics for this strategy — open the factsheet for detail."

The panel's own contract (comment at `ScenarioComposer.tsx:3060-3066` and the `metricsAbsentSettled` block at :8571-8596) allows that sentence only where the route observed that the strategy really has no metrics: no analytics row, or a run that did not finish. Phase 162 removed the same class of falsehood, a claim about the strategy that the code never observed. This record has a completed run and stored CAGR and Sharpe. D-15/D-17 says to **withhold** them. Every other gated site (`recordClears` returns `false` for `unreadable`) shows the withheld idiom with its reason. The factsheet that the sentence sends the allocator to shows a withheld figure, not "no metrics".

The rewritten `194.1-SITES.md` B8 limit says the record is "withheld there". That is true of the wire and not of the render.

The book leg differs too, for the same kind of malformed `headline_since`. `figureRecordScalars` (`src/lib/queries.ts:2826-2833`) regex-filters a non-date `headline_since` to null rather than marking the record unreadable. A book leg therefore shows the stored figure, while a drawer leg says "No computed metrics". This is a pre-existing producer asymmetry. The fix makes it visible as contradictory copy rather than as a span difference.

The state is rare. Producers write ISO days, and the route reports each case to Sentry. It is reachable, though: the round-1 parity fixture pins `headline_since: "garbage"`, and it was rare enough to be WR-01 itself.

**Fix:** Pick one. The first is the one that makes the render match the phase rule.
1. **Carry the flag (founder-scoped, because plan 09 ruled out a fourth field).** Serve `figure_unreadable: true` when `analyticsRankable && record.unreadable`. Keep `cagr` and `sharpe` gated only by `analyticsRankable`, so the panel does not take the "no metrics" branch. Read the flag at the client boundary:
   ```ts
   // constituent-figure.ts parseConstituentRecord
   return {
     spanDays: finiteOrNull(body.figure_span_days),
     observations: finiteOrNull(body.figure_observations),
     crypto: body.figure_crypto === true,
     ...(body.figure_unreadable === true ? { unreadable: true as const } : {}),
   };
   ```
   `gateAnnualized` then returns `"withheld"`, and `gatedValue` / `annualizedCell` render the withheld idiom with its reason. A deploy that predates the field still reads the figure as unknown.
2. **If the fourth field stays ruled out:** keep the route as it is, but stop the false sentence. In the composer, gate `metricsAbsentSettled` so it does not fire when the lazy entry was withheld for this reason. The client cannot detect that today without a signal, which is why option 1 is the real fix. At minimum, rewrite the B8 limit in `194.1-SITES.md` to state the render honestly ("the composer shows two dashes and the 'No computed metrics' note"), so the limit is not described as a withhold it is not.

Add a composer-level test (in `ScenarioComposer.constituent-figure-gate.test.tsx`) that drives a drawer leg whose `/returns` body is an unreadable rankable record, and asserts the withheld idiom and the absence of "No computed metrics". The current tests prove the wire only. The user-facing outcome that WR-01 was about has no test.
