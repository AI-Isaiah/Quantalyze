## Breakpoints (from DESIGN.md, the shell and D-05)

DESIGN.md names no "tablet" token. It fixes the 260 px sidebar as "desktop only", and the shell (`DashboardChrome`) shows that sidebar, drops `MobileTopBar` / `MobileNav` and widens the page padding at Tailwind `md`. D-05 then moves the pin off the viewport entirely: **the Strategy column pins on the table's own width, at the `@3xl` container step (48 rem = 768 px of `Strategies` region)**, the same container step the table already uses for its `@max-3xl:hidden` column collapse.

**Where the pin switches, in viewports.** Region width = viewport − 260 (sidebar) − 64 (`md:px-8` × 2) − 2 (frame border). It reaches 768 px at a viewport of **1094 px**. Every phone, every tablet and every laptop window narrower than that scrolls the whole row together. Pinning and the full column set now switch at the same width, so a pinned table always shows every column.

## The scroller contract (SC-1 and SC-6)

One rule, every surface in this phase:

1. **The page never scrolls sideways.** The universal pass condition holds at every viewport in the table above, on `/allocations?tab=holdings` and `/discovery/crypto-sma`.
2. **A table wider than its column scrolls inside its own scroller**, and that scroller is a `ResponsiveTable` (focusable, named, inset focus ring). Where the table overflows, `scroller.scrollWidth > scroller.clientWidth`.
3. **A scroller is never wider than its containing column.** `scroller.getBoundingClientRect().right <= viewport width` at every viewport.
4. **The fix lives on the ancestor that grows, not on the scroller.** Every grid or flex ancestor between `#main-content` and a scroller has a zero minimum inline size: a grid declares its track as `grid-cols-1` (Tailwind v4: `repeat(1, minmax(0, 1fr))`), and a flex item gets `min-w-0`. No `overflow-x-hidden` on any ancestor (it would clip, not contain), and no px `max-w-[…]` on any page or body shell (DESIGN.md: the shell is the sole owner of the wide measure).
5. **Measure first.** The owner on each route is located by `assertNoReflow` at HEAD before the change. The rows below name the owners the code reading found; if the measure names another, the fix goes on that ancestor by rule 4.

## /compare equity overlay (SC-3, D-07)

| Id | Element | Contract |
|----|---------|----------|
| C-1 | Plotted span and value | Each strategy's line covers **the span its stored headline `cumulative_return` compounds** (D-07): `nav_twr._last_interior_break_suffix`, the stretch after the last interior break. It is drawn from the stored equity levels in `strategy_analytics.returns_series`, never compounded from them. Both producers store levels on a base of 1.0. **Clean row** (no `data_quality_flags.twr_chain_broken`): the span is the whole stored series and point = `(level − 1) × 100`. **Chain-broken row:** the span starts on the day `deriveHeadlineCoversFrom` names (the same single source as the factsheet's `headlineCoversFrom`); only days on or after it are plotted, and point = `(level / openingLevel − 1) × 100`, where `openingLevel` is the stored level on the last stored day before the span. On both rows the last point equals the stored `cumulative_return × 100`. The research step confirms the chain-broken anchor against one stored chain-broken row before planning. A non-finite level is dropped from the line (no point, no zero) |
| C-2 | Y-axis ticks | Unchanged format: integer percent, `{n}%` (`0%`, `5%`, `10%`, `15%`; a negative tick prints `-5%`). Geist Mono, `CHART_AXIS_TICK`, 10 px, the existing frozen tick style; `width={48}` unchanged. No axis title (none today) |
| C-3 | X-axis ticks | Unchanged: the ISO date string (`YYYY-MM-DD`), `interval="preserveStartEnd"`, `minTickGap={60}`. The shared date axis is the union of the plotted spans, so a chain-broken strategy's line simply starts later |
| C-4 | Tooltip value | Signed, 2 dp, through `formatPercent` on the fraction: `+14.54%`, `-3.20%`, `+0.00%`. `formatPercent` prints an ASCII hyphen-minus and signs on the raw value, so a value in (−0.00005, 0) prints **`-0.00%`**. That edge is accepted, not fixed here: the table prints the same string through the same formatter, so chart and table still agree, and changing `formatPercent` is app-wide. The series name stays the label |
| C-5 | Notes under the legend | A block between the legend and the chart: `<div className="mb-3 grid gap-1">`, one `<p className="text-caption text-text-secondary">` per note, in legend order. The notes are: (a) a strategy whose span starts after its first stored day: `Measured since {date} ({name})`, with `{date}` in the `isoToMonthDay` format (`Mar 4, 2025`). (b) A strategy with no finite level: `{name}: no return series yet.` It gets no line and no legend swatch, but it is never silently dropped. (c) A chain-broken strategy whose span start cannot be named (`deriveHeadlineCoversFrom` returns `null`): `{name}: the span of its cumulative return cannot be dated, so no curve is drawn.` It gets no line and no swatch; no span is guessed. Nothing renders when there is no note |
| C-6 | Legend, colours, height | Unchanged (`LINE_COLORS`, 320 px, the swatch legend). Out of scope for this phase |
| C-7 | Empty state | When no strategy draws a line, the existing empty-state copy renders, followed by the C-5 notes that explain why |

**Assertions (SC-3).**
- A unit test with the measured clean series (levels 0.99998 → 1.1454, stored `cumulative_return` 0.1454) renders a last data point of 14.54 (±0.005) and a tooltip string `+14.54%`. It fails at HEAD, where 112 compounded points reach about 1e35%.
- A chain-broken fixture plots only days on or after its covered-from date, its last point equals its stored `cumulative_return × 100`, and the note `Measured since {date} ({name})` renders.
- For every compared strategy, the last tooltip string equals the `CompareTable` Cumulative Return cell string (chart and table always agree, D-07).
- A strategy with no finite level renders `{name}: no return series yet.`

## Accessibility — scroll containers

- **Every horizontal scroller in this phase is a `ResponsiveTable`.** Each has `role="region"`, `tabIndex={0}`, a unique `aria-label` naming the table and the affordance, and an **inset** focus ring (`ring-inset`), so the ring is not clipped by the scroller or a bordered ancestor (UIFIX-02). The Exposure drill-down joins this set (H-3); until now it was a scroll box that could not be focused and had no name.
- **Keyboard:** Tab reaches each region once, and the arrow keys scroll it (the native behaviour of a focused overflow box). The region itself is the tab stop, not each cell.
- **Unique names per page:** `/allocations?tab=holdings` renders Strategies, Holdings, Open positions and Exposure by venue and symbol. No two share a name (axe `landmark-unique`).
- **The visible hint is `aria-hidden`** and pairs with the region's name. The name is never duplicated into an `sr-only` node, which would announce it twice.
- **Unpinning and the z-index change are invisible to assistive tech.** D-1 and P-1 change only CSS position and stacking. Header `scope="col"`, `aria-sort`, the sr-only `Rank` and `Watchlist` header names, and DOM order are unchanged.
- **The /compare notes are plain text in reading order** after the legend, so a screen reader meets them before the chart.
- **Reflow (WCAG 1.4.10):** the page itself never scrolls in two dimensions from V360 to V735. Only data tables scroll, inside their regions; they are two-dimensional content, which the criterion exempts.
- **Gate:** the existing axe matrix (`wcag2a`, `wcag2aa`, `best-practice`) on `/allocations?tab=holdings` and `/discovery/[slug]` reports zero violations at V390.
