## Gaps

### G1 - RESOLVED at 4aed38c87 (was: "cache wins" in memory only; plain upsert)

Resolution: `ce00dd736` writes with `on_conflict="symbol,date", ignore_duplicates=True`. Note the design consequence: a wrongly stored close can no longer be corrected through the product path or the backfill script (insert-only); correcting one is a deliberate manual operation. That is the intended trade (the cache is the source of record).

Original finding, kept as lineage:

Location: `analytics-service/services/benchmark.py`, fetch arm (`to_write` then `supabase.table("benchmark_prices").upsert(cache_rows)`). The read loop swallows `_CACHE_READ_ERRORS` and non-DB errors and continues with whatever `by_date` holds (empty on a page-1 failure, partial on a later-page failure), and two concurrent compute jobs can race the same cold window. `to_write` then contains dates that are already stored, and `upsert` is `ON CONFLICT DO UPDATE`.
Impact: a stored Binance close is replaced by a CoinGecko start-of-day price (measured about 0.05 percent apart by the phase research), silently and permanently, since the cache wins on every later read. The prior code overwrote on every fetch, so this is an improvement, not a regression, and the CHANGELOG Notes book half of it as "flagged, not fixed". The code comments and the script docstring still state the invariant unconditionally.
Fix expected: enforce it at the write, `upsert(cache_rows, on_conflict="symbol,date", ignore_duplicates=True)` (ON CONFLICT DO NOTHING), keep `to_write` as the "nothing to write" short-circuit, and add a test with the cache read raising plus a CoinGecko-only fetch asserting a pre-seeded close is unchanged. Alternatively record it as an accepted risk in this file with the founder's name and date (it is bounded, low-amplitude and self-limiting, but it is not recorded as accepted today).

The strategy's `returns_series` is already in the same projection, so no new tier of data leaves, but this is the first service-role read on that page.
