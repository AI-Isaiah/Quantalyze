<objective>
SC-5, core: the benchmark read is driven by the strategy's first date (`since`), not by a fixed
trailing 1000 days, and the cache read pages past PostgREST's 1000-row cap. Wired end to end through
the CSV runner, the path most benchmarked strategies take.

Purpose: `get_benchmark_returns(days=1000)` reads `.limit(days + 1)` and only ever serves the trailing
1000 days, so older strategies lose alpha, beta, Treynor and R² history on each recompute (ROADMAP
evidence (5), measured on PROD). Phase 169.2's "read in full" is true of `get_btc_closes` only and is
false of this reader (RESEARCH, re-measured at HEAD: the CONTEXT "Claude's Discretion" re-measure).
Read shape chosen (CONTEXT discretion): read from the strategy's first date, keeping `days` as a
floor, so every strategy younger than the window keeps byte-identical inputs.

Output: the `since` keyword with a keyset-paged cache read, the CSV runner passing it, and tests that
fail on the plan-01 head. Plan 03 wires the remaining callers and the census; plan 11 writes the backfill script.
The restoring recompute is named for the Wave 5 consolidated PROD recompute (D-03) and is not run.
