<objective>
Implements CONTEXT decisions: D-02, D-05, D-06.
SOAK-03: the soak checks day attribution against an independent per-day walk that imports no production helper, and goes RED when one deal is moved by one UTC day.

Purpose: today the soak's expected return uses the fold's own per-day P&L, so a deal bucketed onto the wrong UTC day shifts P_t and NAV_{t-1} together and every check stays green. RESEARCH measured that scenario as `parity_ok True`. This closes `[164.6.6.2.3-SOAK-DAY-ATTRIBUTION]`, whose "Done when" is that the soak accumulates an independent per-day trading P&L from the raw deals and compares it day by day.

Decision traceability, by CONTEXT label (CONTEXT has no D-NN ids):
- "Independence rule": the walk imports no `services.nav_twr`, `services.broker_dailies` or `services.mt5_deals` arithmetic, reads raw fields, does its own UTC bucketing, and an AST test asserts this and can fail.
- "Day-attribution check": every day is compared, a named kind `day_attribution_mismatch`, and counts are carried like the existing checks.
- "PROOF-01".

RESEARCH recommendations adopted:
- Flow attribution on the same walk (`flow_attribution_mismatch`).
- The return reading moves to the walk's P&L while the level roll stays on the fold's, which gives two detectors for a mis-bucketed fold.
- Patch the fold in both namespaces (Pitfall 1).
- Drift pins in the test file.

Discretion choice, recorded: the redundant pre-walk `classify_deal` pass is dropped. The `combine_mt5_deal_ledger` call runs first and already raises `Mt5DealClassificationError` on an unknown type (`test_unclassifiable_deal_type_propagates` pins it). After that, nothing from `services.mt5_deals` is used, so the import block goes. Its last name was the pre-existing unused import (the ruff baseline finding), so ruff drops from 1 to 0.

Output: the two modified files and `226-02-SUMMARY.md`.
