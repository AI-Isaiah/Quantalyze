### V.a — A second, unplanned fire proof (found during Task 1)

Worth recording because it is an instance of this phase's own subject matter.
Both fixtures' JSDoc banners originally contained the glob `**` + `/*.ts`. The
`*` + `/` inside that glob **terminates the block comment**, so the remaining
prose parsed as code. `ts.createSourceFile` RECOVERS rather than throwing
(`seam-log-coverage.test.ts:1010`), and returned a tree of nonsense
`BinaryExpression`s with **zero** call expressions — measured, 5 parse
diagnostics.

The red-fixture test caught this immediately, because it asserts a POSITIVE. The
green-fixture test did **not**: it asserts an ABSENCE, and an absence is
satisfied perfectly by a corrupted parse. "SRO-01 green fixture is clean" would
have read as proof while inspecting rubble — a self-referential oracle inside the
self-referential-oracle detector. Fixed by rewording both banners and by adding
`countExpectCallSites` as a vacuity fence: the green test now proves the parse
found real `expect` sites before it proves there are no findings among them.

## VII. NON-COVERAGE — what the rule cannot see

Plan 08 must size its allowlist knowing these bounds, because an allowlist that
implies wider coverage than the rule has is itself a false attestation. Stated in
the gate's own file header too:

1. **SAME-BLOCK ONLY.** Subject resolution searches only the statements of the
   nearest enclosing block (or source-file top level) that PRECEDE the expect's
   own statement.
2. **NO OUTER-SCOPE OR MODULE-LEVEL RESOLUTION.** A literal `const` in a
   `describe` body, at module level, or imported, asserted inside an `it`, is NOT
   flagged — even though the same vacuity is available there. This is the largest
   known blind spot.
3. **NO DATAFLOW THROUGH CALLS, NO MATCHER INSPECTION.** `expect(wrap(lit))` is
   invisible, and only `expect`'s argument 0 is examined; the matcher side and
   the second `expect(subject, message)` argument are ignored.

Additional bound measured here and not in the original spec:

4. **NO MUTATION MODELLING.** A binding whose initializer is literal-only but
   which is mutated before the assertion is flagged anyway — the 19 accumulator
   findings in § III.a. This is the rule's dominant imprecision at HEAD.

Also out of population by construction: the rule scans
`src/__tests__/**/*.test.ts` only. Tests under `src/lib/`, `scripts/`,
`tests/a11y/` and `tests/visual/` — all collected by vitest — are **not**
scanned. `src/lib/wizardErrors.test.ts` (the repo's NUL-carrying, grep-blind
file) is outside this population; the walker reads through `node:fs` rather than
shell `grep` regardless, so a NUL could not silently blind it.
