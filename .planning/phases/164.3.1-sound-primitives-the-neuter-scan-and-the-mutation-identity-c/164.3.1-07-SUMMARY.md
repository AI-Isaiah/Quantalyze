### The rule, and why it is a ratio

> If the committed snapshot is substantially populated (`>= 50` bodies) but PROD's name index holds fewer than **half** as many names, the READER is broken, not the database.

The threshold is calibrated against a **second, independently produced population the gate already holds**: the committed snapshot bodies, generated *from PROD* by `npm run schema:functions`. Their count is therefore a prior **measurement** of PROD's public-schema catalogue, not a number someone chose. D-10 requires thresholds set by measurement, never by taste — and a hardcoded literal would rot the moment PROD's catalogue grew or shrank.

### Wide separation, both directions with their measured values

| Direction | Measured value | Against the 59-name halfway mark |
|---|---|---|
| **FIRES** | a broken reader scores **0** names — measured 2026-09-01 in plan 164.3.1-04's pre-fix probe, where the [VAC04-C2] guard defect made **both** readers print nothing and exit 0 | an order of magnitude below |

PROD would have to lose ~60 functions in a single PR to approach the mark. This is separation, not tuning.
