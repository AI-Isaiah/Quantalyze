## Accomplishments

- **Recorded the blindness against real bytes.** Case A (a `/*` on a continuation line of a
  multi-line template literal, with a real `supabase.from('trades').insert(batch)` below it)
  returns `[]` at HEAD. `unmatchedBlockOpen`'s quote state is function-local and discarded at
  every newline, so line 3 reads its `/*` as unquoted, opens a phantom block, and
  `stripBlockComments` blanks lines 4-7. Main's H-0001 audit-coverage gate is currently blinder
  than it was before SP-I01.
- **Recorded both controls, which is what makes the fix falsifiable.** Case B (byte-identical to A
  minus the `/*`) returns `[5]` — proving the harness, the extraction and the detector all work,
  so "A now returns a site" cannot be satisfied by a stripper that returns every line. Case C (the
  shipped single-line-template arm's shape) returns `[3]` — the regression guard the fix must not
  break, and the reason the shipped arms never caught this.
- **Built the instrument so the before and after legs share one ruler.** The harness bakes in no
  expected values and exits 0 on any successful measurement. Plan 164.3.1-06 re-runs this exact
  committed file, unedited, for its "after" column. A before/after comparison across two different
  instruments measures the instruments, not the fix.
- **Closed the retype hole.** The six declarations (`MUTATOR_CALL_RE`, `FROM_CALL_RE`,
  `unmatchedBlockOpen`, `stripBlockComments`, `stripLineComment`, `findMutations`) are lifted by
  name from the subject's own bytes via `ts.createSourceFile` + `stmt.getText(sourceFile)`,
  transpiled, and evaluated in an empty `node:vm` context. The script contains no reimplementation
  of any of them and has no fallback path — a missing declaration exits 1 naming it.
- **Bound the measurement to bytes.** The artifact carries branch HEAD `a16d9c36`, subject git blob
  hash `dff9d1a1945d252b57910739c05d712fc7ad3c8f`, and the blob-equality proof: working-tree
  `shasum -a 256` and `git show HEAD:… | shasum -a 256` both
  `6a1205ad685b1bd047e1533f6ae9a3b64185bb2be5f63b9c2874f65d6a866ce7`. The harness independently
  hashed the file it read and printed the same value inside the recorded output.

## Decisions Made

- **Subject resolved from the script's own location, not `cwd`.** `path.resolve(SCRIPT_DIR, "..",
  "..", "..")` reaches the repo root from `.planning/phases/<phase>/`. The documented invocation is
  still from the repo root, but the instrument cannot be pointed at the wrong tree by a stray `cd` —
  and plan 06 can run it from any working directory. The resolved absolute path is printed, so the
  provenance is never ambiguous.
- **The harness prints the subject's SHA-256 itself.** This was the plan's stated
  executor's-choice point ("`node:crypto` … or shell out to `shasum` from Task 2 instead"). Doing
  it inside the instrument makes the recorded verbatim output self-binding: the hash in §4 of the
  artifact was produced by the same process that produced the site values, not pasted beside them.
  The Task 2 `shasum`/`git show | shasum` pair is still recorded, and all three agree.
- **The fail-loud arm was observed firing, not merely reasoned about.** Proving it required
  removing a declaration from the subject — which this plan is forbidden to touch. Resolved by
  copying the subject and the harness into a scratchpad tree (with a `node_modules` symlink),
  confirming the copy reproduced `AUDCOV-CAL A=[] B=[5] C=[3]` and the identical `sha256`, then
  renaming `unmatchedBlockOpen` in the copy and observing `FATAL: could not locate 1 of 6 …
  unmatchedBlockOpen` with `EXIT=1`. The real subject stayed porcelain-clean throughout. No
  `git checkout --`, no byte-backup/restore harness, nothing to restore.
- **`module: ESNext` for the transpile.** The extracted snippet has no imports or exports, so
  ESNext output is a plain script with no `exports` reference that `vm.runInContext` would choke on.
