## Decisions Made

- **Did not tune the rule after seeing the count.** 19 of 23 findings are known imprecision. Narrowing the rule to model mutation would have produced a comfortable "4 findings", and doing that *after* seeing the number is precisely the self-referential move this phase exists to stop. The detector shipped in `807702ff` is byte-identical to the one that produced every recorded number.
- **Report via `process.stdout.write`, not `console.log`.** Measured: vitest 4.1.10's default reporter swallows console output from passing tests. The plan's bare verify command would have observed nothing. `--reporter=verbose` and `--disable-console-intercept` also work, but a gate whose evidence depends on the caller remembering a flag is one flag away from being evidence of nothing.
- **Recorded a fourth non-coverage bound** (no mutation modelling) beyond the three the plan specified, since it is the rule's dominant imprecision and plan 08 must size its allowlist knowing it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Both fixtures' JSDoc banners silently corrupted their own parse**

- **Found during:** Task 1 (GREEN — the detector returned `[]` on a fixture that visibly contained the target shape)
- **Issue:** Both banners contained the glob `**` + `/*.ts`. The `*` + `/` inside it **terminates the block comment**, so the remaining prose parsed as code. `ts.createSourceFile` recovers rather than throwing, so it returned a tree of nonsense `BinaryExpression`s with **zero** call expressions (5 parse diagnostics, measured). The red-fixture test caught this because it asserts a positive. **The green-fixture test did not** — it asserts an absence, and an absence is satisfied perfectly by a corrupted parse. "Green fixture is clean" would have read as proof while inspecting rubble: a self-referential oracle inside the self-referential-oracle detector.
- **Fix:** Reworded both banners to avoid the glob, and added `countExpectCallSites` as a vacuity fence — the green test now proves the parse found real `expect` sites before proving there are no findings among them.
- **Files modified:** both fixtures, `src/__tests__/self-referential-oracle.test.ts`
- **Verification:** gate green, 4/4; recorded in the calibration artifact § V.a
- **Committed in:** `807702ff`

**2. [Rule 3 - Blocking] The plan's Task-1 verify command could not observe its own `fails_when` signal**

- **Found during:** Task 1 (GREEN)
- **Issue:** The plan's `<fails_when>` requires the bare `npx vitest run <file>` output to contain the `SELF-REF-ORACLE report-only summary:` line. vitest 4.1.10's default reporter suppresses `console.log` from passing tests, so the bare command printed none of the 24 report lines.
- **Fix:** the gate writes its report with `process.stdout.write`, which is not intercepted. The plan's command now works verbatim.
- **Files modified:** `src/__tests__/self-referential-oracle.test.ts`
- **Verification:** `npx vitest run src/__tests__/self-referential-oracle.test.ts | grep -c SELF-REF-ORACLE` → 24
- **Committed in:** `807702ff`
