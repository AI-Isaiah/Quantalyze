The verdict string `RED (identity ok)` is stable across the mechanism change, but the *proposition
it asserts* is strictly stronger than it was at the baseline — plan 05's SUMMARY flagged exactly
this as plan 09's note to make:

| | pre-phase | now |
|---|---|---|
| What `identity ok` proved | the lane's `TEST FAILED (…)` text carried this run's secret nonce | the raise's psql prefix names this lane's gate scratch file at the failing statement's last line **and** the CONTEXT chain is exactly one `inline_code_block line N at RAISE` frame **and** N resolves through the plan-01 tokenizer spans to the arm's recorded raise line |
| Forgeable by the code under test? | yes — the nonce transmits to the server and `current_query()` reads it back (R4-C02) | no channel to read; refused by the chain-length leg (measured: plan 05 §5, FORGE 3) |

`biting: 30` is therefore the same integer over a **strictly smaller** admissible set. A floor
pinned at 30 is if anything harder to satisfy than it was, which is the safe direction for a ratchet.

### The 104 ÷ 103 split — same number, sharper reason

The identity that runs no backward scan is the literal ellipsis `…`, at **line 58**:

```
 -- executes on every push: it mutates COPIES, requires the FIRST `TEST FAILED (…)`
```

— the file's own header documenting the annotation syntax. Plan 01 recorded the split as *"the
104th identity carries no raise"*. Under the sound primitives the refusal reason is **more
specific**, and this is the one mechanism-level observation this re-derivation surfaces:

| | reason for the no-scan |
|---|---|
| plan 01's line-based framing | the identity is present as text, but no `RAISE EXCEPTION` precedes it |
| the tokenizer, measured here | `no statement contains "TEST FAILED (…)"` — the header is a `--` comment, and the tokenizer **never emits comments as statements**, so the text is not visible to the scan at all |

This is a strengthening, not a movement: both mechanisms perform 103 scans over the same 103
identities. The tokenizer reaches that answer one step earlier and for a structural reason rather
than a lexical one. Recorded because a *silently* identical number arrived at differently is
precisely the kind of thing this plan exists to catch and name.

### Refusal dispositions — all 4, named loudly

None is silently absorbed. Each is the same arm, at the same line, for the same statement as plan
01 recorded (2249 / 2254 / 2268 / 2273 for 2a / 2b / 2c / 2d).

| Arm | Line | Offending statement | Disposition |
|---|---:|---|---|
| `SERVICE-ROLE 2a` | 2249 | `EXECUTE 'REVOKE EXECUTE ON FUNCTION public.create_strategy_share(UUID) FROM service_role';` | **REFUSED — correct, and not a regression.** Not a neuter target: no annotation asks this arm to be neutered, so the refusal costs the corpus nothing. |
| `SERVICE-ROLE 2b` | 2254 | (same) | REFUSED — as above |
| `SERVICE-ROLE 2c` | 2268 | (same) | REFUSED — as above |
| `SERVICE-ROLE 2d` | 2273 | (same) | REFUSED — as above |

Full refusal text, verbatim (2a; the other three differ only in arm name and line):

```
the abort branch for "SERVICE-ROLE 2a" carries an unrecognised statement before its RAISE
(line 2249: EXECUTE 'REVOKE EXECUTE ON FUNCTION public.create_strategy_share(UUID) FROM
service_role';). Neutering only the RAISE would leave that statement executing for the rest of
the file — the measured RESET ROLE class, where a leaked superuser session made sixteen later
arms pass for a reason unrelated to their grants. Extend ABSORBABLE_CLEANUP deliberately, or
restructure the branch.
```

The second `REAL CORPUS` test pins the complement: **every** arm an annotation actually asks to
neuter is still classifiable. The four refusals and the 30 executing arms are disjoint sets, which
is why the corpus runs 30/30 with four standing refusals.

⚠️ **What this measurement does NOT bound** (carried forward verbatim from plan 01, because the
scope limit is unchanged): it bounds non-regression on the shapes **this one file** contains. The
compound line that broke the old line predicate lives in a *different* file. The class is closed by
construction; the number only proves the construction refuses nothing the corpus already relies on.
Phase 164.4 raises the coverage as it backfills the other 70 files.
