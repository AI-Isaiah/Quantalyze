<objective>
Primitive B: replace the in-query identity nonce with SOURCE-LOCATION ATTRIBUTION. The nonce is
forgeable with no file read and no superuser — the stamped text sits in the query text of the
statement the gate is running, and Postgres hands it to server-side code via current_query()
(R4-C02, MEASURED: an IF FALSE-guarded arm scored RED with biting: 1). The locked CONTEXT decision
(D-01: source-location attribution — drop the in-query nonce entirely) drops the nonce and
attributes a raise by WHERE it came from, which the executing SQL cannot choose.

RESEARCH hardened the decision with the one constraint CONTEXT does not state, and it is the single
most important correction in this phase: **the innermost CONTEXT frame alone is FORGEABLE** — a
trigger running EXECUTE over a DO string produces an inline_code_block frame with an
attacker-padded line under the gate file's own psql prefix. What the attacker cannot remove is the
rest of the chain. The attribution rule is therefore three-legged, all measured on PG 16.13:

1. the psql prefix names the gate scratch file the runner itself wrote for this lane;
2. the error's CONTEXT chain is EXACTLY ONE frame, of the shape inline_code_block line N at RAISE;
3. N resolves through the plan-01 tokenizer's statement spans to the arm's recorded raise line
   (raise_file_line = DO_statement_start + N − 1, verified twice in RESEARCH § Key Measurement).

Anything else — extra frames, a named function, at EXECUTE, a non-gate-file prefix, or TEST FAILED
text carried by a NOTICE — scores NO-IDENTITY or SYNTHESISED, loudly. All 104 corpus raises are
single-frame direct DO-body raises, so the passing control holds corpus-wide.

Purpose: SC-3 — "the arm identity cannot be produced by any SQL the gate executes — demonstrated by
re-running the R4-C02 current_query() trigger and observing NO-IDENTITY", with the passing control
in the same run (D-02: criterion 3 is met by demonstration, not by argument — and the genuine-arm
control in the same run is what keeps the demonstration falsifiable, because an attribution that
rejects everything also passes the forgery test). SC-7 — every new failure verdict prints what it saw.
Output: the rewritten verdict path, the verbose pg-lane, the GRAMMAR.md authoring rule, the
demonstration artifact, and a full corpus run green at the plan-01 baseline.

Hard prerequisite honored: plan 164.3.1-01 landed the tokenizer whose statement spans
({ startLine, endLine, text, executableText }, 1-based inclusive; a DO block is ONE statement
whose startLine is the DO line) this plan's line resolution consumes. Read plan 01's SUMMARY and
src/__tests__/sql-statement-tokenizer.test.ts (the span contract file) before touching anything.
