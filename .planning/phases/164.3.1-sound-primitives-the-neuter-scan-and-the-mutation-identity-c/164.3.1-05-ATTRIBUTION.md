## 2. The rule under demonstration

An arm identity is ATTRIBUTED only when **all three** hold:

| Leg | Assertion |
|---|---|
| (a) | the `psql:<file>:<line>:` prefix names **this lane's gate scratch file**, at the failing statement's LAST line |
| (b) | the error's CONTEXT chain is **EXACTLY ONE** frame, `PL/pgSQL function inline_code_block line N at RAISE`, bounded by verbose's `LOCATION:` sentinel |
| (c) | `stmtStartLine + N − 1` equals the arm's recorded raise line, resolved through the Primitive A tokenizer's statement spans |

Anything else — extra frames, a named function, `at EXECUTE`, a non-gate prefix,
a NOTICE-carried identity, an identity carried by a CONTEXT/DETAIL **field**
rather than the message — scores `SYNTHESISED` or `NO-IDENTITY`, loudly.

## 5. ⛔ A correction this demonstration forced — FORGE 2 was double-guarded

The first chain-length neuter run **did not flip FORGE 2**, and that is a finding
worth more than the proof it was meant to produce.

RESEARCH's forgery recipe builds the `EXECUTE`d DO string with the identity
spelled inside it. psql prints that string back as a `SQL statement "…"` frame
of the CONTEXT chain — so the identity is sighted **twice**: once in the ERROR
block's message, and once in a CONTEXT **field**. A field-carried identity is
unattributable on its own, independently of chain length. So FORGE 2 is refused
by **two** controls, and neutering one leaves the other biting.

A neuter proof run on FORGE 2 alone would have "passed" while proving nothing
about leg (b) — a vacuity of exactly the kind this phase exists to close.

**FORGE 3** removes the echo: the trigger stashes the identity in a GUC and the
`EXECUTE`d DO reads it back with `current_setting()`, so the forged statement
text names no identity anywhere. Its HEAD diagnostic carries a single sighting
(no `+N further unattributable sighting(s)` suffix), confirming the second
control is gone and leg (b) is alone.
