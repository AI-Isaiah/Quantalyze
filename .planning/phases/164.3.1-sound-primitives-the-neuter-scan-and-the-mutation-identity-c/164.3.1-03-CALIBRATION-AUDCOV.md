# [AUDCOV-01] calibration — the PRE-FIX "before" record

## 1. What this is

This is the recorded, byte-bound **"before" state** of the `[AUDCOV-01]` live regression, taken
at HEAD **before any fix**, for phase 164.3.1 success criterion **SC-5**.

`[AUDCOV-01]` is the one item in this phase carrying a live regression on `main`. The SP-I01 fix
widened `unmatchedBlockOpen` (`src/__tests__/audit-coverage.test.ts:159`) to track quote state —
but that state is **function-local and discarded at every newline**. `stripBlockComments`
(`:180-206`) calls it per line. So a `/*` sitting on a *continuation* line of a multi-line
template literal is scanned with fresh quote state, reads as unquoted, opens a phantom block, and
blanks the rest of the file. The pre-SP-I01 code found that site. Main's H-0001 audit-coverage
gate is therefore currently **blinder than it was**.

**This plan (164.3.1-03) fixed nothing.** It only measured. `unmatchedBlockOpen` was not widened,
no quote-carry was added, and `src/__tests__/audit-coverage.test.ts` was read but never written
(proved in §2 below). Plan **164.3.1-06** owns the fix.

Plan 164.3.1-06 consumes this document as the **"before" column** of its post-fix A/B/C table. The
reason it exists as a committed artifact rather than a sentence in a summary: a post-fix table
whose "before" column was reconstructed from memory is exactly the unchecked claim this phase
refuses. The numbers below came out of a machine, and the exact command that produced them and the
exact bytes it measured are both recorded here.

## 6. What plan 164.3.1-06 must show

The fix plan 164.3.1-06 owns: carry quote state across lines in
`unmatchedBlockOpen` / `stripBlockComments`, with `quoteAtEnd` forced `null` for `'` and `"`
(only a backtick template can legally span lines in TS, so an unterminated `'` or `"` is a
tokenizer artifact, not an open string).

Re-running the **same committed instrument, unedited**, the post-fix summary line must read:

```
AUDCOV-CAL A=[5] B=[5] C=[3]
```

| Case | Before (this artifact) | Required after | Why |
|------|------------------------|----------------|-----|
| A | `[]` | `[5]` | The fix's whole purpose: the mutation below the multi-line template becomes visible again. |
| B | `[5]` | `[5]` — **unchanged** | The control. If B moves, the fix widened detection rather than corrected it. |
| C | `[3]` | `[3]` — **unchanged** | The shipped arm must not regress. |

Movement on **exactly one row**. A fix that also moves B or C is not the fix.

The instrument is **verdict-free by design** — it asserts nothing, bakes in no expected site
values, and exits 0 on any successful measurement. Expectations live in the verify gates of plans
164.3.1-03 and 164.3.1-06, never in the instrument. That is what lets plan 06 re-run
`164.3.1-03-audcov-extract.mjs` **without editing it**: a before/after comparison across two
different instruments measures the instruments, not the fix.
