## THE OPEN DECISION: the 19 accumulator findings

The 164.3.1-02 calibration measured **23 findings / 14 files / 128 scanned** and deliberately declined to narrow the rule, handing plan 08 two options (§ III.a) and ranking them: (a) teach the rule mutation-awareness, re-measure, re-run the fire proof; (b) allowlist the 19 with their shared measurement.

**Decision: option (a).** Reasoning, recorded because "tune the detector until the number is comfortable" is the move this phase distrusts:

1. **The change is justified independently of the count.** A binding mutated between its declaration and the assertion reading it is not a constant — the premise the finding rests on is simply false at those sites. The calibration itself had already MEASURED those 19 assertions as able to fail. I would have made this change had the count been 4.
2. **Allowlisting them would record a detector bug as a permanent exception.** Nineteen entries whose justification reads "the detector is wrong here" is not what D-05's "measured exception" means. That is how a gate becomes ceremony.
3. **The accumulator idiom is the repo's dominant *honest* gate-test shape** — 12 of the 14 flagged files. A blocking gate that reds on it would be waived by reflex, and a control routinely waived is a control that cannot fail.
4. **It loses no enforcement.** Both options leave those 19 sites unflagged. Narrowing only generalises to sites not yet written, and keeps the allowlist small enough to be read.
5. **Practical, and load-bearing for this wave:** 3 of the 19 sit in files owned by parallel siblings (`audit-coverage.test.ts` → plan 06, `drift-check-scripts.test.ts` → plan 07, `mutation-annotation-parser.test.ts`). Allowlist entries pointing into files being rewritten in adjacent worktrees would have reddened at merge for reasons unrelated to the gate's subject.

## TASK 3 — [MUT-W02], measured

### The defect, observed as the TDD red step (verbatim)

```
 FAIL  … > TDD-RED-STEP: the old single-spelling regex sees the red fixture's tolerance arm
AssertionError: expected '# MW02 RED FIXTURE — a per-job tolera…' to match /\[ "\$name" = "sql-mutation" \]/

- Expected:
/\[ "\$name" = "sql-mutation" \]/
```

The red fixture carries a **working** per-job skip tolerance for `sql-mutation` written `[[ $name == 'sql-mutation' ]]`. The old pin's regex matches none of it, so its `not.toMatch(...)` assertion — *"this hermetic job has NOT grown a tolerance arm"* — passed on a workflow that had grown one. That assertion is now inverted and kept permanently as a contrast pin.

### The parser's measured floor

Measured 2026-09-01 at `420b8fcb`; the measurement command is the gate's own run, which prints the parse on every execution (D-12 diagnostic-first, via `process.stdout.write` because vitest 4's default reporter swallows `console.log` from passing tests):

```
$ npx vitest run src/__tests__/lint-sql-gates.test.ts
MW02 result-loop parse: 11 condition(s), 3 job arm(s) [e2e-seeded, sql-tests, plan-anchor-verify], tolerance-bearing: e2e-seeded(is_fork_pr), sql-tests(is_fork_pr+is_dispatch), plan-anchor-verify(is_pr)
```

**11 conditions** = 3 `$name = …` arms + 1 strict default at chain level, + 2 inner conditions each for `e2e-seeded` and `plan-anchor-verify`, + 3 for `sql-tests` (its failing branch carries a nested message selector).

`RESULT_LOOP_CONDITION_FLOOR = 8` — **not** 11. A floor pinned at the measurement reds on every legitimate arm removal and gets raised by reflex, which is how a floor stops being a measurement (D-10: wide separation, never taste). Total parse collapse is caught separately and unconditionally by the `measureFail` sentinel.

### The sharpest design call

Tolerance arms are identified by **if-chain indent**, not by the presence of a guard variable. `sql-tests`' failing branch contains a nested `if [ "$result" = "skipped" ]` two spaces deeper that only chooses which error text to print. Classifying that as a tolerance would report the aggregator **laxer than it is** — the mirror of the defect being closed here, and the non-vacuity floor would not have caught it. Indent also catches an *unguarded* blanket tolerance, which a guard-variable rule would have missed.
