1. **Derived-counter refactor (`SYNC_STATUS_SUMMARY_KEYS` / `status_counts`).** Diffed the
   registry's summary-key values against the pre-fix hand-written `sum(...)` block
   (`git show ed1b7d92:...cron.py`): `ok→synced, partial→partial, error→failed,
   timeout→timed_out, key_revoked→revoked, transient_failure→transient,
   deferred→deferred` — byte-identical names, plus the new `held→held` bucket, purely

   comprehension) — no leftover hand-written duplicate counting a status twice or
   silently. The response dict spreads `**status_counts` ahead of `total_keys` /
   `total_trades` / etc. with no key-name collision. Confirmed no frontend/TS consumer
   parses this endpoint's body with a schema that could reject an added field — the only
   `synced`-adjacent TS hits are the unrelated `api_keys.sync_status` column, not this
   response.
2. **`TestSyncStatusSummaryBucketCompleteness` bites in both directions — verified by
   construction, not by reading the assertion text.** Ran a standalone probe against the
   live module: adding a fictitious `SyncStatus` member with no registry entry flips the
   set-equality assertion (arm 1); adding a stale registry key with no declared status
   also flips it; and simulating a response dict that dropped the `held` bucket flips the
   membership assertion (arm 2). All three probes correctly went red. This is a real gate,
   not a tautology — it would catch a future hand-written `return {...}` that forgets a
   status a reviewer wasn't watching for.
3. **`held` ordering vs. `partial`/`error`.** Traced the classifier
   (`partial` if `strategy_errors and any_stored` → `error` if `strategy_errors` →
   `held` if `not should_advance_cursor` → else `ok`) against every reachable
   `(strategy_errors, any_stored, should_advance_cursor)` combination. An all-RPCs-failed
   tick always reports `error` (caught before the `held` branch), a genuinely idle tick
   (`not trades`) always reports `ok` (`should_advance_cursor` short-circuits True), and
   `ok` is unreachable unless the cursor actually advanced. No tick that should be
   `error`/`partial` is swallowed by `held`.
4. **`_NON_OK_STATUSES` hoist.** Single module-scope definition
   (`grep -n "_NON_OK_STATUSES"` → declared once at module scope, used at exactly the
   two pre-existing call sites in the `RESULTS_CAP` triage). It is a plain `set[str]`
   literal never mutated anywhere in the file (`grep "_NON_OK_STATUSES\."` → no hits) —
   no shared-mutable-state hazard, no import-time side effect, same membership as the old
   function-local set plus the new `held` entry the fix commit describes adding.
5. **Weakened-assertion audit, re-derived independently.** `git diff ed1b7d92..fbc558f9`
   filtered to removed `assert` lines: exactly 4 — two `status == "ok"` → `"held"`
