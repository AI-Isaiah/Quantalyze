<objective>
DBOOK-01: every day of the founder's Deribit book cumulative return is explained by booked P&L and flows, or withheld by name. No plausibility bound is applied; the close is an attribution reading, not a tolerance.

Purpose: the book compounds to about x3270 over its history (x298 without its 6 days above 30%, CONTEXT Q4 "Measured 2026-11-24"). Nobody can say which days are booked P&L on a real base and which are not. This plan builds the independent per-day attribution oracle end to end (tracer), then the withheld classes, the key-set check and the verdict order. Plan 233-05 (wave 2) adds the emptied, omitted, annotation, carry and rotation classes, the guards and `--print-sql`, and holds the orchestrator's PROD reading, which closes `[185-BOOK-CUMULATIVE-UNEXPLAINED]` only on a CLEAN reading or the founder's answer to a STOP.

Decision traceability, by CONTEXT label (CONTEXT has no D-NN ids):
- "DBOOK-01: the attribution oracle" (founder ruling Q4, option (a)): independent, imports no production helper, recomputes each stored book return from the stored per-key booked P&L, flows and levels in `key_inputs`; a day it cannot reproduce or a day with no stored base level is withheld under a name from a closed set (the book's flags `missing_return_inside_coverage`, `skipped_nonpositive_denominator`, `emptied_stretch` are candidates); capital-outside-base days are named and not nulled (plan 233-05); no plausibility bound.
- "Decided autonomously [DBOOK-01]": the oracle lives in an analytics-service script with its own arithmetic, run against a PROD reading for the SUMMARY and against fixtures in pytest.
- "Deferred Ideas": nulling capital-outside-base days (options (b) and (c)) is NOT built in any 233 plan.
- CONTEXT Phase Boundary and Q2: no change to the derive writer (S1) or the compose (S2); the oracle reads, it writes nothing.
- "PROOF-01", including the milestone rule "money-math oracles import no production helper".

The closed sets, finalised here and fixed as public constants in Task 1 (RESEARCH left the final set to the planner; rated reversible: the names live in one script and the reading):
- WITHHELD_REASONS (a published day the oracle does not reproduce), in priority order: `key_set_not_reproducible`, `no_stored_base_level`, `key_basis_not_reproducible`, `emptied_stretch`, `attribution_mismatch`. The `emptied_stretch` rule lands in plan 233-05 at its priority position.
- OMITTED_REASONS (a day in the book's span the compose did not publish): `no_stored_base_level`, `skipped_nonpositive_denominator`, `missing_return_inside_coverage`, `nonfinite_return`, `outside_published_window`, `omission_unexplained`.
- ANNOTATIONS (named, never nulled, never change a class): `capital_outside_base_options_cash`, `capital_outside_base_flow_day` (RESEARCH A5b: a non-zero composed flow on the day for a participating key), `key_sat_out` (a participating key sat the day out because its writer dropped it, the compose's `missing_return_inside_coverage` per key-day).
`window_truncated`, `out_of_window_flow` and the other book-level degrade reasons are printed beside the reading, never used as day classes.

Orchestrator decisions recorded here (O1/O4; the reading itself is plan 233-05's): "Withheld" in 233 means excluded from the oracle's explained cumulative and named in the reading; published history is unchanged. If the reading finds any PUBLISHED day the oracle cannot reproduce, or the counted key set cannot be reproduced, STOP: withholding a published day is a seam S2 change outside 233, so it becomes a founder question. The verdict also STOPs on `omission_unexplained` (a day the oracle would publish and the compose did not): an oracle whose model disagrees with the compose about which days exist cannot claim the published days are explained by it. This is stricter than the orchestrator's two conditions, in the fail-loud direction.
