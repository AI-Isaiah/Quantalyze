# Phase 167.1.1.2 Plan 02: derivative writers store NULL for unreported P&L Summary

`reported_pnl()` decides "did the venue report a P&L" once, and the Bybit V5, Deribit (coin-settled and linear), CCXT-unified and allocator row-builder sites use it, so a venue that says nothing is stored as NULL instead of a fabricated 0.0.

Note on `commits: 2`: this is the measured count of the two code commits between `plan_head_before` and `plan_head_after`; the SUMMARY commit follows as a third.

## What changed

- `reported_pnl(raw: Any) -> float | None` (positions.py): None for None and for blank strings; otherwise `float(raw)` (a reported 0 / "0" is 0.0; "abc" still raises ValueError).
- Sites: `_parse_bybit_v5_positions`, both branches of `_normalize_deribit_position` (coin-settled multiplies by `rate` only when reported), `_normalize_ccxt_position`, and `_fetch_derivative_rows` in allocator_positions.py (None passes through, else `float(...)`). Neighbouring `value_usd` / `mark_price` / `entry_price` coercions untouched (out of scope per D-05).
- `_bybit_ccxt_has_critical_fields`: logic byte-identical to base apart from a comment (verified: comment-stripped body `cmp` exit 0 against the phase base). ccxt's Bybit parser nulls an exact-zero P&L (omit_zero), so any CCXT None still routes to the raw V5 string, where "0" now yields 0.0.
- Side benefit: a blank V5 `unrealisedPnl` used to raise ValueError and abort the whole batch; it is now None.
