## Summary

The money-math holds against CONTEXT D-01..D-07 on every arm I traced:

- **D-04:** the commit route sums the shared `holdingEquityContribution` (`src/lib/holding-equity.ts`)
  and no longer keeps a private copy. `serverAumUsd` is the equity AUM that both sizes the row and
  feeds the manual-conflict comparison, so there is one basis. The notional sum is gone, and tests
  go RED on it (`route.test.ts` G3 pair 20,000 vs 200,000; `route.per-key-aum.test.ts` 6620 vs 9500,
  plus a notional-invariance case).
- **D-01:** `countedRowCount > 0 && serverAumUsd <= 0` records `server_aum_not_positive` with a null
  size. It sits after `lookup_failed` and before `client_manual_aum`, so a non-empty book never sizes
  from the client figure. `holdingsEmptyOk` moved to `countedRowCount === 0`, so a book whose only
  row is left out is not "empty".
- **D-02 / D-03:** `voluntary_remove` checks `leftOutRefs` first (`server_holding_pnl_missing`,
  null). It does this even when another key reported the same ref. Otherwise it records the ref's
  SIGNED equity (spot `value_usd`, derivative P&L). `aum_left_out_count` / `aum_left_out_refs` sit
  outside the `inputDiff &&` spread, and both are null on a failed lookup.
- **D-05:** all five coercion sites now write None for absent/null/blank. A reported `0` stays
  `0.0`. Readers of the normalised `unrealized_pnl` / `position_snapshots.unrealized_pnl`
  (`analytics_runner`, `position_reconstruction`) select only `size_usd` / `mark_price` /
  `side`, so the shared normaliser change moves nothing else. `position_snapshots.unrealized_pnl` is
  nullable DECIMAL. No SQL function reads `allocator_holdings.unrealized_pnl_usd`.
- **D-06:** `holdingEquityContribution` returns `number | null`. Every caller handles it: the weight
  callers in `queries.ts`, `ScenarioComposer`, `ScenarioComparePanel` and `book-risk-input` use
  `?? 0`, and the summing callers (`summarizeLiveHoldings`, the route, `OpenPositionsTable`) skip
  and count. `tsc --noEmit` is clean. No displayed number moves, because a null P&L added 0 before.
  The composer and the Open Positions footer render the UI-SPEC copy verbatim in States A/B/C,
  state 7 and count 0, and the builder is never called to produce a test expectation.
- **D-07:** `__pnl_missing__` is added to `_BREAKDOWN_PROTECTED_KEYS`, so it never reaches the
  numeric top-N `float()` sort and survives truncation. It is stamped after the empty-book gate.
  No TS or SQL reader iterates breakdown values. `compute_bridge_outcome_deltas` and the
  `holding-compare` path index by symbol, and the e2 script's value sum skips non-numerics.

## Warnings

### WR-01 (MEDIUM): the commit route's holdings projection still says `unrealized_pnl_usd` is "for the comparison figure only", and no test pins the column, so dropping it would silently re-size every derivatives-book commit

**File:** `src/app/api/allocator/scenario/commit/route.ts:840-853` (comment at `:846-848`, projection
at `:852`); test harness `src/app/api/allocator/scenario/commit/route.per-key-aum.test.ts:75`
(and the same pattern in `route.test.ts`)

**Issue:** Since D-04, `unrealized_pnl_usd` is the ONLY input that sizes a derivative into the audit
AUM, and it decides the D-02 remove size and the D-03 left-out set. The comment directly above the
projection still says the opposite:

```ts
// G3 — `unrealized_pnl_usd` is selected for the EQUITY-basis comparison
// figure only; the sizing columns are unchanged. `updated_at` feeds
// `oneKeyPerAccountDay`.
```

The same block's I3 note still talks about `serverAumUsd` being "bloated", which was notional-sum
reasoning. A maintainer who trusts this comment and trims the projection would cause this:
PostgREST omits the field, `holdingEquityContribution` reads `undefined` as null through the loose
`== null` check, and every derivative row becomes "left out". The AUM collapses to spot only. Every
`voluntary_modify` / `voluntary_add` / `bridge_recommended` row on a derivatives book is then sized
on the wrong (spot-only) denominator. A Deribit-only book like the founder's flips to
`server_aum_not_positive`, and every derivative remove becomes `server_holding_pnl_missing`. Nothing
in CI would catch it, because the route test harnesses serve fixtures through a mock whose
`select: () => chain` ignores the column list. The fixtures carry `unrealized_pnl_usd` whatever the
route selects. The rows would name the left-outs, but the recorded `size_at_decision_usd` would be
wrong. This phase exists to prevent that class of error. P-01's own instruction was to correct
route comments, not repeat them, and this one was missed.

**Fix:** correct the comment, and pin the projection with a test that reads the column list the
route passes:

```ts
// 167.1.1.2 D-04: `unrealized_pnl_usd` SIZES the audit row — it is a
// derivative's whole contribution to the equity AUM (`holdingEquityContribution`),
// the D-02 remove size and the D-03 left-out test. Dropping it from this
// projection reads every derivative as "P&L not reported". `updated_at`
// feeds `oneKeyPerAccountDay`.
```

```ts
// route.per-key-aum.test.ts — capture the select() argument in the harness
// (select: (cols: string) => { selects.push([table, cols]); return chain; })
it("the holdings read projects unrealized_pnl_usd (D-04: it sizes the row)", async () => {
  bookM(); okRpc("voluntary_add");
  await POST(mkReq({ diffs: [VALID_VA] }));
  const cols = selects.find(([t]) => t === "allocator_holdings")?.[1] ?? "";
  expect(cols.split(",").map((c) => c.trim())).toContain("unrealized_pnl_usd");
});
```

Neuter check: remove `unrealized_pnl_usd` from the projection string, see the new test go RED, then
restore it from a byte backup.
