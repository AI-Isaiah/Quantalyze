# Phase 167.1.1.2: AUMBASIS - Context

**Gathered:** 2026-10-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Every place that sizes an allocator's book from derivative holdings counts a derivative at its
unrealized P&L, never its notional. A venue that reports no unrealized P&L is stored and shown as
missing, never as 0. This is the founder's rule (167.1.1.1 D-15, verbatim): "Derivatives value are
not counted towards AUM only unrealized profits or losses are". Booked by 167.1.1.1 D-17.

The phase covers three things:
- the scenario commit route's audit sizing (`src/app/api/allocator/scenario/commit/route.ts`);
- the derivative writer paths (`analytics-service/services/positions.py` normalisers and
  `analytics-service/services/allocator_positions.py` `_fetch_derivative_rows`);
- every reader of `unrealized_pnl_usd` named in SC-3: the dashboard, the composer, the commit
  route, the equity curve and the 167.1.1.1 matcher.

The phase also closes TODOS `size_at_decision_usd is recorded on a NOTIONAL basis while the
composer sizes on an EQUITY basis` (TODOS.md, "Founder calls" list, the starred first entry).

</domain>

<decisions>
## Implementation Decisions

### Premise corrections (measured at HEAD dc271389a, 2026-10-20; founder instruction to record them)
- **P-01:** Nothing in the repo reads `size_at_decision_usd` after the commit. The route comment
  says a downstream daily-delta cron divides realized P&L by it. A repo-wide `git grep` finds the
  field only in `route.ts`, `ScenarioCommitDrawer.tsx`, `ScenarioComposer.tsx`, a comment in
  `src/lib/latest-holdings-per-key.ts`, and prose in CHANGELOG/TODOS. No migration and no
  `analytics-service` file reads it. Today the figure lives only in `audit_log.metadata`. The
  route comments that claim a downstream divisor must be corrected, not repeated.
- **P-02:** No past commit row carries a size. PROD holds 4 `match.decision_record` audit rows
  with `source = scenario_commit` in total. All 4 predate `_size_source`, and none has a numeric
  `size_at_decision_usd`.

### Commit sizing (SC-1)
- **D-01 (Q1, founder: "Null size, named (Recommended)"):** when the server's equity-basis AUM is
  at or below zero, the audit row records a null `size_at_decision_usd` under a new
  `_size_source` sentinel `server_aum_not_positive`. This matches 167.1.1.1 D-21. It never falls
  through to `client_manual_aum` or to `no_holdings_snapshot`.
- **D-02 (Q2, founder: "Signed unrealized P&L (Recommended)"):** a `voluntary_remove` of a
  derivative is sized at the holding's signed unrealized P&L, using the same
  `holdingEquityContribution` definition as the AUM. A losing position records a negative size.
  Spot `voluntary_remove` is unchanged (`value_usd`).
- **D-03 (Q3, founder: "Leave it out by name (Recommended)"):** a derivative whose
  `unrealized_pnl_usd` IS NULL is excluded from the commit AUM. Each audit row carries the
  left-out holding refs and their count. The sentinel stays `server_aum`, as in 167.1.1.1 D-18.
  A `voluntary_remove` of such a derivative records a null size by name; the planner picks a
  sentinel that says so, and it is never 0 and never notional.
- **D-04 (SC-1):** the commit AUM is the equity basis: spot `value_usd` plus each derivative's
  signed unrealized P&L. It uses the same `holdingEquityContribution` definition as the
  dashboard. The route reuses that definition; it does not keep its own copy. `serverAumUsd` no
  longer sums notional. A test goes RED on the notional sum.

### Writers (SC-2)
- **D-05 (Q4, founder: "All five sites (Recommended)"):** all five coercion sites write None
  when the venue reports no unrealized P&L:
  - Bybit V5 `services/positions.py` (`get("unrealisedPnl", 0)`)
  - Deribit `services/positions.py` (both `floating_profit_loss or 0` branches)
  - CCXT unified `services/positions.py` (`unrealizedPnl or 0`)
  - `services/allocator_positions.py` `_fetch_derivative_rows` (`or 0`)

  "Reports no P&L" means the key is absent, null, or an empty string. A reported 0 stays 0.0.
  `position_snapshots.unrealized_pnl` (nullable DECIMAL) then also stores NULL; that is accepted.
  A test goes RED on the `or 0` coercion.

### Readers (SC-3)
- **D-06 (Q5, founder: "Leave it out, say so (Recommended)"):** `holdingEquityContribution`
  (`src/lib/queries.ts`) and its client copy `holdingEquityContributionLocal`
  (`live-holdings-summary.ts`) return null for a derivative whose P&L is NULL. Every caller skips
  that holding and counts it. Totals then show "N derivatives without reported P&L left out". The
  Holdings P&L cell keeps showing "—". The copy follows DESIGN.md.
  - This removes the single TS/Python divergence pinned in
    `tests/fixtures/holding_equity_contribution_cases.json` (`expected_ts` 0 vs `expected_py`
    null). The fixture and its "only divergence" test are updated to agree.
  - A non-finite reported value keeps today's behaviour (contributes 0) unless the planner finds
    it must change to satisfy SC-3; the founder ruling covers NULL.
- **D-07 (Q6, founder: "Record it on the snapshot (Recommended)"):** the equity refresh
  (`refresh_allocator_equity_daily` in `equity_reconstruction.py`) keeps leaving a NULL-P&L
  derivative out. It also records the left-out symbols and their count on the snapshot's existing
  `breakdown` JSONB. No migration. The existing `allocator.equity.perp_upnl_missing` audit event
  stays. The record must survive `_cap_breakdown` truncation.
- **D-08:** the 167.1.1.1 matcher already withholds a NULL P&L as `pnl_missing` (its D-18). It is
  only re-verified here, not changed, unless the D-06 fixture change requires a test update.

### Past data (SC-4)
- **D-09 (Q7, founder: "Rewrite nothing (Recommended)"):** nothing is rewritten. No past commit
  row carries a size (P-02). The 15 historic derivative rows whose P&L is exactly 0 cannot be told
  apart from real zeros, so they stay as written.
- **D-10:** SC-4's BEFORE reading was taken 2026-10-20 (marker = PRODUCTION, read-only):
  - current derivative rows: 288 (bybit 251, deribit 27, okx 10), 0 NULL, 0 exactly zero;
  - all-history derivative rows: 17,036, 0 NULL, 15 exactly zero;
  - `position_snapshots`: 2,199 rows, 0 NULL, 0 exactly zero;
  - 7 books hold derivatives, and every one has a positive equity AUM. Notional vs equity AUM
    per book (approximate; latest asof per key, no one-key-per-account dedupe):
    1.36M/0.84M, 1.20M/0.77M, 0.90M/0.57M, 0.69M/0.46M, 0.63M/0.13M (Deribit only),
    0.31M/0.16M, 0.18M/0.10M.

  The AFTER reading repeats the same query once the change is live.
