## Summary

The phase is a **consistency-and-honesty change on money math, with no migration and no new dependency**. One definition (a derivative contributes its signed unrealized P&L; a NULL P&L contributes nothing and is counted) must be read by: the commit route (today a private notional sum plus a private equity re-implementation), the dashboard server helper, the composer's client copy, the compare panel's *third* inline copy, the book-risk widget, and Python's matcher (already correct). Five writer sites stop manufacturing `0.0` for a missing P&L. The equity refresh keeps skipping NULL-P&L derivatives and additionally stamps the left-out symbols and count on the snapshot's `breakdown`.

Four findings the CONTEXT did not have and the planner must plan around:

1. **CCXT's Bybit parser turns an exact-zero P&L into `None`** (`omit_zero`), which is why `_bybit_ccxt_has_critical_fields` exists and why it MUST NOT be touched: a CCXT `None` on Bybit is ambiguous between "absent" and "exactly 0", and the raw V5 fallback is what rescues the real zero. After D-05 the V5 string is the only Bybit source that can say "reported 0.0" versus "no P&L".
2. **`_cap_breakdown` sorts every non-protected value with `float(kv[1] or 0)`**, so a dict/list-valued record key would raise `TypeError` the first time a >20-symbol breakdown is capped, unless the key is added to `_BREAKDOWN_PROTECTED_KEYS`. And the record must be added AFTER the `if not breakdown and not book_emptied:` gate, or it turns an empty book into a written snapshot.
3. **The route's "empty book" test is `holdingValueByRef.size === 0`.** Once left-out derivatives are removed from that map, a book whose only holding is a NULL-P&L derivative would read as `no_holdings_snapshot` (or fall to `client_manual_aum`), which D-01 forbids. The "rows were counted" fact needs its own variable.
4. **Importing `@/lib/queries` into the route is the wrong seam.** `queries.ts` is not `server-only` itself, but it pulls `@/lib/supabase/server` directly and, per the parity test's own comment, reaches `server-only` through an indirect import; the three route test files mock a different subset each, and the compare panel and composer are client components that cannot import it at all (that is why two hand-kept copies exist). Extract the definition into a pure, import-free module and re-export it from both existing homes.

**Primary recommendation:** create `src/lib/holding-equity.ts` (pure, no imports) exporting `holdingEquityContribution(h): number | null` and `holdingEquityIsReported(h)`; make `queries.ts`, `live-holdings-summary.ts`, the route, the compare panel and `book-risk-input.ts` all use it; keep the existing exported names as re-exports so the parity test and every importer keep working. Then thread `null` through the nine call sites (the type checker finds each one), add the two new route sentinels, change the five writer sites with one helper, and add one protected `breakdown` key.

### Pattern 1: one pure definition, `null` is the withheld answer
**What:** `holdingEquityContribution` returns `number | null`. `null` = "a derivative whose `unrealized_pnl_usd` is `null`/`undefined`" and nothing else. Spot non-finite and derivative non-finite still return `0` (D-06 bullet 2). Callers choose: sum skips it, per-key weight uses `?? 0`.
**When to use:** every reader of `unrealized_pnl_usd`.
**Type shape (structural, so the panel's optional field and the route's nullable `value_usd` both fit):**
```typescript
// Source: derived from the current body, queries.ts holdingEquityContribution
export type HoldingEquityInput = {
  holding_type: string;
  value_usd: number | null;
  unrealized_pnl_usd?: number | null;
};
export function holdingEquityContribution(h: HoldingEquityInput): number | null {
  if (h.holding_type === "derivative") {
    if (h.unrealized_pnl_usd == null) return null;          // D-06: withheld, never 0
    return Number.isFinite(h.unrealized_pnl_usd) ? h.unrealized_pnl_usd : 0; // unchanged
  }
  return Number.isFinite(h.value_usd) ? (h.value_usd as number) : 0;         // unchanged
}
```
The compare panel's inline copy treats an absent (`undefined`) P&L like `null` (`?? 0`), so `== null` (not `=== null`) is required to keep that behaviour while moving it onto the shared function.

### Anti-Patterns to Avoid
- **Keeping a private route copy of the derivative rule** (the current `:925-931` block). D-04 forbids it and the type checker cannot protect two copies.
- **Using `holdingValueByRef.size === 0` as "no holdings"** after left-outs leave the map (finding 3).
- **Treating the Bybit CCXT-unified `None` as "no P&L"** (finding 1). It can be a real zero.
- **Adding a numeric-looking `breakdown` key.** `__truncated__: true` already shows readers must not assume numeric values, but `STARTING_BALANCE` *is* numeric and the anchor-adjust code does float arithmetic on it; the new key must never be read as a number (nothing sums `breakdown.values()` in the refresh path, see § 4).
- **Emitting `0` in a count slot for "not measured".** Use `null` when the lookup failed; `[]`/`0` only when measured and none left out.

## Common Pitfalls

### Pitfall 1: empty-book detection after left-outs leave the map
**What goes wrong:** a book whose only holding has NULL P&L reads as `no_holdings_snapshot`/`client_manual_aum` (or `client_unverified`).
**Why:** `holdingsEmptyOk` is `holdingValueByRef.size === 0` (`route.ts:1072`).
**Avoid:** count rows separately (`countedRows.length`) and test D-01 case (c)/(d).

### Pitfall 2: `_cap_breakdown` sort crash on a structured key
**What goes wrong:** `TypeError` in the sort the first time a >20-symbol, over-cap breakdown carries the record.
**Avoid:** add the key to `_BREAKDOWN_PROTECTED_KEYS`; test with 150 large symbols (the E3 test's shape) plus the record.

### Pitfall 3: record placed before the empty-book gate
**Avoid:** assign after `if not breakdown and not book_emptied:` (`:4514`).

### Pitfall 4: "fixing" `_bybit_ccxt_has_critical_fields`
CCXT's Bybit parser nulls an exact zero (finding 1); the function is the guard that rescues it. Leave it, add a comment, and add a test that a CCXT `unrealizedPnl: None` still takes the V5 branch and that V5 `"0"` yields `0.0`.

### Pitfall 5: `==` vs `===` on the P&L null check
The compare panel's payload type makes `unrealized_pnl_usd` optional (`ScenarioComparePanel.tsx:65`); `undefined` must behave like `null`.

### Pitfall 6: excluded parts and `unavailable`
In `summarizeLiveHoldings` the `excluded*` branches add `equity` into `part.amount`; with `null` that would produce `NaN` (`NaN` + number). Use `equity ?? 0` there and keep the `unavailable` increment (UI-SPEC rule 5); only rows that would have entered `total` are counted in `pnlMissing`.

### Pitfall 7: oracle contamination in the conservation test
`live-holdings-summary.test.ts` uses the function under test as its oracle. After the change `0 + null` is `0` in JS but a type error in TS; rewrite it as an independent hand sum.

### Pitfall 8: sentinel text
A new `_size_source` value is a public forensic label. The enumeration comment (`route.ts:1176-1199`) is the only documentation (no ADR table lists it; a grep outside `src` and `.planning/phases` finds `server_aum_manual_conflict`/`client_manual_aum` only in ROADMAP and archived v1.17 planning files), so update that comment, not a doc.
