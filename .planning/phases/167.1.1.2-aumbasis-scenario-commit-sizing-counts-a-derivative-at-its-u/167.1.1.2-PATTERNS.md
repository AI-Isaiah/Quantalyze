**Analogs:** the function body being moved (`src/lib/queries.ts:3782-3792`), and `src/lib/keys.ts` for the

**Module header convention to copy** (`src/lib/keys.ts:1-11`):
```typescript

// ...
// Pure functions, no imports — safe in server, client, and test contexts.

```

**Body to move, and the one change D-06 makes** (current, `src/lib/queries.ts:3782-3792`):
```typescript
export function holdingEquityContribution(h: MyAllocationDashboardPayload["holdingsSummary"][number]): number {
  if (h.holding_type === "derivative") {
    const pnl = h.unrealized_pnl_usd ?? 0;
    return Number.isFinite(pnl) ? pnl : 0;

  return Number.isFinite(h.value_usd) ? h.value_usd : 0;
```

Target shape (RESEARCH Pattern 1): input type is structural (`holding_type: string; value_usd: number | null; unrealized_pnl_usd?: number | null`)
so the panel's optional field and the route's nullable `value_usd` both fit; return `number | null`; `== null` (loose, not `=== null`) on the
derivative P&L so an absent `undefined` behaves like `null` (the compare panel relies on this, RESEARCH Pitfall 5); non-finite derivative and
non-finite spot still return `0`.

**Predicate to relocate beside it** (current `live-holdings-summary.ts:130-135`, keep its semantics byte-for-byte):
```typescript

  if (h.holding_type === "derivative") {

  }
  return Number.isFinite(h.value_usd);
```

**Re-export, do not rename** (so every importer and the parity test keep working): `queries.ts` re-exports `holdingEquityContribution`
(the file already has a "re-exported here for back-compat" idiom at `queries.ts:~2109`); `live-holdings-summary.ts` exports
`holdingEquityContributionLocal` as an alias of the same function and re-exports `holdingEquityIsReported`.
