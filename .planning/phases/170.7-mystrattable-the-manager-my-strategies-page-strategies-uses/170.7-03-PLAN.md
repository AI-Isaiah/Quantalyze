**Date helper: one helper, and a deliberate name.** `src` already has a function named `formatIsoDate`,
module-private in `src/app/factsheet/[id]/v2/FactsheetView.tsx`, and it prints `Oct 9, 2026`, not
`YYYY-MM-DD`; `src/lib/dateday.ts` `isoDayFromDate` reads LOCAL calendar fields. Neither gives the
Created cell's contract (UTC day, `YYYY-MM-DD`, `—` on bad input). The UI-SPEC names the helper
`formatIsoDate`; this plan names it `formatIsoDay` in `src/lib/utils.ts` so the repo never holds two
functions with one name and two outputs (Rule 7: the conflict is surfaced, not blended). The
FactsheetView helper is not touched (out of scope).

**The hydration trap this plan exists to close (measured at planning).** `useDiscoveryPrefs(undefined,
slug)` runs `useCrossTabStorage` with `enabled: false`, whose `isHydrated` STARTS `true`. The table's
prefs-mirror `useEffect` (gated on `prefsHydrated`) therefore fires on the first mount of every
userId-less table and calls `setTableSortKey(prefs.sort.key)`, i.e. the DEFAULTS `sharpe`. Seeding
`useState` from `initialSort` alone would be overwritten one effect later.
</context>
