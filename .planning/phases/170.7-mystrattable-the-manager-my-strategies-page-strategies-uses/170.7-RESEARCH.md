## Summary

`/strategies` is a server component that renders one `Card` per strategy. It loads the owner's strategies with a thin embed (`strategy_analytics ( computation_status )`), then does eight kinds of reads and probes to build per-row footers (untrusted-key pills, share notes, review feedback). It loads **no metric columns**, so it cannot show Return, CAGR or Sharpe today. The shared `StrategyTable` already links every name to `/factsheet/<id>`, already renders "—" for absent or non-complete analytics, and already has an owner mode (`visibility="owner-all-statuses"`) used by the allocator-side `/my-strategies`. D-02 and D-03 are therefore **free once the page mounts the table**; the work is the mount, the Status and Actions columns, and keeping the page's per-row behaviours alive.

The decisive design facts: (1) the table's Actions column and owner mode exist but are allocator-shaped (Mark ownership, Rename, Simulate Impact), so the manager mount must be a **narrow, opt-in extension** that leaves Discovery, Browse and `/my-strategies` byte-identical; (2) the page's per-row footers and the private-link modal are server-built and client-stateful, so they should reach the table as **serializable `ReactNode` slots keyed by strategy id**, which Next documents as supported; the modal then stays inside `ShareableLink`, untouched, which is what keeps its focus return working; (3) four existing invariant tests pin the very things this phase changes and must be edited deliberately, not loosened; (4) **the 170.2 pinning contract changed after its UI-SPEC was written** (founder D-05/D-06 on 2026-10-09: pin on the table's own width at `@3xl`, names content-sized), so this phase must not hard-code the UI-SPEC's `md:` / `STRATEGY_COL_WIDTH` and must be planned against the merged 170.2 code.

**Primary recommendation:** Add one optional prop `managerRows?: Record<string, { actions: ReactNode; note?: ReactNode }>` to `StrategyTable`. When present it (a) adds a non-sortable Status column after Strategy, (b) fills the existing Actions cell with the slot instead of Simulate Impact, (c) renders the optional note as a full-width second row, (d) suppresses the in-name status badge it would otherwise duplicate. The server page builds the slots from the elements it already creates (`ShareableLink`, `StrategyActions`, an Edit link, the key and share-note blocks), widens its embed to the existing ranking column allowlist, shapes rows with the exported `shapeRowAnalytics`, and mounts `visibility="owner-all-statuses"` with `managerRows`. Write the D-05 tests against the **page**, because the component-level equivalents already pass today.

### Pattern 1: Server-built slots into a client table
**What:** The RSC page creates elements of client components (`ShareableLink`, `StrategyActions`) and passes them as props to the client `StrategyTable`, keyed by strategy id.
**When to use:** The per-row UI depends on server-only reads (probes, RPCs) and on client state (modal, clipboard).
**Evidence:** Next's guide states "You can pass Server Components as a prop to a Client Component" and "Props passed to Client Components need to be serializable by React." [CITED: `node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md` lines 298-304 and 350, read this session]. The slot values contain only strings and booleans (`strategyId`, `published`, `hasActiveShare`, `size`, `status`, `hasApiKey`, `hasData`), so they serialize.
**Example:**
```tsx
// Source: pattern from src/app/(dashboard)/strategies/page.tsx (existing element props) + the Next guide above
const managerRows: Record<string, ManagerRowSlots> = Object.fromEntries(
  strategies.map((s) => [
    s.id,
    {
      actions: (
        <>
          <Link href={`/strategies/${s.id}/edit`} className={EDIT_LINK_CLASS}>Edit</Link>
          <ShareableLink
            strategyId={s.id}
            published={isPublishedStatus(s.status)}
            hasActiveShare={liveShareIds.has(s.id)}
            size="sm"
          />
          <StrategyActions strategyId={s.id} status={s.status} hasApiKey={!!s.api_key_id} hasData={!!s.api_key_id} />
        </>
      ),
      note: footerFor(s), // the existing key-mark + share-note + review-feedback block, or undefined
    },
  ]),
);
```

### Pattern 2: Opt-in prop with a byte-identical default
**What:** New behaviour is gated on a prop whose absence reproduces today's output. The repo already does this three times (`visibility`, `placeholderKeys`, `onMarkOwnership`).
**When to use:** Always, for the shared table. Discovery, Browse and `/my-strategies` must not change.
**Pin:** `phase-149-my-strategies-parity.test.ts` pin 2 asserts the two public pages pass no `visibility=`, `placeholderKeys` or `onFinishSetup`. Add the same absence assertion for `managerRows`.

### Anti-Patterns to Avoid
- **Do not fork `StrategyTable`.** Pin 11 requires exactly one file exporting `StrategyTable`.
- **Do not move the modal out of `ShareableLink`.** Its native `<dialog>` and its `modalMounted` latch are why focus returns to the row button (Finding 3).
- **Do not use `getMyStrategies` for this page** (archived rows disappear, wizard drafts appear, wildcard embed).
- **Do not coerce null metrics to 0 anywhere.** `getSortValue` coerces nulls to 0 for sorting only; the STALE-01 partition is what keeps unranked rows out of the ordering.
- **Do not hard-code the 170.2 UI-SPEC's `md:` or `STRATEGY_COL_WIDTH`** (Finding 7).
- **Do not loosen the pinning or width tests to make them pass.** Update them with a dated comment.

### 2. What `StrategyTable` needs, and the minimal extension

What it already has [VERIFIED: StrategyTable.tsx, read in full]:
- A hard-coded `COLUMNS` array (`name`, `cumulative_return`, `cagr`, `sharpe`, `max_drawdown`, `volatility`, `six_month_return`, `aum`), then two sparkline `th`, a `@3xl:hidden` Details `th`, and a final `Actions` `th`. **There is no column-extension mechanism.**
- An existing final **Actions** column. Its cell renders `ownerRowActions` (Mark ownership, Rename; both callback props, absent on every RSC page) and `SimulateImpactButton` when `s.status === "published"`.
- A status badge **inside the name cell** for any non-published row: `{s.status !== "published" && (<Badge type="status" label={s.status} />)}`. A "Published" badge is deliberately absent (Phase 149 Delta 3, pinned by `StrategyTable.pending-chip.test.tsx` "renders NO marker on a published own row").
- `visibility` defaulting to `"published-only"`, with the owner arm `"owner-all-statuses"`. Owner mode also: forces table view (`effectiveViewMode`), hides the view toggle, shows `OwnershipTag` and the pending chips ("Syncing", "No data").
- The name link is already `href={`/factsheet/${s.id}`}` (StrategyTable.tsx:1095).

Verbatim values the extension must respect:

```
StrategyTable.tsx:380   visibility = "published-only",
StrategyTable.tsx:408   const effectiveViewMode = visibility === "owner-all-statuses" ? "table" : viewMode;
StrategyTable.tsx:737   const emptyRowColSpan = showStarColumn ? 14 : 13;
phase-149-my-strategies-parity.test.ts:391   const WIDENING_PROP = 'visibility="owner-all-statuses"';
```

**Extension contract (the minimum).** One optional prop, `managerRows?: Record<string, { actions: ReactNode; note?: ReactNode }>`, plus the requirement that it is passed together with `visibility="owner-all-statuses"`. When it is **absent** every output is byte-identical to today. When **present**:

1. **Status column.** One non-sortable, non-sticky `th`/`td` pair immediately after the Strategy column, containing `<Badge type="status" label={s.status} />`. Not `@max-3xl:hidden` (status is first-order information). Mirror the cell in the placeholder-row block so the td count equals the th count in every configuration (the file's own rule), and add one to `emptyRowColSpan`.
2. **Suppress the in-name status badge** when `managerRows` is present (otherwise "Private" renders twice in one row).
3. **Actions cell** renders `managerRows[s.id].actions` in a `flex items-center justify-end gap-3` wrapper and **does not** render `SimulateImpactButton` (a manager's own page has no allocator portfolio; with `portfolioId` null it would render a disabled button). Keep the `s.status === "published"` guard literal in front of `<SimulateImpactButton`; add `&& !managerRows` after it, because pin 7 requires the literal within 300 comment-stripped characters before the mount.
4. **Note row.** If `note` is present, render `<tr><td colSpan={…}>` after the data row, with the content in an inner block that is `sticky left-0` and as wide as the scroller. `ResponsiveTable` is already `className="@container"`, so `w-[100cqw]` resolves against the scroll region (Assumption A1). This requires the `paged.map` to return a `Fragment` keyed by `s.id` instead of a `<tr key>`.
5. **`OwnershipTag`** is suppressed in manager mode (recommended; a wizard-created manager strategy can carry a mark, and D-01 asks for exactly two added columns). Keep the literal `visibility === "owner-all-statuses" &&` guard in front of `<OwnershipTag` (pin P8 of `phase-150-capital-ownership-invariant.test.ts`).

The Discovery **filter bar** (search, All Filters, Hide examples, Sort) renders unconditionally inside `StrategyTable`. See Open Question 7 for the recommendation to keep it.

### 3. The private-link modal and its focus return

How it is wired [VERIFIED: ShareableLink.tsx and Modal.tsx, read in full]:
- `ShareableLink` is a `"use client"` component that owns **both** the row button and the `Modal`. State: `shareLive` (seeded once from `hasActiveShare`), `modalMounted`, `panelOpen`. `const managing = !published && shareLive;` decides the label: "Share Factsheet" (published), "Manage private link" (unpublished with a live link), "Get private link" (otherwise). A **published** row keeps "Share Factsheet"; D-01's wording covers the unpublished labels.
- The Modal latches: `modalMounted` is set on the first Manage click and then stays true (ShareableLink.tsx:156, `<Modal open={panelOpen}` at :301).
- `Modal` is a native `<dialog>`; its effect calls `dialog.showModal()` when `open` and `dialog.close()` when closed (Modal.tsx:15-19). Closing through `dialog.close()` makes the browser restore focus to the previously focused element, the row button. The component comment states this is why the Modal is not unmounted while open.
- The panel body is `{panelOpen && <OwnerUnpublishedPanel … />}` (ShareableLink.tsx:306); a successful revoke calls `onShareLiveChange(false)`, which flips `shareLive` and closes the panel.

What keeps focus return working in a table, and what could break it:
1. **Do not touch `ShareableLink` or `Modal`.** Mount the same element in the Actions cell via the slot. The button node must be the **same DOM node** when the dialog closes, so the cell must never remount it: rows stay keyed by `s.id`, the slot must not be conditionally re-created per render, and the Fragment key for note rows must be `s.id` too.
2. **No remount on table state changes** (sort, page, density, search). The table re-renders on these, and the slot element identity is stable because it comes from props. A mount-once probe test pins this (Validation Architecture, test T4).
3. **`router.refresh()`** (called by `StrategyActions.updateStatus`) re-renders the server page. Client components keep state when type, position and key are unchanged, so a stable key is again the whole requirement.
4. **Native `<dialog>` inside a `<td>` inside `overflow-x-auto` + `container-type: inline-size`.** A modal dialog is in the top layer, which escapes ancestor clipping. I did not run this in a browser here (Assumption A2); the Playwright focus-return test is the check.
5. **jsdom cannot assert focus return.** The 164.6.6.3.1 review (IN-05) records that "the jsdom polyfill does not model focus at all". The unit layer can only pin the mechanism (no remount, `showModal`/`close` called); the focus assertion itself must be Playwright.

Evidence of the PROD verification: CONTEXT states focus return "was verified on PROD on 2026-10-09 (UIPOLISH UAT #4)". [CITED: 170.7-CONTEXT.md]. Note: the in-repo `164.6.6.3.1-UAT.md` still reads `result: [pending]` for test 4 in this worktree, so do not treat that file as the record. Add a post-deploy UAT line re-checking Close, Esc and revoke on `/strategies`.

### 4. Does `/factsheet/<id>` render for the owner's Private and Pending strategies?

### 5. How metric cells render "—" for a strategy with no analytics

- The row's analytics come from `shapeRowAnalytics(a, strategyId)` (queries.ts:578): `a === null` returns `{ ...EMPTY_ANALYTICS, strategy_id: strategyId }`; a row that is not `isRankableAnalyticsRow` (not `complete` or `complete_with_warnings`) returns `EMPTY_ANALYTICS` with only the real `computation_status` kept. `EMPTY_ANALYTICS` holds `cumulative_return`, `cagr`, `sharpe`, `max_drawdown`, `volatility`, `six_month_return` as `null`.
- The cells call `formatPercent` / `formatNumber` / `formatCurrency`, each starting with `if (value == null || !Number.isFinite(value)) return "—";` (utils.ts:8, 28, 33).
- Tint: `signColor`, `magnitudeColor`, `drawdownColor` return `text-text-muted` for null (no semantic colour on "—", per DESIGN.md).
- The rank cell reads `{hasComputedAnalytics ? `#${rank}` : "—"}`; `Sparkline` returns `null` for fewer than 2 points; AUM is a fact on the strategies row and still prints when present; owner mode adds the "No data" or "Syncing" chip in the name cell.
- Unranked rows are partitioned **below** ranked rows regardless of sort direction (the STALE-01 comparator), so a brand-new strategy sits at the bottom. It still appears (D-03).
- Existing component-level proof: `StrategyTable.pending-chip.test.tsx` (missing-row case asserts every metric cell contains "—") and `StrategyTable.stale-analytics.test.tsx` ("shows the dead rows' metric cells as em-dashes, not blanks or zeros").

**Consequence for D-05:** these component behaviours already pass today. Only the page lacks them. The failing-first test must render the page.

## Common Pitfalls

### Pitfall 1: Silently dropping the page's shipped per-row behaviours
**What goes wrong:** D-01 names only Edit and the private-link control. Swapping Cards for a table drops the footer band (KCS-06 untrusted-key pills, KCS-12 share notes), the draft "Review feedback" line, `StrategyActions` (Submit for Review, Archive, Restore to Draft) and the created date. `StrategyActions` is the only place in `src` that renders "Submit for Review".
**How to avoid:** Carry all of them through `managerRows` (Open Questions 1-2). The 167.2 and 167.2.1 behaviours are pinned by the 69 `it` cases across the three page test files (55 in `page.key-pill.test.tsx`, 10 in `page.share-affordance.test.tsx`, 4 in `page.wizard-draft-banner.test.tsx`).
**Warning signs:** `strategy-row-footer`, `strategy-row-key-mark`, `strategy-row-share-note` testids absent from the rendered page.

### Pitfall 2: Component-level D-05 tests that pass on today's code
**What goes wrong:** the table already links to the factsheet and already prints "—". A test that mounts `StrategyTable` directly is green before any change.
**How to avoid:** the three D-05 tests render the page (Finding 6).

### Pitfall 3: Row objects missing `Strategy` fields
**What goes wrong:** the page's select lists eight columns; the table reads `s.subtypes.some`, `s.markets.some`, `s.supported_exchanges`, `s.aum`, `s.start_date`, `s.is_example`. With an advanced filter active, `s.subtypes.some` throws on `undefined`.
**How to avoid:** select `*` from the owner's own `strategies` rows (as `getMyStrategies` does, owner-scoped) plus the analytics embed, and make the test fixtures full rows.

### Pitfall 4: `->-1->>` alias defeats postgrest-js types
**What goes wrong:** the ranking column string contains `series_end:returns_series->-1->>date`, which postgrest-js's select parser cannot type (it resolves to a ParserError). The page's typed `.select(...)` then yields an error type.
**How to avoid:** cast the result as `queries.ts` does (`as unknown as { id: string; strategy_analytics: unknown }[]`). The alias is measured against the TEST project by its own docblock for the service role; confirm it on the authenticated owner path (Assumption A6).

### Pitfall 5: Archived and wizard-draft semantics change if the query is swapped
**What goes wrong:** `getMyStrategies` pins `.neq("status", "archived")` (pin 4) and does not filter wizard drafts. Reusing it hides archived rows (and their "Restore to Draft") and shows wizard drafts, which the page's `.or("source.neq.wizard,status.neq.draft")` and the Resume banner exist to keep out of the list.
**How to avoid:** keep the page's own query and its `.or(...)` filter (also pinned by `wizard-draft-query-single-source.test.ts` as an allow-listed read).

### Pitfall 6: Believing jsdom proves focus return
**What goes wrong:** a unit test that spies on `close()` passes while focus falls to `<body>`.
**How to avoid:** pin the mechanism in jsdom (mount-once probe), assert focus in Playwright, and add a post-deploy UAT line.

### Pitfall 7: Existing tests that pin the card layout
**What goes wrong:** `page.share-affordance.test.tsx` "N-STRAT row layout (170-05)" asserts `flex-col`, `md:flex-row` and the name-block tokens; `page.key-pill.test.tsx` helper `noteOf` finds the share note via `.closest('[data-testid="strategy-row"]')` (two sites); `e2e/layout-narrow.spec.ts` "/strategies - N-STRAT" cases measure the card name block against the control group. All are invalidated by design.
**How to avoid:** retire the layout assertions with a dated comment citing this phase; re-point `noteOf` and the one inline site at the note row (the data row's next sibling). The testids on the note's inner blocks are kept, so the key-pill assertions that query by those testids alone (12 `strategy-row-*` references in that file, only the two `closest` calls use the card testid) do not change.

### Pitfall 8: Page widening is a pinned decision
**What goes wrong:** `/strategies` stays at `max-w-7xl`, so a dense table is capped while DESIGN.md says dense tables are fluid; or, widening with a prefix regex also widens the wizard form and `[id]/edit`.
**How to avoid:** add an exact-match arm for `/strategies` (an anchored `^\/strategies$`), update the "keeps the legacy card list narrow" test with a dated comment, keep the wizard and edit-path cases narrow.

### Pitfall 9: Placeholder rows and the Status column
**What goes wrong:** `placeholderKeys` rows mirror the data row's td sequence. A Status td added to data rows only misaligns them if the two props are ever combined.
**How to avoid:** mirror the cell in the placeholder block (cheap) and leave `/my-strategies` untouched.

### Pitfall 10: A page-level test now renders the heavy client table
**What goes wrong:** existing page harnesses never needed `fetch` or `localStorage`; the table does (`/my-strategies/page.test.tsx` installs `installFetchMock()` and clears `localStorage`). The repo documents timeouts on heavy RTL renders under CI contention.
**How to avoid:** clone the `installFetchMock`/`restoreFetchMock` and `localStorage.clear()` setup from `my-strategies/page.test.tsx`; give heavy cases an explicit timeout rather than relying on 5 s.

### Pitfall 11: Target size on the Edit link
**What goes wrong:** a text link at `text-caption` is below the 44 px coarse-pointer floor `ShareableLink size="sm"` already meets (`pointer-coarse:min-h-[44px]`).
**How to avoid:** give the Edit link `inline-flex items-center pointer-coarse:min-h-[44px]`.

## Security Domain

`security_enforcement` is not set to false in `.planning/config.json`, so this section applies.

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes (existing) | `auth.getUser()` in layout and page; redirect to `/login` |
| V3 Session Management | yes (existing) | Supabase session cookies; no change |
| V4 Access Control | **yes** | `requireRolePage(..., "manager")` in the layout; `.eq("user_id", user.id)` from the session only; RLS `strategies_read` and `analytics_read` as the backstop; factsheet owner probe keyed on the session user |
| V5 Input Validation | low | Strategy ids come from the owner-filtered list; names render as React text (escaped); no new input |
| V6 Cryptography | no | Share-token derivation stays server-side; the page selects `revoked_at` only, never `nonce` or `generation` |

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| A second surface opting into `owner-all-statuses` without an owner-scoped server query | Information disclosure | Pin 10 edited to name exactly the two consumers; add a pin that the `/strategies` list query contains `.eq("user_id"`; public pages must not pass `managerRows` |
| Wildcard analytics embed leaks JSONB series | Information disclosure | Use the explicit ranking column allowlist, not `strategy_analytics (*)` |
| Private-link secrets reaching the client through slot props | Information disclosure | Slots carry only `strategyId`, booleans and strings; no token, nonce or generation |
| Existence oracle through the factsheet | Information disclosure | Unchanged: a non-owner and a missing id both get the same `notFound()` |
| Archived or unpublished rows shown to a non-owner | Elevation | Owner-scoped query plus RLS; `/factsheet/<id>` already gates the owner lane on the row status and session |
| Mutating actions rendered for the wrong status | Tampering | Reuse `StrategyActions` unchanged (it renders per status); `ShareableLink` gets `published` from `isPublishedStatus` |
