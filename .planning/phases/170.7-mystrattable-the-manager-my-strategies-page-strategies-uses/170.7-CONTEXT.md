<decisions>
## Implementation Decisions

- **D-01:** My Strategies renders the shared `StrategyTable` (`src/components/strategy/StrategyTable.tsx`) with the same metric columns as Discovery. It adds two columns:
  - a **Status** column: Private, Pending review or Published, using the existing badge styles;
  - a final **Actions** column holding **Edit** (to `/strategies/<id>/edit`) and **Manage private link** (or Get private link). It opens the existing private-link modal, whose behaviour and focus return are unchanged.

  Founder choice, 2026-10-09: "Actions column", recommended over a ⋯ row menu.
- **D-02:** A strategy's name opens its factsheet (`/factsheet/<id>`) for every status. That includes Private and Pending strategies, which only the owner can see.
- **D-03:** A strategy with no analytics yet still appears. Its metric cells read "—", per the never-invent-data rule. It is never hidden and never shows 0.
- **D-04:** The page gets the same layout guarantees as Discovery after Phase 170.2:
  - no horizontal page scroll at 360, 375 and 390 px;
  - the Strategy column unpinned below tablet width;
  - at tablet width and above, pinned cells the same width as the header.

  This phase **starts execution only after 170.2 merges**, because both change `StrategyTable`.
- **D-05:** Each criterion gets a test that fails on today's page:
  - the name links to the factsheet;
  - the Actions and Status columns are present;
  - the no-analytics row reads "—".

### Founder decisions after research (2026-10-09)
- **D-06:** the per-row footers move into a full-width note row directly under each strategy's table row: the KCS-06 untrusted-key pills, the KCS-12 share notes and the review feedback. Founder choice (Recommended) over a section under the table.
- **D-07 (corrects D-04's reference):** 170.2's pinning contract is founder D-05/D-06 in 170.2-CONTEXT: pin on the table container's `@3xl` width, names content-sized. It is NOT the superseded `md:`/`STRATEGY_COL_WIDTH` text. 170.7 follows what 170.2 actually merges, and asserts it by relation.
- Research resolutions adopted:
  - Add one optional `managerRows` prop to StrategyTable; absent means byte-identical output.
  - Keep `StrategyActions`.
  - Archived rows stay listed.
  - Status goes right after Strategy.
  - Keep the default sort and the filter bar.
  - Widen `/strategies` in `isWide`.
  - The listed invariant tests are edited with dated comments, never loosened.

### Founder decisions after the UI-SPEC check (2026-10-09)
- **D-08:** review feedback is **amber**, both in the new table note row and in the wizard-draft banner on the same page. Feedback is recoverable (revise and resubmit), so DESIGN.md's colour gate applies. Founder (Recommended).
- **D-09:** My Strategies gets a **Created** date column and defaults to **newest first**. Discovery keeps its Sharpe default. A new strategy is always at the top. Founder (Recommended). This needs an initial-sort prop plus a `created_at` sort key on StrategyTable. When `managerRows` is absent, Discovery stays byte-identical.
- **D-10 (founder override of the review rule, 2026-10-11):** the round-1 review raised only MEDIUM findings, which by the standing rule go straight to verification. Founder chose "Fix 4, then ship" (Recommended): one fixer round for WR-01 (rank gaps under the Created sort), WR-02 (the Sort-by select disagrees with `initialSort`), SFH-1 (the owner's own `is_example` rows hidden by the Discovery hide-examples preference) and WR-03 (the owner-scope pin passes with the list filter removed). SFH-2 and SFH-3 (e2e helper hardening) are booked, not fixed.
- **D-11:** under any sort, the rank column numbers only the rankable rows, contiguously in table order (#1, #2, #3); a row with no rankable analytics shows "—". Under metric sorts this is today's numbering, so Discovery is unchanged. Founder (Recommended) over a dash in every row under non-metric sorts.
- **D-12 (2026-10-11):** the review-feedback note aligns by its BOX edge with the strategy name; its text sits inside the block's own padding (8 px in), like every other pill. No `-ml-2`. Founder (Recommended) over aligning the first glyph. Plan 08's box-plus-8px assertion is the pinned behaviour; the UI-SPEC's "first text line" wording is superseded by this decision.

### Claude's Discretion

- Whether the Discovery filter bar appears here. Omit it if the owner has few strategies; follow DESIGN.md.
