## 0. Read this first: corrections to RESEARCH and traps found while mapping

1. **The 170.2 collision is smaller than RESEARCH Finding 7 says.** RESEARCH expected 170.2 to rewrite the Strategy `<td>` content (wrap, `NowrapWords breakOverlong`, `flex-wrap`). The **revised** UI-SPEC row D-3 says the opposite: "No change (D-06). The name keeps `NowrapWords` in its default per-word `whitespace-nowrap` mode"; row D-2 gives the Strategy column no width class. What 170.2 actually edits is the sticky offsets, one z-index, the hairline and one `whitespace-nowrap` (section "What 170.2 will change"). The Strategy `<td>`'s inner JSX, where 170.7 removes the in-name status badge, is therefore **not** a conflict region any more.
2. **Status header placement: RESEARCH contradicts itself.** Its resolution says "Status goes right after Strategy" and its `td` sketch is "immediately after the Strategy td", but its `th` sketch says "immediately after the `COLUMNS.map` output". The header cells are one `COLUMNS.map` (`StrategyTable.tsx:894-945`) that emits Strategy, Return %, CAGR, Sharpe, Max DD, Volatility, 6 Month, AUM in a row. A Status `th` placed after the map lands after AUM and misaligns every data row. The `th` must be emitted **inside** the map, after index 0 (a Fragment per iteration), or the map split. This is the single most likely column-misalignment bug of the phase.
3. **The note row needs a `Fragment` import.** `paged.map` returns a bare `<tr key={s.id}>` (`StrategyTable.tsx:1046-1050`). `import { useState, useMemo, useCallback, useEffect, useId, useRef } from "react"` (`:3`) has no `Fragment`. Add it (keyed `s.id`).
4. **`tests/a11y/chip-contrast.test.ts:36-60` pins StrategyTable's grey-chip pairs.** It lists `src/components/strategy/StrategyTable.tsx` in `CHIP_SOURCES` and asserts `textOnTrack(source)` has **exactly two** `text-text-<x> bg-track` pairs, both `secondary`. A note row or Status cell that writes a third `text-text-… bg-track` string turns it red. Use the existing `text-text-muted` ink without `bg-track` for the note.
5. **`ShareableLink` must mount exactly once per row.** The table has a second, CSS-hidden copy of per-row content: the `@3xl:hidden` "More" `<details>` cell (`StrategyTable.tsx:1272-1301`) holds relocated values, and `@max-3xl:hidden` hides columns with CSS, not by unmounting. Anything placed in both the Actions cell and a relocated cell mounts two `<dialog>`s, two copy buttons and two `shareLive` states. Put the `actions` slot in the **one** Actions `<td>` (`:1313-1322`) and nowhere else. Section "Mounting ShareableLink once".
6. **Existing page harnesses feed the page thin rows.** `MockStrategyRow` (`page.share-affordance.test.tsx:153-166`) has eight fields and the `strategies` double returns them for every read. The table reads `s.subtypes`, `s.markets`, `s.supported_exchanges`, `s.aum`, `s.start_date`, `s.is_example` (RESEARCH Pitfall 3). Every page test file that survives must enrich its row factory, and the `from("strategies")` double must also tolerate the new `select("*, strategy_analytics (...)")` call.
7. **`next/navigation` is not a problem for the table.** None of `StrategyFilters`, `CustomizeDrawer`, `StrategyGrid`, `SyncBadge`, `WatchlistTabs`, `EmptyWatchlist`, `StarToggle`, `OwnershipTag`, `discovery-prefs` imports it (grepped), so the harnesses' `next/navigation` mock with only `redirect` (`page.share-affordance.test.tsx:187-193`) stays sufficient. `StrategyActions` imports `useRouter`, but every harness mocks `StrategyActions`.
8. **Default sort is Sharpe descending, not newest first.** `useState<SortKey>("sharpe")` / `"desc"` (`StrategyTable.tsx:391-392`). CONTEXT "Claude's Discretion" allows newest first, but that needs a new sort key and an initial-sort prop on the file 170.2 is editing. RESEARCH A5 recommends keeping Sharpe desc; unranked rows sit below ranked rows regardless (`isRankedRow`, `:191-193`).

The type comment for `visibility` (`:258-276`) is the template for the `managerRows` doc: say what it adds, say that **absent means byte-identical**, name the test that pins it, and say why it is a data prop and not a function prop. ### Mounting ShareableLink once

**Current single mount (the thing to preserve):**

```tsx
// src/app/(dashboard)/strategies/page.tsx:851-858
<ShareableLink strategyId={s.id} published={isPublishedStatus(s.status)} hasActiveShare={liveShareIds.has(s.id)} size="sm" />
<Badge label={s.status} type="status" />
<StrategyActions strategyId={s.id} status={s.status} hasApiKey={!!s.api_key_id} hasData={!!s.api_key_id} />
```

**Why it must stay one mount and keep one DOM node.** `ShareableLink` seeds `shareLive` once from `hasActiveShare` (`ShareableLink.tsx:150-156`), latches `modalMounted` on the first Manage click (`:156`, `:300`), and every close path goes through `Modal`'s `open={false}` effect (`Modal.tsx:15-19`: `if (!open && dialog.open) dialog.close()`), after which the browser restores focus to the opener. The component's own comment (`:152-155`) says unmounting an open dialog "would skip that and drop focus to the body". Founder UAT #4 verified this on PROD (CONTEXT, Code Context); jsdom cannot assert it (the 164.6.6.3.1 review IN-05 records that the jsdom polyfill does not model focus, quoted in RESEARCH Finding 3).

**Pattern to copy:** the slot is built **once per row on the server**, keyed by `s.id`, and rendered **once** by the table:

```tsx
// page.tsx (new), composition of the existing elements; props are strings and booleans only (serializable)
const managerRows = Object.fromEntries(rows.map((s) => [s.id, {
  actions: (<>
    <Link href={`/strategies/${s.id}/edit`} className={EDIT_LINK_CLASS}>Edit</Link>
    <ShareableLink strategyId={s.id} published={isPublishedStatus(s.status)} hasActiveShare={liveShareIds.has(s.id)} size="sm" />
    <StrategyActions strategyId={s.id} status={s.status} hasApiKey={!!s.api_key_id} hasData={!!s.api_key_id} />
  </>),
  note: noteFor(s),
}]));
```

Class for the Edit link: `GHOST_ROW_ACTION` (`StrategyTable.tsx:111-112`, the inset focus ring that survives the scroller's `overflow-x-auto`) plus `inline-flex items-center pointer-coarse:min-h-[44px]` to match `ShareableLink size="sm"` (`ShareableLink.tsx:243`, pinned by `ShareableLink.test.tsx:322,340`). `GHOST_ROW_ACTION` is module-private in `StrategyTable.tsx`; the page cannot import it, so either export it or build the Edit link inside the table from `managerRows[s.id].editHref`. Decide in the plan (the second keeps the link style in one file).

**Mount-once census (what to assert):**
- Page level: the existing probe records one entry per `ShareableLink` render: `shareProps` (`page.share-affordance.test.tsx:48-85`), and the existing case "renders the affordance for EVERY status" asserts `expect(shareProps).toHaveLength(4)` (`:275`). Keep that assertion; it fails if the slot is rendered twice or if a re-render re-creates the element. React skips re-rendering a child whose element reference is unchanged, so slot elements built once on the server and passed through props stay at one render.
- Component level (new `StrategyTable.manager-rows.test.tsx`): a slot component that increments a counter in a mount effect; sort, page, density and search changes must leave the count at one per row. This is RESEARCH test T4.
- Real browser (new `e2e/strategies-table.spec.ts`): open Manage private link, close with the Close button, Escape, and after a revoke; assert `document.activeElement` is the row's button each time. Needs the seed env (`HAS_SEED_ENV` skip idiom at `e2e/layout-narrow.spec.ts:402-406`).
- Keys: rows keep `key={s.id}` (`:1047`); the Fragment key for the note pair is `s.id`; never key by index. A remount on `router.refresh()` (called by `StrategyActions.updateStatus`, `StrategyActions.tsx:31`) is avoided only by stable keys and element positions.

### `src/app/(dashboard)/strategies/page.tsx` (query, shaping, slots)
