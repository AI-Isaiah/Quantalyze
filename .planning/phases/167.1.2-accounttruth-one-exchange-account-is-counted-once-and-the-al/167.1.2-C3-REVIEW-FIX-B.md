### SFH-C3-01 (MEDIUM): The Scenario called a failed history read, and every reason that needs the user to act, "being rebuilt"

**Files modified:** `EquityHistoryRebuilding.tsx`, `ScenarioComposer.tsx`, `ScenarioComposer.test.tsx`
**Commit:** `ade513d64`
**Status:** fixed: requires human verification (new user-facing copy; see the note at the end of this entry)

**Applied fix.**
- **One classifier in one place.** `EquityHistoryRebuilding.tsx` now exports `equityHistoryRebuildClass(reason)` and the type
  `EquityHistoryRebuildClass`. Both read one table, `REBUILD_REASON_CLASS`, which assigns each reason one of three classes:
  - `needs_action`: `duplicate_account`, `key_not_syncing`, `shared_account_no_working_key`.
  - `read_failed`: `history_read_failed`.
  - `rebuilding`: `awaiting_derivation`, `account_identity_pending`, `derivation_rejected`, `shared_account_history_truncated`.

  The table is `satisfies Record<EquityHistoryRebuildReason, …>`, so a new reason has to be classed before it compiles.
- **The Overview uses the classifier too.** The Overview no longer has its own hand-written three-way reason ternary. It renders
  `NeedsActionLine` when `isNeedsActionReason(reason)`, and otherwise `REASON_LINE[reason]`. `REASON_LINE`'s key type is now
  `Exclude<Reason, NeedsActionReason>`, and that type is derived from the class table. So moving a reason between classes
  fails to compile until its line moves as well. I measured this: reclassing `derivation_rejected` as `needs_action` gives
  TS2353 (excess key in `REASON_LINE`). Removing its line as well gives TS2322 (the `never` default in `NeedsActionLine`).
  The Overview's rendered copy is unchanged: `AllocationDashboardV2.rebuilding.test.tsx` passes 47/47 without edits.
- **The Scenario picks its one sentence by class.** It never switches on the reason itself. The composer destructures
  `equityHistoryRebuildReason = null` and renders `OWN_BOOK_REBUILDING_LINE[equityHistoryRebuildClass(reason)]`:
  - `rebuilding` (unchanged): "Your book's own history is being rebuilt, so the comparison with your current book is not shown."
  - `read_failed`: "We could not load your book's history just now, so the comparison with your current book is not shown; reload the page to try again."
  - `needs_action`: "Your book's own history is on hold until you fix a key on the Exchanges page, so the comparison with your current book is not shown." Here "Exchanges page" is the same `ExchangesPageLink` (`/profile?tab=exchanges`) the Overview uses, now exported from the same file.

  Each line is one sentence, uses no em dash, promises no date or day count, and never says "appear once".
- **Unknown reasons fail closed.** A null reason, a missing reason, a reason this build does not know, and a prototype key
  (`"constructor"`, blocked by `Object.hasOwn`) all fall back to the generic rebuilding line.

**Tests added (ScenarioComposer.test.tsx, D-02 describe block).**
- `REASON_CLASSES`: one arm for each of the 8 reasons. Each arm renders the Scenario and the Overview's
  `EquityHistoryRebuilding` for the same producer-shaped payload. It then asserts three things:
  - the Scenario sentence is exactly the class's copy;
  - an Exchanges-page link is present on both surfaces if and only if the class is `needs_action`;
  - "reload the page" appears on both surfaces if and only if the class is `read_failed`.

  The class table in the test is written out literally and does not import the component's classifier. That way, a
  reason moved to the wrong class fails the test instead of moving both surfaces together. A compile-time check
  (`[UnlistedReason] extends [never]`) forces any newly added reason into this table. Removing a row gives TS2322 (measured).
- Four fail-closed arms: null, missing, unknown string, and `"constructor"`. All four expect the generic line.

**Neuter, RED, restore, cmp:**
| probe | result |
|---|---|
| New arms against the pre-fix code (the old Scenario sentence, no reason read) | **4 failed**: `duplicate_account`, `key_not_syncing`, `shared_account_no_working_key`, `history_read_failed`. 8 passed. |
| Classifier neuter: `history_read_failed: "rebuilding"` | **1 failed** (`history_read_failed`), restored, `cmp` OK |
| Guard neuter: drop `Object.hasOwn` from `equityHistoryRebuildClass` | **2 failed** (unknown string, `"constructor"`), restored, `cmp` OK |
| After fix | 12/12 passed |

### IN-03 (INFO): The Scenario D-15 arms carried a curve under "rebuilding", which the producer never sends

**Files modified:** `ScenarioComposer.test.tsx`
**Commit:** `5c7c648e3`
**Applied fix.** I read the producer read-only (`derivePhase07Fields` in `src/lib/queries.ts`). For a non-ready book it sends
`equityDailyPoints: []`, `equityDailyReturns: []`, `equitySnapshots: []`, and always a named reason (`equityHistoryReadiness`
never returns "rebuilding" with a null reason). It stamps `equityCurveSource: "derived"` under "rebuilding" only when a
trustworthy v2 curve exists but is held back, for example because a key's account is still pending.

A new helper, `producerRebuildingPayload`, builds that shape. The four book-mode D-15 arms now use it:
- The "derived" book carries its source and a `derivedCurveComputedAt` but no curve points, with reason `account_identity_pending`.
- The "neither source" book carries nothing, and the arm asserts that `equityDailyPoints` really is `[]`.

The blank-mode rows follow the same shape. Only the "ready" row carries a curve and its returns. The SFH-C3-01 arms were
producer-shaped from the start.

**Neuter, RED, restore, cmp.** The neuter adds `equityDailyPoints.length > 0` to the Scenario gate, which is the future
"is anything withheld?" rewrite the reviewer described.

|---|---|
