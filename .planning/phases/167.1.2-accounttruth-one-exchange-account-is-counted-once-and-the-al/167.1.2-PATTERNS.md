```sql
CREATE OR REPLACE FUNCTION enqueue_derive_broker_dailies_for_allocator_keys()
RETURNS VOID
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_catalog
AS $$
DECLARE
  v_key   RECORD;
  v_today TEXT := to_char(now() AT TIME ZONE 'UTC', 'YYYY-MM-DD');
BEGIN
  IF NOT pg_try_advisory_lock(hashtext('derive_broker_dailies_key_fanout')) THEN
    RAISE NOTICE '...: another run holds the lock; skipping';
    RETURN;
  END IF;
  BEGIN
    FOR v_key IN
      SELECT ak.id AS api_key_id
      FROM api_keys ak
      WHERE ak.is_active = TRUE
        AND ak.sync_status IS DISTINCT FROM 'revoked'
        AND ak.disconnected_at IS NULL
    LOOP
      BEGIN
        PERFORM enqueue_compute_job(
          p_strategy_id     := NULL,
          p_kind            := 'derive_broker_dailies',
          p_idempotency_key := 'derive-dailies-' || v_key.api_key_id::text || '-' || v_today,
          p_api_key_id      := v_key.api_key_id
        );
      EXCEPTION WHEN unique_violation THEN
        NULL;
      END;
    END LOOP;
  EXCEPTION WHEN OTHERS THEN
    PERFORM pg_advisory_unlock(hashtext('derive_broker_dailies_key_fanout'));
    RAISE;
  END;
  PERFORM pg_advisory_unlock(hashtext('derive_broker_dailies_key_fanout'));
END;
$$;
REVOKE ALL ON FUNCTION enqueue_derive_broker_dailies_for_allocator_keys() FROM PUBLIC, anon, authenticated;
```

## Conflicts to surface (Rule 7 — pick one, do not blend)

1. **IN-01 (founder copy call 2026-09-25) vs item 7 (founder, 2026-09-27).** IN-01 chose the warm-up note for a zero-history book under `"rebuilding"`; item 7 says that copy "promises a timer that the D-02 hold never honours" and must be chosen by `equityHistoryState`. 2. **"Matching `getLatestExposureSnapshot`" vs per-key latest.** `getLatestExposureSnapshot` takes the ALLOCATOR-wide latest `asof`. Applied literally to Open Positions, a key that did not poll today would lose all its positions (the $0 defect again). The ROADMAP's own sentence says "each key's latest asof", and plan 10's Python helper is per key. Use per key. Borrow from the analog its two-step, truncation-proof read and the honest-empty, not its allocator-wide grain.
   - ⚠️ Truncation: the current read is unbounded and DESC. With several keys and daily rows it can exceed 1000 rows, and a key that stopped polling long ago can then be cut off entirely, so its "latest" is computed from nothing. Either bound the read (e.g. per-key latest `asof` first, then `.in("asof", ...)` per key), or record why the row count cannot reach the cap.
   - Open: should a disconnected or revoked key's last holdings still show as "open"? Today they do. Plan 10's Python counts ELIGIBLE keys only. Decide explicitly; do not inherit.
3. **A migration in PR C vs D-12.** D-12 put the phase's only migration in PR B. Item 7a as written ("enqueue for any eligible key") is a SECDEF body change, which is a migration that auto-applies to PROD on merge (three reviewers before merge; VAC-04 body diff). The alternative "enqueue a reconstruct for a key that has never had one" could live in Python (e.g. the poll job or the refresh job enqueuing via the service-role `enqueue_compute_job` path) with no migration. Pick one and state why. If it is a migration, re-issue `REVOKE ALL ... FROM PUBLIC; GRANT ALL ... TO service_role` and keep its self-verify catalogue-only.
