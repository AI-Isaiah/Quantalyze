### WR-01: D-13's `/compare` flip is owned by no PLAN, and the ready path's content pin was deleted with nothing to replace it

**File:** `src/app/(dashboard)/compare/lib/holding-compare-adapter.ts:77-78` (`HOLDING_COMPARE_HISTORY_STATE`), `:240-243` (the two returns); `src/app/(dashboard)/compare/lib/holding-compare-adapter.test.ts:132-151`; planning: `167.1.2-11-PLAN.md` `files_modified`
**Issue:** D-13 says "Plan 11 owns the flip, and must DECIDE it". That sentence lives only in
`167.1.2-CONTEXT.md` and one ROADMAP bullet. `grep -ci "holding-compare|HoldingFactsheet|D-13|/compare"`
returns **0** for both `167.1.2-10-PLAN.md` and `167.1.2-11-PLAN.md`. Plan 11's `files_modified`
(lines 7-19) lists neither the adapter nor its test. The executor of plan 11 works from the PLAN, so
nothing makes it touch `/compare`. After PR C lands, one of two things happens:

- `/compare` stays hidden permanently, with no one deciding it should; or
- someone flips the constant later, trusting the docblock's claim that the flip "restores the pre-D-13
  behaviour byte for byte".

That claim now has no test behind it. The fix round deleted the one integration case that pinned
what the ready path returns: "computes metrics from ONLY the trustworthy rows when flagged rows are
interleaved", which asserted `a.analytics` equal to the clean-only analytics and +10% on the clean
step. Its replacements pin two things: the filter, through availability (a 1-vs-3 point count), and
the math, on `reconstructAndAnalyze` in isolation. Neither pins which rows the ready branch feeds
into the math. And because `HOLDING_COMPARE_HISTORY_STATE` is a module constant compared inside the
same module, the `historyState: "ready"` return (`:243`) cannot be reached by any test today. This is
the scope-amendment-touches-one-file class: the decision was recorded where a reader of CONTEXT sees
it, and not where the executor who must act on it looks.

**Fix:**
1. Make the state injectable so the ready branch stays under test while the default is
   "rebuilding":
   ```ts
   export async function fetchHoldingCompareItem(params: {
     allocator_id: string;
     holding_ref: string;
     supabase: SupabaseClient;
     /** @internal test seam; production callers omit it (D-13). */
     historyState?: "rebuilding" | "ready";
   }): Promise<HoldingCompareItem | null> {
     const state = params.historyState ?? HOLDING_COMPARE_HISTORY_STATE;
     // ...
     if (state !== "ready") return { ...base, historyState: "rebuilding", analytics: null };
     return { ...base, historyState: "ready", analytics };
   }
   ```
   Restore the deleted interleaved-flagged-rows case against `historyState: "ready"`, asserting that
   `analytics` equals the clean-only analytics and that `cumulative_return` is close to 0.1.
   Gating on `state !== "ready"` also makes the server side fail-closed, not just the card.
2. Add the adapter and its test to plan 11's `files_modified`, plus one acceptance line: "decide the
   D-13 flip (flip with evidence, or record why `/compare` stays hidden and which phase owns a
   flow-adjusted source)".

### WR-02: the composer's new `snapshotCount > 0` disclosure gate silently hides a derived-curve-only book

**File:** `src/app/(dashboard)/allocations/components/ScenarioComposer.tsx:5518`; producer `src/lib/queries.ts:3748-3757`
**Issue:** The round-1 fix gates the "Your book's own history is being rebuilt" disclosure on
`snapshotCount > 0`. Its reasoning: with no snapshot there is nothing to withhold. That is true for
the legacy path only. `snapshotCount` counts **trustworthy legacy `allocator_equity_snapshots` rows**
(`queries.ts:4296-4301`, flagged pre-terminus rows excluded). The candidate own-book series is
`derivedCurve ?? equitySnapshotsToDailyPoints(...)` (`queries.ts:3748-3753`). The derived curve comes
from `allocator_equity_derived` and does not depend on the legacy table.

Take an allocator with a trustworthy derived row and `snapshotCount === 0`. Every legacy row is
terminus-flagged, which the OKX 90-day clamp produces, or the legacy table is empty. Under "ready"
that allocator would see the own-book series and delta. Under D-02 the series is withheld **and** the
disclosure is suppressed. That is the silent gap the disclosure exists to prevent, and the fix
created it. The population today may be small. Per the producer comment, the per-key backfill had not
run (not re-measured here). It grows as derived rows land, before plan 11 flips anything.
**Fix:** Gate on what the producer would have shown, not on the legacy count. The smallest change
reads a field already on the payload:
```tsx
{isOwnBookRebuilding && !isBlankMode &&
  (snapshotCount > 0 || equityCurveSource === "derived") && ( ... )}
```
Add a case: `"rebuilding"`, `snapshotCount: 0`, `equityCurveSource: "derived"` → the disclosure
renders. Neuter check: drop the `|| ...` and the case goes RED.
