### D-02 — the disconnected key (K1–K4)

**1. Chip label.** `Key disconnected` (rendered uppercase by the chip's existing `uppercase`
class, as "Key revoked" is).

Why this string: it is built from vocabulary that already ships, not a new one (167-UI-SPEC rule:
"do not invent a third vocabulary for a state that already has one"). "Key ___" matches the
byte-unchanged "Key revoked" chip, and "disconnected" is the word the key surface already uses
for this exact state ("Disconnected keys" section and `SYNC_DISCONNECTED_HELPER`, "This API key is
disconnected. Reconnect it before syncing holdings.", both in
`src/components/exchanges/AllocatorExchangeManager.tsx`).

> ⛔ **CORRECTED 2026-10-15 (orchestrator, from RESEARCH.md):** an earlier draft said these rows are "hidden by default". They are not. The shipped toggle `showRevoked` starts `true`, so untrusted rows show struck through and hide only when the owner unchecks it. A disconnected key's row follows that same shipped rule. The column below now says "Hidden when the toggle is off".

**2. One chip per row; disconnected wins.** A row whose key is disconnected AND carries an
untrusted `sync_status` (`revoked` or `sign_in_failed`) shows exactly ONE chip:
**`Key disconnected`**.

| `disconnected_at` | `sync_status` | Chip | Struck through | Hidden when the toggle is off |
|---|---|---|---|---|
| set | any (`complete`, `revoked`, `sign_in_failed`, null, …) | Key disconnected | yes | yes |
| null | `revoked` | Key revoked (unchanged) | yes | yes |
| null | `sign_in_failed` | Sign-in failed (unchanged) | yes | yes |
| null | any trusted/neutral status | none (unchanged) | no | no |
| key missing from key list (`source_key_missing`) | — | "Sync status unknown" muted label (unchanged) | no | no |

Why disconnected wins: `disconnected_at` is the owner's own later act and describes the key's
current state. A disconnected key runs no sync (`SYNC_DISCONNECTED_HELPER`), so its `sync_status`
is the outcome of its last sync before it left and is older information. The key surface already
orders it this way: `AllocatorExchangeManager` puts every key with `disconnected_at` set in the
"Disconnected keys" section whatever its status. The chip also names the one action that helps
(Reconnect); a revoked key that is disconnected needs to be reconnected with a new credential
either way.

**3. Row treatment: identical to an untrusted row.** Amber chip, figures struck through and muted
(`numericCell`'s existing untrusted branch), `HoldingNoteIconButton revoked={true}` styling,
hidden while "Show holdings from keys needing attention" is off and counted in "N holdings hidden
from keys needing attention · Show all". ⛔ The toggle label and the hidden-row footer do NOT
change: `UNTRUSTED_KEY_SET_NOUN` is cause-neutral and now covers three causes.

**4. The disclosure clause (K3, K4): no copy change.** A disconnected key's dollars are summed into
the same part as an untrusted key's, so the existing wording covers it byte-for-byte:

- Open Positions footer (K3): `Includes −$1,234.56 from keys needing attention.`
- Composer AUM note (K4), non-narrowed (degrade) branch: `Includes $12,345 from keys needing attention.`
- Composer AUM note (K4), narrowed modelled-book branch: `Excludes $12,345 from keys needing attention.`
  (or the existing combined forms, for example `includes $X and excludes $Y from keys needing attention`).

**5. Consequence the planner must carry, stated rather than hidden (K4).** In
`summarizeLiveHoldings`' narrowed branch the widened predicate is tested BEFORE the eligibility
test (branch order unchanged), so a soft-disconnected key's dropped holdings move from
`excludedNotConnected` ("excludes $X from keys that are not connected") to `excludedUntrusted`
("excludes $X from keys needing attention"). That is D-02's "disclosed the same way as an
untrusted key". **No number moves:** the composer's modelled-book narrowing is unchanged, and
D-02's "stay in the total" holds for every total that already counted the key (Holdings, Open
Positions, the composer's degrade branch). `excludedNotConnected` stays, and still names keys that
are inactive but not disconnected (`is_active = false`, `disconnected_at` null). Its noun and
wording are unchanged.

### D-03 — `/compare` holding card (C1)

Rendering is keyed on `item.historyState` (fail-closed, unchanged rule: only an explicit
`"ready"` with analytics present shows numbers) and on `holding_type`.

**Hierarchy.** The four-metric grid is C1's primary anchor. The caption is subordinate: it sits
below the grid, muted, at body-small size, and is never larger or darker than the values.

**State R — spot, ready.** Reuse the existing ready `<dl>` grid byte-for-byte: labels
`Cumulative return`, `Sharpe`, `Max drawdown`, `Vol (annualized)`; values through the existing
`fmtPct` / `fmtNum`. Below the grid, one new caption:

> `Computed from {N} days of {SYMBOL}'s daily price, so buying, selling or moving more of it does not count as a gain or loss.`

- `data-testid="holding-factsheet-price-basis"`, element `<p className="max-w-prose text-sm text-text-muted">`.
- `{N}` = the number of priced days the metrics were computed from (thousands separators per the
  Numbers Contract; `1 day` / `{N} days`). The adapter must carry it on the ready item (for
  example `analytics.priced_days`). ⛔ Never render the caption without `{N}`: a metric with no
  provenance fails DESIGN.md's dated-document test.
- `{SYMBOL}` = `item.symbol` as the heading already renders it.

**State R0 — spot, ready, too few priced days.** When `analytics.priced_days` is below the adapter's
minimum (the component reads that rule, not "all four metrics null": SFH-02, round 1), the grid still renders, each value an **em-dash `—`**, never
`0`, never blank (DESIGN.md Numbers Contract). The caption is replaced by:

> `Only {N} priced {day|days} of {SYMBOL} so far. These four figures need at least {MIN} priced days.`

- Same `data-testid="holding-factsheet-price-basis"` and classes as State R.
- `{MIN}` is the adapter's own minimum-days constant, read by symbol, never restated as a literal
  in the component (DESIGN.md Voice: "state limitations with the threshold attached").
- A single metric that is null while others are finite (for example Sharpe with zero dispersion)
  shows its em-dash and keeps the State R caption. No per-metric explanation is added, with ONE
  exception: State R2.

**State R2 — spot, ready, at or above the minimum, but vol and Sharpe are null (SFH-02, round 1).**
Vol and Sharpe are over one-day returns taken only between two ADJACENT priced calendar days, so a
holding priced on non-consecutive days has a numeric return and drawdown beside two em-dashes.
When `analytics.priced_days >= MIN` and `analytics.vol === null`, a second muted sentence follows
the State R caption:

> `Volatility and Sharpe need at least two pairs of consecutive priced days.`

- `<p data-testid="holding-factsheet-adjacency-note" className="max-w-prose text-sm text-text-muted">`,
  the State R caption's element and classes, as a direct child of the card's `gap-4` column.
- Keyed on `vol === null`, not on `sharpe === null`: a null Sharpe beside a numeric vol is a
  zero-dispersion case this sentence would describe falsely, so it keeps the bare em-dash.
- It does not appear in State R0, where the threshold sentence already explains every em-dash.

**State F — spot, withheld because its recorded price is a fixed value (CR-01 / SFH-01, round 1, 2026-10-15).**
A spot holding whose `mark_price` is a constant the analytics writer stamps, not a market price,
is returned by the adapter as `historyState: "withheld"` with `withheld_reason: "fixed_price"`. That
covers a stablecoin symbol (the writer's `STABLECOINS` set) and every sFOX row. (A venue
`isCryptoExchange` rejects, the MT5 `ACCOUNT-<hex>` rows, is State F2 since round 2, M-R2-01: its mark
can be the unit's daily close, so "a fixed value" is false for it.) It is NOT null: null is the D-15 answer for an
unowned or nonexistent holding and the page drops it, whereas this holding has rows and a known
owner. The same note slot as State D renders:

> `Return, Sharpe, max drawdown and volatility are not shown for {SYMBOL}: its recorded price is a fixed value, not a market price.`

- `<p data-testid="holding-factsheet-rebuilding" className="max-w-prose text-sm text-text-secondary">`,
  the State D element and classes, unchanged. No metric label, no value, no em-dash, no
  `holding-factsheet-price-basis` caption renders. The header (pill, symbol, venue · type) stays.
- `{SYMBOL}` = `item.symbol` as the heading renders it (an MT5 account reads as `ACCOUNT-<hex>`).
- Fail-closed like State D: a withheld item renders the note even if `analytics` were attached.
- Reuses the "not shown for ... yet" voice of State D and DESIGN.md's "state the cause" rule. It
  does not say "yet": a constant price will not become a market price by waiting.

**State F2 — spot, withheld because the row is an account balance (M-R2-01, round 2, 2026-10-15).**
A spot holding on a venue `isCryptoExchange` rejects (MT5 `ACCOUNT-<hex>` rows) is returned with
`historyState: "withheld"` and `withheld_reason: "account_balance"`. The writer stamps `mark_price = 1.0`
for a USD account but overwrites it with the unit's daily close for a native-unit account, so the mark
varies: a return over it would be the UNIT's return, not the account's. The note slot renders:

> `Return, Sharpe, max drawdown and volatility are not shown for {SYMBOL}: it is an account balance, not a traded asset.`

- Same element, classes, test id, fail-closed rule and "no metric, em-dash or basis line" rule as State F.
- It never says "fixed value": a test pins that an MT5 item cannot show the State F sentence.
- Precedence: a non-crypto venue is State F2 whatever its symbol; State F then applies to a stablecoin
  symbol or sFOX on a crypto venue.

**State N — spot, withheld because no market price has been recorded (M-R2-02, round 2, 2026-10-15).**
A crypto spot holding that HAS rows but whose every day is unpriced (the writer's `0.0` failed-ticker
sentinel on each day: an asset with no `{asset}/USDT` market on its venue) is returned with
`historyState: "withheld"` and `withheld_reason: "no_price"`. It is not State R0: R0's "so far" promises
that waiting fills the history, and for this holding it never will. The note slot renders:

> `Return, Sharpe, max drawdown and volatility are not shown for {SYMBOL}: no market price has been recorded for it.`

- Same element, classes, test id, fail-closed rule and "no metric, em-dash or basis line" rule as State F.
- No time word (round 3, M-R3-01): the copy does not say "yet" or "so far". Waiting will not price an asset
  that has no market, and the adapter cannot tell that from a new holding whose first ticker read failed,
  so the sentence without a time word is true in both cases. The test rejects `/\byet\b|so far|fixed value|account balance/`.
- Boundary: ZERO priced days is State N; 1 to `MIN - 1` priced days stays State R0 ("so far" is true
  there: the history is filling). Zero ROWS stays null (D-15).
- The adapter logs once (`console.warn`) with the holding ref and the row count, no ids and no values,
  so a permanent gap can be told from a newly connected holding.

**State D — derivative (stays `"rebuilding"`).** Reuse the existing note slot
(`<p data-testid="holding-factsheet-rebuilding" className="max-w-prose text-sm text-text-secondary">`),
with the copy corrected. The current copy blames a rebuild and a double-count that this phase
removes, so it would become false for derivatives:

> `Return, Sharpe, max drawdown and volatility are not shown for derivative holdings yet. A price rise is a gain on a long position and a loss on a short one, and these figures wait until that direction is defined for each day.`

No metric label or value renders in State D (unchanged rule, pinned by
`HoldingFactsheet.test.tsx`).

**State X — any other non-ready item (defensive fail-closed path).** If a non-derivative item
arrives without `"ready"` analytics, the same note slot renders:

> `Return, Sharpe, max drawdown and volatility are computed for spot holdings only, and this holding is not recorded as spot.`

Reachability: a spot item can never reach State X. A spot item with 1 to `MIN - 1` priced days is
State R0 (`"ready"` with null metrics), and a withheld spot item (F, F2, N) renders its own named
note, never State X. (Round 2, M-R2-02: a spot item with ZERO priced days is no longer "ready", it
is State N.) State X can only be reached by a `holding_type` that is neither `spot` nor `derivative`
(`parseHoldingCompareId` accepts any `[A-Za-z0-9_-]+` type). The copy names that cause.

⛔ The old rebuilding copy ("hidden while your equity history is rebuilt … could count one
exchange account twice …") is removed from every branch. It describes the dollar-ratio source
D-03 retires.
