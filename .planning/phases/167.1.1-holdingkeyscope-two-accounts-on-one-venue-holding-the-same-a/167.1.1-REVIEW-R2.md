## New findings

### M-R2-01 (MEDIUM, user-facing): State F tells an MT5 native-unit account holder that the recorded price is "a fixed value", which is false for that row

**Location:** `holdingMarkIsFixed` (the `!isCryptoExchange(venue)` arm) together with `HoldingWithheldReason` (only `"fixed_price"`) in `src/app/(dashboard)/compare/lib/holding-compare-adapter.ts`, and `fixedPriceNote` in `src/components/strategy/HoldingFactsheet.tsx`. Specified by UI-SPEC State F and U-09.

**Evidence:** The MT5 builder in `analytics-service/services/allocator_positions.py` (the row built for `symbol = f"ACCOUNT-{api_key_id[:8]}"`) writes `"mark_price": 1.0` for a USD account. For a native-unit account it then overwrites the mark: `if native_close is not None: row["mark_price"] = native_close`. That close is the unit's daily close, so it changes every day. Every MT5 row still reaches State F, and State F prints `…not shown for ACCOUNT-xxxxxxxx: its recorded price is a fixed value, not a market price.` For a native-unit account (the BTCUSDVIEW case, Phase 164.6.6.2.1) both halves of that sentence are false: the recorded mark is not fixed, and it is a market price, just the unit's price and not the account's. FIX-A acknowledges this ("the sentence is slightly loose for that case") and ships it anyway. The phase test `State F names the holding it is about (an MT5 account token reads as itself)` asserts the false sentence for an MT5 token.

Withholding the numbers is correct: a return over the unit's close would be BTC's return, not the account's. Only the stated reason is wrong. DESIGN.md Voice requires copy that "states the fact". The repo has paid for false-cause copy before, which is why the 167.1 chip copy is per cause.

**Fix:** Add a second reason, since the `HoldingWithheldReason` union already exists for this:
```ts
export type HoldingWithheldReason = "fixed_price" | "account_balance";
// in fetchHoldingCompareItem, before the fixed-mark test:
if (!isCryptoExchange(parsed.venue)) {
  return { ...base, historyState: "withheld", analytics: null, withheld_reason: "account_balance" };
}
```
Give it its own copy in the factsheet and add it to the UI-SPEC, for example: "Return, Sharpe, max drawdown and volatility are not shown for {SYMBOL}: it is an account balance, not an asset, so it has no price of its own." Keep `fixed_price` for stablecoins and sFOX. Change the MT5 factsheet test to assert the new sentence, and add an adapter arm with a varying mark on `mt5` that asserts `account_balance`.

**User-facing:** yes. **Data-integrity:** no (no number is shown).

### M-R2-02 (MEDIUM, user-facing): a spot asset the writer never prices reads "Only 0 priced days of X so far" forever, with no log

**Location:** `dailyMarkPrices` (a finite mark at or below 0 is skipped silently) and `fetchHoldingCompareItem` (always `ready` once rows exist and the holding is not fixed-mark) in the adapter. The copy is the State R0 branch of `HoldingFactsheet` (`Only ${pricedDayCount(...)} of ${symbol} so far…`).

**Evidence:** `_fetch_spot_rows` prices every non-stablecoin asset with the `{asset}/USDT` ticker. When that ticker does not exist or fails, it writes `mark_price = 0.0` ("we mark the price 0 rather than abort spot"). An asset with no `/USDT` market on its venue, such as an exchange's earn or receipt token that shows up in the spot balance, therefore writes `0.0` every day. All its rows are gaps, `priced_days` is 0, and the card says "Only 0 priced days of X so far. These four figures need at least 30 priced days." "So far" promises that waiting will fill the history, but it never will. Nothing is logged, so this cannot be told apart from a newly connected holding. Round-1 SFH-03 named this case ("Also log once when `rows.length > 0` and `points.length === 0`"). FIX-A declined it on the grounds that the resolution kept `<= 0` as a silent gap. That decision covers individual sentinel days. It does not cover a holding where every day is a sentinel.

**Fix:** In `fetchHoldingCompareItem`, when `rows.length > 0` and `points.length === 0`, log the ref and the row count with `console.error` (no values). Then either return a withheld item with a new reason, `"no_price"` ("{SYMBOL} has no recorded market price on {venue}; return, Sharpe, max drawdown and volatility need one"), or keep `ready` but use R0 copy without "so far" when `priced_days === 0`. Add an adapter arm with 40 rows at `mark_price: 0` that asserts the chosen shape and the log, and a factsheet arm that asserts the copy.

**User-facing:** yes. **Data-integrity:** no number is invented, but the stated cause is wrong and the case is silent.
