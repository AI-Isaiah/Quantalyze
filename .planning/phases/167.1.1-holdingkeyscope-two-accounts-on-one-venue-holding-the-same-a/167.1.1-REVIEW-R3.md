## Fix-diff review (task 2)

- **`HoldingWithheldReason` union and the exhaustive switch.** The union has three members: `"fixed_price" | "account_balance" | "no_price"`. `holdingWithheldReason` returns `Extract<…, "fixed_price" | "account_balance"> | null`, so it cannot claim `no_price` by type. `withheldNote` covers all three members and is exhaustive under strict mode (probe above). The only production consumer of `withheld_reason` is `HoldingFactsheet` (grep over `src`, tests excluded). No defect.
- **Precedence.** A non-crypto venue is checked first, then sFOX or a stablecoin symbol, and otherwise the result is null. The lowercase and uppercase normalisation matches the writer. No defect.
- **`no_price` branch.** It runs after the zero-rows `null` (D-15) and after the `rebuilding` and fixed-mark returns, so neither D-15 nor the existing states moved. It sits after the contract check, so a bad mark is still a load error and not "no price". No defect at MEDIUM or above.
- **`console.warn` content.** The message is `no priced day for ${holding_ref}: ${rows.length} row(s), none with a valid mark_price`. A `holding_ref` is `holding:{venue}:{symbol}:{type}`. MT5 is the only venue whose symbol carries a key-id prefix, and it returns earlier as `account_balance`, so the warning never prints it. The warning has no allocator id and no values. No defect.
- **Fail-closed.** `analytics` is still read only when the state is `"ready"`, and the test with analytics smuggled in still passes. No defect.

## New findings

### M-R3-01 (MEDIUM, user-facing): State N still promises a price that will never come ("…recorded for it yet.")

**File:** `src/components/strategy/HoldingFactsheet.tsx:66-67` (the `no_price` case of `withheldNote`). The same copy is in UI-SPEC State N and pinned in `src/components/strategy/HoldingFactsheet.test.tsx` ("State N…").

**Issue:** M-R2-02 was raised because "Only 0 priced days … so far" promises that waiting fills the history, while a holding with no `{asset}/USDT` market is written as `0.0` every day for good. The fix moved the holding to a new state, but its copy ends with **"no market price has been recorded for it yet."** "Yet" makes the same promise that "so far" made. The phase's own documents say this is wrong for a cause that waiting will not fix:
- UI-SPEC State F: "It does not say 'yet': a constant price will not become a market price by waiting."
- UI-SPEC State N's rationale and the `HoldingWithheldReason` docblock (adapter lines 102-105): "Waiting will not fill it, so it is not the 'so far' state."

The State N test checks `not.toMatch(/so far|fixed value|account balance/)`, so it guards the literal phrase and not the rule ("no promise of waiting"). Changing "so far" to "yet" passes it. The adapter cannot tell a permanently unpriced asset from a new holding whose first ticker read failed. That is a reason to drop the time word: without it, the sentence is true in both cases.

**Fix:**
```ts
case "no_price":
  return `${lead} no market price has been recorded for it.`;
```
Update UI-SPEC State N and the coverage-table row to match. In the State N test, widen the negative assertion to `not.toMatch(/\byet\b|so far|fixed value|account balance/)` so the test enforces the rule and not just one phrasing. Run it against the current copy and confirm it goes RED, then GREEN after the fix.

**User-facing:** yes. **Data-integrity:** no (no number is shown).
