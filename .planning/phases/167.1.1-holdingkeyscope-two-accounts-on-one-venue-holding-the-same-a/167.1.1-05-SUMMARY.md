# Phase 167.1.1 Plan 05: The holding card states where its numbers come from Summary

**The `/compare` holding card now tells a spot holding's reader that its four figures come from N days of the daily price, shows em-dashes with the 30-day threshold when there are too few priced days, and gives derivatives and unknown types true copy with no numbers.**

## Accomplishments

- **State R:** the ready grid is unchanged; below it a `holding-factsheet-price-basis` paragraph (`max-w-prose text-sm text-text-muted`, a direct child of the card's `flex flex-col gap-4`) reads "Computed from {N} days of {SYMBOL}'s daily price, so buying, selling or moving more of it does not count as a gain or loss." N goes through `formatNumber(n, 0)`; one day reads "1 day".
- **State R0:** when all four metrics are null the grid shows four "—" and the same slot reads "Only {N} priced {day|days} of {SYMBOL} so far. These four figures need at least {MIN} priced days." `{MIN}` is `HOLDING_COMPARE_MIN_PRICED_DAYS`, imported by symbol (client-safe, the adapter has no server-only import). The test types 30 independently of the constant.
- **States D and X:** the note slot keeps its testid and classes. A derivative shows the corrected sentence; any other non-ready type shows the spot-only sentence. The old "hidden while your equity history is rebuilt ... could count one exchange account twice" copy is gone from every branch (`grep -a -c` prints 0). The fail-closed gate is untouched.
- **Page arm:** `/compare` for an owned spot holding with 40 priced days asserts the exact State R sentence.
- No colour, size, weight, class or token beyond the UI-SPEC; no `toFixed`; the display-sign census stays green.

## Decisions Made

- R0 is detected as "all four metrics null", which is the UI-SPEC's own definition. With 30 or more priced days cumulative return and drawdown are always finite, so that state is unreachable with a misleading caption.
- A hand-built non-ready item whose `holding_type` is `spot` shows the State X sentence ("this holding is not recorded as spot"), which would be untrue for that item. The UI-SPEC defines State X as "any other non-ready non-derivative item" and records that a spot item can never reach it (the adapter returns "ready" for every spot item), so I followed the spec. Flagged here, not changed.
