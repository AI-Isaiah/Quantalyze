**Design fixed here (planner's decisions under D-17, so the executor does not re-derive them).**
- WHAT IS STRIPPED. The surrounding characters are whitespace as Python's `str.isspace()` defines it, the apostrophe U+0027 and the double quote U+0022, in any mix and number. Strip with `str.strip()` (no argument, so `str.isspace()`), then `.strip()` of the two quote characters, and repeat until the value stops changing. A single pass misses `' "\t1\t" '`. Whitespace is the whole class, not ASCII only: a no-break space around an id is as much export padding as a tab, and stripping it cannot change a digit. Only the two ASCII quote characters D-17 names are stripped. Typographic quotes stay and show in the shape as `Pi` / `Pf`. The inside of the id is never touched, because joining `1 23` into `123` would invent an id. `=` is not stripped (D-17 does not name it), so a spreadsheet formula id shows as `Sm-...` in the shape and goes to the founder.
- WHERE. In `parse_archive_csv`'s first loop, directly after `row = dict(zip(header, cells))`: `row["billId"] = _strip_bill_id(row["billId"])`. The recorded comparison tuple becomes `tuple(row.values())` instead of `tuple(cells)`. `_check_header` guarantees each header name once, so `row` holds the cells in header order and the tuple differs from `cells` only in the stripped billId cell. The second loop is unchanged and so reads the stripped id everywhere.
- EMPTY AFTER THE STRIP is `missing_bill_id`, settled from the code (see the truths). No new stop class.
- THE SHAPE is made in `okx_archive_classify.py`, beside the non-digit decision. `_bill_id_shape(bill_id)` maps each character to its symbol and merges equal neighbours into runs. A run of one is the bare symbol and a run of n is `<symbol>{n}`. Runs are joined by `-`, at most `_SHAPE_MAX_RUNS` (8) are spelled out, and `MORE` is appended as a ninth part when there are more. `NONDIGIT_SHAPE_RE` (public, `Final`) is the grammar in the truths, built from `_SHAPE_RUN` so the run cap and the regex cannot drift apart.
- FIRST. Two variables, `first_shape: str | None` and `first_len: int | None`, start as None before the tally's file loop. They are set once, inside the existing `if row_nondigit:` branch, after `nondigit += 1`, the first time it runs. The tally already walks files in the order passed and rows in file order, and already skips a bill seen in an earlier file. The `unchainable_row` detail gains `"first_nondigit_shape": first_shape, "first_nondigit_len": first_len` after `last_day`. The `bal_chain_break` / `too_few_pairs` detail and the success reading do not change.
- THE TOKENS go after the day tokens and before `rows_by_quarter=`. That keeps `rows_by_quarter=` the last token, so `test_a_per_file_list_that_does_not_fit_the_quarters_reads_unreadable` (which reads the last token) and `test_two_quarters_are_named_in_input_order` (which reads the text's end) stay green unedited. A missing key reads `unreadable`, as every D-16 key does. A None value reads `none`, because a stop on blank-ccy bills alone has no non-digit id, and `unreadable` would claim a value existed and was withheld.
- THE JOB VALIDATES the shape before echoing it, as D-16 validates every count and day: `_shape_or_unreadable(value)` returns `value` when it is a `str` and `NONDIGIT_SHAPE_RE.fullmatch(value)` holds, else `unreadable`. `_bal_chain_info` uses the same check for `info.bal_chain.first_nondigit_shape` (None stays None) and copies `first_nondigit_len` like the other counts. A future slip in `_bill_id_shape` therefore reads `unreadable` instead of carrying file text.
- `unicodedata` and `re` are standard library, so no package is added.
