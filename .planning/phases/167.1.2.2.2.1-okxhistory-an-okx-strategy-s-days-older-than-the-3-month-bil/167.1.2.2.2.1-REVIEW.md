## Warnings

### WR-01: The completeness proof chains each quarter file on its own, so missing rows at the end of Q2 or the start of Q3 still publish 0.0 days that nothing checks

**File:** `analytics-service/services/okx_archive_classify.py` (`verify_bal_chain`, `_chain_file`: `previous` is reset per file); `analytics-service/services/okx_archive_job.py` (`_census_of`)

**Issue:**
- `_chain_file` starts each file with an empty `previous`, so each file's first bill per currency is never checked. A Q2 file missing its last weeks, or a Q3 file missing its first weeks, still chains internally.
- `parse_archive_csv` turns every covered day with no bill into an explicit zero. `rows_for_strategy` writes that day, and the RPC takes it out of `unrecovered_gaps`.
- The affected days would be late June and early July (for example 2026-06-15 to 07-10). They are:
  - inside both strategies' gaps (05-07 or 05-24 to 08-01);
  - outside the reconcile window, which opens at the run date minus 87 days (about 07-20 today);
  - not covered by the D-03 check, which reads only strategy 4.
- The only remaining guard is a person reading `ts_min_day`, `ts_max_day` and `longest_billless_run` in Step 3. That is the "silent zeros" failure F1 was raised for, at the one seam the job could prove at no cost.

**Fix:**
1. Chain across the requested quarters instead of per file. For each currency, sort the deduplicated union of all files' rows by billId and require `bal == previous bal + balChg` across the file boundary too.
2. Treat a break at the seam as `archive_incomplete reason=quarter_seam_break`, with both quarters' `ts_max_day`/`ts_min_day` in `info`.
3. Keep the per-file reading for its detail.

After this, only the start of Q2 is unproven, and there is no live or archive reference for it. Say so in the runbook, which already asks for `ts_min_day`.

### WR-02: The runbook contradicts the code on transient classes and names a result key a clean calibrate never has

**File:** `docs/runbooks/okxhistory-go-live.md:75-76`, `:514-517`, `:583-584`

**Issue:**
- Lines 76 and 514 still say `link_expired` "is the one transient class". Line 516 says "Any other `error_class` is permanent (`failed_final`): it is a STOP ... return to the founder."
- `TRANSIENT_STOP_CLASSES` now also contains `live_fetch_failed` and `claim_budget_exceeded`, and the job retries both on its own. An operator who follows the runbook would treat a retry in progress as a stop and escalate it.
- The new backstop give-up (`archive_give_up backstop age_h=N` or `age=unreadable`) appears nowhere in the runbook.
- Lines 583-584 tell Step 3 to read `info.bal_chain`. Only the `archive_incomplete` stop writes `bal_chain` (through `stop.info` in `_finish_stop`). A clean calibrate carries `info.bal_continuity` and no `bal_chain`, so the founder is sent to read a proof the result does not contain.
- The orchestrator's "runbook reads the shipped result keys" pass missed all three.

**Fix:**
1. Replace both "one transient class" sentences with the three class names, cited by the symbol `TRANSIENT_STOP_CLASSES`.
2. Add `archive_give_up` (backstop) to the stop reading.
3. Change lines 583-584 to say that a clean calibrate proves the chain by the absence of the `archive_incomplete` stop, and that `info.bal_chain` appears only on that stop. Alternatively, make a passing `verify_bal_chain` return its per-currency reading so a clean result records `info.bal_chain` positively.

### WR-03: The readings that stand in for the declined money gates are missing from the founder's go/no-go, and no reading covers the flow seam

**File:** `docs/runbooks/okxhistory-go-live.md` Step 2 expected readings (`:580-597`) and Step 3 items 1-7 (`:604-628`); `analytics-service/services/okx_archive_job.py` (`_evaluate`, the window of `flow_totals_overlap`)

**Issue:**
- Fixer A answered WR-02/F4 by recording readings for the founder's preview. The runbook names none of them: `insert_returns`, `realized_balance_vs_rolled_nav`, `flow_totals_overlap` and `live_from` each have 0 grep hits. Step 3 item 4 calls the `info` readings "information, not gates", with no bound and no instruction.
- `flow_totals_overlap` is summed over the reconcile window, which starts at `first_full_day` (run date minus 87 days). The flow seam is at `flow_window_first_day` (midnight minus 90 days). A straddle at the seam therefore falls outside the only flow reading, whether it doubles the movement or drops it.
- The result: the written returns of a published strategy (ordinal 2) can shift with no number anywhere showing it. The approved fingerprint deliberately pins no values. That is a user-facing money-math exposure. The gate decision belongs to the founder, but today the runbook does not tell the founder to read what that decision needs.

**Fix:**
1. Add a Step 3 item that names `strategies[].insert_returns`, `info.realized_balance_vs_rolled_nav.diff` and `info.flow_totals_overlap`, and says to return to the founder when the diff cannot be explained.
2. Add an information reading around the seam, for example archive transfer totals against live flow totals over `[flow_window_first_day - 7, first_full_day + 7]`, so a straddle shows up.
3. Put the gate itself (a bound on `realized_balance_vs_rolled_nav.diff`) to the founder as an explicit AskUserQuestion decision, rather than an implicit "not done".

## Info

### IN-01: The work after the last crawl is not checked against the claim budget

**File:** `analytics-service/services/okx_archive_job.py` (`_evaluate` after `_live_reference`; `_apply_targets`)

`_within` bounds only the crawls and downloads. If the price crawl finishes with a few seconds of budget left, the rest of the claim runs on `CLAIM_RESERVE_S` (60 s) alone. That rest is the D-03 reads, `_load_provenance`, `_read_daily_returns`, `_stored_vs_core`, the rebuild and the RPCs. Overrunning the reserve ends in the dispatcher's generic cancellation, the failure WR-06 set out to remove. It is safe, because each RPC is atomic. Consider checking `budget.remaining() >= N` before the evaluation reads and before the first RPC, and raising `claim_budget_exceeded step=evaluate` when it fails.

### IN-02: Step 3 item 2's edge rule can reject a genuinely quiet quarter edge

**File:** `docs/runbooks/okxhistory-go-live.md:611-617`

The rule says "`ts_min_day` and `ts_max_day` must sit at the quarter's first and last days". A complete file from an account that had no bill on 04-01 or 09-30 fails it. Once WR-01 chains the Q2/Q3 seam, the human check is needed only for the start of Q2. Reword it there as "explainable by the account's activity".
