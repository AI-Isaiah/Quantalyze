## Decisions Made

- `daily_return` is fenced to `+/-10`, the fence `finalize_csv_strategy_with_returns` applies to the same table. A JSON number is always finite; the fence keeps an out-of-range number from surfacing later as a float cast error and keeps the two writers agreeing on what a valid row is.
- The already-applied check runs before the compare-and-set. After a success the stored gaps have moved, so the retry of a lost response would otherwise report `gaps_changed`.
- A stored `reconstructed_ranges` that is present but not an array is refused, not overwritten.
- Stored `unrecovered_gaps` entries that are not valid ranges are refused (`stored_gaps_malformed`) rather than guessed at.
- RED-UNDER-SETUP order: fixture 07 (Supabase default privileges) precedes the table-creating fixtures, matching the provenance gate's order and not the fan-out gate's. Reason: the fan-out order (`01, 02, 03, 07`) creates `strategy_analytics` before the default privileges exist, so `service_role` would hold no grant on it and the gate could not run the function as `service_role`. `20260405061912_rls_policies.sql` sits directly after fixture 10, ahead of fixtures 12 and 13, because fixture 13 re-creates the `on_auth_user_created` trigger that migration already creates (`42710` otherwise). No entry was dropped.

## Contract facts for the plans that call this function

- A re-run is `already_applied` only when EVERY row date already has a `csv_daily_returns` row AND lies in a stored `reconstructed_ranges` entry with the pinned source. A retry whose `p_rows` includes a day that was a LIVE row at the first call (never inserted, so never in a range) is not `already_applied`; the gap no longer names that day, so it raises 22023 `row_outside_gap` and writes nothing. Plan 08 should send only days it expects to insert (its planned-set rule already does).
- An empty `p_rows` is refused (22023), as the contract says; plan 08's rule 3 handles the empty case before the RPC.
- The narrowed gaps keep each stored gap's `recorded_at`; the appended ranges carry a fresh UTC `recorded_at`.
- Refusal messages start `apply_okx_archive_rebuild:` and contain one of `gaps_changed`, `gaps_after_mismatch`, `row_outside_gap`, `stored_gaps_malformed`, or a shape description; they carry counts and the earliest offending date only.
