## Accomplishments

- **One evaluation, two modes.** `_live_reference` crawls what the live derive crawls, with its functions and `_BROKER_CRAWL_TIMEOUT_S` bound (equity and open uPnL with the derive's noise guard, `fetch_all_trades(since_ms=None)`, OKX funding, ccxt deposits and withdrawals through the same flow valuer, and the derive's own `_ccxt_full_history_verdict`). `_reconcile` runs `reconcile_leg` for the realized and funding legs (the cent tolerance is the module constant in plan 02, with no parameter here). `_evaluate` then runs `rebuild_union` with `from_day` stable across a partial apply (Resumability rule 2), slices per target with `rows_for_strategy`, and fills `reconcile`, `excluded`, `info`, `strategies` and `fingerprint`. The excluded classes, flow totals, `bal` continuity, `stored_vs_core` and the balance-vs-NAV reading are information.
- **Calibrate writes nothing.** A write spy over every table and RPC sees only `set_compute_job_progress`. The RPC is unreachable from calibrate by two independent barriers (the mode check and the fingerprint gate), and both were neutered in the proofs.
- **D-11.** Every evaluation stop is raised before the first RPC, so a reconcile miss cannot follow a committed target. `last_error` carries `window=<from>..<to>`, per-leg day counts and the offending date range, no amount.
- **D-03.** Stored 0.0 days inside a verified quarter are compared with the archive, read-only; a hit stops `d03_zero_day_has_archive_pnl` and the result lists date, stored return, archive realized and archive funding.
- **Fingerprint.** Content-derived only (see key-decisions). Stable across runs, moved by one cent on one archive day, independent of the equity anchor, covers each target's PLANNED date list.
- **Apply.** `fingerprint_missing` at input, `fingerprint_mismatch` after evaluation, then per target: skip without an RPC when nothing is left to write and the narrowed gaps equal the stored ones (`already_applied`, `insert_days` 0), else one RPC with `p_rows`, `p_expected_gaps` (the stored gaps read) and `p_expected_gaps_after` (the preview's). `P0001` / `22023` is `rpc_refused position=N applied=K`. Any other exception records `{status: null, error_class: "rpc_transport"}` for that target, writes the result block, and re-raises so the dispatcher retries; the re-claim resumes.
- **Carry-forward 2 (plan 16).** `non_usd_ccy` and `unknown_subtype_nonzero` stops now write `census` (`by_ccy`, `by_inst_type`, `by_sub_type`, `unknown_zero_effect`, counts only, same keys as a clean census), pinned by independent literals in `test_okx_archive_job.py#TestIngestStops` and `test_okx_archive_apply.py#TestEvaluationStops`.

### Plan phrasing notes

- **Resumability rule 3 vs the fingerprint.** The plan's "target whose fresh row set is empty but whose expected narrowed gaps differ" cannot arise from live rows filling a gap that the preview planned to write: those days leave the planned set and the fingerprint moves first, so the stop is `fingerprint_mismatch`. The `rpc_refused ... empty_rows_gap_delta` path is reachable with a MATCHING fingerprint when a stored gap lies in a quarter that was not ingested and a live row already sits inside it (nothing planned, gaps would still narrow); that is the scenario the test uses, and it stops the whole apply before any call.
- **`insert_days` on an `applied` answer** is the preview's count. If the RPC reports a smaller `inserted` (a live day appeared since the read and kept its row, D-12), a counts-only warning is logged and the result keeps the preview's number; Result shape v1 has no key for the difference.
