## Decisions this plan records

- **DEC-09-A Cause carries the strategy id.** The ops_alert window is keyed by (source, cause, event) for 3600
  seconds. With one shared cause, two different strategies exhausting within an hour would collapse into one
  page and the second would be lost. `readmit_ceiling:` plus a lowercase uuid is 52 characters, inside
  OPS_ALERT_CAUSE_RE. The strategy id is an internal identifier that the reconcile-sweep Sentry event already
  carries.
- **DEC-09-B Delivery-gated stamp.** It follows mt5_outage_alert's `_finish_recovered` shape: stamp only on
  `await_delivery(...)` True. The stamp is `UPDATE ... SET paged_at = now() WHERE id = <row> AND paged_at
  IS NULL`, so two processes cannot both stamp. They can both page, and a duplicate page is accepted (at
  least once beats at most once for a stranded strategy).
- **DEC-09-C Placement.** It is a guarded call in watchdog_loop, throttled by its own module-level interval
  like sweep_expired_trade_reads, with no new task or loop.
