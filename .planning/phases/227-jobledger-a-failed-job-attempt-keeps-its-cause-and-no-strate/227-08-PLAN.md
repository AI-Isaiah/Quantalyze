## Decisions this plan records

- **DEC-08-A Fail closed on an unknown renew error, open on a missing RPC.** Dispatching a job whose
  ownership could not be confirmed is exactly the run-twice defect, so an unknown error skips the job. The
  watchdog returns it to the queue, which costs latency and never correctness. A missing RPC means the worker
  deployed ahead of the migration, or the migration was rolled back. Treating that as "skip" would stall every
  job, so it dispatches as before. PostgREST reports a function missing from its schema cache as PGRST202,
  not 42883 (the routers/cron.py precedent treats the table-missing pair 42P01 and PGRST205 as one
  condition), so both codes are the missing-RPC condition here.
- **DEC-08-B Never renew the running row** (RESEARCH anti-pattern). Its staleness stays governed by its own
  override, which `test_watchdog_threshold_exceeds_handler_timeout` keeps above its handler timeout. A
  loop-blocking freeze stops the heartbeat too, so a dead worker's waiting rows still age out and reset.
- **DEC-08-C Interval.** `_CLAIM_RENEW_INTERVAL_S` is 120 seconds. An import-time check requires it to be
  above 0 and below the smallest watchdog threshold (the minimum of the 10-minute default and every per-kind override), so a misconfiguration fails at
  boot rather than letting waiting rows reset. The renewal covers every kind's waiting rows, not only derive.
- **DEC-08-D The comment pointer moves in the same change.** The RESIDUAL comment on
  `WATCHDOG_PER_KIND_OVERRIDES["derive_allocator_equity"]` and the docstring in test_main_worker.py both cite
  `[166.5.1-DERIVE-BATCH-RESET-RESIDUAL]`, which the ship deletes from TODOS. Each gets a dated line saying
  Phase 227 HEAL-02 closed it with the claim renewal (CLAUDE.md "TODOS.md holds open work only", rule (b)).
  The original text stays as lineage.
