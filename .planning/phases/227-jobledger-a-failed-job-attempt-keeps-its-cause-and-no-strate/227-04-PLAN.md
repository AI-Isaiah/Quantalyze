## Decisions this plan records

- **DEC-04-A A detector function, not an edit of the sweep (resolves a conflict between RESEARCH and a project rule).**
  RESEARCH Pattern 4 recommended re-registering the sweep with one added statement. This repo forbids that:
  under the Phase 164.7 rule, restated as D-02 in docs/runbooks/derivecron-go-live.md and as D-10 in
  src/__tests__/outagealert-migration-schedules-nothing.test.ts, a migration never schedules or re-registers
  a job, because migrations auto-apply to PROD with no human gate. Registration is a marker-guarded runbook
  step. No migration since 20260907120000 makes the schedule call. The sweep's command therefore stays byte-identical.
  `public.record_reconcile_readmit_exhaustions()` evaluates the sweep's own candidate predicate with the
  ceiling inverted, and writes the durable rows. This also leaves the sweep's 40 RED-UNDER twins, its TS pins
  and the pytest pointer untouched.
- **DEC-04-B Who calls it.** Plan 09's Python reader calls the detector, then reads the unpaged rows. That
  keeps the ruling's split: SQL decides the ceiling and writes the durable row, and Python only pages. It
  also adds no new cron job. The ruling's reversibility note names a table and an ops_alert source, not a
  job. If plan 09's reader does not run, nothing pages and no new row is written. That is the same blind
  spot the page has, because the worker is also what would run any readmit.
- **DEC-04-C Once per exhaustion.** `generation_key` is the id of the newest marker row (by created_at desc,
  id desc), with `UNIQUE (strategy_id, generation_key)`. Re-detection is a no-op. A strategy that cycles
  again after its old markers age out has a new newest marker, so it gets a new row and a new page.
- **DEC-04-D Bounded.** The detector writes at most 100 rows per call, in the sweep's own order.
- **DEC-04-E Drift pin against PROD.** Future sweep changes happen through a runbook plus a manifest
  re-capture, not a migration. So the parity vitest reads the PROD-captured manifest, not 20260819150000.
- **INT-1 reach (RESEARCH, stated plainly).** Real worker-started orphans usually leave a 'computing' or
  'failed' analytics row, and that row drops them out of the sweep before the ceiling applies. So this
  signal guards a narrow population: the claim-to-mark window with no analytics row. The arms seed that
  state. Widening the sweep's analytics conjunct is out of scope.
