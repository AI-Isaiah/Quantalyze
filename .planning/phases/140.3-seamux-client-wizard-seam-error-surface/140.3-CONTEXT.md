<decisions>
## Implementation Decisions (LOCKED)

### The organising principle
The route×consumer walk (15 routes × 7 failure modes, both sides) found **four themes**. Plan around
these, not around a file list:

1. **Stale money data survives a failure** — the CRITICAL. Isolated, and the correct pattern already
   exists in the codebase.
2. **Copy that asserts something false about the user's data or key** — 8 routes.
3. **Silent success on failure** — an unrecognised 200 starts a 15-minute poll; a breaker trip reads
   as a completed recompute; a scope probe **fails OPEN**.
4. **Envelope fragmentation** — five shapes, two mechanisms, `code` absent on 7 of 10 emitters. This
   is the **root cause under most of theme 2** — fix it first or the copy fixes are point-fixes.

**Theme 3 must be planned as ONE unit and must NOT wait behind copy fixes** — `finalize-wizard`'s
fail-OPEN scope probe is a **security gate**, not an error-rendering concern.

### Locked technical decisions
- **B-26 is CRITICAL and money-bearing.** `PortfolioOptimizer.tsx:204-206` sets `error` but never
  clears `suggestions`; the render guard at `:233` only shows the error when `!suggestions`, so it
  falls through to `:302` — **the success branch** — leaving the previous ranked allocation on screen
  with live, clickable "Add to portfolio" links under a small red line. The breaker 503 IS correctly
  detected; the defect is purely that the invalidated result is not discarded.
  **Fix shape already exists one directory away:** `WeightOptimizerSection.tsx` calls `setResult(null)`
  before every re-run. Use it; do not invent a new pattern.
- **B-14 is a publish gate failing OPEN.** `finalize-wizard`'s scope probe casts `as LivePermissions`
  and only rejects on explicit `true`, so a 2xx `{}` or a renamed field publishes **a key holding
  trade/withdraw scope as read-only-verified** — contradicting the fail-CLOSED doctrine written 40
  lines above in the same file. Schema-validate and fail CLOSED.
- **A retry affordance must never be the sole route to a destructive control (TRAP-4).**
  `/api/keys/sync` is limited to 5/60s and denies **codeless**; if codeless falls through to a branch
  rendering the delete-draft button as the SOLE control, five clicks of our own copy destroys the
  composite draft. A previous fix batch shipped exactly this.
- **Do not steer users into the C-01 dead end.** `csv-finalize` retry after Python has committed
  returns `WIZARD_DUPLICATE` with no `strategy_id` → 502 "Please retry." forever. 140.1 fixes the
  reply contract (PYAPI-09); this phase must not add retry affordances that assume it already landed.
- **`CIRCUIT_OPEN_COPY` must have ONE source of truth.** It is duplicated across 10 production files
  and re-declared in 12 test files, each asserting byte-identity against **its own copy** — a
  self-referential oracle. Changing a route's copy AND its own test together is GREEN today.
- **Naming an error arm can turn a vague error into a specific lie (TRAP-3).** `.single()` returns
  `data: null` for not-found, not-owned **and transport errors**; naming that arm "your draft is
  gone" while discarding `error` tells users something false and offers "start fresh".

### Claude's Discretion

  component test vs e2e split.

## 🔧 CORRECTIONS TO THE LOCKED DECISIONS — 2026-07-27, at this phase's own planning gate

The researcher and pattern-mapper contradicted each other on four checkable facts. All four were
verified first-hand by the orchestrator before planning. **The locked text above is preserved
verbatim for provenance; where it conflicts with a correction below, the CORRECTION governs.**

### C-1 — ⚠️ The `CIRCUIT_OPEN_COPY` "self-referential oracle" framing is INVERTED. Do not consolidate the tests.

The locked decision says the ~12 test re-declarations each assert byte-identity *"against its own
copy — a self-referential oracle."* **That is backwards.**

```
grep -rn "export const CIRCUIT_OPEN_COPY\|export .*CIRCUIT_OPEN_COPY" src/ tests/   →  0 hits
```

**No production `CIRCUIT_OPEN_COPY` is exported anywhere.** The test literals therefore *cannot* be
reads of the module under test — they are hand-typed literals, which is exactly correct oracle
independence, and `keys/sync/route.seam.test.ts` says so in a comment. **A plan that consolidates
the 12 test literals onto one shared constant would DELETE a working fence and manufacture the
self-referential oracle that does not currently exist. That is TRAP-9, and TRAP-9 is binding.**

The real gap is the *other* direction: **nothing pins any production copy to any other production
copy.** Ten independent production constants can drift apart and every test stays green. SC2
("drift between any two production copies fails a test") is about **production↔production**, not
test↔production. Fix that; leave the test literals alone.

*Count note (both agents agree): 15 files under `src/` mention the symbol; only 6 test files name
it. Grep the STRING, not the const — grepping the symbol finds 6 of 12.*

### C-2 — `ScenarioCommitDrawer.tsx` is NOT a Class-5 seam site. `140.3-01` names a non-member.

The file exists (the pattern-mapper's "path does not exist" is wrong), but its `body.detail ??` read
is gated at `res.status === 409 && … code === "portfolio_fingerprint_stale"`, and
`src/app/api/allocator/scenario/commit/route.ts` **imports no seam module at all**. The `detail` it
reads is a hand-written string the route itself emits. The nested envelope is structurally
unreachable there.

This false claim is currently repeated in **three** places: TS-05's ledger row, `STATUS_CONTRACT.md`
§2.1, and **`140.3-01-PLAN.md` itself**. Its provenance is a *syntax* grep for `detail ??` — the
recurring defect class of this programme. **`140.3-01` must drop it and the two docs must be
corrected in the same pass.**

### C-3 — `PortfolioImpactPanel.tsx` IS a real, uncovered Class-5 member, and it is NOT a safe template.

`STATUS_CONTRACT.md` §2.1 and `140.3-01-PLAN.md` both offer it as the fix shape to copy. It is the
opposite. `ErrorResponseSchema.safeParse(raw)` runs *two lines above* its `typeof body.detail ===
"string"` check, and `src/lib/api/errorSchema.ts` declares `detail: z.string().optional()` — so a
nested `service_error` body fails the parse, collapses to `{}`, and `error` / `retryAfter` / `detail`
are **all discarded** before the `typeof` check is ever reached. It fetches `/api/simulator`, a real
seam route. **Copying its shape propagates the defect.**

⇒ **The Class-5 membership is still 3, but it is a DIFFERENT 3.** Swap `ScenarioCommitDrawer` out,
swap `PortfolioImpactPanel` in. Shipping the list as written would have fixed a non-member and left
a real member open — while citing the broken member as the template.

### C-4 — TS-32's `BLOCKED-BY: TS-05` names the wrong row. The real blocker is TS-35.

`VenueTransientHTTPException`'s guard admits any `400 ≤ status < 500` and its serialiser emits
`{detail, code, recoverable}` **independent of status** — so the `400 → 424` remap is *body-neutral*
and `"[object Object]"` is structurally impossible. TS-05 is not a prerequisite.

What the remap *is* blocked on is stated in the class's own docstring: *"changing the status alone
buys nothing, because the status is discarded"* — `classifyKeyValidationError` derives both the
wizard code and the returned status from the message string. The row that fixes that is **TS-35**.

**And the remap has a cost no document names:** it reddens `EXPECTED_STATUS = 400` (asserted in 4
places, with an argued failure message) **and all 14 `"status": 400` cases in the committed fixture
`validate_key_venue_transient_contract.json` — which is the exact byte-source TS-35's new parity test
is instructed to bind to.** Sequenced wrong, this phase binds a test to bytes it then invalidates.

⇒ **Schedule as ONE unit: TS-35 (read `body.code`) → TS-32 (remap + fixture + `EXPECTED_STATUS` in
the same commit).** TS-05 sequences independently.

### C-5 — Two classes are UNDER-counted. Both extra members are money- or security-bearing.

- **B-26 has ≥2 live members, not 1.** `src/components/connect/KeyPermissionBadge.tsx` is the second:
  `load` calls `setError(null)` and `setPerms(data)` but **never `setPerms(null)`**, and
  `{loading && !perms && …}` / `{perms && …}` are independent siblings — so "Re-check" during an
  outage renders the **previous Read/Trade/Withdraw verdict** beside the error. That is a stale
  *security* claim about a money-bearing key. (`ReplacementPanel` is a latent third, unreachable only
  because its sole parent conditionally mounts it — pin it, don't fix it.)
- **B-14's unchecked-cast class has 2 members, not 1** — `keys/[id]/permissions/route.ts` does the
  identical unchecked cast over the same upstream **and caches the result for 60 s**. So C-05's
  "the sibling badge route validates" is false, and that cache is C-06's mechanism.

### C-6 — TS-35 under-counts by one, and the third member fails *silently*.

Replaying the cascade's real predicates over the committed fixture's own bytes: `EXCHANGE_UNAVAILABLE`
and `NETWORK_UNAVAILABLE` fall to `UNKNOWN` as the row says — but **`DDOS_PROTECTION` matches
`KEY_IP_ALLOWLIST` and returns 502**, because its detail ends *"Check region / IP allowlist."* and the
cascade's fifth branch tests `includes("ip") && includes("allow")`. **A venue WAF block is rendered
to the user as a problem with their key.** An audit asking *"does it fall through to UNKNOWN?"*
cannot see this one. Bind the parity test to the fixture's **outcomes**, not to UNKNOWN-ness.

### C-7 — Three claims downgraded (do not plan work against them as written)

- **B-11 / B-23 are the same finding**, attributed to different files; B-23 is the source-verified
  one. **Zero of the four wizard surfaces read `Retry-After`** — `SyncPreviewStep`'s "retry" is a
  client-side timer (`elapsedMs >= RETRY_THRESHOLD_MS`). The complete client reader class is three
  sites, exactly one of which (`PortfolioImpactPanel`) is a seam route, and it is 429-gated.
  ⚠️ **`WizardErrorContext` and `ErrorEnvelope` carry no wait field at all** — SC4's "name the real
  wait" is *unrepresentable*, not merely unimplemented. That is plumbing, and it must be budgeted.
- **TRAP-3 does not describe live code.** `finalize-wizard` already uses `.maybeSingle()` and splits
  `strategyErr` (500, scrubbed) from `!strategyRow` (`GATE_DRAFT_GONE`). It is a **template**, not a
  defect. Residual: that arm still conflates not-found with not-owned.
- **TS-33 is narrower than its row.** `wizard_session_id` is **live on the CSV path today** —
  `csv-validate` and `csv-finalize` both send it in the `postProcessKey` context and Python reads it
  from exactly there. True scope: one call site (finalize-wizard) sends no id.

### C-8 — The sharpest finding: SEAMUX-03 and TRAP-4 collide at exactly one site

SEAMUX-03 requires giving `keys/sync`'s five codeless arms a code. The natural code for the **404
arm** is `GATE_DRAFT_GONE`, whose only actionable control is `start_fresh` — and `WizardClient.tsx`
calls `handleDeleteDraft()` **unconfirmed**, bypassing the confirm dialog the chrome's Delete-draft
button uses. That same 404 arm is **TRAP-3 live**: it destructures `data` and discards `error`, so a
Supabase blip during our outage says "Strategy not found".

**One change closes SEAMUX-03, TRAP-3-live and TRAP-4 together; three separate changes TRIP TRAP-4.**
Plan it as one task. *(TRAP-4 is confirmed NOT tripped today — `SyncPreviewStep` maps every non-2xx
to `SYNC_FAILED`, whose actions are `clear_and_retry` / `request_call`. Pin that negatively.)*

### C-9 — Scope corrections that make the phase bigger

- **CONTEXT names 2 Sentry-less routes; the real class is 9 of 15.** Both named lies confirmed

- **`SubmitStep.tsx` is one line causing three SC failures at once** — `KNOWN_FINALIZE_CODES` omits

  notified" *and* emits `wizard_error {code:"UNKNOWN"}`. Fixing that one line moves SC1, SC2 and SC6.

Zero `"use server"` files repo-wide; no server component reaches the seam (a breaker trip can never
500 a page); poll paths structurally disjoint from breaker-feeding paths; short-circuit asymmetry
