# Phase 140.3 Plan G5: SEAMUX-03 coded arms on scenario/optimize + simulator Summary

Both direct analytics-client consumer routes now emit a top-level machine `code` on
every error arm they own (11 + 10 = 21 arms, baseline was 0/12 and 0/8), so a client
discriminates the fault on a stable token instead of sniffing prose. Forwarded upstream
arms preserve `err.seamCode ?? "UNKNOWN"`; per-arm tests redden if any code is dropped.

## What shipped

- **scenario/optimize** — 11 coded own arms; `npx vitest run src/app/api/scenario/optimize` → 32 passed.
- **simulator** — 10 coded own arms including the inline 429 and limiter-misconfigured 503; → 29 passed.
- Both suites together: **61 passed**. `npx tsc --noEmit` exit 0. `eslint` on all four files exit 0.
- `code:` comment-stripped floors met exactly: scenario/optimize **11** (≥11), simulator **10** (≥10).

## Helper-arm exclusions (named, per plan `<interfaces>`)

- **`assertProfileApproved` 403** (both routes) — emitted by a helper shared across 73+ API
  routes; the verifier accepted keys/sync as complete with the equivalent `withAuth` 401
  untouched. Left uncoded.
- **`rateLimitDenyJson` 429/503** (scenario/optimize only) — the deny body is built by the
  limiter helper, not inline in the route. Its 429 body is asserted by an exact `toEqual`
  in the existing SEAMRIM-05 test; coding it would both exceed scope and redden that pin.
  (simulator's 429/503 are hand-built inline and therefore IN scope — coded above.)

## Deviations from Plan

None — plan executed exactly as written. All arm-to-code mappings matched the plan's
`<action>` blocks line-for-line (line numbers shifted +1 on scenario/optimize's 401 and
by the additive-field width elsewhere; classification unchanged).

Two plan premises confirmed correct against the code rather than assumed:
- scenario/optimize's 429 goes through `rateLimitDenyJson` (helper) — the plan's floor of
  11 own arms excludes it, which the exact-`toEqual` SEAMRIM-05 test corroborates.
- simulator's 4xx-forward 422 case (null seamCode) correctly falls to `UNKNOWN`; a 5xx
  AnalyticsUpstreamError falls THROUGH the 4xx arm to the terminal 500 → `UNKNOWN`.

## Threat surface scan

No new security-relevant surface. All new tokens are closed-set stable strings; none names
an env var, host, or internal service. The seamCode forwarding forwards only what the body
already carried. Limiter behaviour untouched (additive code only; Retry-After and retryAfter
byte-kept) — T-140.3-G5-01/02/03 mitigations hold.
