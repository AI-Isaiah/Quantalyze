## Summary

This phase is a **render-surface repair**, not a greenfield build. Every library it needs is already
installed and already used at a named site in this repo (`zod` 4.4.3 for fail-closed schema
validation; `src/lib/retry`'s `parseRetryAfterSeconds` for waits; `src/lib/wizardErrors.ts` +
`src/lib/envelope.ts` + `src/components/error/ErrorEnvelope.tsx` for copy). **No package is
installed by this phase.** The research value is therefore not "what stack" but **"what is the actual
class, and how many members does it have"** — because every enumeration this programme inherited has
been wrong in at least one direction, and three of them are wrong right now.

The four themes CONTEXT.md locks are all confirmed at source. But **three inherited claims are false
or stale**, and one of them would send a plan to edit a file that has no relationship to the seam:

1. **`ScenarioCommitDrawer.tsx:622` is NOT a Class-5 seam site.** `/api/allocator/scenario/commit`
   has zero seam imports; the `detail` it reads is a hand-written string the route itself emits on a
   `409 portfolio_fingerprint_stale`. The site was enumerated by SYNTAX (`detail ??`) rather than by
   BEHAVIOUR (reads a seam envelope) — PART 7 correction #3's lesson, recurring.
2. **`PortfolioImpactPanel.tsx` is NOT a safe fix-shape template**, and STATUS_CONTRACT §2.1 says it
   is. Its zod `ErrorResponseSchema` declares `detail: z.string().optional()`, so a nested
   `service_error` envelope **fails `safeParse` outright** and discards `error`, `retryAfter` and
   `detail` together. Verified by running zod 4.4.3.
3. **TS-32's `BLOCKED-BY: TS-05` premise is stale.** The seven sites now raise
   `VenueTransientHTTPException`, whose serialiser emits `{detail, code, recoverable}` **regardless
   of status**. A 400→424 remap is body-neutral and cannot produce `"[object Object]"`.

Two under-counts also surfaced: the B-26 stale-result class has **at least two live members**, not
one (`KeyPermissionBadge.tsx` is the second, on a security-relevant surface); and the B-14 unchecked-
cast class has **two members**, not one — `keys/[id]/permissions/route.ts` casts identically and then
caches the result for 60 s, so C-05's "the sibling badge route validates" is false.

**Primary recommendation:** Build one new dependency-free leaf `src/lib/seam-copy.ts` (the
`seam-discriminator.ts` / `seam-errors.ts` shape, purity-guarded), collapse the 10 production
`CIRCUIT_OPEN_COPY` declarations onto it, and pin cross-copy drift with a `seam-constants.pin.test.ts`-
style literal-against-literal test. Then sequence theme 3 (fail-closed + observe-the-outcome) FIRST
and independently of the copy work, because **SEAMUX-03 and TRAP-4 are in direct tension at exactly
one site** and that site must be planned deliberately, not discovered mid-execution.

> ⚠️ **A NUANCE THE CONTEXT FRAMING GETS WRONG, and it matters for the test strategy.**
> The 12 test occurrences are **hand-typed literals, not reads of the module under test** — they
> *cannot* be reads, because none of the ten production constants is exported.
> `keys/sync/route.seam.test.ts:172-174` states the discipline out loud:
> *"Static copy the route is allowed to emit. Duplicated deliberately: a test that imported the
> constant from the client could not detect it changing."*
> **So these are NOT self-referential oracles in the `seam-constants.pin.test.ts` sense** — they are
> correct oracle-independence practice, and a planner who "fixes" them by importing a shared constant
> would DESTROY the property SEAMUX-01 depends on.
> The real defect is narrower and different: **nothing pins any production copy to any OTHER
> production copy.** Changing route A's string + route A's own test is green while A now differs from
> B..J. That is a *cross-copy drift* gap, not an oracle gap. Plan for it accordingly.

**Recommended shape — a new dependency-free leaf.** Two facts constrain it:
(a) `wizardErrors.ts` is value-imported by ten `"use client"` components and already imports
`CircuitOpenError` from `@/lib/seam-errors` precisely because that leaf has zero imports;
(b) six of the ten emitters (`bridge`, `portfolio-optimizer`, `admin/match/*`, `scenario/optimize`,
`simulator`) have **non-wizard** consumers that do not import `wizardErrors.ts` at all.

⇒ Create `src/lib/seam-copy.ts` on the `seam-discriminator.ts` model: **zero imports, zero env reads,
zero module-load side effects**, registered with a purity guard
(`src/lib/seam-discriminator.purity.test.ts` is the working template). Export the seam copy constants
from it; have all ten production sites import from it; have `WIZARD_ERROR_COPY.SERVICE_UNAVAILABLE_RETRY`
reference it. **Keep all 12 test literals exactly as they are**, and add ONE new
literal-against-literal pin file (the `seam-constants.pin.test.ts` idiom) that asserts the leaf's
exported string equals a hand-typed literal — so drift reddens once, centrally, without collapsing
the twelve independent per-route oracles.

**The `CIRCUIT_OPEN` → wizard-code gap, proven at source (B-01).**
`src/lib/wizardErrors.ts` already carries a good code, `SERVICE_UNAVAILABLE_RETRY`, with correct copy
("*We paused outbound requests after repeated failures so the service can recover. Your key has not
been saved and nothing was submitted — this is on our side, not your key.*"). But
`SubmitStep.tsx:124-135`'s `KNOWN_FINALIZE_CODES` is a five-member `ReadonlySet`:
`KEY_SCOPE_BROADENED`, `KEY_NETWORK_TIMEOUT`, `GATE_DRAFT_GONE`, `GUARD_BLOCKED`,

`SERVICE_UNAVAILABLE_RETRY` is a member**, so a breaker trip at finalize takes the
`: "UNKNOWN"` arm at `:139` — which renders "*Our team has been notified*" AND emits

`classifyKeyValidationError`, whose `err instanceof CircuitOpenError` branch answers

#### ⚠️ FALSE CLAIM #2 — `PortfolioImpactPanel.tsx` is not a safe template

`STATUS_CONTRACT.md` §2.1:178-179 states *"`src/components/portfolio/PortfolioImpactPanel.tsx:76-77`
already type-checks and is the fix-shape template."* `140.3-01-PLAN.md` repeats it as *"Copy its shape

**The `typeof body.detail === "string"` check is unreachable for the nested envelope**, because two
lines above it the body passes through `ErrorResponseSchema.safeParse` and
`const body = parsedError.success ? parsedError.data : {}`. `src/lib/api/errorSchema.ts:22` declares
`detail: z.string().optional()`. Measured first-hand against the installed **zod 4.4.3**:

```
input : { error: "Analytics service error", retryAfter: 30,
          detail: { code:"SEAM_DEGRADED", dependency:"supabase", retryable:true, detail:"…" } }
result: success = false
```

⇒ `body` becomes `{}`, so `body.error`, `body.retryAfter` **and** `body.detail` are all discarded;
`serverMessage` is `undefined`; the component logs "unrecognized error body shape" and throws
``new Error(`HTTP ${res.status}`)``. **On the exact envelope this phase exists to render, the named
template throws away the entire error body.** Copying it would propagate the defect.

**Correct guidance:** the fix-shape template is the leaf itself —
`seamHumanMessage(body)` / `seamErrorCode(body)` from `src/lib/seam-discriminator.ts`, applied to the
**raw** parsed JSON *before* any narrowing schema. `ErrorResponseSchema` needs `detail` widened (or a
`.passthrough()`/union arm) or `PortfolioImpactPanel` must read the raw body first. Either way this
is a **fourth class member and it is not in any existing plan.**

### Pattern 1 — The dependency-free leaf (the ONE mechanism this programme keeps reaching for)

**What:** a module with zero imports, zero env reads, zero module-load side effects, guarded by a
purity test.
**When to use:** any value that must be reachable from BOTH a `"use client"` component and a route
handler, and must survive the 16 route-test files that `vi.mock` the seam clients wholesale.
**Why it is not optional here:** `wizardErrors.ts`'s own docblock spells out both failure modes —
a non-leaf import drags `@upstash/redis`, `@upstash/ratelimit` and a top-level `Redis.fromEnv()` into
the wizard bundle for every user; and a class reached *through* a mocked module is `undefined`, so
`x instanceof undefined` **throws from inside the catch block**, converting a clean 503 into a crash.

```ts
// Source: src/lib/seam-discriminator.ts (in-repo, shipped by 140.2-06)
// ⚠️ LOAD-BEARING LEAF. Zero imports, zero env reads, zero module-load side effects.
export function seamHumanMessage(body: unknown): string | null {
  if (!isPlainObject(body)) return null;
  const detail = body.detail;
  if (typeof detail === "string") return detail;          // both FLAT shapes (§2.1)
  if (isPlainObject(detail)) {                            // the nested envelope (§2)
    return typeof detail.detail === "string" ? detail.detail : null;
  }
  return null;
}
```

### Anti-Patterns to Avoid

- **Enumerating a class by SYNTAX.** `grep "detail ??"` produced a three-member class of which one

## Common Pitfalls

### Pitfall 1 — Enumerating the class by the shape of the known instance
**What goes wrong:** a "fix every site" instruction closes 3 of 5, 5 of 7, 1 of 2.
**Why it happens:** the grep is written from the defect's syntax, not its behaviour.
**How to avoid:** for every class in this phase, state the behavioural predicate, run the grep,
**read each hit**, and record both the members and the non-members with the reason. This document does
that for all seven classes it touches.
**Warning signs:** a site list with no rejected candidates listed beside it.

### Pitfall 2 — The substring cascade's accidental matches
**What goes wrong:** new copy silently changes classification.
**Why it happens:** `classifyKeyValidationError` tests `lower.includes("ip")`, `lower.includes("rate")`,
`lower.includes("probe")`, `lower.includes("trading")` — raw substrings, ordered, first match wins.
`"ip"` matches inside *multiple, description, recipient, script*; `"rate"` inside *accurate, generate,
separate, moderate*.
**How to avoid:** the `body.code` branch must sit **above** the cascade, as the `CircuitOpenError`
type check already does. Any new copy string must be checked against every branch predicate — the file
already documents this discipline for the MT5 strings ("Collision invariant — re-run if EITHER side is
reworded").
**Warning signs:** a copy edit with no accompanying cascade re-check.

### Pitfall 3 — A narrowing zod schema silently eating the whole body
**What goes wrong:** `safeParse` fails on ONE mistyped field and the caller falls back to `{}`,
losing every other field including the ones it needed.
**Why it happens:** `z.object` rejects the object when any declared key has the wrong type.
**How to avoid:** for **error** bodies use a union or a permissive shape; for **decision** bodies
(the permission gate) keep it strict and fail CLOSED. The two directions are opposite and the same
schema style cannot serve both. `ErrorResponseSchema` is the live counter-example.
**Warning signs:** `parsed.success ? parsed.data : {}` over a body whose shape is not fully enumerated.

### Pitfall 4 — Fixing a route's copy and its own test together
**What goes wrong:** green, while that route now differs from the other nine.
**How to avoid:** the cross-copy pin (Pattern 2) must exist **before** any copy edit, or the edit is
unfalsifiable.
**Warning signs:** a diff touching `route.ts` and `route.test.ts` and nothing else.

### Pitfall 5 — TRAP-8: two changes to one block in one pass
**What goes wrong:** C5 undid C6 in a previous batch.
**Where it bites here:** `keys/[id]/permissions/route.ts` is touched by `140.3-01` (the extraction),
TS-34 (status + `Retry-After`), the copy plan (`CIRCUIT_OPEN_COPY`), and SEAMUX-07 (the second
unchecked cast). **Four plans, one file.** Sequence them into distinct waves and state the ordering.

### Pitfall 6 — Stale coordinates
**What goes wrong:** three stale-coordinate incidents inside a single phase, one caused by a fixer's
own in-flight edit.
**How to avoid:** cite by unique grep-able code text. Every citation in this document is either a
searchable string or a line number **read today** and marked as such.

### Pitfall 7 — TRAP-9 inverted
**What goes wrong:** naming tests that "must be updated" when they are actually the regression fence.
**Where it bites here:** the twelve `CIRCUIT_OPEN_COPY` test literals, and
`analytics-service/tests/test_validate_key_venue_transient.py`'s seven wire pins. The former must
**not** change; the latter's *status* expectations **must** change with the remap and nothing else.

### Oracle Independence

The self-referential oracle is this programme's proven primary failure mode: Phase 140 certified
"5/5 mutation-tested" while **ten simultaneous semantic mutations** produced a byte-identical
`8859 passed | 287 skipped`. Named hazards for **this** phase:

1. **The twelve `CIRCUIT_OPEN_COPY` test literals — the hazard is the OPPOSITE of what CONTEXT says.**
   They are hand-typed and cannot be reads (nothing is exported), and `keys/sync/route.seam.test.ts`
   states the discipline explicitly. **Do not "consolidate" them onto the new leaf** — that would
   convert twelve independent oracles into one self-referential one. The real gap is that no test
   compares any production copy to any OTHER production copy; close it with ONE new pin file, and
   leave the twelve alone. **A plan that deletes them is deleting the fence (TRAP-9).**
2. **`WIZARD_ERROR_COPY` assertions.** Any new copy test must type the expected sentence as a literal
   in the test file. Reading `WIZARD_ERROR_COPY[code].title` on the expected side of an `expect` is the
   defect. (`CsvSubmitStep.tsx:196` already does exactly that in PRODUCTION — legitimate there, fatal
   in a test.)
3. **The TS-35 parity roster.** Derive the expected wizard code / status / recoverable from a
   hand-typed `Record`, never from the fixture and never from `classifyKeyValidationError`. Include the
   silent-shrink guard: exactly 14 cases, exactly 7 distinct codes, exactly 1 non-recoverable.
4. **The `seam-copy.ts` pin.** Its expected string must be typed in the test. A pin that does
   `expect(SEAM_COPY.circuitOpen).toBe(SEAM_COPY.circuitOpen)` is the shape to grep for and forbid.
5. **Zero module mocks in the parity file.** The acceptance grep for the S-5 pattern counts the vitest
   module-mocking call and requires 0. *"A second pair of mocks agreeing with each other is not a fix
   — it is the defect, recreated."*
6. **Sixteen route test files `vi.mock` the seam clients wholesale.** Any predicate this phase reaches
   through such a module evaluates to `undefined` and throws from inside a catch block. **Everything
   this phase adds that a catch arm touches must live in a dependency-free leaf.**
7. **`vi.mock` factories do NOT re-run on `vi.resetModules()`** (D-02, measured at vitest 4.1.10). Any
   negative control built on the opposite premise is a silent false green.
8. **No global `unstubGlobals` safety net** (D-05). A leaked `vi.stubGlobal("fetch")` is this repo's
   known CI-only failure cause (CI Node 22 vs local Node 25). Add `vi.unstubAllGlobals()` in
   `afterEach` for every new file that stubs fetch.
