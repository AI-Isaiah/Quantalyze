## ⚠️ C-8 — ONE change closes three things; three separate changes TRIP a trap. Task 1 is indivisible.

This is the sharpest finding in the phase, and it lands at exactly one site.

- **SEAMUX-03** requires giving `keys/sync`'s five codeless arms a code. The natural code for the
  **404 arm** is `GATE_DRAFT_GONE`.
- **`GATE_DRAFT_GONE`'s only actionable control is `start_fresh`** (its other action is
  `request_call`, a contact form, not a way forward).
- **`start_fresh` is strictly MORE dangerous than the chrome's Delete-draft button.** `WizardChrome`
  renders `Delete draft` → `onDeleteDraft={() => setConfirmDelete(true)}` → a confirm dialog. But
  `WizardClient.tsx`'s `handleStartFresh` calls `await handleDeleteDraft();` **directly, unconfirmed**,
  bypassing that dialog.
- **And that same 404 arm is TRAP-3 LIVE.** It does
  `const { data: strategy } = await supabase…single();` — **destructuring `data` only and discarding
  `error`** — so a Supabase transport blip *during our own outage* produces "Strategy not found" ⇒
  `GATE_DRAFT_GONE` ⇒ one unconfirmed click deletes an **intact** draft.

⇒ **SEAMUX-03 + TRAP-3-live + TRAP-4 are ONE task.** Landing the code without the `error` split and
without the confirmation is the exact change that trips TRAP-4, and *"a previous fix batch shipped
exactly this."*

## ⚠️ TRAP-4 is NOT tripped today. Pin that NEGATIVELY.

Verified: `SyncPreviewStep` maps **every** non-2xx to `SYNC_FAILED`, whose actions are
`["clear_and_retry", "request_call"]` — no `start_fresh`. The trap is latent, and this plan is the
change that could wake it. The negative pin is therefore not ceremony; it is the guard on this
plan's own blast radius.

## ⚠️ The `start_fresh` class is FOUR, not three — corrected first-hand at this planning gate

`140.3-RESEARCH.md` Q5 gives the class as "3 of 3". **`grep -n "start_fresh" src/lib/wizardErrors.ts`
returns four `actions` arrays**, and the fourth is `GUARD_BLOCKED`:

| Code | `actions` | Non-destructive alternative? |
|---|---|---|
| `DRAFT_ALREADY_EXISTS` | `["resume_draft", "start_fresh"]` | ✅ `resume_draft` |
| `GATE_NO_DATA_SOURCE` | `["start_fresh", "request_call"]` | ⚠️ only `request_call` |
| `GATE_DRAFT_GONE` | `["start_fresh", "request_call"]` | ⚠️ only `request_call` |
| **`GUARD_BLOCKED`** | `["clear_and_retry", "start_fresh", "request_call"]` | ✅ `clear_and_retry` — **missing from the research table** |

`GUARD_BLOCKED` is safe on the alternative test, but it is a class member and the guard test must be
written over the **whole `WIZARD_ERROR_COPY` table**, not over a hand-listed three. Enumerating by a
document's list rather than by the table is how "3 of 5" happens.
