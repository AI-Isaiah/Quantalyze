   SEAM_CODE_TO_WIZARD_CODE (wizardErrors.ts:1936) already recognises:
   CIRCUIT_OPEN (breaker open, nothing sent), UPSTREAM_TIMEOUT (our analytics
   deadline fired), UPSTREAM_NETWORK_ERROR (transport failure on our hop).

   `AnalyticsUpstreamError.seamCode: string | null` (analytics-client.ts:119);
   `seamErrorCode(body): string | null` (src/lib/seam-discriminator.ts:259)
   for raw forwarded bodies. Fallback when null: "UNKNOWN".

   keys/sync template's own precedent (MISSING_STRATEGY_ID :78,
   INVALID_STRATEGY_ID :90, DRAFT_LOOKUP_FAILED :193, SYNC_KICKOFF_FAILED :326
   — all non-union, all accepted arm-by-arm by the 140.3 verifier). This plan
   mints exactly ONE: VERIFY_PERSIST_FAILED. Never mint a synonym for a fact

WHY non-union tokens are legitimate (justification the orchestrator requires):
`WizardErrorCode` is the wizard COPY table's key space —
`Record<WizardErrorCode, WizardErrorCopy>` forces every member to ship
user-facing copy, an EXPECTED_TABLE_SIZE bump (currently 55, guarded twice),
and a TRAP-4 table scan. Arms no wizard renders must NOT force copy entries;
the template route itself emits four non-union tokens.

A route denying through defaults must pass `throttledBody` / `misconfiguredBody`
overrides carrying the byte-identical `error` string PLUS a `code` — exactly
keys/sync:136-158 and create-with-key:240-243.
