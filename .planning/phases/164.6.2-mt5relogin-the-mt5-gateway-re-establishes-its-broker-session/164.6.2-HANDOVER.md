# Phase 164.6.2 — MT5RELOGIN: founder handover

**⛔ This is the ONE step in this phase no agent may perform.** Criterion 3 is a founder
decision: no agent enters a credential, reads one back, or asks for one to be pasted. The
code path is built, wired and falsified (plans 01 and 02); the only thing missing is the
credential itself, and it is missing on purpose.

---

## 1. What you are being asked to do

Set three environment variables — `MT5_LOGIN`, `MT5_PASSWORD` and `MT5_SERVER` — on the
**`quantalyze-analytics`** Railway service, production environment, so the analytics worker
can re-establish the MT5 terminal's broker session by itself at each of its own startups.

⭐ **What makes this safe to do:** the **INVESTOR (read-only) password suffices.** Nothing in
this path places an order — only equity and positions are read (criterion 5), and the
per-account authentication that drives real syncs is unchanged (D-03). You never need to
hand over a master/trading password to make this work.

---

## 2. The exact command

Run this in your own terminal, substituting your own values for the three placeholders.
⛔ Every value position below is a PLACEHOLDER; nothing real has ever passed through an agent.

```bash
railway variables \
  --service quantalyze-analytics \
  --environment production \
  --set "MT5_LOGIN=<investor-account-number>" \
  --set "MT5_PASSWORD=<investor-password>" \
  --set "MT5_SERVER=<broker-server-string-exactly-as-MetaTrader-spells-it>"
```

**Why `quantalyze-analytics` and not `mt5-gateway`.** D-00 is a founder decision: the
worker-side shape was chosen over forking the gateway image precisely so the broker password
does NOT move into the gateway container's environment. The gateway reads only
`CUSTOM_USER`, `PASSWORD` (both VNC) and `mt5server_port`, and this phase does not widen that.

⭐ **Optional, and strictly better for the password:** the CLI can take a value from stdin
instead of from the command line, which keeps it out of your shell history and out of the
process argument list. Measured against `railway` 4.36.1 at HEAD:

```bash
railway variable set --service quantalyze-analytics --environment production --stdin MT5_PASSWORD
```

---

## 3. What happens next — and which part is an ASSUMPTION rather than a promise

- Setting a variable triggers a **redeploy** of the analytics service. (The CLI documents this
  by having a `--skip-deploys` flag to suppress it; do NOT pass that flag here.)
- That redeploy is, for our purposes, a **worker restart** — a new analytics process.
- A new analytics process runs `main.lifespan`, which starts `heal_mt5_terminal_session` as a
  background task. That is the boot heal, and it is what re-establishes the session.

⚠️ **The first bullet is RESEARCH assumption A5, not a measured fact, and this document will
not pretend otherwise.** Whether the redeploy actually fires, completes, and reaches the
gateway in a state where the heal can do its work is what plan 04 goes and OBSERVES. If it
does not heal immediately, that is not a failure — it is D-06's measurement producing its
answer.

⛔ **A known and deliberate limit, stated as a limit:** the heal fires at **ANALYTICS startup**,
not when the **gateway** restarts (D-08). So if the gateway restarts and loses its session, a
window exists in which the prober can still report the authorization failure until the
analytics service next starts. Measuring the size of that window is D-06's entire job, and it
is what closes this phase.

**One thing you do not need to change:** `MT5_ENABLED` was measured already set to `true` on
this service, and the heal consults that kill switch as its first statement. If it is ever
turned off, the heal returns silently and nothing is attempted.

**If the variables are absent or malformed**, the worker logs ONE warning naming only the
variable NAMES and carries on booting (D-02). MT5 is one arm of many; it never takes analytics
down. That is also why a green `/health` tells you nothing about whether this worked.

---

## 4. What NOT to do

- ⛔ **Do not set them on `mt5-gateway`.** See D-00 above. If they land there, the heal still
  has nothing to read and the broker password is now somewhere it was deliberately kept out of.
- ⛔ **Do not use master / trading credentials.** Investor (read-only) is sufficient and is the
  intended blast radius.
- ⛔ **Never paste a value into a chat, a PR, an issue, a commit message or a planning file.**
  This repository is PUBLIC and `.planning/` is TRACKED, so every byte here is world-readable
  once pushed. Confirmation back to the agent is **key-name only** — "all three are set" — and
  never a value.
- ⛔ **Do not perform a VNC login first to "help it along".** Establishing the session by hand
  would make the session exist for a reason other than the heal, and would destroy the exact
  observation criterion 2 was written to make. The whole point of this phase is that the hand
  login stops being the mechanism.

## 5. How you will know it worked

Three READ-ONLY instruments, none of which logs in. **Plan 04 runs them** — you do not have to.

| # | Instrument | Invocation | What it tells you |
|---|---|---|---|
| 1 | the repo's own diagnostic script | `./scripts/mt5-diag.sh` (from the repo ROOT — the Railway link is directory-scoped) | a `PROBE` line carrying `initialize`, `last_error`, `terminal_info` and, when readable, `trade_allowed` / `connected` |
| 2 | the narrowed prober arm | `gh workflow run prod-prober.yml -f arm=mt5` | the prober's own verdict for the mt5 arm — ⭐ this is the instrument criterion 2 closes on, because the arm is credential-less BY DESIGN |
| 3 | the scheduled prober | hourly, on the `prod-prober.yml` schedule | the standing baseline, with no dispatch needed |

⛔ **What does NOT verify this, and why it is listed:** a green `/health`, a passing test suite,
a completed Railway redeploy and a quiet log are **all** consistent with the three variables
being ABSENT — the heal is designed to log once and continue in exactly that case. None of
them is evidence. Only an explicit statement from you, plus a key-only listing, moves this
gate.

**What to tell the agent when you are done** (⛔ without quoting any value):

> "The three variables are set on quantalyze-analytics, production."

The agent will then confirm KEY-ONLY with
`railway variables --service quantalyze-analytics --environment production --kv`, filtered to
the three key NAMES — ⚠️ whose raw output carries other variables' values in the same stream
and is therefore NEVER pasted into an artifact, a commit message, a PR body or a transcript.
Only then does plan 04 begin.
