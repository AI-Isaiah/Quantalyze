⭐ **THE `_crash_handler` FINDING IS NEW AND IT IS THE SHARPEST HAZARD IN THIS PLAN.** RESEARCH's
Pitfall 4 covers a raise BEFORE `yield` (uvicorn startup abort). It does not cover the task region.
Placing the heal in the task region — which PATTERNS correctly recommends, because it must not
block the boot — puts it under `_crash_handler`, and a raising task there sets `SHUTDOWN`: the API
survives but the dispatch, watchdog and enqueue loops stop. **A silent analytics outage with a
green `/health`.** The never-raises property is therefore not a nicety; it is what makes the chosen
placement safe, and this plan asserts it twice — structurally (the function carries a top-level
catch-all) and behaviourally (every internal step made to raise, the coroutine still returns None).
