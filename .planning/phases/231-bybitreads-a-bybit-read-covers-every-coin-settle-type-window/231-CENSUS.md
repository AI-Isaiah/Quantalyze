# Phase 231 BYBITREADS: venue-by-path census

Written 2026-11-23, before any fix plan runs (ROADMAP SC-1, PITFALLS Pitfall 3). One row per Bybit
read path, by coin, settle type, window and flow source. Every row ends in a disposition and a pin.
This file cites `file::symbol` only: no line anchors, because Phases 223 and 232 also edit
`exchange.py`, `positions.py` and `bybit_unified_flows.py`.

## Row grammar

Columns: `# | Path (file::symbol) | Axis (C coin, S settle type, W window, F flow source) | Coverage today | Gap | Disposition`.

The Disposition cell is one of four forms, each ending in `pinned by` plus one or more test node ids:

- `fix in plan 0N`: a later plan changes the path; the pin is the test that plan adds or flips.
- `fixed by inheritance of C0N`: the path calls a helper another row fixes; no edit of its own.
- `decided: <reason>`: the path is left as it is, and a test already pins why.
- `decided after the probe (plan 05 fills the counts): <reason>`: the verdict needs the counts-only probe run; plan 05 records them.

Pin notation: a pin that resolves at HEAD is a backticked node id (`python3 -m pytest --collect-only`
from `analytics-service/` resolves it). A pin a later plan must add is written
`NEW(plan 0N): tests/<file>.py::<name>` with no backticks, and the name is the exact name that plan creates.
