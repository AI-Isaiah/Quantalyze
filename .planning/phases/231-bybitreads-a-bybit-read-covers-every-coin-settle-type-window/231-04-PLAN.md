<objective>
VREAD-03: a Bybit strategy trade sync whose start is more than seven days back returns every
execution in its window, or refuses by name.

Purpose: the reader sends `startTime` on the first page only and no `endTime`, and Bybit answers a
start-only request with seven days; a stale cursor or a first sync can therefore store a week and
move on. Making the read complete by construction is the real fix; the named refusal covers the
rare page-cap case.
Output: `_fetch_raw_trades_bybit` on `walk_paginated`, one named error class, four constants, the
VREAD-03 gates and flips, PROOF-01 records, and the recorded Phase 232 dependency.
</objective>

## Decisions this plan applies

- Template: `fetch_bybit_unified_flows` (page callback, contract, walk, dedupe by id). The "allocator
  rebuild windowed reader" CONTEXT names was deleted by Phase 176 (ruling note; RESEARCH F2).
- Contract: `fetcher="fetch_raw_trades_bybit"`, `page_cap=BYBIT_EXECUTION_WINDOW_PAGE_CAP`,
  `on_ceiling="raise"`, `stop_on_short_page=False` (Bybit is cursor-authoritative),
  `stuck_cursor_is_stop=False`, `window_max_days=7`,
  `default_lookback_days=BYBIT_EXECUTION_DEFAULT_LOOKBACK_DAYS` (365, ruling OQ2; without it
  `walk_paginated` walks a None start from epoch, PATTERNS gotcha 1),
  `ceiling_exc=<a constructor that discards the driver's message>`, `ceiling_label="BYBIT_EXECUTION_WINDOW_PAGE_CAP"`.
- Stuck cursor, one behaviour picked (PATTERNS conflict note, Rule 7): follow the unified-flows reader,
  the most recent and the only one pinned to "never a short list": a page that carries rows and
  returns the cursor it was sent raises `BybitTradeWindowIncomplete`. The legacy silent stop is
  retired and its test flipped, old and new expectation recorded.
- `BybitTradeWindowIncomplete(RuntimeError)` (not a `PaginationCeilingExceeded` subclass, so no
  existing `except PaginationCeilingExceeded` catches it by accident) carries a closed `reason`
  (`page_cap`, `cursor_stuck`, `start_too_old`) and a static text per reason with no digits. It falls
  through `run_sync_trades_job`'s generic phase-2 arm, which stores `str(e)[:200]` and DISCARDS the
  drained DQ flags; and through `run_reconcile_strategy_job`'s generic arm. Neither is edited.
- On a cap hit the reader still records `_record_dq_flag("sync_truncated_bybit", True)` and
  `("sync_truncated_bybit_pages", <cap>)` before raising, for any caller that drains; no criterion
  expects the flag to reach storage on a refusal.
- Clock seam: a keyword-only `now_ms: int | None = None` on `_fetch_raw_trades_bybit`
  (wall clock when None); `fetch_raw_trades` keeps calling it without `now_ms`.
- Page size `BYBIT_EXECUTION_PAGE_SIZE = 100` (the venue maximum). Constants are module-level and
  not `Final`, so a test can lower them (as `BYBIT_PNL_PAGE_CAP` is).
- Cap rule (ruling OQ7), applied in Task 3: from `231-PROBE-RESULT.md` `trade-cap-input:`, an
  integer P gives `max(200, ceil(1.5 * P))`; `field-absent` gives 200.
