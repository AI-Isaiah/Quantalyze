## Decisions this plan applies (and where they come from)

- Request shapes (RESEARCH, measured on ccxt 4.5.89): `exchange.fetch_positions(None, {"settleCoin": "USDT"})`,
  `exchange.fetch_positions(None, {"settleCoin": "USDC"})`, `exchange.fetch_positions(None, {"subType": "inverse"})`;
  raw: `private_get_v5_position_list` with `{"category": "linear", "settleCoin": "USDT"}`,
  `{"category": "linear", "settleCoin": "USDC"}`, `{"category": "inverse"}`, each plus `limit` "200"
  and the cursor.
- The fallback decision is per category: a category whose ccxt rows are present, below a full page
  and carry every critical field ships its ccxt rows; any other category (empty, a None field, or a
  full page of 200) is read on the raw cursor path. A flat account therefore costs three ccxt plus
  three raw calls per poll (RESEARCH Pitfall 2; kept, stated, not changed).
- Inverse rows are computed from the raw V5 row on BOTH paths (the ccxt position's `info` is that
  row), the way `_normalize_deribit_position` reads raw `info` fields, never ccxt `notional` or
  `unrealizedPnl`: `size_base` = |positionValue| (coin), `size_usd` = `size_base` x mark,
  `unrealized_pnl` = `reported_pnl(unrealisedPnl)` x mark with None kept None, `entry_price` and
  `mark_price` as USD per coin, `symbol` = the raw `symbol`.
- USDC-linear rows: `symbol` = the raw `symbol` from `info`; every other field as the USDT-linear
  arm computes it (USDC counted as USD, the stable rule). USDT-linear rows are unchanged.
- Bybit stays fail-loud: `_normalize_ccxt_positions` keeps skipping per position for Deribit only.
- The new refusal class falls through `job_worker.classify_exception` and
  `allocator_positions._must_reach_handler_unwrapped` as any RuntimeError does today; neither file
  is edited here.
</context>
