## Design (settled at planning; the executor implements it as written)

1. **Marker predicate, in `src/lib/factsheet/headline-basis.ts`** beside `isOptionsCashWalletBook`: `export const HEADLINE_BASIS_FLAG = "headline_basis"`, `export const HEADLINE_BASIS_SMOOTHED = "smoothed_mtm"`, and `export function isSmoothedHeadlineRow(dqf: unknown): boolean`. It uses the same record-or-null guard and strict `===` (no trim, no case fold), and it returns false whenever `isOptionsCashWalletBook(dqf)` is true. **The reason always wins**: a row carrying both withholds everywhere. The docblock cites the ruling, plan 09, and why the predicate is NOT folded into `headlineVerdict`: the OG card and the single-key arm call `headlineVerdict` on the top-level headline, which on a promoted row IS the smoothed result and must not be withheld.

2. **Composite read path, in `src/lib/factsheet/composite-read-path.ts`.**
   - `applyHeadlineBasis` gains a first branch: when `options.composite === true` and `isSmoothedHeadlineRow(dqf)`, return a redacted copy (every `BASIS_KPI_MAP` server key null) with quality exactly `{ headlineWithheld: true, headlineWithheldCause: OPTIONS_CASH_WALLET_CAUSE }`. It carries no `twrChainBroken`, no `headlineCoversFrom` and no `headlineGuardReasons`: on a promoted row those flags describe the smoothed series, not the cash object being withheld. This function is only ever handed the stored CASH headline (its docblock says so), so this is the cash basis of an options book, withheld under the wave-1 cause and sentences. Update the docblock.
   - `readCompositeFactsheet`: widen the `dqf` input type with `headline_basis?: unknown`, and set `buildOpts.headlineBasis = HEADLINE_BASIS_SMOOTHED` (present-only spread) if and only if `isSmoothedHeadlineRow(dqf) && smoothedAvailable`. A marker with no valid smoothed object leaves the cash basis withheld (the first bullet) and does not switch the basis. `mtmGate.reason` stays the raw `dqf.mtm_gated_reason` read. It is absent on a promoted row, so the MTM segment prints the default "Mark-to-market unavailable for this strategy.", which is true there.

3. **Payload, in `src/lib/factsheet/types.ts` and `src/lib/factsheet/build-payload.ts`:** `FactsheetCommon.headlineBasis?: "smoothed_mtm"`, with a docblock (the basis the stored headline is measured on, present only on a promoted composite, absent means cash). Also `BuildFactsheetOpts.headlineBasis?: FactsheetCommon["headlineBasis"]`, copied into the payload present-only, beside `smoothedGate`, so every unpromoted payload is byte-identical.

4. **Factsheet UI.** In `src/app/factsheet/[id]/v2/basis-context.tsx`, `BasisProvider` takes `initialBasis?: Basis` (default `"cash_settlement"`, D5) and seeds `useState` with it; update its docblock. In `src/app/factsheet/[id]/v2/FactsheetView.tsx`, the one `<BasisProvider>` mount passes `initialBasis={payload.headlineBasis ?? "cash_settlement"}`. The smoothed segment's render condition becomes `SMOOTHED_MTM_UI_ENABLED || <the same payload>.headlineBasis === HEADLINE_BASIS_SMOOTHED`; rewrite the Phase 134 comment there. Its stated reason ("with the dark default the worker never persists a smoothed basis, so the segment would only ever be honest-disabled") does not hold for a row whose worker stored the smoothed basis as the headline. The segment stays hidden for every other row while the flag is off. `resetView` does not touch the basis (measured at planning), so it needs no change; confirm and record. In `src/lib/closed-sets.ts`, update the `SMOOTHED_MTM_UI_ENABLED` docblock only (no code). No new copy: the labels, the withheld sentences (`OPTIONS_CASH_WALLET_PHRASES`) and the tones already exist, and DESIGN.md is untouched.
