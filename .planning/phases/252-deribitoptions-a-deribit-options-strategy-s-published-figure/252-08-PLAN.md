## Design (settled at planning; the executor implements it as written)

1. **Predicate.** At the EXISTING exercise branch of the first loop in `replay_option_positions` (after the `classify_instrument` option check), compute `_row_field_shape(row, "change")` and `_row_field_shape(row, "position")`. If both equal `ROW_FIELD_ZERO`, accept the row. Otherwise raise `OptionExerciseRowError` exactly as at HEAD: same message, same keyword attributes, same census. These are the helper and words that produced the PROD reading, so the accepted set equals the measured shape by construction. `absent` change (missing, null, blank) and `non-numeric` change are not `zero`, so they refuse. That is the planner's reading of "accepted ONLY ... `change` zero" and each gets a case.
2. **Gate placement.** The refusal stays in the first loop, at the same point, so the first error on a ledger with several defects does not change.
3. **Accepted row.** It joins `per_instr` and `ccy_of` like any other option event, so its currency and its UTC day enter the instrument's book.
4. **Close.** No new branch. The gate-admitted row takes the existing generic position read in the per-instrument ordered loop, which reads its own `position` (zero) as the day's end-of-day position, keyed on its UTC day. The ordering, the shortlex tie-break and the last-row-of-day rule are unchanged, so the result is the expiry result (0 on that UTC day). Do not call `_expiry_close`, and do not add a dedicated 0.0 branch: it would be unpinnable, because the generic read already yields 0 for every admitted row.
5. **Sets untouched.** Do NOT add `exercise` to `_OPTION_BOOK_CLOSE_TYPES`. `_expiry_close` accepts an absent change and an absent, null or blank position, which is wider than the decision. Its refusals also raise `OptionExpiryRowError`, which would rename the exercise refusal. Do not add it to `_OPTION_BOOK_EVENT_TYPES` either: that set must stay a subset of `CASH_BEARING_TYPES`, and the measured row carries no cash.
6. **Comments.** Update the comment above `_OPTION_EXERCISE_TYPE` and the D-09 paragraph of the `replay_option_positions` docstring with the dated decision, using the literal text `Founder decision 2026-11-27` (partial reversal of D-09: the measured shape closes, every other shape refuses). Also update the inline comment at the exercise branch. The refusal MESSAGE text stays byte-identical even where its wording now reads as dated, because it is a stored string (`test_the_row_refusals_keep_their_exact_message_bytes` pins it).
