## Advisories (non-blocking, no register mapping, no action required to ship)

1. **The vitest live-DB helper has no production-URL guard.** `src/lib/test-helpers/live-db.ts` `createLiveAdminClient` builds a service-role client from whatever `NEXT_PUBLIC_SUPABASE_URL` holds. `assertNotProductionSupabaseUrl` is called only on the e2e path. So T-02's control is procedural: run live-DB vitest only through `scripts/local-stack/run.sh`, whose `assert_local` refuses a non-loopback URL. This is pre-existing and not introduced by this phase. The phase adds claim / mark-done calls in the harm probe, but the same file already made `claim_compute_jobs` calls before the phase.
2. **The ten-arg parent refusals would become an existence oracle if an authenticated wrapper ever forwarded caller-supplied `p_parent_job_ids`.** Today only service_role can reach them (rls-policy-auditor round 2, and the M1 header). Any future wrapper must not pass untrusted parents.
3. **Pre-existing log lines carry the user id and key id** (`route.ts` 40001-retry `console.warn` and the 500 `console.error`; `AllocatorExchangeManager` `handleReconnect` `console.error` in the owner's own browser). None was added by this phase, and none reaches a response body.

### Client state check (requested scope)

`AllocatorExchangeManager.tsx` state comes only from `initialKeys` (the server query for the signed-in user). Every new mutation (`markRefusedAsDisconnected`, `reconnect_in_flight`, `isQueuedHold`) maps over those rows by `keyId`. No cross-tenant data enters. The only server text rendered is `body.error` from a **409** response, which `route.ts` fixes to one sentence; any other failure renders the client's own `SYNC_FAILED_HELPER` / "Reconnect failed — try again". No DB message reaches the UI.
