# Phase 164.9.1 Plan 04: One Guarded Normalisation Fragment for the Restore Summary

**`scripts/test-only-normalize-analytics-url.sh` now builds the normalisation SQL for both callers from a single function, `emit_guard_block`. The hand-run `--run` path is unchanged. ## Task 1: `--emit-restore-sql` and `--print-sink` (commit `48f84c232`)

- `build_sql()`'s DO block moved into `emit_guard_block <tag> <mutex> <noop> <sink> <expect> <refuse> <write|always>`. `build_sql()` wraps it with `BEGIN;`, the `set_config` lines and `COMMIT;` exactly as before.
- I diffed the `--run` SQL rendered before and after the refactor. The only change is the added read-back block.
- The fragment has no `BEGIN;`/`COMMIT;`, no `pg_try_advisory_xact_lock` and no psql variable. Its dollar-quote tag is `$tonau_rearm$`, which differs from `$tonau$` and from the restore's `$restore$`. It names `public.system_settings`, reads the marker with `shobj_description`, and raises in this order: marker absent, then marker matches PROD, then marker not TEST, then row absent. It then runs the UPDATE, checks ROW_COUNT = 1, reads the row back, and emits a `NORMALIZED:` NOTICE that carries only the length and scheme.
- The sink must match `SINK_SHAPE_RE` (`^http://127\.0\.0\.1:[0-9]+$`) or the script refuses, and the refusal does not echo the rejected value. Each rendered value is also refused if it contains the fragment's tag or a newline, or if it renders as an empty literal (an empty predicate would match every database). All of these refusals fire before anything reaches stdout.
- `--print-sink` runs the same shape check and prints the sink alone.
- `usage()` was re-cut from `2,62p` to `2,72p`, so it still prints the whole header.
- The sink literal occurs once in the script's non-comment lines, at the `NORMALIZE_SINK` default.
- Tracer arm E1 applies `BEGIN;` + the fragment + `COMMIT;` on a TEST-marked cluster, and the row then equals `--print-sink`'s output. **Calibration:** with the UPDATE neutered (`SET value = value`), `emit-test-writes` and `emit-test-landed-the-sink` both FAILED. After a `cp` restore (`cmp` 0) the self-test went back to OK (21 checks).

## Deviations from Plan

1. **[Rule 2 - correctness] Read-back added to the shared write, so `--run` gets it too.** The plan asks for a read-back in the fragment and for `--run` to be behaviourally unchanged. D-17 requires the write to be written once, so the read-back lives in the shared block. On `--run` it changes nothing observable unless a trigger or rule rewrites the row inside the transaction. The existing 19 `--run` checks still pass.
2. **[Rule 2 - security] More refusals than the plan listed.** Besides the loopback-sink check, the emitter also refuses a rendered value that contains the fragment's own dollar-quote tag, contains a newline, or renders as an empty literal. T-164.9.1-17 (injection through the rendered literals) motivated these.
3. **Worktree branch-namespace assertion not applied.** This checkout is a git worktree on `feat/164.9.1-jobrpctruth`, which is not an `agent-*` branch. The orchestrator pinned this branch as the project root, and plans 01 to 03 committed on it. The protected-branch check was run and passed.
4. **Prior count read after Task 1.** Task 2 says to measure the prior count "before editing". I measured it after Task 1's commit and before Task 2's edits, which gives 21. The PHASE-BASE reading, 19, is recorded in the Counts table. The +5 requirement holds against either number (36 ≥ 26).
