## Reproduce-First Gate (PYAPIFIX2-02 — BLOCKING, plan 01 Task 1)

Two red teams reached **opposite** verdicts on whether the MT5 permanence defect is live. The
RED test **is** the reproduction, and **"could not reproduce" is a valid, budget-saving green
exit.** The gate has exactly **three** exits and the executor must take one explicitly:

| Observed | Verdict | Required action |
|---|---|---|
| Tests A/B FAIL with `error_kind == "transient"` | **REPRODUCED** | this failure IS the observed RED — commit the RED tests, proceed to Task 2 |
| Tests A/B PASS **and** the negative control proves the kill-switch was patched out | **NOT REPRODUCIBLE** | **write ZERO production code**; keep the green tests as regression pins; record command + verbatim output + control evidence; skip Task 2 |
| Tests error / cannot be constructed | **INCONCLUSIVE** | escalate with the traceback. Do **not** guess. Do **not** proceed on the strength of a source read alone |

**The negative control is what makes the gate honest.** `long_fetch`'s MT5 kill-switch
(`if source == "mt5" and not mt5_enabled_server():`) *also* returns `error_kind="permanent"`.
Without `patch("services.ingestion.long_fetch.mt5_enabled_server", return_value=True)` in tests
A and B, they would pass **for the wrong reason** and the phase would record a false
NOT-REPRODUCIBLE. The control patches it to `False` and asserts the MT5-disabled detail text, so
the two paths are distinguishable.

⚠️ **The gate command carries NO `-x`** (revision I-4). Under `-x` a REPRODUCED run aborts at
Test A and the negative control never executes — losing the one piece of evidence that makes the
RED trustworthy. All three tests run on every invocation; the SUMMARY shows all three outcomes
from a **single** run.

**Half A is closed by proof, not by code.** RESEARCH C-2 shows the sync `/process-key` 424 gate
is UNREACHABLE for `source="mt5"` (the `@field_validator("source")` wire-boundary whitelist plus
`_is_long_fetch` routing). The proof is recorded with quoted source in the SUMMARY and **no
defensive membership is added** — the wire-boundary validator is the real fence.

"The test now covers it" is **not evidence** — this is the same protocol that closed 13 survivors
in 140.1.1. Two probes, each **observed first-hand**:

2. Apply the mutation. Run. **Observe RED first-hand** and capture the failing assertion text.

4. Re-run. **Observe GREEN.**

## Cross-Artifact Oracle Gate (PYAPIFIX2-01 — BLOCKING, plan 03)

The wire contract's central invariant is that `body["detail"]` stays **byte-identical** to today's
string, because that string is the **input to the TypeScript substring cascade**
(`classifyKeyValidationError`). A reword silently regresses `RATE_LIMITED` / `PROBE_FAILED` /
`DDOS_PROTECTION` to `UNKNOWN`/500 — the 3-code regression this phase exists to prevent.

- [ ] **C1–C5 are genuinely proven** by the wire cases: the router names the copy constant
      directly, so a literal typed in the test pins the real string.
- [ ] ⚠️ **C6 and C7 are NOT** — they read `result["error"]` / `validation["error"]`, values the
      test itself **stubs**. Those cases prove *pass-through* only and would stay green through a
      production copy reword, at the **two highest-traffic sites**. (Revision W-3.)
- [ ] **Therefore the copy pins are mandatory:** the `test_sfox_validate.py:462-471` pattern —
      a function-local `from services.exchange import <CONST>` compared against a module-level
      `EXPECTED_*` literal typed in the test — for `RATE_LIMITED_DETAIL`, `NETWORK_ERROR_DETAIL`,
      and the inline `EXCHANGE_UNAVAILABLE` / `DDOS_PROTECTION` / `PROBE_FAILED` copy.
- [ ] **These are the ONLY permitted production imports in the file**, and only *inside the pin
      functions* — never at module scope, never inside a wire case. A wire case importing a
      production constant is self-referential and must be rejected.
- [ ] **Both polarities of `recoverable` are pinned** — an `AUTH_FAILED` control asserting
      `False`, and an unknown/synthetic-code control asserting `True`. One direction alone leaves
      the field decorative. The `unknown ⇒ True` direction is **derived, not assumed** (revision
      W-4): on this route `recoverable` is a **render hint**, not a retry-loop input, so a wrong
      `True` costs one pointless user click while a wrong `False` reproduces the DOGFOOD-3 dead
      end the phase exists to kill.
- [ ] **The committed fixture** `tests/fixtures/validate_key_venue_transient_contract.json` is
      git-tracked and parity-asserted by the test, so it cannot drift from the pins. It is
      140.3's TS-parity input (the S-5 pattern) — a generated file would be unusable, since the
      `python` and `frontend-test` CI jobs have no `needs:` edge.

## Regression Fence Register — gates that must be able to FAIL

Two gates in the first draft of these plans **could not fail**. Both were rebuilt at plan-check.
They are recorded here so the pattern is recognised, not re-invented.

| Fence | Retracted form | Why it could not fail | Replacement |
|---|---|---|---|
| **The 3-code regression fence** (plan 03 Task 2) | `grep -n "service_error(424" routers/exchange.py routers/portfolio.py` → 0 | **Every** `service_error` call in both routers is multi-line — the call opens `raise service_error(` and the status sits on the NEXT line. A regressing `service_error(\n    424,` scores 0 and passes. Verified at source. | **PRIMARY:** the runtime assertion `type(exc.detail) is str` / `isinstance(body["detail"], str)` plus the exact key set `{"detail","code","recoverable"}` in every wire case — `service_error` nests an OBJECT at `body.detail`, so a regression is RED by construction. **SECONDARY:** the `VenueTransientHTTPException` constructor's own `type(detail) is str` guard (dict ⇒ `ValueError`, pinned by its own test). **CORROBORATION:** a *dispositioning* grep — `grep -n "service_error" …`, every hit listed and shown OUTSIDE the 7 class sites, count unchanged from the pre-plan baseline. |
| **The ID-space fence** (plans 02/03 Task 3) | appending rows named `OB-9` / `OB-1` to `140.1-TS-OBLIGATIONS.md` | The file's ID space is `TS-01..TS-33` and its own header rule forbids forking a second list. An OB-N row forks one *inside the artifact that exists to stop forking* — and no gate would have noticed. | Rows land as **TS-34** (plan 02) and **TS-35** (plan 03), each citing its OB-N provenance in the row body. The count header is recounted **by both plans** (33 → 34 → 35) so a deferred plan 03 cannot leave a self-reporting false count. |

**Grep-gate hygiene, standing rule.** `→ 0` is only a gate when a real regression would produce a
hit. If the file already contains legitimate hits of the pattern, `→ 0` is unachievable and the
gate is decorative in the opposite direction. Prefer: (a) a runtime assertion, (b) a
dispositioning gate that enumerates and accounts for every hit, (c) a `grep -v '^#'` filter when
counting tokens in files whose comments mention the token.
