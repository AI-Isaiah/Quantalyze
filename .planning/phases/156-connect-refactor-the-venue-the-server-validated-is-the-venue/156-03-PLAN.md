⛔ **D-156-1 — THE TRANSITIONAL GATE, AND WHY IT IS NOT THE SHAPE `156-PATTERNS.md` REJECTS.**

`156-PATTERNS.md` § 1 is emphatic that `log_audit_event_service`'s
`auth.role() NOT IN ('authenticated','service_role')` width must be **rejected**, because admitting
`authenticated` in-body makes the defence-in-depth layer a permanent no-op. **That verdict is about
the FINAL body, which plan 07 installs.** It is correct and it stands.

Migration A cannot install the final body, because during the PR-A merge window the **old deploy is
still live and still calls with the user-scoped client**. A `service_role`-only body gate would
refuse it — reproducing the exact outage the split exists to prevent.

So Migration A installs a **two-arm** gate, which is not the rejected shape:

- `service_role` arm → proceed (the new writer).
- `authenticated` arm → **the existing `auth.uid()` check runs unchanged**: NULL uid raises, and
  `auth.uid() <> p_user_id` raises. The cross-user elevation guard (T-88-03) is fully intact.
- anything else (including a NULL/absent role claim) → raise `insufficient_privilege`.

⛔ **The shape that must NOT be written is the flat union** — a single
`IF v_role NOT IN ('authenticated','service_role') THEN RAISE` with the uid check deleted. That
would delete the ownership guard for the `authenticated` caller *while `authenticated` still holds
EXECUTE*, opening cross-user elevation for the width of the window. That is strictly worse than the
residual this phase closes. The arms must be **branched**, never unioned.

**Migration A is safe to sit at indefinitely** — it is a strict superset of today's caller set with
today's guarantees for today's caller. It does not close CONNECT-01; plan 07 does.
