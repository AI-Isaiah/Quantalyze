## Shared Patterns

### One-parser-plus-verdict reader, caller reports, payload flags, render says "unavailable"
**Source:** `src/lib/factsheet/trade-fetch-provenance.ts:99-170` (reader), `src/lib/factsheet/fetch-and-build-payload.ts:985-1026` (caller), `build-payload.ts:1086` + `types.ts:727` (flag), `trade-fetch-lines.tsx:220-261` (render)
**Apply to:** the whole gap-record fix. Reader is pure and total; the caller owns the Sentry report; the flag is optional and spread only when true; the render sentence is muted-secondary (`mt-1 ${SIZE_CLASS[size]} text-text-secondary`), declarative, sentence case.

### Optional payload flag spread only when true
**Source:** `build-payload.ts:1086`
**Apply to:** `unrecoveredGapsUnavailable`.
```ts
...(strategy.reconstructedRangesUnavailable ? { reconstructedRangesUnavailable: true } : {}),
```

### Sentry reports carry a reason string, never raw data
**Source:** `fetch-and-build-payload.ts:995-998`
**Apply to:** the new unrecovered-gaps report. Tags `stage`, `reason`, `strategy_id`; `extra.detail` is the short reason only.

### Dated cache-key bump comment, one bump per phase
**Source:** `src/app/factsheet/[id]/v2/page.tsx:304-305`
**Apply to:** the v24 -> v25 bump (covers both SC-2 and SC-3). Pins move with it (three test files plus one comment, listed above).

### SECDEF public primitive hardening, catalogue-only verify
**Source:** `supabase/migrations/20261019120000_get_published_trade_venues.sql:99-142`
**Apply to:** the new migration and its rollback. `SECURITY DEFINER`, `SET search_path = public, pg_temp`, `RETURNS TABLE` as the column allow-list, explicit `REVOKE ALL ... FROM PUBLIC` and grants, no table read in the DO block ([164.8-DATA-DEPENDENT-MIGRATION-ESCAPE]).

### RED-UNDER twin per arm; edit steps address `file`/`find`/`occurrences`
**Source:** `supabase/tests/test_get_published_trade_venues.sql:186-200` (TV-1) and the `applyFileStep` count check (`scripts/mutation-runner/run.mjs:237-252`)
**Apply to:** every retargeted and new arm. A wrong occurrence count is a `MEASURE_FAIL`, never `no-red`; an arm still pointing at the old migration reads `no-red` once the new `CREATE OR REPLACE` overwrites the body.

### Neuter-the-fix procedure for the TS fixes
**Source:** RESEARCH "Neuter-the-fix procedure" (byte backup, never git checkout/restore/stash on uncommitted work). Apply to SC-2 and SC-3 tests after they are green: copy the file to scratch, record its sha256, apply the one-line neuter by editor edit, see the named test go RED, restore from the byte copy, confirm the sha, re-run GREEN.
