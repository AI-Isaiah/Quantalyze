**Root cause.** 169.4-05 (D-70(1)) drops a benchmark trace whose window reads a BTC null, but not the equity trace of the same event. After that change the two views hold different populations. `computeHorizon` still reported one count pair, `winBench.length` / `lossBench.length`, and `aggregate([])` returned six all-zero series instead of an absence.

**Applied fix:**
- `aggregate()` returns `null` for an empty population.
- `EventSignaturesSet` gives each view its own count. `winCount` / `lossCount` now count EQUITY traces. The new `benchWinCount` / `benchLossCount` count BENCHMARK traces. The four views are `EventSignature | null`, and the doc comments say which count belongs to which view.
- `SignaturePanels`: the horizon title has no count now. Each panel names its own N, for example `Win Event · of BTC · 86 events`. A `null` view renders `SignatureEmptyPanel`, which shows an em-dash and "Not measurable: no win event has a complete ±14-day window of BTC prices." (DESIGN.md null rule). It never draws a chart. The null branch sits in a `SignatureSlot` wrapper so no hook is called conditionally.
- `CrossSignaturePanels`: the legend has no W · L count now. Each cross panel names both of its populations (`… · 86 strategy / 90 BTC events`). If EITHER side is `null`, the panel renders the same em-dash state and names the missing side, because a comparison with one line is not a comparison.

**Every consumer of these fields was checked.** Making the views nullable made `tsc` fail at every reader: the 12 panel props in the two components, plus the test files. So no reader can take the new `null` as 0 without a compile error. Other readers, found by grep: `build-payload.ts` produces the payload and does not read it. `audit-c20.test.ts`, `composite-read-path.test.ts` and `scenario-factsheet-payload.test.ts` check only whether a field is present or null. The `BatchDPanels.*` tests pass `null` for the whole payload field. `compute.ts`'s `winCount` is an unrelated local. `build-payload.ts` was not edited.

**Deviation from the review's Fix text, on purpose:**
- **Cache key not moved.** The review asks for v11. The brief overrides that: v10 comes from this phase's own 169.4-06 and has not shipped (main is on v9). No stored v10 payload can be missing the new keys, and the first shipped v10 build will already carry them.
- **CrossSignaturePanels is not hidden when BTC is unavailable.** Each panel renders the em-dash state with its cause instead. When BTC is unavailable, all eight cross panels show it (measured, see the tests). A cause-naming dash is used rather than a silent absence, which is the rule the repo applies elsewhere. If the founder would rather hide the whole section, that is a one-line gate in `CrossSignaturesSection`.
