## Fixed Issues

### SFH HIGH-1: the multi_asset blend drops BTC's move across every US-market holiday

**Files modified:** `src/lib/factsheet/allocator.ts`, `src/lib/factsheet/allocator.test.ts`,
`src/lib/factsheet/build-payload.null-honest.test.ts`, `src/lib/factsheet/__snapshots__/build-payload.test.ts.snap`
**Commit:** `d74aa4af7`
**Applied fix:** in `alignBlend`, a blend date is now a strategy date on every leg's calendar AND
with a close dated that day for every leg (a dropped close is not a close). A holiday is therefore
not a blend date, and the next common date's interval, through the same `alignCoveredReturns`
call, carries every leg's close-to-close move across it (BTC's Fri-to-Tue, not Mon-to-Tue).
`through` is now read directly from each leg's prices against the last calendar-shared strategy
date, not from the alignment. The reason: a strategy dated wholly after a fixture's last close now
has no blend date at all, and `alignCoveredReturns` returns `through: null` for zero dates, which
would have turned the dated "Prices through May 8, 2026" caption into "Prices unavailable".
**Deliberate behaviour change, pinned:** the date after a holiday is `paired: false` for a
weekday leg (one bridged point where its calendar expects two), so the correlation and the
sleeve scan skip it while the own-series figures keep it. SFH predicted this. A test asserts it so
it is not later filed as a bug. **Crypto-only blends are unchanged:** both legs price every day, so
the blend dates equal the strategy dates. The existing test asserts this, and the new test
re-asserts it.
**Test changed on purpose:** "a leg past its last close makes those blend days null" now asserts
that those days are **not blend dates**. Before, they were null blend dates. `through` is still
`2026-01-08`. The payload test `multi_asset: cum_ret and ann_vol …` now computes its independent
expectation on the dates every leg priced. It asserts that Good Friday 2026-04-03 is excluded, and
that the payload differs from the pre-fix "holiday is a null" figure by more than 1e-4.

### SFH HIGH-2 + REVIEW WR-02: tail windows silently discarded; zero-window caption and +0.00% figures

**Files modified:** `src/lib/factsheet/allocator.ts`, `src/lib/factsheet/types.ts`,
`src/app/factsheet/[id]/v2/BatchDPanels.tsx`, `src/lib/factsheet/allocator.test.ts`,
`src/app/factsheet/[id]/v2/BatchDPanels.null-honest.test.tsx`, the build-payload snapshot
**Commit:** `0ed703e0a`
**Applied fix:** after HIGH-1 the blend has no holiday or past-fixture nulls, so windows run over the
common-calendar series. A null now comes only from a dropped close. `buildAllocatorMetrics` counts
the windows it examines as a new `tail_windows` field, which is null when the blend is unmeasured.
A window holding a null is still dropped and is not counted. `tail_mm_mean`, `tail_mm_median` and
`tail_mm_pos` are null when no window reached the threshold, and the existing formatters render
them as the em-dash. The caption (`tailCaption`) claims only what was measured:
- `tail_windows === 0`: "No 21-day window with every leg priced, so no stress window could be measured."
- `tail_count === 0`: "The portfolio did not draw ≥ 5% in any of the N 21-day windows with every leg priced."
- otherwise: "K of the N 21-day windows with every leg priced were stress windows; MultiMarket was positive in P of them."

### SFH MEDIUM-2: a failed BTC read is captioned as "too few priced days"

**Files modified:** `src/lib/factsheet/build-payload.ts`, `src/lib/factsheet/types.ts`,
`src/app/factsheet/[id]/v2/BatchDPanels.tsx`, `src/app/factsheet/[id]/v2/BatchDPanels.null-honest.test.tsx`,
the build-payload snapshot
**Commit:** `9b15e0c2c`
**Applied fix:** the payload carries `unavailable_leg`: `"BTC"` on multi_asset and crypto_book when
`benchmarkPrices` is the unavailable marker, and null otherwise (60/40 always null). The panel checks
it before the `through === null` branch and renders "BTC prices are unavailable right now, so this
portfolio cannot be measured." "Too few days with every leg priced" is kept for a genuine sparse
overlap. The panel uses a loose `!= null` check, so a payload that lacks the key renders the old
caption and not "undefined prices".
`alignBlend`'s signature is unchanged.
