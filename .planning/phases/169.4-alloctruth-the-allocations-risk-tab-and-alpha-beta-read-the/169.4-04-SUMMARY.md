Changes that are not moved literals, recorded so none is hidden:
- `scenario-benchmark.test.ts`: the pairing case compared `b` with `toEqual`. It now compares each value with `toBeCloseTo(v, 14)`, because the paired BTC return is recovered as close(k)/close(k-1) - 1 and carries float residue. The poison values became positive closes (88,800 and 7,777,700): a return of -888 has no close.
- `return-stats.sites-risk.test.ts`: the two bitwise pins still use `Object.is`. The IR pin checks against `sharpe` / `(mean·N)/te` and the correlation pin against `pearson`. Both now take their operands from the pairs the site uses (`pairScenarioWithBtc`), not the raw `NOISY_B`, which differs by float residue. The claim is unchanged: the site is bitwise the shared function of its own pairs.
- The stress lib suite and the StressVarSection suite use `flatFillGaps`, so their `manyDays` and weekday calendars pair exactly as before, and no literal moved there. Without the fill, the near-market-neutral book's covariance of exactly 0, which is built over whole period-4 blocks, would break for a reason unrelated to the test.

## Deviations from Plan

1. **[Rule 3 - blocking] A docblock in `src/app/api/benchmark/btc/prices/route.ts` (169.4-03's file, outside this plan's `files_modified`) was reworded.** It wrote the parent path in backticks, `` `/api/benchmark/btc` ``. Task 3's bare-path check matches a quote or backtick right after `btc`, and its exclusions cover only the returns route's own files, not the nested prices route. The count was therefore 1, not 0. The sentence now names the parent path without a quote after it, and its meaning is unchanged. 169.4-08 re-runs the same check and would have hit the same line. Commit `8af11616f`.
2. **[Test infra] `btc-closes.test-utils.ts` gained a `flatFillGaps` option in Task 2, and its second parameter became an options object `{ dropped, flatFillGaps }`.** The plan names one helper. The option covers fixtures whose calendar is synthetic and beside the point (see Moved literals).
3. **[Rule 2] The composer logs an F-08 warning on a 2xx body of the wrong shape** ("unexpected body shape"), beside the existing non-ok and thrown-fetch warnings. Before, a non-array body degraded without a log. A stale cached returns array is exactly the D-67 hazard, so it should be visible.
4. **[Rule 2] Both callers map a closes body with no close (`prices: []`) to null.** This keeps the old semantics, where an empty series meant unavailable: the toggle is disabled and the overlay hidden. Otherwise the checkbox would be enabled with no overlay.
5. **[Withdrawn] The stress lib's finite check briefly also required a positive close.** That half had no RED on record, and the route and `parseBtcCloses` already refuse a non-positive close. The follow-up commit returned the check to finite-only, as the plan states.
6. **[Protocol] The `node_modules` symlink was never removed before a commit.** The plan's environment note says to remove it; the orchestrator's brief says never to remove or stage it, and the orchestrator wins. Files were staged individually.
7. **[Protocol] The branch is `feat/169.4-w2-04`, not `agent-*`.** This is a manual worktree with isolation `none`, as the orchestrator set up. The protected-branch check passed.
8. **[Anchor] `fetchBtcDaily` was renamed `fetchBtcCloses`, and the composer no longer imports `computeStrategyCurve`.** Both were `verify-symbol` anchors of this plan. `verify-plan-anchors.mjs --pending` scans only plans without a sibling SUMMARY, so this SUMMARY takes 169.4-04 out of the scanned set. No other pending plan in the phase anchors either symbol.
