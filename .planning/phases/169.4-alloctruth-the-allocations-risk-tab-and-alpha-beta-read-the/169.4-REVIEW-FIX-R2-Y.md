### R2 WR-01: "Stress windows in sample 0" is printed when no window could be examined

**Files modified:** `src/lib/factsheet/allocator.ts`, `src/app/factsheet/[id]/v2/BatchDPanels.tsx`,
`src/lib/factsheet/types.ts` (doc comment only), `src/lib/factsheet/allocator.test.ts`,
`src/app/factsheet/[id]/v2/BatchDPanels.null-honest.test.tsx`
**Commit:** `436b25634`
**Status:** fixed

**Applied fix:**
- `buildAllocatorMetrics` now returns `tail_count: tailWindows > 0 ? tailMm.length : null`. A
  count over zero examined windows is an absence, like the mean, median and positive share. A 0
  with windows examined stays a measured 0.
- The caption in `AllocatorSection` now gates on `p.tail_windows !== null` only. `tailCaption`
  takes `count: number | null` and returns the zero-window sentence before it reads the count.
  The review's suggested `p.tail_count ?? 0` was not used, because it reads a null as 0.
  Without the guard change the caption would have disappeared in exactly the case it exists
  for, and a neuter confirmed that (below).

**Tests moved (intent kept):**
- `BatchDPanels.null-honest.test.tsx`: the 20-day 60/40 case moves from `['0','—','—','—']` to
  `['—','—','—','—']`. It still asserts the zero-window caption.
- `allocator.test.ts`: the gappy case (`tail_windows` 0) moves `tail_count` from `0` to null. The
  calm case (9 windows examined, none a stress window) stays at `0`.

**Snapshot:** unchanged. The three snapshot portfolios have `tail_windows` 22, 22 and 41, and
`build-payload.test.ts` passed without an update.

**Neuter records** (a `cp` byte backup, one neuter at a time, restored with `cp`, checked with `cmp`
and a grep of the fixed line):
1. `allocator.ts` ternary reverted to `tail_count: tailMm.length`: **2 failed / 17 passed**.
   - `no stress window: mean, median and positive share are null ...` (`expected +0 to be null`)
   - `a measured 60/40 too short for a 21-day window ...`
     (`expected ['0','—','—','—'] to deeply equal ['—','—','—','—']`)
2. `BatchDPanels.tsx` caption guard put back to `p.tail_count !== null && p.tail_windows !== null`:
   **1 failed / 3 passed**. The 20-day case failed because it no longer contained
   "No 21-day window with every leg priced ...".

After the restore: both files green.

### R2 SFH-2 (R2-MEDIUM-2): below the paired floor, every factsheet dropped alpha, IR and §IV with no cause named

**Files modified:** `src/lib/factsheet/types.ts`, `src/lib/factsheet/comparator-block.ts`,
`src/lib/factsheet/joint.ts`, `src/app/factsheet/[id]/v2/FactsheetView.tsx`,
`src/app/factsheet/[id]/v2/MetricsColumn.tsx`,
`src/app/(dashboard)/allocations/widgets/attribution/AlphaBetaDecomposition.tsx`,
`src/app/(dashboard)/allocations/widgets/attribution/AlphaBetaDecomposition.book-btc.test.tsx`,
`src/lib/factsheet/__snapshots__/build-payload.test.ts.snap`.
New file: `src/app/factsheet/[id]/v2/FactsheetBody.joint-floor.test.tsx`.
**Commit:** `bf083693f`
**Status:** fixed: requires human verification. This is a rendering-state change on a document
surface. One look is needed at three things: the 9-cell "—" strip and the §IV "—" block in the
browser, the zero-paired form (below), and the PDF/tearsheet print of a below-floor record.

**Applied fix:**
- **Type.** `ComparatorBlock.jointWithheld?: { paired: number; floor: number } | null`.
  `buildComparatorBlock` always sets it: `{ paired, floor }` below `MIN_PAIRED_OBSERVATIONS`, and
  null otherwise. The none block, the unavailable block and the scenario hand-built
  `inertComparatorBlock` leave it absent. Their null joint has another cause (no comparator,
  prices unavailable, and a scenario with no joint by design), so they must not show the floor
  sentence. The field is optional, so those blocks compile unchanged.
- **One sentence.** `pairedFloorReason(comparator, paired, noun, floor)` in `joint.ts`, next to the
  constant, produces "Alpha and beta need at least 10 days paired with {cmp}; this {book|record}
  has N." The Allocations widget now calls it with "book", and its exact-string test is unchanged
  and green. The factsheet calls it with "record".
- **KPI strip** (`FactsheetView.tsx`, `KpiStrip`): the α/IR cells are pushed when the joint exists
  or is withheld, so the strip stays at 9 cells. A withheld joint reads "—" with no sign tone. One
  muted line (`data-testid="joint-floor-reason"`, text-muted, not the amber warning colour) sits
  under the grid. The MTM/smoothed `suppressRelative` "—" is unchanged.
- **§IV** (`MetricsColumn.tsx`): the section stays when the joint is withheld. Every Joint
  Metrics row reads "—", with no accent colour on the alpha dash, and the same muted reason line
  follows.
- **D-69 holds.** No joint figure renders below the floor on any surface. At or above it, the
  widget and the Overview still show the same alpha (fix-C's `it.each([10, 30])` test, green).

**Consumers checked (grep):** only `FactsheetView.tsx:KpiStrip` and `MetricsColumn.tsx` read
`.joint` in `src/`. The OG image, OG metrics, the tearsheet and the PDF routes do not read it.
`factsheet-share/[token]` mounts `FactsheetView`, so the share page gets the same "—" and reason.
That is HTML, not a fixed-height image. The server PDF is a print of the factsheet page
(`SERVER_PDF.md`), so a below-floor record's PDF also carries the extra muted line under the KPI
strip and the retained §IV block. That is the one fixed-page surface where an extra line can move
content, which is why it is named in the human-verification check above. The leverage re-derive (`deriveSeriesBundle`) builds
through `buildComparatorBlock`, so it carries the field too. The OG, share, tearsheet, PDF and
scenario-share tests all passed (below).

**Deliberate consequence: the zero-paired form.** A comparator can have no paired interval at
all while its block is still built (not the unavailable form). The case is a strategy that starts
after the SPX fixture's last close, 2026-05-08, with SPX active. Its block is now
`summary: null, joint: null, jointWithheld: {paired: 0, floor: 10}`. Before this fix that
factsheet showed a 7-cell strip and no §IV. It now shows 9 cells with α/IR as "—", §IV with
every row "—", and "... paired with SPX; this record has 0." twice. The statement is true. It
sits beside the existing bench header, which dates SPX's last close ("SPX to May 8"). It also
matches the widget's accepted fix-C consequence 3 ("this book has 0"). So this is one cause told
consistently, not a wrong cause. A test pins it (below).

**Snapshot moved: 6 keys, one shape.** `src/lib/factsheet/__snapshots__/build-payload.test.ts.snap`
gains `"jointWithheld":null` on the `btc` and `spx` comparator blocks of each of its 3 payloads:
- the composite arithmetic payload,
- the `ingestSource:'api'` payload,
- the single-key geometric payload.

Every block in those snapshots is at or above the floor, so the value is null. The `none` block
does not gain the key. I checked the move mechanically: removing the substring
`"jointWithheld":null,` from the new snapshot yields a byte-equal copy of the old one. No other
value moved.
