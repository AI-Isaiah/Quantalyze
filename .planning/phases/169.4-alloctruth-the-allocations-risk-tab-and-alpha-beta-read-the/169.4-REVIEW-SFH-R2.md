## R2-MEDIUM-1: the signature empty-state names the ACTIVE comparator as the missing data, but the data is always BTC

- **Where:** `src/app/factsheet/[id]/v2/SignaturePanels.tsx:108,115` (`emptyReason` interpolates
  `benchName`, which is `cmp.shortName` from `:64,70`) and
  `src/app/factsheet/[id]/v2/CrossSignaturePanels.tsx:111,121,182` (`view={`${benchName} prices`}`,
  with `benchName={cmp.shortName}` at `:57,64`). Both signature payloads are built from BTC only:
  `src/lib/factsheet/build-payload.ts:827,832` (`computeEventSignatures(stratRet, btcAligned, …)`
  and `(btcAligned, btcAligned, …)`). The active comparator is user-selectable (`btc` / `spx`,
  `factsheet-context.tsx:201`).
- **Failing scenario 1:** the BTC read fails, or leaves no covered interval (D-54, where
  `btcAligned` is all null). Every benchmark view is `null`. The user switches the picker to SPX,
  and the section stays mounted because `hasComparator` is true.
- **What the user sees:** "Win Event · of SPX" over an em-dash reading *"Not measurable: no win
  event has a complete ±14-day window of SPX prices."* That is false: SPX is a full fixture and was
  never consulted. The cross panels also say "no SPX event has a complete ±14-day window of SPX
  prices". The sentence is new text written by the CR-01 fix. The mislabelled title was already
  there (fix-B recorded it as pre-existing). The fix copied that label into a statement about
  which data is missing. Populated panels now also read "Win Event · of SPX · 86 events" while
  they draw BTC trajectories.
- **Failing scenario 2:** the same outage with the default BTC comparator.
- **What the user sees:** *"no win event has a complete ±14-day window of BTC prices"*. This blames
  window completeness for what is really an outage. The fix for round-1 MEDIUM-2 named this exact
  class for the allocator section ("BTC prices are unavailable right now"). The same page now gives
  two different causes for one event.
- **Severity: MEDIUM.** The copy is user-facing and names the wrong cause. No figure is wrong.
- **Recommendation:** these panels are BTC-only, so hard-code `"BTC"` for their benchmark label and
  reason, or thread a `benchmarkName` field from the payload. Do not read the active comparator's
  `shortName`. When the BTC comparator block is unavailable (`comparators.btc` built by
  `unavailableComparatorBlock`), render the allocator's outage wording instead of the
  window-completeness reason. Pin it with a test that mounts `SignaturesSection` with SPX active and
  all benchmark views `null`, and asserts that no "SPX" appears in the empty-state text.

## R2-MEDIUM-2: below the paired floor, every factsheet drops alpha, IR and §IV with no cause named

- **Where:** `src/lib/factsheet/comparator-block.ts:94-103`: under `MIN_PAIRED_OBSERVATIONS`,
  `joint` is `null`. It surfaces in `src/app/factsheet/[id]/v2/FactsheetView.tsx:1470` (the KPI
  strip adds the α/IR cells only `if (j && …)`) and in `src/app/factsheet/[id]/v2/MetricsColumn.tsx:263`
  (§IV "Benchmark — vs X" renders only when `jointCmp.joint` is set). `buildComparatorBlock`
  builds every comparator block (BTC and SPX, strategy / scenario / allocator Overview, OG /
  tearsheet / PDF, and the L≠1 re-derive through `deriveSeriesBundle`). So the floor reaches all
  of them. Fix-C recorded this as deliberate consequences 1 and 2, marked "requires human
  verification".
- **Failing scenario:** a strategy or book with 1 to 9 paired intervals. This happens in a new
  allocator's first week, and on any strategy whose record started less than about two weeks
  before a comparator's last close. For SPX, that is any record starting after roughly
  2026-04-24, because the SPX fixture ends on 2026-05-08. Before this fix, α/IR and §IV rendered
  in these cases (the figure was noise, which was MEDIUM-4's point). Now they are absent.
- **What the user sees:** the picker still reads "BTC" (or "SPX"), and the cumulative chart still
  draws the comparator line. But the KPI strip collapses to the 7-cell layout, the same one
  `cmpKey === "none"` produces, and §IV disappears. Nothing says why. On the allocations page, the
  alpha/beta widget beside it says *"Alpha and beta need at least 10 days paired with BTC; this book
  has N."* So one screen gives the cause in one place and silently drops the section in the other.
  On a strategy factsheet there is no widget, and the absence reads as a missing feature or a
  broken comparator. The repo's null rule (DESIGN.md, #509: an absence names its cause) is met on
  the widget and not here. This change also reaches CSV strategies, which showed §IV at 1 to 9
  paired days before.
- **Severity: MEDIUM.** A surface is hidden with no cause given. No wrong number is shown, and
  parity under D-69 holds, because neither surface shows a figure below the floor.
- **Recommendation:** carry the paired count on `ComparatorBlock` (for example `joint_paired: number`,
  or a `joint_withheld: { paired, floor } | null`). Where the α/IR cells and §IV would be, render
  "—" and one muted line with the widget's wording ("need at least 10 days paired with {cmp}; this
  record has N"), so the two surfaces give one cause, as they already give one number. Fix-C
  avoided this only because `types.ts` belonged to another fixer in round 1. That constraint is
  gone now.
