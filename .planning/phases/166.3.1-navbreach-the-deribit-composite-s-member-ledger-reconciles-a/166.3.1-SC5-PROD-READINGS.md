## Why the books differ from D-08's expectation

`166.3.1-SC5-DECISION.md` measured on 2026-10-13 with a dust floor of 1000 USD: the book 1 Deribit
key and MT5 key were both `dust`-anchored (NULL), and the MT5 key replayed to
`inception_unreconciled`. Between that measurement and the first compose on the deployed code,
FLOWTIMING (PR #1018, v0.131.1.0, merged to main and deployed on 2026-10-13, before
`def5e599a`) moved `USD_FLOORS.dust_nav` from 1000.0 to 100.0 (`account_unit.py`, founder "$100").
The NAVBREACH branch was cut before it (the plan's own note says FLOWTIMING's code was not on this
phase's branch when SC-5 was planned). At the 2026-10-14 derive both book 1 keys' live equity read
is between the new 100 USD floor and the old 1000 USD floor, so the epilogue no longer stamps
`dust`: both keys now store a non-null anchor (`sc5-null-anchor-keys` lists neither), they compose
as ordinary anchored keys, and book 1 has no null-anchor candidate at all. Book 2's MT5 key is
`nonpositive` (terminal exactly zero), which no floor change touches, so it still exits through the
D-08 rule.

So book 1 reads trustworthy without the exit rule having done anything for it: the evidence is
that its row carries no `no_capital_key_exited` flag and its stored inputs hold no null anchor.
What this reading cannot say is whether the NAVBREACH rule would also have rescued book 1 had the
floor stayed at 1000 (the inception residual that blocked it is a property of the MT5 key's stored
series, which was not re-measured here).
