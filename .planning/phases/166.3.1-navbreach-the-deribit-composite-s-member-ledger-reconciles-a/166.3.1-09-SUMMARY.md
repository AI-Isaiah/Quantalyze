# Phase 166.3.1 Plan 09: D-08 A3, the MT5 shapes and the never-worse fences Summary

A no-capital key whose terminal day falls after its last return day now ends on that last return day at the writer's own rolled-back level (nothing after it booked, a Deribit writer basis kept in writer mode by a zero-day pad), both MT5 shapes compose under the same rule, and a bad candidate can no longer make a book worse than today at either layer.

Source: plan 08's scratch CSVs (`ki2.csv`, `ki3.csv`) under `$HOME/.cache/quantalyze/deribitwedge-167.1.2.2.1/navbreach-sc5/`, read with `python -I` and an explicit `sys.path` to this worktree's `analytics-service`, through `variants.py` (which printed it) and a small cross-check script. - `L < P` true, `P = L + 1` day.
- `L in W` (the stored writer day-P&L series) is **False**; W has exactly one day after L, and it is P.
- The key's stored return on L is exactly `0.0` (`r_L == 0` true); no event flow dated on L.
- One event flow, one dropped-day P&L and one writer-basis flow sit after L (the dust deposit and the final day's P&L).
- The stored terminal is at or below `DUST_NAV_FLOOR`; the rolled-back level on L is finite, positive and below the floor.
- `variants.py` V2 (end on L, writer basis padded with a zero day on L) replays with no degrade reason and `writer_basis: True`; V1 (legacy roll) also composes. The `_no_capital_level_on_last_return_day` helper returns exactly the replay's own level on L for this key (`math.isclose`, rel 1e-12: True).

So the zero-pnl pad's condition holds on PROD and the no-pad-over-a-return rule was not loosened. The other two keys do not use the pad at all:
- Book 1's MT5 dust key: P equals L, no writer basis, `inception_unreconciled` (implied start 0.15% against the 0.01% band). Unchanged: `dropped_key`.
- Book 2's MT5 nonpositive key: `P = L + 1`, terminal exactly 0.0, **no writer basis** (a Deribit-only field), one event flow and one dropped-day P&L after L. It takes the walk-back (legacy roll), never the pad; its rolled-back level on L is finite, positive and above the dust floor. Book 2 therefore does not depend on the pad, and the "book 2 would stay on dropped_key" branch of the instruction did not occur, so no stop was needed. (Book 1 stays untrustworthy for the recorded SC-9 reason whatever the pad does.)

Note: PROD's book 2 key carries a dropped-day P&L on P; the plan's test (b) has none, so the walk-back with a P&L term is exercised only by test (a) (writer P&L) and the two-candidate book. No gap in code coverage, but flagged for plan 10's reading.

## What changed

`analytics-service/services/job_worker.py`
- The key_inputs loop only NAMES a candidate (token in `_NO_CAPITAL_ANCHOR_REASONS`, entry in `last_return_day`, stored terminal, A2: terminal at or below `DUST_NAV_FLOOR`, all judged on the STORED terminal at P). The rule is applied after the stitch and the writer-basis build.
- `_no_capital_level_on_last_return_day`: pure helper, `level_{d-1} = level_d - F_d - P&L_d` over the days in (L, P], latest first, on the writer basis when one is stored, else on event-time flows and stored dropped-day P&L.
- Apply block: end day E = P, or L when P > L (A3). Anchor and realized terminal become `(E, level)`; `departed_end_by_key` and `no_capital_exit_by_key` carry E; flows, dropped-day P&L and both writer-basis series are trimmed after E; pad of a 0.0 writer P&L on L only when A3 ran, the trimmed basis is non-empty, L is absent from it and the stored return on L is exactly 0.0. An emptied trimmed basis is dropped (legacy roll).
- `_AllocatorKeyInputs` bundle and `_compose` closure; first compose on the applied inputs, and on `NavReconstructionError` with a candidate in play one re-compose on the inputs as stored (shallow-copy snapshot taken before the rule). No candidate, or a second refusal, takes the unchanged permanent-failure path (`_compose_refused`, the old except body). Counts-only warning.

`analytics-service/services/allocator_equity_compose.py`
- Candidates (keys in `no_capital_exit_by_key`) are replayed inside a handler for `NavReconstructionError` only; a refusal, a missing equity or a blocking reason by the module's own `_is_trustworthy` takes the key back out (anchored lists, per-key maps, departed end, exit map) and adds `NO_ANCHOR` + `DROPPED_KEY`. Other keys' refusals still raise. Counts-and-reason-class warning. `no_capital_exited_keys` is built from the surviving exits.

`allocator_equity_derive.py` is unchanged (`git diff --stat` empty): no band, tolerance or replay rule loosened (D-02). `run_derive_broker_dailies_job` is untouched (all job_worker hunks are at the allocator-equity job).

## Deviations from Plan

**1. [Rule 1 - correctness of the "revert to today" requirement] The rule is applied after the stitch, not inside plan 08's loop block.** The plan says to keep each changed key's stored inputs and restore them on a refusal. Plan 08's block trims and rebinds before the shared-account stitch, so for a stitched candidate the stitched flows and writer basis would already have been built from trimmed inputs and a restore could not reproduce "today". The loop now only names the candidate; the apply block runs once the stitch and `writer_basis_by_key` exist, and a shallow-copy snapshot taken just before it is exactly today's input. Plan 08's behaviour and tests (tracer, A2 test) are unchanged and green. Files: `job_worker.py`.

**2. [Test wiring] Patch target.** The plan says to patch `services.job_worker.compose_allocator_equity`; the job imports that name inside the function, so the wrapper and the spy patch `services.allocator_equity_compose.compose_allocator_equity` (the module the import reads from).

**3. [Fixture, so a neuter can bite] NO-TERMINAL carries a withdrawal.** With the compose fallback in place, a flat zero-anchored key is refused by the replay and falls back to `dropped_key`, so neuter 5 could not turn a flat fixture RED. The fixture has a 500.0 withdrawal on the last day (an emptied account the replay would accept as zero capital), so "anchor 0.0 with no terminal" really composes and is named, and the test goes RED. The intent (no terminal means no level that is not invented) is unchanged.

**4. [Additions beyond the plan, all small]** a healthy-candidate control and a does-not-widen-to-other-keys test in the compose file (without them the fallback tests could pass because the rule never fires); a counts-only log test; an MT5-shaped NOTHING-AFTER test (in writer mode the event-time flows are not what the replay reads, so only the spy sees them there; the return-factor shape makes the trim visible in the book); a pin that a refusal with no candidate, and a second refusal, still delete the row.

**5. [Process, carried from plan 08] Branch name.** `wt/166.3.1-p09` is outside the `agent-*` namespace the commit template expects; it is not protected and the cwd-drift check passed. Each task is a `test` commit then a `feat` commit so the RED state is a real commit.

**6. [Scope] STATE.md, ROADMAP.md and REQUIREMENTS.md were NOT touched**, as in plan 08: the repo's rule is that the gsd-tools handlers clobber them. The orchestrator owns them.
