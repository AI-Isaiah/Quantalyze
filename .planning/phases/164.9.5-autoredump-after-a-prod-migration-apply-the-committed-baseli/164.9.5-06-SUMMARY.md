Two observations. Neither is a FINDING, and both are recorded so `/gsd-secure-phase` does not have to
rediscover them:

- **Default action inputs.** In `redump-pr`, `actions/checkout` and `actions/setup-node` receive the job
  token through their default `token:` inputs, as every checkout in this repo does. That token is not in
  the file text, so the grep above cannot see it. This is not a finding because both actions are
  GitHub-owned and pinned to a full commit sha (item 6), and checkout does not persist the token (item 3).
  Item 6 is what bounds this path.
- **The ghcr login persists for the rest of `redump-dump`.** `docker login` writes the job token into the
  runner's docker config, and it stays there until the job ends. This is not a finding because that token
  is read-only (`contents: read`, `packages: read`), and the later steps (setup-cli, the Supabase CLI, the
  script and `upload-artifact`) already receive the PROD credential or run first-party code. The step is
  the same template as the `check` job in `migration-drift-check.yml`, which the ghcr contract test pins.

actions (item 6). It stays accepted until a ruleset or branch protection exists, which is a founder
decision deferred until paying clients.
