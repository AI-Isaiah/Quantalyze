## (b) New silent failures introduced by the pass

**No new CRITICAL or HIGH.** Each question in the brief, answered:

**Can the D-31 skip now let a dump that lost an extension or schema pass green with no red
anywhere?** Not permanently. On the `ahead` path nothing is written: no artifact is uploaded and
`redump-pr` skips on `changed == 'true'`, so the lost-extension dump never reaches a bot PR, and
the committed pair is not moved. A green skip therefore hides nothing it could pass on.

**Does the next run always catch it?** The skip keeps the committed dump unchanged. So the next
run whose listing is `equal` compares the SAME committed dump against a fresh PROD dump, and its
floor refuses by name. That run is the run of the migration merge that made this run `ahead`, or
of a later one. This holds in every case below:
- An out-of-band drop that persists. It is loud on the next `equal` run and red on that merge
  commit, which is the recorded WR-09 remainder.
- A later migration that really drops the extension. That run refuses (the recorded R2-08 wedge).
- A transient pg_dump omission on the skipped run. Nothing was written, and the next run dumps
  anew.
- A pending run cancelled by GitHub's concurrency group. `supabase-migrate-${{ github.ref }}` with
  `cancel-in-progress: false` still cancels an older PENDING run when a newer one queues. The
  newest run survives, and `db push --include-all` applies the cancelled run's migration too, so
  its redump is `equal` and judges.
- A merge reverted after its `apply-test` refused on TEST. The revert commit touches
  `supabase/migrations/**`, so it triggers its own run, and that run's listing is `equal` again.

The only way no later `equal` redump ever runs is the newest migration run failing before or
inside `redump-dump`. That is red on `main`'s head commit, so it is visible. This is the carried
R2-01 dependency, now carrying one more floor (see R4-01).

**Is the skip still behind every secret, data or integrity gate?** Yes. In `gateDump` all of the
following run before the verdict, and `ahead` cannot reach any of them early:
- `runGitleaksGate`;
- `judgeSecretScan`;
- `judgeIntegrity` (NUL, `client_encoding`, home path);
- `judgeShapeCounts` (zero tables, data statements);
- the D-27 strict-basename refusal.

The code comment above `runGitleaksGate` names the single exception (the completeness floor). So
does the BASELINE.md sentence "the secret, gitleaks, integrity and data-statement refusals still
run first".

### R4-02 (LOW, CAUSED by the round-3 pass, a residual of R3-04): the doubled-quote alternation misses the spaced and the OPTIONS-in-literal forms

**Measured misses against `SECRET_SCAN_RE`:**
- `password = ''abc''`, a spaced libpq keyword. libpq allows spaces around `=`.
- `password= ''abc''`.
- `OPTIONS (password ''abc'')` inside an `EXECUTE '…'` string in a function body.
- `password='' abc''`, a value starting with a space.

Each is the doubled-quote twin of a form that already hits undoubled, or of the spaced libpq miss
R3-04 already records.

**Why LOW.**
- pg_dump writes function bodies dollar-quoted, so a doubled quote appears only in author-written
  nested literals, `COMMENT ON` text and `DEFAULT` literals.
- gitleaks' default ruleset (`useDefault = true`) still runs.
- A credential inside a dumped function body came from a public migration, unless the object
  was created out-of-band.
- There are 0 occurrences today.

**Recommendation.** Record the misses with R3-04. Do not widen to allow spaces:
the widening neuter above shows that turns `IF password = '' THEN` red.
