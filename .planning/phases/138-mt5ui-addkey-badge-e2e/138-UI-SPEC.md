## Color

From `DESIGN.md §Color`. No new hex. 60/30/10 split for these surfaces:

| Role | Value | Usage in this delta |
|------|-------|---------------------|
| Dominant (60%) | `#F8F9FA` page / `#FFFFFF` surface | wizard background, inactive venue cards, inputs |

Accent reserved for: the selected venue card, the primary submit button, the `api_verified` badge
fill (`TrustTierLabel.api_verified`), and inline setup-guide links. Never on the MT5 field labels,
helper text, or card captions.

**Semantic-color gate the executor MUST honor (DESIGN.md §Semantic-color gates):**
- The up-front "use your INVESTOR password, never your master password" instruction is **muted
  neutral text (`text-text-muted`), NOT amber and NOT red.** It is steady-state guidance, not an
  event. Tone is EARNED by an actual failure, not by a preemptive warning. Coloring it amber/red
  preemptively is the exact "color by shape, not by meaning" failure the gate forbids.
- Red (`--color-negative`) appears ONLY after a real rejection — inside the Error Envelope for
  `KEY_AUTH_FAILED` / `KEY_MT5_WRONG_SERVER` / `KEY_MT5_MASTER_PASSWORD`. Not on the form at rest.
- No `⚠` glyph on the resting form. If a glyph is used at all it is only the allowlisted semantic
  set and only adjacent to an actual error string.

## Delta 1 — Flag-gated MT5 venue card (MT5UI-01)

**Pattern:** verbatim clone of the sFOX card append in `ConnectKeyStep.tsx` (lines 82–97).

- Add `MT5_UI_ENABLED = process.env.NEXT_PUBLIC_MT5_ENABLED === "true"` to `closed-sets.ts`,
  mirroring `SFOX_UI_ENABLED`: **single static member access** (so Next.js inlines it into the
  client bundle at build time), strict equality against the exact string `"true"` — `"1"`,
  `"TRUE"`, `"on"`, `""`, unset all read **OFF (fail-closed)**.
- Append the MT5 `ExchangeOption` to the wizard's local `EXCHANGES` array ONLY when
  `MT5_UI_ENABLED` is on (`...(MT5_UI_ENABLED ? [{…}] : [])`). **OFF = byte-identical** — the spread
  is empty, the venue grid renders today's four cards, no MT5 pixel exists. A test pins this
  (mirror `closed-sets.sfox-flag.test.ts` + the `ConnectKeyStep.test.tsx` sfox-gated cases).
- Card content (DESIGN.md §Broker Selector Grid card visual — white surface, 1px `#E2E8F0` border,
  `rounded-md`, active `border-accent bg-accent/5`, inactive `hover:border-accent/50`):
  - name: **`MT5`**
  - caption: **`Live investor (read-only) login. Forex & CFD.`** (declarative, sentence-case,
    no adjectives-where-a-number-belongs — DESIGN.md §Voice)
  - `data-testid="wizard-exchange-mt5"` (the existing per-card testid convention, for the e2e).

Client flag `NEXT_PUBLIC_MT5_ENABLED` (wizard visibility) is DISTINCT from server `MT5_ENABLED`
(`isMt5EnabledServer`, already landed) which admits the read. Both flip in Phase 139; 138 wires +
tests both, dark.

## Delta 2 — MT5 three-field credential form (MT5UI-01)

MT5 collects three credentials that map onto the existing `{api_key, api_secret, passphrase}`
encrypted slots — **the 135 convention, authoritative in `analytics-service/services/job_worker.py:916-917`:**

| MT5 field | Encrypted slot | ConnectKeyStep control | Label (DM Sans 12–13px) | Required | Masked |
|-----------|----------------|------------------------|-------------------------|----------|--------|
| Login (account number) | `api_key` | key input | **`MT5 login`** | yes | no |
| Investor password | `api_secret` | secret input (+ Show/Hide) | **`Investor password`** | yes | yes |
| Broker server | `passphrase` | third field | **`Broker server`** | **yes** | no |

Implementation notes (reuse existing `ExchangeOption` metadata; extend minimally):
- `credentialLabels`/`credentialPlaceholders` already relabel the key+secret inputs (the Deribit /
  sFOX precedent). Set `key → "MT5 login"` (placeholder `Your MT5 account number`) and
  `secret → "Investor password"` (placeholder `Your read-only investor password`).
- The third field (broker server) must be **REQUIRED**. Today `ConnectKeyStep`'s third slot is the
  passphrase, gated by `requiresPassphrase` and hardcoded-labelled `"OKX Passphrase"`. MT5 needs a
  **passphrase-label + passphrase-helper override** on `ExchangeOption` (extend the same way
  `credentialLabels` was added). Do NOT fork a new form component — this is a labeled variant of the
  existing field, exactly as sFOX was.
- Submit gating: the CTA `disabled` predicate must include the broker-server field for MT5
  (`requiresPassphrase && !passphrase` already covers it — set `requiresPassphrase: true` on the
  MT5 card so the server field renders and gates submit).

### Inline helper placement (DESIGN.md §Voice — declarative, threshold-attached)

Two inline helpers, both `text-micro text-text-muted` directly beneath their field (`mt-1`), mirroring
the existing OKX-passphrase helper (ConnectKeyStep lines 399–402):

1. **Under "Investor password"** — the prominent, up-front master-vs-investor steer (the #1 user
   error; master is server-rejected):
   > `Use your investor (read-only) password — not your master password. A master password can
   > place trades, so we refuse it and store nothing.`

   This is muted neutral text, NOT amber/red (see Color gate). It states the fact and its
   consequence, matching the honest tone of the `KEY_MT5_MASTER_PASSWORD` cause copy.

2. **Under "Broker server"** — the "find it in your terminal" guidance (mirrors the
   `KEY_MT5_WRONG_SERVER` fix copy so the resting form and the error agree):
   > `Open your MT5 terminal's login window and copy the server name exactly as it appears there —
   > it is broker-specific and often carries a region or Demo/Live suffix.`

Plus the existing per-exchange setup-guide deep-link (ConnectKeyStep lines 332–342) resolves to
**`/security#mt5-readonly`** for the mt5 selection (the `#${exchange}-readonly` template already
does this).

### Guest-Mode trust signal (server-enforced, surfaced up front)

Mirror the sFOX `SFOX_REJECT_ATOM_BODY` swap (ConnectKeyStep lines 100–104, 193–197): when the
selected venue is `mt5`, swap the **"What we reject"** trust atom body to the MT5-honest structural
claim, so the server-enforced read-only Guest-Mode signal is visible BEFORE the user submits:

> `MT5 master passwords can place trades, so we reject them at connect time and store nothing —
> only a read-only investor login is accepted.`

Every other venue renders today's scope-rejection atom byte-identically.

## Delta 3 — Investor-password setup guide (MT5UI-01)

**Placement decision: INLINE + a flag-gated `/security#mt5-readonly` page section — NOT a modal.**
This is the exact sFOX/Deribit precedent (`#sfox-readonly`, `#deribit-readonly` nested under
`#readonly-key`). Rationale: a modal interrupts; the wizard's established pattern is a quiet inline
deep-link to a stable `/security` anchor, and DESIGN.md's "every surface is a dated document"
posture favors a persistent, linkable reference over an ephemeral overlay.

- Add a `#mt5-readonly` SubAnchor **nested inside the existing `#readonly-key` section** of
  `security/page.tsx`, titled **`MT5`**, mirroring the `#sfox-readonly` block placement and the
  page's `Section id="…"` anchor-stability contract (`security/page.test.tsx`).
- **Flag-gated ABSENT when MT5 is off** — exactly like the sfox block (`security/page.test.tsx`
  "does NOT render the #sfox-readonly block when the server flag is off"). Pre-launch there is no
  MT5 guide to link to.
- Content: sentence-case, declarative steps for finding the investor (read-only) password + the
  exact broker-server string in the MT5 terminal login window. No hero copy, no adjectives.
- The wizard deep-link (`/security#mt5-readonly`) opens it in a new tab (`target="_blank"
  rel="noopener"`), matching the existing setup-guide link.

## Delta 5 — Distinguishable error copy (MT5UI-02) — ZERO NEW COPY

All three failure states already exist in `wizardErrors.ts` (Phase 135) and render through the
canonical Error Envelope (`ErrorEnvelope.tsx` / DESIGN.md §Error Envelope). 138 only wires the mt5
branch to surface them and pins the UX per state. **Author no new envelope strings.**

| Failure | Code | Envelope title | Actions | Distinguishing message |
|---------|------|----------------|---------|------------------------|
| Invalid login / investor password | `KEY_AUTH_FAILED` | "The exchange rejected these credentials." | `clear_and_retry`, `request_call` | The account/investor-password pair never authenticated — fix the creds. |
| Wrong broker server | `KEY_MT5_WRONG_SERVER` | "We could not find that broker server." | `clear_and_retry`, `request_call` | Server name is exact/broker-specific; fix = copy it from the terminal login window. |
| Master password used | `KEY_MT5_MASTER_PASSWORD` | "This MT5 login can place trades." | `try_another_key`, `request_call` | The password was CORRECT but is a master login that can trade → refused, nothing stored. Steers to the investor password. |

UX contract (all via `buildEnvelope(code, correlationId)` → DESIGN.md §Error Envelope visual):
- `role="alert"`, `rounded-md border border-negative/30 bg-negative/5 px-4 py-3`.
- Title 16px DM Sans semibold `#1A1A2E`; body = numbered `fix[]` list (12px DM Sans `#4A5568`).
- Retry CTA below body, above the always-collapsed `<details>` diagnostics.
- The three MUST be visually/textually DISTINGUISHABLE — the e2e asserts each attempt renders its
  own title (no collapse to a generic `KEY_AUTH_FAILED`). The 135 detail-string classification
  (`MT5_MASTER_PASSWORD_DETAIL` / `MT5_WRONG_SERVER_DETAIL`) already routes these; 138 proves the UI
  surfaces them.
- Authoring rule (DESIGN.md): every error path calls `buildEnvelope` — no inline error strings.

## MT5-Manager-Parity (planner decision)

`ApiKeyForm.tsx` (manager surface: `ApiKeyManager` / `StrategyForm` / `AllocatorExchangeManager`)
derives its `<Select>` from `EXCHANGES` ← `UI_EXCHANGE_CODES`. If the planner adds `mt5` to
`UI_EXCHANGE_CODES` behind `MT5_UI_ENABLED` (the sFOX precedent, lines 179–189), the manager
`<Select>` auto-widens to offer MT5 too — but `ApiKeyForm` would then need the SAME MT5 field-label
carve-out (`isMt5`, mirroring the existing `isSfox` branch: relabel key→"MT5 login",
secret→"Investor password", surface the broker-server field + the investor-password steer).

**Recommendation (keep the phase tight):** scope MT5UI-01 to the **wizard `ConnectKeyStep`** (the
surface MT5UI-01's own path names) and keep `mt5` OUT of `UI_EXCHANGE_CODES` this phase, so
`ApiKeyForm` stays byte-identical. If manager-surface MT5 add-key is wanted, the planner adds it as
an explicit task with the `isMt5` carve-out — do not let it ride in silently via a `UI_EXCHANGE_CODES`
widening (that would ship an unlabeled MT5 option on the manager form).

## DESIGN.md constraints the MT5 delta MUST NOT violate

1. **Three-voice type:** form values stay DM Sans; only rendered product figures use Geist Mono
   `.font-metric`. No mono on a form label/input.
2. **Semantic-color gate:** the preemptive investor-password steer is muted, NOT amber/red. Tone is
   earned by an actual rejection event, surfaced only inside the Error Envelope.
3. **No new tokens:** no new font, hex, radius, spacing value, or motion. Reuse the wizard's existing
   utilities; no raw `text-[Npx]` (repo-wide `no-raw-font-px` = error).
4. **AI-Slop Ban:** no icon-in-circle, no gradient, no emoji (only the allowlisted `⚠ — · × ✓`
   adjacent to real text), declarative sentence-case copy — no "Unlock/Empower/seamlessly".
5. **Error Envelope authoring rule:** every error path goes through `buildEnvelope`; no inline
   error strings.
6. **Badge integrity:** no new trust-tier variant; `TRUST_TIER_TOKENS` + its drift gate untouched.
7. **Flag byte-identity:** `NEXT_PUBLIC_MT5_ENABLED` OFF ⇒ the wizard is byte-identical to today
   (empty spread, no MT5 card, no `#mt5-readonly` block); a test pins it.
