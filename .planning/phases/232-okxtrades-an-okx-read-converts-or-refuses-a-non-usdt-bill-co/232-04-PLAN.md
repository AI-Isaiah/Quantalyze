<objective>
VREAD-07, cron half: the cron stores the contiguous oldest prefix an OKX read returns at its deadline and
holds every cursor, so a first window longer than one tick's budget completes across ticks.

Purpose: plan 232-02 makes every stop of the OKX walk return whole windows, a contiguous oldest prefix,
under `daily_pnl_deadline_okx`. The cron passes no deadline today, so a long first window runs into the
60 s per-key cancel and stores nothing on every tick. This plan gives the cron an OKX-only deadline and a
"prefix" tick: store the rows, move no cursor, report `held` with `fetch_partial_prefix`. The next tick
resumes from the stored high-water.
Output: one constant, one helper, five gates in `_sync_single_key`, a new test class with a multi-tick
tracer through the real walk, PROOF-01 records, the runbook corrections and the VREAD-07 close.
</objective>

## Decisions this plan applies (quoted from CONTEXT and its orchestrator rulings)

- CONTEXT "Fix shape?": "A walk stopped by the read deadline returns only fully read windows, a contiguous
  oldest prefix, under a distinct non-error marker so the caller stores that prefix and the next tick
  resumes from the stored high-water [...]; the exact marker and the caller wiring are research outputs."
- Ruling Q2: "reuse `daily_pnl_deadline_okx`". RESEARCH "Cron change (Plan B)" gives the gates: the call
  carries `read_deadline_s` for OKX only; `fetch_prefix_only` = the deadline flag and not degraded; it is
  added to `should_advance_cursor`, to `strategy_advances` and to `recompute_strategy_ids`; status falls
  out of the existing classifier as `held` with a `fetch_partial_prefix` key; the store gate is unchanged.
- Orchestrator follow-on, not fixed: "a marker-present cron strategy whose 30-day window exceeds the OKX
  cron deadline re-reads the same prefix every tick (loud: `held` + `fetch_partial_prefix`); recorded in
  the phase report."
- Heartbeat: `held` is in `_NON_OK_STATUSES`, so `_cron_sync_error_counters` turns a held key into an
  `error` `cron_runs` row naming `held=N` (pinned today by `test_an_all_held_tick_is_an_error_row`). Ruling
  Q2's `held` prefix tick inherits that row. The plan pins the row and does not change it; the reading of
  SC-2 this implies is surfaced to the orchestrator.
- `OKX_CRON_READ_DEADLINE_S = 35.0` is RESEARCH's `[ASSUMED]` split of the 60 s `KEY_SYNC_TIMEOUT`
  (25 s left for the balance read, the per-strategy RPCs, marker writes and enqueues); reversible.
