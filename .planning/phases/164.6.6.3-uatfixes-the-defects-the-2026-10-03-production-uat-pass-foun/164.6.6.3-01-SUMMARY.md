# Phase 164.6.6.3 Plan 01: the deal-history wait, derive half Summary

A fresh MT5 login on the jobs terminal now polls `history_deals_get` until the deal count is stable, and
hands the ledger to the combine only then; an expiry under material equity is a retryable transient with its
own message and ERROR line, never a permanent stamp and never a terminal restart.

## What was built

- **Settle loop (`mt5_read.py`)** runs between the first `history_deals_get` and the POST login bracket, so the
  POST bracket covers the poll window. Settled = two consecutive equal counts AND (count > 0 OR equity not
  material). Equity comes from the PRE `account_info`; the loop never calls `account_info`. Missing or
  non-finite equity skips the wait. On expiry it raises `Mt5HistoryUnsettledError(deal_count, material)` (a
  plain `Exception`, counts and a boolean only) and returns nothing.
- **Settled record (`mt5_client.py`)**: `_MT5_TERMINAL_HISTORY_SETTLED`, written by `note_mt5_history_settled`
  only after the stability check AND the POST bracket passed, with the holder registry's epoch guard.
  `mt5_history_wait_due(terminal_key, holder)` is False only for a real key that is the terminal's previous
  holder AND whose history last settled there. Cleared by the one test reset (the seventh registry).
- **Derive caller (`job_worker.py`)** computes `fresh` inside the lease and before `asyncio.to_thread`
  (before `login()` stamps the holder), passes `settle_history=fresh`, and uses
  `timeout = _MT5_DERIVE_READ_TIMEOUT_S + (_MT5_HISTORY_WAIT_S if fresh else 0.0)`. The sixth `except` arm
  returns `FAILED/transient` with `_MT5_HISTORY_UNSETTLED_MESSAGE`, one ERROR line, no failed-analytics stamp,
  no restart.
- **Test infrastructure**: `deals_by_call` on `_FakeMt5Transport`; autouse `_mt5_read_never_sleeps_for_real`
  in `conftest.py` (per-test fake clock, so no test sleeps or spins).
