## Orchestrator-verified claims — re-measured, not accepted on report

⛔ An agent's verdict is not evidence. These were re-derived independently:

- **T-04 — the fixture, the single highest-risk file in the phase.**
  `tests/fixtures/mt5_login_rejection_observations.json` is the designated landing place for LIVE
  broker rejection text. Parsed: **1 element, 0 non-protocol observations.**
  ⭐ **VERDICT: synthetic, carries no account identifier, no server name, no credential.**
  ⛔ Recorded as a verdict only — no specimen and no searched-for pattern is reproduced here, because
  a proof-of-absence can publish the very thing it proves absent.
- **T-06 — no Retry on an undecryptable key, and it must be DERIVED rather than hand-set.**
  Measured: `KEY_MUST_BE_RECONNECTED.actions = [request_call, expand_log]` against
  `RECOVERABLE_ACTIONS = {clear_and_retry, try_another_key}` ⇒ **overlap 0 ⇒ `recoverable: false`**.
  Offering a Retry on a ciphertext that will never decrypt IS the defect; it cannot render.
- **T-28 — broker text never reaches `error_message`.** Scanned for any concatenation into that
  field: **none**. Every arm's `error_message` is a fixed `_MT5_BACKFILL_MESSAGES` constant; the
  scrubbed broker detail goes only to the audit event's `sanitized_message` and a warning log.
- **T-31 — the kill switch fires before any terminal touch.**
  ⚠️ **One correction to the audit's wording, recorded rather than smoothed over.** The report called
  the gate "the first statement in `_mt5_fetch_window`". It is NOT — three imports precede it, and a
  naive text-offset check appears to show the gate AFTER the lease and the read, because the
  function's docstring names both. Resolved by **AST**, which is the authoritative measure:
  `mt5_enabled_server` line 2412 < `mt5_terminal_lease` line 2430 < `read_mt5_deal_ledger` line 2433.
  ⭐ **The substance holds — the gate precedes the lease and the read.** The phrasing did not.

## The one judgement call, and it was NOT inherited

The review round routed a user-facing defect to Phase 167 CREDTRUST: a genuine credential rejection
now lands on the transient arm, whose copy asserts the network is unavailable and offers a Retry that
cannot succeed. The orchestrator classified that **user-facing, not security**, and explicitly
instructed the auditor NOT to inherit that classification silently.

⭐ **The auditor re-derived it independently and concurred:** no credential exposure, no authz bypass,
no data-integrity loss — the harm is a misleading message. It is the INVERSE of T-02 (which is about
false blame), not a new instance of it. The routing was verified as real rather than narrated: Phase
167's ROADMAP entry carries this phase's dated evidence, with its unmet hard dependency on 164.7 and
the reason a premature fix would mislead customers.

## Accepted and transferred, stated as such

- **T-13 (accept).** `errorCode` is set in component state and consumed ONLY by the `disabled`
  expression — never interpolated into rendered text. Low, and accepted rather than called closed.
- **T-18 (transfer).** `read_mt5_deal_ledger` is intentionally lease-free and unbounded; the
  obligation is discharged by its caller, which supplies both `asyncio.wait_for(...)` and
  `mt5_terminal_lease`. Verified the caller actually does so — a transfer whose recipient does not
  honour it is an open threat wearing a closed label.
