<decision_a01>
## A-01 RESOLVED BY THE PLANNER — the reasoning, so it is not re-litigated

A-01 required this to be settled EXPLICITLY before task-writing, on evidence, with the WHY recorded.
Four shapes were considered and measured at HEAD.

**⛔ REJECTED — re-derive the deals in `equity_reconstruction.py` and call a conversion there.**
`reconstruct_nav` needs `(daily_pnl, terminal_nav, flows_by_day)`, and `combine_mt5_deal_ledger`
builds all three internally from the classified deals and returns none of them. Getting them at a
second site means re-running `classify_deal` / `deal_utc_day` / `deal_cash_effect` — which is exactly
the parallel implementation CONTEXT.md forbids, over the hardened, fail-loud, security-relevant half
of the module (`Mt5DealClassificationError` exists because this is where getting it wrong is costly).

**⛔ REJECTED — widen `combine_mt5_deal_ledger`'s own return tuple.** `job_worker.py` unpacks exactly
`returns, meta = combine_mt5_deal_ledger(...)`. A third element breaks a consumed contract for no gain
over a sibling function.

**⛔ REJECTED — persist RETURNS and convert at read time.** This changes the consumed contract of
`allocator_equity_snapshots.value_usd`, which is a levels column with multiple readers. A-01 names
this shape specifically and forbids taking it silently.

**⛔ REJECTED — `allocator_equity_derive.replay_key_equity`.** Measured, and worth recording because
it LOOKS like the answer: it is pure, lives in `services/`, is well tested, and converts a return
series plus an anchor and flows into a per-day $-level Series with a forward/backward self-check. It
is rejected on three measured grounds. (1) It INVERTS the returns
(`equity_{t-1} = (equity_t − F_t)/(1 + r_t)`) rather than reusing the roll the returns came FROM, so
the levels are re-derived instead of being the same series. (2) It refuses any non-finite return
value — and `combine_mt5_deal_ledger` deliberately emits NaN on every DQ-01 guard-broken day, so the
days the guards exist to MARK are precisely the days this function would refuse. (3) It demands an
ISO-day-STRING index and fails loud on a `DatetimeIndex`, which is what the combiner produces — one
more conversion seam to get wrong for no benefit.

**✅ CHOSEN — a private fold plus a public levels sibling in `broker_dailies.py`, using
`nav_twr.reconstruct_nav`.** It satisfies "call the combiner directly, no parallel implementation"
literally: there is ONE deal fold and both public functions call it. It changes no consumed contract.
And it uses the SAME function `reconstruct_nav_and_twr` calls internally to build the NAV that these
very returns were chain-linked FROM — so returns and levels agree BY CONSTRUCTION rather than by
re-inversion, and a guard-broken day is a level that still exists rather than a refusal.

**Precedent, so this is not a new pattern:** `services/native_nav.py`'s `_roll_bucket` calls
`_union_flow_days` then `reconstruct_nav` directly and describes itself as *"verbatim reuse, never a
fork"*; `tests/test_native_nav_sc4_identity.py` pins that reuse. `broker_dailies.py` already imports
a private `nav_twr` symbol (`_build_nav_meta`), so reaching one more is in-idiom, not a new liberty.
</decision_a01>

<planner_findings>
## MEASURED AT HEAD BY THE PLANNER — read before writing code

**1. What `combine_mt5_deal_ledger` builds and discards.** It folds deals into `trading_by_day` and
`flow_by_day`, shapes `daily_pnl_series` (a `DatetimeIndex` as_unit `"us"`) and a list of
`ExternalFlow`, early-returns an EMPTY gap-filled series plus `_build_nav_meta({})` when there are no
trading deals, and otherwise calls `reconstruct_nav_and_twr(daily_pnl_series, account_equity,
external_flows=flows, open_unrealized_usd=account_equity - account_balance)`, gap-fills the returns and
stamps `series_completeness = "ledger_complete"`.

**2. What `reconstruct_nav_and_twr` does with them, and this is the load-bearing detail.** It computes
`flows_by_day = _flows_to_daily_usd(external_flows)`, then `daily_pnl = _union_flow_days(daily_pnl,
flows_by_day)` — HIGH-1, so a flow on a no-trade day becomes a valid zero-pnl NAV day instead of an
orphan — then `terminal_nav = anchor - upnl`, then `nav = reconstruct_nav(daily_pnl, terminal_nav,
flows_by_day)`. **That `nav` is the level series this plan needs, and the function discards it.**
⛔ The union MUST be applied before the roll in the sibling too, or a legitimate quiet-day or boundary
flow becomes an orphan that `_align_flows` fails loud on.

**3. `reconstruct_nav` is PnL-based, not division-based.** `NAV_{t-1} = NAV_t - pnl_t - F_t`. It has no
`(1 + r_t)` denominator, therefore no ≤ −100%-day refusal and no NaN-return sensitivity. That is the
technical reason it is the right core here and the inverse approach is not.

**4. ⛔ `gap_fill_daily_returns` MUST NOT be applied to levels.** It fills an interior no-activity day
with `0.0`, which is correct for a RETURN and catastrophic for a LEVEL — it would write a $0 equity
day. The levels sibling returns the honest sparse series on the roll's own index; making the calendar
dense is plan 06's concern and uses forward-fill, not zero-fill.

**5. The empty-ledger path must be mirrored deliberately, not by accident.** The existing early return
is marked `MT5-12 EXEMPT` and carries a written argument for why stamping a completeness verdict there
would be the worst of three options. The levels sibling must take the SAME early return (an empty
series) for the same reason — a deposit-only account has no track record and must not produce a curve.
</planner_findings>
