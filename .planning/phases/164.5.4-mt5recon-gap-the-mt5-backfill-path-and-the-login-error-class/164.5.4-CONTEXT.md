<domain>
## Phase Boundary

Three MEASURED defects on the MT5 path, all of one class: MT5 produces a signal that carries a
real verdict, and something downstream degrades it into something the founder cannot act on.

This phase delivers (1) an MT5 branch for the full-backfill job, (2) a classifier that refuses to
guess rather than defaulting to blame, and (3) an honest verdict for `KEY_UNDECRYPTABLE` at the
Python/TypeScript seam.

⛔ The ROADMAP entry (`### Phase 164.5.4`) is the spec for WHAT is broken — it carries PROD log
evidence, dated measurements, file+symbol citations and a `0/6` method census. This file records
HOW, and does not restate it.

⚠️ **USER-FACING.** Anti-vacuity BLOCKS and review findings BLOCK rather than being fix-or-drop.

</domain>

<decisions>
## Implementation Decisions

### Defect (2) — the classifier's failure posture

- **Keep the three-member `Literal` on `classify_mt5_login_error`; add a REFUSAL rule.** Measured
  during discuss: the three classes collapse to TWO real dispositions, so a fourth member changes
  the return type and all three production call sites for no behavioural gain.

  | class | disposition at every call site |
  |---|---|
  | `auth` | `_auth_failed()` / HTTP 400 — PERMANENT, USER-BLAMED |
  | `wrong_server` | `_wrong_server()` / HTTP 400 — PERMANENT, USER-BLAMED |
  | `transient` | propagate untouched / HTTP 424 `recoverable=True` — NO BLAME |

  Production call sites, cited by symbol: `routers/exchange.py` (`validate_key` MT5 arm),
  `services/ingestion/mt5.py` (the `Mt5ClientError` handler), `services/job_worker.py` (the
  MT5 derive branch).

- **Replace the bare single-word tokens with ANCHORED PHRASES.** `_AUTH_TOKENS` currently holds
  both `invalid` and `account`, which is why the observed rejection matches twice over and can
  never reach the `transient` default. Broad single words are the root cause; adding more tokens
  makes over-matching worse.

- **An unrecognised or ambiguous message must NEVER produce a user-attributed permanent stamp.**
  It degrades to `transient`, which the caller propagates untouched.

- **Fail-CLOSED ordering gets an EXECUTABLE pin, not a comment.** A test feeds a message matching
  BOTH tables and asserts `wrong_server` wins. The existing code-gate on the IPC transport codes
  stays ahead of all text matching and keeps its own arm.

- **The refusal rule ships WITHOUT the live spike.** It is independently correct and is what
  removes the wrong-blame stamp.

### The live spike hand-off

- ⛔ **No agent may drive it.** The founder enters credentials; no agent ever enters, reads,
  decrypts, logs or echoes one. The phase designs the hand-off rather than planning a task nothing
  can execute.
- **Captured:** `(code, text)` pairs from login rejections ONLY. Never an account identifier,
  never a broker server name, never a password.
- **Transport:** a fixture table keyed by SYNTHETIC accounts. The repo is PUBLIC and `.planning/`
  is TRACKED, so identifying values are replaced BEFORE anything is written — verdicts, never
  specimens, and never the pattern searched for.
- **Partial sets LAND.** Each measured pair retires one `[ASSUMED]` marker independently; there is
  no all-or-nothing gate.
- **Nothing in this phase blocks on it.** The spike is an additive follow-up.

### Defect (1) — the missing MT5 backfill branch

- **Call `combine_mt5_deal_ledger` directly.** Measured during discuss: it is a PURE function —
  `(deals, account_equity, account_balance, *, server_utc_offset_s) -> (returns, meta)` — with no
  session and no IO, and `equity_reconstruction.py` already imports from `services.job_worker`, so
  the added dependency introduces no cycle. ⛔ No parallel implementation.
- **Extract the `history_deals_get` FETCH+ADAPT half into ONE shared helper** that both the
  backfill job and its sibling call. The combiner is already shared; the fetch is the part that
  would otherwise drift apart again.
- **Add an explicit `venue == "mt5"` branch BEFORE the generic ccxt crawl**, mirroring the existing
  `venue == "deribit"` guard, so the `AttributeError` is unreachable by construction. ⛔ NOT by
  widening the `except` to catch `AttributeError` — that hides the class instead of closing it.
- **An MT5 fetch failure routes through the SAME classifier**, so the backfill path cannot stamp
  permanent-and-blamed either.

### Defect (3) — `KEY_UNDECRYPTABLE` at the language seam

- **Mint a real `WizardErrorCode`** whose copy states the actual remedy.
  - ⛔ NOT a `VENUE_WIRE_CODE_TO_VERDICT` row: it forces an honest verdict member and there is not
    one. `KEY_PROBE_FAILED` is recoverable and renders the same useless Retry; `SEAM_MISCONFIGURED`
    is wrong because an operator cannot fix a corrupted per-row ciphertext.
  - ⛔ NOT a per-route pre-classifier arm: it duplicates the fix once per route.
- **Copy says: reconnect this key.** Python already raises the code with `retryable=False` and the
  real remedy; TypeScript carries that remedy rather than re-deriving it.
- ⛔ **No Retry control.** Offering a retry for a ciphertext that will never decrypt IS the defect.
- **Closed on BOTH routes** — rotate-secret and permissions. Closing one leaves the other on the
  useless envelope.
- **Bounded cost, established by GREP rather than by counting:** `EXPECTED_TABLE_SIZE` appears as
  exactly TWO hand-typed declarations, both in `src/lib/wizardErrors.test.ts`, both `93`, guarded
  by a meta-gate asserting exactly two declarations that agree. Minting moves both to `94` and the
  meta-gate proves they did not diverge. ⚠️ The count must also move in any test TITLE restating
  it. ⛔ `grep` is SILENTLY BLIND to that file (deliberate NUL byte) — always `grep -a`.

## A-01 — "Call `combine_mt5_deal_ledger` directly" does NOT by itself satisfy the backfill job

**SUPERSEDES:** the first bullet of *Defect (1) — the missing MT5 backfill branch*.

**MEASURED at HEAD, both halves:**
- `combine_mt5_deal_ledger` ends `return returns, meta` — its first element is a **RETURN SERIES**.
- `run_reconstruct_allocator_history_job`'s persistence path writes rows carrying
  `"value_usd": round(total, 2)` — **ABSOLUTE LEVELS** — into the
  `persist_equity_snapshots` / `replace_equity_snapshots` pair.

A return series is not a level series. **The combiner is still the right thing to reuse and a
parallel implementation is still forbidden** — what the original decision omitted is that a
**returns → levels conversion** sits between the combiner and persistence, and it has **no working
precedent inside this job**: the sfox path is absent from the file and the Deribit branch
permanently REFUSES rather than reconstructing.

⚠️ **This is an OPEN QUESTION the planner must resolve EXPLICITLY before writing backfill tasks,
not an implementation detail to be discovered mid-task.** Two candidate shapes were surfaced and
neither is pre-decided here: reuse `services.nav_twr.reconstruct_nav` against the same
daily-pnl / flows / anchor triple, or widen the combiner's return shape. ⛔ Whichever is chosen,
record WHY — and a third option (persisting returns and converting at read time) changes a
consumed contract and must not be taken silently.

## A-02 — "Closed on BOTH routes" cannot be delivered by minting a code alone

**SUPERSEDES:** the *Closed on BOTH routes* bullet of *Defect (3)*.

**MEASURED at HEAD:** the permissions route ALREADY carries a dedicated `KEY_UNDECRYPTABLE` arm
that emits the code with the correct copy, and it deliberately does NOT call
`classifyKeyValidationError` (its own docblock records why: most of its real faults would degrade
to `UNKNOWN` through that seam). **So there is nothing for a minted code to fix on that route.**

Its residual defect is in the CLIENT COMPONENT: `src/components/connect/KeyPermissionBadge.tsx`
renders its re-check control unconditionally in the component header — gated only on `loading`,
never on the error code — so an undecryptable key still offers a retry that can never succeed.

⇒ **Defect (3) is TWO tasks, not one, and they touch DIFFERENT languages and different files:**
1. Mint the `WizardErrorCode` and move both `EXPECTED_TABLE_SIZE` pins — closes the
   **rotate-secret** route, which DOES call the classifier seam. ⭐ Precedent is established, not
   invented: several shipped codes already omit both recoverable actions deliberately, the closest
   being the one 164.5.3 itself minted.
2. Gate the re-check control on the error code in `KeyPermissionBadge.tsx` — closes the
   **permissions** route. ⛔ A plan that touches only `wizardErrors.ts` leaves this half OPEN while
   reading as complete.

⚠️ **Confidence is explicitly LOWER on A-02 than on A-01.** A-01 is two direct source reads. A-02
rests on a behavioural reading of an unconditional render; the plan-checker should re-derive it
rather than inherit it.

## A-05 — ⛔ "NOT a `VENUE_WIRE_CODE_TO_VERDICT` row" is WRONG AS LITERALLY WRITTEN

**SUPERSEDES:** the `⛔ NOT a VENUE_WIRE_CODE_TO_VERDICT row` bullet under *Defect (3)*.

Raised by the pattern mapper, then **RE-MEASURED independently at HEAD** rather than accepted:

- `classifyKeyValidationError` reads `VENUE_WIRE_CODE_TO_VERDICT.get(seamCode)` **BEFORE** its
  substring cascade, and that cascade has **no** decrypt/reconnect branch. A wire code with no row
  therefore cannot route — it falls through to the `UNKNOWN` terminal. **So minting a
  `WizardErrorCode` ALONE does not close the rotate-secret route.**
- The 164.5.3 precedent does BOTH: `MT5_VALIDATE_INVARIANT_VIOLATION` is itself a ROW in
  `VENUE_WIRE_CODE_TO_VERDICT` → `{ code: "SEAM_INTERNAL_FAULT", status: 500 }`. Its own inline
  comment records the identical lesson — a code minted without a disposition surfaces to the
  founder as *"we could not classify this failure"*.

⭐ **The row and the mint are NOT alternatives; the row is the ROUTING MECHANISM.** What the
ROADMAP's option (a) actually rejected was a row pointing at an **existing dishonest member**
(`KEY_PROBE_FAILED` — recoverable, same useless Retry; `SEAM_MISCONFIGURED` — an operator cannot
fix a corrupted per-row ciphertext). A row pointing at the **newly minted honest member** is not
option (a); it is how option (c) is delivered. ⛔ My bullet conflated the two and, taken literally,
would have produced a code nothing routes to.

**⚠️ TWO CONSEQUENT EDITS THE CENSUS TRAP WOULD OTHERWISE HIDE — both MEASURED:**
1. `KEY_UNDECRYPTABLE` currently holds an entry in **`VENUE_WIRE_CODES_WITHOUT_VERDICT`**. Adding a
   verdict row means that exemption entry must be REMOVED — a code cannot honestly sit in both.
   ⚠️ Whether a gate asserts the two tables are disjoint was NOT established; treat as UNKNOWN and
   check, do not assume either way.
2. The `⚠️ NOT rostered: KEY_UNDECRYPTABLE` note inside `DASHBOARD_DIALOG_ROUTE_CODES` becomes
   FALSE the moment the row lands. ⛔ A stale comment asserting the opposite of the code is exactly
   the drift class this repo keeps booking — update it in the same commit.
