## A-02 was re-derived at HEAD, not inherited — and it holds

The plan required this, because A-02 itself declared lower confidence than its siblings. Measured
directly against the source rather than read out of CONTEXT.md:

- `src/app/api/keys/[id]/permissions/route.ts` carries a dedicated arm keyed on
  `seamFailure?.code === "KEY_UNDECRYPTABLE"` returning
  `{ code: "KEY_UNDECRYPTABLE", error: "This stored key can no longer be decrypted. Reconnect the key — retrying will not help." }`
  at **500** with `NO_STORE_HEADERS`. ⭐ Correct code, correct copy, `code:`-first. **Nothing on
  the server needed changing, and nothing on the server was changed.**
- The same file's docblock records, measured, why it deliberately does **not** route through
  `classifyKeyValidationError`: five of its six real thrown messages would degrade to
  `{code:"UNKNOWN", status:500}`, because that classifier handles KEY-VALIDATION faults while every
  fault reachable here is PROXY-INFRASTRUCTURE. So a minted `WizardErrorCode` genuinely cannot
  reach this route.
- `KeyPermissionBadge` read `err.code`, handed it to `console.error` and a Sentry breadcrumb, and
  then **threw it away**. The header button's `disabled` was gated on `loading` alone.

⇒ The residual defect was exactly where A-02 said: in the client. **A plan touching only
`wizardErrors.ts` would have left this half open while the phase read as complete.**

## The change

**`KeyPermissionBadge.tsx`** — one new state slot (`errorCode`), written in the branch that
already establishes the code is a non-empty string, under `mountedRef` like every other write in
the file; cleared at the top of `load` beside the existing `setError(null)` / `setPerms(null)`
invalidation; one term added to the button:

```
disabled={loading || errorCode === "KEY_UNDECRYPTABLE"}
```

⚠️ The code is retained for an **affordance decision only and is never rendered**, so the
164.2-01 / 161-ERRPREFIX audience split — curated prose to the user, machine code to the console
and the breadcrumb — is preserved exactly. The existing law asserting the rendered sentence never
contains the code still passes for all six refusals.

**`probe-vocabulary.invariant.test.ts`** — a new assertion **inside** the existing
`!e.retryClearsIt` describe, iterating the same `IRRECOVERABLE` const so it inherits that block's
existing non-vacuity fence rather than adding a second, weaker one. It reads the component through
the file's own `readStripped` helper and requires every `retryClearsIt: false` code to appear in a
`disabled={…}` expression.

## ⛔ Anti-vacuity — three neuters, three observed REDs, three `cmp`-verified restores

⛔ No `git checkout --` / `git restore` / `git stash` was used anywhere. Every restore came from a
`cp` byte backup and was proven with `cmp`. Every neuter was confirmed **applied** with a `grep`
on the mutated symbol before the suite ran.

| # | Neuter | Observed | Restore |
|---|---|---|---|
| 1 | gate term removed → `disabled={loading}` | **2 RED** — `KEY_UNDECRYPTABLE` row + the re-enable case. **All 5 sibling refusals, the happy path and the unparseable body stayed GREEN.** | `cmp: IDENTICAL` |
| 2 | gate widened → `disabled={loading \|\| errorCode !== null}` | **5 RED** — `CIRCUIT_OPEN`, `PROBE_RATE_LIMITED`, `PROBE_BACKEND_UNAVAILABLE`, `PROBE_TIMEOUT`, `PROBE_FAILED` | `cmp: IDENTICAL` |
| 3 | a TEMPORARY 7th roster member, `retryClearsIt: false`, no gate | **RED naming `NEUTER_SEVENTH_CODE`** (+2 sibling laws, expected: the fake code is not emitted by the route) | `cmp: IDENTICAL` |

Neuter 1 proves the gate **acts**. Neuter 2 proves it is **narrow** — the direction that matters
most, since a blanket disable would satisfy a single-code test while regressing every outage path.
Neuter 3 proves the binding is **class-complete**, not a one-member special case.

**A fourth neuter was run beyond the plan's requirement, and it earned its place.** The gate term
was removed from the component while its explanatory comment — which names `KEY_UNDECRYPTABLE`
twice — was left intact. The new binding went **RED naming `KEY_UNDECRYPTABLE`**. That is the
anchor and the comment-stripping doing real work: a whole-file `includes(code)` search would have
passed there, certifying a component whose gate was gone and whose explanation survived. Restored,
`cmp: IDENTICAL`.

### ⚠️ One of my own tests was found vacuous before it shipped

The re-enable case was first written as `await waitFor(() => expect(recheck).toBeDisabled())`. It
**passed against the unfixed component** — the control is *also* disabled while `loading` is true,
so `waitFor` caught the in-flight render and the assertion never measured the gate. Re-anchored on
the settled state (wait for the refusal prose, which renders only when `!loading && error`), after
which it was RED as it should have been. Recorded in the test's own comment so the shape is not
rewritten back.
