# Phase 164.5.4 Plan 01: The MT5 login-error classifier refusal rule — Summary

Anchored-phrase rewrite of `classify_mt5_login_error`'s `[ASSUMED]` token tables plus a
refusal rule, so a login rejection the classifier does not recognise degrades to `transient`
instead of permanently blaming a working credential — and the four production-copy gates that
would have been silently vacuated by that rewrite now assert the classifier's verdict instead
of substring-absence.

## What Was Built

**The defect.** `classify_mt5_login_error` matched broker-supplied free text against tables of
bare single words. `_AUTH_PHRASES`' predecessor held both `invalid` and `account`, so the
ROADMAP's own observed rejection — `Mt5ClientError(0, "Invalid account")` — matched twice over
and could never reach the `transient` default. Two of the three classes (`auth`,
`wrong_server`) become a PERMANENT, USER-ATTRIBUTED verdict at every call site. The founder was
therefore sent to change a password that was fine while the real cause went uninvestigated.

**The fix, in three commits.**

1. `3372b6a1` — the tables become anchored phrases, the refusal rule is recorded at the default
   arm, and the four copy gates are re-pointed IN THE SAME COMMIT.
2. `5ed72ef9` — the refusal rule, the fail-CLOSED precedence and the wrapper's neutrality each
   get an executing pin; the live-spike hand-off lands as an empty, protocol-bearing fixture.
3. `a7113495` — every comment the rewrite made false is corrected across five production
   sources and two test files.

### The phrase tables as shipped

`_WRONG_SERVER_PHRASES` holds ONE member — `"trade server not found"`, the one observed corpus
string. The plan permitted a narrower `"server not found"` sibling "only if a corpus string
needs it"; none does, so it was not added. `_AUTH_PHRASES` holds seven, all anchored on the
credential pair or an explicit password rejection. The bare members carrying the defect — the
account word, the truth-value-negation word, the bridge/terminal words — survive in no form.

### The census trap, closed in the same commit as its cause

Four test files imported the tuples BY NAME and asserted no member appeared in production
operator copy. Those gates had teeth ONLY because the members were short common words. Anchored
phrases would have left all four trivially green while measuring nothing — a test made unable
to fail by the fix it was guarding. Each now feeds its own message corpus through
`classify_mt5_login_error` inside an `Mt5ClientError(0, ...)` (code 0, so the IPC code-gate
cannot answer for the text) and asserts `"transient"`. Each keeps its own corpus, its own
length floor, and its own failure message; the non-empty-table guard was rewritten to assert
the PHRASE tuples are non-empty, because empty tables would make every message classify
`transient` for free. No substring-absence assertion was kept beside the new one.

### Residual, surfaced not smuggled

- **`-6` has no code-gate, and none was added.** `services/mt5_relogin.py` single-sources `-6`
  as "no account is authorized on this terminal" — an INFRASTRUCTURE fault with a shipped heal,
  not a credential rejection — and `classify_mt5_login_error` has no code-gate for it. Under
  the anchored tables a terminal-authorization message matches no phrase and degrades to
  `transient` by the refusal rule, which is the honest verdict and the mechanism the plan
  locked. A `-6` code-gate appears in no source artifact, and inventing a code table from
  memory is Pitfall 5 exactly.
- **Both phrase tables remain `[ASSUMED]`.** They are narrower than before, which is the point,
  but a real broker rejection this repo has never observed will classify `transient` and cost a
  retry. That is the deliberate trade: a missed message costs a retry, a broad member blames a
  working credential permanently. The live-spike fixture is the only sanctioned way to widen them.
