Baseline and classification (B1):
- Phase base: `PHASE_BASE=$(git merge-base HEAD origin/main)`, printed and recorded in the SUMMARY. It is the main commit the phase branch last took in, so `git diff $PHASE_BASE..HEAD` is exactly the phase's change.
- Base worktree: `git worktree add <scratchpad>/base-201 $PHASE_BASE`, then link this worktree's dependencies into it with `ln -s "$(cd node_modules && pwd -P)" <scratchpad>/base-201/node_modules`. Do not run `npm ci` there either. Remove the worktree with `git worktree remove` when this plan finishes.
- Run `npm test` once on HEAD and save the failing test files to the scratchpad. Run exactly those files in the base worktree with `npx vitest run` followed by the saved file list.
- Then classify each failing test, in this order:
  - A test that also fails at the base is **pre-existing**: list it under `pre-existing:` with the base output and do not edit it.
  - A test that passes at the base and fails at HEAD, whose expected literal appears on a removed (`-`) line of `git diff $PHASE_BASE..HEAD` over a non-test file and on no added line, is a **stale pin**. Set the assertion to the literal the phase wrote in its place (the added line in the same hunk, or the owner SUMMARY's new string). List it under `stale-pins:` with file, old literal, new literal and owner plan, and note whether an owner SUMMARY recorded it.
  - A test that passes at the base and fails at HEAD, whose expected value is computed rather than a literal in the source (a locale date, a signed percentage, a codename for a strategy that is now visible), is a **decision-driven change** when three things hold: the source file the test exercises is in the phase diff; the failure's new actual value is exactly what a cited decision or UI-SPEC row specifies (D-11 and the helper, D-15 and the unsigned format, D-09 and D-17 with the name order, a UI-SPEC After string); and the hunk that produced it is that decision's implementation. Re-pin the assertion to the specified value. List it under `decision-pins:` with file, old expectation, new value, the decision ID or UI-SPEC row, and the hunk.
  - Anything else is a **regression**: find its cause in the source, fix it there, never weaken the assertion, and list it under `regressions:` with cause and fix. A value that matches no decision is a regression even if the source is in the phase diff.
- When the pre-existing list is not empty, the full-suite command is `npx vitest run` with one `--exclude '<file>'` per pre-existing file. Paste that command and its result. Otherwise it is plain `npm test`.
