## Interaction contract 1: the `Term` trigger (D-01, D-03, D-19, D-20)

### Two render forms

| Form | When | Trigger element | Affordance | Tab stop |
|------|------|-----------------|------------|----------|
| **A. Static label** | The term sits in a label position (heading, table row label, column header that is not a control, KPI caption, chart or panel title, legend item) as plain text | a `<span tabIndex={0} data-term="<key>">` around the term's text | dotted muted underline, `cursor-help` | one, the span |
| **B. Label inside a control** | The term is the label of an element that is already interactive: a sort button, a tab (`ProfileTabs` "Mandate"), a nav link, a `<summary>`, a link | the control itself, wrapped in `Tooltip` with the registry text (the discovery sort-header pattern) | none added; the control is the affordance | none added |

Never nest Form A inside a `<button>`, `<a>`, `<summary>` or any element with an interactive role (a focusable inside a focusable). Form A inside a `<label>` or a `<th>` is allowed.

### Form A visual (classes are the contract; the planner may add, never remove)

`cursor-help underline decoration-dotted decoration-1 decoration-text-muted underline-offset-2 rounded-sm focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent/50 print:no-underline`

- Text decoration, not `border-b`: the `OptimizerPanel` precedent's look (dotted, muted, 1px), without adding a 1px border box to rows and strip cells (U-02). The `OptimizerPanel` glossary `dt` moves onto `Term`, so one affordance remains in the app.
- No colour, font, size, weight, `uppercase` or tracking class on the trigger: it inherits all of them.
- No hover colour change. Hover shows the bubble after 150ms; that is the feedback.
- The trigger wraps **only the term's own words** (the matched label or alias), not the rest of a longer label: "Max DD (blend vs allocation)" wraps "Max DD"; "Strong mandate fit" wraps "mandate". Exception: a label whose term is a glyph prefix (`α vs BTC`, `IR vs BTC`) is wrapped whole, so the target is not one character.
- `Term` adds **no visible text node**. The 196 factsheet census (`readText`) and every `getByText("α vs …")` locator read the same text before and after. On the factsheet KPI strip, `data-testid="factsheet-kpi-label"` and `first-letter:normal-case` stay on the original element.

### States

| State | Trigger | Bubble |
|-------|---------|--------|
| Rest | dotted underline, label's own colour | none |
| Hover (pointer) | unchanged | opens after 150ms; closes on pointer leave |
| Keyboard focus | focus ring `ring-2 ring-accent/50`, 2px radius | opens after 150ms; closes on blur |
| Open | unchanged | 224px, DM Sans 13px #1A1A2E on white, 1px #E2E8F0 border, 6px radius, above the trigger, flips below near the viewport top (existing primitive) |
| Print view (`printView`, the tearsheet) | **plain label**: no span, no `tabIndex`, no underline, no `data-term`, no bubble (D-20) | none |
| Browser print of an interactive page | `print:no-underline`; text unchanged | none |

### Accessibility

- Accessible name of a Form A trigger is the label text. When focus lands on it, a screen reader announces the label **and then the definition**. The definition must be referenced by `aria-describedby` from the **focusable** element (today `Tooltip` sets it on an inner wrapper and only while open, RESEARCH Pattern 1). Mechanism is the planner's: an opt-in, default-off `Tooltip` prop or a `Term`-owned trigger, keeping `Tooltip.test.tsx`'s DOM depth when the prop is off.
- `role="tooltip"` stays on the bubble.
- Each Form A trigger is one tab stop in DOM order (D-19). The factsheet rail gains roughly 30 to 40 tab stops; accepted by D-19's `tabIndex=0` ruling.
- Inline-text targets are exempt from WCAG 2.5.8 target size.

### Known limits (recorded, not fixed in this phase)

- **No Escape-to-dismiss on the bubble.** The `Tooltip` primitive has none. Adding one to `Term` would call `preventDefault` on Escape inside the "All Filters" panel and collide with D-12's `defaultPrevented` idiom. Booked as a follow-up, not invented here (U-04).
- **No touch path.** No tap handler is added (the touch primitives `TouchTooltip` and `useTapPin` are frozen). A browser that focuses a tapped `tabIndex=0` span will open the bubble through focus; that is browser behaviour, not a contract (RESEARCH A1).
- **The bubble is not hoverable** (`pointer-events-none` in the primitive), so moving the pointer onto it closes it (WCAG 1.4.13 "hoverable"). Primitive behaviour, unchanged.

## Interaction contract 2: glossary registry copy (D-01, D-02, D-03)

### Writing rules (DESIGN.md Voice / microcopy)

1. One or two sentences, declarative, sentence case, active voice, no exclamation.
2. **At most 200 characters** per definition, so the 224px bubble stays at or under about seven lines (U-05).
3. A formula **only where the code computes it** (source column below). A threshold only where the code tests one, or where it is the break-even that follows from the formula itself (a ratio's 1.00, a correlation's 0). No adjective where a number exists.
4. Two terms that are the same number in code must not contradict (Omega and Profit Factor).
5. A generic definition agrees with the discovery context string for the same term (Sharpe, CAGR, Max DD, Volatility).
6. **Discovery header tooltips are moved, not retyped.** The 10 tooltip strings in `DISCOVERY_COLUMNS` move into the registry as a `discovery` context, byte-identical, with `FULL_RECORD_BASIS` and `SIX_MONTH_WINDOW_DAYS` kept as **interpolations**, never resolved into literals. `StrategyTable.headers.test.tsx` and `StrategyGrid.test.tsx` keep asserting the same text.
