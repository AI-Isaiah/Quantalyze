# Phase 164.6.6 Plan 04: Route both MT5 validate sites to the validation terminal Summary

The wizard and worker validates now lease the validation terminal's `terminal_key`, read through one shared reader of `MT5_VALIDATION_GATEWAY_HOST` / `MT5_VALIDATION_GATEWAY_PORT`. Without that pair, both refuse and fire a per-site D-05 Sentry alert. Neither ever falls back to the job terminal, and an AST pin proves that no other production function reads the validation endpoint.

## What changed

- **`services/mt5_relogin.py`**
  - `read_env_validation_gateway_endpoint()` is a sibling of `read_env_gateway_endpoint`. It reads both variables on every call, strips them and parses the port as an int. On a problem it logs once under its own reason keys and returns `None`; it never raises.
  - `alert_mt5_validation_gateway_unconfigured(*, site)` logs at ERROR on every call. At most once per `_MT5_VALIDATION_ALERT_WINDOW_S` (3600.0) **per site**, it also calls `sentry_sdk.set_tag("mt5_validation_gateway_unconfigured", site)` and `capture_message(..., level="error")`. Both Sentry calls sit inside `try/except Exception: pass`, so it never raises.
  - The docstring carries the `SENTRY_DSN` caveat from `routers/cron.py`.
  - `_reset_mt5_validation_alert()` is test-only.
- **`routers/exchange.py::_validate_mt5_key_probe`**
  - The `os.getenv("MT5_GATEWAY_HOST")` block is replaced by the new reader.
  - When the reader returns `None`, the site calls the alert with `site=SITE_VALIDATE_WIZARD`, then returns the existing 500 `MT5_GATEWAY_UNCONFIGURED`. The operator detail text is unchanged.
  - The lease key is `mt5_terminal_key(host, port)`, not a hand-written f-string. The lease wait, deadline and holder/site keyword arguments are unchanged.
- **`services/ingestion/mt5.py::Mt5Adapter.validate`**
  - Uses the same reader. When it returns `None`, the site alerts with `site=SITE_VALIDATE_WORKER` and then raises the existing `RuntimeError("MT5 gateway not configured: ...")`, which now names the validation env vars.
  - The lease key is `mt5_terminal_key`, and `wait_s=None` is unchanged.
  - The unused `import os` is removed.
- **`src/lib/wizardErrors.ts`** is a comment-only change. The `SEAM_INTERNAL_FAULT` note now names `MT5_VALIDATION_GATEWAY_HOST/PORT` as the env cause for a key validation, cited by env name.
