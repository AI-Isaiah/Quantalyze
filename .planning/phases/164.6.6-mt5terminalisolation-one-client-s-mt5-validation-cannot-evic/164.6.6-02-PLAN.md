<objective>
Criterion 2 says client accounts accumulate in the shared terminal's Navigator tree and that
anyone with VNC access can read the full list of client account numbers and their brokers.

⛔ **THE DELIVERABLE IS PREVENTION OR ASSERTION — NEVER AN INVENTORY (D-05, rated one-way).**
The natural-looking task here is "enumerate the Navigator tree and check it is short." That is
forbidden. This repository is PUBLIC, `.planning/` is TRACKED and CI logs are world-readable,
so a check that lists registered accounts publishes exactly the client account numbers and
broker server names criterion 2 exists to protect. A published list cannot be unpublished.

⚠️ **THIS PLAN IS NOT THE ACCUMULATION REMEDY, AND SAYS SO (D-06).** Whether accumulation is
prevented structurally (an ephemeral terminal registers nothing that outlives it) or must be
purged and asserted (serialize-and-restore on the one terminal) is DOWNSTREAM of the D-10
ownership decision, which plan 04 takes at a `checkpoint:decision`. What ships here is the half
that is true under ALL THREE candidate answers: a fence proving this repo never grows a code
path that reads the account store, whichever ownership model wins.

Purpose: make the disclosure surface un-widenable by this repo's own code, and make the
`scripts/mt5-diag.sh` read-only property a runnable assertion instead of a comment.
Output: one new test file, a derived surface, and a calibration per forbidden token.
