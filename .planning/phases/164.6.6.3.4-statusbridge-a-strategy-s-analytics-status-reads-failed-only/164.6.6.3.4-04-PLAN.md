**Files (research Q5 procedure, narrowed by the D-08 amendment).**
- `00-marker.sql`: `SELECT shobj_description(oid, 'pg_database') AS which_database FROM pg_database WHERE datname = current_database();`
- `05-live.sql`: the new body is live: `position('compute_intro_snapshot' IN pg_get_functiondef('public.sync_strategy_analytics_status(uuid)'::regprocedure)) > 0` and the migration ledger row for the new version exists.
- `10-before.sql`: status counts by value over `strategy_analytics`; the target list (`computation_status = 'failed'` AND `EXISTS` a `compute_jobs` row for the strategy) with, per target, an ordinal, the pre-image columns, the count of in-flight jobs, and the read-only PREDICTION in the bridge's own read order: (1) any non-terminal job for the strategy -> `computing` (branch (a) is read first); else (2) the count of `failed_final` jobs that are not a side kind, not a `process_key_long` superseded by a later done derive AND a later done compute, and not superseded by a later done of the same kind -> `failed` if > 0; else (3) `complete_with_warnings` if `computation_warned`, otherwise `complete`.
- `20-resync-<n>.sql`: `SELECT public.sync_strategy_analytics_status('<id>'::uuid);`, one file per target.
- `30-after.sql`: the same reads as `10-before.sql` for the same targets.
- `40-check.sql`: a read-only `DO` block over the targets re-synced so far (Task 1: the one target; Task 2: every target). For each, it re-derives in-flight at check time FIRST: a target with a non-terminal job gets `RAISE NOTICE` naming its ordinal and its current status (recorded, never an exception). Otherwise it RAISEs EXCEPTION naming the ordinal when the status differs from its prediction.
