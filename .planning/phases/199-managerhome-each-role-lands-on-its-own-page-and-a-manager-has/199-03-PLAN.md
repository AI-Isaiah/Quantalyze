- `src/lib/degrade-warnings.ts` is pure TS (no React, no client directive). Closed sets: classes
  degrade, read_failure, in_progress, composition, share_status, provenance, empty, recipient; scopes
  key, day, key_day, whole_history, recipient, none; surfaces my-allocation, scenario,
  strategies-list, factsheet.
- `ACTION_SENTENCES`: the UI-SPEC's twelve ids A-RECONNECT … A-DESELECT verbatim, each with its link
  kind (exchanges, contact, edit, csv, deselect or none). An id added later must quote a UI-SPEC
  target line or shipped copy verbatim and record that origin beside it. This plan adds one:
  A-RECONNECT-ANY-OR-WAIT, the UI-SPEC StalenessBanner target action.
- An entry is { id, surface, class, scope, action, text? }. Ids are dotted with the surface first
  (`allocation.staleness`). `text(args)` returns segments: strings, `{ label }` for a key label (600
  weight) and `{ action, strategyId? }` for the action sentence with its link. Degrade, read_failure
  and recipient entries require text and an action; read_failure and recipient may name a shipped
  sentence as the action when no vocabulary id fits (OQ-3).
- `WHOLE_HISTORY_IDS`: the only ids allowed scope whole_history; their text contains `whole history`.
- Every render site renders `data-degrade-id` and names its id as a string literal in that file,
  which is how the scan attributes it.
