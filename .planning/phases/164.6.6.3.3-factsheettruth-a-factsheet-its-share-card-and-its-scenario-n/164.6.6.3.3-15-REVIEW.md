## Warnings

### WR-01 (MEDIUM, data truth): the EOY Returns current-year row prints the exact Year-to-date figure the same Withheld row dashes

**File:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx`: `EoyReturnsPanel` (the strategy cell at `pctSigned(s, 2)`, read from `view.strategyMetrics.yearly`). The same applies to `CalmarByYearPanel`'s Return column (`src/lib/factsheet/calmar-by-year.ts:5,59`, "the year's return: compounded"). The test pin is `FactsheetView.headline-coverage.test.tsx`, "D1: every EOY Returns year row keeps its strategy figure".

**Issue:** on a Withheld row, the Returns panel's "Year-to-date" reads "—". The cause is `withSuffixWindows` (`build-payload.ts:664`, WR-01 of round 1), which nulls `ytd` because a Withheld row cannot date the break. D-15 itself says it is "Consistent with WR-01's rule for the trailing windows".

`compute()` builds `ytd` as `returnFrom(ytdCutoff)` over the dates after Dec 31 of the last year (`compute.ts:316-317,351`). It builds `yearly[lastYear]` with the same accumulator over the same dates (`compute.ts:283`). Whenever `ytd` is non-null, the two values are identical.

So EOY Returns' last row prints the withheld YTD figure two panels below the "—". That is a number under the Withheld note, and the reader can match it to the cell that hides it.

Plan 15 classifies EOY rows as class (d), "each covers its own calendar year". Its Ambiguous item 2 asks only about "the year that contains the break", which a Withheld row cannot name. The current-year row needs no ambiguity call: it is the same number as a cell the page already withholds. The kept-cells test D1 now pins that leak as intended behaviour.

**Failure scenario:**
1. A single-key api strategy is Withheld (chain broken, no `headline_since`), and its record runs into 2026.
2. Returns › Year-to-date reads "—".
3. EOY Returns › 2026 › Strategy reads "+3.84%", which is the value `ytd` held before redaction.
4. Calmar by Year › 2026 › Return reads the same "+3.84%".

**Fix:** under `wholeRecordWithheld`, dash the strategy, benchmark and Δ cells of the record's last calendar year in `EoyReturnsPanel`, and the Return, Max DD and Calmar cells of that year in `CalmarByYearPanel`. Pass the gate as a prop, the same pattern as `RollingMetricsPanel`. Narrow test D1 to "every year row except the last". Add a case pinning that the last row reads "—" on Withheld and carries a digit on Dated. If the founder prefers to decide this together with Ambiguous item 2, book it in that question. In either case, record the identity with YTD in the SUMMARY so the decision is made knowing it.

### WR-02 (MEDIUM, data truth): Rolling Metrics "Now" prints trailing-6-month Vol, Sharpe and Sortino where the same row's trailing 6 Month return is withheld

**File:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx:860-865`. The comment there reads: "'Now' is the latest 6-month window only and stays". The test pin is "D5: the three Rolling Metrics 'Now' cells keep their figures".

**Issue:** `withSuffixWindows` nulls `p6m`, `p3m`, `mtd` and the rest on a Withheld row, because the break cannot be dated and a trailing window may straddle it (`build-payload.ts:643-648`, "its whole-record windows compound across the break that caused the withhold"). The rolling "Now" cell is computed over the same trailing 6-month span (`view.rollingWindow`, label "6mo").

Plan 15 keeps it as class (d), "per-window". That follows the decision's literal "whole record" wording, but it breaks the WR-01 rule that D-15 says it is consistent with. Under the "Headline figures withheld" note, the 6 Month return reads "—", while "Rolling Metrics (6mo) › Sharpe › Now" prints an accented Sharpe for the same six months. The accent stays because `RollingRow` accents `current` when it is not "—" (`:885`).

A Withheld row means `headline_since` is absent or malformed, so nothing rules out a break inside the trailing window.

**Failure scenario:**
1. A Withheld row's break falls inside the last six months.
2. 6 Month reads "—", and the headline Sharpe reads "—".
3. Rolling Sharpe "Now" reads "2.41", accented, computed across the break.

**Fix:** either dash `current` under the gate too, in `stats` (`{ ...r, current: null, avg: null, min: null, max: null }`), and flip D5 to "—"; or put the question to the founder next to the three open Ambiguous items. The second route must state that the trailing-window rule (WR-01) already dashes the matching 6 Month return, so the choice is not made on the narrower "whole record" reading alone.

### WR-03 (MEDIUM, a test that cannot fail): no render-level test pins the gate's basis term, so dashing a non-Withheld view goes undetected

**File:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx:266` (`isHeadlineWithheld(payload.dataQuality, railBasis)`). Tests: `FactsheetView.headline-coverage.test.tsx`, describe "D-15 extended again: Dash all of them".

**Issue:** the gate has three terms.

- `!selected` is pinned by the 62-case window exemption. Neuter N2 was 63 RED.
- The verdict is pinned by the Dated contrast.
- `railBasis` has no rail-level test. The only basis assertion is predicate-level, `isHeadlineWithheld(WITHHELD_DQ, "mark_to_market")` false (`:689`). No test renders `MetricsColumn` under `mark_to_market` or `smoothed_mtm` with a Withheld `dataQuality`.

Under MTM, the rail's figures come from the MTM series and the MTM stored scalars, not the redacted cash headline, so all 62 cells must show digits there. Plan 15's neuter list (N1-N4) does not include the basis term. Two regressions would pass every test and dash 62 valid MTM figures on a page whose own Withheld note does not show under MTM (`headlineCoverageNote` returns null off cash, `:93`):

- a refactor that passes `"cash_settlement"`, or the unresolved `useBasis()` value, in place of `railBasis`;
- a rewrite of the gate to `dataQuality.headlineWithheld === true`.

**Failure scenario:**
1. A Withheld row has a live MTM bundle, and the user toggles to Mark-to-market.
2. Every Skew, VaR, Best/Worst, bootstrap and joint cell reads "—" with no note explaining why.
3. CI stays green.

**Fix:** add one case to the "Dash all of them" describe.

- Render the Withheld payload with an MTM bundle under `BasisProvider` plus `SetBasis basis="mark_to_market"`, the pattern of the test at `:294-336`.
- Reuse `readCell` over `CASES`, and assert every class (a) cell carries a digit.
- Add a premise that the same render under cash dashes them, so the test is not vacuous.
- Run it RED once under a byte-restored neuter that replaces `railBasis` with `"cash_settlement"` in the gate.
