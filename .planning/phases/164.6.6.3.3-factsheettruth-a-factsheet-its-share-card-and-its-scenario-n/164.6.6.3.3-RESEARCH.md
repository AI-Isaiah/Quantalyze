## Summary

The item-2 hypothesis is **proven, and the defect is wider than the scout wrote.** `compute_all_metrics` takes the cumulative return and the CAGR from the suffix after the last interior NaN, but it also takes Calmar's denominator (max drawdown), volatility, Sharpe, Sortino, the drawdown series and duration, MTD/YTD/3M/6M and every distribution scalar from the **full** series. I rebuilt Quantum Drift's composite scalar input from its stored `csv_daily_returns` rows and ran the HEAD code: it reproduces the PROD row to about 1e-13 (cumulative 0.0, CAGR 0.0, Calmar 0.0, Sharpe 8.1023, Sortino 22.497, volatility 3.0588, max drawdown -0.7828, six-month 26003.80, three-month 178.87). The cause is that the last guard-NaN day sits 12 calendar days before the end, so the suffix is 12 days of exactly 0.0. All five guards (the four named plus `pnl_dominated_guard`) look identical to the compute: a NaN day. Only the NaN *position* matters, so one seam fixes all of them, and the suffix start the codebase already uses (`_last_interior_break_suffix`) is the right rule: the first valid day after the last guard NaN.

Items 3, 4, 5 and 6b are small and local. The factsheet gate for a flat strategy leg must live in `comparator-block.ts` (not `jointMetrics`): `jointMetrics` is also called by the Allocations alpha/beta widget, whose 166.2 test T16 pins beta exactly 0 for a flat leg. The KS bug is the alternating series summing to 0 at lambda 0 (measured: p=0.000 at lambda 0 and p=0.020 at lambda 0.001); the Numerical-Recipes convergence rule returns 1. The OG card's red "—" is at `route.tsx:257-258` (the scout's "~233" has drifted). Eclipse reads `complete` on PROD now.

**Primary recommendation:** Add ONE headline-series seam at the top of `compute_all_metrics` (suffix when an interior break exists, the series itself otherwise, so clean series stay byte-identical), store `data_quality_flags.headline_since` from that same suffix (no migration), read it in TS through one shared helper used by the composite and single-key paths, and withhold the stored headline of any row that carries an interior-break flag but no `headline_since` (a pre-D-01 mixed-basis row) until the Wave 5 recompute restores it.

### 1.2 Suffix start rule (Discretion item)

Use `_last_interior_break_suffix`: the maximal contiguous valid run ending at the last valid day. "The last break" and "the first day after the last guard fires" are the same day by construction, because a guard day *is* a NaN day. Behaviour by NaN position [VERIFIED: nav_twr.py:586-610]:

| NaN position | Suffix | Stored stats change? |
|---|---|---|
| none | whole series | no (identity) |
| leading only (a day-0 guard, or a DQ-02 terminus) | the valid run after it = all valid days | no |
| interior | the run after the last interior NaN | **yes** |
| trailing only | the leading run up to the last valid day | no (it is the whole valid series) |
| interior + trailing | the run ending at the last valid day | yes |

Composite note: only *in-index NaN* breaks the chain. The stitch's absent inter-member days are zero-filled by `gap_fill_daily_returns` (job_worker.py around 8769, `densify_policy="zero_fill"`), so they do not shorten the suffix, matching what cumulative and CAGR already do today.

## Common Pitfalls

### Pitfall 1: Truncating the chart series by accident
**What goes wrong:** rebinding `returns` itself to the suffix shortens `returns_series`, `drawdown_series`, sparklines, rolling and the sibling kinds, so the lists' sparklines and the rolling panels lose the pre-break record.
**How to avoid:** a separate `headline` variable; assert in test 4/5 that `returns_series` length is unchanged on a broken series.
**Warning signs:** `sibling_kinds` keys shorter than before.

### Pitfall 2: Nulling `cumulative_return` blanks a composite
**What goes wrong:** `hasBasisHeadline` needs a finite cumulative; `readCompositeFactsheet` returns null on a miss (composite-read-path.ts:374-380), rendering the "still computing" placeholder.
**How to avoid:** keep cumulative finite down to a 1-day suffix (Section 1.4); redact legacy rows AFTER the gate.

### Pitfall 3: Redacting a legacy row on the wrong key
**What goes wrong:** `twr_chain_broken` alone is not "mixed basis" once recomputed.
**How to avoid:** the discriminator is `twr_chain_broken === true && headline_since` absent. Test both directions.

### Pitfall 4: Stale `headline_since` after a re-stitch
**What goes wrong:** the composite path merges into existing flags (job_worker.py:9353-9363 area).
**How to avoid:** explicit `merged_flags.pop("headline_since", None)` on the clean branch, with a test.

### Pitfall 5: Gate placed in `jointMetrics`
See Anti-Patterns: breaks T16 and mislabels the widget's `undefined_beta` cause.

### Pitfall 6: Cache key not bumped
The public payload cache is id- and computedAt-keyed; a new `dataQuality` shape on a cached v12 payload would render the old (note-less) page. Bump to v13 and update the pin test.

### Pitfall 7: `unbuildableNoteKindOf` change breaks callers' types
`strategies/page.tsx:627` and `page.tsx:988` call it with one argument and the exhaustive `never` switch; adding the optional second parameter keeps both compiling, but the three note tables must all gain the key (compile-enforced).

### Pitfall 8: Public-text leakage
The guard reason phrases and the failed-analytics sentence are public (published strategies; the OG route and share pages). No flag names, no job or status vocabulary, no magnitudes. The date is the only specific.

### Pitfall 9: the skip-trailer tokens
Never write a CI-skip token in a commit message or PR body, even to deny it (CLAUDE.md "CI gate integrity" section 1). Say "the skip trailer".

### KS tail probability
```ts
// Source: Numerical Recipes probks rule; numbers in Section 2.2
function ksTail(lam: number): number {
  if (!(lam > 0)) return 1;
  const a2 = -2 * lam * lam;
  let fac = 2, sum = 0, prev = 0;
  for (let j = 1; j <= 100; j++) {
    const term = fac * Math.exp(a2 * j * j);
    sum += term;
    if (Math.abs(term) <= 1e-3 * prev || Math.abs(term) <= 1e-8 * sum) return Math.max(0, Math.min(1, sum));
    fac = -fac; prev = Math.abs(term);
  }
  return 1;
```
