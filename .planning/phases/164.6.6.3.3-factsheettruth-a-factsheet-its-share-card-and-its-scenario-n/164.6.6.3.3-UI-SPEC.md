## 1. "Measured since" note (D-01, D-02, D-03, D-12)

### 1.1 When it renders

The note renders on the slots in §1.4. The gates are the existing `headlineCoverageCaveat` gates:
- the basis is `cash_settlement`;
- `dataQuality.twrChainBroken === true`;
- for the strip only, no leverage what-if is applied.

The four guard-only rows with a leading-only break have `twrChainBroken` false, so they show no
note. That is correct, because their headline is the whole valid record.

Under mark-to-market or smoothed basis, no note renders. This is unchanged: those figures do not
come from the stored cash headline.

### 1.2 Inputs: guard reasons and the date

**Guard reasons, a closed plain-words map.** Each guard flag reaches readers only as its phrase.
Flag names, balance magnitudes and job vocabulary never reach the page; this is public text.

| Flag (`data_quality_flags`, strict `=== true`) | Phrase |
|---|---|
| `negative_nav_guard` | a zero or negative account balance |
| `dust_nav_guard` | a near-zero account balance |
| `flow_dominated_guard` | a deposit or withdrawal larger than the balance |
| `pnl_dominated_guard` | a one-day gain or loss larger than the balance |
| none of the four set (the break has another cause) | a break in the return chain |

**Join rule `{R}`:** phrases go in the table's order. One phrase stands alone. Two are joined with
" and ". Three or four are joined with ", " and a final " and ". Example: `a zero or negative
account balance, a near-zero account balance and a deposit or withdrawal larger than the balance`.

**Implementation contract:** the map is a `const` table typed `satisfies Record<GuardReason,
string>`, so a new reason that has no phrase is a compile error. Model it on the
`status-surface-copy.ts` tables.

**Date `{D}`:** `isoToMonthDay(headline_since)`, for example `Apr 18, 2026`.
- The **only** source of `{D}` is `data_quality_flags.headline_since` (RESEARCH 1.6).
- **Valid** means: a string matching `^\d{4}-\d{2}-\d{2}$` that `isoToMonthDay` turns into a real date (not "—").
- **A malformed value is treated exactly as an absent one.** A non-string, a non-ISO string, or an impossible date is not a date. It never yields an undated note; it makes the row a Withheld row (§1.3), because without a valid `headline_since` the stored scalars cannot be shown to cover one span (D-03).
- The series-derived `deriveHeadlineCoversFrom` read is not a source of `{D}` in this phase (§7 item 5).
- The UI never invents a date.

### 1.3 Variant selection and copy (verbatim; `{D}`, `{R}` and `{B}` are the only slots)

**Precedence, one rule, evaluated once on a chain-broken cash row:**

1. `headlineWithheld === true` → **Withheld**.
2. else a valid `{D}` (§1.2) → **Dated**.
3. else → **no note** (invariant violation; a read-path unit test pins it unreachable).

The read path sets `headlineWithheld` (planner names the field; present only when true) **exactly
when** `twr_chain_broken === true` and `headline_since` is absent **or malformed**, and redacts the
seven stored headline scalars to null in that same step. So the mapping is one-to-one:

| `headline_since` on a chain-broken row | Read path | Variant | Headline figures |
|---|---|---|---|
| valid | figures kept | Dated | shown |
| absent | `headlineWithheld: true`, figures null | Withheld | "—" |
| malformed | `headlineWithheld: true`, figures null | Withheld | "—" |

**Why arm 3 renders no note: it is unreachable on a payload this phase builds.** Arm 3 is reached only by a
chain-broken payload with neither the marker nor a valid date, and the read path never produces
one. The only other source would be a payload cached before this phase deploys, which carries
mixed-basis figures and no marker. The plan **must bump the payload cache key version**
(`buildFactsheetPayloadCached` keyParts, today `factsheet-v2-payload-v12`) so no such payload is
rendered under the new copy. **There is no full-history Undated variant.** Arm 3
renders no full-history note, and a unit test pins that the read path never emits
`twrChainBroken: true` with neither `headlineWithheld` nor a valid `headlineCoversFrom`. A failure
of that invariant is a read-path bug, caught by that test, and not a rendering state.

The `⚠ ` prefix (U+26A0, then a space) is rendered by the slot, on the **Withheld** note only (S1 and S2, §1.4). The Dated note and the span labels carry no `⚠`. The helpers return the text without it.

`{B}` is ` in both columns` when the rail's benchmark column is shown (a comparator is selected),
and empty otherwise. It appears only in S2, S3 and S4, the three rail panels with a benchmark
column (§1.5).

**Dated (the D-01 note):**

| Slot | Text |
|------|------|
| S1 KPI strip, no α/IR cells shown | `Measured since {D}; earlier history is unreliable (it includes {R}). Every figure in this strip covers only that span; the chart shows the whole record.` |
| S1 KPI strip, α/IR cells shown | `Measured since {D}; earlier history is unreliable (it includes {R}). Every figure in this strip except α and IR covers only that span; α, IR and the chart cover the whole record.` |
| S2 Rail, Main Metrics | `Measured since {D}; earlier history is unreliable (it includes {R}). Cumulative Return, CAGR, Ann. Volatility, Sharpe, Sortino and Calmar cover only that span{B}; Skew, Kurtosis and the chart cover the whole record.` |
| S3 Rail, Returns (new slot) | `Measured since {D}. The trailing returns cover only that span{B}; Win Rate and Profit Factor cover the whole record.` |
| S4 Rail, Max Drawdown (new slot) | `Measured since {D}. Max Drawdown covers only that span{B}; the other figures in this panel cover the whole record.` |
| S5 Rail, Cumulative Return Metrics | `Measured since {D}. Every return in this panel covers only that span.` |

**Withheld (D-03, a legacy mixed-basis row or a malformed `headline_since`).** S1 and S2 render
this text; S3, S4 and S5 render nothing.
`Headline figures withheld: earlier history is unreliable (it includes {R}), and the span after it has not been measured yet.`

**Selected range** (`windowCoverageCaveat`, strip and rail Main Metrics). After D-01 every headline
figure is on the suffix, so the subject is "Its figures", not "Cum. Return, CAGR and Calmar":
- range starts before a valid `{D}`: `This range starts before {D}, where the full-history figures begin. Its figures include returns from before that date, which the full-history figures leave out.`
- no valid `{D}` (a Withheld row; a selected range is re-derived from the stored series, so its figures do show): `The record has a break in the return chain at a date this view cannot name, so this range may span it. Its figures compound across any break inside it.` This is the only undated sentence left in the phase, and it is reachable.
- range starts on or after `{D}`: no note (unchanged).

The code comment beside the strip's `coverageCaveat` must also change. It currently says "the
engine's Max DD already spans the whole record", and D-01 makes that false.

### 1.5 Benchmark column span (rail S2, S3, S4)

The rail's benchmark column (`b = jointCmp.summary`) is computed today over the whole record, while
on a Dated row the strategy's headline figures cover only the suffix. A row would compare two
different spans.

**Rule:** on a Dated row at full history, each benchmark cell is computed over the **same span as
the strategy figure on that row**:
- headline rows (Cumulative Return, CAGR, Ann. Volatility, Sharpe, Sortino, Calmar; the trailing returns; Max Drawdown) take the benchmark summary of the slice from `{D}` to the record's end;
- whole-record rows (Win Rate, Profit Factor, Longest DD) keep the whole-record benchmark summary.

On a Withheld row the headline rows' benchmark cells read "—": there is no measured span to compare
against. The whole-record rows are unchanged. A selected range is unchanged (the windowed view
already slices both legs).

**This is its own planner task, not a copy change.** It is a compute change: a suffix-sliced
benchmark summary (for example `compute()` on the benchmark slice from `{D}`, beside the existing
`jointCmp.summary`), wired into the headline rows' `bench` props, with its own failing-first tests:
a Dated row's headline benchmark cells equal the suffix summary and differ from the whole-record
one; whole-record rows are unchanged; a Withheld row reads "—" in the headline benchmark cells; a
clean row and a selected range are byte-identical to today. The `{B}` copy slot ships with it, never
before it.

This follows D-06's "card equals factsheet" principle (one figure, one span) and 170.2 D-07 (chart
and table always agree). `{B}` in S2–S4 says so in the copy. The existing `bnDated` header
(comparator prices stop early) is unaffected and still names its own end date.

### 1.6 6 Month and 1 Year rows: gate on record length (D-12, changes D-57)

D-12 is locked: Quantum Drift reads "—" for 3M and 6M. Today the 6 Month and 1 Year rows are
omitted when `m.p6m` / `m.p1y` is null (Phase 169 D-57), and D-01 makes a long chain-broken record's
windows null. That would hide the 6M row that D-12 says reads "—".

**Rule (both the Returns panel and Cumulative Return Metrics):**
- a 6 Month or 1 Year row is **omitted** when the **whole record** is shorter than the window (record length from the view's first to last date, the same calendar rule `compute()` uses);
- it **renders "—"** when the record covers the window but the value is null (the suffix does not cover it).

**3 Year and 5 Year are out of scope and keep today's rule** (omitted when the value is null,
Phase 169 D-17, a founder decision). Changing them would amend D-17 for consistency only, and no
decision in this phase requires it. Consequence, accepted: Cumulative Return Metrics runs two
omission rules (6M/1Y by record length, 3Y/5Y by null), so a long chain-broken record omits its
3Y/5Y rows where it shows "—" for 6M/1Y (§7 item 6).

**Test impact.** `MetricsColumn.window-rows.test.tsx` asserts that a null `p6m` omits the row. Its
short-record cases stay green (the record is shorter than the window). A new case is needed: a long
record with a chain-broken short suffix renders 6 Month and 1 Year as "—". The scenario mount
(`scenario-factsheet-payload.ts`, "D-57 omits all four rows") stays green because its record is
short.

## 2. Flat strategy leg (D-04)

### 2.1 Rule

When the paired strategy slice has no dispersion (`dispersion(paired, 0).sd === 0`, gated in
`comparator-block.ts` after `jointMetrics`), the factsheet renders "—" for exactly these fields:
`Alpha (ann)`, `Beta`, `Information Ratio`, `Up Capture` and `Down Capture` in §IV, and the strip's
`α vs {cn}` and `IR vs {cn}` cells.

`Correlation`, `R²` and `Treynor` already read "—". `Tracking Error` keeps its number, because it
is a real measurement (the benchmark's own volatility).

Every one of these "—" cells is colourless:
- the strip's `signTone` returns `undefined` for a non-finite value;
- §IV `Alpha (ann)` takes no accent (§6).

The strip keeps its cell count; the α and IR slots stay and read "—".

**Precedence**, first match wins:
1. native-unit arm (existing `withheldReason`);
2. paired-floor withholding (existing `pairedFloorReason`; the joint is null);
3. flat leg (this rule; the joint is non-null and the five fields are NaN).

The render picks the flat-leg reason from a present-only marker on the comparator block, for
example `flatLeg: true`, never by testing the values for NaN. The planner names the field.

Out of scope, and unchanged: the Rolling Beta chart still draws 0 for a flat window (T17-pinned),
and the Allocations alpha/beta widget still shows beta 0 (T16-pinned).

### 2.2 Reason lines (verbatim)

`{span}` is `this record's` at full history and `the selected range's` while a range is selected.
This is the same noun switch `pairedFloorReason` makes.

| Where | Text | Markup |
|-------|------|--------|
| Under the KPI strip, only when the α/IR cells are shown | `Alpha, beta, information ratio and capture need daily returns that vary; {span} do not.` | The existing `joint-floor-reason` `<p>`: `px-3 sm:px-4 py-2 text-micro font-mono`, hairline top border, `color: var(--color-text-muted)`. Its own `data-testid="joint-flat-leg-reason"`. |
| §IV, under Joint Metrics | same sentence | `BenchmarkMetricsBody` `withheldReason` slot: `mt-2 text-fixed-11 text-text-muted`. Same `data-testid="joint-flat-leg-reason"`. |

The reason line is muted and has no `⚠`. A flat leg is an honest fact about the record, not a
warning (DESIGN.md: muted means steady-state, honest-empty).

**The flat-leg line and the paired-floor line never render together.** Under the first-match-wins
precedence above, a joint that is withheld by the paired floor is null, so the flat-leg arm (which
requires a non-null joint) cannot match; and a flat-leg joint is not floor-withheld. Each slot shows

## 3. OG share card (D-06, D-07, D-11)

### 3.1 Values

The card shows the factsheet's stored value. The `values.length >= 30` gate in `og-metrics.ts` is
removed (the route keeps its own `rows.length >= 2` floor).

The card withholds CAGR in exactly two named cases, and nowhere else (D-11):
- **E1:** the span is under 0.95 years;
- **E2:** the 169.4.1 D-46 rule applies (`twr_chain_broken` or `insufficient_window`, where the stored CAGR covers only the suffix).

In those two cases the card shows "—" while the factsheet shows its CAGR. Sharpe and Max DD must
always equal the KPI strip's string.

**The `cum > 0` check stays, as an implementation guard, not a display exception.** It protects
`Math.pow(cum, 1 / years)`, which has no real value when compounding reaches zero or below (a full
wipeout). It applies only to the computed fallback, a CAGR key the embed did not carry. When the
stored CAGR is present, the card shows it, subject only to E1 and E2, whatever `cum` is. The parity
test (`route.page-agreement.test.tsx`) therefore lists E1 and E2 and no third exception.

### 3.2 Format (string parity with the strip)

| Stat | Card format | Matches strip |
|------|-------------|---------------|
| Sharpe | 2dp, or "—" when non-finite (unchanged) | `num(m.sharpe)` |
| CAGR | signed, 1dp: `+0.7%`, `-3.1%`, `0.0%`, or "—" | the strip's CAGR cell |
| Max DD | **unsigned**, 1dp: `-3.7%`, `0.0%`, or "—". **Change:** today's signed `fmtPct` prints `+0.0%` for a zero drawdown, while the strip prints `0.0%`. | the strip's Max DD cell |

**Sign from the rounded value (both surfaces).** A value that rounds to zero at 1dp prints `0.0%`,
with no `+` and no `-`. For example, `-0.0004` prints `0.0%` on the strip and on the card; today
the strip prints `-0.0%` and the card `-0.0%` or `+0.0%`. Both surfaces use one shared rounding-aware
helper so their strings cannot drift.

### 3.3 Colours

Tone is computed from the value rounded to 1dp of a percent.

| Stat | Rounded > 0 | Rounded < 0 | Rounds to 0 | Non-finite ("—") |
|------|-----------|-----------|-----------|------------------|
| Sharpe | `#1A1A2E` | `#1A1A2E` | `#1A1A2E` | `#1A1A2E` |
| CAGR | `#15803D` | `#DC2626` | `#1A1A2E` | `#1A1A2E` |
| Max DD | (not reachable) | `#DC2626` | `#1A1A2E` | `#1A1A2E` |

Implementation: `tone` is `undefined` unless the rounded value is finite and non-zero. Today's
`tone={cagr >= 0 ? "pos" : "neg"}` and `tone="neg"` colour a "—" and a zero; both go. The label
colour stays `#64748B`, the value font stays 56px monospace 700, and the card's layout, header,
footer and `verified` mark do not change. The card carries no footnote for E1 or E2; D-46 found it
has no room, and the factsheet's note carries that context.

**Contrast**, at 56px (WCAG large text, 3:1 needed): `#1A1A2E` on `#F8F9FA` is about 16:1;
`#DC2626` and `#15803D` are each above 4.5:1. All pass.

### 3.4 Strip tone and sign (coherence with the card)

The strip's `signTone` returns `positive` for `v >= 0`, so an exact zero and a value that rounds to
zero paint green. `maxDdTone` paints a value such as `-0.0004` red although it prints as zero.
DESIGN.md says a zero is neutral and the sign comes from the rounded value.

**Rule:** at all five toned strip cells (Cum. Return, CAGR, Max DD, α, IR) the tone and the printed
sign come from the value rounded to the cell's precision (1dp of a percent for the returns and Max
DD; 2dp for IR). A value that rounds to zero is neutral and unsigned. Every other value keeps
today's tone.

Scope: the strip and the OG card, the two parity surfaces. The shared `pctSigned` formatter used
elsewhere on the page is not changed in this phase (Rule 7 item 7).
