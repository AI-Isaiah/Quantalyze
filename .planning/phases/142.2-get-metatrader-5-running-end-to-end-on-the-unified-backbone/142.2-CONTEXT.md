# Phase 142.2: Get MetaTrader 5 running end to end on the unified backbone - Context

**Gathered:** 2026-08-03
**Status:** Ready for planning

<domain>
## Phase Boundary

A founder connects a real MetaTrader 5 account through the wizard and sees **correct**
performance rendered from the unified backbone — `key → dailies → backbone → UI` — with no
step requiring a human to know an internal error code, a server name, or a flag.

This phase does **not** build an MT5 pipeline. v1.15 already shipped one (6/6 phases, tag
`v1.15`), and MT5 is already wired into the unified backbone at
`analytics-service/services/broker_dailies.py:403` (`combine_mt5_deal_ledger`). This phase
proves the existing pipeline is **correct against an external oracle**, and closes the
connect-experience defects that make it unreachable or misleading today.

**Scope anchor:** the connect experience + the correctness of what it produces. Not new MT5
capability.

</domain>

<decisions>
## Implementation Decisions

### Production flag state (blast radius)

Prod is currently in an **incoherent half-state** that this phase resolves first:
`NEXT_PUBLIC_MT5_ENABLED=true` is set (Production only), so the MT5 wizard card renders for
**every** production user — `MT5_UI_ENABLED` at `src/lib/closed-sets.ts:124` is a bare
`process.env.NEXT_PUBLIC_MT5_ENABLED === "true"` with **no founder gate**. But server-side
`MT5_ENABLED` is **absent from all 29 Vercel production vars**, so
`isMt5EnabledServer()` (`src/lib/closed-sets.ts:178`, strict `=== "true"`) is false and
`src/app/api/strategies/create-with-key/route.ts:147` rejects every submission. Every user who
clicks MT5 today gets a demonstrably false error. This is a **live user-facing defect**, not a
founder-only dogfood issue.

- **D-01:** Set server-side `MT5_ENABLED=true` in Vercel **now, before writing any code**. This
  is an env fix, not a code fix — the leading hypothesis in `TODOS.md` is confirmed at source.
  Chosen over hiding the card or deferring the flip because it is the only option that both ends
  the lie today and unblocks dogfood. Accepted cost: real users can connect MT5 and will meet the
  unfixed field/copy until D-03/D-05 land.
  - ⚠️ **A Vercel env change requires a REDEPLOY to take effect.** Setting the var alone does
    nothing. This is a plan task, not an assumption.
  - Side effect, and a desirable one: `/security#mt5-readonly` — the investor-password guide the
    wizard links to — also gates on `isMt5EnabledServer()`
    (`src/app/(marketing)/security/page.tsx:544`). It is currently **blank in production**, so the
    founder was told to use an investor password while the page explaining what that is rendered
    nothing. The flip fixes this; the guide content itself is already correct.
- **D-02:** Set `MT5_ENABLED=true` in **all three environments** — Production, Preview,
  Development. Rationale: a gate that is true in one environment and false in another is exactly
  the bug class just found, and no test can see the difference.
  - ⚠️ **Consequence the planner must handle:** `NEXT_PUBLIC_MT5_ENABLED` is **currently
    Production-only**. "All three" therefore means extending **both** vars to Preview and
    Development. Setting only the server var there produces the mirror-image half-state
    (server on, card hidden).

### Broker-server field

- **D-03:** Unmask via a **per-venue masking flag**, not a global change. MT5 reuses OKX's
  passphrase slot (`ConnectKeyStep.tsx:141` relabels it "Broker server"), and that slot renders
  `type={showSecret ? "text" : "password"}` at `ConnectKeyStep.tsx:697`. OKX's passphrase is a
  **genuine credential and must stay masked**. Add a `passphraseSecret: boolean` alongside the
  per-venue `passphraseLabel` / `passphrasePlaceholder` config the file already carries — MT5
  `false`, OKX `true`. Config addition, not new machinery; the OKX render must stay
  byte-identical.
- **D-04:** **Defer the typeahead.** `TODOS.md` asks for "plain text + searchable typeahead", but
  there is **no broker-server list anywhere in the repo** (zero hits for `broker_server` /
  `server_name` across `.py`/`.ts`/`.tsx`) and no public canonical registry. A partial list is
  worse than none — it invites picking a near-match that fails validation. Ship plain text plus
  the helper copy already written at `ConnectKeyStep.tsx:144` ("copy the server name exactly as
  it appears in your MT5 terminal"), which is the only reliably correct instruction. Log the
  typeahead to `TODOS.md` **with the data-source problem named**, so it is not re-opened as a
  simple UI task.

### Error-copy honesty

The generic block is worse than "exchange-generic": `src/lib/wizardErrors.ts:477`'s `cause`
reads *"Client-side format check failed before sending the key to the exchange"* — **factually
false** for the founder's case, which was a server-side feature gate. MT5 already has correct
dedicated copy (`KEY_MT5_MASTER_PASSWORD`, `KEY_MT5_WRONG_SERVER` with Demo/Live-suffix guidance
at `wizardErrors.ts:470`); the route simply never reaches it.

- **D-05:** **Split `KEY_INVALID_FORMAT` into honest codes.** It currently buckets ~12 unrelated
  causes per route — malformed body, unsupported exchange, missing `api_key`, sFOX gate, MT5
  gate, missing secret ×2, missing passphrase, missing `wizard_session_id`, three length caps —
  all rendered as "your API key format is wrong". Distinct causes get distinct codes
  (missing-required-field, unsupported-venue, venue-not-enabled, input-too-long).
  `KEY_INVALID_FORMAT` retains **only actual format failures**, which makes its existing copy
  true again.
  - ⚠️ Note for the planner: D-01 makes the MT5-gate arm (`route.ts:147`) **unreachable**. A
    narrow fix aimed only at that arm would be fixing a line that can no longer fire. The value
    is in the class, not the instance.
- **D-06:** Scope the split to the **two wizard routes**:
  `src/app/api/strategies/create-with-key/route.ts` (14 sites) and
  `src/app/api/strategies/composite/add-key/route.ts` (14 sites) = **28 sites**. These are the
  two paths a founder actually submits credentials through, so both can tell the same lie to a
  real user. `src/app/api/keys/validate-and-encrypt/route.ts` (5) and
  `src/app/api/verify-strategy/route.ts` (6) are internal / public-verification surfaces with
  different callers and their own copy contracts — **log those 11 sites to `TODOS.md`**, do not
  fold them in.

### Proof / verification

- **D-07:** The oracle is **external**: the MT5 terminal's own equity and balance figures, or
  the broker statement, for a fixed window. Our rendered equity curve and period return must
  match within a stated tolerance. Explicitly **not** internal consistency (dailies compound to
  displayed equity, backbone agrees with UI) — that is the self-referential shape that let three
  money bugs survive six review passes. `broker_dailies.py` already claims to honour
  `account_info().equity` as authoritative; this tests that claim.
- **D-08:** **Measure the server-UTC offset live, then assert on it.** MT5 brokers stamp deals in
  broker-server time (commonly UTC+2/+3, DST-shifting) while dailies bucket by UTC date. A wrong
  offset silently misassigns near-midnight deals to the adjacent day — **period totals still
  reconcile while the daily series is wrong**, which corrupts Sharpe, max drawdown, and every
  risk metric derived from the series. This is the failure mode D-07's oracle cannot see on its
  own. Read the gateway's server time against UTC at connect, persist the observed offset, and
  make a **near-midnight deal an explicit regression test** — a deal within the offset window of
  midnight must land on the day the terminal shows. Rejected: assuming UTC (invisible failure),
  and hardcoding the broker's offset (breaks at DST, wrong for every other broker).
  `139-VERIFICATION.md:12` already names `MT5_SOAK_SERVER_OFFSET_MIN` as the intended carrier.
- **D-09:** Verify against the **live funded account** — the one the founder tried to connect —
  not a demo and not the v1.15 soak account. Real fills, real fees, real swap charges, real
  equity. Uses the investor (read-only) password, which cannot place trades. Demo rejected
  because synthetic fills/swaps prove the plumbing without proving the money math, and demo
  accounts often carry an artificial starting balance that exercises different anchor logic. The
  soak account rejected because v1.15 shipped green against it **with both open items intact** —
  it has already demonstrated it does not catch these.
  - ⚠️ **Must be a TRADING day.** A weekend run proves nothing. Phase starts Mon 2026-08-03, so a
    live session is available this week.
- **D-10:** **If the terminal comparison disagrees, fix it in-phase — uncapped.** The founder
  explicitly chose the unbounded option over a split-if-shared-money-math stopping rule. A
  shared-backbone root cause affecting every venue is therefore **in scope**, and the planner
  must size for that possibility rather than treat it as an escape hatch. The phase does not
  close until the terminal and the UI agree. Rationale: a known-wrong number rendered to users is
  worse than an unfinished phase.
- **D-11:** Verify **every surface that renders strategy performance** — strategy detail
  (`/strategy`), public factsheet, scenario composer, portfolio PDF, browse.
  - The founder correctly challenged this: all surfaces take dailies → unified backbone, so they
    *should* be identical by construction, and `job_worker.py:6043` says exactly that. **This was
    checked, not assumed**, and the architecture largely holds — MT5's annualization is already
    handled correctly by v1.15 (`create-with-key/route.ts:510` stamps
    `isCryptoExchange(exchange) ? "crypto" : "traditional"`;
    `finalize-wizard/route.ts:731` states "stamp `traditional` for mt5 (forex/CFD)"), and
    `portfolio-stats.ts` **defaults** to `periodsPerYear = 252`, so a caller that forgets to pass
    a basis still lands on the correct clock for MT5. The fragile direction is crypto, not MT5.
  - The residual reason to check all five is narrow and specific: the **backbone-bypass surfaces**
    logged in `TODOS.md` — `_compute_portfolio_analytics`
    (`analytics-service/routers/portfolio.py:628`), `equity_reconstruction.py`, and the bespoke TS
    stacks `portfolio-stats.ts` / `scenario-blend-panels.ts` / `health-score.ts` — **re-derive**
    metrics rather than reading them. They consume the same dailies but recompute annualization
    independently. They are the one place the founder's model could be false today.
  - Framing for the planner: this is **one daily series checked five ways**, not five independent
    risks. Same account, same window, five views. Four of the five checks are cheap.

### Claude's Discretion

None — every gray area presented was decided by the founder.

- **Per-venue wizard config** (`ConnectKeyStep.tsx:129-150`): the MT5 card already carries
  `credentialLabels`, `credentialPlaceholders`, `passphraseLabel`, `passphrasePlaceholder`, and
  helper copy. D-03 extends this exact shape with `passphraseSecret` — no new pattern.
- **Dedicated MT5 error codes** already exist and already have correct copy:

- **`MT5_REJECT_ATOM_BODY`** (`ConnectKeyStep.tsx:163`) — the honest master-vs-investor password
  explanation, already written and venue-keyed at :382.
- **MT5 is already on the unified backbone** — `combine_mt5_deal_ledger`
  (`broker_dailies.py:403`) with fail-loud `Mt5DealClassificationError` **before** any series is
  produced. No new pipeline needed.

### Established Patterns
- **Server flag read as a function, never a module-load const** (`closed-sets.ts:178` and its
  comment) — so it evaluates per-request and is never inlined into the client bundle. Any new
  server gate must follow this.
- **Closed-set no-widening pin**: mt5 stays OUT of `UI_EXCHANGE_CODES` / `EXCHANGES` /
  `FUNDING_EXCHANGES` / `CRYPTO_EXCHANGES` regardless of the flag (`closed-sets.ts:119-122`).
  D-01/D-02 must not widen these.
- **asset_class is the single annualization clock selector**, with a fail-loud cross-check
  against the legacy venue blend (`job_worker.py:6065`). MT5 → `traditional` → √252.
- **Dailies are canonical; derive everything.** Metrics, charts, and coverage all descend from
  the daily series.

### Integration Points
- `src/app/api/strategies/create-with-key/route.ts:147` — the MT5 server gate D-01 opens
- `src/app/api/strategies/create-with-key/route.ts` + `composite/add-key/route.ts` — the 28
  `KEY_INVALID_FORMAT` sites D-05/D-06 split
- `ConnectKeyStep.tsx:693-700` — the shared passphrase input D-03 makes per-venue
- Gateway: `MT5_GATEWAY_HOST=mt5-gateway.railway.internal:8001`, Railway-internal (unreachable

<specifics>
## Specific Ideas

- The founder's own framing of the architecture, which shaped D-11: *"They should all take
  dailies, then unified backbone, and from the unified backbone, it should be the same."* Treat
  this as the **invariant under test**, not as an assumption to build on. Where a surface
  re-derives instead of reading, that is a finding.
- The oracle standard comes from a prior lesson the founder has already paid for: money-math
  oracles must pin **economics**, not the implementation's own formula. Three money bugs survived
  six review passes on self-referential oracles.
- v1.15 shipped **6/6 phases green** with both open items intact. A green unit suite is therefore
  explicitly **not** evidence for this phase's goal. Verification is end-to-end against a live
  account on a trading day, or it has not happened.

</specifics>
