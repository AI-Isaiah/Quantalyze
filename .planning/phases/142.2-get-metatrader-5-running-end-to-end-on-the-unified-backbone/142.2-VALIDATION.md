## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework (TS)** | Vitest (`vitest.config.ts`) + `@vitest/coverage-v8`; CI runs sharded with `--coverage`, merged by the `frontend-coverage` job |
| **Framework (PY)** | pytest (`analytics-service/pytest.ini`, `asyncio_mode = auto`, `testpaths = tests`, `xdist_group` marker for shared-TEST-DB serialization) |
| **E2E** | Playwright (`e2e/*.spec.ts`), `npm run test:e2e` |
| **DB gates** | Plain SQL in `supabase/tests/test_*.sql` — **the only DB gate that runs in CI** |
| **Quick run command (TS)** | `npx vitest run src/lib/strategyGate.test.ts` |
| **Quick run command (PY)** | `cd analytics-service && pytest tests/test_broker_dailies.py -x` |
| **Full suite command** | `npm run typecheck && npm run lint && npm run test` **and** `cd analytics-service && pytest && mypy --strict .` |
| **Estimated runtime** | quick ~30s · full TS ~6 min · full PY ~4 min |

⚠️ `pytest` for analytics-service **must** be run from `analytics-service/`. A repo-root run misses
the VCR `cassette_library_dir` and makes **live broker calls**.
⚠️ Reproduce any CI-only vitest failure under `PATH=/opt/homebrew/opt/node@22/bin` before calling
it a flake — CI is Node 22, local is Node 25.

## Sampling Rate

- **After every task commit:** `npx vitest run <touched spec>` **or** `cd analytics-service && pytest tests/<touched> -x`
- **After every plan wave:** full TS suite **and** full PY suite (`pytest` + `mypy --strict`)
- **Before `/gsd:verify-work`:** both full suites green, the SQL gate applied on **TEST**
  (`qmnijlgmdhviwzwfyzlc`), and `npm run test:e2e` for the wizard specs

## Oracle Independence

> The failure this catches: assertions that read their expected value out of the module under test.
> ⚠️ Live precedent on this codebase: **three money bugs survived six review passes** behind
> self-referential oracles. This section is not boilerplate here.

- [ ] No test imports a **constant** from the module it tests — expected values are **literals** in the test
- [ ] No assertion compares a value to itself via a re-export, fixture, or table under test
- [ ] Table/registry sizes are pinned to a **literal count** (e.g. `14`), not to `len(THE_TABLE)`
- [ ] Any fake/double is pinned against the real contract it stands in for (version, key shape, semantics)
- [ ] **The D-15 economic fixture asserts an ECONOMIC INVARIANT** — that a realized-empty series is
      *materially understated versus the same book with realized PnL present* — **not** that the
      combiner returns what the combiner computes. A test that only checks the verdict string is
      self-referential and does **not** satisfy SC-1.
- [ ] The gate's verdict allow-list is pinned as **literals in the test**, not imported from
      `strategyGate.ts` — otherwise widening the allow-list silently widens the test with it
