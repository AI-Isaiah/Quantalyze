<objective>
SC-3 and SC-2, consumer half, plus SC-4: the fills-cursor gate of `run_sync_trades_job` never stamps past a stopped symbol's unread fills, never holds on a venue-unlisted symbol, and records the precondition for turning raw ingestion on for Binance.

Purpose: Phase 232 made the gate stamp the newest persisted fill and hold on `sync_truncated_*` and `binance_partial_symbols`. A Binance read that stops early with a bound (page cap, a page it cannot page past, deadline; recorded by 250-06 and 250-07) returns every fill it read, including healthy symbols' fills newer than the stopped symbol's unread span, so the plain maximum would stamp past that span. The gate now takes a read-through bound from the drained flags and stamps the newest persisted fill at or before it, so the next run seeds at that stamp (minus the 1 h overlap). For a cap stop the bound IS the capped symbol's newest read fill, so the stamp lands on it and the next run resumes past the cap. For a stop whose covered prefix holds no persisted fill after the cursor, nothing is stampable and the cursor stays. The deadline form of that case is the founder-ruled known limit (250-CONTEXT `### Founder ruling 2026-11-25 (UTC) — quiet-prefix deadline case`), and the ruling keeps exactly what this gate does here: stamp only a persisted fill at or before the bound, holds win, no read-through stamp. The same ruling makes the switch name that limit as an exception, which this plan writes into the SC-4 comment. The cursor itself is the resume point, written by the same monotone `advance_sync_cursor` RPC as every stamp.

Output: the gate change in `services/job_worker.py`, the SC-4 comment, a new gate test file driving the REAL `run_sync_trades_job`, PROOF-01 records.

|---|---|---|---|---|

| `binance_deadline_symbols` | list[str] | 250-07 | same as the row above | the read deadline stopped the symbol |
| `binance_read_through_ms` | plain `int` epoch ms, not `bool`, `>= 0` | 250-06 (cap and untimed), extended by 250-07 (deadline); exactly ONE `_record_dq_flag` call per read, after the gather, value = the minimum over stopped symbols | it bounds the stamp | every stopped symbol is complete through this instant; the gate stamps the newest persisted fill whose timestamp is at or before it |
| `binance_fill_cursor_advance_plus1` | bool | HEAD key; 250-03 moves the recording to the parent | no | the same-millisecond +1 step fired |

Rules: no new key starts with `sync_truncated_` or equals `binance_partial_symbols` (the gate holds on those). `_record_dq_flag` SUMS two ints, so the bound is recorded once. Every flag is recorded by the parent coroutine of `_fetch_raw_trades_binance` (before the tasks are built or after the gather), NEVER inside `_fetch_one`: `asyncio.gather` runs each `_fetch_one` in a Task holding a COPY of the context, so a `_record_dq_flag` call inside it is lost (measured on 2026-11-25 with the worktree venv: a flag recorded inside a gathered task left the parent's drain empty; HEAD's `binance_fill_cursor_advance_plus1` is dropped exactly this way).
