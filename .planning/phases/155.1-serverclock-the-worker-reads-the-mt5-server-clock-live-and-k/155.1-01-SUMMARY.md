- **Found during:** Task 1 review

- **Fix:** that branch returns all-None offsets (the plan's own shape).

## Findings for plans 03 and 04 (recorded, not fixed here)

- **INTEGER overflow is still reachable on other branches.** `measured_offset_s` and `expected_offset_s` are INTEGER. A far-future tick under the `fixed` clock (no datability check) or a year 2094-2099 tick under a rule can exceed int4 and fail the insert, because D-19 forbids a plausibility class and no bound was invented. If plan 03 wants this closed, the options are BIGINT columns (a migration shape change, cheap now, costly after PROD apply) or an explicit decision. Surfaced for the founder, not decided.
- **Insert failure outcome is not pinned.** The derive lets a DB error from the reading insert bubble. Plan 03 must pin the exact outcome (the handler's unhandled-exception path via `classify_exception`) and add a 175-style transient return if that path does not already give `transient`.
- The mismatch message is not yet in `test_every_new_derive_message_is_blame_free_for_the_mt5_classifier`'s census (plan 03). Checked by hand: it classifies `transient`.
- `Mt5DealLedgerRead` fields use `tick_read_at` from `_tick_read_now()`; the tracer test monkeypatches `services.mt5_read._tick_read_now`.
