# Phase 164.6.6.2.1 Plan 02: Native levels and live balance to USD Summary

Three pure functions in `services/native_to_usd.py` price native levels and live balances at the stored daily BTC close, with an exact-day lookup and no carried price.

## What was built

- `convert_native_levels_to_usd(levels, unit, btc_closes)`: USD level on day D is the native level times the stored close of D. A day without a usable close, or with a non-finite native level, is absent. Entry contract mirrors the returns converter (`unit None` returns the same object; no closes returns an empty `DatetimeIndex` series). The result is sorted with the input's name. The module docstring gained a paragraph naming the levels rule and its oracle.
- `latest_completed_close_day(now)`: UTC midnight of the UTC date of `now` minus one day. A naive datetime raises `ValueError`.
- `price_live_balance(native_amount, unit, btc_closes, now)`: `(amount x close, day)` using only the close dated `latest_completed_close_day(now)`, else `None`. 0.4213 BTC at 61950.00 gives 26099.535 dated the previous UTC day.

`benchmark.py` was not touched. The shared JSON oracle is not extended (it stays RETURNS-only for TypeScript); a comment in the test file says so.
