# Phase 164.6.6.2.1 Plan 08: Key-mode USD inputs for a BTC key Summary

Key mode no longer skips a BTC MT5 key: its per-key returns, flows, dropped-day P&L and realized terminal are the native series priced at the stored close of each day, its anchor is the live balance at the latest completed close, and a missing close is named (`native_unpriced`, `unpriced_close_day`, `unpriced_days`) instead of priced at a stale one.

## What was built

- `_convert_native_key_to_usd` (module level in `job_worker.py`, pure): USD returns via `convert_native_returns_to_usd`, reindexed onto the native index; day P&L and flows via `convert_native_levels_to_usd` (amount x the close of that day); realized terminal = native realized NAV level at the last USD return day P (forward-filled natively, from `reconstruct_mt5_nav_levels`) x close(P); `unpriced_days` = native return days after the first that the USD series lacks (plus a flow day with no close), excluding days after the last stored close (the live tail, D-17), and a TWR-dropped day only when its P&L cannot be priced.
- MT5 key-mode branch: `_native_key_usd` replaces the skip for BTC; the closes load (plan 07's one read) now also feeds the conversion. The skip (`native_unit`) remains for an unsupported code. The material-equity floor still judges NATIVE usable days; conversion happens after it. The BTC key's unit is persisted after that floor.
- Epilogue: `_anchor_basis` is `price_live_balance(equity, ...)` for a native key; arm order is `native_unit` (skip), then `native_unpriced` (live close missing), then the existing balance_error / nonfinite / nonpositive / dust / flow_drop ladder, now judging the USD anchor. `key_inputs` gains `native_unit`, `priced_through`, `unpriced_days` and, when the anchor is NULL, `unpriced_close_day` (all additive).
- The 164.6.6.2 D-13 "skipped honestly" comment block is replaced by a block naming D-09 and D-17.

**2. [Plan wording] The conversion lives in a module-level helper**
`_convert_native_key_to_usd` instead of inline in the derive: the derive is one ~3000-line function, and a pure helper keeps the new rules testable and type-checked. It imports `_usable_closes` from `native_to_usd` (an underscore name) rather than restating the finite-and-positive close rule a second time; flagged for plan 09 / cleanup if a public name is preferred.

**3. [Plan wording] The unit write for a BTC key moved after the material-equity floor**
The plan did not say when; the skip path wrote it before the combine. A BTC key now writes it where strategy mode does (after the floor), so a series never exists beside a stale unit.

**Total deviations:** 1 blocking-class test-design adjustment, 2 notes. No scope beyond the key-mode writer and its tests.

## Handoff notes for plan 09 (compose, not decided here)

- `priced_through` equals `realized_terminal_day` (the last USD return day P); it is the T1 `departed_end_by_key` value. A key whose live close is missing keeps its series and terminal at P and has a NULL anchor.
- `dropped_day_pnl` for a BTC key includes the FIRST native return day when it has a P&L (the converter drops that day's return). The compose's `replay_key_equity` adds it to the day set, which gives the first USD return its opening level; unpriced days are excluded from it by name.
- Flows are persisted for every flow day that has a close (even after P); a flow day without a close is omitted and, when it is on or before the last stored close, named in `unpriced_days`. MEASUREMENT M3 showed the compose's backward roll is wrong across a hole unless it is told about the unpriced days (I2=build).
- `native_unpriced` is not added to `_NO_CAPITAL_ANCHOR_REASONS` (a BTC key has capital).
