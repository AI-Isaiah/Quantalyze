# Phase 164.6.6.2.1 — UI Design Contract

> Visual and interaction contract for BTCUSDVIEW: a native-unit (BTC) account also gets a USD
> view. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> What this phase adds:
> - the factsheet gains a BTC/USD unit toggle;
> - the strategy list gains a compact "in BTC" chip;
> - the owner's key card shows the native balance beside its USD value at a named close;
> - the dashboard prices the account in USD, with the native amount one hover away, and names the
>   account whenever an unpriced day leaves it out of the total.
>

## The rules this phase adds

**1. The view gate.** Every factsheet change is gated on two payload values. The UI reads nothing
else.

| Value | Meaning | Rendering |
|-------|---------|-----------|
| `returnsUnit === null` | USD family | **Byte-for-byte unchanged.** No toggle, no disclosure, no new node, no new class. The payload carries no `usdView` key. |
| `returnsUnit` set, `usdView` present | Native strategy whose USD conversion succeeded | Native view by default (D-01). The USD segment is enabled. |
| `returnsUnit` set, `usdView` absent | Native strategy whose USD view could not be built | Native view only. The USD segment is `aria-disabled` and shows a reason. |

**2. Native is the default on every load (D-01).** SSR renders the native view, and the chosen view
is component state only. **[discretion: no persistence]** CONTEXT allowed browser storage as a
convenience, and this spec declines it. Reading storage after mount would re-render a
USD-preferring viewer's factsheet a moment after first paint. Nothing is written to `localStorage`,
a cookie or the URL. The toggle is ephemeral, like the leverage input.

**3. A figure always names its unit on a native strategy.**
- In the native view a return label reads `… in BTC`. This is the 164.6.6.2 contract, unchanged.
- In the USD view the same label reads `… in USD`, through `withUnit(label, "USD")`.

On a native strategy no return label is ever bare, in either view. How the selected view supplies
the label unit is the planner's call. The rendered strings below are the contract.

**4. The masthead and the document's dating stay native in both views (D-19, and the founder ruling
of 2026-08-26).** These render from the **native** payload and never change on a toggle:
- The H1 and the `Returns in BTC` chip (164.6.6.2 A1). Their tooltip ("measured in BTC") stays true
  because D-15 keeps every benchmark-vs-BTC figure hidden (D-19).
- The trust-tier row.
- `FreshnessChip` **and** `SeriesRecencyLine`. Both state one fact from one derivation
  (`resolveSeriesEnd`, 2026-08-26), so they read the same series. `Track record through {date}`
  therefore always prints the native record's last day. The USD series' own span is stated by the
  disclosure line (B).
- `CapacityChip`, which stays `—` with no capacity span and no bar (164.6.6.2 D-21).

Everything below the masthead follows the selected view: the KPI strip, the charts, the
MetricsColumn and every panel. The disclosure block is new and appears only in the USD view.

**5. Benchmark-vs-BTC stays hidden in the USD view (D-15).** A BTC-denominated account's USD series
carries about 1 BTC beta by construction, so these figures would measure the denomination, not the
manager. In the USD view every 164.6.6.2 withholding renders **in the same places and the same DOM as in
the native view**. Only the reason phrase changes per view: the native view keeps `returns are in BTC`,
and the USD view says `returns are converted from BTC`, because a BTC benchmark against a USD series is
not a flat line, so the native view's "flat line" sentence would be false there (checker FLAG 1). The withholdings are:
- no BTC comparator button, and the `BTC not available: returns are in BTC` span;
- no α / IR vs BTC;
- the BTC correlation row and the strategy × BTC cells read `—`;
- the BTC event studies render as `SignatureEmptyPanel`s;
- the Stress Windows BTC column reads `—`.

SPX and every other non-BTC comparison render in the USD view as they do in the native view, over
the USD series (164.6.6.2 D-17).

**6. Never invent a USD number (D-02, D-17).**
- A day with no stored BTC close has no USD value. It shows as a marked chart break, the em-dash, or
  the native amount alone. It is never `0`, a carried value or an interpolated one.
- A live balance is priced only at the latest completed daily close, which is the previous UTC
  day's close. An older close is never used.

**7. Copy claims only what the data guarantees (D-21).** Every conversion sentence says "the stored
daily BTC close". None says `BTC/USDT`. `benchmark_prices` has no source column, and its fallback
source is quoted in BTC/USD.

## B. The USD disclosure block (the conversion explained)

The block renders **only in the USD view**, as the **last child of `<header>`**. It is full-width and
follows the two-column masthead row.

```tsx
<div className="mt-4 flex max-w-3xl flex-col gap-1" data-testid="factsheet-usd-disclosure">
  <p className="text-caption text-text-muted">{disclosureLine}</p>
  {unpricedNote && <p className="text-caption text-text-muted" data-testid="factsheet-usd-unpriced-note">{unpricedNote}</p>}
</div>
```

It sits in the masthead because the ControlBar does not print. A printed USD view must carry the
sentence that says how its figures were made.

**Disclosure line (D-21, D-22, B2).**
- Default: `Shown in USD, converted from BTC at the stored daily BTC close. Priced through {usdEnd}.`
- With a leading price hole: `Shown in USD, converted from BTC at the stored daily BTC close. Priced from {usdStart} through {usdEnd}.`

Terms:
- `{usdEnd}` and `{usdStart}` are the USD series' last and first dates, formatted `Mon D, YYYY` in UTC.
- **A leading price hole** means the USD series starts later than the native series' **second**
  date. The first native day can never carry a USD return, because a return needs a prior close.
  That one-day offset is inherent and is not a hole. Anything later is a hole and must not start
  silently (D-22).
- A trailing gap gets **no extra clause**. The native `Track record through {nativeEnd}` in the
  masthead and `Priced through {usdEnd}` together state both ends.

## C. The curve break (D-06)

An interior BTC-price hole **does not disable the USD view**. The USD view renders a marked break at
each unpriced stretch, plus a note naming the days.

**What is absent.** Native day `d_k`'s USD return needs a stored close on every calendar day in
`[d_{k-1}, d_k]`. This is the existing `convertNativeReturnsToUsd` rule, unchanged. So an unpriced
day removes the return of every native day whose interval contains it:
- If the unpriced day is itself a native day and another native day follows, **both** returns are
  removed: that day's and the next native day's.
- If the unpriced day falls between two native days, only the later one's return is removed.

The note counts the removed returns (`{k}`), so a second drop is never silent.

**Rendering: option (a), a marked break.**
- `usdView.missingSegments` lists each run of absent USD return days as
  `{ start, end, kind: "gap", days }`.
- The frozen `TimeSeriesChart` draws each run on the cumulative track (`segmentMarkers: true`, already
  set). It renders a **6px hatched seam** at the first present point after the run, labelled
  `{days}d — no data`, with the SVG title `No data {start} → {end} ({days} days)`.
- **The line joins the two neighbouring points across the seam.** The absent days are not in `dates`,
  so the run collapses to the seam's x.

What renders is a marked break on a continuous line, not a lifted line, and this spec claims no more
than that.

**Why (a) over (b).** Option (b) would carry null placeholders so the line truly lifts. That needs
interior nulls in the USD series and a change to how the frozen chart island paths a null, which the
Phase-52 git-delta guard reds. Option (a) is better here:
- The seam is the established FS-02 gap idiom on this same chart.
- The joining segment claims no value for an absent day: those dates are absent, the seam sits on the
  join, and the note names them.

Moving to (b) becomes a founder call only if UAT finds the seam unclear.

**Other charts.** The underwater, rolling, histogram and remaining charts get no seam, and their
frozen islands are not edited. The unpriced note covers every figure on the page.

**Metrics.** Every USD figure is computed over the USD returns that exist, that is over priced days
only. The note says so.

**Head and tail.** Covered by the disclosure line (B, D-22). No seam and no note.

## E. The key card balance line (D-07, D-17, first caller of `nativeAmount`)

**Surface.** `AllocatorExchangeManager`, active key row, existing line
`{exchange} · Read-only · Balance …`. The balance renders only on the row `balanceBearers` picks.

**Pricing (D-17).** A native balance is priced at the **latest completed daily close**, which is the
previous UTC day's close, and the label names that close's date.
- If that close is not stored, only the BTC amount shows. An older close is never used.
- The date shown is the **stored date of the close used**, never one computed from the viewer's
  clock. The planner sources it as a field written beside `account_balance_usdt`. Without that field
  the card renders the unpriced form.

| Key state | Balance segment (DOM text; CSS uppercases the line) | `title` on the balance `<span>` |
|-----------|-----------------------------------------------------|---------------------------------|
| USD-family key | ` · Balance {formatUsd(account_balance_usdt)}`, unchanged | none (unchanged) |
| Native key, priced | ` · Balance {nativeAmount(native, unit)} · ≈ {formatUsd(usd)} at {Mon D} close`. Example: ` · Balance 0.4213 BTC · ≈ $26,100 at Oct 8 close` (0.4213 × $61,950.00 = $26,099.54, which `formatUsd` prints as `$26,100`). | `Converted from BTC at the stored daily BTC close for {Mon D, YYYY}.` |
| Native key, latest close not stored | ` · Balance {nativeAmount(native, unit)}`. Example: ` · Balance 0.4213 BTC`. No `≈`, `$`, date or `—`. | `No USD value yet: the latest daily BTC close is not stored.` |
| Native key, no native balance read | ` · Balance —` | none |

Rules for every native state:
- Native comes first because it is the truth (D-01, D-03). The `≈` marks the USD value as derived, and
  that value is in whole dollars (Numbers Contract amounts).
- The segment has its own `<span>`, so the `title` attaches to the balance only.
- A native key with a native balance counts as having a balance even when its USD value is null. An
  unpriced day must not move the balance to a sibling row. The planner pins this.
- `account_balance_native` and `account_currency` come through the D-07 owner-only GRANT migration.
  The migration PR goes first and the code PR after it.

## Accessibility

- **Contrast.** No new pair is introduced.

  | Pair | Ratio |
  |------|-------|
  | muted `#64748B` on white | 4.85:1 |
  | amber `#B45309` on white | 5.05:1 |
  | chip `#4A5568` on `#F1F5F9` | 6.87:1 |
  | dashboard note `#4A5568` on `bg-page` | existing pair |

- **Toggle.** A `role="group"` named `Units`, with `aria-pressed` buttons. A disabled segment uses
  `aria-disabled`, stays focusable and has a visible reason line. Focus is kept on activation. A
  polite live region announces each switch and is silent on mount.
- **Leverage in the USD view.** `aria-disabled` and `readOnly`, still focusable, with a visible reason
  line.
- **Chip.** An sr-only `Returns ` completes the visible abbreviation.
- **No fact lives only in a tooltip.**
  - The key card's priced and unpriced states differ in visible text.
  - The holdings tooltip is duplicated in an sr-only span.
  - The chart seam's meaning is restated in the visible note.
- **Status regions.** The dashboard unpriced-account note is `role="status"`, like
  `DepartedHistoryNote`.
- **Reflow.** Nothing scrolls horizontally at 360, 375 or 390px (supported), or at 320px (extra
  check).
- **Print.** The toggle does not print. The disclosure block prints whenever the USD view is active.
- **Colour.** Colour is never the only signal.
