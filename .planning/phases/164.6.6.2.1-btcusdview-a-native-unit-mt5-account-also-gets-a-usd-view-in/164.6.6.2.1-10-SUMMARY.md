# Phase 164.6.6.2.1 Plan 10: Positions poll and history backfill price a BTC MT5 account Summary

The MT5 positions poll now writes a USD-priced Holdings row (native quantity, stored unit, close as mark) for a BTC account, or leaves it out with a named note, and the history backfill writes per-day USD equity rows for it on priced days only.

## Precondition

Re-run by this executor before any edit, from this worktree with the main checkout as `LINKED_CHECKOUT`: the btcusdview migration commit is an ancestor of `origin/main`, and the catalogue query printed `which_database: PRODUCTION (marker names production),1,1` (marker, GRANT and `quantity_unit` column all present). One earlier attempt of the same command timed out in the CLI and was repeated; it printed the expected line. An earlier dispatch had correctly halted on this gate when PR 1 was not yet merged.

## What was built

- `allocator_positions._fetch_mt5_account_rows`: the `ccy != "USD"` skip became `ccy != "USD" and not unit.native`. For a native unit, after the existing equity extraction and floor, the poll loads `get_btc_closes()` and calls `price_live_balance(1.0, ...)` at the injected clock. Unpriced returns `([], MT5_NATIVE_UNPRICED_NOTE.format(day="Oct 8"))` with an INFO log carrying the unit only. Priced returns the existing row shape with `quantity` = floored native equity, `mark_price` = the close, `value_usd` = quantity x close, `quantity_unit` = `"BTC"`; `raw_payload` still carries the REPORTED equity. `MT5_NATIVE_UNPRICED_NOTE`, `_utc_now()` and a fixed English month table (no `strftime("%b")`, which follows the process locale) were added.
- `equity_reconstruction._mt5_fetch_window` / `_mt5_rows_from_levels`: the native early return is gone. `_mt5_rows_from_levels` takes `native_unit` and `btc_closes`; it forward-fills the NATIVE levels exactly as before, prices them per day with `convert_native_levels_to_usd` (which drops an unpriced day), then clips and builds rows. The unit's floors are passed to `reconstruct_mt5_nav_levels`.

## Deviations from Plan

**1. [Plan premise wrong] `" btc "` is not a skipped currency**
- **Found during:** Task 2
- **Issue:** the plan's behavior block says `" btc "` still skips before any row. The shared classifier (`classify_account_currency`) strips and upper-cases before deciding, so `" btc "` is `BTC`, in the poll, the derive and the backfill alike.
- **Fix:** `" btc "` was dropped from the skip parametrize and added to the BTC priced parametrize instead. `EUR`, `ETH` and `b!tc` still skip.
- **Files modified:** `analytics-service/tests/test_equity_reconstruction.py`
- **Verification:** the priced case passes for both spellings.

**2. [Rule 2 - missing critical] unit floors forwarded to the backfill reconstruction**
- **Found during:** Task 2
- **Issue:** with the default `USD_FLOORS` a BTC level would be judged against the $1000 dust floor in the NAV quality meta, flagging every day. `reconstruct_mt5_nav_levels` already takes `floors=`.
- **Fix:** pass `floors=_unit.floors`; for USD-family accounts this is `USD_FLOORS`, the old default, so USD output is unchanged.
- **Files modified:** `analytics-service/services/equity_reconstruction.py`
