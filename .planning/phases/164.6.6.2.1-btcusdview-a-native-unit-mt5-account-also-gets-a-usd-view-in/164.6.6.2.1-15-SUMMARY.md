## Deviations from Plan

**1. [Rule 1 - Bug avoided] "Native key" definition.** The plan says a native key with a null native balance reads `Balance —`, and also that a USD-family key (`account_currency` `"USD"`, native null) is byte-identical to today. `parseReturnsUnit("USD")` is set, so the two cannot be separated by the unit alone, and the worker (`_persist_account_unit`) stores a USD-family code ONLY and writes `account_balance_native` only for a native account (nulling `account_balance_usdt` in the same statement). I therefore keyed "native" on (well-formed code AND non-null native balance). Every other key renders today's expression, which reads `Balance —` while `account_balance_usdt` is null. Known limit: a native-code key with a null native balance AND a non-null legacy `account_balance_usdt` would show that dollar figure; the worker clears it, so this is unreachable in the written states. Kept out of a client-side copy of the Python `USD_FAMILY` set on purpose (a second list to drift).
- Files: `src/components/exchanges/AllocatorExchangeManager.tsx`; pinned by the USD-family `it.each` (USD, null, malformed lower-case code) in the native-balance test. Commit 928319be8.

**2. [Rule 3 - Blocking] USD-family line has no wrapper span.** Existing pins do `getByText(/Read-only · Balance/)`, which matches the paragraph's own text nodes; wrapping every balance in a span would have broken them. Only native states get the span (the plan's "own span" rule is for the native states). Commit 928319be8.

**3. Test-expectation correction (no behaviour change).** My first draft of the "missing field is rejected" arm included `account_balance_native`; it is accepted when absent because it shares `_strictNumberOrStringNumericNullable` with `account_balance_usdt`, which reads an absent key as null. I left the shared helper alone and dropped that field from the arm, with a comment. Commit 50c5ab285.
