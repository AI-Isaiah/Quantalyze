## The continuation contract (planner decision; it refines RESEARCH Code Example A, read why)

- A SEGMENT is today's cursor walk on `[w_start, end]`: at most `_BYBIT_WINDOW_PAGE_CEILING` pages, the first page sent
  with no cursor. The constant keeps its name and value (100): plan 01's probe reads it.
- The window ends normally on an empty page, or on a page with no cursor (the existing full-page-no-cursor WARNING is
  kept and still does not refuse).
- A page fetched WITH a cursor is a stalled page, and ends the segment, when it returns the cursor it was sent, or when
  it adds no new id although it holds at least one row OLDER than the oldest timestamp the window had read before this
  segment began (in the first segment of a window: any row). A page that adds nothing while every row sits at or above
  that boundary is NOT stalled. Reason (this is where it differs from Code Example A, whose "added == 0 -> stalled" would
  refuse a readable window): the first pages of a continuation segment re-read the overlap at the old boundary BY DESIGN
  (an inclusive endTime, or a same-millisecond group cut by the previous segment), so "added nothing" is expected there
  and only there. In a window's first segment the rule is exactly today's deployed stall check, so no loudness is lost.
  A venue that answers old rows under new cursors forever is still bounded by the page ceiling and the strict-lowering
  rule below.
- When a segment ends without the window ending, let `oldest` be the oldest timestamp read in this window so far:
  (1) if `oldest + 1` is strictly below the current end, start a new cursor-less segment on `[w_start, oldest + 1]`
  (one past is safe under an inclusive or an exclusive endTime; dedupe absorbs the re-read rows);
  (2) else, ONCE per value of `oldest`, if the segment that just ended returned at least one row newer than `oldest`
  (proof that the venue's endTime is inclusive, so the rows at `oldest + 1` took segment capacity), start a new segment
  on `[w_start, oldest]` (no +1) — the OKX walk's own one-time retry, for the same reason; under an exclusive endTime that
  segment would skip the rest of a group at `oldest`, which is why the inclusive-end proof is required first;
  (3) else one counts-only WARNING ("bybit trade window stopped on a page that did not advance", venue,
  `window_age_days`, `page_rows`, `rows`: the existing wording, so the existing tests' `"100"` and venue assertions hold)
  and `TruncatedTradeRead(_TRUNCATED_READ_MESSAGE, site="bybit_no_advance")`.
- More than `_BYBIT_WINDOW_SEGMENT_CEILING` segments in one window: one counts-only WARNING ("bybit trade window hit the
  segment ceiling", venue, `window_age_days`, `segments`, `rows`) and `site="bybit_segment_ceiling"`. Value 100 (about
  10^6 rows per 7-day window; RESEARCH section 3).
- NotSupported after any row was read in the walk: `site="bybit_not_supported"` (behaviour unchanged).
- What it cannot pass, by design: more than one segment's rows (100 pages x 100) at ONE millisecond. That stays the loud
  `bybit_no_advance` stop.
- `TRUNCATED_READ_SITES: Final[frozenset[str]]` = the nine tokens `bybit_not_supported`, `bybit_no_advance`,
  `bybit_segment_ceiling`, `okx_not_supported`, `okx_no_advance`, `okx_page_ceiling`, `generic_not_supported`,
  `generic_no_advance`, `generic_page_ceiling`. Plan 01's probe declares the same nine names; plan 10 pins the two
  together.
