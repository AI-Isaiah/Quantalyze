Build the store a resumable Bybit read keeps its progress in (D-02), as a self-contained module with no import of
`services.job_worker` or `services.equity_reconstruction` (no cycle; the scope type lives here). Plans 07 to 10 wire it
into the read and the handler; this plan proves the store on its own against the repo's fake client.

Claude's discretion from CONTEXT, decided here (the migration in plan 03 carries the same decisions as TR-1..TR-6):
- What is persisted: raw compact trades per complete window, not fold state (RESEARCH section 1: fold state would split
  the 430-line replay and reorder float additions).
- How the two-year edge and the moving `now` are pinned: only the grid ORIGIN is pinned (the first claim's start);
  `now` is not pinned, the window containing it is never stored (plan 07), so a trade made after the first claim is read
  by the claim that finishes, as in a single pass.
- Expiry: 7 days, written per row, purged opportunistically.
- How a job that keeps making no progress is stopped by name: the pessimistic stalled-claims counter (a claim killed by
  the hard bound or a watchdog counts as stalled too) plus the 24 h job-age backstop; a new job starts with a fresh
  count and the stored windows, so the stop is a reason a later run can clear.

Purpose: SC-1 (the resumable half). Output: the store module, its tests, and one fake-client fix.

## The module contract (names are load-bearing: plans 07 to 11 call them)

- Constants: `TRADE_READ_VERSION: Final[int] = 1` (bumped by any change to the projection's column order or to what the
  Bybit read covers; Phase 173 will bump it), `STORE_EXPIRY_S = 7 * 24 * 3600`, `STORE_CHUNK_TRADES = 5000` (equal to the
  migration's count CHECK), `STALLED_CLAIMS_LIMIT = 3`, `JOB_BACKSTOP_S = 24 * 3600`, `STATE_TABLE =
  "allocator_trade_reads"`, `WINDOW_TABLE = "allocator_trade_read_windows"`, `STATE_COLUMNS` and `WINDOW_COLUMNS` (tuples
  of the migration's column names), `PROJECTION_FIELDS = ("timestamp", "symbol", "side", "amount", "price", "cost",
  "fee")` (documents the positional order).
- `project_trade(trade) -> list[Any]` and `unproject_trade(row) -> dict[str, Any]`: positional
  `[timestamp_ms:int, symbol, side, amount, price, cost, fee_cost]`; `fee_cost` is `fee.get("cost") or 0.0` when `fee` is a
  dict (exactly the replay's own reduction in `_compute_daily_equity`), else `fee` unchanged; the dict built back has the
  seven `PROJECTION_FIELDS` keys only. `unproject_trade` raises ValueError on a row that is not a 7-element list with an
  int timestamp and str-or-None symbol and side. A projection holding a non-finite float makes the window NOT storable.
- `@dataclass(frozen=True) WindowMeta(window_start_ms, window_end_ms, chunk_count, n_trades)`; `@dataclass ReadState(
  grid_origin_ms, stored: dict[int, WindowMeta], claims, stalled_claims)`.
- `async begin_claim(supabase, api_key_id, *, venue, since_ms, job_id) -> ReadState | None` (the bookkeeping in the must-haves;
  it also calls `purge_expired` once, best-effort; it loads window METADATA only, never the trades column, paging with
  `.range()` in pages of `_META_PAGE_ROWS` (500) until a short page so a PostgREST row cap cannot truncate it; only whole,
  current windows enter `stored`).
- `async load_window(supabase, api_key_id, meta) -> list[dict[str, Any]] | None` (fetches that window's chunks, checks the
  chunk set and the per-chunk counts, unprojects in chunk order; None on any defect, with one counts-only WARNING).
- `async save_window(supabase, api_key_id, window_start_ms, window_end_ms, trades) -> bool` (projects, refuses a
  non-finite value by returning False with one counts-only WARNING; deletes the window's existing rows first so a
  re-read with fewer chunks leaves no stale chunk; then upserts each chunk on `api_key_id,window_start_ms,chunk_index`
  in its own request; returns True when every chunk was written).
- `async record_progress(supabase, api_key_id) -> None` (stalled_claims = 0, updated_at now).
- `async purge_keys(supabase, api_key_ids) -> None` and `async purge_expired(supabase) -> None` (both tables; best-effort).
- Store-fault disposition (one rule for every public store call; it is what makes deploy order and a failing gateway
  harmless): an exception raised by the client inside `begin_claim`, `load_window`, `save_window`, `record_progress`,
  `purge_keys` or `purge_expired` is caught as `Exception` (so `asyncio.CancelledError` still propagates), logged once at
  WARNING with its class name and the key id only (`trade read store unavailable (<class>) key=<id>: ...`, the tail
  naming what happens next), and answered: `begin_claim` -> None ("this claim reads without the store"), `load_window`
  -> None (the window is re-read), `save_window` -> False (the window stays unstored; its trades stay in the claim),
  `record_progress` / the purges -> return normally. `TradeReadStalled` from `begin_claim` is a decision, not a fault,
  and always propagates. Consequence to state in the docstring: a store that answers `begin_claim` but refuses every
  write makes no progress, so the job ends at the named stall after `STALLED_CLAIMS_LIMIT` claims, never in an endless
  defer loop.
- `class TradeReadDeferred(Exception)` with `windows_done`, `windows_total`, `trades_stored` and a static message built
  from those counts; `class TradeReadStalled(Exception)` with `cause` ("stalled_claims" | "job_age") and `claims`, static
  message. Neither subclasses a ccxt class.
- `@dataclass(frozen=True) TradeReadScope(supabase, api_key_id: str | None, deadline: float, job_id: str | None,
  job_created_at: Any)`; `trade_read_scope(scope)` context manager (set, yield, reset with the token);
  `current_trade_read_scope() -> TradeReadScope | None`; `claim_deadline(budget_s) -> float`; `deadline_passed(scope) ->
  bool`; `job_too_old(scope) -> bool`; the seams `_monotonic = time.monotonic` and `_wall_ms()`.
- Every database call goes through `services.db.db_execute` with a local closure and `services.db.rows` (the house idiom).
