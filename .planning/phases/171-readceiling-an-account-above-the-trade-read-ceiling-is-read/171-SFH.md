## Round-1 findings

- S-1 FIXED. `_read_bybit_window` returns a bool: False on the full-page-no-cursor exit
  (`:788-793`) and on the short stalled exit (`:800-801`), True on every other normal exit. The
  caller saves only `if storable and complete and await store.save_window(...)` (`:1008`). An
  uncertain window is still read live, still enters this claim's output, and is never frozen
  for later claims. The empty-continuation case (WR-01) takes the existing `bybit_no_advance`
  refusal (the `empty_continuation` guard on both `elif` arms falls to the raise), so it is loud.
- S-2 FIXED. In the `state is None` branch, a `TruncatedTradeRead` becomes `ccxt.RequestTimeout`
  with static text (`:960-967`). `classify_exception` maps `RequestTimeout` to transient
  (`job_worker.py:1171-1178`). Observable: the forced crawl logs
  `account crawl failed ... exc_class=RequestTimeout` (`equity_reconstruction.py:5735-5741`) and
  re-raises `_AccountCrawlRetryableError`; the job row carries the static message; `begin_claim`
  already logged its own WARNING. Bounded: transient errors consume `attempts` against
  `max_attempts` (default 3, `job_worker.py:15419-15445`), so a persistent store defect ends as a
  FAILED job after three tries, not a loop. Small reads that finish under layer 1 are unaffected.
  Residual (below the bar): when the store is down AND the venue truncation is genuine (the
  single-millisecond case), the job retries three times and ends with the store-blaming text.
  Loud and bounded, so not a finding.

## R2-1 (MEDIUM, data integrity) - the short stalled exit ends the window with no log, and its rows reach the DONE write

- Where: `analytics-service/services/equity_reconstruction.py:795-801`
  (`if len(page) < _TRADE_PAGE_LIMIT: return False`).
- Scenario: a page fetched WITH a cursor returns the cursor it was sent (or adds no new row while
  holding an older stamp), and is shorter than 100 rows. The window ends there and returns False.
  Unlike the sibling uncertain exit just above it (`:779-787`, full page with no cursor, one
  WARNING), this exit logs nothing. The venue claimed more rows existed (it handed back a cursor),
  yet the window stops. The rows read are placed in `fresh`, converted to `window`, appended to
  `output`, and the replay builds the allocator history from the union. S-1 stops the window
  being stored, which fixes the repeat-reuse problem. It does not stop this claim's output being
  a possibly partial list that is written as the whole rebuild.
- Baseline note: this restores the TRADEPAGES D-02 stop, so it matches the pre-phase silent
  behavior and is a deliberate decision, not a regression. It is reported because the phase
  itself now names the exit "UNCERTAIN" in the docstring (`:733-737`) and logs the other
  uncertain exit, so the only uncertain stop that the operator cannot see is this one. A
  truncation from here can never be told apart from a clean read in Sentry or the logs.
- Impact: a wrong or short allocator equity history, persisted, with no signal. Rare (needs a
  venue cursor quirk) but silent when it happens.
- Minimal fix: one counts-only WARNING before the `return False`, same shape as the existing one
  (no venue text, no ids):
  ```python
  logger.warning(
      "bybit trade window ended on a page that did not advance "
      "venue=bybit window_age_days=%d page_rows=%d rows=%d",
      age_days, len(page), len(trades),
  )
  return False
  ```
  Do not turn it into a refusal: that would reverse the D-02 decision. A test can assert the
  WARNING via `caplog` next to the existing short-stalled test in `test_trade_pages.py`.

## Noted, below the reporting bar (loud, not silent)

- A window that is deterministically uncertain (for example a final page of exactly 100 rows with
  no cursor) is now never stored. It is re-read live on every claim, and if reading it consumes
  the whole budget no `record_progress` happens in that claim, so three such claims end in the
  named `TradeReadStalled` stop. This is loud and fail-closed (nothing written), and needs a
  window whose read alone exceeds the budget; it can only strand an account, never write wrong
  data.
- `TruncatedTradeRead` raised inside the S-2 conversion drops its typed `site` (`from None`).
  The window code logs a counts-only WARNING for `bybit_no_advance` and `bybit_segment_ceiling`
  but none for `bybit_not_supported`, so that one site leaves only the converted
  `RequestTimeout` in the trail.
