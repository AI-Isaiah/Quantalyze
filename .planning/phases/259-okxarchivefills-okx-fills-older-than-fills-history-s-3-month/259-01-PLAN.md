Facts read from the live loop body (cite by symbol, never by line; Phase 256 is moving lines in this file):
- The stored `timestamp` is `datetime.fromtimestamp(int(ts_raw) / 1000, tz=timezone.utc).isoformat()` with `ts_raw = fill.get("ts", "")`. `fillTime` is never read.
- Linear SWAP/FUTURES (settle in the inline tuple `("USDT", "USDC", "BUSD", "USDE", "PYUSD", "USDB")`) multiply `fillSz` by `Decimal(str(_okx_contract_size_for_inst_id(raw_inst_id, exchange)))` and stamp `fill.setdefault("_ingest_ctval", _ct)` only when `_ct != 1.0`; inverse settle and SPOT/MARGIN keep `fillSz`.
- `raw_data = dict(fill)` is taken AFTER the setdefault; `posSide` is kept when in `_OKX_VALID_POS_SIDES`; `position_direction` is `long`/`short` only when `posSide` is not `net`.
- `_make_fill_dict` trims `raw_data` through `_trim_raw_data` unless `_STORE_FULL_RAW_DATA` (env `EXCHANGE_STORE_RAW_DATA=1`, read at import). The golden pins it False with monkeypatch.
- `_okx_contract_size_for_inst_id` falls back to `exchange.markets` when the prefix is not in `_OKX_INGEST_CONTRACT_SIZE`. An `AsyncMock` exchange answers every attribute (its `markets.get(...)` returns a coroutine), so the golden uses a plain fake exchange object with `markets = {}` and an async `private_get_trade_fills_history`.

Hand-typed instants used by the golden (verified with Python at planning time; never computed by the code under test):
- 1782907200123 = 2026-07-01T12:00:00.123Z (`ts`), with `fillTime` 1782907200122 (one ms earlier, as in the OKX docs example) so a helper that read `fillTime` would fail the timestamp arm.
