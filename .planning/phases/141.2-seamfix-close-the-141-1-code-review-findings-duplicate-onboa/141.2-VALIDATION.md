# Phase 141.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

**Why this file is unusually strict here.** This phase repairs a phase whose own review found
a pin that could not fail (finding 13) and a regression test that stayed green because it
exercised the read path while the defect was on the write path (finding 10). Both were
*present* and *passing*. Coverage was never the problem — falsifiability was. Every row below
therefore has to answer "can this fail?", and the answer must be a pasted RED, not a claim.

**SC-L reconciliation (revision r2):** the original row read "omit the idempotency argument at
one caller". That mutation is NOT type-expressible — `PostProcessKeyArgs.context` is a
REQUIRED field (`process-key-client.ts:320`), so the omission cannot compile through the real
call site. Plan 05 records the decision that `context` STAYS required (the compile-time layer
is the stronger guarantee; the helper's undefined-arm default is the runtime belt behind it).
The row above is the mutation that IS performable, and it pins that belt directly at the
helper. It is no longer claimed that the omission mutation runs through `postProcessKey`.

*Rules:*
- **Observed means run.** Paste the failing assertion. "The test covers it" is not evidence.
- **A skipped mutation is recorded as skipped, never as caught.**
- **Prefer the second member of a class.** Finding 10's lesson is sharper: prefer the *path* the
  author did not have in mind.

## Oracle Independence

- [x] No test imports a **constant** from the module it tests — expected values are **literals**.
      Verified at close of phase: the one violation (below) is DELETED. Two derived left-hand
      sides survive in `seam-constants.pin.test.ts` and both are legitimate under the stated
      rule, because each composes **two independently-pinned** constants so the sides can
      genuinely disagree: `SEAM_RETRY_BACKOFF_MS + SEAM_RETRY_JITTER_MAX_MS` (a compensating
      300+200 edit reddens it while both individual pins stay green) and the A-25/A-14
      relational pins. Arithmetic over a SINGLE already-pinned constant is the shape that
      cannot fail, and there is none left.
- [x] No assertion compares a value to itself via a re-export, fixture, or table under test.
      `BUDGET_TABLE` is a widened VIEW used for hand-typed key lookup; every expectation is a
      literal from `EXPECTED_TIMEOUT_MS` / `EXPECTED_RETRIES`, typed in the test file.
- [x] Registry sizes pinned to a **literal count**, not `len(THE_TABLE)` — and, since plan 02,
      per-map as well as in total (`1 + 4 + 3 + 5`), which is what SC-E proved necessary: the
      total-only fence stayed green across the D-03 map move while its own message went false.
- [x] Any fake/double is pinned against the real contract it stands in for — `FAKE_THRESHOLD`
      / `FAKE_WINDOW_MS` are hand-typed in `src/test/helpers/upstash-breaker.ts` and pinned
      literal-against-literal here; the flag-monitor doubles are index-simulating and
      per-test configurable in their row payloads (plan 03).

✅ **Known violation FIXED, not inherited (plan 06):** `seam-constants.pin.test.ts:560` asserted
`Math.ceil(BREAKER_FAILURE_THRESHOLD / 2) === 3` — arithmetic over a constant the preceding test
pins to 5, so it cannot fail (finding 13). **It is DELETED, not replaced** — the behaviour it
claimed to defend is genuinely covered at `resilient-fetch.retry.test.ts:1092-1109`, so a
replacement would be a second copy of an existing test rather than new coverage. If a future
change does add one, it must not import the threshold to compute its own expectation.

⚠️ **The flag-monitor fetch doubles are URL-blind** — the whole suite would pass against a
permanently dead query, which is how the original defect survived. Any new denominator test must
