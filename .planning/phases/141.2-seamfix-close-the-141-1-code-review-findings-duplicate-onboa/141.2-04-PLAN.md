<objective>
Close finding 9: `hasContractualWait` returns true for ANY non-null `Retry-After` on a 503,
so `Retry-After: 0` — which RFC 9110 says means "retry now" — and an empty value both DISABLE
the retry, returning attempt 1's 503 to the user for exactly the transient blip the retry was
added to absorb. D-06: parse the value; treat it as a contractual wait only if it parses to a
positive number. Zero, empty, and unparseable all fall through to the normal backoff.

value; the Railway platform edge is the sole remaining candidate and is [ASSUMED], unverified.

verifies the responder is bound by — but no prose may claim the concrete trigger is observed.
