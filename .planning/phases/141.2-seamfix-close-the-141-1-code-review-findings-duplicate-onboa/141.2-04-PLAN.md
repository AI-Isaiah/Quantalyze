<objective>
Close finding 9: `hasContractualWait` returns true for ANY non-null `Retry-After` on a 503,
so `Retry-After: 0` — which RFC 9110 says means "retry now" — and an empty value both DISABLE
the retry, returning attempt 1's 503 to the user for exactly the transient blip the retry was
added to absorb. D-06: parse the value; treat it as a contractual wait only if it parses to a
strictly positive wait. Zero, empty, and unparseable all fall through to the normal backoff.

RULE 7 CONFLICT, RESOLVED — do not re-open it at execution time. Two source artifacts
disagree on the fix shape:
- RESEARCH §4.4 and its finding-9 Code Example say hand-roll the parse
  (`Number(raw.trim())` + `Number.isInteger(seconds) && seconds > 0`) and never mention that
  a shared parser exists.
- PATTERNS names `src/lib/retry/retry-after.ts` `parseRetryAfterSeconds` as the EXACT
  in-repo analog: the B20 shared parser, already consumed at 10+ sites including the seam
  route `keys/[id]/permissions/route.ts`, whose own docblock declares it "the single
  by-construction guard for that whole class".
RESOLUTION: REUSE `parseRetryAfterSeconds`. Its contract — strictly positive seconds or
`null`, never NaN/0/negative — is exactly D-06's requirement; it already handles the
delta-seconds form, the RFC 9110 HTTP-date form (resolved against the response's OWN `Date`
header, so a skewed client clock cannot distort it), and a defensively-missing `headers.get`.
An HTTP-date `Retry-After` is still a contractual wait — treating it as one is CORRECT, not a
gap to enshrine in prose. Hand-rolling a second parser would fork the class guard the helper
exists to centralise (Rule 7: pick the more tested pattern, don't blend; the researcher
simply missed the helper). The plan-checker ratified this resolution.

Honesty constraint (RESEARCH §4, OQ-5 answered): the repo's only contract-bound 503 emitter
(`error_contract._validate`) raises on `retry_after <= 0`, so it CANNOT produce the bad
value; the Railway platform edge is the sole remaining candidate and is [ASSUMED], unverified.
The fix is correct as a code-shape repair regardless — the check asserts a contract it never
verifies the responder is bound by — but no prose may claim the concrete trigger is observed.
