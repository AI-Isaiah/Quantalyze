- **D-03 (2026-09-25, orchestrator, ratifying research A3; reversible).** One new leaf module,

  `corrwith` restricted to dispersing columns), so the class has one implementation.
- **D-07 (2026-09-25, planner discretion; reversible).** The test invariant for every fixed site is:
  a compounding-NAV constant yield produces EXACTLY the output that an exactly-constant (all-zero)
  series of the same length produces today at that site. That makes each fix a statement about
  economics (no dispersion means no ratio), not about the implementation. A cent-rounded NAV (real
  quantisation dispersion) is the control on the other side of the floor, so widening the floor goes
  red. Because every fixed site then emits only an output shape it already emits for an exactly
  constant input, no new shape reaches any TS reader.
  ⛔ **AMENDED 2026-09-26 by founder decision D7 (AskUserQuestion, "Show — everywhere"; the sentence
  above is kept as lineage and is superseded FOR DISPLAY).** The test invariant stands: a
  compounding-NAV constant yield still produces EXACTLY what an all-zero series produces at every
  site. What changed is the value both produce when the ratio does not exist. D-07 had each site map
  `null` to "the value it already emits for an exact constant", which was `0` at eight sites and put
  "Sharpe 0.00", "Correlation 0.00" and "Beta 0.00" on screen while a sibling surface (the OG card,
  DistributionPanels, the /compare matrix) showed "—" for the same series. Under D7 a statistic that
  does not exist STAYS EMPTY END TO END (null, NaN in a `number` field, a missing matrix cell, or a
  gap in a rolling series) and renders "—" or a gap on every page, never 0.00 and never "unchanged".
  Constant-yield and all-zero series read the same, and every page agrees. See D-24 for the sites.

### Founder direction (2026-09-25): compute once, read it everywhere

- **D-17 (2026-09-25, FOUNDER DIRECTION, verbatim: "Why don't you calculate Sharpe once and the 20
  places all read it from there?"; relayed by the orchestrator; reversible per site: each site's edit
  is one function body).** The TS half (T1-T20) is restructured around computing each figure ONCE,
  instead of pasting the floor guard into twenty local copies of the same formula. D-15's "every TS
  site gets the SAME floor from ONE module" stands; what changes is that the per-site FORMULAS go too.
  Every site is classified, from the code at `7bfce8490`, into:
  - **Tier 1**: the site recomputes a figure the analytics service already persists for the SAME
    series (`strategy_analytics` columns, `metrics_json`, `portfolio_analytics`). Remedy: delete the
    local computation and read the persisted value; a null renders the existing honest absence. No
    floor guard is needed there, because the Python side already has it (Phase 166, plans 01 and 03).
  - **Tier 2**: the series exists only on the TS side at that moment (a what-if blend, a user's pick
    of strategies, a resample, a per-key book the persisted rows do not describe, a comparator over its
    covered span). Remedy: ONE shared module that every Tier-2 site calls, and the per-site formula is
    removed.
  - **Dead**: the function has no production caller (measured by grep over `src/`, tests excluded).
    Remedy: delete it with its tests. A formula nobody reads is a second copy waiting to be reused.

  **The shared module (planner discretion within D-17, recorded).** `src/lib/return-stats.ts`, a new
  file, holds Phase 166's floor (`DISPERSION_RESIDUE_REL`, `residueFloor`, `dispersionIsResidue`,
  `dispersionIsReal`, the Python rule verbatim and pinned to the Python constant by a test) AND the
  ratio functions every Tier-2 site calls: `dispersion(xs, ddof)` returning the mean and an sd that is
  exactly 0 when the dispersion is residue (the D-07 invariant stated once: no dispersion means the
  value an exact constant gives), `sharpe`, `pearson` and `beta`. It builds on the repo's existing
  primitives `mean` and `stdDev` in `src/lib/portfolio-math-utils.ts` rather than adding a third mean,
  so there is one mean, one sd, one Sharpe, one correlation and one beta. The name is not
  `dispersion-floor.ts` (the orchestrator's example) because the module now holds the ratios, not only
  the floor. The arithmetic order of each shared function is the one the factsheet already uses
  (`compute.ts` for the Sharpe; the sums form of `build-payload.ts` `pearsonCorr` for the
  correlation), so the factsheet snapshot, which rounds every number to 12 significant digits, cannot
  move; a site whose unrounded value moves in a pinned test is a STOP-and-report, never a snapshot or
  golden update.
  ⚠️ **Two arithmetic consequences, recorded 2026-09-26 (plan-check round 3, I3).** (a) `jointMetrics`'
  information ratio moves to `sharpe(active)` over `active[i] = rets[i] - bench[i]`, and its tracking
  error to `dispersion(active, 0).sd * Math.sqrt(periodsPerYear)`. Today both are built from
  `mean(rets) - mean(bench)`; the shared path takes `mean(active)`, a DIFFERENT summation, so the
  values agree to rounding, not bitwise. The snapshot rounds to 12 significant digits, and plan 06b's
  test `T16 info_ratio and tracking_error move to the active series` pins the noisy-input values to
  12 significant digits of today's formula (a larger move is a STOP). (b) `sharpe()` returns null on
  any non-finite input. Every adopting site answers null with the value it emits today for a
  degenerate input, so `compute` still reports a Sharpe of 0 for a series holding a NaN (today's
  `s > 0` is false on a NaN `s`, which also gives 0), and `computeOgHeadline` still reports NaN. Plan
  06a's test `T13 non-finite input keeps today's sharpe` pins the `compute` case, computed against a
  series holding one NaN, so a later change to the null mapping goes red.
