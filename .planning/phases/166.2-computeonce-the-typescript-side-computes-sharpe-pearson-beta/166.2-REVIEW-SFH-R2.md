## (b) New silent failures introduced by the fix pass

### SFH-R2-H1 (HIGH, NEW, caused by the fix pass): the Rolling Metrics "Now" column shows a stale Sharpe as current

- **Location:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx` `rollingStats`, the `current` field
  ("most recent non-null"), rendered by `RollingMetricsPanel` / `RollingRow` in the "Now" column.
  The fix that exposed it is `src/lib/factsheet/rolling.ts` `rollingSharpe`, where `?? 0` was
  dropped (SFH-M1).
- **Precondition broken:** `rollingStats` was written when the only nulls in a rolling array were
  the LEADING warm-up nulls. It walks backward to the first finite value and labels that value
  "Now". Since the fix pass, `rollingSharpe` also returns null for a TRAILING window with no
  dispersion. The walk steps over that window and reports an older one as "Now".
- **Measured (probe):** 300 active days, then 200 zero days, window 126, P = 365.
  `rollingSharpe`'s last finite value sits at index 424 of 499 and equals **1.7088**. The
  `rollingSortino` "Now" is `0`, and the `rollingVol` "Now" is `0`. The page would read:
  **Sharpe Now 1.71 · Sortino Now 0.00 · Vol Now 0.0%**.
- **Why the number is an artifact:** the last window that still has a Sharpe holds one non-zero
  return among 125 zeros. Its Sharpe is exactly `sign(r) · √P / √(w − 1)`: ±1.71 at w = 126 and
  P = 365, ±1.41 at P = 252, and ±3.55 at the 30-day fallback window. The magnitude says nothing
  about the strategy, and the sign is the sign of its last trade.
- **User impact:** the rolling panel appears on the public factsheet. A strategy that has been flat
  for its last rolling window shows a confident current Sharpe that is 75+ days stale, next to a
  0.0% current volatility. Before the fix pass the cell read 0.00, which D7 also forbids but which
  was not stale. The fix pass swapped one wrong value for a more convincing wrong value. The rolling
  CHART is correct: it shows a gap. Only the summary table's "Now" substitutes.
- **Reach:** any series whose last `window` returns are identical. That covers a dormant strategy
  that reports 0 on inactive days, and a book whose final months are a constant yield. When every
  window is null (a whole-life constant yield), `current` is null and the row reads "—" correctly.
- **Class check:** I grepped `src/app/factsheet`, `src/lib/factsheet` and `src/components/strategy-v2`
  for other "latest value" readers of rolling arrays (`[length - 1]`, `.at(-1)`, `findLast`,
  "latest", "current"). This is the only one. `TimeSeriesChart`'s avg reference line and regime
  segmentation both skip non-finite values and need no change (the regime tail is LOW-3).
- **Lineage:** round 1's SFH-M1 recommended dropping `?? 0` without checking this consumer. That
  omission belongs to the round-1 report, and a confirmation round exists to catch this kind of
  miss.
- **Recommendation:** "Now" is the LAST element, not the last finite one.

```ts
// rollingStats: "Now" is the current window; a current window with no ratio is "—".
const last = arr.length > 0 ? arr[arr.length - 1] : null;
const current = last != null && Number.isFinite(last) ? last : null;
// min / max / avg keep skipping non-finite values, as today.
```

  Add a case to the existing rolling-panel test: an active series with a trailing flat window.
  "Now" must read "—" and must not read the stale value. Show it RED under the current walk.

### Checked and cleared (no new HIGH or CRITICAL)

- **NaN into JSON.** The factsheet payload is cached through `unstable_cache`, so a NaN
  becomes `null`. Every renderer I read tests `v == null || !Number.isFinite(v)` before
  formatting: `MetricsColumn` `num`, `pct`, `pctNeg`, `signed`; `format.ts` `pctSigned`;
  `AnalyticalPanels` `num`, `pctSigned`; `BatchDPanels` `fmt`, `fmtDelta`, `signed`, `DeltaRow`,
  `PercentileBar`; `BootHist` `show`; and the KPI-strip `signTone`. A `null` never reaches
  arithmetic. `fmtDelta` returns "—" before it computes `b - a`.
- **Sorting or ranking on NaN.** `computePeerPercentile` no longer ranks a NaN Sharpe. No changed
  site sorts a ratio.
- **`buildAllocatorMetrics` throw.** The throw is latent: every caller passes `blend(...)` over
  `alignReturns(X, dates)` legs and `stratRet`, and all of these are the length of `dates` by
  construction. It cannot escape to the page today.
- **allocator cross term.** `crossCorr = 0` is exact only when `corr` is null because a leg has no
  dispersion. `pearson` and `dispersion` share the floor, so that leg's `annVol` is exactly 0 and
  the dropped term was 0. A NaN leg makes `annVol` NaN, and the scan never selects NaN. That
  behaviour predates the fix pass.
- **`computeScenario` `dispersion(portDaily, 1)`.** It is guarded by the `n < 10` early return, so
  the `stdDev` n < 2 branch is unreachable. The average is `null` when no pair is measured, and
  every consumer (`KpiStrip`, `CorrelationHeatmap`, the scenario-share page, `queries.ts` `avgRho`)
  already handles `null`. The missing matrix cells are handled by `clusterOrder` (distance 1),
  `tooSimilarPairs` (skip), the composer's reordered-matrix copy (skip) and the heatmap ("—").
- **`computeAlphaBeta` null.** `tsc` enforces the null at both callers.
  `computeScenarioBenchmark` passes it through, `ScenarioBenchmarkSection` renders it with
  `formatNumber`, `computeScenarioStress` maps a null β to a null impact, and
  `AlphaBetaDecomposition` renders its "—" branch.
- **`percentContributionToRisk`.** A NaN `portVar` becomes NaN after `Math.max(NaN, 0)` and
  `sqrt`, `dispersionIsReal` reads that as false, and the function returns null. There is no NaN
  path to the screen.
- **`scenario-stress` `computeVarPath`.** A NaN sd gives `NaN !== 0`, which matches the old
  `dispersionIsResidue(NaN)` false, and the finite guard runs earlier anyway. The behaviour is
  unchanged.
- **No remaining `?? 0` on a shared result.** A grep for `pearson|sharpe|beta|betaOf|sharpeRatio|
  dispersion(...) ?? 0` over non-test `src/` returns 0 hits.
- **Tests that cannot fail.** None found. The merge-base pin in `return-stats.single-source.test.ts`
  re-throws when the base commit is unreachable and never skips. The page-agreement test has a
  dispersing control. The residue and leverage tests now assert real values: Test C asserts a
  real beta first.

## (c) D7 residues: a 0 for a statistic that does not exist, on a rendered page

### SFH-R2-H2 (HIGH, pre-existing, and half-fixed by the pass): Sortino and Calmar render 0.00 for a ratio that does not exist, and the peer panel ranks it 5th

- **Location:** `src/lib/factsheet/compute.ts` `compute` (Sortino `ddDev > 0 ? … : 0`, Calmar
  `maxDd !== 0 ? … : 0`); `src/lib/factsheet/bootstrap.ts` `headlineStats` (Sortino
  `downDev > 0 ? … : 0`); `src/lib/factsheet/peer-cohort.ts` `computePeerPercentile` (the Sortino
  rank has no finite guard). The values render in the KPI strip, the Main Metrics column, the
  bootstrap panel and the peer `PercentileBar`.
- **Measured (probe):**
  - Constant yield: `sharpe NaN · sortino 0 · calmar 0`, with `cagr 0.0760` and `max_dd 0`. The
    bootstrap Sortino is `point 0, lo 0, hi 0, 0 bins`, which `BootHist` renders as "no variance ·
    all resamples produced 0.00". The peer ranks are Sharpe `NaN`, **Sortino 5**, Max DD 100.
  - All-positive dispersing series: `sharpe 33.87 · sortino 0 · calmar 0`, with `cagr 0.201`. The
    peer ranks are **Sharpe 100th and Sortino 5th on the same panel.**
- **Issue:** a book with no losing day has no Sortino, and a book with no drawdown has no Calmar.
  In both cases the ratio would be infinite, which means "undefined", not "zero". A value of 0.00
  claims the book earns nothing per unit of downside risk. The peer bar's "5th" claims the book is
  near the bottom of the cohort. For the books this phase targets, and for any
  all-positive book, the page therefore inverts the truth.
- **Same-page contradiction, the H1 shape:**
  - On the api arm, `overlayBasisScalars` replaces the KPI Sortino and Calmar with the persisted
    Python scalars. Python's `_safe_float` withholds a degenerate Sortino or Calmar as `null`,
    which renders "—". The peer bar, however, ranks the TypeScript `strategyMetrics.sortino` (0)
    and prints "5th". One page shows Sortino "—" in the KPI strip and "5th" in the peer panel.
  - On the csv arm, where there is no overlay, the KPI strip now reads **Sharpe "—" · Sortino
    0.00 · Calmar 0.00** for a constant-yield book. Before the fix pass all three read 0.00: wrong,
    but consistent.
- **The codebase's own wording:** `basis-context.tsx` (the M-1 note in `useBasisSeriesView`)
  already calls `compute()`'s `ddDev = 0` Sortino of "0.00" "a fabricated value" and replaces it
  with NaN on the levered MTM path. The same value is still shown unguarded on the base path.
- **Why this is partly the fix pass's doing:** the pass guarded the Sharpe inside
  `computePeerPercentile` and left the Sortino unguarded in the same return statement. It changed
  `headlineStats` to `?? NaN` for the Sharpe and kept `: 0` for the Sortino two lines below. The fix
  report listed the Sortino and Calmar arms as residues because "these are not dispersion ratios".
  D7's own text is broader than that. CONTEXT's D-07 amendment says: "a statistic that does not
  exist STAYS EMPTY END TO END … never 0.00 … every page agrees".
- **Rating rationale:** the harm is the same kind that made round-1 H1 HIGH: a public page, a
  sibling surface that says "—", and a mislead in the harmful direction. The defect predates the
  phase and can be fixed separately, so the orchestrator may choose to fix or to book it. I have
  not lowered the rating for that.
- **Recommendation:**
  - In `compute`, the Sortino arm becomes `: NaN` and the Calmar arm becomes `: NaN`.
  - In `headlineStats`, the Sortino arm becomes `: NaN`, and `bootstrapCI` drops a non-finite
    Sortino resample, as it now does for the Sharpe.
  - In `computePeerPercentile`, `sortino` becomes
    `Number.isFinite(stratSortino) ? percentileRank(...) : NaN`.
  - Every formatter on these paths already renders NaN as "—".
  - Check the three `?? 0`-style consumers of `compute().sortino` and `.calmar` before landing:
    `calmar-by-year` (it imports only `cumEq` and `drawdowns`, so it is safe), the style-drift
    halves (`fmt`, which is safe), and `health-score` (which reads Python analytics, not
    `compute`).

### SFH-R2-M2 (MEDIUM): the bootstrap Sharpe CI covers only the resamples that have a Sharpe, and the caption does not say so

- **Location:** `bootstrapCI` (the filtered `sharpes`) and the `AnalyticalPanels` caption
  "{n_resamples} stationary block-bootstrap resamples · 95% CI".
- **Issue:** for a sparse-trading series, a few resamples can draw a window with no dispersion.
  They are now dropped, which is right under D7. The Sharpe CI and histogram are therefore
  conditional on the other resamples, while the caption still reports all 2,000. Below
  `MIN_SHARPE_RESAMPLES` the CI reads "—", which is honest. Above it, the dropped count is never
  disclosed.
- **Recommendation:** carry the Sharpe resample count in the payload, and have the caption or the
  row name it when it is below `n_resamples` ("1,987 of 2,000 resamples have a Sharpe").

### SFH-R2-M3 (MEDIUM): `KpiStrip` "Avg |ρ|" now averages only the measured pairs, and only the heatmap says so

- **Location:** `computeScenario` (unmeasured pairs are left out of the sum and the count), which
  `KpiStrip` reads as `avg_pairwise_correlation`, and `CorrelationHeatmap`, which adds
  "· k of n pairs measured".
- **Issue:** leaving the pairs out is the correct D7 fix. But the KPI strip and the
  scenario-share page's KPI read the average without the count, and the heatmap caption is the only
  disclosure. When a flat leg is added, the KPI's delta is taken over a different pair set than
  the baseline's, with no cue.
- **Recommendation:** add the "k of n" qualifier (or a tooltip) to the KPI when k < n, or record it
  as accepted.
