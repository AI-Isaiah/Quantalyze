# Phase 166.2 Plan 05: the factsheet builder's beta, correlation, information ratio and rolling Sharpe on return-stats Summary

**`jointMetrics`, `rollingBeta`, `rollingSharpe`, build-payload's `pearsonCorr` and `buildAllocatorMetrics` now compute through `src/lib/return-stats.ts`. A compounding constant-yield leg now reads beta 0, correlation 0 (NaN in the payload), information ratio 0 and rolling Sharpe 0, which is what an all-zero leg already gives. Before, the factsheet showed float-residue betas of about 1e12 to 1e13, correlations of about 0.01 to 0.07, and information ratios and rolling Sharpes of 3e10 to 3e14.**

## Accomplishments

- `joint.ts`: `beta` is `betaOf(rets, bench) ?? 0` and `corr` is `pearson(rets, bench) ?? 0`. The tracking error is `dispersion(active, 0).sd * sqrt(N)` and the information ratio is `sharpe(active, { periodsPerYear, ddof: 0 }) ?? 0`, both over `active[i] = rets[i] - bench[i]`. Alpha, r2, Treynor and the captures keep their formulas. The private `mean` and `pstdev` are deleted.
- `rolling.ts`: each `rollingBeta` window is `beta(winS, winB) ?? 0`, and each `rollingSharpe` window is `sharpe(win, { periodsPerYear, ddof: 0 }) ?? 0`. `rollingVol` and `rollingSortino` now read `stdDev(w, false)` and `mean` from `portfolio-math-utils`. The private `mean` and `pstdev` are deleted.
- `build-payload.ts`: one import line was added, and `pearsonCorr`'s body is now `return pearson(a, b) ?? NaN;`. The function name and both call sites (the benchmark list and the matrix) are unchanged.
- `allocator.ts`: in `buildAllocatorMetrics`, `s` and `mmS` come from `dispersion(..., 0).sd` and `corr` from `pearson(rets, mmRets) ?? 0`. The blend-vol grid scan and the tail logic are unchanged.
- The two hand-rolled sum/variance loops in `buildAllocatorMetrics` and the one in `pearsonCorr` are gone.

## Decisions Made

- `beta` is imported as `betaOf` in joint.ts. The local `const beta` is read by the returned object, so renaming the local would have been a wider edit.
- `buildAllocatorMetrics` slices the mm leg to `rets.length` before `dispersion`, because the old loops read only the first n points of `mmRets`. `pearson` already uses the first `min` points. For the equal-length callers (build-payload's legs all share `dates`), the slice changes nothing.
