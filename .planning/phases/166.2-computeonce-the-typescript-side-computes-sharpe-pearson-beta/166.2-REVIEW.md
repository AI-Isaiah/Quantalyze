## Summary

Scope: `git diff ea4167a3f..HEAD -- src/`. The core module, `src/lib/return-stats.ts`, is sound.
`dispersion`, `sharpe`, `pearson` and `beta` use the documented floor
(`1e-12 * max(1, |mean|)`) with correct NaN handling. `sharpe` returns null on non-finite input,
`pearson` returns null through `denom > 0`, and `beta` returns null through `varX > 0`. `ddof` is
used consistently: population for the factsheet, OG, compare-holding and joint paths, and sample
for the scenario, sample-basis and scenario-benchmark IR paths. Each matches the site's code
before the change. Annualisation still comes from each caller's `periodsPerYear`
(`annualizationPeriods(assetClass)` on the factsheet and OG paths). No site's arithmetic order
changed.

Deleted files: `src/lib/correlation-math.ts` exported `pearson` and `rollingCorrelation`. Neither
has a remaining importer. A grep of `src/` for `correlation-math`, `rollingCorrelation` and
`computeRollingMetric` returns 0 hits. The old `pearson` behaviour, including null on zero variance
(G11.E.5), moved into `return-stats.pearson-contract.test.ts` intact. `rollingCorrelation` and
`computeRollingMetric` had no production callers. No behaviour was lost.

Tests: all 14 phase test files pass (4 files / 96 tests, then 10 files / 369 tests, both runs with 1
skip, the env-gated merge-base block).

The main problem is item 1 of the brief. D-07 tells every site to map `null` to "the value it
already emits for an exact constant". That means `?? 0` in 8 places. Several of them reach a
renderer as a literal `"0.00"`, while a sibling surface shows the same undefined value as `"—"`.
The OG card and the factsheet KPI strip disagree on Sharpe for the same input (CR-01). The factsheet
shows `Correlation 0.00` in one panel and `—` in another for the same pair (WR-01). D-07 locked
this choice, so each finding names the lock and its routing. It is still the defect the brief asked
about, and it is user-facing.

Answers to the five brief items:

1. **Null/NaN to renderer.** Handled correctly: `holding-compare-adapter` (null), `sample-basis-ratios`,
   `scenario.ts` Sharpe (null), `scenario-benchmark` (null, "—"), `scenario-stress` (null),
   `CompareCorrelationMatrix` ("—" with "Insufficient data"), `og-metrics` (NaN, "—"),
   `build-payload` `pearsonCorr` (NaN: `DistributionPanels` filters the strip on `Number.isFinite`
   and prints "—" in the matrix, so no `toFixed` on NaN), and `diversificationRatio` (null, "—").
   Defective (`?? 0` reaching a renderer as a number): `compute.ts` Sharpe (CR-01),
   `joint.ts` beta/corr/IR/R² (WR-01), Risk-tab `CorrelationMatrix` (WR-02), `scenario.ts`
   correlation matrix and `avg_pairwise_correlation` (WR-03), and `rolling.ts`, `allocator.ts`,
   `bootstrap.ts` and `computeAlphaBeta` (WR-04).
2. **Factsheet and OG Sharpe.** Same function, same floor, same `ddof` (0), same `rf` (0) and
   the same `annualizationPeriods(assetClass)`. The null handling differs: the OG card maps null to
   NaN ("—") and `compute` maps it to 0 ("0.00"). There are two older divergences as well. OG
   requires 30 or more observations while `compute` needs 2. OG reads
   `resolveDailyReturnSeries`, which can difference `returns_series`, while the factsheet reads

3. **The source-scan gate can fail. It does not pass vacuously on an empty tree, but its reach is

## Critical Issues

### CR-01: Factsheet KPI Sharpe shows "0.00" where the OG card and the persisted analytics show "—"

**File:** `src/lib/factsheet/compute.ts` (`compute`, `const sharpe = sharpeRatio(...) ?? 0`). Rendered by `src/app/factsheet/[id]/v2/FactsheetView.tsx` (KPI strip `{ label: "Sharpe", value: num(m.sharpe) }`) and `src/app/factsheet/[id]/v2/MetricsColumn.tsx` (`Row label="Sharpe"`).

**Issue:** For a series with no real dispersion, `sharpe()` returns null. That covers an exact
constant, the float residue of a compounding constant yield (the phase's own target), and a
constant non-zero yield such as `consecutive(300, 0.001)`. `compute` turns that null into `0`, and
`num(0)` renders `"0.00"`. On the same input:
- `computeOgHeadline` returns NaN, and the OG card shows `"—"` (`og-metrics.ts`, `?? NaN`).
- The analytics service persists `sharpe = None` for a constant series (its headline-Sharpe path),
  so the tearsheet (`formatNumber(analytics.sharpe)`) shows `"—"`.

The v2 KPI strip reads `compute`'s value whenever no persisted `cash_settlement` overlay exists.
`overlayBasisScalars` returns `base` unchanged when `serverScalars` is absent, which is the
single-strategy default. The browser leverage re-derive (`basis-context.tsx`, via
`deriveSeriesBundle` → `compute`) takes the same path. So a steady-yield product shows a Sharpe of
`0.00` on its factsheet, `—` on its share card and `—` on its tearsheet. A Sharpe of 0 says "no
excess return per unit risk". For a strictly positive constant yield that is false: the ratio is
undefined. Before this phase the value was residue garbage of about 1e13, so the phase improved it
but ended on a fabricated number rather than an absence.

This is the D-07 lock ("map null to today's value"). The CONTEXT site table routes T13's
*headline read* to Phase 169 plan 04. Two things remain outside that routing: the levered re-derive
path, and every non-headline consumer of `compute().sharpe`, namely `comparator-block.ts`
benchmark summaries and the `style-drift.ts` halves rendered by `BatchDPanels` (`h1.sharpe`,
`h2.sharpe`).

**Fix:** Make the absence representable and let the formatters, which already map null and NaN to
"—", do the rest:
```ts
// compute.ts
const sharpe = sharpeRatio(rets, { periodsPerYear, ddof: 0, rf }) ?? NaN;
// (or type ComputeResult.sharpe as number | null and return null)
```
`num()` in `MetricsColumn.tsx` and `FactsheetView.tsx` already renders non-finite values as "—".
Re-pin the T13 site test to "constant yield equals all-zero equals NaN" rather than "equals 0". If
the D-07 lock is kept, route this explicitly: Phase 169 plan 04 must cover the levered and
non-headline consumers too, not only the persisted headline read.

## Warnings

### WR-01: One factsheet page shows the same strategy/benchmark correlation as "0.00" and "—"

**File:** `src/lib/factsheet/joint.ts` (`jointMetrics`: `betaOf(...) ?? 0`, `pearson(...) ?? 0`, `sharpe(active, ...) ?? 0`) and `src/lib/factsheet/build-payload.ts` (`pearsonCorr`: `pearson(a, b) ?? NaN`).

**Issue:** For a strategy leg with no real dispersion, `build-payload` `pearsonCorr` returns NaN,
and `DistributionPanels` drops it from the correlation strip and prints `"—"` in the matrix.
`jointMetrics` on the same pair returns `corr = 0`, `r2 = 0`, `beta = 0` and `info_ratio = 0`.
`MetricsColumn.tsx` renders those as `Correlation 0.00`, `R² 0.00`, `Beta 0.00` and
`Information Ratio 0.00`, and the KPI strip IR cell (`FactsheetView.tsx`, `num(j.info_ratio)`)
does the same. The same page therefore states both "uncorrelated" and "correlation undefined" for
one pair. The difference existed before for an exact constant. This phase extended both behaviours
to the constant-yield class and kept them apart on purpose (D-07).

**Fix:** In `jointMetrics`, map null to `NaN` for `beta`, `corr` and `infoRatio`, and derive
`r2 = Number.isFinite(corr) ? corr * corr : NaN`. Change the `treynor` guard from `beta !== 0` to
`Number.isFinite(beta) && beta !== 0`. Check the `alpha` arm too, because
`(m - NaN * mb) * N` is NaN, which is the honest answer for an undefined beta. Every renderer
already uses `num()`/`signed()`, which render "—" on non-finite values.

### WR-02: The Risk-tab correlation matrix renders an undefined correlation as "0.00", and a new test pins that behaviour

**File:** `src/app/(dashboard)/allocations/widgets/risk/CorrelationMatrix.tsx` (`pearson(av, bv) ?? 0`, cell `{val.toFixed(2)}`); `CorrelationMatrix.residue.test.tsx`.

**Issue:** A pair where one leg is flat or a constant yield, or where the aligned overlap is under
2 points, renders `0.00` with the neutral colour, which reads as "uncorrelated". The /compare matrix
(`CompareCorrelationMatrix.tsx`) renders the same condition as `"—"` with the title "Insufficient
data". That follows the G11.E.5 contract that `pearson`'s own doc comment cites: "No correlation"
and "correlation cannot be measured" are different answers. The new residue test asserts
constant-yield cell equals all-zero cell, and the all-zero cell is `0.00`. The test therefore locks
in the misleading display rather than guarding against it.

**Fix:** Change the matrix type to `(number | null)[][]` and keep `pearson`'s null. Render
`val === null ? "—" : val.toFixed(2)` with a `title="Insufficient data"`, and make
`correlationColor`/`textColorForCorr` neutral on null. Update the residue test to assert the `"—"`
cell.

### WR-03: `computeScenario` counts undefined pairs as ρ = 0 in the down-good "Avg |ρ|" KPI

**File:** `src/lib/scenario.ts` (`computeScenario`: `const corr = pearson(...) ?? 0;` then `absCorrSum += Math.abs(corr); corrCount += 1`).

**Issue:** A member with no real dispersion now reads ρ = 0 against every other member. Those zeros
go into the matrix and also into `avg_pairwise_correlation`, which `KpiStrip` marks `"down-good"`
and which `scenario-share/[token]/page.tsx` and `portfolio-pdf` render as "Avg |ρ|". Adding a
constant-yield sleeve therefore pulls the book's average |ρ| down and makes the blend look more
diversified, because of pairs whose correlation is undefined. Before this phase, an exact constant
behaved the same way. This phase extended it to the constant-yield class.

**Fix:** Skip null pairs in the average:
```ts
const c = pearson(strategyReturns[idA], strategyReturns[idB]);
correlation_matrix[idA][idB] = c === null ? 0 : Number(c.toFixed(3)); // or widen the type to allow null
if (j > i && c !== null) { absCorrSum += Math.abs(c); corrCount += 1; }
```
`avg_pairwise_correlation` already falls back to `null` when `corrCount === 0`.

### WR-04: The rest of the `?? 0` family reports an undefined ratio as a measured 0

**File:** `src/lib/factsheet/rolling.ts` (`rollingSharpe`, `rollingBeta`: `?? 0`); `src/lib/factsheet/allocator.ts` (`buildAllocatorMetrics`: `corr = pearson(...) ?? 0`); `src/lib/factsheet/bootstrap.ts` (`headlineStats`: `?? 0`); `src/lib/portfolio-stats.ts` (`computeAlphaBeta`: `sharedBeta(r, b) ?? 0`).

**Issue:**
- `rollingSharpe` and `rollingBeta` plot a flat or residue window as 0 on the rolling charts and in
  the `RollingMetricsPanel` min/max/avg summary. That pulls the average toward 0 and can set the
  min or max. A gap (`null`, which the output array type already allows) is the honest value.
- `allocator.ts` `corr = 0` feeds the sleeve grid scan (`blendVar` treats the legs as independent)
  and is rendered by `BatchDPanels` as `"Correlation with …" +0.00` through `signed(p.corr)`.
- `bootstrap.ts` counts a resample with no dispersion as a Sharpe of 0 in the CI histogram. This is
  realistic for a sparse-trading series whose block resample can come out all zeros, and it
  narrows or shifts the reported interval.
- `computeAlphaBeta` reports beta 0 and `alpha = mean(r) * N` for a constant benchmark.
  `scenario-benchmark` guards this itself, but `AlphaBetaDecomposition.tsx` calls
  `computeAlphaBeta` directly with no guard. Its benchmark is BTC, so this is hard to reach in
  practice.

Each is D-07 ("today's value"), and each is a `?? 0` the brief names as a defect.

**Fix:** `rollingSharpe`/`rollingBeta`: return `null`. `allocator`: carry `NaN`/`null` and skip the
correlation term, or refuse the scan, when corr is undefined. `bootstrap`: drop resamples whose
Sharpe is null from the distribution rather than adding 0s. `computeAlphaBeta`: return
`{ alpha: null, beta: null }` on a null shared beta, or document that callers must guard, as
`scenario-benchmark` does.

### WR-05: The source-scan matcher misses common Sharpe, Pearson and beta spellings that its header does not list

**File:** `src/lib/return-stats.single-source.test.ts` (`SHAPES`, and the header block "KNOWN UNMATCHED (D-22…)").

**Issue:** The header says a copy in one of seven listed forms is caught only by layers 1 and 2,
which implies that other forms are caught. Running the shipped regexes through a probe shows these
also produce **0 hits**, and none of them is on the list:

| form | shape it should be |
|---|---|
| `(m - rf) / sd * Math.sqrt(N)` (the textbook excess-return Sharpe) | Sharpe |
| `m * periodsPerYear / sd` (unparenthesised) | Sharpe |
| `m * Math.sqrt(periodsPerYear) / sd` | Sharpe |
| `(m * this.periodsPerYear) / sd`, `(m * PERIODS_PER_YEAR) / (sd * SQRT_N)` | Sharpe |
| `annRet / annVol` | Sharpe |
| `sxy / (sx * sy)`, `cov / sx / sy` | Pearson |
| `sxy / sxx`, `covar / bVar` | beta |

The numerator lookbehind on S3 (`(?<![\w.$)])`) excludes every parenthesised numerator such as
`(m - rf)`. S0 needs a `)` straight after the annualiser. P0, P2 and BETA need `cov` in the
numerator. So a new file with an ordinary Sharpe copy passes all three layers, since layers 1 and
2 are keyed to the 16 existing files. The gate does fail on what it claims to match, and it does not
pass vacuously (see Summary item 3). Its stated reach is simply wider than its real reach.

**Fix:** Within D-22's constraint that there be no silent widening, extend the KNOWN-UNMATCHED list
now with the forms measured above. Book widening S3 (allow a parenthesised numerator) and S0 (accept
`\w+` annualisers and the unparenthesised form) as a follow-up that re-measures the 26-hit
merge-base pin. Until then, the gate's claim should say "catches the nine listed forms", not imply
full coverage.

### WR-06: `diversification.ts` still has a second σ_p floor next to the shared one

**File:** `src/lib/diversification.ts` (`percentContributionToRisk`: `if (!(portVar > 1e-15)) return null;`, compared with `diversificationRatio`: `dispersionIsReal(sigmaP, 0)`).

**Issue:** Both functions judge the same quantity, the portfolio σ from the same levered covariance,
inside one `computeDiversification` call. DR uses the shared floor (sd > 1e-12). PCR, and ENB
through it, use a local variance floor of 1e-15 (sd > about 3.2e-8). For σ_p between those values
the panel shows a DR but "—" for PCR and ENB. The phase set out to have one floor. This file is on
the Tier-2 list and still carries a second one. The PCR ratio (`w·Σw / wᵀΣw`) divides by a
dispersion. It is not caught by the gate because `1e-15` is not a retired token and the shape does
not match. In practice the gap is pathological, but the drift is the class this phase exists to
remove.

**Fix:** `if (!dispersionIsReal(Math.sqrt(Math.max(portVar, 0)), 0)) return null;`, matching
`computeRiskDecomposition` in `portfolio-stats.ts`. If a looser floor is intentional for PCR, record
why next to the line.

### IN-02: Gaps in the gate's text handling (comment stripper, retired tokens, empty-tree sub-test)

**File:** `src/lib/return-stats.single-source.test.ts` (`stripComments`, `RETIRED`, `wholeTreeOffenders` test).
**Issue:** (a) `stripComments` does not know about strings. A string or regex literal containing
`/*` (for example a glob `"src/*"`) blanks everything up to the next `*/`, and a `//` not preceded by
`:` blanks the rest of its line, so a formula after such a literal is hidden from the shape matcher.
No current `src/` file triggers this; it was measured. (b) The `RETIRED` tokens are compared as
literal strings including whitespace, so re-introducing `std>0?` instead of `std > 0 ?` escapes
layer 2. (c) "whole-tree retirements" passes on an empty walk. It relies on the sibling tests to go
red. Add `expect(files.length).toBeGreaterThan(0)` so it stands on its own.
**Fix:** Normalise whitespace before matching retired tokens (`code.replace(/\s+/g, "")` against a
whitespace-free token). Add a non-empty assertion to the walk. Either skip string and template
literals in `stripComments` or record the limitation beside KNOWN-UNMATCHED.

### IN-03: Two `og-metrics.test.ts` Sharpe arms lost their original intent

**File:** `src/lib/factsheet/og-metrics.test.ts` ("CAGR hidden (NaN) for a dense sub-year series", "Sharpe hidden (NaN) below the 30-observation floor").
**Issue:** The first test's comment still says "plenty of observations for Sharpe", and it used to
assert that the Sharpe is shown while CAGR is hidden. Its fixture is constant, so the D-07 change
correctly flipped it to NaN. The "Sharpe shown on a sub-year series" intent now rests only on the
first test (40 alternating returns). In the 30-observation-floor test, the Sharpe assertion is now
vacuous: a constant fixture gives NaN whether or not the `>= 30` gate exists. The test still fails
through its `maxDd` arm if the gate is removed, so the test as a whole is not vacuous. The two
isNaN assertions themselves can fail: with the floor removed, the Sharpe is about 3e16 and finite.
**Fix:** Give both tests a non-constant fixture, for example alternating `0.002` and `-0.001`. The
sub-year test can then assert `Number.isFinite(sharpe)` again, and the 29-row test's Sharpe arm
bites on the observation gate. Keep the D-07 NaN assertions in a separate, named constant-series
case.

### IN-04: `buildAllocatorMetrics` mixes three different `n` values if the legs ever differ in length

**File:** `src/lib/factsheet/allocator.ts` (`buildAllocatorMetrics`).
**Issue:** `s` is taken over all of `rets`, `mmS` over `mmRets.slice(0, n)`, and `corr` over
`min(len)`. Today every caller in `build-payload.ts` passes date-aligned, equal-length series, so the
current output is right. The old code assumed equal length too, but failed as NaN. The new code
quietly computes each figure over a different window.
**Fix:** Assert `mmRets.length === rets.length` at entry, as `jointMetrics` does, or document the
contract.
