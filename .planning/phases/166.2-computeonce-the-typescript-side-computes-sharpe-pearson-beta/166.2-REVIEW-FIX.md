## Fixed Issues

### CR-01 / SFH-H1: the factsheet Sharpe read "0.00" where the OG card read "—"

**Status:** fixed: requires human verification (display logic)
**Commit:** `9670242ae`
**Files:** `src/lib/factsheet/compute.ts`, `bootstrap.ts`, `peer-cohort.ts`, `types.ts`,
`src/app/factsheet/[id]/v2/AnalyticalPanels.tsx`, `BatchDPanels.tsx`, `basis-context.tsx`, and tests
**Applied fix:**
- `compute` returns a NaN Sharpe on null. That path also carries the levered browser re-derive, the
  `comparator-block` benchmark summary and the `style-drift` halves. Their formatters (`num`,
  BatchDPanels `fmt`) already render non-finite values as "—".
- `computePeerPercentile` returns a NaN rank for a non-finite Sharpe. `percentileRank(NaN)` used to
  report the 0th percentile. `PercentileBar` now renders "—" over an empty track for NaN and for null
  (the JSON-cache form).
- `bootstrap`'s `headlineStats` skips a resample that has no Sharpe instead of counting it as 0. The
  point is NaN when the full series has no Sharpe. The CI is NaN below `MIN_SHARPE_RESAMPLES` (40),
  the smallest count whose 2.5% and 97.5% order statistics each leave a resample outside the
  interval. `BootHist` never calls its formatter on an absent value and omits the band and the point
  line.
- New `src/app/api/og/factsheet/[id]/route.page-agreement.test.tsx` renders the OG card, through the
  real route handler, and the factsheet page, through the real `FactsheetBody`, from one constant
  series. It asserts "—" on the OG card, the KPI tile and the Main Metrics row, and no literal
  "NaN" anywhere on the page. A dispersing control reads a number on all three.

### WR-01 / SFH-M3: `jointMetrics` showed 0.00 beside a "—" for the same pair, and up_capture broke D-07

**Status:** fixed: requires human verification (display logic)
**Commit:** `9d07bbec0`
**Files:** `src/lib/factsheet/joint.ts`, `types.ts`, `return-stats.sites-joint.test.ts`, `basis-context.leverage.test.tsx`
**Applied fix:** beta, corr and info_ratio keep null as NaN. r2 is NaN when corr is. Treynor is NaN
unless beta is finite and non-zero. Alpha becomes NaN through beta. Up and down capture are NaN
when the benchmark has no dispersion or has no up (down) days. T16 now pins all of these as NaN on
the all-zero bench. The constant-yield equality now covers every field that divides by the bench's
dispersion; tracking error and IR are excluded, with the reason stated, because they move with the
bench's level. The test also adds a no-down-days case. Leverage Test C held vacuously before this
change: its fixture dates predated the bundled BTC history, so it proved 0 = 2·0. The dates now sit
inside that history, and the test asserts a real beta first.
