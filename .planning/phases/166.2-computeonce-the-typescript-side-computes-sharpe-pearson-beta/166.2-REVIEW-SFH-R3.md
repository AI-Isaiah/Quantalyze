Scope: the round-2 fix pass, `10f16f1eb..HEAD` outside `.planning/`, at HEAD `20b0b6821`. Cited by
symbol only. The brief asks three things: (a) are SFH-R2-H1 and SFH-R2-H2 closed, (b) did the fix
pass add a new HIGH or CRITICAL silent failure, and (c) what D7 residues (a 0 standing in for a

session scratchpad, and both were deleted afterwards. Neither was committed. The probe series were

## (b) New silent failures introduced by the fix pass: none at HIGH or CRITICAL

Checked and cleared:

- **NaN into arithmetic or comparisons.** No changed value feeds a subtraction, a product or an
  ordering without a guard:
  - `jointMetrics` Treynor divides only when `Number.isFinite(beta) && beta !== 0`, so the new
    exact `beta` of 0 gives NaN ("—"), not Infinity.
  - `commonSenseRatio = tailRatio * m.profit_factor` would carry a NaN through to `num`'s "—".
  - The `accent={m.kurt > 6}` prop and the Recovery Factor accent are false for NaN.
  - The KPI strip's `signTone` and `maxDdTone` test finiteness.
- **Sorting and ranking.** `computePeerPercentile` guards both ratios now. No changed path sorts a
  ratio.
- **JSON (NaN becomes null).** `unstable_cache` is the one cache (`buildFactsheetPayloadCached`),
  and every renderer on these paths tests `v != null && Number.isFinite(v)`: `num`, `pct`,
  `signed`, `pctSigned`, `show` and the `BootHist` point line. `BootHist` checks
  `Number.isFinite(point)` before it formats anything, so a `null` point renders "—". The
  scenario empty-render test covers the round trip explicitly. It serialises the empty payload
  through JSON and asserts "—" and the absence of `NaN`, `Infinity` and `>null<` in the whole body.
- **The empty scenario body (D-26).** `emptyComputeSummary` and `emptyBootstrapCI` are consumed
  only through `FactsheetBody`. No surface of the composer reads `strategyMetrics` for arithmetic,
  and the chart arrays stay empty. The new test renders the real `FactsheetBody` in `scenarioMode`
  from the real builder, for three cases: an empty input, a poisoned input and a JSON round trip.
  It can fail: the pre-fix zeros would print "0.00" in Main Metrics.
- **An absent `n_valid` on a cached payload.** The caption falls back to `n_resamples`, and so it
  says nothing about dropped resamples. That silence cannot outlive a deploy, because the key
  moved from v6 to v7, `unstable_cache` is the only cache that holds a `FactsheetPayload` (the
  share page and the discovery page build fresh), and every fresh build (`bootstrapCI`,
  `deriveSeriesBundle` for MTM and leverage) writes `n_valid`. The field is absent only on a
  hand-built fixture, and `BootstrapCIPanel.resample-count.test.tsx` pins that fixture to "no
  count, no NaN".
- **The v7 key.** The fix pass changed the values `compute` returns, and `build-payload` produces
  the payload, so any payload cached before the pass would carry the old values. The one keyed
  cache is `buildFactsheetPayloadCached`. The comment in `fetch-and-build-payload` names v7 too.
  No consumer is missed.
- **`beta` returns an exact 0 for a flat `y`.** The covariance is 0 and `var(x) > 0`, so the beta
  exists and is 0, which is what an all-zero `y` already gave. A flat strategy's Correlation
  reads "—" beside a Beta of 0.00 on the same page, and that is not a contradiction: the
  correlation is 0/0, while the beta is 0/`var(x)`. The probe printed `beta flat y 0`. `rollingBeta`
  and `computeAlphaBeta` both inherit the change, and the T16/T17 tests pin that a constant yield
  equals the all-zero strategy element by element.
- **`KpiStrip` `pairCoverage`.** It counts the upper triangle with the same finiteness test as
  `CorrelationHeatmap`'s `measuredPairs`. The engine (`computeScenario`) writes a row for every
  member and leaves out only the null cells, so `Object.keys(matrix)` and the heatmap's `ids`
  describe the same set, and the two captions cannot disagree for an engine matrix.
- **`AlphaBetaDecomposition`.** The reason is now conditional (`benchmarkFlat`), and it uses the
  same floor `beta` uses. Any other cause gets the neutral sentence. The round-2 LOW-2 is closed.
- **Tests that cannot fail.** None found. Each new test either asserts its precondition on the real
  builder (rolling-now, empty-render) or pairs its case with a control (resample-count, pair-coverage,
  sites, page-agreement).

### HIGH-1 (pre-existing; the fix pass created the on-page disagreement): Calmar by Year reads 0.00 for a year with no drawdown

- **Location.** In `src/lib/factsheet/calmar-by-year.ts`, `calmarByYear` computes
  `const calmar = maxDd !== 0 ? yearRet / Math.abs(maxDd) : 0;`. The value is rendered by
  `CalmarByYearPanel` in `AnalyticalPanels.tsx` as `num(r.calmar)`, on the public factsheet.
- **Measured.**
  - Constant yield: the rows are `2022 · +7.57% · 0.0% · Calmar 0.00` and `2023 · +0.70% · 0.0% ·
    0.00`. The headline Calmar is NaN ("—").
  - A two-year series whose first year has no down day: the row is `2022 · +16.88% · 0.0% · Calmar
    0.00`. The same book's headline Calmar is 1.49, and its 2023 row is 1.60.
  - One loss in 100 days: the 35-day stub row for 2023 reads 0.00. It is flagged as partial.
- **Why it is HIGH.** A year with no drawdown has no Calmar: the ratio would be infinite. A value of
  0.00 says the year earned nothing per unit of drawdown, which inverts a year that was all gain.
  For the constant-yield books this phase targets, every row reads 0.00. The headline Calmar now
  reads "—" for the same book because of SFH-R2-H2. Before the fix pass, both surfaces read 0.00,
  wrong but consistent. The reach is wider than the headline's: any year with no down-to-date
  point qualifies, which includes a short stub year at either end of a series whose few days were
  all gains.
- **Caused or pre-existing.** Pre-existing. The phase never touched `calmar-by-year.ts`. The fix
  pass made the disagreement visible, as it did with the Sortino in SFH-R2-H2. The fix is separable.
- **Recommendation.** `const calmar = maxDd !== 0 ? yearRet / Math.abs(maxDd) : NaN;`.
  - `num` already renders "—". `CalmarYearRow.calmar` is typed `number`, so NaN fits. The panel is
    the only reader.
  - D-07 holds: an all-zero year also becomes NaN.
  - Add a red-first case: a constant-yield series's rows read "—" in the Calmar column, a dispersing
    year keeps a finite value, and the test asserts no "0.00" in that column.

### HIGH-2 (pre-existing): Profit Factor reads 0.00 for a book that never lost, next to Omega, Recovery and Avg Win / Avg Loss reading "—"

- **Location.** In `src/lib/factsheet/compute.ts`, `compute` computes
  `const profitFactor = lossSum !== 0 ? winSum / Math.abs(lossSum) : 0;`. `MetricsColumn` renders it
  twice: in the Returns panel (`num(m.profit_factor)`, with the comparator's `num(b?.profit_factor)`)
  and in the Extended Metrics panel.
- **Measured.** The constant yield and the all-positive series both give `profit_factor 0` with
  `win_rate 1`. In the same Extended Metrics panel, `omega_ratio` and `recovery_factor` are `null`
  ("—"), and `ratioStr(avg_win, avg_loss)` returns "—" because `loss === 0`.
- **Why it is HIGH.** A book with no losing day has no profit factor: gross gain divided by a gross
  loss of 0 is infinite. A value of 0.00 is the worst possible reading, "no gain per unit of loss",
  shown for the best possible record, while three rows in the same panel say "—" for the same
  absence. The analytics service already treats this case as an absence (`services/metrics.py`,
  the D-09 comment: "no losing day -> `profit_factor` is +inf -> ... -> None").
- **Caused or pre-existing.** Pre-existing. The fix pass did not touch it and did not create the
  disagreement: Omega and Recovery already read "—". The fix is separable.
- **Recommendation.** `const profitFactor = lossSum !== 0 ? winSum / Math.abs(lossSum) : NaN;`.
  - D-07 holds: an all-zero series also gets NaN, which is right, because it has no gains and no
    losses.
  - Every reader already handles NaN. `num` renders "—". `commonSenseRatio` becomes NaN and renders
    "—", which agrees with the Python `None`. The comparator block copies the field into `summary`,
    where `num` formats it.
  - Before landing, grep the non-factsheet readers of `ComputeSummary.profit_factor`: the
    allocator-portfolio payload shares `compute`.
  - Add a red-first case: the all-positive and constant-yield series read "—" in both Profit
