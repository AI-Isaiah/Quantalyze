# Phase 164.5.3 Plan 05: Founder-facing MT5 credential-update dialog Summary

**A shared `UpdateMt5SecretDialog` (password-only, D-03) wired into both `ApiKeyManager` and `AllocatorExchangeManager`, PATCHing Plan 04's `/api/keys/[id]/rotate-secret` and rendering failures through the repo's canonical `ErrorEnvelope` via the shared `recogniseDashboardDialogCode` roster.**

## Accomplishments

- `UpdateMt5SecretDialog.tsx`: a shared, credential-safe dialog (single password field, reveal toggle, scrubbed on every close path and on re-pointing to a different key) that PATCHes `/api/keys/[id]/rotate-secret`, calls `onUpdated()`+`onClose()` on a genuine 2xx, and renders `ErrorEnvelope` inline (dialog stays open, neither callback fires) on any non-2xx.
- `ApiKeyManager.tsx`: an "Update password" button, gated to `exchange === "mt5"`, opens the dialog for that row's id; a successful update re-runs the card's own `loadKeys()`.
- `AllocatorExchangeManager.tsx`: the same affordance in BOTH the active and disconnected sections, distinct from Reconnect everywhere it appears (Reconnect never opens this dialog; this dialog never touches `disconnected_at` directly — that stays the route's own D-05 job); a successful update triggers the component's existing `startTransition(() => router.refresh())` mechanism.
- Closed a repo-wide gate this plan's own dialog tripped: `src/lib/dialog-envelope.invariant.test.ts` (161-10 / WIZERR-07) requires every dashboard dialog calling `buildEnvelope()` + mounting `<Modal>` to be rostered in `DASHBOARD_DIALOG_ROUTE_CODES` and read the shared recogniser — done in the same commit as the dialog itself.

## Decisions Made

See `key-decisions` in frontmatter — summarized: used the shared `recogniseDashboardDialogCode` roster rather than a raw client-side cast (required by the repo's own dashboard-dialog-envelope invariant law); rostered the two sibling MT5 classifier codes (`KEY_AUTH_FAILED`, `KEY_MT5_WRONG_SERVER`) alongside the plan-named `KEY_MT5_MASTER_PASSWORD` so every realistic MT5 validation failure gets specific copy, not the generic UNKNOWN card; disposed the two codes with no real copy entry (`NEW_SECRET_REQUIRED`, `KEY_UPDATE_UNSUPPORTED_VENUE`) as deliberately-not-enveloped, both unreachable from this dialog in practice; reworded the dialog's helper copy to avoid the literal substring "MT5 account" after discovering `Modal.tsx` always renders its children regardless of the `open` prop, which was colliding with Plan 01's non-MT5-row assertion.
