Add `PATCH /api/keys/[id]/rotate-secret` — the credential-update route D-04 calls for. Owner-scoped,
MT5-only (per Assumption A2: the phase's explicit MT5 framing; a ccxt-secret-rotation generalization is
NOT in scope and is not built speculatively), password-only (D-03), validate-before-persist (D-04), and
clears the failure state only on confirmed success (D-05).

⭐ **Decision, resolving RESEARCH.md's Open Question 2**: the persist step uses `createAdminClient()`
directly from this route — NOT a new `SECURITY DEFINER` RPC. RESEARCH calls both "equally safe"; the
admin-client path needs NO second migration (this phase already ships exactly one, Plan 01's
GRANT-extend), keeping the migration/review surface to what CONTEXT.md's Non-Negotiable section
describes ("it ships A migration", singular). D-07's requirement (the persist step cannot use a
user-scoped client) is satisfied either way; this route satisfies it with `createAdminClient()` plus an
explicit `.eq("user_id", ...)` filter, exactly as `validate-and-encrypt`'s persist arm and
`create-with-key`'s `rpcAdmin` already do for writes to this same table.

⭐ **Decision, resolving RESEARCH.md's route-skeleton tension**: `withAuth()`'s handler signature is
`(req: NextRequest, user: User) => Promise<NextResponse>`, and its wrapper is `async (req: NextRequest)
=> {...}` — it does NOT forward a Next.js dynamic-route `{ params }` argument. `keys/[id]/permissions/
route.ts`, the one existing `withAuth`-wrapped route with a `[id]` segment, works around this by parsing
`req.url`'s pathname manually — its own comment calls this a compatibility shim, and RESEARCH.md's
route-skeleton note says not to copy it. Since `withAuth` cannot receive the MODERN
`params: Promise<{id}>` signature `strategies/[id]/name/route.ts` uses, and since both a defended
auth posture AND the modern params convention are wanted, this route HAND-ROLLS the same stack
`withAuth` provides — `assertSameOrigin`, `createClient().auth.getUser()`,
`approvalGate.assertProfileApproved(supabase, user.id)` (all imported directly, the exact primitives
`withAuth` itself calls) — combined with `{ params }: { params: Promise<{ id: string }> }`. This gets
BOTH properties PATTERNS.md asked for without modifying the shared `withAuth` utility (out of scope,
high blast radius — CLAUDE.md Rule 3).

Purpose: today a wrong MT5 password is fixable only by Delete + Add Key, destroying the row's id and
sync history. This route lets a founder correct it in place.

Output: one new route, its test, and the seam-registration edits every new `resilientFetch` call site

hand-typed anti-drift literals in `seam-constants.pin.test.ts` — measured requirement, not speculative:
