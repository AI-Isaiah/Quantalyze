<objective>
HOLD-02: match scoring applies the native-unpriced marker per ACCOUNT, as the TS reader does. Today `_load_holding_portfolio_context` lets a marker remove only its own key's older rows and then takes the account's newest day from the surviving rows. So when key A of an account carries a marker for day D and key B's newest rows are D-1, B's rows still count in the match AUM, while Holdings counts nothing for that account (measured: 700.0 against 0).

This plan writes one hand-typed case table that both runtimes replay, proves the Python side RED on it at HEAD, changes the matcher to the TS reading-day rule, and proves each arm on both sides with a named neuter.
