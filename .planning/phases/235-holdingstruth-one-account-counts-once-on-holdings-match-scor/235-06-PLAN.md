noun: the exchange ACCOUNT. SC-4's cues "second" and "another" count accounts. A key belongs to an account through the S4 identity (exchange, login, venue_server), settled by 170.4 D-09 and Phase 225.
decision: no-change. This phase consumes that identity through `accountGroups` and `accountLoginIdentity` and adds no new identity model.
rationale: "a second key whose cause another key already printed" is a key of a SECOND all-failing account, beside an account whose dated line already printed the cause. Plan 05 attributes it per account and this plan names it per account.
invariant_test: every counted holdings row maps to an account through the identity read. HOLD-01's gate in 235-01 (arms A1 to A6) encodes it, so the suggested invariant test is already a plan task.
</assumption_delta_decision>

<objective>
HOLD-05, the message half: every failing key of a shared account is named in the missing-data message, even when another account with the same cause already printed a line. Today `missingDataLines` suppresses the shared-account fallback as soon as every printed `shared_account_failing` gap is named. An all-failing account whose history reaches yesterday has no gap, so its keys are named nowhere and no fallback prints (RESEARCH's S3 probe).

This plan gives `missingDataLines` an optional `sharedFailingGroups` argument and one rule. A group named by a dated line is covered. A group with no dated line whose keys all label gets a new undated labelled line from one new registry entry. A group with an unlabelled key keeps the book fallback. The plan then wires plan 05's payload field into the Overview and runs the phase-wide gate sweep. It also records the ship obligations, which executors do not run.

Purpose: SC-4, the HOLD-05 half of SC-5, and the phase's closing checks.
Output: the rule, the registry entry, its gates, the Overview wire-up, the arms, the PROOF-01 transcripts, and the "For the ship" section in the SUMMARY.
</objective>
