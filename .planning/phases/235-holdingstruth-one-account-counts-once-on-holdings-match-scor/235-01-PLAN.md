<objective>
HOLD-01: a Holdings row whose key is missing from the identity read fails loud, with a test per reader. Today `keyAccountOf` maps an unknown key to its own `key:<id>` account, and the two dollar callers fall back to the key id for a key their `accountByKey` lacks, so an incomplete identity read silently double-counts an exchange account.

This plan makes the identity mapping itself strict (one named error class, `HoldingsIdentityError`), adds `strictAccountOf` for the two callers that read `fetchLatestHoldingsPerKey`'s `accountByKey`, rewrites the seven fixtures that relied on the retired default, and proves each reader RED on its neutered copy.

Purpose: SC-1 and the HOLD-01 half of SC-5. After this plan an identity gap shows the existing error page instead of a wrong figure.
Output: the error class and the two strict mappings, four production hunks (one per reader plus a docblock), the per-reader tests, the rewritten fixtures, and the PROOF-01 transcripts in the SUMMARY.

Schema fact that bounds the blast radius (read from `supabase/schema/baseline.sql`): `allocator_holdings.api_key_id` is NOT NULL with a foreign key `ON DELETE RESTRICT`, and the trigger function `enforce_allocator_holdings_owner_coherence` asserts that `allocator_id` equals the key's `user_id`. A row whose key is absent from the owner's `api_keys` read is therefore a contract violation (like a non-parseable `updated_at`, which already throws `HoldingsUpdatedAtError`), never a normal state.
</objective>

## Flagged assumption (edge probe: HOLD-01 unclassified, status unresolved)

The spec-less edge probe could not classify HOLD-01. Planner assumption, flagged and not auto-resolved: the only edge is MAP MEMBERSHIP. (a) A key present in `keys` whose identity token is null is a legitimate own account and keeps `key:<id>` (arm A3 pins it). (b) A key absent from `keys` is the failure. (c) With an EMPTY `keys` list, any holdings row in the window is absent, so `fetchHoldings` throws rather than returning an empty series. By the schema fact in the objective, (c) cannot arise for a real owner, so a throw there is a contract violation surfaced, not a new blank page for a real book. Verifier: treat this as an assumption to confirm, not as a proven edge.
