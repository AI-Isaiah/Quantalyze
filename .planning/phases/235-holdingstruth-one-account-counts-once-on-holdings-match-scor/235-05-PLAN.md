<objective>
HOLD-05, the producer half: `key-data-gaps.ts` emits the attributed key ids for the `shared_account_failing` cause, grouped per account, and the My-allocation payload carries them to the message. Today `keyDataGaps` emits a shared-account gap only when the group's tail has a range, so an all-failing account whose history reaches yesterday leaves no trace in the payload and its keys can never be named.

This plan adds a sibling export (the existing `keyDataGaps()` return is asserted whole and must not change shape), a queries.ts sibling built from the same input, and the payload field in both literals. Plan 06 makes the message name every group by label.

Purpose: the data half of SC-4.
Output: `sharedAccountFailingGroups`, `deriveSharedAccountFailingGroupsField`, the payload field, the producer, derive and payload arms, and the PROOF-01 transcripts in the SUMMARY.
</objective>
