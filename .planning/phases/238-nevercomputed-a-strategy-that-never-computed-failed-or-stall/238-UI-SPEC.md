# Phase 238 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** This phase is copy and state work on existing surfaces. It adds no layout, no primitive,
no token and no new action wording. It ships as two PRs (founder ruling 2026-11-24, CONTEXT
"Shipping split"):

1. **PR-1 (FACT-05, no migration).** On `/strategies`, the share note of a row whose link shows
   "not available", and whose compute state is `failed`, `stalled` or `never_started`, stops telling
   the owner to wait. It names the action the row's remedy already names (founder answer "(a) Reuse
   the remedy"). The published row's public-link note changes in the same PR (founder answer "Yes,
   same PR"). Sections 1 and 3 below.
2. **PR-2 (FACT-03, migration, executed after Phase 233).** `strategy_analytics.computed_at` becomes
   nullable. A never-computed row renders no compute date anywhere and never a 1970 date. Section 2.

## Global rules (apply to every section)

- **G1. Reuse the remedy; author no action words.** Every action a new note names is an existing
  `ACTION_SENTENCES` entry, copied by reference. These entries are word-for-word copies of
  `ownerRemedy`'s texts, and `degrade-warnings.test.tsx` pins that. The only new words are the two
  lead sentences and `KCS12-PUBLIC-UNKNOWN` (Copywriting Contract).
- **G2. A note never says to wait when nothing is running.** No note this phase places contains
  `yet`, `once a computation succeeds`, or `appear there`. `KCS12-MINT-A` (`in_progress`) keeps its
  wait, because something is running there (CONTEXT, decided autonomously).
- **G3. One state read, one action.** A note and the Health detail on the same row derive their action
  from the same `ComputeState`, the same shape and the same viewer. When both render, they end on the
  same action id (§1.3).
- **G4. No new tokens, sizes, weights, colours, live regions or controls.** Each line keeps its host's
  existing element and class.
- **G5. Primary visual anchor (checker FLAG 1, 2026-11-24).** On the `/strategies` row the Health word
  stays the focal element and the share note follows it, muted. On the owner's pending factsheet the
  remedy line stays the focal line and the note follows it. On the factsheet (PR-2) nothing visible
  changes except the date cells, which read `—` for a NULL date.

## 1. PR-1 (FACT-05): the share note names an action

### 1.1 Which note each row gets (first match wins)

The order follows the existing selection: `shareNotes` in `strategies/page.tsx`, then `uncomputedNote`,
then `recipientShareNoteFor`. Rows marked **changed** are this phase. Every other row renders today's
note, byte for byte.

| # | Row | Note | Status |
|---|---|---|---|
| 1 | Computed and buildable (probe `buildable`) | none | unchanged |
| 2 | Probe could not check (throw, timeout, `read_error`, `not_visible`) | `KCS12-PROBE-UNREADABLE` / `KCS12-PUBLIC-PROBE-UNREADABLE` | unchanged |
| 3 | An unbuildable kind (`too_short`, `cannot_build`, `analytics_failed`, `finished_not_built`) | the kind's existing `KCS12-*UNBUILDABLE*` line (170.1 D-08 / 167.2.1 D-02) | unchanged |
| 4 | Unpublished, arm `in_progress` (queued, retrying, running) | `KCS12-MINT-A` | unchanged |
| 5 | Unpublished, arm `unreadable` (the jobs read failed) | `KCS12-UNREADABLE` | unchanged. The state is unknown, so a computation may be running. |
| 6 | **Unpublished, arm `not_available`, no kind** (state `failed`, `stalled` or `never_started`) | **`KCS12-MINT-B-LEAD` + the row's action** (§1.2, §1.3) | **changed** (was `KCS12-MINT-B`) |
| 7 | Published, no kind, state **known** `failed` / `stalled` / `never_started` | **`KCS12-PUBLIC-LEAD` + the row's action** | **changed** (was `KCS12-PUBLIC`) |
| 8 | Published, no kind, state **known** `queued` / `retrying` / `running` | `KCS12-PUBLIC` | unchanged words. Something is running, so the wait is true. |
| 9 | Published, no kind, state **known** `finished` | the existing public `finished_not_built` line (`KCS12-PUBLIC-FINISHED-NOT-BUILT`) | newly reachable (§1.5). The 170.1 D-08 comment in `armOf` ("a published row can never take the finished-not-built kind") becomes untrue for a Stale (no data yet) published row, so update it in the same change. |
| 10 | **Published, no kind, state unknown** (not read, or the read failed) | **`KCS12-PUBLIC-UNKNOWN`** | **changed** (was `KCS12-PUBLIC`) |

**Un-built `finished` with no kind.** On an unpublished row this cannot occur: `uncomputedNote` always
passes `jobsFinished: state?.state === "finished"`, so a finished unpublished row takes
`finished_not_built` (row 3). Every other path into row 6 already carries a kind from the probe. The
only kindless `finished` row is a **published** one. Today its state is `null` (167.2-REVIEW IN-04),
so it gets row 10. When §1.5 supplies its state, it gets row 9.

`KCS12-MINT-B` is **retired**. No render path may produce its sentence after PR-1. Whether the
`MINT_TOKEN_NOTES.not_available` key is deleted, or kept for type totality and never rendered, is the
planner's choice. The grep invariant in the Test Contract decides it either way.

### 1.2 Composition: the lead sentence, then the remedy

```
note = LEAD(mode) + " " + ACTION_SENTENCES[actionId].sentence
```

- `LEAD("mint-token")` = `KCS12-MINT-B-LEAD`: the arm's first sentence with `yet` removed. This is the
  same edit 170.1 D-08 made for `finished_not_built`.
- `LEAD("public-url")` = `KCS12-PUBLIC-LEAD`: same treatment.
- The second part is the vocabulary sentence, verbatim. A note has **no third sentence, no reason
  clause and no "no computation is running"**. That phrase is the Health detail's fact, and it would be
  false beside a Health word of `Updating` (UI Considerations, unresolved row).

Every composed sentence is written out in the Copywriting Contract, one KCS12 row per mode and action.

### 1.3 Which action (the same rule the Health detail uses)

```
remedy   = ownerRemedy(state, shape, strategyId)          // no build facts, as strategies.stale-no-data
actionId = viewerRemedyAction({ remedy, managerSurface: isManager, shape })
shape    = shapeOf(s, compositeHistory)                    // the page's resolveStrategyShape wrapper
```

- `state` and `compositeHistory` come from the row's **one** jobs read: `armOf` for an unpublished row,
  `failedFactsOf` for a published one (§1.5). Neither path adds a second read.
- **The viewer mapping is required.** The share note renders for every role (`noteFor` is every role's,
  Phase 199 D-02). The edit page and the CSV wizard are manager-guarded, and `viewerRemedyAction` is
  what keeps an allocator-only viewer from being sent there (199 CD-11). Raw `ownerRemedy` is never used
  on `/strategies`.

Resulting action per state, shape and viewer:

| State (`stateLineKeyOf`) | Shape | Manager or `both` | Allocator only |
|---|---|---|---|
| `failed_permanent` | any | `A-CONTACT-RESOLVE` | `A-CONTACT-RESOLVE` |
| `failed_transient` / `_orphaned` / `_unknown` / `_other`, `stalled`, `never_started` | `single` | `A-RESYNC-EDIT` | `A-EXCHANGES-KEY` |
| same | `unlinked` | `A-LINK-KEY-EDIT` | `A-CONTACT-CHECK` |
| same | `composite` | `A-COMPOSITE-CONTACT` | `A-EXCHANGES-KEY` |
| same | `csv` | `A-CSV-FIXED` | `A-CONTACT-CHECK` |
| same | `unknown` (the member read failed; or no member and no key while the composite history is `seen` or `unreadable`, an `unreadable` history being a non-exhaustive jobs read) | `A-RELOAD` | `A-RELOAD` |

**Parity invariant (G3).** On a row whose Health is `Stale (no data yet)`, the note's action id equals
the `strategies.stale-no-data` detail's action id, because both lines run this computation on the same
inputs. A test pins it (Test Contract 4).

### 1.5 The published row's note (PUBLIC_URL_NOTE)

**Decided here (CONTEXT, Claude's Discretion: "whether PUBLIC_URL_NOTE takes a state-free action
sentence or the published path reads the state").** Recommendation: **use the state where the page
already read it, and a state-free sentence everywhere else. Add no jobs read.**

- `failedFactsOf` already reads the jobs of every published row whose Health is `Analytics failed` or
  `Stale (no data yet)`. For those rows the note takes its state from that read (rows 7 to 9 of §1.1).
  `armOf` keeps returning `state: null` for a published row, so IN-04's removed RPC stays removed. The
  planner orders or memoises the two so that the note reads the same promise. Today `shareNotes` is
  built before `failedFacts`.
- A published row whose Health is `Updating`, `Key problem`, `—` or `Healthy` has no jobs read. Its
  state is unknown, and it takes `KCS12-PUBLIC-UNKNOWN` (row 10). So does a read that failed (state
  `unreadable`).
- **Why not read the jobs for every published uncomputed row.** It would reverse IN-04 for a value the
  state-free sentence already answers truthfully, and it would move the `D-08 PUBLISHED-FINISHED` zero-RPC
  pin. With this recommendation that pin keeps `rpcCalls === []` and only its expected sentence is
  re-pointed.

`KCS12-PUBLIC-UNKNOWN` passes the three tests a state-free sentence must pass:

1. It is true whether or not a computation is running ("If no computation is running, …").
2. Its action is open to every shape and every role: the contact form opens for all of them.
3. It does not offer a reload, because a reload re-reads nothing on this path.

It contains no `yet` and does not promise that the numbers will appear.

### 1.6 Overlap with the Health detail on the same row

**When both lines render.** Only on a row whose Health is `Stale (no data yet)`: a missing analytics
row older than the computing window. A `pending` or `computing` embed reads `Updating` and gets no
detail. A key-problem row gets key lines instead, and an archived row gets none. On those rows the
note is the **only** line that names the action, so the note always carries the action itself. It
never depends on whether the detail rendered.

**How the pair avoids reading as a duplicate.** Each line opens with its own fact, as on the
`Analytics failed` rows that already ship. Those rows print the detail ("The last computation … did
not produce figures. Use the contact form to have it resolved.") above the note ("… opens a page
without its factsheet. Analytics are not available for this strategy. Use the contact form to have
it resolved."). This phase applies the same rule:

```
No figures yet, and no computation is running. Start a new computation with Resync on this strategy's edit page. Use the contact form if it does not complete.
Right now, a private link to this strategy shows that its factsheet is not available. Start a new computation with Resync on this strategy's edit page. Use the contact form if it does not complete.
```

The detail states the strategy's condition. The note states what a recipient of the link sees. The
shared closing sentence is one action reached from two facts, not a second fact. The 199 rule "one
fact, one sentence" concerns naming a key twice and is not engaged. Neither line is shortened or
hidden based on the other. A conditional variant would double the copy table and its tests in exchange
for one fewer repeated sentence. It also breaks the TODOS closing condition, which asks for a note per
state that names the action.

## 2. PR-2 (FACT-03): a NULL `computed_at` renders no date

### 2.1 Invariants

- **N1.** NULL means "never computed". A row nothing has computed carries NULL. Every write that stores
  figures stamps the date. The PR-2 census must check this at the INSERT sites, because one of them can
  write a `complete` row without the column. `sync_strategy_analytics_status`'s no-existing-row arm
  inserts `VALUES (p_strategy_id, 'complete', NULL, …)`, and after `DROP DEFAULT` that row carries
  NULL. The surfaces below must render correctly even if such a row is built.
- **N2.** A NULL date renders as **no date**: no `timeAgo`, no `formatDay`, no `1970`, and no
  placeholder sentence where a sentence used to carry the date. Where a labelled value cell must show
  something, the cell shows the DESIGN.md null rule `—`, uncoloured.
- **N3.** A NULL date is never fresh. Every freshness reader treats it as `stale` (`computeFreshness`)
  or as zero freshness (`freshnessScore`). That is already true of each, and PR-2 pins it.

### 2.2 Surfaces that render a `strategy_analytics.computed_at` date, and their NULL rendering

Measured with `grep -rn "computed_at\|computedAt" src --include='*.tsx'` at `fcc2bee63`, then
classified by the table each read comes from.

**Character rules** (following `status-surface-copy.ts`). ASCII apostrophes U+0027, sentence case, a
full stop at the end, no date and no duration. The one non-ASCII character is the `…` inside
`Change key…` (U+2026), which is the shipped button label quoted verbatim by `A-LINK-KEY-EDIT`. Grep
invariants: no new row contains `yet`, `once a computation succeeds`, `appear there` or `wait`. The 16
lead-plus-action rows also never contain `no computation is running`. `KCS12-PUBLIC-UNKNOWN` is the
one row that uses that phrase, and only as the condition "If no computation is running", because its
state is unknown.

**Why these words.**
- The lead keeps the first sentence the recipient-facing note always had, minus `yet`. `yet` promises a
  change on its own, and 170.1 D-08 removed it from `finished_not_built` for the same reason.
- The action is the remedy itself (founder ruling (a)). It is the same words the Health detail and the
  owner page's KCS-09 remedy already use, so the product names one action one way.
- `KCS12-PUBLIC-UNKNOWN` conditions its action on the one fact it cannot see ("If no computation is
  running"). It points at the one remedy open to every viewer and shape. It promises nothing and
  offers no reload that would change nothing.

## Accessibility

- **Contrast.** Muted `#64748B` is 4.76:1 on `#FFFFFF`, AA at 12px. The accent link `#1B6B5A` on
  `#FFFFFF` is the shipped link pair. It is underlined, so it does not rely on colour (WCAG 1.4.1).
- **Link names.** Each note has at most one link, and its accessible name is its phrase (`edit page`,
  `contact form`, `upload a new CSV strategy`, `Exchanges page`). The sentence around it gives the
  context. This matches the Health detail. When both lines render, two links with the same name and
  target sit in one row note. The same is already true of shipped `Analytics failed` rows, and axe
  `best-practice` passes on them today.
- **No live regions** (G4). Server-rendered, static. No `role`, no `aria-live`.
- **Reading order** equals DOM order equals visual order: review feedback, key lines, Health detail,
  share note (199 D-06).
- **axe.** `/strategies` and `/factsheet/[id]` stay in the app-wide axe matrix (`wcag2a`, `wcag2aa`,
  `best-practice`) with zero violations.
