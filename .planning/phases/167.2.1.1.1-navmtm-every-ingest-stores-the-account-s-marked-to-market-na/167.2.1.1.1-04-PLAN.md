<objective>
CONTEXT D-02: "Derive, daily for every key (Recommended). The mark comes from the equity read the derive already makes,
with no extra venue calls. Every active key gets a daily derive or mark whether it traded or not. Today a strategy
derive is queued only after new trades (`analytics-service/routers/cron.py`)."

RESEARCH section 3 measured that the key-mode fan-out (`derive-allocator-key-dailies`) already derives every eligible
key daily, so every key will get its mark from plan 06's writer. The gap is the strategy return series: `cron_sync`
queues a strategy derive only when that strategy stored new trades, so a quiet strategy's factsheet is never recomputed
and never reaches its latest mark (Pitfall 5). This plan closes that gap in `cron_sync` and nowhere else.

Purpose: SC-2's "the strategy return series ... use the stored marked NAV for every day it exists" needs a daily
strategy derive; SC-1's daily write for strategy-backing keys comes from the same derive.
Output: the changed recompute list and its tests.
</objective>
