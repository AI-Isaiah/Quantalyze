# Phase 167.2.1.1.1 Plan 12: NAVMTM key mode - the allocator curve uses the stored marks and the compose reproduces them

**From the first stored mark on, a key's derive persists the marked returns and a key_inputs row that describes the marked series (terminal, writer basis, flows, anchor), so My Allocation's compose rolls back from the last stored mark and lands on every stored NAV; a derive that cannot apply a stored mark refuses by name and writes nothing.**

## What was built (`run_derive_broker_dailies_job`, `analytics-service/services/job_worker.py`)

- **One seam, both modes.** The apply seam plan 07 placed above the `<2`-day short-circuit, the MT5-12 verdict seam and every csv write now also runs in key mode (`_returns_are_allocated` is always False there). A refusal therefore returns before any write, exactly as in strategy mode. `_stored_marks` is read once and kept for the epilogue.
- **Inputs per venue in key mode.** ccxt and sFOX reuse plan 07's branch (terminal `equity - open_unrealized_usd` on the last return day, flows summed per day). MT5 and Deribit are handed the quantities their key-mode builder already computed: `_realized_terminal`, the composed flows and the writer day P&L (`_composed_day_pnl_usd`, else `_day_pnl_usd`), with the roll on the writer's identity (`roll_basis="day_pnl"`). A key with no writer basis (a BTC key with an interior unpriced hole) falls back to the returns roll.
- **Coherence block (Pitfall 4)**, right after the apply, from the one `apply_marks` result: `_realized_terminal = (last mark day, its stored nav)`; `external_flows` loses the flows dated after the last mark (`held_out_flow_days`); for a writer basis the day P&L is the pre-start values joined with `writer_day_pnl`, the composed flows are cut at the last mark day; a native-unit key's `priced_through` moves to the last mark day.
- **W7 anchor** in `_run_key_mode_compose_epilogue`: when `_applied_marks.terminal[0]` equals `mark_day_for(_mark_read_at)` and a stored mark exists for that day, the anchor basis is its `nav_usd`, the read-failure arms (`balance_error`, `native_unpriced`) are skipped, the value arms judge the stored value, and `anchor_asof` is the mark's `marked_at`. Otherwise nothing changes.
- **Additive key_inputs fields** (present-only, 167.1.2.2 D-15 voice): `marks_since`; `mark_gap_days` and `mark_flow_read_days` when non-empty.

## Per venue: what feeds the compose

| Venue | Terminal (day, level) | Flows | Writer basis | Anchor |
|---|---|---|---|---|
| OKX, Bybit | last mark day, its stored nav | event-time flows, cut at the last mark | none (replay rolls through the stored returns) | the stored mark of the label day |
| sFOX | same | same (the series' own flows) | none | same |
| MT5 USD | same | event-time flows cut; composed flows cut | pre-start deal-ledger day P&L + marks' level identity (M_d - base - F_d; 0.0 on a flow-carrying gap day) | same |

The anchor-versus-last-mark residual is zero whenever the last day is marked (W7): every roundtrip test asserts the compose's last level equals the stored mark, including the cases where the derive's own live read differs. Where the last day has no mark (today's mark refused), the residual is the move between the two reads, left for MARKSOURCE (L5).

## Info 2: every reader of `anchor_usd` was checked, none needs a change

- The allocator compose (`anchors_by_key`, the departed-key path, the 166.3.1 D-08 no-capital rule) wants the last measured level and the no-capital reasons; the stored mark gives the former and the same ladder gives the latter.
- `equity_reconstruction._polled_empty_since` compares `anchor_asof` with the holdings poll's time. A stored anchor carries its own `marked_at`, so a positive stored mark read before an empty poll is neither proof nor contradiction (pinned by `test_stored_mark_anchor_is_no_empty_poll_proof`; with the derive's wall clock instead the same payload logs the false contradiction WARNING, drill D-AS).
- `src/lib/departed-history.ts` `departedAnchorOf` and `scripts/accounttruth-census.mjs` count a finite `anchor_usd` as anchored (read, not changed).
- The comments in `realized_terminal_payload` and `native_nav` that call `anchor_usd` the live equity describe the measure (equity including open uPnL); the stored mark is that same measure (L4).

## Deviations from Plan

**1. [Rule 1 - tests encoding superseded key-mode behaviour] Seven existing plan 06 and 15 tests changed (three files outside the plan's list).** Their fixtures store a mark through the real writer in key mode, which the key-mode derive now reads back and applies in the same run. That is the intended behaviour, and it changes what those tests observed: the terminal (`realized_terminal_usd` is the mark, not the realized value), the persisted series (a mark row instead of a realized row), the `<2`-day short-circuit (the mark adds a row), and, over fixtures with no ledger terminal (Deribit stub ledger, a BTC ledger priced on one close), a named refusal. Their subject is the mark's own write, so they now read no stored mark back through a new helper `marks_not_applied()` in `test_nav_marks_writer.py` (a patch of `read_key_marks` to `[]`): `test_idle_key_short_circuit_still_writes_its_mark`, `test_okx_nav_minus_open_is_the_realized_terminal_the_derive_stores`, `test_mt5_usd_key_derive_marks_equity_with_open_profit_and_the_balance_identity`, `test_mt5_btc_account_is_priced_at_the_closed_days_close_in_both_modes`, `test_deribit_key_derive_marks_the_collapsed_equity_with_its_per_currency_detail`, and the Deribit block of `test_okx_deribit_mt5_sfox_make_no_added_call`. `test_realized_series_is_unchanged_by_the_l4_read` keeps its combine-argument equality and now states the new fact: ok and skipped runs persist the same marked rows, and the days before the first mark equal the run that stored no mark. The plan's acceptance line ("tests diff lists only the new module") therefore does not hold; every change is a wrapper or an assertion that follows the new behaviour, and the apply itself is covered by the new module and plan 07's.

**2. The plan text is inconsistent about the gap-day flag, and the "live read 0.0" case cannot exist on OKX.**
- A gap day carrying a flow has a level (the compose's flow-day union), so it does not raise `missing_return_inside_coverage`; a flow-free gap day does, and only when another key trades that day (a sole key's book has no such day). The OKX scenario therefore has two gap days (03-08 with the deposit, 03-09 without) and the flag is asserted beside a sibling key.
- An OKX terminal is `equity - upl`, which needs a usable equity (plan 07's rule), so a live read of 0.0 refuses by name and never reaches the anchor. `test_stale_last_mark_does_not_anchor` therefore refuses today's mark with `upnl_unreadable` and a healthy live balance (anchor = the live read, not the stale mark); the plan's literal case (live zero, anchor None `nonpositive`) is `test_stale_last_mark_does_not_mask_a_live_zero` on Deribit, whose terminal comes from the ledger. Drill D-ST goes RED on both.

## Findings (recorded, not fixed)

- **Plan 07's OKX scenario with a flow loses its pre-start days to the wall clock.** `run_ccxt("okx")` passes a March flow while the DQ-02 retention terminus reads `datetime.now`, so every pre-start row is NaN'd (measured: persisted rows were only the two marked days). Its SC-3 roll test is unaffected and its pre-start assertion is made for Deribit only, so nothing fails. This module pins `flow_coverage_terminus_day` off in its ccxt harness for that reason.
- **A key-mode derive whose live equity is unusable, with stored marks, now refuses (no key_inputs row, no csv write).** Same rule as plan 07's strategy mode (no realized terminal, no marked series). The previous key_inputs row and series stay what the compose reads until the next healthy derive; before this plan the same read wrote a null anchor and the compose degraded to the legacy curve. Worth a founder look.
- **A BTC key whose USD series has an interior unpriced hole dated after the first mark** keeps its `unpriced_days` and `segment_terminals`, which describe realized levels; the compose then reports `key_inputs_mismatch` (blocking, loud) for it. Not handled: the marks cover those days, and no test fixture builds the case.
- **The stored-value arms of the anchor ladder (nonfinite, nonpositive, dust, flow_drop) are structurally unreachable for a stored mark** (the writer refuses those values), kept so the ladder stays one rule; they carry no test of their own.
- Held-out flows: the deposit dated the read day is left out of this derive and enters the next one. The day-granular flow limits of plan 03 (OQ-8) apply unchanged.
