# Phase 167.2.1.1.1 Plan 15: NAVMTM Bybit/Binance marked-equity read Summary

Every Bybit and Binance derive now stores the key's marked NAV as the reconstruct anchor reads it (all-asset wallet plus summed position open profit, with the forced path's refusals), at most once per key per UTC day, and refuses the mark whenever it would book anything but open profit as the first marked day's return.

## What was built

- `equity_reconstruction.py`: `_AnchorPartialSet.wallet_total_usd` (set at the one assignment `_wallet_total = total`; nothing else in `_fetch_current_equity` changed, no line removed) and `read_marked_equity_usd`, placed directly after it. It calls `_fetch_current_equity(exchange, venue, refuse_unread_positions=True)` once. Tokens: `ForcedRebuildRefusedError` -> `positions_unreadable`; no total or no wallet total -> `balance_error`; a non-empty partial-unpriced set -> `wallet_unpriced`. Otherwise `(total, total - wallet, wallet)`. It raises `ValueError` for any venue but Bybit/Binance.
- `nav_marks.py`: `MARKED_EQUITY_VENUES`; `build_mark_read(marked_equity=..., usdt_wallet_usd=...)`. A tuple supplies `equity`, `open_pnl` and the marked wallet; a string is the refusal. `wallet_basis_mismatch` when `abs(marked_wallet - usdt_wallet) > max(_BYBIT_UPNL_TOLERANCE_USD, _BYBIT_UPNL_TOLERANCE_REL x |usdt_wallet|)`, judged after the finite check (a NaN wallet is `nonfinite`, never a silent pass) and before `nonpositive`/`dust`. A missing derive wallet is `balance_error`. A caller's refusal token with no figures is now returned as itself (before, an absent `equity` read as `balance_error`, which would have swallowed `positions_unreadable`).
- `job_worker.py`: `_read_marked_equity_once_per_day` (module level). It reads `read_stored_mark` for (key, `mark_day_for(_utc_now())`) FIRST; a hit returns the row and makes no venue call (W3). Otherwise it runs `read_marked_equity_usd` under `asyncio.wait_for(..., _BROKER_CRAWL_TIMEOUT_S)`; a timeout or any exception the wrapper did not tokenise is `positions_unreadable`, logged with the exception class only. The ccxt branch calls it for `venue in MARKED_EQUITY_VENUES` right after the derive's own equity read and before the trades crawl, and `_mark_read_at` is re-stamped when the read returns. The convergence-point writer returns a pre-read row untouched, and for a fresh read builds the mark from `marked_equity` with the derive's own `equity` (its realized USDT wallet) as `usdt_wallet_usd`.

## The ccxt default-request finding (read_first)

Read from the installed ccxt **4.5.85** sources in the venv. `requirements.txt` pins **4.5.88**, so this is the 4.5.85 reading: re-read `bybit.fetch_positions` and `binance.fetch_positions_risk` when the pin moves. The wrapper's docstring records this.

- `bybit.fetch_positions()` with no arguments: loads markets if needed, then ONE `privateGetV5PositionList` with `category=linear`, `settleCoin=USDT`, `limit=200`, no pagination (`paginate` defaults False). The linear USDT book only: USDC-settled and inverse positions are not in it, and Bybit's own `totalPerpUPL` cross-check inside the anchor is what refuses an account that holds them.
- `binance.fetch_positions()` with no arguments: `positionRisk`, which is `fetch_positions_risk` for the linear USD-M book (one request after `load_markets` and `load_leverage_brackets`, which ccxt caches per exchange object, so a fresh per-job exchange pays them once).

## D-16 accepted call count, per Bybit/Binance key per UTC day

One `fetch_balance()`, one `fetch_positions()` and one `fetch_ticker("<ASSET>/USDT")` per held asset that is neither a stablecoin nor an extra-stablecoin suffix, on the first derive of the closed day. Every later derive of that key that day makes none of them (W3). The derive's own `fetch_account_equity_and_upnl_usd` read is separate and unchanged (so the derive makes two `fetch_balance()` calls on the first derive of the day). OKX, Deribit, MT5 and sFOX make no added call (pinned by `test_okx_deribit_mt5_sfox_make_no_added_call`: the OKX venue object fails on any attribute access, and the other three run with spies on `read_marked_equity_usd` and `read_stored_mark`).

## Plan 11's pre-merge dry run: the exact call sequence

Per active Bybit or Binance key, read-only, from the phase worktree's `analytics-service/` with the main checkout's venv, on a ccxt exchange built the way the derive builds it. In this order, which is the derive's order:

```python
from datetime import datetime, timezone
from services.equity_reconstruction import read_marked_equity_usd
from services.exchange import fetch_account_equity_and_upnl_usd
from services.nav_marks import build_mark_read

# 1. the derive's own USDT wallet figure (the level its realized series is anchored on)
usdt_wallet, balance_error, _wedge, upnl_unreadable = await fetch_account_equity_and_upnl_usd(exchange, venue)
# 2. the anchor-style marked read (the L4 read)
marked = await read_marked_equity_usd(exchange, venue)      # tuple, or a refusal token
# 3. the shipped rule on both: a MarkRead, or one token from MARK_REFUSAL_TOKENS
built = build_mark_read(
    venue=venue, marked_at=datetime.now(timezone.utc),
    equity=None, open_pnl=None,
    balance_error=balance_error, upnl_unreadable=upnl_unreadable,
    marked_equity=marked, usdt_wallet_usd=usdt_wallet,
)
```

`built` being a `str` is the refusal token to count (`wallet_basis_mismatch`, `wallet_unpriced`, `positions_unreadable`, `balance_error`, others); a `MarkRead` is a key that would be marked. Nothing is written: no `write_nav_mark`, no database call. For the page-limit count plan 11 asks for, add one separate `len(await exchange.fetch_positions()) >= _POSITIONS_PAGE_LIMIT` (import it from `services.equity_reconstruction`); that is an extra read that is not part of the shipped rule. `tests/test_nav_marks_l4_read.py::test_the_dry_run_sequence_reaches_the_verdict_the_derive_stores` runs this exact sequence (`_dry_run_one_key`) beside the derive and asserts the verdicts agree for a markable and a mixed-basis key.
