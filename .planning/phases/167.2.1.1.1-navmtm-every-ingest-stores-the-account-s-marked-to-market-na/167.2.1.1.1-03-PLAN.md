## The interface this plan fixes (plans 07, 08, 09, 12, 16 and 17 call it; do not rename)

`services/nav_marks_apply.py` (pandas + stdlib + typing only; no Supabase, no network, no logging of amounts):
- `MARK_APPLY_REFUSAL_TOKENS: Final[frozenset[str]]` = the five tokens in the must-haves.
- `class MarkApplyRefusal(ValueError)` with attribute `token`; `str(exc)` is `"mark apply refused (<token>)"`.
- `class AppliedMark(NamedTuple)`: `day: str` (ISO mark_day), `nav: float` (the stored NAV in the series' unit).
- `class MarkedSeries(NamedTuple)`: `returns: pd.Series` (same index dtype as the input), `marks_since: str | None`,
  `mark_gap_days: tuple[str, ...]`, `mark_flow_read_days: tuple[str, ...]`, `held_out_flow_days: tuple[str, ...]`,
  `marked_levels: dict[str, float]`, `writer_day_pnl: dict[str, float]`, `terminal: tuple[str, float] | None`,
  `covered_from: str | None`, `covered_days: tuple[str, ...]`.
- `def apply_marks(returns: pd.Series, flows_by_day: Mapping[str, float], realized_terminal: tuple[str, float] | None,
  marks: Sequence[AppliedMark], *, day_pnl: Mapping[str, float] | None = None,
  roll_basis: Literal["returns", "day_pnl"] = "returns") -> MarkedSeries`.

The rule (RESEARCH 5.1, D-05 as revised; the numbered items are what the tests pin):
1. `marks` empty: `returns` comes back equal (values, index, NaN), every other field empty or None.
2. S = the first mark day. Days before S keep their input value exactly.
3. L_real(S-1): `realized_terminal = (E, T)` must name the input's last index day (else `mark_terminal_day_mismatch`;
   an empty input takes `realized_terminal` None). If E < S, L_real(S-1) = T plus any flows dated in (E, S-1]. If
   E >= S, roll back from E to S-1 by the compose convention, `L(d-1) = (L(d) - F_d) / (1 + r_d)`; a day in that span
   whose return is NaN uses `day_pnl` when it holds the day (`L(d-1) = L(d) - P_d - F_d`), otherwise
   `mark_base_unrollable`. A day absent from the input inside the span is `r = 0` with its flow (HIGH-1 convention).
3b. `roll_basis="day_pnl"` (D-14, the allocated-capital input): `day_pnl` is required (absent or empty is
   `mark_base_unrollable`) and `realized_terminal = (E, T)` must name day_pnl's LAST day (else
   `mark_terminal_day_mismatch`); the input returns are never read for the base. If E < S, L_real(S-1) = T plus any
   flows dated in (E, S-1]. If E >= S, `L(d-1) = L(d) - P_d - F_d` for every day d of (S-1, E], a day absent from
   day_pnl being `P = 0` with its flow. Rules 4-14 are unchanged (the output still keeps every input day before S and
   still emits only mark days from S on).
4. If no input day precedes S (empty input, or the input starts on or after S), S has no base: no row on S, its level
   is still pinned, and the next mark chains from it.
5. For mark d with previous mark p (or S-1 for S) and gap days G strictly between them:
   `base = level(p) + sum(F_g for g in G)`, `r(d) = (M_d - base - F_d) / base`; base <= 0 is `mark_base_nonpositive`.
6. Output index: input days before S, then exactly the mark days that have a return. Gap days and every realized
   input day on or after S are absent.
7. `mark_gap_days`: unmarked calendar days strictly between S and the last mark day, ascending.
8. `writer_day_pnl`: for each marked day with a return, `M_d - base - F_d` (the level identity), and `0.0` for every gap
   day carrying a flow (the compose steps the level by the flow there).
9. Flows dated after the last mark day are in no base and no numerator: their days are listed in `held_out_flow_days`
   (the caller keeps them out of this derive's stored flows window; the next derive places them).
10. `mark_flow_read_days`: mark days d where a flow is dated d + 1 (the read day, since a mark is read on the UTC day
    after its label): named, arithmetic unchanged. (A planner decision recorded here: a flow dated the read day may be
    inside the read; flows carry days only, so it cannot be placed by instant. The founder sees it in the phase summary.)
11. `marked_levels`: every mark day -> its nav. `terminal`: (last mark day, its nav).
12. A non-finite nav, flow, P&L or terminal is `mark_input_nonfinite`; mark days not strictly ascending and unique is
    `mark_days_not_ascending`.
13. `covered_from`: the first day whose absence is covered by a mark's return rather than refused: the day after the
    last INPUT index day (a NaN day included) before S, or S itself when no input day precedes S; None without marks.
    Plan 07 stamps it, so the runner (plan 08) never re-derives it from stored rows (which lack the NaN days and would
    move the boundary).
14. `covered_days`: every calendar day from `covered_from` through the last mark day that has no output row, ascending
    (it contains `mark_gap_days` and the quiet days between the last pre-start day and S). Callers pass it as
    `covered_days` to `derive_basis_series` (Task 3).

Facts measured at plan time (HEAD b1291a7e1): `derive_basis_series` accepts `densify_policy` in
`_ALLOWED_DENSIFY_POLICIES` and computes `gap_spans` from every absent day in `[min, max]` of the sparse rows; no
tracked file names `apply_marks`, `nav_marks_apply` or `covered_days` (baseline 0 each).
