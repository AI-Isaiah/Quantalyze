# Phase 167.2.1.1.1 Plan 08: NAVMTM compute half Summary

The analytics runner now reads the marks boundary the derive stamps, stops turning a day a later mark's return covers into a NaN chain break, and publishes the date real marks begin.

## What changed

`run_csv_strategy_analytics` (`analytics-service/services/analytics_runner.py`):

- `existing_flags` is read above the broker dense reindex (a pure read of the same row; nothing between the two positions writes it).
- `_read_navmtm_flags` validates the four prestamp keys once (exact `YYYY-MM-DD` real calendar date, the snapshot-rebuild-boundary rule; a list must be all valid dates). A malformed key is dropped with `csv analytics: NAVMTM flag <key> is malformed (<reason>) for <strategy>; not carried`; the value is never logged.
- With a valid `marks_covered_from`, only rows dated before it are re-densified; rows on or after it are used as stored. Without one the reindex is the old code path unchanged.
- `covered_days` = every absent calendar day of the loaded span on or after the boundary, passed to `derive_basis_series`. `None` (no boundary) is byte-invisible.
- `marks_since`, `marks_covered_from`, `mark_gap_days`, `mark_flow_read_days` are carried present-only beside `native_unit`, outside both `_warned` loops, and typed in `DataQualityFlags`. None is a member of `NAV_TWR_GUARD_KEYS` or `ALLOCATED_CAPITAL_GUARD_KEYS` (a test pins that), so none can promote `computation_status`.
- The simple-sum rule (D-14) needed no runner change, as planned. `test_simple_sum_rule_published_for_a_configured_strategy` pins the published figure. No `marks_not_applied` key exists anywhere.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pre-start reindex is not clipped to the last stored pre-start row**
- **Found during:** Task 1 design, against `nav_marks_apply` rule 13.
- **Issue:** The plan wrote "reindex dense over `[min, the day before marks_covered_from]` clipped to the last such row". `covered_from` counts a NaN INPUT day, so a refused day immediately before marks start sits before the boundary while no stored row follows it among the pre-start rows. Clipping would leave it absent, outside `covered_days` (it precedes the boundary), a gap span but not a NaN, and the chain would bridge it: the DQ-03 bridging the reindex exists to forbid.
- **Fix:** with rows on or after the boundary the dense span ends at the day before it; with none the span ends at the last stored row as it always has. `test_trailing_refused_pre_start_day_still_breaks_the_chain` pins it (headline_since 2026-03-06, gap span for 03-05) and D-G2 turns it RED.
- **Files modified:** analytics-service/services/analytics_runner.py
- **Commit:** 1c56c7aef

### Plan-text adjustments (no behaviour change)

- The runner does not itself raise `twr_chain_broken` (it only bridges the derive's prestamped copy), so the chain-break observable at runner level is `headline_since`. The guard test prestamps `twr_chain_broken` and asserts it is carried; the gap test asserts it is absent.
- The simple-sum test sums seventeen returns (fourteen pre-start days, three marked rows), not eight, to give the real compute a series long enough; the assertion is the same (sum of every stored row, differs from the compounded figure by more than 1e-6).
- The commit-protocol agent-branch allow-list was not applied: this is the orchestrator-designated worktree on branch `feat/167.2.1.1.1-p08`, not an agent-isolated branch, and the protected-branch check passed.
