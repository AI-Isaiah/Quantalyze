# Phase 153.6 Plan 05: Cluster B's remaining absorption sites + the parity roster Summary

Our own abandoned threads stopped voting to trip `breaker:mt5-gateway`, stopped contaminating the recovery-latency population Phase 155 reads — and a hand-written fourth copy of the MT5 probe body now reds a guard that cannot go vacuously green per-file.

## What Was Built

### B2 — the stage-1 connect abandon arm (`routers/exchange.py:543`)

`Mt5Client.__init__`'s construction fence raises `Mt5SessionAbandoned("connect")` from **inside** the stage-1 connect `to_thread`. The dedicated D-40 arm added in 153.5 sits on a **different `try`** (stage 2, the probe), so the fence landed in `except Exception as connect_err:` and was answered **503 `MT5_GATEWAY_UNREACHABLE` with `dependency="mt5-gateway"`** — one of exactly three sites that COUNT toward the breaker. A fault that is our own zombie thread, and that the very next request clears by taking a fresh lease, was casting votes to trip the breaker against a healthy gateway.

New arm placed exactly between `except asyncio.TimeoutError:` (:532) and `except Exception as connect_err:` (:593), byte-mirroring the stage-2 disposition: WARNING naming the decision only, `trace.outcome = "transient"`, `VenueTransientHTTPException(424, "NETWORK_UNAVAILABLE", NETWORK_ERROR_DETAIL, recoverable=True)`. No new user-facing code minted. Stage-2 arm untouched.

### B3 — `_timed` suppresses the stage event for fence refusals (`services/mt5_client.py:793`)

`restart()`'s check 2 is the one fence that raises from **inside** the `_timed` bracket, and it has to: three cleanup invariants must run before its raise, so it is written inline rather than via `_assert_live`. `_timed`'s `except BaseException` therefore emitted `{'stage': 'restart', 'duration_ms': 0, 'ok': False, 'error_class': 'Mt5SessionAbandoned'}` for a restart that deliberately did nothing — dragging measured recovery latency toward zero exactly when abandonment is most frequent.

`except Mt5SessionAbandoned: raise` added ahead of the emit arm, carrying `_assert_live`'s own contract sentence verbatim (⛔ *"NOT a `mt5.stage` event… If a COUNT is ever wanted it needs a distinct event name"*) plus the two facts that make it safe: check 1 of `restart()` already sits outside the bracket for this reason, and the class is raised at exactly four sites, all our own fences.

**`restart()` is untouched — confirmed.** `git diff services/mt5_client.py` is `26 insertions(+), 0 deletions(-)`: the arm and its comment, nothing else. Pitfall P6 (the three interacting cleanup invariants at :1276-1295) was not approached.
