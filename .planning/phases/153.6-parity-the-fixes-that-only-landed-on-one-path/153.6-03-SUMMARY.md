# Phase 153.6 Plan 03: The venue lock, DB half — Summary

**`api_keys.attested_venue` now carries a venue only the two SECURITY DEFINER wizard RPCs can write, so the ASVS V4 scope-broadening probe gate stops taking a client-writable label as evidence — and `20260810120000`'s header stops claiming the bypass it left open was self-defeating.**

## Accomplishments

- **The forgery route is closed by removing the column's authority, not the client's write.** `attested_venue` is stamped inside both SECURITY DEFINER wizard RPCs from the `p_exchange` the server itself validated at mint time; a `SECURITY INVOKER BEFORE INSERT` trigger NULLs anything a non-privileged caller supplies. A DELETE + re-INSERT round trip therefore lands `NULL`, which the gate reads as PROBE. `INSERT`/`DELETE` stay granted (D-02/D-03) and no privilege statement appears anywhere in the file.
- **Both RPC re-bases are provably minimal.** `create_wizard_strategy` re-based on `20260602190000:62-157`, `add_wizard_composite_key` on `20260710180000:53-141` (both re-grepped as HEAD this session). A mechanical diff of each new body against its canonical `supabase/schema/functions/` dump shows *only* the `attested_venue` column + `p_exchange` value, plus the rationale comment. Both advisory-lock fences (`wizdraft:`, `wizcomposite:`) survive, and the migration's own post-verify aborts if either goes missing.
- **The backfill's premise is written down and enforced.** Census re-measured read-only against `khslejtfbuezsmvmtsdn` at 2026-08-11 ~20:05 UTC: **29 rows — deribit 13, okx 9, bybit 5, mt5 2**; both mt5 rows belong to **one owner** and were created **2026-08-04** (11:37 and 14:20 UTC). Identical to D-01d, and no unexpected mt5-labelled row appeared. The pre-flight pin passes exactly on that shape, **aborts** on drift-with-signature, and emits a NOTICE on a signature-free (non-PROD) apply.
- **The guard-that-cannot-skip problem is addressed in both directions.** The new column comment names `20260811210000` (assertion 5's gate); the `exchange` re-stamp preserves the `20260810120000` substring (assertions 2/3's gate); the migration asserts that substring survived; and the SQL test now asserts *positively* that the older marker is present whenever the newer one is — so a future re-stamp that drops it **fails** rather than going quiet.
- **`20260810120000`'s threat model now matches reality** and is calibrated as a self-targeted control bypass, not a breach.

## Decisions Made

1. **Census pin placed as pre-flight, before the backfill.** PATTERNS No-Analog #1 recommends framing the composed pin with `20260419140917`'s pre-flight/post-verify pairing; the counts it reads (`exchange` labels) are untouched by the backfill, so placement is presentational and the pairing convention wins.
2. **A fifth post-verify was added: RPC `EXECUTE` privileges.** The file deliberately issues no `GRANT`/`REVOKE` because `CREATE OR REPLACE FUNCTION` preserves the ACL. That is a *claim*; `has_function_privilege` turns it into an assertion, in the same self-verifying posture as `20260602190000` and `20260710180000`. (Deviation Rule 2 — see below.)
3. **UTC-anchored census signature.** `(created_at AT TIME ZONE 'UTC')::date` rather than `created_at::date`, so a session TimeZone difference cannot shift the discriminator's date. Measured timestamps (11:37, 14:20 UTC) sit mid-day, so this is belt-and-braces rather than load-bearing.
4. **The false sentence is paraphrased, not quoted.** Quoting it under a refutation would have left the falsehood greppable and quotable out of context — and would have failed the plan's own `grep -q "never be corrected back"` gate. Stated at the site.
5. **`20260810120000`'s `COMMENT ON COLUMN` SQL is left byte-unchanged.** Editing an applied migration's statements rewrites history rather than the database; `20260811210000` re-stamps the comment at apply time. A note above it says so.
