# Phase 153.6 Plan 06: the parse miss gets its Retry back — Summary

**A probe body our schema cannot read — what a half-rolled analytics deploy serves for the minutes between its first new pod and its last old one — now carries `KEY_SCOPE_CHECK_UNREADABLE` with honestly recoverable copy, while `KEY_SCOPE_CHECK_UNAVAILABLE` keeps its structural Retry suppression for the genuinely permanent probe-status arm; both `EXPECTED_TABLE_SIZE` pins were re-cut 74 → 75 and the three pins that prove this is a fix rather than an addition are grep-proven unmoved.**

## The defect, in one line

153.2-04 moved the parse miss off `KEY_NETWORK_TIMEOUT` on the reasoning that
the body *"stays unreadable until a deploy changes one side or the other"*. That
sentence is true — and it is satisfied by the deploy that is **already rolling**.
The destination code's copy holds no member of `RECOVERABLE_ACTIONS`, so
`buildEnvelope` derives `recoverable: false` and `ErrorEnvelope` renders no Retry
at all. The fix for one dead end built another one on the wizard's last step.

### Why the oracle is the TITLE and not the Retry control

`SubmitStep.tsx` records the KNOWN_FINALIZE_CODES trap three times already, and
every instance points the same way: an omitted member falls to `UNKNOWN`, and the
user sees a generic dead end instead of the remedy. **For this code it points the
other way.** `UNKNOWN`'s copy carries `clear_and_retry`, so it *is* recoverable
and *does* render a Retry. An assertion phrased "a Retry renders" would have
passed against a completely unwired code — right control, wrong reason, invisible
ship, every route-side test green. So `route.test.ts` pins the rendered title
against a hand-typed literal and explicitly `.not.toBe(UNKNOWN_TITLE)`.

This is not hypothetical: it is the **E-roster** mutation below, run and observed.

### Deviation: the prose figure is twenty-two, not twenty

The plan said re-cut *nineteen → twenty*. Re-deriving with the file's own scanner
(comment-stripped source, `emitterRe("[45]\\d\\d")`) measured **29 sites / 21
distinct codes BEFORE this change**, and 22 after. "Nineteen" was measured at
153.1-06 and was never re-cut when 153.2-04/05 put `SEAM_MISCONFIGURED`,
`RATE_LIMITED` and `DRAFT_STATE_INVALID` on the wire (`expectedSites` moved
25 → 27 → 29 and the sentence did not). Writing "twenty" would have re-published
a two-year-old drift as a fresh measurement — the exact defect class this phase
exists to close — so the figure was re-measured and the drift is noted at the
site. Nothing asserts the number; the cost of the old value was a false sentence,
not a false green, which is why it was worth re-measuring rather than
incrementing.
