The `[id]` / `(dashboard)` bracket-and-paren path segments in
`vitest.node-env.ts` were the one thing that looked like it could quietly
mis-glob (picomatch reads `[id]` as a character class). It does not: the node
project resolves **exactly 291** files against a 291-entry list, so every entry
matches its literal path, none is stale, and there are no duplicates.

The `vi.stubGlobal` conversions were checked for the second-order hazard rather
than just the pattern: the conversion makes a leaked stub *disappear before the
next test*, so any later test in the same file that had been silently riding the
leaked mock would now hit the real `fetch`. Traced all four multi-`describe`

genuinely closed rather than relocated — it is now unstubbed before the next
test, and the identical pattern at `ReplacementCard.test.tsx:288` is likewise a
stub now.

## Narrative Findings (AI reviewer)

### Warnings

#### WR-01: the retimed file is still order-dependent — its second test kept the 1000ms default for the same cold `next/dynamic` import

**File:** `src/app/(dashboard)/allocations/AllocationsTabs.scenario-state-preservation.test.tsx:422`

**Issue:** The fix raises the budget on the first `findByTestId` only:

```
341:    expect(
342:      await screen.findByTestId("kpi-strip-mock", undefined, { timeout: 10_000 }),
343:    ).toBeInTheDocument();
```

and justifies leaving the second one alone at `:336-338` — *"The second `it`
below needs no budget: by then the dynamic chunk is resolved in this file's
module registry."* That reasoning is correct **only while test 1 runs first**.
Line 422 is the identical cold-import wait on the default 1000ms:

```
422:    expect(await screen.findByTestId("kpi-strip-mock")).toBeInTheDocument();
```

Reproduced, not theorised:

```
$ npx vitest run 'src/app/(dashboard)/allocations/AllocationsTabs.scenario-state-preservation.test.tsx' -t "fresh draft"
 Test Files  1 failed (1)
      Tests  1 failed | 1 skipped (2)
```

versus the whole file, which passes in 4.29s. So the file's verdict still
depends on which of its tests ran — the same class of defect the change set out
to remove, half-removed. It is *not* a live CI break: shards split by file, both
tests always run in declaration order, and the full-suite and both-shard runs
above are green. It bites a developer running `-t` / `it.only` on the second
test, and it re-arms as a red CI the moment anyone `it.skip`s the first test
while debugging or splits the file.

**Fix:** give the second wait the same explicit budget, so the file stops
depending on its own execution order rather than depending on it more quietly:

```ts
// Same cold `next/dynamic` import as test 1 — do not rely on test 1 having
// warmed this file's module registry, or `-t`/`it.only` selection reds it.
expect(
  await screen.findByTestId("kpi-strip-mock", undefined, { timeout: 10_000 }),
).toBeInTheDocument();
```

(applies to both occurrences in that test, `:422` and `:434`).
