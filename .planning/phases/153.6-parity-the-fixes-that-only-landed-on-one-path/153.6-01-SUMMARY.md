# Phase 153.6 Plan 01: Cluster A + B1 — the shared MT5 probe body Summary

The three fixes 153.3 landed on `routers/exchange.py` and never on `services/ingestion/mt5.py` now exist on both paths *by construction*: one module, `services/mt5_probe.py`, both callers delegate to it, and the divergent copies are deleted.

## What Was Built

Lifted from the router (the correct twin), closures converted to module-level functions taking the client as a **parameter**. Import edges are exactly `services.mt5_client` and `services.mt5_validation` — AST-verified, zero edges to `routers.*` or `job_worker` (D-07).

**A2 + B1 as ONE edit (D-14).** The extracted `read_terminal` carries `except Mt5SessionAbandoned: raise` ahead of *both* sibling arms. Porting the router's broad arm to the worker without it would have imported B1 onto the worker path.

**A1** lands on the worker structurally: `run_probe` returns without calling `order_check` once `classify_trade_capability(info, {}, terminal) == "undetermined"`, POST login bracket still running.

**A3** — `services/ingestion/mt5.py`'s D-31 arm raises `Mt5GatewayMisconfigured` instead of a bare `RuntimeError`, and `classify_exception` gained one arm above the ccxt hierarchy returning `("permanent", MT5_GATEWAY_MISCONFIGURED_DETAIL)`.

### The exact curated message

```
MT5 gateway refuses automated trading (the 'Disable automatic trading through the
external Python API' option is in force), so read-only capability cannot be proven.
This needs an operator, not a retry — see docs/runbooks/mt5-go-live.md.
```

Contains no member of `_WRONG_SERVER_TOKENS` (`server`, `connect`, `ipc`, `network`, `terminal`, `not found`) or `_AUTH_TOKENS` (`authoriz`, `account`, `invalid`, `password`, `login`), and no credential word (`password`, `investor`, `master`, `secret`) — asserted against the **live** tables, so a token added to `mt5_validation` reds the guard.

## Deviations from Plan

**1. [Rule 3 — blocking] `run_probe` signature widened beyond the plan's sketch**
- **Found during:** Task 1
- **Issue:** the `<interfaces>` sketch gave `run_probe(client, *, login, log_prefix)`, but the body must call `client.login(login, investor_pw, server)`.
- **Fix:** added `investor_pw` and `server` keyword-only parameters. The plan explicitly delegated exact signatures to the executor ("keep parameters minimal and framework-free"); both stay plain strings, no framework types.
- **Commit:** `3535df3d`

**2. [Rule 3 — blocking] Router log prefix normalised**
- **Found during:** Task 2
- **Issue:** the router logged `validate_key: MT5 terminal_info unreadable (...)`; the worker logged `mt5.validate: terminal_info unreadable (...)`. One shared format string cannot reproduce both.
- **Fix:** adopted the RESEARCH reference implementation's `"%s: terminal_info ..."` with prefixes `validate_key` / `mt5.validate`. The router's line loses the literal `MT5` token. No test asserted on these strings (grep-verified across `tests/`, `services/`, `routers/`), and the message body remains MT5-specific (`terminal_info`).
- **Commit:** `489b9f05`

- Anticipated by the plan's ⚠️ instruction. Detail in *Pin Re-cuts* above.
