# Phase 164.6.6.3.5: DOMAINONE — one canonical address - Context

**Gathered:** 2026-10-07
**Status:** Ready for planning

<domain>
## Phase Boundary

Everyone lands on one address, `quantalyze.xyz`, and the product never points a user at
`quantalyze.com`, a domain we do not own.

**Measured 2026-10-07 (scout at `origin/main` `8edf78cf`, read-only DNS):**
- `quantalyze.com`'s MX is `mail02.max-recall.com`, with SPF on that host and DMARC `p=reject`. It is
  an unrelated company's mail server. Every message a user sends to an `@quantalyze.com` address
  (correlation ids, account details, security reports) reaches a third party. Outbound mail "from"
  `@quantalyze.com` would be rejected by its DMARC policy.
- `quantalyze.xyz` has NO MX, SPF, DMARC or Resend DKIM record. It can neither receive nor send mail.
- The ROADMAP's "18 mentions" was a reading. Outside `.planning/` and `CHANGELOG.md` the repo names
  `@quantalyze.com` addresses about 158 times (security@ 103, support@ 34, test@ 6, notifications@ 5,
  privacy@ 4, alerts@ 3, hello@ 2, founder@ 1), plus URL and host mentions in env defaults, host
  allow-lists, `public/.well-known/security.txt`, tests and docs. Re-count at plan time.
- The existing contact form (`RequestCallModal` → `/api/for-quants-lead`) writes to
  `for_quants_leads` and shows in the founder CRM. Its founder email notification is skipped when
  Resend is not configured, so the form works without any mail setup.

</domain>

<decisions>
## Implementation Decisions

### Contact (founder, 2026-10-07, AskUserQuestion)
- **D-01:** No contact email address anywhere in the product. The founder chose "No email: a
  contact form" over moving to `@quantalyze.xyz` with forwarding, and over a single founder-owned
  address. Every user-facing `security@`, `support@`, `privacy@`, `hello@` and `founder@` mention is
  replaced by a pointer to the contact form.
- **D-02:** Copy that tells a user to send a correlation id, draft id or diagnostics ("email
  security@… with the correlation id below") now tells them to use the contact form with that id.
  The form must be able to carry the id: a prefilled field from the link, or a field the user pastes
  into.
- **D-03:** `public/.well-known/security.txt` keeps a `Contact:` line (RFC 9116 requires one), as the
  https URL of the contact page instead of a `mailto:`. Its `Canonical`, `Policy` and
  `Acknowledgments` URLs move to `https://quantalyze.xyz`.

### Outbound mail (founder, 2026-10-07: "Dont want to setup resend")
- **D-04:** No Resend or mail-domain setup is done or booked. The sender defaults (`PLATFORM_EMAIL`,
  `RESEND_ALERT_FROM`, `notify-admin`) stop naming `quantalyze.com`. Code that sends mail keeps its
  existing behaviour when Resend is not configured (it skips). Nothing new is built to send mail.

### The redirect
- **D-05:** A request to the exact host `quantalyze-rho.vercel.app` (any path and query) gets a
  permanent redirect to the same path and query on `https://quantalyze.xyz`, measured live after
  deploy. Preview and per-deployment Vercel URLs are untouched, because preview deploys and CI checks
  use them. Re-measure at plan time which hosts those are.

### URLs, env defaults and allow-lists
- **D-06:** Every `https://quantalyze.com` fallback (`NEXT_PUBLIC_APP_URL` defaults in API routes and
  `email.ts`, `.env.example`, Plausible domain) moves to `https://quantalyze.xyz`. Host allow-lists
  (the factsheet PDF and tearsheet routes, `founder-lp-report`, the CSRF origin tests) drop
  `quantalyze.com` / `www.quantalyze.com`, and keep or gain `quantalyze.xyz`.
- **D-07:** Test fixtures that need an address use RFC 2606 names (`example.com`), never a real
  domain we do not own. That covers CI's `PLATFORM_EMAIL: test@quantalyze.com`.
- **D-08:** Docs and runbooks are corrected or the stale passage removed. `security-contact.md`,
  which describes provisioning `security@quantalyze.com`, is rewritten for the contact-form model.
  `.planning/` and `CHANGELOG.md` are history and are not rewritten.

### Live impact and the gate
- **D-09:** Live impact is checked and recorded: the PROD values of `NEXT_PUBLIC_APP_URL`,
  `NEXT_PUBLIC_SITE_URL`, `PLATFORM_EMAIL` and the allowed origins (names and the domain part only,
  never secrets), and the Supabase auth redirect allow-list.
- **D-10:** A gate fails on any new `quantalyze.com` in tracked source outside `.planning/`,
  `CHANGELOG.md` and a small named allowlist of lineage lines (for example the analytics tests that
  assert `$host` is never `quantalyze.com`). It is shown RED once.

### Claude's Discretion
- Where the general contact page lives (a new `/contact` route reusing the existing form and
  `for_quants_leads`, or the existing modal opened from a link), as long as every pointer reaches
  one working form without an email address.
- The redirect mechanism (`vercel.json` host-matched redirect or `src/proxy.ts`), as long as preview
  and per-deployment hosts are not redirected.
- The exact copy wording, kept in the existing voice of `wizardErrors.ts` and
  `status-surface-copy.ts` (one constant per surface, not 100 hand-edited strings).

</decisions>
