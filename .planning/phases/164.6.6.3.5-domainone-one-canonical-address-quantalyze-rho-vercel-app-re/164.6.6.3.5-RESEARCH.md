## Summary

Eight findings change the plan, in order of consequence:

1. **The PDF routes and the monthly founder cron refuse `quantalyze.xyz` today.** The production host allow-lists in `src/app/api/factsheet/[id]/pdf/route.ts`, `.../tearsheet.pdf/route.ts` and `src/app/api/cron/founder-lp-report/route.ts` hold `quantalyze-rho.vercel.app`, `quantalyze.com`, `www.quantalyze.com` and NOT `quantalyze.xyz`. PROD's `NEXT_PUBLIC_APP_URL` is already `https://quantalyze.xyz`, so the cron's `isAppUrlAllowed` is false in production and a PDF request on the xyz host gets the `500 Internal server error` branch. D-06's "keep or gain `quantalyze.xyz`" is therefore **load-bearing, not cosmetic**: after the D-05 redirect the rho host never serves a PDF request, so unless xyz is added every PDF download in production is dead. Add `quantalyze.xyz`; the positive-control tests move from `quantalyze.com` to `quantalyze.xyz`.
2. **The redirect mechanism: use `next.config.ts` `redirects()`** with `has: [{ type: "host", ... }]`. Measured on a local `next dev --webpack` server with a forged `Host` header: exact host gives `308` with `Location` carrying path AND query; every preview/per-deployment host, look-alike host and suffix-spoof host gives `200`. Cron requests arrive on the per-deployment URL (measured in PROD logs), but a `missing` header clause keeps them out of the redirect anyway (verified).
3. **Hosts that exist** (measured): PROD answers `200` on both `quantalyze-rho.vercel.app` and `quantalyze.xyz`; `www.quantalyze.xyz` already 307s to apex; `quantalyze.com` is a third-party WordPress host. Preview and per-deployment hosts are `quantalyze-<hash>-<team>-projects.vercel.app` (GitHub deployments API). CI, e2e and the prober never touch the rho host (they use `localhost`, Railway, Supabase).
4. **Census:** `quantalyze.com` occurs **220 times in 61 tracked text files** outside `.planning/` and `CHANGELOG.md`, plus **1 in the binary `public/security-packet.pdf`** (a `mailto:` link annotation that `git grep` does NOT surface and a byte read does). Classes below. The security packet PDF is a surface neither CONTEXT nor UI-SPEC names; D-01 covers it, so it must be regenerated.
5. **A new `/contact` route needs three lockstep edits or it 307s anonymous users to `/login`:** `PUBLIC_ROUTES` in `src/proxy.ts`, a `ROUTE_CONTRACT_MANIFEST` entry in `src/lib/routing/route-contract-manifest.ts`, AND the auth-bounce exemption in `src/proxy.ts` (without it a signed-in user opening the new-tab pointer from the wizard is redirected to the dashboard). `npm run lint` runs `check-route-contract.ts`, which enforces the first two.
6. **Migration:** the smallest change is three nullable-or-defaulted columns on `for_quants_leads` (`source`, `topic`, `reference`) plus replacing the full unique index `for_quants_leads_email_day_uniq` with the SAME-named index restricted `WHERE source = 'request_call'`. No data-reading block. `firm` is `NOT NULL`: store `''` for a contact message with no firm (decision A below).
7. **Live impact (D-09):** PROD `NEXT_PUBLIC_APP_URL` = `https://quantalyze.xyz`; PROD `NEXT_PUBLIC_SITE_URL` = `https://quantalyze-rho.vercel.app` (the one value that should move); Preview env holds the rho host for both. `PLATFORM_EMAIL` and `ADMIN_EMAIL` in PROD are on `gmail.com`, not `quantalyze.com`; `RESEND_API_KEY` and `RESEND_ALERT_FROM` are unset in PROD. Supabase auth Site URL is already `https://quantalyze.xyz` and its allow-list already contains the xyz and rho patterns. Changing the code fallbacks changes nothing live.
8. **The "existing new-lead badge" does not exist.** `Sidebar.tsx` gives the `For-quants leads` item no `badge`; the only badge in `ForQuantsLeadsTable.tsx` is the "founder notify" one. Contact rows appear in the founder queue automatically (default view is `processed_at IS NULL`). UI-SPEC's "the existing new-lead badge counts contact-form rows too" is a no-op requirement; do not build a badge.

**Primary recommendation:** Sequence the work so the gate lands first and is shown RED against the 220-hit tree, then sweep to GREEN: (1) allow-list gain of `quantalyze.xyz` + redirect + env defaults, (2) migration + route contract (`stored`/`duplicate`) + `/contact` page + proxy/manifest lockstep, (3) copy sweep by shape with pins moved in the same commit, (4) docs, security.txt, security packet PDF, (5) post-deploy live measurement of the redirect and of `/contact`, recorded in a LIVE-IMPACT artifact.

### Pattern 1: Host-matched permanent redirect (measured)
**What:** one entry in `next.config.ts` `redirects()`.
**When to use:** D-05.
**Example:**
```typescript
// Source: node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/redirects.md
// ("has" type "host"; "value" is a regex-like string; query values are passed through)
// Measured locally 2026-10-07 with `next dev --webpack` and a forged Host header.
{
  source: "/:path*",
  // `.` MUST be escaped: the value is a regex-like string. Next anchors it
  // (a suffix-spoof host and a look-alike host both came back 200 below).
  has: [{ type: "host", value: "quantalyze-rho\\.vercel\\.app" }],
  // Belt and braces: Vercel's cron arrives on the per-deployment host, but a
  // cron request must never be redirected (cron does not follow redirects).
  missing: [{ type: "header", key: "x-vercel-cron-schedule" }],
  destination: "https://quantalyze.xyz/:path*",
  permanent: true, // 308, method-preserving
},
```

### Pattern 2: Contract-stable response for "success means stored"
**What:** `/api/for-quants-lead` returns `{ ok: true, status: "stored" }` for a written row, `{ ok: true, status: "duplicate" }` only for a request-a-call 23505, and the honeypot returns the `stored` shape. Both clients render success only on the named status. (Field name is the planner's per UI-SPEC; `status` is a suggestion.)
**Where today:** the route returns bare `{ ok: true }` on the honeypot branch, on 23505 and on success: `return NextResponse.json({ ok: true });` ×3, and `if (insertErr?.code === "23505") { return NextResponse.json({ ok: true }); }` [VERIFIED: src/app/api/for-quants-lead/route.ts]. `RequestCallModal` treats any `res.ok` as success.

### Anti-Patterns to Avoid
- **Redirecting by `.vercel.app` wildcard.** It would redirect every preview and per-deployment URL, breaking Vercel preview checks. Match the exact host.
- **Unescaped `.` in the host `value`.** `quantalyze-rhoXvercelXapp` would match.
- **Editing the allow-lists by deleting `quantalyze.com` only.** That leaves xyz absent (Finding 1).
- **Treating `res.ok` as stored.** Honeypot and dedupe branches also return 200.
- **Rendering the `ref` query param unvalidated.** UI-SPEC's charset rule `^[A-Za-z0-9_-]{8,64}$` is the fence.
- **Reading tracked files with a `grep` that skips binary/NUL files in the gate.** `src/lib/wizardErrors.test.ts` carries a NUL byte (it is in the `-I` hit list only because `git grep -I` still saw text before it); the PDF carries a hit `git grep -a` did not return. Read bytes as `latin1`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Host-conditional redirect | A `Host` check in `proxy.ts` or a route | `redirects()` with `has: host` | Platform-level, before filesystem and proxy, preserves query |
| Repo-wide literal ban | `grep` in a shell step | A script modelled on `scripts/check-planning-hygiene.ts` + a vitest that plants a violation in a scratch tree | Tracked-file enumeration, NUL/binary safe reads, EMPTY-SCAN refusal, own-source self-match handling are all solved there |
| TS enum ↔ SQL CHECK drift | Hand-synchronised lists | A parity test like `strategy-sources-migration-parity.test.ts` | Two hand-typed lists drift silently |
| Pointer rendering in 100 strings | Per-string JSX | `ContactPointerText` over copy constants (UI-SPEC) | One renderer, one phrase, one test |
| Query-string building | String concatenation | `contactHref()` builds with `URLSearchParams`/`encodeURIComponent`, omits absent keys | UI-SPEC contract |
| Security-packet PDF | Editing the binary | `node scripts/build-security-packet.mjs` after editing `scripts/build-security-packet.html` | The runbook's only supported path; needs local Chrome (present on this machine) |

**Key insight:** this phase is 90% mechanical substitution that is easy to do incompletely. The gate, not discipline, is what makes "one canonical address" true.

## Common Pitfalls

### Pitfall 1: PDF routes and the cron stay broken on xyz
**What goes wrong:** the allow-list sweep deletes `quantalyze.com` and leaves xyz absent. **Why:** the lists never contained xyz. **Avoid:** add `quantalyze.xyz` to all three lists; positive-control test on `https://quantalyze.xyz/...`; a negative-control test that `quantalyze.com` is refused. **Warning sign:** `[pdf] Refused to render: request origin not allow-listed in production` in PROD logs; the cron's `APP_URL_ALLOWED=false` ConfigError.
(Live PDF probe not run: no public strategy id was reachable from `/browse`. The refusal is established from code, `appUrl()` returning `null` → 500, and from PROD `NEXT_PUBLIC_APP_URL` being xyz.)

### Pitfall 2: `/contact` 307s to `/login`
**What goes wrong:** page exists, proxy has no entry. **Avoid:** edit `PUBLIC_ROUTES`, add `isContactRoute` to `isAuthBounceExempt`, add the manifest entry `{ route: "/contact", class: "public", notes: ... }`. **Warning sign:** `npm run check:route-contract` prints UNCLASSIFIED or MISSING-FROM-PUBLIC; e2e lands on `/login`.

### Pitfall 3: Every 23505 is a false success for contact messages
Today's unique index makes a second same-email same-day message a silent `{ ok: true }` with nothing stored. Partial index + `stored` status fixes it (Q3).

### Pitfall 4: The gate matches itself and its own tests
The gate script and its test must name the literal. ### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Reflected content via `?ref=` | Tampering / XSS | server-side charset+length validation, render as a controlled input value only; an invalid value appears nowhere in the DOM |
| Open redirect via the host rule | Spoofing | exact, escaped, anchored host value; destination is a fixed `https://quantalyze.xyz` origin with only the path substituted |
| Host-header SSRF into puppeteer | Elevation | keep the production allow-list; only the value set changes |
| Internal-token egress by cron | Information disclosure | `isAppUrlAllowed` keeps refusing unknown hosts; xyz becomes allowed |
| Contact-form abuse (spam, enumeration) | DoS | shared `publicIpLimiter` (10/min/IP), honeypot, 8192-byte body cap, CSRF same-origin check (bot filter, not a real CSRF defense for an unauthenticated route) |
| Stored message content in the CRM/email | Tampering | `escapeHtml` in the notification, React escaping in the table |
| Data-minimisation | Privacy | the form stores name, email, message, optional firm and reference, source IP and UA (already stored for leads); the `/legal/privacy` page should not claim otherwise |
