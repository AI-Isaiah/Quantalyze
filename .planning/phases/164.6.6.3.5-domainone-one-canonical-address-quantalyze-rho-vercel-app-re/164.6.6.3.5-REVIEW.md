## Warnings

### WR-01: Every contact message is stamped `notify_succeeded_at` although no email is sent, so the CRM shows security, support and privacy messages as "notified" when nobody was alerted

**File:** `src/app/api/for-quants-lead/route.ts:719-770`, `src/lib/email.ts:273-321` and `src/lib/email.ts:990-999`
**Severity:** MEDIUM. **Confidence:** 8/10.

**Issue:** `notifyFounderGeneric` calls `send()` without `throwOnFailure`. When `send()` has no
Resend client (`email.ts:273`) or no sender (the new D-12 branch at `email.ts:304-321`), it logs
a warning, schedules a `failed` dispatch row and **returns normally**. The lead route treats that
normal return as a clean send. It writes `notify_succeeded_at` at `route.ts:754-758`, and the
CRM's "stuck pending notify" predicate (`ForQuantsLeadsTable.tsx:160-172`,
`notify_attempted_at IS NOT NULL AND notify_succeeded_at IS NULL`) never fires.

**Failure scenario (current PROD config, per RESEARCH line 98):** `ADMIN_EMAIL` is set and
`RESEND_API_KEY` is unset. A researcher picks "Security report" on `/contact` and submits. The
row is stored, `send()` skips, and the row gets `notify_succeeded_at = now()`. The founder gets
no email, and the CRM row looks like the founder was told. The only way to learn of the report
is to open `/admin/for-quants-leads` without being prompted. Meanwhile `/contact`
(`page.tsx:53-56`) and `security.txt` promise "The founder reads every message and replies …
within one business day".

RESEARCH line 287 recorded this as pre-existing and out of scope for request-a-call leads. This
phase makes it worse in two ways:

1. It routes every support, security and privacy contact in the product into this path, where
   before it carried only sales leads.
2. It adds a second skip path, D-12's missing sender, that also reports success, against the
   brief's "never silently succeeds" rule.

**Fix:** Have the lead route opt into strict delivery, so a skipped send lands in `notify_error`
instead of `notify_succeeded_at`:

```ts
// email.ts
export async function notifyFounderGeneric(
  subject: string,
  bodyHtml: string,
  opts: { throwOnFailure?: boolean } = {},
) {
  const founder = founderEmail();
  if (!founder) return;
  await send(founder, safeSubject(subject),
    `<div style="font-family:'DM Sans',sans-serif;max-width:600px;">${bodyHtml}${SIGNATURE}</div>`,
    "founder_generic", undefined, { throwOnFailure: opts.throwOnFailure ?? false });
}

// route.ts, both notifyFounderGeneric calls
await notifyFounderGeneric(subject, html, { throwOnFailure: true });
```

The existing `catch` at `route.ts:771-801` then writes `notify_error = "[email] Resend not
configured — send failed"` (or the `PLATFORM_EMAIL` variant), and the CRM badge shows the row as
not notified. `captureFailure(err, "founder_notify")` would then fire on every lead while Resend
is deliberately unset (D-04). If that volume is unwanted, apply the module-scope once-per-process
guard the route already uses for `ADMIN_EMAIL`. Add a route test with Resend unset that asserts
`notify_succeeded_at` is never written. Separately, the `/contact` intro copy should not promise
a founder read "within one business day" while the founder receives no alert at all. That copy
decision belongs to the founder, so route it rather than fix it here.
