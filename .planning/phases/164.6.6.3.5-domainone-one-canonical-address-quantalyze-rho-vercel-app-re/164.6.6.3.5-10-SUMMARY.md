# Phase 164.6.6.3.5 Plan 10: No invented sender, xyz URL fallbacks Summary

Every mail sender default that named the retiring domain is gone: `getPlatformEmail()` returns `null` when `PLATFORM_EMAIL` is unset or blank, and `email.ts`, the founder LP cron, the flag monitor and the `notify-admin` edge function each skip with a logged warning instead of sending from an address we did not configure; the four `NEXT_PUBLIC_APP_URL` fallbacks plus `notify-admin`'s `APP_URL` fallback now point at `https://quantalyze.xyz`.

## What was done

**Task 1 (tracer), commit `d6f0d1de7`.** `platform.ts` docblock states the D-12 decision; `getPlatformEmail()` is `string | null`. `email.ts` drops the module-load `PLATFORM_EMAIL` / `FROM`; `send()` reads the sender at send time after the no-Resend branch and, when null, warns `[email] PLATFORM_EMAIL not configured — skipping send to <redacted recipient>`, marks the dispatch row `failed` with `PLATFORM_EMAIL not configured`, and throws for `throwOnFailure` callers (awaiting the audit write first, same as the no-Resend branch). New `platform.test.ts` (6 cases) and 3 new `email.test.ts` cases (no sender skip, `throwOnFailure` throw, sender read at send time with name `Acme`). The `email.test.ts` Resend mock now records `from` and `html`.

**Task 2, commit `f899c5d5f`.**
- founder-lp-report: sender read once next to `resend`, added to the config gate and its message (`PLATFORM_EMAIL=${!!sender}`), threaded into `dualAlert` / `sendFailureAlert` (null sender returns early with `[cron/founder-lp-report] PLATFORM_EMAIL not configured — skipping failure alert email`; Sentry still fires) and used at the success send.
