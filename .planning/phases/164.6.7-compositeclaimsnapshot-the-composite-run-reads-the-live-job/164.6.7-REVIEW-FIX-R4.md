## The structural fix: closing the class, not the site

Rounds 2, 3 and 4 each found the same defect one database call further into a stamp closure:
- round 2: the marker re-read;
- round 3: the composite status read;
- round 4 (SFH-R4-01): the D-15 error-only write.

Round 4 therefore routes EVERY database call inside `_stamp_strategy_analytics_failed` and the
composite `_stamp_failed` through one module-level wrapper, `_stamp_io`. It covers:
- the composite status read (`_read_existing_failed_row`);
- the live marker re-read (`_read_refresh_marker_state`);
- the D-15 error-only write (`_upsert_error_only`);
- the loud stamp write (`_upsert`).

On failure `_stamp_io` does three things:
- logs ONE ERROR carrying the site, the operation kind (`_STAMP_OP_*`), `_read_failure_text`
  and the cause (`scrubbed` plus the scrubbed detail);
- makes ONE `_capture_read_failure` capture, tagged `compute_job_id`;
- raises `StampIOUnavailable`. Its text is `"{site}: could not {op} ({failure}), so no terminal
  stamp is confirmed for: {scrubbed}"`, with the failure placed before the cause and capped at
  120 characters, so the 500-character cut cannot drop the cause. "Confirmed" rather than
  "written", because a write that timed out at the gateway may have committed.

A `_READ_PROGRAMMING_ERRORS` member is logged and captured the same way, then re-raised
unchanged, so it is filed `unknown`.

**Exception types.**
- The new base `HandlerIOUnavailable` is what `classify_exception` maps to `transient`.
- `RefreshMarkerRereadUnavailable` subclasses it. It is kept for the entry read and the chain
  edge, so `test_7_unreadable_status_writes_nothing_and_raises_transient` still holds.
- `StampIOUnavailable` is its sibling and is raised only by `_stamp_io`.
- Neither is a `ValueError`, so the F-5 `except ValueError` arm cannot catch them. As a side
  effect, a `JSONDecodeError` from a stamp write inside the MTM `try` no longer re-stamps under
  the chain-break cause.

**The marker read split.** `_refresh_marker_live_state` used to catch every failure and answer
`READ_ERROR`, so a wrapper around it would never see one. It now delegates to the raw
`_read_refresh_marker_state`, which raises. It keeps its catch for the chain edge and the tail
mirror only. The stamps call the raw reader through `_stamp_io`, so they never hold a
`READ_ERROR`. Their two `READ_ERROR` arms and `RefreshMarkerRereadUnavailable` raises were
therefore dead code, and they were deleted. The ERROR line keeps the words "re-read the refresh
marker", because the lane probe's `_REREAD_FAILURE_FRAGMENT` scans the handler log for them.

**The landed-stamp line moved.** The "no longer protects it" ERROR used to fire BEFORE the loud
write. A failed loud write then put the cause on two ERROR lines (it and `_stamp_io`'s). Now it
fires only after `_stamp_io(... _STAMP_OP_LOUD_WRITE ...)` returns, in the past tense ("stamped
… FAILED"). This also keeps the worst row at 3 events, where the old placement would have made
it 4.

**Deliberately NOT wrapped: the single-key series heal** (`_heal_delete_basis_series`). It runs
after the loud stamp has LANDED with the cause in `computation_error`, so its failure loses no
cause. A transient raise there would retry a job whose terminal stamp already landed, which
violates "no partial terminal stamp" by construction. It keeps its WARNING and the job stays
`permanent`. The reason is recorded in `_stamp_io`'s docstring, and the disposition is pinned
(below).

`unknown` failure in the service, and that is out of proportion for a readability point in this
phase. The ERROR line names the class through `_read_failure_text`, and so does the tagged
capture. That now holds at every programming-error site, stamps included.
