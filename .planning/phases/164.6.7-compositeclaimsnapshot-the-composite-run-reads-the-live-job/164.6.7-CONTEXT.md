<domain>
## Phase Boundary

The composite (`stitch_composite`) run's terminal stamp, the `_stamp_failed` closure inside
`run_stitch_composite_job` (`analytics-service/services/job_worker.py`), decides "protected
background refresh or loud user failure" from the claim-time `job.get("metadata")` snapshot. The
SQL status bridge (`sync_strategy_analytics_status`, its `is_protected` column) decides from the
LIVE `compute_jobs` row. A marker retracted after the claim makes the two layers disagree about
the same job. This phase makes the Python decision read the live row, the way the single-key
honour sites already do through `_refresh_marker_still_on_row`.

ROADMAP success criteria (binding): (1) harm shown on the local lane first; (2) both layers reach
the same verdict for a post-claim retraction, proven by execution; (3) a regression test observed
RED when the fix is neutered; (4) the runbook precondition removed or restated to match.

</domain>

<decisions>
## Implementation Decisions

### Probe (success criterion 1)
- **D-01 (2026-09-25, research OQ1):** The harm probe stays a RECORDED LOCAL RUN, like
  164.9.1 plan 01, not a CI gate. It lives at `analytics-service/scripts/probe_composite_claimtime.py`,
  is not collected by pytest, runs only against the loopback stack booted by
  `scripts/local-stack/run.sh`, and refuses a non-loopback host before it imports any service
  module. No worker, no `uvicorn`. Its verdict lines are pasted into the plan SUMMARYs.
  Reason: no CI job runs Python on the local stack today, and adding one is new infrastructure
  beyond this phase; the durable CI regression is the unit test (criterion 3).
  Reversibility: reversible. A later phase can wrap the same script in a CI step.

- **D-02 (2026-09-25, research OQ2):** The fix SHIPS even if the probe shows no end-state
  difference. The two layers disagreeing on the DECISION for the same job is itself a
  data-integrity defect. The probe's end-state verdict is recorded either way: it sizes the harm,
  it does not gate the fix. Reason: criterion 2 is about the decision, and the H2/H3 end-state
  effects depend on seed data whose production shape is unmeasured (research assumption A1).
  Reversibility: reversible (the fix is about ten lines of Python and no migration).
  ⚠️ Planner note, not a new decision: D-02 covers an END-STATE null result. If the pre-fix probe
  shows the two layers AGREEING on the decision for a post-claim retraction, the research premise
  itself is disproved, and execution stops for a replan rather than proceeding.

### Residue (research OQ3)
- **D-03 (2026-09-25, research OQ3):** The residual window between the Python live re-read and
  `mark_compute_job_failed` (milliseconds; the single-key derive arm carries the identical
  residual) is RECORDED as a `TODOS.md` entry whose owner is whoever next changes the shared SQL
  bridge (`sync_strategy_analytics_status`). It is not fixed here. Reason: closing it needs a
  change to a bridge every job kind shares (branch (b) clearing `computation_warned`, or moving
  the decision inside the bridge's transaction), which is a migration that auto-applies to PROD.
  Reversibility: reversible (the entry names the fix shape).

### Scope fixed by the orchestrator brief
- **D-04 (2026-09-25):** No migration. The SQL end already decides on the live row (research
  "Migration verdict"). Reversibility: reversible.
- **D-05 (2026-09-25):** The fix mirrors `_refresh_marker_still_on_row` at the existing
  single-key call sites: narrow-only (the live read runs only when the snapshot would GRANT
  protection), fail toward LOUD on any error, the handler-local `supabase` client, the marker
  literal spelled ONCE in the closure (Gate 11), and no new comment or log text containing the
  words the M-3 source scan bans. Tests: retracted gives loud, a marker-present control stays
  error-only, a failing re-read gives loud; `_FakeSupabase` gains a `live_job_metadata` seam that
  defaults to ABSENT so every other construction is byte-unchanged. Neuter to RED, then restore.
  Reversibility: reversible.
- **D-06 (2026-09-25):** Three plans in three strictly sequential waves: 01 harm probe (pre-fix),
  02 fix and regression plus the post-fix probe as the criterion-2 proof, 03 runbook currency and
  `TODOS.md`. Reversibility: reversible.
- **D-07 (2026-09-25):** Runbook `docs/runbooks/ledger-refresh-go-live.md`, section "Before the
  COMPOSITE fan-out is ever scheduled": items 2, 4 and 5 are restated as MET, cited by symbol;
  item 6 (watching the composite's own runs) stays BLOCKING. `TODOS.md` `161.1-D13` wording is
  corrected. Reversibility: reversible.
- **D-08 (2026-09-25):** `CHANGELOG.md` and `VERSION`/`package.json` go in the SHIP commit, not
  in a plan task. Reversibility: reversible.
- **D-09 (2026-09-25, orchestrator decision on round-1 review SFH-01 / WR-03; amends D-05's "a
  failing re-read gives loud"):** A TRANSIENT failure of the live re-read (an exception, a
  timeout, a 5xx) must NOT make the destructive un-publishing stamp at the composite site. The
  read goes through `db_read_with_retry`. If it still raises, it is logged at ERROR and sent to
  Sentry (`capture_exception`), `_stamp_failed` writes nothing, and the job fails TRANSIENT
  (`RefreshMarkerRereadUnavailable`, mapped by `classify_exception`) so the queue retries it. A
  DEFINITIVE answer (the row was read and the marker is not on it, or there is no row or no id)
  still takes the loud path. `_refresh_marker_still_on_row` returns a `MarkerLiveState`
  (present / retracted / no_id / no_row / other_source / read_error). Every call site, the
  composite one and the three single-key ones, logs "RETRACTED … user-initiated" only for
  `retracted`, and logs `no_id` / `no_row` at ERROR. ⚠️ Scope as implemented: the transient
  retry applies at the COMPOSITE site only. The single-key stamp closure in
  `run_derive_broker_dailies_job` still takes the loud path on `read_error`. That closure has
  many callers, and none of them was audited for a raise. This was surfaced to the orchestrator
  and not decided here. Reversibility: reversible.
  ⛔ **AMENDED 2026-09-26 (orchestrator decision; the "Scope as implemented" sentences above are
  kept as lineage and no longer describe the code).** Un-publishing a strategy on a transient
  read error is user-facing, so the single-key stamp closure (`_stamp_strategy_analytics_failed`
  in `run_derive_broker_dailies_job`) now follows the composite site: on `read_error` it writes
  nothing to `strategy_analytics` (neither the error-only write nor the destructive stamp) and
  raises `RefreshMarkerRereadUnavailable`, so the job fails TRANSIENT and retries. A definitive
  non-present answer still takes the loud path. Every caller of the closure was traced to
  `dispatch` with no handler that catches the raise (the trace is in 164.6.7-REVIEW-FIX.md,
  "Round 1 — single-key completion"). The two non-stamp single-key sites are unchanged: on
  `read_error` the chain-edge forward sends hop 2 no marker, and the tail mirror only logs.
  Reversibility: reversible.
