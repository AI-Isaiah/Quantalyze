# Phase 169.1.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is a correctness phase, not a design phase.** It changes how chart axis tick VALUES are
computed so the server (Node 22) and the browser (Chromium) produce byte-identical values. It adds
no component, no copy, no colour, no spacing and no type size. The whole contract is:

1. **No visible change from what the browser renders today**, on every chart in scope, with one
   named exception (rule 2).
2. **The one intended visible change:** where a chart's y-axis crosses zero (or its baseline) and
   the browser today draws that tick from a tiny negative float, the tick now renders as an exact
   zero, so it reads with the chart's existing zero label and existing baseline style, on the
   server AND in the browser. Measured case: the factsheet daily-returns chart, whose zero tick the
   browser renders today as `-0.0%` with the dashed gridline style; it becomes `+0.0%` with the
   solid baseline style, which is exactly what the server already renders
   (`.planning/debug/e2e-equitychart-detached-320.md`, "same diag under next dev").
3. **Hydration is invisible.** The tree the server paints is the tree that stays. No React #418,
   no client-side rebuild after first paint, so the Overview EquityChart a user (or a test) is
   looking at is never replaced under them.

Every value below is taken from the code at the phase branch head (cited by symbol; line numbers
drift) or from `DESIGN.md`. Nothing here is a new design decision.

## Tick contract (the binding rules)

These are the rules the executor implements and the auditor checks. They are the only
"interaction" this phase has.

| ID | Rule |
|----|------|
| TK-1 | **Engine independence.** A chart's tick `value` array is a pure function of its inputs and is byte-identical in Node 22 and Chromium, whatever the platform's `Math.pow(10, n)` / `10 ** n` returns. Values come from an integer index times the step, rounded to the step's decimal places, never from a running `v += step` sum or a raw power of ten. |
| TK-2 | **Zero snaps to exactly 0.** A tick whose value is zero at the step's precision is emitted as `0` (positive zero), never as a tiny negative or as `-0`. Its label is whatever that chart's existing formatter prints for `0`: `+0.0%` in rows 1 and 2 (percent), `+0.00` (ratio), `0.0%` in rows 3 and 4 (their formatter adds `+` only for `x > 0`), `0` in row 5. A zero tick never reads `-0.0%` or `-0.00`. |
| TK-3 | **Baseline styling is chosen by value at the step's precision, not by exact float equality.** In rows 1 and 2 the `isBaseline` decision (today `t.value === config.baseline`) must give the same answer on server and client for a tick that sits on the baseline (0 for percent and ratio charts, 1 for growth charts). Rows 3 and 4's `t.value === 0` zero-dash test must hold for the snapped zero from TK-2. Row 6 already uses a tolerance (`1e-9`); keep its output identical. |
| TK-4 | **Labels and styles do not change.** No formatter, font size, weight, colour, stroke, dash pattern, opacity, padding or tick count changes. The only change a viewer can see is rule 2 above. |
| TK-5 | **Tick set shape is preserved.** Same tick count, same first and last tick, strictly ascending, no duplicates (the React key in rows 1, 3 and 4 is `y-${t.value}`, so two ticks rounding to the same value would collide). Caps stay as they are: 12 ticks in `niceLinearTicks`, 8 in `niceTicks` and `niceCountTicks`, 10 log candidates. |
| TK-6 | **Degenerate inputs keep today's output.** `hi <= lo` keeps each helper's current early return (row 1: one tick at `lo`; rows 3 and 4: none; row 5: a single `0` tick). Row 6's 3-tick fallback, its `console.warn` and its `captureChartIssue` call stay as they are. |

## Copywriting Contract

This phase adds no user-facing copy. The only text it touches is tick labels, which come from the
existing formatters in the scope table.

| Element | Copy |
|---------|------|
| Primary CTA | none: no action is added (correctness fix) |
| Empty state heading | none new; each chart keeps its existing empty and partial-history states unchanged |
| Empty state body | none new |
| Error state | none new. A hydration mismatch is a defect caught by tests, never a message shown to a user (rule 3) |
| Destructive confirmation | none: no destructive action in this phase |
| Zero tick label | `+0.0%` (rows 1-2 percent and growth), `+0.00` (rows 1-2 ratio), `0.0%` (rows 3-4), `0` (row 5), `+0%` (row 6, the existing `pct === 0` → `toFixed(0)` branch). Never `-0.0%`. |

Note on the brief's wording "0.0%": the factsheet daily-returns chart's formatter prints `+0.0%`
for an exact zero (sign `+` when `pct >= 0`), and that is what the server renders today. This
contract keeps each formatter's own output and does not unify the sign rule across charts; doing so
would be a visible change outside rule 2.
