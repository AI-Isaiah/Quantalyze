## Warnings

### WR-01: The placement pin false-passes when the step is neutralised inside its own `run:` line or by a non-literal `continue-on-error`

**File:** `src/__tests__/e2e-seeded-hydration-guard.test.ts:113-115, 135, 141, 362-370`

**Issue:** `selfTestPlacements` treats a step as blocking when three things hold:
- one uncommented line matches `npx playwright test\b.*\s<self-test path>(\s|$)`;
- the step has no `continue-on-error: true` written as the literal `true`;
- the step has no `if:`.

It never checks what the rest of that `run:` line does, and it never checks a `continue-on-error` whose value is an expression.

I copied the real matcher (lines 62-154) into a scratch script, unchanged. I ran it against the real `ci.yml`, swapping out only the step's `run:` line for each case below. **All six report `{"job":"e2e-seeded","advisoryBecause":[]}`, which means "blocking":**

| case | edit to the step | effect in CI |
|---|---|---|
| `orTrue` | `... --reporter=list \|\| true` | the step can never fail |
| `coeExpr` | adds `continue-on-error: ${{ github.event_name == 'pull_request' }}` | advisory on every PR |
| `listOnly` | adds `--list` | lists the tests, runs none, exits 0 |
| `grepNone` | adds `--grep NOMATCH --pass-with-no-tests` | runs nothing, exits 0 |
| `shellIf` | `if false; then npx playwright test <spec> ...; fi` | never runs |
| `echoed` | `run: echo npx playwright test <spec> --retries 0` | prints the command and runs nothing |

The `echoed` row contradicts the matcher's own self-test name: *"finds no placement when the self-test is dropped, commented out or only echoed"* (line 362). That case covers only `echo e2e/hydration-guard.self-test.spec.ts` (line 366), without the `npx playwright test` prefix. So the name claims more than the test checks.

`|| true` and an expression-valued `continue-on-error` are the two most likely ways someone would "quiet" a flaky step. The pin exists to catch exactly that, and it passes them silently. The step's comment says the pin "pins every invocation of the self-test to a placement like this one" (`ci.yml:6288-6289`). That is wider than what the pin checks.

**Fix:** The self-test has one dedicated step, so pin it exactly instead of matching a pattern:

```ts
// The whole run value must be exactly this command (allow only the two flags
// the step uses today); anything else on the line, or a block scalar, is advisory.
const EXACT_RUN = new RegExp(
  `^ {8}run: npx playwright test ${GUARD_SELF_TEST.replace(/\./g, "\\.")}` +
    `(?: --retries 0)?(?: --reporter=list)?\\s*$`,
);
// ...
if (!step.some((l) => EXACT_RUN.test(l))) {
  advisoryBecause.push("its `run:` is not exactly the self-test command (shell wrapper, extra flags, or echo)");
}
// any continue-on-error key, whatever its value, is advisory:
if (step.some((l) => /^ {6}(?:- | {2})continue-on-error:/.test(l))) { ... }
if (lines.some((l) => /^ {4}continue-on-error:/.test(l))) { ... }
```

Add the six cases above to "self-tests of the real matcher", each expected to report a reason. Narrow line 362's test name to what it covers, or add a case for an echoed `npx playwright test <spec>` line. The step's `run:` is already a single line, so this reddens nothing at HEAD.
