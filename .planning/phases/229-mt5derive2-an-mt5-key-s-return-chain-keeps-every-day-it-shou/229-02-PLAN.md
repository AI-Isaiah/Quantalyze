<objective>
An inception day's P&L is never dropped as NaN without a flag (MT5D-05). CONTEXT decided "flag by name": with no timing the day has no base to book a return against (pre-history capital is zero), so the honest outcome is a named annotation (a count of days), not a status-promoting warning, matching D-12's "no return, no warning" for the deposit-only case.

`chain_linked_twr` reaches its inception branch only when the day has no `DayTiming`, and today it `continue`s without looking at P&L. This plan counts a day-0 skip whose P&L is above a relative noise floor and carries the bool along the same present-only chain as the D-15 `flow_timing_day_level_large` annotation, stopping before the frontend (an unknown `data_quality_flags` key is ignored by `src/lib/factsheet`).

Wave 2: it depends on plan 229-01 (same `nav_twr.py` and `test_nav_twr.py`) and on plan 229-03 (same `job_worker.py`).

Output: the flag, its registry entries, the four carries, and their tests.
</objective>
