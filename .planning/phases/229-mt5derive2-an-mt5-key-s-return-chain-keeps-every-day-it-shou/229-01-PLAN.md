<objective>
Fix the empty-cohort-0 money-math gap at its root (MT5D-04) and record the founder's acceptance of the D-15 band (MT5D-06).

Today `_judged_cohorts` judges cohort 0 on every non-inception timed day even when it holds no P&L, so a day that re-funds an emptied account is dropped by the base guard on a start of about zero, and the interior chain break then cuts the headline to the suffix. The new rule (CONTEXT, Decided autonomously, "Empty cohort 0"): an empty cohort 0 is skipped whenever a later cohort on the same timed day is judged, on every day; a cohort 0 with P&L is always judged; a day with no judged cohort keeps today's behaviour; 188's tiny-base rule keeps precedence because it is judged on the day's starting NAV after the cohort guards.

MT5D-06 is closed by the founder ruling of 2026-11-24 ("Keep 1.0, accept band (Recommended)"): no change to the ratio or the copy. This plan makes no source edit for it: it records the acceptance and its reason in the SUMMARY and proves the existing boundary pin can fail.

This moves published MT5 returns (a re-fund day into an emptied account is now measured). Known and intended consequence inside the phase: `tests/test_mt5_soak.py::test_one_checked_day_among_knife_edge_sweep_days_is_not_green[10000.0-10050.0]` goes RED with `timed_day_not_nan` once this lands, because the soak's own oracle still encodes the old rule. That node is owned by plan 229-04 (wave 2), which rewrites the oracle independently. This plan does NOT touch `analytics-service/scripts/mt5_soak.py` or `analytics-service/tests/test_mt5_soak.py`, and node-repair must not either.

Output: the cohort rule, its tests, the replacement of the one moved pin, the D-15 record.
</objective>
