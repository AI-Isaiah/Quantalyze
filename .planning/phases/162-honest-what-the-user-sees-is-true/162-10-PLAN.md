# 162-10 — Trim credentials at one chokepoint, so a correct key is not called wrong

## Why this exists

Found 2026-08-25 in a live production connect. A founder with a correct OKX key could not
connect it; the UI said **"Authentication failed. Check your API key and secret."** The
credential was fine — we send whatever was pasted, byte-for-byte, into the venue's HMAC.

`trim()` appears in this route ONLY inside emptiness guards (`:182-186`,
`api_key.trim().length === 0`). The value forwarded to `validateKey` (`:502`) and to the
legacy handler (`:338`) is the RAW string. `api_secret_normalized` (`:103`) is an sFOX-only
non-string coercion, not a strip. Python repeats the shape:
`analytics-service/routers/exchange.py:216` calls `.strip()` only to TEST for emptiness.

So one invisible trailing character produces a byte-different secret, the signature does not
verify, and OKX answers `50113 Invalid Sign` — which we render as a statement about the
user's credential. That is HONEST-01's exact class: a fault of ours reported as the user's.

**Measured discrimination (Railway logs, prod):** a FAKE key returns `50111 Invalid
OK-ACCESS-KEY` (key not recognised) at 21:29:11; a real key with a bad signature returns
`50113 Invalid Sign` (key recognised) at 21:30:12. The two codes are distinguishable and we
collapse them into one sentence.

## ⚠️ Traps

1. **Do NOT "fix" this by trimming inside the emptiness guard.** That is the CURRENT shape and
   it is exactly what fails. The guard already trims; the payload does not.
2. **Trimming validate-but-not-encrypt is WORSE than not trimming.** The key would validate
   once against the venue and then be stored in a form that never authenticates again — a
   latent failure that surfaces days later as a mysterious sync death. Both paths take the
   same trimmed value or neither does.
3. **Whitespace-only must stay a MISSING FIELD.** `"   "` trims to `""`; it must hit the
   existing `KEY_MISSING_REQUIRED_FIELD` arm, never be sent to a venue as an empty credential.
4. This route's request body carries RAW key material (SEAMCORE-06). Do not add logging of
   any credential value, trimmed or otherwise, while working here.
