# Phase 154 — UI Design Contract

> Visual and interaction contract for WIZCONT-01 / WIZCONT-02 / STALE-01. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

⛔ **This is a BUGFIX phase on a shipped wizard surface, not a redesign.** The contract
locks the states this phase touches and explicitly forbids restyling anything else.
Every reused component keeps its current markup, tokens, and copy byte-identical unless
a row below says otherwise. DESIGN.md governs; where this spec and DESIGN.md could ever
disagree, DESIGN.md wins.

⛔ **STALE-01 mechanism gate (mirrors CONTEXT.md and ROADMAP criterion 2):** the root
cause is NOT established and this phase forbids planning a fix before plan 154-01's
investigation closes on a failing regression test. Accordingly, this spec defines the
*honest screens* the eventual fix must land on — what the user sees when the backend has
moved on, when a re-derive is in flight, and when the poll gives up — and deliberately
prescribes **no polling mechanism, no timeout, and no new threshold number**. The
existing ladder in `SyncPreviewStep.tsx` (`SLOW_HINT_MS` 15 s / `WARN_THRESHOLD_MS`
60 s / `RETRY_THRESHOLD_MS` 900 s, `POLL_BACKOFF_MS`, `MAX_CONSECUTIVE_POLL_ERRORS` 3)
is the only timing vocabulary this phase may reference, and this spec does not move any
of those constants.

## Spacing Scale

Project base unit is 4px (DESIGN.md ladder: 2 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64).
This phase introduces **no new spacing values** — every touched state reuses the
measurements already in the components it edits:

| Token | Value | Usage in this phase (existing, verbatim) |
|-------|-------|------------------------------------------|
| xs | 4px | inline gaps inside status rows (`gap-1`, chip padding) |
| sm | 8px | button-row gap (`gap-2` on the Resume/Start-fresh row), `mt-2` body-under-heading |
| md | 12px | banner padding y (`py-3`), `mt-3` button row, member-list `pt-3` |
| lg | 16px | banner padding x (`px-4`), banner bottom margin (`mb-4`) |
| xl | 24px | section spacing between step blocks (`mt-6`) |

Exceptions: none. Any new banner/state block copies an existing block's padding
(`px-4 py-3` on `rounded-md border`) rather than inventing a spacing combination.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #F8F9FA `bg-page` | overlay/page background, status-card fill (`bg-page` inside the sync card) |
| Secondary (30%) | #FFFFFF `bg-surface` | banner surfaces, the overlay panel, resume banner (`bg-white`) |
| Accent (10%) | #1B6B5A `accent` | reserved list below |
| Warning | #B45309 text / #FEF3C7-family fills (`bg-warning/5`, `border-warning/40`) | recoverable, in-flight states ONLY |
| Destructive/Negative | #DC2626 `negative` | terminal permanent failure ONLY (gate_failed envelope, confirmed-dead poll) |
| Muted | #64748B `text-muted` | timestamps, elapsed counters, informational dedup notice |

**Accent reserved for:** the "Resume draft" primary button, the pulsing progress dot
(`bg-accent` `animate-pulse`), and existing active/focus states. Nothing else on this
surface may take accent.

**Semantic-color gate applied to STALE-01b (normative — this is the visual half of the
bug):** red renders **only on a verdict that is CURRENT**. While a re-derive is in
flight, the screen is in a *recoverable* state and renders **amber** (warning tokens),
never the red `gate_failed` envelope — a red refusal computed from a stale analytics
row is exactly the defect. Amber = "the system is handling this"; red = "this is the
final answer." A screen may not show red while the backend is still producing the
answer.

**Numbers Contract holds:** any count the screen cannot currently know (trades/days
mid-recompute) renders em-dash `—`, never `0`, never a stale number presented as fresh.
A `—` cell carries no semantic color.

## State Contracts (the heart of this phase)

### 1. Resume affordance — `ContributionWizardOverlay` (WIZCONT-01)

**No new component.** `WizardClient.tsx` already owns the complete resume banner
(`:899-925`) with both CTAs, testids, and the TRAP-4-safe Start-fresh flow. The fix is
that the overlay supplies a real `initialDraft` instead of the hardcoded `null`
(`ContributionWizardOverlay.tsx:146`); the banner then renders inside the overlay with
zero new UI. The contract pins what must stay true when it does:

| Aspect | Contract |
|--------|----------|
| Placement | Top of the wizard content area, above the current step, inside the overlay's `px-6 py-5` body — same DOM position as on `/strategies/new/wizard`. First thing the eye meets on reopen. |
| Container | Existing markup verbatim: `rounded-md border border-border bg-white px-4 py-3`, `mb-4`. |
| Heading | "We saved your progress." — existing copy, verbatim, unchanged. |
| Body (API draft) | "A draft from an earlier session is ready. Secrets are never stored in your browser, so you will need to paste your API secret again." — existing, verbatim. |
| Body (CSV draft) | "A CSV upload draft from an earlier session is ready. Re-select the file and continue." — existing, verbatim. Becomes reachable when the CSV short-circuit at `WizardClient.tsx:198` is fixed (in scope per CONTEXT.md — same class). |
| Primary CTA | `Button size="sm"` "Resume draft" (`data-testid="wizard-resume"`) — accent fill. Resumes to `sync_preview` via the existing `handleResume`. |
| Secondary CTA | `Button size="sm" variant="ghost"` "Start fresh" (`data-testid="wizard-start-fresh"`). ⛔ MUST keep opening the existing confirm-delete dialog (`handleStartFresh` → `setConfirmDelete(true)`), never delete directly — TRAP-4 (140.3-10) is a standing invariant. Cancel leaves the draft AND the banner intact. |
| Explicit, never silent | The user always chooses. The overlay must never auto-jump into the draft's step without the banner (CONTEXT.md locked decision). |
| No disabled buttons | Standing UAT direction — both CTAs are always clickable while the banner shows. |

### 2. Long/stalled wait — `SyncPreviewStep` (STALE-01a)

The existing copy ladder is the contract and is NOT re-copywritten: 15 s slow hint
("First sync of the day can take up to 45 seconds…"), 60 s amber patience line ("…can
take up to 15 minutes… Your draft is saved."), 900 s red "taking much longer" line, the
amber `wizard-sync-interrupted` banner (role="status") with its honest auto-retry
variant, and the recoverable `SYNC_FAILED` envelope after 3 consecutive poll errors.

What the FIX must land on (screen truths, no mechanism prescribed):

| Backend truth | Screen must show | Tone |
|---------------|------------------|------|
| Job chain reached a terminal success | The existing `passed` render ("Your verified factsheet is ready") — never "Fetching trades…" a render-cycle longer than the fix's detection allows | neutral/positive |
| Job chain reached a terminal failure | The existing `gate_failed` / failure render via `buildEnvelope` + `ErrorEnvelope` — honest red, with the envelope's existing Retry where the code is recoverable | negative |
| Poll itself gives up (existing 3-consecutive-errors rule) | The existing recoverable `SYNC_FAILED` envelope. Never a silent freeze on the spinner card | negative, recoverable |
| Nothing terminal yet, work genuinely in flight | The existing spinner card + elapsed counter + copy ladder, unchanged | neutral → amber by ladder |

Hard rules: "Fetching trades…" is a *claim about the present* and may only render while
that claim is true per whatever ground truth the 154-01 investigation establishes. No
new timeout copy, no new threshold, no fourth banner. If the fix needs a sentence for
"the job finished; refreshing this view" it reuses the status-card lead-line slot
(500-weight `text-body` line inside the existing card), copy: **"Sync finished —
loading your results…"** — neutral, no semantic color, present only for the transition
render if one exists at all.

### 3. Stale-refusal / re-derive in flight (STALE-01b)

New state contract (the only genuinely new visual state in this phase). While a
re-derive is in flight, the gate's answer is not current, so:

| Aspect | Contract |
|--------|----------|
| Shape | Follow the existing `wizard-sync-interrupted` banner pattern exactly: `role="status"`, `rounded-md border border-warning/40 bg-warning/5 px-4 py-3` — an inline branch in `SyncPreviewStep`, **not a new component file** |
| Heading | "Recomputing this strategy's analytics" — `text-body font-medium text-text-primary` |
| Body | "The previous result is out of date and is being recalculated. This screen updates when it finishes — your draft is saved." — `text-caption text-text-secondary` |
| Tone | Amber (recoverable) per the semantic gate above. ⛔ Never the red envelope, never "failed" copy, while the re-derive is in flight |
| Controls | None required. If the investigation shows a manual retry is safe here, reuse the existing "Retry sync" secondary button contract (incl. the F-3 auto-retry suppression: when the queue is auto-retrying, relabel to the existing "The sync is retrying automatically — no action needed." and render no button). No new retry mechanics may be invented ahead of 154-01 |
| Numbers | Any metric/count from the stale row is NOT shown; absent values render `—` per the Numbers Contract |
| A11y | `role="status"` (`aria-live="polite"` semantics) — non-blocking state change per DESIGN.md 9-state minimums; the terminal failure states keep `role="alert"` via `ErrorEnvelope` |

### 4. Dedup resolves to existing row (WIZCONT-02) — deliberately small

When a token-less re-connect matches an existing key/strategy server-side, the wizard
continues with the existing row. This is a *success* outcome, not an error:

| Aspect | Contract |
|--------|----------|
| Shape | One informational line in the flow the user is already in — the same neutral strip pattern as the session-expired notice: `rounded-md border border-border bg-page px-3 py-2 text-caption text-text-secondary`. NOT an `ErrorEnvelope`, NOT amber, NOT red — nothing failed and nothing needs recovering |
| Copy | "These credentials are already connected. We continued with your existing strategy instead of creating a duplicate." |
| Behavior | The wizard proceeds exactly as the fast idempotency-fence path does today (it already silently returns the existing draft pre-validate). The line is the only UI delta; no confirmation, no fork in the flow |
| Numbers/PII | Never echo the credential or account id back in copy; the venue's non-secret identity stays server-side |
