# Phase 164.6.6.3.6 — criterion 1 gate protocol (founder-run)

**Date:** 2026-10-15. **Status:** measurement only; builds nothing (D-14); adds no remote verb (D-15).

The gate answers one question by measurement: can a headless MetaTrader 5 terminal authorize on a
broker server it has never seen? It runs on the VALIDATION terminal only (D-01, D-02, D-04).

⛔ **Every step is a FOUNDER act.** No agent touches either gateway, Railway, a broker or PROD for
these steps (D-01).
⛔ **Paste yes/no, seconds, counts, error codes and kinds only.** Never a server string, account
number, password, host or service name, key id or user name. The readings go to
`164.6.6.3.6-CONTEXT.md` under `## Live verification`.
⛔ **Placeholders only. The repo is public.**
⛔ **The jobs terminal is never used** (CONTEXT, Standing constraints).
⛔ **Do not validate any key in the wizard, and do not merge anything that redeploys the analytics
service, from S0 until S8 is done** (RESEARCH Pitfall 1).

## How this protocol is delivered and run

The orchestrator hands over ONE S-step at a time. Each S-step is self-contained: it repeats every
command it needs, and it reaches the Appendix A scripts only through their `/tmp/qz_*.py` names,
which its precondition checks exist.

**Three shells.**
- **Shell L** is the founder's laptop, at the repo root. It is needed for `scripts/mt5-diag.sh` and
  for `railway domain`. One-shot commands run from Shell L (Reading B, `mt5-diag.sh`) carry no secret
  in their argv.
- **Shell G** is an interactive `railway ssh --service <validation-gateway>` with no command
  argument.
- **Shell A** is an interactive `railway ssh --service <analytics-service>`.

The tmux-session option of `railway ssh` is never used, because it installs tmux on the gateway
(RESEARCH Pattern 3).

**History.** The first command in every Shell G and Shell A session is
`unset HISTFILE; set +o history 2>/dev/null`. The last is `history -c 2>/dev/null`. Reason: the base
image sets `HOME=/config`, a persistent volume (RESEARCH Pattern 3).

**Credentials** are typed only at script prompts: `input()` for the login and server, and `getpass`
for the investor password. They are never put in an argv, an env assignment on a command line, a file
on `/config`, or a pasted reading.

**Halt rules.** Each stops the gate and returns to the orchestrator:
- any Fail bullet;
- an identity mismatch in S1;
- M1 authorizing in S3 (the control did not reproduce);
- a failed M3 restore in S5;
- a validate-site or scrub line in the analytics logs, or a Reading A validate-site row, inside the
  gate window. The readings since the last clean check are void. ONE voided reading is repeated, on
  Broker-5 if its broker is already spent; a second void goes to the founder;
- the founder aborting at any point.

**On ANY halt, the orchestrator hands over `### Halt clean-up` FIRST**, before any AskUserQuestion.
Its Record line travels with the halt signal.

Every measured step's precondition includes "no validate-site or scrub line in the analytics logs
since the previous step's Record".

**Absence needs a control** (RESEARCH Pattern 2). A Journal count of 0 is a reading only if SOME
window read by the same reader shows `j_authorized_on >= 1`. That can be S2's control, or any later
window, such as the A4 switch-back from a demo account after S3, and it qualifies the earlier
absence readings retroactively. Record which control window qualified which reading. If no window
ever reads 1 or more, every Journal absence is "no observation". A 0 on S2's same-account control
alone does not void anything.

**Interpreter (a stated choice inside D-01).** Every script runs as the Linux `python3` mt5linux
client on loopback port 8001 of `<validation-gateway>`. That call executes inside the bridge's Wine
`python.exe` with its MetaTrader5 package, which is D-01's interpreter. A second MetaTrader5 client
launched directly under Wine is not used (RESEARCH Alternatives).

**Step timing.** Start each measured call about 60 s after a `mt5 validation liveness: state=` line
in the analytics logs, so the next liveness tick is more than 8 minutes away (RESEARCH Pitfall 2).
The cadence is read from the logs, not from a variable.

### S1 — read-only inventory (Shell G, then Shell A)

**Where:** Shell G, then Shell A. **Precondition:** S0 passed. Every command is read-only.

1. Open Shell G (`railway ssh --service <validation-gateway>`) and run the history-off line:
   ```sh
   unset HISTFILE; set +o history 2>/dev/null
   ```
2. Shell kind and user. Read both; paste only the shell kind and root yes/no:
   ```sh
   echo "$0"; id -un
   ```
3. Tool presence:
   ```sh
   for t in python3 wine s6-setuidgid pgrep ss base64 xdotool xte ydotool wmctrl; do
     if command -v "$t" >/dev/null 2>&1; then echo "$t yes"; else echo "$t no"; fi
   done
   ```
4. Process counts. Use the `ps -eo args` form only, because a `comm` match never sees a Wine process
   (RESEARCH Pitfall 6):
   ```sh
   ps -eo args | grep -c '[t]erminal64.exe'
   ps -eo args | grep -cE '[m]t5linux|[s]erver.py'
   ps -eo args | grep '[t]erminal64.exe' | grep -c 'config:'
   ```
   The first is the terminal count, expected 1. The second is the bridge count, expected at least 1.
   The third is the BASELINE config-argument count. Record it. Every later restore compares against
   this baseline, not against a hard-coded 0.
5. Paths, existence only, and the `servers.dat` size in bytes:
   ```sh
   I="/config/.wine/drive_c/Program Files/MetaTrader 5"
   ls -d "$I" >/dev/null 2>&1 && echo "install dir yes" || echo "install dir no"
   ls -d "$I"/[Ll]ogs >/dev/null 2>&1 && echo "logs dir yes" || echo "logs dir no"
   ls -d "$I"/[Cc]onfig >/dev/null 2>&1 && echo "config dir yes" || echo "config dir no"
   wc -c "$I"/[Cc]onfig/servers.dat 2>/dev/null || echo "servers.dat no"
   ```
   Paste the byte count only, not the path.
6. Bridge port:
   ```sh
   ss -tln | grep -c ':8001'
   ```
   If `ss` is absent, use a socket connect instead:
   ```sh
   python3 -c 'import socket; s=socket.socket(); s.settimeout(3); print("open", "yes" if s.connect_ex(("127.0.0.1", 8001)) == 0 else "no")'
   ```
7. Client versions (rpyc major only; mt5linux expected 0.1.9):
   ```sh
   python3 -c 'import importlib.metadata as m; print("rpyc major", m.version("rpyc").split(".")[0]); print("mt5linux", m.version("mt5linux"))'
   ```
8. Identity guard, so the gate never runs on the jobs terminal. In Shell G, print the first 8 hex
   digits of the sha256 of `RAILWAY_PRIVATE_DOMAIN`:
   ```sh
   python3 -c 'import hashlib,os; v=os.environ.get("RAILWAY_PRIVATE_DOMAIN",""); print("gateway digest", hashlib.sha256(v.encode()).hexdigest()[:8] if v else "empty")'
   ```
   Then close Shell G with `history -c 2>/dev/null` and `exit`. Open Shell A
   (`railway ssh --service <analytics-service>`), run the history-off line, and print the same digest
   prefix for `MT5_VALIDATION_GATEWAY_HOST` and for `MT5_GATEWAY_HOST`:
   ```sh
   unset HISTFILE; set +o history 2>/dev/null
   python3 -c 'import hashlib,os; [print(k, hashlib.sha256(os.environ[k].encode()).hexdigest()[:8] if os.environ.get(k) else "empty") for k in ("MT5_VALIDATION_GATEWAY_HOST", "MT5_GATEWAY_HOST")]'
   history -c 2>/dev/null
   ```
   The founder compares the prefixes by eye and records "validation match: yes/no" and "jobs match:
   yes/no". That `RAILWAY_PRIVATE_DOMAIN` equals the host the analytics service dials is an
   ASSUMPTION. If it is empty, record "no observation" and confirm the service by its dashboard name
   instead. Never paste a digest, only the two yes/no readings.
9. Input-tool inventory for route (a): the `xdotool`, `xte`, `ydotool` and `wmctrl` lines from item 3,
   plus a Python X11 binding check, run in a Shell G session (reopen it and run the history-off line
   first if it was closed):
   ```sh
   python3 -c 'import Xlib' 2>/dev/null && echo "Xlib yes" || echo "Xlib no"
   ```
   State plainly: nothing is installed to make route (a) work. Installing anything is an image change
   (164.6.5 D-05) and a posture change (D-15).
10. Close every open shell with `history -c 2>/dev/null` and `exit`.

- **Pass:** one terminal process, bridge up, the install, logs and Config dirs present, validation
  match yes, jobs match no.
- **Fail:** anything else, with the halt rule. An identity mismatch halts the gate.
- **Record:** every item above as yes/no or counts, including the baseline config count.

### S9 — verdict (criterion 1)

**Where:** the orchestrator, from the pasted Record lines. **Precondition:** S0 to S8 have Record

- **Fail:** a halted gate, an unresolved under-measured negative, or a verdict outside the closed set.

        "j_mentions_server": sum(any(k in s for k in keys) for s in lines),

out["elapsed_s"] = round(time.monotonic() - t0, 1)

try:
