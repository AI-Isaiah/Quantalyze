# Phase 239 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** This phase makes **no visual change**. It adds no token, size, weight, colour, spacing
value, component or string. Everything visible stays as it ships today, and `DESIGN.md` governs it
unchanged.

- **CACHE-02** changes *how* the shared `FactsheetProvider` stores the selected range: as dates
  instead of axis indices. It also changes *what window* a 3M/6M/12M preset selects: N calendar
  months ending on the latest day, instead of 63/126/252 axis points. The `PeriodControl` buttons
  keep their look, labels, order and ARIA.
- **CACHE-04** is a no-change ruling (founder, 2026-11-24). Discovery keeps ranking BTC-unit and
  USD returns together as pure performance, with no BTC price conversion and no separate group. The
  `in BTC` chip stays and no copy changes.

The only thing a viewer can see change is **which dates** a preset or a kept manual range covers.
Those dates show in the existing range eyebrow, the brush window and the charts. §1 is the contract
for them.

**Sources:** `239-CONTEXT.md` (founder rulings Q1, Q2, Q4, Q5 and Claude's Discretion), ROADMAP
`### Phase 239`, REQUIREMENTS CACHE-02 and CACHE-04, `DESIGN.md`, and the `237-UI-SPEC.md` layout
precedent. Every code anchor was measured at worktree HEAD `f1f2bba73` on 2026-11-24. Anchors are
cited by symbol rather than by line number.

## 1. CACHE-02: the interaction contract for the selected range

### 1.1 Presets (founder Q4 "Presets roll, manual stays", Q5 "12 calendar months")

| Tab | Click result |
|-----|--------------|
| `3M` | A **rolling** preset: start = the first axis date **on or after** (latest axis date − 3 calendar months); end = the latest axis date |
| `6M` | the same, with 6 calendar months |
| `12M` | the same, with 12 calendar months |
| `ALL` | `resetXRange()`. This clears any preset or manual range, so the view shows the current full range. Unchanged. |

- **A preset rolls.** While a preset is active, a new latest day moves both ends: the end becomes
  the new latest day and the start is recomputed from it. A preset always ends on the latest day
  (SC-1).
- **Front growth: a preset still ends on the latest day** (SC-1). That is what the CONTEXT pins for
  a preset. Its start stays the same date only when the series already reached back N calendar
  months. On a shorter series the start was index 0, so front growth moves it earlier, towards
  (latest − N months). "The same dates are kept" is the **manual-range** contract (§1.2), not the
  preset's.
- **The preset is held until something replaces it.** A pan, zoom, brush, keyboard move, `ALL`, a
  reset, or a basis or unit change replaces it (§1.3).
- **`axisLength <= 1` still resets** to the full range, exactly as `selectPeriod` does today.
- **Short series.** If the series is shorter than N calendar months, the start resolves to index 0.
  The window equals the full range, and `resolveRangeScope` labels it `Full history`, as an
  equivalent index window does today. Nothing new is shown.
- **Month-end arithmetic is not decided here.** Examples: the 31st minus N months, or 29 February
  minus 12 months. The CONTEXT is silent, and the choice is not visual. The planner picks one rule
  and pins it in a test.

### 1.2 Manual ranges (every other writer)

The manual class is every `setXRange` call outside `PeriodControl` (measured with
`grep -rn 'setXRange(' src --include='*.tsx' | grep -v '\.test\.'`):

- `TimeSeriesChart`: drag-zoom, drag-pan, wheel zoom and the keyboard (arrow pan, `+`/`-` zoom)
- `MasterBrush`: drag-select, re-anchor click and edge drag

The contract for a manual range:

- **It keeps its exact start and end dates when the series grows at either end.** This includes a
  manual range whose end was the latest day: when a newer day arrives it stays on its old end date
  and **does not roll**. Only 3M/6M/12M roll.
- **Resolution on each render, against the active axis:** start → the first index on or after the
  start date; end → the last index on or before the end date (CONTEXT, Claude's Discretion).
- **Off-axis fallback:** if the stored dates fall off the axis, the view falls back to the **full
  range**, as the shrunk-axis case does today (`userRange[1] <= maxIdx ? userRange : fullRange`).
  The planner pins the exact partial-overlap boundary in a test that mirrors the existing
  shrunk-axis test. That choice is not visual.
- **Consequence the viewer can see, accepted by the ruling:** a range kept on growth reads
  `Selected range: <start> – <end>`, and `Reset to full history` stays offered, because the range
  no longer spans the whole axis. This follows from "manual stays". No new copy or control results.

### 1.3 Kept exactly as today

- The `setXRange` clamps: the three-axis max (cash, `mark_to_market`, `smoothed_mtm`) and
  `MIN_VISIBLE_SAMPLES` (5), applied in `setXRange` as today (CONTEXT). Whether a window that
  resolves narrower than 5 samples after growth or shrink is widened at resolve time is not decided
  here. That choice is not visual, and the planner makes it.
- `fullRange` stays cash-sized, and the opening window is the full history (the
  `ScenarioFactsheetChart.opening-range.test.tsx` D-07 contract).
- The range resets in `FactsheetView`: on an actual basis toggle, on a unit-view (BTC/USD) toggle,
  and on ControlBar `Reset view`. The `Reset to full history` button, `TimeSeriesChart` double-click,
  `Home`, `Esc` and `MasterBrush` double-click all still call `resetXRange()`, which clears a preset
  intent too.
- The range is never persisted (Phase 193 D-02). `factsheetViewStateCodec` gets no range field.
- The change lives in the shared provider, so the real factsheet's pan, zoom and brush keep their
  dates too. There is no composer-only fork.

### 1.4 No active-tab state

`PeriodControl` keeps `aria-selected={false}` on **every** tab, and no tab gets selected styling,
even though the provider now remembers a rolling preset intent. Lighting the active preset would be
a visual and ARIA change that this phase does not make. The brush and the range eyebrow stay the
source of truth for what is selected.

## Accessibility

- **ARIA unchanged.** `role="tablist"` with `aria-label="Period"`, and `role="tab"` with
  `aria-selected={false}` on every tab. The composer's WCAG-AA axe gate keeps passing on the same
  DOM.
- **No live region.** A preset rolling on growth is not announced. No `role="status"` or
  `aria-live` is added. The range eyebrow is the existing visible statement of the window.
- **Keyboard unchanged.** Tabs are `<button>`s in DOM order. Chart keyboard navigation (arrows,
  `+`/`-`, `Home`, `Esc`) behaves as today, and an arrow or zoom result is a manual range (§1.2).
- **Target size and contrast unchanged.** Tabs stay at 24px minimum height. `#4A5568` on `#FBFCFD`
  is the existing pair.
