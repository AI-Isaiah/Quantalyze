### What the embedded Python must emit — recommended shape

⛔ **Constraint that governs the choice**, `arms/mt5.mjs:102-106` verbatim:

```
 * ⚠️ ONE DELIBERATE DIFFERENCE from mt5-diag.sh's output shape: `terminal_info`
 * is emitted in BOTH branches ("present" / null) rather than only when null. In
 * mt5-diag.sh the healthy reading is the ABSENCE of a key, which would make the
 * classifier's OK test satisfiable by a truncated or malformed line. A positive
 * marker cannot be produced by something going missing.
```

**Recommended (Option A — nest the two booleans under `terminal_info`):**

```python
ti = mt5.terminal_info()
if ti is None:
    out["terminal_info"] = None
else:
    d = ti._asdict()
    out["terminal_info"] = {"connected": d.get("connected"), "trade_allowed": d.get("trade_allowed")}
```

Why A over the alternatives:

- It keeps the **positive marker**: a JSON object cannot be produced by a field going missing, so
  the OK test at `:234` stays unsatisfiable by a truncated line.
- It keeps branch (7) — `initialize ok but terminal_info() returned null` — working unchanged,
  which criterion 4 requires.
- It records exactly the two fields and nothing else, satisfying decision 5 literally.
- ⚠️ Emit **raw** `d.get(k)`, not `bool(d.get(k))`. `bool(None)` is `False`, which would render a
  *missing* key as a confident `false` — the same "absence produced a positive reading" failure the
  comment above exists to prevent. Raw gives `null`, which prints as `null` and is visibly not a
  boolean.

Option B (top-level `out["connected"]` / `out["trade_allowed"]`, no `terminal_info` key) is
**rejected**: it deletes the presence marker branch (7) keys on, and forces every null fixture to
change.

## Common Pitfalls

### Pitfall 1: the `SELF_TEST_SCENARIOS` pair
**What goes wrong:** you add `6.txt` and the run dies at the tail with
`the counted scenario set is complete: 79 header(s) printed, SELF_TEST_SCENARIOS is 78`.
**Why it happens:** the runner's completeness assertion is the control; the header numeral is only
the display.
**How to avoid:** bump `run.mjs:149` **and** `prod-prober-wiring.test.ts:1822` in the same commit.
**Warning signs:** a green self-test with a red vitest shard, or vice versa.

### Pitfall 2: a remedy under 40 characters, or a near-duplicate
**What goes wrong:** the green-fixture leg fails with *"every mt5 kind carries a REMEDIES entry of
at least 40 chars"* or *"no two mt5 remedies are the same string"*.
**Why it happens:** `run.mjs:1106-1114` ranges over **every key of `REMEDIES`**, not only the kinds
the table exercises.
**How to avoid:** write the remedy first, count it, and diff it against the `-10005` text.

### Pitfall 3: putting the `-6` branch after branch (8)
**What goes wrong:** nothing fails — branch (8) is the unconditional tail, so a `-6` branch below it
is dead code and `6.txt` still reports `mt5-terminal-error`. The self-test catches it; a reviewer
reading only the diff might not.
**Why it happens:** `classifyProbe` ends in an unguarded `return`.
**How to avoid:** insert between `:268` and `:270`. `arms/mt5.mjs:152-155` says it outright:
*"⛔ THE ORDER OF THESE BRANCHES IS THE ARM."*

### Pitfall 4: `bool(d.get(k))` in the probe body
**What goes wrong:** a terminal whose `_asdict()` lacks `connected` records `connected: false` — an
absence rendered as a confident measurement.
**How to avoid:** emit raw `d.get(k)`. See TASK THREE.

### Pitfall 5: treating a green prober as the acceptance signal
**What goes wrong:** the phase is "verified" by an hourly run that went green because a human fixed
the login, not because the code changed.
**Why it happens:** the live `-6` is real and recurring (run `34758502223`, 2026-09-13).
**How to avoid:** the acceptance signal is `--self-test` at `79/79` plus the falsifier's observed
RED. The phase's own fence says so.

### Pitfall 6: the `-6` reading is intermittent, so a live confirmation may or may not be available
**What goes wrong:** you dispatch `--arm mt5` to "see the new kind fire" and get a healthy terminal.
Measured: `34706551355` (2026-09-12 16:52Z) read `initialize=true … connected=true trade_allowed=true`;
`34758502223` (2026-09-13) read `-6`.
**How to avoid:** a live dispatch is a **bonus observation**, never a gate. The fixture is the gate.
