# Phase 164.8.3 Plan 03: `terminal_info()` recorded as two booleans exactly — Summary

The prod-prober's MT5 arm now records `terminal_info()` as the two fields `docs/runbooks/mt5-go-live.md` Step 2 calls the verification — `connected` and `trade_allowed`, nested, taken raw — retires the `"present"` string sentinel in favour of the JSON object shape itself as the positive marker, tightens the presence check to a type test so a stray string can no longer read as a healthy terminal, and drops `build` and the production install `path` from a world-readable Actions log.

**Duration:** 22 min · **Tasks:** 2 · **Files changed:** 3 · **Commits:** 2

---

## Accomplishments

1. **`MT5_PROBE_PY` narrowed to D-05's two booleans, nested.** The five-key flatten loop and the `"present"` sentinel are gone; the `else` arm now assigns `out["terminal_info"]` a dict built from `ti._asdict()`. The constant remains a literal array of strings joined with `\n`, still calls exactly `initialize()` / `last_error()` / `terminal_info()`, and still contains no `${` — all three self-test gates over it pass unchanged.
2. **The divergence argument rewritten from ONE to TWO, dated.** The positive-marker argument survives in substance and is sharpened (an object is a marker; an absent key is not, and neither is a bare string). The new field-set divergence from `scripts/mt5-diag.sh` is argued on the runbook's two-field criterion, and the file is named as deliberately left alone because its own `Reading the result:` note interprets `tradeapi_disabled` for a human.
3. **`terminalInfoPresent` tightened to a TYPE test.** Object, non-null (`typeof null === "object"`), non-array. This closes the exact hole the sentinel used to close, now that the sentinel is gone — proven by driving a bare-string `terminal_info` through the real `classifyProbe`.
4. **The OK info line reduced to the two booleans.** `build=` dropped; neither boolean judged. `path` is no longer collected at all, which is a genuine reduction in what a PUBLIC log can carry.
5. **`ok.txt` rewritten — and it is the only fixture changed.** Line 1 (the CLI banner) is byte-identical, which keeps it load-bearing proof that the arm SCANS for the PROBE line rather than assuming line 1.
6. **Five `164.8.3 CRITERION 7` assertions added to the EXISTING byte-for-byte scenario**, reading the CAPTURED `mt5: ` log line rather than `verdict.info` or the arm's source. No `scenario()` added; the count stays at 80.

## Deviations from Plan

**1. [Rule 2 — Missing critical] `Array.isArray` guard added to the presence check**

- **Found during:** Task 1(c)
- **Issue:** The plan specified an object test with a null guard, correctly noting `typeof null === "object"`. It did not mention that `typeof [] === "object"` too — a JSON array `terminal_info` would have passed the specified test, read as a healthy terminal, and printed `connected=undefined trade_allowed=undefined` as a GREEN reading. That is the same class of failure the tightening exists to close.
- **Fix:** `ti !== null && typeof ti === "object" && !Array.isArray(ti)`. The probe emits a dict; an array is not one.
- **Files modified:** `scripts/prod-prober/arms/mt5.mjs`
- **Verification:** self-test 80/80; the plan's stray-string calibration still passes; branch (7) still fires on `terminal-info-null.txt`.
- **Commit:** `cd88ee23`

**2. [Rule 2 — Missing critical] The four CRITERION 7 assertions placed OUTSIDE the scenario's `&&` chain**

- **Found during:** Task 2
- **Issue:** The plan said "FOUR SEPARATE `expect(...)` calls — one property each, so a failure names which property broke rather than crediting one RED to four controls". The file's prevailing idiom chains assertions with `&&`, which short-circuits: a failure in the first would prevent the other three from running at all. Plan 02 already RECORDED this exact structural vacuity for two by-name absence lists in the same file.
- **Fix:** Each property is its own `pass = expect(...) && pass;` statement, appended after the scenario's existing chain. All four always run and each reports independently — which is what neuters A–D then proved.
- **Files modified:** `scripts/prod-prober/run.mjs`
- **Verification:** neuters A, B, C, D each reddened exactly one assertion while the other three printed green.
- **Commit:** `2068007d`

**Total deviations:** 2 auto-fixed (both Rule 2 — missing critical correctness). **Impact:** both strengthen the assertions the plan asked for; neither widens scope beyond the three files the plan names, and `git diff --name-only d5a3a62b..HEAD` lists exactly those three.
