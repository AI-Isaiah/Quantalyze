### `scripts/prod-prober/arms/mt5.mjs` (probe arm, SSH exec, request-response)

**Analog:** `scripts/mt5-diag.sh` (62 lines, read in full)

**The rules, verbatim** (`mt5-diag.sh:9-18`) — carry into the arm module's header:
```bash
# ⛔ READ-ONLY, and deliberately so: it calls initialize() + terminal_info() and
# NEVER login(). A login() is an "account change"; while
# `[Experts] Account=1` is armed, MT5 re-clears `Enabled` on every account
# change, so a probe that logged in would itself re-break the thing it is
# measuring. That is not hypothetical — it happened during the 2026-08-13
# investigation, where each diagnostic round re-disabled algo trading.
#
# ⚠️ Do NOT "improve" this by reading Config/terminal.ini instead. MT5 only
# rewrites that file on a clean exit, so it can report `Enabled=0` while the
# running terminal is already correct. The live terminal_info() is the oracle.
```

**The probe body and how it reaches the terminal** (`mt5-diag.sh:25-46`):
```bash
SERVICE="${MT5_DIAG_SERVICE:-mt5-gateway}"
RPYC_HOST="${MT5_DIAG_HOST:-127.0.0.1}"
RPYC_PORT="${MT5_DIAG_PORT:-8001}"

import json
from mt5linux import MetaTrader5
mt5 = MetaTrader5(host="${RPYC_HOST}", port=${RPYC_PORT})

B64=$(printf '%s' "$PROBE" | base64 | tr -d '\n')
railway ssh --service "$SERVICE" \
  "python3 -c \"import base64;exec(base64.b64decode('${B64}'))\"" 2>&1 | grep '^PROBE ' || {
    echo "mt5-diag: no PROBE line returned — the gateway may be down, or rpyc unreachable on ${RPYC_HOST}:${RPYC_PORT}." >&2
```

with `stdin` closed and a timeout (RESEARCH Pitfall 4); the classifier reads

**The three non-negotiables** (`prod-body-drift-check.sh:24-35`):
```bash
# 1. NEVER SKIP. The credential check is the FIRST thing this script does and
#    an absent credential is `exit 1`, never `exit 0` and never a `::notice::`
#    skip. ...
```

Rule 3 IS RESEARCH Pitfall 8 for the prober: `psql -v ON_ERROR_STOP=1 -At`, check exit status,
non-zero → a measure-fail defect kind, never "zero rows".

**LEFT/RIGHT with a hash-bound acknowledgment — the cron-drift shape** (`:12-18`, `:37-44`):

```bash
# LEFT  : supabase/schema/functions/<name>.sql — the committed canonical body.
# RIGHT : PROD's live definition, obtained through an INJECTABLE fetcher so the
#         gate's logic is testable without touching production.
# ...
# To wave it through, the PR's migration must carry
#     -- prod-body-ack: <sha256>
# where <sha256> is the hash of the NORMALIZED PROD body, which this gate
# prints when it fails. The hash BINDS the acknowledgment to the exact PROD
# content: a stale ack, or one written without looking, does not match.
```
Port: LEFT = `cron-manifest.json` (`captured_at`, per-job `command_sha256`), RIGHT = PROD

`cron-drift: manifest captured <date> sha <a> — PROD now sha <b>` and the two readings ("PROD

## Shared Patterns

### Credential gate — per-name, first, unconditional, fatal
**Source:** `scripts/prod-body-drift-check.sh:121-133`
**Apply to:** `scripts/prod-prober/run.mjs` (script half) and `prod-prober.yml` (workflow half, see Analog B above)
```bash

# Deliberately before ANY work detection, so this gate can never rationalise an
# exit 0 out of "there was nothing to do" while it is unconfigured.
for var in SUPABASE_PROJECT_REF SUPABASE_ACCESS_TOKEN SUPABASE_DB_PASSWORD; do
  if [ -z "${!var:-}" ]; then
    echo "::error::${GATE}: ${var} is not configured, so this gate CANNOT read PROD."
    echo "::error::This is a HARD FAILURE, not a skip. A gate that reports success while"
    echo "::error::unconfigured is the SKIP-01 defect this phase exists to remove: it would"
    echo "::error::be green having checked nothing, on the workflow guarding production"
    echo "::error::migrations. Configure the secret, or delete this gate deliberately."
    exit 1
  fi
done
```
⚠️ Difference for the prober: this analog EXITS at the first absent name. The prober must instead
`addDefect("credential-absent", <arm>, null, "<NAME> is not set")` per name and KEEP RUNNING the
arms whose credentials are present (CONTEXT `:44-45`, all four arms every time), exiting 1 at the
end. No script in the repo prints a per-name `credential: <NAME> present` line today — the
closest is the aggregate `::notice::Drift-check credentials present.` at
`migration-drift-check.yml:110`. The per-name print is new; RESEARCH F1 specifies it and the
`credential-absent` self-test scenario proves it.

### Never print PROD text, names only
**Source:** `scripts/prod-body-drift-check.sh:29-32`; `main.py:881-883` (`/health` names secrets, never values); `migration-drift-check.yml:171-173`
