## D-18 — the posture, MEASURED and FLIPPED

Run 34018874984 put a check-run named `probe` with conclusion `failure` on its commit.
This workflow's primary trigger is `schedule:` (hourly), and scheduled runs execute
against the DEFAULT branch — so an hourly red prober lands a red check on main's HEAD.
Railway's wait-for-CI reads the whole check-suite.

`analytics-deploy-verify.yml:17-24` records the consequence FROM AN INCIDENT: on
2026-06-21 a red check on the merge SHA made Railway SKIP the deploy, prod never
converged, and the check stayed red. That probe runs 6-hourly and exits 0 for exactly
this reason. This one runs HOURLY, on the same path.

So the scheduled path now exits 0, with the dedup'd P1 issue as the loud signal.
NOT a general relaxation: a manual dispatch still exits with the script's status, the
self-test step still hard-fails (a BROKEN prober stays loud; only a prober reporting a
real PRODUCTION defect goes quiet at the check-suite level), and no `continue-on-error`
or `|| true` was introduced. The wiring pin CAUGHT this change and was rewritten to
permit exactly one guarded `exit 0`; two neuters prove it still bites.
