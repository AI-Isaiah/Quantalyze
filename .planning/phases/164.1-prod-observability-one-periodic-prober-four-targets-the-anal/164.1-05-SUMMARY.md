## Decisions Made

1. **The narrowed live invocation is an `if`/`else` pair, each arm capturing its own status** — not a shared `status=$?` after `fi`, and not an argv array. Both alternatives would have broken the property being pinned: `fi` would sit between the bare command and `status=$?`, and an argv array would erase the byte-identical bare line the script's header documents.
2. **The wiring test runs under jsdom, not the node project.** `vitest.node-env.ts` is outside this plan's `files_modified`, and `mutation-runner-floors.test.ts` — the direct analog — is likewise unlisted. Cost is one jsdom construction; no behavior differs.
3. **`::add-mask::` appears exactly once in the file** so the plan's count-one acceptance gate is unambiguous; the header refers to masking in prose without the literal.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The plan's stated source-derived scenario count does not exist in the source**

- **Found during:** Task 2 (writing the `kinds and floors` block)
- **Issue:** The plan's `<behavior>` says "the source contains exactly 50 `=== SELF-TEST k/50:` headers numbered 1..50 contiguously". It does not. `scripts/prod-prober/run.mjs:978-982` auto-numbers the headers at RUNTIME off the same `printed` counter its own completeness assertion reads. Measured: `grep -c '=== SELF-TEST' scripts/prod-prober/run.mjs` is **3** (a template literal, an assertion message and the PASSED banner), and `grep -o '=== SELF-TEST [0-9]*/50:'` matches **0**. A pin written as the plan describes would have asserted over an empty match set and passed while measuring nothing — precisely the vacuity class this phase exists to remove.
