# Phase 164.1 Plan 02: PYAPI-06 closed at both halves Summary

**The analytics seam can no longer send an anonymous request, and can no longer discard the one absent-header case that is our own outage: `analytics-client.ts` throws a named `SeamConfigError` above the `try` when `ANALYTICS_SERVICE_KEY` is empty and emits `X-Service-Key` unconditionally, while `verify_service_key` answers an absent header with its own 401 machine code `SERVICE_KEY_ABSENT` — each guard proven to bite by deleting it, watching the test go red, and restoring the file byte-identically.**

## Accomplishments

1. **The TypeScript half (D-09).** `analyticsRequest` — the ONE chokepoint all nine analytics wrappers inherit — now refuses at call time when `SERVICE_KEY` is empty, with a message that starts `[analytics-client]`, names `ANALYTICS_SERVICE_KEY`, says this is a deployment misconfiguration on our side and NOT an analytics-service failure, and never carries the value. The `X-Service-Key` entry is now an unconditional property. It was a truthiness-guarded spread, which is the whole of TODOS 0.04: with the secret absent the header simply VANISHED, every wrapper issued an anonymous request, the service answered 401, a 401 never trips the 140.2 breaker, and the seam ran dark for seven days behind a green board.

2. **Placement is the design, not a detail.** The throw sits ABOVE the `try`, mirroring the tenant-claim reasoning at `analytics-client.ts:415-441`. Catch arm 1b already rethrows a `SeamConfigError` unwrapped, so inside the `try` it would *currently* be correct — but correct-by-arm-order is one reshuffle away from a config fault reaching ops as "the analytics service is not reachable", which is T-164.1-09 by name. Above the `try` it cannot happen by construction. There is deliberately NO module-load assertion: CONTEXT D-09 rejects it, and local dev plus any build step that merely imports the module must keep working.

3. **The Python half (D-10).** A new `if not provided:` arm between the header read and the `compare_digest` returns `service_error_response(401, "SERVICE_KEY_ABSENT", retryable=False, detail="Unauthorized")`. The status stays 401 — moving absent to 400 would change the public contract for unauthenticated callers — and the wrong-key body stays byte-identical. Only the CODE is new.

4. **D-11 held mechanically, not rhetorically.** No `_auth_log` and no `_capture_secret_misconfig` in the new arm, because an absent header is internet background noise and capturing it buries the real signal. The proof is stronger than an assertion: `git diff HEAD~1 -- analytics-service/main.py` shows **34 inserted lines and ZERO deleted**. Nothing in the `if provided:` block, or anywhere else in that file, could have moved.

5. **The pins moved without weakening.** `test_missing_service_key_returns_clean_401` now asserts the code AND, in the same test, that a wrong key still yields exactly `{"detail": "Unauthorized"}`, plus `resp.json() != wrong.json()`. The file itself now proves the two bodies differ, rather than leaving a reader to notice that two assertions in two functions happen to disagree. The zero-event pin and `faults == ["unset", "mismatched"]` are untouched.

6. **The new wire code was dispositioned, and the roster was watched going red first.** `SERVICE_KEY_ABSENT` reddened `seam-venue-vocabulary.invariant.test.ts` on two assertions before either edit was made. Only then was the row hand-typed into `EXPECTED_EMITTED_CODES` (37 → 38 codes, 42 → 43 call sites, `DERIVED_FLOOR` unchanged at 22 since 0.6 × 38 = 22.8) and the reasoned exemption added to `VENUE_WIRE_CODES_WITHOUT_VERDICT`. That ordering is what makes the green a design rather than an accident.
