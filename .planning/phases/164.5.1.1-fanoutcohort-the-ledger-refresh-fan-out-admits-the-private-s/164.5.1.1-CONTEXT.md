<decisions>
## Implementation Decisions

### The status set
- Admit `private` and nothing else: the set becomes `{published, pending_review, private}`. This
  is exactly the measured defect and no more. `archived` is NOT added, and the phase does not
  mirror `ALLOWED_STRATEGY_STATUSES` (which would drag in `draft`, and a draft strategy has no
  factsheet to refresh — the existing narrower pair is right about that).
- The set stays an INLINE literal in the function body, where it lives today. One site, covered by
  the gate. No shared SQL constant or helper is introduced.
- ⛔ The sibling recurring fan-out (`20260412094449:239`, poll positions) is **NOT** widened in
  this phase. It enqueues a different job kind, so widening it would arm a SECOND, UNMEASURED
  production behaviour in the same migration. This deliberately departs from the project's
  "close the class, not the instance" rule, and the reason is stated rather than hidden: there is
  a measurement for the ledger fan-out and only a suspicion for the sibling. It is booked and
  measured separately.
- `ALLOWED_STRATEGY_STATUSES` (`analytics-service/routers/cron.py:148` =
  `{draft, pending_review, published}`) is **measured first** — who reads it, and what each reader
  does with it — and only then decided. It is not changed blind in this phase.

### The gates
- `supabase/tests/test_ledger_refresh_fanout.sql` gains an arm proving a `private` strategy IS
  SELECTED, carrying a `RED-UNDER` annotation. Without it the widening is asserted, not proven.
  ⚠️ Measured 2026-09-17: the file holds 44 `RED-UNDER` arms today and NONE of them touches
  `private` — its fixtures are created as `draft` and promoted to `published`. The gate was green
  while the function was useless in production.
- A **cohort-agreement arm** is added: no status may appear as stale in `ledger_refresh_staleness`
  that the fan-out then refuses. This is the defect as a CLASS — `private` shipped in July 2026,
  the fan-out in September, and nothing compared the two. A future sixth status cannot repeat it.
- Both new arms are **neuter-verified**: neuter the arm, observe RED, restore, observe GREEN.
  Mandatory, both arms, per this project's anti-vacuity rule. A neuter that does not APPLY reads
  as GREEN and measures nothing.
- `ARMS_FLOOR` in `scripts/mutation-runner/run.mjs` is raised to the newly measured value, read by
  SYMBOL and never from a number restated in prose.

### Rollout and blast radius
- After the PROD apply, the verification waits for the **natural `25 * * * *` tick**. A manual
  invocation would prove only that the function finds candidates; the scheduled tick proves
  pg_cron finds them under the registered identity and privileges — and that distinction is
  precisely what made this phase necessary.
- The deribit composite `081f2912…` (141 days, the oldest factsheet in the system) stays excluded.
  D-01 excludes composites by name and with its own rationale; silently reversing it here is the
  class of side effect this phase exists to clean up. Booked separately.
- The disconnected key `87bb2086…` stays excluded. `ak.disconnected_at IS NOT NULL` is doing
  exactly its job.
- `T-164.5.1-09-07` — the fan-out's all-candidates-failed branch — is exercised in THIS phase once
  candidates exist. That is the unblock for Phase 164.5.1's verification.

### Claude's Discretion
- The migration's file name, internal structure and comment placement, within this repo's
  migration house style.
- How the cohort-agreement arm is expressed in SQL, provided it can be neutered and observed RED.
- The exact shape of the `ALLOWED_STRATEGY_STATUSES` measurement.
