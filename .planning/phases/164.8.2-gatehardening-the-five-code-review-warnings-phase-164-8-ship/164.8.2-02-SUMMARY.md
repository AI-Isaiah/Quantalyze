## `[ASSUMED A1]` — OBSERVED, on which flavours, and what it says

The plan required that GNU grep's behaviour be **observed and recorded per grep flavour, never asserted as a permanent cross-platform test**. It was observed on all three, using the C-0331 block and pattern verbatim.

The research could not measure GNU grep because a `docker run ubuntu:24.04` pull did not complete. **It did not need a pull:** `postgres:16` was already in the local image cache and is Debian-based, so it carries GNU grep 3.11.

| grep | how obtained | `-Eiq` (pre-fix) | `-aEiq` (post-fix) | reading |
|---|---|---|---|---|
| **ugrep 7.8.4** | this repo's `grep` shell function (`exec -a ugrep …`, passes `-I`) | **rc 1 — reads the list CLEAN** | rc 0 — branch fires | **the defect, reproduced** |
| **BSD grep 2.6.0-FreeBSD** | `/usr/bin/grep`; also what `spawnSync("bash", …)` resolves under vitest on this machine | rc 0 | rc 0 | no difference |
| **GNU grep 3.11** | `docker run --rm postgres:16` (Debian; the family ubuntu-latest runs) | rc 0 | rc 0 | **no difference** |

The GNU reading was taken across `LC_ALL=C`, `C.UTF-8` and `en_US.utf8`, and across four fixture shapes: a NUL before the matching line, a NUL **on** the matching line, an invalid-UTF-8 `\xff` before it, and a `\xff` on it. `-a` never changed the verdict in any of the twelve combinations.

**What this means, stated plainly.** A1 is **false for the runner's grep**. The review's WR-04 scenario — "one byte makes the last check before the PROD apply pass without reading the list, on CI" — **did not reproduce on GNU grep**. The `-a` fix is still correct and is kept, on two grounds that do not depend on A1: it is the repo's stated mandatory rule (`test-restore-from-baseline.yml:1291-1293`), and it removes a real flavour dependence that bites today on any environment whose `grep` is ugrep or a `-I`-passing wrapper — which is what a developer running these gates locally actually has. But it should not be described as having closed a live production exposure on CI, and the PROD pin's message now says exactly that.

The pre-fix reading is also **printed by the test on every run** (`[WR-04 A1 OBSERVATION] pre-fix (\`grep -Eiq\`, no -a) on the NUL fixture: step-rc=…, branch-fired=… — grep here is: …`), so the CI log will carry the GNU reading from the runner itself rather than from this container. Under the default vitest reporter a passing test's stdout is hidden; it is visible with `--reporter=verbose` and on any failure. Locally it printed: `step-rc=1, branch-fired=yes — grep here is: grep (BSD grep, GNU compatible) 2.6.0-FreeBSD`.

**Not yet obtained:** the line from an actual ubuntu-latest CI run. No CI run exists for this branch yet, so no run id can be quoted. The container reading above is the same grep family and version line but is not the runner itself.

## The deliberate `PROD_C0331_TAIL` move (RESEARCH Pitfall 3)

The pin's message before this plan, quoted in full:

> "the PROD `Push migrations to production` C-0331 tail CHANGED. The one automatic applier of DDL to production is not something to edit as a side effect of editing the job around it."

That is precisely why the PROD `-a` is its own commit (`5362f807`), separate from the TEST one, and why the pin's `it` title changed from "is byte-identical to its pre-164.8-05 form" to "is its pre-164.8-05 form EXCEPT the `-a` added deliberately by 164.8.2". The message now names the phase, the date, the one line that moved, the four things that did not (`--linked`, `/tmp/migration-list.txt`, the `::error::` wording, the `exit 1`), the reason, and the measurement above — and closes with "Any FURTHER change is what this pin exists to stop". The existing `| tee`-dropping calibration is untouched and still bites.

## Decisions Made

1. **The `-a` fix is kept despite A1 being disproved.** Reverting it because "GNU grep was never blind" would re-introduce a flavour dependence in a check that gates production, and would contradict a rule the repo states in imperative form two lines above one of these very greps. What changed is the *justification*, and the justification is now written down in the pin's own message where the next reader will meet it.
2. **The NUL in the fixture is spelled `\u0000`, not pasted.** The editor initially wrote a raw `0x00` byte into the source; it was replaced via a node script that asserts exactly one raw NUL before and zero after. A literal NUL in this file would have made it the second file in the repo that plain `grep` silently skips (`src/lib/wizardErrors.test.ts` is the first) — a self-inflicted instance of the exact defect class this plan closes.
3. **IN-04 uses one local helper for both call sites** rather than two verbatim copies. The repo's self-containment convention is about not creating a cross-file helper module that only wiring tests import; two identical closures inside one `describe` would be duplication with no independence benefit, since both pins read the same file.
4. **`runScript`'s `files` option was widened to `string | Uint8Array`.** The property under test is what a BYTE does to grep, so the fixture must be able to be bytes. Backward compatible; no other caller changed.
