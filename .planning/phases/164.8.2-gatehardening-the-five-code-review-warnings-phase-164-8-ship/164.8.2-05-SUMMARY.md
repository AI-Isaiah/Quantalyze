## Deviations from Plan

### [Rule 1 - Bug] The plan's IN-06 harness could not reach the line it was meant to test

- **Found during:** Task 1, before writing the arm.
- **Issue:** the plan specifies `BASELINE_FILE=<tmp>/does-not-exist.sql`. Measured against the
  UNFIXED script exactly as written:

  ```
  exit=1
  grep: /…/does-not-exist.sql: No such file or directory
  ::error::restore-test-from-baseline: MEASURE_FAIL: could not count the filtered line class in /…/does-not-exist.sql (grep exited 2).
  ```

  An absent baseline never reaches the filter line: the `grep -ac` COUNT ~170 lines above reads
  the same path and fails first with its own message. So the arm would have been RED before AND
  after the fix — it measures the count site, not the site under test — and its
  "output contains `MEASURE_FAIL`" half would have passed on the pre-fix script, which is the
  vacuity class this phase exists to remove.
- **Fix:** give the harness a REAL baseline (so the count site succeeds, as it does on a real
  run) and inject the read failure AT THE CALL SITE with a `grep` shell function that returns 2
  for the `-v` invocation and delegates every other one to `command grep`. That reproduces the
  real shape — a read that failed HERE while the count succeeded — and it binds to the line under
  test. Both the measurement and the reasoning are recorded in a comment above the arm.
- **Files modified:** `src/__tests__/restore-test-from-baseline.test.ts`
- **Commit:** `c6862804`

### [Rule 1 - Bug] Task 1's third `<verify>` conjunct is grep-flavour dependent and reads 0 on this box

- **Found during:** Task 1 verification.
- **Issue:** `grep -c 'could not read ${BASELINE_FILE} while filtering'` returns **0** here while
  `grep -cF` on the same pattern returns **1**. `grep` on this machine is **ugrep 7.8.4**, whose
  BRE parses `{BASELINE_FILE}` as an interval expression; GNU grep treats a non-interval `{` as
  a literal. The conjunct's `fails_when` reads 0 as "the wrap is missing or the message drifted",
  which would be a FALSE red here.
- **Fix:** the conjunct was run in the flavour-independent `-F` form and returns exactly 1. The
  durable pin is not the shell conjunct at all — the vitest arm asserts the wrapped two-line
  form appears in the script exactly once, through `node:fs`, with no grep in the path. Recorded
  rather than silently "fixed" in the plan: a gate that reports the opposite of the truth on one
  of two common grep flavours is worth naming.
- **Files modified:** none (a measurement about the verify command).
- **Commit:** n/a

### [Deliberate, per plan] IN-02's derivation is partial

The plan permits the fallback if the full derivation exceeds ~20 lines. Walking every
`run_arm "<n> …` label back to the refusal message its legs grep for is a parser of the
self-test's own bash. What IS derived: the sentence is read as PROSE (comment prefixes stripped,
lines rejoined) so a wrapped list is not missed, every number it names must resolve to a real
`run_arm` label — a list naming a phantom arm is red — and 26 must be among them. The comment
above the arm says this outright rather than implying a completeness it does not have.
