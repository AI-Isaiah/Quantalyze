### Anti-Patterns to Avoid
- **`grep -o … || true`** in a gate: banned softening token; use `awk` or the `set +e; …; rc=$?; set -e; [ "$rc" -le 1 ] || fail MEASURE_FAIL` idiom (`restore-test-from-baseline.sh:986-987`).
- **A test that greps for a string instead of running the step** — wiring tests extract and execute (`extractRunScript`, `spawnSync("bash", …)`).
- **A neuter that does not apply** reads as GREEN (memory: anti-vacuity). Every calibration must `expect(mutated).not.toBe(SRC)` first — the wiring tests do this (`:714 expect(widened).not.toBe(SRC)`).
- **Widening the redaction globs to `.sql/.csv`** — the two-loop pin at `test-restore-workflow-wiring.test.ts:622-650` reds on it by design, and the locked decision rejects it.
- **A shared test helper** — rejected by the locked decision and by Phase 164.8 Plan 05 Task 2's convention.
- **Env-overridable ceiling `"${FRONTIER_EXEMPT_CEILING:-3}"`** (the review's sketch): it would NOT be seen by the SC-9 scan (`=(\d+)\b` needs bare digits) and it hands CI an env knob that can raise the ceiling without a reviewed edit — the opposite of `WAIVED_CEILING`, which is `overridable ONLY by --self-test` (`run.mjs:3911`). Prefer a bare constant; if the self-test needs a different value, thread it the way `run.mjs` does (an explicit self-test-only parameter), not via ambient env.

## Common Pitfalls

### Pitfall 1: The SC-9 meta-arm reds on the new ceiling for a reason unrelated to WR-02
**What goes wrong:** `gate-family-meta.test.ts` reports `a threshold in this family has NO measurement beside it` or a `KNOWN_THRESHOLD_SITES` set mismatch.
**Why:** `FRONTIER_EXEMPT_CEILING=3` matches `shConst`; the found set must equal the known set.
**How to avoid:** `MEASURED 2026-09-09` within 80 lines above; add the key to `KNOWN_THRESHOLD_SITES`. Run `npx vitest run src/__tests__/gate-family-meta.test.ts` in the same task.

### Pitfall 2: The absurdity floor pre-empts the ceiling arm
**What goes wrong:** the new RED arm exits 1 for `MEASURE_FAIL — … ledger_rows` rather than the ceiling.
**Why:** the floor fires before the frontier block when the ledger reports ≥ 50 rows and < 50 % match. The self-test stub reports no row count, so it should not fire — but the arm must assert on the ceiling's `::error::` text, not on exit 1 alone (`run_arm` compares exit codes only; capture output for this arm the way the sibling's `run_arm` writes `$out`, or add a `grep -aq 'FRONTIER_EXEMPT_CEILING exceeded'` leg).
**Warning signs:** an arm that is "ok (exit 1)" for the wrong reason — the classic anti-vacuity trap named in CONTEXT.

### Pitfall 3: Moving a byte-pin without reading its message
**What goes wrong:** `PROD_C0331_TAIL` reds with "The one automatic applier of DDL to production is not something to edit as a side effect".
**How to avoid:** the PROD `-a` is its own commit with that justification; the pin's string moves in the same commit; the calibration at `:1066-1075` stays.

### Pitfall 4: Platform-dependent grep in a permanent test
**What goes wrong:** a WR-04 calibration that asserts "without `-a` the check reads clean" passes on ugrep and fails on GNU grep (or vice versa) — CI Node22/ubuntu vs local Node25/macOS (memory).
**How to avoid:** assert only the invariant (`-a` ⇒ exit 1 on the NUL fixture); record the without-`-a` observation per platform in the SUMMARY.

### Pitfall 5: `git checkout --` in a neuter harness
Restores to HEAD and destroys uncommitted work (memory L-04, CONTEXT). Take `cp` backups; verify the restore by grepping the newest fix, not by hash alone.

### Pitfall 6: `if-no-files-found: error` after narrowing (Option A only)
An aborted run may produce none of the globbed channel files and no staging output → the upload reds on "no files" — acceptable only if that is a deliberate fail-closed reading. Option B sidesteps this by always staging `README.txt`.

### Pitfall 7: The local `grep` is ugrep behind a shell function
`type -a grep` → shell function; `/usr/bin/grep` is BSD 2.6.0. Any bash falsifier run locally sees ugrep; CI sees GNU grep. `sed -i -E` is BSD locally (the wiring test forces `false` for that reason, `wiring:722-724`).
