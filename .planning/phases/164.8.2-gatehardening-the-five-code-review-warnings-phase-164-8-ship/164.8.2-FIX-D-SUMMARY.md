## 3. What was done about the IN-04 layout binding, and why it is not the tautology

The pin required exactly one line matching `^\s*# \(\d{4}-\d{2}-\d{2}: ` inside the
W2 block. The finding is right that the word derivation under it was real, and
right that the line shape was a convention the pin itself introduced.

I took the **structural** option rather than the "make the shape a stated,
checked requirement" option, because a checked layout requirement is still a
layout requirement — it converts a surprising red into an explained red, not into
no red.

The binding is now over the block's **prose**: leading `# ` stripped, lines
rejoined with a space. That is IN-02's existing idiom in the same file, whose own
comment already gives the reason ("Matching the raw block would bind to whatever
happened not to wrap"), so this is one idiom hoisted rather than a second one
invented — `w2Prose` is now a single definition used by both arms. Over that prose
the predicate is: **exactly one dated sentence naming a count word, and that word
is the live `^refuse_*() {` count.** `[^.]*?` keeps a date in one sentence from
reaching a word in the next.

**Why this is not a regression to the tautology.** The check this arm replaced
compared a `grep -c` against a byte-identical copy of itself and could not fail.
Here both halves are still derived from the script: `n` is counted off the live
refusal declarations and mapped through the WORD table; nothing is re-typed. The
three calibrations observe the predicate flip on a drifted word and on a deleted
date, and hold green on a pure reflow.

⚠️ **One self-inflicted repeat of the finding, caught by measurement.** My first
reflow calibration located the claim using the pre-IN-04 line pattern and asserted
the file carried exactly one — putting the layout requirement back into the arm
through its own calibration. Running it against the reflowed script produced
`the reflow calibration has nothing to reflow`, which is the finding again. The
break point is now derived from the count word. The comment in the code records
this so the next editor does not re-introduce it.

I also did **not** pin the historical half ("the old predicate reddened on this
reflow") inside the arm. That claim is evidence about a shape that no longer
exists, and asserting it would re-couple the arm to that shape. It is recorded
above instead, with the RED quoted.

## 4. The DSN assertion on the four staged `.sql` files

⛔ The file set was **not** re-narrowed. `census.sql`, `survivors.sql`,
`restore.sql`, `refdata.sql` are admitted by founder decision and are net narrower
than what they replaced. The assertion is about **DSN shapes**, per the brief.

`assert_public_sql_dsn_free` runs between `build_transaction` and
`run_transaction` — every published file exists, the database is untouched. Pattern
is the same `postgres(ql)?://` the self-test's arm redaction check uses, so both
readings of "a DSN" in this script are one string. The dollar-quote half of that
check is deliberately **not** applied: these files are SQL and are full of
dollar-quoted bodies, so it would refuse every legitimate run. The match is never
printed — a hit is the credential; the refusal names the file.

Measured before shipping it: the real `supabase/schema/baseline.sql` carries **0**
`postgres(ql)?://` matches, so the guard cannot false-refuse a real restore.

⚠️ **It is not named `refuse_*`, and that is a measured choice.** The
`refuse_*() {` count is derived by `--self-test`'s closing line and by this test
file into the claim that every refusal fires before a write **and is armed by a
named-message arm**. This check has no cluster arm — arming it needs the throwaway
lane, which is out of scope — so joining that family would have made a true
sentence false. Re-measured after the edit: the count is still **9**, and IN-01's
derived word is still `NINE`.

Three vitest arms, all **executed** with no cluster and no database (the IN-06
sourcing technique: `main "$@"` stripped, `RESTORE_DB_URL` the literal
`stub-never-used`, never dialled): wiring/ordering, per-file DSN detection
(seeded one file at a time — a guard scanning only `restore.sql` passes three of
four), and grep-rc handling.
