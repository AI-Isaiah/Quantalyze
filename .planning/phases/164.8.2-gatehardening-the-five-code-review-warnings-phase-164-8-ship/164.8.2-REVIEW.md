#### WR-01: The new staging step is default-**IN** for three whole extension classes, and says the opposite three times

**File:** `.github/workflows/test-restore-from-baseline.yml:1576-1580` (the `for c in` glob),
comments at `:1510`, `:1518`, `:1544-1546`, echo at `:1584`
**Confidence:** **CONFIRMED by executing the shipped step.**

The by-name loop at `:1570` is genuinely default-out. The channel loop three lines below it is not:

```yaml
for c in "${outdir}"/*.err "${outdir}"/*.log "${outdir}"/*.out; do
```

I extracted the step verbatim, seeded a fixture `${RUNNER_TEMP}/test-backup` and ran it:

```
$ RUNNER_TEMP=… bash stage.sh
staged manifest:
  brand-new.log
  future-census.out          <- contents: CREATE POLICY p ON t USING (owner=current_user)
  ledger.csv
staged 3 file(s) from …; everything else the script wrote stays in the job's temp dir and never enters the artifact.
```

`future-census.out` and `brand-new.log` are files the script does not write today. They were
staged into the world-readable artifact with nobody naming them, and one carried exactly the
`CREATE POLICY … USING (<qual>)` byte class WR-05 exists to withhold.

Three statements shipped in the same diff are therefore false:

- `:1510` — "⛔ THE ALLOWLIST IS BY NAME, **NEVER BY GLOB**, AND THAT IS THE WHOLE POINT."
- `:1518` — "a file the script gains tomorrow is **OUT until someone adds its name here** and says why."
- `:1584` — the step's own runtime echo: "everything else the script wrote … **never enters the artifact**."

The redaction step upstream does not compensate: its `sed` scrubs DSN / host / user / server-name
only. Owner names and reconstructed DDL pass straight through.

The wiring arm cannot see this either: `expectedStaged()` derives the expectation from the
workflow's *own* two lists (`test-restore-workflow-wiring.test.ts:951-957`), and `UNEXPECTED` is
`"future-thing.txt"` — a `.txt`. The default-out rule is proven for one extension and asserted for
all of them.

**Fix (either, plus one honest sentence):**

```yaml
# (a) enumerate the channels too — six names, same discipline as the .sql files
for c in census.err ledger.err marker.err refdata.err dump.log transaction.out; do
  if [ -f "${outdir}/${c}" ]; then cp -p "${outdir}/${c}" "${stage}/"; fi
done
```

or keep the globs and rewrite `:1510`/`:1518`/`:1584` to say what is true — *"by name for content
files; the three redacted diagnostic channel classes are admitted by extension, so a future
`.err/.log/.out` file is IN by default"*. Then extend the arm: set
`const UNEXPECTED_CHANNEL = "future-thing.out"` and assert whichever rule you chose.

#### WR-04: IN-05's seam derivation is blind to 3 of the 16 documented seams — including the DSN

**File:** `src/__tests__/restore-test-from-baseline.test.ts:928`
**Confidence:** **CONFIRMED by mutation.**

```ts
const declared = [...SRC.matchAll(/^([A-Z_]+)="\$\{[A-Z_]+:-/gm)].map((x) => x[1]);
```

That shape finds 13 seams. The `--help` ENV SEAMS block documents 16. The three it cannot see are
`RESTORE_DB_URL`, `RESTORE_OUT_DIR` and `PGBIN` — all genuine environment seams
(`restore-test-from-baseline.sh:1535`, `:1791-1800`, `:1985`), and the first is the destructive
DSN itself.

Deleting the `RESTORE_DB_URL` entry from the operator contract, and separately the `PGBIN` entry:

```
baseline missing: []
after deleting RESTORE_DB_URL from ENV SEAMS, missing: []      <- STILL GREEN
after deleting PGBIN from ENV SEAMS, missing: []               <- STILL GREEN
```

The arm's title is "every env seam the script DECLARES is named in the `--help` ENV SEAMS block",
and the SUMMARY frames `UNDOCUMENTED_SEAMS = []` as meaning "all 13 declared seams are documented".
Both read as complete coverage of the operator contract; the derivation covers 81% of it and misses
the entry an operator most needs before running `DROP SCHEMA public CASCADE`.

**Fix:** widen the derivation to the seams the script actually *reads*, not just those it declares
in one spelling:

```ts
const declared = [
  ...new Set([
    ...[...SRC.matchAll(/^([A-Z_]+)="\$\{[A-Z_]+:-/gm)].map((x) => x[1]),
    ...[...SRC.matchAll(/\$\{(RESTORE_[A-Z_]+|PGBIN|REFDATA_[A-Z_]+)(?::-|\}|:\?)/g)].map((x) => x[1]),
  ]),
];
```

and add a floor (`expect(declared.length).toBeGreaterThanOrEqual(16)`) so a narrowing of the regex
itself is red rather than quietly smaller.

#### WR-05: IN-04's job bound silently degrades to slice-to-EOF — the opposite discipline to IN-03, in the same commit

**File:** `src/__tests__/critical-regressions.test.ts:1054`, used at `:1058`
**Confidence:** **CONFIRMED by mutation.**

```ts
const NEXT_JOB_RE = /\n {2}[A-Za-z_][\w-]*:\n/;
```

The trailing `:\n` requires the successor job key to be a bare line. Probed against three
successors that are all valid YAML:

```
"  zz_after_apply:"                        -> bound excludes successor: true
"  zz_after_apply:  # a trailing comment"  -> bound excludes successor: FALSE
"  zz_after_apply: "                       -> bound excludes successor: FALSE
```

In both failing cases `after.match(NEXT_JOB_RE)` returns `null`, `applyJobBlock` falls back to
`after` (end of file) and returns the exact unbounded slice IN-04 was raised to remove — with no
throw, no message, and the two `apply:` pins silently satisfiable by a successor's text again. The
calibration at `:1071` seeds a *bare* key, so it cannot see this.

This is notable because `suffix()` — nine lines of the same commit, in the sibling file — was fixed
for precisely this class by making the missing-anchor case **throw**
(`supabase-migrate-test-first.test.ts:994-1010`, with the comment "A silent degradation by
construction: the failure mode is a PASS"). One of the two IN fixes adopted that discipline; the
other reproduced the shape it names.

Latent today (`apply` is the last job), which is why this is a Warning and not a Blocker.

**Fix:**

```ts
const NEXT_JOB_RE = /\n {2}[A-Za-z_][\w-]*:[^\S\n]*(#[^\n]*)?\n/;
```

and, matching IN-03's discipline, make the fallback explicit rather than silent — either throw when
`apply` is not the last job and no bound was found, or assert in the calibration that a
comment-suffixed and a space-suffixed successor are both excluded.

#### WR-06: The new staging step publishes the very channels a failed redaction says must not be published

**File:** `.github/workflows/test-restore-from-baseline.yml:1548-1550` (`if: always()`), against
`:1475-1481`
**Confidence:** CONFIRMED by reading; the triggering condition (an `rm -f` failure) is low-realism
but is explicitly coded for.

`withhold_channels()` counts removals that fail, prints

```
::error::N unredacted channel file(s) could NOT be removed and may reach the artifact.
         Do NOT publish this run's artifact: treat the TEST pooler host, its IP and the DB user as disclosed.
```

and then `return 0`, so the trap exits the step 1. The new staging step runs `if: always()`,
does not consult the redaction step's outcome, and copies whatever `*.err/*.log/*.out` survived —
after which the `if: always()` upload publishes them. The workflow ships exactly what its own error
message tells the operator not to ship.

The step's comment at `:1575` states the assumption as fact — "The diagnostic channels, **AFTER the
redaction step above has scrubbed them**" — and the fail-closed trap the step already carries is
the natural place to enforce it.

**Fix:** give the redaction step an `id:` and gate the channel loop on it:

```yaml
      - name: Redact connection metadata from the backup directory (public artifact)
        id: redact
        …
      - name: Stage the public artifact (enumerated allowlist; default-out)
        if: always()
        env:
          REDACT_OUTCOME: ${{ steps.redact.outcome }}
        run: |
          …
          if [ "${REDACT_OUTCOME}" = "success" ]; then
            for c in "${outdir}"/*.err "${outdir}"/*.log "${outdir}"/*.out; do …; done
          else
            echo "::error::redaction did not succeed (${REDACT_OUTCOME}) — NO channel file is staged."
          fi
```
