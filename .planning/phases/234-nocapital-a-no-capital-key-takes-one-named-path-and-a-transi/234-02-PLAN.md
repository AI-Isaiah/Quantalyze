## Decisions this plan records

- **DEC-02-A Proof formula (CONTEXT Claude's Discretion).** `ledger_level = sum(composed flow_usd) + sum(composed pnl_usd)` over the key's OWN `key_inputs` row (RESEARCH "NOCAP-01"). The MT5 writer builds both from the deal ledger (`mt5_day_pnl` over deals, classified BALANCE/CREDIT/BONUS deals for flows), never from `account_info`, and `history_deals_get` is a full-history fetch, so the sum is the balance the deals imply. Confirmed when `ledger_level <= DUST_NAV_FLOOR`, one-sided, mirroring A2's `<=` (CONTEXT post-research). No own basis, or a non-finite sum, is no proof.
- **DEC-02-B Gate order.** The ledger proof runs BEFORE the D-10 bound: D-10 reasons about amounts walked back from the stored terminal, and for MT5 that terminal is evidence only once the ledger confirms it. A key that passes the proof still meets D-10.
- **DEC-02-C Venue set.** `LEDGER_PROOF_VENUES = frozenset({"mt5"})`. Deribit's terminal is reconciled to inception at write time (native_nav's inception gate), the ccxt venues cannot form a candidate, sfox stores no terminal (RESEARCH venue table; CONTEXT post-research).
- **DEC-02-D Negative terminal.** Refused at selection on every venue, after the funded check (CONTEXT NOCAP-01: "A stored terminal below -DUST_NAV_FLOOR is not an exit").
- **DEC-02-E How the affected tests are re-aimed.** A test whose subject is the MT5 exit gets a hand-derived own basis whose sum equals its stored terminal (writer identity `L(t-1) = L(t) - F(t) - P(t)` with prev0 = 0), so it still exits. A test whose subject is a venue-independent gate (D-10, inception) and that used an MT5 row without a basis moves to `"deribit"` with every number unchanged: a Deribit row written before D-06 carries no basis, Deribit is outside the proof set and is a full-history venue, so the test reaches its own gate again. Neither kind is weakened; each asserts its own token.
