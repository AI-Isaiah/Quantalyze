<objective>
NOCAP-02 (and its NOCAP-03 token). Any `Exception` raised while a no-capital candidate is in play, from the apply loop or from the compose call, reverts once to the inputs exactly as stored and the job carries on to the upsert (TODOS `[166.3.1-NOCAP-NONNAV-EXCEPTIONS]`).

Purpose: today a `KeyError` or `ValueError` from a candidate's inputs escapes the job, `classify_exception` files it as `unknown`, the dispatcher retries, and the previous `equity_curve` row stays stale on every attempt (RESEARCH "NOCAP-02"). The rule exists to make a book better, so a candidate must never cost the book its row (166.3.1 plan 09, T-166.3.1-39).
Output: the two revert arms, the `candidate_exception` token and the fault tests.

No external API integration.
</objective>

## Outcome table for the compose call (CONTEXT NOCAP-02)

| Raised by the first compose | Candidate in play | Outcome |
|---|---|---|
| `NavReconstructionError` | no | `_compose_refused` (today) |
| `NavReconstructionError` | yes | revert, count `compose_reverted` per candidate, compose once on `no_capital_stored` (plan 01) |
| any other `Exception` | no | propagates (today) |
