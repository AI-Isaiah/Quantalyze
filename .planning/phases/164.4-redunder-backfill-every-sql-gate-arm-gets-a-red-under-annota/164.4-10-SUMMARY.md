## Findings

### 1. ⭐ A SECOND independent instance of the LAYERED-ARM class — measured, not assumed

`test_enqueue_compute_job_dedupe_non_terminal.sql` arm **B1** is fenced by **two independent
arbiters**: the RPC's optimistic look-up in `20260826150000`, and the partial unique index
`compute_jobs_one_inflight_per_kind_strategy` in `20260416125430`.

The single-step twin was built, **proven applied** (`diff` against the repo file showed exactly the
intended one-line change), and run on a real lane. Result:

```
NOTICE: B1 OK: 2 calls -> 1 row, both returned ebe177fe-…
NOTICE: ALL ASSERTIONS PASSED (B1, B2) - enqueue_compute_job dedupe is fenced.
EXIT=0
```

The index rejects the second INSERT, `ON CONFLICT DO NOTHING` swallows it, and the lost-race
re-read hands back the SAME id — so the gate passes while the RPC's own dedupe is entirely gone.
A single-step twin would have shipped looking correct and proving nothing. B1's twin therefore
carries both steps, and the file's header explains why so the next reader does not re-derive the
dead end. This is the same class wave 10 found, reached independently in a different file.

### 2. ⭐ The re-base hazard bit THREE of the four files
