### Blocker 1 — `test_compute_jobs_error_kind_copy_parity.sql` is UN-BASELINEABLE (`[REDUNDER-PGCRON]`, new mechanism)

**Measured, not argued.** The file's arms need `compute_jobs_error_kind_check` to admit the
fourth kind `'orphaned'`. Exactly one migration widens it —
`20260826140000_compute_jobs_error_kind_orphaned.sql` — and that migration **hard-RAISEs** when

```

        terminalizer cannot be re-registered. …
```

Without it the baseline is RED, on the arm rather than on the apply:

```
ERROR:  P0001: TEST FAILED (2/A-3): computation_error_copy branches on {orphaned} but
        compute_jobs_error_kind_check does NOT admit those values …
```

So the file cannot reach a GREEN baseline on today's lane under any apply list. Editing the
migration is forbidden; hosting pg_cron is `[REDUNDER-PGCRON]`, deferred by founder decision
(SCOPE AMENDMENT #2).

**⚠️ And the deferral would be INVISIBLE.** `classifyGateIdiom` (`parse.mjs:1052`) calls
`gateNeedsPgCron(text)`, which scans **the gate file's own executable text**
(`parse.mjs:996-1002`). This gate never mentions pg_cron — its apply list does. So the file
classifies `pending`, not `lane-blocked`, and the run's `lane-blocked:` line — the print whose
whole purpose is to name every exclusion — would not name it. Confirmed on the run above: it
appears in `pending: 13 …`.

**Options for the founder:**

| # | Option | Cost | What it buys |
|---|---|---|---|
| A | Widen the `lane-blocked` classifier to consider a file's `RED-UNDER-SETUP` apply list, and defer this file with the other four | a real `parse.mjs` change plus its red/green self-test fixture — a scope expansion mid-batch | the exclusion is PRINTED, which is criterion 1 as amended |
| B | Book it to `TODOS.md` under `[REDUNDER-PGCRON]` and drop it from the phase's reachable set, leaving it in `pending:` | zero code | honest in the ledger, but `pending:` then contains a file no batch can ever close — a permanently misleading count |
| C | Resolve `[REDUNDER-PGCRON]` first (host pg_cron on both lanes) | its own plan; two hosts, `shared_preload_libraries` | unblocks this file **and** the other four (71 of 355 idiom sections) |

phase's subject is exactly that class of lie. C is the better end state but is a separate plan.

### Blocker 2 — `test_resync_retry_single_job.sql` assertion (b) is a WAIVER CANDIDATE

and assertion (c) is proven falsifiable. Assertion (b) is not.

exists to describe aborts psql before the arm can name itself. This is structurally the same class
as wave 9's `[REDUNDER-WAIVER-01]` — an arm that looks un-falsifiable for a reason that is not the
grammar's — and it has the same shape of third option.

## Findings (booked, not fixed here)

1. **`[REDUNDER-SAVEPOINT]` is a CLASS OF THREE, not one.** Plan 164.4-00 found
   `20260416201929_audit_log_hardening.sql`. This plan measured two more, each on the lane:
   `20260417031851_user_app_roles.sql:433` and
   `20260510173005_process_key_long_idempotency_drain.sql:397`, both
   `ERROR 42601 syntax error at or near "TO"` — `SAVEPOINT` / `ROLLBACK TO SAVEPOINT` inside a
   PL/pgSQL `DO` body, which PL/pgSQL cannot parse. An AST-level scan of every migration puts the
   class at **exactly 3**. None of the three has ever applied to a vanilla cluster as written, so
   either the deployed bodies differ from the repo (VAC-04's own subject) or they never applied.
2. **`test_resync_retry_single_job.sql`'s header claim about assertion (a) is not what the lane
   measures.** The header says the dedup anchor is
   `compute_jobs_one_inflight_per_kind_strategy`. Excluding `process_key_long` from that index's
   predicate on a real lane — **proved applied** by re-reading `pg_indexes.indexdef`, which came
   back carrying the two-element `ARRAY['compute_intro_snapshot', 'process_key_long']` — left the
   gate at **exit 0**. So the RPC's own select-existing, not the index, is what makes (a) pass
   today. Assertion (a) therefore still needs a twin against the `enqueue_compute_job` body in
   `20260515210300`; the index mutation is a NO-RED and must not be shipped as one.
3. **The `lane-blocked` classifier is apply-list-blind** — see Blocker 1. Worth booking separately
   from `[REDUNDER-PGCRON]` because it is a runner defect, not a substrate one.
