## Pattern Assignments

### P1. The annotation shape — `supabase/tests/test_strategy_shares_rls.sql`

**Analog:** the reference file. Every new annotation must be **indistinguishable in style** from
these. All four excerpts below are verbatim at HEAD.

#### P1.1 Where the marker sits — copy this exactly

The marker pair is the LAST thing before the assertion's own statements. Not after the section
banner, not in a header block, not in a sidecar. Verbatim, `test_strategy_shares_rls.sql:407-425`:

```sql
  -- ======================================================================
  -- SHAPE 1c: generation is BIGINT — HEADROOM, and NOT the N1 fix
  -- ======================================================================
  -- ⛔ Read the failure message before concluding anything from a green here.
  -- Widening the counter buys DISTANCE to the overflow ceiling, nothing else. A
  -- client that can WRITE `generation` reaches 2^63-1 as easily as 2^31-1, and
  -- the wedge that follows is identical and still unrecoverable without DDL.
  -- The INSERT half of that write access is closed (SHAPE 3b: `generation` is
  -- absent from the INSERT grant); the UPDATE half — a bounded-increment rule —
  -- is DEFERRED and is a merge gate for plan 164-03.
  -- RED-UNDER: change `generation BIGINT` back to `generation INTEGER` in the
  --            STEP 1 CREATE TABLE.
  -- RED-UNDER-M: {"arm":"SHAPE 1c","apply":[{"kind":"edit","file":"supabase/migrations/20260827120000_strategy_shares_generation_model.sql","find":"  generation  BIGINT","replace":"  generation  INTEGER","occurrences":1}]}
  SELECT format_type(a.atttypid, a.atttypmod) INTO gen_type
    FROM pg_attribute a
   WHERE a.attrelid = 'public.strategy_shares'::regclass AND a.attname = 'generation';
  IF gen_type IS DISTINCT FROM 'bigint' THEN
    RAISE EXCEPTION 'TEST FAILED (SHAPE 1c): strategy_shares.generation is %, expected bigint. …', gen_type;
  END IF;
```

**Copy:**
- two-space indent inside the `DO $$` body; markers at comment line start (`^[ \t]*--[ \t]*` — the
  rule-1 anchor, `parse.mjs:58-60`);
- prose FIRST, twin on the NEXT line, no blank line between them;
- prose continuation lines aligned under the text with `--            ` (12 spaces);
- twin is ONE line of JSON, never wrapped;
- section banner is `-- ===…===` / `-- NAME: one-line claim` / `-- ===…===`, then the WHY prose,
  then the marker pair.

**Deliberately differ:** nothing about the shape. Differ only in the mutation you choose.

#### P1.2 How the `"arm"` name is chosen — it is NEVER invented

⛔ The `"arm"` value must be a string that literally appears inside `TEST FAILED (<arm>)` **in this
same file**, and must be unique within the file (`GRAMMAR.md:351`). The runner's needle is
`` `TEST FAILED (${arm})` `` (`run.mjs:544`) and its identity regex is
`/TEST FAILED \(([^)]*)\)/g` (`run.mjs:947`) — one definition, no fallback.

The 30 existing arms are all **sub-suffixed identities**, not stripped section labels:
`SHAPE 1c`, `TRIGGER 3d-i`, `N1 1a`, `SERVICE-ROLE 2f`, `NONCE 4c`.

**So the two units are different things and the plan must keep them apart:**
- **SECTION** = the *coverage* unit the founder locked (one twin per named assertion group). It is
  derived from the identity strings — prefix + number with the sub-suffix stripped
  (`SHAPE 2a` → `SHAPE 2`, `TRIGGER 3d-i` → `TRIGGER 3`) — **not** from the `-- ====` banners.
- **ARM** = the *machine* unit. Its value is one real identity from that section.

⚠️ Measured this session: the banner convention is NOT uniform across the 44. In
`test_ledger_refresh_composite_arm.sql` banners delimit arms (20 banners); in
`test_reconcile_dropped_enqueue_sweep.sql`, `test_strategy_analytics_stuck_computing_reaper.sql` and
`test_retention_orphaned_running.sql` they delimit coarse "Part 1 / Part 2" blocks (8 / 12 / 6
banners for 39 / 29 / 25 sections). **A plan that derives sections from banners will undercount.**
Derive from identities; copy the banner style for readability only.

**Shape 2 — live-DB `sql` step with a prerequisite neuter** (`:1561-1577`):

the apply. `neuter` can only name an **idiom** arm (`neuterArm`'s needle is the literal,

**Shape 3 — LAYERED multi-step** (`:675-681`): two `edit` steps in one ordered `apply`, applied to
the same per-file buffer; the second removes the migration's own verification term that would
otherwise abort the apply.

**Shape 4 — waiver** (`GRAMMAR.md:480-483`; **the corpus has none — this is the only artifact kind
with no in-repo analog**):

```sql

  --            never be the FIRST failure.
  -- RED-UNDER-M: {"arm":"<ARM>","waiver":"a deleted nonce column aborts the apply; no first-failure mutation exists"}
```

The reason string is what `run.mjs:2198` prints (`  waived: <arm> — <reason>`). Per CONTEXT: +1 to
`WAIVED_CEILING` per accepted waiver with the reason pinned beside the constant; **>5 total →
STOP and escalate**, do not ratchet. An arm that cannot fail **at all** is the FINDING (→ `TODOS.md`),
never a waiver.

  are never judged (`run.mjs:1836-…`).

#### P2.2 The fixture shape — copy `02-fixture-sanitize-tables.sql`

It is the *additive* pattern and the one a new subsystem fixture should imitate: a 3-line WHY
header, then `ALTER TABLE … ADD COLUMN IF NOT EXISTS`, then `CREATE TABLE IF NOT EXISTS` stubs
carrying **only the columns the code under test names**, then no-op stub functions:

```sql
-- Additive stand-ins for every relation sanitize_user names. Column sets are
-- the ones the function actually writes — nothing else. Empty tables: the
-- SANITIZE arms assert on strategy_shares, not on these.
ALTER TABLE profiles
  ADD COLUMN IF NOT EXISTS company TEXT, ADD COLUMN IF NOT EXISTS description TEXT, …;
CREATE TABLE IF NOT EXISTS api_keys (user_id UUID);
CREATE OR REPLACE FUNCTION public.log_audit_event_service(…)
 RETURNS void LANGUAGE plpgsql AS $f$ BEGIN RETURN; END $f$;
```

`01-fixture-core.sql` is the *base* and is destructive by design (`DROP SCHEMA IF EXISTS auth
CASCADE; DROP SCHEMA public CASCADE;`) — a new fixture must be `NN-fixture-<area>.sql` and additive,
never a second base. `run.sh:44-51` states what stand-ins do and do not prove; quote it, do not
re-litigate it.

#### P2.3 Discovering a new file's setup list — the iterative task, no shortcut

```bash
bash scripts/pg-lane/run.sh --workdir "$SCRATCH/lane" \
  --apply scripts/pg-lane/fixtures/01-fixture-core.sql <stand-ins…> supabase/migrations/<under-test>.sql \
  --gate supabase/tests/<gate>.sql
# iterate until exit 0; the first ERROR names the missing object.
# ⛔ never point --workdir inside the repo (dirty-checkout defect).
```

⚠️ `CREATE OR REPLACE` chains: the setup must contain the migration that **LAST** defines the
object, and the mutation must target THAT one (memory `⭐Re-base SQL fn before CREATE OR REPLACE`).

### P3. The floor-ratchet pattern — `run.mjs:117-226`

**Analog:** all three constants, verified at HEAD: `FILES_FLOOR = 1` at **`run.mjs:129`**,
`ARMS_FLOOR = 30` at **`run.mjs:197`**, `WAIVED_CEILING = 0` at **`run.mjs:226`**.

#### P3.1 What a compliant floor edit looks like

`src/__tests__/gate-family-meta.test.ts:572-596` scans `THRESHOLD_BEARING_FILES` for any
`const NAME_{FLOOR|MIN|CEILING|MAX|LIMIT}_… = <int>` and requires, **within
`JUSTIFICATION_WINDOW = 80` lines above** (`:542`), BOTH a measurement token
(`/MEASURED|measured|Measured|scored|SAMPLE SIZE|sample size/`, `:549`) AND a date
(`/\b20\d\d-\d\d-\d\d\b/`, `:550`). Comment-only lines never produce a site (`:576`).

So the block must carry, verbatim in this vocabulary — copy `run.mjs:147-197`:

```
// ⭐ RE-DERIVED <DATE> …
//   VALUE        <n> — …
//   DATE         <YYYY-MM-DD>, at HEAD <sha>.
//   COMMAND      `node scripts/mutation-runner/run.mjs` -> exit 0
//                  coverage: files <a>/71
//                  arms: <e>/<a>/<w>   (executed/annotated/waived)
//                  biting: <b>
//                  per-arm lane time: mean <t>s over <n> arm run(s)
//   SAMPLE SIZE  <n> arms executed, all <n> `RED (identity ok)`, …
//   COVERAGE     <n> annotated gate files of 71 in supabase/tests/, namely …
//   RECORD       .planning/phases/164.4-…/164.4-NN-SUMMARY.md
```

#### P3.2 ⭐ LINEAGE vs CURRENCY — the discipline to copy, and the one most likely to be missed

`run.mjs:147-149` states it: *"The 2026-08-29 pin above STAYS as lineage: it is not superseded, it
is re-earned."* And `:193-196` puts a short **CURRENCY** statement immediately above the value.

**So a floor move APPENDS a new dated block and edits the CURRENCY lines + the integer. It does NOT
rewrite the historical measurements.** Concretely, in every batch PR:

- **Rewrite (currency):** `run.mjs:123` (`printed coverage: files 1/71 — still 1 annotated`),
  `:128` (`Phase 164.4 raises FILES_FLOOR as it backfills the other 70 files`), `:188`
  (same for ARMS_FLOOR), `:193-196` (CURRENCY), `:398` (`1 of 71 — see FILES_FLOOR`), `:418`
  (`raises the coverage as it backfills the other 70 files`), `parse.mjs:882`
  (`unchanged at 1 of 71`).
- **Leave alone (lineage):** `run.mjs:137-141`, `:154-174`, `:214-221`, `:591-596`, `:1303`,
  `:1613-1619` — each is a dated record of a run that happened. Rewriting a historical measurement
  is a worse defect than a stale claim.

#### P3.3 Floors read a RUN, never the artifact

`run.mjs:119-121`: *"A floor picked by reading the finished artifact always passes and would prove
nothing."* Read `coverage:` / `arms:` / `biting:` / `lane-invocations:` off the run log
(`run.mjs:2156-2201`), never off a `grep -c` (memory
`⛔Gate tokens must be counted PRE-EDIT`). Naive grep over-counts by 3 on the reference
(`GRAMMAR.md:38-44`); greedy `"arm"` extraction returns the **neuter's** arm.

#### P3.4 `WAIVED_CEILING` is an UPPER bound and its own hole

`run.mjs:199-226` is the model comment for an upper bound: it names the hole it closes (a waiver
twin satisfies parity, raises `filesAnnotated` and `armsAnnotated`, spawns no lane, lowers no
`biting`, exits 0), then measures. Raise it only +1 per reviewed waiver, with that waiver's reason
in the block. It is enforced twice — `run.mjs:2224-2233` and `ci.yml:1096-1108`.

**Apply to:** the fixture-target refusal (P2.4) and both new print lines.

`grep -c` counter for any number a plan asserts — use `--parse-only` and the run log. Every number in
