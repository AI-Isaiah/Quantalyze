### WR-01 / SFH-R2 N-1: probe failures sent one event per row per page load

**Files modified:** `fetch-and-build-payload.ts`, `fetch-and-build-payload.test.ts`, `page.tsx`, `page.key-pill.test.tsx`
**Commit:** `244b80ac8`

**Applied fix**
- The resolve stage captures to Sentry only when the caller is `"build"`. That covers the G0 read
  error, `compositeUnbuildable` and `singleKeyUnbuildable`.
- For a probe, the refusal arm of `FactsheetBuildability` now carries `NotBuildableDetail`:
  `{ code?, gate?, source? }`.
- `StrategiesPage` counts `read_error` (per code), `composite_unbuildable` and
  `malformed_series` (per gate and source) across the fan-out. `captureProbeOutcomes` then sends
  **one** event per page load, with stage `factsheet-probe-outcomes`.
- Its tags hold the count per reason, `counted_rows`, and `read_error_codes` as ranked
  `code:count` pairs. The level is `warning` when only composites refused, otherwise `error`.
  `extra` holds the gate and source counts.
- No id reaches the event. The per-row console lines keep the ids.

**Tests**
- `WR01-OUTCOMES-ONE-EVENT`: 6 read errors (4 with `57014`, 2 with no code) and 2 composites give
  one event with `read_error_codes: "57014:4,none:2"`.
- `WR01-COMPOSITE-ONLY-WARNING`: composites alone give one event at warning.
- `PROBE-READ-ERROR` was updated.
- The lib capture tests were rewritten: a probe captures nothing and returns the detail.

**Neuters:** each was RED on 3 tests.
- (a) The stage captures for probes again.
- (b) The page aggregate is removed.

### SFH-R2 N-3: probes had no deadline

**Files modified:** `fetch-and-build-payload.ts`, `fetch-and-build-payload.test.ts`, `page.tsx`, `page.key-pill.test.tsx`
**Commit:** `8fb9eadb5`

**Applied fix**
- `probeFactsheetBuildable` races the resolve against `FACTSHEET_PROBE_DEADLINE_MS` and rejects
  with a named `FactsheetProbeTimeoutError`.
- The deadline aborts an `AbortController`. `resolveFactsheetInputs` passes that controller's
  signal to the strategies query through `.abortSignal()`, which the installed postgrest-js
  2.110.1 provides.
- A build passes no signal, so its query is unchanged. That also keeps every other test file's
  admin mock working.
- When the deadline cancels a read, the read logs at warn and is not captured as a second outage.
- `StrategiesPage` counts a timeout as its own reason (`timeout`) in the one outcomes event, at
  error level. The row gets the "could not check" line.

**Why 5 s.** The reasons are recorded at the constant:
- The live-DB lane measured the probe at 14 to 20 ms on real rows (`167.2.1-01-SUMMARY.md`).
- The repo's other status probe with a deadline, `MOUNT_PROBE_TIMEOUT_MS` in `SyncPreviewStep`,
  uses 5 s for the same reason.
- The page-wide stall is now bounded by ceil(computed rows / 4) x 5 s.

**Tests**
- `SFH-R2 N-3 PROBE DEADLINE` (lib, fake clock). The read is still open at deadline minus 1 ms. At
  the deadline the probe rejects with the named error and the signal is aborted. A probe that
  answers in time clears its timer. A build passes no signal.
- `N3-PROBE-DEADLINE` (page). The hung row says "could not check" and the other row is
  unaffected. The read was aborted. The one event carries `timeout: "1"`.

**Neuters:** each turned both tests RED.
- (a) The race is removed.
- (b) The query is no longer given the signal.

### SFH-R2 N-5: a short `daily_returns` beside a long `returns_series` was called malformed

**Files modified:** `fetch-and-build-payload.ts`, `fetch-and-build-payload.test.ts`
**Commit:** `55bc6f0a3`

**Applied fix**
- `countedSeriesColumn` decides which column the builder reads, using the resolver's own
  `normalizeDailyReturns`. That is `daily_returns` whenever it normalizes to at least one entry,
  and otherwise the `returns_series` wealth curve.
- It counts only that column.
- The malformed capture, and now the probe's detail, carry `source`.
- A single valid daily return beside a 31-point wealth curve is `too_few_points`, because that is
  what the builder will do.

**Tests**
- Two new PARITY fixtures: the shadowed short series (`too_few_points`), and a shadowed series
  that is really malformed (`malformed_series`, source `daily_returns`).
- A `source` assertion in `SFH M-3 MALFORMED CAPTURE`.

**Neuter:** restoring the old count turned 3 tests RED.

## Recorded limits

- **The composite csv read cannot be aborted.** `readCompositeFactsheet` in `composite-read-path.ts`
  (not in this set) issues it with no signal. At the deadline, a composite probe answers
  "could not check", but its csv read may finish in the background. The limiter slot is released
  when the probe answers, so in that one case the cap of 4 concurrent reads can be exceeded
  briefly. This is stated in the `probeFactsheetBuildable` docstring.
- **A shadowed short series gets the "too short" copy.** A row whose `daily_returns` is short
  and valid beside a long `returns_series` is now `too_few_points`, and its note reads
  "Its stored results hold fewer than 2 days of returns". That is true of the column the builder
  reads, not of every stored column. A sharper sentence would live in `status-surface-copy.ts`,
  which is not in this set.
