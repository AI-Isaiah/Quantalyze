### WR-02: why the cache key and not the copy

- Softening the public lines ("the link cannot show numbers …") would not fix the first half of
  the finding. A buildable row shows **no note** while the link serves a cached placeholder, and
  no wording change can reach a note that is not rendered.
- `revalidateTag` on compute completion is unavailable. `strategy_analytics` is written by the
  Python worker and the SQL finalizer, and neither can reach Next's cache. The only
  `revalidateTag("factsheet-v2:<id>")` in `src/` is the admin review route's.
- The finalizer stamps `computed_at = now()` on every successful run (the terminal-success branch
  of `sync_strategy_analytics_status`). So every compute that can change the builder's answer
  moves the key.
- The key stays viewer-independent. `computed_at` is a property of the row. `analytics_read`
  admits anyone for a published row, and `anon` holds the table grant, so every viewer of a
  published row reads the same `computed_at` from the signature probe. The owner lane still
  bypasses the wrapper, and the `withPublishedOnly` literal and the one-`unstable_cache` pins are
  unchanged (the phase-148 guards stay green).

## Recorded, not fixed (for the orchestrator)

1. **WR-01, the Sentry half has a residual.** "One event per page load" holds for the page's own
   captures, which are probe throws. By handoff item 2 (SFH M-2), a `read_error` is still captured
   **once per failed resolve inside the stage**. Under pool saturation, `/strategies` therefore
   still sends one stage event per failed row. The limiter reduces how many rows fail. It does not
   reduce the events per failed row. Closing this means changing the stage's capture for
   `caller:"probe"` (returning the code, so the page aggregates it), which is fixer A's design in
   `fetch-and-build-payload.ts`. I did not reverse it without a decision.
2. **WR-01 cost follow-up (routed, no TODOS entry booked).** The probe is still one heavy
   service-role read per computed row per load. A writer-side `factsheet_buildable` verdict, or a
   column-light resolve read, would remove it. `/strategies` has no pagination.

   change that does not stamp it (a recompute entering `computing`, and the protected
   failed-refresh branch), and a `null` cached from a transient admin **read error**. Both still
   drain on the 1-hour TTL. The first predates this phase: it is the uncomputed-row path's
   KCS12-PUBLIC during a recompute. Fixing the second means not caching a `read_error` null, and
   that changes the cached callback the phase-148 pin spells as
