## Deviations from Plan

**1. [Rule 3 - Blocking, environment] First ledger run measured the developer shell, not CI. Re-measured in the CI env.**
- **Found during:** Task 2, the first `test:live-db:ledger` run.
- **Issue:** The verdict was `NEW: 68 failing arm(s)`, all classified `K1-baseline-privilege-state-absent` / `C8-thrown-error-not-assertion`, across 14 files. Of the thrown errors, 49 were `Management API query failed (404): {"message":"Cannot POST /v1/projects/http://127.0.0.1:54421/database/query"}`. Root cause: `SUPABASE_ACCESS_TOKEN` was set in the executor's shell. `src/lib/test-helpers/live-db.ts` derives `HAS_INTROSPECTION` from that token plus a project ref, and the ref falls back to a regex over `NEXT_PUBLIC_SUPABASE_URL` that only matches `https://`. So the introspection arms un-skipped, and they POSTed to `api.supabase.com` with the lane URL as the "ref". CI's `frontend-live-db-lane` job sets neither variable, and in CI those arms skip.
- **Fix:** Re-ran the whole session (fresh `down`/`up`) under `env -u SUPABASE_ACCESS_TOKEN -u SUPABASE_PROJECT_REF`. Verdict: OK, 7/7. No ledger line was added and no test was changed.
- **Not a phase regression:** none of the 68 arms are in this plan's file, and all 25 g10b arms passed in both runs.
- **Files modified:** none.

No other deviations. The seam route was the primary one, so the scratch-worktree fallback was not needed.
