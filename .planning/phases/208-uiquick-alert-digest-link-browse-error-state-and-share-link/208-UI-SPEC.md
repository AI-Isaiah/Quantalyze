## Surface B — `/browse` read states (`src/app/browse/page.tsx`, D-02..D-04)

| State | What renders where the card grid sits | Redirect / crumb |
|-------|----------------------------------------|------------------|
| `ok` | Today's card grid, unchanged | One-category redirect and crumb rule as today |
| `empty` | No grid. The existing line, verbatim: `No strategies published yet. Check back soon.` (existing classes `py-16 text-center text-text-muted`, unchanged) | Never redirects, keeps the Browse crumb |
| `error` | No grid, no fallback cards, no empty line. The error block below. | Never redirects, keeps the Browse crumb |

In all three states the `h1` "Browse Verified Strategies", its sub-line, the signed-out sign-up block and `<Disclaimer variant="footer" />` render as today.

### Error block (exact markup contract)

```tsx
<div role="alert" className="rounded-md border border-negative/30 bg-negative/5 px-4 py-3">
  <p className="text-base font-semibold text-text-primary">{TITLE}</p>
  <p className="mt-2 text-sm text-text-secondary">{BODY}</p>
  <Link href="/browse" prefetch={false} className={buttonClassName({ size: "sm", className: "mt-3 pointer-coarse:min-h-[44px]" })}>
    Try again
  </Link>
</div>
```

| Slot | Copy (exact) |
|------|--------------|
| TITLE | `We couldn't load the strategy categories.` |
| BODY | `No categories are listed because the read failed, not because nothing is published.` |
| CTA | `Try again`: a link (`role` link, accessible name exactly `Try again`, `href="/browse"`). The label matches the repo's error pages (`src/app/error.tsx`, Phase 207). |

- **Touch target:** `size: "sm"` has no min-height, so the link carries `pointer-coarse:min-h-[44px]`, the repo's idiom for sm controls (ShareableLink row, factsheet share button).
- **Accessibility:** the CTA is a block-level button-styled link on its own line, not inline prose, so the DESIGN.md 2026-06-28 persistent-underline rule does not apply and `link-in-text-block` cannot fire on the strict public axe row. `text-text-secondary` on `bg-negative/5` is about 7.8:1 (ErrorEnvelope's own measurement).
- **Retry mechanism, for the planner to verify:** the observable contract is the link above. `prefetch={false}` is the **Recommended default (agent)**, so no prefetched payload is reused. The planner verifies against the Next 16.4.2 docs in `node_modules/next/dist/docs/` that a click on a same-URL `Link` re-runs the server read, and confirms it with one manual click against a forced failure. If a same-URL `Link` turns out not to re-run the read, fall back to a plain `<a href="/browse">` and record the `@next/next/no-html-link-for-pages` lint outcome.
- **Deviation recorded (CONTEXT D-03 discretion):** DESIGN.md's Error Envelope authoring rule asks every error path to call `buildEnvelope(code, …)`. `/browse` cannot. It is a server component, ErrorEnvelope is a client component whose Retry is a function prop a server page cannot pass, and no `wizardErrors.ts` code describes a category read. CONTEXT allows "otherwise match the envelope shell classes", so the block copies the shell, title and body classes verbatim and omits the diagnostics accordion (no correlation id exists on this path). Precedent: the same shell is already rendered inline, without `buildEnvelope`, in `src/components/ui/ScopedBanner.tsx`, `src/app/(dashboard)/allocations/components/WidgetState.tsx`, `src/components/auth/DeleteAccountButton.tsx` and `src/components/portfolio/PortfolioOptimizer.tsx`, among others.

## Surface C — ShareableLink row button (`src/components/strategy/ShareableLink.tsx`, D-05..D-07)

### Label states (exact strings)

| Trigger | Button label | Icon | Clears after |
|---------|--------------|------|--------------|
| idle, published | `Share Factsheet` (unchanged) | link | — |
| idle, unpublished | `Get private link` / `Manage private link` (unchanged) | link | — |
| minting | `Creating link…` (unchanged, button disabled) | link | — |
| copy landed | `Link copied!` (unchanged) | check, `text-positive` | 2000 ms |
| both copy paths failed | `Copy failed — copy the URL manually` (unchanged; now true on BOTH lanes, because the URL is on screen, see Surface D) | failure icon, `text-negative` | 4000 ms |
| mint answered **401** | `Signed out — sign in again to share` | failure icon, `text-negative` (the same mint-failed branch) | 4000 ms |
| mint answered **403 or 404** | `You can't share this strategy here` | same | 4000 ms |
| any other mint failure (5xx, 429, 503, network, empty or unparseable body, missing url) | `Couldn't create the link — try again` (unchanged) | same | 4000 ms |

- The 401 and 403/404 strings MUST NOT contain `try again` or `retry` (case-insensitive). D-12 asserts the absence.
- **Wording of 403/404:** D-06 names two causes, a 403 same-origin refusal ("this page") and a 404 lost ownership ("this account"). `here` is true for both. Naming the account would be false for a 403. **Recommended default (agent).**
- **Length:** the new labels are 35 characters (401) and 34 (403/404). The longest existing label, `Copy failed — copy the URL manually`, is 35, so the `/strategies` row width does not grow. The label is never truncated or ellipsed.
- The 4000 ms reset is today's behaviour for every failure label and is kept. Clicking again after a 401 or 403/404 re-runs the mint and shows the same string again. No new disabled state is added.

### Live region (D-07)

- One `<LiveRegion message={rowFailureText} />` is rendered as the **sibling after** the row `Button`, outside the `Modal` (the dialog's `showModal()` makes everything outside it inert, so the row region and the dialog region are separate).
- It is always mounted. `message` is the exact visible failure label from the table above (the copy-failed row or one of the three mint-failed rows) while that label shows, and `null` otherwise.
- Success (`Link copied!`) is not announced. That is unchanged and outside D-07's scope.
- **Test note:** the failure sentence now appears twice in the DOM (button + `sr-only` region). Existing `getByText(/…/)` assertions on these strings become ambiguous. Query by `getByRole("button", { name })` and `getByRole("status")`, using exact strings.

### Logging (D-05, no visual)

Every catch calls `console.warn("[ShareableLink] <what failed>", { strategyId, err })`. Never the URL or token.

## Surface D — Copy-failed dialog, both lanes (D-08..D-10)

The dialog opens only when both copy paths failed after a URL was known. On the mint lane the URL was minted; on the published lane it was built synchronously.

| Element | Mint lane (unpublished) | Published lane |
|---------|-------------------------|----------------|
| `Modal` `title` | `Private link` (unchanged) | `Public link` |
| Helper paragraph (`<p id={helperId} className="text-caption text-text-muted">`) | `Your private link is live, but this browser would not copy it for you. Use Copy link, or select the link and copy it yourself.` | `This browser would not copy the link for you. Use Copy link, or select the link and copy it yourself.` |
| `Input` `label` | `Private link URL` (unchanged; tests pin it) | `Public link URL` |
| `OwnerUnpublishedPanel` below | rendered (unchanged) | **not rendered** |

### URL row layout

```tsx
<div className="mb-4 flex flex-col gap-2">
  <p id={helperId} className="text-caption text-text-muted">{HELPER}</p>
  <div className="flex items-end gap-2">
    <Input ref={urlFieldRef} label={LABEL} readOnly value={url}
           aria-describedby={helperId}
           wrapperClassName="min-w-0 flex-1"
           className="font-mono text-caption" />
    <Button type="button" variant="primary" size="md" onClick={copyFromField}>{COPY_LABEL}</Button>
  </div>
  <LiveRegion message={dialogFailureText} />
</div>
```

- `aria-describedby={helperId}`: when focus lands on the field as the dialog opens, assistive tech reads why the dialog opened, even if the row region's announcement was lost to the inert background.
- The dialog's `LiveRegion` sits **inside** the Modal children (inside the URL block) and is mounted whenever that block renders.

### Copy link button states (exact accessible names)

| State | Label | Behaviour |
|-------|-------|-----------|
| idle | `Copy link` | Click copies the URL already in the field, straight from the handler. No `fetch` comes first. It goes through the shared bounded write (3 s) and then the `execCommand` fallback (D-08 exported helper). |
| working | `Copying link…` | `disabled`; lasts at most the 3 s bound |
| copied | `Copied` | Back to idle after 2000 ms |
| failed | `Copy failed` | Back to idle after 4000 ms. The field takes focus again and is fully selected: `focus()`, `select()`, `setSelectionRange(0, value.length)`. The dialog region announces `Copy failed`. |

- These four names are distinct as exact strings from the mint-lane panel's own button (`Create share link`, `Copy share link`, `Creating link…`, `Copying…`, `Link copied`, `Couldn't copy the link — try again`). Tests MUST match exact strings, never `/copied/i` or `/Copying/`.
- **Hierarchy:** **Copy link** is the primary (accent) action. The panel's `ShareLinkButton` keeps its existing secondary-surface styling and is not touched.
- **Open-time focus (D-09):** the existing effect still focuses and selects the field after `showModal()`, and now also calls `setSelectionRange(0, value.length)`. The field's `onFocus` does the same. The one-off check is Playwright WebKit on an iPhone device profile, recorded in the SUMMARY and VERIFICATION (no CI project added).
- **Overflow:** the URL field is a read-only single-line input, so a long URL scrolls horizontally inside it (`min-w-0 flex-1` lets it shrink beside the button at phone widths). Never truncated in the value.
- **Close:** unchanged. Close button, Esc and backdrop go through `Modal`'s `onClose`, and native `dialog.close()` returns focus to the row button.

### Factsheet `ShareLinkButton` (D-08 bound only)

No copy change. `mintAndCopy` goes through the shared bounded write, so a hanging write ends in the existing `failed` label `Couldn't copy the link — try again` instead of staying on `Creating link…` / `Copying…`. `copyPublishedUrl` and `shareButtonLabel` are byte-unchanged (Phase 164 D-09).
