<objective>
Build the one apt entry point the whole phase routes through and prove it end-to-end on ONE workflow site (the tracer), per the D-02 correction dated 2026-10-07 in 164.9.8-CONTEXT.md.

Purpose: the 2026-10-07 hangs survived the runner image's own 15 s / 1-retry apt settings because apt's timers are inactivity timers and a trickling fetch never trips them (RESEARCH Findings 2). A wall-clock bound per network phase, a bounded retry in a fresh apt process, and skipping apt entirely where the image already ships the tool (D-04) are what end the hang. This plan creates that script and wires it into ci.yml's `sql-tests` `Install psql client` step with its own step time limit (D-03).

Output: `scripts/ci-apt.sh` (with `--self-test`), one converted ci.yml step.
</objective>

    Behavior of `install`:
    (a) Skip (D-04): if `--provides CMD` was given and CMD is on PATH, print exactly one line beginning `apt-skip: ` that names CMD, the resolved path, and the first line of `CMD --version`, then exit 0 without invoking any apt binary.
    (b) Otherwise print one `apt-bound:` line stating attempts, per-phase timeout and kill-after, then print the effective config with `apt-config dump` for the keys Acquire::Retries, Acquire::http::Timeout and Acquire::https::Timeout (failure of the dump is non-fatal), so assumption A1 becomes a measurement on every non-skip run.
    (c) Network options defined ONCE in a bash array: `-o Acquire::Retries=1 -o Acquire::http::Timeout=15 -o Acquire::https::Timeout=15` (same values the image sets; command-line `-o` is applied last per apt.conf(5), so it survives any apt.conf.d ordering bug). Never add an option that weakens signature verification (no allow-unauthenticated, no insecure-repositories setting).
    (d) Resolve the wall-clock binary once as `command -v timeout` falling back to `command -v gtimeout`; if neither exists print `::error::MEASURE_FAIL:` naming the missing binary and exit 1. Run every network phase as sudo followed by the RESOLVED ABSOLUTE path of that binary with `--kill-after` (default 10 s, overridable by env `APT_KILL_AFTER` for the self-test) and the phase timeout, then apt-get with the option array. The timeout binary sits INSIDE sudo so the signal reaches apt-get itself, and its absolute path survives sudo's secure_path.
    (e) For attempt 1..N: network phase `update -y`, then network phase `install -y --no-install-recommends --download-only` with the packages. If both succeed, run the local unpack `sudo apt-get <options> install -y --no-install-recommends <packages>` with NO wall-clock wrapper (archives are cached; dpkg must never be killed mid-unpack) and exit with its status. If either network phase fails or is killed, print `::warning::apt attempt a/N failed or hit the S s wall-clock cap`, print forensics (`ls -l /var/lib/apt/lists/partial` and `ss -tn`, each head-limited and each `|| true`, so the next occurrence names the stalled host per assumption A2; print nothing from the environment, no tokens, no DSNs), and sleep `APT_RETRY_SLEEP` seconds (default 3) before the next attempt.
    (f) After the last attempt print `::error::MEASURE_FAIL: apt could not fetch '<packages>' in N attempts of S s per phase. A dead or trickling package mirror, not a repo defect.` and exit 1.

    `--self-test` may be a stub for this task (Task 2 fills it); it must not be absent from the usage text.

Do NOT add, remove, rename or reorder any step. Do not touch any other job in this task.
