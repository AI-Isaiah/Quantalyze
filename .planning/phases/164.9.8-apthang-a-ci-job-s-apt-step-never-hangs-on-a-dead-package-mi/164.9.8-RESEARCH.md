## Summary

Four hangs on 2026-10-07 (and a fifth class the booking did not list) share one log signature: `apt-get update`/`install` prints a `Get:1 file:/etc/apt/apt-mirrors.txt Mirrorlist` line, `azure.archive.ubuntu.com` answers nothing for ~30 s and is marked `Ign:`, `archive.ubuntu.com` then serves the `InRelease` files, and then the step produces NO output until the job or the operator cancels it (19.5 min in three `sql-mutation` attempts that died on the 20-min job ceiling; 67.5 min in `e2e-seeded`). **The runner image already sets `Acquire::Retries "1"` and `Acquire::http::Timeout`/`Acquire::https::Timeout "15"` in `/etc/apt/apt.conf.d/zz-retries`** (runner-images PR #14643 merged 2026-09-11, ordering fix PR #14726 merged 2026-09-15; the script is present at the exact image tag the failing jobs ran, `ubuntu24/20260927.320`). The 30 s azure delay in every log is those two settings working (2 tries x 15 s). So the stall that survives is one apt's timeouts do not bound: `Acquire::*::Timeout` is an inactivity timer, apt has no minimum-throughput setting, and runner-images issue #14823 (open, acknowledged by GitHub 2026-10-01) documents the trickle case (74.8 MB at 61.5 kB/s, 20 min, no `Err:`/`Ign:`).

Therefore **CONTEXT D-02 as worded (more timeouts/retries via `-o` flags or a drop-in) is necessary hygiene but NOT sufficient**; it duplicates what the image sets. The only bound that covers a trickle is wall-clock: kill the network phase at a deadline and retry in a fresh apt process (which re-resolves and can land on a healthy node), plus a per-step `timeout-minutes` as the backstop. D-03 (step time limits) and D-04 (skip psql) do the heavy lifting: the `postgresql-client` install, 10 of the 14 apt sites, installs only an 11.6 kB `all` meta-package because `psql 16.15` is already on the image, so skipping it removes apt exposure from 10 sites entirely. `postgresql-16-cron` (2 sites) is NOT on the image and must keep a bounded apt path.

**Primary recommendation:** Add ONE wrapper `scripts/ci-apt.sh` (explicit `-o` timeouts, `--provides` skip, wall-clock `sudo timeout` per network phase, `update` + `install --download-only` retried up to N times, dpkg phase local and never killed, `apt-config dump` + forensics printed). Route all 14 apt-install sites through it by editing `run:` blocks IN PLACE (no new steps, no composite action), give all 18 apt-reaching steps a `timeout-minutes`, and add a glob-census guard test `src/__tests__/contracts/ci-apt-bounded.contract.test.ts`. A prototype of exactly this form was run against 30 workflow-reading test files in a scratch clone: all green, zero existing tests moved.

### What bounds apt by default, and why it did not help

| Setting | Value on the failing image | Source |
|---------|----------------------------|--------|
| `Acquire::Retries` | `1` | runner-images `configure-apt.sh` at tag `ubuntu24/20260927.320`: `apt_retries=1` for x64, written to `/etc/apt/apt.conf.d/zz-retries` [VERIFIED: gh api contents @ tag] |
| `Acquire::http::Timeout`, `Acquire::https::Timeout` | `15` | same file: `apt_timeout=15` [VERIFIED] |
| apt's built-in `Timeout` | 30 s (`ServerState ... TimeOut(30)` in `methods/basehttp.cc`; PR #14643 says unchanged across 22.04/24.04/26.04) | [CITED: salsa.debian.org/apt-team/apt methods/basehttp.cc, main branch; noble ships apt 2.7.x, not separately checked] |
| image bug history | `80-retries` was overridden by another apt.conf.d file; fixed by renaming to `zz-retries` in PR #14726 (merged 2026-09-15) | [CITED: github.com/actions/runner-images/pull/14726] |

`zz-retries` verbatim: `Acquire::Retries "$apt_retries"; Acquire::http::Timeout "$apt_timeout"; Acquire::https::Timeout "$apt_timeout";` with a comment "A leaf name sorts after every NN-* file, so ours wins." The measured 30 s per mirror in every log equals 2 attempts x 15 s, consistent with these values being in force. The EFFECTIVE values were not dumped on the failing runners (no job printed `apt-config dump`), so this is an inference [ASSUMED, A1]; the wrapper prints them so it becomes a measurement.

**Semantics (cited):**
- `Acquire::http::Timeout`: "sets the timeout timer used by the method; this value applies to the connection as well as the data timeout" [CITED: manpages.ubuntu.com apt-transport-http(1), noble]. It is an inactivity timer. Issue #14823 states it outright: "`Acquire::http::Timeout` fires only when no data arrives for 15 s, so a trickling transfer never trips it ... apt has no minimum-throughput setting" [CITED: github.com/actions/runner-images/issues/14823, open, GitHub: "we're aware ... working on the case" 2026-10-01].
- `Acquire::Retries`: "Number of retries to perform. If this is non-zero APT will retry failed files the given number of times." [CITED: apt.conf(5)]. Per PR #14643, retries are spent on the SAME URI before apt moves to the next mirror in `apt-mirrors.txt`, so a high count delays failover.
- `mirror+file:` (`apt-transport-mirror`): "If the acquisition of a file via a mirror fails, the method ensures that another possible mirror from the list is automatically tried until either the file is retrieved or no mirror is left in the list"; priority: "The mirrors with the lowest number are tried first" [CITED: apt-transport-mirror(1)]. PR #14643 adds that "the mirror method re-sorts from priority:1 for every item and keeps no failure state", which is why each of 26 index items repeats the azure attempt in the logs (`Ign:` x26 in #14594).
- Option precedence: apt reads APT_CONFIG, then `Dir::Etc::Parts` in alphanumeric order, then the main file, then "the command line options are applied to override the configuration directives" [CITED: apt.conf(5)]. So `-o` on the command line beats any apt.conf.d file, immune to the sort-order class of bug #14726 fixed.

**Conclusion (the part the booking did not know):** the failures occurred with timeouts already at 15 s/1 retry. What is left is a stall apt's own timers do not end: a trickle, or an item whose request got no response headers (apt prints `Get:` only once a transfer starts, so a hung request is invisible in the log). The log cannot say which host or index the final silent fetch was on [A2]. Because the mirror fallback had already succeeded for `InRelease`, the stalled fetch may well be on `archive.ubuntu.com` itself, which is why dropping azure from the mirror list (Claude's-discretion item) is NOT recommended without a measurement: it could remove the fast same-datacenter mirror and not fix the stall.

## Recommendation (concrete design)

1. **`scripts/ci-apt.sh install [--provides CMD] [--attempts N] [--phase-timeout S] PKG...` and `--self-test`.** Full prototype under Code Examples. Behavior: if `--provides CMD` is on PATH, print `apt-skip: CMD is already on PATH at <path>: <version>` and exit 0. Else print `apt-config dump` of the three Acquire keys, then up to N attempts of `sudo timeout --kill-after=10 S apt-get -o ... update -y` and `... install -y --no-install-recommends --download-only PKG`, retrying the whole pair on any failure/kill (sleep between), then the local dpkg phase `sudo apt-get install ...` which touches no network and is never killed. After the last attempt: `::error::MEASURE_FAIL: ...` and exit 1. On each failed attempt print forensics (`ls -l /var/lib/apt/lists/partial`, `ss -tn`) so the NEXT occurrence names the host (answers A2). Explicit `-o Acquire::Retries=1 -o Acquire::http::Timeout=15 -o Acquire::https::Timeout=15` satisfy D-02 and are immune to apt.conf.d ordering. Defaults: `--phase-timeout 60`, `--attempts 3`.
2. **Edit the 14 apt-install sites' `run:` IN PLACE** (no new steps anywhere, no `uses:`):
   - 10 `Install psql client` steps (#1,2,4,5,6,7,13,15,17,18): replace the two apt lines with `bash scripts/ci-apt.sh install --provides psql postgresql-client`. Keep `set -euo pipefail` and `psql --version`.
   - 2 mutex-acquire dead branches (#14, #16): replace the two apt lines INSIDE `if ! command -v psql ...; then ... fi` with the same call, byte-identically in both files.
   - 2 pg_cron steps (#3, #12): replace `apt-get update` + `apt-get install` with `bash scripts/ci-apt.sh install --attempts 2 --phase-timeout 60 "postgresql-${major}-cron"`; keep `apt-cache policy` (move after the install; it then also shows `Installed:`), `dpkg -s`, the artifact `ls` checks. Identical `run:` text in ci.yml and the nightly (the parity pin enforces it).
3. **`timeout-minutes`, derived from measured healthy durations** (jobs API, last ~25 runs per workflow; n = successful executions; seconds):

### Anti-Patterns to Avoid
- **Adding a step (drop-in, "bound apt") to `sql-mutation`:** moves parity and scope-step pins (measured); edit in place.
- **A local composite action:** throws in the parity parser.
- **A short `timeout-minutes` on the mutex-acquire steps:** they legitimately wait up to ~33 min for the lock.
- **Killing `apt-get install` mid-dpkg:** only `update` and `install --download-only` may be killed; the unpack phase runs after the archives are cached.
- **Treating "psql present" as an assumption:** print the path and version every run.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Wall-clock kill of a child | a bash `sleep`+`kill` watchdog | GNU `timeout --kill-after` (run inside `sudo`) | signal delivery, exit code 124, no orphan |
| Skip-if-present | `dpkg -s` / `apt-cache policy` parsing | `command -v psql` | the consumer needs the binary on PATH, not the package |
| Effective apt config | reading `/etc/apt/apt.conf.d/*` by hand | `apt-config dump Acquire::...` | merges all sources including `-o`; the runner-images tests assert the same way |
| Workflow census | a hand list of 18 steps | `readdirSync` over `.github/workflows` | a workflow added later is covered automatically |
| Mirror failover | editing `/etc/apt/apt-mirrors.txt` | `apt-transport-mirror` already falls back; retry with a fresh process | edits are unsupported by evidence (Findings 2) |

**Key insight:** apt's own timers cover a dead mirror, not a slow one. A bound that works against a slow one is wall-clock, applied per phase and retried, and the cheapest bound of all is not running apt (the psql skip).

## Common Pitfalls

### Pitfall 1: Believing the timeouts are missing
**What goes wrong:** adding `-o Acquire::http::Timeout=...` everywhere and declaring victory; the next trickle hangs identically.
**Why it happens:** the booking evidence reads "no network timeout"; the image sets 15 s/1 retry since runner-images PR #14643.
**How to avoid:** keep the `-o` flags (D-02, immune to ordering bugs) but treat wall-clock + retry + skip as the real fix. Print `apt-config dump`.
**Warning signs:** a hang whose log shows `Get:` lines then silence, with no `Err:`.

### Pitfall 2: Raising or crowding sql-mutation's 20-minute ceiling
**What goes wrong:** CLAUDE.md: the 20 is a declared CEILING, "never raised". Two tests pin it (`sql-mutation-nightly-parity` timeouts, `sql-mutation-scope-step`).
**How to avoid:** the pg_cron step is bounded to 6 min worst case; healthy rest-of-job is <= ~11 min; no new step is added. Measured: raising 20 to 30 reds both tests.

### Pitfall 3: Parity drift with `sql-mutation-nightly`
**What goes wrong:** parity pins named steps and `run:` byte-equal but NOT step `timeout-minutes`, `if:`, `env:` or `with:` (measured: a one-sided `timeout-minutes` change leaves all 395 tests green).
**How to avoid:** edit the pg_cron `run:` identically (the pin enforces it); copy `timeout-minutes: 6` by hand to the nightly's step (it has a comment between `name:` and `run:`, so insert the key right after the `- name:` line); add guard rule R5.

### Pitfall 4: Editing the mutex-acquire suffix in one file
**What goes wrong:** two tests pin the suffix (from `if ! command -v psql`) byte-identical between `supabase-migrate.yml` and `test-restore-from-baseline.yml`.
**How to avoid:** change both in the same commit; keep the `if ! command -v psql` line; no `timeout-minutes` on those steps.

### Pitfall 5: `echo`-string false positives in the guard
**What goes wrong:** the Playwright steps contain `echo "... skipping apt install."`; a naive `/apt install/` guard fails on a correct tree (hit while prototyping).
**How to avoid:** match apt at COMMAND position only (line start or after `&&`/`||`/`;`, optional `sudo`).

### Pitfall 6: Skip-CI token anywhere (CLAUDE.md "CI gate integrity" 1)
**What goes wrong:** GitHub honours the skip tokens anywhere in a commit message or PR body, even inside a sentence denying them, and a squash merge carries them into `main`. Measured 2026-09-17: zero workflow runs.
**How to avoid:** write "the skip trailer" in prose; never type the literal tokens in commits, PR body, CHANGELOG, ROADMAP or this phase's docs. Bind the PR board to the head SHA by COUNT (`gh api repos/AI-Isaiah/Quantalyze/actions/runs?head_sha=<sha>`), not by "no red".

### Pitfall 7: `workflow_dispatch` on main as proof (D-06; CLAUDE.md "CI gate integrity" 2)
**What goes wrong:** a dispatched run scans full gitleaks history (37 pre-existing fixture hits) and goes red for reasons unrelated to the SHA.
**How to avoid:** prove the phase with the PR's own CI run on its head SHA (the `apt-skip:` lines are in that log).

### Pitfall 8: Docs-only PRs can red main
**What goes wrong:** `.planning/` files read by `frontend-test` assertions (`scripts/classify-changed-paths.mjs` keeps a list including `.planning/config.json`) mean a docs/bookkeeping change can break main.
**How to avoid:** this phase's code PR touches `scripts/` and `.github/` so it is classified as code. Run the `.planning`-reading tests (`critical-regressions`, `verify-plan-anchors`) before any bookkeeping commit; never write a SUMMARY for a deferred plan.

### Pitfall 9: Release toll
**What goes wrong:** a PR touching non-planning paths needs a `VERSION`/`package.json` bump (byte-equal 4-digit strings, asserted by `critical-regressions.test.ts`; never `npm version`) and a unified CHANGELOG entry written BEFORE the push per CLAUDE.md "CHANGELOG discipline". Do not name a skip token in it.

### Pitfall 10: `ubuntu-latest` becomes 26.04 within weeks
See Findings 4. A red pg_cron step after 2026-10-19 may be the deliberate PostgreSQL-major guard, not apt.

## Code Examples

### The wrapper (prototype, exercised with stubs; final default `--phase-timeout` is 60)
```bash
#!/usr/bin/env bash
# scripts/ci-apt.sh -- the ONE place a workflow touches apt.
#   bash scripts/ci-apt.sh install [--provides CMD] [--attempts N] [--phase-timeout S] PKG...
#   bash scripts/ci-apt.sh --self-test
set -euo pipefail
ATTEMPTS=3
PHASE_TIMEOUT=60
PROVIDES=""
# Command-line -o options are applied LAST by apt (apt.conf(5)), so they beat any apt.conf.d file.
APT_OPTS=(-o Acquire::Retries=1 -o Acquire::http::Timeout=15 -o Acquire::https::Timeout=15)
# timeout INSIDE sudo so TERM/KILL reaches apt-get itself. Only update and --download-only may be killed.
net() { sudo timeout --kill-after=10 "${PHASE_TIMEOUT}" "$@"; }
forensics() {
  echo "--- apt forensics (what the killed phase left behind) ---"
  ls -l /var/lib/apt/lists/partial 2>/dev/null | head -n 15 || true
  ss -tn 2>/dev/null | head -n 15 || true
}
install_pkgs() {
  if [ -n "${PROVIDES}" ] && command -v "${PROVIDES}" >/dev/null 2>&1; then
    echo "apt-skip: ${PROVIDES} is already on PATH at $(command -v "${PROVIDES}"): $("${PROVIDES}" --version 2>&1 | head -n 1)"
    return 0
  fi
  apt-config dump Acquire::Retries Acquire::http::Timeout Acquire::https::Timeout || true
  local a
  for ((a = 1; a <= ATTEMPTS; a++)); do
    if net apt-get "${APT_OPTS[@]}" update -y \
      && net apt-get "${APT_OPTS[@]}" install -y --no-install-recommends --download-only "$@"; then
      sudo apt-get "${APT_OPTS[@]}" install -y --no-install-recommends "$@"   # archives cached: no network
      return 0
    fi
    echo "::warning::apt attempt ${a}/${ATTEMPTS} failed or hit the ${PHASE_TIMEOUT}s wall-clock cap"
    forensics
    [ "${a}" -lt "${ATTEMPTS}" ] && sleep "${APT_RETRY_SLEEP:-3}"
  done
  echo "::error::MEASURE_FAIL: apt could not fetch '$*' in ${ATTEMPTS} attempts of ${PHASE_TIMEOUT}s per phase. A dead or trickling package mirror, not a repo defect."
  return 1
}
# self_test(): stub sudo/apt-config/apt-get on PATH; (1) one hung `update` then success must pass,
# (2) an always-hanging `update` must fail after N attempts, (3) --provides sh must print "apt-skip:".
# (full body in the planner's task; the prototype printed:
#  "ci-apt self-test OK: retry-after-hang, fail-after-N, skip-when-present." in 3.3 s)
```
Planner notes: resolve `timeout` as `command -v timeout || command -v gtimeout` and fail loud if neither (a bare macOS dev box has neither; the dev box used for research had `/opt/homebrew/bin/timeout`). Keep `-qq` differences out: `prod-prober.yml` used `update -qq`; the wrapper's verbosity is uniform, which is the point.

### Known Threat Patterns for this stack
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Compromised/poisoned mirror content | Tampering | apt verifies signed `Release` files; the azure mirror is plain `http://` but signatures protect it; the change adds no unauthenticated path |
| Log leakage in a PUBLIC repo | Information disclosure | forensics print `ls` of apt partial files and `ss -tn` (runner/mirror IPs only); no env, tokens or DSNs; keep it that way |
| Supply chain via a new package | Tampering | no new package; `postgresql-client` skipped where present, `postgresql-16-cron` unchanged |
| Retry loop masking a real failure | Repudiation | fail loud: `::error::MEASURE_FAIL` after N attempts, warnings per attempt, step limit as backstop |
