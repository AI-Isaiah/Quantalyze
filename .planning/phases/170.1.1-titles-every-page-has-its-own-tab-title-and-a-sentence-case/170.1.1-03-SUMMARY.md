## Notes for the reviewer

- **Edit page owner predicate.** The page serves only the owner's strategy (`.eq("user_id", user.id)`), so `generateMetadata` mirrors that with a `getUser()` call. That is the page's own owner-only predicate, not the banned `published OR owner` form. Without it, `/strategies/<someone else's published id>/edit` would title the tab with that manager's name while the body says "Strategy not found".
- **Discovery strategy H1 vs title.** The factsheet body shows `strategy.name ?? codename`, while the breadcrumb and (now) the tab title use `displayStrategyName`. For a non-institutional row with a real name and no codename, the tab reads `Strategy #<8 chars>` while the factsheet H1 shows the real name. This follows the plan and T-170.1.1-05 (a withheld name must stay withheld); it is a visible mismatch the orchestrator may want to rule on. The `Strategy #<prefix>` label is the existing breadcrumb label, not a new id leak path.
- Only the /portfolios/[id] metadata has a test (what the plan asked for). The discovery-strategy withheld-name path and the other fallbacks are covered by tsc and reading, not by a test.
