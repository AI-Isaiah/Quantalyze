## What the tests encode

- **Sync twin shares the async helper's predicate and budget.** A 504 once then a value is retried (pins the shared `_is_transient_read_error`); `ConnectTimeout` and `RuntimeError` propagate after one call; exhaustion is a bare re-raise of the same object after `DB_READ_MAX_RETRIES` calls.
- **2D control run.** The preferences test runs the function twice, once with no timeout and once with a ReadTimeout on the preferences read, and asserts every other table's read count equals its control count. The control was measured, not assumed to be once.
- **2F second read.** `test_second_read_stays_single_attempt` pins that the `mandate_edited_at` read still propagates a ReadTimeout on its first attempt (D-02a moves only named reads).
- **2E.** The retried case still raises the capped event once and never calls `capture_exception`; the exhausted case is captured once, logged, and remembers no job id.
