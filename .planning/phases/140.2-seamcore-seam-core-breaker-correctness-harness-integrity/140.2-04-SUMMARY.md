**Three corrections to the planning documents, all settled by running the rule rather than reading it:**

1. **CONTEXT is wrong about shape 5** — `fetch(new URL("/x", base))` was caught all along. RESEARCH

2. **PATTERNS.md §PART 6 is wrong about the warmers.** It states *"Also unmatched:
   `fetch(url.replace(/\/+$/,"") + "/health")` where `url` is one hop removed"* and that the warmers

**Row I was not in the plan's shape list and is a genuine addition.** A fixed point computed *during*
traversal would satisfy shapes 3 and 4 and still miss it. It is the only fixture that can fail while

- **The four-path allowlist is exactly-NECESSARY, not merely sufficient.** Every one of the four

  entire value is the sixth seam that has not been written yet — which is the correct shape for a
  mechanism, and the reason the fixtures rather than the lint output are its proof.

### The false-positive cost, measured rather than waved away

The widening does have a cost, and it is one hop of an imprecision that already existed:

| Case | BEFORE | AFTER | |
|---|---|---|---|
| two-hop value DERIVED from the base (`const configured = Boolean(base)`) then used in an unrelated fetch | clean | REPORTED | ***NEW*** |
| the one-hop version of the same (`const configured = Boolean(process.env.X)`) | REPORTED | REPORTED | pre-existing |
| a shadowing re-declaration of a tainted name in an inner scope | REPORTED | REPORTED | pre-existing |

Only the first is new, and it widens a class the rule already had rather than opening one. Zero
instances across 1360 files. The direction is a **loud false positive, never a silent miss**, and
that trade is now stated in the rule's docblock (the SCOPES / function / module bullets) instead of
being discovered by whoever trips it. No inline disable was added anywhere.

### The docblock correction, in full

The old text read *"CEILING (honest): tainting is ONE hop … A fixed-point alias pass would close it;
it is not built because the shape has never appeared in this repo."* Both clauses were wrong: the
ceiling was real, and the aliased shape does occur (the plan's premise). The replacement states the
transitive behaviour and then names the **residual** ceiling honestly — taint crosses neither
**function** boundaries (a base URL passed as a parameter) nor **module** boundaries (an exported
const imported elsewhere), and it is keyed by **name for the whole file** rather than scope-resolved,
so a shadowing re-declaration stays tainted. It names that last one's error direction as a loud false
positive rather than leaving it implied, and points at the backstops: the `SEAM_EXCLUSIONS` source
scan and the 13-member binding roster from 140.2-03, plus review of any new `resilientFetch` call site.
