# Phase 166.1 ENGINEFLOOR: silent-failure review, round 1

The floor itself is sound. Every S and C site reads `services/dispersion.py`, the
floor is applied to the leg that is divided by, and no site in the diff still
divides by a residue std. The defects sit one layer out. The phase correctly
turns a fabricated ratio into `None`, and then **callers turn that `None` into
`0`**, which is rendered as a confident "no change" or "zero correlation". The
two HIGH findings were reproduced at HEAD with the phase's own
`nav_constant_yield` fixture. They are not inferred.

## HIGH

### HIGH-1: C3's new `None` becomes a rendered "correlation toward 0.00"

- **Where:** `portfolio_optimizer.find_improvement_candidates` (C3,
  `corr_with_portfolio`) → `src/lib/portfolio-analytics-adapter.ts`
  `parseOptimizerSuggestionRow` (`asNumber(v.corr_with_portfolio) ?? 0`) →
  `src/components/portfolio/WhatWedDoCard.tsx` `corrLine`. The type
  `OptimizerSuggestionRow.corr_with_portfolio` in `src/lib/types.ts` is `number`,
  not `number | null`.
- **Measured at HEAD:** a portfolio of one constant-yield strategy
  (`nav_constant_yield(1e-4)`) plus a noisy candidate returns
  `corr_with_portfolio: None, sharpe_lift: 0.0`. The adapter maps the `None` to
  `0`. The card's gate (`sharpe_lift < 0` rejects, so `0` passes) lets it through,
  and `0 < 0.3` renders **"reduce average correlation toward 0.00"**. That tells
  the user the candidate is a perfect diversifier, when the correlation is
  undefined.
- **Also:** `sharpe_lift` is `0` on the same row, from the pre-existing
  `if current_sharpe is not None else 0` fallback. S1 now sends every
  constant-yield book down that branch, so the phase widens the reach of an
  existing fabricated zero.
- **Hidden:** the backend is correct, and the fabrication happens after the
  backend. No backend test can see it. `test_c3_*` asserts the Python `None` and
  stops there.
- **Fix:** make `corr_with_portfolio` `number | null` in `types.ts`, remove the
  `?? 0` in `parseOptimizerSuggestionRow`, and skip `corrLine` when it is `null`.
  `PortfolioOptimizer.tsx` already types it `number | null`. Add a vitest case
  where a `null` correlation renders no correlation clause.

### HIGH-2: the simulator and replacement deltas coerce the phase's `None` to `0.0`, rendered as "unchanged"

- **Where:** `services/simulator_scoring.py` `simulate_add_candidate`
  (`corr_delta` and `sharpe_delta` through `_delta`), and
  `services/bridge_scoring.py` `find_replacement_candidates` (`sharpe_delta`,
  `corr_delta` through its own `_delta`). Both `_delta` helpers coerce `None` to
  `0.0` by docstring.
- **Measured at HEAD:**
  - For a noisy two-strategy book plus a constant-yield candidate, C4 makes
    `proposed_avg_corr` `None`, and the result is `corr_delta: 0.0`. The NEW-C11-02
    guard in `simulate_add_candidate` covers a `None` **current** only. Its own
    comment says a coerced `0.0` renders as a confident "Correlation unchanged
    (±0.000)". The proposed side reaches the same fabrication.
  - For a book of constant-yield strategies plus a noisy candidate, S1 makes
    `current.sharpe` `None`, and the result is `sharpe_delta: 0.0` beside
    `current.sharpe: None`. That reads as "Sharpe unchanged".
  - `bridge_scoring` has no flat-candidate or flat-incumbent guard. The same
    inputs give `corr_delta` or `sharpe_delta` `0.0` in `ReplacementCard`.
- **Hidden:** before the phase, an all-zero leg already took this path. The phase
  routes every constant-yield leg into it too, and that is the population the
  phase exists for. A wrong ~1e13 number has been swapped for a wrong "±0".
- **Fix:** a delta whose either side is `None` is `None`. Apply that in both
  `_delta` helpers, or at the `corr_delta`/`sharpe_delta` call sites the way
  NEW-C11-02 does for the current side. Then confirm that `PortfolioImpactPanel`
  (which already renders `corr_delta === null`) and `ReplacementCard` accept
  `null` for `sharpe_delta` as well. In `bridge_scoring`, `composite` must treat a
  `None` axis as 0 contribution *explicitly* and not through the rendered delta.

## MEDIUM

### MEDIUM-1: book-level average correlation quietly drops the masked pairs

- **Where:** `portfolio_risk.compute_avg_pairwise_correlation`, fed by C1's
  masking in `compute_correlation_matrix`.
- C1 correctly sets a constant-yield leg's row and column to `None`. The average
  then skips every `None` pair (`if val is not None`) and returns the mean of the
  remaining pairs. That value is the "Avg Correlation" KPI and the PDF figure,
  labelled as the whole book, but it is computed over a subset that excludes the
  constant-yield strategy, and no flag says so. The phase widens this from
  all-zero legs to constant-yield legs.
- **Fix:** return the pair count used next to the value, or set a
  `partial_data`-style disclosure when any pair was masked. The narrative already
  has the SF-F2 partial-data hedge to hang it on.

### MEDIUM-2: S7's residue branch reports an undefined share as `0`

- **Where:** `portfolio_risk.compute_risk_decomposition`, the
  `dispersion_is_residue(port_vol, 0.0)` branch.
- The branch's own comment says marginal and component attribution is
  "genuinely undefined" when the portfolio carries no risk. It still emits
  `marginal_risk_pct: 0` and `component_var: 0`, so the rows sum to 0% where
  every real split sums to 100%. S7 now sends two constant yields here, and
  `test_s7_risk_decomposition_of_constant_yields_splits_no_risk` pins `[0, 0]`,
  which locks the zero in place.
- **Fix:** emit `None` for the two undefined fields (keep `standalone_vol`), check
  that the consumer renders a null as "—", and pin `None` in the test.

### MEDIUM-3: the D-24 rejection shows under a label that claims a Sharpe > 10

- **Where:** `csv_validator._check_sharpe_sentinel`, the constant-series branch.
- The branch reuses rule key `daily_sharpe_sentinel`. `CsvValidationEnvelope`
  builds the prominent cause line and the `<details>` summary from
  `CSV_RULE_LABELS["daily_sharpe_sentinel"]` = "Daily Sharpe > 10 looks
  unrealistic". Its headline is "1 row failed validation", and `row: 0` points at
  the first row. Under D-24, a two-row upload of a constant 0.01% gets that copy.
  The accurate sentence ("Daily returns do not vary …") appears only inside the
  collapsed details list. A user checking row 0 for a large number will find
  nothing wrong with it.
- **Fix:** give the branch its own rule key (for example
  `constant_positive_returns`) with its own `CSV_RULE_LABELS` entry, and
  update the S3 tests to assert that key.

## LOW

### LOW-1: an unreachable `else 0` fabrication on the line C3 edited

`find_improvement_candidates` skips any candidate with `len(aligned) < 30`, so
the C3 conditional `... if len(aligned) > 10 else 0` can never take its `else`.
It is dead code, and it would state a correlation of exactly 0. The phase
rewrote this line and kept it. Delete the conditional.

### LOW-2: C7 behaviour tests exercise a replica, not `verify_strategy`

The C7 behaviour tests run `_c7_block`, a hand copy of the matching block.
`test_c7_verify_strategy_matches_through_dispersing_corrwith` pins substrings of
the real source only. A change in `verify_strategy` around the helper call
(argument order, threshold comparison) would leave every C7 test green. The file
discloses this ("no pure seam"). Recorded so the gap is not mistaken for coverage.

### LOW-3: the S-site constant-yield tests do not assert their residue precondition

`test_dispersion_floor_sites.py` S1/S2/S4/S5/S6/S7 take `nav_constant_yield(...)`
and never assert `0 < std <= residue_floor(mean)`. S3 and S8 do, and so does the
correlation file's `_residue_leg`. Measured today, all 11 fixtures have a
non-zero std of 1.0e-16 to 1.5e-16, so the tests do bite. If a numpy or platform
change ever returned an exact `0.0`, those tests would pass against the old
`== 0` guards without failing. Add one parametrized precondition test over
`CONSTANT_YIELDS`, or assert the precondition in the S-site tests.
