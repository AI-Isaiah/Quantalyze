# Phase 166.1 Plan 03: correlation sites C1-C8 stop reporting a correlation over a residue leg Summary

Two helpers in `services/dispersion.py` now carry the rule "a correlation needs two legs that
really disperse": `pairwise_correlation_or_none` and `dispersing_corrwith`. All eight correlation
sites outside `metrics.py` use them or the `both_move` mask. Before the fix, two strategies with the
same compounding constant yield `corrwith`-ed each other at **1.0**, so `find_matched_strategy`
returned the twin as a match. A 1e-4 NAV yield showed a 0.05 correlation and a **1.0 diagonal** in the
portfolio matrix, and a 337-point rolling correlation series near -0.28. Each site now emits exactly
what an all-zero leg already gets there: None, or an empty series. No new output shape reaches a
reader.

## Deviations from Plan

**1. [Rule 1 - redundant code] `dispersing_corrwith` has no separate target check.** The plan's
action names "an EMPTY float Series when the target's dispersion is not real". The first
implementation had an explicit target check before the per-column loop. Its drill could not go red,
because the per-column rule (both legs must disperse on the pairwise rows) already rejects every
column when the target is flat. The check was removed, so the helper has one rule and the planned
behaviour is unchanged: a flat target gives an empty float Series (11 ids, drilled). Commit
`64af22b25`.

**2. [Test strength] Two tests were reworked after a drill showed they could not fail.**
- The overlap test now uses a constant-yield overlap instead of zeros.
- The C8 no-dispersing-candidate test now includes an all-zero-only candidate set. This is the
  case that took the broad `except` today. A residue-only set gives a small residue value, not NaN,
  so it could not go red on the unedited site.
- Both were fixed before their RED commits.

**3. [Process] TDD split into RED and GREEN commits** for Tasks 2 and 3 (tdd.md contract), as
plan 01b did.

**4. [Scope note] C6 is tested behaviourally.** The plan named a pure seam only for C7's absence.
C6 was driven through `_compute_portfolio_analytics` with a compact local stub client, following
the advisor's one-attempt rule. The residue survives the single-strategy weighted sum unchanged, so
the test is a real end-to-end D-07 comparison, not a source pin.
