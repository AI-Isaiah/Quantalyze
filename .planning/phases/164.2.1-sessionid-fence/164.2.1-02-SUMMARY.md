### [Rule 3 - Blocking] Local machine username in this phase's own planning artifacts reddened `npm test`

- **Found during:** Task 2, first `npm test`.
- **Issue:** `src/__tests__/check-planning-hygiene.test.ts` failed with **8**
  `LOCAL-USERNAME` violations — "the local machine username appears inside a
  home-directory path on a public repo. Replace it with the placeholder
  `<user>`." All eight were in this phase's own artifacts:
  `164.2.1-01-PLAN.md:114,135,161`, `164.2.1-02-PLAN.md:72,79,79,92`,
  `164.2.1-RESEARCH.md:212`.
  **Pre-existing, not caused by this plan:** the three files were last written by
  the planning commit `bedda506`, which `git merge-base --is-ancestor bedda506
  368a323c` confirms is an ancestor of this plan's base. Wave 1 never ran the
  full suite (it ran the touched files plus a 45-file neighbourhood), so nothing
  had surfaced it. The scanner derives its needle from the live `USER`, so on CI
  (`USER=runner`) it would never have fired — this is a local-only gate, which is
  precisely why it went unnoticed.
- **Why fixed rather than deferred:** Task 2's `<verify>` runs `npm test`, and a
  criterion may not be weakened to make it pass. The repo is PUBLIC and
  `.planning/` is TRACKED, so this is a genuine (if small) disclosure. The fix is
  the repo's own established convention, not an invention: **9** existing
  `.planning/` files already carry `/Users/<user>/claude-projects/quantalyze` and
  `-Users-<user>-claude-projects-quantalyze`, including `<automated>` verify
  commands in `164.4.1-01/03/04-PLAN.md`.
- **Fix:** `sed -i '' "s/$(id -un)/<user>/g"` across exactly those three files
  (written here with `$(id -un)` rather than the literal name — the scanner
  flags the username in ANY tracked file, this SUMMARY included, and it caught
  the first draft of this very line).
  Occurrences counted PRE-edit — `01-PLAN.md` 3, `02-PLAN.md` 4,
  `RESEARCH.md` 1 = **8**, matching the violation count one-for-one — and **0**
  after. `git diff --stat`: 7 insertions, 7 deletions across 3 files, nothing
  else. No plan semantics were touched: only the username inside a path changed,
  producing the same template form every other phase already uses.
  ⚠️ **Both `<verify>` blocks in `02-PLAN.md` were executed with the REAL
  absolute path resolved, BEFORE this substitution** — the recorded commands are
  now templates, exactly like `164.4.1`'s, not commands that were never run.
- **Files modified:** `164.2.1-01-PLAN.md`, `164.2.1-02-PLAN.md`,
  `164.2.1-RESEARCH.md` (planning artifacts only — no source file was touched)
- **Verified:** `check-planning-hygiene.test.ts` **42 passed (42)** file-scoped,
  then the full suite green as recorded above.
