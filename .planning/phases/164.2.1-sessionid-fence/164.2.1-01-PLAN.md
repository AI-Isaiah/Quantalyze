## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser localStorage → `loadWizardState` | attacker-influenceable (any script/extension in the origin, DevTools); the payload is HMAC-signed with a per-tab nonce in sessionStorage |
| `WizardClient` → `create-with-key` POST | the emitted `wizard_session_id` becomes a client-owned idempotency token; the DB index is the guarantee |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-164.2.1-01 | Tampering | `loadWizardState` — injected/forged `apiKeyId` to force a restore for a different key | low | mitigate | the field rides INSIDE the signed `p` string (`writeWizardState` signs the whole JSON); a modified `apiKeyId` fails HMAC exactly as any other field; and the gate can only DECLINE more often, never grant more (Task 2's forged-envelope pin covers the non-string case) |
| T-164.2.1-02 | Denial of Service | `deriveWizardResumeOverrides` — attacker forces a decline to deny resume | low | accept | declining only refreshes the idempotency token; the draft, the resume banner and the server-side draft row are untouched (`WizardClient` seeds `newWizardSessionId()` on mount); the same actor could simply clear localStorage |
| T-164.2.1-03 | Information Disclosure | `apiKeyId` (an `api_keys.id` UUID, not a secret) persisted in localStorage | low | accept | the same UUID is already in the server draft row read by the overlay and in the `reuse_api_key_id` POST body; no credential material is stored; length bounded at `FINGERPRINT_MAX_LEN` so the envelope cannot carry a serialized payload in this field |
| T-164.2.1-04 | Repudiation | stale `persistPointer` closure stamps the wrong key, later mis-declining or mis-restoring | medium | mitigate | Task 3: explicit `keyId` argument + WIRE test with a responder id distinct from the preselect id |
| T-164.2.1-SC | Tampering | npm installs | low | accept | no package is installed by this phase (RESEARCH: Package Legitimacy Audit not applicable) |
</threat_model>
