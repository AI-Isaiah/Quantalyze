## Anti-Vacuity Protocol (SC-2)

⛔ Three failure modes this phase must not ship, each already observed in this milestone:

1. **The throwaway-id trap.** `WizardClient` seeds a fresh `newWizardSessionId()` on mount, so
   "emitted id ≠ A's id" is TRUE before any fix exists. SC-1c alone is therefore vacuous.
   The same-key POSITIVE CONTROL (SC-1d) is what gives it power — it must FAIL if the gate
   declines unconditionally.
2. **The mock trap.** See Wave 0 above.
3. **The stale-closure blind spot.** `persistPointer` closes over the pre-connect key. On the
   *reuse* arm that stale value happens to equal the preselect id — so the defect is invisible in
   exactly the preselect test. WIRE must assert the POST envelope's key, not just the session id.

**Neuter sequence** (SC-2), never `git checkout --` (it destroys uncommitted work in a
neuter/restore harness):

```
count tokens PRE-edit           # a token counted by reading the finished file always passes
cp <file> $SCRATCH/<file>.bak   # byte backup, re-taken after every edit (they go stale)
shasum -a 256 <file>            # BEFORE
<neuter: drop the incoming-key clause from the gate predicate>
npx vitest run <unit> <component>   # expect RED, naming the new arms
cp $SCRATCH/<file>.bak <file>   # restore from the byte backup
shasum -a 256 <file>            # AFTER — must equal BEFORE
npx vitest run <unit> <component>   # expect GREEN again
```

⚠️ The SEAMRIM pins (SC-3) must stay GREEN **under the neuter**. That is what discriminates
"the new gate broke" from "the source gate was narrowed" — a neuter that reddens them has
changed the wrong thing.
