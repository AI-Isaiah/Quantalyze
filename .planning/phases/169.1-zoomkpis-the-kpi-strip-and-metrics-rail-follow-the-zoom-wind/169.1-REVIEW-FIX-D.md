### MD-01 residual: TimeSeriesChart pan, x-pull and wheel re-derived the windowed view per event

**Files modified:**
- `src/app/factsheet/[id]/v2/TimeSeriesChart.tsx`
- `src/app/factsheet/[id]/v2/TimeSeriesChart.window-gesture.test.tsx` (new test file)

**Commit:** `2c36c4d63`
**Status:** fixed

**Applied fix:**
- **Pan and x-pull.** `onPointerDown` takes topic B's `useRangeGesture()` hold (`begin(xRange)`) in the x-pull and pan branches, after the `button !== 0` return. Y-pull never moves the x-range, so it takes no hold.
- **Release paths.** The hold is released in `onPointerUp`, which pointer cancel also routes to. It is also released in a new `onLostPointerCapture` handler, which clears the drag refs too. The unmount cleanup releases it as well.
- **Wheel.** A burst takes the hold on its first tick. Each tick re-arms a `WHEEL_SETTLE_MS` (150 ms, exported) timer, and the hold is released when the timer fires. The timer is cleared on unmount, and also when a drag starts inside a burst: the drag then takes over the hold and its pointer up releases it. A wheel tick during a drag sets no timer.
- **Ownership.** `holdingRef` records whether THIS chart took the hold, and a chart releases only a hold it took. The hold is one value shared across the page. Without this, a chart that never held would release another component's hold whenever it unmounted, for example the Volatility Matched chart unmounting when the comparator is set to None.
- **Charts stay live.** The charts still read the live `xRange`, so they follow the gesture on every event. Only `useWindowedView`'s derive waits.

**Evidence** (`TimeSeriesChart.window-gesture.test.tsx`, 8 cases):
- **Setup.** The test counts `bootstrapCI` through a pass-through `vi.mock`, as topic B's test does. The chart is mounted without the MasterBrush, so the brush's own hold cannot stand in for a missing one. The range is zoomed to [100,199] first, because at full history the "0 derives" assertion would pass vacuously.
- **Counts.** Pan (6 moves), x-pull (6 moves) and wheel (6 ticks, each within the settle window): **0** derives during the gesture and **1** after release or settle.
  - The live range changes on every event.
  - The strip and rail scope stay on [100,199] until release.
  - The settled `strategyMetrics` and `bootstrapCI` equal `windowView` of the final range.
  - `rail.view` is the same object as `strip.view`.
- **Releases.** Each of these releases the hold: pointer cancel, lost pointer capture, unmount mid-drag, and unmount mid-wheel-burst. The last one also asserts that no timer is left pending.
- **Ownership.** Unmounting a second chart that took no hold leaves the first chart's hold in place.
- **Before the fix.** With the hold removed: **6** derives during each 6-event gesture, measured in a throwaway copy of the test with the scope assertions removed.

**Neuter runs.** Each mechanism was neutered on its own, then restored with `cp` and confirmed with `cmp`:

| Neutered | Result |
|---|---|
| `beginGesture` call removed | 8/8 red |
| Wheel settle timer replaced by an immediate release | 2 red (wheel burst, unmount mid-burst) |
| Unmount cleanup removed | 2 red (unmount mid-drag, unmount mid-burst) |
| Ownership guard removed | 1 red (the other chart's unmount) |
| `onLostPointerCapture` unwired | 1 red (lost capture) |

- When `stratAnnVol` is not finite, `buildComparatorBlock` emits `volMatched: null` and `volMatchedLabel: null`. This is the same form as `noneComparatorBlock` and `unavailableComparatorBlock`. No scale factor is invented.

- **Readers of `volMatched` checked.** They are `chart-configs.ts` (`Array.isArray` guard), `FactsheetView.tsx:662` (filter by key only) and the type, which is already `| null`.

**Evidence:**
- **Unit cases.** A strategy vol of NaN and of Infinity each gives a null series and a null label. A finite vol keeps `SPX × d.dd` and a full-length series.

## Residuals

These are also listed in the frontmatter.

1. **Shared-hold root cause, owner needed in `basis-context.tsx`, topic B's file.** The hold `held` is one slot with no owner, so any holder's `end()` releases every hold.
   - **What this round closed.** TimeSeriesChart's ownership guard closes only the case where a chart that never held unmounts.
   - **Overlapping holders stay open.**
     - A wheel tick on chart A takes the hold and arms the 150 ms settle.
     - Within that window, a MasterBrush drag or a wheel on chart B calls `begin()` and overwrites `held`.
     - A's timer then calls `end()` and clears it.
     - For the rest of that gesture, every event derives again. B does not take the hold again, because its `holdingRef` is already set.
   - **Impact.** Performance only: the figures stay correct. The window is narrow.
   - **Fix.** A token or a refcount in `basis-context.tsx`.
   - **Same class in `MasterBrush.tsx:64`.** It ends the hold on unmount unconditionally. Measured: the brush mounts unconditionally at `FactsheetView.tsx:410`, so that unmount happens only together with the whole view.
2. **Keyboard pan/zoom on the chart still derives once per key press**, including on auto-repeat. This is outside the brief, which covered pointer and wheel only.
