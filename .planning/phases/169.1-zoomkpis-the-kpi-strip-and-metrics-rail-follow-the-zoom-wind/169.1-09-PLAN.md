<objective>
Make the Rolling Sharpe chart's strategy line continuous across the days the active day basis
excludes (D-38). Plan 169.1-06 keeps the rolling Sharpe VALUES exactly the engine's, null on an
excluded day (D-33, D-27). `TimeSeriesChart.tsx`'s `buildPath` starts a new subpath after every null,
so without this plan an active-basis strategy's rolling Sharpe line breaks at every zero-return day.
The orchestrator decided (D-38) to keep the values and change only the drawing, scoped so no other
line, above all the comparator line Phase 169 plan 169-03 deliberately breaks past `through`, moves.

Purpose: the chart reads as one rolling Sharpe line while every number stays the engine's.
Output: an opt-in bridge in `buildPath`, the config field that enables it on the rolling Sharpe's
strategy series only, and one test file.
</objective>

**Facts measured at plan time (2026-09-26, before Phase 169 plan 169-03 ran; re-read at HEAD).**
- `buildPath(values, X, Y, useLog)` walks `values`; a null, non-finite, or (under log scale)
  non-positive value sets `prevValid = false`, so the next finite value opens a new subpath with `M`.
  The series map in `TimeSeriesChart` calls it once per non-muted series, and `closePathToBaseline`
  fills under it only for a config with `fill` (the rolling Sharpe config has none).
- `CHART_CONFIGS` entry `rollingSharpe` has `stratField: "strategyRollingSharpe"` AND
  `comparatorField: "rollingSharpe"`: the chart draws the strategy series (stroke
  `var(--color-accent)`) and a comparator series (stroke `var(--color-text-muted)`).
  `resolveSeries` builds one `ResolvedSeries` per series; `ResolvedSeries` carries `name`, `values`,
  `color`, `width`, `opacity` and an optional `fill`.
- Phase 169 plan 169-03 pads each comparator per-day chart array, the rolling series included, with
  null past the comparator's `through`, and relies on the comparator line breaking there
  (`TimeSeriesChart.coverage-gap.test.tsx`). A bridge applied to the comparator series would draw no
  segment past `through` (no finite value follows), but it WOULD join an interior comparator null, so
  the bridge is scoped to the strategy series, never the comparator's.
- Before 169.1-06, `rollingSharpe` emits null only for the leading warm-up (a zero-variance window
  gives 0, not null), so every existing strategy rolling Sharpe line, including the Scenario charts',
  which reuse `CHART_CONFIGS`, has no interior null on finite returns and renders identically.
- The chart's average line (`showStratAverage`), its Y-domain scan and the crosshair read `values`,
  not the path, so they do not change.
