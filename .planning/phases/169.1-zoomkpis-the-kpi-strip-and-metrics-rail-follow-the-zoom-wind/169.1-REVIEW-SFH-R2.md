## Findings

### MEDIUM-1: a null vol-matched series leaves a "Volatility Matched" panel showing only the strategy line, with no reason given. The comparator side still falls back to an invented × 1.00.

**Location:** `src/lib/factsheet/comparator-block.ts` (the `vmScale` / `vmAvailable` block, about
lines 113-125). The consumers are `src/app/factsheet/[id]/v2/chart-configs.ts` (`resolveSeries`,
the `Array.isArray(cmpRaw)` gate) and `src/app/factsheet/[id]/v2/FactsheetView.tsx` (the
`PerformanceCharts` `configs` filter).

**What happens.** Fix D sets `volMatched` and `volMatchedLabel` to `null` when `stratAnnVol` is not
finite. `resolveSeries` handles a null comparator field by pushing nothing. So the panel still
renders, still titled "Cumulative Returns — Volatility Matched" with the subtitle "comparator
returns scaled so its ann vol equals the strategy's", and it draws the strategy curve and nothing
else. Neither the panel nor the legend says that the match was skipped.

`PerformanceCharts` already filters out this exact degenerate panel when `cmpKey === "none"`. The
reason given in the 2026-05-20 comment is that a panel with only the strategy line "is visually
identical to the Equity Curve panel above it". With a comparator selected and `volMatched === null`,
the new code produces that same panel, and nothing filters it out.

**When it happens.** `comparatorAnnVol` is the overlaid cash `strategyMetrics.ann_vol`
(`build-payload.ts`, `comparatorAnnVol: strategyMetrics.ann_vol`). `overlayBasisScalars`
(`basis-metrics.ts`) maps a persisted null `volatility` to `NaN`. So any row whose engine stored a
null volatility now gets this panel. That is the `_safe_float` None for a zero-variance or
under-two-return series, and also MD-03's active-basis bundle with fewer than two non-zero days.
This is a narrow set of rows, but the result looks like a real chart.

**The comparator side is only half closed.** The new comment says "no curve scaled by an invented
factor". However, `vmScale` still falls back to `1` whenever `benchSummary` is null, or when
`benchSummary.ann_vol` is not `> 0`. Both `NaN` and `0` fail that test. In that case `vmAvailable`
is `true`, the curve is the raw comparator, and the legend reads `"<short> × 1.00"`. That figure
was never measured.

This round's `compute.ts` change keeps the fallback live. A comparator with one covered day in the
bundle now has `ann_vol` NaN (it was 0), which still fails `> 0` and still yields × 1.00. A
comparator whose covered returns are all zero gives the same result.

**Hidden errors:**
- A strategy with a persisted null volatility.
- An active-basis bundle with fewer than two non-zero days.
- A comparator with fewer than two covered returns.
- A flat comparator.

All four render as a plausible chart with no visible failure.

**Recommendation.**
1. Close both sides with one predicate: `vmAvailable = Number.isFinite(stratAnnVol) &&
   benchSummary != null && Number.isFinite(benchSummary.ann_vol) && benchSummary.ann_vol > 0`.
   Drop the `: 1` fallback, because it can then never be read.
2. In `PerformanceCharts`, do one of two things when the active block's `volMatched` is null:
   - filter out the `volMatched` panel, which extends the existing `cmpKey === "none"` rule and
     its stated reason; or
   - render a one-line reason on the panel, for example "No volatility match: the strategy or
     the comparator has no measurable volatility over this record".

Either way, a test should pin the panel's absence or its reason.

```ts
const benchVol = benchSummary?.ann_vol;
const vmAvailable =
  Number.isFinite(stratAnnVol) && benchVol != null && Number.isFinite(benchVol) && benchVol > 0;
const vmScale = vmAvailable ? stratAnnVol / (benchVol as number) : NaN;
const volMatched = vmAvailable ? scatterCovered(benchReturns, cumEq(coveredReturns.map(r => r * vmScale))) : null;
// ...
volMatchedLabel: vmAvailable ? `${short} × ${vmScale.toFixed(2)}` : null,
```

### MEDIUM-2: a `conventions` echo that is present but not an object is still treated as "no row" without any log. The build is cached on the config tier.

**Location:** `src/lib/factsheet/composite-read-path.ts`, `readCashConventions`. This is the
`failed: false` return that maps a non-object `conventions` to `null`.

**What happens.** HIGH-1's fix makes a failed read distinguishable from an absent row, and that
part is sound. Now take a read that succeeds but returns `conventions` as a string, a number or an
array, which would be an engine-writer or a migration defect. It still returns `{ conventions:
null, failed: false }`, which is the same answer as a row with no echo. No log and no capture
follow. `conventionsDegraded` stays false, so `unstable_cache` stores that build for the full TTL.

This is the outcome HIGH-1 exists to prevent. The build runs on the config tier, which the frozen
echo is there to override, so the curve can be drawn on a method the stored headline was not
computed under. Here the bad build is also cached. `resolveMetricsConventions` does
`console.warn` on a malformed field inside an object echo, but `console.*` does not reach Sentry
in this repo, as `fetch-and-build-payload.ts` says. A malformed echo as a whole gets no signal at
all.

**Hidden errors:** an engine change that writes `conventions` as a JSON string, for example a
double-encoded `json.dumps`. A migration or backfill that writes an array. Any change to the
payload's shape.

**Recommendation.** Keep the two cases apart. A missing key (`undefined` or `null`) is a
legitimate older run, so it stays `failed: false`. A key that is present but not an object should
either:
- answer `failed: true` with `code: "malformed"`, so it rides the existing capture-and-bypass path; or
- be captured on its own with `reason: "conventions_malformed"`.

```ts
const raw = (data as { conventions?: unknown } | null)?.conventions;
if (raw === undefined || raw === null) return { conventions: null, failed: false };
if (typeof raw !== "object" || Array.isArray(raw)) {
  const message = `conventions is ${Array.isArray(raw) ? "array" : typeof raw}`;
  console.error("[factsheet] cash_settlement conventions malformed; resolving from the config", { strategyId, message });
  return { conventions: null, failed: true, code: "malformed", message };
}
return { conventions: raw as Record<string, unknown>, failed: false };
```

## Paths checked that are sound

- **The degraded build is kept out of the public cache (`v2/page.tsx`).** `buildFactsheetPayloadCached`
  has exactly one call site, so there is no `generateMetadata` or other caller that catches only
  `FactsheetReadError` and would let `FactsheetDegradedBuildError` escape as a 500.
  - **On a cold miss,** the throw happens before `cacheNewResult`, so nothing is stored.
  - **On a stale entry,** the background revalidation's `.catch` keeps the last good entry. This
    relies on the same Next 16.2.11 mechanism the `FactsheetReadError` comment measured.
  - **The other callers are uncached.** The owner lane, the discovery detail page and the share
    page all call `fetchAndBuildPayloadWithReason` or `fetchAndBuildPayload` directly (the share
    page is `force-dynamic`), so `conventionsDegraded` being ignored there caches nothing.
- **Sentry capture of the failed read.** It is captured once, at the resolve stage's success exit,
  for `caller === "build"` only. That covers the composite arm (`conventionsReadFailure` is
  assigned only after `readCompositeFactsheet` returns non-null) and the single-key arm. A build
  that fails later sends its own `read_error` instead. The tags carry `code` (`"threw"` for a
  thrown chain, `error.code || "none"` otherwise) and `strategy_id`.
- **The range-gesture hold cannot stick on any normal path.**
  - **Brush:** `MasterBrush` takes the hold unconditionally on pointer down. Every pointer-down
    branch sets `dragRef`, and pointer up, cancel and lost capture all go through `onPointerUp`,
    which releases the hold while `dragRef` is set. An unmount mid-drag is released by the effect.
  - **Chart:** `TimeSeriesChart` takes the hold only on pan and x-pull and releases it on pointer
    up, cancel, lost capture and unmount.
  - **Wheel:** a wheel burst re-arms one settle timer, and `releaseRange` always clears it.
  - **Wheel during a drag:** a wheel tick during a pan or x-pull leaves the release to the drag.
    During a y-pull, the y-pull's pointer up releases it.
  - **Stable identities:** `begin` and `end` keep one identity for the provider's life, so a
    consumer's cleanup effect never fires because a gesture began.
  - **Two components:** when two components overlap, the worst outcome is an early release, which
    costs only performance. No combination leaves `held` set with no owner.
- **The window caveat (`windowCoverageCaveat`).** It uses the same gates as the full-history
  caveat. A `null` `headlineCoversFrom` puts the caveat on every range rather than none, and an
  unparseable date (`"—"`) takes the same undated branch. `scope.start` comes from the same held
  range as the figures, so the caveat and the numbers cannot describe different ranges. The rail
  and the strip both switch on `selected`. The Cumulative Return Metrics panel does not follow the
  window, and it keeps the stored-headline caveat.
- **`compute.ts` `annVol = NaN` below two basis returns.** Every rendered consumer formats through
  `pct`, so the value shows as "—". A JSON cache round-trip turns it into `null`, which every
  consumer here tests with `Number.isFinite` or with formatters that render "—". The comparator
  case is MEDIUM-1.
- **`build-payload.ts` rolling vol and Sortino on `dense`.** On a single-key row this is the
  identity positions over `stratRet`, which equals the old `activeBasis` arm. On a composite it is
  the zero-filled calendar series mapped back through `positions`. Nothing is caught or defaulted.

## Considered, below the bar

These are not counted above.

- **No on-page signal on a degraded build.** A degraded public build renders with nothing on the
  page saying the conventions read failed. D-30 decides that a blip must not blank the factsheet.
  The operator signal is the Sentry event. The curve differs only if the config was edited after
  the run.
- **Repeated uncached builds during an outage.** While the conventions read is failing, every
  public request for an affected id runs a full uncached build and sends a Sentry event. That is
  loud, not silent, but it adds load during an incident.
- **`MasterBrush` can release another component's hold.** Its unmount effect calls `end()` even
  when the brush did not take the hold, which `TimeSeriesChart` deliberately avoids with
  `holdingRef`. The effect is an early release, never a stuck hold.
