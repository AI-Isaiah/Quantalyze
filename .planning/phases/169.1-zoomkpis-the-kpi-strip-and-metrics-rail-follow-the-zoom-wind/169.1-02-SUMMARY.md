selected slice by the shared `deriveSeriesBundle`, labelled "Full history: ..." or

## What was built

- **basis-context.tsx.** `rederiveArgs(view)` is the one argument builder the leverage arm and
  the window arm both pass to `deriveSeriesBundle`. The leverage arm's behaviour is unchanged,
  and every existing leverage test passes unedited. `resolveRangeScope` decides full vs
  selected. A full scope names the view's own first and last dates (W3), and a selected scope
  names the clamped indices' dates. `WINDOW_FOLLOW_FIELDS` is the exported follow-list.
  `windowView` re-derives only those fields; its `strategyMetrics` has no overlay and no
  re-pin. A comparator block whose base summary and joint are both null stays the base block
  by reference. `windowView` withholds on fewer than 2 observations (`short-slice`) and on a
  missing `periodsPerYear` (`no-annualization-basis`), replacing every follow-list field (W1).
  `useWindowedView` reads the range through `useDeferredValue` and returns the base view by
  reference at full history. Otherwise it shares one derive per window across consumers.
  The non-comment count of `deriveSeriesBundle(` is 2.
- **KpiStrip.** While a range is selected it shows:
  - the seven scalars from the windowed view;
  - alpha / IR from the windowed joint;
  - the paired-floor reason with the noun "range";
  - the short-track count from the window.

  The chain-broken coverage caveat is hidden (D-78). A data eyebrow sits above the strip. On
  a withheld `no-annualization-basis` window, one sentence states that the figures need an
  annualization basis, and a reset shows them.
- **MetricsColumn.** These figures read the windowed view: Compound Performance, Main
  Metrics (both columns), Win Rate / Profit Factor, Max Drawdown, Best / Worst, Worst 10,
  Extended Metrics and §IV. §IV uses the noun "range" inside a window. While a range is
  selected:
  - the month / YTD / 3M / 6M / 1Y rows are omitted, selected by `data-window-key` /
    compute() field, never by label;
  - one sentence explains why;
  - Cumulative Return Metrics is omitted;
  - Rolling Metrics summarises the base arrays over the window's indices;
  - EOY Returns, Calmar by Year and §III Style carry a "Full history" note.

  The rail eyebrow sits between the Strategy Thesis and §I.
- **AnalyticalPanels.** `BootstrapCIPanel` reads the windowed view. `CalmarByYearPanel` keeps
  the base view and shows the scope note.
- **joint.ts.** `pairedFloorReason` noun union is `"book" | "record" | "range"`. "range" prints
  "the selected range has N.". The record and book tests were not edited.

## Known limits

- **Compounding method (D-27 as amended 2026-09-26).** The window arm passes
  `isArithmetic: false` through `rederiveArgs`, as the leverage arm does. So on a composite
  persisted with the arithmetic method, a window's cumulative return and CAGR are geometric.
  Plan 169.1-03 carries the compounding method (founder decision "Fix it in plan 14
  (Recommended)"; 14b closes it), and it edits `rederiveArgs`.
- **The Scenario mount shows window figures (D-82).** Evidence: the Scenario test name and
  commit above.
- The window derive runs the full `deriveSeriesBundle` (bootstrap, correlations, stress
  windows) for each new window. Only the follow-list fields are used. The deferred range and
  the one-entry cache bound it to one derive per settled window across consumers (T-169-45).
  A narrower derive would be a new function, which D-27 rules out.
