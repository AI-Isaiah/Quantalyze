## Gate order — OLD vs NEW

| | OLD | NEW |
|---|---|---|
| 1 | pydantic body validation → **422** | **INTERNAL_API_TOKEN bearer → 500 (secret unset) / 401 (absent or wrong)** |
| 2 | slowapi `@limiter.limit` → **429** | pydantic body validation → 422 |
| 3 | `_verify_internal_token` → **403** | slowapi (two stacked limits) → 429 |
| 4 | — | `_verify_internal_token` → 403 *(defence-in-depth; unreachable through the full app)* |

Middleware is the only layer earlier than both: a decorator cannot get ahead of
pydantic, which resolves before any handler decorator (RESEARCH G-4).

The budget-burn oracle is limiter **storage**, not the next call's status.

## Which envelope, and why

| Site | Mechanism | Shape | Why |
|---|---|---|---|
| middleware 500 `INTERNAL_TOKEN_UNCONFIGURED` | `service_error_response` | `body.detail.{code,dependency,retryable,detail}` | SERVICE-PERMANENT per STATUS_CONTRACT R-1; the direct sibling of `main.py`'s S-23 `SERVICE_KEY_UNCONFIGURED` arm, six lines below, same file, same middleware |
| middleware 401 `UNAUTHENTICATED` | `service_error_response` | same | CALLER 4xx; `_validate` accepts it with `dependency=None, retryable=False`. Uses the middleware envelope, not the route's, because it *is* a middleware site — a caller must not have to know which layer refused it |
| route 4xx (403, 422 scope rejections) | `_envelope_error` | top-level DESIGN-05 | **Unchanged.** Plan 05's finding stands: `/process-key` is S-22 and its sibling route-level refusals all use `_envelope_error`. Not touched here |
| slowapi 429 | slowapi default `{"error": ...}` | **unchanged** | PYAPI-08 (plan 08) owns the 429 envelope + `Retry-After`. Deliberately not pre-empted |

Both middleware refusals **RETURN**, never raise: this is a
`BaseHTTPMiddleware` above the `ExceptionMiddleware`, so a raise renders a
bodyless `500 text/plain` **and** re-raises into Sentry (QUANTALYZE-4). Guarded
permanently by an `ast.Raise` assertion over **both** `verify_service_key` and
`_gate_process_key` — a substring grep would be permanently red, because both
functions' comments contain the word "raise" while documenting this exact trap.

`analytics-service/docs/STATUS_CONTRACT.md` records both new sites and states
that 401-at-middleware supersedes the handler's 403-first behaviour.

## Limiter key design

| Condition | Bucket (LITERAL) | Limit |
|---|---|---|
| valid claim, payload ≠ `public` | `process_key:t:<user_id>` | 100/hour |
| valid claim, payload == `public` | `process_key:anon` | **30/hour** |
| absent / malformed / bad MAC / expired | `process_key:unverified:<sha256(cred)[:16]>` + WARN | 100/hour |
| stacked ceiling, all traffic | `process_key:ceiling:<sha256(cred)[:16]>` | 500/hour |

`X-Tenant-Claim` = `<payload>.<exp>.<hex-hmac-sha256>`, MAC over
`"<payload>.<exp>"`, key = `INTERNAL_API_TOKEN`, `hmac.compare_digest`, TTL
300s. **No new secret, no new library** (G-15 / T-140.1-SC): the HMAC key is the
secret this endpoint already authenticates with, so the claim adds zero new
trust surface — an attacker who holds it already has full `/process-key` auth.

**Sizing rationale.** The anon bucket sits *below* a tenant's because anonymous
traffic is the untrusted half and has the least recourse (an anonymous visitor
cannot be contacted, account-limited, or billed), and because Vercel's teaser
cap of 600/hour per IP is the vector that made C-09 cheap. The 500/hour ceiling
is one platform-wide bucket by construction post-PYAPI-04 (every admitted caller
presents the same token) — 5× what the whole platform shared before this phase,
and the backstop for N tenants each staying inside their own window while
collectively burying the service. All three are founder-retunable literals.

**No new IP-derived key** was introduced. `get_remote_address` is untouched, and
`test_process_key_limit_key_func_is_not_get_remote_address` pins that both new
key functions are distinct objects from it and from each other.

## Forged-claim proof

Four tests, each asserting the attacker does **not** reach a tenant bucket:

| Test | Attack | Asserted landing |
|---|---|---|
| `test_key_func_forged_claim_falls_to_unverified` | one MAC hex char flipped, same payload/exp | `process_key:unverified:…`; explicitly **not** `process_key:t:victim`, **not** `process_key:anon` |
| `test_key_func_garbage_secret_cannot_forge_tenant_bucket` | structurally perfect claim minted with the WRONG secret | `process_key:unverified:…` |
| `test_key_func_expired_claim_falls_to_unverified` | valid MAC, `exp` in the past (replayed/captured claim) | `process_key:unverified:…` |
| `test_key_func_ignores_unsigned_x_user_id` | `X-User-Id: victim` alone, and `X-User-Id: victim` *over* a valid `tenant-a` claim | never `t:victim`; the claim wins |

The secret is never logged, never echoed, and never on the wire: it is the HMAC
**key**, and `expect(claim).not.toContain("internal-test-token")` pins that in
the vitest. The WARN log carries `claim_present: bool` — presence, never
content — so an operator can distinguish "a caller stopped minting"
(rotation/deploy) from "a caller sent something invalid" (expired/tampered).

| `TENANT_CLAIM_HEADER`, `ANON_PAYLOAD` | `Final[str]` | the wire constants |

Three things 07 must know:

1. **`functools.partial` is safe.** slowapi decides whether to pass the request
   by checking for a parameter literally named `request` on the key function
   (`slowapi/extension.py` `__evaluate_limits`), and `partial` preserves it.
   Verified by reading the installed source, not assumed.
2. **`_credential` already falls back to `X-Service-Key`.** The nine PYAPI-03
   routes authenticate with `X-Service-Key`, not a bearer, so they hash the
   right credential without a second change. With no tenant claim on those
   routes they land in `<scope>:unverified:<hash>` — one honestly-named
   platform bucket, which is what they effectively have today anyway
   (G-10/G-11: behind Railway's edge `get_remote_address` collapses to the
   proxy IP), minus the per-client disguise.
3. **Per-bucket sizing needs slowapi's callable limit provider.** A provider
   declaring a parameter named `key` receives the key function's output
   (`slowapi/wrappers.py` `LimitGroup.__iter__`). `exempt_when()` takes **no**
   arguments and cannot see the request; a second decorator whose key function
   returns `""` makes slowapi log an ERROR on every non-matching request.
   `routers/process_key.py:_process_key_limit_for` is the working shape.
