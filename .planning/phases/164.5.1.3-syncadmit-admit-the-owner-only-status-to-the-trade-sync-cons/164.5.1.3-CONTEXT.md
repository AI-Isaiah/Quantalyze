<decisions>
## Implementation Decisions

### Area 1 - The widening verdict

- **Q1: Is the constant's gap real at HEAD?** YES, re-measured this session.
  `ALLOWED_STRATEGY_STATUSES = {"draft", "pending_review", "published"}` has ONE declaration and
  ONE functional reader (the other three occurrences are comments). Cite BY SYMBOL.
- **Q2: Is `private` a real status?** YES. Migration `20260716130000_strategies_status_private.sql`
  widened the CHECK to `('draft','pending_review','published','archived','private')`. `private`
  is omitted from the allowlist BY ABSENCE, which is why the literal does not appear in
  `cron.py` at all.
- **Q3: What is the measured harm?** 5 of 5 key-bearing `private` strategies sit on keys with NO
  in-set sibling, so those keys are never synced and their trades are never stored. The sibling
  hypothesis was falsified 5/5. A 6th `private` strategy carries no key and is structurally
  unsyncable by ANY widening — ⛔ it must not be counted as harm the constant causes.
- **Q4: Lean?** TOWARD WIDENING, not yet committed. It closes a measured, user-facing data gap
  and structurally ends the held-cursor stall. The commitment is gated on Area 2.

### Area 2 - Ordering versus Phase 164.5.1.4 SYNCCURSOR (THE CENTRAL RISK)

- **Q1: What exactly is the exposure?** The resume cursor is per-KEY while stores are
  per-STRATEGY. On a key backing N strategies where one `sync_trades` succeeds and another
  raises, `synced_count > 0` holds, the cursor advances, and the failed strategy's window is
  permanently stranded. Pre-existing and deliberate, pinned by
  `test_C0198_partial_success_does_advance_last_sync_at`.
- **Q2: ⭐ Does widening actually make it reachable?** ONLY IF a key ends up backing N >= 2
  ADMITTED strategies. Verified in code this session: `synced_count = sum(per_strategy_stored
  .values())` with a single cursor write per key, so with N == 1 the tick either stores
  (cursor advances, nothing stranded) or raises (`synced_count == 0`, trades present, so
  `should_advance_cursor` is False and the cursor HOLDS for retry). **N == 1 is safe.**
- **Q3: ⛔ Is N known?** NO — and this is the one decision-critical measurement the prior
  production read does NOT contain. `164.5.1.2-PROD-SESSION.md` counted STRATEGIES
  (`private_strategies_with_key = 5`, `without_in_set_sibling = 5`), never DISTINCT KEYS. If the
  five sit on five distinct keys, every key gets N == 1 and the strand path stays UNREACHABLE.
  If any key backs two or more, that key goes to N >= 2 and the path goes live.
- **Q4: Decision.** ⛔ The ordering verdict is CONDITIONAL ON ONE READ and must not be guessed:
  - **max(strategies per key after widening) == 1** -> SYNCADMIT may ship BEFORE 164.5.1.4. The
    widening cannot reach the strand path, and this must be pinned by a gate so a later key
    gaining a second private strategy cannot silently re-open it.
  - **max >= 2** -> 164.5.1.4 SYNCCURSOR lands FIRST, or this phase carries its own containment.
    ⚠️ 164.5.1.4 is a ROADMAP booking only (directory holds just `.gitkeep`, plans are `TBD`), so
    "lands first" means real unplanned work, and that cost belongs in the decision.
  ⛔ Shipping the widening while asserting the strand path is unreachable, WITHOUT this read,
  would be exactly the unverified-claim failure this repo keeps booking.

### Area 3 - Scope of the widening

- **Q1: Which statuses?** `private` ONLY.
- **Q2: What about `archived`?** ⛔ NOT admitted. Surfaced by this session's measurement: the
  allowlist omits TWO statuses, not one. `archived` is correctly omitted — an archived strategy
  is retired and must not resume syncing. Recording this so a later reader does not "complete"
  the allowlist by symmetry.
- **Q3: Shape of the change?** A one-set-member change at the single declaration. No new gate
  shape, no new constant, no second reader.
- **Q4: Anything else move?** No. The single functional reader keeps its existing predicate.

### Area 4 - Gate design (anti-vacuity BLOCKS here: data-integrity AND user-facing)

- **Q1: What must the gate pin?** That a `private` strategy's trades ARE stored after the
  widening — the user-facing behaviour — not merely that the set contains a new string.
- **Q2: Calibration?** neuter -> observe RED -> restore, byte-identity verified with `cmp`, and
  the OBSERVED failure text recorded. ⛔ A set-membership assertion over the constant is
  satisfied by the literal and is NOT sufficient on its own.
- **Q3: Regression surface?** 164.5.1.2's D-03 gate and all three
  `TestC0198CursorOnlyAdvancesWhenStored` members must pass UNCHANGED.
- **Q4: If Area 2 resolves to N == 1?** Add a gate pinning that assumption, so a future key
  gaining a second `private` strategy fails loudly rather than silently reaching the strand path.
