    1. WIDEN the trigger. `strategy_shares_enforce_monotonic_generation` is `BEFORE UPDATE` today.
       Make it `BEFORE INSERT OR UPDATE` and branch on `TG_OP`:

       - `TG_OP = 'INSERT'` → **force** `NEW.generation := 1`. Not "reject if wrong" — force it, so
         no caller can express a starting counter. This is R3's closure and it holds for
         `service_role` and any BYPASSRLS role too, which the column grant alone does not. ⚠️ Keep
         the existing `nonce`, `strategy_id` and provenance pins on their current UPDATE-only path;
         forcing `generation` on INSERT must not disturb the DEFAULT-populated `nonce`, which the
         mint RPC reads back through RETURNING.
       - `TG_OP = 'UPDATE'` → keep all five existing rules, and ADD rule (6):

             IF NEW.generation > OLD.generation + 1 THEN RAISE EXCEPTION …

         Combined with the existing monotonic rule this pins the counter to *stay* or *advance by
         exactly one*. Nothing else is expressible.

    2. WHY THAT BOUND CLOSES THE ART. 17 ABORT — record this reasoning in the migration prose,
       because the next reader will ask why there is no exception handler:

       Overflow becomes **unreachable by construction**. `generation` starts at 1, moves only by
       +1, and every +1 is a separate committed statement — so reaching `2^63-1` requires ~9.2e18
       revokes. `sanitize_user`'s B1 arm therefore cannot raise `22003`, and it needs no handler.

       ⛔ REJECTED ALTERNATIVE, and say so in the file: wrapping the B1 arm in
       `EXCEPTION WHEN numeric_value_out_of_range THEN … CONTINUE`. That converts a loud, complete
       failure into a **silent, incomplete erasure** — the subject's links survive and the caller is
       told the erasure succeeded. Aborting is strictly better than that. The fix belongs at the
       root, which is this trigger.

    3. Update the table/trigger COMMENTs. The table comment currently warns that `generation` is
       "monotonic by ENFORCEMENT, not by construction … a raw PATCH could rewind it" and that
       `BIGINT` is headroom, not the N1 fix. Both sentences are now stale — the rewind was already
       closed by rule 1, and the ceiling-jump is closed here. Rewrite them to state what is true
       after this change rather than deleting them.

    4. Regenerate `supabase/schema/functions/strategy_shares_enforce_monotonic_generation.sql`
       (`npx tsx scripts/dump-sql-functions.ts`) and leave it check-clean.
