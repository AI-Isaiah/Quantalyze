## The load-bearing constraints (full reasoning in the parent)

- ⛔ **FLAG-3 is ONE indivisible task.** Deleting `MetadataStep.tsx:491`'s `disabled` without
  widening the `.trim()`-only `handleSubmit` guard at `:222-233` lets a 2-character description
  POST — re-shipping the exact defect this phase exists to delete.
- ⛔ **The red state must be STRUCTURALLY impossible to leave un-wired.** The border derives from
  `aria-[invalid=true]`, never a hand-toggled class. `Field.tsx:72` is the only writer of
  `aria-invalid`; three sites already derive from it. `AllocateDialog.tsx:354-357` is the one
  JS-ternary holdout — convert it. ⚠️ It already carries the CORRECT focus ring that
  `MetadataStep.tsx:334` lacks, so the two files swap fixes in opposite directions.
- ⛔ **No disabled button for a validation reason.** A blocked control must be clickable and
  explain itself — the founder's standing rule (`+Allocation` overlay precedent). Submit refuses
  via the predicate, it does not grey out.
- ⛔ **Focus the FIRST invalid control on a refused submit**, opening a collapsed `<details>` first
  if the field is inside one.
- ⚠️ **D-21: ASCII `Validating...`**, never `Validating…`. One spelling everywhere — picked, not
  blended (Rule 7).
- ⚠️ **The pinned MT5 chip is a `<span>`, not a disabled `<button>`** (D-15), and MT5 must be
  **preselected** from `detectedExchange`. Widening the chip set without the preselect is
  explicitly forbidden.
- ⚠️ **`prefers-reduced-motion`** must suppress any animation you add — `globals.css:182` already
  handles `.animate-pulse`; prefer that utility over a bespoke animation.
