# Phase 153.2 Plan 02: The form refuses at the field — the whole class Summary

**Every rule this form can evaluate now refuses at its own field, the money rule is the
server's own imported predicate rather than a re-typed bound, and a refused submit states
how many fields are wrong, names the first, and puts the cursor in it — opening the
collapsed disclosure first when that field is hiding inside it.**

## Accomplishments

### Task 1 — three more fields refuse at themselves (commit `e8d978b1`)

**One map, not three chains.** `fieldErrors: Record<MetadataFieldId, WizardErrorCode | null>`
replaces 153.2-01's single description branch. The inline message, the submit predicate,
the focus target and (in Task 2) the summary line all read that one derivation, so the
message a user sees and the reason their submit was refused are the same fact by
construction. A fifth field is one entry plus one `FIELD_ORDER` slot.

**The money rule is imported, never restated.** `validateDollarField` calls `isValidDollar`
from `@/lib/dollar-validation` — literally the function `finalize-wizard/route.ts:504,516`
applies at its `aum` and `max_capacity` arms. It mirrors **both halves** of the route's
condition (`!isOmitted(x) && !isValidDollar(x)`), so a blank field stays valid; a mirror
that checked only the predicate would refuse every blank AUM client-side while the server
accepted it. It also performs the same string→number step `SubmitStep.tsx:171-172` performs
(`value ? Number(value) : null`), so the value the guard judges is the value the wire
carries. `csv-finalize/route.ts:396-415` applies the same `Number(raw)` and the same
bounds, so the CSV branch agrees without a second mirror.

**Three controls moved off the primitives.** `Input` and `Select` colour their border from
a JS `error &&` expression and never write `aria-invalid` — the FLAG-1 defect shape, where
a control can be red while assistive technology cannot tell. Category, AUM and max capacity
now wrap a bare control in `Field`, whose `error` prop is the only writer of the ARIA state,
and the border derives from it in CSS. Each also picked up the clip-proof, full-opacity
inset focus ring (the primitives' `focus:ring-accent/20` measures ≈1.3:1 against
`bg-surface`, under WCAG 1.4.11's 3:1 floor). ⛔ The primitives themselves were **not**
changed — the codename select, the asset-class select and the leverage-range input still
use them, and rewriting a shared primitive is a blast radius this plan did not price.

**The category demand is withheld when it cannot be met.** With no options in the select,
"Choose a category." is an instruction the user cannot follow, so the sentence is suppressed
and the existing honest block (`metadata-categories-empty`) or the load-failure line states
the real cause. ⛔ The **refusal** is untouched — the code stays in the map, so a draft with
no category still cannot reach `onComplete` (ISSUE-010 cannot reopen). The suppression is
derived from the options actually rendered rather than from the two states that produce
them, which covers the third such state (the fetch has not settled) by construction.

**Two fields deliberately have no mirror, and say so.** The codename is a `<select>` over
`STRATEGY_NAMES`, so the server's `STRATEGY_NAME_SET` arm is unreachable from this form; the
capital-ownership radio group is defaulted and cannot be cleared. Both carry a comment
stating why, so a later reader does not read the absence as an oversight — and the comment
records that the server arms still matter (153.2-05 routes them for the shape-drift case).

### Task 2 — the refusal names the first problem and goes there (commit `10432c8d`)

- **DOM order is declared, not inferred.** `FIELD_ORDER` is an explicit array beside the
  map with a comment saying it mirrors the render order. An implicit `Object.keys` order
  couples the behaviour to how the map happens to be typed; a JSX reorder would then change
  which control the cursor lands in with every test still green. A new row reads the four
  controls out of the live DOM and asserts they arrive in that order.
- **The disclosure opens before the focus.** AUM and max capacity live inside the collapsed
  "More details (optional)" `<details>`. `handleSubmit` tests **containment**
  (`detailsRef.current?.contains(control)`) rather than consulting a hard-coded list of
  which fields are in there, sets `.open = true`, then focuses and
  `scrollIntoView({ block: "center" })`. The element is driven imperatively because it stays
  a bare native `<details>` with no `open` prop for React to own.
- **The summary is visible first, announced second.** One `const` renders as a
  `text-caption text-negative` line above the submit row and is handed verbatim to
  `<LiveRegion assertive>`. This resolves FLAG-6 in the direction `LiveRegion`'s own
  contract requires (Shared Pattern G): the announcement re-states copy the surface shows,
  it does not author copy only AT receives. The label comes from `FIELD_LABELS`, the same
  map the `Field`s are given, so the sentence cannot name a field the form does not show
  (T-153.2-05). ⛔ The visible line is not `role="alert"`, and no terminal error panel
  renders for a field problem.
- **The submit button stays enabled throughout**, and `onComplete` runs only when the map
  is empty.

## Deviations from Plan

### Auto-fixed / recorded

**1. [Rule 2 — Copy correctness] The summary sentence agrees with its number**

- **Found during:** Task 2, writing the sentence.
- **Issue:** The UI contract's template is `{n} fields need attention. The first is {Label}.`
  which renders **"1 fields need attention"** in the single-field case — and the
  single-field case is the *common* one, since most refused submits are one missing
  description.
- **Fix:** The count and the second sentence are kept verbatim; only the noun and verb
  agree with the number (`1 field needs attention. The first is Description.`). DESIGN.md
  governs voice and is authoritative over the spec where they conflict; a grammatical error
  in the most frequently rendered copy on the surface is not something the contract intended
  to mandate. The deviation is recorded in the source docblock and pinned by a literal test
  oracle in both the singular and plural arms, so a silent re-wording in either direction
  reds.
- **Files modified:** `MetadataStep.tsx`, `MetadataStep.test.tsx`
- **Commit:** `10432c8d`

**2. [Rule 2 — Honesty] The category demand is suppressed on the LOAD-FAILURE path too**

- **Found during:** Task 1.
- **Issue:** The plan named only the empty-catalogue state. But when the
  `discovery_categories` query errors, `categories` is also empty and the user equally
  cannot choose one — they would read "Could not load strategy categories." and
  "Choose a category." together, the second of which they cannot act on. The un-settled
  initial fetch is a third such state.
- **Fix:** The suppression is derived from `categories.length === 0` — "there are no options
  to choose from" — which covers all three states by construction rather than by enumerating
  two of them. The refusal is unaffected in every case.
- **Files modified:** `MetadataStep.tsx`
- **Commit:** `e8d978b1`

**3. [Rule 3 — Blocking] The `grep -c 'aria-[invalid=true]:border-negative' >= 4` gate is
answered by a rendered-DOM row, not by four spellings**

- **Found during:** Task 1 verification.
- **Issue:** The three converted controls share an identical class run, so hoisting it into
  one `VALIDATED_CONTROL_CLASS` constant (the "one spelling cannot drift" discipline this
  phase preaches for constants and predicates) leaves the source grep at **3** — two real
  class strings plus one pre-existing comment from 153.2-01 — not the 4 the plan's gate
  counts. Inlining three copies to satisfy the grep would have re-created exactly the drift
  surface the gate exists to prevent, and the gate counts **spellings**, not fields: a field
  that quietly reverted to a JS-coloured border while a fourth spelling survived elsewhere
  would still pass it.
- **Fix:** Kept the shared constant and added
  `[FLAG-1] ALL FOUR validated controls derive their invalid border from the ARIA state` —
  a row that reads all four controls out of the rendered DOM and asserts each carries the
  derivation token, carries the inset ring, and does **not** carry `ring-accent/20`. That
  counts fields, which is what the gate is for. The two intent-level gates the plan states
  alongside it both pass literally: no validated field uses a primitive's `error` prop, and
  `isValidDollar` is imported from `@/lib/dollar-validation`.
- **Files modified:** `MetadataStep.tsx`, `MetadataStep.test.tsx`
- **Commit:** `e8d978b1`

**4. [Rule 3 — Blocking] The `ErrorEnvelope` acceptance grep matched the plan's own required
