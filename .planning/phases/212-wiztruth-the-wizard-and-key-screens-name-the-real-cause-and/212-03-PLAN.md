<objective>
SC5, per the CONTEXT "Decided autonomously / Orphan refusal" and "Post-research, SC5 / Scope of the
early refusal" decisions: in the MT5 credential arm of `create-with-key` (the only arm that knows
the venue identity before validation), refuse an orphaned key with the existing `KEY_ORPHANED` 409
before spending the up-to-120 s `validateKey` call. This reverses the documented Phase 161-05 order
("the credentials speak first"); the tests pinning that order are inverted, as ROADMAP SC5
requires (CONTEXT, RESEARCH and PATTERNS say "two"; the measured count below governs over all three). Measured 2026-11-14 by re-grepping `route.test.ts` for every MT5 orphan shape (key row
found, both `strategies` reads empty, no `strategy_keys` row): THREE cases pin the old order and
are inverted, and a fourth (the wizard-session NEGATIVE CONTROL) is re-fixtured, not inverted.

Arms, named (UI-SPEC SC5): identity known before validation = `create-with-key` credential arm with
`exchange === "mt5"` only. Identity known only after validation = ccxt venues (id from the validator
response), sFOX (no id), any 23505 race: unchanged. No validation at all = the `reuse_api_key_id`
arm (`handleReuseExistingKey`), where an orphan is the case it resumes: unchanged.
`composite/add-key` mints no `KEY_ORPHANED`: not an SC5 site. `held` has the same latency class and
is out of scope (recorded, not changed).

Purpose: a user whose key is orphaned hears the true refusal at once instead of after a long wait.
Output: one helper, one early arm, corrected comments, inverted and new tests.

Spec-less probe fallback: skipped. The phase has no requirement IDs and no SPEC.md; this is a
recorded choice, and the requirement set is ROADMAP Phase 212 SC1-SC8.
