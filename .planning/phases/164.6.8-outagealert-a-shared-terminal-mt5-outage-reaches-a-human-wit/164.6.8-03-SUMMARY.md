# Phase 164.6.8 Plan 03: Prober incident issues Summary

One GitHub issue per prober incident: a defect run opens a new issue when none is open, comments on the open one otherwise, and the first clean full run comments "Recovered" and closes it, so the next defect opens a fresh issue (the one event GitHub emails).

## Deviations from Plan

**1. [Rule 1 - consistency] Step `if:` keeps a status clause.** The plan's guard drops the status clause. Doing so would break three existing wiring assertions ("keys on the MEASURED defect count", two calibration mutants), and the plan forbids weakening them. The guard is `!cancelled() && inputs.arm == '' && steps.probe.outcome != 'skipped' && steps.probe.outputs.status != ''`: it runs on clean and dirty runs and refuses a probe that published no status (never a clean reading). The two calibration tests' mutation target string was updated to the new guard; no assertion was relaxed.

**2. Body footer wording.** The open-body footer said "subsequent failures comment here until this issue is closed" (label dedup). It now says the first clean full run closes the issue. Other text is unchanged in wording.

**3. Branch namespace.** The worktree branch is `wt/164.6.8-p03`, outside the `agent-*` namespace the commit assertion lists. Committed on the orchestrator-named branch; it is not a protected branch.
