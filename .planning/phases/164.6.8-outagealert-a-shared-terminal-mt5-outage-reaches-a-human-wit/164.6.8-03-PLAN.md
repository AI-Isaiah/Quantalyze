Replace the forever-open, label-deduplicated prober issue (#773, title frozen at 2026-09-10, 60 comments) with one
GitHub issue per incident, per D-07. An incident starts at the first scheduled full run with defects and ends at
the first scheduled full run with none, which closes the issue. The next defect therefore opens a fresh issue,
and a fresh issue is the one GitHub event that emails a human.

only the constant `prod-prober` label. `src/__tests__/prod-prober-wiring.test.ts` gate `[164.8.3-01] AUTO-ISSUE
DEDUP` forbids selection that reads a defect kind, because a kind-keyed selection can hide a new kind behind an old
kind's issue. Incident boundaries here come from the run's clean/dirty status alone, so that gate stays green
unchanged in meaning.
