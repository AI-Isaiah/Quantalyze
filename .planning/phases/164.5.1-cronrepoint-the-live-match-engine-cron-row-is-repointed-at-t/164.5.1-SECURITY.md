## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| analytics-service → Supabase API gateway | A 60 s ceiling that answers 504 with no Postgres error code. The exception shape crossing back is what plans 02 and 05 classify | Service-role reads; no credential in the response |
| pg_cron → `POST /api/match/cron-recompute` | A fixed, parameterless hourly request. There is no channel for one tick to hand a position to the next, which is why the cursor must be server-side | Allocator ids (`profiles.id` UUIDs — non-secret identifiers) |
| founder → `system_flags.match_engine_enabled` | The manual stop control. Its READ is the surface plan 02 hardens | One boolean |
| admin UI / service role → `public.system_settings` | The grants do not distinguish operator configuration from engine bookkeeping; an admin can hand-edit the cursor row | Cursor UUID, pass-start timestamp |
| operator → PROD via browser SQL editor or CLI | UNGUARDED by automation. The `COMMENT ON DATABASE` marker is the only control | Arbitrary SQL — plan 09's surface, not Wave A's |
| `.planning/`, `docs/`, `TODOS.md` → the public internet | The repo is PUBLIC and all three trees are TRACKED | Every sentence written is world-readable |
| PROD `cron.job` → the prober process | Read-only. The command text that comes back may carry a credential and must never be echoed | Job command strings |
