# Phase 164.5.1 Plan 04: Repoint Pre-Flight Summary

**A new `preflightCronRepoint` verb in `scripts/prod-prober/run.mjs` reads PROD `cron.job`, compares it against the committed manifest with the SAME `compareManifest` the live cron-drift arm uses, and aborts non-zero WITHOUT WRITING on a mismatch — proven by a self-test scenario that hashes the fixture manifest before and after every invocation leg, not by inspection.**

## Accomplishments

- `preflightCronRepoint({ seams, manifestPath, functionsDir, log })` in `scripts/prod-prober/run.mjs`, placed immediately after `captureManifest` under its own section-header comment: reads the manifest first (refusing 3 on an absent/unparsable file), then the database marker (refusing 3 on a measureFail or empty marker, logging the marker on success), then `cron.job` (refusing 3 on a measureFail, malformed records, or a count mismatch — the SAME three refusals `captureManifest` uses), then calls `CRON_DRIFT_MOD.compareManifest` and returns 1 if it reports any defect, 0 if it reports none. Zero filesystem write calls anywhere in the body.
- `--preflight-repoint [--manifest <path>]` CLI flag in `main(argv)`, defaulting `--manifest` to `CRON_DRIFT_MOD.MANIFEST_PATH` (a deliberate asymmetry from `--capture-manifest --out`, documented inline: this verb only ever reads the oracle and never rewrites it). Mutually exclusive with `--capture-manifest` — both together refuse with 3 rather than guessing which the operator meant, verified to create no file.
- One new `--self-test` scenario driving all five behaviours the plan specified: a MATCH leg (manifest.json + prod-ok.json → 0, marker logged), a MISMATCH leg (prod-schedule-moved.json → 1, `match_engine_cron` named, no command text printed even on the abort path), a marker-failure leg (→ 3, "Nothing was written.", proven via the seam tally that `cron.job` was never read), and a source-scan leg proving zero write-call names in the function's own region. `SELF_TEST_SCENARIOS` moved 80 → 81 in `run.mjs`, and the hand-typed `expect(SELF_TEST_SCENARIOS).toBe(81)` mirror pin moved with it in `src/__tests__/prod-prober-wiring.test.ts`, in the same task.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The self-test's own source-scan anchor self-matched its own scenario text, twice**
- **Found during:** Task 2 (running `--self-test` after writing the new scenario)
- **Issue:** The anti-vacuity source-scan assertion built its search anchor as the literal string `"export async function preflightCronRepoint"` (and, on the first fix attempt, `"export async function captureManifest"`) and searched for it via `indexOf` over the whole file. Because the scenario itself lives in `selfTest()`, which appears EARLIER in the file than the real `preflightCronRepoint`/`captureManifest` declarations, and because the scenario's own source text contains these same words (calling the functions by name, and building the search anchor as a quoted literal), `indexOf` found the scenario's OWN text first on both attempts — not the real declaration — so the computed "region" was empty or wrong, and the scan reported false positives (`writeFileSync`/`appendFileSync`/`mkdirSync` "found" inside the scenario's own `writeCallNames` array literal).
- **Fix:** Anchored the region on the PRECEDING export (`captureManifest`, structurally guaranteed by the plan's own "placed immediately after captureManifest" instruction), and built the search anchor via `["export async function ", "captureManifest", "({"].join("")` so the full contiguous phrase never appears as a literal substring anywhere in the scenario's own source bytes — the only place it can match is the real declaration. Also removed the literal write-call names from a plain-English comment inside `preflightCronRepoint`'s own body (originally mirroring the plan's own action-text phrasing), replacing it with a description that does not spell them, since that comment IS inside the scanned region.
- **Files modified:** `scripts/prod-prober/run.mjs`
- **Verification:** `node scripts/prod-prober/run.mjs --self-test` — scenario 71/81 passes all 13 sub-assertions, including the write-call-name scan reporting `found: none`.
- **Committed in:** `1ade4f2e` (Task 2 commit; both fix attempts were made before the commit, not as a follow-up)
