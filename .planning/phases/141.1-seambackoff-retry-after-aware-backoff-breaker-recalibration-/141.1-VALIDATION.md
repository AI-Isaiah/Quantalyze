## Oracle Independence

> The failure this catches: assertions that read their expected value out of the module under test.
> This repo has a documented history of exactly this failure mode on money math — three bugs
> survived six review passes behind self-referential oracles.

- [ ] No test imports a **constant** from the module it tests — expected values are **literals** in the test
- [ ] No assertion compares a value to itself via a re-export, fixture, or table under test
- [ ] Table/registry sizes are pinned to a **literal count**, not to `len(THE_TABLE)`
      *(SC-J is exactly this: `.toBe(4)` / `.toBe(2)` / `.toBe(2)` / `.toBe(5)`, hand-typed)*
- [ ] SC-L's 56 000 ms is a **hand-typed literal**, not re-derived from the formula under test
- [ ] SC-A's disagreement fixture puts row and registry in **conflict** — a test that reads both
      from the same source proves nothing (this is exactly why 558 tests stayed green)
- [ ] Any fake/double is pinned against the real contract it stands in for

**Deliberate self-reference:** SC-L. Its mutation edits `seam-budgets.invariant.test.ts` itself —
SC-4b's arithmetic is test-resident by design, so the "production source" being mutated IS the
test file. Independent cover: the `56_000` oracle is a hand-typed literal (never derived from the
formula under test), and plan 07 T3's anti-shortcut mutation (`failing` 3→6 ⇒ the hand-typed
`277_500` assertion REDs at 405_000) proves the arithmetic cannot be gamed from the constants
side. No other deliberate self-reference exists.
