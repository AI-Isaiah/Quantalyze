Made D-11's three claims true rather than deleting them: the four verdict maps are now
immutable at compile time and at runtime *including their entries*, `FlowType` /

**The fifth flow is not hypothetical.** This is the most load-bearing thing found. The plan
framed a 5th `FlowType` as a future risk; it already exists on the other side of the seam.
`internal_report` is a fully-supported server flow with its own whitelist, its own inline
branch and its own scalar handling. The moment anyone wires a TS emitter, the old ternary
would have handed an *inline* flow the 15s *enqueue* budget and reported a healthy Railway as
`UPSTREAM_TIMEOUT` 504. The `default` arm now makes that a compile error. The docblock records
the fact rather than the hypothetical, so it is falsifiable.

## Deviations from Plan

### 1. [Rule 1 — Bug] The switch conversion reddened `resilient-fetch.wiring.test.ts`

- **Found during:** Task 2 regression sweep. 2 failed / 3875 passed.
- **Issue:** `discoverBudgetKeyForArms()` scans `budgetKeyFor`'s body for string literals
  after stripping `=== "…"`. That strip is coupled to the **ternary** form. The switch's
  `case "teaser":` labels survived it, so the guard reported `teaser` / `csv` / `onboard` /
  `resync` as four phantom BUDGET KEYS: `expected [ 'bridge', 'csv', …(15) ] to deeply equal
  [ 'bridge', 'encrypt-key', …(11) ]`. The function's actual returns never changed.
- **Fix (the CAUSE, not the check):** the extractor now (a) strips flow-type tests in **both**
  syntactic forms the function has worn, and (b) keeps only RETURN statements — which is what
  this file's own census recipe already claims to measure (*"→ 2 returned key literals"*) and
  what stops the new fail-loud `default` message from ever minting a phantom. Neither step
  widens the guard: mutation I proves a new arm returning a new key is still discovered and
  still fails the roster, and a third syntactic form would yield FEWER bindings than the
  roster lists, which also fails. Both failure directions stay loud, and the docblock now
  records that invariant for the next person.
- **Files modified:** `src/lib/resilient-fetch.wiring.test.ts` (not in the plan's
  `files_modified` — the coupling was only discoverable by making the change).
- **Commit:** `3a8a59f7`

### 2. [Rule 2 — Correctness] Deep-froze the entries, not just the maps

- **Issue:** The plan specifies `Object.freeze({…})` per map and `Object.isFrozen(map)`
  assertions. A shallow freeze closes the ADD vector but leaves the REPOINT vector open:
  `RETRY_SAFE_ANALYTICS.bridge.retries = 5` reaches the gate through a row that is **already a
  legal YES**, so no key-set pin in the file would see it — and five retries on a handler that
  appends an audit row per attempt is the same elevation T-141.1-11 names. Freezing one level
  and calling the result "immutable" in a docblock is the exact over-claim class this phase
  exists to remove.
- **Fix:** a `freezeVerdicts` helper (no imports — leaf purity survives) freezes the map and
  its entries; both levels asserted; mutation D proves they are separately load-bearing.
- **Commit:** `522bfde4`

### 3. [Plan-sanctioned choice] `Exclude`-to-`never`, not `Record<FlowType, true>`

- **Issue:** The plan's action text sanctions either form ("pick whichever reads cleaner
  beside the existing pins"); its acceptance criterion then names the `Record<FlowType, true>`
  coverage const specifically. The two forms are not equivalent for the goal. A
  `Record<FlowType, true>` const reddens on a union edit and is cleared by adding one entry to
  itself — it forces a COVERAGE ENTRY, and the runtime pin stays green, so **no verdict is
  forced** and the docblock claim would still be false.
- **Fix:** used the `for-quants-lead` `Exclude`-to-`never` form applied to the existing
  `EXPECTED_ALL_FLOW_KEYS` / `EXPECTED_ALL_ANALYTICS_KEYS` lists, which is the form PATTERNS
  §7(c) names for exactly this problem. It is the only one of the two that CHAINS: clearing
  it requires naming the member in the list, which is what reddens the runtime pin, which
  forces the verdict (mutation F). The criterion's substance — "REDs in AT LEAST two places
  WITHOUT editing any hand-typed list" — is met (mutation E, two sites).
- **Commit:** `14c1748e`

### 4. [Rule 1 — Correctness] Kept the widened annotation; a bare `as const` was rejected

- **Issue:** The plan's Task 1 states the readonly conversion "must not require consumer
  changes — verify with typecheck". A bare `as const satisfies` **does** require them: the
  resulting narrow key type has no `teaser` / `csv` member, so
  `RETRY_SAFE_FLOW_TYPES[args.flow_type]` (a `FlowType`-typed index) stops compiling at
  `process-key-client.ts`, `RETRY_SAFE_ANALYTICS[options.budgetKey]` stops compiling at
  `analytics-client.ts`, and the SC3 belt tests (`…teaser` → `toBeUndefined()`) stop compiling
  too. The whole "absence ⇒ no-retry" contract is expressed through that widened index.
- **Fix:** `as const satisfies` **at the literal** (validity checked where the error points at
  the offending row) read back out through a `Readonly<Partial<Record<…>>>` annotation, which
  is what makes both mutation vectors compile errors while preserving the index. Verified: no
  consumer change was needed anywhere.
- **Commit:** `522bfde4`
