### `supabase/migrations/20261106120000_refusalrace_metadata_merge_rpcs.sql` (migration, CRUD merge)

**Analogs:** `supabase/migrations/20260712130000_set_compute_job_progress.sql` for the function body and ACL; `supabase/migrations/20261019120000_get_published_trade_venues.sql` for the plain `CREATE FUNCTION` choice, the COMMENT and the catalogue-only verify block; `supabase/migrations/20261105120000_sync_status_protect_refused_derive.sql` for the header (`SET LOCAL lock_timeout`, no explicit BEGIN/COMMIT, line 124) and its REVOKE/GRANT lines (1063-1064).

**Function body pattern to copy** (`20260712130000`, lines 61-88). The existing merge writer is the proof that `||` inside a single UPDATE is the house form:
```sql
CREATE OR REPLACE FUNCTION set_compute_job_progress(
  p_job_id      UUID,
  p_claim_token UUID,
  p_progress    JSONB
) RETURNS BOOLEAN
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_catalog
AS $$
BEGIN
  UPDATE compute_jobs
     SET metadata = COALESCE(metadata, '{}'::jsonb)
                 || jsonb_build_object(
                      'member_progress',    p_progress,
                      'member_progress_at', to_jsonb(now())
                    )
   WHERE id = p_job_id
     AND claim_token IS NOT DISTINCT FROM p_claim_token
     AND claim_token IS NOT NULL
     AND status = 'running';
  RETURN FOUND;
END;
$$;
```
Differences to apply for this phase: `CREATE FUNCTION public.<name>` (plain, not OR REPLACE, both names are new, per the `20261019120000` header lines 33-35: "a collision must fail loud instead of replacing someone else's body"); schema-qualify `public.compute_jobs`; no `claim_token` fence on the marker (D-09); use RESEARCH "Pattern 3" bodies (marker returns `RETURN FOUND` boolean with the `jsonb_typeof(metadata) = 'object'` guard; retraction returns a jsonb outcome object `retracted | done | no_marker | no_row`). Write the marker test as `(metadata ->> 'source') IN ('ledger-refresh', 'ledger-refresh-composite')` so the existing TS regex oracle parses it (same text form as `sync_strategy_analytics_status.sql` lines 150, 374).

**Header pattern** (`20261105120000`, line 124; `20261019120000`, lines 55-57 for the older BEGIN/COMMIT form). Follow the latest:
```sql
SET LOCAL lock_timeout = '3s';
```

**ACL pattern** (`20260712130000`, lines 101-102). Name `anon` and `authenticated` explicitly; `FROM PUBLIC` alone leaves Supabase default grants:
```sql
REVOKE ALL ON FUNCTION set_compute_job_progress(UUID, UUID, JSONB) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION set_compute_job_progress(UUID, UUID, JSONB) TO service_role;
```

**COMMENT pattern** (`20260712130000`, lines 90-99): plain `COMMENT ON FUNCTION public.<name>(<args>) IS '...';` citing the phase and the migration number. No guarded-COMMENT DO block is needed for a new function.

**Catalogue-only verify block** (`20261019120000`, lines 99-142). Copy the shape and change the assertions to service_role HAS / anon, authenticated, PUBLIC do NOT, and `'search_path=public, pg_catalog' = ANY(proconfig)`.
