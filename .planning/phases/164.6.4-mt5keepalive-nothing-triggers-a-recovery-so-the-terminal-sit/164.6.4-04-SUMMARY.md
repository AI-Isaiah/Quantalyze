### `analytics-service/services/mt5_session_episodes.py` (hardened)

1. **`started_at_is_lower_bound` is a PARAMETER.** It was an unconditional `True`, so every
   row claimed an unbounded start. It is now true exactly when there was no open run to
   continue (boot, crash, orphan, unparsed row) and `false` when the run was opened at an
   OBSERVED transition — whose bound the same row already carries as
   `since_previous_reading_s`.
2. **The consecutive-blind escalation.** `logger.log(WARNING if blind else INFO, …)` once the
   blind run has covered the independent hourly instrument's own window, with the count
   `max(1, ceil(_INDEPENDENT_INSTRUMENT_WINDOW_S / poll_interval_s))` so a cadence retune
   carries through. `None` cadence ⇒ no derivable threshold ⇒ never escalates (the boot heal
   fires once per process). Any measured reading resets it — `dark` included, because
   darkness is not blindness.
3. **The header records the semantic stretch.** The table's own `COMMENT` says "Heartbeat
   rows written by cron jobs"; these are session episodes written by a lifespan task. The
   shape fits, the words do not, and it is now stated rather than hidden. ⛔ Not "fixed" by
   editing the COMMENT — that is a migration, which is what D-5 chose this sink to avoid.

Both `_count_blind_reading` / `_clear_blind_run` are SEPARATE functions for the same reason
`_stamp_reading_and_measure_gap` is one: the shared never-raises predicate requires
`record_mt5_session_reading`'s body to be EXACTLY the `try`, and a `global` beside it is a
second top-level statement. ⛔ Keep the gate strict; move the declaration.

**1. [Rule 2 — missing correctness] `started_at_is_lower_bound` was an unconditional `True`**
- **Found during:** Task 1(e), writing the "true exactly when there was no open run to

### Deliberate divergences from the plan's literal wording

**4. `unattributed` is asserted in the LOG LINE, not in a row field.** The plan's task 1(d)
says "Assert the row says `unattributed`". No such row exists, by a wave-2 decision the module
implements: a `code=0` reading is `not_measured`, so it opens and closes NOTHING. The
ABSENCE of a row IS the record that nothing was measured; writing one would assert a state
the tick did not observe, which is the guess IN-02 forbids. The test asserts
`unattributed=True` in the emitted line, asserts no row was written, and carries this
reasoning in its docstring.

**5. The wave-2 harness was imported beyond the two names `coupling_justified` names.** Also
`_FakeCronRuns`, `_seed_open_row`, `_assert_no_secret_reached_any_row` and the credential
literals — all wave-2-established, all on the SAME already-declared file edge (no new one).
Copying a 120-line PostgREST-shaped fake whose `.eq()`-honouring UPDATE is the only reason
the compare-and-set is observable at all would be the drift shape this repo has a dated
record of. The two things this suite needs and wave 2's fake does not have (an ordered write
log, a between-read-and-write hook) are added by SUBCLASS.

**6. Two commits, split module-then-gates rather than task-1-then-task-2.** Both tasks edit
the same two files and the never-raises predicate constrains the same function the transition
logic lives in, so a task-shaped split would have meant writing the test file twice. The seam
taken is real and each commit is independently green (the module commit was verified against
the wave-2 suites: 171 passed, mypy clean, before the gates landed).
