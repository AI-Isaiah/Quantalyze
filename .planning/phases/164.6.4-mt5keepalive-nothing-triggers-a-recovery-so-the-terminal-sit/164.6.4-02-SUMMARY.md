# Phase 164.6.4 Plan 02: the session monitor and the durable episode sink Summary

The MT5 terminal's broker session now has something that NOTICES it has lapsed and ACTS — a
sixth `main.lifespan` task on a ten-minute DETECTION POLL CADENCE — and every
`authorized ↔ dark` transition lands as ONE ROW in `public.cron_runs`, so a successor can choose
the keepalive interval against `n>1` instead of the single wave-5 observation.

## What was built

### Task 1 — THE TRACER (commit `dfd1540a`)

**`analytics-service/services/mt5_session_episodes.py`** (new, 620 lines, fully annotated)

- `record_mt5_session_reading(kind, code, *, source, poll_interval_s)` — the whole decision
  table, stateless, never-raising. The open run is re-read from the DATABASE on every
  observation, so there is NO in-process episode state a redeploy could reset. D-5's
  "re-read the open episode AT BOOT" is answered by **having no memory, not by remembering
  harder**, and that reasoning is written at the site.
- `classify_reading(kind, code)` — the two positive CLASSES map to `authorized` (a clean probe
  raises nothing, so there is no code to read); `-6` maps to `dark`; every other code including
  `0` maps to `not_measured`, and `0` additionally marks the reading `unattributed` (IN-02).
- `_close_row(...)` — **a COMPARE-AND-SET**. The UPDATE carries `.eq("status", "running")` in
  its own predicate, so a superseded close is a NO-OP against an already-closed row.
- `_open_row(...)` — re-reads and superseded-closes every standing `running` row BEFORE the
  insert, so "at most one open row" is restored by every WRITE rather than by a read that
  happened to look.
- `_recognised_open_state(metadata)` — `None` for absent / malformed / unrecognised
  `schema_version`, routing those to the SUPERSEDED path.
- `record_mt5_heal_outcome(...)` — the TWO-observations-per-tick rule.
- `_stamp_reading_and_measure_gap()` — the module-level monotonic stamp of the previous
