<objective>
Make the monitor's two safety properties STRUCTURAL and CALIBRATED, and make the two-numbers
prohibition mechanical rather than prose.

⛔ The heal's never-raises AST predicate CANNOT be reused as the WHOLE gate for a loop, and copying it
would be worse than not gating (researcher C-3). It requires the function body be EXACTLY one `Try`,
which for a loop puts the `while` inside the guard — so the guard's handler runs ONCE, after which
the `try` is over and THE LOOP IS GONE. A single transient error on tick 3 would silently end the
keepalive for the life of the process, with a WARNING that looks exactly like a transient miss and a
worker that stays green. That is the same defect class this phase exists to remove, arriving inside
the fix.

A loop needs TWO properties and this plan gates both:
  P-outer — the task can never escape: the whole body inside one `try` / `except Exception`, the
  handler body itself guarded (IN-06), no `finally:` and no `else:` (both sit OUTSIDE the handler).
  P-inner — the loop can never be killed by one tick: every statement of the `while` body inside a
  guard whose bare-`Exception` handler CONTINUES.

Purpose: `_crash_handler` calls `SHUTDOWN.set()` on ANY background-task exception, which stops
dispatch, watchdog and enqueue behind a green `/health`. A keepalive is a LOOP, so that hazard is
permanent rather than one-shot.

Output: one widened shared predicate plus one new loop-survival predicate, each with a calibrated
mutant list; per-call validation gates for the one cadence knob; and a fence that reds if a keepalive
interval ever appears.
</objective>
