### WR-02 = SFH-M-03: the benchmark calendar was inferred from the bounded window

**Files modified:** `src/lib/factsheet/align.ts`, `src/lib/factsheet/build-payload.ts`,
`src/lib/factsheet/fetch-and-build-payload.ts`, `169.5-CONTEXT.md`, and the tests `align.test.ts`,
`build-payload.benchmark-opt.test.ts`, `comparator-block.coverage.test.ts`,
`fetch-and-build-payload.benchmark.test.ts`, `EoyComparatorCoverage.test.tsx`, `TimeSeriesChart.coverage-gap.test.tsx`
**Commit:** `750e641e1`
**Applied fix:**
- `alignCoveredReturns(prices, dropped, dates, calendar)`: `calendar: WeekdayCalendar` is a required argument.
  The inference (`for (const d of closeDates) calendar[...] = true`) is deleted. The docblock says the calendar is
  an input fixed per comparator and explains why it is never inferred.
- `CoveredAlignment.coveredToEnd` is required. The two hand-built alignments in `build-payload.ts`
  (`unavailableAlignment` and the correlation's strategy leg) now state `coveredToEnd: false`. Both had
  `through: null`, and an absent field already read as not covered, so behaviour is unchanged.
- `alignComparators` passes `COMPARATOR_CALENDARS.btc` / `.spx` / `.eth` / `.gld` / `.ief`. The route's
  `anyCovered` probe (`fetch-and-build-payload.ts`) passes `COMPARATOR_CALENDARS.btc`. That probe reads only
  `.returns`, which the calendar does not affect, so the argument is there to type-check and for consistency.
- **Browser re-derive:** `basis-context.tsx` calls `deriveSeriesBundle`, which calls `alignComparators`. So it
  uses the same masks by construction, and it needed no edit. The coverage caption (`ComparatorPicker`) already
  read `COMPARATOR_CALENDARS` (WR-01). The block and the caption now read the same calendar, which closes the
  interim divergence that group B recorded.
- Test call sites: SPX fixtures (`SYN_SPX`, the real `SPX_DAILY` in the WR-01 coverage case) take
  `CALENDAR_WEEKDAY`. Every BTC-shaped series takes `CALENDAR_7D`. On every existing case the explicit mask equals
  what the old code inferred. All existing literals held, and no test assertion was changed.
- CONTEXT D-64(2) has a dated amendment (2026-09-30, review WR-02). The original sentence is kept as lineage.

### Hand-off from group C: the discovery page's BTC read log carried `id: null`

**Files modified:** `src/app/(dashboard)/discovery/[slug]/[strategyId]/page.tsx`
**Commit:** `47efe9830`
**Applied fix:** `readFactsheetBenchmark(createAdminClient(), dailyReturns, buildOpts, strategy.id)`. This is the
resolved row's id, the same value the route passes as `id`. The comment above the call used to say "A read error or
throw is the unavailable form". It now says that an error or throw from the two DB calls (the paged read and the
first-date probe) gives the unavailable form, logged with the strategy's id, and that a bug in the pure merge/align
code throws to the error boundary (SFH-M-01).
**Test:** none added. The parameter feeds a log line only, and no existing test renders this page against
`readFactsheetBenchmark`. `tsc` checks the argument's type. It does not check that the page passes it, since the
parameter is optional.
