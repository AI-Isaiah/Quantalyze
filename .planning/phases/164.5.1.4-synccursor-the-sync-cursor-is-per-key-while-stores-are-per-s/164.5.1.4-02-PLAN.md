<objective>
Wire the per-STRATEGY resume marker end to end — table to fetch window — so that a partial fan-out
leaves the failed strategy's window re-drivable on the next tick, and prove it with a gate that reads
what the next tick actually asks the venue for.

**Purpose.** `_sync_single_key` already computes the per-strategy breakdown it needs:
`per_strategy_stored[sid]` is written inside the fan-out loop and `recompute_enqueue_errors[sid]` is
written in the loop after it. Nothing persists either. The remedy is to PERSIST what the code already
computes and to read it back when the window is chosen — not to compute something new. The key
cursor is untouched: it stays the bootstrap fallback for a strategy that has no marker row yet, and
it keeps carrying the account-balance write.

⭐ **The one line that decides whether this phase works.** The per-strategy advance condition is NOT a
mirror of `should_advance_cursor`. A strategy advances when the tick was idle, or when its trades
stored AND its recompute enqueue did not fail. Computed after both loops. That single condition
closes the trade-stranding criterion and the recompute-stranding criterion together; a naive mirror
closes only the first and looks correct.

⭐ **The second thing that decides whether this phase works, and RESEARCH's own snippet gets it
wrong.** A missing marker row must fall back to the key cursor — that is what makes the migration
inert on arrival. But the key cursor advances on a partial failure. So if the failed strategy is
never given a row, it falls back to a cursor that has already moved past its window and is stranded
exactly as before, and the whole change is inert on the first failure — the common case. Therefore a
held strategy gets its PRE-TICK resume point written down this tick, and the reader tells an absent
row from a present-NULL row by membership.

**Output.** Two small helpers and two wiring changes in `analytics-service/routers/cron.py`, a
two-tick consequence gate in `analytics-service/tests/test_cron_router.py`, and a calibration record
carrying the observed RED.
</objective>
