### ⭐ The One Thing That Must Not Pass Vacuously — independently falsified

Both coupled requirements hold, each proven by its own mutant:

**1. Persist-on-hold.** Every strategy in the fan-out gets a row, held or advancing. The held branch writes the PRE-TICK resume point resolved through the *same* `_strategy_resume_point` the read floor uses.

**2. Membership, never `.get()`.** `_strategy_resume_point` is `if strategy_id in strategy_cursors: return strategy_cursors[strategy_id]; return key_cursor`. Membership is preserved end-to-end: `cron_sync`'s chunked SELECT populates `_cursor_by_strategy` only for rows RETURNED, and each key's sub-mapping is filtered by `if sid in _cursor_by_strategy`. A strategy with no row is ABSENT, never present-with-null.
