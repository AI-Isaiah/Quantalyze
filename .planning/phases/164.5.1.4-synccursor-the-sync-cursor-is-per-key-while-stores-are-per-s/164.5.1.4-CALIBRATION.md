## Section 1 — the two-tick consequence gate (plan 02)

**Gate:** `analytics-service/tests/test_cron_router.py::TestSyncCursorPerStrategyResume`
**Subject under test:** the per-STRATEGY resume path in `analytics-service/routers/cron.py`
**Property pinned:** on a two-strategy key where one `sync_trades` RPC raises, the NEXT tick still
asks the venue for the failed strategy's window — measured at the `since_ms` keyword that reaches
`fetch_all_trades`, not at the marker row write.

### The neuter, and why this target rather than the alternatives

**Applied:** the window expression inside `_sync_single_key` was replaced with its pre-phase form —
the plain parse of the key row's own `last_sync_at`, ignoring the marker mapping entirely. In other
words, the marker READ was removed and the marker WRITE was left fully intact.

| candidate target | rejected because |
|---|---|
| the body of `_strategy_resume_point` | it would neuter the read AND the hold-write together, so a gate that only pinned the row write would also go red — the gate could pass the calibration while still being vacuous |
| the marker upsert (the WRITE) | reddens for the trivial reason that no row exists; proves nothing about whether anything READS the marker |
| **the window expression (the READ)** — chosen | the table still receives correct rows every tick and nothing consumes them. This is the sharpest available neuter: it reproduces exactly the failure mode CONTEXT Area 5 names — "a test that merely asserts the new column is written would pass against a marker nothing reads". If the gate survived this, it would be pinning the row and not the consequence. |

**Proof the neuter APPLIED** (a neuter that does not apply reads as GREEN, and one applied to the
wrong occurrence reds loudly while measuring nothing):

```
cmp <backup> routers/cron.py
  -> "... differ: char 24155, line 494"   cmp_exit=1
```

and the working diff showed exactly the intended three-line-to-one-line replacement at the
`fetch_all_trades` call site, with no other hunk.

### The OBSERVED RED — quoted verbatim from the run, not asserted

```
collecting ... collected 2 items

tests/test_cron_router.py::TestSyncCursorPerStrategyResume::test_partial_fanout_leaves_failed_strategy_window_refetchable FAILED [ 50%]
tests/test_cron_router.py::TestSyncCursorPerStrategyResume::test_full_success_lets_the_fetch_window_advance PASSED [100%]

E       AssertionError: THE CONSEQUENCE: tick 2 must ask the venue for strat-B's
        outstanding window (since_ms=1768435200000), not the advanced key cursor.
        Got since_ms=1789842747126. A marker that is written but never read
        produces exactly this failure.
E       assert 1789842747126 == 1768435200000

========================= 1 failed, 1 passed in 10.43s =========================
```

⭐ **Read what the failure line says, because it is the whole point.** The test did NOT fail on a
missing marker row — every row-existence assertion in the test passed under the neuter, since the
write was untouched. It failed on the ONE assertion that measures what the venue is actually asked
for: `1789842747126` is the ADVANCED key cursor, `1768435200000` is the millisecond parse of T0, the
resume point the failed strategy was held at. That is the stranding defect reproduced live, with the
marker table being written correctly the entire time.

**The control behaved correctly under the neuter, and that is expected, not a miss.**
`test_full_success_lets_the_fetch_window_advance` stayed GREEN: with no failure holding anything
back, the key cursor and the markers agree, so removing the read cannot change the window. A control
whose job is to prove the pinned window is a CONSEQUENCE of the failure has nothing to detect when
there is no failure. The consequence test is the arm this neuter targets, and it bit.

### Verdict

**The gate BITES.** It pins the consequence — the fetch window the next tick asks for — and it goes
RED when the marker read is removed while the marker write stays correct. It is therefore not
satisfiable by an implementation that writes a marker nothing consumes.
