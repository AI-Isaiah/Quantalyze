second conjunct — a strategy is not advanced when its `derive_broker_dailies` enqueue raised — is the
whole of success criterion 4, and RESEARCH's Pitfall 1 is explicit that a gate which only injects a

`cron_sync` test reaches the marker SELECT through a bare mock and therefore takes the fail-open
branch — the wiring would be permanently green and permanently unexercised. And three pieces of prose
in the tree describe the world before this phase: two in the test file frame the per-strategy fix as
future work, and one in `cron.py` states that a failed enqueue is never re-driven, which this phase
makes false.

**The decision this plan records.** A persistently-held strategy pins the whole key's fetch window,
because the fetch is per-KEY and the marker is per-STRATEGY. CONTEXT is silent on it. It is
PRECEDENTED — the `held` status's own comment already documents the same growth at key level and
accepts it — and it is an efficiency cost on a re-fetch that is idempotent by construction, not a
correctness or user-facing loss. Under the founder's deferral rule that makes it fix-or-drop rather
than a phase. It is FIXED here in the cheap and honest way: the held set is named in the result
envelope and in a log line that states the cost, so it is visible rather than inferred.
