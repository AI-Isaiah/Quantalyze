## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] TOAST relations were reported as lost non-public dependents, aborting every restore**

- **Found during:** Task 2 (the first end-to-end run of the harness).
- **Issue:** The derived `pg_depend` closure resolved a dependent's owning schema for `classid = pg_class` through `pg_class.relnamespace`. A TOAST relation lives in `pg_toast`, so every public table with a varlena column produced a dependent whose owning schema was `pg_toast` ≠ `public`, whose key fell through to `pg_describe_object()`, and which therefore matched no survivor key. **Measured, not predicted** — the first run of both arms died on:
  ```
  ERROR:  restore aborted: toast table pg_toast.pg_toast_16428 depends on public and is NOT a
          censused survivor …
  ```
  Against the real TEST this would have aborted every preflight and every restore, permanently.
- **Fix:** resolve a TOAST relation through its **carrier** — the table whose `reltoastrelid` it is — exactly the pattern `pg_trigger.tgrelid` / `pg_policy.polrelid` / `pg_rewrite.ev_class` already used, applied one class further. A `CASE WHEN c.relkind = 't'` branch, so a non-toast relation is unaffected and a toast relation for a NON-public table would still be reported under that table's schema (this is narrower than blanket-excluding the `pg_toast` schema, which was the tempting shortcut).
- **Files modified:** `scripts/restore-test-from-baseline.sh`.
- **Verification:** both arms went from `0/2` to `2/2`; the fix is commented in place with the measured error string, so the next reader does not re-derive it.
- **Committed in:** `fcfd29d2`.

## Risks measured here that Plan 04's preflight must answer

These are **not** defects in this plan; they are things the fixture cannot decide and the real preflight will, transactionally, against TEST itself. Named now so nobody meets them as a surprise at the founder checkpoint.

1. **`pg_default_acl` is not in the refclassid whitelist's resolution set.** `ALTER DEFAULT PRIVILEGES … IN SCHEMA public` records a `pg_depend` row on the `public` namespace whose `classid` is `pg_default_acl`, which the closure does not resolve → own schema NULL → key falls to `pg_describe_object()` → **the closure will abort**. The real dump restates those default privileges (`supabase/schema/baseline.sql:15115-15138`), so they are re-created rather than lost, i.e. this would be a FALSE abort. It was left unresolved deliberately: the plan's design tolerates a false abort (safe, rolls back, names the object) and does not tolerate a false pass, and the fixture carries no default ACLs so I could not measure whether TEST does. If Plan 04's preflight names it, the fix is one more carrier branch (`defaclnamespace`) plus a Plan-02-style arm — a founder-visible decision, not a silent widening.
2. **A `FOR ALL TABLES` publication would break survivor class (c).** `pg_publication_tables` lists such a publication's tables while `pg_publication_rel` holds no rows, so the census would emit `ALTER PUBLICATION … ADD TABLE`, which errors on an all-tables publication. It fails LOUD inside the transaction, so it is safe; PROD's `supabase_realtime` is not `FOR ALL TABLES` in the dump, but TEST was not measured.
3. **`functions=` compares `count(DISTINCT proname)` in `public` against the normalizer's distinct `CREATE FUNCTION` names** (real dump: 120, matching `BASELINE.md`). Aggregates or procedures created by other means would diverge; on TEST this is measured inside the transaction and simply rolls back.
4. **The fixture's `tables=` happens to be 2 on both sides of the restore** (`e2e_leftover`+`fx_keep` → `fx_keep`+`fx_other`), so NEUTER 3's byte-equality diff was carried by `policies=` and `ledger_rows=` rather than by `tables=`. The G-preflight arm asserts `public.e2e_leftover`'s presence separately, so the coincidence costs no coverage — noted so the number is not read as evidence it is not.
