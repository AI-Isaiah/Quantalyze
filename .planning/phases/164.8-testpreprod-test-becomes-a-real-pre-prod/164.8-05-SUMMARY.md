# Phase 164.8 Plan 05: TEST-first apply pipeline — Summary

**TEST is now the stage every migration crosses before PROD, and the check that says so was rebuilt after it turned out it could not fail.**

## Performance

- **Duration:** spread over 2026-09-08 and 2026-09-09
- **Tasks:** 4 of 4
- **Files modified:** 3

## Accomplishments

- `supabase-migrate.yml` gained `dispatch-ref-guard`, `apply-test` and `apply-test-verdict`; PROD `apply` now carries `needs: [plan, apply-test]` and requires `apply-test` to have SUCCEEDED, so a skipped TEST apply blocks PROD instead of passing as grey.
- The applied-set verification was rebuilt. As shipped it compared the dry-run's planned set against a scrape of the whole push stdout — which includes the CLI's confirmation prompt restating the planned set verbatim. `applied` was therefore always a superset of `planned`, and the check could not fire on the partial apply it exists to catch.
- The pipeline was proven end-to-end by a SHA-bound dispatch with every job green.

## Known limits, recorded rather than closed

1. **The applied-set comparison has still never run on a non-empty set.** Both dispatch proofs (`34354619770` and `34367135073`) had 266/266 on both ledgers, so planned and applied were both empty and equality held trivially. The non-empty behaviour rests entirely on the extracted-and-executed pins. The first real-world exercise comes with the next merge that carries a migration.
2. **The no-op arm of the new pin is not calibratable against the code.** A no-op log contains no 14-digit version at all, so the old and the new scrape both return the empty set and no mutation of the scrape flips that verdict. What that arm genuinely proves is that an awk pattern matching nothing does not abort the step under `set -euo pipefail`.
3. **An earlier dispatch (`34354619770`, headSha `06db9958`) was cancelled at the `plan` job** while it waited on the Production reviewer gate — the one point where it needed a human rather than a decision. That run is the wiring reading it produced, not this task's evidence. Recorded in the plan's Task 4 precondition.
