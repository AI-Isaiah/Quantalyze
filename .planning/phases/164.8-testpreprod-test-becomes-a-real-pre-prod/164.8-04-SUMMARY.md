## Why the plan halted

Task 2's amendment is **conditional** delegation. The founder's words, verbatim: *"Delegate,
but only if TEST is measurably quiet."* Conditions (a)-(c) fix how the measurement must be
taken — acquire the shared-TEST advisory lock **first**, probe **while holding it**, count
`idle in transaction` as ACTIVE, and name every session on any non-zero count. All three need
a session-mode Postgres connection to TEST.

There is none available to this executor. Measured:

| Source | Reading |
|---|---|
| `.env.test.local` | three variables, none a DSN: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` |
| `.env.local` | no Postgres DSN of any kind |
| `~/.pgpass`, `~/.pg_service.conf` | do not exist |
| Keychain `quantalyze-test` | an ACCOUNT (`demo-allocator@quantalyze.test`), not a DSN |
| `gh secret list` | `TEST_SUPABASE_DB_URL` exists ONLY as a repo secret (2026-05-13) |
| `psql` | installed, 18.6 — the blocker is the credential, not the client |

**An unmeasured gate is not a passed gate.** Dispatching on the strength of the green preflight
would answer a different question: the preflight proves the *transaction* is correct, and says
nothing about whether other people's CI is mid-run.

**The substitute that was available was refused on purpose.** This executor does hold TEST's
service-role key, so a PostgREST probe was reachable — and it is exactly the wrong instrument:
every PostgREST request is its own pooled session, so a SESSION advisory lock cannot be held
across the read. Condition (a) — the ordering rule the founder wrote down because probing first
"measures a window that has already closed" — is unsatisfiable by construction there. That probe
would have produced a green-looking `activity-gate: 0 active sessions` line with nothing behind
it. Refusing it is the whole point of the gate.

**Task 2's falsifier was not observed either**, and that is recorded as NOT OBSERVED rather than
waived: the second `idle in transaction` session needs the same missing credential. Per the
plan's own words, a gate that cannot see a held-lock session is the vacuity this phase exists to
prevent — so there is no basis to call the predicate proven.

**Task 3 was not started, deliberately.** Its work is to empty
`scripts/vac08-ledger-baseline.txt` *because the restore made its 31 entries present*. No
restore ran, so those 31 are still measured absent. Emptying the file now would be the mute
button its own header forbids, and VAC-08 would immediately report `31 baseline entr(y/ies) are
no longer MEASURED absent`.

### Deviation 2 — a script defect was found, assessed, and BOOKED rather than auto-fixed

The preflight log carries `scripts/restore-test-from-baseline.sh: line 765: toast: command not found`.
Cause: `restore-test-from-baseline.sh:821` has an **unescaped** backtick pair inside the
`<<TXN_CLOSURE` heredoc, whose delimiter is unquoted, so bash executed the quoted prose
`toast table pg_toast.pg_toast_16428` as a command. The sibling occurrences at `:799`, `:801`,
`:847`, `:849` are correctly escaped; this one was missed.

- **Impact, measured not assumed:** the backticks sit inside a single-line `--` SQL comment, so
  the generated transaction stays valid SQL and merely loses that comment's quoted text. The
  preflight ran to a byte-for-byte-equal post-census with the defect present.
- **Why not auto-fixed under Rule 1:** the script only ever executes via `workflow_dispatch`
  **from `main`**, so any edit costs another founder merge sitting between the preflight and the
  restore — real timing cost on a one-way door, spent on a lost code comment.
- **Booked:** `deferred-items.md` item 5, with the remedy and a self-test arm to add so the
  *class* (an unescaped backtick eating heredoc content) is caught. A future occurrence inside
  SQL rather than a comment would silently delete statement text.
