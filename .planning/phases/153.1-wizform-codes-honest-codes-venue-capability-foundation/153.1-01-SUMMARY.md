## Task 3 — per-route status fragment + interpolation-tolerant body (D-34 foundation)

**Commit:** `e01f8732` · `src/lib/wizardErrors.invariant.test.ts` (+192, −14)

**Re-derived anchors.** `EMITTER_RE` was at `:100-101` and the predicate docblock at

**(a) Status is per-route.**

- `RouteUnderTest` gains `readonly statusRe: string` (now `:175`); both existing entries
  carry `"400"`, so `create-with-key` and `composite/add-key` are byte-identical in
  behaviour.
- `EMITTER_RE` → `emitterRe(statusRe)` factory (now `:149`). Nothing outside this file

- `deriveEmittedCodes(source, statusRe = "400")` — the three incumbent SELF-TESTs call it

- Predicate docblock rewritten: the old prose claimed the population is "exactly the
  INPUT-VALIDATION rejections", which is true of the two incumbents and **false** of
  `finalize-wizard` (400/403/404/409/502/503). Leaving it green under a changed premise is
  this file's own Pitfall 1.

**(b) The body survives `${…}`.** `error:[^}]*\}` → `error:[\s\S]{0,160}?\}`. The old class
**excludes** `}` outright, so no amount of backtracking could cross the brace closing an
interpolation. The lazy bounded run backtracks to the first `}` that is actually followed
by `\s*,\s*\{[^}]*status:`, i.e. the object literal's real close.

**⭐ The lazy-match cap: 160, and why.** Both bounds measured on the comment-stripped
sources of all three routes:

- longest **real** `error:` … `}` body = **90** chars (`DRAFT_ALREADY_EXISTS`,
  create-with-key) → the cap must clear 90 with headroom;
- shortest distance from **any** `error:` to the **next** emitter's `status:` = **202**
  chars (finalize-wizard) → the cap must stay under 202 so cross-emitter reach is
  arithmetically impossible.

160 sits between: ~1.8× the longest real body, 42 chars short of the nearest neighbour.

**Non-regression proof (run and pasted):**

```
create-with-key      statusRe="400"          sites=12
composite/add-key    statusRe="400"          sites=12
finalize-wizard      statusRe="[45]\\d\\d"   sites=0   []
```

predicate.** All fourteen pre-existing coded arms are `{ error, code }`-first (and one is
lowercase), so none is visible. **153.1-06 reconciles against 0** — a number that does not
move after the reorder is how a blind scanner is caught.

## Deviations from Plan

**1. [Rule 3 — blocking] The closing anchor needed `,?`, which the plan's prose omitted.**
- **Found during:** Task 2.
- **Issue:** the plan specified "a closing match on `]` followed by any whitespace then
  `)`". `SubmitStep.tsx`'s roster is one argument of a multi-line argument list and closes
  `],\n        );` — a comma sits between. A bare `/\]\s*\)/` matches nothing and the
  roster still derives `[]`, i.e. the fix would have shipped blind.
- **Fix:** `/\]\s*,?\s*\)/`. The plan's own `<read_first>` states the close is `],\n );`,
  so the intent is unambiguous; only the regex prose was short.
- **Proven:** dropping `,?` reds both new SELF-TESTs.

**2. [Documented resolution] Two acceptance criteria contradicted their own action text.**
Both resolved in favour of the stricter reading, in Task 1 above (grep-0 vs the message
spec; `150_000` vs `120_000`). Neither is a silent change.

**3. [Scope addition, +1 assertion] A fifth SELF-TEST and a lowercase negative.**
The plan owed four SELF-TESTs. Added (a) a containment test for the new lazy cap — a new
number in the predicate with no falsifier is a magic constant — and (b) a lowercase-literal
negative inside the D-34 test, because the plan names the literal class as one of the two
levers that must not be relaxed and nothing else pinned it. Both watched failing.
