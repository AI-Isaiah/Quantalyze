# Phase 153.1 Plan 03: ONE requirement filter over the fix[] copy table Summary

Landed the WIZFORM-03 **class** mechanism: a `fix[]` bullet declares a requirement,
and one filter at the top of `formatKeyError` decides whether it renders — for every
code, every interpolation arm, and every bullet added later. Three venue bullets and
one surface bullet are tagged, the D-17 replacement copy is in the table verbatim,
and four whole-table sweeps plus **six** watched mutations pin it.

**Base commit:** `413d124f` (wave-1's final commit). `src/lib/wizardErrors.ts` was
untouched by waves 0–1, so every anchor the plan cited at `0c4f01d8` held exactly —
`:484`, `:701`, `:713`, `:1448` were the four bullets, verified at source before
editing.

**Exported names 153.2 / 153.4 import by name:**

| Kind | Name |
|---|---|
| type | `WizardSurface` (`"connect" \| "submit" \| "csv" \| "allocate"`) |
| type | `VenueCapabilityName` (`"substitutable"` — one member today) |
| type | `FixRequirement` (union: `{kind:"venueCapability", capability, is}` \| `{kind:"surface", surface}`) |
| field | `WizardErrorCopy.fixRequires?: readonly (FixRequirement \| null)[]` |
| field | `WizardErrorContext.venue?: string` |
| field | `WizardErrorContext.surface?: WizardSurface` |

⛔ `requirementMet`, `applyFixRequirements`, `VENUE_CAPABILITY_PREDICATES` and the
three `REQUIRES_*` constants are **module-private on purpose** — the same reasoning
153.1-02 applied to `venueCapabilities()`. A consumer that calls the filter itself
would double-filter, and a consumer that builds its own `FixRequirement` literal at a
call site re-invents the vocabulary the table owns.

**⚠️ Deviation from the plan's literal expression: `fixRequires` is filtered in
LOCKSTEP.** The plan specified
`{ ...entry, fix: entry.fix.filter((_, i) => requirementMet(...)) }`, which carries the
**unfiltered** `fixRequires` through onto a **filtered** `fix`. `formatKeyError` returns
a `WizardErrorCopy`, and that type declares the two arrays index-aligned — so the plan's
expression makes the function return a value that violates its own type's stated
invariant, a trap for the first consumer that reads both. Implemented as:

```ts
const keep = entry.fix.map((_, i) => requirementMet(requires[i] ?? null, context));
return {
  ...entry,
  fix: entry.fix.filter((_, i) => keep[i]),
  fixRequires: requires.filter((_, i) => keep[i]),
};
```

Behaviour of `fix` — the only field any consumer reads — is identical to the plan's.

## Deviations from Plan

**1. [Rule 1 — the plan's own gate would have shipped defeated] The prohibition was
spelled literally in comments and pushed `grep -c 'if (code === '` from 3 to 5.**
- **Found during:** Task 1, running the acceptance grep.
- **Fix:** both comments name the pattern in prose and say *why* it is not written out.
- **Why it matters:** the acceptance criterion is "the count is unchanged". Passing it by
  strengthening the check (wave-1's route) was not available here — the comments really
  did make the gate unable to distinguish prose from a branch. Rewording costs nothing
  and keeps the gate live for the next reader.

**2. [Rule 2 — invariant hardening] `fixRequires` is filtered in lockstep with `fix`.**
The plan's expression returns a `WizardErrorCopy` whose `fixRequires` no longer aligns
with its `fix`, violating the invariant the field's own docblock declares. Two extra
lines fix it; `fix` — the only field any consumer reads — is identical either way.
Detailed in Task 1.

**3. [Scope addition, +3 assertions] A positive control and two behaviour `it`s.**
The plan owed four sweeps. Added: (a) the positive control, without which M6 shows sweep
1 is green for a matcher that matches nothing — the phase's own named failure class; and
(b) the two Task-2 behaviour assertions as permanent tests rather than one-off scratch
calls, so the D-17 replacement sentence and the byte-identical ccxt arrays are pinned
against future copy edits.

**4. [Scope addition, +3 mutations] Six mutations instead of the three the plan owed.**
M4 (surface resolver), M5 (reference identity) and M6 (blind regex) each pin a mechanism
that the plan's three mutations do not reach. M6 in particular is the one that found a
real weakness in the sweep as first written.
