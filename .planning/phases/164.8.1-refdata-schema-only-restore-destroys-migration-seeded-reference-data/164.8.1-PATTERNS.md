### 1a. A pre-write refusal: `refuse_bad_migration_corpus()` — `:467-484`

**This is the analog for the allowlist load + validation.** Copy the whole shape:

```bash
MIGRATION_BASENAMES=()
refuse_bad_migration_corpus() {
  [ -d "$MIGRATIONS_DIR" ] || fail "migrations dir not found at ${MIGRATIONS_DIR}."
  local f base
  MIGRATION_BASENAMES=()
  for f in "$MIGRATIONS_DIR"/*.sql; do
    [ -e "$f" ] || continue
    base="$(basename "$f" .sql)"
    case "$base" in
      *[!A-Za-z0-9_.-]*) fail "migration filename '${base}' contains characters this script refuses to interpolate into SQL." ;;
    esac
    MIGRATION_BASENAMES+=("$base")
  done
  if [ "${#MIGRATION_BASENAMES[@]}" -eq 0 ]; then
    fail "no migration files found under ${MIGRATIONS_DIR}. The repo-side list is EMPTY, so the ledger seed would be empty — that is not a restore."
  fi
  note "migrations: ${#MIGRATION_BASENAMES[@]} file(s) under ${MIGRATIONS_DIR}"
}
```

**Copy:** the module-level `NAMES=()` array declared *outside* the function and repopulated
inside it; the per-item **charset refusal before any interpolation** (`case … *[!A-Za-z0-9_.-]*`
— the table names go into SQL, so this is an injection boundary, not hygiene); the **EMPTY-is-an-ERROR**
branch with a sentence saying what emptiness would silently produce; the closing `note` that prints
the count and the source path. Every refusal in this file is registered in `run_restore()`'s
ordered call list at `:1014-1017` / `:1029-1030` — **before** `RESTORE_OUT_DIR` exists for the
filesystem-only ones. An allowlist refusal is filesystem-only, so it belongs in the `:1014-1017`
block beside `refuse_bad_migration_corpus`.

**Do NOT copy:** the recursive-glob avoidance rationale (irrelevant); do not add a new
`fail()`/`note()` variant — there is exactly one of each (`:212-216`) and the vitest at
`:493-526` asserts refusals are `::error::`-prefixed and unsoftened.

### 1c. The abort: `TXN_WHITELIST` — `:726-749` (the closest analog for the non-empty gate)

```bash
  cat >> "$out" <<TXN_WHITELIST
DO \$restore\$
DECLARE r record;
BEGIN
  FOR r IN
    SELECT * FROM (VALUES
      ('pg_operator',    (SELECT count(*) FROM pg_operator     WHERE oprnamespace  = 'public'::regnamespace)),
      …
    ) AS t(cls, n)
    WHERE t.n > 0
    ORDER BY 1
  LOOP
    RAISE EXCEPTION 'restore aborted: public holds % object(s) of class % which the derived-census whitelist does not resolve; extend the refclassid set (a new class = a new self-test arm) before restoring', r.n, r.cls;
  END LOOP;
END
\$restore\$;
TXN_WHITELIST
```

**This is the shape the reference-data gate should be**, with the predicate inverted (`WHERE t.n = 0`):
a `VALUES` list built from the allowlist, a `FOR r IN … LOOP`, and a `RAISE EXCEPTION` whose message
(a) starts `restore aborted: `, (b) **names the offending item with a `%` placeholder** — CONTEXT's
"must fail LOUD and name the empty table", and (c) ends with the REMEDY sentence in the same
imperative voice ("extend the refclassid set (a new class = a new self-test arm) before restoring").
Every abort message in this file has all three parts — see also `:853`, `:908`, `:930`, `:962`.

**Copy:** the loop-over-VALUES form rather than a chain of `IF`s (it names *every* empty table on the
first offender rather than the alphabetically-first, and it is the form the vitest's region pins
already understand). Copy the `\$restore\$` dollar-tag — every DO block in this file uses that one tag.

**Do NOT copy:** a bare `IF v_n = 0 THEN RAISE` with the table name baked into the string. The whole
point of the allowlist is that the set moves; a hand-written per-table block would drift from it.

### The CLI contract — `:13-45`

```
  bash scripts/pg-lane/run.sh \
       --workdir <scratch-dir> \
       --apply <file.sql> [<file.sql> ...] \
       [--post-apply <file.sql>] \
       --gate <gate.sql>
```
"boot a throwaway cluster under `<scratch-dir>/pgd`, apply the `--apply` files in order, run the
optional `--post-apply` file, then run `--gate` streaming psql output. Exit 0 iff the gate passed.

**The idiom for a test that needs real DDL executed:** put the DDL in the `--apply` list (fixtures
first, then the real `supabase/migrations/*.sql` files), and put the assertions in a `--gate` SQL file
under `supabase/tests/`. `run_lane()` `:406-410` is the whole execution:

```bash
  psqlq -q -c "CREATE ROLE anon NOLOGIN; CREATE ROLE authenticated NOLOGIN; CREATE ROLE service_role NOLOGIN BYPASSRLS;"
  for f in "${applies[@]}"; do psqlq -q -f "$f"; done
  if [ -n "$post" ]; then psqlq -q -f "$post"; fi
```

## 5. Anti-vacuity idiom — and a CONTRADICTION to resolve

### ⛔ The contradiction

CONTEXT `<code_context>` says: *"neuter, observe RED, restore from a `cp` byte backup - NEVER
`git checkout --`"*. That rule is real (it is the repo's memory entry on
`git checkout --` destroying uncommitted work in neuter/restore harnesses), **but the repo's most
recent and most tested shape is stronger: never mutate the checkout at all.**

`scripts/mutation-runner/run.mjs:51-54`, invariant 1 of four:

> **THE CHECKOUT IS NEVER MUTATED.** Every mutation lands on a copy in a scratch dir. This eliminates
> the **stale-byte-backup class** and the shared-git-index race BY CONSTRUCTION rather than by
> discipline, and the run asserts `git status --porcelain` is clean before it exits.

**House rule says pick one and say why.** Pick the **scratch-copy** shape. It is more recent (Phase
164.3+, re-affirmed 164.7), more tested (384 biting arms run through it every `sql-mutation` job), it
subsumes the byte-backup rule, and it names the failure mode the byte backup still has — a backup
taken before an edit and restored after a *later* edit silently reverts the later one.

**Do not blend.** Reserve `cp` byte backups for the *human's* out-of-band falsification record — the
"observed RED then restored" evidence written into a SUMMARY, which is how arms 1-18 were proven
(`restore-test-from-baseline.sh:1187-1193`, "Every arm has a NAMED falsifier that was OBSERVED RED
and then restored from a byte backup; the record is `164.8-02-SUMMARY.md`"). For anything **committed**,
mutate a scratch copy.

### The concrete example the planner should imitate — arms 11 and 14, `:1328-1346`

This is the scratch-copy shape *already inside the file being edited*, so a new arm has zero excuse
to invent another:

```bash
  # ── the two SCRATCH COPIES the arms need ──────────────────────────────────
  # Both live under the harness's mktemp dir, never in the checkout, and both
  # assert their anchor was found: an awk that matched nothing would produce a
  # faithful copy and an arm that silently tests the unmutated script.
  local shape_script="$SELFTEST_TMPD/shape-plus-one.sh"
  awk '!d && index($0, "note \"expected shape from the dump text:") > 0 { print "  EXP_TABLES=$((EXP_TABLES + 1))  # arm 11: the EXPECTED derivation, mutated on a scratch copy"; d = 1 }
       { print }
       END { if (!d) { print "ANCHOR-NOT-FOUND" > "/dev/stderr"; exit 1 } }' "$0" > "$shape_script" \
    || fail "MEASURE_FAIL: could not build arm 11's shape-mismatch scratch copy — the derive_expected_shape anchor moved."
  grep -aq 'EXP_TABLES=\$((EXP_TABLES + 1))' "$shape_script" \
    || fail "MEASURE_FAIL: arm 11's scratch copy does not carry the mutated derivation."
```

**Copy all four properties:** (1) the copy lives under `$SELFTEST_TMPD`, never in the checkout;
(2) the `awk … END { if (!d) … exit 1 }` **anchor assertion** — a mutation that matched nothing
produces a faithful copy and an arm that tests the *unmutated* script; (3) the independent
`grep -aq` **verifying the mutation landed**, because the awk could succeed and write the wrong thing;
(4) both failures are `MEASURE_FAIL:`, not silent.

⛔ **Mutate the EXPECTED side, not the observed side** — `:1771-1777`:

> THE MUTATION IS ON THE **EXPECTED** SIDE […] The expected shape is DERIVED FROM THE DUMP TEXT while
> the database is built BY REPLAYING THAT SAME DUMP, so an extra `CREATE TABLE` line in a dump copy
> raises expected and actual EQUALLY and the assertion cannot fire — measured self-contradictory at
> plan-check iteration 2.

**This applies directly to the refdata gate and is the phase's most likely self-contradiction.** The
replay reads the migrations; the gate reads the database that the replay just built. Mutating a
migration raises *both* sides. A falsifier for the non-empty gate must therefore weaken the
**allowlist/gate side** (e.g. an allowlist naming a table the replay does not touch, so the gate's
subject is genuinely empty), or use an **overlay fixture** that makes the table empty independently —
never edit the reference INSERT.

## Shared Patterns

### Failure vocabulary
**Source:** `scripts/restore-test-from-baseline.sh:212-216`
**Apply to:** every new line of shell in this phase
```bash
fail() {
  echo "::error::${GATE}: $*" >&2
  exit 1
}
note() { echo "${GATE}: $*"; }
```
Runtime refusals → `fail` (`::error::`, exit 1). Broken instruments → the same `fail` with the message
prefixed **`MEASURE_FAIL:`** (`:567`, `:614`, `:649`, `:663`, `:1040`). Progress → `note`. Inside arms,
`echo "MEASURE_FAIL: …"; return 1` (not `fail`, which would exit the harness).
⛔ There is **no** `::warning::` in this file and the vitest at `:556-561` forbids it, alongside
`continue-on-error` and `exit 0`, in the whole `--run` region — "in this repo that token has meant
'a gate that reported instead of failing'" (`:540-543`).

### rc capture, never `|| true`
**Source:** `:605-616` (⛔ A7) and `:654-665` (⛔ A8)
**Apply to:** every `grep -c` / external command whose output the new code compares
```bash
  set +e; n=$(grep -ac '^survivor	' "$1"); rc=$?; set -e
  [ "$rc" -le 1 ] || fail "MEASURE_FAIL: could not count survivor rows in ${1} (grep exited ${rc}). An unreadable census is not a census of nothing."
```
A7's recorded cost: `grep -c … || true` turned "no matches" (rc 1, a reading) and "file unreadable"
(rc 2, a broken instrument) into the same empty string, and the comparison `"" = ""` **passed
vacuously**. Every `grep` in this file is `grep -a` — `grep` is measurably NUL-blind in this repo.

### The value is proven to be a number before anything relies on it
**Source:** `:567`, `:1040`
```bash
  case "$pre_survivors" in ''|*[!0-9]*) fail "MEASURE_FAIL: the survivor count read '${pre_survivors}', not a number. …" ;; esac
```

### SQL literal escaping
**Source:** `:405-407` — `sql_lit() { printf "%s" "$1" | sed "s/'/''/g"; }`
**Apply to:** every allowlist table name interpolated into the replay SQL or the gate's `VALUES` list.
