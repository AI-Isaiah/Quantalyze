# Phase 164.8.1 Plan 02: the replay, its gate, and three armed arms — Summary

The TEST restore now replays the 23 allowlisted reference statements inside its own
transaction — after the dump and survivors, before the ledger seed — and refuses to
commit a database in which any allowlisted table is empty or any kind-admission CHECK
admits a value its registry lost.

## What was built

**The replay (scripts/restore-test-from-baseline.sh, `build_transaction`).** The
extractor runs to `$RESTORE_OUT_DIR/refdata.sql`; a quoted heredoc emits
`SET LOCAL search_path = public, pg_catalog;`, the SQL is concatenated on its own
line, and a second heredoc restores `pg_catalog` **before** the ledger DDL. Pitfall 1
is not hygiene here: the replayed bytes are the migrations' originals and name their
targets unqualified.

**The gate (`TXN_REFDATA_GATE`).** The `TXN_WHITELIST` loop-over-VALUES shape with the
predicate inverted — it aborts on a table that is EMPTY rather than one that is
non-empty. Plain `count(*)`, no `to_regclass` guard on the loop: inside this
transaction the dump has just created these tables, and a guard would turn the
loudest symptom into a silent pass. A second leg refuses a PARTIAL replay: a CHECK
constraint that still admits a kind the registry no longer carries.

**Refusal 8, `refuse_bad_refdata_allowlist()`.** Filesystem-only, called after the
migration-corpus refusal and before `write_census_sql`. It refuses an absent
allowlist or extractor, an allowlist with zero entries, a non-zero extractor (echoing
its stderr first), a table name outside `[a-z0-9_.]` before any interpolation, and an
extractor that exits 0 emitting no `-- refdata-expect:` trailer.

**The census.** One `refdata:<schema.table>=<n|absent>` row per allowlisted table,
appended with `printf` after the quoted heredoc rather than by unquoting ~90 lines of
catalogue SQL (deferred-items:99). Nothing after the extension guard runs on TEST
today and the `restore:` summary line is pinned byte-for-byte by three arms, so the
census is where the reading has to live — and `--mode preflight` already compares it
pre/post byte-for-byte.

**The fixture substrate.** `refdata-allowlist.txt` with ONE entry; the allowlisted
INSERT in `20260103000000_fixture_c.sql`, deliberately UNQUALIFIED so it exercises the
bracket; `fx_keep_kind_check` in `baseline-fixture.sql` so the W1 leg has objects that
exist on the lane; and `fixture_a`'s "NEVER executed by anything" header corrected,
because it stopped being true.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 - Bug] `extract-reference-inserts.mjs` exited 0 having emitted NOTHING when
invoked through any path that is not its realpath**

- **Found during:** Task 1, while building a scratch copy of the harness under `mktemp -d`.
- **Issue:** the main guard was
  `resolve(process.argv[1]) === resolve(fileURLToPath(import.meta.url))`.
  `import.meta.url` is the module's REALPATH; `process.argv[1]` is what the caller typed.
  On macOS `mktemp -d` returns `/var/folders/…` and `/var` is a symlink to `/private/var`,
  so the compare was false for every copy under a temp dir and `main()` never ran —
  exit 0, no stdout, no stderr. A tool whose entire job is to produce the SQL a restore
  replays was silently doing nothing. On Linux CI the paths happen to match, so this
  would never have shown up there.
- **Fix:** compare `realpathSync` on both sides, keeping the plain compare as the fast
  path and a `try` so an unreadable `argv[1]` cannot crash at module load.
- **Files modified:** `scripts/extract-reference-inserts.mjs`
- **Commit:** 3579ea1c
- **Consequence for this plan:** it is also why refusal 8 carries a zero-trailer branch
  and why arm 24 leg (c) exists. The bug was found by that refusal firing.

**2. [Rule 3 - Blocking] the extractor's map key used a raw NUL byte, which reddened a
gate this plan is required to run**

- **Found during:** Task 1, running `src/__tests__/drift-check-scripts.test.ts` (named in
  Task 3's `read_first`).
- **Issue:** `listed.set(\`${e.file} ${e.qualified}\`, e)` — three raw U+0000 bytes at
  lines 558/563/593. The repo's invisible-character gate refuses them in any scanned
  script, and `grep` treats the whole file as binary so a search for any line in it reads
  as "no match" (the hazard MEMORY records for `src/lib/wizardErrors.test.ts`). The
  failure was PRE-EXISTING on this branch — the lines are untouched by this plan — but
  `drift-check-scripts.test.ts` is one of the three files Task 3 must run green.
- **Fix:** `|` as the separator. It cannot appear in either component: field 1 is
  `[A-Za-z0-9_.-]+\.sql` (BASENAME_RE) and field 2 is `[a-z_][a-z0-9_]*\.[a-z_][a-z0-9_]*`
  (QUALIFIED_RE), both charset-refused at parse time. The comment records why.
- **Files modified:** `scripts/extract-reference-inserts.mjs`
- **Commit:** 3579ea1c

**3. [Rule 2 - Missing critical functionality] arm 23 leg (b) and arm 24 leg (c), beyond
the plan's two legs each**

- **Issue:** the plan specified two legs for arm 23 and two for arm 24. Both left a guard
  unmeasured — the exact defect class W1 exists to catch.
  - The `SET LOCAL search_path = public, pg_catalog` bracket had no arm at all. It reads
    as hygiene and would be deleted by the next reader; RESEARCH Pitfall 1 says every
    unqualified target then stops resolving.
  - The zero-trailer refusal was reachable only through the extractor seam. Without an
    arm it was a branch whose only witness was the layer below it.
- **Fix:** arm 23 leg (b) deletes the bracket on a scratch copy and requires the abort to
  report an unresolvable unqualified target; arm 24 leg (c) points `REFDATA_EXTRACTOR` at
  a two-line stub that exits 0 printing nothing. Both were observed RED (N5, N8).
- **Commit:** ca2d6cdf

**4. [Rule 1 - Bug] the closing narrative's "every BRANCH of every one of them is armed"
was false before this phase**

- **Issue:** W2 asked for the refusal COUNT to be re-measured. Measuring it surfaced that
  the sentence beside the count was also untrue: `refuse_wrong_baseline_sha` alone has
  four `fail` exits (dump absent, doc absent, no parseable sha row, mismatch) and only
  the last has an arm. Extending a false claim to an eighth refusal would have made it
