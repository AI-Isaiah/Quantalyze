## New traps measured while writing this

⚠️ **The Actions runner ECHOES every script line with an ANSI colour prefix**, so a
naive `grep` over a job log matches the SOURCE of an `echo` rather than its OUTPUT. The
first read of these logs mistook the echoed string `mode=restore requires -f confirm=…`
for evidence that a run was a restore. Filter `\[36;1m`-prefixed lines out before
concluding anything about what a run printed.

⚠️ **`gh api …/actions/jobs/<id>/logs` needs `--allow-escape-sequences`**, or it exits 1
with EMPTY stdout — an empty log that reads as "nothing there". Already booked in
`164.7-06-SUMMARY.md`; re-confirmed here on logs of 1581 and 1725 lines.
