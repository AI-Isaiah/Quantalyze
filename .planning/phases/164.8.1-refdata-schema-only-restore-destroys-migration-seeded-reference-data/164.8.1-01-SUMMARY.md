# Phase 164.8.1 Plan 01: the reference-data allowlist and its extractor — Summary

A (file, table, count)-keyed allowlist of the 23 migration statements a schema-only TEST
restore destroys, plus a zero-dependency extractor that turns it into replayable SQL and
refuses — loudly, by name — anything it cannot prove safe, audited in CI in both drift
directions.

## What was built

**`scripts/restore-test-refdata-allowlist.txt`** (written by the previous executor run,
verified independently here). 22 entries over 19 migration files and 8 tables, pinning 23
top-level statements. Dated masthead carrying: what an entry is and why it is never a bare
table (L-02); C1-C4 with the single named `auth.users` exception to C3; the direction rule
in both senses; the VAC-08 ledger-presence sentence verbatim; three stated limitations; and
the L-03 note that `system_settings.analytics_service_url` is replayed as the migration
wrote it while the TEST-points-at-PROD-compute hazard is booked elsewhere.

**`scripts/extract-reference-inserts.mjs`**. Three modes:

- **emit** — prints each allowlisted statement's ORIGINAL bytes, sliced by offset, each
  followed by `-- refdata: <basename>:<line> <schema.table>`, then one
  `-- refdata-expect: <schema.table>=<n>` trailer per table. 23 statements, 8 trailers, no
  transaction-control statement, no `$`-tag.
- **`--audit`** — scans all 266 migrations and reddens on an unlisted top-level reference
  INSERT into an allowlisted table AND on a pinned count that stopped matching its file.
  Prints a census carrying every number the masthead claims.
- **`--self-test`** — drives 16 refusal kinds red+green end-to-end over
  `scripts/extract-reference-inserts-fixtures/`.

**`src/__tests__/refdata-allowlist.test.ts`** — AIM block declared first over synthetic
corpora with non-empty answers, then the live file: 22 entries, every count re-measured
against the real migration bytes with a ±1 calibration, every basename and schema checked,
both masthead sentences asserted with text-mutation calibrations, and the workflow wiring
pinned self-test-before-audit in both files with two calibrations each.

## The A4 reading — RESEARCH's assumption is FALSE

RESEARCH A4 assumed `maskSql`'s "dollar-quote interior scanned as code" does **not** split a
`DO` body at inner `;`. Measured, before writing any dependent code:

```
A4 FALSIFIED — spans: 3
0                         "DO   \nBEGIN\n  RAISE NOTICE 0"
1 QUALIFIES-AS-TOP-LEVEL -> "INSERT INTO api_keys (id, api_key_encrypted) VALUES (1, 2)"
2                         "END"
```

A body INSERT that is not the body's first statement surfaces as its own top-level-looking
span. So `dollarBodyRanges()` — A4's stated fallback, an independent dollar-depth scan of the
ORIGINAL text — is the shipped C1 mechanism, and `c1-dollar-body.red` is its falsifier.

**The corpus reading the plan asked for**, `public.strategies` over all 266 migrations:

| | replayable (top-level literal) | excluded by C1 | refused/skipped by C2 |
|---|---|---|---|
| with the dollar-depth scan (shipped) | **1** — `20260515095804_teaser_anchor_strategy.sql:78` | 25 | 0 |
| with it neutered on a scratch copy | 1 | 0 | 25 |

Zero `strategies` spans outside the teaser file, as required. ⚠️ Stated honestly: on TODAY's
corpus the 25 body occurrences would also be caught by C2, so the scan's protection is
currently latent rather than active. It is not redundant — the `c1-dollar-body` fixture is a
pure-literal `DO`-body INSERT, exactly the shape a future guarded seed would take, and with
the scan neutered that leg exits 0.

- **Issue:** the plan's C1 mechanism ("C1 falls out — a `DO` block is one span beginning with

  `statements()` splits at inner `;`.
- **Fix:** implemented A4's stated fallback (`dollarBodyRanges` over the ORIGINAL text) as the
  primary mechanism, plus the `c1-dollar-body` red fixture the plan required in that case.
- **Commit:** 440c98a4

  would have made one of the two false by position.
- **Fix:** appended at the END of `sql-gate-lint`, which satisfies both "after the app-GUC
  steps" and "FOURTH sibling". No existing step moved relative to another.
- **Commit:** 7ab93837
