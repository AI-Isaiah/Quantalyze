## Warnings

### WR-01: The contract pins which paths are named but not which flags are set, so the gate can be narrowed or weakened while the pin stays green

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts:164-170, 214-218, 223` (`pathSet`, `flagSet`, `surfaceProblems`)
**Execution status:** mypy half EXECUTED. Test half UNEXECUTED (reasoned from reading `pathSet` and `flagSet`).

**Issue:**
- `pathSet` drops every token that starts with `--`. `flagSet` only checks that `--strict` and `--follow-imports=silent` are present. It does not check that the flag set is exactly those two.
- As a result, this ci.yml line would pass every assertion in the test:
  `run: mypy --strict --follow-imports=silent --exclude=services/ingestion/ --allow-untyped-defs services/ routers/ models/ main.py main_worker.py main_worker_healthz.py sentry_init.py`
- I ran it. It reports `Success: no issues found in 87 source files`, not 100. It silently drops the MC-3 package (`services/ingestion/`), which is where the gate started, and it switches off a `--strict` sub-check.
- The Makefile `typecheck` recipe is worse off: its flags are never looked at, because `makefileTypecheckArgs` feeds the flags only into `pathSet`. So `$(MYPY) --no-strict-optional services/ …` passes too.
- The comment at the ci.yml gate claims that the test makes a narrowed surface "a RED check". The REGISTRY row claims the path set "equals the running-service surface". An `--exclude=` flag narrows the surface without changing the path set, so it defeats both claims.
- A related gap the test does not declare: an `[[tool.mypy.overrides]]` entry in `pyproject.toml` with `ignore_errors = true` or `follow_imports = "skip"` for `main` or `main_worker` would also switch the gate off, and nothing would go red.

**Fix:** Pin the exact flag set for ci.yml and pin an empty flag set for the Makefile (its flags come from pyproject). Add a calibration leg that injects `--exclude=services/ingestion/` and expects a red result.
```ts
const REQUIRED_CI_FLAGS = ["--follow-imports=silent", "--strict"];
const ciFlags = [...flagSet(ciTokens)].sort();
if (JSON.stringify(ciFlags) !== JSON.stringify(REQUIRED_CI_FLAGS)) {
  problems.push(`ci.yml: mypy flag set is ${JSON.stringify(ciFlags)}; exactly ${JSON.stringify(REQUIRED_CI_FLAGS)} is allowed — any other flag can narrow or weaken the gate while the path set stays equal`);
}
const mkFlags = [...flagSet(makefileTypecheckArgs(makefileText))];
if (mkFlags.length) problems.push(`Makefile: typecheck recipe carries flags ${mkFlags.join(" ")}; flags come from pyproject.toml only`);
```
Also add the pyproject `overrides` case to the header's "WHAT IT DOES NOT PIN" list, or pin it: no override whose `module` matches a surface member may carry `ignore_errors` or `follow_imports = "skip"`.

### WR-02: A package directory without `__init__.py` is invisible to the surface, so the claim "a package added without widening this line is RED" is false for namespace packages

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts:172-194` (`readListing`, `diskSurface`). The claim appears in `.github/workflows/ci.yml` in the comment above the step `Type gate - mypy strict over the running-service surface`: "a top-level module or package added without widening this line is a RED check, not a stale comment".
**Execution status:** UNEXECUTED (reasoned from reading; relies on PEP 420 behaviour and mypy's default `namespace_packages = True`).

**Issue:**
- `diskSurface` only counts a directory as a surface member when it has `e.hasInit`.
- Python 3.12 imports a directory with no `__init__.py` as a namespace package. For example, a `from workers.dispatch import x` inside `main.py` would work at runtime.
- mypy would reach that directory by import. Under `--follow-imports=silent`, that means it follows the code and suppresses its errors, which is the "reached, not checked" state this phase set out to remove.
- The test's own calibration leg (d) only covers `hasInit: true`, so it cannot catch this case.
- `docs/` holds no `.py` files today, so nothing is exposed right now. The gap is a latent hole in a guarantee the phase states in ci.yml, REGISTRY.md and the registry invariant.

**Fix:** Count any top-level directory that contains a `.py` file anywhere beneath it (recursively, skipping `__pycache__` and dot-directories) as a surface member unless it is in `EXCLUDED`. `__init__.py` should not be what decides it. Then add a calibration leg for a phantom `{ name: "newns", kind: "dir", hasInit: false }` that contains a `.py` file. As a smaller alternative, soften the ci.yml, REGISTRY.md and registry-invariant wording to say "a regular package (with `__init__.py`)".

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts:386-389`
**Execution status:** UNEXECUTED.
**Issue:**

### IN-02: The invocation count only sees single-line invocations inside the `python` job

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts:101-106` (`mypyInvocationCount`)
**Execution status:** UNEXECUTED.
**Issue:**

### WR-04: The step can be switched off by its own YAML keys and the pin stays green

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts` (`ciMypyArgs`); `.github/workflows/ci.yml` step `Type gate - mypy strict over the running-service surface`
**Execution status:** EXECUTED.
**Issue:** `ciMypyArgs` jumps from `- name:` to the first `run:` and never looks at the step's other keys. Inserting `if: false`, `continue-on-error: true`, or a `shell:` override that swallows the exit status each left the pin GREEN. The current step carries none of these.
**Fix:** Collect the step's keys (from `- name:` to the next step at the same indentation) and fail on any key other than `name` and `run`. Assert the `python` job itself carries no `continue-on-error`. Add calibration legs for `if: false` and `continue-on-error: true`.

### WR-05: `pyproject.toml` (and inline module directives) can switch the gate off for a named module, and the pin never reads them

**File:** `analytics-service/pyproject.toml` `[tool.mypy]`; the contract test
**Execution status:** EXECUTED (scratch copy: an `ignore_errors = true` override for `main` made `mypy --strict --follow-imports=silent main.py` pass on an untyped function).
**Issue:** CI runs with cwd `analytics-service/`, so this config always applies. An `ignore_errors` override, a `[tool.mypy]` `exclude`/`files`, `follow_imports = "skip"` on a surface module, or `strict = false` weakens the gate with the ci.yml line unchanged. The Makefile `typecheck` recipe relies on pyproject alone. The same class includes a module-level `# mypy:` inline config comment or a file-level bare `# type: ignore` in a surface file (none exist today).
**Fix:** In the pin, read `pyproject.toml` and assert: `strict = true`; `follow_imports = "silent"`; no `ignore_errors` anywhere; no `exclude` or `files` key in `[tool.mypy]`; every `[[tool.mypy.overrides]]` `module` entry is in a hand-typed third-party set equal to today's (`ccxt.*`, `pandas.*`, `scipy.*`, `quantstats.*`, `pandera.*`). Assert no tracked surface `.py` file carries a `# mypy:` line or a line that is exactly a bare `# type: ignore` before its first statement. Calibration legs for an `ignore_errors` override on `main` and for an inline directive.
