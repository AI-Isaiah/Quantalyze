### WR-05: `pyproject.toml` and inline directives can switch the gate off

**Files modified:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts`, `src/__tests__/contracts/REGISTRY.md`, `src/__tests__/contracts/contracts-registry.test.ts`
**Commit:** bcb55b562
**Applied fix:** a new `mypyConfigProblems` function, with its own main assertion. It requires:
- exactly one `[tool.mypy]` table, whose keys are exactly `python_version`, `strict` and `follow_imports`, with `strict = true` and `follow_imports = "silent"`. So there can be no `exclude`, `files` or `ignore_errors` key;
- `[[tool.mypy.overrides]]` entries that carry only `module`, `ignore_missing_imports` and `follow_imports`, and whose modules equal the hand-typed `THIRD_PARTY_OVERRIDES`. That set is exactly today's five (`ccxt.*`, `pandas.*`, `pandera.*`, `quantstats.*`, `scipy.*`): nothing was added, and set equality means a removal also goes red;
- no mypy configuration in any other table;
- no tracked `mypy.ini` or `.mypy.ini`. mypy reads those before `pyproject.toml`, so this was added as the same class;
- no surface `.py` file with a `# mypy:` line, and no bare `# type: ignore` before a file's first statement.

The TOML reader is deliberately narrow. It reports any line it cannot parse instead of skipping it, and leg (u) covers that.

Legs:
- (n): an `ignore_errors = true` override on `main`.
- (o): an `exclude` key.
- (p): `strict = false`.
- (p2): `follow_imports = "skip"`.
- (s): a sixth override module.
- (t): a tracked `mypy.ini`.
- (u): a multi-line array.
- (q): an inline `# mypy:` in `main.py`.
- (r): a top-of-file `# type: ignore` in `sentry_init.py`.

A config control passes the real inputs through the function. It also proves the reader actually read them: `main.py` is non-trivial, override tables were parsed, and `tests/` files were not scanned.
