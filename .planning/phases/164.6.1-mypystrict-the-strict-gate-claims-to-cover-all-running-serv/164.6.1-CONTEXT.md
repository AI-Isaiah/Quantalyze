## Implementation Decisions

### Strict surface (what the invocation names)

- **D-01: The invocation widens to the FOUR top-level service modules, not `main.py` alone.** New invocation: `mypy --strict --follow-imports=silent services/ routers/ models/ main.py main_worker.py main_worker_healthz.py sentry_init.py`.
  Evidence, measured 2026-09-23 at this branch's base with the CI-pinned `mypy==2.2.0` (`analytics-service/requirements-dev.txt`) from `analytics-service/`:
  - `main.py` imports all three at runtime: `from sentry_init import init_sentry` at module top, and `import main_worker` / `from main_worker import (...)` / `import main_worker_healthz` inside `lifespan`. The `analytics-service/Dockerfile` header records that the worker was MERGED into the API process ("There is ONE service"), so `main_worker.py` code runs in production inside `uvicorn main:app`.
  - `services/mt5_session_monitor.py` already does `from main_worker import SHUTDOWN`, so today `main_worker.py` is FOLLOWED by the gate with its errors SUPPRESSED by `--follow-imports=silent` — it is "reached but not checked", the exact state criterion 3 warns a green run cannot distinguish.
  - Per-file strict error counts: `main.py` 5 (the ROADMAP's five, now at `lifespan`, `_crash_handler`, `verify_service_key` ×2, `health`), `main_worker.py` 9 (all `no-untyped-def` on local helper closures such as `_safe_mark`, `_claim_priority`, `_mark_done`), `main_worker_healthz.py` 0, `sentry_init.py` 1 (`arg-type`: `_redact_before_send` typed with plain dicts where `sentry_sdk.init(before_send=...)` expects the SDK's event/hint types). Widened invocation: **15 errors in 3 files, 100 source files checked** (today: 0 errors, 96 files).
  - Why not `main.py` alone: the phase's named defect is a comment asserting coverage of ALL running-service code. Adding only `main.py` would force the corrected comment to disclaim `main_worker.py`/`sentry_init.py` — keeping a known member of the same defect class open. The repo's standing rule is to close the whole class across its surface, and the deferral rule allows a phase only for data-integrity or user-facing gaps (this is neither), so the choice is fix-or-drop: fix. The extra cost is 10 annotations.
  - ROADMAP criterion 1 (`main.py` 0 errors) is a subset of this and is still met literally.

- **D-02: Before/after file set is stated explicitly (criterion 4), and is MECHANISED, not only written.** Before: every module under `services/`, `routers/`, `models/` (96 source files, as mypy counts them). After: that set plus exactly `main.py`, `main_worker.py`, `main_worker_healthz.py`, `sentry_init.py` (100). No module leaves. The planner records the two mypy "checked N source files" lines verbatim in the SUMMARY.

- **D-03: A vitest contract test pins the invocation to the surface derived FROM DISK.** It reads the `ci.yml` mypy step and asserts the path list equals: the `services/`, `routers/`, `models/` packages plus every top-level `analytics-service/*.py` file (so a future top-level service module added without widening the gate is a RED check, not a stale comment). It also asserts the Makefile `typecheck` target names the same set (see D-05). It must be proven able to fail (neuter → observe RED → restore) per the repo's anti-vacuity rule, and it registers wherever `src/__tests__/contracts/REGISTRY.md` / `contracts-registry.test.ts` requires. Rationale: every correction of a restated scope in this repo that shipped as prose alone went stale (`CLAUDE.md` records four such for the mutation floors); a coverage claim is exactly that shape.

### Fixing the errors

- **D-04: Real annotations only.** No blanket `# type: ignore`, no `Any` casts to get green, no runtime behaviour change. `verify_service_key` takes Starlette's `RequestResponseEndpoint` for `call_next` and returns `Response`; `lifespan` returns `AsyncIterator[None]`; `_crash_handler` takes `asyncio.Task[None]` (the researcher confirms the actual task result type at the `add_done_callback` site); `health()` gets the return type its body actually produces. `sentry_init._redact_before_send` is re-typed to the SDK's own `Event`/`Hint` types (`sentry_sdk.types`), with no change to what it does; if the SDK's types force a narrowing that would change behaviour, a single narrowly-scoped `# type: ignore[arg-type]` with a written reason is the fallback, and the reason must say why a real type is impossible. Any ignore that is added is listed by symbol in the SUMMARY.

### Comments and other statements of the gate's coverage

- **D-05: Every place that STATES the gate's surface is corrected in the same change** — the comment above the `ci.yml` mypy step (criterion 2), the `analytics-service/Makefile` `typecheck` target and its `help` line (it claims to be "byte-for-byte the command the CI gate runs" — it is `services/ routers/ models/` only, so it goes false the moment CI widens), and the Makefile `lint` help line, which calls `services/ingestion/` "the current CI gate" (false since B-mypy part g). The `pyproject.toml` `[tool.mypy]` header only points at "the ci.yml mypy step" and needs no change unless research finds a surface claim in it. The corrected `ci.yml` comment names the four top-level modules explicitly, keeps the existing reasons for `scripts/` and `tests/` being outside, and states the `--follow-imports=silent` consequence plainly (a module reached only by import is followed with its errors suppressed, which is why the entry modules are named on the command line). Cite by symbol; no `ci.yml:NNNN` line numbers in the new prose.

### Proving the gate can fail (criterion 3)

- **D-06: Two-layer neuter proof.** (a) LOCAL, at execute time: neuter one error shape (drop the `Task[None]` type argument on `_crash_handler`), run the exact CI step command from `analytics-service/`, OBSERVE a non-zero exit naming `main.py`, restore byte-identically and re-run to 0. Also neuter one `main_worker.py` annotation and observe it named — this proves the D-01 widening, since a followed-silently module would stay green. (b) CI, on GitHub: criterion 3 says the `python` JOB must be observed RED, and a local run is not that. CI runs only on `pull_request` to `main`, pushes to `main`, and `workflow_dispatch`, and this run stops before the PR. So the CI observation is **carried as an explicit OPEN step for ship time**: on the phase PR, push a single neuter commit, observe the `python` job's mypy step RED naming `main.py` (bind to the head SHA), then push the restore. Criterion 3 is NOT to be marked closed by the local proof alone; the SUMMARY and VERIFICATION must say so.
  Why not `workflow_dispatch` now: it runs the whole CI corpus (about 50 job-minutes, and several jobs take the shared-TEST advisory mutex) on a deliberately broken commit, and `CLAUDE.md` records that a dispatch widens the gitleaks scan to full history and goes red on unrelated history, so it gives a noisy board for one step's verdict. The PR's own CI is the cheaper and cleaner place to observe it.
