  `cp /tmp/tinybase-14/<site>.bak <file>`, prove it with `cmp -s`. Never `git checkout`, `restore`
  or `stash` on uncommitted work. The drill is never committed.
- A drill counts as RED only when the site's NAMED arm fails in its log, never on a generic FAIL
  elsewhere in the file. vitest runs with `--reporter=default`, and the gate looks for a ` FAIL `
  line carrying the arm's title (the substrings in the gate table below). pytest runs with
  `-q -rf`, and the gate looks for a `FAILED tests/<file>::<arm>` line.
- An arm added because a named arm stayed GREEN carries a title that begins `KL5-DRILL <site>:` (for
  site K, a function name beginning `test_kl5_drill_K_`). The gate accepts that title in place of
  the site's named arms, and it exists only in the test file, so the gate still reads a real failure.
