## Summary

The change opens exactly `/api/og/factsheet` and its subpaths to signed-out callers and replaces a raw 140-unit slice with a word-boundary shortener. No unpublished or other-tenant data can reach an anonymous caller. Three layers keep it closed:

1. `withPublishedOnly` is applied to the one `strategies` read (`route.tsx:400-437`).
2. RLS: `strategies_read`, `strategies_org_read` and `analytics_read` in `supabase/schema/baseline.sql:15091-15093` and `:15677-15681` give an anon caller published rows only. Policies are permissive, so a published org row is visible to anon, which is the same exposure as the public `/factsheet/[id]` page. No column-level revokes exist on either table, so the embed columns the route reads are readable for a published row.
3. The card depends only on the published row. Signed-in and signed-out renders of the same URL are the same image, so `public, s-maxage` is not keyed to a viewer.

The PUBLIC_ROUTES match (`src/proxy.ts:72-74`, `path === route || path.startsWith(route + "/")`) admits `/api/og/factsheet` and `/api/og/factsheet/*` and nothing else. `src/proxy.test.ts` pins the negatives `/api/og`, `/api/og/other-card/…`, `/api/og/factsheetx` and `/api/og/factsheetx/…`.

`shortenOgDescription` is correct on every edge I traced:
- 140 code points is returned unchanged; 141 is cut.
- A head that ends exactly at a word is kept whole.
- Under D-05 a single overlong word is hard-cut. A boundary at index > 0 is preferred over the hard cut.
- Whitespace is collapsed before measuring, a whitespace-only description becomes `""`, and null/undefined return `""`.
- Code points are counted (`Array.from`), so no surrogate pair is split.
- No trailing space can come before "…": the input is collapsed and trimmed, and the cut lands before a space.

Under the old `.slice(0, 140)`, OD1 ends with "alpha om" and goes RED. ## Warnings

### WR-01: A malformed id from any anonymous caller goes down the failure path: a DB round-trip, a `no-store` card, an unthrottled `console.error` and the throttled Sentry slot real read failures depend on

**File:** `src/app/api/og/factsheet/[id]/route.tsx:387-452` (no id validation before `.eq("id", id)`; the `res.error` branch at `:442-445` sets `failed` and calls `reportOgFailure("read", …)`). The behaviour is pinned as intended by `route.public-access.test.tsx` P3.

**Scenario:** Before this phase the proxy 307'd every signed-out request, so only a signed-in user could reach this branch. Now any caller can reach it with no session: a crawler, an unfurler following a mangled link such as `/api/og/factsheet/undefined`, or a script. For `GET /api/og/factsheet/not-a-uuid`:

- PostgREST answers 22P02, so `failed = true`.
- `console.error("[og:factsheet] read failed", …)` runs on every request, with no throttle.
- `shouldCaptureNow("og-factsheet:read")` (`src/lib/sentry-capture.ts:342-351`, 60 s window per instance) spends the stage's one capture slot on the bogus id.
- The card is sent `no-store`, so the CDN never absorbs repeats, and each one costs a DB read and a Satori render.

The consequence that matters is the Sentry slot. One malformed hit per minute per instance suppresses every real `read` failure capture for this route, such as a statement timeout or a column drift (SFH-02's purpose). Real read failures then reach only the logs, among the 22P02 noise.

A non-uuid id is a genuine not-found, not a read failure. The sibling public route `src/app/api/factsheet/[id]/tearsheet.pdf/route.ts:14,145` already rejects a non-uuid id before any DB work with `isUuid`. This route is the one public strategy-id route that does not.

**Confidence:** 6/10. The mechanism is certain. How much it matters depends on real malformed-id traffic and on whether a 22P02 that crowds out a real failure in Sentry is acceptable.

**Fix:** Short-circuit before the read, and treat the malformed id as a not-found. That means the generic card, `LONG_CACHE_CONTROL` and no report, the same as D-02's unknown id:

```tsx
import { isUuid } from "@/lib/utils";
// …
const { id } = await ctx.params;
// …
let failed = false;
if (isUuid(id)) {
  try {
    const supabase = await createClient();
    const res = await withPublishedOnly(/* unchanged */).maybeSingle();
    if (res.error) { failed = true; reportOgFailure("read", id, res.error); }
    data = res.data ?? null;
  } catch (err) { failed = true; reportOgFailure("read", id, err); }
}
// else: a malformed id is a genuine not-found → generic card, long cache, no report
```

Then change `route.public-access.test.tsx` P3:
- Assert `LONG_CACHE`, no `afterSpy` call and no `strategies` read for `not-a-uuid`.
- Keep a separate case that gives a valid uuid a 22P02/timeout `error` and asserts `FAILURE_CACHE_CONTROL` plus one capture, so SFH-02 stays pinned.
