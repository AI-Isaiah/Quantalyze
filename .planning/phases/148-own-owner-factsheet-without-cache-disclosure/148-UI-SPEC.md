**Accent reserved for (this phase):** the OWN-04 preview link text ONLY. The banner carries **zero accent and zero semantic color** — it is muted-neutral by the DESIGN.md semantic-color gates.

**⛔ Banner color gate (locked in CONTEXT, derived from DESIGN.md gates):**
- **Never red/negative** — an unpublished draft is absence/private state, not an error. Red = permanent failure only.
- **Not amber** — amber = recoverable via a disclosed one-click action. Publication is **admin-only**; the owner has no action that flips it, so amber would falsely promise a remedy.
- **Muted neutral is the correct gate**: "steady-state, honest-empty." Banner tokens: `border-border` #E2E8F0, `bg-surface-subtle` #FBFCFD, heading `text-text-primary` #1A1A2E, body `text-text-muted` #64748B (4.8:1 on #FBFCFD — AA at 12px per the 2026-04-30 precedent).

## Component Contract 1 — Owner-lane "Unpublished" banner

**Renders on:** the owner lane ONLY (`factsheet/[id]/v2` when the page resolved via the Lane-B owner probe). The published/public lane renders **byte-identical to today** — no wrapper, no reserved space, no hidden node. Zero-diff on the published lane is an acceptance term.

**Placement:** first child inside the factsheet document container, ABOVE `FactsheetHeader` (the masthead eyebrow "Institutional Factsheet · Quantalyze", `FactsheetView.tsx` `<header className="border-b border-text …">`). Full document width. `mb-6` (24px) below it before the masthead. Rationale: the notice is viewer-context ("who can see this"), not document content — it sits above the two-weight rule frame so the dated document underneath stays untouched, and it is the first thing an owner reads before any number.

**Visual (data-panel primitive, per DESIGN.md — NOT a card):**
- Square corners (no radius), flat (no shadow), 1px hairline border `border border-border`, `bg-surface-subtle`, `px-4 py-3`.
- This is exactly the existing `NotEnoughDataPanel` treatment on this same surface (`FactsheetView.tsx:556-563`) — reuse its shape; do not invent a new banner primitive.

**Anatomy:**
- Heading: `UNPUBLISHED — ONLY YOU CAN SEE THIS` (source copy sentence-case "Unpublished — only you can see this", uppercased via CSS). 12px Geist Mono semibold, `uppercase tracking-[0.18em]`, `text-text-primary`. Em-dash is a permitted semantic glyph.
- Body (4px below heading, `mt-1`): 12px DM Sans regular `text-text-muted`, copy in the Copywriting Contract below.
- No icon, no dot, no close button.

**Interaction:** none. Static, **not dismissible** — a document states its own status; a dismissed banner lets an owner screenshot/print a draft that reads as published. For the same reason the banner **prints** (no `print:hidden`): a draft handed to an LP on paper must carry its unpublished status. Passes the five-second print test by design.

**Accessibility:** `role="note"` with `aria-label="Visibility notice"` on the section. NOT `role="alert"` (nothing went wrong) and NOT `aria-live` (server-rendered static content, present at load).

**Data source constraint (contract, not implementation):** the banner condition MUST derive from the page's lane decision (a prop passed by the server component, e.g. `viewerNotice="owner_unpublished"`), **never from a field added to the cached payload**. Writing it into the payload would change the `factsheet-v2-payload-v6` shape (forcing the v7 bump protocol) and — worse — put owner-lane state into an object whose other consumer is the shared public cache. Lane knowledge stays out of the payload; if the planner nonetheless needs a payload change, the documented v6→v7 bump protocol is mandatory.

## Component Contract 2 — OWN-04 preview link (SyncPreviewStep)

**Renders on:** BOTH terminal-success render branches of `SyncPreviewStep` — the single-key branch (`FactsheetPreview` site at ~`:2194`) and the composite branch (~`:1917`). Same element, same copy, both sites.

**Placement:** directly below the `FactsheetPreview` panel, inside its `mt-6` block, at `mt-3` (12px) under the panel. Left-aligned (report layout is left-anchored). ABOVE the existing CTA row (`Use this key and continue` / `Try another key`) — the link is a preview affordance subordinate to the step's primary action, so it must not sit in the button row.

**Affordance:** a text link, NOT a button — it must not compete with the step's primary `Button` (accent bg) per the established secondary-CTA restraint (CSV escape-hatch precedent). Style: 13px DM Sans medium, `text-accent underline underline-offset-4` (persistent underline — WCAG 1.4.1 rule for links distinguishable in flowing content), trailing `→` glyph with a preceding space, hover `text-accent-hover` (#155A4B) at 150ms ease-out.

**Caption:** same line or wrapped beneath (`mt-1`), 12px DM Sans regular `text-text-muted`: see Copywriting Contract.

**Target & behavior:** `href={/factsheet/${strategyId}/v2}` — `strategyId` is a required prop of `SyncPreviewStep`, so inside these success branches the id is always resolved. Opens in a **new tab** (`target="_blank" rel="noopener noreferrer"`): the wizard is a stateful flow; same-tab navigation would eject the founder mid-onboarding.

**No-disabled-states rule (standing UAT direction — binding):** there is NO disabled/greyed variant and NO placeholder. In the pre-success phases (`kicking_off` / `waiting_for_complete` / `gate_failed`) the link simply does not exist — those branches don't render `FactsheetPreview` either, so the condition is structural, not a spinner-gated disable. Because OWN-04 lands strictly after OWN-02, the rendered link can never land on `notFound()` (SC3).

**Finalize-step repetition (CONTEXT delegated this call to UI-SPEC): DO NOT repeat.** The link renders in SyncPreviewStep only. Rationale: minimal contract per scope note; the post-finalize "where is my strategy" surface is Phase 149's ranking, and duplicating the link there now would pre-empt that phase's surface. One site, two render branches.

## Copywriting Contract

Voice rules apply (DESIGN.md): declarative sentence case, state the limitation with its consequence attached, active voice, no adjectives.

| Element | Copy (verbatim) |
|---------|-----------------|
| Banner heading | `Unpublished — only you can see this` (rendered uppercase via CSS) |
| Banner body | `This factsheet is visible only from the account that uploaded the strategy. Anyone else who opens this link sees a 404 until Quantalyze review publishes it.` |
| Preview link | `View full factsheet →` |
| Preview link caption | `Visible only to you until the strategy is published.` |
| Primary CTA | unchanged — `Use this key and continue` remains the step's primary CTA; this phase adds no new primary CTA |
| Empty state | none new — pre-resolution the link is structurally absent (no placeholder copy); the factsheet's existing empty/insufficient-data panels are untouched |
| Error state | none new — factsheet load failure keeps `ErrorEnvelope` (`buildEnvelope`, no inline strings); wizard errors keep `wizardErrors.ts`. The owner lane failing its build renders the existing `error.tsx` boundary, unchanged. |
| Destructive confirmation | none — no destructive actions in this phase |

The banner body deliberately names the exact recipient consequence ("sees a 404") — without it, owners share the URL and the recipient's 404 reads as a bug (CONTEXT rationale, locked).
