### WR-01: a docs-only push to `main` takes the short path

**Files modified:** `scripts/classify-changed-paths.mjs`, `.github/workflows/ci.yml`, `src/__tests__/contracts/ci-docs-path-filter.contract.test.ts`
**Commit:** `be6019263`

**Applied fix:** This implements the founder's 2026-09-27 routing (ROADMAP `### Phase 164.9.4`, "ROUTED IN 2026-09-27 … a docs-only push to `main` runs the full corpus").

**`classifyPushRange()` (new):**

- It diffs the pushed range `before..HEAD` (two-dot, `--no-renames -z`) and applies the same `judge()` the PR path uses.
- On a squash merge `before` is HEAD's first parent, so this is the ROADMAP's first-parent diff.
- On a multi-commit push it is the union of all pushed commits. That is deliberately STRICTER than `HEAD^1..HEAD`, which would see only the last commit. A code commit under a later docs commit stays code.

**Fail SAFE to code, never red.** In each of these cases the classifier emits `docs_only=false` with a named reason and exits 0:

- the before-SHA is absent, malformed or all zeros;
- the push is forced (string or boolean flag);
- the before-SHA is not in the clone, or is not an ancestor of HEAD;
- the diff fails;
- the range is empty.

It never exits 1, because a red `changed-paths` would skip every dependent and redden `frontend` on `main`. The existing PR path keeps its MEASURE_FAIL exit 1, unchanged.

**What did not change:**

- `workflow_dispatch` and every other event that is neither a push nor a PR still hard-code a code verdict.
- `changedFilesAgainstBase()`, which is shared with `sql-gate-subset.mjs`, is untouched.

**`ci.yml`:** the `classify` step gets `PUSH_BEFORE_SHA: ${{ github.event.before }}` and `PUSH_FORCED: ${{ github.event.forced }}` through `env:`, never interpolated into `run:`. `changed-paths` still carries no `if:`. The job header's "push corpus is never filtered" sentence carries a dated correction and is kept as lineage.

**The "zero gate runs" constraint (CLAUDE.md, the skip-trailer section).** A docs-only push produces a SHORT run, not a missing one:

- `changed-paths`, the always-on jobs and the `if: always()` `frontend` aggregator still run;
- nothing is filtered at the `on:` trigger, and the existing `push: branches: [main]` pin still holds;
- the new aggregator scenario **S1p** executes the real aggregator body with `eventName: "push"` and every filterable row skipped. It shows a GREEN board, with the uniform docs-only arm claiming `e2e-seeded` and `test-db-drift` ahead of their trusted-event arms.

**Tests:**

  - **Row 14:** a docs-only push goes short (`docs_only=true`), checked through `classifyPushRange` and end to end through `main()` with `GITHUB_EVENT_NAME=push` and `$GITHUB_OUTPUT`.
  - **Row 15:** a code push is not filtered. It includes a code-then-docs two-commit push, with a calibration that the last commit alone IS docs-only.
  - **Row 16:** an undeterminable range falls back to code. It covers seven shapes: a non-ancestor sibling, a forced push given as a string and as a boolean, a zero SHA, a SHA absent from the clone, an empty SHA and a non-hex SHA.
