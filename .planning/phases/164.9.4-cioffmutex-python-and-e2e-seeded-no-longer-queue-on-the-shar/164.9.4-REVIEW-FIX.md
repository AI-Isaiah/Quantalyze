**Commit:** `964d675a6`

**Applied fix.** This implements the orchestrator's decided design. `predecessorVerdict` now
requires all three of the following:

- **(a)** A completed `frontend` check run concluded `success`. That is the
  `PREDECESSOR_REQUIRED_CHECK`, CI's `if: always()` aggregator.
- **(b)** Every GitHub Actions check run is completed, with a conclusion in
  {success, skipped, neutral}.
  - It is read with `filter=all&per_page=100`.
  - It is deduplicated explicitly by `(check_suite.id, name)`, keeping the highest id. Two runs are
    never collapsed across suites.
  - An Actions run with no numeric `id`, no `check_suite.id` or no `name` is refused.
- **(c)** Every GitHub Actions check suite on `before` has `status: completed`.
  - It is read from `repos/<repo>/commits/<before>/check-suites?per_page=100`.

The reader (`readPredecessor`) makes both calls. The seam is renamed to `fetchPredecessor` and
returns `{ runs, suites }`.

Each of these runs the full corpus and prints its reason:
- a truncated page, on either body;
- a foreign `head_sha`, on either body;
- a malformed body;
- a throw.

**Self-test rows.**

Proven (short path):
- a queued Vercel suite with zero runs;
- an in-suite re-run, with an older red attempt and a newer green attempt;
- a green CI suite beside a green scheduled suite.

Unproven (full corpus):
- no `frontend`;
- only scheduled checks;
- a skipped `frontend`;
- a queued Actions suite with no runs;
- a completed Actions suite with no runs that concluded `failure`;
- a newer red attempt in the same suite;
- a red run in another suite beside a green run of the same name;
- truncated, malformed and foreign suite bodies;
- a run with no `check_suite`.

The end-to-end fake `gh` now appends its argv and answers by path. The argv pin asserts both
`filter=all` and `check-suites` calls.

**Contract tests.** Two new neuter legs:
- leg 7 deletes requirement (a) and pins its three FAIL lines;
- leg 8 deletes requirement (c) and pins the queued-suite FAIL line.

Neuter leg 5's existing FAIL strings are unchanged.

**Permissions** stay `contents: read` + `checks: read`. Both endpoints need only `checks: read`. The
existing permissions arm still passes.

**Measured live, read-only, against three `main` commits:**
- The `claude`, `vercel`, `railway-app` and `fly-io` apps each leave a suite `queued` with zero runs
  on every commit, so requirement (c) is filtered to `github-actions` suites.
- Every Actions suite on a finished commit is `completed`.
- In-flight commit `91f4239a19` shows an `in_progress` Actions suite. Under (c) it now reads as

- `filter=all` returns `check_suite.id` on every run.

**Decisions:**
- **Stricter than the decided design (c):** a suite's conclusion must also be in the ok set. Without

  that failed to start, for example a workflow-file error. This is one line, and it errs in the safe
  direction.

  `predecessorVerdict` calls against `main` SHAs `53c32630378e`, `187441725614` and `91f4239a19fe`

  run's suite directly. The self-test row feeds the shape the review describes: a suite that is not

### WR-02 (2) + IN-01 + SFH LOW-08: the derivation fails closed, with per-source exclusions

**Files modified:**
- `src/__tests__/contracts/ci-docs-path-filter.contract.test.ts`
- `164.9.4-CONTEXT.md` (D-16)

**Commit:** `f47a0097f`

**Applied fix.** A small lexer, `lex()`, now finds every `.planning` occurrence in a scanned source.

What it reads as literals:
- strings in `'`, `"` and backtick quotes, with a template's `${…}` kept raw;
- Python `'''` and `"""` strings;
- multi-line strings.

What else it handles:
- comments are skipped (`//`, `/* */` and `#`);
- JS regex literals are recognised.

Each occurrence either derives a planning file, or is an unrecognised shape that is red until named.

Derived as a planning file:
- a static literal wherever `.planning` sits in it: after `./`, after `${ROOT}/` or `{ROOT}/`, or
  mid-string;
- a root or directory joined with literal segments, using `,` or `/`;
- a directory literal plus a basename literal in the same file;
- an ABSENT file, which is kept, never dropped.

Unrecognised, so red until named:
- a computed path (`${…}`, `{…}` or a glob);
- the bare root, or a directory held for a later join with a variable;
- a regex literal;
- a `.planning` outside any literal or comment.

The unrecognised shapes cannot be resolved statically. That is the documented fail-loud case.

**The import closure now also follows:**
- parenthesised multi-line Python imports and relative Python imports;
- scripts spawned through split `join(…, "scripts", …)` segments, backtick literals, or `../`-relative
  literals.

**Exclusions.**
- `NOT_READS` replaces the global `FIXTURE_COLLISIONS`. It holds `(source, token, reason)` entries in
  the same block as `NOT_SCANNED`.
- `.planning/STATE.md` is now excluded only for `verify-plan-anchors.test.ts`.
- A fence arm asserts two things for every entry:
  - its source is tracked and is not also in `NOT_SCANNED`;
  - its source still produces that exact token, so stale entries go red.

**What the new grammar measured:**
- 42 previously invisible `(source, token)` pairs: docstrings, alert and email copy, scratch-tree
  fixtures, absent paths, predicates.
- Each is named with a reason. Two shared reasons cover most of them: FIXTURE and DOCSTRING.
- No new real-tree reader was found. `TEST_READ_PLANNING_PATHS` is unchanged at seven entries.

**New and changed arms:**
- 17 synthetic scanner rows and 6 synthetic closure rows drive every blind-spot shape through the
  pure `scanSource()` and `importsOf()`, so the grammar is shown to fire.
- The "list cannot lag" arm now reports every missing path at once, instead of stopping at the first.
