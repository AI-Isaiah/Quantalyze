## Critical Issues

### CR-01: Merging now reddens `main` on a race: `python` fails or skips at random, and a red `python` removes VAC-08 and fails the `frontend` aggregator

**File:** `.github/workflows/ci.yml` — job `python`, step `Run pytest --cov=services --cov=routers --cov=main_worker --cov-report=term-missing --cov-fail-under=80`. Also job `test-db-drift`'s `needs: [python, changed-paths]` and the `frontend` aggregator's `test-db-drift` arm.
**Issue:** Moving `python` onto the lane turns
`tests/test_compute_jobs_fencing.py::test_defer_compute_job_token_fence` from a steady SKIP into a
race between two outcomes (MEASUREMENT, `### Root cause of the python red`):

- **The test skips** when httpx's 60 s read timeout fires first, because `_rpc_retry_timeout`
  matches `timed out`.
- **The test fails** when Kong's 60 s upstream timeout answers 504 first. supabase-py renders that
  as `JSON could not be generated`, which the skip does not match.

The lane measured SKIP twice locally and FAIL once in CI (run `36304648008`). The gate is
therefore non-deterministic both ways:

- **Green:** the job passes while the 40001 retry loop is still present, so a green job measures
  nothing about the defect.
- **Red:** the failure cascades through the existing wiring.
  1. `test-db-drift` has `needs: [python, changed-paths]` and no `always()`, so it is SKIPPED.
  2. VAC-08, the repo-vs-TEST drift check, does not run on that commit.
  3. The `frontend` aggregator's `test-db-drift` arm errors on a skip for a push or a same-repo PR,
     so `frontend` goes red.
  4. On `main`, Railway waits on CI and skips the analytics deploy when CI is red.

Before this phase the same test was a steady SKIP on shared TEST, so none of this cascade could
fire. The ROADMAP already records that SC-3 cannot pass until Phase 164.9.3.2 DEFER40001 lands. The
code on this branch carries no merge interlock to enforce that order.

**Fix:** This is a merge-order fix, not a code change in this phase.

- **Do not merge PR #880 before Phase 164.9.3.2 lands.** After it lands, merge `origin/main` into
  the branch and take a fresh SHA-bound run of the merged tree.
- **Count a green `python` as SC-3 evidence only if the log shows
  `test_defer_compute_job_token_fence` as PASSED.** A green job with that test SKIPPED is the race
  landing on its silent side, not a pass.
- **Record the `e2e-seeded` verdict from the same run.** The contrast fix arrived through the
  merge and has not been measured on the lane.
- **Use neither in-phase workaround.** Widening `_rpc_retry_timeout`'s match to the 504 text, or
  raising Kong's timeout so httpx always wins, re-hides the loop, and the ROADMAP forbids both.
