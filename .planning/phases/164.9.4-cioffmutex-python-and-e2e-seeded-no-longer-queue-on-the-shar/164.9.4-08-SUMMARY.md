# Phase 164.9.4 Plan 08: e2e-seeded leaves the shared-TEST key Summary

**The ci.yml `e2e-seeded` job no longer takes the shared-test-db key or reads a shared-TEST secret. It boots a Supabase CLI local-stack lane private to its runner, asserts the handoff is loopback through `run.sh --assert-local-handoff`, exports the lane URL and masked keys through the job environment file, then seeds, builds, verifies the inline and runs the seeded specs against it, and tears the lane down. `ci.yml` now carries the key numeral zero times. Every pin that went red on the change moved in the same commit, and each was observed RED under a neuter.**

## Decisions Made

- The holder-set `it`'s `sql-tests` negative became part of the exactly-empty message and no longer stands as its own expect. The dated comment above the `it` records this.
- The six exports use one grouped `{ printf …; } >> "${GITHUB_ENV}"` redirect instead of six separate appends. The first line naming the environment file still falls after the seam call and before the seed step, which is the order plan 09's handoff-order pin reads.
- The removed acquire step's "NOTE on hold length" also carried a reason unrelated to the mutex: the seed runs before the build so the prerender sees the demo rows. That sentence now lives in the seed step's comment.
