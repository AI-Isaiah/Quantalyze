### WR-01: The docs-only push short path silently removes the backstop that `[CI-DOCSPATH-01]` relies on, and TODOS still asserts that backstop

**Files:**
- `scripts/classify-changed-paths.mjs:205-233` (`classifyPushRange`) and `:602-611` (the push
  branch in `main()`)
- `TODOS.md:9264-9270` (the `[CI-DOCSPATH-01]` entry, "BOTH HALVES" paragraph)

**Issue:**

- **What `[CI-DOCSPATH-01]` says.** It records a known exposure of the docs-only PR filter. Two
  vitest files read `.planning/` from disk and are hosted by `frontend-test`, which the filter
  skips:
  - `src/__tests__/lint-sql-gates.test.ts`, arm G3, reads `.planning/REQUIREMENTS.md` and
    `.planning/ROADMAP.md`;
  - `src/__tests__/verify-plan-anchors.test.ts` reads Phase 159's `159-VERIFICATION.md`.

  So a `.planning/`-only PR that breaks either one is not caught by its own board. The entry
  accepts that exposure on one stated ground. Detection is "DEFERRED, never LOST", because "it
  still fires twice — on the UNFILTERED merge push to `main` … and on the next code PR".
- **What round 1 changed.** The WR-01 fix classifies a `.planning/`-only push to `main` as
  `docs_only=true`. `frontend-test` carries `if: needs.changed-paths.outputs.docs_only != 'true'`,
  so on that push it is skipped too. The first of the two backstops is gone.
- **The consequence, traced through the aggregator.** Take a docs-only merge that breaks G3 or a
  plan anchor:
  1. The PR board is green, as the entry already accepts.
  2. The merge push to `main` is now a short run. `frontend-test` is skipped, and the uniform
     docs-only arm tolerates it, so `main` records a green run on a commit whose own corpus would
     be red.
  3. The red first appears on the next unrelated code PR (or code push). That change gets blamed
     for a failure it did not cause, which is the misattribution this repo's fail-loud-and-accurate
     rule counts as a real cost.
- **Why it matters beyond the docs.** The trade-off was never surfaced. The founder's 2026-09-27
  routing asked for a docs-only push to take the short path and still produce a recorded green
  run. It does not mention giving up this backstop. The entry was written on the premise that
  push-to-main is never filtered, and that premise is now false.
- **Re-verified at HEAD.** `TODOS.md:9265-9267` still reads "the UNFILTERED merge push to `main`
  (the `push: branches: [main]` trigger is deliberately not filtered, because every commit to main
  must produce its own recorded green run)". The classifier's own header and the
  `ci-docs-path-filter` contract test were each given dated corrections in round 1. This entry was
  not, which is the scope-amendment-touches-more-than-one-file trap.

**Fix:** Do not revert the push classification. The founder routed it. Make the trade-off
explicit and choose one of the two options below.

1. **Record it (minimum).** Add a dated correction to `[CI-DOCSPATH-01]` in `TODOS.md`, directly
   under the "BOTH HALVES" paragraph, and keep the original as lineage:

   ```markdown
   ⛔ **CORRECTED 2026-10-02 (Phase 164.9.4 review round 2): ONE backstop remains, not two.** Since
   the 164.9.4 WR-01 fix, a `.planning/`-only push to `main` is classified `docs_only=true`
   (`scripts/classify-changed-paths.mjs` `classifyPushRange`), so `frontend-test` is skipped on the
   merge push too and `main` records a GREEN short run. A docs-only merge that breaks
   `lint-sql-gates.test.ts` G3 or `verify-plan-anchors.test.ts` now surfaces ONLY on the next code
   PR or code push, which will read the red as its own. The paragraph above is kept as lineage.
   ```

   Surface the same sentence in the CONTEXT.md decision log and in the ROADMAP routed item, so the
   founder sees what the short path costs. This is the scope-amendment rule.

2. **Keep the backstop (if the founder prefers).** On a push only, keep `docs_only=false` when the
   pushed range touches a file that a `frontend-test` assertion reads. Today those files are
   `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md` and
   `.planning/phases/159-rank-public-ranking-integrity/159-VERIFICATION.md`. Add a self-test row
   that is RED against the current classifier. This keeps the founder's short path for the common
   `STATE.md` / `state.json` / `*-VERIFICATION.md` close-out merges. The cost is that the path
   list is hand-kept, so add a vitest pin that derives the list from the `.planning/` reads in
   those two test files, so the list cannot drift.
