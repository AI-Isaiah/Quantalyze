### ⛔ THE CHAIN THE OBSERVATION STANDS FOR — and why it terminates in a RED board

A neutered detector does not produce a red board; it produces a **green, short** one. That is why
the interesting chain is the one where the detector FAILS rather than lies:

1. A failing classifier makes the `changed-paths` job **red**. *(Not proven locally — GitHub's
   scheduler. See the limit below.)*
2. Every job carrying `needs: [changed-paths]` **skips** — a failed `needs:` job skips its
   dependents, which `ci.yml` already states verbatim in the `sql-tests` and `e2e-seeded` arms.
   *(Not proven locally — GitHub's scheduler.)*
3. `needs.changed-paths.outputs.docs_only` arrives as the **EMPTY STRING**, not `"false"`.
   *(Not proven locally — GitHub's scheduler.)*
4. The uniform arm's FIRST conjunct `[ "$docs_only" = "true" ]` is therefore **false** for every
   row. → **PROVEN, scenario S5.**
5. Every skipped row falls through to the strict default or to a pre-existing non-tolerant branch.
   → **PROVEN, scenario S5.**
6. The aggregator **exits 1**. → **PROVEN, scenario S5** (`expected an empty detector output to
   FAIL CLOSED`, exit 1, and the uniform arm's message absent from the output).

⛔ **Stated plainly: links 1–3 are NOT proven locally.** The contract test proves the aggregator's
SHELL behaves correctly under injected inputs; it does not prove GitHub produces those inputs.
That half is closed by the two real PRs in **plan 04**, and by nothing here.

The CALIBRATION block closes the OTHER direction — that the classifier itself can fail at all —
and it does so on **every CI run**, not once: it rebuilds both mutated copies from the file on disk
each invocation, asserts each mutation APPLIED before believing its red, and carries a non-vacuity
control requiring the unmutated copy to exit 0.
