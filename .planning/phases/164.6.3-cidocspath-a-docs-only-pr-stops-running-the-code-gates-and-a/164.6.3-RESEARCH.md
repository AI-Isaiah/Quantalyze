## Summary

The mechanism this phase needs is already in this repository three times over, and the cheapest correct design is to copy it rather than import anything. `scripts/check-version-bump.mjs` already computes a PR's changed-file list from a `git diff --name-only ${baseRef}...HEAD` against `origin/$GITHUB_BASE_REF`, already classifies that list into "planning-only" vs "not", already fails closed with a `MEASURE_FAIL` when it cannot read the base, and already carries a `--self-test` with five fixture cases — and it already runs successfully on fork PRs, because `actions/checkout` on a `pull_request` event materialises the merge ref inside the **base** repository, so `origin/main` is present regardless of where the head branch lives. That is the whole fork problem, already solved, in a job (`version-gate`) that is on the always-on list. A new `scripts/classify-changed-paths.mjs` built to the same shape needs no new third-party action, no new `permissions:` scope, no new secret, and no new pattern for a reviewer to learn.

The real work is not the detector, it is the `frontend` aggregator at `ci.yml:2193`. Its result loop's default arm sets `fail=1` on any non-`success` **including `skipped`**, so filtering jobs without teaching that loop turns every docs-only PR RED. Worse, two of its rows (`e2e-seeded`, `sql-tests`) already carry tolerance arms that fire *before* a naively-appended docs-only arm would, and both of those arms treat a skip on a same-repo PR as a hard failure by design. The uniform arm therefore has to sit at the **top** of the loop body, not the bottom, and it has to be scoped by a declared `ALWAYS_ON` row list so that a `plan-anchor-verify` skip can never be excused by it. That shape is one arm and one list — not a per-row tolerance — which is exactly what the four job headers that forbid per-row tolerances by name are protecting.

Two findings change the plan's scope beyond what CONTEXT.md records. First, **three** jobs take the shared-TEST mutex, not two: `python` takes key `61616158` at `ci.yml:3864`, and the job's own header says so verbatim — "Each CI run takes this lock THREE times (python ~7m, e2e-seeded ~8-9m …, sql-tests the balance)". The ROADMAP, the TODOS entry and CONTEXT.md all name only two. Second, **`frontend-lint` is not a pure code gate**: `npm run lint` runs `tsx scripts/check-planning-hygiene.ts`, a security gate that scans every tracked file for the founder's macOS username and absolute home paths on a PUBLIC repo, and whose header states that agents "routinely write absolute worktree and scratchpad paths into new planning artifacts". A docs-only PR is precisely the PR class that gate exists to catch. `frontend-lint` belongs on the always-on list, and adding it costs 70 measured seconds.

**Primary recommendation:** add one `changed-paths` job that runs `node scripts/classify-changed-paths.mjs` (built on `check-version-bump.mjs`'s idiom, allow-list = `.planning/**` only, fail-closed on every error and on an empty diff), put a single-line `needs: [changed-paths]` + `if: needs.changed-paths.outputs.docs_only != 'true' && <existing condition>` on the 16 filterable job keys, add ONE uniform arm at the TOP of the aggregator loop gated by an `ALWAYS_ON="plan-anchor-verify"` list, keep `plan-anchor-verify` / `secret-scan` / `version-gate` / `docs-link-check` / **`frontend-lint`** always-on, and pin the whole thing with an executing (not grepping) vitest contract test in the `src/__tests__/contracts/ci-anti-skip-gate.contract.test.ts` idiom that extracts the aggregator's shell body from `ci.yml` and runs it under injected result-and-flag scenarios.

### ⭐ The single-definition argument (recommended, and it is nearly free)

`scripts/check-version-bump.mjs:35-36` already defines "planning-only":

```js
  const nonPlanning = changedFiles.filter((f) => !f.startsWith(".planning/"));
  if (nonPlanning.length === 0) return defects; // planning-only PR: exempt by design
```

`[VERIFIED: scripts/check-version-bump.mjs:35-36]` — quoted verbatim.

CONTEXT.md forbids adding a *second exemption mechanism* to `version-gate`, and rightly. It does not forbid making the two definitions **provably identical**. Recommend: define the docs allow-list as exactly `.startsWith(".planning/")` and add a vitest arm asserting the two predicates agree over a shared fixture table. If a later phase widens one, the arm reddens. ⛔ Do NOT refactor `check-version-bump.mjs` to import the new module in this phase — that is a behavioural change to an always-on gate for no gain (Rule 3, surgical changes).

### Pattern 1: The detector job — copy `check-version-bump.mjs`'s shape

**What:** A standalone job whose only output is a boolean, computed by a repo-owned Node script with a fixture-driven self-test.
**When to use:** Whenever a workflow decision depends on the PR's diff.

```yaml
# Source: composed from the in-repo idiom at ci.yml:3570-3597 (version-gate)

    # `needs: [changed-paths]`, and a skipped `needs:` job SKIPS its dependents
```

### Pattern 2: The classifier — allow-list, fail-closed

```js
// Source: shape copied from scripts/check-version-bump.mjs:100-122
const DOCS_ONLY_PREFIXES = [".planning/"];   // ⛔ ALLOW-LIST. Never a deny-list.

export function judge(changedFiles) {
  if (changedFiles.length === 0) return false;        // empty diff ⇒ CODE
  return changedFiles.every((f) => DOCS_ONLY_PREFIXES.some((p) => f.startsWith(p)));
}

function main() {
  if (process.argv.includes("--self-test")) return selfTest();
  if (process.env.GITHUB_EVENT_NAME !== "pull_request") {
    emit(false, "not a pull_request — the push/dispatch corpus is never filtered (D: trigger scope)");
    return 0;
  }
  const baseRef = process.env.GITHUB_BASE_REF ? `origin/${process.env.GITHUB_BASE_REF}` : "origin/main";
  let changedFiles;
  try {
    // ⚠️ --no-renames: with rename detection, `src/x.ts -> .planning/x.md`
    // prints ONLY the destination, so a deleted code file would classify as
    // docs-only. check-version-bump.mjs carries this same hole today.
    changedFiles = git(["diff", "--name-only", "--no-renames", `${baseRef}...HEAD`])
      .split("\n").filter(Boolean);
  } catch (e) {
    console.error(`MEASURE_FAIL: could not read ${baseRef} — ${e.message}`);
    return 1;                                          // ⇒ job red ⇒ board red
  }
  emit(judge(changedFiles), `${changedFiles.length} changed file(s)`);
  return 0;
}
```

**Why the three-dot diff is fork-safe.** On a `pull_request` event `actions/checkout` checks out the GitHub-computed merge ref inside the **base** repository, so `origin/$GITHUB_BASE_REF` resolves regardless of where the head branch lives; `base...HEAD` is then the merge-base-to-head diff, i.e. exactly the PR's own changes. ⭐ This is not a theory: `version-gate` runs this exact computation on fork PRs today and is green `[VERIFIED: .github/workflows/ci.yml:3585 (`if: github.event_name == 'pull_request'` — no same-repo restriction) + scripts/check-version-bump.mjs:102-105]`.

### Pattern 4: The uniform aggregator arm — FIRST in the loop, scoped by a declared list

```bash

          # Phase 164.6.3 / CI-DOCSPATH-01 — the ONE uniform docs-only arm.
          # ⛔ This is NOT a per-row tolerance. It is one predicate driven by one
          # detector output, applied to every row EXCEPT the declared ALWAYS_ON
          # set. The four job headers above that forbid a per-row tolerance arm by
          # name (frontend-seam-redis, sql-gate-lint, sql-mutation,
          # frontend-local-stack) are not breached: none of them is given an arm
          # of its own, and on a CODE PR (docs_only != 'true') this block is INERT
          # and every row takes byte-identically the path it took before.
          docs_only='${{ needs.changed-paths.outputs.docs_only }}'
          # Aggregator rows the docs-only filter may NEVER skip. plan-anchor-verify's
          # whole subject is .planning/**, so a docs-only PR is the PR where it
          # matters most. A skip of THIS row is never excused here; it falls through
          # to its own strict arm below.
          ALWAYS_ON="plan-anchor-verify"
          echo "docs-only filter: docs_only='${docs_only}' always_on='${ALWAYS_ON}'"
          for r in \
            ...unchanged...; do
            name="${r%=*}"; result="${r#*=}"
            echo "$name: $result"
            case " $ALWAYS_ON " in *" $name "*) filterable=false;; *) filterable=true;; esac
            if [ "$docs_only" = "true" ] && [ "$filterable" = "true" ] && [ "$result" = "skipped" ]; then
              echo "$name: skipped by the docs-only path filter (changed-paths said docs_only=true); tolerated UNIFORMLY, not per-row."
            elif [ "$name" = "e2e-seeded" ]; then
              ...existing arms, byte-unchanged...
```

**Why FIRST and not last.** If the arm is appended after the three existing per-row arms, a docs-only PR hits `e2e-seeded`'s arm first, which computes `is_fork_pr=false` on a same-repo PR and sets `fail=1` — and `sql-tests`' arm does the same. The board would be RED on exactly the PRs this phase exists to speed up. Placing the arm first is required for correctness, and it is also the shape that makes the "one arm, not a per-row tolerance" claim true on inspection.

**Why it cannot green a code PR.** Three independent conjuncts must all hold: `docs_only = "true"` (false on any code PR, and empty-string when the detector failed), the row must not be in `ALWAYS_ON`, and the result must be exactly `skipped` — a `failure` or `cancelled` falls through to the pre-existing arms untouched.

### Anti-Patterns to Avoid

- **Appending the docs-only arm to the bottom of the loop.** Dead code behind `e2e-seeded` and `sql-tests`; reddens every docs PR. See above.
- **`if: ${{ needs.changed-paths.outputs.docs_only == 'false' }}`.** Fails open on a detector failure.
- **Putting the filter on `plan-anchor-verify`.** ⛔ Locked-rejected, and it is the one gate whose subject *is* the diff being filtered.
- **A deny-list of code paths.** Any new top-level directory would default to "docs" and silently skip the corpus. Allow-list only.
- **Folding the detector into `deps-cache` or `frontend-typecheck`.** CONTEXT.md permits it, but both are in the filtered set and `deps-cache` has zero dependents today; making them a `needs:` parent of 16 jobs reverses the dependency direction the file's comments rely on (`ci.yml:59-61`: "No downstream job `needs:` this"). Keep the detector standalone.
- **Breaking any job's `if:` across lines.** See Pattern 3.

## Common Pitfalls

### Pitfall 1: The aggregator reddens — it does not wedge. Fixing the named hazard leaves the real one live.
**What goes wrong:** A planner reads ROADMAP criterion 4 ("pending forever"), confirms there is no branch protection, ticks the box, and ships a filter that turns every docs-only PR RED via the aggregator's strict default arm.
**Why:** `ci.yml:2434-2436` — `elif [ "$result" != "success" ]; then fail=1` — treats `skipped` as failure, and the aggregator is `if: always()` so it always runs to deliver that verdict.
**Avoid:** The uniform arm, placed FIRST. Scenario S1 in the contract test is the proof.
**Warning sign:** a docs-only PR whose only red check is `frontend`.

### Pitfall 2: Appending the uniform arm after the existing per-row arms
**What:** `e2e-seeded`'s and `sql-tests`' arms run first and set `fail=1` on a same-repo docs PR, so the new arm is unreachable for exactly the two rows that matter most.
**Avoid:** arm FIRST, `ALWAYS_ON` list for the exception. Scenario S7 catches it.

### Pitfall 3: ⚠️ THREE jobs take the mutex, not two — `python` is the one everyone forgets
**What:** ROADMAP, TODOS and CONTEXT.md all say `e2e-seeded` and `sql-tests`. `python` takes key `61616158` at `ci.yml:3864` and holds it for ~7 minutes. Its own header states it `[VERIFIED: .github/workflows/ci.yml:3656-3658]`:

> "158-REVIEW CR-04 — why 90 and not 60. Each CI run takes this lock THREE times (python ~7m, e2e-seeded ~8-9m across build + the Playwright batch, sql-tests the balance) ≈ 20m of lock-time per run."

Confirmed empirically: the log archive for run `34717952454` contains three distinct acquires (5s, 340s, 615s).
**Why it matters:** `python` must be in the filtered set (it is), and criterion 5's evidence must account for **three** absent acquires, not two. A SUMMARY claiming "the two mutex holders" repeats an error this research corrects.
**Avoid:** filter `python`; state "three" in the plan, the PR body and the CHANGELOG.

### Pitfall 4: `frontend-lint` is not a pure code gate
See §Which Jobs Get the `if:`. A filter that skips it makes the planning-hygiene leak gate blind to the exact PR class it was built for, on a public repo.

### Pitfall 5: `frontend-test` hosts two arms whose subject is `.planning/**` content
`src/__tests__/lint-sql-gates.test.ts:161` reads `.planning/REQUIREMENTS.md` and `.planning/ROADMAP.md` and fails if a planning sentence still claims "five shapes" `[VERIFIED: src/__tests__/lint-sql-gates.test.ts:161]`. `src/__tests__/verify-plan-anchors.test.ts:782` reads a real `.planning/phases/159-…/159-VERIFICATION.md` `[VERIFIED: src/__tests__/verify-plan-anchors.test.ts:782]`.
**Consequence:** a docs-only PR that reintroduces the forbidden sentence, or deletes that VERIFICATION file, will not be caught until the next code PR.
**Severity:** deferred detection, not lost detection — the next code PR (or the merge push, which is unfiltered) reddens. ⛔ Do NOT "solve" this by widening the always-on set to `frontend-test` (379 s + 333 s — that is most of the saving) or by moving the tests (out of scope). **NAME IT in the SUMMARY and in a `ci.yml` comment**, and route it to a follow-up if the planner judges it worth one. Naming a known limit is this repo's house style; discovering it later is the defect.

### Pitfall 6: Rename detection hides a deleted code file
`git diff --name-only` with rename detection prints only the destination path, so `src/x.ts → .planning/x.md` classifies as docs-only while deleting a source file. Pass `--no-renames`. ⚠️ `check-version-bump.mjs` carries this same hole today; do not fix it there in this phase (surgical changes), but note it.

### Pitfall 7: Breaking an `if:` across lines
`src/__tests__/critical-regressions.test.ts:758-762` matches `e2e-seeded`'s `if:` with a single-line regex. See Pattern 3.

### Pitfall 8: `'' == 'false'` fails open
Use `!= 'true'`. See Pattern 3.

### Pitfall 9: The merge push still pays full price — say so
CONTEXT.md locks the `push: main` trigger as unfiltered. Every docs-only change therefore still runs the full 4,760 s corpus once, on merge, and still takes the mutex three times there. **The claimable saving is the PR-side run only.** A SUMMARY claiming the whole 3,001 (or 4,760) job-seconds would be false.

### Extracting and executing the aggregator loop (the Layer-2 harness)

```ts
// Source: src/__tests__/contracts/ci-anti-skip-gate.contract.test.ts:42-68 (verbatim shape)
function extractRunScript(yml: string, stepName: string): string {
  const lines = yml.split("\n");
  const start = lines.findIndex((l) => l.trim() === `- name: ${stepName}`);
  if (start === -1) {
    throw new Error(`ci.yml has no step named "${stepName}". …`);   // ← the CALIBRATION property
  }
  const runIdx = lines.findIndex((l, i) => i > start && l.trim() === "run: |");
  if (runIdx === -1) throw new Error(`step "${stepName}" has no "run: |" body`);
  const indent = lines[runIdx].length - lines[runIdx].trimStart().length;
  const body: string[] = [];
  for (const line of lines.slice(runIdx + 1)) {
    if (line.trim() === "") { body.push(""); continue; }
    if (line.length - line.trimStart().length <= indent) break;
    body.push(line.slice(indent + 2));
  }
  return `${body.join("\n")}\n`;
}
```
⚠️ **This phase's target step differs from the anti-skip gate's in one way that matters:** the aggregator body contains `${{ … }}` expressions (`needs.*.result`, `github.event_name`, and the new `needs.changed-paths.outputs.docs_only`). The harness must substitute them from the scenario record **before** `spawnSync`, and must assert that the substitution consumed every `${{` it found — an unsubstituted expression left in the script is a silent vacuity (the shell would see a literal and the scenario would not be the scenario).
