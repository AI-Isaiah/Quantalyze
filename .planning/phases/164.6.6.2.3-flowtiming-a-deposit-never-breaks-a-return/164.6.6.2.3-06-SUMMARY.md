# Phase 164.6.6.2.3 Plan 06: MT5 writer basis, so the allocator compose stays exact Summary

The MT5 key-mode derive now stores `composed_day_pnl` and `composed_flows` through the existing `writer_basis_payload` serializer, so the compose's existing writer-mode roll reproduces the writer's levels whatever return convention the stored returns use; on the MM-2x timed deposit day the replayed prior level is exactly 0.1 where the legacy inversion gave 0.1099.

## What changed

**`analytics-service/services/job_worker.py`** (no `allocator_equity_*` module touched)
- `WRITER_BASIS_VENUES` is `frozenset({"deribit", "mt5"})`, comment rewritten: why MT5 joined (position-relative returns cannot be inverted by the legacy roll; D-14 compose code unchanged) and that both readers change on purpose.
- USD MT5 key-mode branch: `_composed_flows_usd = nav_twr._flows_to_daily_usd(external_flows)`, built from the same `_mt5_flow_by_day` the payload's `flows` field comes from (one summing rule, the one `mt5_day_pnl` itself uses). The day P&L is `mt5_day_pnl`, already `_day_pnl_usd`. The payload block's comment no longer says MT5 never sets the basis.
- Native-unit (BTC) key: `_NativeKeyUsd` gains `composed_day_pnl` and `composed_flows`; new `_native_key_usd_writer_basis` builds, for every calendar day from the first NAV day to `priced_through`, `L_d = native realized level (carried over quiet days) x that day's own close`, `F_d = native flow x its own close`, and `composed_day_pnl = nav_twr.level_day_pnl(L, F, prev0)` with `prev0` the fold's native pre-first-day capital (`N_0 - P_0 - f_0`, about 0 on a full history) priced at the first day's close. Any missing close on that calendar sets both to `None` (never a neighbour's close); an interior hole sets both to `None`.
- A new local `_composed_day_pnl_usd` carries the native key's basis P&L, so `dropped_day_pnl` keeps its current source (native P&L x close) and `writer_basis_payload` receives the level-identity pair.
- Holed native key with `flow_timing_timed_days > 0`: `segment_terminals` is stored empty (counts-only warning naming `key_inputs_mismatch` and this plan), so the compose's existing "hole whose terminal is missing is not guessed" rule composes it unsplit and raises `key_inputs_mismatch`.

**`analytics-service/tests/test_allocator_equity_writer_basis.py`**: 76 -> 87 tests.

## Deviations from Plan

**1. [Interpretation] Test scale.** The plan's compose-exactness test says "an MM-2x-shaped deposit day (prior level 0.1)". A 0.1 USD base is under the USD dust floor ($1000), so a USD key's day would be dust-guarded, not measured. The shape (prior level / deposit / P&L = 0.1 / 1.0 / 0.011) is scaled x100000 into dollars (`_MM2X_USD_SCALE`); every figure above is stated as a fraction of the book, so "0.1 against 0.1099" holds at any scale. The native BTC key path uses the unscaled BTC shape's logic with its own hand figures.

**2. [Interpretation] More days in the tracer ledger.** The derive refuses a ledger with fewer than two usable return days, so the tracer has two ordinary trading days after the deposit day. The deposit day is still the only one the legacy inversion gets wrong.

**3. [Interpretation] "Absence" of `segment_terminals`.** The withholding stores `segment_terminals: []`, which is the exact shape every hole-free key stores today and reads identically in `read_native_key_inputs`. The hole+timed test asserts the empty list beside non-empty `unpriced_days`, and the hole+no-timed-day test asserts the terminal is present for the same fixture shape.

**4. [Scope] Tests live in one file.** The plan lists `test_mt5_derive_branch.py` and `test_derive_allocator_equity_job.py` in `files_modified`; all new tests are in `test_allocator_equity_writer_basis.py` (importing the existing helpers `_derive_mt5_key`, `_hole_deals`, `_btc_closes_on`, `_mm2x` timed-deal builders), and neither listed file needed an edit. The existing MT5 and BTC derive tests pass unchanged.

**5. [Process] Branch namespace.** The pre-commit allow-list expects `agent-*` branches; this worktree is the orchestrator-named `wt/164.6.6.2.3-p06` (attached HEAD, not protected/default, cwd sentinel checked). Committed on it as plans 01, 03, 05 and the caller directed.

## Known limits (recorded, not fixed)

- A flow persisted on a day later than `priced_through` would make a basis-mode replay a `writer_basis_mismatch` (blocking), exactly as it already makes the legacy replay a `realized_terminal_day_mismatch`. The basis builder filters its own flows to `<= priced_through` so it never raises; the loud outcome is the existing one.
- The withholding rule keys on `flow_timing_timed_days > 0` anywhere in the ledger, not on a timed day inside a specific segment. Conservative on purpose: a holed key with any timed day is blocked rather than guessed.
