services/mt5_parity_findings.py (new; imports only stdlib, services.mt5_parity, services.mt5_parity_capture, services.nav_twr and services.parity_diff):
- `FlagClass = Literal["explained_acceptable", "defect", "unknown"]`
- `MARKS_KEYS: Final[tuple[str, ...]] = ("marks_since", "marks_covered_from", "marks_trailing_since", "mark_gap_days")`
- `FLAG_CLASSIFICATION: Final[Mapping[str, FlagClass]]`, built from the tuples:
  - every NAV_TWR_GUARD_KEYS and NAV_TWR_LEGACY_GUARD_KEYS key maps to defect;
  - every NAV_TWR_ANNOTATION_KEYS key maps to explained_acceptable;
  - marks_since, marks_covered_from, marks_trailing_since, cumulative_method and native_unit map to explained_acceptable.
  - mark_gap_days is NOT in the table: it is value-dependent. An empty list is explained_acceptable; a non-empty list is a defect.
- `classify_flag(key: str, value: object) -> FlagClass`: unknown for any key outside the table and outside mark_gap_days.
- `FlagReading` is a frozen dataclass(slots=True) with `account_label`, `key`, `flag_class` and `computed_at_minute`.
- `classify_account_flags(label: str, analytics_row: Mapping[str, Any]) -> tuple[tuple[FlagReading, ...], tuple[Finding, ...]]`. It reads `data_quality_flags`, `computation_status` and `computed_at`. Each defect or unknown key becomes a Finding of kind `flag`. A `complete_with_warnings` status with no key from NAV_TWR_GUARD_KEYS or NAV_TWR_LEGACY_GUARD_KEYS becomes a Finding of kind `flag`, subject `computation_status`, bucket `unknown`.
- `Finding` is a frozen dataclass(slots=True):
  - `id`: `F-155-NN`, assigned by `number_findings` after a deterministic sort on (kind, account_label, subject);
  - `kind`: `flag` | `surface` | `cross_store`;
  - `subject`: a flag key, `<surface>.<figure>`, `<surface>.state` or `cross_store`;
  - `account_label`;
  - `bucket`: a member of mt5_parity.BUCKET_LABELS for surface and cross_store findings; `defect` or `unknown` for flag findings;
  - `lead`: a one-sentence root-cause lead built from a template. It names keys, surface ids, symbols, ISO dates, day counts and ratios via ratio_3sf, and never a raw figure.
- `Observation` is a frozen dataclass(slots=True) with `account_label`, `surface` and `reason` (`not_rendered_while_unpublished`, `not_applicable:<reason>`, `not_compared:unit_view`).
- `ANNUALIZATION_MATCH_SIG_FIGS: Final[int] = 3`
- `matches_reannualization(a: float, b: float) -> bool`: true when ln(1+a)/ln(1+b) or its inverse equals REANNUALIZATION_FACTOR at ANNUALIZATION_MATCH_SIG_FIGS. This is the CAGR basis shift parity_diff documents: `(1+new) = (1+old)^(365/252)`. It is false on a, b <= -1, a zero log, or a == b.
- `matches_sharpe_reannualization(a: float, b: float) -> bool`: true when a/b or b/a equals sqrt(REANNUALIZATION_FACTOR) at the same s.f. It is false on a zero or a == b.
- `classify_matrix(matrix: Mapping[str, Any]) -> tuple[tuple[Finding, ...], tuple[Observation, ...]]`. Per account, the reference is the `factsheet` cell; when that is not state value, the reference is the first owner_visible value cell in surface-id order, and the lead names which. Rules:
  - A cell with visibility not_rendered_while_unpublished is an Observation only.
  - not_applicable is an Observation.
  - same_as is skipped (it is the same computation).
  - error is a Finding: `<surface>.state`, bucket unexplained, lead naming the symbol and the error class from `reason`.
  - A value cell whose unit_view differs from the reference's is an Observation `not_compared:unit_view`.
  - cumulative_return and max_drawdown: |a − b| > MT5_PARITY_TOLERANCE is a Finding, bucket unexplained.
  - last_return_date: unequal is a Finding, bucket unexplained, lead "series ends on a different day".
  - cagr: when both figure_states are shown and |a − b| > MT5_PARITY_TOLERANCE, matches_reannualization gives bucket annualization_convention; otherwise the bucket is unexplained.
  - sharpe: when both are shown and ratio_3sf(a) != ratio_3sf(b), matches_sharpe_reannualization gives annualization_convention; otherwise unexplained.
  - A figure_state of withheld or short on one owner-visible value cell and shown on another, for the same figure, is a Finding `<surface>.<figure>` with bucket unexplained and lead "figure gate disagrees across surfaces". When every owner-visible value cell withholds the figure, that is consistent and produces no finding (withheld_by_gate passes here, as plan 01 reserved).
  - cross_store.days_differing > 0 is a Finding of kind cross_store, bucket unexplained. The lead names days_differing of days_compared and first_differing_day.
- `LabelMissing(ValueError)`: a census or matrix ordinal with no label.
- `MatrixMismatch(ValueError)`: the matrix's account labels differ from the capture's labels.
- `render_census_markdown(census_rows: Sequence[Mapping[str, Any]], edges_rows: Sequence[Mapping[str, Any]], labels: Mapping[str, str]) -> str`
- `render_findings_markdown(findings, observations, flag_readings, mode: str) -> str`
- `ScanProfile = Literal["record", "fixture"]`
- `scan_tracked_text(text: str, profile: ScanProfile = "record") -> tuple[str, ...]`: the sorted rule names that hit, never the matched text.
  - Rules: `uuid` (the synthetic zero pattern `00000000-0000-4000-8000-` is exempt), `home_path`, `digit_run_5`, `long_hex`, `sig_figs_gt_3`, `thousands_separated`.
  - The fixture profile runs uuid and home_path only. Fixtures legitimately carry synthetic amounts.
  - `sig_figs_gt_3` exempts the repo's phase-id shape, a three-digit integer followed by one or more single-digit dot groups (155.1, 155.2, 164.6.6.2.1). The census server literal names 155.1 and the ledgers name 155.2, and ratio_3sf can never emit that shape, since a three-digit value renders with no decimal.

scripts/mt5_parity_records.py: `main(argv: Sequence[str] | None = None) -> int`, a thin argparse wrapper run as `cd analytics-service && python3 -m scripts.mt5_parity_records <subcommand>` (the scripts-package precedent, e.g. scripts.backfill_btc_benchmark), with subcommands:

- Exit codes: 0 ok, 1 scan hit, 2 input refusal (prints the exception class and message to stderr).
