3. `mt5_parity.py`. Implement the constants, `LegResult`, `ExplainerContext`, `EXPLAINERS`, `classify_breach`, `Window`, `gate_b_legs`, `AccountVerdict`, `Verdict`, `evaluate_account`, `verdict_to_json`, `render_verdict_markdown` and `ratio_3sf`.
   - Leg arithmetic per D-B. E is equity in the account unit, and oracle equity at an edge is the worksheet reading with id `statement_equity` or `weekend_close_equity` whose `as_of` equals the edge date.
     - start_level gap = |E_ours(start) − E_oracle(start)| / E_oracle(start)
     - end_level gap = |E_ours(end) − E_oracle(end)| / E_oracle(start)
     - cum_return carries two gaps and passes only when BOTH are within tolerance:
       - the money gap |(E_ours(end) − E_ours(start)) − (E_oracle(end) − E_oracle(start))| / E_oracle(start);
       - the curve gap |r_curve − (E_oracle(end)/E_oracle(start) − 1)|, where r_curve is the product of (1 + r) over our stored daily returns dated in (start, end], minus 1.
       Record the larger of the two as the leg's gap.
     - A leg passes when gap <= MT5_PARITY_TOLERANCE (inclusive).
   - Any missing input makes that leg `passed=False, gap=None, reason="not_measurable:<input>"` (fail closed, never a pass): no mark on the edge, no reading, no returns.
   - `evaluate_account`: if every leg passed, the bucket is WITHIN_TOLERANCE. Otherwise call `classify_breach`.
   - The one explainer registered here is EDGE_INSTANT_MISMATCH. It matches when a breaching level leg's edge mark has a `marked_at` outside [Friday edge date + WEEKEND_ATTESTED_FROM_UTC_HOUR, Sunday + WEEKEND_ATTESTED_TO_UTC_HOUR] UTC.
   - `classify_breach` loops over every EXPLAINERS entry, collects the matches, and returns `(matched[0], tuple(matched))` if any matched. After the loop it returns `(UNEXPLAINED, ())`.
   - `AccountVerdict.passed` is true only when the bucket is in PASSING_BUCKETS and no leg carries a not_measurable reason. A `withheld_by_gate` engine bucket never passes here; it passes only in the plan 08 matrix.
