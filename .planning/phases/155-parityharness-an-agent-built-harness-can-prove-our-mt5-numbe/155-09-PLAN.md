<objective>
The MT5-09 data layer (success criterion 5 of this phase, pre-verification for 155.2). For every account, run each live surface's own TypeScript computation on its own stored input, then record a headline tuple per surface:
- cumulative return over the full record;
- last return date;
- CAGR, Sharpe and max drawdown;
- the figure-gate state.

The output is `surface-matrix.json`. Classification of cross-surface differences happens in Python (plan 08), so `MT5_PARITY_TOLERANCE` keeps one definition.

Purpose: the founder's 155.2 render check starts from a data layer already measured, and any two-store or surface-specific divergence is a named finding before he sits down.
Output: `src/__tests__/mt5-parity-surfaces.test.ts`.

Surface list per CONTEXT (founder decision "All live surfaces"), each cited by symbol, as RESEARCH Slice A corrected it at HEAD:
- "Strategy detail" is the factsheet page. `(dashboard)/strategies/[id]/` holds only edit and a layout guard.
- The composer's route and the owner list are owner-visible while unpublished.
- The share card, both factsheet PDFs and the Discovery list are published-only.
- `StrategyTable.tsx::gatedMetric` and `strategies-row-adapter.ts::gatedSharpe` are file-private:
  - gatedSharpe is reached through the exported `toStrategyRows`, which calls it;
  - gatedMetric's one-line composition, `gatedValue(analytics[key], gateAnnualized(rowRecord(row)))`, is rebuilt from the exported `gatedValue`, `gateAnnualized` and `rowRecord`.
  Nothing is exported to make this possible. No UI file changes.
</objective>

- `cross_store`: `{"days_compared": int, "days_differing": int, "first_differing_day": "YYYY-MM-DD" | null}`. It compares the strategy_analytics daily-return series (via resolveDailyReturnSeries) with the per-key csv_daily_returns, using exact equality.

  - `discovery_card`: the same row shaping as owner_list_card
