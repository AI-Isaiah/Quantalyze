Before anything else, run `node scripts/verify-plan-anchors.mjs` on this plan file and stop if it exits non-zero.

Every file follows the same rules:
- one statement starting WITH or SELECT, ending in exactly one `;`;
- no `--` comment anywhere, and no uuid literal;
- schema-qualify every table as `public.<t>`;
- read "today" as `(now() AT TIME ZONE 'UTC')::date`, never `current_date`, so plan 04's frozen `public.now()` shadow reaches it;
- never select `venue_account_id` or `api_keys.label`.

Every file starts from the same key CTE: the MT5 keys `public.api_keys WHERE exchange = 'mt5'`, ordinal-labelled `'k' || row_number() OVER (ORDER BY created_at, id)` as `key_ordinal`, including disconnected keys so ordinals stay stable. A key's strategies are `public.strategies WHERE api_key_id = key.id`.

1. `marker.sql`: a byte-for-byte copy of `docs/runbooks/marksource-okx-census/marker.sql`.
2. `bind.sql`: one row per key ordinal with these columns:
   - `key_ordinal` and `api_key_id` (the id is capture-dir only, so the loader can prove the ordinal-to-key map did not move);
   - `analytics_rows` and `analytics_max_computed_at` over the key's strategies' strategy_analytics rows;
   - `marks_count` and `marks_max_created_at` from api_key_nav_marks;
   - `key_inputs_computed_at` from allocator_equity_derived with kind = `'key_inputs:' || key.id::text`;
   - `returns_count` and `returns_max_updated_at` from csv_daily_returns where api_key_id = key.id or strategy_id in the key's strategies;
   - `equity_curve_computed_at` from allocator_equity_derived kind `equity_curve` for the key's user_id;
   - `holdings_max_updated_at` from allocator_holdings for the key.
   ORDER BY key_ordinal.
3. `census-accounts.sql`: one row per key ordinal, then a final summary row UNION ALL'd with `key_ordinal = 'all'`, `keys_examined = count of MT5 keys`, and every other column NULL. With zero MT5 keys the summary row still prints `keys_examined = 0`, so an empty census never reads as a query that matched nothing (the marksource SF-M5 precedent). Columns, in this order:
   - `key_ordinal`, `keys_examined` (NULL on per-key rows), `account_currency`;
   - `native_unit_marked`: true when any of the key's marks has a non-null native_unit;
   - `strategies_linked` (count), `strategy_statuses` (sorted text array of strategies.status), `asset_classes` (sorted distinct text array), `strategy_key_windows` (count of strategy_keys rows for the key);
   - `s_raw_marks`: min(mark_day) over the key's marks;
   - `s_key_inputs`: key_inputs payload ->> 'marks_since';
   - `s_flags`: data_quality_flags ->> 'marks_since' of the key's single non-archived strategy's analytics row, NULL when there is not exactly one;
   - `s_agree`: true only when all three are non-null and equal as dates;
   - `mark_count`, `last_mark_day`;
   - `first_return_date`, `last_return_date`: the first and last element date of returns_series when it is a jsonb array, else of daily_returns;
   - `returns_series_len`, `daily_returns_len`: jsonb_array_length when an array, else NULL;
   - `record_observations`: metrics_json ->> 'record_observations';
   - `record_span_days`: last_return_date::date minus first_return_date::date;
   - `computed_at`, `computation_status`, `computation_warned`, `series_completeness`;
   - `keys_sharing_login`: the count of OTHER mt5 keys whose venue_account_id equals this key's, computed inside the statement so the login is compared but never output;
   - `key_inputs_present` (bool), `first_flow_present` (bool: composed_flows holds at least one row);
   - `identity_ratio`: (payload realized_terminal_usd − sum of composed_day_pnl pnl_usd − sum of composed_flows flow_usd) divided by the absolute flow_usd of the earliest composed_flows row by utc_day_iso. NULL when key_inputs is absent or that flow is 0;
   - `identity_days`, `identity_flow_days`: row counts of composed_day_pnl and composed_flows;
   - `flag_keys`: a sorted text array of jsonb_object_keys(data_quality_flags) from the same single analytics row;
   - `server`: the literal text `unmeasured (155.1 reading owns it)` (founder decision "Shared server: measure it": the server travels inside the encrypted credential, so SELECT cannot read it).
   ORDER BY key_ordinal, with the summary row last.
4. `census-edges.sql`: for each key with marks, one row per Friday from the first Friday on or after min(mark_day) through the last Friday on or before today − 1. Use generate_series over dates and filter ISO day-of-week 5, so every Friday since S is listed rather than two hard-coded dates (RESEARCH Pitfall 4). A key with no marks gets one row with `friday` NULL and `mark_present` false. A final summary row `key_ordinal = 'all'` carries `rows_examined` = the count of per-key rows. Columns:
   - `key_ordinal`, `friday`, `mark_present`;
   - `open_pnl_ratio`: open_pnl_native/nav_native when native_unit is set, else open_pnl_usd/nav_usd; NULL when absent or the nav is 0;
   - `marked_at`;
   - `hours_after_utc_midnight`: extract(epoch from marked_at − date_trunc('day', marked_at AT TIME ZONE 'UTC') AT TIME ZONE 'UTC') / 3600;
   - `rows_examined`.
   The weekend-window judgement stays in Python (`WEEKEND_ATTESTED_*` in services/mt5_parity.py), so the constant has one definition.
5. `README.md`, after the marksource README's structure:
   - Purpose (PARITY-04, PARITY-03, Phase 155).
   - A table naming `marker.sql`, `bind.sql`, `census-accounts.sql` and `census-edges.sql` in backticks, each with what it measures. State that the census-accounts identity and flag columns cover what RESEARCH called census-inception and census-flags.
   - "How to run": the phase orchestrator only, through the Supabase MCP, `marker.sql` first, continue only if the answer names PRODUCTION, one query per call, results written as the returned JSON array to `raw/<stem>.json` inside the gitignored capture directory. Executors never run these files against PROD.
   - "What may be written down": tracked text gets ordinals, labels MM2, MM3 and FX-AI_V, day counts, dates, ratios to 3 significant figures and verdicts. Raw rows stay in the capture directory.
   - The server literal and why.
   No markdown links (lychee checks this tree offline), no planning-tree path, no home path.
