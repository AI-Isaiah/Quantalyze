## Deviations from Plan

**1. [Plan premise, test design] Neuter (b)'s "SOL appears" does not hold, so a second fixture pair carries it.**
The plan expected the OKX old/new pair to go RED when the reader's same-account filter accepts every key with rows. Measured: it stays GREEN (8 of 8). Plan 07's `derivePhase07Fields` also applies `oneKeyPerAccountDay` to the dollar rows, and the departed key's older-day SOL row loses to the new key's newer day there, so the derive masks the reader's rule for that shape. The reader's rule is only load-bearing when the replacement key wrote NO row, so nothing in the derive can outrank the old key's rows. Added `key-bybit-old` (departed, `acct-Y`, LTC 3,000 on 2026-09-15) and `key-bybit-new` (same account, no rows, clean empty poll dated 2026-10-02); with the neuter, LTC appears and the mixed book goes RED. The OKX pair is kept as the plan wrote it: it pins the combined outcome. No production change; this is a test-design correction.

**2. [Plan shape] Task 1's neuter note says the poll supersession alone; the mixed-book case also fails under it** (its Deribit book rides the same clean poll). Expected, recorded for honesty: T1 is two RED tests, not one.
