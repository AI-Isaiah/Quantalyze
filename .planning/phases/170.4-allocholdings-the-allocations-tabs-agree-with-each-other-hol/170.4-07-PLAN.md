<objective>
Implement D-08 ("One Key is One Strategy") at the source and apply D-10's one-account-once rule to the
dashboard's dollars, while the Scenario fingerprint keeps the row set the commit RPC recomputes.

Purpose: `derivePhase07Fields` keeps one row per `holdingScopeKey` (venue:symbol:type), so two live keys
holding one symbol lose one key's position. Keying per key fixes that, and once plan 09 lets two keys of one
account keep same-day rows, plan 11's rule must keep the dollars counted once. The fingerprint is a
separate contract with `commit_scenario_batch` (plan-checker N2): narrowing it would refuse every book-mode
commit by an allocator with such a pair, so it reads the un-narrowed rows.
Output: the per-key derive with the account-day rule, the fingerprint row set, the Scenario helpers and hook
wiring, and their tests.
</objective>
