<objective>
Gap closure for founder D-06 (CONTEXT, 2026-10-10), compose half: "the writer stores its own composed flows and day P&L and the allocator compose reads them (RESEARCH 6.4)". Plan 10 stores them; this plan makes the compose roll on them so its implied start matches the writer's prev0.

Stitching, read from code at planning time (`job_worker.py`, the kept-key choice before `stitch_sources`): a shared account's kept key is the working member with the EARLIEST first return day, and only members that start STRICTLY earlier (eligible but not working, e.g. `sync_status` `error`) are stitched onto it. Members with the same first return day are excluded, not stitched. The plan still handles the stitched case at the account level, because PROD's allocators were not measured member by member.

Purpose: plan 06 Task 1 measured on PROD, all from one key_inputs row per key: compose implied start c = 0.01311 of the first-return level, writer prev0 / first_nav = -8.525e-09 under both the current wedge and the balance anchor. The compose rebuilds the writer's NAV from other numbers (event-time USD flows, stored returns, the dropped days), and the gap accumulates over the account's history. Rolling on the writer's own flows and day P&L makes each step the writer's identity, so the levels, and therefore the inception check, are the writer's.
Output: a writer-basis mode in `replay_key_equity`, its threading through `compose_allocator_equity` and the compose job's key_inputs reader, the measured-shape end-to-end test and its guards.

No migration (the fields are JSONB payload keys, plan 10). No TypeScript change: the `equity_curve` payload shape is unchanged.
