# Phase 167.1.2.2.1 Plan 10: the Deribit writer stores its own composed flows and day P&L (D-06, writer half) Summary

**Every Deribit key-mode NAV-path derive now stores `composed_flows` (native flow quantity x the day mark, non-zero days) and `composed_day_pnl` (`NAV_t - NAV_{t-1} - F_t`, every NAV day) in its `key_inputs` payload, read off the same levels the stored returns are chained from, and a new reader hands them back as two day-keyed maps.**

`PLAN_BASE` is `35accc310cc8894e815639b7aeb077385b4cdbd4`. `commits: 3` is measured with `git rev-list --count`, taken before this SUMMARY's own commit. `DW_SP` was the scratch directory outside the repo. Nothing is shipped; the code goes in PR-2.

## Contract for plan 11 (exact names)

- `key_inputs` payload fields, Deribit key-mode NAV path only:
  - `composed_flows`: `list[{"utc_day_iso": "YYYY-MM-DD", "flow_usd": float}]`, one row per day with a non-zero flow (USD = native quantity x that day's mark).
  - `composed_day_pnl`: `list[{"utc_day_iso": "YYYY-MM-DD", "pnl_usd": float}]`, one row per NAV day (`NAV_t - NAV_{t-1} - F_t`, day 0 against the prior capital `prev0`).
  - The two always travel together. They are stored only when `realized_terminal_usd` / `realized_terminal_day` are stored too, so a row that carries them always carries the terminal the compose rolls back from.
  - The writer's identity, held by the stored values: `realized_terminal_usd = prev0 + sum(composed_day_pnl) + sum(composed_flows)`.
- Reader, in `analytics-service/services/allocator_equity_derive.py`:
  - `read_writer_basis(payload: Mapping[str, Any]) -> tuple[dict[str, float], dict[str, float]] | None`
  - returns `(flows_by_day, pnl_by_day)`, each `{ISO day: USD float}`, or `None` when both fields are absent or null (a row written before D-06).
  - raises `ValueError` on: only one of the two present or non-null, a field that is not a list, a row that is not a mapping or lacks `utc_day_iso` / its amount key, a non-ISO day, a repeated day, a boolean or non-numeric amount, a non-finite amount.
- Writer-side helpers: `writer_basis_payload(day_pnl: pd.Series, composed_flows: pd.Series) -> dict[str, Any]` (raises `NavReconstructionError`, counts-only message, on a non-finite value), `native_nav.native_composed_flows(ledger, *, indexable_currencies, venue="")`, `broker_dailies.native_ledger_composed_flows(ledger, indexable)`.
- Unchanged: the event-time `flows` field (`usd_signed`), every other payload field, the MT5 and ccxt payloads.
- The pre-existing pin tests need nothing from plan 11 beyond the patch entry already added in the three shared harnesses (below).

## Task 1: the tracer (D-06)

`test_the_deribit_derive_stores_its_composed_flows_and_day_pnl` runs a zero-start BTC book (`_btc_book`: marks moving every day, BTC deposits on day 0 and on day 2, the second after the first return day) through `run_derive_broker_dailies_job` key-mode with the REAL combine, day-P&L, terminal and composed-flows functions. Each deposit's event-time `usd_signed` is quantity x mark x 1.013, so the event-time `flows` field and the composed flows differ by construction. It asserts against an exact `Fraction` forward build: composed flows equal `qty x mark` on exactly the two deposit days; one `composed_day_pnl` row per NAV day equals `NAV_t - NAV_{t-1} - F_t` (relative 1e-12, absolute 1e-9); `realized_terminal_usd` equals the `fsum` of both stored series (prev0 is 0); the `flows` field still carries the `usd_signed` values; `read_writer_basis` returns the same two maps.
