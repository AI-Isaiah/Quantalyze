## Focus questions

- **Admin-only?** Yes. Same-origin check, then session, then `isAdminUser`, all before the service-role client is constructed. Non-admin gets 403 with the admin client never built (F3).
- **Leak to non-admins?** No path. The payload is kind names only; `compute_job_kinds` is in any case SELECT-able by `authenticated` under RLS (migrations 20260411144407, 20260516104201), so the names are not secret.
- **Probes bounded?** Per-request cost is bounded by the registry size (one `limit(1)`, `id`-only query per row). The registry is writable only by migration or service role (authenticated has SELECT only; service_role has ALL), so a request cannot grow it. The `Promise.all` is not capped, which is the accepted T-07 trade-off.
- **`data-strategy-table-prefs-applied`:** a client-only attribute set on `<html>` in an effect gated on `prefsHydrated` (`StrategyTable.tsx:292, 650-654`), removed on cleanup, value is the constant `"true"`. It carries no user data, is not in SSR HTML, is read only by e2e specs, and opens no injection or disclosure surface.
