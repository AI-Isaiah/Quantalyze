## Resolved finding (orchestrator-approved, 2026-10-13)

`StrategyTable.default-mounts.test.tsx` went RED on all three mounts after the fix. The plan's premise
("its fixture has no example row, so the byte pin must not move") was wrong in one respect. The pin is
`container.innerHTML` after effects, and the fixture recorded the "Hide examples" checkbox WITHOUT
`checked=""`. That absence was the flash itself: React writes the attribute only at creation, the old initial
state was unchecked, and the effect flipped only the DOM property. With the fix the box is created checked.
Confirmed against pre-fix source (3 passed) and measured: adding `checked=""` to the three mounts equalled the
new output byte-for-byte, and it was the only difference.

Resolution (commit `c898cd4ed`): surgical hand edit of
`src/components/strategy/__fixtures__/strategy-table-default-mounts.json`, adding ` checked=""` after
`type="checkbox"` on the "Hide examples" input in `discovery`, `browse` and `myStrategiesOwner` (3 occurrences,
not regenerated), plus a dated "170.6.2 COPYPASS D-06" note in the test header beside the TRADESYNC edit.
Proof the pin encodes the fix: edited fixture GREEN 3/3 on the fix; with the pre-fix `StrategyTable.tsx` copied
in from a byte backup it is RED 3/3; restored from backup, `cmp` exit 0, rerun GREEN 3/3.
