### SC-1: /recommendations header with no mandate (founder "Accept all", 2026-10-13)
- **D-01:** The unset-mandate header description reads exactly **"Strategies from the daily match engine. Set your mandate to see yours."**
  - It replaces "Strategies matched to your mandate, updated daily. No mandate is set yet." in `src/app/(dashboard)/recommendations/page.tsx` (`:342-346`).
  - The set header and the unknown header are unchanged.
  - The `NoMandateState` CTA body is unchanged.
  - Tests:
    - an exact-string pin on the new header;
    - `not.toMatch(/matched to your mandate/i)` on the unset branch;
    - the existing `/fit your mandate/` negatives (MG1/MG4) and MP5's set/unset derivation stay green.

### SC-2: rebuilding panel (167.1.2 D-26; founder "Accept all", 2026-10-13)
- **D-02:** The named-key line reads **"One of your keys, {Exchange} — {nickname or ••••last4}, is not syncing, so we cannot confirm which exchange account it reads. Check it on the Exchanges page."**
  - The label comes from `dataSourceLabel`, unchanged.
  - When the key is unknown: **"One of your keys is not syncing, so we cannot confirm which exchange account it reads. Check it on the Exchanges page."**
  - The multi-key line "Some of your keys are not syncing, …" is kept. Reason lines carry no numbers (T-167.1.2-22a).
- **D-03:** "yet" is dropped from the `shared_account_history_truncated` line. It implies a heal that never ships. Add a negative `/\byet\b/` assertion across every rendered reason line.
- **D-04:** The headings by class:
  - `needs_action` reads **"Your equity history is waiting on a key"**;
  - `read_failed` reads **"We could not load your equity history"**;
  - `rebuilding` keeps "Your equity history is being rebuilt";
  - `held_back` keeps "We are holding back your equity history".
  - The h2 level and the region's `aria-labelledby` are kept. Sentence case.
- **D-05:** Overview and Risk render the same heading for the same class (parity test). The Scenario composer's class-keyed line is unchanged; only its heading-map pin moves. Pins that move:
  - `AllocationDashboardV2.rebuilding.test.tsx`;
  - `OverviewRisk.history-parity.test.tsx`;
  - `RiskTabPanel.book-series.test.tsx`;
  - `ScenarioComposer.test.tsx` (the heading map at `~:18098`).
  - Re-point them; never delete one.

### SC-3: anonymous /browse flash (founder "Accept", 2026-10-13)
- **D-06:** `StrategyTable`'s `showExamples` starts from the default (`!DEFAULTS.hide_examples`, i.e. examples hidden) for every non-`managerRows` mount. `managerRows` keeps `true` (170.7 SFH-1). So the SSR HTML and the first paint equal the settled state for an anonymous visitor. The logged-in /discovery page shares the component and gets the same fix. A user who saved "show examples" sees them appear after hydration, which is the benign direction.
  - Proof, RED today: `renderToString` with no `userId` and an `is_example` row asserts the example name is absent.
  - Proof: a per-commit probe asserts the example-row count never goes from >0 to 0.
  - Proof: a `managerRows` mount still shows its own example rows on first paint.

### SC-4: admin Compute Jobs kind filter (founder "Accept", 2026-10-13)
- **D-07:** The filter lists the kinds that actually have jobs.
  - The list comes from a distinct-kinds query through the existing admin route (`/api/admin/compute-jobs`). It is its own query, not derived from the paginated page, behind the same `isAdminUser` gate and service-role client.
  - The currently selected kind always stays in the list.
  - The hardcoded `KIND_OPTIONS` (3 kinds) in `src/components/admin/ComputeJobsTable.tsx:59-64` is removed. "All kinds" stays.
  - No migration.
  - Tests: a component test where a kind outside the old three (e.g. `derive_allocator_equity`) appears as an option, RED today; a route test where two seeded kinds come back in the facet.

### Claude's Discretion
- The facet's API shape: an extra payload field, or a `?facets=kinds` branch of the same route.
