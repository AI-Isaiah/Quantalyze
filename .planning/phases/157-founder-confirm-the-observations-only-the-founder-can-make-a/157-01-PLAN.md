Create `157-STAGING-KIT.js` as one self-contained ES2020 IIFE with no imports, so it can be pasted in a console or run by the claude-in-chrome `javascript_tool`. This follows CONTEXT "Decided autonomously": the kit lives in the phase directory.

1. Install. Capture the original fetch once as `orig` (bound to window). Assign `window.fetch` to the router. If `window.__fconf` already exists, do not wrap twice: print a console message and return, so a second paste cannot chain two wrappers.

2. Normalise every call. Accept a string, a URL or a Request as `input`. Resolve it with `new URL(..., location.href)`. Take the method as `init.method`, else `input.method` for a Request, else GET, upper-cased. Never read `init.body`, `init.headers`, cookies, localStorage or sessionStorage (RESEARCH "Security Domain", V2/V3).

3. Classify:
   - `isApi`: same origin AND pathname starts with `/api/`.
   - `isRest`: pathname starts with `/rest/v1/`, any origin, since Supabase is cross-origin.
   - Everything else goes to `orig(input, init)` untouched. This covers `/auth/v1/*` (token refresh MUST pass, per RESEARCH finding 4), PostHog, Sentry, RSC `?_rsc=` fetches and assets.

4. Decide. For `isApi` or `isRest`, look up the armed mode's STUB table first, matching method plus pathname pattern (with the select-column rule in Task 2 for REST). A hit returns a fresh `new Response(...)` built per call, and the request never leaves the browser. Otherwise, if the method is GET or HEAD and the route is in the armed mode's explicit PASS list, call `orig`. Otherwise REFUSE: return status 599, body `{"code":"FCONF_REFUSED"}`, `Content-Type: application/json`, and push an entry to `__fconf.refused`.

5. Fail closed with no mode armed. Before any `arm(...)`, the PASS and STUB tables are empty, so every `/api/` and `/rest/v1/` call is refused. This covers CONTEXT "The stub fails closed" and RESEARCH Pitfall 2.

6. Record. Every hit, pass and refusal is recorded as a string of METHOD, a space, and the pathname. Before recording, scrub ids in two places:
   - path segments: replace any uuid-shaped or all-digit segment with `:id`;
   - query string: replace `eq.<value>` with `eq.:id`. The query is kept only for `/rest/v1/` entries, as the `select=` parameter.
   Recording METHOD keeps host-page read noise separable from a refused write. Hits go to `__fconf.hits`, passes to `__fconf.passed`, refusals to `__fconf.refused`. All three are plain arrays.

7. Control object. `window.__fconf` exposes:
   - `mode`, read-only via a getter;
   - `arm(mode, envelopeCode?)`, which throws on an unknown mode or an unknown envelope code;
   - `hits`, `passed`, `refused`;
   - `version`, a constant string naming the HEAD sha the literals were read at. The executor fills it from `git rev-parse --short HEAD` at write time.

8. Marker. A fixed-position element with `id="fconf-staging-marker"`, high z-index, high contrast, `pointer-events: none` so it never blocks a click. Set its text with `textContent` only, never innerHTML. It reads:
   - `STAGED RESPONSES ACTIVE — FCONF-0x (no mode armed)` before arm;
   - `STAGED RESPONSES ACTIVE — FCONF-03 (connect)` in connect mode.
   Task 2 adds the other modes' strings. A reload drops both the wrapper and the marker. This covers CONTEXT "While the stub is active, a fixed, visible marker...".

9. Connect mode (FCONF-03a, CONTEXT "⛔ CORRECTED" item 1). Stub rows:
   - `GET /api/strategies/wizard-draft`: 200, body `{"draft":null,"kind":null}`, headers `Content-Type: application/json` and `Cache-Control: private, no-store`.
   - `POST /api/strategies/create-with-key`: 500, body exactly `{"code":"SEAM_INTERNAL_FAULT"}`, headers `Content-Type: application/json` and `Cache-Control: private, no-store`, no Retry-After.
   - `GET /api/strategies/composite/members` (with any query): 200 `{"members":[]}`. This serves the page-route "Try another key" fallback.
   Connect mode also carries the resume-path reads and the kickoff stub that the fallback path needs (Task 2 defines them once and shares them across modes).

The smoke test therefore tests the same code the founder runs (RESEARCH "Validation Architecture").
