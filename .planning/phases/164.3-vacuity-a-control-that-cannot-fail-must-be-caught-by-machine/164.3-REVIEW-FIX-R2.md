measured it with an instrument that agrees with it by construction.* So the rule for
this round was: **every proof must use an oracle that does not share the
implementation's derivation.** Concretely, for each finding:

### R2-C01 (Critical): a comment ended the neuter scan early and leaked `SET ROLE`

**Files:** `scripts/mutation-runner/run.mjs`, `src/__tests__/mutation-runner-neuter.test.ts`
**Commit:** `76e9f5c4`

`BRANCH_HEAD` was tested **in the loop condition** — before `IGNORABLE_LINE` and with no
comment stripping — so a whole-line `--` comment containing `THEN`/`BEGIN`/`ELSE`/
`ELSIF`/`LOOP`/`DECLARE`/`EXCEPTION` terminated the backward scan before the statement
above it was ever classified.

**Observed RED first, by an INDEPENDENT ORACLE.** The oracle does not read run.mjs's
regexes; it asserts a property of the **output** — *no accepted neuter may leave a
`SET ROLE` live* — which is the leak class stated directly, derived from what WR-07
exists to refuse rather than from the scan's own rules. Input built from outside:

```
A (comment says EXCEPTION): found=true leakedSetRoleStillLive=true
B (no comment):             found=false leakedSetRoleStillLive=false
   reason: the abort branch for "ARM A" carries an unrecognised statement before its RAISE
           (line 4: SET ROLE postgres;). …
```

**After:**

```
A (comment says EXCEPTION): found=false leakedSetRoleStillLive=false
B (no comment):             found=false leakedSetRoleStillLive=false
```

**Fix.** Classify first, terminate last, and terminate only on **executable** text:
ignorable → `continue`; branch head on comment-**stripped** text → `break`; anything else
→ refuse. `stripTrailingComment` is deliberately naive about string literals — a needle
inside a literal strips to something that no longer matches `BRANCH_HEAD` and therefore
**refuses**, which is the safe direction (a loud named defect beats a silent leak).

**Tests.** The shipped suite's only comment case used `-- an explanatory comment`, which
carries no trigger word and could never have caught this. Added: one arm per branch-head
word (7), the independent output-property oracle over five realistic comment spellings,
and — the other direction — a real branch head carrying a trailing comment must still
end the scan, so the fix cannot be "passed" by never terminating and refusing the whole
corpus. **14 → 23 tests**, corpus unchanged at 30/30/0.

### R2-W01 + R2-W02: the leak assertion measured `$TMPDIR`, and counted a shared directory

**File:** `src/__tests__/drift-check-scripts.test.ts`
**Commit:** `081503fd`

`dirname(mkdtempSync(join(tmpdir(), "probe-")))` is **identically** `os.tmpdir()` —
mkdtemp creates inside the path it is given, so `dirname` hands it straight back. The
comment claiming it "counts the REAL temp root, not `$TMPDIR`" described the exact
quantity it had been rewritten to stop using.

**Measured, independent oracle** (ask a `bash -c mktemp -d` child where it lands, compare
with what the test computes):

```
=== default TMPDIR ===
test computes tempRoot as:     /var/folders/…/T
child mktemp -d actually in:   /var/folders/…/T
tempRoot === os.tmpdir():      true      BLIND: false

=== TMPDIR overridden ===
test computes tempRoot as:     …/scratchpad/tmproot
child mktemp -d actually in:   /var/folders/…/T
tempRoot === os.tmpdir():      true      BLIND: true
```

**Observed RED first — by neutering the SUBJECT, not the measurement.** The gate's
`EXIT INT TERM` traps (IN-04's actual fix) were removed and `TMPDIR` overridden. The
shipped test **PASSED**:

```
Test Files  1 passed (1)
     Tests  1 passed | 39 skipped (40)
--- leaked dirs actually present in the REAL temp root: 63
```

A control that cannot fail, inside the finding about controls that cannot fail.

**After the fix, same neutered subject, same environment:**

```
AssertionError: a failing run left its mktemp -d behind. RETURN traps do not fire on
exit; this script family's stated purpose is that nothing it creates survives.:
expected [ 'tmp.pAloGpPkHE' ] to deeply equal []
```

Traps restored (`shasum -a 256` = `acccf34b…`, verified) → **40/40 green under both the
default and an overridden `TMPDIR`**.

**Fix, both halves.**
- **W01:** ASK the child. `bash -c 'd=$(mktemp -d); printf %s "$d"; rmdir "$d"'` — the
  same primitive, the same interpreter and the same environment the gate uses, correct on
  macOS (confstr, ignores TMPDIR) and Linux (GNU, honours it) without the test knowing
  which. It also cleans up after itself; the old `probe-` directory was never removed, so
  the anti-leak test leaked.
- **W02:** attribute by **content**, not by a bare count of a machine-wide directory.
  Added dirs are filtered by the `missing.txt` signature the gate itself writes and
  compared as a **set**, plus a **calibration** step that plants a directory of exactly
  that shape and requires the detector to see it — so a filter matching nothing cannot
  masquerade as "no leak".

⚠️ The 13 scratch directories my neutered-subject proof runs leaked were cleaned up,
attributed by the same signature.
