## D-16 honoured: there is no mechanism-5 rule

Mechanism 5 — an arm made structurally unreachable by an earlier arm covering the same state — is not decidable from SQL text. A rule for it could not fire, and a rule that cannot fire is the exact defect this phase exists to eliminate. Rather than leave that as a silent absence someone later "completes", the script exports `DELEGATED_MECHANISMS`, naming the mechanism, the decision (`D-16`), and its actual detector (the mutation runner's first-failure identity assertion). Three assertions pin it:

- `RULES.filter(r => r.mechanism === 5)` must be empty,
- a `DELEGATED_MECHANISMS` entry for mechanism 5 must exist with `decision === "D-16"`,
- `RULES.map(r => r.mechanism).sort()` must equal exactly `[1, 2, 3, 4]`.

The `--self-test` path fails independently if a mechanism-5 rule appears, so the CI job catches it even if the vitest file is deleted.

## Decisions Made

1. **Allowlist entries carry an exact count.** The plan specified file + rule + reason. A count was added because without one, a *new* violation of an already-allowlisted rule in an already-allowlisted file is invisible — which is threat T-164.3-15 verbatim.
2. **No npm-script alias, no chaining into `npm run lint`.** `PATTERNS §2` suggests registering aliases, but mode identity forbids a second invocation path here: the header documents one command and CI runs that command. Two entry points means two failure attributions for one gate.
3. **The self-test step runs first in CI.** A corpus scan reporting "0 findings" is indistinguishable from a defanged linter unless something independently proves the rules still fire.
4. **`vitest.node-env.ts` left alone.** The new test touches no DOM and would qualify for the node project, but plan 02's `drift-check-scripts.test.ts` was not added either, and that file is shared across concurrently-running wave agents. Conformance to the in-practice convention over a speed micro-win.
5. **Task 1's commit deliberately omitted the ci.yml half of the mode-identity assertion**, which Task 2 adds with the job itself, so that each commit is independently green rather than leaving a knowingly-red intermediate state.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `BEGIN;` transaction starts parsed as PL/pgSQL blocks**

- **Found during:** Task 1, first full-corpus run
- **Issue:** The block-structure walker pushed a frame for every `BEGIN` token. Every gate file in this corpus opens with `BEGIN;` (a transaction start, never closed by an `END`), so **57 of 71 files** reported `MEASURE_FAIL — unclosed block(s)`. Silent under a naive design; loud here only because MEASURE_FAIL is a distinct result.
- **Fix:** `BEGIN` followed by `;` / `TRANSACTION` / `WORK` / `ISOLATION` opens a transaction, not a block, and is not pushed.
- **Verification:** measure-fails 57 → **0** across the corpus.
- **Committed in:** `6dd246d4`

**2. [Rule 1 - Bug] R1 missed the first statement of every handler**

- **Found during:** Task 1, first self-test — R1 did not fire on its own red fixture
- **Issue:** A handler's opening statement begins at the `;` that ended the guarded body, i.e. *before* the `EXCEPTION` keyword, so containment-based statement selection skipped it — and that is precisely the statement most likely to hold the probe. The rule would have shipped unable to fire on the shape it exists for. Caught only because the self-test demands a red fixture fire.
- **Fix:** statements are clipped to the handler span rather than tested for containment.
- **Verification:** R1 fires on its red fixture and on the mutated real gate file (line 1076).
- **Committed in:** `6dd246d4`

**3. [Rule 2 - Missing Critical] Duplicate findings made allowlist counts author-formatting-dependent**

- **Found during:** Task 1, corpus measurement
- **Issue:** `a !~ 'x' AND a !~ 'y'` on one line produced two identical findings, so the allowlist's exact counts would have depended on how an author wrapped their conditions — a brittle pin that would fail on cosmetic reflows and get relaxed.
- **Fix:** findings deduplicated by (rule, line, message).
- **Verification:** corpus total settled at a stable 43.
- **Committed in:** `6dd246d4`

**4. [Rule 1 - Bug] A test assertion that could not pass**

- **Found during:** Task 1, first green run — "leaves the corpus untouched" failed
- **Issue:** the guard regex included `exec\(`, which matches the linter's own `regex.exec(` calls. The assertion could never pass, which is the mirror image of this phase's defect.
- **Fix:** narrowed to real mutation APIs (`writeFileSync`, `appendFileSync`, `unlinkSync`, `rmSync`, `mkdirSync`, `child_process`).
- **Committed in:** `6dd246d4`
