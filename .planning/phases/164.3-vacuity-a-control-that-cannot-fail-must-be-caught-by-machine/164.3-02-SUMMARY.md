**Two machine drift gates on one shared body normalizer: an unskippable repo-vs-PROD `CREATE OR REPLACE` body diff on the existing migrations-PR job, and a repo-vs-TEST ledger check joined on `name` with a body assertion — plus the skip-that-reads-as-PASS inside the very workflow VAC-04 joins, converted to a hard failure.**

## Accomplishments

- **One normalizer, two callers (D-05).** `scripts/sql-body-normalize.mjs` is a string-aware SQL lexer: strips `--` and *nested* `/* */` comments, collapses whitespace, extracts dollar-quoted function bodies (all overloads), and compares them. D-05's measured case is a committed fixture — a body whose only `INTO STRICT` sits in a comment normalizes to text without that token.
- **VAC-04 ships unskippable.** The credential assertion is the script's first act and an absent credential is `exit 1`. Drift is waved through only by a `-- prod-body-ack: <sha256>` pragma whose hash equals the sha256 of the *normalized PROD body*, so a blind or stale ack fails.
- **D-17 closed rather than booked.** The `configured=false` → `::notice:: skipped` branch in `migration-drift-check.yml` — green having checked nothing, on the workflow guarding production migrations — is a hard failure, and the three `if:` conditions that consumed it are deleted.
- **VAC-08 joins on `name`.** The version-join that a naive reading would have shipped was itself the vacuous control: it reported 12 of 12 recent migrations missing when all 12 were present.
- **Both gates are proved able to fail.** 56 vitest cases, plus a `--self-test` with an `--expect-inverted` mode that makes the self-test's own arms falsifiable.

## Decisions Made

### The fetcher mechanism for VAC-04 (recorded per the plan's output spec)

**Chosen: the CLI dump path.** `supabase link --project-ref` (already the job's proven idiom with these exact secrets), then `supabase db dump --linked --schema public -f "$RUNNER_TEMP/prod-schema.sql"`, then `node scripts/sql-body-normalize.mjs --extract-fn <dump> <name>` as `BODY_FETCH_CMD`. The dump file is written to the workspace and **never** `cat`'d or echoed.

**Rejected: constructing a psql DSN.** The plan permitted it "only if the dump path fails". It was not written, deliberately: a fallback that has never executed is untested code on the credential path, and this phase's entire subject is code that reads as a control without being one. If the dump path fails in practice, the failure will be loud (see the guard below) and the fallback can be added *with* a test.

**Fail-loud guard on the dump itself:** if the dump contains zero `CREATE [OR REPLACE] FUNCTION` lines, the step exits 1. A dump the gate cannot read functions out of is not a pass — that is the exact "could not measure vs measured zero problems" collapse the phase constraints forbid.

### Fork behavior verified for D-17

Two facts, and I am explicit about which is measured and which is documentary:

1. **In-repo precedent (measured, read this session):** `ci.yml:958` gates the `sql-tests` job with `if: (github.event_name == 'push' || github.event.pull_request.head.repo.full_name == github.repository) && vars.E2E_TEST_DB_CONFIGURED == 'true'`. `ci.yml:2755` uses the same shape. This is the repo's established same-repo carve-out and I mirrored it (dropping the `push` arm, since `migration-drift-check.yml` is `pull_request`-only).
2. **GitHub's documented behavior (not executed here):** secrets — including environment secrets, which this job uses via `environment: Production` — are withheld from `pull_request` runs originating on a fork. That is what makes an unconditional hard failure unacceptable, and the job-level `if:` the correct remedy: a fork PR now shows a **visibly skipped job** instead of a red one nobody can fix.

D-17's own caution ("verify the vars/secrets are set for FORK PRs too, or a hard failure turns every fork PR red") is therefore satisfied by *removing fork PRs from the job entirely* rather than by assuming the secrets are present.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Body extraction added to the normalizer — without it the gate could never pass**

- **Found during:** Task 1 (before implementation, while reading the real corpus)
- **Issue:** The plan specified the normalizer as comment-strip + whitespace-collapse, and the gates as "normalize BOTH the snapshot body and the PROD body … if normalized bodies are equal, pass". But the snapshot files hold migration source (`CREATE OR REPLACE FUNCTION _enqueue_compute_job_internal(p_strategy_id UUID, …)`), while `pg_get_functiondef`/`pg_dump` re-render the statement (`public._enqueue_compute_job_internal(p_strategy_id uuid, …)`, `RETURNS uuid`, `AS $function$`). Comparing whole normalized statements would have reported DRIFT on **every function, forever** — a gate that always fires, which gets switched off exactly as fast as one that never can.
- **Fix:** Added `extractFunctionDefs` / `diffFunctionBodies` to the same shared module (preserving "one implementation, two callers"). Postgres stores `prosrc` verbatim, so the dollar-quoted body is byte-identical across renderings — the comparison is now meaningful. Verified against the real 2-overload `supabase/schema/functions/_enqueue_compute_job_internal.sql`: both the 7-param and 10-param overloads parse and self-MATCH.
- **Files modified:** `scripts/sql-body-normalize.mjs`, `src/__tests__/sql-body-normalize.test.ts`
- **Verification:** 37 vitest cases; comment-stripping neutered → 7 RED → restored GREEN (sha-verified restore).
- **Committed in:** `bbf57861`

**2. [Rule 2 - Missing Critical] The normalizer is string-aware, so the plan's documented limitation does not apply**

- **Found during:** Task 1
- **Issue:** The plan instructed documenting that `--` inside string literals is also stripped, "acceptable because the SAME normalization is applied to both sides". Symmetric, yes — but a regex stripper deletes the rest of the line *including the closing quote*, silently re-framing every byte after it. In PL/pgSQL bodies full of `RAISE EXCEPTION '…'`, that is a lot of re-framing.
- **Fix:** Implemented a proper lexer (needed for body extraction anyway) that tracks line comments, nested block comments, `'…'` with `''`/`E''` escapes, `"…"` identifiers and `$tag$…$tag$`. The header documents the *narrower* residual limitation (no `U&'…'` UESCAPE modelling) rather than a limitation that no longer exists.
- **Files modified:** `scripts/sql-body-normalize.mjs`
- **Verification:** explicit cases asserting `--` inside a string literal survives, and that `''` escapes are honored.
- **Committed in:** `bbf57861`

**3. [Rule 2 - Missing Critical] `UNCOMPARABLE` fails closed instead of passing quietly**

- **Found during:** Task 2
- **Issue:** A `LANGUAGE sql … RETURN expr` function has no dollar-quoted body. Nothing in the plan said what to do; the tempting answer is a warning-and-continue.
- **Fix:** Both gates `exit 1` on `UNCOMPARABLE`, with a message saying the gate refuses to report a pass for something it did not compare. The `-- prod-body-ack:` pragma is available if it is deliberate.
- **Files modified:** `scripts/sql-body-normalize.mjs`, `scripts/prod-body-drift-check.sh`, `scripts/test-ledger-drift-check.sh`
- **Verification:** `diffFunctionBodies` case asserting the status; both gates' `case` arms set `bad=1`.
- **Committed in:** `bbf57861`, `1f3a8ded`, `b922a50e`
