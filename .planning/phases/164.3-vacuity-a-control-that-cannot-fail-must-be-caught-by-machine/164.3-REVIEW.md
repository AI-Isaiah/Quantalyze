## Critical Issues

### CR-01: The VAC-06 pin depends on a `.planning/phases/` file that this repo's mandated ship path deletes

**File:** `src/__tests__/vac06-mechanism-arms.test.ts:38-44`, asserted at `:209` and read at `:210`, `:224`

`DEMOS` resolves to
`.planning/phases/164.3-vacuity-a-control-that-cannot-fail-must-be-caught-by-machine/164.3-VAC06-DEMOS.md`,
and `:209` is `expect(existsSync(DEMOS), ...).toBe(true)`.

The two artifacts ship in **different commits with different fates**:

- the test: `bb2e5a18 test(164.3-10): pin the five VAC-06 demonstrations` — `src/` only
  (verified: `git show --stat bb2e5a18` lists one file).
- the record: `2f7080e9 docs(164.3-10): all five vacuity mechanisms re-introduced` —
  `.planning/phases/**`.

Two mechanisms remove the record while keeping the test:

1. **The PR branch.** `CLAUDE.md` makes `/gsd-pr-branch` a non-optional step before every
   PR, and it drops commits under `.planning/phases/`. The PR that ships this phase will
   therefore carry `vac06-mechanism-arms.test.ts` and not `164.3-VAC06-DEMOS.md` →
   `frontend-test` red → `frontend` (the required aggregator) red.
2. **Milestone completion.** `/gsd-complete-milestone` relocates the phase dir to
   `.planning/milestones/v1.20-phases/`. The path in `:38-44` is then permanently wrong
   and the failure is permanent.

Both failures are *loud*, which is better than the alternative — but they redden the
required check for a reason the change under test did not cause, and the standard remedy
for that is to weaken the assertion, which would destroy the pin.

**Fix:** move the machine-checked half of the record out of the transient tree. Either
relocate the demonstrations to a durable path next to their subject
(`scripts/mutation-runner/VAC06-DEMOS.md`), or keep the prose in the phase dir and add a
committed manifest the test can read:

```ts
// src/__tests__/vac06-mechanism-arms.test.ts
const DEMOS = join(REPO_ROOT, "scripts", "mutation-runner", "VAC06-DEMOS.md");
```

Do **not** make the assertion tolerate absence — an `if (!existsSync(DEMOS)) return;` is
exactly the skip-that-reads-as-pass this phase exists to remove.

### CR-02: `plan-anchor-verify` hard-fails on the legitimate post-archive state, blocking every PR

**File:** `scripts/verify-plan-anchors.mjs:578-586`; enforced again at `.github/workflows/ci.yml:1166-1169`

`findPendingPlans` returns `measureFail: true` whenever `.planning/phases` contains zero
`*-PLAN.md` files, on the stated reasoning that "zero pending plans because zero plans were
found is a broken glob, not a clean corpus". That reasoning is sound for a broken glob and
wrong for the state `/gsd-complete-milestone` produces: it moves every phase dir into
`.planning/milestones/v{X.Y}-phases/`, leaving `.planning/phases/` legitimately empty.

Measured, exact input that fails wrongly:

```
$ mkdir -p ptest/.planning/phases/00-x
$ node scripts/verify-plan-anchors.mjs --pending --root ./ptest
MEASURE_FAIL: .planning/phases contains NO *-PLAN.md files. Zero pending plans because
zero plans were found is a broken glob, not a clean corpus.
$ echo $?
1
```

This is not hypothetical for this repo — `git ls-tree` over history finds commit
`e9a57671` ("chore(planning): untrack stale duplicate phase dirs") with zero `-PLAN.md`
under `.planning/phases`. When it recurs, `plan-anchor-verify` exits 1, its aggregator row
(`ci.yml:1384-1392`) is strict on `pull_request`, and the required `frontend` check is red
on **every** PR until someone creates a phase directory. The mitigation available to the
person hitting it is to disable the job.

**Fix:** distinguish "the corpus could not be located" from "the corpus is archived".
Consult the archive before declaring a broken glob:

```js
if (planFiles === 0) {
  const archived = existsSync(join(root, ".planning", "milestones"))
    && readdirSync(join(root, ".planning", "milestones"))
         .some((d) => d.endsWith("-phases"));
  if (!archived) {
    return { planFiles: 0, pending: [], measureFail: true,
      measureReason: ".planning/phases contains NO *-PLAN.md files and no archived "
        + "milestone phases exist either — this is a broken glob, not a clean corpus." };
  }
  // Measured zero: every phase has been archived. Print it and pass.
  return { planFiles: 0, pending: [], measureFail: false, measureReason: null };
}
```

and relax `ci.yml:1166-1169` to accept `total_plans == 0` only on that same archived
signal, keeping MEASURE_FAIL for the unarchived case.

### WR-01: VAC-04 absorbs a failed PROD read into "new function — pass", and has no floor on comparisons

**File:** `scripts/prod-body-drift-check.sh:172-176` (the absent branch), `:244-250` (the summary and verdict); fetcher wired at `.github/workflows/migration-drift-check.yml:183,192`; extractor at `scripts/sql-body-normalize.mjs:552-563`

The fetcher is `node scripts/sql-body-normalize.mjs --extract-fn <dump>`, and
`--extract-fn` exits **0 with empty stdout** when the name is not in the dump — measured:

```
$ node scripts/sql-body-normalize.mjs --extract-fn dump.sql not_in_dump ; echo $?
0                      # stdout empty
```

`:172-176` reads empty stdout as `absent in PROD — treated as a NEW function (pass)` and
`continue`s without incrementing `checked`. If every name goes down that branch the gate
prints `0 body comparison(s)` and exits 0 at `:249-250`, having compared nothing. There is
no floor requiring `checked > 0` when `NAME_COUNT > 0`.

The dump-shape guard at `migration-drift-check.yml:186` does not close this: it only
proves the dump contains *at least one* `CREATE ... FUNCTION` anywhere.

Two concrete inputs that pass wrongly:

- **A non-`public` function.** The dump is taken with `--schema public`
  (`migration-drift-check.yml:183`). Any `CREATE OR REPLACE FUNCTION private.f(...)` in a
  PR's migration is absent from the dump → "new function (pass)" even if PROD holds a
  drifted body. Measured today: all 112 function definitions in `supabase/migrations/*.sql`
  are `public.`, so this is latent, not live — it becomes live with the first non-public
  function.
- **Any extractor regression.** A change to the name matching at `sql-body-normalize.mjs:558-560`
  (`d.name === name`, last path segment only) that stops matching yields the same empty
  stdout for every name, and the whole gate goes green.

**Fix:** make "absent" a *measurement* rather than an empty pipe. Ask the dump for its
function-name index and only accept absence when the name genuinely is not in it:

```bash
# once, before the loop
node "$NORMALIZER" --function-names "$DUMP_PATH" > "$TMP/prod-names.txt" \
  || fail "could not index PROD's function names."

# in the absent branch
if grep -aqxF -- "$fname" "$TMP/prod-names.txt"; then
  echo "::error::${GATE}: '${fname}' IS in the PROD dump but no body could be extracted."
  bad=1; continue
fi
```

and add the floor:

```bash
if [ "$NAME_COUNT" -gt 0 ] && [ "$((checked + absent))" -ne "$NAME_COUNT" ]; then
  fail "MEASURE_FAIL: ${NAME_COUNT} function(s) named, ${checked} compared, ${absent} absent — the arithmetic does not close, so this run did not account for every function."
fi
```

Widen the dump to the schemas migrations actually target (or fail loud on a non-`public`
qualified name) at `migration-drift-check.yml:183`.

### WR-03: nothing forbids an annotation whose mutation satisfies the first-failure check by writing the expected string

**File:** `scripts/mutation-runner/parse.mjs:116-138` (`validateStep` for `edit` / `insert-after`); consumed by `scripts/mutation-runner/run.mjs:553-581`

The identity assertion is `firstFailureArm(run.output) === ann.arm`, and
`firstFailureArm` (`run.mjs:318-321`) is a plain `/TEST FAILED \(([^)]*)\)/` over the
lane's output. `validateStep` validates *shape* — kind, path safety, `occurrences`, `nth`
— and imposes no constraint on the **content** of `replace` or `text`. The gate file is in
`corpusRels` (`run.mjs:434`), so an annotation may edit the gate itself.

The combination means an annotation of the form

```json
{"arm":"X","apply":[{"kind":"edit","file":"supabase/tests/<gate>.sql",
  "find":"<any 1-occurrence line>","replace":"RAISE EXCEPTION 'TEST FAILED (X): x';","occurrences":1}]}
```

produces `RED (identity ok)`, counts toward `armsExecuted`, and raises the biting count —
for an arm that was never exercised. This is not an abstract shape: four steps in the real
corpus already target the gate file (`supabase/tests/test_strategy_shares_rls.sql:1965`),
so "annotations only edit migrations" is not an invariant anyone can rely on, and Phase
164.4 backfills ~70 more files against this schema.

**Fix:** reject the self-satisfying shape at parse time, in `validateStep`:

```js
const injected = step.kind === "edit" ? step.replace : step.text;
if (/TEST\s+FAILED\s*\(/i.test(injected)) {
  throw `${at}: the mutation's inserted text contains a "TEST FAILED (" literal. A mutation that WRITES the string the identity check looks for proves nothing — it satisfies the detector instead of the arm.`;
}
```

### WR-05: the local-stack teardown assertion — the one control that proves cleanup — passes when its own producer fails

**File:** `scripts/local-stack/run.sh:296-308` (with `running_project_containers` at `:252-254`)

```bash
leftover="$(running_project_containers || true)"
if [ -z "$leftover" ]; then count=0; else count="$(printf '%s\n' "$leftover" | grep -c .)"; fi
...
if [ "$count" != "0" ]; then ... exit 1; fi
```

`|| true` collapses every `docker ps` failure — daemon stopped, socket permission denied,
docker not on PATH — into an empty string, which becomes `count=0`, which prints
`SELF-TEST: surviving <id> containers -> 0` and reaches `SELF-TEST PASSED`. "Could not
count" and "counted zero" share the code path, in the assertion whose entire purpose is
proving the D-04 orphan class is closed. Exact input: stop the Docker daemon after
`cmd_down` returns and before `:297`.

**Fix:**

```bash
local leftover count rc=0
leftover="$(running_project_containers)" || rc=$?
if [ "$rc" -ne 0 ]; then
  echo "SELF-TEST FAILED: MEASURE_FAIL — 'docker ps' exited ${rc}; the teardown assertion could not be evaluated. Unmeasured is not zero." >&2
  exit 1
fi
```

### WR-06: a deliberately-deferred plan stays "pending" forever and couples every unrelated PR to its anchors

**File:** `scripts/verify-plan-anchors.mjs:552-575`

"Pending" is defined as "`*-PLAN.md` with no sibling `*-SUMMARY.md`". Plan 07 of this very
phase was deliberately not executed (founder deferral) and therefore has no SUMMARY, so
`164.3-07-PLAN.md` is in the scanned set permanently — confirmed by running the gate at
HEAD:

```
scanned: 3 pending plan file(s) of 70
  pending: .planning/phases/164.3-.../164.3-07-PLAN.md
```

Any later PR that shrinks a file that plan anchors, or moves code it quotes, reddens the
required `frontend` check for a reason unrelated to that PR. D-13 removed exactly this
coupling for VAC-04 on main-push; it survives here on the PR trigger, and the only exit
available today is to fabricate a SUMMARY for work that was never done.

**Fix:** honor an explicit deferral so a plan can leave the pending set honestly — e.g.
treat a sibling `<n>-DEFERRED.md`, or a `status: deferred` line in the PLAN's own
frontmatter, as terminal alongside a SUMMARY:

```js
const summary = name.replace(/-PLAN\.md$/, "-SUMMARY.md");
const deferred = name.replace(/-PLAN\.md$/, "-DEFERRED.md");
if (existsSync(join(abs, summary)) || existsSync(join(abs, deferred))) continue;
```

and print the deferred count so the exemption is visible rather than silent.

### WR-07: `neuterArm` absorbs exactly one abort-path statement; any other one leaks silently into every later arm

**File:** `scripts/mutation-runner/run.mjs:265-271`

```js
let start = raiseAt;
while (start > 0 && /^[ \t]*RESET[ \t]+ROLE[ \t]*;[ \t]*$/i.test(lines[start - 1])) start -= 1;
```

The header (`:217-243`) documents why this is a correctness requirement and how the
`RESET ROLE;` leak was found — and states plainly that it "was loud HERE only by luck".
The scope of the fix is one literal statement. A corpus arm whose abort branch reads
`RESET search_path;`, `SET ROLE postgres;`, `PERFORM set_config(...)` or `ROLLBACK TO
SAVEPOINT s;` before its `RAISE` produces the identical class of silent state leak, and
`neuterArm` leaves it live without any signal. Phase 164.4 backfills ~70 files against this
primitive, which is where the luck runs out.

**Fix:** stop guessing which cleanup is safe to absorb and refuse the ones you cannot
classify, so the failure is a `neuter-missed` defect instead of a silent leak:

```js
const ABSORBABLE = /^[ \t]*RESET[ \t]+ROLE[ \t]*;[ \t]*$/i;
const IGNORABLE  = /^[ \t]*(--.*)?$/;               // blank or comment
let start = raiseAt;
while (start > 0 && ABSORBABLE.test(lines[start - 1])) start -= 1;
// Refuse an unrecognised statement between the branch head and the RAISE.
for (let k = start - 1; k >= 0 && !/\b(THEN|BEGIN|ELSE|LOOP)\b/i.test(lines[k]); k -= 1) {
  if (IGNORABLE.test(lines[k])) continue;
  return { text, found: false, reason:
    `the abort branch for "${arm}" carries an unrecognised statement before its RAISE (${lines[k].trim()}). ` +
    `Neutering only the RAISE would leave it executing for the rest of the file — the measured RESET ROLE class. ` +
    `Extend the absorbable set deliberately.` };
}
```

### IN-01: a gate file carrying structured twins but no prose marker is invisible to the runner

**File:** `scripts/mutation-runner/parse.mjs:307-319`

`scanCorpus` adds a file to `annotatedFiles` only when `result.prose.length > 0`, and
`runCorpus` (`run.mjs:391`) / `parseOnlyCorpus` (`:742`) iterate only that list. A file with
5 `RED-UNDER-M` twins and 0 prose markers is never parsed, never parity-checked, its arms
never execute, and it does not count toward coverage — with no defect raised. The parity
gate at `parse.mjs:288-292` is per-file and is only reached for files already in the list.

The hole is covered today, but only outside the gate: `src/__tests__/mutation-runner-floors.test.ts:163-173`
walks *all* files and asserts `twins === prose` for any file with `twins > 0`. A developer
running `node scripts/mutation-runner/run.mjs` locally sees green regardless.

**Fix:** in `scanCorpus`, treat `prose.length > 0 || structured.length > 0` as annotated,
so the runner's own parity check fires on the structured-only shape.

### IN-02: zero-width spaces embedded in JSDoc to escape `*/`

Both files carry a U+200B inside a block comment (`a/*c*​/b`, `.planning/phases/*​/`) to keep

### IN-03: `umask 077` in `write_env_handoff` does nothing it claims

**File:** `scripts/local-stack/run.sh:156-159`

The comment says *"Create with restrictive permissions BEFORE any key material is

### IN-04: temp directories leak on the `fail()` path in both shell gates

**File:** `scripts/test-ledger-drift-check.sh:155-158` with `fail()` at `:71-74`; `scripts/pg-lane/run.sh:192-200` with `fail()` at `:61`

`trap "rm -rf '$tmp'" RETURN` fires on function *return*, not on `exit`; every `fail()` call
inside `check()` exits the shell and leaves the `mktemp -d` behind. Same shape in
`pg-lane`: `legacy_run` sets `OWNED_WORKDIR` at `:193` but the EXIT trap is only registered
inside `run_lane` at `:164`, so an early `fail` at `:132-137` (missing gate/apply file)
leaks the directory. Small directories, but this is the script family whose stated purpose
is that nothing it creates survives.

**Fix:** register `trap 'rm -rf "$tmp"' EXIT INT TERM` alongside the `RETURN` trap in
`test-ledger-drift-check.sh`, and move `pg-lane`'s `trap cleanup EXIT` above the argument
validation in `run_lane`.

### IN-05: CI's arms floor and `run.mjs`'s arms floor compare two different quantities

**File:** `.github/workflows/ci.yml:1038` vs `scripts/mutation-runner/run.mjs:672-675`

`run.mjs` compares `biting = armsExecuted - (no-red + wrong-first-failure)` to
`ARMS_FLOOR`. The CI assertion parses `arms: E/A/W` and compares raw `E` (executed) to the
same constant. On a run with non-biting arms these disagree, and the CI message
("ARMS_FLOOR regression: N arm(s) executed < floor") names a quantity the constant was not
measured against. Not a hole — the runner exits 1 on any such defect first — but two
meanings under one name is how a floor decays into a number nobody compares.

**Fix:** have the runner print a distinct `biting: N` line and assert on that in CI, or
rename the CI check to "executed-arm floor" and state that it is the weaker of the two.

### IN-06: the meta-command preflight regex has two pairs of identical alternatives

**File:** `.github/workflows/ci.yml:924`

`'^\\\!|^\\!| \\\!| \\!'` — in ERE, `\\\!` and `\\!` both denote a literal backslash
followed by a literal `!`, so alternatives 1/2 and 3/4 are duplicates. The check works;
the redundancy reads as a deliberate distinction that does not exist.

**Fix:** `'(^| )\\!'`.

### IN-07: the pg-lane collision guard is narrower than the message it prints

**File:** `scripts/pg-lane/run.sh:154-160`

`pg_isready` exits 0 only for a server *accepting* connections; a postgres that is starting
up, in recovery, or refusing connections exits 1 and the guard passes, after which the
script prints nothing about it. The blast radius is bounded — `pg_ctl -w start` at `:173`
then fails to bind and `set -e` aborts before any `psqlq` runs, so the neighbour's
`DROP SCHEMA public CASCADE` scenario stays closed — but the refusal message
("something is already listening on 127.0.0.1:$PORT") claims a broader check than
`pg_isready` performs.

**Fix:** either state the limit in the message, or make the guard a socket bind test
(the same `node -e` primitive `alloc_port` already uses at `:87`) so a non-postgres
listener is detected too.
