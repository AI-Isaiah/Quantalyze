## Critical Issues

### R2-C01: WR-07's refusal is defeated by a comment — the `RESET ROLE` leak class is still reachable, silently

**File:** `scripts/mutation-runner/run.mjs:259` (`BRANCH_HEAD`), enforced at `:306-318`

```js
const BRANCH_HEAD = /\b(THEN|BEGIN|ELSE|ELSIF|LOOP|DECLARE|EXCEPTION)\b/i;
...
for (let k = start - 1; k >= 0 && !BRANCH_HEAD.test(lines[k]); k -= 1) {
  if (IGNORABLE_LINE.test(lines[k])) continue;
  return { text, found: false, reason: ... };
}
```

`BRANCH_HEAD` is tested **in the loop condition, before** `IGNORABLE_LINE` is consulted,
and it is a bare word match with no comment stripping. So a whole-line `--` comment that
happens to contain `THEN`/`BEGIN`/`ELSE`/`ELSIF`/`LOOP`/`DECLARE`/`EXCEPTION` — and
`exception` is the single most likely word in a comment sitting next to a
`RAISE EXCEPTION` — terminates the backward scan **before** the unclassifiable statement
is ever examined. The commit message claims the scan "refuses anything that is not blank,
a comment, or absorbable". It does not.

Measured, exact input that leaks (run against HEAD):

```
DO $$
BEGIN
  IF x THEN
    SET ROLE postgres;
    -- now raise the exception the harness looks for
    RAISE EXCEPTION 'TEST FAILED (ARM A): boom';
  END IF;
END
$$;
```

```
A found: true | reason: -
A: leaked 'SET ROLE postgres;' still live: true
```

versus the same text with the comment removed:

```
B found: false | reason: the abort branch for "ARM A" carries an unrecognised statement
                         before its RAISE (line 4: SET ROLE postgres;) …
```

The neutered output confirms the leak — the `RAISE` is replaced with
`NULL; -- neutered ARM A`, and `SET ROLE postgres;` is left executing for the rest of the
file. That is verbatim the class the header describes as "a leaked superuser session made
sixteen later arms pass for a reason unrelated to their grants", and it is now a *silent*
pass rather than a `neuter-missed` defect.

I scanned the real corpus (104 raise sites, 30 annotated arms): **zero live instances
today**, so the phase's own gate is not currently wrong. But 164.4 backfills ~70 files
against this primitive, and the shipped test suite cannot catch it — the only
comment-adjacent case in `mutation-runner-neuter.test.ts` uses `-- an explanatory
comment`, which contains no branch-head word.

**Fix:** classify before terminating, and terminate only on executable text.

```js
const stripComment = (l) => l.replace(/--.*$/, "");
for (let k = start - 1; k >= 0; k -= 1) {
  if (IGNORABLE_LINE.test(lines[k])) continue;          // blank or whole-line comment
  if (BRANCH_HEAD.test(stripComment(lines[k]))) break;  // real branch head: scan complete
  return { text, found: false, reason: /* unchanged */ };
}
```

and add the missing arm to `src/__tests__/mutation-runner-neuter.test.ts`:

```ts
it("a comment mentioning EXCEPTION does not end the scan early", () => {
  const r = neuterArm(
    ["  IF NOT raised THEN", "    SET ROLE postgres;",
     "    -- raise the exception the harness looks for",
     "    RAISE EXCEPTION 'TEST FAILED (ARM E): x';", "  END IF;"].join("\n"), "ARM E");
  expect(r.found).toBe(false);
});
```

### R2-W01: IN-04's leak assertion measures `$TMPDIR` under a comment saying it deliberately does not — and cannot fail under a TMPDIR override

**File:** `src/__tests__/drift-check-scripts.test.ts:605-613`

```ts
// ⚠️ This counts the REAL temp root, not $TMPDIR. macOS `mktemp -d` with
// no template ignores TMPDIR and uses the confstr path — a first version
// of this check pointed at a scratch TMPDIR, measured 0 leaks with the fix
// AND 0 without it, and would have shipped as a test that cannot fail.
const tempRoot = dirname(mkdtempSync(join(tmpdir(), "probe-")));
```

`mkdtempSync(join(X, "probe-"))` creates its directory **inside `X`**, so
`dirname(...)` is `X`. Measured at HEAD:

```
mkdtemp:          /var/folders/.../T/probe-CQDFaZ
dirname(mkdtemp): /var/folders/.../T
os.tmpdir():      /var/folders/.../T
IDENTICAL: true
```

`tempRoot === os.tmpdir()` identically — i.e. `$TMPDIR`, the exact quantity the comment
says was the vacuous first version. The rewrite changed nothing except adding a leaked
directory. Under a `TMPDIR` override on macOS (this session has one; GSD worktrees and
wrapper harnesses set it routinely) the two diverge and the assertion goes blind:

```
test would count in:                    /private/tmp/.../scratchpad/tmproot
a shell mktemp -d actually lands in:    /var/folders/.../T
test blind to the real temp root: true
```

In that environment `countScratch() - before` is 0 with **and** without the EXIT trap —
a control that cannot fail, inside the finding about controls that cannot fail. It bites
today only because the default macOS `TMPDIR` happens to equal the confstr path and
because GNU `mktemp` on Linux honours `TMPDIR`.

Secondary: the `probe-…` directory is never removed. The anti-leak test leaks.

**Fix:** ask the child where its `mktemp -d` actually lands, instead of assuming.

```ts
const probe = spawnSync("bash", ["-c", 'd=$(mktemp -d); printf %s "$d"; rmdir "$d"'],
  { encoding: "utf8" });
expect(probe.status, "could not locate the shell's temp root").toBe(0);
const tempRoot = dirname(probe.stdout.trim());
```

### R2-W02: the same assertion is a race on a globally shared directory

**File:** `src/__tests__/drift-check-scripts.test.ts:612-624`

```ts
const countScratch = () => readdirSync(tempRoot).filter((n) => n.startsWith("tmp.")).length;
...
expect(countScratch() - before).toBe(0);
```

This counts **every** `tmp.*` directory in the machine-wide temp root, not only the ones
this run created. Any concurrent process that creates one during the window makes the
delta positive (spurious red); any that removes one makes it negative (also red). `tmp.`
is the default `mktemp -d` prefix used by three scripts in this repo alone
(`pg-lane/run.sh`, `prod-body-drift-check.sh`, `test-ledger-drift-check.sh`) and by a
great deal of unrelated software. Vitest runs test files in parallel workers.

**Fix:** compare name **sets** and assert only on additions attributable to the run, or
give the child a private temp root and use a `mktemp -d -t` template (which honours
`TMPDIR` on both platforms) so the measurement is isolated:

```ts
const before = new Set(readdirSync(tempRoot).filter((n) => n.startsWith("tmp.")));
run(...);
const added = readdirSync(tempRoot).filter((n) => n.startsWith("tmp.") && !before.has(n));
expect(added, "a failing run left its mktemp -d behind").toEqual([]);
```

### R2-W03: WR-01's "the arithmetic must close" floor is structurally unreachable

**File:** `scripts/prod-body-drift-check.sh:237` (declaration), `:249, :266, :276, :345`
(increments), `:357-359` (the assertion)

Every path through the `for fname in "${NAMES[@]}"` loop increments `accounted` exactly
once — the fetcher-failure branch (`:249`), the empty-body branch (`:266`), the
missing-snapshot branch (`:276`) and the fall-through at the loop's end (`:345`). There is
no `continue` that skips it and no `break`. `accounted == NAME_COUNT` is therefore
guaranteed by the loop's own structure, and

```bash
if [ "$accounted" -ne "$NAME_COUNT" ]; then
  fail "MEASURE_FAIL: … only ${accounted} reached a disposition …"
fi
```

can only be made to fire by deleting one of its own increments — which is precisely how
the fix report proved it RED ("accounting floor's producer removed"). It cannot detect
"a loop that silently skipped a name", because the counter is incremented alongside the
disposition rather than derived from it.

The control that actually bites here is the `checked -eq 0` branch at `:360-370`, and
that one is genuinely good — `drift-check-scripts.test.ts:327-345` drives it with a
failing fetcher and observes `ZERO bodies compared, and only 0 of 1`.

**Fix:** derive the total from the independent tallies instead of a parallel counter, so
a dropped disposition shows up as a mismatch:

```bash
failed=0            # incremented in the three error branches, alongside bad=1
compared_names=0    # incremented once at :345
if [ "$((compared_names + absent + failed))" -ne "$NAME_COUNT" ]; then
  fail "MEASURE_FAIL: ${NAME_COUNT} named, ${compared_names} compared / ${absent} absent / ${failed} failed — the dispositions do not sum."
fi
```

Or delete the tautology and keep only the `checked`/`absent` reasoning, which is the half
that measures something.

### R2-W04: WR-03 refuses one spelling; a mutation can still satisfy the detector by renaming another arm

**File:** `scripts/mutation-runner/parse.mjs:107-116`, applied at `:135, :157, :170`

`refuseSelfSatisfying` rejects injected text matching `/TEST\s+FAILED\s*\(/i`. That closes
the literal shape GRAMMAR rule 3 documents, and only that one. The equivalent attack
carries no such literal — it *edits an existing* raise so a different arm reports under
the arm-under-test's ID. Measured at HEAD, this parses clean:

```json
{"arm":"X","apply":[{"kind":"edit","file":"supabase/tests/g.sql",
  "find":"OTHER 1): boom","replace":"X): boom","occurrences":1}]}
```

```
errors: []
structured accepted: 1
```

`firstFailureArm` (`run.mjs:318-321`) is a plain `/TEST FAILED \(([^)]*)\)/`, so the run
reports `RED (identity ok)` and raises `biting` for an arm whose own logic never ran —
the same outcome rule 3 exists to prevent. The gate file is in `corpusRels`, so this is
representable today.

**Fix:** refuse mutations that *target* the failure literal as well as ones that write it.
The needle side is the general shape:

```js
// in validateStep, for `edit` and `insert-after`
const targeted = step.kind === "edit" ? step.find : step.anchor;
if (INJECTS_FIRST_FAILURE_LITERAL.test(targeted) || /\bTEST\s+FAILED\b/i.test(targeted)) {
  throw `${at}: the mutation TARGETS a "TEST FAILED" literal. Rewriting a failure message ` +
        `— in either direction — changes what the identity check reads instead of what the ` +
        `arm does. Mutate the code under test.`;
}
```

Update GRAMMAR rule 3 to state both halves, and re-measure the 30 real annotations against
the widened rule before shipping it.

### R2-W05: WR-06's deferral exemption is self-service and has no floor — a PR can empty the pending set and the gate still passes

**File:** `scripts/verify-plan-anchors.mjs:568-594`; CI side at `.github/workflows/ci.yml:1219-1228`

A plan leaves the scanned set when it has *either* a sibling `<n>-DEFERRED.md` whose
`body.trim().length > 0` — a one-byte file qualifies — *or* the line `status: deferred`
anywhere in its own frontmatter. Both are writable by the same PR that adds the plan.

The CI assertion demands only that the count **line is printed**, never anything about its
value, and the claim floor is deliberately absent by design (`ci.yml:1168-1174`, sound
reasoning for the pre-WR-06 world). Composed, the state
`scanned: 0 pending plan file(s) of 70` + `deferred: 2 …` + `claims: 0 checked` is a
**pass**, with VAC-05 having re-resolved nothing. WR-06 removed a coupling and installed a
switch in its place; "it is printed" is not a control, because nothing compares the print
to anything.

**Fix:** make the marker cost what the honesty costs, and make the exemption visible to a
machine rather than to a log reader:

```js
// deferralMarker: a marker must carry a date and an owning phase, like 164.3-07-DEFERRED.md does
if (!/\b20\d{2}-\d{2}-\d{2}\b/.test(body) || !/\bPhase\s+\d/i.test(body)) return null;
```

and in `ci.yml`, refuse the all-deferred state outright:

```bash
deferred_n=$(echo "$deferred_line" | sed -E 's|^deferred: ([0-9]+) .*|\1|')
if [ "$total_plans" -gt 0 ] && [ "$pending_n" -eq 0 ] && [ "$deferred_n" -gt 0 ]; then
  echo "::error::MEASURE_FAIL: every non-executed plan is exempted by a deferral marker. Zero claims re-resolved."; exit 1
fi
```

### R2-W06: `baseline-wiring-claim`'s "fails in BOTH directions" holds only for one spelling of the repoint

**File:** `src/__tests__/baseline-wiring-claim.test.ts:47-58`

```ts
const assignments = lines.filter((l) => /^\s*BASELINE_FILE=/.test(l));
return assignments.some((l) => l.includes("supabase/schema/baseline.sql"));
```

Direction 1 (lane unwired ⇒ doc must say `NOT WIRED YET`) is solid and correctly
red — I confirmed the current state produces it. Direction 2 depends on Phase 164.5
spelling the path as one literal on the assignment line. A perfectly ordinary repoint —
`BASELINE_FILE="${REPO_ROOT}/supabase/schema/${BASELINE_NAME}"`, or setting it from a
`SCHEMA_DIR` variable — reads as *unwired*, and the test then **enforces the now-false
`NOT WIRED YET` prose while staying green**. That is the same claim-vs-thing failure one
level up, and it is exactly the moment this pin exists for.

**Fix:** resolve the variable rather than pattern-match the source line — run the lane and
ask it:

```ts
const res = spawnSync("bash", ["-c",
  `source <(sed -n '1,/^cd /p' ${RUN_SH} | grep -E '^[A-Z_]+=') 2>/dev/null; echo "$BASELINE_FILE"`]);
```

or, more robustly, have `run.sh` grow a `--print-baseline-path` mode (the same seam
`--assert-teardown` already established) and read that.

### R2-I02: the IN-02 invisible-character pin embeds the invisible characters literally

**File:** `src/__tests__/drift-check-scripts.test.ts:677-678`

The `INVISIBLE` character class is written with the raw U+200B/U+200E/U+2066… bytes, so the
file that forbids invisible characters is itself a scanner tripwire (it fired this
environment's `invisible-unicode` warning on read) and is not in its own `SCRIPTS` list.
Use escapes, which are byte-equivalent and visible: `/[\\u00AD\\u180E\\u200B-\\u200F\\u202A-\\u202E\\u2060-\\u2064\\u2066-\\u2069\\uFEFF]/`.

### R2-I03: `--assert-teardown` is an undocumented public mode, and `usage()` now prints a shell directive

**File:** `scripts/local-stack/run.sh:369` (the mode), `:34-37` (the INVOCATIONS block), `:358` (`usage`)

The new mode is explained where it is dispatched but is absent from the header's
INVOCATIONS list, which is the block `usage()` prints. Separately, `usage()` is
`sed -n '3,45p'`, and line 45 is now `set -euo pipefail` — the help text ends with a shell

### R2-I04: pg-lane's new IN-07 self-test arm mis-diagnoses a listener that never started

**File:** `scripts/pg-lane/run.sh:466-470, 480`

The readiness loop breaks when the bind *fails* (listener up). If the background node
listener never comes up, the loop simply exhausts its 40 iterations and falls through; the
lane then runs unrefused and the arm reports
`non-postgres listener run exited N, expected 2 — the guard is narrower than its message`,
which blames the guard for a fixture that did not start. Assert the precondition before
judging the guard:

```bash
[ "$listener_up" = "1" ] || st_fail "could not stand up a plain TCP listener to collide with (fixture failure, not a guard failure)"
```

Also cosmetic: the self-test now has five arms and still prints `SELF-TEST 1/4 … 2/4`.
