## Critical Issues

### R3-C01: the neuter scan still ends early on a branch-head keyword in a string literal, a block comment or a dollar-quoted body — the R2-C01 `SET ROLE` leak, three more spellings

**File:** `scripts/mutation-runner/run.mjs:266` (`BRANCH_HEAD`), `:277`
(`stripTrailingComment`), enforced at `:332-334`

R2-C01 correctly reordered the scan so a whole-line `--` comment can no longer terminate
it. It did **not** fix the underlying defect, which is that `BRANCH_HEAD` is a bare word
match applied to any executable line:

```js
const BRANCH_HEAD = /\b(THEN|BEGIN|ELSE|ELSIF|LOOP|DECLARE|EXCEPTION)\b/i;
const stripTrailingComment = (line) => line.replace(/--.*$/, "");
...
if (IGNORABLE_LINE.test(lines[k])) continue;                 // blank or whole-line --
if (BRANCH_HEAD.test(stripTrailingComment(lines[k]))) break; // "real branch head"
```

`stripTrailingComment` removes `--` comments; it does not remove **string literals**,
**block comments** or **dollar-quoted bodies**. Any of those carrying `THEN`/`BEGIN`/
`ELSE`/`ELSIF`/`LOOP`/`DECLARE`/`EXCEPTION` is accepted as "a real branch head", the loop
`break`s, and every statement above it is never classified — which is verbatim the leak
R2-C01 was raised for.

Measured at HEAD (`neuterArm(text, "ARM A")`, four inputs built from outside the function):

| input | `found` | `SET ROLE postgres;` still live after the neuter |
|---|---|---|
| A: `PERFORM run_sql('BEGIN');` | **true** | **true** |
| B: `/* we then raise the exception */` | **true** | **true** |
| D: `EXECUTE $q$ DECLARE junk int; $q$;` | **true** | **true** |
| G: `PERFORM set_config('x', 'a THEN b', false);` | **true** | **true** |
| F: `-- now raise the exception` (the R2-C01 regression) | false | false ✅ |
| E: `SET ROLE postgres; -- then abort` (control) | false | false ✅ |

Exact input for case A:

```
  IF NOT ok THEN
    SET ROLE postgres;
    PERFORM run_sql('BEGIN');
    RAISE EXCEPTION 'TEST FAILED (ARM A): boom';
  END IF;
```

→ `found=true`, the `RAISE` is replaced with `NULL; -- neutered ARM A`, and
`SET ROLE postgres;` is left executing for the rest of the file. Silent, no defect kind,
no log line.

Case C (`/* explanatory */`, no keyword) is refused — so a legitimate block comment above a
`RAISE` is a spurious `neuter-missed`, i.e. the primitive is wrong in both directions.

The shipped test cannot catch this. `mutation-runner-neuter.test.ts`'s new arms iterate
`BRANCH_HEAD_WORDS` inside `--` comments, and the arm named **"INDEPENDENT ORACLE: no
accepted neuter may leave a SET ROLE live"** is quantified over five hand-picked
whole-line `--` comments. It is not an oracle over the class it names; it is the same five
comment spellings the fix was written against.

I re-ran the real corpus with a replica of the scan: **38 arm scans, 0 non-structural
terminators today** — same posture as R2-C01. Phase 164.4 backfills ~70 files against this
primitive.

**Fix:** terminate only on text that is *structurally* a branch head, after masking
literals — not on a keyword appearing anywhere.

```js
/** Mask -- comments, block comments, single-quoted and dollar-quoted text. */
const executableText = (line) =>
  line
    .replace(/\$([A-Za-z_]\w*)?\$.*?\$\1?\$/g, " ")  // dollar-quoted
    .replace(/'(?:''|[^'])*'/g, "''")                 // string literals
    .replace(/\/\*.*?\*\//g, " ")                     // block comments
    .replace(/--.*$/, "");

/** A line that IS a branch head, not one that merely mentions one. */
const isBranchHead = (line) => {
  const t = executableText(line).trim().replace(/;$/, "");
  return (
    /^(BEGIN|DECLARE|ELSE|LOOP)$/i.test(t) ||
    /^EXCEPTION(\s+WHEN\b.*)?$/i.test(t) ||
    /\b(THEN|LOOP)$/i.test(t)                          // IF … THEN / FOR … LOOP
  );
};
...
if (IGNORABLE_LINE.test(lines[k]) || executableText(lines[k]).trim() === "") continue;
if (isBranchHead(lines[k])) break;
```

Verified against the real corpus before shipping: the 38 arm scans above all terminate on
lines this predicate accepts (`0 non-structural terminators`), so it refuses nothing that
exists. Then make the oracle an oracle: quantify the "no accepted neuter leaves a
`SET ROLE` live" arm over the four shapes in the table above, not over five `--` comments.

### R3-C02: GRAMMAR rule 3 — BOTH halves — is defeated by splitting the failure literal; a `sql` step is not subject to 3b at all

**File:** `scripts/mutation-runner/parse.mjs:107` (`INJECTS_FIRST_FAILURE_LITERAL`),
`:109` / `:137` (the two refusals), `:162` (the `sql` arm);
`scripts/mutation-runner/run.mjs:427-432` (`armIdentities` / `identityRewriteDetail`)

Both halves of rule 3 look for the **literal source text** `TEST FAILED (`. Nothing looks
at what the mutation *evaluates to*. SQL concatenates string literals, so the literal never
has to appear:

```

sql step, literal (rule 3a should refuse)
   errors=1 accepted=0        ✅
sql step, SPLIT literal (no `TEST FAILED (` anywhere in the annotation)
   errors=0 accepted=1        ⛔
edit step, SPLIT literal in `replace`
   errors=0 accepted=1        ⛔

firstFailureArm(runtime output) = "X 1"
```

The accepted annotation, verbatim:

```json
{"arm":"X 1","apply":[{"kind":"sql",
  "stmt":"DO $$ BEGIN RAISE EXCEPTION '%', 'TEST FAI' || 'LED (X 1): synthetic'; END $$"}]}
```

At runtime the lane emits `ERROR:  TEST FAILED (X 1): synthetic`, `firstFailureArm` reads
`X 1`, the runner reports `RED (identity ok)` and `bitingArms` rises — for an arm whose own
logic never ran, against a gate file that was never touched. This is the *original* WR-03
class, not a variant of it: **the mutation satisfies the detector instead of the arm.**

Why neither half sees it:

- **3a** (`INJECTS_FIRST_FAILURE_LITERAL = /TEST\s+FAILED\s*\(/i`) matches source text only.
  `'TEST FAI' || 'LED ('` does not contain it.
- **3b** (`identityRewriteDetail`) is called only for `edit` / `insert-after` steps
  (`run.mjs:661`, `:958`). A `sql` step never reaches it — `run.mjs:641-644` `continue`s
  before the file-step branch. And even for the `edit` variant above, `armIdentities`
  uses `/TEST FAILED \(([^)]*)\)/g` on the file text, which the split literal does not
  match, so the multiset is unchanged and `identityRewriteDetail` returns `null`.

The code and the docs both assert the opposite. `parse.mjs:130-133`: *"That shape is refused
by CONTENT … A rule stated over the annotation's spelling can always be re-spelled around;
the invariant over the file cannot."* `164.3-REVIEW-FIX-R2.md`: *"The class is closed by 3b,
the content invariant, and only by 3b."* Neither is true, and the reader who believes it is
the reader who will re-open it — the fixer's own words about 3a.

Secondary, same root cause and measured separately: an ordinary-looking mutation that
**negates the arm's own guard** evades both halves while preserving every identity —

```json
{"arm":"TENANT 1a","apply":[{"kind":"edit",
  "file":"supabase/tests/test_strategy_shares_rls.sql",
  "find":"IF NOT raised THEN\n    RESET ROLE;\n    RAISE EXCEPTION '",
  "replace":"IF TRUE THEN\n    RESET ROLE;\n    RAISE EXCEPTION '",
  "occurrences":15,"nth":1}]}
```

```
3a parser errors   : []
3a accepted        : 1
   applied.ok      : true
3b identityRewrite : null
   mutated block   :
  IF TRUE THEN
    RESET ROLE;
    RAISE EXCEPTION 'TEST FAILED (TENANT 1a): tenant A minted a share for tenant B's …';
```

The arm reports `RED (identity ok)` and bites, while the owner-coherence `WITH CHECK` it
claims to test was never evaluated. 3b's invariant is over *identities*, not over
*attribution*, and those are not the same property.

**Fix, two parts.**

1. **Close 3a's spelling hole by evaluating, not by pattern-matching.** Refuse an injected
   text whose *concatenation-collapsed* form names the literal:

```js
/** Collapse SQL literal concatenation before applying the rule. */
const collapseSqlConcat = (s) => s.replace(/'\s*\|\|\s*'/g, "").replace(/'\s*\n\s*'/g, "");
function refuseSelfSatisfying(at, field, injected) {
  if (typeof injected !== "string") return;
  if (!INJECTS_FIRST_FAILURE_LITERAL.test(injected) &&
      !INJECTS_FIRST_FAILURE_LITERAL.test(collapseSqlConcat(injected))) return;
  throw `${at}: "${field}" injects a "TEST FAILED (" literal (directly or by concatenation). …`;
}
```

2. **Make the runtime the arbiter, which is the only thing that cannot be re-spelled.** The
   lane already produces the output; assert over it. Record the identity multiset of the
   *baseline* run's output and require the mutated run's first failure to come from a raise
   that exists in the pristine gate file:

```js
// after `run` in runCorpus, before crediting the arm as biting
if (first !== null && !armIdentities(pristineGateText).includes(first)) {
  addDefect("identity-rewrite", ann.arm, gateRel,
    `MEASURE_FAIL: the first failure names "${first}", which no RAISE in the pristine ` +
    `gate file declares. The mutation SYNTHESISED the identity the detector reads.`);
  continue;   // do NOT count this arm as biting
}
```

That refuses the `sql` step above (`X 1` may exist, but the raise that produced it does
not), costs one array lookup, and is stated over the thing that actually happened.
Then re-measure the 30 real annotations and update `GRAMMAR.md` rule 3 — including the
sentence claiming 3b closes the class, and the `sql` row of the schema table, which
currently cites only rule 3a.

Add a self-test arm (8/8) whose fixture uses the split literal, so the rule cannot be

### R3-W01: `identityRewriteDetail` is blind to identity **swaps**, which are multiset-preserving

**File:** `scripts/mutation-runner/run.mjs:427-434`

```js
export function armIdentities(text) {
  return [...text.matchAll(/TEST FAILED \(([^)]*)\)/g)].map((m) => m[1]).sort();
}
export function identityRewriteDetail(before, after, file) {
  const b = armIdentities(before);
  const a = armIdentities(after);
  if (b.join(" ") === a.join(" ")) return null;
```

Sorting then joining discards **position**. Exchanging two arms' identities leaves the
sorted multiset byte-identical, so a single `edit` whose `find` spans both raises returns
`null`. Combined with a second step that breaks the *other* arm's code, the other arm
raises under the arm-under-test's ID — the exact outcome 3b exists to refuse, reached
through 3b.

Today this particular shape is caught incidentally, because a `find` spanning two raises
necessarily contains `TEST FAILED (` and 3a's needle rule fires. That is luck, not the
invariant: R3-C02's split-literal evasion applies here too, and 164.4's ~70 files will not
all format their raises the same way.

**Fix:** compare positions, not a sorted multiset.

```js
const identitiesInOrder = (text) =>
  [...text.matchAll(/TEST FAILED \(([^)]*)\)/g)].map((m) => m[1]);
...
const b = identitiesInOrder(before);
const a = identitiesInOrder(after);
if (b.length === a.length && b.every((id, i) => id === a[i])) return null;
```

A pure reordering of the file's *arms* (which no mutation should do either) then also
reads as a rewrite, which is the correct direction.

### R3-I02: `laneReadsCommittedBaseline()` can create a directory in the repo root if the probe prints an empty path

**File:** `src/__tests__/drift-check-scripts.test.ts:625-628` (the analogous probe in the
IN-04 arm), and the pattern generally

`const tempRoot = dirname(probe.stdout.trim())` yields `"."` for empty stdout. The

calibration step that follows (`mkdtempSync(join(tempRoot, "tmp."))`) would then plant a

as its own defect kind. One line closes it:
