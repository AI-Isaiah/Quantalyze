### CR-02: `plan-anchor-verify` hard-failed on the legitimate post-archive state

**Files:** `scripts/verify-plan-anchors.mjs`, `.github/workflows/ci.yml`, `src/__tests__/verify-plan-anchors.test.ts`
**Commit:** `5e7b4c58` (with WR-06 — one rewrite of one function; see the note below)

**Observed RED first**, the review's exact input:

```
$ node scripts/verify-plan-anchors.mjs --pending --root /tmp/ptest
MEASURE_FAIL: .planning/phases contains NO *-PLAN.md files. Zero pending plans because
zero plans were found is a broken glob, not a clean corpus.
$ echo $?   → 1
```

**Fix — classification, not tolerance.** Per instruction, the MEASURE_FAIL instinct was
kept and only the classification corrected. The two states are now separated by *what they
are*:

- **MEASURE_FAIL** (exit 1): `.planning/phases` cannot be **located** (`corpusState:
  "unlocatable"`) **or** cannot be **read** — `readdirSync` throwing, at the top level or
  in any phase directory (`"unreadable"`). Skipping an unreadable phase dir would let it
  report as a phase with no plans.
- **exit 0**: present, opened, every entry enumerated, zero plans → `corpusState:
  "archived"`, and an explicit line is printed:
  `measured-zero: .planning/phases exists, was READ, and contains 0 *-PLAN.md file(s) …`

⛔ The zero is only accepted *after the directory has been opened and enumerated*. An
`existsSync` never followed by a read would be the same "unmeasured reads as zero" defect
with the opposite sign.

**ci.yml demands the measurement, not the count.** `total_plans -eq 0` no longer fails on
its own; it requires the `measured-zero:` line. All three arms simulated against real logs:

```
archived corpus            → ARCHIVED ACCEPTED
unlocatable corpus         → MEASURE_FAIL … could not be located   (exit 1)
zero WITH the line removed → MEASURE_FAIL: unmeasured zero          (exit 1)
```

**A test encoding the OLD behaviour was replaced, not deleted:** "reports MEASURE_FAIL
when the corpus glob finds no plan files at all" became three tests — unlocatable,
unreadable (with a real `chmod 000`, and an explicit non-vacuous skip where a chmod cannot
bite), and archived.

   break every real PR.

   (`accounted == NAME_COUNT`), a comparator producing zero rows for a non-empty body is an

   `MEASURE_FAIL — ZERO bodies compared, and only N of M …`. A bare floor on `checked` would
   have been wrong: a PR that only *adds* functions legitimately compares nothing, and that

**Neuter → RED (accounting floor's producer removed):**

⚠️ **One bug found while writing this fix and worth knowing:** `IFS=$'\t' read -r a b` does
