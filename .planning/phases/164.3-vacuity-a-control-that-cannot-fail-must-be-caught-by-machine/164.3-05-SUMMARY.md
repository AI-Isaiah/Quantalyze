## The final grammar key names (164.4's contract)

Top level: **`arm`** (required, unique per file) · **`apply`** | **`waiver`** (exactly one) · **`neuter`** (array of `{"arm":…}`, forbidden on a waiver).

Step kinds and their keys:

| kind | keys |
|---|---|
| `edit` | `file`, `find`, `replace`, **`occurrences`** (required), `nth` (default 1) |
| `insert-after` | `file`, `anchor`, `text`, **`occurrences`** (required), `nth` (default 1) |
| `sql` | `stmt` |

Plus one per-file header line, **`RED-UNDER-SETUP`** — `{"apply":[…repo-relative paths…]}` — declaring the SQL the lane applies before this gate.

Markers are recognised only as `^[ \t]*--[ \t]*MARKER`. Unknown keys, `apply`+`waiver` together, a missing `occurrences`, `nth` > `occurrences`, a duplicate arm, or a `..`/absolute path are all parse errors naming the line.

## Decisions Made

- **`RED-UNDER-SETUP` was added beyond the plan.** The runner has to know which SQL to apply before a gate. The alternative was a gate→fixtures map inside the runner — a sidecar that would drift from the gate exactly as the plan's own reasoning says a sidecar manifest would. One in-file line keeps claim and executable adjacent.
- **`--file`/`--arm` exit 2, not 0.** A run that executed a subset of arms and printed "no defects" is a partial check reading as a full PASS — `SKIP-01`'s shape, on this phase's own defect list. Costing nothing, this makes the mistake impossible to make in CI.
- **The self-test's floor override is an internal option, not an env var.** The plan suggested an env override; an env var is a lever that could weaken the gate from outside. A function parameter reachable only from `selfTest()` cannot.
- **`ARMS_FLOOR` ships at 0 with a loud comment rather than a guessed number.** The real corpus has zero `RED-UNDER-M` twins, so no honest full-corpus measurement exists. Inventing a floor would be the fabricated-baseline defect. Recorded as a known gap (below), asserted in the contract test, and logged to `WINDOWS.md`.
- **`NULL;` substitution for neutering,** not deletion — so an `IF … THEN` whose only statement was the `RAISE` keeps a non-empty body.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] The plan gave the runner no way to know a gate's apply list**

- **Found during:** Task 2
- **Issue:** The plan says "pristine copies of the file set (fixtures + migrations + gate, per the lane README's sequence)", but never says how the runner determines that set for an arbitrary gate file. Hardcoding it would work for the one annotated file and break for 164.4's 70.
- **Fix:** Added the `RED-UNDER-SETUP` in-file declaration, parsed and validated like the other markers; a gate with annotations but no setup line is a hard `parse` defect ("the runner refuses to guess a corpus").
- **Files modified:** `parse.mjs`, `GRAMMAR.md`, all fixtures
- **Verification:** 4 parser cases; the full-corpus run reports the missing line as a defect.
- **Committed in:** `88ebbc45`, `03668516`

**2. [Rule 1 - Bug] The checkout guard conflated two different facts**

- **Found during:** Task 2
- **Issue:** The guard compared `git status --porcelain` to empty and so fired on its own newly-created fixture files — reporting `dirty-checkout` on a run that had touched nothing. A guard that always fires gets disabled, and then it protects nothing.
- **Fix:** Snapshot the tree before and after the run and diff the two. Asserts what it claims ("this run touched nothing") rather than something stricter and wrong. An unrunnable `git status` is a `MEASURE_FAIL`, never "clean".
- **Files modified:** `run.mjs`
- **Verification:** `--fixture-corpus` exit 0 with untracked WIP present; guard still reports any real change.
- **Committed in:** `03668516`

**3. [Rule 1 - Bug] ⭐ The self-test check for MEASURE_FAIL was itself vacuous**

- **Found during:** Task 3, while proving the self-test could fail
- **Issue:** With the `occurrences` assertion neutered, self-test check 4/5 **still passed**. The fixture declared `occurrences:3, nth:3` against a file with 1 match, so locating the 3rd match failed independently and a redundant downstream guard produced the same defect. The check therefore never exercised the count comparison it is named after.
- **Fix:** Changed the fixture to `nth:1`, where the needle *is* locatable and only the `occurrences` comparison can reject it. Re-neutered: check 4/5 goes RED (`exit code is 1 (got 2)`). The reasoning is recorded in the fixture itself so nobody "simplifies" it back.
- **Files modified:** `fixtures/selftest/occurrence-mismatch-gate.sql`
- **Verification:** neuter → RED → restore → green, both observed.
- **Committed in:** `83147a79`
- **Why it matters beyond this plan:** a redundant guard can make a test pass for a reason unrelated to the mechanism it names. Single-point neutering is what exposed it; running the suite and seeing green would not have. This is the phase's own thesis, found inside the phase's own detector.

**4. [Rule 3 - Blocking] `tsc --noEmit` failed on the parser's `setup` property**

- **Found during:** Task 3
- **Issue:** `result.setup?.apply` errored with `Property 'apply' does not exist on type 'never'` — TS inferred `null` from `let setup = null` in the `.mjs`. A leading JSDoc `@type` tag did not take; an inline cast did.
- **Fix:** `let setup = /** @type {{apply: string[], line: number} | null} */ (null);`
- **Files modified:** `parse.mjs`
- **Verification:** `tsc --noEmit` exit 0 (measured directly, not through a pipe).
- **Committed in:** `83147a79`
