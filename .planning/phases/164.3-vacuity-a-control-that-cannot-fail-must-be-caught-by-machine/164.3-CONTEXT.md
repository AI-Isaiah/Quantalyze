## Implementation Decisions

### Mutation runner (criterion 1) — scope and honesty
Runs over the **annotated** corpus only. It MUST print coverage as `files_annotated /
files_total` on every run and enforce a ratchet floor, because a runner reporting PASS while
covering 1.4% of the corpus is the same shape as the SKIP-that-reads-as-PASS on this phase's
own defect list. Coverage today is 1/71; the floor starts there and only rises.
For each annotated arm: apply the mutation named in its `RED-UNDER`, assert the file goes RED,
restore, assert GREEN. An annotation whose mutation does not redden its arm FAILS THE BUILD.

### Disposable-PostgreSQL lane (criterion 2) — and it must clean up after itself
`PROC-01`'s implementation, promoted from the mid-phase script. Two defects its own reviewers
already hit are requirements, not anecdotes: it reused another agent's cluster and then
`DROP SCHEMA public CASCADE`, and it enabled RLS on nothing but the table under test.
⚠️ **A third, measured 2026-08-28: the harness leaks clusters.** Eleven orphaned postmasters
were found still running from the Phase 164 harness, holding memory and datadirs, contributing
to a disk-exhaustion incident. The lane MUST stop and remove every cluster it starts, including
on failure and interrupt.
⭐ Cross-phase payoff: this lane is what makes Phase 159's two remaining open items
(concurrent-CAS, and the 409 remedy that a browser structurally cannot produce) closable.

### Criterion 5 (plan-anchor verification) — stays in this phase
It is a different artifact (PLAN.md, not SQL) at a different execution point, and shares no
code with the runner. Kept anyway: the phase is scoped by ROOT CAUSE — *the claim and the thing
are never compared* — not by subsystem, and splitting would leave a one-criterion phase.
Planned as its own wave so it can be lifted out if it bloats. Evidence it is real: both wave-3
plans were stale on arrival — `164-03` specified a two-argument `deriveShareToken` that would
have minted links failing verification, and `164-04` anchored edits at `v2/page.tsx:563-573`
in a file that had shrunk to 423 lines.

### Claude's Discretion
Runner language (bash vs node), linter host (custom vs an existing SQL lint), how the coverage
floor is stored. Any choice must keep the runner runnable locally AND in CI with identical
semantics — an A/B that changes invocation mode is not an A/B.
