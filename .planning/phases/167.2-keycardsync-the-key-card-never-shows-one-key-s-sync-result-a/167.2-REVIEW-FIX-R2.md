### WR-02: the Delete trap, resolved per FOUNDER DECISION 2026-09-24

**Files modified:**
- `src/components/strategy/ApiKeyManager.tsx`
- `src/components/strategy/key-card-copy.ts`
- tests
- `167.2-UI-SPEC.md`, `167.2-CONTEXT.md` (KCS-23), `.planning/ROADMAP.md` (the 167.2 deviation
  line)
- `deferred-items.md`

**Commits:** `b3d53f587` applied the orchestrator's first rule: refuse only for a non-archived
composite, before the confirm, in amber. The founder then decided otherwise, and `596d0f171`
applies that decision and supersedes the earlier rule.

**Applied fix (final):**
- A composite member key's Delete is never refused. When the existing "permanently remove" confirm
  opens, a bounded (15 s) membership read runs (`readKeyCompositeMemberships`). It embeds each
  composite's own name and status. The confirm's Delete is held only while that read is open.
- A key in any composite, of any status, gets an amber warning inside the confirm
  (`deleteCompositeWarning`, KCS-DELETE-COMPOSITE). The warning:
  - names every composite (an unnamed one is still listed);
  - says the key is removed from them;
  - says that a composite with no other key left becomes unlinked;
  - for a published composite, says the database guard (`api_keys_published_composite_delete_guard`)
    will refuse the delete.
- The owner can then confirm and delete.
- A failed or timed-out read shows KCS-DELETE-UNCHECKED and still lets the owner choose. The
  failure is captured.
- The round-1 refusal copy is retired.

**Owner path for drafts:** the draft-specific wording from `b3d53f587` was dropped with the
refusal. For the record, the owner-reachable members editor, found by symbol, is the strategy
wizard. Its connect-key step (`MultiKeyConnectStep`) re-posts members through
`/api/strategies/composite/set-members`. `/strategies` opens it only for the latest wizard draft
(`readLatestWizardDraft`).

**Tests:**

  after confirm.
- `R2-WR02-TWO-PUBLISHED`.
- `R2-WR02-UNREADABLE`: the warning shows, the failure is captured with tags only, and the delete
  still proceeds.
- `R2-WR02-NO-MEMBERSHIP`.

### R2-M1: a late transport failure was rendered as a definitive "Sync failed"

**Files modified:**
- `src/components/strategy/ApiKeyManager.tsx`
- tests

**Commit:** `3e74d60c4`

**Applied fix:** `syncFailureMessage` now returns an `EnqueueAnswerError` with one of three kinds:
- `verdict`: the route's own JSON `error` or `human_message` body;
- `transport`: a non-JSON failure;
- `unrecognized`: a 2xx without enqueue evidence.

A thrown fetch counts as transport. Only a late `verdict` replaces the `enqueue_bound` panel. The
`late-enqueue-answer` capture carries a `kind` tag. A live attempt shows the same message as before.

**Tests:** `R2-M1-TRANSPORT` covers a non-JSON 504 and a rejected fetch. Both went RED under the
neuter. `LATE-REJECTION` (a verdict) still passes.
