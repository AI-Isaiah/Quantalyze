# Phase 167.2 Plan 02: the post-add sync is the tracked attempt, and the two overlaps are blocked Summary

**The sync after an Add Key now runs through `handleSyncTrades(newKeyId)` as the card's one tracked attempt: it holds the marker, is polled, and reports failure on the panel. Connect Key is blocked with the locked KCS01 reason while an attempt is live. Every Resync, Use & Sync and panel Retry is refused while an add is in flight.**

- **Tasks:** 2 of 2
- **Files modified:** 5 (1 created, 4 modified)

## Accomplishments

- **KCS-01, first half (Task 1).** `handleAddKey` no longer links the strategy or fires the untracked `fetch("/api/keys/sync")` chain. After the validate returns `api_key_id`, it runs `retireWithheldSuccess()` (R5, kept), closes the form and starts `handleSyncTrades(newKeyId)` without awaiting it. The post-add sync therefore takes the in-flight marker and links the new key. A failed link sends no sync request, so NEW-C37-03 holds. The sync enters `computing` only on enqueue evidence, is polled, and ends through `endAttempt`. A link failure now appears as that attempt's `Sync failed`, with the same `Failed to link key to strategy: …` message. The comment lineage of the removed chain (B-06, FINDING-10, R6 corrected, WR-01) sits above the call.
- **KCS-01, second half (Task 2).** `key-card-copy.ts` builds KCS01-BLOCKED and KCS01-BLOCKED-NOLABEL verbatim from the UI-SPEC. `ApiKeyForm` gains an optional `submitBlockedReason` prop. When it is set, the form renders the reason in a `<p className="text-xs text-text-muted mt-3">` after the error line, disables Connect Key, links the two through `aria-describedby`, and refuses the Enter-key submit. `ApiKeyManager` passes the reason while `syncingKeyId` is set.
- **P7, the reverse overlap.** `addInFlightRef` is set from before the validate request until the add hands off to its own attempt, and it is cleared in `finally`. `handleSyncTrades` registers nothing while it, or a live attempt, is set. Resync and Use & Sync are disabled on `!!syncingKeyId || loading`. The R4 / R5 key-scoped disables are unchanged (KCS-05).
- **Pins moved, none deleted.** Every case whose premise KCS-01 removed now pins the prevention. Each one names KCS-01 and keeps its lineage. The `it(` count is 57, the same as at `origin/main`'s merge-base, with 7 more `it.each` rows. See "Moved pins" below.
