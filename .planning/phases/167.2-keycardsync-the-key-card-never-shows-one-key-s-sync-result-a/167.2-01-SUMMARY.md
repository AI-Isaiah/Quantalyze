## Accomplishments

- `src/lib/compute-state.ts`: the route's selection, member projection and stitch-only stall rule, lifted and not rewritten. The one intended change is KCS-20: the non-stitch fallback is now the latest FACTSHEET-CHAIN job, so a newer `reconcile_strategy` or `sync_funding` row can no longer answer `done` for a strategy whose chain job failed.
- `deriveComputeState` / `recipientArm` / `jobPhaseOf` / `isFactsheetJobInFlight`. The derivation picks one of eight locked states. `done_pending_children` becomes `queued` (KCS-19). An empty selection becomes `never_started` only when the read was exhaustive; otherwise it is `unreadable` (KCS-20). The measured trigger shape derives `failed { permanent }` → `not_available`.
- `/api/strategies/[id]/sync-progress` now uses the shared helpers and reads a 100-row window (`COMPUTE_STATE_READ_LIMIT`). Every guard runs in the same order as before. PIN-COMPOSITE-BYTES and PIN-COMPOSITE-WINS are byte-unchanged and green.
- `src/lib/status-surface-copy.ts` holds every S4-S9 string from UI-SPEC (KCS06, KCS09, KCS21, KCS12, KCS10, KCS11), with one pinned test per id. The tables are compile-time total.
- `src/lib/strategy-shape.ts`: the one composite predicate (a `strategy_keys` head count above zero). If the count errors, comes back null or throws, the result is `unknown` and never `single`.
- Comment-only corrections: `StitchJobStatus` (done_pending_children is in flight), `SyncProgressResponse.jobStatus`, and the two SyncPreviewStep docblocks (null means no factsheet-chain job is visible).

## Decisions Made

- **Unknown shape in a shape-remedy state (KCS-21, the planner's decision, carried out).** It renders the locked KCS09-UNREADABLE remedy, "Reload this page to try again.", with no link. The remedy's `id` is `KCS09-UNREADABLE`. No new copy was authored.
- **`jobPhaseOf("stitch_composite")` is `compute`.** This follows the RESEARCH Q3 table. A running stitch reads as `fetch` with key N of M while any member is not yet `successful`, and as `compute` once every member is. Through `deriveComputeState`, the `unknown` phase cannot be reached, because the selection admits only recognised kinds. `jobPhaseOf` still returns `unknown` for any other kind string, and the tests cover that.
- **A `degraded` member counts as not successful** for key N of M. That is the literal UI-SPEC rule (n = successful + 1, capped at m).
- **`untrustedKeyCaption` resolves display names with `Object.hasOwn`**, so a stored code such as `constructor` renders as stored and never resolves to a prototype member.
- **The shape remedy hrefs pass the strategy id through `encodeURIComponent`.** For a uuid this changes nothing.
