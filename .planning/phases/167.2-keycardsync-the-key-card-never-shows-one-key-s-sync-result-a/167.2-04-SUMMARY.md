# Phase 167.2 Plan 04: the key card says when it stopped checking, not that the sync failed Summary

**If the sync panel's two-minute poll budget or its 30-second missing-row grace runs out, the attempt now ends in a muted `No result yet` state. The detail sentence says how long the panel waited, and there is no Retry. "Nothing recorded yet" appears only after clean reads that never saw a row. A failed read runs to the cap. The old "Analytics computation timed out" sentence is gone from the source. An evidenced failure now shows the server's own `computation_error`, or no detail at all.**

## Accomplishments

- **key-card-copy.ts (KCS-22 / KCS-14).** Three constants move here from `SyncProgress.tsx` with their comments and lineage: `POLL_MAX_ATTEMPTS` (40) and `MISSING_ROW_GRACE_POLLS` (10), plus the new `POLL_INTERVAL_MS` (3 000). The new `formatBoundDuration` returns whole "N seconds" below one minute and "N minutes" above it, and throws on a fraction. `PANEL_STOP_COPY` (`satisfies Record<PanelStopReason, …>`) holds KCS22-CAP and KCS22-NOROW verbatim from the UI-SPEC, and computes their durations from the bounds.
- **SyncProgress.** The UI-only `no_result` status gets idle's muted treatment. The label comes from `PANEL_STOP_COPY[stopReason ?? "poll_cap"]`, and the detail sits in `text-xs text-text-secondary mt-1 ml-6`. There is no Retry. `onStatusChange` now takes an optional `SyncStatusInfo`. The poller's `onError(reason)` maps `"missing_row"` to `missing_row` and anything else to `poll_cap`. An evidenced failed row is forwarded with `{ computationError }`. The poller's schedule is `POLL_INTERVAL_MS`.
- **useStrategySyncPoller (interval arm only).** The attempt cap now calls `onError("cap")`. At the grace boundary the arm calls `onError("missing_row")` only when both hold: the effect-local `sawRow` is false (it is set by any read that returns data), and the read was clean. Otherwise it keeps polling. The option doc, the module header and the grace-site comment say this. The ladder arm has no changes: every diff hunk sits above the `LADDER MODE` block.
- **ApiKeyManager.** A new `no_result` arm ends the attempt, sets `panelStopReason` and clears `syncError`. `panelStopReason` resets when each attempt is registered, and the panel gets `stopReason={panelStopReason}`. The `error` arm's FINDING-8 default becomes `prev ?? info?.computationError ?? null`, so an enqueue failure's message is never overwritten. The rewritten comment does not quote the retired sentence.
