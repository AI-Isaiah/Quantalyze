# Phase 167.2 Plan 10: a key-card success waits for the job queue Summary

**Before the key card's sync panel forwards a terminal success, it now reads `/api/strategies/[id]/sync-progress` once. It forwards the success only when that read is real and `isFactsheetJobInFlight` finds no factsheet-chain job still running. A warned strategy's resync therefore no longer says "Synced with warnings" while its chain is mid-run. An unreadable answer never counts as a success.**

## Accomplishments

- **SyncProgress (KCS-18).** A terminal can pass plan 03's evidence gate (a `computing` read, or `computed_at` moved from the baseline). After that:
  - A `failed` terminal is forwarded as it stands.
  - A success (`complete` or `complete_with_warnings`) first calls `jobQueueSaysChainSettled`, which does `fetch("/api/strategies/<id>/sync-progress", { cache: "no-store" })`. It returns `true` only when the answer is HTTP ok, parses to a JSON object, is not `degraded: true`, carries a `jobStatus` that is null or a string, and `isFactsheetJobInFlight(jobStatus)` is false.
  - Every other answer returns `false`, and the helper never throws.
  - `jobCheckInFlightRef` allows one read at a time. `computingTokenRef` is an object that an effect keyed on `syncStatus` sets and its cleanup clears. The read captures it, and it must still be the same object when the answer lands, so an answer arriving after unmount or after the panel left `computing` forwards nothing.
  - `warnedUnreadableRef` limits the `console.warn` for unreadable answers to one per attempt. The panel is keyed per attempt, so this resets with each new attempt.
  - The comment names KCS-18 and RESEARCH P1. `Date.now` does not appear in the file (count 0).
- **Tests.** `SyncProgress.poll.test.tsx` gets a queue of sync-progress answers, defaulting to a real `done` read, so PIN 5 and PIN 5c pass unedited. It adds WARNED-ROW-MID-CHAIN and eleven fail-closed and concurrency cases (17 test rows). `ApiKeyManager.poll.test.tsx` turns plan 03's fixed `done` arm into a `jobStatuses` queue (the lineage is noted in the file) and adds WARNED-ROW-KEYCARD, which runs on the real card, panel and poller.

## Decisions Made

- The check lives in `SyncProgress` after the evidence gate. The `ApiKeyManager.test.tsx` sites that drive `capturedOnStatusChange` by hand therefore still mean "a status the panel forwarded", as with plan 03.
- The late-answer guard uses an identity token rather than a boolean. A panel that leaves `computing` and comes back gets a new token, so an answer from the earlier stretch cannot forward into the later one.
- A missing or non-string `jobStatus` counts as unreadable. The route always sends the key, so a body without it is not the projection.
