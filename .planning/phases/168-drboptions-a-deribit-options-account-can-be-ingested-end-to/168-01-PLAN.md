<objective>
Classify Deribit's `assignment` transaction-log type as cash-bearing on both twins in exactly the
shape the 2026-09-23 census measured, keep the unobserved shape refused, and prove it end to end
through the native-ledger crawl (D-01, D-02, D-02 amended, D-03, D-04, D-05, D-07 structural part).

Purpose: every Deribit options account with a nonzero-change `assignment` row currently fails
ingestion with the unknown-type refusal and the wizard's Retry cannot clear it. The fix must
neither drop the realized cash (the census shows the `assignment` is the only cash event of that
expiry) nor double-count it (the shape where a same-instrument `delivery`/`settlement` also exists
was never observed, so it stays loud).

Why the six-literal swap is in this plan and not plan 02: adding `assignment` to
`CASH_BEARING_TYPES` without it leaves a commit where `mark_to_market` sums the full `change`
inside summary coverage while the options settlement summary also carries it (RESEARCH Pitfall 2).
Putting the set edit, the guard and the swap in one task keeps every commit on the branch fail
closed. Plan 02 pins each site's behaviour with its own test.

No migration is needed: this is pure Python under `analytics-service/`.

Seventh literal, decided in plan 02 (D-04): `scripts/deribit_acceptance.py`
`check_perp_only_eligibility` also names the option events by the literal pair. It is an offline
byte-identity-control eligibility check, not a P&L path, so leaving it for one commit cannot make
any ingestion fail open; it is therefore not part of this plan's same-commit set, and plan 02
Task 1 swaps it to `_OPTION_BOOK_EVENT_TYPES` with its own neutered test.

Output: the D-03 evidence file, the classification, the shared co-occurrence guard, the option
book event constant, the windowed-crawl backstop, and the tests that pin them.
</objective>
