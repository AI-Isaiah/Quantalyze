### The prepared recipe — for the founder, after the merge

**Step 0 — the precondition that makes the rest meaningful.** Confirm this phase's restore-script changes are on the default branch. ⛔ If they are not, **STOP**: the dispatch would run the OLD script, prove nothing about this phase's guards, and still destroy and rebuild a shared schema. That is the worst of both outcomes and it looks green.

**Step 1 — derive the confirm token AT THE DISPATCHED REF.** It is the first 8 hex characters of the sha256 row recorded in `supabase/schema/BASELINE.md`. ⛔ It moves with that file, so a value copied out of any planning document is stale by construction — which is why no token value is written here. Read it from the file at the ref you are about to dispatch.

**Step 2 — PREFLIGHT FIRST.** `mode=preflight` runs the whole transaction and rolls it back.

```
gh workflow run test-restore-from-baseline.yml --ref <default-branch> -f mode=preflight
```

Read, in order: the `── pre-census (read-only) ──` banner and its counts; one `survivor` line per censused object and the `survivors censused: <n>` total; ⚠️ **any `survivor` line whose key begins `pub:public.`** — that is a pre-write refusal the preflight names, whose remedy is a founder-run publication drop recorded in the restore log, then a re-preflight; the `expected shape from the dump text: …` line; the `transaction assembled at … (filtered: <n> …)` line, where **a `filtered:` count of 0 against the real dump means the filter stopped matching, not that there was nothing to filter**; and the closing `preflight: post-census == pre-census (byte-for-byte …) … mode=preflight` line. **Anything else on that closing line — above all a diff — means the database was modified: treat it as modified.**

**Step 3 — DECIDE.** There is no automatic promotion from a green preflight to a restore, by design. ⚠️ And per the measurement above, the preflight does **not** exercise the extension guard, so a green preflight is a statement about the rollback, not about that guard.

**Step 4 — EXECUTE, only on a green preflight.**

```
gh workflow run test-restore-from-baseline.yml --ref <default-branch> -f mode=restore -f confirm=<token derived in step 1>
```

**Step 5 — READ THE RESULT.** The restore log ends with the script's one-line summary followed by the pinned-CLI post-verify. ⚠️ The post-verify proves the ledger's **shape** only — the CLI parses it and finds nothing pending — and proves no object exists.
