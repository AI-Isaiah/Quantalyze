     computed relation name, an array/spread/variable payload, or a dynamic function name is

     pipeline: every `.schema(\"x\")` call site is checked against the exposed-schema list

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `.from()` receiver-lookback window too narrow for a multi-line chain**
- **Found during:** Task 2 (running the census over the real corpus)
- **Issue:** The variable-to-schema correlation used to skip the table/column check on a
  schema-scoped `.from()` call looked back only 12 characters (with no trailing-whitespace
  allowance) before the `.from(` keyword. `src/__tests__/retention-crons.test.ts` writes
  `const schemaScoped = (admin as any).schema("cron"); ... await schemaScoped\n  .from("job")` —
  the receiver identifier sits on the PREVIOUS source line, well outside a 12-character window,
  and the trailing `\s*$` was missing so even a shorter gap would not have matched. The census
  therefore reported a spurious `absent-table: job` alongside the correct
  `unexposed-schema: cron` finding for the same call site.
- **Fix:** Widened the lookback window to 60 characters and changed the receiver regex to
  `/([A-Za-z_$][\w$]*)\s*$/` so trailing whitespace/newlines between the receiver and `.from(`
  no longer defeats the match.
- **Files modified:** `scripts/live-db-fixture-drift-census.mjs`
- **Verification:** Re-ran the census; the spurious `absent-table: job` finding disappeared and
  `retention-crons.test.ts` now reports exactly its one genuine `unexposed-schema: cron` finding.
  `--self-test` re-run clean (4/4 classes still isolate correctly).
- **Committed in:** `ba951e1a` (Task 2 commit, since the fix was made and verified while
  producing the seeded baseline it corrects)

---

**Total deviations:** 1 auto-fixed (1 bug)
**Impact on plan:** Necessary for correctness — without the fix, the seeded baseline would have

absent from the `public` catalogue because it lives in `cron`, a schema question the

## ROADMAP Criterion 13 — Signature-by-Signature Verdict

RESEARCH traced only 3 of the ROADMAP's 5 recorded failure signatures statically. This plan's
census independently REPRODUCES those 3 from the real corpus (not merely from the catalogue, as
RESEARCH's own citation for the overload case was) and finds a 4th column-shaped defect RESEARCH's
sample did not name:

| ROADMAP signature | Reproduced? | How |
|---|---|---|
| `PGRST203` (2 live overloads of `claim_compute_jobs_with_priority`) | **YES, from the real corpus** | `src/__tests__/claim-failed-retry-dedupe-migrations.test.ts:397` calls `.rpc("claim_compute_jobs_with_priority", { p_batch_size, p_worker_id })` — a payload that is a subset of BOTH declared overloads' parameters, so the census's `ambiguous-overload` rule fires on it directly (not merely on the catalogue's declaration count). |
| `PGRST205` (table absent from schema cache) | **NOT reproduced as a corpus finding** | The census's `absent-table` class is proven to fire on its fixture (a call to a genuinely undeclared relation), but no `.from()` call site in the current corpus names a relation the `public` catalogue does not declare. `PGRST205` in the original 38-failure run may be schema-CACHE staleness on shared TEST specifically (a live-only condition this static tool cannot see) rather than a catalogue mismatch — recorded as a gap, not rounded into a claim of coverage. |
| `PGRST204` (`api_keys.key_hash` absent) | **YES, from the real corpus** | `src/__tests__/claim-dedupe-done-pending-children-guard.test.ts:300` inserts `key_hash` into `api_keys`; the census's `absent-column` rule fires. The census ALSO found the insert's `status` key is not a column (RESEARCH's sample did not name this second defect in the same insert). |
| `Invalid schema: cron` | **YES, from the real corpus** | `src/__tests__/retention-crons.test.ts:96` calls `.schema("cron")`; `cron` is absent from `config.toml`'s `[api].schemas` list, and the census's `unexposed-schema` rule fires. |
| `42501` (permission denied) | **NOT statically decidable** | Documented explicitly in the tool's header: which role a live client authenticates as is a runtime fact, not anything present in tracked text. This class is out of the census's declared scope by design, not by oversight. |

variable `.insert`/`.update`/`.upsert` payloads, computed relation/schema/function names) —
counted honestly, never silently folded into "ok". These, plus the `PGRST205` gap and the
inherently-undecidable `42501` class, are the residue plan 08 must classify by execution in the
