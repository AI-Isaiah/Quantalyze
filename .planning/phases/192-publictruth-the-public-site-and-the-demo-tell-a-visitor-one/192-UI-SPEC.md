# Phase 192 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** This phase is mostly copy. It edits sentences on existing marketing pages, replaces one home-page section with a sign-up call to action, and finishes `/demo`. It adds **no new visual language**: every element below reuses a class string, component or token that already ships on the same page. Requirements: TRUST-01, ROUTE-03. Locked decisions: `192-CONTEXT.md` D-01..D-10. Governing documents: `DESIGN.md` (Voice / microcopy, AI-Slop Ban, Numbers Contract, Meeting hero rule, Semantic-color gates).

**Two rules every row below obeys:**
1. **Never invent data.** A figure that cannot be computed is removed together with the claim it supports (D-08). No fee figure, legal entity or jurisdiction is written (REQUIREMENTS Out of Scope).
2. **The sentence changes, the behaviour stays** (D-03, D-04 and the SC-2 note). The phase rewrites what a page says about TLS and factsheet visibility. It does not change either behaviour.

### Shared sentences (one source each, D-02 / D-05 / D-06)

Each shared sentence is defined **once**, as an exported constant, and every page renders it from that constant. Claude's discretion (CONTEXT) prefers an existing module. Put the constants in `src/lib/status-surface-copy.ts`, which CONTEXT names as the centralised copy module and which already exports public sentences (`KCS10_PUBLIC_SENTENCE`, `SHARE_CARD_COPY`).

| Id | Constant (suggested) | Copy (verbatim) | Rendered on |
|----|----------------------|-----------------|-------------|
| S-KEY | `KEY_STORAGE_SENTENCE` + `KEY_STORAGE_LINK = { href: "/security#key-handling", label: "How we store keys" }` | "We store your read-only API key encrypted, under a data key of its own, and only our analytics service can decrypt it." followed by a space and the link **How we store keys**, then a full stop | Home (new section), `/for-quants` (the "Envelope encryption at rest" trust row), Terms §2 |
| S-COST | `LISTING_COST_SENTENCE` | "Listing a strategy is free. A success fee may apply to matched allocations, as set out in the manager agreement." | `/for-quants` hero sub-line, Terms §7 |
| S-EXCH | `EXCHANGE_LIST` (derived, not typed) | `new Intl.ListFormat("en", { style: "long", type: "disjunction" }).format(EXCHANGES)`. At HEAD this reads "Binance, OKX, Bybit, or Deribit". Never type the names or the count by hand | Home (new section), `/for-quants` How-it-works step 01 |

**S-KEY must be true clause by clause at HEAD (D-01).** What this research measured on 2026-11-06, for the planner to re-read rather than trust:
- `analytics-service/services/encryption.py` encrypts credentials with **Fernet** under a fresh per-credential DEK (`generate_dek` → `Fernet.generate_key()`). It wraps the DEK with a KEK that it reads from the analytics service's own `KEK` environment variable, and tracks a `KEK_VERSION` for rotation.
- The code path has **no Supabase Vault**, and it does not use **AES-256-GCM**. Fernet is AES-128 in CBC mode, authenticated with HMAC-SHA256.
- So `/security` (AES-256-GCM, Vault-held KEK), `/for-quants` (Fernet, but a Vault-held KEK) and the home form ("Your keys are never stored.") are each false somewhere.
- If any clause of S-KEY turns out false at HEAD (for example, if the web tier can decrypt), **delete the clause**. Never soften it with an adjective.
