## Decision notes (recorded for the founder)

- **A retired route answers like an unknown URL, not with a 404, for a signed-out visitor (conflict resolved, reversible).** D-11 removes /demo from PUBLIC_ROUTES. The planning brief also asked that a removed public route 404. The two cannot both hold for a signed-out request: `src/proxy.ts` sends every signed-out request for a path outside PUBLIC_ROUTES to /login before Next routes it. With the entry gone, a signed-out /demo gets a 307 to /login, the same answer every URL that never existed gets today. A signed-in /demo passes the proxy and reaches Next, which has no route for it, so it gets the 404. Keeping a /demo entry in PUBLIC_ROUTES only to get a signed-out 404 would keep demo wiring in the proxy, against D-11, so D-11 is followed (CLAUDE.md Rule 7: the locked decision wins over a verification instruction). The proof is stated to match: the build has no /demo route, the signed-out answer equals a never-existing control path, and the proxy test pins both directions. Reversibility: reversible (one array element in `src/proxy.ts`). The orchestrator can flip it by re-adding the entry; the founder has not been asked.
- **One commit for the lockstep.** `scripts/check-route-contract.ts` Rule 1 (a page needs a manifest entry), Rule 2 (a public entry needs PUBLIC_ROUTES) and Rule 4 (an entry needs a page) bind the page, its manifest entry and its PUBLIC_ROUTES entry together. The page's own two test files import it, and `src/__tests__/display-sign-single-source.test.ts` reads it by path. So Task 1 touches more than five files, but four of them are deletions and the rest are single-row edits.
- **What this plan does not remove.** The public PDF endpoint under `src/app/api/demo` and the `/api/demo` PUBLIC_ROUTES entry (plan 192-15), the demo-only components and readers (plan 192-13), the demo e2e specs and CI wiring (plan 192-14), the match-queue demo props (plan 192-12). Each of those still compiles after this plan: nothing imports a page file.
- **Phase 193 fence.** Nothing under `src/app/factsheet` or `src/lib/factsheet` is touched (the factsheet "Demo portfolios" section and the demo payload producers belong to Phase 193).
- **No PROD writes or deletes (D-11).** The PROD demo rows stay.
- **Worktree builds.** `node_modules` in a phase worktree is a symlink that resolves outside the worktree, so Turbopack needs a temporary `turbopack.root` (plans 192-07 and 192-09 recorded this), and the build needs the full placeholder env of the `npm run build` step in the `frontend-build` job of `.github/workflows/ci.yml`, including `SHARE_TOKEN_SECRET`.
