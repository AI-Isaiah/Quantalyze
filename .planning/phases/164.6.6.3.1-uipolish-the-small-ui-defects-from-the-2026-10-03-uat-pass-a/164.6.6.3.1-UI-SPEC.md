## Element Contracts

One contract per item. Each lists the visual result, the interaction, and the states it must
cover.

### Item 1 — Edit-form strategy name (D-01, D-02)
- **Surface:** `src/components/strategy/StrategyForm.tsx`, edit mode.
- **Options:** if `strategy.name` is in `STRATEGY_NAMES`, the list is `STRATEGY_NAMES` as today.
  If not, the strategy's own name is **prepended** as the first option, label = value = the
  name verbatim, with no suffix or marker. No duplicates.
- **Selection:** the picker preselects `strategy.name`. "Alpha Centauri" is never substituted
  for an existing name. Create mode is unchanged (`STRATEGY_NAMES[0]` default).
- **Payload (D-02):** the edit-mode update carries `name` only when the picked value differs from
  the name the form opened with. A deliberate pick still renames. A save that only changed other
  fields sends no `name` key.
- **No visual change:** same `Select`, same label, same position.

### Item 6a — One disclaimer; a dated batch chip (D-07)
- **Remove** `<Disclaimer variant="footer" />` from `src/app/(dashboard)/recommendations/page.tsx`
  and `<Disclaimer />` (default variant = `footer`, the same text) from
  `src/app/(dashboard)/portfolios/[id]/page.tsx`. `DashboardChrome` stays the sole owner of the
  footer disclaimer. Census at `5e96cb62b`: these are the only two `<Disclaimer` sites under
  `src/app/(dashboard)`.
- **Batch chip:** the recommendations header pill reads `Batch: Fresh · Oct 6`. Anatomy, left
  to right: existing tone dot, `Batch:`, freshness word, a `·` separator with one space each
  side, then the date in a `.font-metric` span. Same pill (`rounded-sm px-2.5 py-0.5
  text-fixed-11 font-medium`, the tone colours) and same `title` tooltip.
- **Opt-in:** the date is shown through an opt-in on `FreshnessBadge` (or a call-site
  composition). The portfolio (`label="Analytics"`) and tearsheet callers stay byte-identical.
- **Null:** the chip already renders only when `batch.computed_at` is set. No date is ever
  fabricated, and an unparseable timestamp shows no date segment rather than "Invalid Date".

### Item 6c — Bottom-nav label wraps whole (D-08)
- **Surface:** `src/components/layout/MobileNav.tsx`, both the `<Link>` and the `<button>` cell
  arms.
- **Cell:** add `min-w-0` to every `flex-1` cell.
- **Label:** wrap the label text in a span with `text-center leading-tight`. Break at word
  boundaries only, with no mid-word break, no `truncate` and no `line-clamp`.
- **Height budget:** 8 + 20 (icon) + 2 (gap) + 2 × 12.5 (two 10px lines at 1.25) + 8 = 63px,
  plus the 1px top border = **64px**, exactly the `pb-16` reservation in `DashboardChrome`. A
  label that would need three lines at 320px is a defect. At 320px with five cells (64px each),
  every current label ("My Allocation", "Add a Strategy", "My Strategies", "Discovery", "Risk",
  "Bridge", "Strategies", "Profile") fits in at most two lines.
- **Unchanged:** the 44px minimum, the focus outline, the active accent, and the badge position
  (absolute on the icon).

### Item 6d — α survives the uppercase (D-09)
- **Surface:** the KPI strip label `<p data-testid="factsheet-kpi-label">` in
  `src/app/factsheet/[id]/v2/FactsheetView.tsx`.
- **Render:** when a label begins with `α`, render the glyph in its own
  `<span className="normal-case">α</span>` followed by the rest of the string. The container keeps
  `uppercase`, its tracking, `whitespace-nowrap overflow-hidden text-ellipsis` and the muted
  colour.
- **Result:** "α VS BTC", never "Α VS BTC". The DOM text content stays `α vs BTC`, so screen
  readers and tests see the true symbol. The React `key` stays the label string.
- **Out of scope:** the `α` in `BatchDPanels.tsx` and `OutcomesWidget.tsx` sits in sentence-case
  prose, not under `uppercase`, so it is unaffected.

### Item 6e — Loading is not empty (D-03)
- **Surface:** `src/components/strategy/ApiKeyManager.tsx`.
- **State:** add a "first read settled" flag, set when the first `loadKeys` call returns on any
  arm, clean or error. Later re-reads (after a sync, a password update or a Retry) never bring
  the loading caption back. Rows already on screen stay put during a re-read.
- **Loading render:** same `Card`, same inner box as the empty state (`text-sm text-text-muted
  text-center py-4`), text "Loading keys…", on an element with `role="status"` and
  `aria-live="polite"`. Because the box is the same, the swap to the list or the empty sentence
  changes only the text and the layout does not jump.
- **No skeleton blocks and no spinner** (DESIGN.md § Motion: no spinning, no decorative
  animation). One caption line only, per D-03.
- **Mount condition:** `!firstReadSettled && !showForm`, parallel to the empty state's
  `!showForm`.
- **Empty render:** only when `firstReadSettled && listedKeys.length === 0 && !loadError &&
  !showForm`.
- **Error render:** unchanged (`loadError` card + Retry).

### Item 6f — "Manage private link" (D-05, D-06)
- **Surface:** the `ShareableLink` mount in `src/app/(dashboard)/strategies/page.tsx`, the row's
  action cluster.
- **Data:** ONE batched read of the owner's non-revoked shares for the listed strategy ids,
  server-side in the page, shaped like the factsheet's `hasActiveShare` derivation. It is
  passed to each row as a boolean. No per-row read.
- **Label matrix:**

  | Row state | Button label | Click |
  |-----------|--------------|-------|
  | published | "Share Factsheet" (unchanged) | copies the public URL (unchanged) |
  | unpublished, read confirmed no live share | "Get private link" (unchanged) | mints and copies (unchanged) |
  | unpublished, read confirmed a live share | **"Manage private link"** | opens the Modal |
  | unpublished, read failed | "Get private link" (D-06) + logged | mints and copies (unchanged; the route reuses a live token) |

- **Button:** the same `Button variant="secondary" size="sm"` with
  `pointer-coarse:min-h-[44px]`, the same link glyph, `aria-haspopup="dialog"`. No new colour.
- **Modal:** `Modal` titled "Private link", body = `OwnerUnpublishedPanel` with
  `strategyId` and `hasActiveShare={true}`. That gives the existing notice ("Unpublished —
  shared through your private link" plus its body sentence), "Copy share link", and the existing
  inline revoke confirm. No copy is authored here.
- **After revoke:** once the panel's state flips to not-live and the Modal closes, the row
  button reads "Get private link" without a full page reload. The row label and the panel must
  never disagree.
- ⚠️ **Interpretation recorded (Claude's discretion; the planner should confirm with the
  founder):** D-05 says the button "opens the existing share panel/dialog, showing the live
  link with copy and revoke". At HEAD, `ShareableLink` opens no panel. It copies. The only
  existing share panel with copy + revoke is `OwnerUnpublishedPanel`, and it does **not** print
  the URL text, so this contract reuses it inside the existing `Modal` and reads "showing the
  live link" as "showing that the link is live, with copy and revoke". Printing the URL itself
  would need an extra mint-or-reuse call on open, with its own loading and failure states. That
  is not specified here. If the founder wants the URL visible, it is an addition to this
  contract, not a reinterpretation.

### Item 8 — Key-card venue label and layout (D-10)
- **Venue:** the line under the nickname reads `dataSourceLabel(key).exchange` from
  `src/lib/api-key-label.ts`. The inline `charAt(0).toUpperCase()` title-case is deleted.
- **Layout:**
  - **Row:** `flex flex-wrap items-center justify-between gap-x-4 gap-y-3`.
  - **Left block:** `flex min-w-0 flex-1 items-center gap-3`. The avatar is `shrink-0` and the
    text column `min-w-0`, so the nickname and venue line wrap at word boundaries inside the
    block.
  - **Action cluster:** `flex shrink-0 max-w-full flex-wrap items-center gap-2`, and every
    action `Button` gets `whitespace-nowrap`.
- **Result:** "Use & Sync", "Resync", "Update password" and "Delete" each stay on one line. When
  the card is too narrow, the whole action cluster drops to its own row under the left block,
  left-aligned. Below roughly 320px, buttons wrap whole within that row. A button is never
  split one word per line, and the venue line never stacks one word per line beside the
  actions.
- **Closure:** 164.5.3 closes only after a founder re-read (D-10). The executor does not mark
  it closed.
