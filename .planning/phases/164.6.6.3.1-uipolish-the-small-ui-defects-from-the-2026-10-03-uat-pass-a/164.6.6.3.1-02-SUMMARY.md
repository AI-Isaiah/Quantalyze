# Phase 164.6.6.3.1 Plan 02: Key card loading state, shared venue label and wrapping Summary

The key card now says "Loading keys…" until its first read settles (never "No API keys connected." over a user who has keys), a thrown first read lands in the existing retryable error card, the venue line reads the shared label ("MT5", "OKX"), and the card's layout carries the measured wrapping classes.

## What changed

`src/components/strategy/ApiKeyManager.tsx`
- `firstReadSettled` state beside `keys`. `loadKeys` sets it on the error arm and the clean arm, never on the superseded early return, and nothing resets it. `grep -c "setFirstReadSettled(true)"` is 3 (error arm, clean arm, mount catch).
- Mount effect: `loadKeys().catch(...)` logs `[ApiKeyManager] api_keys first read threw:` with the error object only, sets `loadError` (the Error message, or a fixed sentence) and the flag.
- A sibling `Card` with `<p role="status" aria-live="polite" className="text-sm text-text-muted text-center py-4">Loading keys…</p>` mounts on `!firstReadSettled && !showForm`; the empty-state Card gained `firstReadSettled &&`. Same box as the empty state, no spinner, no skeleton, muted not red or amber.
- Venue line: `{dataSourceLabel(key).exchange}` replaces the inline title-case; the ` · Last synced …` suffix is untouched.
- Layout: row `flex flex-wrap items-center justify-between gap-x-4 gap-y-3`; left block `flex min-w-0 flex-[1_1_14rem] items-center gap-3`; avatar `shrink-0`; text column `min-w-0`; actions `flex max-w-full shrink-0 flex-wrap items-center gap-2`; `whitespace-nowrap` on the four action Buttons (Resync, Use & Sync, Update password, Delete). `Button` itself is unchanged.
