Census G (plan 01 context): the guards are `{s.api_key_id && (` around the check icon in
`StrategyTable` (`title="Verified via exchange API"`), `{s.api_key_id && (` around `VerifiedBadge` in
`StrategyGrid`, and `{strategy.api_key_id && (` around `VerifiedBadge` in the
`/browse/[slug]/[strategyId]` page header. `VerifiedBadge` itself renders only when
`trustTier === "api_verified"`. `trust_tier` comes from `get_published_trust_signals`
(`supabase/schema/functions/get_published_trust_signals.sql`): the newest `strategy_verifications`
row per strategy (`DISTINCT ON (strategy_id) ... ORDER BY created_at DESC`), published strategies only.

So the badge a visitor sees changes only on two kinds of published row:
- composite: tier `api_verified` and `api_key_id` NULL (a strategy_keys-backed strategy). Grid and
  detail would newly SHOW the badge.
- key-bearing, not verified: `api_key_id` set and tier not `api_verified` (or no row). StrategyTable
  would newly HIDE the public check.
The orchestrator reports both counts as 0 on PROD; Task 2 re-measures them.

This plan does not touch `src/lib/queries.ts`, `src/lib/constants.ts` or `src/lib/types.ts` (plans 01
and 03 own them).
</context>
