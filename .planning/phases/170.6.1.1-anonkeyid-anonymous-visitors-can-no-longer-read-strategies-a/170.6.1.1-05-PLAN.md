## The D-03 grant-shape decision and its evidence

Shape: REVOKE the TABLE-level SELECT, INSERT, UPDATE and DELETE from `anon`, then GRANT column-level
SELECT to `anon` on every column except `api_key_id`. A column-level `REVOKE SELECT (api_key_id)`
alone is a silent no-op while the table-level SELECT stands, because a table-level privilege covers
every column. Repo precedent: migration `20260410225608_api_keys_column_revoke.sql` (SEC-005) took
exactly this shape for `api_keys` and records that the column-only revoke "is a silent no-op when the
role has SELECT via a broader table-level grant (the same bug that broke migrations 012 and 017)".
Revoking a table-level privilege also revokes that privilege's column-level grants on every column,
which is how D-04's "table and column level" is met; the self-check proves it with
`has_any_column_privilege`.

PROD reading, read-only, 2026-10-13, marker query first (PRODUCTION): anon's effective table
privileges on `strategies` are `DELETE, INSERT, REFERENCES, SELECT, UPDATE`, all five ACL entries
granted by `postgres`; 0 entries for the PUBLIC pseudo-role; 32 columns, 0 with an explicit column
ACL; anon can SELECT all 32, `api_key_id` included; `authenticated` also holds `DELETE, INSERT,
REFERENCES, SELECT, UPDATE` and can read `api_key_id` (out of scope, see the phase boundary); 5
policies (`strategies_delete`, `strategies_insert`, `strategies_org_read`, `strategies_read`,
`strategies_update`, all `TO public`); ledger tip `20261011120100`; server_version_num `170006`; 3
published strategies, 3 with a key, 3 with an `api_verified` verification row, 0 where key presence
and `api_verified` disagree.

Why the column grant list is DERIVED from the catalogue inside the DO block, not typed out: the
sql-mutation pg-lane builds `strategies` from fixtures with far fewer columns than PROD (plan 06's
gate applies `01`, `02`, `03` and `10`), so a typed 31-column GRANT would fail there with `column does
not exist`. Deriving "every attnum > 0, not dropped, not api_key_id" at apply time grants exactly the
31 measured columns on TEST and PROD and the fixture's columns on the pg-lane. The migration header
still lists the 31 PROD columns by name for review.

Default-deny (W5): a column added to `strategies` by a LATER migration is NOT anon-readable until a
migration grants it. Plan 06's gate arm GRANT 3 goes RED on such a column, and its raise text names
both remedies: grant the column to anon in the migration that added it, or add it to the gate's
named `HIDDEN_COLUMN_EXEMPTIONS` list with a reason. The list is empty today.

`REFERENCES` stays with anon: the phase boundary is two grant changes, and REFERENCES does not read
or write a row.
