## Warnings

### WR-01: A malformed strategy id in a public URL now renders the error boundary and pages Sentry, where it used to be a 404

**Severity:** MEDIUM · **Confidence:** 8/10
**File:** `src/lib/queries.ts:1296` (`getPublicStrategyDetail`), `src/lib/queries.ts:1354` (`getFactsheetDetail`). The new `failAnonRead` path reaches these callers: `src/app/strategy/[id]/page.tsx:27,88`, `src/app/browse/[slug]/[strategyId]/page.tsx:21,36`, `src/app/factsheet/[id]/tearsheet/page.tsx:225,285`.

**Issue:** `strategies.id` is `uuid` (`supabase/schema/baseline.sql`, `CREATE TABLE ... "strategies"`, `"id" "uuid"`). None of the three public pages validates the route param before calling the reader (`grep isUuid src/app` finds only API routes). For a non-UUID id, `.eq("id", strategyId)` makes PostgREST answer **22P02** (`invalid input syntax for type uuid`), not PGRST116. Before this fix, `if (error || !strategy) return null` turned that into a 404. Now the arm is `error.code !== "PGRST116"`, so 22P02 goes to `failAnonRead`, which captures to Sentry at `level: "error"` and throws.

**Failure scenario:** a share link truncated in a chat or email (`/strategy/3f2a9c1e-...` cut short), a typo, or any crawler or scanner probing `/strategy/<junk>` or `/factsheet/<junk>/tearsheet`:

1. The visitor gets "Something went wrong / Try again" with a 5xx instead of the not-found page. Retrying can never succeed.
2. Each request raises a Sentry error event tagged `op=getPublicStrategyDetail, code=22P02`. On `/browse/[slug]/[strategyId]`, `generateMetadata` (`:21`) and the page (`:36`) call the reader without a `cache()` alias, so each request raises two events.
3. Bot traffic floods the same `op` tag that the round-1 fix exists to make a trustworthy alert for 42501 after PR-B. The real outage signal gets buried in noise from probes.

The new test file covers only 42501 and PGRST116, so nothing pins this case.

**Fix:** reject a non-UUID id as not-found before the query. This uses the same helper the PDF route already uses for this purpose (`api/factsheet/[id]/tearsheet.pdf/route.ts:163`):

```ts
import { isUuid } from "@/lib/utils";

// getPublicStrategyDetail / getFactsheetDetail, first line
if (!isUuid(strategyId)) return null; // malformed id = no such strategy, never an outage
```

Add a control arm to `queries.anon-read-errors.test.ts` for each reader. Seed `{ code: "22P02", ... }` with id `"not-a-uuid"`, and assert it resolves to `null` with zero Sentry events. The arm fails against the current code. The other option is to treat 22P02 like PGRST116 in the `if`. The guard is better: it skips the round trip, and it does not hide a 22P02 coming from some other column.
