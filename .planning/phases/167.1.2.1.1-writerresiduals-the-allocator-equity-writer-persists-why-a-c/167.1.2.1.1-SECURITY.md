## Forgery analysis (T-10)

- Direct INSERT into `audit_log` is refused by `audit_log_service_insert` (`WITH CHECK (auth.role() = 'service_role')`), and UPDATE/DELETE are revoked from `authenticated` and `service_role`.
- The only user-callable door, `public.log_audit_event`, denies `allocator.holdings.sync_completed` (and `sync_failed`, `persist_failed`) to any non-service_role caller, by exact name.
- No `src/` path writes `sync_completed` (it appears only as a constant, a union member and a map entry); the two `from("audit_log")` calls in `src/` are reads.
- The `user_id` filter in the reader is a cross-tenant guard, not the forgery guard; the owner's own user_id matches. The forgery guard is the migration above.

### Fix-round specifics

- **M-1 leader (`e6d151b5c`).** Leader = smallest WORKING eligible key id, falling back to the smallest
  eligible key id when none works. Pure election; the result is a bool. T-11 and T-12 hold.
  `test_the_leader_is_elected_among_working_keys_not_failing_ones` and
  `test_an_all_failing_book_still_raises_the_left_out_event` assert one event, and assert that key
  ids, allocator id, venue ids and venue names are absent from the message.
- **M-2 left-out events (`65f176af2`).** The block sits after the hold (the hold block at
  `hold_reason = _refresh_hold_reason(latest)` returns first) and before the breakdown loop. A hold
  still returns DONE before `persist_equity_snapshots`, so T-09 is intact: the move did not put any
  snapshot write ahead of the hold. `test_a_left_out_account_is_raised_when_the_day_waits_on_a_reconstruct`
  covers the second early return.
- **M-3 identity-pending (`482313287`).** `identity_pending_venues(key_rows, VENUES_WITH_ACCOUNT_ID - {"deribit"})`
  in the refresh only. Deribit is excluded because the refresh loop skips every `venue == "deribit"`
  holdings row (they add $0), so two unstamped Deribit keys cannot double-count in this total. The
  derive keeps the full set (`identity_pending_venues(key_rows, VENUES_WITH_ACCOUNT_ID)`), so T-05
  (derive blocks) is unchanged. The narrowing removes a false hold, not a protection.
- **B2 split (`b70f9b0af`, `e72caff18`, `8c2493405`).** `compose_empty` is stored when the compose is
  trustworthy, or when the only blocking token is `dropped_key` AND every key is either anchored with
  no return rows, null-anchored with reason `native_unit` / `native_unpriced`, or null-anchored dust
  with no returns. Anything else (another blocking token, a key with returns and a real anchor)
  stores `compose_empty_blocked` with the compose's blocking tokens via `blocking_degrade_tokens`.
  The stored `compose_empty` row has `degrade_reasons` = [`compose_empty`] only, so the reader's
  sole-token arm gives `awaiting_derivation`, and the census CASE
  (`scripts/accounttruth-census.mjs`, `jsonb_array_length(...) = 1` arm) gives the same answer. No
  blocking token is DROPPED from a row that has a curve: this branch runs only when the compose's
  curve is empty.
- **No new id, USD or venue-bearing field** in `refusal_payload`, `_refresh_audit_counts` (17 integer
  fields), or the departed counts; the fix rounds added no log line.
