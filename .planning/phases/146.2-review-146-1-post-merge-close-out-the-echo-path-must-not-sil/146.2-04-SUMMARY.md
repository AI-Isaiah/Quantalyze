# Phase 146.2 Plan 04: R3 Readmit Attempt Ceiling Summary

Bounded B4's reaped-orphan readmission at 3 cycles per rolling 90-day window using the
terminalizer's existing marker rows as the attempt counter — zero DDL — and discharged the
carried 146.1 claim that the B4-BLANKET neuter had never actually been run.

## What was built

**`supabase/migrations/20260819150000_reconcile_sweep_readmit_attempt_ceiling.sql`** re-registers
`reconcile_dropped_enqueue_sweep` (same jobname, same `35 * * * *`) with exactly one added
conjunct in the batch CTE:

```sql
           AND (
                 SELECT count(*)
                   FROM public.compute_jobs cjc
                  WHERE cjc.strategy_id = s.id
                    AND cjc.status = 'failed_final'
                    AND cjc.last_error LIKE 'orphaned_running_reaped:%'
               ) < 3
```

**Zero table DDL, as the plan-checker verified.** The counter already existed: 144's terminalizer
UPDATEs the running row **in place** to a persistent `failed_final` marker row, and the sweep
INSERTs a **new** row on each readmission — so the per-strategy marker count rises by exactly one
per reap-readmit cycle. `compute_jobs.attempts / max_attempts / reclaim_count` were **not** used:
the sweep's INSERT names only `(strategy_id, kind, metadata)`, so every per-job retry field returns
to its default on each readmission and cannot carry a cross-row cycle count.

### N = 3 and what it actually buys (wall clock, stated as a range)

Auto-selected as the plan's recommended checkpoint option (`auto_advance: true`, gate `blocking`,
not `blocking-human`). Derivation:

- **3 matches `compute_jobs.max_attempts`** — the house per-job ceiling. Rule 11: conform.
- **One cycle ≈ 4–5 h**: the terminalizer's 4 h claim window plus up to 1 h waiting for the next
  sweep tick.
- The predicate readmits while the count is 0, 1 or 2, so the budget **depends on the entry path**
  and both numbers are recorded because the smaller one is the real one for the population B4 opened:
  - entering with **no job rows at all** (the original dropped-enqueue shape, count 0) → at most
    **3 sweep readmissions ≈ 12–15 h**;
  - entering as a **terminalized orphan** (already carrying marker #1 from the death that produced
    it) → at most **2 further readmissions ≈ 8–10 h**.

The plan's checkpoint text said "~12h of cycles". That is the upper of the two paths; the header and
this SUMMARY state both rather than quoting only the flattering one.

### It cannot reintroduce the failure it prevents

Structural, not argued: the delta is a conjunct `AND`ed into an existing `WHERE`, so the candidate
set can only **shrink**. A strategy the pre-ceiling body excluded stays excluded at any marker count.
Arms C2 / C2b / C3 stayed green throughout. The refused blanket status-list widening appears in **no**
form. `count(*)` is never NULL, so the new conjunct carries no three-valued-logic hazard of its own —
which is why it needs no `IS TRUE` wrapper while the exemption above it does.

Starvation is bounded on the other side too, and that is exactly what arm **C5b** exists to pin: a
strategy one below the ceiling must **still** be readmitted. Tightening the ceiling to `< 2` reddens
C5b (observed below).

## Known residual — the 90-day wall (stated, not fixed)

**The bound is N per rolling retention window, not N forever, and nothing here implies otherwise.**
`retention_compute_jobs_failed` (jobid 8) DELETEs on `COALESCE(next_attempt_at, created_at)` older
than 90 days, and the terminalizer deliberately re-stamps `next_attempt_at` so its marker rows
survive the full ninety. Each marker row is therefore collected 90 days after **its own** reap — a
rolling window, not a synchronised reset. A strategy that exhausts the ceiling is set down for ~90
days and then gets another 3 cycles.

That is still a ceiling — an unbounded loop becomes at most 3 cycles per quarter — which is what R3
asks. It is filed as an accepted residual and deliberately **not** chased with a DDL counter column:
a permanent lifetime bound needs durable state that outlives retention, which is a schema change and
a different decision.

**Second residual, smaller:** the ceiling bounds readmission **by this sweep**. It does not bound a
hand re-enqueue or a future mechanism writing `compute_jobs` directly. The conjunct governs one cron
body and claims nothing beyond it.
