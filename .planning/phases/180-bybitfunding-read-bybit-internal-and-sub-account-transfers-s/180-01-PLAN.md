Every request sends `limit` "50", `startTime` and `endTime` as strings, and `cursor` when one was returned. Statuses are compared as `str(row.get("status"))`. Every row in another status is counted in `other_status_rows`, so a wrong success set is visible in the record, never hidden. `/v5/user/query-api` (`private_get_v5_user_query_api`) gives `isMaster` (a boolean) and `uta` (`0` regular, `1` UTA); `userID` and `parentUid` are never kept. None of these endpoints states a retention period (RESEARCH A10), so each source is read NEWEST window first and stops at its first failure: the windows it did read keep their counts, and the depth bucket says how far back it answered.
