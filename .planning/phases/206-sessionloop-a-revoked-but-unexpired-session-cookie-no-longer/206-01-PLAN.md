<objective>
Stop the redirect loop for a browser that holds a session cookie the auth server no longer
accepts. Only the proxy's signed-in bounce branch changes (D-01). It now calls
`supabase.auth.getUser()` and redirects only when that returns a user. A null user or an error
falls through, so `/`, `/login`, `/signup` and `/forgot-password` render (D-02). The call runs
only in that branch (D-03), and no reporting is added (D-04). Tests in `src/proxy.test.ts`
cover the refused, error and confirmed arms. They are shown able to fail by a RED-first run and
two neuters, each restored from a byte backup (D-05).

Purpose: `getSession()` reads only the cookie, while the pages decide with `getUser()`. When the
two disagree (a revoked but unexpired session, an admin ban or delete, `session_not_found`, or an
unreachable auth server), the browser ping-pongs until `ERR_TOO_MANY_REDIRECTS` on the landing
page and on the sign-in page (199-REVIEW-R3, WR-01-R3). Every loop shape passes through this one
branch.

Output: the changed branch in `src/proxy.ts`, the new tests in `src/proxy.test.ts`, and
`206-01-SUMMARY.md` with the gc-206 evidence lines.
</objective>
