### The two deliberate refusals — both correct

**WR-06 (dead ternary, semantics NOT flipped): the refusal is right, and
iteration 1 was wrong.** I traced `diffFunctionBodies`
(`scripts/sql-body-normalize.mjs:519-528`): `SNAPSHOT_ONLY` is emitted only when
`candDefs.some(c => c.name === d.name)` **or** `candDefs.length === 0`. And
`chainIndex` is built from **filenames**, not from the parser
(`scripts/baseline-content-drift-check.mjs:271-274`:
`index.set(n.slice(0, -4), …)`). So in the first case the lookup always hits and
names a chain file a human can open; in the second it misses and the fallback
already names the dump. Iteration 1's proposed flip would have pointed every
`SNAPSHOT_ONLY` at a 726 KB dump instead of a 40-line chain file — strictly
worse. Applying it reddens the new arm, as claimed. The added **pair** of
assertions (with and without an index) is what makes the rule falsifiable in
both directions; a single assertion would have been the weaker shape.

**WR-07 (no ratchet for gate (b)): the asymmetry argument holds.** Gate (b)'s
live comparand is a fresh `supabase db dump` of PROD parsed by the *same two
independent readers* that read the committed dump
(`.github/workflows/migration-drift-check.yml:295-296`), so regenerating
`supabase/schema/baseline.sql` from PROD does structurally clear any divergence
it can report — unlike gate (a)'s `create_allocator_connected_strategy` row,
which survives a re-dump. A ratchet row here really could only record a declined
remedy. **One caveat that the header's "BY CONSTRUCTION" overstates** — see WR-D;
it is a premise gap, not a reason to add the ratchet.

**File:** `src/__tests__/local-stack-lane-wiring.test.ts:121-131`

Seven green, and `setup 0ms` proves the env-restore fence really is gone. This

DEF-16-1's ordering class, on an aggregator-BLOCKING job.

### WR-D: gate (b)'s comparand and its documented remedy use DIFFERENT dump scopes, so the WR-07 refusal's "BY CONSTRUCTION" is conditional on something nothing checks

**File:** `scripts/prod-body-drift-check.sh:220-250` (the new NO-RATCHET decision
block), against `.github/workflows/migration-drift-check.yml:203` and
`supabase/schema/BASELINE.md:150`

**Issue:** The refusal rests on "gate (b) compares the committed dump against the
LIVE CATALOGUE THAT DUMP IS TAKEN FROM. Every divergence it can report is
therefore cleared by regenerating, BY CONSTRUCTION." The two dumps are not taken
the same way:

```
migration-drift-check.yml:203   supabase db dump --linked --schema public -f "$DUMP"   # the comparand
BASELINE.md:150                 supabase db dump --linked -f supabase/schema/baseline.sql  # the remedy
```

A function in any non-`public` schema that the second command captures and the
first does not is `baseline-only` **forever**: regenerating with the documented
command reproduces it, and there is deliberately no ratchet. That is precisely
the state the refusal argues cannot exist.

Not live today — measured: all **123** `CREATE FUNCTION` statements in
`supabase/schema/baseline.sql` are `"public".`, and both name readers return the
same 121 names. So this is a premise gap, not a red gate. But the VAC-04 step
one screen up already understands the coupling and states it —
`PROD_DUMP_SCHEMAS="public"` carries *"Must stay in step with the --schema flag
on the dump above"* — while the baseline's own regeneration command does not.

**Fix (cheapest, keeps the refusal intact):** make the remedy the same operation
as the comparand.

```diff
-supabase db dump --linked -f supabase/schema/baseline.sql
+# --schema public is NOT optional: gate (b) compares this file against
+# `supabase db dump --linked --schema public` (migration-drift-check.yml:203).
+# A function captured here from another schema would be `baseline-only` on every
+# later migration PR, and gate (b) has no ratchet BY DECISION — a divergence a
+# regeneration cannot clear is exactly the state that decision assumes away.
+supabase db dump --linked --schema public -f supabase/schema/baseline.sql
```

and add the scope condition to the asymmetry paragraph in
`prod-body-drift-check.sh`, so "by construction" reads as the conditional it is.

### IN-B: `RECORDED_SHA_RE_ALL` is exported but never used as a regex — only as a `.source` donor

**File:** `scripts/check-baseline-staleness.mjs:60-72`, used at `:300`

`main()` does `new RegExp(RECORDED_SHA_RE_ALL.source, "g")`, which is identical
to `new RegExp(RECORDED_SHA_RE.source, "g")`. The exported constant's own `g`
flag is never exercised, so it is a stateful object that exists only to be
re-derived — and a future caller who used it directly would hit the `lastIndex`
trap the comment at `:300` warns about.

**Fix:** either drop the constant and build the counter inline from
`RECORDED_SHA_RE.source`, or make it a factory: `export const recordedShaMatcher
= () => new RegExp(RECORDED_SHA_RE.source, "g");`.
