## Decisions Made

1. **PRECEDENT B, as the plan decided.** Gate (a) ships green on a dated ratchet. Not re-litigated.
2. **Ratchet matching on name AND side**, with the flip case printing both sides and a "re-measure before touching the row" instruction — a flip means something moved on *both* sides, so silently re-pointing the row would be the absorption the correction exists to prevent.
3. **No gate-(b) ratchet.** See "What was NOT established".
4. **`--baseline-live` as a MODE, not a new script.** It must call the *same* `assert_credentials`, and it must be able to consume the dump the sibling leg already took.
5. **The new CI step's comment avoids the literal `if:` token.** The acceptance criterion pins that token's count in the file, and a comment mentioning it would have moved the count. The comment points at the D-17a block instead, which spells it out.
6. **The VAC-04-failure short-circuit is documented, not "fixed".** GitHub skips later steps after a failure, so a VAC-04 failure prevents gate (b) running. Adding `if: always()` would reintroduce exactly the step-level condition the plan forbids — and the resulting state is a *loudly red job*, which is categorically different from SKIP-01's green-having-checked-nothing. Stated in the workflow comment.
