## What was built

### `scripts/preflight-drop-allocator-fn.sh` (new, 1003 lines)

A sibling of `scripts/prod-body-drift-check.sh`, inheriting its three
non-negotiables in behaviour (never skip; never print PROD text; never pass
something it did not measure) and its injectable `*_CMD` seam style, so every
red path is observable with no credential and no production access.

Four assertions, in order, each PRINTING its measurement:

| | Assertion | Prints |
|---|---|---|
| — | **SIGNATURE** — exactly one live overload whose 11 argument TYPES equal the committed baseline's | overload count, expected types, live types, argument count |
| (a) | **BODY** — live definition vs `supabase/schema/baseline.sql` through `scripts/sql-body-normalize.mjs` | name/arity, both sha256 hashes, differing-line count, status |
| (b) | **DEPENDENTS** — `pg_depend` joined to `pg_proc` on this overload's oid | the row count; on non-zero, each dependent's kind and catalogue identity |
| (c) | **CALL EVIDENCE** — `pg_extension` probed FIRST, then the call count | the probe's row count, the availability verdict, the entry count and calls |

`EXPECTED_NARGS=11` is pinned **independently of the baseline parse**, so a
parser that silently short-read the argument list refuses instead of agreeing
with itself.

**D-02 is mechanical, not aspirational.** Every catalogue reader must print
`rows=<N>` as its first line followed by exactly N payload lines. A reader that
prints nothing therefore fails the *protocol* — it never reaches a zero branch,
because "said nothing" and "measured zero" are different bytes and only one of
them parses. A reader whose header and payload count disagree is also refused.

**Six distinct exit codes**, separating *could not measure* from *measured and
bad*:

```
1 usage / absent credential
2 MEASURE_FAIL — a measurement could not be TAKEN
3 signature mismatch
4 live body differs from the committed baseline
5 at least one dependent object
6 pg_stat_statements measured ABSENT (D-02)
```

A code outside 1–6 is the shell aborting under `set -e`. It is still a refusal
and is documented as not being one of the six.

An `--expect-absent` mode is included for task 5's post-apply confirmation, with
its own two self-test arms, so that step does not require authoring a tool under
time pressure after a production DDL.

## Deviations from Plan

### Auto-fixed issues — the self-review round (commit `c5ebe319`)

**F-01 [Rule 2 — missing critical functionality] The migration had no explicit transaction.** CRITICAL.
- **Found during:** task 3's migration-reviewer axis.
- **Issue:** every recent migration wraps itself in `BEGIN;` / `SET lock_timeout = '5s';` / `COMMIT;` (`20260907120000:156-157`, `20260907130000:172-173`) and this one did not. It is not only convention. STEP 2 RAISEs when the function survives STEP 1; unwrapped, that RAISE would leave a **COMMITTED removal behind a FAILED migration** — the object gone, the ledger saying it never happened, and the two halves of the file disagreeing about production. `lock_timeout` matters independently: removing a live `authenticated`-reachable function needs a lock an in-flight call holds, and without the timeout the statement would queue behind that call and block every new call behind itself, turning a governance cleanup into an outage.
- **Fix:** wrapper added with both halves of the reasoning in the file. Then **measured**, not asserted — a new lane proof E runs the real unmodified file through psql's `\i` with `ON_ERROR_STOP` relaxed so the session survives the RAISE and can look at the database afterwards. It observes `ROLLBACK` and `ATOMICITY PROVEN … count=1`. Without the wrapper that proof fails, which is what makes it a test of the wrapper rather than of PostgreSQL.
- **Commit:** `c5ebe319`

**F-02 [Rule 1 — bug, cosmetic] Check 2's arity list printed a trailing space.** `rtrim()`. Commit `c5ebe319`.

**F-03 [Rule 1 — bug] `|| true` collapsed grep's three exit statuses.**
- **Issue:** `expected_n="$(grep -ac '' … || true)"` — grep exits 0 when it counted rows, 1 when there are none and ≥2 on an ERROR. The `|| true` merged all three, so an UNREADABLE argument-type list arrived as a count of zero. It was refused downstream, but with the wrong reason, and one "helpful" message edit away from becoming a pass. This is SP-C06's exact shape, in new code.
- **Fix:** captured and branched; ≥2 is now its own MEASURE_FAIL. Commit `c5ebe319`.

**F-04 [Rule 1 — bug] `head … || true` merged two different facts.** "Could not read the reader's output" and "the output was empty" both produced an empty first line. Both still refuse; now each refuses with the reason that is true. Commit `c5ebe319`.

**F-05 [Rule 2] Implicit ordering coupling between assertions.** `assert_body` consumes a file `assert_signature` produces. A reorder would have surfaced as a normalizer error naming nothing. Asserted explicitly, with the cause in the message. Commit `c5ebe319`.

**F-06 [Rule 2] The exit-code map was silent about codes outside 1–6.** Recorded: any other non-zero code is the shell aborting under `set -e` — still a refusal, never one of the six. Commit `c5ebe319`.

**F-07 [Rule 1 — bug, PUBLIC-REPO DISCLOSURE] A checked-out home directory leaked into a tracked file.**

⛔ **The apply was BLOCKED on this round, and the reason was HIGH-1.**

### HIGH-1 — `--expect-absent` was a check that CANNOT FAIL

`--expect-absent` is the mode that records that a **one-way production removal
took effect**. Its pass condition is the signature reader reporting `rows=0` —
and silence produces `rows=0` too. REPRODUCED with a reader that touched no
database at all: `ALLOC_SIGNATURE_CMD` set to a bare `printf` of `rows=0` gave
**EXIT=0** and `verdict : NOT FOUND — zero overloads measured in the live
catalogue.`

`--expect-present` is self-defending against exactly this — a misdirected reader
yields `rows=0`, which it refuses with `EX_SIGNATURE`. `--expect-absent` inverts
that predicate, and the guard evaporated with it.

**Fixed with a POSITIVE CONTROL**, because only a positive control closes this
class: an assertion whose PASS requires the apparatus to have genuinely reached
the subject. A new **IDENTITY** assertion runs FIRST in BOTH credentialed modes,
reads `shobj_description(oid,'pg_database')` for `current_database()`, and
requires exactly ONE row whose marker CONTAINS `ALLOC_EXPECT_DB_MARKER`. New exit
code **7**. The marker is COMPARED, never PRINTED — this repository is PUBLIC.

A SQL NULL marker renders as an empty line, which the `rows=` protocol strips, so
a marker-less database arrives as `rows=0` or as a `rows=1`/zero-payload
self-contradiction. Both refuse; neither is ever "identity confirmed".

Post-fix, all three shapes of the reproduction refuse: no pin → exit 1 naming the
variable; pin but no identity reader → exit 1 naming the unset reader; pin plus a
database-less identity reader → **exit 7** naming the positive control.

### HIGH-2 — the credential check was presence-theatre

`assert_credentials` asserts three variables are non-empty **and then never uses
them**; every reader is a free-form command prefix from the same environment. So
"the credential check is the FIRST thing this script does" was TRUE and proved
nothing about which database was read. Same remedy: the IDENTITY assertion is now
the only thing in the file that binds a MEASUREMENT to PROD, and
`ALLOC_EXPECT_DB_MARKER` joins the credential loop with its own named message.

⚠️ **Stated bound, not papered over:** the readers are independent command
prefixes, so the file cannot force IDENTITY and the signature read into one TCP
session. It binds per reader-CONFIGURATION, in the same run, moments apart. An
operator who points two readers at two databases defeats it. That is narrower
than "no binding at all" and it is printed on every run.

### MED-1 — `pg_depend` is blind to plpgsql callers, and (b) claimed completeness

A plpgsql body that CALLS another function records **no** `pg_depend` row — the
call is resolved from the body text at execution time. So (b) printed *"ZERO —
nothing in the catalogue depends on this overload"* while an in-database caller
sat invisible. Worse: the bare removal does not abort on such a caller either. It
**succeeds**, and the caller breaks at RUNTIME, after the one-way DDL.

Split into **(b.1)** `pg_depend` and **(b.2)** a new `pg_proc.prosrc` reader
excluding the target's own oid, new exit code **8**. (b.1)'s verdict now reads
"ZERO pg_depend rows reference this overload" and carries its own scope line, and
the closing scope notice no longer bounds only PostgREST callers.

MEASURED on the lane (`164.5-06-LANE-PROOF.log`, third round): **F2a** —
`pg_depend rows = 0 while prosrc naming bodies = 1`, taken BEFORE any removal, so
the zero is not an artefact of the function's absence; **F2b** — the bare removal
SUCCEEDS and calling the survivor raises `42883`, measured **by calling it**.
