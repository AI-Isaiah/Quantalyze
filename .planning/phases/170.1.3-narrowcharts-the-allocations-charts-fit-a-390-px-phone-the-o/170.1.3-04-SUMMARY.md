## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in the planned mechanism] `fitTickLabel` is wrong for an end-anchored y tick.** For `TimeSeriesChart` and `ReturnQuantiles`, `fitTickLabel(x, label, size, 0, maxX, "end")` returns the `start` anchor at the unchanged x, which lays "+1000.00" across the plot starting at the axis. I added `fitEndLabelX` (move right until the box starts at 0, anchor stays `end`) for `TimeSeriesChart`, whose `PAD.left` is used in about forty places and must not move, and grew the left gutter in `ReturnQuantiles`, where the mobile arm's font bump is the root cause and a gutter keeps the label right-aligned against the axis (the same pattern as plan 01's `rightAxisPad`). Files: `chart-ticks.ts`, `TimeSeriesChart.tsx`, `ReturnQuantiles.tsx`. Commits `a7dacc395`, `dde450b9d`.

**2. [Rule 2 - missing mechanism] Top-edge cuts needed a vertical rule.** `fitTickLabel` is horizontal only; the EOY legend and the calendar month labels are cut at the top (the em box reaches about one font size above the baseline: a 13 px label on baseline 10 was cut by exactly 3 px). I added `fitBaselineY` (`ceil(fontSize * 1.05)`), deterministic and not a DOM read. For the calendar, the label band grows with the baseline (mobile 14 -> 18, desktop unchanged at 14) so a descender never lands on the first cell row; `tap-charts-viewport.test.tsx`, which taps cell centres with the old 14 offset, still passes. Files: `chart-ticks.ts`, `DistributionPanels.tsx`, `HeatmapPanels.tsx`.
