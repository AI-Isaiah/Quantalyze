## Summary

**Review 5 WR-01 is resolved.** `YearCalendar` now passes `w={gridW}` to every year. Every row in
the year stack has the same viewBox width (770) and the same `scale`, so on a wide desktop the week
columns line up again. `estLabelWidth`, `labelsRight` and the growth arithmetic are gone, and
nothing else reads them.

**D-05 is resolved for labels and hover.**
- **Month labels:** the loop at `HeatmapPanels.tsx:284-296` skips any slot whose date is outside
  the year (`dt.getUTCFullYear() !== year`). This covers both the leading days before Jan 1 (which
  used to be dropped by `doy < 1`) and the trailing next-year days. A non-leap year draws 12 labels.
  A leap year that starts on a Sunday keeps day 366 (Dec 31), which is the same month, so no label
  changes.
- **Hover and tap:** `cellPayload` returns null for a next-year day (`:459-460`). In production this
  guard cannot be reached, because `dailyReturnsByYear` files every date under its own year (both
  payload builders and the scenario payload use it), so an out-of-year slot is always `null`. It is
  harmless defence, and the jsdom hover pins exercise it with a synthetic cell.

**The fixture regeneration is correct.**
- **Standard fixture:** it loses exactly three `Jan` texts at x 742: Overview 2026, composer 2025
  and composer 2026. These are the non-leap calendars, and 742 = 14 + 52 × 14 is the day-366 column
  for offsets 2 and 3. No width, x, y or anchor changed.
- **Long-label fixture:** width goes back from 774 to 770 and loses the `Jan` at x 756 on 2023
  only. The 2024 row is a leap year and is unchanged.
- **MEASUREMENT:** the dated reason rows E1-E7 match the diff line for line.

**The test changes hold.**
- **Floors:** 16 → 15, 32 → 30 and 16 → 15 equal 12 months plus 3 weekday labels per calendar.
- **Exact `Jan` count:** the G-02 case asserts exactly one `Jan`, so a returning 13th label fails it.
  The desktop comparators would also catch it as a text-string difference.
- **Pattern minimum:** `minPatternTexts` now applies per svg. `Math.max(0, ...[])` gives 0 when no
  svg matches, so an empty emitter still fails. The new vitest pin can fail.
- **1280 clip rule:** the long-label 1280 cases now run the clip rule before comparing, which closes
  the "no long-label clip case at 1280" gap.
- **Mock restore:** `afterEach(vi.restoreAllMocks)` restores only `spyOn` targets under vitest 5.
  `beforeEach` re-arms the `useBreakpoint` mock, so the `getBoundingClientRect` spy does not leak
  into other describes.

I found no regression in the EOY (G-01) code, which this diff does not touch. The one MEDIUM is
below.

## Warnings

### WR-01: D-05's "cells stop at the year's last day" is not implemented, and the code comment says it is

**File:** `src/app/factsheet/[id]/v2/HeatmapPanels.tsx:411-424` (canvas draw loop). The comment that
claims otherwise is at `:288-289`: "it gets no label (and no cell)".

**User-facing:** yes. Every daily calendar on the factsheet, the Overview and the composer is
affected, at every width.

**Issue:** CONTEXT D-05 says "From now on the month labels and cells stop at the year's last day",
and its heading is "Each year's calendar draws only that year's days". The fix changed the label
loop and `cellPayload`, but not the canvas loop. That loop still paints all 54 × 7 slots and draws
every `null` slot as a "missing day" placeholder (`missingFill` plus a `missingStroke` outline).
Out-of-year slots are always `null`, so they are still drawn and look exactly like a real day with
no data.

**Scenario:** in the 2023 calendar (Jan 1 is a Sunday, offset 6), week 0 shows six placeholder boxes
for Mon 26 to Sat 31 Dec 2022. Week 53 is a whole column of seven placeholder boxes for 1 to 7 Jan
2024, the column whose label D-05 removed. In 2025 (offset 2), week 52 shows Thu to Sun as
placeholders for 1 to 4 Jan 2026, and week 53 is entirely 2026. So the column the founder decided to
stop drawing is still drawn, now without its label.

The tests miss it. jsdom's `getContext("2d")` returns null, so the draw effect returns early and no
pin observes the canvas. The svg-text fixtures and the clip rule do not read canvas pixels.

**Fix:** skip out-of-year slots in the draw loop the same way the label loop does, with no fill and
no stroke:
```tsx
const yr = parseInt(year.year, 10);
for (let wk = 0; wk < tintGrid.length; wk++) {
  for (let d = 0; d < 7; d++) {
    const dt = new Date(Date.UTC(yr, 0, wk * 7 + d - year.firstWeekOffset + 1));
    if (dt.getUTCFullYear() !== yr) continue; // D-05: only this year's days
    // ... existing fill / missing-placeholder drawing
  }
}
```
Add a jsdom pin that stubs `HTMLCanvasElement.prototype.getContext` with a recording
`fillRect`/`strokeRect` and asserts that no rect is drawn at week 53 for 2023. Without that pin the
gap stays invisible to the gate.

**Scope check for the coordinator:** this changes the canvas on every desktop calendar, because the
leading and trailing placeholder boxes disappear. The D-05 text names cells explicitly, but its
D-04-exception sentence only mentions "one label fewer". If the founder meant labels and hover only,
correct the comment at `:289` and the D-05 wording instead of the code. Whichever is chosen, the code
and CONTEXT must say the same thing.
