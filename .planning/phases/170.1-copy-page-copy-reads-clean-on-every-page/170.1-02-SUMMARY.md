## Open issues / things the next reader should know

- **Bespoke rule keys in the `<summary>` / multi-rule cause line.** The plan's locked rule sends every unlabelled key to "This value does not pass a format check". That includes the producer's bespoke rules (`too_many_rows`, `date_format_ambiguous`, `empty`, `parse_error`), whose list lines render verbatim but whose `<summary>` now reads the fallback sentence instead of the raw key. It satisfies "no raw rule name in the DOM", but "This value does not pass a format check" is a poor summary for `too_many_rows`. Adding labels for those four keys is a one-line-each follow-up; I did not do it because the plan locks the label set. Needs a founder or planner call.
- **Legacy persisted rows.** Rows persisted before plan 01 have no `column`; composed lines degrade to "Row N: label." (no column) and the format hint cannot fire for them (it reads `column`). Intended.
- Plan 01 (the producer emitting `column`) was not available to this worktree; every fixture uses the row shape the plan states. Run both plans together before shipping.
- `column` in composed (non-column_in_dataframe) lines is plain text, not font-metric: UI-SPEC marks that line [discretion] and locks the data voice only for the missing-column sentence.
