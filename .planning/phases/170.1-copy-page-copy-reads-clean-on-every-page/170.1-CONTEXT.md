#### D-14 amendment (founder, 2026-10-16, after the D-14 round's review)
- **Founder decision, verbatim: "One more round."** If dates still do not come out clean after this round's narrow review, CSV timezone handling is split into its own phase; no further loop inside 170.1.

- **Zones fail closed:** a zone that survives the strip is a date error at its real row through the existing `coerce_dtype` line ("A value is not a valid date or number"); `utc=True` never converts a date silently.
- **Duplicate-header narrowing:** the founder sentence applies when two headers collide on a schema-declared column after normalisation, including an exact repeat that pandas renames (`n` and `n.1`). An undeclared pair (for example `Notes,notes`) validated before and is still accepted, because undeclared columns are never read.

- **Founder decision 2026-10-16, verbatim: "Tiny round for both"** after the final round's review found dates clean and two MEDIUMs left: R-1 (a repeated declared header behind a blank first row narrower than the header was accepted; the header record is now read with the stdlib `csv` reader, empty records skipped, and a failed read fails closed with no fallback) and SFH-R2 (an unsupported zone in a day-first column read as `not_nullable`; rows with a rejected zone now get `coerce_dtype`).
