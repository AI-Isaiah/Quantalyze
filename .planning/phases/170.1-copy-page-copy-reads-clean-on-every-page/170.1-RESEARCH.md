## Summary

This is a copy phase with six independent change surfaces: (1) metadata titles through a root `title.template`; (2) a shared label vocabulary applied to roughly 45 render sites; (3) two copy modules (`status-surface-copy.ts`, `key-card-copy.ts`) with string rewrites and one new note kind; (4) the wizard success path (`SubmitStep` plus a `/strategies` status line); (5) a Python producer change with a wire contract that currently DROPS any new field (`_FORWARDED_ROW_KEYS`); (6) two small render fixes (chart subtitle, KPI suffix). The surfaces touch mostly disjoint files, with five shared-file collisions called out in "File-overlap map". Planning work is dominated by pin moves: the copy pins are dense for D-08/D-09/D-10 (about 60 assertions across 15 files) and nearly absent for D-01 admin surfaces (three admin pages have source-regex tests only), so D-01 needs new render tests rather than moved ones.

Three findings change how the plans must be written. First, the D-08 list note cannot be fixed by editing `unbuildableNoteKindOf` alone: `/strategies` reduces the job state to a three-valued arm before choosing a note (`readRecipientArm` returns `recipientArm(deriveComputeState(...))`), and a `finished` job, a `failed` job and a `never_started` job all map to `not_available`. The finished-job kind must be chosen from the `ComputeState`, which the list page currently throws away; and for a PUBLISHED row the page deliberately never reads jobs (pinned by `PUBLIC-NO-READ`). Second, the D-10 format hint as locked ("every required column of the chosen format is missing") cannot fire in the very scenario that was routed: a daily-returns file uploaded under the Trade list format still has its `date` column, so 5 of 6 required columns are missing, not 6 of 6 (measured). Third, the UI-SPEC renders non-pandera rule messages from `CSV_RULE_LABELS`, which would replace actionable producer messages (`too_many_rows`, `date_format_ambiguous`, `empty`, `parse_error`) with a generic fallback; the plan must route only the pandera-built `failed rule '...'` rows through labels.

**Primary recommendation:** Plan 10 file-disjoint plans in three waves (foundation first; label sweeps after it; the `/strategies` cluster as an ordered pair), put every `src/app/(dashboard)/strategies/page.tsx` edit in ONE plan, and treat the three flagged design calls as orchestrator questions before the plans lock.

### Anti-Patterns to Avoid
- **Reading "finished" from the arm.** `recipientArm` maps `stalled`, `failed`, `finished` and `never_started` to the same `not_available` `[VERIFIED: src/lib/compute-state.ts recipientArm, read lines 564-581]`. Deriving `finished_not_built` from `arm === "not_available"` would print "The last computation finished" for a failed or never-started job, which is exactly the CR-01 contradiction the copy module's tests guard against.
- **Giving the new kind to `in_progress` or reusing `cannot_build`.** Both are locked out by the UI-SPEC (orchestrator FLAG resolution).
- **Putting a title string with the brand into a child segment.** It doubles ("X — Quantalyze — Quantalyze").
- **Sharing `title` and `openGraph.title` through one variable** (done today in `factsheet/[id]/v2/page.tsx`, see Pitfall 2).

## Next.js metadata: how the root template interacts with existing titles

All statements `[CITED: node_modules/next/dist/docs/01-app/03-api-reference/04-functions/generate-metadata.md]` (Next 16.3.8 installed docs) unless marked.

1. **Child segments only.** `title.template` in `layout.js` applies to child route segments and NOT the segment it is defined in (L285). `title.default` is required with a template (L286). A template defined in a layout does not apply to a `title` in the `page.js` of the SAME segment (L287). Consequence: the root template affects every page below `src/app/` (all of them), and the root `/` page, which exports no metadata, falls back to `default`.
2. **String title in a page augments the nearest parent template** (L343); a string `title` in a nested layout also becomes the default for children that define none and is itself templated by the parent (L338). Consequence: `src/app/(marketing)/demo/layout.tsx` (`title: "Quantalyze — Live demo"`) and `src/app/(marketing)/legal/layout.tsx` (`Legal — ${PLATFORM_NAME}`) both double-suffix unless stripped. `demo/page.tsx` and `demo/founder-view/page.tsx` export no metadata, so they inherit the layout's segment.
3. **`title.absolute`** (L291-345) bypasses the template. Not needed in this phase; every route should go through the template. Do not use it to dodge the double-suffix problem.
4. **Client components cannot export metadata** (L110, L118). `src/app/(dashboard)/admin/partner-roi/page.tsx` and `partner-import/page.tsx` start with `"use client"` `[VERIFIED: grep this session]`, so each gets a sibling `layout.tsx` exporting `metadata`. A segment `layout.tsx` metadata applies to the page in the same directory (the layout is the parent segment of the page's metadata level; layouts and pages in one folder merge, with the page winning), so a layout-level `title: "Partner ROI simulator"` is templated by the ROOT layout's template (the layout here is a child of root). `[ASSUMED]` that a same-folder layout's string title is templated by the root template exactly like a page's; the docs state the layout `title` string "will augment `title.template` from the closest parent segment" (L338), which covers it. The page-titles census test (below) plus one `next build` smoke would confirm.
5. **Route groups** `(dashboard)`, `(auth)`, `(marketing)` do not create segments, so they neither add nor block templates `[ASSUMED: standard App Router behaviour, not re-read in this session]`. There is no `metadata` in `(dashboard)/layout.tsx` or `(auth)/layout.tsx` `[VERIFIED: grep for metadata exports listed only the 20 files in the Title Inventory]`.
6. **`openGraph.title` and `twitter.title` are NOT passed through the root template.** UI-SPEC: "stay as they are". Files that build OG titles today: `strategy/[id]/page.tsx:50,56`, `factsheet/[id]/v2/page.tsx` (`openGraph.title`), `(marketing)/security/page.tsx:35`, `(marketing)/for-quants/page.tsx:49`.
7. **`generateMetadata` for dynamic routes** runs in addition to the page body. `fetch` is memoized per request but Supabase queries are only memoized if they go through `fetch` with identical options `[ASSUMED]`; the repo's precedent is `react.cache()` around readers (`src/lib/queries.ts` `getStrategyDetailV2`, `fetchStrategyLazyMetrics`). Recommendation: for the five dynamic dashboard routes (discovery slug, discovery strategy, portfolio, manage, documents, edit, admin user, admin match allocator, admin partner-pilot) use either a name-only RLS read inside `generateMetadata` (cheap, one row) or wrap the page's reader in `cache()`. Do NOT add owner-inclusive predicates to metadata on public routes: `src/__tests__/phase-148-owner-lane-cache-isolation.test.ts:489` asserts `generateMetadata` in the factsheet pages never reaches the owner-inclusive predicate.

## Common Pitfalls

### Pitfall 1: Double brand suffix
**What goes wrong:** a page keeps "— Quantalyze" in its own title and the root template appends it again.
**Why it happens:** 20 files already embed the brand (Title Inventory), plus `legal/layout.tsx` and `demo/layout.tsx`, which are LAYOUTS and so are easy to miss.
**How to avoid:** the new `src/__tests__/page-titles.test.ts` scans every file that exports `metadata`/`generateMetadata` and fails on a segment title string containing "Quantalyze" or "|", and asserts the root template literal. Keep OG titles out of the scan.
**Warning signs:** a tab reading "Contact — Quantalyze — Quantalyze".

### Pitfall 2: One variable feeding `title` and `openGraph.title`
**What goes wrong:** in `factsheet/[id]/v2/page.tsx` the same `const title` is passed to `title`, `openGraph.title` and `twitter.title`. Stripping the brand for the tab strips it from the social card too (the UI-SPEC says OG titles stay).
**How to avoid:** keep `const ogTitle = ...` unchanged and set `title` to the bare segment.

### Pitfall 3: `readRecipientArm` loses the state
**What goes wrong:** deriving "finished" from `arm === "not_available"` (see Anti-Patterns).
**How to avoid:** return the `ComputeState`; gate on `state.state === "finished"` AND `mode === "mint-token"`; add a test per ComputeState variant (queued, running, retrying, stalled, failed, finished, never_started, unreadable) asserting only `finished` selects the new note.

### Pitfall 4: `StrategiesPage()` is called with no arguments by four test files
`page.key-pill.test.tsx:425`, `page.share-affordance.test.tsx:268`, `page.wizard-draft-banner.test.tsx:227`, `page.table.test.tsx:293` call the default export without props (`as unknown as () => Promise<ReactElement>`). Destructuring `{ searchParams }` from `undefined` throws in all four. Either update the four helpers to pass `{ searchParams: Promise.resolve({}) }` (preferred: tests then also exercise the param) or give the parameter a default. `requireRolePage-wiring.test.tsx` imports only `./strategies/layout`.

### Pitfall 5: The producer projection drops the new field
`_forwarded_pandera_rows` copies exactly three keys; a producer-only change makes the unified `/process-key` path (the one in production once `process_key_unified_backbone` is on) silently lose `column`, and the UI then falls back to the generic label. The existing key-set tests at `test_csv_validator.py:757` and `test_process_key.py:4814` will go red, which is correct; move them deliberately.

### Pitfall 6: Cell echo through `failure_case`
`failure_case` is the raw cell for every rule except `column_in_dataframe`. Reading it unconditionally leaks CSV content into a persisted, user-visible message. Read it only when `check == "column_in_dataframe"`, and add a test with a distinctive header AND a distinctive cell value that must not appear anywhere in the produced errors (the existing T-161-07 tests are the template).

### Pitfall 7: The format hint never fires in the routed scenario
See Open Question 2. A test built from a hand-made fixture with ALL required columns absent would pass while the founder's real specimen still shows no hint.

### Pitfall 8: Generic label replaces an actionable producer message
See Open Question 3: `too_many_rows` would read "This value does not pass a format check" and `date_format_ambiguous` would lose "Please re-upload with ISO dates in YYYY-MM-DD format".

### Pitfall 9: A default "Coming soon" tooltip remains reachable
`SegmentedControl.tsx:50` falls back to "Coming soon" when a disabled option has no `disabledReason`. If any caller omits it the string reaches a user. Check the three `FactsheetView.tsx` call sites and the others, then remove the default (render no tooltip).

`Badge type="status"` renders on `StrategyTable.tsx:1475,1624`, `StrategyHeader.tsx:46`, `RequestIntroButton.tsx:129`, `PendingIntros.tsx:170`, `AdminTabs.tsx:275`.
