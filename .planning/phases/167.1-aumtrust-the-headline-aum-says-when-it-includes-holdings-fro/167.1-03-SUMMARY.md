# Phase 167.1 Plan 03: AUMTRUST State B and the marker's absence states Summary

**When a committed manual AUM differs from the live total, the override note now reads "Overrides live-holdings total $50,000, which includes $12,345 from keys needing attention." The disclosure moves with the live total, so one number never carries two markers. Every UI-SPEC § 1 state where the marker must be absent is now pinned by a test that has been seen failing.**

## Accomplishments

- **State B (`ScenarioComposer.tsx`):** the `scenario-aum-override-note` span renders `Overrides live-holdings total {formatUsd(liveHoldingsSum)}`. Under `showUntrustedMarker` it then adds `, which ` and an unclassed `<span data-testid="scenario-aum-untrusted-note">` holding `buildUntrustedAumClause(liveHoldingsSummary.untrusted.amount)`, and ends with `.`. The note sits inside `overrideNoteShowsLive`, and State A sits inside `fieldShowsLive`. Those two conditions cannot both be true, because one needs `sanitizedManualAum` to be undefined and the other needs it defined, so there is only ever one marker (D-08, D-18). With no untrusted holding, the note's JSX text nodes join to exactly `Overrides live-holdings total $X.`, as before.
- **Tests (the AUMTRUST describe):** a general `atBook(specs)` builder plus `expectDistinctTriples` and `commitAum` helpers. There are 13 new cases:
  - State B with its exact textContent, the one-marker count and the nesting.
  - The all-trusted override regression.
  - Placement following the committed value rather than keystrokes.
  - Absence states 1, 2, 4, 6 and 7.
  - D-07 (a negative derivative gives `Includes -$1,235 from keys needing attention.`).
  - D-15 pin 4.
  - Tone for State A and State B.
  - The `D-06` component pin.

  Every expected string is typed out literally. Each case either checks its fixture for distinct triples or reuses a fixture that is checked elsewhere, and every state that needs a commit asserts the commit landed (`manualAumUsd` on the drawer) before it asserts anything is absent.

## Deviations from Plan

**1. [Drill substitution] Drill 2 as written cannot make any case RED; drill 2b hits the real gate instead**
- **Found during:** Task 2
- **Issue:** removing `(fieldShowsLive || overrideNoteShowsLive)` from `showUntrustedMarker` left all 14 AUMTRUST cases GREEN. Each render site already requires the live total to be on screen: State A is gated by `showUntrustedMarker && fieldShowsLive`, and State B sits inside `overrideNoteShowsLive &&`. So that conjunct does not change what renders. It is a redundant restatement, not the gate that protects state 4.
- **Fix:** no source change. The code is correct, and restructuring it only so this drill would bite would be a change the product does not need. Drill 2b neutered the actual gate (`fieldShowsLive`'s `liveHoldingsSum > 0` half), and the state 4 case went RED, so the case can fail.
- **For plan 05:** `showUntrustedMarker` means "the live total is on screen and part of it is untrusted", but nothing that renders depends on its on-screen half on its own. If M3 (option (b)) reads `showUntrustedMarker` from a new site, that site needs its own placement gate, or the conjunct becomes load-bearing and needs a drill of its own.
