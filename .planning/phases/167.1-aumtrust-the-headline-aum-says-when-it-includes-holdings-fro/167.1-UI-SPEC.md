### ⛔ Tone decision (D-09): MUTED, not amber, and why

**The call.** Every marker renders as `text-xs text-text-muted`: no fill, no border, no glyph and
no role.

**The evidence, taken in order:**

1. **DESIGN.md § Semantic-color gates: "Gate on *what the value means*."** The marker qualifies a
   figure that stays **correct**. D-03 says the total is byte-identical and the untrusted holdings
   are genuinely in it. What the marker adds is a statement of composition, not a state. The
   recoverable *state* (a key needing attention) is already rendered in amber, per row, by the
   `HoldingsTable` and `OpenPositionsTable` chips. That is where the state is named and where its
   remedy lives. Colouring the total's disclosure amber would colour a sum by the shape of one of
   its inputs, which is the failure mode the gate calls out ("coloring by shape instead of by
   meaning").
2. **The sibling precedent in the same row is muted, and a test pins it.** `scenario-aum-modelled-note`
   exists because "a headline money figure may not change meaning silently" (Phase 151 review F2),
   which is this phase's exact reason. It is `text-xs text-text-muted`, and the composer test
   asserts its class does NOT match `/warning|amber|danger|destructive/i` and that it has no
   `role`. Two money-basis disclosures in one row must not take two tones.
3. **The noun's existing usage is muted.** `UNTRUSTED_KEY_SET_NOUN` already appears in
   `HoldingsTable`'s hidden-row footer ("N holdings hidden from keys needing attention") as
   `text-xs text-text-muted`. The marker uses that noun so a reader can find the rows it talks
   about. Using the same voice keeps the two sentences recognisably the same kind of statement.
4. **No new treatment.** Amber inline prose (as opposed to an amber chip) has no sibling in either
   host surface. Picking it would mint a treatment, which D-09 forbids.

**What this costs, stated rather than hidden.** A muted marker is less conspicuous than an amber
one. This is accepted because the noun links to the amber chips one tab away, and because a marker
that shouts about a correct number would teach the reader to distrust the number.

⚠️ **ADDED 2026-09-24 (code review round 3 IN-03): state 6 means EXACT equality, and that is
narrower than it reads.** `fieldShowsLive` tests `sanitizedManualAum === liveHoldingsSum`. The live

is true, and the exact-equality rule is kept deliberately (review [9]; behaviour unchanged). State 6
is reached in practice only when every summed value is whole, or a bottom-up resize matches the sum
exactly. ⛔ Do not plan against state 6 as the common "manual equals live" case.

Gating notes:

- It renders when **the count is ≥ 1**, not when the amount is > 0. A book whose only untrusted

- In the unreachable-in-production degrade branch (`contributingApiKeyIds: []`), a `revoked`

These are formatter outputs measured this session with `toLocaleString("en-US", { style:
"currency", currency: "USD", maximumFractionDigits: 0 })`, which is the body of `formatUsd`. The

override note next to it already prints the same form. `-$0` is accepted as the renderer's honest
rounding of a sub-dollar negative sum. It is not special-cased, because special-casing it would
fork the composer's single renderer.

the field's value **is** the live total, so the adjacent sentence qualifies the field it sits next
to. This is the same construction as the sibling "Overrides live-holdings total …".
