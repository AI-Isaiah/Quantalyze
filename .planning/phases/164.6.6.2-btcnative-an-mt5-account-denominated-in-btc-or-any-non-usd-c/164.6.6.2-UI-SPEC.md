## The one rule this phase adds

**Gate.** Every change in this spec is gated on a single payload value, `returnsUnit`:

| `returnsUnit` | Meaning | Rendering |
|---------------|---------|-----------|
| `null` | USD family (D-04: USD, USDC, USDT, EURR, DAI) or no unit recorded | **Byte-for-byte unchanged.** No new node, no new class, no changed string. |
| `"BTC"` | Native-unit series (D-08 `data_quality_flags.native_unit: "BTC"`, D-02 the key's `account_currency`) | The contracts below. |

- The UI reads ONE field. How the server derives it (D-02 key column vs D-08 flag) is the planner's
  call, but every surface in this spec must read the same field, so the masthead chip, the KPI
  labels, the share card and the composer cannot disagree.
- Every label helper returns its input unchanged when the unit is `null`. A USD strategy must not
  take a different code path that happens to produce the same text. It must take the same
  `null`-unit early return.
- `"BTC"` is the only non-null value this phase can produce (D-06 refuses every other currency).
  The helpers take the unit as a string parameter, not a hard-coded `"BTC"`, so the follow-up
  phase adds a unit without touching copy.

**Unit principle (D-10, narrowed by D-17).** A figure that is the strategy's BTC series alone is
shown, labelled in BTC. **Only a figure that pairs the strategy with BTC itself** (the BTC
overlay; alpha, beta and correlation against BTC; the BTC event studies; the BTC stress-window
column) is withheld. It reads `—` and names the reason `returns are in BTC`. A BTC-in-BTC benchmark
is a flat line (D-10). **Every other USD-priced comparison renders exactly as it does today
(D-17).** That covers SPX, the ETH / S&P 500 / Gold / IEF correlations, the allocator demo blends
and the peer percentile.

**Placement on the factsheet masthead (D-09 "beside the strategy name").**
- **Public arm, when `returnsUnit` is set:** the H1 and the chip sit in `<div className="flex flex-wrap items-baseline gap-3">`, H1 first, then the chip. This is the wrapper class the owner arm already uses.
- **Owner arm:** the order is H1, then the chip, then `Rename…`.
- **When `returnsUnit === null`:** the public arm still emits the bare `<h1>` with no wrapper, exactly as today.
- The chip does NOT go on the trust-tier row below. That row is provenance (trust tier, ownership, type chips). The unit is part of the document's identity, so it sits with the name.
- Below 640px the row wraps and the chip drops under the H1, left-aligned. Nothing truncates.

**Contract note for the planner: where the D-18 conversion happens.**
- **One place, client composer.** The conversion runs in the scenario composer's client-side series path, at the point where a constituent's daily return series is resolved for blending (`resolveDailyReturnSeries` / `src/lib/scenario-blend-adapter.ts`, wherever the planner finds the single entry). It does not run on the server, and it is not duplicated in `scenario.ts` maths. The planner pins the exact seam by symbol.
- **Price source.** The BTC/USD daily close from `benchmark_prices`, which the composer already reads. No new fetch and no new price source.
- **Arithmetic.**
  - USD value on day *t* is the BTC value on day *t* multiplied by the BTC close on day *t*.
  - The USD daily return is the ratio of consecutive USD values minus one. In the returns domain this is the same thing as `(1 + r_btc,t) × (1 + r_px,t) − 1`.
  - The blend consumes the USD return series. The BTC series is never blended directly.
- **Missing price, never invented.** A day whose USD return cannot be formed from two priced days is `null` for the BTC strategy. It is not zero, not carried forward and not interpolated. From there the composer's existing missing-day handling applies (coverage window, paired-day rules), unchanged.
- **Scope.** This is the composer's USD conversion only. The persisted USD view (allocator snapshots, `account_balance_usdt`) stays in 164.6.6.2.1 (D-18, D-15).
- **USD rows.** A USD row's series passes through untouched, on the same `null`-unit early return.

| `withUnit(label, unit)` | `src/lib/factsheet/returns-unit.ts` (new) | `unit == null` returns `label` unchanged (the same string reference). Otherwise `` `${label} in ${unit}` ``. Every A/B/C/D/E label above goes through it. |
| `nativeUnitReason(unit)` | same module | `` `returns are in ${unit}` ``. The one reason string. Every `Not measurable: …` / `… not available: …` line composes from it. |
| `nativeAmount(v, unit)` | `src/app/factsheet/[id]/v2/format.ts` | Null or non-finite → `—`. `\|v\| ≥ 1`: 2 decimals with thousands separators (`1,234.56 BTC`). `0 < \|v\| < 1`: 4 significant digits (`0.05231 BTC`). Exactly 0 → `0.00 BTC`. The suffix is a space plus the unit. Never a `$`. This mirrors the DESIGN.md currency rule for prices (2dp at 1 or more, 4 significant digits below 1). |

No call site may inline `toFixed` or `"in BTC"`. The unit string comes from `returnsUnit` every time.
