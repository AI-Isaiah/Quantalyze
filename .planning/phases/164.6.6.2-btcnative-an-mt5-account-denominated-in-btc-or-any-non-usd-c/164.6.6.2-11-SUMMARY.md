**1. [Rule 3 - Blocking] Parity test mocks `readBtcCloses`, not `readBenchmarkPrices`' client read**
- **Found during:** Task 3
- **Issue:** the plan says to mock "the supabase client and `readBtcCloses`' underlying read". `readBenchmarkPrices` lives in the same module as `readBtcCloses`, so it can only be reached through the Supabase client; faking `benchmark_prices` rows would have meant a second table arm for a window that plans 09 and 10 already inject as `readBtcCloses`.

No seam output is mocked: the route, the composer, `resolveSharedScenario` and `getMyAllocationDashboard` all run for real.
- **Files modified:** `ScenarioComposer.test.tsx`
- **Commit:** 3ddcc8ad6
