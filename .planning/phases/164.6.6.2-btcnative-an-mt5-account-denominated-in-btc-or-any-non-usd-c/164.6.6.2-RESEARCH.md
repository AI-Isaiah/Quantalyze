**Capturing the account's currency**
- **D-01:** The currency comes from `account_info().currency` on every derive and backfill read.
  `Mt5Client.account_info()` already returns it, so no new RPC is needed. It is parsed with the
  existing validator in `allocator_positions.py` `_fetch_mt5_account_rows`: blank means a transient
  error, a non-code means refuse, otherwise an uppercase code.
- **D-02:** It is stored in a new nullable text column `api_keys.account_currency`, written by
  derive. The factsheet reads the unit from the strategy's key.
- **D-03:** A currency change between reads (the broker re-denominates) fails loud. Log ERROR, end in
  a transient failure, keep the existing series, and never mix units in one series.
- **D-04:** "USD" means the `USD_FAMILY` set the code already uses (`external_flows.py`: USD, USDC,
  USDT, EURR, DAI). Behaviour for those is unchanged. Every other currency is "native".

**The dust floor and the other USD-sized thresholds**
- **D-05:** The dust floor is per currency, in native units: BTC 0.01 (about the $1000 USD floor at
  today's prices). The USD family stays at 1000.
- **D-06:** A non-USD currency with no floor defined (EUR, ETH, and so on) is refused. Its metrics
  stay null and a named data-quality flag says the unit isn't supported yet. Never guess.
- **D-07:** The other USD-sized thresholds on the MT5 path use the same per-currency table, so a
  broken key holding 5 BTC still fails loud. These are the material-equity fail-loud ($100,
  `_DERIBIT_EMPTY_LEDGER_FLOOR_USD`), the history-settle materiality (`mt5_read.py`
  `material_equity_floor_usd`) and the uPnL materiality (`nav_twr.py`, `job_worker.py`).
- **D-08:** A native-unit series is flagged with `data_quality_flags.native_unit: "BTC"`. The
  factsheet reads it, and it is not a warning.

## Summary

The phase is narrower than it first looks because the TWR arithmetic is already unit-neutral. `combine_mt5_deal_ledger` and `reconstruct_mt5_nav_levels` both call `nav_twr.reconstruct_nav_and_twr` directly, and the only unit-sized constants on that path are `DUST_NAV_FLOOR` (used in `_guard_denominator` and the uPnL-materiality gate) plus one the CONTEXT does not list: the absolute `max(1.00, 1e-6 * abs(terminal))` tolerance in `reconcile_flow_residual`, which for a BTC account would accept a residual of a whole BTC. A single new leaf module (`services/account_unit.py`, stdlib + `USD_FAMILY` only) holding one `UnitFloors` table, plus a default-preserving `floors=` parameter threaded through `reconstruct_nav_and_twr` -> `chain_linked_twr` -> `_guard_denominator` and the two MT5 combiners, keeps every other venue (Deribit, sFOX, ccxt, CSV) byte-identical, because they never pass it.

The currency is already in hand: `read_mt5_deal_ledger` returns the PRE `account_info` dict, which carries `currency`. The derive, the backfill and the sync-balance arm each receive that dict. The one place the floor cannot be passed in from the caller is the history-settle materiality, because the caller builds its argument BEFORE the read that reveals the currency; the floor must be resolved inside `_settle_deal_history` from `info`. D-03's change check belongs in `run_derive_broker_dailies_job` between the read and the combine, comparing against `ctx.key_row["account_currency"]` (the key row is loaded with `select("*")`, so the new column arrives for free). The `native_unit` flag rides the existing pre-stamp -> runner path, but `analytics_runner` rebuilds `data_quality_flags` wholesale from a fresh dict, so it must be carried present-only and non-promoting exactly like `mtm_gated_reason`, and the runner must read the existing flags BEFORE it computes metrics (it currently reads them after) so it can skip the BTC benchmark for a native series.

Three findings change the plan's shape and are not in CONTEXT: (1) PROD evidence that MM-2x holds only just over 0.01 BTC today, i.e. right at the D-05 floor, so the first re-derive may still dust-guard many historical days (the phase's own acceptance depends on it, Open Question 1); (2) the factsheet's AUM is the manager's declared `strategies.aum`, a USD figure, never the live balance, so D-11's "2.41 BTC" has no BTC source today and using the new native balance would publish a live balance on a public page (Open Question 2); (3) the BTC-to-USD conversion of D-18 has more than one blend seam (composer, shared-scenario resolver, the portfolio page), so it must be one pure function called at each seam, not a composer-only patch.

**Primary recommendation:** Build one `account_unit.py` leaf (table + classifier), thread a default-preserving `floors` argument through the nav_twr core and the two MT5 combiners, resolve the unit once per derive/backfill/sync read from `account_info["currency"]`, persist `account_currency` + the native balance (and null the stale `account_balance_usdt`) from derive via a service-role UPDATE, carry `native_unit` present-only and non-promoting through the pre-stamp and the runner, and read that one flag everywhere on the frontend as `returnsUnit`.

### Pattern 1: One table, default-preserving parameter

**What:** `account_unit.py` owns `UnitFloors(dust_nav, material_equity, residual_abs_tol)`. The USD-family row is the ONLY place `1000.0` and `100.0` are written; `nav_twr.DUST_NAV_FLOOR` and `job_worker._DERIBIT_EMPTY_LEDGER_FLOOR_USD` become aliases of it so their names, importers and tests are untouched and Deribit/sFOX/ccxt cannot drift.
**When to use:** every threshold in D-07, plus `reconcile_flow_residual`.
**Example:**
```python
# services/account_unit.py  (stdlib + external_flows.USD_FAMILY ONLY: a leaf, like mt5_probe/mt5_concurrency)
from dataclasses import dataclass
from services.external_flows import USD_FAMILY

@dataclass(frozen=True, slots=True)
class UnitFloors:
    dust_nav: float          # D-05: a NAV denominator below this is gibberish
    material_equity: float   # D-07: "material" for the fail-loud and the settle wait
    residual_abs_tol: float  # nav_twr.reconcile_flow_residual absolute band (NOT in D-07; see Pitfall 2)

USD_FLOORS = UnitFloors(dust_nav=1000.0, material_equity=100.0, residual_abs_tol=1.00)
_NATIVE: dict[str, UnitFloors] = {
    "BTC": UnitFloors(dust_nav=0.01, material_equity=0.001, residual_abs_tol=1e-5),  # 0.001 / 1e-5 are [ASSUMED]
}
# nav_twr.py:   DUST_NAV_FLOOR = USD_FLOORS.dust_nav          (name kept, value unchanged)
# job_worker.py: _DERIBIT_EMPTY_LEDGER_FLOOR_USD = USD_FLOORS.material_equity
```

### Pattern 2: Present-only, non-promoting flag carry (the `mtm_gated_reason` precedent)

**What:** `analytics_runner` rebuilds `data_quality_flags` from a fresh dict every run. `native_unit` is carried from the pre-stamped row like `mtm_gated_reason`, and never touches `_warned`.
**Example (the shape to copy):**
```python
# analytics_runner.py (after existing_flags is read)
_native_unit = existing_flags.get("native_unit")
if isinstance(_native_unit, str) and _native_unit:
    data_quality_flags["native_unit"] = _native_unit   # present-only; _warned untouched
```

### Pattern 3: One payload field, many readers

**What:** `payload.returnsUnit?: string | null` is set once in `buildFromResolved` from `dqf.native_unit` (validated `^[A-Z]{2,10}$`, else null) via a conditional spread so a USD payload is byte-identical (the `cumulativeMethod` precedent in `build-payload.ts`). Every UI surface and the OG route read that one derivation.

### Anti-Patterns to Avoid

- **Putting `native_unit` in `NAV_TWR_GUARD_KEYS`.** That tuple is what promotes `computation_status` to `complete_with_warnings`; D-08 says the unit "is not a warning". [VERIFIED: analytics-service/services/nav_twr.py:220-231 and analytics_runner.py:1896-1900]
- **Stamping the key-mode anchor reason `"dust"` for a funded BTC key.** The epilogue stamps `"dust"` when `abs(equity) <= DUST_NAV_FLOOR`; 0.01 BTC would read as "too small to measure" in the departed-history copy and be omitted by compose as immaterial. Use a distinct `native_unit` token.
- **Resolving the settle floor in the caller.** The caller builds `material_equity_floor_usd=` before the read that reveals the currency.
- **Hand-rolling the BTC interval logic for D-18.** Use `alignCoveredReturns`.
- **Reading `api_keys.account_currency` from the factsheet.** Not needed (the flag is on the row the factsheet already reads), and it keeps the column un-granted.

## Common Pitfalls

### Pitfall 1: MM-2x sits on the floor D-05 sets
**What goes wrong:** MM-2x's current equity is only slightly above 0.01 BTC, and `reconstruct_nav` rolls the NAV BACKWARD from that anchor. Any historical day whose reconstructed NAV was below 0.01 BTC is dust-guarded again, so the first BTC re-derive can still produce a chain-broken, mostly-guarded series (`twr_chain_broken`, `insufficient_window`), and the phase's own acceptance ("MM-2x shows non-zero BTC returns") is not guaranteed.
**Why it happens:** D-05 set 0.01 BTC as the dollar-equivalent of $1000 at about $100k/BTC. An account worth about $1000 today is, by construction, right at the floor in either unit.
**How to avoid:** make the floor a one-line table value (it is), say so in the plan, and add a founder checkpoint after the first re-derive: if the series is still mostly guarded, the lever is the table value, a founder decision (D-05 is locked), not a code change.
**Warning signs:** after D-16, `cumulative_return` still `0` or `dust_nav_guard` still true; `csv_daily_returns` row count barely changes.

### Pitfall 2: The residual tolerance is a hidden USD constant
**What goes wrong:** `reconcile_flow_residual` uses `tol = max(1.00, 1e-6 * abs(terminal))` (`nav_twr.py:640`). For a BTC account the `1.00` is one BTC, so a roll that drops or mis-values a flow passes the construction self-check silently.
**Why it happens:** the CONTEXT's D-07 list was written from the dust/materiality sites; this one has no "USD" in its name.
**How to avoid:** `abs_tol` parameter, default `1.00`, MT5 passes `floors.residual_abs_tol`.
**Warning signs:** a mutation test that drops a flow in a BTC fixture stays green.

### Pitfall 3: The key-mode epilogue silently persists BTC as dollars
**What goes wrong:** `_run_key_mode_compose_epilogue` persists `flows` as `usd_signed` and `anchor_usd = equity`, then stamps `anchor_null_reason = "dust"` for `abs(equity) <= DUST_NAV_FLOOR`. For a BTC key that is a wrong-unit anchor or a wrong-reason null, and `_NO_CAPITAL_ANCHOR_REASONS = frozenset({"dust", "nonpositive"})` (`equity_reconstruction.py:2087`) is the "this account has no capital" proof vocabulary.
**How to avoid:** a native-unit key persists `anchor_usd: null`, `anchor_null_reason: "native_unit"`, `flows: []`. `native_unit` must NOT join `_NO_CAPITAL_ANCHOR_REASONS` (a funded BTC account has capital) and compose (`allocator_equity_compose.py:382`, `if _null_reasons.get(k) == "dust": continue`) must treat it as an honest omit rather than a blocking `DROPPED_KEY` (decision for the planner; recommendation in Open Question 4). Add a case to `departed-history.ts` `unavailableSentence` (its `default` already yields a generic sentence, so it is safe but vague).

### Pitfall 4: The runner computes BTC-benchmarked metrics for a BTC-unit series
**What goes wrong:** see Q4. alpha/beta/correlation/information ratio get persisted against USD BTC returns.
**How to avoid:** read flags first; pass `benchmark_rets=None` for a native series; do not stamp `benchmark_unavailable`.

### Pitfall 5: Settle floor resolved before the currency is known
**What goes wrong:** `material_equity_floor_usd=` is passed by the caller before the read. Using the USD floor (100) for a BTC account means `abs(0.01) > 100` is False, so a funded BTC account is treated as "not material" and the wait for a fresh login's deal history is skipped, reproducing the Finding-C empty-history race for exactly this account.
**How to avoid:** resolve inside `_settle_deal_history` from `info`.

### Pitfall 6: Derive tests and fixtures break wholesale on a blank currency
See Q7. 26 fixtures. Do the fixture edit first and separately.

### Pitfall 7: `account_balance_usdt` is rewritten by the sync arm every sync
**What goes wrong:** clearing it once in derive is undone by the next `sync_trades` if the sync arm still returns the BTC equity.
**How to avoid:** the sync arm returns `None` for a non-USD-family currency (Q2), AND derive nulls the stale value once.

### Pitfall 8: The allocator positions gate and D-04 disagree
`allocator_positions.py` skips when `ccy != "USD"` (exact), D-04 says USD_FAMILY. Harmless for real MT5 currencies, but two answers to one question. Have the positions poll call the same classifier so `MT5_NON_USD_NOTE` and the derive agree.

### Pitfall 9: A date-only "USD return = BTC return x BTC price move" can double-count day 0
`alignCoveredReturns` pairs index 0 with BTC's own return dated the first strategy date (D-64). Converting day 0 as `(1+r)*(1+btc_0)-1` gives the first day a price move the strategy's NAV was not yet exposed to. Decide explicitly (recommendation: start the converted series at index 1, i.e. drop day 0, and document it) and pin it with the UI-SPEC's hand oracle.

### Classifier shape (recommended, Wave 1)
```python
# services/account_unit.py
import re
from dataclasses import dataclass

_CODE_RE = re.compile(r"[A-Za-z]{2,10}")  # == allocator_positions._CURRENCY_CODE_RE (move, do not copy)

class AccountCurrencyBlank(Exception): ...          # transient: payload degradation
class AccountCurrencyMalformed(Exception): ...      # refuse, never echo the raw text
class AccountCurrencyUnsupported(Exception):        # D-06: no floor defined
    def __init__(self, code: str) -> None:
        super().__init__("account currency has no floor defined")
        self.code = code

@dataclass(frozen=True, slots=True)
class AccountUnit:
    code: str
    native: bool
    floors: "UnitFloors"

def classify_account_currency(raw: object) -> AccountUnit:
    text = raw.strip() if isinstance(raw, str) else ""
    if text == "":
        raise AccountCurrencyBlank
    code = text.upper()
    if not _CODE_RE.fullmatch(code):
        raise AccountCurrencyMalformed
    if code in USD_FAMILY:
        return AccountUnit(code, False, USD_FLOORS)
    floors = _NATIVE.get(code)
    if floors is None:
        raise AccountCurrencyUnsupported(code)
    return AccountUnit(code, True, floors)
```

```ts
// src/lib/factsheet/returns-unit.ts  (sketch; oracle: [1.0, 1.1] BTC NAV x closes [60000, 66000] => 0.21)
export function convertNativeReturnsToUsd(
  series: readonly DailyPoint[],
  unit: string | null,
  btc: Pick<BtcCloses, "prices" | "dropped"> | null,
): DailyPoint[] {
  if (unit == null) return series as DailyPoint[];           // USD rows: same reference, untouched
  if (btc === null) return [];                                // no price source: nothing invented
  const dates = series.map((d) => d.date);
  const a = alignCoveredReturns(btc.prices, btc.dropped, dates, COMPARATOR_CALENDARS.btc);
  const out: DailyPoint[] = [];
  for (let k = 1; k < series.length; k += 1) {               // k=0 dropped: Pitfall 9
    const b = a.returns[k];
    if (!a.paired[k] || b === null) continue;                 // a day without a price stays absent
    out.push({ date: series[k].date, value: (1 + series[k].value) * (1 + b) - 1 });
  }
  return out;
}
```
