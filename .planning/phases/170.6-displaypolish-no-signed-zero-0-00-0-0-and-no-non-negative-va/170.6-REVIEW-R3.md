## Narrative Findings (AI reviewer)

### WR-01. MEDIUM (confidence 6): an inline raw comparison gated by `&&` paints a tone with no rule firing; the `&&` form was added to R7 but not to R2 or R1

**File:** `src/__tests__/display-sign-single-source.test.ts:289-304` (`findR2` only walks `TERNARY_AFTER_CMP_RE` and `IF_RETURN_AFTER_CMP_RE`) and `:269-280` (`findR1`, same limit). The new R7 use-regex is at `:420`.

**Issue:** R2-SFH-1 taught R7 to follow a NAMED boolean into `b && <El token/>` and `cn(.., b && token)`. The simpler shape skips the named boolean and puts the raw comparison in the same position. That shape is still invisible to every rule. A probe run against the HEAD guard returned these hit counts:

| source | R1 | R2 | R5 | R7 |
|---|---|---|---|---|
| `cn("a", delta > 0 && "text-positive")` | 0 | 0 | 0 | 0 |
| `{delta > 0 && <span className="bg-positive/10">up</span>}` | 0 | 0 | 0 | 0 |
| `{v > 0 && "+"}{fmt(v)}` | 0 | 0 | 0 | 0 |
| `const up = delta > 0;` then `cn({ "text-positive": up, "text-negative": !up })` | 0 | 0 | 1 | 0 |

In the last row, R5 counts only the negative token, so a positive-only clsx object passes. With any of these shapes, a raw `0.00004` that prints `0.00%` is painted green or given a `+`, which violates D-02 and D-03, and the guard stays green while claiming a single source (D-05).

No such site exists in `src` today. The only `> 0 &&` tone at HEAD is `AdminTabs.tsx:219` (`counts.declined > 0 && …text-negative`), which is a count, and R5 already counts it. So this is a gap in the guard, not a live defect.

The round-2 fix report says R2-SFH-1 closed "the && form". It closed that form only for named booleans, and the inline form is the more direct of the two.

**Fix:** in R2 (and in R1 for a `"+"`), also scan a raw comparison followed by `&&`, then test the tail exactly as R7 now does:

```ts
const AND_AFTER_CMP_RE = new RegExp(`(?:${CMP_ZERO})\\s*\\)?\\s*&&`, "g");
for (const m of code.matchAll(AND_AFTER_CMP_RE)) {
  const tail = ternaryTail(code, (m.index ?? 0) + m[0].length);
  if (TONE_TOKEN_RE.test(tail)) out.push({ file, line: lineOf(code, m.index ?? 0), rule: "R2", text: lineText(code, m.index ?? 0) });
}
```

Add RED self-test rows for the three inline shapes above, and a GREEN row for `rows.length > 0 && <p className="text-negative">`, which the existing `length|size|count` lookbehind keeps quiet. Optionally extend R7's use-regex to a `"<token>": name` clsx-object key.
