# Phase 170.6 Gap G01: Max Drawdown hero tone on the browse detail and strategy pages

**Both `src/app/browse/[slug]/[strategyId]/page.tsx` (HeroMetric) and `src/app/strategy/[id]/page.tsx` (MetricCard) passed a constant `colorClass="text-negative"` to Max Drawdown; they now use `drawdownTone(analytics.max_drawdown, 2, 100) === "negative" ? "text-negative" : "text-text-primary"`, the StrategyBreakdownTable pattern from plan 02.**

Defect source: plan 02's SUMMARY "Findings for the orchestrator". A drawdown printing `0.00%` or `—` read red, against D-03 (tone follows the rounded sign) and D-04 (Max DD never green). Only the Max DD colour changed.

## What

- Two one-expression edits plus the `drawdownTone` import from `@/lib/factsheet/display-sign`. Nothing else in either page changed.
- Two new tests, `page.max-dd-tone.test.tsx` beside each page. The existing `strategy/[id]/page.test.tsx` is source-shape only (the page "cannot be mounted"), so the new tests mock `@/lib/queries` (and Supabase, Sparkline, Disclaimer, etc.) and render the async server component directly, reading the className of the value element next to the "Max Drawdown" label. Hand-typed cases: -0.12 prints `-12.00%` and is red; -0.00004 prints `0.00%` and is not red; 0 prints `0.00%` and is not red; null prints `—` and is not red; none of the four is ever `text-positive`.

## RED seen

Before the fix, 6 of 16 failed (3 per page): the -0.00004, 0 and null cases, each `expected 'mt-1 text-2xl font-bold font-metric t…' not to contain 'text-negative'` (received `…text-negative`). The -0.12 and never-green cases passed, as they should.

## Neuter proof

For each page: byte backup to a temp dir, `perl` replaced the `drawdownTone(...) === "negative" ? ... : ...` expression with the constant `"text-negative"`, `cmp` confirmed the neuter applied. The page's test went RED (3 failed / 5 passed). Restored with `cp`, `cmp` clean (`restored-byte-equal`), `git status` showed only the intended files. No git restore, checkout or stash used.
