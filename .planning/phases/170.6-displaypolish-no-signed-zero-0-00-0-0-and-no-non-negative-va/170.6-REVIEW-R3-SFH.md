# Phase 170.6 round-3 silent-failure review

## Checked and found sound (no finding)

- **`captureToSentry` cannot throw into render or the effect.** `src/lib/sentry-capture.ts:206-232` wraps scrub, record scrub and the dynamic import in an outer `try`, and the import chain ends in a `.catch` that resolves. It returns a settled promise, never a rejection. The `new Error(...)` in `KpiStrip.tsx:592` cannot fail.
- **Hook order is safe.** `KpiStrip` has no early return before the `useEffect` (`KpiStrip.tsx:586`). The only `return` in the effect is its own guard.
- **Reported once, not zero times, not every render.** The effect dep is the number `impossibleDrawdown`. The same figure on a re-render does not re-fire. A new distinct impossible figure fires again. Strict-mode double mount is dev only. Reporting runs only on the client after commit.
- **`—` cannot hide a valid value on the primary cell.** The test is `signTone(raw, 2, 100) === "positive"`, i.e. the value rounded at the 2 dp the cell prints. A rounded zero prints `0.00%` and reports nothing. Every in-repo producer of the figure is non-positive by construction (`scenario.ts:598-666`, `maxDD` starts at 0 and only goes down).
- **R7 cap reporting.** For an assignment whose comparison is inside the first 1200 characters, `capped` is `rhs.length >= R7_RHS_CAP`, so a cap hit is emitted as a finding and not read as clean. See finding 4 for the case where it is not.

## Findings

### 1. MEDIUM (confidence 7): the delta pill and the "Live:" tooltip still print a figure derived from the impossible drawdown, and an impossible LIVE value is never reported

`src/app/(dashboard)/allocations/components/KpiStrip.tsx:527-551` (flag set at `:527-533`, pill built from `scenVal` / `liveVal` at `:536-551`, tooltip at `:~570`).

The new gate acts only on the PRIMARY value (`showScenarioPrimary ? scenVal : raw`). `delta = scenVal - liveVal` and `title={\`Live: ${formatLiveValue(liveVal)}\`}` read the raw values, not `primaryRaw`.

- Scenario value impossible (`scenVal = 0.04`): the cell prints `—`, and the pill beside it prints `+X.XX%` computed from 0.04, coloured improved or regressed by `deltaPillClass`. The cell declares "uncomputable" while the pill computes from it.
- Live value impossible (`liveVal = 0.04`) with a valid scenario value: the primary is real, so `impossibleDrawdown` stays null. Nothing is reported. The pill prints a delta against the garbage baseline, and the tooltip prints `Live: +4.00%`. This is the exact "+4.00% with no signal" defect R2-SFH-2 set out to remove, one hover away. It also means the Sentry report depends on which mode the allocator is viewing.

Fix: compute `impossibleLive = metricKey === "max_drawdown" && isImpossibleDrawdown(liveVal)` (and the same for `scenVal`). Null the operand: `delta = null` when either side is impossible, and print `—` in the tooltip. Feed either impossible side into `impossibleDrawdown`. Add RED tests for scenario-impossible, live-impossible and valid-primary.

### 2. MEDIUM (confidence 6): `computeRegimeChange` guards NaN but not `null`, and the skip is whole-series and silent

`src/lib/portfolio-insights.ts:57` (`average`), `:140-144` (guard).

`rolling_correlation` reaches this function as JSON (`types.ts:1493` types `value` as `number`, but it is a jsonb round trip). A NaN written by the analytics side comes back as `null`, not `NaN`. `sum + null` coerces to 0, so `average` returns a finite number and `Number.isFinite` passes. A window with some `null` points is averaged as if those days were correlation 0. That can manufacture a "Correlation regime shift" card (0.60 down to a diluted 0.36) and let that series win `best` over a healthy pair. The R2-SFH-3 tests use only `NaN` and `undefined`, never `null`, so the shape that actually crosses the wire is untested. The guard closes the synthetic case, not the real one.

The opposite direction is also lossy. One bad point among 10 discards the whole pair with no log and no count. If every pair carries one bad point, the card disappears with no trace, though 9 of 10 points were usable.

Fix: map each window with `typeof v === "number" && Number.isFinite(v)`, drop non-finite points, and skip the series only when fewer than, say, `ceil(window / 2)` finite points remain in either window. Add a `null`-point test that expects `null` or the healthy pair. If a series is skipped for being unusable, say so (`logForDebugging` or a Sentry breadcrumb), so an all-skipped portfolio is distinguishable from a calm one.

### 3. MEDIUM (confidence 6): `ternaryTail` truncates at 400 characters without reporting, and its terminators are not JSX-aware, so R2 and the new R7 `&&` / `?` use scan can miss a tone token

`src/__tests__/display-sign-single-source.test.ts:238-262` (`ternaryTail`, default `cap = 400`), used by `findR2` (`:~296`) and the R7 use loop (`:~427`).

The task rule is that a scan hitting a cap is reported, never truncated. This round added the `cap` parameter and a report for the R7 right-side cap, but the other consumers still use the silent 400 default. `return code.slice(from, limit)` returns the same string whether it ended naturally or hit the limit. A raw-sign ternary or `up && (<JSX>...)` whose tone token sits past 400 characters (a long parenthesised JSX first arm, then `text-negative` in the else arm) passes. Parentheses raise `depth`, so the tail does not end early. It just runs out at 400.

The tail also ends early on a `,` or `;` at depth 0 and treats `'` as a quote. In a JSX arm such as `x > 0 ? <p>Up, up</p> : <p className="text-negative">` the comma in JSX text ends the tail before the else arm. `<p>Don't</p>` opens a quote that swallows the rest. The R7 `&&` shape makes this more reachable, because the gated element is JSX.

Fix: have `ternaryTail` return `{ text, capped }` and make R2 and the R7 use loop emit a finding on `capped`, as the R7 right side now does. Add a RED row with a 450-character first arm and a RED row with a comma in JSX text before the tone token.

### 4. MEDIUM (confidence 5): R7 still misses several shapes of the same defect, and a capped right side is only reported if its comparison is inside the cap

`src/__tests__/display-sign-single-source.test.ts:405-411` (`r7Assignments`), `:421` (`useRe`), `:~182-183` (token prefixes).

- `r7Assignments` runs `!rhs.includes("0") || rhs.includes("=>") || !cmp.test(rhs)` BEFORE the `capped` flag is set. A right side longer than 1200 characters whose zero comparison comes after character 1200, or that contains an arrow in its first 1200, is dropped silently, not reported. The cap report exists only for the sub-case that already matched. Fix: when `rhs.length >= R7_RHS_CAP` and the declaration is a boolean-looking assignment, report before the `cmp`/`=>` filters.
- The use regex needs `name ?` or `name &&`. A flag used in an object key (`cn({ "text-positive": up })`, `clsx({ "bg-negative": !up })`), as `up || "text-negative"`, or as `if (up) return "text-positive"` is not matched. A boolean wrapped in an arrow (`const isUp = (v) => v > 0; isUp(x) ? "text-positive" : ...`) is skipped by the `=>` filter and the name is followed by `(`, not `?`. These are ordinary Tailwind idioms for exactly the raw-sign chip the guard exists to stop.
- The token prefixes cover `text|bg|border|stroke|fill|ring` only. `outline-`, `shadow-`, `from-`/`via-`/`to-`, `divide-`, `decoration-`, `accent-` and `caret-` + `positive`/`negative` are tone tokens and are not matched by R2, R5 or R7. A generic `\b[\w-]*-(?:positive|negative)\b` removes the whole prefix list as a thing to maintain.

Fix: add the object-key and `if (flag)` use shapes and the wrapped-arrow case with RED self-test rows, move the capped report ahead of the filters, and widen the prefix to any `-positive|-negative` utility (re-pin R5 where it moves).

Verdict: 4 findings (MEDIUM and above)
