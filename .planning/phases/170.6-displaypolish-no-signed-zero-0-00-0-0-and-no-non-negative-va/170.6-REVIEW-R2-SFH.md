## Findings

### 1. MEDIUM (confidence 8): R2 and R7 are blind to `bg-*` / `border-*` tone tokens, so the exact defect WR-03 fixed still passes the guard

`src/__tests__/display-sign-single-source.test.ts:178-181` (`NEG_TOKEN`, `POS_TOKEN`, `TONE_TOKEN_RE`), used by `findR2` and `findR7`.

The token set is `var(--color-positive|negative)`, `text-positive`, `text-negative`, the two hex values, `CHART_POSITIVE`, `CHART_NEGATIVE`. It has no `bg-positive`, `bg-negative`, `border-*`, `stroke-*` or `fill-*`. The WR-03 site was `const isHedge = pcr < 0; ... isHedge ? "bg-positive" : "bg-accent"`. Run `findR7` on that original code and it returns nothing, because `bg-positive` does not match `TONE_TOKEN_RE`. WR-04 turned R7 into a pinned count rule, but the rule still cannot see the one shape that actually slipped through in this phase. The fixer noted this in REVIEW-FIX "Not done" and left it.

Failure scenario: a developer adds `const up = delta >= 0;` and then `className={up ? "bg-positive/10 text-accent" : "bg-negative/10 text-accent"}` (the shape already used at `portfolios/[id]/manage/page.tsx:14-16`, `admin/compute-jobs/page.tsx:179`). R2 and R7 both stay green. A raw-sign green/red chip or bar ships, and a value that prints `0.0%` is painted green. This is the same silent-failure class as before, with the guard saying "single source" while a second implementation exists.

Hidden shapes it also misses: a boolean used as `isHedge && <Chip/>` (R7 requires `name ?`), and a boolean assignment whose right side runs past 160 characters or spans a `;`-free multi-line expression (`R7_ASSIGN_RE`).

Fix: add `\b(?:bg|border|stroke|fill|ring)-(?:positive|negative)\b` to `POS_TOKEN` / `NEG_TOKEN`. R5 and R8 pins will then move; re-pin each with a reason, or scope the new tokens to R2 and R7 only. Add a red self-test row for `up ? "bg-positive" : "bg-accent"`.

### 2. MEDIUM (confidence 4): `drawdownTone` turns a positive max drawdown into a neutral, plus-signed figure with no signal

`src/app/(dashboard)/allocations/components/KpiStrip.tsx:203-204`, `valueColorClass(..., drawdown)`; `KpiStrip.test.tsx` case "a positive 0.04".

The comment states a positive drawdown "is an upstream sign bug". The fix makes the cell neutral, but it still prints `+4.00%` as a Max DD with no log, no `captureToSentry` and no dash. An invariant violation (drawdown above 0, which would mean the sign convention flipped in `scenario.ts` or the analytics service) now looks like ordinary data instead of green. The test pins "not green, not red" and so locks the silence in.

Failure scenario: the Python analytics emits max drawdown as an absolute magnitude for one code path. Every allocator sees `+8.00%` Max DD in neutral grey and nobody is told. Before the fix it was at least visibly wrong (green).

Recommendation: either print the dash for `rounded > 0` on the drawdown cell, or report once through the project's capture path (`captureToSentry`) when `max_drawdown_12m > 0`. This is a judgement call. If the founder prefers neutral rendering, record that decision, because the current text calls it a bug and handles it quietly.

### 3. MEDIUM (confidence 4): the regime-change sentence turns a NaN average into a dash inside a real insight

`src/lib/portfolio-insights.ts:136-157`, `average()` at `:57`.

`computeRegimeChange` has no finite check. If a series point value is `undefined` or `NaN`, `average` returns NaN and `delta` is NaN. `best.delta < minDelta` is false for NaN, so the NaN candidate (always the first one, since `best == null`) passes the noise-floor test and is emitted. Before WR-01 the sentence read "from NaN to 0.62", visibly broken. After the `formatFixedSigned` swap it reads "from — to 0.62" or "from — to —": a plausible "Correlation regime shift" card with dashes as numbers, medium severity, and no hint the input was corrupt. The direction word ("loosened") is also derived from `NaN > x` being false. A null point value is coerced to 0 by `+`, so only an absent or NaN value gets here, which is why confidence is low.

Fix: skip the series when `!Number.isFinite(recent) || !Number.isFinite(prior)`, and add a test with a NaN point expecting `null`.
