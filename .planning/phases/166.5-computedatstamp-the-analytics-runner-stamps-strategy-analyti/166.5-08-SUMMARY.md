## Known limits (R-04, R-05, R-06)

- **R-04.** A strategy's first-ever `strategy_analytics` row keeps the column `DEFAULT now()` (NOT NULL), so its first date is the insert time, not a compute time.
- **R-05.** A `failed` row with NO sentence (the shape of scope arm S1, `failed` only because excluded side kinds once failed it) still resolves to `complete` under a side trigger. The hold keeps its predicate (`failed` AND a sentence present); the literal broad reading would invert S1 and re-open 164.6.6.3.4 D-05. Every real analytics failure writes a sentence and D-08 protects exactly those.
- **R-06.** A successful last-in-flight side job writes no first `complete` row for a strategy that has none (it used to insert one with the default date).
- **The PDF mixed-vintage window, booked as `[166.5-PDF-MIXED-VINTAGE-WINDOW]` (`TODOS.md`, plan 07).** The runner stamps in the metrics upsert and writes the sibling series AFTER it. The factsheet payload cache is not exposed (it reads only series written before the stamp); the PDF route is. A PDF rendered between the stamp and the sibling write shows the new scalars beside the previous run's lazy panels, carries the NEW ETag, can be served by the CDN for 3600 s (stale up to 86400 s more), and stays 304-valid until the next real recompute moves `computed_at`. **Measured width (plan 07, local stack, loopback): median 24.1 ms, max 41.6 ms** over 5 calls of one `upsert_strategy_analytics_series_batch` round trip with a 12-kind, 560 034-byte payload. A lower bound for PROD (no network hop). Closing option, booked not taken: write the siblings before the success write.
- **Deploy skew, NOT harmless in one direction (corrected after the silent-failure review, SFH-2).** The migration applies on the merge push and the Railway worker deploys separately. New bridge with the old worker: the bridge writes no date and the old worker does not stamp one, so a real recompute in the gap leaves `computed_at` unmoved; the factsheet payload cache key and the PDF ETag then repeat after the recompute and the previous run's figures are served. Old bridge with the new worker stamps twice, which is harmless. The ship is sequenced to close the harmful direction: PR 1 ships the runner stamp and code without the migration; PR 2 ships the migration only after Railway `/health` reports PR 1's merge commit. The Wave 5 preconditions above still apply.
- **Failed recomputes keep a too-new date until one succeeds (D-04).** See the residual above.
- **IN-R4-02** (cross-transaction clocks) is moot: the runner stamps from the database clock, so no two transactions compare clocks. **IN-R4-03** (the 42883 on the Python call after a rollback of the two-argument bridge) is recorded only; this phase's rollback restores the TWO-argument body, so it does not reintroduce it.
- **`[166.5-STALE01-PREMISE]` is booked** (`TODOS.md`, plan 07): STALE-01 hid figures on a `failed` row because the date dated the failure; a failed row now carries an honest last-good date. Behaviour unchanged, a founder question.
