## Shared Patterns

### 1. `CREATE OR REPLACE` re-base discipline (applies to the migration, down file, snapshot, verify block)
**Source:** `20261009120000_sync_status_analytics_scope.sql` plus `20261003120000_sync_status_bridge_residues.sql`.
- Re-base on the LATEST definition across all migrations (verified: `20261009120000`; nothing later mentions the bridge; PROD bridge arity is already `(uuid, uuid)`).
- Do not re-issue `COMMENT ON FUNCTION` (applied-ness key for arms 0a/0b).
- Restate `REVOKE ALL ... FROM PUBLIC, anon, authenticated` and `GRANT EXECUTE ... TO service_role`.
- Verify block reads catalogue and body only, runs on a COMMENT-STRIPPED copy (`v_body`) and also on `pg_get_functiondef` (`v_fn`).
- Every twin that edits the bridge text carries a layered stand-down of the anchor it triggers.

### 2. DB-clock stamp as a payload literal (applies to the two Python success writes)
**Source:** RESEARCH Pattern 1 (measured on PostgREST v14.10 / PG 17.6.1.113): `"computed_at": "now"` resolves to the transaction start; omitted key leaves the old date; `"nowish"` fails 22007. Neither a trigger, an RPC nor Python `datetime.now()` (D-02).

### 3. Provenance-wrapped success upserts (applies to both Python writes, unchanged)
**Source:** `upsert_or_drop_provenance(payload, _write_complete, where=...)` used by `_mark_complete` and `_write_headline_and_by_basis`. It exists for the PGRST204 deploy window on the two provenance keys; adding `computed_at` (an existing column) creates no new window, which is why this phase needs no deploy-ordering shim.

### 4. SQL gate conventions (applies to the new gate and every edited gate)
**Source:** `test_sync_status_analytics_scope.sql` header (lines 1-147) and 166.3.1's success-only gate.
- Plain PL/pgSQL `DO` blocks, `RAISE EXCEPTION 'TEST FAILED (ARM): ...'`, whole file in `BEGIN; ... ROLLBACK;`, no pgTAP, no psql meta-commands.
- Drive real RPCs (`mark_compute_job_done`, `mark_compute_job_failed`, `PERFORM sync_strategy_analytics_status(s[, job])`) rather than `UPDATE strategy_analytics`.
- Seed dates far from `now()` (10 or 30 days) so "equals the seed" can only hold if the writer's value was discarded.
- Each arm: `RED-UNDER:` prose + adjacent `RED-UNDER-M:` JSON; SETUP guards not twinned; every identity carries a digit.
- The new migration is appended LAST to each affected gate's `RED-UNDER-SETUP` apply list; both lanes (full local-stack replay in `sql-tests`, per-gate apply list in the mutation lane) must see the new bridge.
- A new `supabase/tests` file or arm moves several censuses; grep them all (project memory).

### 5. AST census style (applies to the new Python census and any new `strategy_analytics` payload key)
**Source:** `test_computing_started_at_stamp.py`, `test_computation_error_provenance_census.py`. Exact-count anti-vacuity pins, shape-matched carve-outs (never name-matched), unrecognized forms raise (never pass unclassified), synthetic defect strings proving each rule can fire.

### 6. Fail-loud, "tests must be able to fail"
**Source:** project CLAUDE.md and memory: neuter, see RED, restore from a byte backup (never `git checkout/restore/stash` on uncommitted work). Applies to every new test and gate arm, including both D-07 guards and the D-08 arm.
