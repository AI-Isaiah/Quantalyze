## Narrative Findings (AI reviewer)

### LOW-1 (ADVISORY) — evidence gate retains a genuinely-truncated account when a large missing WITHDRAWAL understates the base without sign-flipping NAV

**File:** `services/nav_twr.py:551-579` (`flow_coverage_gap_evidence`), consulted at
`services/job_worker.py:2370-2375`.

**Why it's real (but accepted):** The gate segments only on (a) a pre-terminus negative-NAV guard,
or (b) a fetched flow at/near the retention floor. A genuinely-truncated venue (returns extend
before the OKX-90d/Bybit-365d floor) with NO transfers inside the retention window and NO negative
NAV → neither signal → retains full history and ships `complete`. I traced the backward roll
(`NAV_{t-1}=NAV_t−pnl_t−F_t`): a missing *deposit* over-states the early base → *under*-states early
returns (safe direction), so the residual harmful case is a large missing *withdrawal* that
under-states the early base and over-states early returns while staying positive throughout (guard
never fires). That ships over-stated as `complete` with no warning. This is EXPLICITLY documented in
the `flow_coverage_gap_evidence` docstring as a founder-directed tradeoff ("keeping the full,
correct history of a flow-less key is preferred over blanket-truncating"). **Not blocking** — it is
a deliberate, documented accepted-residual, and the P78 golden-parity panel + founder confirmation
gate the actual production flip. **Recommendation:** confirm the P78 panel includes a
missing-large-withdrawal fixture so the residual's magnitude is bounded before the flip.

### LOW-2 (ADVISORY) — `negative_nav_guard_pre_terminus` localizes on ANY pre-terminus NaN, which may be a dust/flow-dominated guard NaN rather than the negative-NAV one

**File:** `services/nav_twr.py:559-579`.

**Why it's real:** The predicate gates on the whole-series `negative_nav_guard_fired` bool but then
returns `True` if ANY pre-terminus row is NaN — and pre-terminus NaN can also come from
`dust_nav_guard` / `flow_dominated_guard` (all three NaN their broken days; gap-fill uses 0.0 not
NaN, confirmed at `broker_dailies.py:127`, so NaN is guard-only). So a negative-NAV guard that fired
*post*-terminus alongside an unrelated dust NaN *pre*-terminus yields a spurious `True` → the
evidence gate segments. **Effect is conservative** (over-segments → truncates + warns
`flow_coverage_incomplete`), never an over-stated factsheet, and the scenario is narrow.
**Not blocking.** **Recommendation (optional):** if the standalone core ever tags per-day guard
provenance, tighten the pre-terminus check to the negative-NAV days specifically.

### LOW-3 (ADVISORY) — ccxt deposit fee model `amount − fee` assumes `amount` is gross-of-fee

**File:** `services/ccxt_flows.py:286-293` + `_fee_usd` at :102-160.

**Why it's real:** For a withdrawal the `amount + fee` debit model is unambiguous. For a deposit the
code applies `amount − fee`; if a venue already reports the ccxt unified `amount` NET of the
exchange fee, this double-subtracts the fee. **Magnitude is immaterial** (a fee next to a capital
move) and the direction is conservative (reduces NAV — never over-states performance), and the fee
degrades to 0.0 whenever unpriceable. **Not blocking.** **Recommendation:** spot-check one real
deposit row per ccxt venue at P78 to confirm the deposit `amount` semantics before trusting the
sub-cent fee correction; the withdrawal path (the one that matters for the bias-fix) is unambiguous.
