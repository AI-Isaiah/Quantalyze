# v1.6 Milestone Input — Scenario Tab Series-Space Purification

**Status**: SCOPED input for `/gsd:new-milestone` (not yet started). Authored 2026-07-03,
directly after v1.5 P61-BUG-1/2 landed (PR #570, v0.35.0.31).
**Origin**: user directive during v1.5 Phase 61 — "strategies are mixed with holdings.
In the scenario tab we don't need to see holdings, because structurally they do not
exist. There is no 'current' picture." + "have a final think what belongs into the
scenario tab and what does not."

## Principle (the one-line contract)

**The scenario tab operates in series space, not position space.** A scenario is a
hypothetical weighting of *return streams over a window*. Holdings are only ever a
*derivation source* for a book's return series and its natural weights — never a unit
the tab models. CSV strategies have no holdings at all; an API key's current positions
are irrelevant to a timeline blend. Both P61 bugs were position-space machinery leaking
into series space (the compare engine rebuilt drafts from a holdings *snapshot* whose
spans could not match the series the drafts were authored on).

## Empirical grounding (prod, khslejtfbuezsmvmtsdn, verified 2026-07-03)

- **gate=false real users: 0.** All 5 allocators with eligible API keys
  (`is_active ∧ sync_status≠'revoked' ∧ disconnected_at IS NULL`) have per-key
  `csv_daily_returns` series → `perKeyDailiesGateSatisfied = true` for every real book.
- 2 users have holdings rows but zero eligible keys — both are stale
  `phase10-rpc-*@test.local` residue (latest asof 2026-04-26), not real users.
  (Candidate cleanup rows; delete or ignore.)
- **Conclusion: the holdings-snapshot fallback engine serves nobody on prod.**

## Requirements

### R1 — Remove the holdings-snapshot fallback engine (the big one)

Delete the per-symbol holdings-unit path from the scenario surfaces:

- `buildStrategyForBuilderSet` (holdings→units) in `scenario-adapter.ts` and its
  composer/compare call sites — the engine-set selection becomes:
  book mode → per-key units (+ merged added units); blank mode → added units only.
- The holding-ref machinery scoped to scenario: `buildHoldingRef` scopeRefs as engine
  unit ids, `symbolByHoldingId` maps, and `collapseAliasedHoldingStrategies`
  (scenario-dealias) *if* per-key + added units never alias (verify: per-key ids are
  UUIDs, added ids are strategy UUIDs — the collapse is holdings-only by construction;
  it already passes non-holding ids through untouched. If confirmed, the collapse call
  and `src/lib/scenario-dealias.ts` retire together).
- Behavior for gate=false (transient states: brand-new key before backfill lands, or
  eligible key with 0 rows): the composer already renders the calm DSRC-02 fallback
  note ("per-source modeling needs per-key history"). Decision needed (D1 below):
  keep book mode read-only-empty behind that note, or fall back to blank mode
  (added-only) until the gate opens.
- **Frozen-engine note**: `src/lib/scenario.ts` / `scenario-window.ts` stay zero-diff.
  `scenario-dealias.ts` deletion is allowed only via the same reviewed re-baseline act
  as v1.5 used for spine guards (it is holdings-support code, not blend math).

### R2 — Drafts persist explicit series membership (schema v3 → v4)

Today a draft means "whatever the live book looks like when opened" implicitly:
`entryMode` is ephemeral `useState`, never persisted, so compare cannot distinguish a
blank-authored draft from a book draft (red-team F5 on PR #570, pre-existing class).

- Add explicit membership to the draft: which per-key series ids are in the scenario
  (or a `book: true|false` marker + per-key toggle map — decide shape in research;
  favor listing ids so key-set drift after save is detectable and disclosable).
- Codec: non-destructive upgrade branch (v3 drafts get membership derived the way
  compare derives it today: gate=true ⇒ book member), same pattern as v1.5's
  `upgraded_v2_windowless`.
- Closes F5 by construction; also makes the P61-BUG-2 compare mirror self-describing
  instead of gate-inferred.
- Downstream: share-mint gate + share-resolve read the SAME membership field (a
  book-only draft is one whose membership is only per-key ids).

### R3 — Move AUM out of the tab's KPI strip

AUM is a position-space fact. Its one legitimate consumer is commit sizing (weight ×
AUM), which lives at the COMMIT boundary.

- Remove the AUM KPI from the scenario KpiStrip (return-form metrics only — same
  presentation contract as the public share page, which already renders "No USD, no AUM").
- Keep `scenarioAum` feeding the commit diff modal unchanged.
- DESIGN.md check for the strip layout after removal.

### R4 — Share-page partial-projection caption (red-team F3, small)

Mixed keys+added shares render the added legs renormalized to 100% — materially
different numbers from the owner's blend under the same name. Add a one-line caption:
"computed from this scenario's catalog strategies only" (needs no private data).
With R2 landed, the caption can render conditionally (only when the draft's membership
includes book series).

### R5 — Cleanup & guards

- Delete the two `phase10-rpc-*@test.local` residue users' holdings rows (or the users)
  from prod.
- Regression net: the v1.5 P61 suites (ScenarioComposer P61 block, scenario-compare
  per-key block, T_CP8, share T_SH13/14) must survive R1 verbatim or be re-pointed as
  reviewed acts — they pin the per-key + added path, which is exactly the path that
  remains.
- Grep-guard candidate: no `holding:` scopeRef may appear in an engine unit id on the
  scenario surfaces post-R1 (cheap invariant test).

## Decisions needed at kickoff (AskUserQuestion material)

- **D1**: gate=false book behavior after R1 — (a) blank-mode fallback (added-only
  composer + note; recommended: honest, zero new code) vs (b) read-only empty book mode.
- **D2**: R2 membership shape — explicit per-key id list (recommended; drift-detectable)
  vs boolean book marker.
- **D3**: does toggling a data source off persist with the draft now that membership is
  explicit? (Today `includeByApiKeyId` is deliberately ephemeral — "Resets on reload."
  Persisting it changes a documented UX contract; keep-ephemeral is the conservative
  default, but R2 makes persisting it trivial if wanted.)

## Suggested phase shape (4 phases, continues numbering at 62)

1. **62 — Membership schema (R2)**: draft v4 + codec branch + compare/share/mint read
   membership. Pure additive; lands before any deletion so R1 has the new source of truth.
2. **63 — Fallback-engine removal (R1)**: composer + compare + adapter deletions,
   dealias retirement (if verified), D1 behavior, R5 guards.
3. **64 — Presentation purification (R3 + R4)**: AUM KPI out, share caption in.
4. **65 — Authed prod canary**: qa-demo Atlas book sweep (the P61 recipe) + blank-mode
   and share round-trips.

Order matters: R2 before R1 (membership replaces the gate as the selector), R3/R4
anytime after, canary last.
