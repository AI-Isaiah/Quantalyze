# Requirements: Quantalyze — Sprint 8: Bridge V2

**Defined:** 2026-04-17
**Core Value:** Allocators act on Bridge recommendations and see whether those suggestions actually worked.

## v1 Requirements

### OUTCOME — Post-allocation outcome tracker

- [x] **OUTCOME-01**: Allocator can record outcome (allocated X% on date D, or rejected with reason) via inline banner on the strategy's Holdings table row.
- [x] **OUTCOME-02**: Banner surfaces only for strategies with a prior `match_decisions.decision = 'sent_as_intro'` and no existing `bridge_outcomes` entry (dismissible per session, reappears next visit).
- [x] **OUTCOME-03**: `bridge_outcomes` table enforces three-tier RLS: owner-select, owner-insert, admin-select, service-role-all.
- [x] **OUTCOME-04**: Outcome recording blocks if allocator never received this strategy as a Bridge intro (join-verified against `match_candidates`).
- [x] **OUTCOME-05**: Immediately after recording, UI shows an estimated delta (e.g. "Estimated: +2.1% (3d)") computed from whatever returns data exists; label upgrades to "30-day: +4.3%" as windows complete.
- [x] **OUTCOME-06**: Daily cron computes 30/90/180-day realized delta from `strategy_analytics.returns_series`; idempotent via `WHERE delta_30d IS NULL` guard.
- [x] **OUTCOME-07**: Upserted outcome triggers delta recomputation on next cron run via `needs_recompute` flag.
- [x] **OUTCOME-08**: Every outcome recording + update is logged via `log_audit_event` with `entity_type = 'bridge_outcome'`.

### MANDATE — Mandate profile builder

- [x] **MANDATE-01**: Allocator can set `max_weight` (slider, 5–50%, default 25%) in My Allocation settings.
- [x] **MANDATE-02**: Allocator can set preferred strategy types (multi-select chips) and excluded exchanges (multi-select from Binance / OKX / Bybit) — always-visible Basic section.
- [x] **MANDATE-03**: Allocator can set correlation ceiling (slider 0–1, default 0.6), risk budget (max drawdown %, default 20%), liquidity preference (High / Medium / Low), style exclusions — Advanced accordion, collapsed by default.
- [x] **MANDATE-04**: Mandate form auto-saves on blur per field with "Last saved: N min ago" timestamp; no submit button.
- [x] **MANDATE-05**: All mandate writes go through `update_allocator_mandates(...)` SECURITY DEFINER RPC scoped to `auth.uid()`.
- [x] **MANDATE-06**: Direct UPDATE on `allocator_preferences` remains admin-only; allocator writes land only through the RPC.
- [x] **MANDATE-07**: `ALLOCATOR_PREFERENCES_COLUMNS` in `src/lib/admin/match.ts` stays in sync with schema; smoke test asserts against `information_schema.columns`.
- [x] **MANDATE-08**: Every mandate update is logged via `log_audit_event` with `entity_type = 'allocator_preference_mandate'`.

### SCORING — Mandate-aware scoring engine

- [x] **SCORING-01**: `match_engine.py` bumps to `ENGINE_VERSION = v2.0.0`; v1 cached batches invalidated via existing version-check.
- [x] **SCORING-02**: `score_candidates()` outputs `mandate_fit_score` inside `score_breakdown` JSONB on `match_candidates`.
- [x] **SCORING-03**: `mandate_fit_score` composes inside `W_PREFERENCE_FIT` as `0.6 × existing_preference_fit + 0.4 × mandate_fit_score`; total scoring weights sum = 1.0 unchanged.
- [x] **SCORING-04**: Allocators with empty mandates get `mandate_fit_score = 1.0` (no penalty, graceful degradation).
- [x] **SCORING-05**: Mandate updates invalidate the allocator's cached batch via `updated_at` comparison (no full recompute).
- [x] **SCORING-06**: `match_batches.effective_preferences` snapshots the effective scoring inputs at scoring time (mandates + overrides).
- [x] **SCORING-07**: Constraint enforcement: candidate exceeding `max_weight` → `mandate_fit < 1.0`; style exclusion hit → hard exclude; correlation ceiling breach → penalized.

### FEEDBACK — Rule-based feedback loop

- [x] **FEEDBACK-01**: `feedback_engine.py` (new module) computes per-dimension scoring weight adjustments from `bridge_outcomes` history.
- [x] **FEEDBACK-02**: Adjustment rule: `success_rate < 0.4` → `max(0.5 × default, current)`; `success_rate > 0.7` → `min(1.5 × default, current)`; 0.4–0.7 → no change.
- [x] **FEEDBACK-03**: Minimum 5 outcomes required before any adjustment; cold start falls back to defaults.
- [x] **FEEDBACK-04**: Adjusted weights persisted to `allocator_preferences.scoring_weight_overrides` JSONB column.
- [x] **FEEDBACK-05**: Every scoring weight dimension (`W_PORTFOLIO_FIT`, `W_PREFERENCE_FIT`, `W_TRACK_RECORD`, …) adjusts independently per allocator.
- [x] **FEEDBACK-06**: Each scoring run reads overrides from `allocator_preferences` and snapshots them into `match_batches.effective_preferences`.

### DASHBOARD — Outcomes widget

- [x] **DASHBOARD-01**: Outcomes widget renders as a new widget inside the existing react-grid-layout grid on My Allocation (not a new tab container).
- [x] **DASHBOARD-02**: KPI strip (top) shows total outcomes recorded, win rate %, average realized delta in Geist Mono 13px.
- [x] **DASHBOARD-03**: Timeline list (below KPI) shows columns Original Strategy | Replacement | Date Recorded | Status | Best Available Delta (30d → 90d → 180d, green/red) in DM Sans 14px body.
- [x] **DASHBOARD-04**: Expanded row shows three-column delta comparison (30d / 90d / 180d) with mini sparklines of original vs replacement equity curves diverging.
- [x] **DASHBOARD-05**: Empty state: illustration + "Your Bridge outcomes will appear here after you act on one" + CTA pointing at Bridge.
- [x] **DASHBOARD-06**: State matrix fully covered — loading (skeleton rows), error ("Could not load outcomes" + retry), partial ("Estimated" / "Pending" delta labels).

## Out of Scope

| Feature | Reason |
|---------|--------|
| ML-based recommendation model | Rule-based v1 ships Sprint 8; `bridge_outcomes` schema is ML-ready; ML is a Year-2 swap of the weighting function |
| New top-level `mandate_fit` weight | Would require total-weight rebalance; composition inside `W_PREFERENCE_FIT` preserves sum = 1.0 |
| New `allocator_mandates` table | Extending `allocator_preferences` avoids migration churn and keeps single source of truth per allocator |
| Separate feedback-weight table | JSONB column on `allocator_preferences` suffices; per-batch snapshot lives on `match_batches.effective_preferences` |
| Full column-level RLS on mandates | Postgres doesn't support it; SECURITY DEFINER RPC gives the same guarantee |
| PDF report generation | Sprint 10 (was Sprint 9) — LP-facing surface |
| Mobile responsive polish | Sprint 11 — desktop-only acceptable for current demo surface |
| Real-time WebSocket data | Year 2 |
| White-label partner portal | Year 3 |
| LLM-generated commentary | Liability risk for institutional product |
| FOR UPDATE SKIP LOCKED on delta cron | Idempotent `WHERE NULL` guard is sufficient; simpler, no lock overhead |
