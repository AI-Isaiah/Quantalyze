## Structural Decisions

### 4-phase wave structure for v0.17.0.0 (Option B-prime, post cross-AI review)

**Chosen:** Phase 12 ‖ Phase 13 (parallel Wave 1) → Phase 14a (Wave 2 eager) → Phase 14b (Wave 3 lazy).

Phase 12 (Python analytics-service) and Phase 13 (TypeScript Discovery) touch zero overlapping files — independent code surfaces. Running them in parallel compresses the estimate by 2 phase cycles. Phase 14 strictly depends on Phase 12 (UI consumes the new JSONB keys), so it ships in Wave 2.

Phase 14 split into 14a + 14b per cross-AI review 2026-04-26: original Phase 14 carried 30 REQs. Both reviewers (fresh Claude subagent + Grok-4-1-fast-reasoning) flagged this as too dense. Lazy panels (4–7) are a natural cleavage point — they share mount infrastructure (IntersectionObserver scaffold) but are independent of the eager half (panels 1–3). Splitting enabled: (a) early visible win on eager panels, (b) Trade Mix audit close-out moves to 14b, (c) automated parity diff tools built once and reused, (d) axe-core CI runs against complete 7-panel mount in 14b.
