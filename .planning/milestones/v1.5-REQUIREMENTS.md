# Requirements: Quantalyze — v1.5 Scenario Coverage-Window Blend

**Defined:** 2026-07-01 (scoped via `/gsd:new-milestone`)
**Core Value:** Allocators model the impact of composition changes before they make them — and the modeled "mean strategy" must be an *honest* average of strategies that are actually co-live over the shown window, not one diluted toward zero by members that have already ended.

**Design source:** `.planning/SCENARIO-COVERAGE-WINDOW-ADR.md` (ADR-001). Research: `.planning/research/{STACK,FEATURES,ARCHITECTURE,PITFALLS,SUMMARY}.md`.

**The change (departure from v1.2–v1.4):** this milestone **deliberately rewrites the FROZEN `scenario.ts` core**. The current convention — "all-started / no-end-bound / 0-fill-the-tail / divisor = every started strategy" — lets an *ended* strategy keep dividing the blend and dilute the tail toward zero. v1.5 replaces it with a **coverage-window membership model**. SCENARIO-05 (zero-diff) and the frozen-spine guards are **re-baselined as a reviewed act**, not honored.

**LOCKED invariants (must NOT regress):** `no-invented-data` (degenerate/zero-member windows render honest empty states — never fabricated zeros or divide-by-zero) · 252-day annualization is product-wide · factsheet **parity-by-construction** (`compute.ts` runs on the same blended series `computeScenario` emits) · the WCAG-AA floor · no live-book / cross-tenant leak on shared scenarios.

**Decisions locked at kickoff:** REPLACE the convention (not an additive mode); shared scenarios **recompute-on-open**; interior mid-window gaps **0-filled** (constant divisor); weighted blends **renormalize** surviving weights to sum-to-1 after a drop; the coverage window is **persisted** in the saved/shared scenario (recompute today's numbers at the owner's window); intersection is the **default + snap target, NOT a hard max** (widening past coverage is allowed and auto-drops the non-covering member). Full UX scope selected (all three tiers).

**Zero new runtime dependencies** (research STACK): reuse `dateday.ts` + already-sorted return series; the coverage-span / intersection math is a small pure-TS helper.

Phase numbering continues from v1.4's Phase 54 (no reset) — v1.5 is Phases 55+.

## v1 Requirements

Each maps to exactly one roadmap phase (filled by the roadmapper). Dependency order (all four researchers converged): **compute core → factsheet-parity re-verify → UI/state & legibility → persistence (saved/shared/compare) → golden & e2e re-bake → authed QA canary.**

### BLEND — coverage-window compute core

- [x] **BLEND-01**: `computeScenario` blends over an explicit `[winStart, winEnd]` window (a new optional field on `ScenarioState`, mirroring how leverage was added), replacing the implied-union date axis.
- [x] **BLEND-02**: A strategy is a blend member iff `enabled AND its data span ⊇ the window`; the divisor counts members only — an ended strategy no longer divides the blend or dilutes the tail.
- [x] **BLEND-03**: Interior mid-window gaps stay 0-filled so the divisor is constant across the window (documented deliberate simplification).
- [x] **BLEND-04**: Weighted (non-equal) blends renormalize surviving members' weights to sum to 1 after a coverage drop.
- [x] **BLEND-05**: A zero-member window renders an honest empty-state — no divide-by-zero, no fabricated zeros (`no-invented-data` preserved).
- [x] **BLEND-06**: The engine output exposes `member_count`, the effective `[winStart, winEnd]`, and `N` (trading days) so consumers and the UI *read* the divisor rather than infer it.
- [x] **BLEND-07**: The blend matches an independent from-scratch (numpy) computation to floating-point precision over the max-overlap window — verified on the 6-strategy golden dataset (mm/neon1/pokeokx/uc244 + OKX/Bybit) *before* any golden re-bake.

### WINDOW — timeline & auto-toggle control

- [x] **WINDOW-01**: The scenario defaults its timeline to the max-overlap (intersection) window of the selected+on strategies (default + snap target — not a hard cap).
- [x] **WINDOW-02**: Widening the window past a strategy's coverage auto-toggles that strategy OFF (removed from blend + divisor).
- [x] **WINDOW-03**: Narrowing the window until a strategy regains full coverage auto-toggles it back ON — operating only within the user's selected subset, never adding an unselected strategy.
- [x] **WINDOW-04**: A **"Common period (all in)"** preset snaps the window to the selected set's common overlap with all members ON.
- [x] **WINDOW-05**: A **"Full range (some drop out)"** preset widens to the union of the selected set, auto-dropping non-covering members.
- [x] **WINDOW-06**: When the selected set shares no common window, the app names the outlier(s) and offers a one-click deselect (guided empty-intersection fix), not a dead-end.

### COVERAGE — legibility & disclosure

- [x] **COVERAGE-01**: A coverage timeline (mini-gantt) shows each selected strategy's data span against the active window, so "why did X drop?" and "how much history to keep it?" are visible.
- [x] **COVERAGE-02**: Each strategy row shows one of three states — **in-blend** / **manually excluded** / **auto-excluded (outside window)** — the third visually distinct and carrying an inline reason (e.g. "ends Jan 2025 — outside window").
- [x] **COVERAGE-03**: An always-visible blend header states **member count · effective window · N**, degrading honestly ("1 strategy — not a blend", "window truncated from full range").
- [x] **COVERAGE-04**: An auto-excluded row offers a one-click **"include → shortens window to [date] (−N months)"** affordance that shows the cost before applying.

### PERSIST — saved / shared / compared scenarios

- [x] **PERSIST-01**: The coverage window is saved as part of a scenario (`ScenarioDraft` schema_version bump + migration); reopening a saved scenario recomputes today's numbers at the owner's saved window.
- [x] **PERSIST-02**: A shared link recomputes-on-open at the owner's window under the new rule, with no live-book / cross-tenant leak, and the recipient's view matches the owner's (identical window derivation via one shared helper).
- [x] **PERSIST-03**: Compare (2+ scenarios side-by-side) works with each scenario's own persisted window.

### PARITY — no-regression across the blast radius (~12 consumers)

- [x] **PARITY-01**: The real factsheet on the blend stays parity-by-construction — it consumes `computeScenario`'s series and never re-derives the blend (asserted with a single-source-of-truth guard, not assumed).
- [x] **PARITY-02**: stress/VaR, benchmark, Monte-Carlo, compare, and the KPI strip produce correct results on the coverage-window series — the latent union-window assumptions documented in `scenario-benchmark.ts` / `scenario-compare.ts` are cleared.
- [x] **PARITY-03**: SCENARIO-05 zero-diff + the `phase-{29,30,31,32,52}-frozen-spine-guards` are re-baselined as a reviewed act (never deleted, never blind `--update-snapshots`); `no-invented-data`, 252-annualization, and WCAG-AA stay green.

### VERIFY — goldens & live QA

- [x] **VERIFY-01**: The svg-golden bake (WR-02) and seeded e2e re-diffs are re-baked deliberately (per-chart, reviewed) and green after the math change — never in the same commit that changes the math.
- [x] **VERIFY-02**: An authed prod canary on `/allocations` verifies widen→auto-drop, narrow→auto-restore, both window presets, the empty-intersection guidance, and divisor == visible membership, live.

### POLISH — Tier 3 refinements

- [x] **POLISH-01**: The chart brush-zoom stays a **view** control, visually distinct from the analytical window — never merged (view vs. membership).
- [x] **POLISH-02**: The auto-toggle transition animates — a dropped strategy visibly moves to the excluded state instead of silently vanishing.
- [x] **POLISH-03**: A one-time union→intersection default-change note ("Now showing the common period where all N overlap · show full range") with an escape hatch, so returning users aren't surprised.

## v2 / Future Requirements

Acknowledged, not in this roadmap.

### Blend refinements

- **BLEND-F1**: Correlation / diversification matrix computed over *mutually-present* days rather than 0-filled-union vectors (avoids understating correlation on non-overlapping tails). Decide in the compute phase or defer.
- **BLEND-F2**: An interior-gap density floor above which a member is "too sparse to be honest" (the ADR treats interior gaps as rare for daily series; no threshold set yet).

### Cross-venue

- **VENUE-F1**: Trading-calendar / cross-venue "same day" normalization and any per-asset annualization divergence (crypto-365 vs 252). 252 stays the universal basis this milestone; this is the known deferred reconstruction-mismatch item.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Proxy / backfill of short histories to extend a member's span | Direct `no-invented-data` violation — there is no honest proxy for a manager track record (research FEATURES anti-feature). |
| Per-date dynamic divisor as the primary model (ADR Option B) | Produces a *ragged* blend whose membership silently changes day-to-day and can't be steered; rejected in favor of window-fixed membership. |
| Additive "aligned mode" keeping today's convention as default (ADR Option C) | Two code paths, and the tail-dilution stays the default. REPLACE, don't add. |
| Merging chart brush-zoom into the analytical window | View vs. membership footgun (research); kept separate by POLISH-01. |
| `computeCompositeCurve` (My-Allocation overlay) coverage-window behavior | Not a scenario-tab consumer; with `window` optional it keeps union behavior. Out of scope to keep the blast radius tight. |
| Cross-venue calendar normalization / per-asset annualization | Deferred (VENUE-F1); 252 stays universal this milestone. |
