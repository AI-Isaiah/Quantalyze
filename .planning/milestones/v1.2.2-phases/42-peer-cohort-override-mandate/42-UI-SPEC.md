### Delta Color Rule

The own-book delta compares a hypothetical blend's ratios to the allocator's live book. Sign color MUST follow:

- Positive delta (blend > book): `var(--color-positive)` — but only for RISK-CORRECTED metrics (Sharpe, Sortino) where a higher value is unambiguously better.
- Negative delta (blend < book): `var(--color-negative)` for those same metrics.
- For Max Drawdown (shallower = better): the sign semantics INVERT — a negative delta (blend drawdown shallower than book) is the favorable direction. Use `var(--color-positive)` when blend max_dd > book max_dd (less negative = better) and `var(--color-negative)` the other way. This matches the existing `PercentileBar` label "Max DD (shallower = better)" convention.
- The delta MUST also carry a `+`/`-` sign prefix in text, independent of color, for WCAG non-color-only communication. Format: `+0.24` or `−0.18` (use Unicode minus U+2212 for the negative sign in display, not ASCII hyphen).
- When the live book is unavailable (no `allocator_equity_snapshots`): render the honest empty state; do NOT render zeroed deltas.

Accent (`#1B6B5A`) is NOT used for deltas — it means "verified/action" in this design system. Deltas use the positive/negative semantic colors only.

## Component Inventory

### 1. PeerPercentilePanel — header re-label (scenarioMode path)

**File:** `src/app/factsheet/[id]/v2/BatchDPanels.tsx`

The existing component reads `payload.ingestSource` and early-returns if not `"api"`. Phase 42 (PEER-01) removes that hard guard and replaces it with a dual path: the api path continues unchanged; a new scenario path renders when `scenarioMode && payload.scenarioPeer != null`.

**Changed elements (scenario path only):**

The `<h3>` header currently reads:
```tsx
Peer Percentile <DemoBadge>Demo cohort</DemoBadge>
```

Replace with:
```tsx
<h3 className="text-[12px] font-semibold uppercase tracking-[0.18em] text-text-primary">
  Peer Percentile
</h3>
```
No badge. The disclosure moves BELOW the bars (see disclosure element below).

The existing `N={p.cohortSize}` span in the header is RETAINED verbatim:
```tsx
<span className="text-[9px] font-mono uppercase tracking-wider text-text-muted">
  N={scenarioPeer.cohortSize}
</span>
```

The three `PercentileBar` rows (`Sharpe`, `Sortino`, `Max DD (shallower = better)`) are REUSED UNCHANGED.

**New: disclosure element** — rendered after the bars, replacing the existing synthesized-cohort italic footnote:
```tsx
<p className="mt-2 text-[10px] text-text-muted">
  hypothetical blend · ranked vs verified strategies · sample/252 basis
</p>
```

Exact copy (verbatim):
> hypothetical blend · ranked vs verified strategies · sample/252 basis

This is not italic — it is plain caption text at 10px muted. The "·" separator (U+00B7 middle dot) is the DESIGN.md editorial separator used throughout the factsheet.

**n < 252 suppression:** when `scenarioPeer` is present but `payload.strategyMetrics.n < 252`, the entire scenario peer panel does not render (consistent with the existing `n < 252` caveat already shown in MetricsColumn's "Main Metrics" panel). No partial render; honest absence.

**cohortSize < 20 suppression (PEER-03):** when the server returns a cohort below min-N (~20), `scenarioPeer` is `null` (the server omits it). The gate `payload.scenarioPeer != null` naturally handles this — no UI-level check needed beyond null-guard. The empty state is honest absence (no panel at all).

**Empty state (when panel would have rendered but suppression fires):** render nothing. The existing `n < 252` warning in "Main Metrics" already contextualizes insufficient data for the allocator. Do NOT add a second message.

**a11y:** The `<section>` wrapper has no `aria-label` (it is within an `EditorialSection` that provides the heading context). The disclosure `<p>` is plain text in reading order — a screen reader will encounter it naturally. No `aria-live` region needed (the panel renders server-side once, not as a dynamic update).

### 2. ConstituentMandatePanel — per-constituent mandate chips

**File:** new `src/app/factsheet/[id]/v2/MandatePanels.tsx` export (added to existing file).

**When it renders:** only when `scenarioMode === true`. In non-scenario factsheets this component returns `null` — no behavior change to the real route.

**Data source:** each constituent in the scenario blend exposes `strategy_types`, `markets`, `leverage_range`, and `description` from the strategies table. These are passed into the factsheet payload (or derived from the blend's constituent metadata). The CONTEXT.md PEER-04 decision: per-constituent chips from genuinely-available fields only.

**Panel shell:** uses the existing `Panel` component (the same `<section>` + `<header>` + `<h3>`) with title `"Mandate"`. The `Panel` component is the internal factsheet primitive at MetricsColumn.tsx line 173.

**Layout inside the panel:**

One sub-block per constituent, separated by `border-b border-border/40` hairlines. Last sub-block has no hairline (`last:border-0`).

Each constituent sub-block:
```
[Constituent Name]          11px DM Sans semibold text-text-primary
[chip row: types chips]
[chip row: markets chips]
[chip row: leverage chip]   if leverage_range is present
```

If a constituent has no `strategy_types`, no `markets`, and no `leverage_range`:
```
[Constituent Name]
no mandate metadata          11px italic text-text-muted
```

This is the honest-empty-per-constituent path (PEER-04 verbatim).

**Chip styling** — reuse the existing badge token ladder from DESIGN.md:

Neutral-outline chip (strategy_types, markets):
```tsx
<span className="inline-flex items-center rounded-sm border border-border px-2 py-0.5 text-[10px] font-medium uppercase tracking-wider text-text-secondary">
  {value}
</span>
```
Token references: `rounded-sm` (4px, DESIGN.md badge ladder), 1px `--color-border` border, 10px DM Sans medium uppercase — matching the `TrustTierLabel` `csv_uploaded` variant's geometry (inline-flex items-center rounded-sm border px-2 py-0.5 text-xs font-medium) but using `--color-text-secondary` text (neutral, not semantic).

Leverage chip (when `leverage_range` is present) — uses the same neutral-outline geometry:
```tsx
<span className="inline-flex items-center rounded-sm border border-border px-2 py-0.5 text-[10px] font-medium uppercase tracking-wider text-text-secondary">
  {leverage_range}×
</span>
```
No special color for the leverage chip — it is metadata, not a warning.

Chip rows use `flex flex-wrap gap-1` (4px chip gap, 8px wrap gutter not needed at this density).

**description field:** NOT rendered as a chip. The strategies table `description` field is free-text prose (potentially multi-sentence). Rendering it as a chip would be a misuse of the chip pattern. It is omitted from the mandate chip row in v1.2.2. A future phase may render it as a sub-paragraph.

**DOM structure (single constituent sub-block):**
```tsx
<div className="py-2 border-b border-border/40 last:border-0">
  <p className="text-[11px] font-semibold text-text-primary mb-1">{constituent.name}</p>
  {hasAnyChip ? (
    <div className="flex flex-col gap-1">
      {strategy_types.length > 0 && (
        <div className="flex flex-wrap gap-1">
          {strategy_types.map(t => <Chip key={t}>{t}</Chip>)}
        </div>
      )}
      {markets.length > 0 && (
        <div className="flex flex-wrap gap-1">
          {markets.map(m => <Chip key={m}>{m}</Chip>)}
        </div>
      )}
      {leverage_range && (
        <div className="flex flex-wrap gap-1">
          <Chip>{leverage_range}×</Chip>
        </div>
      )}
    </div>
  ) : (
    <p className="text-[11px] italic text-text-muted">no mandate metadata</p>
  )}
</div>
```

`Chip` is a local inline component (not a shared primitive — keeping the spec surgical per Rule 2): `<span className="inline-flex items-center rounded-sm border border-border px-2 py-0.5 text-[10px] font-medium uppercase tracking-wider text-text-secondary">`.

**a11y:**
- Each chip `<span>` has no role by default; it is static display text. No `role="img"` or ARIA needed — the chip text is the label.
- The constituent name `<p>` provides contextual heading for the chip rows beneath it. A screen reader will read "Constituent Name [name], trend-following, crypto, 2×" in natural reading order.
- The constituent sub-blocks are within a `<section>` element (Panel), giving screen readers a navigable landmark for the mandate section.
- When the panel renders nothing (no `scenarioMode`), it returns `null` — no empty `<section>` in the DOM.

**Empty state — no constituents with any metadata:**

When ALL constituents in the blend have no `strategy_types`, no `markets`, and no `leverage_range`, the panel body reads:

```tsx
<p className="text-[11px] italic text-text-muted">
  No mandate metadata available for this blend&apos;s constituents.
</p>
```

The `Panel` title "Mandate" still renders — the honest empty copy appears in the panel body. Do NOT hide the panel entirely when data is absent; the absence itself is informative.

### 3. OwnBookDeltaPanel — blend vs live book delta

**File:** `src/app/factsheet/[id]/v2/BatchDPanels.tsx` (new export, sibling to `PeerPercentilePanel`).

**When it renders:** only when `scenarioMode === true && ownBookDelta != null`. When the allocator has no `allocator_equity_snapshots` (no live book), `ownBookDelta` is `null` and this panel does not render.

**Panel shell:** uses the existing `Panel` component with title `"vs Your Book"`. No `benchHeader`.

**Data:** `ownBookDelta` carries signed differences on the sample/252-basis ranking metrics (same convention as the peer rank, per CONTEXT.md PEER-05):

```ts
type OwnBookDelta = {
  sharpe: number | null;   // blend_sharpe - book_sharpe (sample/252 basis)
  sortino: number | null;  // blend_sortino - book_sortino
  max_dd: number | null;   // blend_max_dd - book_max_dd (note: sign inversion for display)
  book_n: number;          // observation count of the live book (for basis note)
};
```

**Rows:** rendered using the existing `Kpm` + `Row` pattern from MetricsColumn, but the value cell uses a colored signed format instead of a plain number. Three rows: Sharpe, Sortino, Max Drawdown.

**Value format:**
- Sharpe and Sortino: `+0.24` or `−0.18` (Unicode minus). Color as per §Delta Color Rule.
- Max Drawdown: the delta is `blend.max_dd − book.max_dd` where max_dd is expressed as a negative percentage (e.g. −0.15). A POSITIVE delta here means the blend has a LESS-NEGATIVE max_dd (shallower = better). Display as `+1.8pp` or `−2.3pp` (in percentage-points). Color INVERTED vs the sign: positive delta → `--color-positive`; negative delta → `--color-negative`. The label reads "Max DD (blend vs book)".

**Basis note** (below the table, same italic 10px muted style as other footnotes):
```tsx
<p className="mt-2 text-[10px] italic text-text-muted">
  Delta = blend minus your live book · sample/252 basis · {book_n} book observations
</p>
```

Exact copy template:
> Delta = blend minus your live book · sample/252 basis · {N} book observations

Where `{N}` = `ownBookDelta.book_n.toLocaleString()`.

**Empty state (no live book):** the panel does not render. No placeholder, no "add your book" CTA — that is a conversion action, out of scope for a factsheet panel. The §III Style section simply ends after `PeerPercentilePanel`.

**a11y:**
- Signed delta is communicated by both color AND the leading `+`/`−` character. Color alone is never the sole signal (WCAG 1.4.1).
- The sign character `−` (U+2212) renders as "minus" in most screen readers, correctly conveying the sign.
- The `<section>` (Panel) has `h3` title "vs Your Book" — descriptive for screen reader navigation.
- No `aria-live` — the delta is static once the factsheet renders.

## Summary

Phase 42 touches three narrowly-scoped display elements on the scenario blend's `MetricsColumn`, all built from existing primitives. The `PeerPercentilePanel` loses its "Demo cohort" badge and gains a 10px muted disclosure line ("hypothetical blend · ranked vs verified strategies · sample/252 basis") underneath the unchanged percentile bars; it renders only when `scenarioPeer != null` AND `n >= 252`. A new `ConstituentMandatePanel` drops into §V Terms and renders per-constituent neutral-outline chips (`rounded-sm border border-border px-2 py-0.5 text-[10px] font-medium uppercase tracking-wider text-text-secondary`) for `strategy_types`, `markets`, and `leverage_range`, falling back to "no mandate metadata" italic copy per constituent when fields are absent. A new `OwnBookDeltaPanel` drops into §III Style after the peer panel and renders a three-row `Kpm` table (Sharpe / Sortino / Max DD) with signed Unicode-minus deltas colored via `--color-positive` / `--color-negative`, sign carried non-color-only by the `+`/`−` prefix, and a 10px italic basis note; it is silently absent when no live book exists. No new colors, sizes, fonts, or third-party dependencies are introduced — every token is DESIGN.md-verbatim, every layout primitive is inherited from the existing factsheet editorial shell.
