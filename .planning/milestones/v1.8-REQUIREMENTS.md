# Requirements: Quantalyze v1.8 Flow-Aware Time-Weighted Returns

**Defined:** 2026-07-05
**Core Value:** Allocators act on Bridge recommendations and see whether those suggestions actually worked — and can model composition changes before they make them. For v1.8: every track record's *return magnitude* is honest on every exchange. Anchor-to-today silently over/under-states flow-heavy accounts (a live Deribit account onboarded at +458% cum / 229,214% CAGR, founder-confirmed inflated); this milestone replaces it with true time-weighted returns computed from a daily NAV series that dates every external cash flow.

## Grounding facts (verified 2026-07-05, planning-time)

- **Root cause pinned:** `services/transforms.py:trades_to_daily_returns_with_status` (L148–159 & L196–199). `initial_capital = account_balance − total_pnl`; when ≤ 0 (profits withdrawn) it silently falls back to today's tiny equity as the return base — no DQ flag. Cross-exchange, not Deribit-specific.
- **Method verified:** the design formula `r_t = (NAV_t − NAV_{t-1} − F_t)/NAV_{t-1}` is Wikipedia TTWROR **Formula 1** (end-of-day flow convention) = GIPS true-TWR (the accuracy-hierarchy top when a daily NAV exists). Modified Dietz and IRR/money-weighted are **anti-features**.
- **No new dependencies.** `ccxt==4.5.59` exposes `fetchDeposits`/`fetchWithdrawals` for all four venues (`has==True`); `pandas==2.2.3`/`numpy==2.4.6` cover the NAV/TWR math. `fetchDepositsWithdrawals` is absent everywhere → two-call pattern (already in `equity_reconstruction._fetch_transfers`).
- **Exactly two callers** of the bug function: `services/broker_dailies.py:130` (`combine_realized_and_funding`) and `services/analytics_runner.py:1309` (legacy CSV).
- **Flow sourcing 60–80% built:** OKX live in `_fetch_transfers` (L642); Deribit flows in-band in the `get_transaction_log` crawl under `_EXTERNAL_FLOW_TYPES`; Binance/Bybit are new branches on the same `_fetch_transfers` helper.
- **Two Key Decisions logged (PROJECT.md, 2026-07-05):** (1) **SPLIT annualization** — RETURN/CAGR (and Calmar) on the 365/calendar clock, RISK (Sharpe/vol/Sortino/rolling_\*) stays 252. Supersedes ANNUAL-02 for the return metric only; risk-comparability preserved. See TWR-05. (2) **uPnL basis = realized-basis intra-window NAV + `unrealized_pnl_in_anchor` DQ flag when material**; per-day true-up only if Phase 77 confirms historical marks on read-only keys.
- Research: `.planning/research/SUMMARY.md` (+ STACK/FEATURES/ARCHITECTURE/PITFALLS), HIGH confidence.
- **Carries v1.7 Phase 72 acceptance** (ONB-01) — no LTP factsheet ships until this lands; v1.7 closes when the P72 canary re-runs green.

## v1 Requirements

### NAV/TWR Core (TWR)

- [x] **TWR-01**: New pure `services/nav_twr.py` — backward daily-NAV reconstruction `NAV_{t-1} = NAV_t − pnl_t − F_t` from the real exchange anchor (today's equity), placing dated flows on their UTC days. I/O-free, stdlib/pandas/numpy only, revert-proof tests (modeled on `deribit_txn.py` discipline), numpy-pinned parity oracle.
- [x] **TWR-02**: True chain-linked daily TWR `r_t = (NAV_t − NAV_{t-1} − F_t)/NAV_{t-1}` (end-of-day flow convention — flow in the numerator, NOT the denominator); cumulative `Π(1+r)−1`. Edge cases covered: same-day multi-flow, day-0 flow, zero-NAV interior days, partial window. (Annualization basis is TWR-05.)
- [x] **TWR-03**: The silent `estimated_start ≤ 0 → account_balance` fallback (`transforms.py:154` & `:199`) is **deleted unconditionally on both branches** — replaced by fail-loud DQ guards. A partial fix that leaves one branch is the same bug (regression-tested on both). *(74-02: both fallbacks + the `prev_equity.replace(0)` swap deleted on both branches; divergence + fallback-deletion + source-scan pins mutation-honest.)*
- [x] **TWR-04**: Both callers (`broker_dailies.py:130`, `analytics_runner.py:1309`) routed through the core with the new `external_flows` + `open_unrealized_usd` params; **zero-flow input reproduces today's output byte-for-byte** (the shared-path regression pin) before any adapter touches production data. (NOTE: TWR-04's byte-identity pin is scoped to the NAV/flow path; the TWR-05 annualization change is an intended, separately-parity-gated delta — the two must not be conflated.) *(74-02: both branches delegate to reconstruct_nav_and_twr; all 4 74-01 byte-identity pins GREEN rtol 1e-12; params threaded, defaults None/0.0.)*
- [x] **TWR-05**: Split the annualization basis in `metrics.py` (founder decision 2026-07-05) — **RETURN/CAGR (and Calmar = CAGR/|maxDD|) annualize on the calendar clock (365 / true elapsed-calendar-days)**; **Sharpe / volatility / Sortino / rolling_\* stay 252**. quantstats `cagr` uses `years = len(returns)/periods`, so crypto's per-calendar-day series mis-annualizes at 252 — fix by passing the calendar basis to `cagr`/`calmar` (or, more robustly, computing `years` from the real date span so it is frequency-proof for CSV/MT5 too). Supersedes ANNUAL-02 for the return metric only; risk-metric 252 comparability preserved. Mutation-verified: a 365-day fixture's CAGR must differ from the 252 computation by the expected factor, and Sharpe must be unchanged.

VCR fixtures on LTP068's known flow days.
- [ ] **FLOW-03**: Binance/Bybit/OKX dated flows via a promoted-shared `_fetch_transfers`, each with its **own-transfer EXCLUSION** filter: Binance `transferType==0` external-only; Bybit on-chain deposit/withdraw only (inter/internal-transfer excluded); OKX deposit/withdrawal-history (auto-excludes own-transfers). One fixture per venue asserting a real deposit + an internal own-transfer → only the deposit becomes `F_t`. Binance SPOT-vs-USDⓈ-M wallet-scope verified against the live account roster.
- [x] **FLOW-04**: uPnL basis reconciliation — `exchange.py` companion open-uPnL read; the core holds a realized-basis terminal NAV for the backward roll and re-adds uPnL only to the reported *current* NAV; `unrealized_pnl_in_anchor` DQ flag raised when the wedge is material (per Key Decision). Per-day true-up pursued only if historical marks prove retrievable on read-only keys. ### Fail-Loud Data Quality (DQ)

- [x] **DQ-01**: Every NAV denominator guarded — dust-floor ($1000), negative reconstructed NAV, and flow-dominated capital (`Σ|F|` dwarfs base) each **break the chain-link for that day and flag `complete_with_warnings`**, never emit a fabricated number or synthetic base. Any `clamp`/`floor`/`max(…, dust)`/`replace(0,…)` on a NAV denominator is forbidden (it is the same corruption class as the bug). Reuses the existing `data_quality_flags` / `ReturnsComputationMeta` machinery.
- [x] **DQ-02**: Missing-flow reconciliation gate — `NAV_today − reconstructed_start − Σpnl ≈ Σflows` within tolerance; a mismatch (e.g. a deposit outside OKX's 90-day retention) **fails loud and refuses pre-terminus reconstruction** rather than silently attributing the gap to performance. Transient fetch failure distinguished from genuine end-of-history (WR-04 truncation-vs-no-data precedent); series segmented at the terminus.

## Out of Scope

| Feature | Reason |
|---------|--------|
| 365-day basis for the RISK metrics (Sharpe/vol/Sortino) | Out of scope BY DECISION — TWR-05 moves only RETURN/CAGR to 365; the √252 risk-comparability convention (ANNUAL-02's real intent) stays. Return and risk are orthogonal clocks. |
| Money-weighted return / IRR | Anti-feature — answers the investor-dollar-experience question, not manager skill; would make flow-heavy accounts non-comparable (the opposite of the goal). |
| Modified Dietz as the primary method | A deliberate downgrade when a daily NAV exists; true chain-linked TWR is the GIPS standard here. |
| Any silent base substitution / heuristic-capital fallback | This IS the bug being removed. |
| New quant library (`empyrical`/`pyfolio`/`ffn`) | They bake in flow-free + 252/US-equity assumptions that conflict with this milestone; the pinned stack already covers the math. |
| Frontend / factsheet UI changes | Presentation is untouched; this is an analytics-service return-math correction. The factsheet renders the corrected series unchanged. |
