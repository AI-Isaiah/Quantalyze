- [x] **SFOX-02** ⏳ — The system reads an sFOX account's balances, trades, and transactions through `SfoxClient`, read-only enforced (no order/withdraw capability exercised; key-permission scope asserted at the ingestion boundary).
- [x] **SFOX-03** ⏳ — A user can connect an sFOX API key through all three key routes (`api/keys/validate-and-encrypt`, `api/strategies/create-with-key`, `api/strategies/composite/add-key`); the worker `validate_key`/`encrypt_key` path accepts `sfox` + `key_permissions`, and an invalid/insufficient key fails closed with honest copy (never a false-verified).
- [ ] **SFOX-04** ⏳ — The database accepts `'sfox'` as a valid exchange everywhere an exchange value is constrained, via a RED-guarded constraint-widening migration applied to the TEST project first (auto-applies to prod on merge). **Scope corrected by Phase-118/119 research (2026-07-18, evidence-based, was a pre-research "≥5" guess):** widen exactly the **4 key-save CHECKs** the deribit precedent `20260704200446` widened — `api_keys.exchange`, `compute_jobs.exchange` (nullable form), `strategies.source`, `strategy_verifications.source` — in lockstep with TS `SUPPORTED_EXCHANGES` + the pydantic Literals. **Deliberately SKIP** `funding_fees` + `position_snapshots` (derivative/funding-specific; sFOX is SPOT — deribit skipped them too) and the `verification_requests` VIEW (DROP CONSTRAINT on a VIEW errors — never touch). - [x] **SFOX-06** ⏳ ⚠️ — The reconstructed sFOX equity is validated against a live sFOX account ground-truth (anchor-consistency / parity check, the `deribit_ground_truth.py` pattern); a material divergence fails loud rather than displaying a wrong curve.

### FLIPRETRY — derived-allocator-equity FLIP retry (root-caused)

> Retries the v1.11-close FLIP that was rolled back after wedging the sequential prod worker on a slow live exchange crawl. The flip is data-driven (no flag): `src/lib/queries.ts` `extractTrustworthyDerivedCurve` → `equityCurveSource`.

- [x] **FLIPRETRY-01** ⏳ — Each derived-equity exchange crawl is bounded by a hard `asyncio.wait_for` per-crawl timeout, so a slow/hanging live crawl (deribit native ledger ~inception; bybit 19k rows) can never block the worker event loop.
- [ ] **FLIPRETRY-02** ⏳ — The key-mode derived-equity backfill runs batched / off-hours on its OWN worker (never the sequential prod worker's loop), and is re-scheduled via `cron.schedule('derive-allocator-key-dailies', '30 5 * * *')`.
- [ ] **FLIPRETRY-03** ⏳ ⚠️ — After backfill, the derived curve passes `E2_GROUND_TRUTH_*` anchor-consistency validation before it is ever shown; `extractTrustworthyDerivedCurve` flips the display source only when the curve is trustworthy (else legacy basis).
- [ ] **FLIPRETRY-04** ⏳ — Worker health/liveness is preserved throughout backfill (healthz never stale past the restart threshold); the enqueue is safe to re-run and has a documented rollback (delete jobs + empty `allocator_equity_derived` + unschedule cron).

### DERIBITFIX — deribit `correction` txn-log classification

- [ ] **DERIBITFIX-01** ⏳ ⚠️ — The deribit native-ledger ingest classifies the `correction` txn-log type correctly, on EVIDENCE of what deribit `correction` means (CASH_BEARING vs INFORMATIONAL) — not a guess — so a deribit account containing a `correction` entry ingests without raising `LedgerValuationError`.
- [ ] **DERIBITFIX-02** ⏳ — A regression fixture with a `correction`-bearing ledger proves ingest succeeds with correct equity; genuinely-unknown future txn types still fail loud (no silent absorption / corruption).

## v2 / Future Requirements

- sFOX trade EXECUTION or fund movement — out of scope (read-only integration only; see Out of Scope).
- Additional non-ccxt exchanges beyond sFOX — deferred until a second one is requested.
- `allocator_equity_snapshots` legacy store retirement (STITCH-02 / BACKBONE-03) — remains deferred from v1.11; unblocked only after the FLIP is live + the derived surface is proven.

## Out of Scope

- **Executing trades / moving money via sFOX** — the integration is read-only ground-truth ingestion; keys are validated as read-only and no order/withdraw path is built. Financial-action safety rule.
- **Railway static IP** — Railway Hobby has no static IP (Pro-only, $20/mo); rejected in favor of the $2/mo Fly.io dedicated-v4 proxy (founder decision 2026-07-17).
- **NordVPN / in-container tunnel egress** — rejected as fragile for server egress (founder decision); the Fly proxy is the sanctioned static-IP path.
- **US-region egress** — geo-matters (Bybit/Binance 403/451 from US); the Fly proxy must sit in a geo-allowed region (`ams`), matching today's Railway AS400940 Amsterdam egress.
