## Context-Aware Label (interaction contract)

The single header button at `AllocationsTabs.tsx:759-766` reads its label from the
already-derived `activeTab` (URL-derived via `parseTab`; no new state). Deterministic
per tab — never a silent no-op, never a dropdown-every-time (ADDALLOC-03).

| activeTab | Visible label | Action | aria-label (must be corrected) |
|-----------|---------------|--------|-------------------------------|
| `scenario` | **`+ Strategy`** | open `StrategyBrowseDrawer` | `Add strategy — open the strategy picker` |
| `holdings` | **`+ Allocation`** | open `ContributionWizardOverlay` | `Add allocation — connect an exchange or upload a CSV` |
| `overview` | **`+ Allocation`** | open `ContributionWizardOverlay` | `Add allocation — connect an exchange or upload a CSV` |

**Bug being fixed:** today the button is hard-wired `onClick={() => changeTab("scenario")}`
with `aria-label="Add allocation — open Scenario tab"` — a mislabel + a wrong action on
Holdings/Overview. The corrected aria-label MUST match the visible label + the real action
(no stale "open Scenario tab").

**Wiring seam (integration note for planner, not a visual decision):** the button lives in
`AllocationsTabs.tsx`, but both overlays currently mount inside `ScenarioComposer.tsx`
(local `browseOpen` state) which is lazy-mounted **scenario-tab-only**. On Holdings/Overview
`ScenarioComposer` is not rendered, so the `ContributionWizardOverlay` open-state must be
hosted where it is reachable on those tabs (lift the state to `AllocationsTabs`, or mount a
tab-agnostic overlay host). Visual/interaction contract is unchanged either way; flagged so
the planner sizes the rewire correctly.

assert the new href + copy.

## Focus / Keyboard / A11y Contract

Preserve the existing sibling-overlay a11y posture (do not regress; do not over-build a
full focus-trap the codebase deliberately omits — matches `ScenarioCommitDrawer` precedent).

| Contract | Requirement |
|----------|-------------|
| Open → focus in | On open, focus moves INTO the dialog (panel `tabIndex={-1}` `.focus()`), so a Tab lands on a real control, never background content (WCAG 2.4.3). Existing in `ContributionWizardOverlay`. |
| Escape | `Escape` closes the overlay (document-level `keydown`, cleaned up on unmount). Existing in both overlays. |
| Backdrop | Click on backdrop dismisses; clicks inside the panel `stopPropagation`. Existing. |
| Close → focus return | On close, focus returns to the triggering header button (the `+ Strategy`/`+ Allocation` control). The trigger is the button in `AllocationsTabs`; the host that owns open-state must restore focus to it so keyboard users are not dropped at `document.body`. |
| Dialog semantics | `role="dialog"` + `aria-modal="true"` + a matching `aria-label`. Existing on both. |
| Single modal | At most one `role="dialog"[aria-modal]` visible at a time (the Browse→"Add your own" handoff closes Browse before opening the wizard — existing wiring). |
| Button focus ring | Header button keeps `focus-visible:outline focus-visible:outline-2 focus-visible:outline-accent` (existing) — not clipped (UIFIX-02 is Phase 117; do not regress here). |
| Label ↔ action parity | `aria-label` must state the real per-tab action (see the label table). A screen-reader user must not hear "open Scenario tab" while the button connects an exchange. |

No new axe surface is introduced; the wizard's existing axe coverage
(`/strategies/new/wizard` both branches) carries over via `WizardClient` reuse.
