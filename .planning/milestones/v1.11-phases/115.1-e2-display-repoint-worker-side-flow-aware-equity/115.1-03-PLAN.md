    in log/exception messages (the T-115-05 rule, allocator_equity_derive.py:68-69).

    Algorithm (RESEARCH §Q5 "concrete wiring", steps verbatim):
    1. **Drop unanchored keys FIRST**: partition `anchors_by_key` — keys with anchor None or
       missing are excluded from ALL downstream inputs (returns/flows/weights). Record each
       via the core's honest-degradation reason semantics (mirror REASON_NO_ANCHOR /
       DROPPED_KEY naming — read the core's constants and reuse them, do not invent strings).
       This ordering is load-bearing: segmenting over the returns key-set and then curving
       over the anchored subset trips the MEDIUM-6 stray-key raise.
    2. `seg = segment_coverage(anchored_returns_by_key)` — computed EXACTLY ONCE. Do not
       call it again anywhere; `seg.seams` is the single shared seam list.
    3. `per_key_equity = {k: replay_key_equity(returns_by_key[k], flows_by_key.get(k, []), anchors_by_key[k])}`
       for anchored keys (match the core's actual signature — read it, don't guess).
    4. **Per-Segment blend** (carry-ins #1+#4): weights = static current-equity shares
       `w_k = anchor_k / sum(anchors over anchored keys)`. For each `Segment s` in
       `seg.segments`: slice `{k: returns_by_key[k].loc[list(s.days)] for k in s.keys}`,
       restrict weights to `s.keys` (the core renormalizes internally — reproducing the TS
       ABSENT-window renorm, the HIGH-1 divergence fix), call `blend_concurrent_returns` per
       segment. ASSERT `exclusive_fill_days == 0` per segment output (structurally
       guaranteed for dense per-key series) — if nonzero, raise: the wiring regressed (the
       EXCLUSIVE_FILL canary). Concatenate segment outputs in day order; seam gap-days stay
       ABSENT (no invented data); union `degrade_reasons` across segments.
    5. `ledger = build_allocator_ledger(anchored_flows_by_key, seg.seams, per_key_equity, anchored_returns_by_key)`
       — the returns arg is mandatory for `computable=True`.
    6. `curve = allocator_equity_curve(per_key_equity, seams=seg.seams)` — the SAME
       `seg.seams` object as step 5 (carry-in #2).
    7. `scalars = mwr_and_dietz_from_ledger(ledger, ...)` (read the signature).
    8. `is_trustworthy = _is_trustworthy(union of: per-segment blend degrade_reasons +
       per-key KeyEquity degrade_reasons + AllocatorEquity/curve degrade_reasons +
       dropped-key reasons)` — F4 is satisfied structurally because step 4 makes
       EXCLUSIVE_FILL exclusive-only; no blend reason is filtered out.
    9. Assemble the payload dict per the interfaces contract. `curve` entries come from the
       core's curve output keyed by ISO day string (`str(d)` — never reformat); WR-02: do
       NOT compute or store any headline cumulative return derived from the curve (the
       curve deliberately excludes day-0; allocator_equity_derive.py:592-604).

    Edge cases (all honest, none fabricated): zero anchored keys → payload with empty curve,
    `is_trustworthy=False`, reasons listing the drops (the frontend fallback handles it);
    single anchored key → sole-key passthrough (weight 1.0) is the correct sequential-leg
    semantic. NO code fences in this module beyond normal Python; no pandas
    `to_datetime`/`DatetimeIndex` anywhere.
