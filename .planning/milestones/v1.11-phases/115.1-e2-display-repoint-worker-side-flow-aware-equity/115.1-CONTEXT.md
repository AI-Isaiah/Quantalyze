## Implementation Decisions (founder-locked / P115-inherited)

### BACKBONE-03 else-branch (founder-ratified)
Census did NOT clear → ship the display-repoint, leave the legacy store in place. NEVER write or
upsert `allocator_equity_snapshots` (two-writers race with the legacy first-writer-wins jobs) —
the derived curve lands on a SEPARATE new keyed surface.

### Consume the P115 core, do not re-derive
The worker derivation calls the frozen P115 core functions. The core is I/O-free by design; 115.1
supplies the real inputs (per-key `csv_daily_returns`, current-holdings anchors, real external
flows) and persists the output.

### Worker-side real-flow crawl (worker-only)
Real deposits/withdrawals require worker-only key decryption + an exchange flow crawl
(`ccxt_flows` / deribit native ledger) — the read-endpoint is flow-BLIND and cannot source it
(this is exactly why the P115 read-endpoint was DROPPED at plan-check). The crawl feeds the ONE
dated `ExternalFlow` ledger the core already consumes.

### The FOUR P115 carry-ins (MUST be honored — proven by red teams)
1. **HIGH-1 segment-wise blend wiring.** Feed `blend_concurrent_returns` one `Segment` at a time
   (via `segment_coverage`) so a key's exclusive lead/tail day is NOT 0-filled at full weight.
   This is the structural fix deferred from P115; the interim `exclusive_fill_days` flag over-counts.
2. **Shared seam list.** Pass the SAME seam list to BOTH `build_allocator_ledger` and
   `allocator_equity_curve` (the `seams=` param exists for this) so curve and ledger cannot disagree
   on rotation ownership (the MEDIUM-6 double-count guard is only load-bearing if they share).
3. **ISO-string day-index boundary.** The core keys days via `str(d)` and now asserts a
   `YYYY-MM-DD` index at its boundary — the worker MUST supply string-day indices, never a raw
   `DatetimeIndex` (would silently misalign flow vs return days).
4. **F4 — make `EXCLUSIVE_FILL` exclusive-only BEFORE gating display.** `exclusive_fill_days`/
   `EXCLUSIVE_FILL` currently fires on benign INTERIOR partial-missing days → would read
   `is_trustworthy=False` for every normal non-coextensive multi-key allocator (never-green gate).
   115.1 MUST compute it exclusive-only (via the #1 segmentation wiring) before any display gates on it.

### The FOUR carry-in wiring points confirmed by research (planner must honor)
- Carry-in #1/#4 (segment-wise blend / exclusive-only EXCLUSIVE_FILL): per-key series are DENSE
  calendar-daily (`broker_dailies.py:124-137`) → coverage segments == window segments → per-Segment
  feeding makes `exclusive_fill_days==0` STRUCTURALLY within a segment; EXCLUSIVE_FILL becomes a
  regression canary, not a never-green gate. TRAP: drop unanchored keys BEFORE `segment_coverage`
  (else the shared-seam MEDIUM-6 stray-key guard raises).
- Carry-in #2 (shared seam list): pass the SAME seams to both `build_allocator_ledger` and
  `allocator_equity_curve`.
- Carry-in #3 (ISO-string day index): worker supplies `YYYY-MM-DD` string indices, never DatetimeIndex.
