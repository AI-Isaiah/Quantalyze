# Phase 115.1 Plan 03: compose_allocator_equity — pure composition over the frozen P115 core Summary

Implemented `services/allocator_equity_compose.py`, the I/O-free composition layer that
turns real per-key inputs (returns, flows, anchors) into the phase-wide display-row
payload by orchestrating the FROZEN P115 derivation core with all four carry-ins wired
exactly as ratified — flipping the Wave-1 RED pins to GREEN without touching the core.

## What was built

`compose_allocator_equity(returns_by_key, flows_by_key, anchors_by_key) -> dict` returning
`{curve, flags, degrade_reasons, is_trustworthy, scalars: {mwr, dietz, computable}, inputs: {n_keys, anchor_asof, composed_at}}`.

The module consumes ONLY `services.allocator_equity_derive` (the single derivation source):
`segment_coverage`, `replay_key_equity`, `blend_concurrent_returns`, `build_allocator_ledger`,
`allocator_equity_curve`, `mwr_and_dietz_from_ledger`, `_is_trustworthy`.

## The four carry-ins — proven wiring

1. **Segment-wise blend + exclusive-only EXCLUSIVE_FILL (#1/#4):** the blend is fed ONE
   `Segment` at a time (`for s in seg.segments: blend_concurrent_returns({k: returns[k].loc[list(s.days)] for k in s.keys}, weights|s.keys)`).
   Because per-key series are dense calendar-daily, every covering key has a row for every
   day inside a coverage segment, so `exclusive_fill_days == 0` STRUCTURALLY. Compose
   **raises** (`NavReconstructionError`, USD-free) if it is ever nonzero — the regression
   canary, not a never-green gate. Green pin:
   `test_carryin_1_4_segmentwise_blend_no_exclusive_fill_on_offset_windows`
   (A d0..d9 / B d3..d9 reads `is_trustworthy=True`, no `exclusive_fill` token).
2. **Shared seam list (#2):** `seg = segment_coverage(...)` is computed EXACTLY ONCE and the
   SAME `seg.seams` object is passed to BOTH `build_allocator_ledger(..., seg.seams, ...)`
   AND `allocator_equity_curve(..., seams=seg.seams)`. `returns_by_key` is threaded into the
   ledger so `scalars.computable == True`. Green pin:
   `test_carryin_2_shared_seam_list_curve_ledger_agree` (seam gap-days absent from the
   curve; `computable` True).
3. **ISO-string index boundary (#3):** every series index stays a bare `YYYY-MM-DD` string;
   `segment_coverage` asserts this at its boundary and compose lets the
   `NavReconstructionError` propagate. No `to_datetime` / `DatetimeIndex` in code (only two
   documentation references). Green pin:
   `test_carryin_3_datetimeindex_rejected_iso_string_accepted`.
4. **TRAP — drop unanchored keys BEFORE segmentation:** `anchored_keys` is partitioned FIRST,
   so `segment_coverage` and the shared seam list never reference a key the anchored curve
   drops → the core's MEDIUM-6 stray-key guard can never raise. The dropped key surfaces via
   `DROPPED_KEY` in `degrade_reasons`. Green pin:
   `test_unanchored_key_dropped_before_segmentation_no_raise`.

## Mutation-falsifiability (Task 2 counter-pin)

Added `test_naive_rawunion_blend_reddens_exclusive_fill_offset_windows`: feeds the SAME
offset-window fixture RAW (whole union) into `blend_concurrent_returns` and asserts
`exclusive_fill_days == 3`, `DegradeReason.EXCLUSIVE_FILL` present, `is_trustworthy is False`.
This documents that the segment-wise compose path — not the raw union — is what earns
`is_trustworthy=True`, without monkeypatching compose internals. The naive wiring
measurably fails.

## Deviations from Plan

None — plan executed as written. The plan's "concatenate segment outputs in day order" step
was honored by iterating `seg.segments` (already in day order) and unioning each segment's
degrade reasons; the concatenated blended RETURN series itself has no payload field (the
displayed `curve` is the $-equity from `allocator_equity_curve`, and WR-02 forbids a headline
return off it), so no unused series is materialized (CLAUDE.md Rule 2 — simplicity).
