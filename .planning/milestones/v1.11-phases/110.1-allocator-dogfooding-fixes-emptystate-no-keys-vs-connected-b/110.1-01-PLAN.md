<objective>
Fix the two frontend data-honesty findings from live founder dogfooding
(2026-07-16): (1) the /allocations EmptyState conflates "no keys connected"
with "keys connected but zero holdings" and tells a fully-connected allocator
to connect a key; (2) the Exchanges tab subtitle asserts "Active Allocation
auto-synced" while `allocator_holdings` is empty, implying an allocation the
holdings can't back.

Purpose: honest copy per the project's no-invented-data / state-limitations
principles (DESIGN.md §Voice). No engine, no new data path, no seeded holdings.
Output: both surfaces branch on a real data signal; regression tests that fail
without each fix.
</objective>
