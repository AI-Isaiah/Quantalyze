# Phase 110.1 Plan 01: Allocator dogfooding fixes — EmptyState honesty + holdings-gated Exchanges subtitle Summary

**Two data-honesty fixes: the /allocations EmptyState now distinguishes no-keys from connected-but-empty (Manage-exchanges link, not a Connect CTA), and the Exchanges tab only asserts "Active Allocation auto-synced" when allocator_holdings actually back it — both gated on real server-derived booleans, both regression-tested.**

## Accomplishments
- **DOGFOOD-1:** `EmptyState` gains a required `hasConnectedKeys` prop and a third branch. A fully-connected allocator with zero open positions now sees honest copy ("Your exchange is connected — no open positions have synced yet…") and a **"Manage exchanges →"** link, instead of being told to "Connect a read-only exchange API key." The no-keys and syncing branches are byte-identical (locked copy preserved). Signal derived from `activeVenues.length > 0` in `AllocationDashboardV2` — no new query, no payload change.
- **DOGFOOD-2:** The Exchanges-tab subtitle is now three-way. `AllocatorExchangeManager` takes a required `hasHoldings` prop; the affirmative "N connected · Active Allocation auto-synced" renders only when holdings exist, else "N connected · first sync in progress" (any key syncing) or "N connected · no open positions yet". The real per-key `account_balance_usdt` still renders. `hasHoldings` is a server-side `allocator_holdings` head-count in `profile/page.tsx`, threaded through `ProfileTabs → ExchangesTabContent → AllocatorExchangeManager` (required-prop, so tsc guarantees the wiring).
- Regression tests for both findings that fail without the fix (verified RED before implementing).

## Decisions Made
- **hasConnectedKeys via `activeVenues.length > 0`** (not a new payload field): `activeVenues` is built server-side from `activeKeys = apiKeys.filter(k => k.is_active)`, so the semantics match the CONTEXT-named signal without touching `MyAllocationDashboardPayload` or `src/lib/queries.ts` (CONTEXT §Claude's Discretion).
- **hasHoldings via server head-count** (`count:"exact", head:true`, scoped `eq("allocator_id", user.id)`): same authorization scope as the existing admin reads on the page; no row payload fetched; no seeded holdings (no-invented-data).
- **Copy:** declarative, sentence-case, em-dash — verified against DESIGN.md §Voice and the AI-Slop Ban (no icon-first empty state; minimalism gate one headline / one sub-line / one link holds for the new branch).
