<objective>
Fix DOGFOOD-3 (latent validate-and-encrypt mislabel) at its root: the Python
`_FAIL_CLOSED` default ({read:T, trade:T, withdraw:T, probe_error:T}) flows
into `validate_key_permissions`'s scope-assertion branches, so ANY transient
probe failure is labeled "Key has withdrawal permissions. Please use a
read-only key." (error_code=WITHDRAW_SCOPE) — and the legacy Next route's
backstop additionally asserts "trading or withdrawal permissions" on any
read_only:false 200. Neither claim is backed by scope evidence.

Purpose: honest error causes (fail-loud, no invented diagnosis) while keeping
the fail-closed REJECTION intact — a key we cannot verify is still refused.
Output: probe_error derives a distinct PROBE_FAILED error at the Python layer;
the TS backstop no longer asserts scopes it didn't observe; regression tests
at both layers.
</objective>
