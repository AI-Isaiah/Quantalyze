## Surface-by-Surface Interaction Contract

### 1. Disconnect Modal (replaces "Remove key" modal)

**Trigger:** "Disconnect" button on each API key row in `AllocatorExchangeManager.tsx`. Replaces existing "Remove" `variant="secondary"` button.

**Button label change:** "Remove" → "Disconnect" (variant stays `secondary` on the row).

**Modal title:** "Disconnect {venue}?"
- `{venue}` = the human-readable exchange name capitalised (e.g. "Disconnect Binance?")
- Uses existing `Modal` component — `title` prop

**Modal body copy (locked — D-02):**

```
We'll stop syncing this key. Your historical holdings stay available
for audit and are reflected in past performance.
```

Font: DM Sans 14px, `text-text-secondary`.

**Holdings count loading state:**
- While fetching count: `<p className="mt-3 text-xs text-text-muted">Checking holdings…</p>`
- This matches the existing "Checking imported holdings…" pattern in the current code exactly.

**Cascade checkbox (D-02 — default UNCHECKED):**

Rendered only when `deleteHoldingsCount > 0`. Checkbox default = `false` (unchecked).

```
[ ] Also delete {N} historical holding{s} from this key
```

Sub-copy below checkbox (13px, `text-text-muted`):
```
Unchecked: holdings are kept for audit continuity and reflected in past performance.
Checked: holdings are permanently deleted and excluded from all historical metrics.
```

Contrast with existing code: current modal says holdings "can't be left orphaned" and makes the checkbox required to proceed. The Phase 08 spec REVERSES this: the RPC `delete_allocator_api_key(p_cascade_holdings=false)` already supports retaining holdings (D-02 explicit design decision). Checkbox is optional and unchecked by default. The Disconnect button is enabled regardless of checkbox state (not gated on checkbox when `deleteHoldingsCount > 0`).

**Zero holdings state:**
- `<p className="mt-3 text-xs text-text-muted">No historical holdings are tied to this key.</p>`
- Checkbox not rendered.

**Disconnect button (destructive):**
- `variant="danger"` (existing variant in `Button.tsx`)
- Label: "Disconnect" (loading state: "Disconnecting…")
- Disabled only while `deleteLoading` or while `deleteHoldingsCount === null` (count still loading)

**Cancel button:** `variant="secondary"`, label "Cancel"

**Error state:**
```tsx
<p role="alert" className="mt-3 text-xs text-negative bg-negative/5 border border-negative/20 rounded px-3 py-2">
  {deleteError}
</p>
```
Matches existing error pattern in the current modal verbatim.

**Post-disconnect:** key row removed from list optimistically; `router.refresh()` syncs server state. No toast. No aria-live announcement beyond the modal close.

**Keyboard:** `<dialog>` element (existing `Modal` component) handles focus trap and Escape-to-close natively.

### 3. Note Indicator on Holdings Rows

**Column placement:** Trailing column (rightmost), after all metric columns. Rationale: the holdings table is read left-to-right with identity columns (venue, symbol) first, then metrics, then actions. The note icon is an action/annotation affordance — it belongs with actions on the right, consistent with the existing "Sync now" / "Remove" button column pattern in `AllocatorExchangeManager`.

**Icon glyph:** Inline SVG. Use a square-with-lines "note" glyph (not a chat bubble — institutional register). Three horizontal lines inside a rounded rectangle, 16×16px SVG.

**Three icon states:**

| State | Visual | When |
|-------|--------|------|
| Empty | Outlined icon, `text-text-muted` #718096 | No note exists for this holding scope |
| Has note | Solid (filled) icon, `text-accent` #1B6B5A | Note exists and holding is from active key |
| Revoked + has note | Solid icon, `color-warning` #D97706 | Note exists but holding is from revoked key |
| Revoked + empty | Outlined icon, `color-warning` #D97706 | No note, holding from revoked key |

The amber tint on revoked-key note icons signals that context — a note on a revoked holding. The amber is `--color-warning`, consistent with the chip treatment.

**Button wrapper:**
```tsx
<button
  type="button"
  aria-label={hasNote ? `Edit note for ${symbol} ${holdingType}` : `Add note for ${symbol} ${holdingType}`}
  aria-expanded={isExpanded}
  aria-controls={`note-row-${rowId}`}
  className="flex items-center justify-center h-8 w-8 rounded hover:bg-border/50 transition-colors"
  onClick={() => toggleExpand(rowId)}
>
  {/* icon SVG here */}
</button>
```

- 32×32px hit area (8px padding around 16px icon)
- Hover: `bg-border/50` (subtle grey wash) — matches row hover pattern
- Transition: 150ms ease-out (DESIGN.md motion micro)
- No tooltip (aria-label is sufficient; avoid tooltip jitter on dense table rows)

**Keyboard:** Space/Enter toggles expand. Focus ring: `focus-visible:ring-2 focus-visible:ring-accent/40`.

### 4. Four Note Surfaces — State Machine

All four note surfaces share the same state machine and save-status component. Differences are in how the edit surface is mounted.

#### State Machine

```
idle ─── [click Edit / click icon] ──► editing
editing ─── [blur textarea] ──────────► saving ──► saved (2s flash) ──► idle
                                                └──► error
error ─── [user edits textarea] ──────► editing
saved ─── [user edits textarea] ──────► editing
```

#### Unified States Per Note Surface

| State | UI |
|-------|----|
| **loading** | Skeleton placeholder — 1 line, 60% width, `animate-pulse` (DM Sans 14px height proxy) |
| **empty (read)** | Placeholder text: "{Surface-specific}" — see Copy Contract below. Clicking anywhere in the area or pressing Enter on the note icon enters editing state |
| **read (has content)** | `NoteRender.tsx` rendered markdown. "Edit" button: `variant="ghost"`, label "Edit", 12px, top-right of the note area |
| **editing** | Plain `<textarea>` with Geist Mono 13px, `resize-none`, `w-full`, border `--color-border`, focus border `--color-border-focus`. Save fires on `onBlur`. `NoteSaveStatus` visible below textarea |
| **saving** | Textarea remains editable (not disabled). `NoteSaveStatus` shows "Saving…" |
| **saved** | `NoteSaveStatus` shows "Note saved" flash (2s) then "Last saved: {N}s ago". Textarea replaced by `NoteRender.tsx` read view |
| **error** | Textarea stays editable. `NoteSaveStatus` shows "Save failed — retry". Error is inline, no toast |

#### `NoteSaveStatus` Component Spec

Mirrors `MandateSaveStatus.tsx` exactly (same layout, same aria, same tick). Copy differences:

| `saveState` | MandateSaveStatus | NoteSaveStatus |
|-------------|-------------------|----------------|
| `saving` | (via "Mandate saved" flash logic) | "Saving…" |
| `saved` | "Mandate saved" (2s flash) → "Last saved: N min ago" | "Note saved" (2s flash) → "Last saved: N s/min ago" |
| `error` | inline field error | "Save failed — retry" |
| `idle` (no timestamp) | "Not saved yet" | (empty — note hasn't been edited this session) |
| `idle` (has timestamp) | "Last saved: N min ago" | "Last saved: N min ago" |

```tsx
// NoteSaveStatus — positioning and className mirror MandateSaveStatus exactly:
<div
  role="status"
  aria-live="polite"
  data-testid="note-save-status"
  className="text-xs text-text-muted font-metric tabular-nums tracking-tight"
>
  {/* saved flash: uses mandate-saved-flash CSS animation from globals.css */}
  {/* same checkmark SVG and accent/10 circle as MandateSaveStatus */}
</div>
```

The `mandate-saved-flash` CSS animation in `globals.css` is reused verbatim — no new keyframe needed.

### 5. Markdown Render Contract (NoteRender.tsx)

**Component:** `src/components/notes/NoteRender.tsx` — single shared helper for all four note surfaces.

**Dependencies (D-11 — React 19 / Next.js 16 compatible latest stable):**
- `react-markdown` — latest stable (researcher discretion per CONTEXT.md — use latest stable as of 2026-04-21)
- `rehype-sanitize` — latest stable
- `remark-gfm` — latest stable

**Sanitization config (D-13):**

```ts
import { defaultSchema } from 'hast-util-sanitize';

const noteSchema = {
  ...defaultSchema,
  // Allow GFM extensions (tables already in defaultSchema via remark-gfm passthrough;
  // del/strike added explicitly)
  tagNames: [
    ...(defaultSchema.tagNames ?? []),
    'del',   // GFM strikethrough
    'table', 'thead', 'tbody', 'tr', 'th', 'td', // GFM tables
  ],
  // Explicit denials (belt-and-suspenders — defaultSchema already blocks these)
  // No <img>, <iframe>, <script>, <style>, no event handlers
};
```

**Link rewrite:** All `<a>` tags get `rel="noopener noreferrer"` + `target="_blank"` via the `components` prop override on `<ReactMarkdown>`:

```tsx
components={{
  a: ({ href, children }) => (
    <a href={href} rel="noopener noreferrer" target="_blank" className="text-accent underline hover:text-accent-hover">
      {children}
    </a>
  ),
}}
```

- Only links with `href` matching `/^https?:\/\//` are rendered as links; others are rendered as plain text (enforced by the sanitize schema's `protocols` config: `{ href: ['http', 'https'] }`)

**Rendered element styles (applied via `className` on the component wrapper):**

```tsx
<div className="prose-note text-sm text-text-primary leading-relaxed">
  <ReactMarkdown ...>
    {content}
  </ReactMarkdown>
</div>
```

### 6. `useNoteAutoSave` Hook Contract

**File:** `src/components/notes/useNoteAutoSave.ts`
**Clone source:** `src/components/mandate/useMandateAutoSave.ts`

**Differences from `useMandateAutoSave`:**
- Endpoint: `PATCH /api/notes` with body `{ scope_kind, scope_ref, content }`
- No per-field fieldName concept — single content field per hook instance
- No `savingFields` set — notes are single-field saves
- No 429 / exponential backoff (notes are low-frequency; a simple retry-once on 5xx is sufficient — no need for the mandate's 4-attempt exponential chain. On 5xx: retry once after 2s. On 400/401: surface error, no retry.)
- `save(content: string)` fires on textarea `onBlur` (not per-keystroke)
- Return shape: `{ saveState: SaveState; lastSavedAt: Date | null; save: (content: string) => Promise<void> }`

**Save trigger:** `onBlur` on the `<textarea>`. No debounce. No save on every keystroke.

**Flush on unmount:** Fire-and-forget save if `content !== lastSavedContent` on unmount (mirrors existing NotesWidget unmount flush pattern in the current code).

### 7. Save Status Copy (aria-live)

All save-state strings, verbatim:

| State | aria-live text |
|-------|---------------|
| `idle` (no prior save this session) | `""` (empty — no noise when note hasn't been touched) |
| `idle` (has lastSavedAt) | `"Last saved: {relative}"` — e.g. "Last saved: just now" / "Last saved: 2 min ago" |
| `saving` | `"Saving…"` |
| `saved` (2s flash) | `"Note saved"` (with checkmark icon, using `.mandate-saved-flash` animation) |
| `error` | `"Save failed — retry"` |

**"Note saved" flash:** Reuses `.mandate-saved-flash` CSS animation + the same checkmark SVG + `bg-accent/10 text-accent` circle wrapper from `MandateSaveStatus`. Text changes from "Mandate saved" to "Note saved" — no other change.

**Relative time:** Uses the existing `formatRelativeTime` helper from `src/components/mandate/formatRelativeTime.ts`. The same 15s self-tick pattern from `MandateSaveStatus` is preserved in `NoteSaveStatus`.

### 8. LAYOUT_VERSION

**Decision:** Bump `LAYOUT_VERSION` from 2 → 3.

**Rationale:** Phase 08 adds a new `notes-1` widget entry with default position `x:0, y:27, w:4, h:4` to `DEFAULT_LAYOUT`. Any change to the `DEFAULT_LAYOUT` array warrants a version bump per the established convention. The holdings table in Phase 08 is not a react-grid-layout widget (it's a page-level section), so only the NotesWidget entry drives the bump.

**Impact:** localStorage-persisted custom layouts are reset for all users on next page load. Server-side impact is zero. No user-facing banner (per Phase 05 Voice-D8 tech debt decision — localStorage-only reset, no notification).

**Widget registry entry to add:**

`widgetId: "notes"` maps to the existing `NotesWidget` in `widget-registry.ts` (verify the exact widget slug during planning — it may already be `"notes"` or similar from Sprint 3).
