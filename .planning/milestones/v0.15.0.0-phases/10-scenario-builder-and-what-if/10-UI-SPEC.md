# Phase 10 — UI Design Contract

> Visual and interaction contract for the Scenario Builder body that ships under the `allocations.ui_v2` feature flag (Phase 09.1 D-17). Generated by gsd-ui-researcher, verified by gsd-ui-checker. All tokens trace to `DESIGN.md` (locked) and `src/app/globals.css` `@theme inline` block. NO new design system, NO new component library, NO new dependencies.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom Tailwind v4 `@theme inline` tokens; project explicitly does NOT use shadcn — see `src/app/globals.css`) |
| Preset | not applicable |

## Spacing Scale

Declared values (multiples of 4 — DESIGN.md §Spacing scale verbatim):

| Token | Value | Usage |
|-------|-------|-------|
| 0.5 | 2px | Hairline border insets, mono digit kerning corrections |
| 1 | 4px | Icon gaps, badge inner padding, delta-pill arrow gap |
| 2 | 8px | Inline form-field gaps, KPI cell internal vertical rhythm |
| 3 | 12px | Composition-row inner padding (left/right), secondary button padding-y |
| 4 | 16px | **Default element spacing.** Card padding (sm), KpiStrip cell gap, drawer body padding-x |
| 6 | 24px | Card padding (md), section gaps inside composer body, drawer header padding |
| 8 | 32px | Major section breaks (Composition list ↔ Bridge add card ↔ Browse strategies row) |
| 12 | 48px | Empty-state vertical padding, drawer-header → first-row gap |
| 16 | 64px | Reserved for full-page empty states; not used in Scenario tab body |

**Container widths (DESIGN.md §Layout):**
- Scenario tab body content max-width: **1100px** (inherits main content area; centered).
- Sticky `ScenarioFooter` width: **100% within tab content area** (does NOT escape to viewport).
- `StrategyBrowseDrawer` width: **620px**, `max-width: 96vw` (matches `BridgeDrawer` from Phase 09.1 D-16).
- `ScenarioCommitDrawer` width: **720px**, `max-width: 96vw` (slightly wider — accommodates inline `RejectedForm` + `AllocatedForm`).

**Border radii (DESIGN.md):**
- 4px (sm) — delta pills, mandate-fit chips, status badges
- 6px (md) — buttons (primary / secondary / ghost), search input, weight number-input
- 8px (lg) — cards (composition rows, browse-drawer rows, commit-drawer diff rows), drawer panels

**Row heights:**
- Composition-row: ≥ **44px** touch-target (DESIGN.md §Spacing). Toggle switch + symbol cell + weight input + delta pill all align on the 44px baseline.
- Browse-drawer row: ≥ **56px** (room for 2-line strategy meta: alias on line 1, markets/types/mandate-fit on line 2).
- Sticky footer height: **56px** (per CONTEXT D-12).

**Exceptions:** none. The 44px row-target is the only deviation from the strict 4-multiple ladder, and it is the existing project-wide table-row height (DESIGN.md §Spacing).

## Interaction Contracts

### Composition-row toggle (D-02)

- Toggle switch: 32×18px track, 14px knob. OFF state: track `--color-track` `#F1F5F9`, knob `--color-surface` `#FFFFFF`, 1px `--color-border`. ON state: track `--color-accent` `#1B6B5A`, knob `--color-surface` `#FFFFFF`. Animation: 150ms ease-out (DESIGN.md Motion).
- Click toggle → row weight is removed; remaining ENABLED rows' weights renormalize so they sum to 1.0 (CONTEXT D-02). Visual: each affected row's weight input number animates to its new value over 150ms (number-tick transition; no slide).
- Toggled-off row: opacity 0.5, weight input shows `0.0%` and is disabled (cursor-not-allowed), symbol cell strikethrough, delta pill hidden.
- aria: toggle has `role="switch"`, `aria-checked`, accessible label `"Toggle {symbol} on/off in scenario"`.

### Bridge "Add to scenario" (D-03 / D-05)

- Source 1 — `BridgeDrawer` confirm stage: clicking "Add to scenario" closes drawer and adds the suggested strategy at the FLAGGED HOLDING's current weight. The flagged holding REMAINS enabled (allocator must explicitly toggle it off to swap).
- Source 2 — `BridgeWidget` candidate card row CTA: same semantics, in-place toast-style confirmation "Added {strategy_alias} at {weight}%" (3s auto-dismiss, surface above sticky footer).
- Result: composition list's "Strategies added" group gains the new row; sticky-footer diff count increments; KpiStrip and equity overlay recompute via `computeScenario()` adapter.

### Browse-add (D-06)

- Open via "Browse strategies" CTA row OR EmptyState's secondary CTA.
- Search input: debounced 200ms; alias-substring search (Claude's discretion default). Empty input shows full verified-strategy list.
- Filter pills: clicking a pill toggles its active state; active pills carry accent border + accent foreground; inactive pills carry `--color-border` border + `--color-text-secondary` foreground.
- Row "Add" button: replaces with `--color-text-muted` "Added ✓" disabled-state for 2s, then drawer row dims (opacity 0.6) to indicate already-added; row stays visible (no jump). Multi-add session continues until close.
- Browse-add weight allocation: per CONTEXT D-03 — new strategy takes `1 / (active_set_size + 1)` and existing active rows renormalize.

### Weight input (CONTEXT D-17 stretch)

- Step 0.1%, min 0.0%, max 100.0%, Geist Mono right-aligned, suffix `%`. Focus ring accent. Disabled when row is toggled off.
- On blur OR Enter: commit weight; remaining active rows renormalize so total = 100.0%; KpiStrip + equity overlay recompute.
- aria-live="polite" announces "Weight updated to N.N%" on commit.
- If planner picks defer-to-Phase-11 for direct weight changes (D-17 option c), the weight input is render-only (read-only display of computed weight) and no `voluntary_modify` group ships in Phase 10. **UI-SPEC default: ship as `voluntary_modify` synthetic kind** (D-17 option a) so the composition list naturally exposes weight inputs.

### Sticky footer (D-12)

- Position: pinned to the bottom of the tab content area (NOT viewport — switching tabs hides it).
- Diff count chip: rounded 4px, 12px label, count + " changes". Tint: green/red/muted based on whether the net direction improves all primary KPIs (improves all = green; regresses any primary = red; below-noise = muted). Default state when 0 diffs: hidden / footer compresses to "No changes yet".
- "Reset" button: ghost style, foreground `--color-text-secondary`; on hover: foreground `--color-negative`, border `--color-negative`. Click → opens **destructive confirmation modal** (modal copy in §Copywriting).
- "Commit scenario" button: primary style, accent bg, white text, `cursor-not-allowed` + 50% opacity when diff count = 0. Click → opens `ScenarioCommitDrawer`.

### localStorage resume + invalidation (D-08 stretch / Claude's discretion)

- Storage key: `allocations.scenario_v0_15`. Shape: `{ schema_version: 1, init_holdings_fingerprint, toggleByScopeRef, addedStrategies, weightOverrides, lastEditedAt }`.
- On Scenario tab mount: if stored fingerprint mismatches current `holdingsSummary` fingerprint → render warning banner inline at the top of the composer body (warning token, dismissible) with two buttons: "Reset and start from current holdings" (destructive ghost) + "Keep my draft anyway" (secondary). Default focus on "Keep my draft" per CONTEXT default.
- SSR-safe: all reads guarded by `typeof window === "undefined"` early-return, try/catch around getItem/setItem (Phase 08 `allocations.showRevokedHoldings` precedent).

### Commit flow (D-09 / D-15)

- Click "Commit scenario" → `ScenarioCommitDrawer` opens with grouped diff sections.
- Each per-row form pre-fills from scenario state: `RejectedForm.size_at_decision_usd` ← live holding's last AUM contribution; `AllocatedForm.size_at_decision_usd` ← scenario row weight × scenario AUM; both forms' effective_date default to today.
- "Submit all" disabled while any per-row form has `aria-invalid="true"`. On click: confirmation modal "Submit N decisions? This will record N outcomes and feed the daily delta cron."
- On success: drawer body collapses to a single green confirmation card "N decisions recorded. Scenario draft reset to new live state." Drawer auto-closes after 1.5s. Scenario localStorage cleared. Composition reinitializes from fresh live holdings.
- On per-row error: error rendered inline beneath the failing row's form, `role="alert"`, `aria-live="assertive"`. The remaining successful rows are NOT rolled back (researcher to confirm with planner whether the API route is one-shot transaction or N atomic txs — UI contract assumes per-row independent atomicity for graceful degradation).

### Reset (SCENARIO-09)

- Click "Reset" → destructive confirmation modal (centered, 480px wide, surface card, accent border-bottom under title).
- Modal copy fixed in §Copywriting.
- On confirm: localStorage cleared; toggleByScopeRef reset to all-on; addedStrategies reset to []; weightOverrides reset to live-holdings-derived values. Composer body re-renders with fresh state. Sticky-footer diff count → 0.

### Equity / Drawdown overlay toggle (D-14)

- Top-right of each chart: 3-state pill row "Live · Scenario · Both". Single-select (radiogroup). Default: "Both" on first scenario edit; "Live" if scenario has no diff (zero-diff state shows live-only).
- Active pill: accent foreground + 1px accent border + 8% accent bg tint. Inactive: muted foreground + transparent bg.
- aria: `role="radiogroup"` `aria-label="Equity series visibility"`. Each pill `role="radio"` `aria-checked`.

### `/compare` deep-link (Claude's discretion default = ship for flagged holdings)

- Composition row for a FLAGGED holding (where `flaggedHoldings[]` contains an entry for this scope_ref AND a top candidate exists) renders a small "Compare →" ghost button to the right of the row actions.
- Click → routes to `/compare?ids={holding_scope_ref},{top_candidate_uuid}` per Phase 09 D-15. Tab state preserved on browser back.

### Empty state (claude's discretion default)

- When `holdingsSummary.length === 0`: render `EmptyState` with composer-specific copy and the dual-CTA layout described in the Component Inventory.
- When `holdingsSummary.length > 0` but `flaggedHoldings.length === 0`: NO empty state — composer renders as normal. The "Bridge inline card" section is simply hidden.

## Accessibility Contract

- Every interactive element receives a visible focus ring: `outline: 2px solid var(--color-border-focus)`, `outline-offset: 2px`. NO `outline: none` without a paired focus-visible style.
- Composition row toggles: `role="switch"`, `aria-checked`, `aria-label="Toggle {symbol} on/off in scenario"`.
- KPI delta pills: paired with `aria-label="Sharpe delta: +0.31 (improved)"` — direction word is mandatory so screen readers don't rely on color.
- Drawer focus-trap (matches `BridgeDrawer` precedent): focus moves to drawer header on open; tab cycles inside drawer; Escape closes; focus restores to invoking button on close.
- Sticky footer is `role="region" aria-label="Scenario draft summary and actions"` so screen-reader users can land on it via landmark navigation.
- Color is NEVER the sole signal for delta direction — every pill has a sign prefix (`+`, `−`) or an arrow icon (`▲`, `▼`); the noise-floor neutral state uses no glyph and an explicit "no change" aria-label.
- Reduced-motion: all 150ms transitions on toggle / modal / drawer respect `@media (prefers-reduced-motion: reduce)` and snap to end-state (existing project convention, see `globals.css` `.animate-pulse`).
- All form fields inside `ScenarioCommitDrawer` inherit `RejectedForm` / `AllocatedForm` accessibility (Phase 01 contract — labelled, error-associated via `aria-describedby`, errors `role="alert"`).
