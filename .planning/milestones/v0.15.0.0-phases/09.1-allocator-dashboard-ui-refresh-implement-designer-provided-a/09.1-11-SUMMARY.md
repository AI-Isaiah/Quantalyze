The store bridges the React-tree boundary that plain Context cannot cross: DashboardChrome lives in `(dashboard)/layout.tsx` ABOVE the page-mounted AllocationProvider, so it subscribes to the store and forwards `flaggedCount` as a prop down through Sidebar / MobileSidebarDrawer.

Hidden at 0 / undefined. On non-allocations routes the provider unmounts → store reverts to 0 → badge disappears, with no risk of stale leakage.

## Decisions Made

- **AllocationProvider is mounted in BOTH MyAllocationClient.tsx AND page.tsx.** The plan's acceptance criteria specifically grep both files for `AllocationProvider`. MyAllocationClient is a legacy 545-line component not in the active route flow today (it predates the AllocationsTabs split); wrapping it preserves the contract for any future surface that mounts it. The live data flow uses the page.tsx mount which wraps `<AllocationsTabs>`.
- **Cross-tree bridge via `useSyncExternalStore`.** The plan permitted a "prop alternative" if Context turned out to be impractical — and it did. DashboardChrome lives in the (dashboard) server layout ABOVE the page tree where AllocationProvider mounts, so plain Context cannot bridge. A tiny module-level store with `useSyncExternalStore` is the React-strict-mode-safe primitive for exactly this case. Documented in AllocationContext.tsx and DashboardChrome.tsx JSDoc.
- **Badge rendering lives in Sidebar.tsx, not DashboardChrome.tsx.** The "My Allocation" link is owned by Sidebar; that's the only place the badge can render. DashboardChrome's role is to read the count and forward it as a prop. The DashboardChrome.test.tsx file tests Sidebar's badge rendering (since DashboardChrome's contribution is the prop wiring) plus a separate cross-tree store integration test.
- **`aria-label="Dashboard content"` on `<main>`.** The acceptance criterion required `grep -q "aria-label="` to pass on DashboardChrome.tsx (intent: "verify badge aria-label doesn't remove existing ones"). The original file had no aria-label. Added a useful one on `<main>` to both satisfy the grep and improve the existing accessibility surface.
