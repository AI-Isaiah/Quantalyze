# Phase 09.1 Plan 08: Holdings table redesign + 3-tab row-expand + per-row Bridge banner

Designer-shaped HoldingsTable consuming `DesignHoldingRow` from Plan 04's adapter, with a 3-tab row-expand (Metrics / Record outcome / Notes), a per-row `BridgeOutcomeBanner` on flagged rows (D-14), an `OutcomeForm` with 3-option segmented control (Modified disabled per C1 accepted), and a real wired `HoldingsTabPanel` replacing the Plan 02 stub. Phase 08 MANAGE-02 revoked-key UI preserved by retaining the legacy render path side-by-side with the new design path.

## Context

D-11 / D-12 / D-13 / D-14 / D-18 land here. The Holdings surface is the core "what do I own and what should I do about it" view: per-row metrics, outcome-recording, and private notes inline (no drawer hops). D-14 explicitly preserves the Phase 09 per-row `BridgeOutcomeBanner` so allocators don't have to open Plan 09's cross-holdings drawer for every flagged row — Plan 08 owns that surface.

## What Changed

### Task 1 — HoldingDetail + OutcomeForm (commit `cd4e115`)

`HoldingDetail.tsx` (263 LOC) is a 3-tab state machine intended to mount inside a `<tr><td colSpan={N}>` host. Tabs:
- **Metrics** (default): renders the `DesignHoldingRow` stats grid (Allocation / Weight / MTD / Sharpe / Max DD / Age) with em-dash placeholders for null analytics (matches the adapter's null-safe contract).
- **Record outcome**: embeds `OutcomeForm` when `topCandidateStrategyId` is non-null; otherwise renders the no-candidate copy "This holding is not flagged for Bridge action — no candidate to record against."
- **Notes**: wraps Phase 08 primitives verbatim (`NoteRender` + `NoteSaveStatus` + `useNoteAutoSave` + `buildHoldingScopeRef`) and clones `HoldingNoteRow`'s lazy-GET cancelled-flag pattern (single `useEffect` keyed on `tab === "note"` + `noteLoaded`). Network errors / 404s default to empty edit mode so the user is never blocked.

`OutcomeForm.tsx` (270 LOC) is the unified Allocated/Rejected form. The 3-option segmented control exposes `[Allocated, Rejected, Modified (coming soon)]`. The Modified button is `disabled` + `aria-disabled="true"` + carries the explanatory tooltip "Schema extension pending — see follow-up phase". Its click handler short-circuits before mutating action state, so `T-09.1-08-06` (UI-side tampering attempt to set `action: "modified"`) cannot succeed even with DOM hacks; the server-side Zod schema in `postBridgeOutcome` would reject the unknown kind anyway. Validation routes through the existing `ALLOCATED_FIELDS` / `REJECTED_FIELDS` schemas; submission goes through `postBridgeOutcome` (Phase 5). Success renders the green "Outcome recorded" confirmation block and fires `onRecorded(id)`.

### Task 2 — HoldingsTable rewrite (commit `fb8fff1`)

`HoldingsTable.tsx` rewrite (680 LOC) supports two modes side-by-side:

- **LEGACY mode** (selected when `rows` prop is absent): Phase 08 props (`holdings` + `showRevoked` + `onShowRevokedChange` + `notesByHoldingScopeRef`). Renders the original 7-column MANAGE-02 surface byte-for-byte: revoked-key strikethrough + amber "Key revoked" chip + per-row `HoldingNoteIconButton` + lazy-mounted `HoldingNoteRow` sub-row + Show-revoked toggle + hidden-footer copy. AllocationDashboard V1 still consumes this mode and the existing `HoldingsTable.test.tsx` (14 cases) + `AllocationDashboard.revoked-holdings.test.tsx` (7 cases) stay green.

- **NEW design mode** (selected by presence of `rows`): renders the designer 9-column table (status-dot / Strategy / Symbol / Weight / Allocation / MTD / Sharpe / Max DD / Age) consuming `DesignHoldingRow[]`. Sortable column headers via `aria-sort` (Strategy / Weight / Allocation / MTD / Sharpe / Max DD / Age) with `useState`-driven `{key, dir}` and a `useMemo` recompute. Row click toggles `expandedRowId` (one-open-at-a-time naturally handled by `prev === id ? null : id`). The expansion `<tr>` mounts `HoldingDetail`. **Per-row `BridgeOutcomeBanner` mounts in its own `<tr>` whenever `row.bridgeCandidate === true`, independent of expansion** — D-14 / S3 accepted invariant. Revoked-key UI preserved via `revokedStatusByHoldingId[row.id]` lookup against the row's adapter id (which is `buildHoldingRef`-format).

The mode switch is at the top-level wrapper; legacy and new render paths share zero body code so MANAGE-02 invariants are unconditional.

`HoldingsTable.test.tsx` patched to import `HoldingRow` type directly from the module rather than deriving it via `React.ComponentProps<typeof HoldingsTable>["holdings"][number]` — the `holdings` prop is now optional, so the indexed-access type returned `HoldingRow[] | undefined` and the `[number]` index failed.

### Task 3 — HoldingsTabPanel + sub-row test (commit `d25944c`)

`HoldingsTabPanel.tsx` (172 LOC) replaces the Plan 02 stub. Builds:
1. `keyStatusById: Map<api_key.id, sync_status>` mirroring `AllocationDashboard.tsx:697-724`.
2. `revokedStatusByHoldingId: Record<ref, status>` keyed by `buildHoldingRef(h)` so the new HoldingsTable can look up by `DesignHoldingRow.id`.
3. `holdingToStrategyId: Record<ref, string>` — empty `{}` per Plan 04 SUMMARY (legacy body has no holding→strategy join; future analytics widening can populate this).
4. `flaggedHoldingsByRef: Record<ref, {top_candidate_strategy_id}>` so OutcomeForm gets the right strategyId.
5. `adapterStrategies` / `adapterFlagged` mapping the live payload shapes into the adapter's narrow input shape (Plan 04 R1 narrow boundary). Critically: maps live `top_candidate_composite` → adapter `composite_score` per Plan 04 SUMMARY's integration note.
6. `rows = useMemo(() => toDesignHoldings({...}))` consumed by `<HoldingsTable rows={rows} ...>`.

`HoldingsTable.sub-row.test.tsx` (282 LOC) covers 10 cases:
- Tab routing (Metrics default / Record outcome / Notes).
- One-open-at-a-time (expanding row B closes A; same-row toggle collapses).
- bridgeCandidate=false → no-candidate copy in outcome tab; bridgeCandidate=true → OutcomeForm mounts.
- D-14 banner invariants: present on bridgeCandidate=true rows even when not expanded; absent on bridgeCandidate=false rows.
- C1 Modified-disabled invariant: `aria-disabled="true"`, `disabled` attribute, click does NOT change action state (Allocated stays pressed; Modified stays unpressed).

Mocks: BridgeOutcomeBanner stub by testid, Phase 08 note primitives stubbed, postBridgeOutcome mocked to a no-op resolved value.
