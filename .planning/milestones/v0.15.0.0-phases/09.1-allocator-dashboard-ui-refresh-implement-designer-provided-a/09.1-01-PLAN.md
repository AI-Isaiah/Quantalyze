| client → localStorage | Any allocator can set `allocations.ui_v2="true"` to opt into the V2 shell. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09.1-01-01 | Information Disclosure | `allocations.ui_v2` flag via `?ui=v2` URL override | mitigate | URL override is gated by `NEXT_PUBLIC_QA_MODE === "true"`; production env omits that flag so URL-based opt-in is unavailable to allocators during bake. localStorage-based opt-in remains for internal QA. V2 is functionally equivalent to legacy (same data, same RLS). |
| T-09.1-01-02 | Tampering | localStorage key `allocations.ui_v2` | accept | Any tampering is per-allocator and only changes their own view. No cross-tenant leakage (RLS already enforces ownership on `/api/*`). Invalid values fall through to `false` (conservative). |
| T-09.1-01-03 | DoS via storage | Corrupted localStorage JSON | mitigate | `loadUiV2Flag` uses try/catch; any exception returns `false`. No parse of JSON (value is a literal string). |
</threat_model>
