# Phase 09.1 Plan 01: Feature flag + V2 shell scaffold Summary

`allocations.ui_v2` feature flag, AllocationDashboardV2 empty shell, DOM markers on both bodies, and a `+ Allocation` header button — all gated so production stays on legacy.

## Context

This plan is the rollout substrate for Phase 09.1's dashboard rewrite. Plans 02..11 will land the new 4-col grid, KpiStrip rewrite, EquityChart, HoldingsTable with 3-tab row-expand, Bridge hero + drawer, and the rest of the designer's Overview composition — all behind the `allocations.ui_v2` flag. Production allocators stay on the existing AllocationDashboard until the bake window completes; QA / internal users opt in via localStorage or `?ui=v2` (when NEXT_PUBLIC_QA_MODE is on).

## What Changed

### Task 1 — feature flag + V2 shell + +Allocation button (commit `f654f05`)

Inside `src/app/(dashboard)/allocations/AllocationsTabs.tsx`:

- New module-scope constant `UI_V2_STORAGE_KEY = "allocations.ui_v2"` and `loadUiV2Flag()` function. SSR returns `false` (conservative default — show legacy). Client returns `true` only when localStorage canonically holds `"true"`. Anything else (missing key, garbage value, exception thrown by Safari private mode) returns `false`.
- Inside the component body: `useState<boolean>(() => loadUiV2Flag())` followed by `useEffect(() => setUiV2Flag(loadUiV2Flag()), [])`. The first render returns the SSR-safe default so server + client match exactly; the effect re-reads on mount and flips to V2 when the flag is set, on the second render. This is the React 19 hydration-safe pattern. Without it, an SSR pass would render `legacy` and a client pass would render `V2`, triggering React's hydration mismatch warning.
- `qaMode = process.env.NEXT_PUBLIC_QA_MODE === "true"` and `uiOverride = qaMode && searchParams.get("ui") === "v2"`. Combined with the localStorage flag via `uiV2 = uiV2Flag || uiOverride`. The override does NOT write to localStorage — it is a per-request opt-in only.
- Performance render branch rewritten to `activeTab === "performance" && (uiV2 ? <AllocationDashboardV2 {...props} /> : <AllocationDashboard {...props} />)`.
- New `+ Allocation` header button above the tablist, routes to `?tab=scenario` via `changeTab("scenario")`. Styled per DESIGN.md: `bg-accent` (#1B6B5A), white text, `rounded-md`, focus-visible outline at the accent color.

New file `src/app/(dashboard)/allocations/AllocationDashboardV2.tsx`:

- `"use client"` component exporting `AllocationDashboardV2(_props: MyAllocationDashboardPayload)`.
- Renders a single `<div data-ui-v2-shell="true">` placeholder card with placeholder copy "Allocator dashboard V2 shell — widgets landing in plans 02 through 11."
- Props mirror MyAllocationDashboardPayload so the shell is a drop-in substitute at the AllocationsTabs render site as plans 02..11 fill it in.

In `src/app/(dashboard)/allocations/AllocationDashboard.tsx`:

- Added `data-legacy-dashboard="true"` to BOTH outer `<section>` wrappers — the zero-holdings render path (line ~775) and the main render path (line ~792). This was a Rule 2 expansion of the plan's instruction (which said "outer wrapper element" singular) — the function has two return paths, both of which need the marker for the routing test to pass regardless of holdings state.

### Task 2 — feature-flag routing test + hydration-mismatch invariant (commit `0e9e18f`)

New file `src/app/(dashboard)/allocations/AllocationsTabs.feature-flag.test.tsx` with 7 cases, all DOM-level (`container.querySelector('[data-ui-v2-shell]')` / `[data-legacy-dashboard]`):

1. localStorage="true" → V2 shell renders, legacy absent.
2. localStorage="false" → legacy renders, V2 absent.
3. Missing key → legacy renders (default-false per D-17).
4. ?ui=v2 + NEXT_PUBLIC_QA_MODE="true" → V2 renders.
5. ?ui=v2 alone (no QA mode) → legacy renders (URL override is QA-gated).
6. localStorage.getItem throws (Safari private mode) → legacy renders.
7. Hydration-mismatch invariant: `vi.spyOn(console, "error")` and assert no call args contain "hydration" / "did not match" / "server rendered" across 3 render variants (flag-off, flag-on, QA-gated URL override).

Component bodies are mocked with stubs that emit only the marker attribute, so tests don't depend on the legacy dashboard's heavy widget tree. The marker contract is locked from the source side too: acceptance criteria re-grep `data-ui-v2-shell` in `AllocationDashboardV2.tsx` and `data-legacy-dashboard` in `AllocationDashboard.tsx` so the mocks can't drift away from reality.

Localstorage is mocked via `vi.stubGlobal("localStorage", ...)` (the Phase 08 idiom from `useDashboardConfig.test.ts`). NEXT_PUBLIC_QA_MODE is controlled per-test via `vi.stubEnv` / `vi.unstubAllEnvs` in afterEach.
