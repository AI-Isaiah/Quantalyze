## Decisions Made

- **Geist Mono over serif for KPI values (DESIGN.md compliance).** The plan literal in `09.1-06-PLAN.md:163` proposed `style={{ fontFamily: "var(--font-serif, Fraunces, Georgia, serif)" }}` for the value text. DESIGN.md is unambiguous: "Data/Tables: Geist Mono (tabular-nums) ... All numbers in the product use this." The designer's own reference (`app.jsx:417-422`) also uses `font-mono tnum`, fontSize 18, weight 500. Per CLAUDE.md ("Always read DESIGN.md before making any visual or UI decisions ... Do not deviate without explicit user approval"), I used `font-mono text-lg font-medium tabular-nums` instead. Documented the choice with an inline code comment so a future reviewer doesn't "fix" it back to serif.
- **Preserved `analytics: any` typing on the prop.** The legacy caller passes a heterogeneous payload (sometimes `null`, sometimes the strategy-analytics object, sometimes a portfolio analytics shape). Tightening the type to a union here would cascade into a non-trivial caller-side refactor that's out of this plan's scope. Kept the existing `// eslint-disable-next-line` marker.
- **Stale forces em-dash AND stale-sub-copy on every cell.** Stricter than the legacy "stale just suppresses warmup helper" behavior. Justification: the new 5-cell layout has no global "as of" chrome (the designer panel surfaces timeframe at the page header), so the per-cell stale signal is the only place a user can see staleness on the strip. The Phase 07 / 07-05 page-level WarningBanner still carries the global signal — this is additive, not duplicative.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug / DESIGN.md compliance] Used Geist Mono for KPI numeric values instead of the plan's literal `var(--font-serif, ...)` suggestion**
- **Found during:** Task 1 (KpiStrip rewrite)
- **Issue:** The plan literal specified `style={{ fontFamily: "var(--font-serif, Fraunces, Georgia, serif)" }}` for the value text, but DESIGN.md mandates Geist Mono (`font-mono tabular-nums`) for ALL numeric data ("Data/Tables: Geist Mono ... All numbers in the product use this"). Serif is reserved for display headings. The designer reference (`app.jsx:417-422`) also confirms `font-mono tnum` for the value, so following the plan literal would have produced output that mismatched both DESIGN.md and the designer's own intent.
- **Fix:** Used `font-mono text-lg font-medium tabular-nums` Tailwind classes (resolves to `var(--font-mono)` → `var(--font-geist-mono)`). Added an inline comment documenting the deliberate departure so a future reviewer doesn't revert it.
- **Files modified:** `src/app/(dashboard)/allocations/components/KpiStrip.tsx`
- **Verification:** Visual: `font-mono` Tailwind class resolves to Geist Mono per `globals.css:41`. Compile: typecheck clean. Behavioral: tests still pass (font is style-only, no semantic effect).
- **Committed in:** `f829a92` (Task 1 commit)

**2. [Rule 2 - Missing critical] Strengthened stale path to emit per-cell stale sub-copy on EVERY cell**
- **Found during:** Task 1 (KpiStrip rewrite)
- **Issue:** The legacy KpiStrip's stale handling was implicit: when `allKeysStale === true`, the warmup helper was suppressed and the `as-of` timestamp + timeframe right-edge chrome carried the global signal. The new 5-cell designer layout has no `as-of` chrome (timeframe is surfaced at the page header), so without an explicit per-cell stale sub-copy, a stale dashboard would render 5 unexplained em-dashes with no on-strip indication of why. That's a UX regression — the user should never see a value-less strip without an explanation.
- **Fix:** Added `STALE_SUB = "Last sync stale — awaiting next update"` and a `resolveSub` precedence chain that emits this on every cell (including AUM) when `allKeysStale === true`. Forces every numeric cell to em-dash regardless of underlying value. Stale precedence beats both the warmup helper AND the R4 Avg ρ pending copy.
- **Files modified:** `src/app/(dashboard)/allocations/components/KpiStrip.tsx`
- **Verification:** New test "Stale path: allKeysStale=true → every cell renders '—' AND every cell shows stale sub-copy" asserts `screen.getAllByText("—").length === 5` AND `screen.getAllByText("Last sync stale — awaiting next update").length === 5`. Phase 07 warmup invariants still pass (Test D specifically asserts stale suppresses warmup AND only required em-dash count > 0; the new behavior is a strict superset).
- **Committed in:** `f829a92` (Task 1 commit)
