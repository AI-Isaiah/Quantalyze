# Phase 09.1 Plan 05: 4-col grid body + write-time normalization Summary

Replaced the empty Plan-01 V2 shell with the full Overview-tab body — 4-col CSS grid with HTML5 DnD + D-01 pointer-resize, hover/focus-within chrome (D-04 keyboard-reorder + always-present overflow menu), 39-entry popover picker, and write-time normalization (D-19) so persisted `config.tiles[*].k` is always a `WIDGET_REGISTRY` id.

## Context

This plan is the visual spine of Phase 09.1's V2 dashboard. Prior plans landed the substrate: Plan 01 the feature flag + empty shell, Plan 02 the 6-tab AllocationsTabs migration, Plan 03 the `{k,w}` `TileConfig` shape + `useDashboardConfigV2` hook + `LAYOUT_VERSION 4`, Plan 04 the holdings adapter, and Plan 06 the 5-cell `KpiStrip` rewrite. Plan 05 fills `AllocationDashboardV2.tsx`'s body so the flag-on path renders a real, accessible, drag-and-drop grid that downstream plans can plug widgets into.

The D-19 write-time normalization piece eliminates an entire class of subtle bugs that would otherwise silently break the f2 widget-gating gate: designer short keys (`bridge`, `kpi`, `equity`, ...) are collapsed to `WIDGET_REGISTRY` ids (`bridge-outcome-banner`, `kpi-strip`, `equity-curve`, ...) before any tile is persisted. Render code, filters, and the picker can all reason about `t.k` as a registry id without short-key coalescing.

## What Changed

### Task 1 — WidgetGrid + WidgetChrome + SizeStepper (commit `1f1aaee`)

Three new components in `src/app/(dashboard)/allocations/components/`:

**`SizeStepper.tsx`** — 4 buttons (1/2/3/4) with `aria-label="Width N of 4"` + `aria-pressed` per the active width. Geist Mono numeric labels at 9.5px per DESIGN.md (matches designer source `widget-grid.jsx:192-217`). Active width gets the accent background.

**`WidgetChrome.tsx`** — absolute top-right chrome wrapper revealed by the parent `.widget-cell:hover` OR `.widget-cell:focus-within` rule (D-04 keyboard accessibility). Renders:
- `<SizeStepper>` for width
- Drag handle `<button aria-label="Reorder widget" aria-pressed={kbdMode}>` — Enter/Space toggles keyboard-reorder mode; ArrowUp/ArrowDown then call `onMove(k, "prev" | "next")` with the parent resolving the sentinel; Esc exits the mode.
- Close button `<button aria-label="Remove ${k} widget">` — fires `onRemove(k)`.
- Always-present overflow `⋯` button that opens a `role="menu"` popover with three `role="menuitem"` buttons: Move up / Move down / Remove. This is the screen-reader path — it does NOT depend on hover or keyboard-reorder mode and is reachable by Tab navigation. Outside-click dismisses (scoped to the menu ref).

**`WidgetGrid.tsx`** — the host component. CSS grid with `gridTemplateColumns: "repeat(4, minmax(0, 1fr))"` and `gap: 10`. Per-cell:
- `data-widget-id={k}` (Shared P2 — preserves IntersectionObserver + analytics).
- `draggable` + `onDragStart`/`onDragOver`/`onDrop` for HTML5 reorder. Self-drag is a no-op.
- `style.gridColumn = "span ${w}"` so width changes are pure CSS.
- Right-edge `.widget-resize-handle` (6px, `cursor: col-resize`) with a pointer-capture `onPointerDown` that listens to `window.pointermove` + `pointerup`, computes target span from `delta / (colWidth + gap)`, snaps to `[1..4]`, and calls `onResize(k, finalW)`. The in-progress target is stashed in `handleEl.dataset.pendingW` so React isn't re-rendered during the drag.
- Hover/focus-within reveal of the chrome via inline `<style>` scoped to `.widget-grid` (no styled-jsx; the repo doesn't configure it).
- Responsive breakpoints (`@media (max-width: 980px)` → 2 cols; `≤640px` → 1 col) match the designer.

## Threat Flags

No new network endpoints, auth paths, file access patterns, or schema changes introduced. The plan's threat-register entries (T-09.1-05-01..05) are all mitigated as designed:

- **T-09.1-05-01 (Tampering — drag-drop reorder state):** `moveWidget` operates on tile keys; invalid keys (not in the array) are filtered by the reducer's `findIndex < 0` guard. The `"prev"` / `"next"` sentinels are resolved in the parent (`onMoveWrapper`); out-of-range neighbors no-op. Tested by WidgetGrid.test.tsx Test 7 (self-drag no-op).
- **T-09.1-05-02 (Information Disclosure — widgets rendering data for another allocator):** All widgets receive `props = MyAllocationDashboardPayload`, which is RLS-scoped by the server query (`getMyAllocationDashboard`). `renderWidget` does not refetch.
- **T-09.1-05-03 (XSS — picker widget names):** `WIDGET_REGISTRY` is a static const; no user-provided strings enter the picker. React default-escapes.
- **T-09.1-05-04 (Focus-trap bypass — picker popover escape):** Esc + outside-click both dismiss the popover. The popover is non-modal by design (D-04); focus is intentionally NOT trapped.
- **T-09.1-05-05 (Integrity — short-key vs registry-id mix):** Mitigated by D-19 write-time normalization in `useDashboardConfigV2.addWidget` + `loadV2Config` + `defaultV2Config`. STRATEGY_COMPOSITE gate filters by direct id equality. Pinned by the new D-19 test in `useDashboardConfig.test.ts`.
