## Top 3 Priority Fixes

1. **Bridge surface tint tokens missing** — User-facing impact: none today (chrome is on-brand and stable), but every Bridge surface (BridgeWidget hero/card, BridgeDrawer mandate-gates card, HoldingsTable amber chip) still inlines five hex literals (`#FED7AA`, `#FFF7ED`, `#FFFAF3`, `#FFFBF4`, `#FEF3C7`, `#FDE68A`). When DESIGN.md eventually adds a `--color-bridge-surface` / `--color-bridge-border` family the swap is mechanical; until then these can drift if someone changes one site without the others. Concrete fix: extend `globals.css` + DESIGN.md with `--color-bridge-bg-50`, `--color-bridge-bg-100`, `--color-bridge-border-100`, `--color-bridge-border-200` and replace the 7 literal sites — `BridgeWidget.tsx:114-115, 202, 239-240` + `BridgeDrawer.tsx:221` + `HoldingsTable.tsx:55-56`. (Already noted as out-of-scope in `09.1-REVIEW-FIX.md` IN-01 — this audit confirms it as the single largest remaining design-system loose end.)

2. **Font-size ladder consolidation** — 13 distinct inline font sizes ship today, including sub-pixel values like `10.5`, `11.5`, `12.5`. Most are direct designer-bundle ports (the prototype uses these to optically tighten dense table rows). User-facing impact: none — the rendered text is still legible and the rhythm matches the prototype. Risk: the design system documents a ladder of 10/11/12/13/14/16/24/32/48, and the next person who reaches for a body label has 13 possible answers instead of 5. Concrete fix: snap `10.5 → 11`, `11.5 → 12`, `12.5 → 13` everywhere except the chart axis labels and Geist Mono numeric pills (where the half-pixel actually matters for `tabular-nums` alignment). Highest-frequency offenders: `HoldingsTable.tsx`, `BridgeDrawer.tsx`, `WidgetPicker.tsx`, `outcomes/OutcomesWidget.tsx`, `widget-grid` chrome.

3. **CustomRangePicker `paddingTop: 14` magic-number alignment hack** — `CustomRangePicker.tsx:289, 306, 356` uses literal `paddingTop: 14` to vertically align the `→` arrow + day-count counter with the Start/End date labels above. User-facing impact: none on default zoom, but the alignment breaks at smaller font sizes (zoom > 110%) because the inputs grow taller while `14` stays fixed. Concrete fix: replace the three `paddingTop: 14` overrides with `display: flex; align-items: flex-end; min-height: <input-height>` on the input row, so the arrow + counter inherit baseline from the inputs.
