# Phase 09.1: Allocator Dashboard UI refresh — Context

**Gathered:** 2026-04-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Land the designer-provided `Allocator Dashboard.html` vision on `/allocations` so Phase 10 (Scenario Builder) builds on top of the refreshed shell. This is a **re-architecture** of the dashboard surface — layout system, tab structure, KPI strip, holdings row-expand, and Bridge UX all change in a coordinated shift. It is NOT a style-only polish.

The phase must preserve Phase 06–09 data wiring: `holdingsSummary` projection, `flaggedHoldings`, `matchDecisionsByHoldingRef`, `equityDailyPoints`, `snapshotCount`/`allKeysStale`/`minHistoryDepthMonths`/`activeVenues`, Phase 08 note primitives + `buildHoldingScopeRef`, `AllocationsTabs` D-04 `searchParams` derivation, ADR-0023 audit taxonomy.

**In scope:** new 4-col snap-grid; 5-tab structure + Scenario stub slot; redesigned KpiStrip + EquityCurve + HoldingsTable + BridgeBanner + BridgeDrawer; 3-tab row-expand (Metrics / Record outcome / Notes); widget picker covering all 50+ registered widgets; feature-flag rollout.

**Out of scope (deferred):** intraday hourly chart (1D / 1W timeframes); mobile responsive polish; dark mode; Top movers / Activity feed widgets from `extra-widgets.jsx`; widening the server payload with per-holding Sharpe/DD/age (use a read-side adapter instead).

<decisions>
## Implementation Decisions

### Grid architecture

- **D-01:** Replace `react-grid-layout` (+ `react-resizable`) with the designer's custom 4-col CSS grid (`gridTemplateColumns: repeat(4, minmax(0, 1fr))`). Widget cells span 1–4 cols via a ¼/½/¾/full size stepper; reorder via HTML5 drag; resize via a right-edge pointer handle that snaps to the same 4 positions. Source reference: `designer-bundle/project/src/widget-grid.jsx:1-163`.
- **D-02:** Bump `LAYOUT_VERSION` 3→4 in `src/app/(dashboard)/allocations/lib/dashboard-defaults.ts`. On mismatch, `useDashboardConfig.loadConfig()` resets to the new default layout (same behavior as Phase 05 1→2 and Phase 08 2→3 bumps). **No migration code** — users with custom layouts lose them once (Voice-D8 accepted precedent; no banner). Existing `localStorage` key `quantalyze-dashboard-config` is reused.
- **D-03:** Widgets render at **auto-height** (content-driven). The `TileConfig` shape changes from `{i, widgetId, x, y, w, h}` (RGL grid units) to `{k, w}` where `k` is the widget id and `w ∈ [1..4]`; no `x`, `y`, or `h`. Row wrapping is implicit via CSS grid flow.
- **D-04:** Hover chrome (size stepper + drag handle + close button) floats absolute-positioned at top-right of each tile, `opacity: 0` by default, `opacity: 1` on `.widget-cell:hover`. **Accessibility contract:** add `:focus-within` to the CSS reveal rule so keyboard focus inside a tile also exposes chrome; ensure the drag handle has `role="button"` + `aria-label="Reorder widget"` and the resize handle is reachable via Tab. If a screen-reader-only path is needed, mirror the stepper as a menu item in an always-present `⋯` dropdown.

### Tabs + widget scope

- **D-05:** Tab set: **Overview, Holdings, Outcomes, Mandate, Risk, Scenario** (6 tabs). First 5 come from the design; Scenario is retained (existing `AllocationsTabs.tsx` + `ScenarioStub.tsx`). `AllocationsTabs` must migrate from 2 → 6 tabs while preserving the D-04 contract (`searchParams.get("tab")` derivation every render, `performance` alias deleted on mount, silent fallback for unknown values). Tab keys: `overview` (default, no query param), `holdings`, `outcomes`, `mandate`, `risk`, `scenario`.
- **D-06:** `Overview` tab = widget grid with 7-widget default (`bridge`, `kpi`, `equity`, `holdings`, `allocation`, `mandate`, `outcomes`; widths `4,4,4,3,1,2,4`). `Holdings` tab = full-width HoldingsTable. `Outcomes` tab = full-width OutcomesWidget. `Mandate` tab = MandateForm (existing from Phase 2 at `/profile?tab=mandate` — move the form here or iframe/link; Claude's discretion) + a live MandateSnapshot widget. `Risk` tab = a curated grid of existing risk widgets (`var-expected-shortfall`, `tail-risk`, `risk-decomposition`, `alpha-beta-decomposition`, `regime-detector`, `correlation-matrix`). Scenario tab keeps its current body for this phase (see D-07).
- **D-07:** Scenario tab: **keep `ScenarioStub.tsx` + `ScenarioFlaggedHoldingsList`** unchanged in behavior; only restyle to new design tokens so the tab doesn't look abandoned. Phase 10 replaces the body with the composer. This preserves Phase 09's flagged-holdings surface + Phase 10's contract.
- **D-08:** Preserve all 50+ `WIDGET_REGISTRY` entries. Widget picker (`designer-bundle/project/src/widget-grid.jsx:237-319`) is extended to list the full registry; drop the "soon" badges from `correlation` / `funding` / `flows` (they already exist as real widgets in `widgets/intelligence`, `widgets/meta`, `widgets/monitoring`). Picker shows the 7 Overview defaults as "on your dashboard"; everything else appears in the add list. Phase 07 `STRATEGY_COMPOSITE_WIDGETS` f2 gating stays: when `strategies.length === 0`, those 18 widgets are filtered out of `visibleConfig` but remain in the picker (still addable — they no-op gracefully on empty strategies because widget-gating filter hides them at render).
- **D-09:** Port the design's **KpiStrip shape** (5 cells: AUM / YTD TWR / Sharpe / Max DD 12m / Avg ρ — each with `sub` line) but route the sub-copy through the existing warm-up paths: `snapshotCount`, `allKeysStale`, `minHistoryDepthMonths`, `activeVenues` must still drive the Phase 07 D-10 stale / warm-up / venue-specific branches (dashes → `—` when stale; 3-month venue copy when MIN depth ≤ 3). The `KpiStrip.warmup.test.tsx` invariants must still pass after the rewrite.
- **D-10:** Port the design's **SVG EquityChart** (`designer-bundle/project/src/charts.jsx:5-245`) with period toggle (1M / 3M / 6M / YTD / 1Y / ALL / CUSTOM), custom range picker (`range-picker.jsx`), holding overlays via Holdings-table checkbox, and crosshair hover. Chart data source is `equityDailyPoints` (Phase 07 VOICES-ACCEPTED f7 parallel-prop path); benchmark comes from existing BTC baseline wiring. Intraday (hourly `EQUITY_HOURLY`) series is **out of scope** — defer 1D/1W toggles.

### Row-expand + Bridge UX

When no active breach, render the design's "no active breaches" stub with a "Show last recommendation" restore button. Variants `subtle` and `card` stay in the codebase (tweakable via admin QA mode — see D-19).
- **D-16:** Bridge drawer (`designer-bundle/project/src/bridge.jsx:94-301`) is a right slide-over (`width: 620, maxWidth: 96vw`) with 2 stages: `browse` (ranked candidates + mandate-breach grid) → `confirm` (apples-to-apples gate fix + potential allocation size + note to manager). Backdrop dismisses. `confirm` stage's "Send intro" routes through the existing intro flow (`/api/bridge/*` or equivalent). Do NOT introduce a parallel bridge API.

Rows without a strategy match show `—` for strategy-derived columns; venue/symbol always present. **No server-side payload widening.** Adapter is unit-tested in isolation.
- **D-19:** Strip the Tweaks panel's `postMessage` prototype bridge (designer-side only). Keep the panel + floating trigger but gate visibility on `NEXT_PUBLIC_QA_MODE === "true"` (new env flag, also usable for the ui_v2 override). Defaults shipped as production constants: `density: "comfortable"`, `accentIntensity: "muted"`, `displayFont: "serif"`, `bridgeVariant: "full"`, `chartStyle: "area"`, `showBench: true`, `showOutcomes: true`.
