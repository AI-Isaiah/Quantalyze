<objective>
Make the seam's diagnostics safe in BOTH directions, at every site, by one mechanism.

Purpose: `SEAMCORE-06`. TRAP-1 is binding and it is two-sided:
  - **Under-redacting leaks live credentials.** undici embeds outgoing headers in the error message
    and, in one shape, in the error NAME. On this seam that is `INTERNAL_API_TOKEN`,
    `X-User-Access-Token` (a live user Supabase JWT), `X-Service-Key`, and — on the key-connect path
    — raw exchange `api_key` / `api_secret` / `passphrase`.
  - **Over-redacting destroys the diagnosis.** A short secret substring-matched against prose
    destroys the `ECONNREFUSED` / `ENOTFOUND` token, which is the most valuable thing in the line.
    Today the core drops `err` ENTIRELY on the network-failure arm, so TLS expiry, DNS `EAI_AGAIN`,
    connection refused and a header `TypeError` are indistinguishable (A-10).

Two corrections to the phase's own inputs, both stated so nobody re-derives them:
  1. **The Sentry clause is ADDITIVE, not a leak to plug.** A grep for `captureException` /
     `captureMessage` across the core, both clients and every seam route file returns ZERO. The seam
     captures nothing to Sentry today. Say so rather than implying an existing capture leaks.
  2. **The existing scrubber is not the answer.** `finalize-wizard`'s route-local
     `scrubInternalToken` knows exactly one env secret, is unreachable from the core or the clients,
     and has no minimum-length refusal — so a short token would substring-match prose and mangle the
     syscall token, which is TRAP-1's explicit over-redaction warning.

Output: one dependency-free redaction leaf, applied at every enumerated site, plus the structured
transition event the breaker has never emitted.
</objective>
