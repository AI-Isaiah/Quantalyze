# ⚠️⚠️ THE HEADLINE FINDING — M19 no longer reddens

**This is the single most valuable thing this plan produced, and it is reported loudly rather than
quietly re-recorded as the old verdict.**

Ledger row **M19** — `nx: true → nx: false` on the breaker's lock write — was OBSERVED RED by plan
140.2-01 in wave 1:

```
× R-3 nx trip idempotency — a later trip does NOT ratchet the first writer's expiry
  → expected 30 to be less than or equal to 27
```

**At the final tree, the identical mutation leaves the entire real-Redis lane green: `Tests 7 passed (7)`.**

### The mechanism, diagnosed at source rather than guessed

Plan 140.2-07 restructured `recordSeamFailure`'s trip path and inserted a guard **ahead of** the lock
write (`resilient-fetch.ts:1107`):

```ts
const existing = decodeBreakerLock(await redis.get<string>(breakerKey));
if (existing) {
  if (existing.expiresAtMs > now) return;               // ← wave 7. NOW carries trip idempotency.
  if (admittedAtMs <= existing.armedAtMs) return;       // ← A-25
}
…
written = await redis.set(breakerKey, value, { ex: ttlS, nx: true });   // ← M19's target
```

R-3 drives two **sequential** trips. The second now returns at that guard and **never reaches the
`set` at all**, so the `nx` flag is unobservable by it.

### What this is, and what it is not

- **It is NOT a behaviour regression.** The property R-3 pins — the first writer's expiry stands — is
  still enforced, and more strongly than before (byte-identical value equality rather than a TTL band).
- **It IS a falsifiability regression.** The row's mutation stopped being able to fail. A ledger row
  that cannot redden is an asserted row, and an asserted row is exactly what this phase exists to end.

### Disposition — replacement, not deletion

`140.2-VALIDATION.md` §4 already anticipated this: *"If a later plan restructures the code so a row's
mutation is no longer reachable (**for example M18/M19 after the breaker value gains an encoded
expiry** …) the row is not skipped. Name the replacement mutation targeting the same property, run
THAT, and record both."*

So: **M19 stays in the ledger, recorded GREEN with its mechanism**, and **M19R** was added — deleting
the guard that now carries the property. **OBSERVED RED, a clean single-row receipt:**

```
× R-3 trip idempotency — a later trip does NOT ratchet the first writer's expiry
AssertionError: A second trip rewrote a still-live lock. The first writer's expiry must stand, or a
second instance tripping moments later ratchets the outage window open indefinitely.
  Expected: "open:1785126390121:1785126420121"
  Received: "open:1785126394138:1785126424138"
Tests  1 failed | 6 passed (7)
```

### The residual, named rather than closed

**`nx: true` is now defensive-ONLY** — it guards the concurrent race where two Fluid Compute instances
both read `null` and both write. **No test in this repo falsifies it.** Reaching it sequentially
requires a key that EXISTS in Redis but decodes to `null` (the rolling-deploy value-format skew wave 7
documented), where `nx: true` refuses the trip write and `nx: false` overwrites the corrupt value —
a real behavioural difference.

**Deliberately NOT closed here.** Writing that assertion would pin *"the trip write is refused against
a corrupt lock"* as correct, and nobody has decided whether it is: it means the breaker cannot arm
until the corrupt key's TTL expires. Freezing an undecided behaviour in the phase's final wave is the
wrong call. **Handed to Phase 141**, which owns the breaker's timing behaviour next, with the
mechanism written out in `140.2-VALIDATION.md` §8 so it does not have to be rediscovered.

## 1.1 Protocol — and it was enforced mechanically, not by discipline

Every row: apply ONE mutation to **production source** → run the row's command → record the failing
test names and assertion text verbatim → restore **from a `/tmp` copy** → verify. **Never**
`git checkout`, `git stash` or `git clean`; the destructive-git prohibition was honoured absolutely.

The runner **aborts before applying** if the tree is not pristine, so a row can never be measured
against another row's leftovers:

```
PRE-flight  : grep -rn MUTANT src/ tools/ tests/  == 0   AND  sha256 manifest (13 files) verifies
APPLY       : exactly-one-match assertion; a pattern matching 0 or 2+ times is a FATAL abort
RUN         : scoped vitest, full output captured to a per-row log
RESTORE     : cp from /tmp/140212/pristine/
POST-verify : MUTANT scan == 0  AND  sha256 manifest verifies  AND  git status clean
```

**All 62 runs passed all three post-axes.** Not one row was batched.
