<objective>
Build the real-Redis lane FIRST, before any semantic change to the seam core, so that every
behaviour change later in this phase is provable against the Lua that actually runs in production.

Purpose: `SEAMCORE-09` / ROADMAP SC4. The in-repo fake (`src/test/helpers/upstash-breaker.ts`) is a
FIXED window anchored at first call, with no previous bucket and no carry-over, and it **increments
on denial** where the deployed Lua does not. Four of the seven properties this phase depends on are
unobservable through it. A better fake is still a fake that cannot execute the deployed script.

Output: a spike verdict, a `vitest.redis.config.ts` lane, `tests/redis/seam-breaker.redis.test.ts`,
a `frontend-seam-redis` CI job wired into the `frontend` aggregator, local ergonomics, and **six
observed mutation receipts**. This plan is the SOLE owner of M18, M19, M20 and the real-Redis halves
of M14, M15 and M16; none of them is observable anywhere else in the phase.

⚠️ **This plan opens with a spike whose outcome gates the rest of it.** SRH serving `EVALSHA` to
`@upstash/ratelimit@2.0.8` is UNVERIFIED — Upstash's own `ratelimit-js` CI uses real cloud
databases, not SRH, so there is no upstream proof. A failed spike is a **valid, budget-saving
outcome**: it is recorded as the plan's primary finding and triggers a re-plan, not a scramble.

📍 **Deliberate divergence from PATTERNS, recorded so nobody "corrects" it back.** `140.2-PATTERNS.md`
gives this lane's test-file home as `tests/integration/**`, noting it is "already in the vitest
include list". This plan uses `tests/redis/**` instead, and the reason is exactly the property
PATTERNS offers as a convenience: being inside the main include list would make the lane run as part
of the sharded suite, where the two containers do not exist and where roughly twenty suite files
DELETE `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` from the environment in order to
exercise the core's unconfigured path. A directory outside the main glob is what keeps the sharded
run byte-unaffected and lets this lane own its own environment and its own CI job.
</objective>

  `<prefix>:<identifier>:<windowIndex>` where prefix is "breaker", identifier is
  `${BREAKER_KEY}:failures`, and windowIndex is `Math.floor(Date.now() / 30000)`.

⚠️ **This is the PRE-PHASE shape and it is deliberately what this lane pins.** Plans 140.2-06 and

in the lock's VALUE. Both plans own the corresponding re-expression of this lane's assertions, and
each declares this file in its `files_modified`. This plan pins the shape as it stands at wave 1 —
that is correct, and the later re-expressions are their plans' obligation, not a defect in this one.
