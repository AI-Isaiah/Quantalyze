<decisions>
## Implementation Decisions (LOCKED)

### The headline problem: the phase's own verification is not trustworthy
**10 simultaneous semantic mutations to the seam core produced `8859 passed | 287 skipped` — byte
identical to the number Phase 140 certified as "5/5 success criteria mutation-tested."** Threshold
5→30, cooldown 30→5, window 30s→3600s, the Redis TTL →3600, the public teaser's budget 60s→5s: all
GREEN. **0 of 13 budgets are pinned to a literal.**

Root cause is a **two-layer self-referential oracle**: the test fake harvests its threshold from
production's own `slidingWindow(BREAKER_FAILURE_THRESHOLD, …)` call, and every test loop bound is
`mod.BREAKER_FAILURE_THRESHOLD`. Assertions read their expected value out of the table under test.

⇒ **`SEAMCORE-07` is the phase's spine, not a chore.** Pin constants and budgets to LITERALS in an
oracle the implementation does not export. Any plan that leaves a tuning value unfalsifiable has not
delivered this phase.

### Locked technical decisions
- **A live-Redis integration test is required (`SEAMCORE-09`).** The fake is FIXED-window; the
  deployed limiter is epoch-aligned SLIDING with weighted carry-over and no-increment-on-denial.
  A script-text guard over the fake pins only what the fake already models. Decide and document how
  it runs in CI — **a test that does not run in CI is not a gate** (this repo's standing rule:
  `*_live.py` and `skipIf(!HAS_LIVE_DB)` vitest never execute in CI).
- **Recording must be driven by ATTRIBUTABILITY, not `status >= 500` (`SEAMCORE-01`).** It must
  handle a `text/plain` body — that is the shape an unhandled FastAPI exception takes (TRAP-2).
- **The recording window must cover the BODY READ (`SEAMCORE-02`).** Today the classification `try`
  closes before every body read, so for the most common Railway degradation (headers fast, body slow)
  `recordSeamFailure()` is NEVER called. The core's own docblock is false about this.
- **Fail-OPEN stays.** A broken breaker must never become the outage. This is a deliberate divergence
  from the rate limiter's fail-closed and must not be "harmonised".
- **Do not use `resetUsedTokens`** (TRAP-6) — it is a full-keyspace Lua SCAN on the DB shared with 15
  production limiters. Own the counter key.
- **Log direction must match the caller** (TRAP-7): a one-deadline-for-the-whole-write-chain orphans
  the async IIFE, Fluid Compute freezes the instance, and the breaker never arms — during exactly
  the correlated incident it exists for.
- **Scrubbing must preserve the syscall token** (TRAP-1). undici embeds outgoing headers — and in one
  shape the error NAME — in the message; on this seam that is `INTERNAL_API_TOKEN`,
  `X-User-Access-Token` (a live user JWT) and raw exchange credentials. But over-redacting destroys
  the `ECONNREFUSED`/`ENOTFOUND` token, which is the most valuable thing in the line. Cover EVERY log
  site (≥5) **and Sentry capture**, and handle per-request (non-env) secrets.

<specifics>
## Specific Ideas

- **A-21 is the highest-value single fix**: move the deadline/body-read inside the classification try.
- **A-22**: the URL template and `AbortSignal.timeout()` are INSIDE the try, so a malformed
  `ANALYTICS_SERVICE_URL` throws before a packet leaves, is logged as "network failure reaching the
  analytics service", and after 5 requests opens the global breaker permanently — from a config typo,
  with the log pointing ops at Railway.
- **A-23**: no `redirect` option is set. Verified on Node 25: after a 302 to a different origin,
  `Authorization` is stripped but `X-Service-Key`, `X-Internal-Token` and `X-User-Access-Token` are
  **forwarded verbatim**. `redirect: "error"` is a one-line closure.
- **A-12 is a self-sustaining outage**: routing the `/health` warmers into the core looks like an
  obvious cleanup and ESLint won't object — but a cold `/health` probe failing is NORMAL, so the
  warmer would trip the breaker, and the breaker would then block the recovery probe. Zero tests fail.

**Already strong — protect, do not re-derive:** failure classification at the `>=500` boundary (both
directions), trip-comparison direction/shape, fail-open direction, breaker-check-before-fetch
ordering, header forwarding, the **route retrofit layer** (delete-arm / swap-copy / drop-`Retry-After`
/ drop-`code` are ALL RED at four routes — the best-covered part of the phase), error identity and
`retryAfterS` propagation. Also: **no SSR exposure anywhere** — a breaker trip can never 500 a page.
</specifics>
