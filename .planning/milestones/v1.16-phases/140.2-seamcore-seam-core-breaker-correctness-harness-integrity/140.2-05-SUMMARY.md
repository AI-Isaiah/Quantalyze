## Decisions Made

1. **`SeamBodyReadError` must not escape `postProcessKey`** — implemented exactly as `<error_leaf_decision>` item 3 binds. Its `try` now covers the body read; the new class is mapped through the EXISTING `isAbort` discriminator so it reaches the EXISTING `UPSTREAM_TIMEOUT` 504 / `UPSTREAM_NETWORK_ERROR` 502 envelopes. Zero new codes, zero new `human_message` copy. `CircuitOpenError` stays FIRST in the catch order.
2. **`SeamConfigError` is homed in `resilient-fetch.ts`, not the leaf.** The leaf's export set is a privileged surface (browser-reachable, mock-surviving) and its pin exists to force a decision per member. Nothing catches this class by type and it is never rendered, so widening the leaf would buy nothing. This keeps the pin at exactly the two members the plan's artifacts specify.
3. **The base-URL guard checks the protocol, not just parseability.** `new URL("localhost:8002/x")` parses with protocol `localhost:`, so a parse-only guard would pass the single most likely typo (a missing scheme) straight through to a fetch rejection and back into the network arm — i.e. it would have closed A-22 for one shape and left the likelier one open.
4. **The override ceiling is 300_000 ms**, the Vercel function ceiling every seam route declares. A deadline past the lambda's own ceiling can never fire, so it is unbounded in practice and violates SC-4b by construction.
5. **`SeamResponse` is spelled as a subset of `Response`.** This was chosen for stub compatibility and it is why the predicted casualty wave did not materialise.
6. **`process-key-client`'s `NextResponse` construction stays outside the widened try**, so plan 140.2-11 can still observe the A-27 null-body-status crash it owns.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `json()` conflated PARSING with TRANSPORT, so a 503 with an empty body became "not reachable" plus a spurious breaker failure**
- **Found during:** Task 2, by the pre-existing `analytics-client.test.ts` case "uses res.statusText when JSON body has no detail field"
- **Issue:** `instrumentBody` wrapped every `res.json()` rejection as a `SeamBodyReadError` and recorded a breaker failure. But `Response.json()` does two things — read the bytes and parse them — and a `SyntaxError` means the bytes ARRIVED. An upstream answering 503 with an empty body or a `text/plain` traceback is Railway REPLYING. The fix as first written rebuilt the A-22 defect (caller/upstream fault counted as degradation) inside the fix itself, and broke the plan's own instruction that "a body that is genuinely absent or unparseable keeps the fallback".
- **Fix:** `if (err instanceof SyntaxError) throw err;` before classification — rethrown raw, records nothing, so every `.catch(() => fallback)` arm sees exactly what it saw before. `SyntaxError` is the only shape the parse half produces (undici reports an aborted read as a `DOMException` and a dropped connection as a `TypeError`).
- **Files modified:** `src/lib/resilient-fetch.ts`
- **Verification:** the existing case went green without being touched; a new dedicated case ("an UNPARSEABLE body is not a breaker failure — the parse error is rethrown raw") plus negative controls in both client test files pin it.
- **Committed in:** `85278c52`

**2. [Rule 1 - Bug] The transport arm's deadline test missed jsdom's `DOMException`**
- **Found during:** Task 1, Step 2
- **Issue:** `err instanceof Error && (name === "AbortError" || "TimeoutError")` is correct on Node (whose `DOMException` extends `Error`) and WRONG under jsdom (whose does not) — `analytics-client.ts` documents exactly this trap 400 lines away. Every timeout in the vitest environment was logged as "network failure reaching the analytics service". Only the log line differed, which is why no assertion could see it.
- **Fix:** one `isDeadlineError()` helper shared by the transport arm and the new body-read arm.
- **Files modified:** `src/lib/resilient-fetch.ts`
- **Committed in:** `8322bec4`

**3. [Rule 3 - Blocking] Two `let res: Response` declarations folded into Task 1's commit**

- **Issue:** changing the core's return type left `analytics-client.ts` and `process-key-client.ts` tsc-red. Deferring them to Task 2 would have left a committed, non-compiling tree on the branch.
- **Fix:** the two declarations changed to `SeamResponse` in the same commit; all behavioural client work stayed in Task 2.
- **Verification:** `npx tsc --noEmit` exits 0 at every commit from `8322bec4` onward.

**4. [Rule 2 - Missing Critical] Protocol validation added to the base-URL guard**

**5. [Rule 2 - Missing Critical] Double-body-read must not record a breaker failure**
