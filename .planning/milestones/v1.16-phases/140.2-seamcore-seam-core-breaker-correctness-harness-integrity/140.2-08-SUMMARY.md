## 2. THE OVER-REDACTION PROOF

TRAP-1 pulls in two directions and a one-sided test ships one of them green. Four independent proofs
that the leaf does not destroy the diagnosis:

**(a) Two-sided on ONE input.** `seam-redaction.test.ts` scrubs a realistic undici message carrying
`INTERNAL_API_TOKEN`, `X-Service-Key` and a live user JWT alongside
`connect ECONNREFUSED 10.0.0.1:8002`, then asserts on that SAME result:

```
not.toContain(INTERNAL_TOKEN)   not.toContain(SERVICE_KEY)   toContain("<redacted>")
toContain("connect ECONNREFUSED 10.0.0.1:8002")   toContain("syscall: 'connect'")   toContain("errno: -111")
```

**(b) The minimum-length refusal, with the refusal SIGNALLED.** `MIN_REDACTABLE_SECRET_LENGTH = 12`,
derived: the shortest preserve tokens (`ENOTFOUND`, `ETIMEDOUT`, `EAI_AGAIN`) are 9 characters. A
`CRON_SECRET` of `"CONN"` is refused, `ECONNREFUSED` survives intact, and the line gains
`[seam-redaction: refused to redact 1 value(s) shorter than 12 chars (CRON_SECRET) — this line may be
under-redacted…]`. The env var NAME is named; its VALUE never is.

**(c) All eight preserve tokens on one line.** A single line carrying every member plus a real
credential: the credential goes, all eight survive. A per-token sweep would let one destroyed member
hide behind seven survivors.

**(d) The mechanism, not just the test.** Redaction is exact-value `split`/`join` of known secrets —
never a regex built from a secret (escaping bugs, ReDoS on a value we do not control). A preserve
token can therefore only be destroyed when a secret VALUE contains one; that is verified AFTER
redaction, and the notice **names the colliding env var** so the operator can fix the secret.

**Proof it is not vacuous:** ledger row **M33** lowering the constant to 3 produces
`code: 'E<redacted>REFUSED'` and reddens (§4).

**Also proven: the scrub does not over-redact at the Sentry boundary.** The capture test asserts the
dispatched message still contains `ECONNREFUSED` after the token is gone.

### Task 3 — the transition event + the coverage guard — `a5f2957c` (RED) → `230d59bf` (GREEN) → `6d483e29`

**The transition event carries exactly four fields:**

```
{ breakerKey, failures, cooldownS, correlationId }
```

asserted as an **exact key set**, so a future field carrying a path or a header reddens rather than
ships. `JSON.stringify(payload)` is additionally asserted to contain no `INTERNAL_API_TOKEN`, no
`/api/`, no `authorization`, no `bearer`.

- `breakerKey` comes from the **verdict** — driven with a named dependency, the event reports
  `breaker:supabase`, not the residual global key. The field is meaningful only because 140.2-06 made
  keys per-dependency; an event that reported the global key for every trip would be decorative and
  indistinguishable from a correct one on the global path.
- `failures` is read from the limiter verdict (`limit - remaining`), not asserted back from the
  constant.
- `cooldownS` is derived from the **lock**, not the constant.
- `correlationId` is `<key>@<armedAtMs>` — derived from the lock, so the OPEN and the CLOSE of one
  lock share it. A request-scoped id could not: the request that trips a circuit is never the request
  that observes it heal.
- **OPEN** fires only when *this* call armed the lock; `nx` answering `null` means a sibling instance
  won and is emitting its own, so claiming a transition would double-count across a Fluid Compute fleet.
- **CLOSE** fires on the first observed tombstone read, deduped per lock per instance (bounded set,
  cleared at 64). **No half-open state machine and no probe scheduler were built** — TTL expiry IS the
  half-open transition (locked decision 3), so the first read that observes the tombstone is the only
  moment the close is observable at all.
- It is a **plain structured log with no I/O**, so TRAP-7 cannot apply. Stated in the docblock so a
  future network sink becomes an awaited call at both sites.

**`src/lib/seam-log-coverage.test.ts`** — a comment-stripped, **string-literal-masked**, quote-aware
balanced-paren scan over the six seam files, in two halves: bare **catch-bound** identifiers, and bare
**error-shaped bindings** (`error`, `*Err`, `*Error`) which is how the Supabase errors arrive. String
masking tracks `${…}` interpolation depth — a message containing the word *error* is prose, but
`${err}` inside a template is a real reference, and both directions are pinned by their own cases.
The allowlist is by reason: `scrubSeamError` / `scrubSeamString` wrapping, plus `.retryAfterS`,
`.deadlineExceeded` and `.code` — non-string facts from types we define. It carries its **own
positive control, negative control and a fail-loud lower bound** on sites scanned, because a guard
that asserts an ABSENCE reads as protection while proving nothing if its matcher silently breaks.

**Registration.** `src/lib/seam-redaction.test.ts` and `src/lib/seam-log-coverage.test.ts` are both in
`CONTRACT_GUARDS` **and** `REGISTRY.md`. Waves 2, 3 and 4 each found a guard that was silently
deletable; there is no fourth.
