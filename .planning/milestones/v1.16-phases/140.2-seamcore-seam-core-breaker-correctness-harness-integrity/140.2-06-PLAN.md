<objective>
Replace `status >= 500` with an attributability decision, and replace the one global breaker key
with per-dependency keys.

Purpose: `SEAMCORE-01` / ROADMAP SC2, obligation `TS-06`, and the OB-8 acceptance criterion
inherited from 140.1.2.

Today the core records a failure for every `>= 500` and nothing else. That is wrong in both
directions: a `500` is SERVICE-PERMANENT and must NEVER count (retrying it is useless and a handful
of input-triggered 500s from an anonymous caller on the public teaser would deny key-connect
platform-wide), while a body-slow degradation and a `503` on a named dependency must.

⚠️ **OB-8 is binding and it is NOT a classification bug.** The 140.1.2 review confirmed the
venue/service classification at the amplifying sites is CORRECT. The harm is the global
`breaker:railway` key — one tripped dependency suppressing unrelated calls — and that key is exactly
what this plan replaces. Do not "fix" the classification.

⚠️ **Changing the breaker KEY breaks the test harness in a way no earlier plan's file list revealed.**
`src/test/helpers/upstash-breaker.ts` hardcodes `BREAKER_KEY_LITERAL = "breaker:railway"` and
`seedBreakerOpen` writes exactly that key. Four test files call `seedBreakerOpen` — nine call sites
in total — and one of them also writes the key directly. After per-dependency keying, every one of
those seeds a key the core may no longer read. **That is not a compile error and it is not
necessarily a test failure: a seeded key nobody checks produces a test that passes while asserting
nothing.** This plan owns that casualty list explicitly; see Task 2.

Output: a dependency-free discriminator leaf, per-dependency keying, a harness that still means what
it says, and a table-driven oracle whose expectations are hand-typed.
</objective>

**The status → breaker-verdict table.** This IS `SEAMCORE-01`. Derived from STATUS_CONTRACT §1 + §6
and cross-checked against `error_contract._validate`.

  400 401 403 404 422 → CALLER            → NEVER counts → no key
  429                 → CALLER, THROTTLED  → NEVER counts → no key
  424                 → CALLER'S EXCHANGE  → NEVER counts → no key.  Its `dependency` is a VENUE
                        slug and MUST NEVER become a breaker key (STATUS_CONTRACT §4)
  503                 → SERVICE-TRANSIENT  → COUNTS       → key `breaker:<dependency>`, where
                        `dependency` is required and membership-checked against
                        {mt5-gateway, kek, supabase, egress-proxy}
  500                 → SERVICE-PERMANENT  → NEVER counts → no key. Includes the bodyless
                        `text/plain` unhandled-exception shape
  2xx                 → success            → no
  transport throw / deadline / body-read rejection → COUNTS → the residual GLOBAL key
                        `breaker:railway`. A connection that never completed names no dependency,
                        and that is genuine Railway degradation.

**The body-shape branch** (STATUS_CONTRACT §2.1, verbatim — reading `body.detail.code`
