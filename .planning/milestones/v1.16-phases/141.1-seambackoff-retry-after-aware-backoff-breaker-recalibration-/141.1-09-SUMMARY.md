## Deviations from Plan

### 1. [Acceptance-criterion intent] `grep -n "unreachable today" TODOS.md` returns 2, not 0

- **Criterion:** *"`grep -n "unreachable today" TODOS.md` → 0 (the false parenthetical is corrected)."*
- **Actual:** 2 hits. **Both are my own correction text**, which quotes the phrase in order to name what it corrects: the 140.5 bullet now reads *"…the path 141 adds — ⚠️ **CORRECTED 2026-07-31 (141.1-09): no longer "unreachable today".** 141 shipped that path…"*, and the ledger's G3 verdict line identifies the obligation as *"the `handleRetrySync` "unreachable today" parenthetical"* so a reader can find it.
- **The false ASSERTION is gone.** Nothing in the file now claims the path is unreachable; both surviving occurrences assert the opposite.
- **Resolution — kept, not "fixed".** Deleting the quoted phrase would satisfy the grep and leave a correction that cannot say what it corrected, and a verdict that cannot name its obligation. This is the same trade plans 01, 04 and 07 each declined (07's Deviation 1 is the identical shape: a fence whose comment must name the construct it fences). No wording was contorted to move a number.

### 2. [Acceptance-criterion interpretation] The `DISCHARGED|RE-BOOKED` criterion measures LINES, and TODOS.md is one-bullet-per-long-line

- **Criterion:** *"`grep -Ec "DISCHARGED|RE-BOOKED" TODOS.md` grew by ≥ 4."*
- **Issue:** `grep -c` counts matching *lines*. TODOS.md's house style puts each bullet on a single very long line, so my first draft — which carried three `DISCHARGED` tokens inside one prose lead — scored **2**, while genuinely discharging five obligations.
- **Resolution:** restructured the section lead from one prose sentence into **five per-obligation bullets**, each ending in an explicit uppercase verdict (`**DISCHARGED**`), and added the token to G2's own in-place row beside its existing `✅ RESOLVED`. Now 7 lines / 7 occurrences.
- **Why this is not gaming the number:** every one of the five discharges is real and was independently verified (evidence under *Traced vs cut*). What changed is that the verdicts became **uniformly greppable**, which is the entire purpose of a ledger whose acceptance criterion is a grep. No verdict was invented, and the accurate verb was kept where it differs — G3's is a *correction*, and its bullet says so before stating the obligation is thereby discharged.

### 3. [Surgical] `compute-queue.md` tightened from 4 inserted lines to 3

- My first disambiguation blockquote ran to 4 insertions against a *"1–3 line change only"* criterion. Rewording to two quote lines plus the blank separator brought it to 3 while keeping every load-bearing element (names both breakers, states they differ, links the new runbook). What was dropped was decoration (`Upstash-backed, breaker:railway and friends`), which the link itself carries. Caught before commit.

### 4. [Rule 2 — correctness of a claim being written] H1's limiter attribution made precise

- The plan's H1 text names rate-limit values without saying which side of the seam they live on. Tracing `optimize-weights` on the **Vercel** side found `userActionLimiter` = 5/60 s, which does **not** match the quoted "20/min" — the quoted figures are the **Python** router's. More importantly, the Vercel limiter is checked once per user request *before* the handler, so a seam retry cannot double-consume it; only the Python limiter sees the second call.
- Writing the ambiguous version would have shipped a backlog item whose numbers a future reader could not reconcile with the file they'd naturally open (`src/lib/ratelimit.ts`). The ledger entry now names the side, the exact limits, and the reason the TS-side limiter is unaffected.
