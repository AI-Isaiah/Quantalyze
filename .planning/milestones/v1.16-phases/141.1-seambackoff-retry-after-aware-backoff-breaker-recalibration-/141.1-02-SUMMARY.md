## Deviations from Plan

### 1. [Rule 1 — Bug] The planned D-03 pin was VACUOUS on `simulator`

- **Found during:** Task 2 mutation testing.
- **Issue:** The plan specifies the D-03 pin as
  `evidence.toMatch(/concurrent|is_disconnected|doubled/i)`. Implemented verbatim, the
  required mutation (delete the COST sentence from `simulator`) stayed **GREEN**. Cause:
  `simulator`'s evidence separately says the failure-path row "cannot be **doubled** by a
  seam retry" — an unrelated sentence about a different property — so the alternation was
  satisfied incidentally. The pin would have reported agreement forever while the cost it
  exists to protect had been deleted. This is the phase's own thesis turned on the guard.
- **Fix:** Anchored the pin on the two tokens that appear ONLY in the COST sentence —
  `/second concurrent full compute/` **and** `/request\.is_disconnected\(\)/` (verified: 4
  occurrences in evidence, one per analytics YES entry, all inside the COST sentence). The
  mutation now reddens for all four keys. A comment in the test records the measurement so
  nobody relaxes it back to an alternation.
- **Files modified:** `src/lib/seam-retry-registry.test.ts`
- **Commit:** `aecc82ff`

### 2. [Rule 3 — Blocking] `s` (dotAll) regex flag fails typecheck

- **Found during:** Task 3 verification.
- **Issue:** The plan's SC-G′ resync behavior specifies `/pending.*running.*done_pending_children/s`.
  `tsc --noEmit` rejects it: `TS1501: This regular expression flag is only available when
  targeting 'es2018' or later`. Runtime was green; the build was not.
- **Fix:** `/pending[\s\S]*running[\s\S]*done_pending_children/` — semantically identical,
  no flag. Re-ran the resync mutation afterwards to confirm the pin is still load-bearing
  in the new form (it is: RED).
- **Files modified:** `src/lib/seam-retry-registry.test.ts`
- **Commit:** `902b0e3d`

### 3. [Plan-sanctioned fallback] Needle hoisted to a non-test module

- **Found during:** Task 3a.
- **Issue:** The plan's first choice is exporting `citationsIn` from
  `seam-citations.invariant.test.ts` and importing it, with a directive to measure for
  duplicate test registration. **First probe was misleading:** with the import present but
  UNUSED, `seam-retry-registry.test.ts` alone still ran 27 tests — the import was being
  elided. Re-probed with actual usage: the file alone ran **73** tests, i.e. the invariant
  file's whole 46-test suite re-registered under the wrong filename.
- **Fix:** Took the plan's sanctioned fallback — hoisted `CITE`, `citationsIn` and
  `CONVERSION_PROTOCOL` into `src/lib/seam-citations-needle.ts`, imported by both test
  files. One regex, two consumers; no second copy (the 17 unrewired `stripComments` copies
  are the anti-pattern this avoids). Confirmed after: registry alone 31, both files 78 =
  31 + 47, no duplication.
- **Files modified:** `src/lib/seam-citations-needle.ts` (new),
  `src/lib/seam-citations.invariant.test.ts`, `src/lib/seam-retry-registry.test.ts`
- **Commit:** `902b0e3d`

### 4. [Rule 2 — Correctness] Re-measured the comment-line figure instead of bumping it

- **Issue:** The invariant test's vacuity fence documents a MEASURED figure ("10863 comment
  lines across the 34 files, 2026-07-30"). Appending a 35th file makes that prose stale,
  and inventing a new number would violate the no-invented-data rule the same docblock
  preaches.
- **Fix:** Actually re-measured (11255 across 35) and recorded BOTH datapoints with dates.
  The floor stays 6500 per the plan — recorded in-comment as a deliberate choice ("it is a
  FLOOR, not a tracker") so the next appender does not feel obliged to ratchet it.
- **Files modified:** `src/lib/seam-citations.invariant.test.ts`
