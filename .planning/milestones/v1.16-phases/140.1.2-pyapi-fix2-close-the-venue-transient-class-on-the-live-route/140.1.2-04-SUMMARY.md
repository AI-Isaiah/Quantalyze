### Decision, with the OBSERVED reason

**`EQUAL: False` ⇒ design (a)'s set equality is unavailable. Design (b) — containment — adopted.**

The plan's decision rule anticipated "FastAPI `response_model` post-processing". **That is not the
cause, and saying so would have been a guess dressed as a finding.** The route declares
`@router.post("", response_model=None)` (`routers/process_key.py:808`). The real cause, read at
source:

```python
# routers/process_key.py:783-800 — _run_validate_only
envelope: dict[str, Any] = {"ok": True, "valid": True, "read_only": ..., "correlation_id": ..., "step": "validate"}
if val.preview is not None:
    envelope["preview"] = val.preview
if val.daily_returns_series is not None:
    envelope["daily_returns_series"] = val.daily_returns_series
```

`_keys_assigned_to` renders the **union of every key ever assigned**, so the AST fingerprint
`dict:correlation_id,daily_returns_series,ok,preview,read_only,step,valid` is a strict **superset**
of shape 3's observed body `dict:correlation_id,ok,read_only,step,valid`. Wire ⊆ declared is the
true relation, and it is a property of the router's design, not of the framework.

**Design (a)'s other half WAS adopted**, because it is independently correct: `_envelope_error`
joined `_SHAPE_BEARING_FUNCTIONS` and its dict fingerprint is now pinned in
`_EXPECTED_200_FINGERPRINTS`. Rationale: shape 6 reaches the wire as a bare
`return _envelope_error(...)` at HTTP 200, so its dict IS a 200 shape — while the delegate sat
outside the tuple only the `call:_envelope_error` **edge** was fenced. Its non-200 uses are
unaffected (they wrap it in `JSONResponse(status_code=4xx, …)`, which `_declared_status` excludes).
Without this, shape 6's body would have been an orphan and deleting *its* row would have survived.

### The strength check the probe alone would NOT have caught

Plain containment ("some driven row covers this declared shape") is **too weak**, and this was
checked rather than assumed. Shape 2's body `{correlation_id, ok, queued, verification_id}` is a
subset of shape 1's declared shape, so under a non-injective relation **deleting the shape-1 row
would still have passed** — and the plan's mid-table probe would never have revealed it. The
matching is therefore **one-to-one** (Kuhn's augmenting path, six a side): every declared shape must
have its **own** reaching fixture, so *any* deleted row leaves a shape unmatched by pigeonhole.

A second assertion catches the opposite direction: a `_SHAPES` row whose body is contained in **no**
declared shape is an orphan — a fixture fabricating a shape the route cannot emit.
