**W-4 — the `unknown ⇒ recoverable=True` polarity, DERIVED not assumed.** Two sources appear to
contradict, so the source was read (revision, at `services/exchange.py` ≈:979-1023):

- **PATTERNS §V1** labels `PERMANENT_VALIDATION_ERROR_CODES` *"fails unsafe on omission"* — i.e.
  an unenumerated PERMANENT code is retried forever.
- **The constant's own comment block** states the opposite framing verbatim: *"THE RULE IS AN
  ALLOW-LIST OF PERMANENT, NOT A DENYLIST OF TRANSIENT … An unknown future code therefore fails
  SAFE (transient → the caller retries and succeeds) instead of failing terminal (the caller is
  told to fix credentials that were never broken) … the reverse default is the exact shape of the
  H-1 defect this constant closes."*

They are not actually in conflict — they name **two different harms**, and the direction is
decided by **which harm this field can cause on THIS route**:

1. **This `recoverable` is a RENDER hint, not a retry-loop input.** Nothing on `/api/validate-key`
   consumes it in an automated loop; the wizard reads it to decide whether to offer a retry
   affordance. The worker's automated-retry decision is a DIFFERENT field on a DIFFERENT path
   (`error_kind` in `long_fetch` — plan 01's subject, V2). So the DoS-shaped harm PATTERNS' V1
   column warns about (*"retried forever"*) is **not constructable here**: the cost of a wrong
   `True` is one pointless user click on a dead credential.
2. **The cost of a wrong `False` is the defect this entire phase exists to kill** — a real venue
   blip rendered with no retry affordance ("our team has been notified"), the DOGFOOD-3 dead end.
   Asymmetric, and the asymmetry points at `True`.
3. **Inverting would make the router contradict the frozenset it imports.** Deriving `False` from
   non-membership in an ALLOW-LIST OF PERMANENT is a category error: non-membership means "not
   known to be permanent", which the constant's contract defines as retryable.
4. **The unknown case is nearly unconstructable at C6/C7 anyway** — the producer's code space is
   CLOSED (every branch sets a code; see the W-2 block above), so this is a fail-safe default for
   a branch that should never fire, not a routine path.

**Required pins (both):** (a) a control case asserting a synthetic/unknown code ⇒
`recoverable is True`, whose failure message states the harm (*"an unrecognised venue verdict must
still offer a retry affordance — the alternative is the UNKNOWN/500 dead end"*); (b) the
`AUTH_FAILED` permanent control already specified, asserting `recoverable is False`. **Both
directions pinned, or the field is decorative.**
