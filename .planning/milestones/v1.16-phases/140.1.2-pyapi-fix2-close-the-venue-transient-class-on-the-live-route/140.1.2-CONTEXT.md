## Implementation Decisions (LOCKED)

### PYAPIFIX2-01 is the reason this phase exists — everything else is small
The class was closed on the **wrong route**. `/process-key`'s sync arm (fixed in 140.1.1) serves
teaser / csv / internal_report. **`/api/validate-key` (`routers/exchange.py:522`) is the live
key-connect path** — `create-with-key`, `composite/add-key`, `keys/validate-and-encrypt`.
Traced end-to-end by a red team: `exchange.py:522` → `analytics-client.ts:174-181` wraps as
`AnalyticsUpstreamError(detail, status)` → `classifyKeyValidationError`, **a substring cascade over
the human string** (`wizardErrors.ts:967-1035`). Results:
`RATE_LIMITED`→`KEY_RATE_LIMIT` ✓ · `PROBE_FAILED`/`MISSING_SCOPE`→`KEY_PROBE_FAILED` ✓ ·
`DDOS_PROTECTION`→`KEY_IP_ALLOWLIST` (wrong code, right flavour) ·
**`NETWORK_UNAVAILABLE` → `UNKNOWN`/500** · **`EXCHANGE_UNAVAILABLE` → `UNKNOWN`/500**.
⇒ **A Binance maintenance window during key-connect renders as "something went wrong, our team has
been notified", with no retry affordance** — verbatim the DOGFOOD-3 dead end `wizardErrors.ts:940-960`
was written to kill. *(`NETWORK_ERROR_DETAIL` contains "Network" but the branch tests
"timeout"/"etimedout" — a two-string near-miss, not a rewording risk.)*

**Enumerate by BEHAVIOUR, not by the two named sites.** A red team found the full consumer set is 8,
and that `_validate_mt5_key` answers **400** at three further classified-upstream arms
(`exchange.py:335` probe timeout, `:345` `Mt5AccountMismatchError`, `:361` transient `Mt5ClientError`)
— structurally identical to the enumerated sFOX site `:152`, and **outside TS-32's carve-out**.
⚠️ `exchange.py:522` **is already in TS-32** — reported at base coordinate `:505`. Not a new escape;
the carve-out's *completeness* is what failed.

### PYAPIFIX2-02 is REPRODUCE-FIRST — two red teams disagree
Claim: `MT5_WRONG_SERVER` (`services/ingestion/mt5.py:104`) and `MT5_MASTER_PASSWORD` (`:224`) are in
neither `PERMANENT_VALIDATION_ERROR_CODES` nor `long_fetch.py:391`'s local `permanent_codes`, so the
live worker path yields `error_kind="transient"` → **3 gateway-serialised retries → `failed_final`**
for a credential that can never succeed. **MT5 is `ENABLED=true` in production.** The master-password
case is security-shaped: `mt5.py:218-227` rejects it *because it is trade-capable*, and the reply
blames the venue. TypeScript already calls both **400 client faults** (`wizardErrors.ts:1002/1005`) —
**the two sides hold opposite verdicts.**
**Counter-claim:** a second red team found MT5 branches *before* `create_exchange`
(`exchange.py:351-380`, `internal.py:220-222`), has its own `validate()`, and never calls
`validate_key_permissions` — so the sync 424 gate is unreachable for MT5.
**Both can be true**: the 424 half unreachable, the `long_fetch` half live. **Reproduce the worker
path before scoping. "Could not reproduce" is a valid, budget-saving outcome.**

## Specific Ideas

- **`cron.py:138`'s `CREDENTIAL_REJECTION_CODES` is the design to copy.** It is a **fourth** copy of
  the permanent-codes concept that nobody had named — and **the only one whose omission direction is
  safe** (omission means "retry next tick", never "deactivate"). The other three
  (`PERMANENT_VALIDATION_ERROR_CODES`, `long_fetch.py:391`, `_ROUTE_TERMINAL_ERROR_CODES`) fail unsafe
  on omission. If a unification is proposed, this is the polarity to unify *toward*.
- **The allow-list is structurally uncompletable** — `csv_adapter.py:172` mints `first_rule.upper()`,
  an open code space from pandera rule names. **No enumeration can ever cover it**, so any fix keyed
  on a string list is wrong by construction; gate on `source`/provenance instead.
- **Verified CLOSED — do not re-open:** `ADAPTER_INIT_FAILED` 3/3 (re-attacked by behaviour predicate
  over all 21 `create_exchange` sites, nothing missed) · the S-01…S-24 5xx site map (independent AST
  count matched site-for-site — *"the one enumeration in the phase I could not break"*) ·
  `_ROUTE_TERMINAL_ERROR_CODES` membership (exactly 5) · the cross-language fixture (4 extra mutations
  all caught) · zero self-referential oracles.
