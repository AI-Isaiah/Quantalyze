## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The wire harness stubbed a re-imported module, not the namespace the app handler reads**

- **Found during:** Task 3's plan-close gate (the unscoped `pytest -q`), not during Task 2.
- **Issue:** The new file passed in isolation (`19 passed`) but **12 of its 14 wire cases FAILED under the full suite** — meaning the venue boundary was never stubbed and those cases were exercising real clients. Not a flake and not an ordering "quirk": sibling suites call `tests/limiter_stub.evict_module("routers.exchange")`, which pops the module from `sys.modules`; the next `from routers import exchange` builds a **new module object**, while `main.app`'s routes still hold the function objects from the **first** import, whose `__globals__` is the **original** module dict. `monkeypatch.setattr` on the re-imported module therefore never reaches the code the wire request executes. Demonstrated directly rather than inferred: after `evict_module`, `app handler globals IS reimported.__dict__` → **False**.
- **Fix:** Root cause, not a workaround. A `_handler_globals(path, method)` helper resolves the namespace from the **registered endpoint** — `inspect.unwrap(route.endpoint).__globals__`, unwrapped past the slowapi decorator whose own globals belong to slowapi — and the three arrange helpers use `monkeypatch.setitem` into it. That dict is the one the running handler is guaranteed to read whatever import order the suite imposes. The resolver **raises** if the route is absent, so a vanished/renamed route can never silently make every assertion vacuous. The app's own limiter (`main.app.state.limiter`) is reset for the identical reason. **Zero assertions were weakened.**
- **Files modified:** `analytics-service/tests/test_validate_key_venue_transient.py`
