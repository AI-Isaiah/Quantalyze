# Phase 141.2 Plan 05: onboard's retry becomes conditional on a usable idempotency key — Summary

Finding 1 / D-01 closed at the five-caller `postProcessKey` chokepoint: a new leaf-pure
`retriesForFlow(flowType, context)` decides the `/process-key` retry from the flow's audited
verdict AND the presence of a truthy `wizard_session_id`, using `Boolean()` so the predicate is
byte-identical to Python's `bool(context.get("wizard_session_id"))`.

**Required statement, verbatim from the plan's output spec:** Using the chokepoint helper per
RESEARCH §5.1; CONTEXT D-01's original one-call-site wording was corrected by the
pattern-mapper (C-1) — the chokepoint serves D-01's spirit and closes the class. `context`
stays required by decision.

  Flow verdict is consulted FIRST (key presence NARROWS a YES, it can never create one — a
  helper testing the key first would hand `teaser` a retry the moment a caller happened to
  include a session id, which is the SC3 anti-feature reached through the new argument instead
  of around it). Zero value imports; the leaf-purity pin still holds.
- **The chokepoint** is one physical line: `retriesForFlow(args.flow_type, args.context)`.
  The belt that was an inline `?? 0` moved inside the helper, unchanged in meaning.
- **The wiring roster** was updated in the same commit as the expression, with the
  name-not-arithmetic tradeoff and the "never widen the extractor" instruction written down
  where the next editor will hit it.
- **The onboard evidence** now says the antecedent is ENFORCED, not asserted, and records that
  the second producer (`keys/validate-and-encrypt`) is safe by the predicate itself — its
  zero-retry budget row and its dated dormancy claim remain true and useful as defence in
  depth, but neither is load-bearing for the verdict any more.

### Scope, stated honestly

**This is CLASS CLOSURE, not a reduction in live retry volume.** The production census in
RESEARCH §0.5/§1.2 found every post-F6 producer stamping the id and zero surviving
NULL-carrying drafts. What changed is that an antecedent which was *asserted* is now
*checked* — a producer that stops sending the id loses the retry automatically instead of
silently invalidating the reasoning. No claim is made that this prevents duplicate writes
happening today.

CI gates are advisory at merge in this milestone (branch protection deferred), so the correct
phrasing throughout is that these pins **would have caught** the defect — not that any gate
stopped it.
