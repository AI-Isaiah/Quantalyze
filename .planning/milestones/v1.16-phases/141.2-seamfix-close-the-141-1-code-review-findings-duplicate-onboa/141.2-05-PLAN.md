<objective>
Close finding 1 (BLOCKER): `onboard`'s retry-safety evidence rests on `idempotent_by_session`
being true, but `finalize-wizard` forwards NO `wizard_session_id` when the draft's column is
NULL (nullable by design), Python then skips the duplicate pre-check and mints a fresh
server-side uuid4 per attempt — so the unique constraint cannot collide and one user submit
inserts two `strategy_verifications` rows on the money path.

D-01 as corrected (CONTEXT correction 3, RESEARCH §5.1, PATTERNS C-1): this is NOT a one-line
call-site change. `PostProcessKeyArgs` has no retry field; the decision is made inside
`process-key-client.ts:502` from `flow_type` alone — a chokepoint with five callers. The fix
threads idempotency-key presence into that shared chokepoint via a named leaf-pure helper in
the registry, with a ONE-LINE call site: the guard is co-located with the evidence whose
antecedent it enforces, it covers the CLASS (the registry itself names a second onboard
producer, `keys/validate-and-encrypt`, safe today only by a budget-row pin plus a dated
dormancy claim), and the predicate can be made byte-identical to Python's.

DECIDED, not deferred — `context` stays REQUIRED. `PostProcessKeyArgs.context` is a required
field (`process-key-client.ts:320`), so "a caller omits the context" is not type-expressible:
the compiler already forbids the omission this fix guards against. That is the CORRECT state
and this plan does NOT relax it: making `context` optional would let a future caller compile
silently while leaning on the runtime default — the fail-closed default is a belt for
non-typed access paths (JS callers, casts, future refactors), not an invitation to omit. The
enforcement is therefore two-layer: required field at compile time, helper default at runtime.
Consequence for the ledger: SC-L's original mutation ("omit the idempotency argument at one
caller") cannot compile through the real call site; the ledger row is reconciled to the
mutation that IS performable — flip the helper's undefined-context default from 0 to 1 — which
pins the runtime belt directly. The VALIDATION ledger carries this reconciliation.

Honest framing (RESEARCH §0.5): prod census shows the NULL path carries ~zero live traffic —
every post-F6 producer stamps the id and there are zero drafts. D-01 is CLASS CLOSURE — it
converts an asserted antecedent into an enforced predicate. The summary must not claim it
prevents duplicate writes happening today.

Wave 2, depends on plan 02: the helper reads the post-D-03 registry (onboard is the only YES
flow), plan 02 owns the registry files and extends the process-key-client.test.ts pins in
wave 1.

Purpose: finding 1 (D-01). SC-K, SC-L.
Output: an enforced key-presence predicate at the five-caller chokepoint, fail-closed at both
layers, roster updated, both seam sides running the same predicate.
