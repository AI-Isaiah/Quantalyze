## What shipped

### Task 1 — `src/lib/source-scan.ts`, the shared comment handler

Two exports over **one** tokenizer, deliberately duals: `stripCommentsPreserveLines` blanks exactly the spans `extractComments` returns, so a guard that counts and a guard that reads prose cannot drift apart.

- **Line-preserving** (char-for-char blanking) — copies `seam-log-coverage.test.ts:299-305`, *not* `seam-copy.purity.test.ts:55-61`'s line-destroying variant. PATTERNS §2 names picking the wrong one of the two as a live hazard, because only the line-preserving one can report a location.
- **String and template contents survive** in both directions; a `//` inside a string is not a comment, and a citation inside a string literal is not prose about this repo.
- **Regex-literal aware.** Not decoration: `.replace(/\/\*[\s\S]*?\*\//g, "")` — a line three of the repo's own `stripComments` copies contain — holds the character pair `//` inside the pattern. A scanner without regex awareness reads it as a line comment and blanks the rest of a **real** line, i.e. goes silently blind on exactly the files these guards watch. Known limit stated in the docblock rather than hidden: after `)` the module chooses division.
- **Python is minimal and says so**: `#` plus triple-quoted strings, single pass. The census's docstring double-extraction (RESEARCH §3.1 bug 3) cannot recur here by *construction* rather than by a dedup key — a `#` inside a docstring IS the docstring.
- **Trailing comments are blanked**, unlike both in-repo variants. That is the honest choice for a population count and it costs their false-positive safety net, so the docblock places a **vacuity-fence obligation** on every caller.

17 self-tests, both polarities throughout, every expected value a hand-typed literal.

### Task 3 — the dynamic-import needle, in all FOUR sets

All four sets used `/^\s*import\s/m`, which **requires whitespace after `import`**, so `import("x")` matched nothing — in every position. Every one of the four dependency-free seam leaves could have acquired a dependency with green CI, and `src/lib/sentry-capture.ts` already uses that exact idiom in-repo, documented as keeping Sentry out of bundles. "Lazy-import it so it doesn't ship" is therefore a locally-idiomatic tidy-up that would have defeated every purity guard in this repo.

`seam-redaction.test.ts` was edited **deliberately, not by copy-paste**: its env case asserts `process.env` IS present (call-time read) — the opposite polarity of the other three — and it uses `RATIONALE`, not `PURITY_RATIONALE`. The new case there also names the glob trap, so the next person widening these needles does not find three of four again.

Each needle has a positive control asserting **both** polarities *and* asserting that the three pre-existing needles are **blind** to the smuggled shape — the measurement that justifies the fourth case existing, rather than an assurance that it does.

**Prose hygiene (WP-15):** the "sixteen" integer is gone from all **six** sites in the three purity files (docblock + `PURITY_RATIONALE` in each), replaced by the predicate — *"every route test that mocks a seam client wholesale"*. ## Deviations from plan

### 1. [Rule 1 — root cause] The env restore landed as TWO scopes, not one `afterEach` to the inherited env

- **Found during:** Task 2, in the mandated full-suite fallout measurement.
- **The plan specified:** snapshot `{...process.env}` at module scope, restore to it in the existing `afterEach`.
- **What that does, measured:** it reverts a file's own module-scope and `beforeAll` env after that file's **first** test, so every later test in the file runs unconfigured. **5 files reddened**, and they are not "silently depending on a leak" as the plan's premise assumed:
  - `src/lib/dateday.test.ts` sets `process.env.TZ = "America/New_York"` in `beforeAll` and **restores it in `afterAll`** — it already does, by hand and correctly, exactly what a file→file guard should do for everyone. The plan's mechanism would have forced a rewrite of *correct* code to satisfy the harness.
  - `csv-finalize/route.test.ts:143` and three sibling suites assign `process.env.INTERNAL_API_TOKEN` once at module scope as file-level configuration.
- **Landed instead:** `afterEach` restores to a **`beforeEach` baseline** (kills test→test), `afterAll` restores to the **inherited** env (kills file→file).
- **Why this is not a weakening:** it closes *both* leak classes the plan's shape closes, plus keeps legitimate file-level configuration working. The canary is unchanged and still reds under SC-ENV-1. **Fallout from the env half: zero files, zero edits.**
- **Files:** `src/test-setup.ts` (the reasoning is recorded in the file itself, not only here). **Commit:** `81be6823`.

### 2. [Rule 3 — blocking] 32 files carrying a module-scope `vi.stubGlobal`

- **Found during:** Task 2's full-suite run — 24 files / 124 tests red.
- **Root cause, measured with a purpose-built hook-order probe:** `unstubGlobals: true` restores globals **before each test, including the first**, and the runner's restore hook is registered before user hooks. Probe result: `[undefined, "beforeEach"]` — **a module-scope stub does NOT survive; a `beforeEach` stub DOES.**
- **Fix:** relocated the existing `vi.stubGlobal(...)` calls into a `beforeEach` in **all 32 files** carrying the shape — not just the 19 that failed. The other 13 are the same defect, silent today; fixing the class is the standing rule.
- **Why relocation and not `vi.spyOn`:** the plan asks for "properly-scoped setup + the config-level restore", which relocation satisfies exactly and leak-proof by construction. A 32-file `spyOn` rewrite closes nothing extra at much greater risk.
- **This also closes a real leak,** not just a breakage: a module-scope stub is never undone, so it is the longest-lived form of the DEF-16-1 shape.
- **Commit:** `81be6823`. All 32 enumerated below.

### 3. [Rule 2 — correctness] Regex-literal tokenization in `source-scan.ts`

- Not in the plan's behavior block. Added because without it the module mis-reads `.replace(/\/\*[\s\S]*?\*\//g, "")` as a line comment and blanks real code — a **silent** blinding of the four guards that import it, on files that contain that exact line. Covered by a dedicated both-polarity test (`expect(strip(src)).toBe(src)` for a regex holding `//`, and a division case where the trailing comment must still be blanked). **Commit:** `882b0219`.
