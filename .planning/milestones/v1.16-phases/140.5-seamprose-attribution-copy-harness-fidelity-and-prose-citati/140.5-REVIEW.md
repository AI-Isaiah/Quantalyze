## Summary

This phase's subject is prose/citation/comment truth plus a small set of deliberate
type/behaviour hardenings. I derived the surface from the 8 plans' `files_modified`
frontmatter, cross-checked against the `140.5` commit range (`5733a610^..a89cedbf`,
including the post-phase route fix `a89cedbf`), and reviewed the **diff**, not file
history. The `140.4-16` wave was excluded.

I separated the load-bearing logic changes from the prose churn and reviewed the
logic adversarially:

1. **`mintTenantClaim` now takes `TenantIdentity` (object) not two bare strings** —
   traced all call sites (`postProcessKey`, `analyticsRequest`) and the three fail-loud
   guards. `identity?.userId` feeds GUARD 1, which rejects `undefined`/empty with the
   named `TenantClaimError`, so a JS/`as unknown` caller passing nothing still fails loud,
   not with a bare `TypeError`. Secret-transposition is now a compile error. Correct.
2. **`SeamBreakerVerdict` became a discriminated union on `counts`; the `&& breakerKey
   !== null` fail-open was deleted at all three `resilient-fetch.ts` recording sites**
   (1667, 1966, 1999). I verified **every** producer arm in `seam-discriminator.ts`:
   the two `counts:true` producers (the 503/refine arm at ~506, and the `TRANSPORT`
   constant at 513) both set a non-null `breakerKey` (`GLOBAL_BREAKER_KEY` or
   `${PREFIX}${dep}`); every `counts:false` arm sets `breakerKey:null`. The
   keyless-counting state is now unrepresentable, so the deleted conjunct was provably
   dead and no verdict is dropped. Pinned by `seam-breaker-failopen.regression.test.ts`.
3. **`Retry-After` relay in `postProcessKey`** — additive, unconditional on status
   (`res.headers.get("Retry-After")` copied verbatim only when non-null); does not
   reintroduce the forbidden status-keyed behaviour selection. Correct.
4. **Transport marker (`seamTransportCode`) + consumer** — set on `AnalyticsTimeoutError`
   and via `notReachableError()`, read in `wizardErrors.ts:1805-1815` through `typeof`
   (never `instanceof`, survives wholesale mocks), resolved via the shared wire→wizard
   table to `SERVICE_UNREACHABLE`/502 **before** the message-substring cascade. Closes
   B-02 (the `"timed out"` vs `"timeout"` hole) by type/data, not substring. Correct.
5. **CSV three-way upstream arm** (`CsvUploadStep`/`CsvSubmitStep`) — `res.json().catch(()=>({}))`
   means a non-JSON edge/WAF body can't crash the arm; roster-first ordering keeps the
   route's WR-07-corrected `SEAM_MISCONFIGURED` sentence and routes codeless failures to
   the §4a founder copy with an always-rendered correlation id. `KNOWN_CSV_VALIDATE_CODES`
   excludes `CSV_RATE_LIMIT` on purpose so its `Retry-After` rides the shared envelope.
   Correct and consistent with the guard.
6. **`permissions/route.ts` post-phase fix `a89cedbf`** — removing the over-broad
   `includes("not configured")` clause from `isConfigError` is correct: our own env-var
   fault stays matched by the `INTERNAL_API_TOKEN` sentinel (its message contains the
   token), while a reached-and-answered upstream KEK fault whose sentence merely contains
   the phrase now falls to the generic `PROBE_FAILED` envelope instead of being
   mis-reported as our layer being unreachable. The characterization test was flipped to
   lock the fix.

All other changed source is comment/docstring/prose only. I mechanically confirmed the
