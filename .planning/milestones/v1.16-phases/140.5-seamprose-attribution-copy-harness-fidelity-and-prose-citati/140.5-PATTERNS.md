### ⭐ THE RULE A PLAN MUST FOLLOW

> **`seam-copy.ts` is for a sentence a SERVER route emits into an envelope it builds by hand,
> on a path that can reach an anonymous visitor. `WIZARD_ERROR_COPY` is for a sentence
> addressed by a `WizardErrorCode`, carrying a `cause` and `fix[]`.**

§4a's founder copy is **three parts** — a title, a cause sentence, and a rendered
`correlation_id`. `CsvValidationEnvelope.tsx:59-76` reads the **`cause` field of
`WIZARD_ERROR_COPY[envelope.code]`** to fill its second line. A string-only leaf cannot supply
that, and `seam-copy.purity.test.ts:143-155` **refuses a second export** in those words:

```ts
// EXPECTED_EXPORTS — "A SECOND copy export is specifically refused: … a sibling
// export is a second name that can be reworded independently, which is the drift
// this module exists to close."
const EXPECTED_EXPORTS: string[] = ["CIRCUIT_OPEN_COPY"];
```

⇒ **§4a's sentence belongs in `WIZARD_ERROR_COPY`, as ONE new `WizardErrorCode` entry.** Putting
it in `seam-copy.ts` would require widening a deliberately-frozen one-member set AND would still
leave `CsvValidationEnvelope`'s cause line empty.

**What to copy — the entry shape, verbatim template** (`wizardErrors.ts:817-828`, the entry §4a
replaces at the non-validation arm):

```ts
CSV_VALIDATION_FAILED: {
  title: "Validation failed. See per-row breakdown below.",   // ← the LIE on a 401
  cause: "One or more rows in your file failed schema or business-rule checks.",
  fix: ["Expand each rule below to see the row-level breakdown.",
        "Fix the offending rows and re-upload."],
  docsHref: "/security#csv-format",
  actions: ["clear_and_retry"],
},
```

**What to AVOID:** the `docsHref` and `actions` fields are not optional in the type
(`WizardErrorCopy`, `:263-273`). `actions` feeds `RECOVERABLE_ACTIONS` in `envelope.ts:54-57`
(`clear_and_retry` | `try_another_key`) → `recoverable`. **§4a says "try again in a moment"** ⇒
`actions` must include `clear_and_retry` or the copy promises a control the envelope won't render.
Re-derive this polarity; do not copy it from a sibling.

**Also avoid:** adding a `CSV_*` prefix by reflex. §4a covers *every* non-validation upstream
status from the CSV validator; the code name should say that, and `SEAM_CODE_TO_WIZARD_CODE`
already demonstrates naming a wizard member after the FACT, not the producer (`:1645-1651`).
