## Accomplishments

### Task 1 — the registry, five stamps, three written exemptions (`15cb987b`)

`SeriesCompleteness` (Literal) + `SERIES_COMPLETENESS_VALUES` (frozenset, exactly 5 members,
verified `len == 5` and Literal-args == frozenset at runtime). The docstring names it as the ONE
**producer** registry and records that there is deliberately no SQL `CHECK` and no TypeScript
import — the gate's admissibility allow-list is a hand-typed **subset**, because "what a producer
may emit" and "what the gate may trust" are different questions.

`series_completeness` added to `NavTWRMeta` and **kept out of `NAV_TWR_GUARD_KEYS`**. That
exclusion is load-bearing and documented at the annotation: guard-key membership is what
`_prestamp_flags` iterates to promote `computation_status` to `complete_with_warnings`, a status
the publish gate **passes**. Routing a gating signal through the promotion channel would make it
invisible to the gate it exists to feed.

### Task 2 — seven per-return-path verdict tests (`67adc0aa`)

One case per *return path*, not per function. The deribit allocated-capital branch gets its own
case precisely because it has its own `return` and is the live account. The two sFOX cases also
assert their `nav_gap_days` premise so neither can pass vacuously. Every expected value is a
hand-typed string literal; nothing imports `SERIES_COMPLETENESS_VALUES`.

### Task 3 — the D-15 economic acceptance oracle (`479549b8`)

`test_funding_only_series_is_understated_and_never_certified` builds **two different combiner calls
with different inputs** and asserts both halves:

- **Economics** — `cumulative(gapped) < cumulative(truth) − 0.05`, the bound hand-typed. Designed
  understatement is **8.77 percentage points** (truth +9.17% vs gapped +0.40%). The equity anchor
  is real in both runs, so missing fills are mis-attributed to a *larger* derived starting capital
  and a ~+9% year reads as ~+0.4%. Compounding is done by the test from first principles
  (`(1+r).prod()−1`), not via `compute_all_metrics`, so a shared compounding bug cannot cancel out
  of both sides.
- **Trust** — the verdict is `fill_derived_unproven` and is not in the hand-typed admissible list.

It also pins the **premise** that makes this the dangerous case: the gapped series is dense, has
≥2 interpretable rows (so `job_worker.py:4340` does **not** fire) and reports
`computation_status_hint == "complete"`. It looks perfectly publishable — which is exactly why the
refusal must be a trust verdict rather than a row-count or emptiness check. An anti-vacuity floor
pins that the truth book shows material return, so the inequality cannot be satisfied by two
near-zero series.

## Honest limitations

- **`mypy` cannot enforce the verdict's presence.** Combiners return `dict[str, Any]` and
  `NavTWRMeta` is `total=False`, so the type checker pins the key's *type* where present but cannot
  flag a return path that omits it. Required-ness is the plan-05 runtime seam assert's job. This is
  written at the annotation and is **not** claimed as satisfied here — VALIDATION.md's SC-5
  "static half" is weaker than its row implies.
- **This plan proves the producer side only.** The D-15 oracle pins that the *combiner* refuses to
  certify a gapped perp. That the *gate* then acts on it is plan 142.2-06's TS half.
- **142.2 closing means MT5 is reachable, not correct** (D-17). Nothing here is evidence of MT5
  correctness against a live terminal — that is Phase 142.3.
