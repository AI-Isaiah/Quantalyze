## Critical Issues

### CR-01: `composite_stitched` is stamped unconditionally — the D-15 refusal does not survive a composite wrapper

**Files:**
- `analytics-service/services/job_worker.py:6845` (the unconditional stamp)
- `analytics-service/services/job_worker.py:5491-5567` (`_reconstruct_ccxt_member`)
- `analytics-service/services/job_worker.py:5959-5966` (member joins the stitch; `metas.append(member_meta)`)
- `src/lib/strategyGate.ts:81-82` (the claim)

**Issue:**

`combine_realized_and_funding` stamps `fill_derived_unproven` **always** (`broker_dailies.py:264`),
precisely so a perp whose realized stream came back short cannot publish a funding-only series.
On the single-key path that works: `job_worker.py:4408` refuses to persist an unverdicted series,
the derive prestamp writes `fill_derived_unproven` (`:4840`), and `isDailyReturnsSourced` refuses
it.

The composite path calls the **same combiner**. `_reconstruct_ccxt_member` imports
`combine_realized_and_funding` (`:5517`) and returns `(returns, has_option_activity, member_meta)`.
On success the member joins the stitch and its meta — which carries
`series_completeness == "fill_derived_unproven"` — is collected into `metas` (`:5966`). Nothing
ever reads it. The composite headline then writes:

```python
"series_completeness": "composite_stitched",   # job_worker.py:6845
```

`composite_stitched` is a member of `SERIES_TRUSTED_FOR_DAILY_BRANCH` (`strategyGate.ts:88-92`).
A composite carries `api_key_id = NULL` and zero `trades`, so `tradeCount === 0 && csvRowCount > 0`
holds by construction — the gate takes the daily-returns branch and, with ≥7 rows and
`complete`/`complete_with_warnings`, **passes**. The admin approve path
(`strategy-review/route.ts:251` first pass, `:364` TOCTOU re-check) publishes it.

The FIX B guard at `:5566` (`if not realized and funding: raise _CcxtMemberDegrade`) catches only
the *fully* empty realized stream. A **partial** truncation — the OKX bills paginator and the
bybit funding cursor, both booked as live bugs in `TODOS.md` under `DEF-142.2-04` — produces a
non-empty realized list, passes the guard, and lands in the stitch. That is exactly the
population `DEF-142.2-04` says must not be certified.

The code asserts the opposite. `strategyGate.ts:81-82`:

> `composite_stitched` — stitched from constituent series that each carried their own verdict.

and `142.2-05-PLAN.md:187-188`:

> The verdict means: "this series is the deterministic stitch of member series" — trust inherited
> from members

Nothing inherits. The member verdicts are in hand at the stamp site and are discarded.

**Blast radius, stated honestly:** this is **behaviour-preserving** relative to the deleted
`!input.apiKeyId` term (composites were admitted unconditionally before too), and plan 04's PROD
census recorded **0 published composites**. So there are no live victims today. It is
nonetheless a reachable publish path for a materially understated track record, and the phase's
own artifacts claim it is closed — which is what makes it a blocker rather than a deferral: the
next reader will not re-derive this.

**Fix** — the data is already local at the stamp site; derive the verdict instead of asserting it:

```python
# job_worker.py, just above headline_payload (:6804)
from services.broker_dailies import SERIES_COMPLETENESS_VALUES

# A stitch is only as trustworthy as its least-trustworthy member. Hand-typed subset,
# deliberately NOT imported from strategyGate.ts (the TS policy is independent by design).
_MEMBER_TRUSTED_FOR_STITCH = frozenset({"ledger_complete", "user_supplied", "composite_stitched"})

_member_verdicts = [m.get("series_completeness") for m in metas]
_stitch_verdict = (
    "composite_stitched"
    if _member_verdicts and all(v in _MEMBER_TRUSTED_FOR_STITCH for v in _member_verdicts)
    else "fill_derived_unproven"   # a member declined to certify → the stitch cannot certify either
)
```

then `"series_completeness": _stitch_verdict` at `:6845`. Note that `degraded_members` must be
treated as untrusted too — a degraded member contributes an all-zero series (`:6134`), which is
a fabricated flat leg, not an audited one.

Correct `strategyGate.ts:81-82` in the same change so the docstring states what the code does. If
the founder prefers to ship as-is (0 published composites; behaviour-preserving), then the
docstring and `142.2-05-PLAN.md` must be corrected to say the verdict is asserted, not inherited,
and the gap logged as a named `DEF-142.2-*` item — silently leaving the false claim is the worst
of the three options.

| `verify-strategy:128` | "Unsupported exchange. Supported: …" | `KEY_UNSUPPORTED_VENUE` |
| `verify-strategy:141` | "sFOX integration is not yet available." | `KEY_VENUE_NOT_ENABLED` |

Both files carry a comment declaring the lockstep the split just broke:

- `validate-and-encrypt:91-94` — *"The four request-shape rejections all answer `KEY_INVALID_FORMAT`
  (**create-with-key's exact token for the same facts**, two of them byte-identical sentences)."*
- `verify-strategy:75-78` — *"Mirrors … **the sibling create-with-key, which codes all five of these
  request-shape rejections `KEY_INVALID_FORMAT`**."*

Neither statement is true after this change. Two routes now answer different machine tokens for
byte-identical sentences ("sFOX integration is not yet available." is `KEY_VENUE_NOT_ENABLED` at

**Fix:** apply the same four-way split to both routes' arms and delete the two now-false lockstep

### WR-02: the `user_supplied` stamp discriminates on current column state, not provenance, and `strategies.api_key_id` is `ON DELETE SET NULL`

**Files:**
- `analytics-service/services/analytics_runner.py:1541-1546`, `:1564`
- `supabase/migrations/20260405061911_initial_schema.sql:51`

**Issue:**

`analytics_runner.py:1541` states the rule as provenance:

> ⛔ PROVENANCE, never current column state. Stamping because "the verdict is currently NULL"
> would promote a KEYED funding-only perp … The discriminator is `api_key_id IS NULL`
> (`_is_broker_sourced`) : the wizard's CSV branch.

`api_key_id IS NULL` **is** current column state. `_is_broker_sourced` (`:1233`) is a live read of
`strategies.api_key_id`, and that column is declared:

```sql
api_key_id UUID REFERENCES api_keys ON DELETE SET NULL,   -- initial_schema.sql:51
```

So deleting an `api_keys` row flips a keyed strategy to `api_key_id IS NULL`. Its broker-derived
`csv_daily_returns` rows survive the delete: the strategy-mode payload
(`job_worker.py:4522-4530`) writes `{strategy_id, date, daily_return}` with no `api_key_id`, so the
`ON DELETE CASCADE` on `csv_daily_returns.api_key_id` (migration `20260624120000:39`) never reaches
them. Any subsequent `run_csv_strategy_analytics` for that strategy would then compute
`_is_broker_sourced = False`, `_was_composite = False` → `_stamp_user_supplied = True` (`:1564`)
and **overwrite `fill_derived_unproven` with `user_supplied`** — an allow-listed verdict on a
funding-only perp series.

**I could not close the loop into a proven exploit.** `compute_analytics_from_csv` has exactly two
enqueue paths — `csv-finalize/route.ts:824` and the `derive_broker_dailies` follow-on chain — and
after the key is deleted neither fires for that strategy without a fresh CSV upload, which the
edit page gates on `source === "csv"` (`strategies/[id]/edit/page.tsx:67-71`). So today the
sequence is not reachable end-to-end. It is a warning rather than a blocker for that reason.

What makes it worth fixing now is that the safety rests on an unwritten assumption ("nothing
re-enqueues the CSV analytics job for a de-keyed strategy") while the comment claims a stronger,
different property ("provenance"), and one new enqueue site would silently convert this into a
fail-open on the money path.

**Fix** — make the discriminator actually provenance-bearing, and fail closed rather than
relabel. E.g. gate the stamp on the strategy's own `source` column (the wizard CSV branch writes
`source = 'csv'`), which does not move when a key is deleted:

```python
_source = _strategy_row.get("source") if isinstance(_strategy_row, dict) else None
_stamp_user_supplied = (
    _source == "csv" and not _is_broker_sourced and not _was_composite
)
```

At minimum, correct the comment to say the discriminator is current key linkage and record the
`ON DELETE SET NULL` interaction, so the next reader does not inherit a guarantee that was never
made.

### WR-03: `strategyGate.ts`'s allow-list docstring asserts a member-verdict guarantee that does not exist

**File:** `src/lib/strategyGate.ts:81-82`

**Issue:** Companion to CR-01. The docstring reads:

```
 * - `composite_stitched` — stitched from constituent series that each carried
 *                         their own verdict.
```

The members do carry verdicts; the stitch discards them (`job_worker.py:6845`). This sentence is
the reason a reviewer would skip checking the composite path — it reads as a statement that the
check happened upstream. `strategyGate.ts` is the single file a future maintainer will open to
answer "what does this gate trust and why", so a false guarantee here is load-bearing.

**Fix:** ship with CR-01 (make it true), or correct it to state the actual semantics:

```
 * - `composite_stitched` — the deterministic stitch of member series. NOTE: the
 *                         stitch job stamps this UNCONDITIONALLY; it does not
 *                         read member verdicts. A composite containing a
 *                         `fill_derived_unproven` member is admitted here.
 *                         Tracked as DEF-142.2-XX.
```
