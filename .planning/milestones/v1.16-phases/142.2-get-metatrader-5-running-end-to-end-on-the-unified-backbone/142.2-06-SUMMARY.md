# Phase 142.2 Plan 06: Gate on the Verdict, Not the Venue — Summary

TypeScript's opinion about which venue deserves trust is deleted; the publication gate now reads
`strategy_analytics.series_completeness` — a verdict it cannot compute — through a positive
allow-list, at one shared predicate invoked from all three former sites.

| 3 | `967e0f18` | `strategyGate.invariant.test.ts` — zero venue literals, with an anti-vacuity floor and three scanner SELF-TESTs |

**The shape of the fix.** The venue list was a proxy for a question a venue name cannot answer — "is
this daily series complete?" — and its only enforcement was a comment telling the reader to keep it
in lockstep with a Python set. The Python set widened to three venues; TypeScript stayed at one. The
judgement now lives with the producers, who stamp the verdict at the moment they write the series
and can still see its inputs. The stale comment was deleted rather than amended: it is part of the
defect, and divergence is now **detectable** (the invariant test + the deleted second copy) rather
than re-instructed.

## The Acceptance Test Is a REFUSAL

MT5 passing is not the test. The falsifiable safety property is that a keyed **perp** with
`seriesCompleteness='fill_derived_unproven'`, 135 csv rows and 0 trades is still **REFUSED** — and
it is pinned twice: once on the pure gate, once through the admin route that actually publishes.
The trap in both fixtures is `computationStatus: "complete"`: the pipeline SUCCEEDED, 135 rows
exist, nothing errored. Only the producer's verdict stands between that funding-only series and a
public factsheet carrying an understated track record.
