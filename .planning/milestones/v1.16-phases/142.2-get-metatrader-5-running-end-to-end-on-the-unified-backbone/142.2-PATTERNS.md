**Consequences the planner must absorb, in priority order:**

1. **Composites become un-approvable.** Today a composite has `api_key_id = null`, so
   `!input.apiKeyId` puts it on the daily-returns branch — this is the documented behaviour
   (`strategy-review/route.test.ts:1073`: *"Composites (apiKeyId null) source history"*). Pattern 3
   **deletes the `apiKeyId` term** and replaces it with a positive verdict allow-list. If
   `run_stitch_composite_job` does not stamp a verdict, every composite's
   `series_completeness` is `NULL` → trade branch → `INSUFFICIENT_TRADES` → **no composite can ever
   be approved again**. RESEARCH.md's A5 ("composites never route through `checkStrategyGate`") is
   true only for `SyncPreviewStep`; it is **false for the admin approve path**, which is the path
   that publishes.
2. **The CSV-upload verdict cannot be enforced by a Python assert.** The `user_supplied` verdict
   RESEARCH.md assigns to "the `analytics_runner` CSV path" is stamped *after* the rows were
   already written by a different language. The assert-at-the-persist-seam idiom (Pattern 2) covers
   producer 1 only. Either the enforcement moves to the `strategy_analytics` stamp seam (which all
   three paths do reach), or it is placed at all three write sites, or the CSV path is exempted
   **explicitly and in writing**, never by omission.
3. **The Falsifiability Ledger row SC-5** ("add a combiner return path that omits the verdict") is
   satisfiable by an assert that only guards producer 1, and will report caught while producers 2
   and 3 stay unguarded. That is precisely the instance-fix-as-class-fix shape.

**Analog:** itself. The per-venue config is a three-part pattern: an optional interface key, a

**(a) Optional interface key** (`:43, 64-70`):

```tsx

  …
  passphraseLabel?: string;
```

`passphraseSecret?: boolean;` goes here, beside its three siblings.

**(b) Defaulted read** (`:390-402`) — **this is the byte-identity mechanism**. Every default is the

```tsx

    activeExchange?.passphraseHelper ?? …
```

is what makes OKX (and every future venue that omits the key) byte-identical without touching the
OKX config entry. D-03's "OKX `true`" is satisfied by the default, not by an edit.
