## FIX 1 — an unexamined series is not a trade shortage

**Commit `ba69f1ad`.**

The migration is additive with **no backfill**, so every pre-existing
`strategy_analytics` row reads `series_completeness = NULL`. Fail-closed
correctly routed those to the trade branch — where a keyed Deribit/MT5 strategy
with 0 trades and 135 daily rows was answered:

> Strategy has only 0 trade(s). A minimum of 5 trades is required.

That is verbatim the false, unwinnable message the phase exists to delete.

**Not fixed with a backfill** — forbidden by the migration's own comment: a
backfill fabricates a trust claim about series whose inputs no longer exist to
examine. The data was right; the **diagnosis** was wrong.

### What landed

New gate outcome `SERIES_PROVENANCE_UNVERIFIED` → wizard code
`GATE_SERIES_PROVENANCE_UNVERIFIED`. The split is **"did a producer look?"**,
never "do we like the answer?":

- `fill_derived_unproven` / `sampled_gapped` — a producer examined the series and
  found it wanting. **Trade-branch routing unchanged.**
- `NULL`, `""`, or a verdict this module has not been taught — nobody looked.
  Say that, and offer the remedy that makes a producer look.

Both arms **refuse**. No admission decision changes anywhere; a dedicated test
pins the full admission table across all five verdicts plus `null` / `""` /
unknown.

The remedy is `clear_and_retry` + `request_call` and deliberately **not**
`try_another_key`. That action is what earns the destructive control
(`keyReplacementIsEarned`), which fires `handleDeleteDraft()` and destroys the
draft plus every `strategy_keys` member. Answering "we never recorded where your
returns came from" with "delete your work" is the dead end being removed.
`clear_and_retry` is not a placebo: `kickoffRetryCanChangeTheOutcome` keys off
exactly that action, so the envelope renders a Retry wired to
`handleKickoffRetry` — a real re-sync, which is what makes a producer stamp.

### Landmines, cleared rather than worked around

- **Render-loop anti-vacuity floors RAISED**, never lowered: `driven` 14 → 15,
  distinct codes 13 → 14, with a new scenario row driving the new code. A note
  now states explicitly that a new reachable code raises these and that walking a
  floor back down silently un-pins whichever code stopped being reachable.
- **Both hand-typed copy-table size guards** bumped 61 → 62, each with its
  reasoning re-run over the new entry *before* the number moved, as those guards
  demand: destructive-class membership (carries neither `try_another_key` nor
  `start_fresh`, so it is out of the scanned population by construction), and all
  four `FORBIDDEN` unsubstantiated-claim fragments. The one needing care was
  "data is unchanged" — the entry does make a server-state claim ("nothing on our
  side recorded how that series was built"), but it is **observable**: it
  restates the exact value the gate just read and is the sole reason the refusal
  fired.
- `wizardErrors.invariant.test.ts` (SC-10) stays green: it derives codes emitted
  by the two *connect* routes, and a gate code is not among them. The union-size
  floor still passes.
- `strategyGate.invariant.test.ts` stays green: the **allow-list is unchanged at
  three members**. The new set is a separate, message-only set.
- Added to the hand-typed `allGateCodes` array and deliberately **not** to
  `intentionallyUnknown` — it is terminal and wizard-reachable, so it must
  resolve to real copy.

### Admin route

No source change needed: the route already calls `checkStrategyGate` and renders

## FIX 2 — the composite verdict is derived, not a bare literal

**Commit `25fe50b4`.**

`run_stitch_composite_job` stamped `composite_stitched` unconditionally while
`member_metas` was already in hand at the site (the guard-flag union loop reads
the same list twenty lines earlier). A member whose combiner **measured** a
coverage hole was laundered into a verdict the publish gate trusts.

**The obvious fix was rejected as a serious regression.**
`combine_realized_and_funding` stamps `fill_derived_unproven` for every ccxt
venue **always and unconditionally** — the normal case for that path, not a
finding about the account. Propagating it would refuse essentially every ccxt
composite. Unlike a single key (fills in `trades`, never needs the daily branch),
a composite has **zero trades by construction**, so the daily branch is its only
route to publish; that refusal would be terminal.

So only **known gaps** propagate: any member stamped `sampled_gapped` (sole
producer `combine_sfox_balance_history`, only when `nav_gap_days > 0`) downgrades
the composite to `sampled_gapped`. Everything else keeps `composite_stitched` —
behaviour-preserving.

### False claims corrected

- `strategyGate.ts` said composites were "stitched from constituent series that
  each carried their own verdict". Untrue before this commit — the stamp never
  consulted them.
- `142.2-05-PLAN.md:187-188` said "trust inherited from members". Annotated in
  place with a dated correction rather than rewritten, since the plan is a
  historical record.

Both now state precisely what **is** inherited (known gaps) and what is **not**
(unproven-ness, blocked on the ingestion-truncation work booked as
`DEF-142.2-04`).

## FIX 3 — composite preview now agrees with the publish gate

**Commit `44408cea`.**

The composite arm reached `setPhase("passed")` without evaluating any
admissibility. Harmless while the admin path admitted composites on the deleted
`!input.apiKeyId` term — both sides agreed by accident. Admission now needs a
positive verdict this arm never read, so a composite on an unstamped row saw
**passed**, submitted, and was then refused.

The arm calls the **shared** `isDailyReturnsSourced` — the same predicate the
admin route's TOCTOU re-check calls — rather than restating it. That route
already learned this lesson: a hand-written copy under a comment saying the two
"must never diverge" diverged anyway. A third hand-copy would be the same mistake
a third time.

Intent preserved: a composite must not be false-failed for having zero fills.
That is exactly why it is `isDailyReturnsSourced` and not `checkStrategyGate` —
the full gate would apply the trade-count floor to a strategy with zero trades by
construction.

The shared `defaultAnalyticsRow` fixture gained
`series_completeness: "composite_stitched"` — the truthful post-phase state for a
completed stitch, which is what all 23 existing cases model.
