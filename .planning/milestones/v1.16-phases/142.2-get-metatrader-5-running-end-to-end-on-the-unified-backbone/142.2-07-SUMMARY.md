- The founder's actual failure is closed **as a class**. ## Deviations from Plan

**None on substance — the plan executed as written.** Three points worth recording, none of which changed scope:

**1. `grep -c "Client-side"` returned 1 on the first check, not 0.** The offender was my own replacement comment, which quoted the sentence it was documenting. The acceptance criterion is a raw repo grep with no comment exclusion, so a pasted citation keeps reporting the class open — which is precisely the discipline `ConnectKeyStep.tsx`'s docblock already records for the same reason. The comment now *describes* the removed clause and cites that precedent. This is the identical failure mode as the 14-vs-12 count, met from the other direction.

**2. My own denylist self-test was wrong, and the test caught it.** I wrote `"a flagrant mismatch"` as an example of innocent prose that must not trip the guard — but `flagrant` starts with `flag` at a word boundary, so the prefix rule matches it. Rather than weaken the rule to exact-word (which would let `flags`, `gated` and `environment` through — the forms the offending copy would actually take), the example was replaced and the false positive is **declared** in the docblock as a known limit, with instructions to add a narrow exemption rather than drop the allowance.

**3. `node_modules` is absent in this worktree.** Node's resolution walks up to the parent repo, whose `package-lock.json` is byte-identical (same `shasum`), so `vitest`, `tsc` and `eslint` all resolve and run. **No package was installed** and no symlink was created.
