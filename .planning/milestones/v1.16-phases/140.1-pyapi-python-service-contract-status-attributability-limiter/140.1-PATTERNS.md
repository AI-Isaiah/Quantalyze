### `analytics-service/services/rate_limit.py` / limiter key functions (services, request-response)

**Analog:** `analytics-service/routers/process_key.py:75-105` (`_process_key_rate_limit_key`) — this IS the pattern to replicate at every IP-keyed site (Class 2), not a separate analog to look up.

**Never-raise discipline** (`process_key.py:99-105`):
```python
auth = request.headers.get("Authorization", "")
if auth.startswith("Bearer "):
    token = auth[len("Bearer "):]
else:
    token = auth or "unauthenticated"
token_id = hashlib.sha256(token.encode("utf-8")).hexdigest()[:16]
return f"process_key:{token_id}"
```
Copy this shape (header-read only — `key_func` cannot see the parsed body per RESEARCH G-7; must never raise per G-8) for the tenant-claim HMAC key function RESEARCH recommends (Q1.2), and for the `optimizer.py:31` fix.

**Shared-instance registration pattern** (`services/rate_limit.py:29` + `main.py:173`):
```python

limiter: Limiter = Limiter(key_func=get_remote_address)
# main.py
app.state.limiter = limiter
app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)
```

Deleting the 3 private `Limiter()` instances (`exchange.py:40`, `csv.py:24`, `portfolio.py:146`) means importing this singleton instead — mirrors the Phase-19/API-5 fix documented in the module's own docstring (`services/rate_limit.py:1-18`), which is the direct precedent for this exact repair.
