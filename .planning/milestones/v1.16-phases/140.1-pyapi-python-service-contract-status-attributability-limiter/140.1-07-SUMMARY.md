## FINDING-10 — a TENTH IP-keyed route the plan did not predict


The plan's do-not-touch list (critical warning 2) describes `simulator.py:232` as
**"correctly user-keyed"**. Against the source that premise is **false**. The
function's own docstring records why: the PR#241 red-team removed the `X-User-Id`

`_check_simulator_user_rate` against `req.user_id`, leaving the slowapi decorator

the class this plan closes.

the header is absent."* The function does not read `X-User-Id` at all.

the more specific of the two conflicting instructions. Quarantined mechanically:
`IP_KEYED_QUARANTINE = frozenset({"simulator.py"})` and the gate asserts

simulator is repaired, forcing the allow-list to shrink rather than rot.

**Cost of leaving it:** `/api/simulator` is 20/hour, platform-wide, at the slowapi
tier. Unlike L-1..L-9 it has a real per-user tier underneath it, so the user-facing
exposure is a *ceiling* one tenant can exhaust for everyone — meaningfully less

### Casualty class C — two latent test-infra defects PYAPI-03 exposed

Both were pre-existing and both are fixed at the root rather than worked around.

**C-1 — `sys.modules.pop("routers.exchange")` never re-imported anything.**
`from routers import exchange` runs importlib's `_handle_fromlist`, which imports
the submodule **only if the parent package lacks the attribute**. The pop clears
`sys.modules` but not `routers.exchange` on the package, so the fixture got the
**stale** module back, silently, decorators intact. Latent as long as no earlier
module imported the router; `tests/test_limiter_identity.py` does, which is how it
surfaced — as 48 failures at a line that looked correct. Fixed by
`tests/limiter_stub.py::evict_module`, which drops both. Verified:

```python
import routers.exchange; first = routers.exchange
sys.modules.pop("routers.exchange", None)
from routers import exchange as second
second is not first   # -> False   (pre-fix: no re-execution at all)
```

**C-2 — `test_process_key.py` minted a SECOND `services.rate_limit`.** It popped
the module at its own import time to rebuild a real `Limiter` after sibling files
shimmed `slowapi.Limiter`. Since PYAPI-03, four routers bind that singleton **at
their own import time**, so re-popping leaves them holding limiter #1 while
`app.state.limiter` gets limiter #2 — silently breaking the API-5 shared-storage
invariant that `test_process_key_shares_main_limiter_instance` and
`test_simulator_router.py::TestG15_004_LimiterIsCanonicalSingleton` exist to
protect. Removed. Its *cause* is removed too: the two sibling stub files now
`import services.rate_limit` **before** swapping `slowapi.Limiter`, so the
canonical singleton is never built from the shim and there is nothing to rebuild.

## The oracle file — `tests/test_limiter_identity.py` (63 tests)

Three gates. Every expected value is a **literal**; nothing is read back out of
the limiter and compared to itself (programme non-negotiable #3).

**Gate 1 — per-route key identity (the WIRING), 37 tests.** Reads the limit
slowapi **actually registered** on the endpoint (`limiter._route_limits[name]`),
not the module-level helper. A test that inspected `tenant_or_platform_key` would
stay green through a refactor that dropped every `key_func=` — which is *precisely*
L-9, where the helper existed and the decorator did not use it. Per L-row:
mounted at its literal path · key is not `get_remote_address` · key is **not the
singleton default either** (acquiring it by omission is L-9's exact shape, and the
default is no longer IP-derived, so `is not get_remote_address` alone would now
pass vacuously) · key is `partial(tenant_or_platform_key, scope=<literal>)` ·
limit value unchanged · nine distinct scopes.

**Gate 2 — bucket behaviour (the CONTRACT), 17 tests**, all driven through the
**registered** key function so they prove the decorators, not the helper. Verified
claim → `optimize_weights:t:tenant-alpha` / `validate_key:t:tenant-alpha`;
claimless → the literals `platform:/api/optimize-weights` /
`platform:/api/validate-key`; teaser → `optimize_weights:anon`; two tenants get
two distinct literal buckets (pinned as two literals, not `!=`, so a constant-
returning key function is still caught); **forged** claim (wrong secret) and
**expired** claim both fall to the ceiling and never reach a tenant — separating
"we parsed the shape" from "we checked the MAC"; six hostile-input arms plus an
unset-secret arm prove the never-raise contract (G-8) and that the key is never
empty (an empty key makes slowapi **skip** the limit).

The claim minter in the test re-implements the wire format independently rather
than calling any helper the verifier uses.

**Gate 3 — class closure (the COUNT), 9 tests.** The enumerated class is exactly
nine and its rows are `L-1..L-9` · `get_remote_address` NAME-token scan over
`routers/*.py` equals the literal `{"simulator.py"}` · `services/rate_limit.py`
contains no such token · the singleton default `is default_platform_key` and is
not `get_remote_address` · **AST** walk finds zero `Limiter(` constructions under
`routers/` · all five routers' `limiter` **is** the singleton · `app.state.limiter`
**is** the singleton · the set of statically rate-limited routes equals a literal
10-element set · a behavioural sweep over *every* registered `routers.*` limit
(independent of the table, so it covers a route added without updating it) ·
`routers/match.py` still has **no** limiter, asserted so the Phase-146 note goes
red when someone closes the gap instead of rotting.

**One deliberate relaxation, stated:** the per-route assertions iterate over **all**
registered limits rather than indexing `[0]`, and the limit-value gate asserts the
**distinct set** `== {"20 per 1 minute"}`. slowapi appends to `_route_limits` on
every decoration, and sibling suites reload router modules, so the list can hold N
identical copies within one session. Iterating is strictly **stronger** than
`[0]` — a second, wrongly-keyed decorator can no longer hide behind a correct
first one — while the distinct-set form still catches a second decorator with a
different value.
