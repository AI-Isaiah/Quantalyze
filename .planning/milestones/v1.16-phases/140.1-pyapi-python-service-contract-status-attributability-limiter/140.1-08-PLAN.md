<critical_warnings>
1. **The 422 echo mechanism:** pydantic v2 puts the input value in each error's `input` key; for a
   `model_validator(mode="after")` failure (like `_validate_per_flow_required_keys`,
   process_key.py:201-243) `loc` is `[]` and `input` is the ENTIRE model input including
   context.api_secret. The handler must build detail from `type` + `loc` ONLY and DROP `input`,
   `ctx` and `url`.
2. **Global handler ⇒ global blast radius.** It changes the 422 shape for EVERY router. The known
   TS `.detail` consumers (Class 5, count 3 + 1 correct): analytics-client.ts:179,
   keys/[id]/permissions/route.ts:147, ScenarioCommitDrawer.tsx:622 (all become CORRECT once detail
   is a scalar string — the fourth, PortfolioImpactPanel.tsx:76-77, already handles both).
   Record for 140.2: spot-check ScenarioCommitDrawer:622 against the new shape. Do not edit TS.
3. **PYAPI-08's body must carry BOTH `code:"RATE_LIMITED"` AND a scalar `detail` string.** With
   detail-as-string, analytics-client.ts:179 works with ZERO TS change (X-6's one-line TS fix
   becomes unnecessary — state this explicitly in the SUMMARY so 140.2 doesn't re-do it).
4. **mypy --strict handler signatures:** `(Request, Exception) -> Response` to satisfy Starlette's
   add_exception_handler overloads; narrow with cast(RequestValidationError, exc) /
   cast(RateLimitExceeded, exc) — never `# type: ignore` (locked decision).
5. **PYAPI-06 must not create an outage:** the startup assertion logs + captures loudly but does
   NOT sys.exit, and /health stays HTTP 200 when only a config term degrades — a red /health
   triggers Railway's restart loop, turning a config warning into an outage. Absent-secret and
   mismatched-secret produce DISTINCT tags (rotation vs attack); no log/tag/capture may contain any
   substring of any secret. Rate-limit the request-time captures (a stale key fires per-request).
6. **RATE_LIMITED is already a registered recoverable WizardErrorCode** (process_key.py:298-299) —
   reuse the literal, do not mint a new code.
7. **slowapi version claim (ASSUMPTION close):** the handler/`_headers_enabled` behaviour was read
   at 0.1.9; CI pins 0.1.10. Verify against the pinned version source (pip download slowapi==0.1.10
   into the scratchpad, or read the tag on GitHub) and record one line of evidence in the SUMMARY.
</critical_warnings>
