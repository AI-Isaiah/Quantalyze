<objective>
Close the publish/permission gate that fails OPEN — **both members of the class**.

Purpose: requirement `SEAMUX-07`. This is a **security gate, not error rendering**, and CONTEXT is
explicit that it must not queue behind copy work. It is scheduled at the earliest wave the two
arrived plans leave free.

`finalize-wizard`'s scope-broadening probe does `return (await res.json()) as LivePermissions;` and
then rejects only on `livePerms.trade === true || livePerms.withdraw === true`. A 2xx `{}`, or one
renamed field, makes both `undefined` ⇒ both gates pass ⇒ `{ ok: true }` ⇒ **the draft finalises to
`pending_review` with a key holding trade/withdraw scope published as read-only-verified.**

⚠️ **The class has TWO members, not one — correction C-5, verified first-hand.**
`src/app/api/keys/[id]/permissions/route.ts` does the identical unchecked cast
(`return (await res.json()) as PermissionPayload;`) over the **same** upstream endpoint, inside an
`unstable_cache` fork with `{ revalidate: 60 }` — so it not only fails open, it **caches the
unvalidated verdict for a minute**. C-05's claim that "the sibling badge route validates" is FALSE,
and that cache is C-06's mechanism. **A plan that fixes only `finalize-wizard` closes 1 of 2**, which
is this programme's signature failure mode.
</objective>
