### 🔴 FINDING-A — the `≥ 7 members` criterion and `<interfaces>` were mutually unsatisfiable as written, and closing the class is what resolved it

the thing that would trivially produce seven: *"it must not create two codes with the same meaning."*

- `CIRCUIT_OPEN` is a **wire** code. `SERVICE_UNAVAILABLE_RETRY` is already the **wizard** member for
  "the breaker is open, we declined to try, nothing was submitted". Minting `CIRCUIT_OPEN` as a second
  union member is exactly the forbidden duplicate, and PostHog `wizard_error {code}` values are
  contractually stable, so it could not be a rename either.
- Aliasing therefore adds **one** set member, not two → 6, not 7.

Resolved by **enumerating the class instead of the instance**, which is the phase's own discipline and
turned out to be the honest answer rather than a workaround. `finalize-wizard` puts exactly **five**
non-`WizardErrorCode` codes in front of a user, enumerated first-hand from source, not presumed:

> **`CIRCUIT_OPEN` is a WIRE code. It is aliased onto the existing `SERVICE_UNAVAILABLE_RETRY` wizard
> member through the ONE wire→wizard table in `src/lib/wizardErrors.ts`
> (`SEAM_CODE_TO_WIZARD_CODE`, read via `recogniseSeamErrorCode`). It does NOT become a
> `WizardErrorCode`.**

Rationale: `SERVICE_UNAVAILABLE_RETRY`'s copy is already correct for a breaker trip (it says the pause
is on our side and that nothing was submitted), code IDs are contractually stable for PostHog, and a
second member with one meaning is how a vocabulary starts lying.

**`actions` was a BEHAVIOUR decision and was made here.** It drives `recoverable` through
`RECOVERABLE_ACTIONS` in `src/lib/envelope.ts`, which decides whether a Retry control renders at all.
`try_another_key` is **deliberately absent** from all three new members: none of these verdicts is a
fault in the user's key, and offering "try another key" would re-commit the exact lie `DDOS_PROTECTION`
was telling.

⚖️ **The one `recoverable` divergence, and why it is not a defect.** The contract marks `AUTH_FAILED`
non-recoverable because retrying the SAME credentials cannot succeed. The wizard offers
`clear_and_retry` because clearing the fields and entering DIFFERENT credentials is precisely the fix.
Different questions, both answered correctly. Collapsing them would either strip the only actionable
control off a wrong-key error or tell the caller a dead credential is worth retrying unchanged. The
divergence is pinned **by name** (`DIVERGENT_WIRE_CODE = "AUTH_FAILED"`) so a *second* one reddens.

**`recoverable` was NOT wired into any automated retry** — the W-4 rider is honoured; retry is Phase 141.

### Two lookup tables, deliberately — `RATE_LIMITED` is in two vocabularies with two meanings

`SEAM_CODE_TO_WIZARD_CODE` maps the app-global handlers' vocabulary, where `RATE_LIMITED` is **our own
limiter** (429). `VENUE_WIRE_CODE_TO_VERDICT` maps the venue-transient contract, where the identical
string is **the exchange throttling us** (400). Merging them would force one answer onto both
producers and blame a venue for our own limit, or the reverse. Telling them apart needs the upstream
STATUS, which this function still discards — that is TS-32 / TS-34's and was not smuggled in. Recorded
in-file and in the ledger as a residual, not left to be rediscovered.
