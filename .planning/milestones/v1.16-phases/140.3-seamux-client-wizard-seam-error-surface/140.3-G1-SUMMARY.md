# Phase 140.3 Plan G1: Poll-Disjointness Re-Tiering + Guard Registration Summary

**One-liner:** Re-tiered the phase gate's own inert retry-storm fence from a file-scoped source scan
whose claim was false at HEAD into a runtime, tick-scoped, wrapper-proof observation of
`globalThis.fetch`, kept and narrowed the source backstop into a checkable inverted URL allow-list,
and registered all four of this phase's guards so none can be deleted with green CI.

## 1. What was wrong, stated precisely

`src/lib/seam-poll-disjointness.pin.test.ts` claimed *"ZERO fetch calls exist on the poll path."*
**That claim was FALSE at HEAD.** `SyncPreviewStep.tsx` — a module on the pin's own hand-typed roster
— makes three real network calls, two of them to `/api/keys/sync`, which is a seam route. The pin
passed anyway because its needle was `/\bfetch\s*\(/` and every one of those calls is spelled
`wizardFetch(`.

Both of the pin's negative predicates were inert, not just that one:

| Predicate | Why it could not fail |
|---|---|
| `ZERO fetch calls exist on the poll path` (`/\bfetch\s*\(/`) | The corpus contains **0** matches for that needle and **11** for a wrapper-aware one. The subject's only network-call spelling is invisible to it. |
| `no poll module imports a seam client` | Matches an **import edge**. All three roster modules are `"use client"`, and **0** `"use client"` production modules in this repo carry a seam import edge — a browser reaches the seam over HTTP, never by import. Dead by construction. |

This was **not a regex slightly too narrow.** Broadening the needle makes the pin RED on a clean
tree, because the property is not true at file granularity. The property that *is* true is
**tick-scoped**: the repeating poll tick must not target a seam route, while the user-initiated
kickoff may and does. Tick-ness is a runtime fact about when a callback fires, not a lexical fact
about a file. **No needle can express it** — hence a re-tiering, not a needle edit.

⚠️ **No user was ever at risk.** The safety property holds at HEAD: the tick's real target
`/api/strategies/[id]/sync-progress` imports no seam module (re-measured below: **0**). Only the
guard was inert.

⚠️ **Branch protection on `main` is OFF** by a settled founder decision, so every gate below is
**advisory at merge**. Each one **would have caught** a regression. None of them **did stop** one, and
none of them can. (Not re-raised.)

## 3. Task 1 — the runtime tick fence (the load-bearing assertion)

**New file:** `src/app/(dashboard)/strategies/new/wizard/steps/SyncPreviewStep.poll-disjointness.runtime.test.tsx`
(469 lines; a sibling, not 40 lines bolted into the 710-line PROG file whose stated subject is the
progress piggyback's *render* behaviour).

**Why a `globalThis.fetch` spy is indirection-proof by construction** (written into the docblock):
`wizardFetch` (`wizard-correlation.ts:58`) calls the **unqualified** global `fetch` in its body
(`:63`). An unqualified `fetch` resolves against the global object at call time. That is not a
property of `wizardFetch` specifically — it is a property of every wrapper: a future `apiFetch`, a
wrapper of a wrapper, an inline `const f = fetch`. **The global is the only door out of the browser.**
A source needle has to guess a spelling; this pin does not have to know one.

**Hard constraint honoured:** `vi.spyOn(globalThis, "fetch")` + `vi.restoreAllMocks()` in `afterEach`,
alongside `vi.clearAllTimers()` / `vi.useRealTimers()`. **`vi.stubGlobal` appears nowhere.**

**Phase separation** — render, two `advanceTimersByTimeAsync(0)` flushes, record
`mark = fetchSpy.mock.calls.length`, then 5 × (advance 3000 + flush). `kickoffCalls = slice(0, mark)`,
`tickCalls = slice(mark)`. Measured: kickoff **1** call (`/api/keys/sync`), tick **4** calls (all
`/api/strategies/composite-strat-1/sync-progress`).

**Five cases:**

1. **Seam-route set is DERIVED from disk and non-trivial** — `>= 12` (actual 15, bound set below
   actual per the SSR pin's stated idiom at `:186`), plus shape pins: `/api/keys/sync` and
   `/api/scenario/optimize` present, `/api/strategies/[id]/sync-progress` absent. The length bound
   alone would pass a derivation producing the wrong *shape* of path (keeping the `src/app/` prefix,
   say) while classifying every URL as safe — the two positive members are what pin the shape.
2. **The route matcher matches a seam route and NOT a near-miss** — six slots, both polarities,
   carrying the SSR pin's explanatory comment (the comment is what stops the next editor deleting the
   negative half). Positives: `/api/keys/sync`, `/api/keys/abc-123/permissions` (dynamic-segment
   wildcard), `/api/strategies/composite/add-key` (depth), `/api/keys/sync?x=1` (query stripping).
   Negatives: **`/api/strategies/composite-strat-1/sync-progress` → false** — the load-bearing one,
   because it is the LIVE tick target and has the same segment *count* as the seam route
   `/api/strategies/composite/add-key`, differing only at segment 3, so it forces the matcher to be
   route-specific rather than "any `/api/` URL"; and `/api/keys/syncing` → false (superstring).
3. **The poll tick issues at least one network call (POSITIVE control)** — falsified by **M86b**.
4. **NO tick-phase call targets a seam route** — the load-bearing assertion.
5. **The KICKOFF does target a seam route** — the honesty case. It records, executably, why the old
   claim was false, and forces anyone "simplifying" this back into a file-scoped scan to make it fail
   first.

**Mock design is load-bearing and is documented in the mock's own comment** (see §6, M86).

**Docblock states what this does NOT prove**, at more length than the assertions: jsdom under fake
timers rather than a browser; one component rather than all three roster modules (which is precisely
why the source backstop is kept); nothing about production tick scheduling or a fourth poller added
tomorrow; direct import edges only in the seam-route derivation.
