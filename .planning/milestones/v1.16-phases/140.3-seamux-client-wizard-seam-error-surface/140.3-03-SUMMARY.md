# Phase 140.3 Plan 03: Close the fail-OPEN publish gate at 2 of 2 — Summary

**One-liner:** Both sites that read the live `{read, trade, withdraw}` triple now parse it through one
required-fields zod schema and fail CLOSED on a miss — the wizard refuses the publish, and the badge
route refuses *without* leaving an unvalidated verdict in its 60-second cache.

---

## What was actually broken, restated from source

`fetchLivePermissions` did `return (await res.json()) as LivePermissions;` and the gate below rejects
only on `livePerms.trade === true || livePerms.withdraw === true`. A cast checks nothing at runtime, so
a 2xx `{}` — or one renamed field — left both scopes `undefined`, `undefined === true` is false at both
gates, the probe returned `{ ok: true }`, and **the draft finalised to `pending_review` with a key
holding trade/withdraw scope published as read-only-verified.**

`src/app/api/keys/[id]/permissions/route.ts` did the **identical** unchecked cast over the **same**
`/internal/keys/{id}/permissions` upstream — and did it *inside* an `unstable_cache` fork with
`{ revalidate: 60 }`, so the unvalidated verdict was replayed for a minute to callers that never saw
the body. **Correction C-5 is confirmed: the class has 2 members, and review finding C-05's claim that
"the sibling badge route validates" is FALSE.** A plan that fixed only `finalize-wizard` would have
closed 1 of 2 — this programme's signature failure mode.

## Task 1 — the schema, and member 1 (`finalize-wizard`)

### The schema's final field list, and why each is what it is

| Field | Disposition | Why |
|---|---|---|
| `read` | **REQUIRED** `z.boolean()` | absence is the drift that publishes a write-capable key |
| `trade` | **REQUIRED** `z.boolean()` | the gate reads it directly; `undefined === true` is false, so absence = grant |
| `withdraw` | **REQUIRED** `z.boolean()` | same |
| `probe_error` | **optional** `z.boolean()` | its absence already carries a safe meaning ("no probe error"); it is the service's own fail-CLOSED signal, not part of the scope verdict |
| unknown extras | **STRIPPED** (zod default) | the body is consumed by a decision and forwarded to a client — the NEW-C40-01 rationale on `EncryptKeyResponseSchema` applies unchanged |
| `detected_at` | **REQUIRED**, but only on `KeyPermissionsPayloadSchema` | `.extend()`ed on for the badge route, which renders it. All six of the emitter's return arms set it (read at source in `routers/internal.py`: sfox empty-key, sfox success, sfox auth-rejection, sfox transient, sfox ctor-failure, ccxt success), so a body without it is drift. The wizard's probe does not read it, so it is not on the base schema. |

**The fallback direction is INVERTED relative to `src/lib/api/errorSchema.ts`** — deliberately, and
stated in the docblock. That schema degrades an unparseable body to `{}` so error *copy* degrades
gracefully; here the same fallback would BE the vulnerability. Only the mechanism
(`z.object(...).safeParse`) is reused.

### The call site

`fetchLivePermissions` now `safeParse`s, and on a miss returns a sentinel that joins the **existing**
`if (livePerms.probe_error)` arm. No second rejection path, no new code, no new sentence.

**The sentinel carries `probe_error: true` and NOTHING ELSE.** Returning a full fail-closed triple
(`{read:false, trade:false, withdraw:false, probe_error:true}`, which is what the Python service's own
`_FAIL_CLOSED` emits) was considered and rejected: it would make the parse-miss path depend on the
`probe_error` gate being *checked first*. Carrying no scope fields makes a parse miss structurally
incapable of presenting a verdict however those gates are later reordered. TypeScript narrows the union
correctly on the existing truthiness check — no type predicate, no cast, `tsc --noEmit` exit 0.

The route-local `interface LivePermissions` was **deleted**, not kept alongside: the type is now
`z.infer`red from the schema, so there is one declaration shared with member 2.

### Five cases, every fixture hand-typed in the test

| # | Case | Failing without the fix? |
|---|---|---|
| 1 | a 2xx `{}` REFUSES the publish | ✅ RED (200 → expected 502) |
| 2 | a 2xx with `trade` renamed to `can_trade` REFUSES the publish | ✅ RED |
| 3 | a 2xx with a non-boolean `trade` (`"false"`) REFUSES the publish | ✅ RED |
| 4 | the parse-miss envelope is byte-identical to the `probe_error` arm's | GREEN both sides — it asserts the *doctrine*, against the same literal |
| 5 | **ANTI-REGRESSION CONTROL** — a well-formed 2xx read-only body still PUBLISHES | GREEN both sides, by design |

**Byte-identity is asserted against a hand-typed literal**, `{error: "Exchange permission probe failed",
code: "KEY_NETWORK_TIMEOUT"}`, declared once in the test and compared to BOTH arms — never by comparing
the two code paths to each other. Every fixture body is typed in the test; nothing is imported from the
module under test.

`AssertionError: An empty 2xx leaves 'trade'/'withdraw' undefined … expected 200 to be 502`.

## Task 2 — member 2 (`keys/[id]/permissions`), and the cache

The same schema (`.extend()`ed for `detected_at`), the same fail-closed posture — **ONE pattern for the
class.** The route-local `interface PermissionPayload` is gone; `KeyPermissionsPayload` is used directly
at both use sites rather than re-aliased to a route-local name.

### The no-cache proof

**Mechanism.** The fix fails closed by **THROWING** out of the cached callback. The fork `await`s the
callback and writes the entry only after it RESOLVES, so a throw leaves no entry — the same mechanism
this file already relies on for `CircuitOpenError` (T-140-32) and for a body-read abort, and it is
verified against the REAL `next/cache` boundary in the sibling `route.seam.test.ts`. An error returned
as a **value** would have been memoized: that is the defect restated, not fixed.

**Proof, behavioural rather than structural.** Against the test double's faithful memoizing branch
(which, like the fork, writes nothing when the callback rejects):

1. `memoize = true`, upstream answers 2xx `{}` → route answers **502**, and `memoStore.size === 0`.
2. The upstream then recovers; the very next call answers **200** with `read: true`.
3. `RF.calls === 2` and the stubbed `fetch` was called **twice** — the second call genuinely re-hit the
   upstream rather than replaying a memoized rejection-as-success.

The anti-regression twin asserts the other half: a well-formed 2xx **is** still cached
(`memoStore.size === 1`, second call served with `RF.calls === 1` and one `fetch`). A fix that disabled
the 60-second window would flood the internal endpoint on every badge render, so both directions are
pinned.

### The response shape, and why no copy was authored

The thrown message is diagnostics-only and deliberately matches **none** of the handler's classifier
substrings (`INTERNAL_API_TOKEN`, `Upstream 5`, `ECONNREFUSED`, `not configured`, `aborted`,
`timeout`), so it lands on the route's **existing** generic arm: `502 { error: "Could not check key
scopes. Try again.", code: "PROBE_FAILED" }`. `KeyPermissionBadge` already renders that shape
(`err.code ? \`${code}: ${message}\` : message`) — confirmed by reading the consumer, which was **not
edited**: its stale-scope-chips defect is B-26 / SEAMUX-09 and belongs to plan `140.3-07`.

**Observed RED before the production change: `3 failed | 1 passed`** —
`AssertionError: An empty 2xx used to reach the badge as {read: undefined, trade: undefined, withdraw:
undefined} … expected 200 to be 502`.

### 🚧 Explicitly LEFT for `140.3-09` (TS-34)

**The `!res.ok` arm at `keys/[id]/permissions` was deliberately not touched by this plan.** Its
substring cascade, its hardcoded **502** where the upstream said 429, and its dropped `Retry-After`
header are TS-34's remaining half and are owned by plan `140.3-09`. This plan touched **only the 2xx
path**. Two changes to one file in one pass is TRAP-8 — that is why the split exists, and it is stated
here so `140.3-09` does not inherit a false assumption. The same applies to this file's
`CIRCUIT_OPEN_COPY` declaration, which belongs to plan `140.3-04` and is byte-unchanged.
