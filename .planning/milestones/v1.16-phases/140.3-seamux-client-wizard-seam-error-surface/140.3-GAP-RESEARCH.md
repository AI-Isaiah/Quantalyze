## Summary

The poll pin's defect is **not** a regex that is slightly too narrow. It is a guard whose **subject,
granularity and observation point are all wrong**, and whose needle was never once measured against a
corpus where the thing it looks for actually occurs. One command settles it:

```
$ # comment-stripped scan of src/app/(dashboard)/strategies/new (19 production files)
HEAD  /\bfetch\s*\(/             call sites found in wizard corpus: 0
WIDE  /\w*[Ff]etch\s*\(/         call sites found in wizard corpus: 11
```

The shipped needle finds **zero** network call sites in a 19-file corpus that contains **eleven**.
That measurement reddens **on the untouched tree** — no mutation, no revert, no fixture. It is a
better falsifier than M75c was, and it costs one assertion.

But broadening the needle does not fix the pin, and this is the finding that should drive the plan:
**both candidate broadenings go RED at HEAD.** `SyncPreviewStep.tsx` makes three real network calls
today, two of them to `/api/keys/sync` — a seam route. The pin's stated property, *"ZERO fetch calls
exist on the poll path"*, is **false at file granularity**. The property that is actually true and
actually worth protecting is narrower: **the repeating tick must not target a seam route.** A
file-scoped source scan cannot express "the repeating tick", because tick-ness is a runtime fact
about a callback, not a lexical fact about a file.

The repo already owns the right observation point, already has the harness, and already has the
idiom. `vi.spyOn(globalThis, "fetch")` sees wrapper-issued calls **by construction** (proven below),
`SyncPreviewStep.progress.render.test.tsx` already drives real poll ticks with fake timers and
already filters `fetchSpy.mock.calls` by URL, and the seam-route set is derivable from disk in one
grep. The two files run together in 1.15s.

**Primary recommendation:** move the load-bearing assertion to a **runtime tick observation** in the
existing render harness, keep the source pin but **narrow its claim to what it can actually carry**,
and add the three controls the repo's own 140.2 ancestor carries and this pin dropped — positive
control, negative control, and a fail-loud lower bound on sites scanned. Do **not** reach for the
TypeScript compiler API or a new ESLint rule; this repo has written down why, twice, in the same
domain.

## Q2 — The self-test idiom: extract it, then answer whether it is sufficient

### The idiom, extracted precisely

`src/lib/seam-ssr-exposure.pin.test.ts:237-246`, verbatim:

```ts
it("the import-edge regex matches an edge and NOT a prose mention", () => {
  // The negative half is the load-bearing one. `wizardErrors.ts` and
  // `seam-errors.ts` both carry docblocks naming all three modules precisely
  // to explain why they must never import them; a scan that flagged those
  // would be "fixed" by weakening it.
  expect(SEAM_IMPORT_EDGE.test(`import { x } from "@/lib/resilient-fetch";`)).toBe(true);
  expect(SEAM_IMPORT_EDGE.test(`import { y } from "./analytics-client";`)).toBe(true);
  expect(SEAM_IMPORT_EDGE.test(`// do NOT simplify this to @/lib/resilient-fetch`)).toBe(false);
  expect(SEAM_IMPORT_EDGE.test(`import { z } from "@/lib/seam-errors";`)).toBe(false);
});
```

**Structure:** four fixtures in two pairs.
- **2 positives** — the two *import spellings* the repo actually uses (`@/lib/…` and relative `./…`).
- **2 negatives** — (i) a **prose mention** of the needle's own subject; (ii) a **near-miss module**
  (`seam-errors`, which is *not* a seam client but shares the naming prefix).

The file carries a second, different self-test at `:194-201` — pinning that the **assembled** needle
bytes are correct (`DIRECTIVE_BODY.split(" ")` equals `["use","server"]`). That one guards
*needle construction*, not *needle coverage*. Two distinct jobs, often conflated.

### ⚠️ The direct answer: a self-test in that exact shape would have been GREEN. It would NOT have caught this.

Measured, applying the SSR pin's own four-fixture structure to the poll pin's needle:

```
true   literal call        <-  const r = await fetch("/api/keys/sync");
false  wizardFetch call    <-  const r = await wizardFetch("/api/keys/sync");
false  void wizardFetch    <-  void wizardFetch(`/api/strategies/${id}/sync-progress`)
true   window.fetch        <-  window.fetch("/api/x")
true   globalThis.fetch    <-  globalThis.fetch("/api/x")
true   prose mention       <-  // we never fetch (from the seam) here
false  prose w/o paren     <-  // this module does not fetch anything
false  prefetch(           <-  router.prefetch("/x")
false  refetch(            <-  refetch()
```

`[VERIFIED: measured 2026-07-28]`

A faithful transplant of the idiom would read:

```ts
expect(NEEDLE.test(`const r = await fetch("/api/keys/sync");`)).toBe(true);   // ✅ passes
expect(NEEDLE.test(`// this module does not fetch anything`)).toBe(false);    // ✅ passes
```

**Both green. The pin ships inert anyway.**

**Precise reason:** a self-test's fixtures are authored **from the same mental model that authored the
needle**. It is a consistency check between the author's intent and the author's regex — not between
the regex and the codebase. It reliably catches exactly two defect classes:

1. **Needle-construction bugs** (a "simplified" assembly producing wrong bytes) — the `:194-201` job.
2. **Prose false-positives** (the guard crying wolf, then getting weakened) — the `:237-246` job.

It **cannot** catch a spelling the author did not know exists. That is a fact about the *corpus*, and
a self-test never reads the corpus.

So the verifier's prescribed fix — *"add the SSR pin's needle self-test"* (§5.1, "Owner") — is
**correct but insufficient on its own.** It should still be added (it is cheap and it guards a real
class). It must not be the thing the repair rests on.

### What the missing control actually is — and the repo already named it

The 140.2 ancestor both new pins were modelled on carries **three** controls. The contracts registry
states this as its one-line summary of the file:

> **Carries its own positive control, negative control and a fail-loud lower bound on sites scanned**,
> because a guard asserting an ABSENCE reads as protection while doing nothing if its scanner breaks.
>
> — `src/__tests__/contracts/contracts-registry.test.ts:164` (registry entry for `seam-log-coverage.test.ts`)

`[CITED: src/__tests__/contracts/contracts-registry.test.ts:164]`

The third control, implemented:

```ts

  // A scanner that matched NOTHING would report every file clean forever — the
  // failure mode that makes a source guard worse than no guard…

  expect(catchBindings).toBeGreaterThanOrEqual(6);

```

**Inventory of the three controls across the four pin files:**

| Control | `seam-log-coverage` (140.2) | `seam-ssr-exposure` (140.3-16) | `seam-poll-disjointness` (140.3-16) |
|---|---|---|---|
| Positive control (needle matches a real edge) | ✅ `:365`+ | ✅ `:242-243` | ❌ **absent** |

Both new pins bound the **corpus** (how many files / how many bytes were read) but neither bounds the
**needle's yield** (how many sites the needle actually found). Those are different assertions, and
only the second one dies when a needle goes blind.

### ⚠️ The zero-population problem — why the SSR pin gets a pass and the poll pin does not

A guard whose correct answer on its own corpus is **zero** cannot measure needle productivity there.
Three escapes exist:

- **(a) synthetic positive fixture** — the self-test. Weakest, for the reason above.
- **(b) productivity on a DIFFERENT corpus where the pattern demonstrably occurs.** Strongest, when
  available.
- **(c) don't be a source scan.**

For **`seam-ssr-exposure`**, option (b) is genuinely unavailable: there are **zero** server directives
anywhere under `src/` (that IS the property). Its self-test is the best it can do, and the file is
therefore **correctly built for its constraints.** Do not "fix" it.

For **`seam-poll-disjointness`**, option (b) was available all along and is devastating: **0 found vs
11 present** across the wizard corpus. The contrast the verifier drew between the two files (§5.1,
point 3 — "same author, same commit, one file guarded its own oracle and one did not") is **real but
mis-diagnosed**: the SSR pin is not better because it has a self-test. It is better because its
property genuinely admits no corpus check, while the poll pin's did — and skipped it.

### Recommendation (Q2)

Add **all three** controls to the repaired poll pin, in the 140.2 ancestor's shape:
1. positive control (real repo idioms: `fetch(`, `wizardFetch(`, `globalThis.fetch(`);
2. negative control (prose mention; `prefetch(`; `refetch(` — all three measured above as
   correct non-matches for a `*Fetch(` needle, and all three occur in this repo);
3. **the yield bound** — assert the needle finds ≥10 sites in the wizard corpus.

## Q3 — How do you falsify a guard whose subject is source text?

### The analogy is exact, and the phase already owns the lesson

The phase's hardest-won finding, from `140.3-11`'s M77c and restated at `140.3-16-SUMMARY.md:251-253`:

> **Only a POSITIVE case can falsify a carry**: a deleted carry and a correct absence both produce
> `null`.

The structural analogue: **an inert guard and a clean codebase both produce "no violation."** A guard
that returns `[]` tells you nothing about whether it *can* return anything else.

### Why M75c got it wrong — precisely

M75c injected a literal `fetch("/api/keys/sync")` into `useStrategySyncPoller.ts`. It went RED. It
therefore proved: *the needle matches a spelling the mutator invented.* It did not — and structurally
could not — prove: *the needle matches the spellings the subject actually uses.*

Measured, on the roster at HEAD:

```
--- every /api/ literal in the roster (comment-stripped) ---
useStrategySyncPoller.ts: []
SyncPreviewStep.tsx:      ["/api/keys/sync","/api/strategies/${strategyId}/sync-progress","/api/keys/sync"]
SyncProgress.tsx:         []
```

The roster's **entire** network-call vocabulary at HEAD is `wizardFetch(` — three sites, zero
`fetch(`. M75c mutated the one roster file that makes **no** network calls at all, using the one
spelling the roster **never** uses. `[VERIFIED: measured 2026-07-28]`

### The correct mutation shape — three properties, all with in-repo precedent

**Property 1 — the mutation must be drawn from the subject's own vocabulary, MEASURED not invented.**

Procedure: before writing the falsifier, enumerate the spellings that actually occur in the roster
(one command, shown above). Mutate using one of *those*. Had this been done, `wizardFetch(` would
have been the obvious and only choice.

**Property 2 — it must be a DISCRIMINATOR, not merely a positive.** The repo has a name for this and
an implementation:

> The fixtures below are chosen to pin the detection **STRATEGY**, not just the outcome. […] Fixture
> "renamed binding" is **the discriminator**: an implementation that looked for a variable called
> `ANALYTICS_URL` would pass every other invalid case and still miss the one an author is most likely
> to write by accident.
>
> — `tools/eslint-plugin-quantalyze/tests/no-raw-analytics-fetch.test.ts:14-25`

`[CITED: tools/eslint-plugin-quantalyze/tests/no-raw-analytics-fetch.test.ts]`

That file carries **two** discriminators, one per detection property — including a *negative*
discriminator (an untainted two-hop alias, structurally identical to a violating fixture, differing
only in the seed) that distinguishes "widening the taint" from "widening the name match." The
registry entry records both by name (`contracts-registry.test.ts:162`).

Applied here: `wizardFetch(` **is** the discriminator. An implementation that matches on the
identifier `fetch` passes every literal-`fetch` fixture and fails only this one.

**Property 3 — feed it through a PARAMETERIZED scanner, not the real tree.** Two in-repo idioms:

| Idiom | Where | Shape |
|---|---|---|
| Pure entry point + tmp fixture tree | `scripts/check-admin-route-manifest.ts:363` `runCheck(rootDir, manifest)`; driven by `src/__tests__/check-admin-route-manifest.test.ts` via `mkdtempSync` (`:158`) with **8 violation fixtures** (`:371-469`) | *"split into pure helpers + a `runCheck(rootDir)` entry point so the regression suite can drive it against a tmp fixture tree"* (`check-admin-route-manifest.ts:353-362`) |
| ESLint `RuleTester` valid/invalid | `tools/eslint-plugin-quantalyze/tests/*.test.ts` — 22 fixtures in the analytics-fetch file alone | Declarative positive/negative fixture pairs |

A tree mutation tests **one** spelling, requires a revert, and leaves nothing behind. A fixture set
tests **N** spellings, needs no revert, and is **permanent regression coverage**. The repo has chosen
fixtures everywhere it built a real gate.

**⚠️ The poll pin is architecturally incapable of property 3 today.** Its corpus is built at module
scope from `process.cwd()`:

```ts
// src/lib/seam-poll-disjointness.pin.test.ts:124-129
const SOURCE = new Map<string, string>(
  POLL_PATH_MODULES.map((f) => [f, stripComments(readFileSync(join(process.cwd(), f), "utf8"))]),
);
```

There is no exported predicate and no injectable root. Enabling fixture-driven falsification requires
extracting a pure `scan(sources: Map<string,string>): string[]` — which is exactly the
`check-admin-route-manifest.ts` refactor, and is the same ~10 lines.

### 🔑 The strongest falsifier here is not a mutation at all

The **yield bound** (Q2, control 3) reddens **on the untouched tree** with the shipped needle:
`0 < 10`. No mutation, no revert, no `git checkout --`, no MUTANT marker to sweep. A control that
fails on a clean tree when the needle is wrong strictly dominates a mutation that must be applied and
undone.

**Prefer controls that fail on the untouched tree over mutations that must be staged.** This is the
generalisable rule the phase should carry forward, and it is the one thing in this document that is a
genuinely new methodological claim rather than a rediscovery of existing repo practice.

### Recommendation (Q3) — the ledger row to write

Replace M75c with **M75d**, in three parts:

| Part | Shape | Expected |
|---|---|---|
| **M75d-a** *(no mutation)* | Run the new yield-bound control against the **shipped** needle `/\bfetch\s*\(/` on the wizard corpus | **RED** — `0 < 10`, on the untouched tree |

## Common Pitfalls

### Pitfall 1 — "Just widen the regex"
**What goes wrong:** the widened needle goes RED at HEAD on a clean tree (measured: `CALL_EDGE` and
`ROUTE_PATH` both match `SyncPreviewStep.tsx`).
**Why:** the pin's stated property is false at file granularity — the file makes 3 real calls, 2 to a
seam route.
**Avoid:** re-state the property as tick-scoped before touching the needle.
**Warning sign:** you find yourself adding an exclusion to keep the pin green.

### Pitfall 2 — Prose defeating your own grep (this phase's #1 defect, 8+ instances)
**What goes wrong:** the docblock explaining the banned pattern contains the banned pattern.
**Why:** guard files are *about* their needles.
**Avoid:** `stripComments` first (both pins do); assemble needles at runtime (`seam-ssr-exposure.pin.test.ts:75`); **measure after writing**.
**Warning sign:** `140.3-16-SUMMARY.md:151-156` — *"I was bitten by my own greps twice […] **This is
the single highest-frequency defect in this phase and it does not stop happening just because you
know about it.**"* The verifier itself then made a prose-mention miscount (Q5, fact 2). Budget for it.

### Pitfall 3 — Self-test mistaken for coverage
**What goes wrong:** the needle self-test is green and the guard is inert.
**Why:** self-test fixtures come from the author's model, not the corpus.
**Avoid:** add the **yield bound** on a corpus where the pattern occurs.
**Warning sign:** every fixture in the self-test is a spelling you wrote yourself.

### Pitfall 4 — Leaked `fetch` stub → CI-only failure
**What goes wrong:** green locally (Node 25), red in CI (Node 22).
**Why:** `vi.stubGlobal("fetch")` without `vi.unstubAllGlobals()`. **38 files stub; 4 never unstub** (DEF-16-1).
**Avoid:** `vi.spyOn(globalThis,"fetch")` + `vi.restoreAllMocks()` — the shape the existing harness already uses (`:196-199`).

### Pitfall 5 — Absorbing SEAMUX-03
**What goes wrong:** the gap plan grows an arm-by-arm pass over 9 routes.
**Why:** it is adjacent and visible.
**Avoid:** SEAMUX-03 is **owned by Phase 141+** by both the gate and the verifier. Keep `REQUIREMENTS.md:128` at `- [ ]`.

### Pitfall 6 — Rewriting a gitignored ledger
**What goes wrong:** `.planning/` has no git backup; a truncating rewrite is unrecoverable.
**Why:** it has happened on this project (MEMORY: BSD `sed` truncated `ROADMAP.md` to 4 lines).
**Avoid:** targeted `Edit` + appends, never `Write`, never `head|sed` pipes. `140.3-16` followed this (Deviation 3) — match it.
