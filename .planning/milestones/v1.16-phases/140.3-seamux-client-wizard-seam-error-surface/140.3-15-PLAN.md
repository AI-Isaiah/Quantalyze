## TS-38 — our config fault, wearing their outage's envelope

140.2's review-fix pass gave `SeamConfigError` an operator-facing log at `process-key-client.ts` that
NAMES it, so a malformed `ANALYTICS_SERVICE_URL` no longer reads to ops as Railway being down. What it
could **not** do is change the returned envelope: `postProcessKey` is declared **never to throw** at
its five caller routes, none of which has a catch for it, so `analytics-client`'s remedy (rethrow
unwrapped) was unavailable — and inventing a `code` and a `human_message` is **authoring copy**, which
was 140.2's fence. Its own in-file note hands the work here.

So today a config fault on our side still returns `UPSTREAM_NETWORK_ERROR` 502 /
*"Could not reach the ingestion service."* — a false claim about whose fault it is, which is
SEAMUX-04's exact subject.

⚠️ **This has no in-repo analog.** No existing code distinguishes *our* config fault from a dead
upstream on the client surface. The nearest shape is the sibling `UPSTREAM_TIMEOUT` envelope twenty
lines below — **shape only; the semantics are new.**

⚠️ **The anonymous teaser renders this string directly**, so the same static-copy constraint that
governs `CIRCUIT_OPEN_HUMAN_MESSAGE` applies (threat T-140-08): **no URL, no status, no service
internals.**

⚠️ **`recoverable: false`** — the condition is permanent until redeployed. A retry affordance here is
a control that cannot ever succeed.

⚠️ **A pinned falsifier must stay green:** *"ME-01: NAMES a SeamConfigError as our own config fault in
the operator log"* in `process-key-client.test.ts`. That pins the operator half. **This plan adds the
user half without disturbing it** (TRAP-9).

## TS-20 — the diagnostic that was relocated, not deleted, and is currently lost

`body.detail.correlation_id` now exists on three service outcomes (`SCORING_FAILED`, `EVAL_FAILED`,
`SIMULATION_FAILED`). Plan 140.1-04 moved the diagnostic **out** of the body — it had been leaking raw
exception text including table names, row payloads and DSNs — and replaced it with this id.
**If nobody renders the id, the diagnostic is simply lost rather than relocated.** It is also the
cheapest support channel this system will ever get.

**The render slot already exists.** `ErrorEnvelope.tsx` renders `correlation_id:` in a
`<code className="font-metric tabular-nums">`. What is missing is the **read path**.

⚠️ **`nestedDetail` is deliberately NOT exported from `src/lib/seam-discriminator.ts`.** Its own
comment explains why: *"the exported surface stays the three predicates, because everything exported
from a leaf is browser-reachable and survives every wholesale seam mock — both are privileges."* So
`correlation_id` **cannot be reached today**, and reaching it is a deliberate widening of a guarded
surface.

⚠️ **`140.3-11` faced the identical question for `dependency` and was required to decide and record
it.** Read `140.3-11-SUMMARY.md` FIRST and **use the same mechanism**. Two plans inventing rival
readers for one leaf is precisely the drift class this programme exists to close.

⚠️ **`EXPECTED_EXPORTS` in `seam-discriminator.purity.test.ts` is a hand-typed set and a HARD GATE.**
If the leaf gains an export, that set is edited in the **SAME commit**.
