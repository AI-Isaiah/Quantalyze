### Measurement correction (on the record)

The 140.3-VERIFICATION receipt counted this route as **"0 code-bearing arms / 1 bare `{error:}`"** using `grep -cE 'code:\s*"'`. That grep is **blind to this route's style**: every arm routes through `csvErrorEnvelope(code, …)` → `csvErrorBody(code, …)`, which emits `{ ok:false, code, human_message, debug_context, correlation_id }` using **shorthand `code,`** — there is no literal `code: "` token in the source. **On the wire the route has been fully coded all along.** The correct receipt for this route is the parsed-body assertion in the extended test file (Task 2), NOT the source-spelling grep.
