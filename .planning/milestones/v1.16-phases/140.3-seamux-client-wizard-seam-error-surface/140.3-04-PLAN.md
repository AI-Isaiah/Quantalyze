Purpose: requirement `SEAMUX-01` (the copy half; the classifier half is plan `140.3-05`).

**None is exported.** Nothing pins any of the ten to any other — route A's copy can be reworded, its
own test updated alongside, and the suite stays green while A now differs from B..J.

## ⚠️ THE LOCKED FRAMING IS INVERTED. Read correction C-1 before you touch a test file.

CONTEXT's locked text calls the ~12 test re-declarations *"a self-referential oracle"*. **That is
backwards, and acting on it would delete a working fence (TRAP-9, which is BINDING).**

```
grep -rn "export const CIRCUIT_OPEN_COPY\|export .*CIRCUIT_OPEN_COPY" src/ tests/   →  0 hits
```

Because nothing is exported, the twelve test literals **cannot** be reads of the module under test.
They are hand-typed literals — which is exactly correct oracle independence — and
`src/app/api/keys/sync/route.seam.test.ts` says so out loud in a comment. **Consolidating them onto
the new leaf would convert twelve independent oracles into one self-referential oracle: it would
MANUFACTURE the defect the locked text mistakenly believes already exists.**

⇒ **Leave all twelve test literals exactly as they are.** The real gap is the other direction —
production↔production — and it is closed by ONE new pin file.

## ⚠️ Grep the STRING, not the symbol

Six of the twelve tests declare a named `const CIRCUIT_OPEN_COPY`; **six inline the literal in the
assertion**. A plan that greps the symbol finds 6 of 12 — the exact under-delivery shape this
programme keeps hitting. The same applies on the production side: nine are `CIRCUIT_OPEN_COPY`, the
tenth is `CIRCUIT_OPEN_HUMAN_MESSAGE`. **Every enumeration in this plan greps the sentence.**
