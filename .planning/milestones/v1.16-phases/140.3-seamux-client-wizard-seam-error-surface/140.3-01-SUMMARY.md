### 1. [Rule 2 — missing critical functionality] The machine code needed somewhere to live at two of the three sites

- **Found during:** Task 1.
- **Issue:** the plan's `must_haves.truths[0]` requires all three sites to read *"the machine code
  **and** the human string through the one discriminator"*. At `analytics-client` and
  `keys/[id]/permissions` there was no existing field to put the code in, and an unread extraction
  would have been dead code that lint would flag.
- **Fix:** `AnalyticsUpstreamError` gained an **additive, optional** `seamCode` (defaults `null`, so

  `{ code: seamCode }`, and the `cause` is **omitted entirely when the code is null** so non-seam log
  lines stay byte-identical to their pre-plan form. `code` is already in `seam-redaction`'s
  `PLAIN_OBJECT_DIAGNOSTIC_KEYS` **and** in its `SAFE_PROPERTIES`, so it renders as
  `[cause: code=SEAM_DEGRADED]` and carries no credential.
- **Why this is not TS-34:** TS-34 is *mapping* `RATE_LIMITED` to a throttle state, answering 429
  instead of 502 and forwarding `Retry-After`. None of that happened. Carrying the code so the later
  plan does not have to re-extract is the opposite of TRAP-8 — it stops that plan needing to touch
  the extraction again.
- **Files:** `src/lib/analytics-client.ts`, `src/app/api/keys/[id]/permissions/route.ts`.
- **Commit:** `9a74e3f5`.
