## The predicate, verbatim (the rule's published contract)

> **Flag an `await`ed PostgREST call expression whose result is destructured — in EITHER the object
> form (`const { data } = await …`) or the ARRAY form inside a `Promise.all` — where no binding for
> `error` is introduced, and the chain is not terminated by `.throwOnError()`.**

Operationally, as implemented and as measured:

- **PostgREST call** = the member/call chain contains a `.from(…)` or `.rpc(…)` call **and** contains
  no `storage` segment.
- **Unchecked** = the ObjectPattern binds a `data` **or** `count` KEY and binds no `error` KEY.
  `error` must be the **KEY**, never the local name — so `{ data: error }` is still reported and the
  rule is **not rename-satisfiable**.
- **Array form** = each element is matched **positionally** against its own `Promise.all` argument and
  judged **independently**, so a partially-checked `Promise.all` reports only the unchecked members.
- `...rest` and `.throwOnError()` satisfy the check.

### Measured population under THIS predicate

`155 sites in 75 files` over `src/**/*.{ts,tsx}` at the 140.4 tree (measured with the rule itself via
the ESLint Node API, filtered on `ruleId`, **not** a grep paraphrase). It is higher than the mapper's
73 chiefly because it also sees the array form and counts each unchecked member separately.

⚠️ **First measurement of this was WRONG and the correction is worth recording**: an unfiltered count
returned **385 sites in 123 files**, because ESLint reports *unknown-`eslint-disable`-directive* errors
alongside rule reports when run with an override config. Filtering on
`ruleId === "quantalyze/no-unchecked-supabase-read"` gives 155. A number is only as good as the
predicate *and the harness* that produced it.

### The rule's message (names the canonical shape, not just the prohibition)

> "Unchecked PostgREST read: this destructure takes `data`/`count` but never binds `error`. supabase-js
> resolves a failed read AS A VALUE, so an unchecked destructure is indistinguishable from real data — a
> null count coerced by `?? 0` renders as a measurement nobody took (SEAMRIM-11 / C-3). **Use the
> checked-read shape the codebase already uses: bind it and fail loud — `const { data, error } = await …;
> if (error) throw …` (or the whole-result form `const res = await …; if (res.error) throw …`) — or
> terminate the chain with `.throwOnError()`.** If this is a deliberate exception, add a
> `SEAMRIM-11 sanctioned-exception:` comment in this file."
