## Part 1 — derive `SEAM_FILES` from the IMPORT EDGE, not from the budget table

### The conflict, surfaced as CONTEXT §5 requires

`src/lib/seam-log-coverage.test.ts`'s own docblock argues **against** deriving:

> *"The eight seam files. Hand-typed, and **deliberately NOT derived from `SEAM_ROUTE_BUDGETS`**: that
> table lists fifteen ROUTES, of which **only five carry credential-bearing error logs**, and a
> derived list would **silently widen or narrow** this guard whenever the budget table moved."*

**Half 1 — "would silently WIDEN": REFUTED, and the cost was measured.** Widening is the point. The
guard's own predicate, ported over the derived roster at plan time, reports **27 sites across 9 of the
18 derived members, and 0 on the current 8** — the roster's members are clean and the hole's shape is
exactly the roster's complement. Those are not false positives: each catch stands over the **original**
undici error, because `resilient-fetch.ts` rethrows it (*"wrapping here would silently reclassify every
timeout in the codebase"*). Plans 07/08/09 have already closed all 28.

**Half 2 — "would silently NARROW": REAL, and the review's WP-1 does not close it.** Delete a row → a
file leaves the roster → the guard stops watching it, with green CI and nothing to see in the diff.
**This plan closes it with a set equality in both directions**, which a `toHaveLength` pin cannot do —
mutation M14 measured that a *swap* passes a count check.

**Half 3 — "not a lint rule on purpose": SURVIVES.** The predicate needs per-file `catch`-binding
state. It stays a test.

### The source: the import edge, which sidesteps the objection entirely

The docblock argues only against deriving from `SEAM_ROUTE_BUDGETS`. It says nothing about the
**third** derivation that already exists and is the *causal* definition of membership: a file is a
seam file iff it **imports one of the three seam modules**.
`src/lib/seam-poll-disjointness.pin.test.ts` already implements it (`SEAM_MODULES`, `SEAM_IMPORT_EDGE`,
`deriveSeamRoutePaths`) and it is CI-wired in two files. A roster derived from the import edge does not
move when the budget table moves; it moves when a route starts or stops importing the seam — which is
exactly when it should.

⚠️ **This SUPERSEDES the review's WP-1 as written** (*"derive `SEAM_FILES` from
`SEAM_ROUTE_BUDGETS ∪ SEAM_EXCLUSIONS`"*). That source is measurably a **superset**: the union contains
`debug-key-flow` and `cron/warm-analytics`, excluded precisely because they do **not** enter the core,
so folding them in adds two files the guard has no business inspecting.
