<objective>
Close the wire↔render vocabulary boundary by **removing a roster's jurisdiction**, not by widening it.

## The structural defect, measured

`SubmitStep.tsx`, in the finalize response handler:
```ts
const translated = recogniseSeamErrorCode(data.code);
const candidate  = translated === "UNKNOWN" ? data.code : translated;
const surfaced: WizardErrorCode =
  candidate && KNOWN_FINALIZE_CODES.has(candidate as WizardErrorCode)
    ? (candidate as WizardErrorCode) : "UNKNOWN";
```
A **successfully translated** code must still pass a second, independently-maintained membership
check. `KNOWN_FINALIZE_CODES` is already a `ReadonlySet<WizardErrorCode>` — so the second gate adds
**no type safety**; it adds only an obligation to edit two lists. That obligation is written down
**twice inside the set that drops the codes** (both saying *"admitted HERE IN THE SAME COMMIT"*) and
was skipped for the two codes `140.3-01` minted.

**Consequence, confirmed by set arithmetic (CONTEXT §5):**
`RATE_LIMITED` and `VALIDATION_FAILED` **are** in `SEAM_CODE_TO_WIZARD_CODE` (6 members, added by
`140.3-01`) and **are not** in `KNOWN_FINALIZE_CODES` (9 members) ⇒ both collapse to `UNKNOWN`.

> **`140.3-01` ships with ZERO user-visible effect for the two codes it added.** The honest
> `RATE_LIMITED` copy — *"the cap is ours, not your exchange's"* — **exists and is unreachable**,
> while `KEY_RATE_LIMIT`, the one that blames the exchange, renders. C-5 measured that copy emitted at
> **three** sites for **our own** limiter, contradicting `wizardErrors.ts`'s own stated contract.

## The remedy — ROW 1, because it deletes a roster's jurisdiction rather than adding to it

```ts
const translated = recogniseSeamErrorCode(data.code);
const surfaced: WizardErrorCode =
  translated !== "UNKNOWN"
    ? translated                                   // the ONE wire→wizard table is the authority
    : data.code && KNOWN_FINALIZE_CODES.has(data.code as WizardErrorCode)
      ? (data.code as WizardErrorCode)             // route-minted wizard codes only
      : "UNKNOWN";
```
This restores each list to what it actually is: `SEAM_CODE_TO_WIZARD_CODE` owns **wire** codes;
`KNOWN_FINALIZE_CODES` owns **route-minted wizard** codes (`KEY_SCOPE_BROADENED`, `GATE_DRAFT_GONE`,
`GUARD_BLOCKED`, …). **The membership check is not weakened** — an unrecognised wire code still falls
to `UNKNOWN` by both paths.

⚠️ **Do this INSTEAD of adding `VALIDATION_FAILED` + `RATE_LIMITED` to `KNOWN_FINALIZE_CODES`.**
Adding them is coverage-law **ROW 2 — a hand-typed roster, partial by construction** (measured 9/37
codes · 8/15 files · 2/3 codes) — and it leaves the next author with the same two-list obligation the
last three commits demonstrably failed to discharge. **The test that the change is structural rather
than another roster edit is that the two codes become reachable without touching either list.**

## What is NOT in scope, and why — say this in the plan rather than discovering it later

**A total wire→render mapping is IMPOSSIBLE.** `analytics-service/services/ingestion/csv_adapter.py`
emits `error_code=first_rule.upper() if first_rule else "CSV_VALIDATION_FAILED"` — a **pandera check
name**, uppercased. Traced to source, the rule name may contain parentheses and commas, so it is not
even a valid identifier after `.upper()`. **That is an open string set with no registry**, so no closed
union and no exhaustiveness check can ever be total over the Python side. **Any plan promising a total
mapping is promising something unachievable.** This plan closes the TS-controlled half and says so.

**27 of the 53 TS wire codes are lowercase, and that is a two-vocabulary CONVENTION, not 27 bugs**
(CONTEXT §5c): every lowercase one is an operator/diagnostic code on an admin or account route
(`would_orphan_last_admin`, `rpc_shape_drift`, `ratelimit_misconfigured`, …); the 26 SCREAMING ones are
the user-facing seam/wizard vocabulary. **0 of the 37 Python literal codes are lowercase.** The sole
offender that crosses into the wizard surface is **`draft_state_invalid`**, TS-minted by us at

`wizardErrors.ts` already records it as knowingly out of scope in the TS-35 ledger row. **Record it;
do not normalise 27 codes.**

**`WireErrorCode` (WP-11) is DEFERRED, deliberately.** A union scoped to the wizard/seam surface is
bounded and cheap (26 SCREAMING TS + 42 Python literal); a repo-wide union spans **two deliberate
conventions** plus an open Python set, and would either force the 27 operator codes into a vocabulary

with a real chance of being wrong, and the coverage law does not reward rushing a shared artefact.
**Record what a union would uniquely close — `draft_state_invalid` becomes a COMPILE error, because it
is TS-minted — as the strongest argument for whichever phase picks it up.**
