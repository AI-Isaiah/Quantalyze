## ⚠️ §4's RECORDED FIX IS WRONG. CONTEXT §5c SUPERSEDES IT. Read this before writing any SQL.

§4 says *"add `wizard_session_id` to the `strategies` INSERT so the already-live
`strategies_user_wizard_session_uniq` bites."* **That two-column index breaks legitimate first
submits, permanently.** The trigger is measured at source:

`src/lib/wizard/localStorage.ts:377-379` restores `wizardSessionId` **unconditionally on `source`**:
```ts
if (loaded.wizardSessionId) {
  out.wizardSessionId = loaded.wizardSessionId;
}
```
The `source === "csv"` branch immediately below gates only `step`, and there is **one shared storage
key** — `STORAGE_KEY = "quantalyze_wizard_state_v1"` (`localStorage.ts:51`) — for both wizards.
`clearWizardState` fires on submit / delete-draft / start-fresh only, so an **abandoned** API draft
leaves the payload intact.

Trace: user opens the API-key wizard → session `S` → `create_wizard_strategy` writes
`strategies(user_id, wizard_session_id = S, source='wizard')` → user abandons → user opens the CSV
wizard → `deriveWizardResumeOverrides` restores `S` → the CSV finalize collides on `(user_id, S)` →
the RPC aborts → **the user's first legitimate CSV submit fails, and every retry reuses `S`, so it
fails forever.**

**Therefore the index must be `(user_id, wizard_session_id, source)`.** API writers use
`source='wizard'` (`create_wizard_strategy.sql`, `add_wizard_composite_key.sql`), CSV uses `'csv'`, so
scoping by `source` preserves the existing API-path guarantee **exactly** and removes the cross-source
collision entirely. This is the classic TRAP shape: the naive fix breaks something else.

⚠️ **Pitfall, verbatim from `140.4-RESEARCH.md`: "Warning sign: an index definition with two columns."**
