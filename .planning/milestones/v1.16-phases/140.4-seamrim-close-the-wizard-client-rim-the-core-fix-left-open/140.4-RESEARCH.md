## Summary

The eight items are not eight problems. They are **three mechanism decisions and five applications of them.**

1. **Where a value can be wrong, make the wrong value unrepresentable at the boundary that produces it** — not at each of the places that reads it. This is the answer to C-3 (`throwOnError()` changes the *awaited type*), to the gate fail-open (`strategyGate` must not treat "unknown span" as "pass"), and to the wire↔render vocabulary (delete the second allow-list's authority rather than widen it).
2. **Where a roster must be complete, derive it from the edge that actually defines membership** — which for the seam is the *import edge over the three seam modules*, already implemented and already running in CI in two files. The synthesis's premise that no guard derives from anything but `/resilientFetch\s*\(/` is **refuted by measurement**.
3. **Where an observability sink must deliver on Vercel, use `after()` and return the promise** — a pattern this repo already worked out, documented and shipped in `src/lib/audit.ts` after a red team found the identical defect in May 2026. `sentry-capture.ts` re-created it.

Two things I found that the review did not, and that change the shape of the plan:

- **C-3's fail-open half exists at BOTH consumers of `checkStrategyGate`, and the second one is the admin *publish* gate.** `src/app/api/admin/strategy-review/route.ts:99-115` runs the same six-member `Promise.all` and checks `.error` on exactly two of them — while the file's own comments state the fail-loud rule twice, verbatim. On a timestamp-read failure it approves and writes `status: "published"`. Demonstrated by execution below.
- **The recommended C-2 fix has a reachable first-submit-breaking false positive**, caused by `deriveWizardResumeOverrides` restoring `wizardSessionId` across the CSV/API source boundary (`src/lib/wizard/localStorage.ts:377-379`). The fix must scope the index by `source`, or it converts a silent duplicate into a permanent loud failure on a legitimate first CSV submit.

**Primary recommendation:** land the three mechanism decisions first (Items 1, 4/5, 3), because Items 2, 6, 7 and 8 each become a small, bounded application of one of them; then treat the 139-site unchecked-read backlog and the 12-site scrub backlog as explicitly **partial by construction** ratchets, not as closures.

### RECOMMENDATION — three parts, two mechanisms, and an honest ratchet

**(1a) `strategyGate.ts` must fail CLOSED on an unrepresentable span. — MECHANISM ROW 1 (shared artefact: a domain leaf both tiers pass through).**

Inside the trade-sourced `else` branch, once `tradeCount >= STRATEGY_GATE_MIN_TRADES`, a `null` `spanDays` is a **contradiction**, not an absence: `StrategyGateInput` documents `earliestTradeAt` as *"Timestamp of the earliest trade, or null when no trades exist"* (`strategyGate.ts:31` [SOURCE]), and we are in the branch where trades demonstrably exist. Return a failure (`INSUFFICIENT_DAYS`, or a new `TRADE_SPAN_UNKNOWN`) rather than falling through to `PASS`.

*Why this is the highest-value single line in Item 1:* it closes the publish-side harm at **both** consumers, in one file, without touching either call site, and it holds even if a future third consumer forgets the checked read. **Cost:** one branch; two existing test files (`strategyGate` unit tests + `admin/strategy-review/route.test.ts`) may pin the current pass-through and will need the polarity re-derived — treat as TRAP-9 territory and land the stronger assertion in the same commit. **Rules out:** nothing.

**(1b) `.throwOnError()` at the reads, because on postgrest-js 2.110.1 it is a TYPE-level chokepoint, not a runtime convenience. — MECHANISM ROW 3 (per-site) for the 139-site backlog; ROW 1 for the *type* property at each converted site.**

Measured from the installed types, not from training data:

- `node_modules/@supabase/postgrest-js/dist/index.d.mts:733` — `throwOnError(): PostgrestBuilder<ClientOptions, Result, true>` [MEASURED]
- `:824` — `then<…>` resolves to `ThrowOnError extends true ? PostgrestResponseSuccess<Result> : PostgrestSingleResponse<Result>` [MEASURED]
- `:628-639` — `PostgrestResponseSuccess<T>` is `{ success: true; error: null; data: T; count: number | null }`; `PostgrestResponseFailure` is `{ success: false; error: PostgrestError; data: null; count: null }` [MEASURED]

**The consequence the planner must understand:** after `.throwOnError()`, `data` is `T`, **not `T | null`**. Every downstream `?? 0` / `?? null` on that value becomes provably dead code, and `tsc --noEmit` participates. The else-branch must be reshaped to the same success shape, or the conditional hoisted out of the `Promise.all`.

### Is it sufficient and safe?

**Sufficient: yes.** There is no alternative DB chokepoint. `strategy_verifications` has **no `user_id` column** — stated in the tenant-scope migration's own comment (`20260726000225.sql:38`, and again at `:127`: *"strategy_verifications has no user_id column; strategy_id is the tenant key"*) [SOURCE]. So a tenant-scoped uniqueness on the verification table is not expressible without a schema change. `strategies (user_id, wizard_session_id)` is the only available one.

**Transaction guarantee: correct, and stated at the site.** `finalize_csv_strategy` is `LANGUAGE plpgsql SECURITY DEFINER` with **no `EXCEPTION` block** (full body read, `:236-325` [SOURCE]). An unhandled 23505 aborts the function and the enclosing statement. The function's own comment at `:311-315` [SOURCE]: *"both inserts run in the same transaction (the SECURITY DEFINER function body is implicitly transactional). The FK check happens at COMMIT, not at the second INSERT."* So a duplicate submit rolls back both rows — the pre-migration behaviour.

**Safe: NOT as stated. There is a reachable false positive the review does not name.**

`src/lib/wizard/localStorage.ts:377-379` [SOURCE]:
```ts
if (loaded.wizardSessionId) {
  out.wizardSessionId = loaded.wizardSessionId;
}
```
This is **unconditional on `source`**. The `source === "csv"` branch immediately below (`:381-400`) only gates `step`. And there is one shared storage key — `STORAGE_KEY = "quantalyze_wizard_state_v1"` (`localStorage.ts:51` [SOURCE]) — for both wizards. `clearWizardState` fires on submit / delete-draft / start-fresh only, so an **abandoned** API draft leaves the payload intact.

Trace: user opens the API-key wizard → session `S` → `create_wizard_strategy` writes `strategies(user_id, wizard_session_id = S, source='wizard')` → user abandons → user opens the CSV wizard → `deriveWizardResumeOverrides` restores `wizardSessionId = S` → CSV finalize with the proposed column write **collides on `(user_id, S)`** → RPC aborts → the user's *first legitimate* CSV submit fails, and every retry reuses `S`, so it fails **permanently**.

That converts a silent duplicate into a loud, unescapable failure on a legitimate first submit. The direction is safe (fail-closed) but the product break is real.

### RECOMMENDATION — a three-part change, not one

**(2a) Write `wizard_session_id` in `finalize_csv_strategy`'s `strategies` INSERT AND re-scope the index to `(user_id, wizard_session_id, source)`. — MECHANISM ROW 1 (a DB constraint; the strongest chokepoint available).**

Adding `source` to the index preserves the existing API-path guarantee exactly (all API drafts carry `source='wizard'`, so uniqueness within that source is unchanged) while removing the cross-source collision entirely. It is a `DROP INDEX` + `CREATE UNIQUE INDEX` inside the same transaction as the function replacement, with a STEP-0 pre-flight duplicate check and a STEP-3 self-verify DO block — copy the structure of `20260726000225` verbatim (`:104-118` pre-flight, `:140-194` self-verify [SOURCE]), which is the newest and best-shaped migration in the tree.

*Alternative considered and rejected:* leave the index alone and fix only `localStorage.ts:377` to gate the restore on `loaded.source === source`. That removes the known trigger but leaves the guarantee dependent on client discipline for a DB-level invariant — and the failure mode if a second trigger is ever found is a permanent user-facing dead end. Do **both** if you like (the client gate is one line and independently correct), but the index scope is the load-bearing half.

⚠️ **Migration hygiene, from this repo's own recorded history:** `supabase/tests/test_wizard_session_idempotency.sql:46-51` [SOURCE] asserts the index **by name** and asserts it is UNIQUE. Re-scoping it means that file changes in the same commit. And per MEMORY, apply to the TEST project (`qmnijlgmdhviwzwfyzlc`) via MCP **before** merge, because merge auto-applies to PROD.

**(2b) A 23505 arm in `process_key.py`. — MECHANISM ROW 3 (per-site), and it is a bounded set of one.**

### RECOMMENDATION (3b) — the limiter and the breaker should NOT have the same posture. Here is the argument.

**That argument survives, and I would not change either posture.** The asymmetry is correct because the two components protect different parties:

- Socket refused → 5 retries with `Math.exp(i)*50` backoff ≈ 4.29 s → **races** the 5 s sentinel → **non-deterministic**. [CITED, 140-VERIFY-C3-C5.md §(b), measured there against the installed dists.]

**So the recommendation is: keep both postures; make the *mode* observable.** `checkLimit` should distinguish the timeout sentinel from a genuine allow — the sentinel's `reason: "timeout"` is already on the wire and is currently discarded at `ratelimit.ts:317`. Reading it costs one destructure and turns the silent fail-open into a recorded one. **MECHANISM ROW 1** (one leaf, all callers).

**Two halves. One transfers perfectly; the other does not.**

**Does NOT transfer — `_source_name_tokens`.** `:140-155` [SOURCE] uses Python's `tokenize` and keeps only `NAME` tokens, deliberately: *"comments and strings are other token types."* That is the right tool for *"does this file reference this symbol"*. 1. Walk `routers/` + `services/` + `main.py` with `ast`.
2. Collect every `raise HTTPException(...)` and every `JSONResponse(...)` whose `status_code` is an integer literal `>= 500`.
3. Assert the resulting `{(file, lineno-independent key)}` set **equals** a hand-typed quarantine keyed on `(module, function name, status)` — **not on line numbers**, because P2 measured 19 citations checked / 5 wrong and three in-range commits each broke some.

### ⚠️ A correction that changes the answer

CONTEXT §6 fences off the DESIGN.md §Error Envelope rule as *type-impossible* because `buildEnvelope(code: WizardErrorCode)`. A non-wizard surface *can* construct the object literal and render `<ErrorEnvelope>` without touching `buildEnvelope` or `WizardErrorCode`.

### RECOMMENDATION — a `<LiveRegion>` primitive, not `ErrorEnvelope`. — MECHANISM ROW 1 (a shared component), and it is DESIGN-neutral by construction.

`ErrorEnvelope` carries a **visual contract**: `border-negative/30 bg-negative/5`, a locked title typography (*"16px DM Sans semibold #1A1A2E … REQ DESIGN-02"*), a fix-step list, a Copy-diagnostics block, and a Retry/Cancel control pair (`ErrorEnvelope.tsx:8-30`, `:132-140` [SOURCE]). - requires reading and conforming to `DESIGN.md` and, under CLAUDE.md, **explicit user approval**;
- entangles an a11y regression fix with the founder-owned §Error Envelope decision that CONTEXT §6 explicitly fences off;
- means those surfaces must now mint a `code` and a `correlation_id`, which is the pressure that would push someone toward `buildEnvelope` and straight into the fenced decision.

```tsx

  return <p role={assertive ? "alert" : "status"} aria-live={assertive ? "assertive" : "polite"} className="sr-only">{message}</p>;
}
```
The idiom is already in the tree verbatim at `src/components/ui/CardShell.tsx:77` [SOURCE] — `<p role="status" aria-live="polite" className="sr-only">` — so this is an **extraction, not an invention** (Rule 11).

**Cost:** one new primitive file + one line per surface + one assertion per surface. **Rules out:** nothing in scope. It does **not** discharge the DESIGN.md §Error Envelope question — that stays founder-owned and untouched, which is the point.

## Common Pitfalls (specific to this phase)

### Pitfall 1 — "widen the roster" is landed without landing the scrubs
**What goes wrong:** the derived roster reddens 8 routes / 12 sites immediately; CI is red on merge and the pressure is to narrow the roster back.
**Avoid:** land the 12 scrub edits **first**, then the derivation, in that order. Verify with the **full** suite between them.
**Warning sign:** a commit that adds the derivation and an exclusion list in the same diff.

### Pitfall 2 — the C-2 migration lands without the `source` column in the index
**What goes wrong:** a user with an abandoned API draft gets a permanent, unescapable failure on their first CSV submit (traced above from `localStorage.ts:377`).
**Avoid:** the SQL test's cross-source control case (assert a CSV finalize with a session id already used by a `source='wizard'` draft **succeeds**).
**Warning sign:** an index definition with two columns.

### Pitfall 3 — the breaker capture lands before the delivery fix
**What goes wrong:** an alert that is never delivered, and the phase records the finding as closed. The subject's own docblock forbids it (`resilient-fetch.ts:898-901`).
**Avoid:** `captureToSentry` returns its promise and the seam route arms `after()` it **first**; the breaker capture second.

### Pitfall 4 — a scoped-green run
**What goes wrong:** measured five times in this programme; mutation M8 in run 2 was **GREEN on both files named "rate limit"** and RED only on the full pytest run.
**Avoid:** CONTEXT §8 — full suite, never a scoped path.

### Pitfall 5 — TRAP-9 on the two tests that pin regressions
**What goes wrong:** `test_pyapi_09c_…` (C-2) and `csv-validate-route.test.ts:382-397` (C-1's residual) each require deleting or rewriting an assertion. A relaxed assertion silently deletes coverage.
**Avoid:** land the strictly stronger replacement **in the same commit**, and re-scope rather than delete where the old assertion still proves something true (the C-2 case).

### Pitfall 6 — line-number citations in the new guards
**What goes wrong:** P2 measured 19 citations checked / 5 wrong, including `2d58fd45`, whose stated purpose was *"a pointer cannot drift"* and which invalidated four.
**Avoid:** key the 5xx quarantine on `(module, function, status)`, never on `lineno`. Prefer symbol references in every new docblock.

### Pitfall 7 — restating TRAP-1 and TRAP-4 as instances
**Avoid:** TRAP-4 as the property — *a terminal error render must not offer a destructive control as the sole affordance, nor place a retry beside one; this is a property of the render, not of a code list; treat `recoverable` as unreliable because `try_another_key` earns it for codes whose only retry is destructive.* TRAP-1 as the property — *no caught value, nor any alias of one, may reach a log or a response body unscrubbed* (strike the two named sibling files; the measured leaks are at three files the rule never names, and the live one is an **alias**).
