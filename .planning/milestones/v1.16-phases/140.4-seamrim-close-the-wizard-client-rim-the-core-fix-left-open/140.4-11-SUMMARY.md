## How the pin's population is derived

Test: `PROPERTY — no reachable terminal code renders the destructive control as its SOLE affordance`

Every row of the driven table is a **production INPUT** — an HTTP arm, a thrown fetch, or a
`checkStrategyGate` fixture — described by what it *is* (`"kickoff 404 (uniform across 'no such
draft' and 'not yours')"`, `"gate: keyed account with trades spanning under a week"`), never by the
code it produces. The code under test is **read back off the rendered envelope's
`data-error-code`** and collected into a `Map`. The table therefore never states which code a
scenario yields — `KNOWN_KICKOFF_CODES` and `gateFailureToWizardError` decide, and the pin follows.
Re-point either at a different member and the population moves with it, silently and correctly.

Three guards sit on top of it:

1. **Drive check per row** — a row whose envelope carries no code fails immediately, naming the
   input. A row that cannot name its state cannot pin a property about it.
2. **Vacuity fence** — `expect(observed.size).toBeGreaterThanOrEqual(11)`, hand-typed (never
   `scenarios.length`, which would measure the loop against itself), with the message *"A loop that
   renders nothing satisfies every assertion inside it and reports agreement forever — which is
   worse than having no guard at all."* Proven live: raising it to 12 fails with `expected 11 to be
   greater than or equal to 12`.
3. **Set-level restatement** — after the loop, the observed map is filtered for entries whose whole
   control set is `["key-replacement"]` and asserted empty, so a per-row escape cannot hide it.

The **oracle** is separate from the population and hand-typed on purpose:
`CODES_THAT_EARN_KEY_REPLACEMENT = ["GATE_INSUFFICIENT_TRADES", "GATE_INSUFFICIENT_DAYS"]`.
Deriving it as `actions.includes("try_another_key")` would compare production's answer to
production's answer and could never fail — Oracle Independence hazard #6 in its classic form. A
twelfth code arriving is asserted *not* to render the destructive control, which is the safe
default.

**Positive counterpart** (a negative-only oracle is what M-9 measured going vacuous):
`POSITIVE — GATE_INSUFFICIENT_TRADES DOES earn the key-replacement control`. Without it, a render
that dropped every control from every state would satisfy every negative in the file while
destroying the wizard's primary recovery route.

**Named mislabel case:** `GATE_INSUFFICIENT_TRADES renders NO Retry — handleKickoffRetry
re-evaluates an IDENTICAL gate`.
