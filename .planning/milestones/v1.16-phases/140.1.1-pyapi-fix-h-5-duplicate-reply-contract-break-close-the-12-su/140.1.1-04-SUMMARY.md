## Why the 424 was worse than it looks (H-2)

`services/exchange.py` `create_exchange` is `EXCHANGE_CLASSES.get()`, a dict build,
`cls(config)` and two attribute sets. **Zero network I/O.** Nothing has been sent to any
venue when these arms fire, so every non-`ValueError` escape is a `TypeError` /
`AttributeError` / `ImportError` / OOM in our own adapter construction.

As a `424` it was breaker-inert **and** a 4xx, so a plain bug in our code counted against
nothing and paged nobody — while the body told the user their exchange was down. As a
`400` it blamed the caller's *request* for our bug, an accusation they cannot act on. Both
verdicts are self-concealing in the same direction.

## Task 2's `dependency`-drop is enforced upstream, not just intended

Worth stating plainly because it is the mechanism this phase is supposed to demonstrate:
plan 01 landed the guard, plan 04 consumed it. Had B1's fix been written the naive way —
carrying `dependency=str(exchange_name)` onto the new 500 — it would have raised at
import-adjacent construction time and the test would have errored, not silently shipped.
That is "enforce, don't document" working across two plans in one phase.

## Decisions Recorded

### 1. OQ-2 resolved — `ADAPTER_INIT_FAILED`

Three candidates were live. `EXCHANGE_INIT_FAILED` (the shipped B1 code) **names the
venue**, and `dependency` is the one field 140.2 discriminates on — a code asserting
"exchange" beside `dependency: null` and `retryable: false` is a body arguing with
itself. `INTERNAL` (the S-06b analog's code) is correct but non-specific: PATTERNS
explicitly said copy the *shape*, not the string, and collapsing a distinct, greppable
adapter-construction failure into the generic bucket destroys the discriminator's value
for the exact class this plan exists to make visible.

`ADAPTER_INIT_FAILED` names **our adapter construction**. Registered in
`STATUS_CONTRACT.md` §7 so 140.2 does not have to re-derive it.

### 2. B3 — the member found only because the mapper ran

The review named **one** site. RESEARCH named **two**. The pattern-mapper found
**three**. B3 differs from B2 by a single letter — `initialise` vs `initialize` — so
every `grep "Failed to initialize"` sweep, including the ones that produced the review,
missed it.

This is recorded as a durable lesson in `STATUS_CONTRACT.md`: **the enumeration predicate
for this class is "an `except` arm around a callee that performs no network I/O", not a
copy string.** A point-fix of the named site would have shipped a 2-of-3 closure with a
fully green suite — the instance-not-class defect the mapper exists to catch.

The in-repo proof the class was real: `verify_strategy` calls `create_exchange` **twice**,
~50 lines apart, and the second call's handler (B4) already answered `500`. One function,
one callee, two verdicts.

### 3. `ValueError` → `400` preserved at all three sites, and pinned

`create_exchange` raises `ValueError` for a name absent from `EXCHANGE_CLASSES`, and that
name comes off the caller's request (B2/B3) or their own `api_keys` row (B1). That IS
caller input. Three new tests pin it so the remap cannot later widen into "every escape
is a 500", which would blame us for a venue we never supported. All three arms are
**byte-unchanged** in the diff.

### 4. No `ValueError` arms were added where none existed

The plan permitted adding a `ValueError` → 400 arm only if `create_exchange`'s
`ValueError` can actually reach the site. **All three already had one**, so nothing was
added — no dead arms.

## Oracle Discipline (programme non-negotiable #3)

Zero self-referential oracles, verified by construction:

- Neither new test file imports **anything** from `services.error_contract` or from the
  `routers.*` module under test beyond the handler being driven. `500`, `400`,
  `"ADAPTER_INIT_FAILED"` and the copy sentence are **literals typed into the test files**.
- `test_create_exchange_attribution.py` declares its own `_ADAPTER_INIT_CODE` and
  `_ADAPTER_INIT_COPY` module constants. This is deliberate and load-bearing: the whole
  claim being tested is that three sites do not drift, and an oracle that read the string
  out of one of them could not detect drift in the other two.
- The S-11 rewrite and `test_service_key_log_companion.py` pin **whole response bodies as
  dict literals**. B1's entire defect was an *extra field* (`dependency`), which a
  key-by-key assertion is structurally incapable of catching.
- The log tests assert literal event names, literal `log_level` strings and literal
  counts — never a value read back from `main`.

## TS-consequence note (no code change here — recorded for 140.2)

B2 and B3 now emit an **object** `body.detail` where they previously emitted a scalar
string. Per `STATUS_CONTRACT.md` §2's standing obligation, `src/lib/analytics-client.ts`
renders that as the generic dead end until 140.2 reads `body.detail.detail` (O-5).

**For these three sites that render is CORRECT, and this is the distinction worth
carrying.** A SERVICE-PERMANENT fault has no user remedy and no wait worth advertising —
a dead end is an honest one. That is the opposite of M-4's venue-transient case, where a
generic dead end *hides* a real "try again shortly". TS-05 sharpens the rendering later;
nothing here is blocked on it. `/api/verify-strategy` (B3) is on the doc's
not-seam-reachable list, so its envelope change is for log/operator consistency rather
than any TS renderer.

### 1. [Rule 2 — missing critical functionality] Two stale claims elsewhere in the files being edited

- **Found during:** Task 1, after the S-11 row edit.
- **Issue:** the plan mandates updating `STATUS_CONTRACT.md`'s S-11 row. But **§5**
  ("Why an exchange fault is 424") states the `424` code vocabulary as
  "`EXCHANGE_PROBE_FAILED` / `EXCHANGE_INIT_FAILED`" — naming a code that, after this
  plan, exists at zero raise sites. And `routers/internal.py`'s own handler docstring
  (`:216-217`) told the reader `424 — the caller's EXCHANGE failed to connect or to
  answer the probe (S-11/S-12)`, which is false for S-11 the moment the arm changes.
  Both sit in files already in the plan's `files_modified`.
- **Fix:** §5 now names only `EXCHANGE_PROBE_FAILED` and carries a scope note — this
  section answers *"the user's exchange is down"* and does **not** license venue
  attribution merely because a venue name is in scope; **the test is whether we actually
  spoke to the venue on that path.** The `internal.py` docstring's `424` line now covers
  S-12 only, and its `500` line names S-11 with the no-network-I/O reason.
- **Commit:** `d04c2afa`.

### 2. [Rule 2] B2 and B3 became 5xx-capable, which falsifies the S-table's completeness claim

- **Found during:** Task 2.
- **Issue:** §7 declares itself "the authoritative enumeration of every 5xx-capable site
  reachable from the seam". B2 and B3 were `400`s, so their **absence was correct**. The
  remap makes them 5xx-capable, and leaving them out would silently break the one
  property that table exists to guarantee.
- **Fix:** a registration block under the S-11 note listing both sites with endpoint,
  trigger, class and emitted envelope, explicitly **not** numbered into `S-nn` (neither
  is a remap of an existing S-row — the same convention the doc already uses for the
  PYAPI-04 and PYAPI-07/08 additions). It also records the British-spelling find and the
  B4 in-function proof, so the next reader does not have to re-derive the class.
- **Commit:** `637074b0`.

Everything else executed exactly as written. No architectural changes, no package
installs, no `ValueError` arms added, no `B4`/`B5–B8` sites touched.
