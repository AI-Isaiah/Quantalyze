### TD-3 (MED-HIGH) — `dependency` holds TWO disjoint vocabularies, discriminated by a different field
On 500/503 it is one of ours (`:117`, `:165`); on 424 it is the caller's venue (`:174-180`).
`_validate` enforces the disjointness, but a consumer reading `body.detail.dependency` in isolation
cannot tell which vocabulary it is in — **and Phase 140.2's breaker key-builder is exactly such a
consumer.** Safe today only because 424 is 4xx and gets filtered by status first.
**Split the wire field into `dependency` (always ours) and `venue` (always theirs) BEFORE 140.2 keys
on it** — makes I-12 structural and the breaker key correct with no status side-read. Cost: one
additive key + a deprecation.

### TD-4 (MED) — `_ROUTE_TERMINAL_ERROR_CODES` needs the opposite polarity and doesn't get it
`process_key.py:363-372` enumerates codes **this route mints itself**, which must default *terminal* —
but `:397-403` applies a single uniform "unknown ⇒ recoverable" default to both universes. The comment
at `:352-356` says the two fail safe in opposite directions; the code implements one and compensates by
enumerating the other exhaustively. **Verified complete today** (5 codes: `CSV_FINALIZE_FAILED`,
`MISSING_STRATEGY_ID`, `STRATEGY_NOT_OWNED`, `UNKNOWN`, `VALIDATION_UNEXPECTED`). But a **sixth
route-minted code added later and not registered ships `recoverable: true` on "you don't own this
strategy" — inviting infinite retry.** No structural link between "codes this route mints" and the set.

### TD-5 (MED) — two required parameters can only ever be wrong
Across all **24 live call sites**, `retryable` is a pure function of `status_code` (500→False ×13,
503→True ×5, 424→True ×2, 4xx→False ×4, **zero exceptions**), and `retry_after` on a 503 is literally
`RETRY_AFTER_SECONDS[dependency]` at all five sites. Five `_validate` arms exist to check the caller
re-derived values the contract already fixes. Textbook unrepresentable-vs-validated. Proposed
five-function API (`transient`/`permanent`/`venue`/`caller`/`throttled`) is **smaller** than the
130-line `_validate` it replaces and `mypy --strict`-checkable.

### TD-6 (LOW-MED) — leaks around the builder

only I-16); zero external callers today. `RETRY_AFTER_SECONDS` is `Final[dict]` — `Final` stops

### TD-7 (LOW-MED) — the cross-language coupling is CONVENTIONAL, not structural

### On the known `long_fetch` divergence (judged, not re-reported)
The design consequence is that "permanent" is a property of a **code** in one universe and of a
**code + which module is asking** in the other — the same `MISSING_SCOPE` is terminal at the route and
infinitely retried by the worker. The in-code divergence note is honest and the scope call was right.
**But the resolution should be typed** (one `ErrorCode` enum carrying `permanent: bool`, replacing all
three sets) rather than re-pointing one set at another — re-pointing preserves the possibility of the
next divergence.
