# Phase 140.1.1 Plan 01: error_contract Class-C guard gaps — Summary

Closed all four Class-C guard gaps in `analytics-service/services/error_contract.py` —
C1 (scalar `detail` unenforced), C2 (a 429 with `Retry-After` was unconstructable),
C3 (the `>=500` arm accepted a venue `dependency`), C4(a) (a 503's `Retry-After` was
untied from `RETRY_AFTER_SECONDS`) — with 4 new test files, 48 new tests, and the two
doc reconciliations that keep the arms from shipping already-falsified.

**PYAPIFIX-04 and PYAPIFIX-06 closed.** The circular deferral is broken: 140.2/140.3
are TypeScript-only and 146 is rate-limit-only, so none of these could reach an owner.

## What Was Built

| Guard | Location | Form |

| **C2** — 429 arm | `_validate`, after the 424 block, before the generic CALLER arm | `dependency` forbidden · `retryable` required · positive `retry_after` required · `return` so the generic arm never sees a 429 |
| **C3** — 500 dependency | `_validate`, inside `if status_code >= 500:`, after the `retryable` check | `if dependency is not None and dependency not in SERVICE_DEPENDENCIES:` — MEMBERSHIP |
| **C4(a)** — 503 Retry-After source | `_validate`, 503 arm, after the `retry_after is None` check | `RETRY_AFTER_SECONDS.get(dependency)` → `None` raises (no transient arm) · mismatch raises (helper-site drift) |
| **C1** — scalar detail | `service_error_body`, before the dict literal | `if detail is not None and not isinstance(detail, str):` raise, naming the received type |

Exactly **5 hunks** in `error_contract.py` (`git diff 56fb7167..HEAD | grep '^@@'`):

## Decisions Recorded

### 1. PYAPIFIX-04's guard placement: `service_error_body`, not `_validate`

`grep -rn "service_error_body" --include='*.py'` returns exactly three hits, all inside
`error_contract.py`: the definition and two calls (`service_error`,
`service_error_response`). **Both** of those also call `_validate` first — so both
entry points pass through both functions and either location gives complete coverage.
RESEARCH round 1's stated reason for choosing `service_error_body` ("guarding
`_validate` covers only one entry point") is **false**; the conclusion survives on a
different ground: `_validate` does not receive `detail`, so putting the guard there
means widening a private signature and threading a sixth argument through two call
sites, while `service_error_body` already has the parameter.

**Consequence, and it is why this worked cleanly:** PYAPIFIX-06 (Task 1) lands in
`_validate` and PYAPIFIX-04 (Task 2) lands in `service_error_body`, so the two
requirements cannot collide in one hunk even though CONTEXT.md describes them as "the
same function".

### 2. A 429 carries `retryable: true` (OQ-4b) — decided here, doc moved with it

The alternative was exempting 429 from the `retry_after` ⇒ `retryable` rule at
`:100-101`. That would emit `retryable:false` in the body while sending a `Retry-After`
header on the wire — literally the self-contradicting response R-1 forbids, and the
same defect PYAPIFIX-02 closes one requirement away in the same phase.

The decisive structural fact: **the 424 arm already REQUIRES `retryable=True` on a
4xx.** "4xx ⇒ not retryable" is the *generic arm's* rule, not an invariant of the
contract, and the file already carries a precedent for a 4xx that opts out. The 429 arm
is consistent with the existing structure, not a special case bolted on. The arm's
in-code comment cites the 424 arm for this reason.

Per C-21 the doc moved in the same plan: `STATUS_CONTRACT.md` §1 now has a dedicated
**CALLER, THROTTLED** row (`429` · `Retry-After` required · `dependency` forbidden ·
`retryable: true` · never counts) plus a `#### Why 429 is retryable: true` subsection
recording this reasoning. Without it the arm would have shipped contradicting the
table it is supposed to implement.

### 3. C4(a) uses `.get()`, never a bare index (checker W-2)

`kek` and `egress-proxy` ARE in `SERVICE_DEPENDENCIES` — so they pass the 503 arm's
membership check — but are deliberately ABSENT from `RETRY_AFTER_SECONDS`. A bare
`RETRY_AFTER_SECONDS[dependency]` would turn that contract violation into an opaque
`KeyError`, contradicting the module docstring's promise that "The guards raise
`ValueError`". `test_error_contract_retry_after_source.py` asserts
`pytest.raises(ValueError)` for exactly those two dependencies, so a bare-index
implementation **fails** the test rather than passing it by accident.

### 4. The 500 guard is MEMBERSHIP, never PROHIBITION

Six live sites legitimately name one of ours on a 500 (`internal.py:276`, `:292`,
`exchange.py:124`, `:242`, `:253`, `:525`) and seven pass none (`main.py:597`, `:691`,
`exchange.py:492`, `simulator.py:459`, `portfolio.py:1197`, `match.py:1797`, `:1881`).
A prohibition reading reddens all thirteen and destroys six operator signals. The four
permitted-dependency cases plus the `dependency=None` case in
`test_error_contract_500_dependency.py` are the executable fence against that
misreading — they exist *only* to fail if someone later "tightens" the guard.

`grep -n "dependency is not None and dependency not in SERVICE_DEPENDENCIES"` → **1 hit.**

## Oracle Discipline (programme non-negotiable #3)

Zero self-referential oracles across all four files, verified by construction:

- `RETRY_AFTER_SECONDS` is **never imported** by any of the four test files. The waits
  `15` / `16` / `30` / `31` are quoted literals, each carrying the comment
  `# Literal, NOT imported from RETRY_AFTER_SECONDS`. This is the exact discipline whose
  absence let the review's `RETRY_AFTER_SECONDS["supabase"] 15 → 900` mutation SURVIVE.
- `SERVICE_DEPENDENCIES` is **never imported**. `test_error_contract_500_dependency.py`
  types its own `OUR_DEPENDENCIES` list — an oracle that iterated the set under test
  could not fail when a member is removed from it.
- `_FALLBACK_DETAIL` is **never imported**. The fallback is asserted as the quoted
  string `"The request could not be completed."`.
- The positive 429 case asserts `Retry-After == "30"` — a quoted **string** literal, so
  it pins the *wire* value rather than reading back the `retry_after=30` int argument.
- Every non-scalar in `test_error_contract_scalar_detail.py` is built in the file.

## Deviations from Plan

One, and it is additive rather than a change of direction.

**[Rule 2 — missing critical functionality] `STATUS_CONTRACT.md` §3 carried the same
false sole-source claim as the code docstring, and the new 429 row would have
contradicted it.**

- **Found during:** Task 3, while making the two mandated doc edits.
- **Issue:** the plan mandates editing `STATUS_CONTRACT.md` §1 (the 429 row) and
  `error_contract.py`'s `RETRY_AFTER_SECONDS` docstring. But §3 of the same document
  states the identical unqualified rule — *"A raise site reads
  `RETRY_AFTER_SECONDS["<dependency>"]`; it never inlines a number"* — with no
  qualification. Landing a `429` row that makes `Retry-After` **required**, while §3
  three sections later blanket-forbids the only way a 429 can obtain one, would create
  a fresh internal contradiction **inside the document being reconciled**. That is the
  precise failure C-21 exists to prevent ("the arm ships already-falsified otherwise"),
  just at a second site in the same file.
- **Fix:** narrowed §3 to per-dependency `503` waits, named the same two
  helper-bypassing sites (`routers/internal.py:227`, `main.py:526`) that the code
  docstring now names, and recorded that `_validate` now enforces the `503` half.
  Consistent wording across both artifacts.
- **Files modified:** `analytics-service/docs/STATUS_CONTRACT.md` (already in the
  plan's `files_modified` list — no new file was touched).
- **Commit:** `7454330c`.
- **Explicitly NOT done:** PATTERNS' C4 row forbids closing C4(a) and declaring C4
  shut. The unguardable half is **documented, not claimed closed** — both the code
  docstring and §3 now say in as many words that `_validate` cannot reach those two
  sites.
