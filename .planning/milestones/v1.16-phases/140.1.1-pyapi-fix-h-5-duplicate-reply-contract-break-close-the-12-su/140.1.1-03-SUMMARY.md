## The stubbing boundary, per duplicate arm

The plan's central constraint is that a second pair of agreeing mocks is not a fix. So
the only patched symbol in the entire file is `routers.process_key.get_supabase` — the
network dependency. `_wizard_duplicate_reply`, `_resume_duplicate_job` and the handler
itself are **never** patched (`grep -n "patch("` → **1 hit**, that one target), and the
file imports **nothing** from `routers.process_key` (`grep -c "^from routers\|^import routers"` → **0**).

| Arm | Fixture case | What the DB fake returns | What the route then does, unforced |
|---|---|---|---|
| `queued:true` | `queued_true_resumed_wedge` | `strategy_verifications.status = "draft"`; `compute_jobs.status = "pending"`; `enqueue_compute_job` → `"job-under-test"` | `_is_long_fetch` true + status in `_RESUMABLE_VERIFICATION_STATUSES` → real enqueue → `queued: true, job_state: "enqueued"` |
| `queued:false` | `queued_false_finished_duplicate` | `strategy_verifications.status = "published"` | status not resumable → `(False, "not_applicable")`, no enqueue → `queued: false, job_state: "not_applicable"` |

**Both arms are selected by DB state alone.** The request body is byte-identical between
them (`_onboard_body()`, one function, no parameters) — so the two replies differ because
the *route* decided differently, not because the test asked for a different reply. That is
what makes this a contract test rather than a shape assertion.

The gate the duplicate path needs (`process_key.py`'s
`idempotent_by_session = flow_type != "teaser" and bool(context.wizard_session_id)`) is
constructed explicitly: `flow_type: "onboard"`, `source: "okx"`, and a literal
`wizard_session_id`. **No live TypeScript caller sends one today** — H-5 is latent, per
CONTEXT's second correction — which is exactly why the pytest has to build the state by
hand.

## The five cases, and why each exists

| # | Case | `expect_valid` | Why it is in the corpus |
|---|---|---|---|
| P1 | `queued_true_resumed_wedge` | `true` | The shape PYAPI-09 introduced and the guard **rejects at HEAD** (`queued:true` carrying `code`+`idempotent`) → 502 + Sentry. The defect itself. |
| P2 | `queued_false_finished_duplicate` | `true` | The **regression control**. This arm was accepted before PYAPI-09 and must stay accepted; without it a widening that simply stopped inspecting `queued` would look correct. |
| N1 | `queued_absent` | `false` | No `queued` key. The read site's `?? true` fallback is why `queued` was made required in the first place — a missing key must be refused, not coerced. |
| N2 | `empty_code` | `false` | `typeof "" === "string"`, so a type-only check renders an unnamed condition as a named one. |
| N3 | `idempotent_without_duplicate_code` | `false` | `queued:true` + `code:"OTHER"` + `idempotent:true`. **This is the anti-degradation case**: it forces plan 05's widening to be scoped to the `WIZARD_DUPLICATE` contract instead of collapsing to `() => true`. |

`test_negative_cases_are_not_shapes_the_route_can_emit` checks the negatives are
**unreachable**, not merely unwanted: each must differ from both proven-real shapes in
key set or in `code`. A negative the route can actually produce would turn plan 05's
guard into a 502 generator on live traffic.

## Oracle Discipline (programme non-negotiable #3)

Zero self-referential oracles:

- **Nothing is imported from `routers.process_key`** — not the reply builder, not the
  status frozensets, not the `"WIZARD_DUPLICATE"` string. An oracle that read its
  expectations out of the module under test could not fail when that module drifts,
  which is the defect being closed.
- **The fixture is the only oracle for the reply.** `_assert_matches_fixture` reads
  `_BY_NAME[case]["body"]` and nothing else.
- **The identity literals are typed twice** (once in the fixture, once in the test) and
  compared — never sourced from one another.
- **`_DISCRIMINANT_KEYS` is a literal tuple** in the test, and the shrink guard asserts
  `len(_CASES) == 5` against a **literal**, not against a count derived from the file it
  is guarding.
