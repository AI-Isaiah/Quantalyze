## D-19 — the defect the gate caught (NEW; in no plan, and no gate could have found it)

**Part 3 arm E went RED on the very first real execution.** 26 seeded stranded rows, **zero** foreign
competitors, ONE tick terminalized **26 of 26**. Expected 25.

**Cause.** Both arms bound their batch through a `WHERE strategy_id IN (SELECT … LIMIT 25 FOR UPDATE
SKIP LOCKED)` subquery. `FOR UPDATE` makes the subplan un-hashable, so the planner attaches it as the
**INNER side of a nested-loop semi-join and RE-EXECUTES it once per outer row**. Each re-execution
applies a fresh `LIMIT`, so the cap is **per-rescan, never global**. Measured plan (PostgreSQL 17.6):

```
Update on strategy_analytics sa
  ->  Nested Loop Semi Join
        ->  Index Scan on strategy_analytics sa      (outer)
        ->  Subquery Scan on "ANY_subquery"          (re-executed)
              ->  Limit  ->  LockRows
```

**Why every gate missed it.** They all grep for the **PRESENCE** of the bound's tokens — and the
tokens are present. Only **executing the body against real rows** falsifies it. That is the D-16
argument, vindicated: this is the class of defect a 637-line static-plus-structural gate cannot
reach, found within minutes of the gate finally being run.

**Impact — stated precisely, NOT overstated.** The bound is a **blast-radius control**. Unbounded,

## Oracle Independence

> The failure this catches: assertions that read their expected value out of the module under test, so the test passes for any implementation.

⚠️ **Scope of this checklist's close-out, stated so it is not over-read:** the four boxes were
confirmed against **the test surface this phase created or modified**, from the evidence in the
seven executor SUMMARYs. They are **not** a re-audit of every test in the repository.

- [x] No test imports a **constant** from the module it tests — expected values are **literals** in the test — *the reap-threshold drift gate is the load-bearing case: it reads the interval literal out of the migration FILE and compares it to the Python constant, i.e. two independently written artifacts. Proven non-vacuous by mutating the migration's literal and watching the gate redden (`assert {'17 hours'} == {'16 hours'}`, plan 142.1-05) — which is also the direct proof that the C-10 re-point landed, since before it the gate was reading the other file.*
- [x] No assertion compares a value to itself via a re-export, fixture, or table under test — *two deliberate constructions carry this. (i) SQL gate Part 6 writes the sentinel offset TWICE on purpose — once in row A's seed and once in the expectation — so the seed-integrity control compares two independently written expressions rather than a value against itself; using the variable in the seed would have made the control unfalsifiable, which is exactly the pre-retrofit Part-4a defect. (ii) The Part 6 block and the trigger DDL were **extracted programmatically from the shipped files, never re-typed**, for the local mutant runs — a re-typed oracle passes when the shipped artifact is wrong.*
- [x] Table/registry sizes are pinned to a **literal count**, not to `len(THE_TABLE)` — *and every census counter that moved this phase was **re-derived from a live scan, not assumed**: `kept 13 / runner 7 / worker 6 / n1 2 / n2 1 / skipped 0` (plan 142.1-06), each bumped in the same commit as the change that caused it. See the deliberate note below.*
- [x] Any fake/double is pinned against the real contract it stands in for (version, key shape, semantics) — *the PGRST204 injection is **schema-faithful, not positional**: it rejects any write from `_mark_unrecoverable` whose payload names the unknown column, the way PostgREST would, rather than "raise on the first call only". Under first-call-only, a broken fallback that re-sent the identical payload would SUCCEED on call two. The exemption is matched by the payload's exact 5-key **shape**, not by file+function, and both directions were driven live (`assert 0 == 1` and `assert 2 == 1`).*

of *assertions*. **D-19 was a defect in the SQL execution plan** — every gate's oracle was
independent, correctly written, and green, because they all assert on the PRESENCE of the bound's
tokens rather than its EFFECT. No box on this checklist would have caught it. Only running the body
against real rows did.
