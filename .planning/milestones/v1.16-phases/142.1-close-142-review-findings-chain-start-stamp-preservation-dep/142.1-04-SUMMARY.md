# Phase 142.1 Plan 04: Rework the two-runtime stamp gate (D-07, D-04, D-03) — Summary

Three changes to one gate, in the order that made each one falsifiable. **D-07**
stopped the AST half aborting the build on a payload it cannot read — the DB
trigger owns the invariant now, so the census's job is hygiene, and hygiene must
not veto a refactor. **D-04** widened the TS half from `src/app/api/**/*.ts` to
the whole `src/` write surface, which is where the permanent-spinner class was
re-creatable in silence. **D-03** is the money one: `csv-finalize`'s terminal-failed
placeholder was the lone writer of 17 across three languages missing
`computation_warned`, letting a failed CSV import render as a green factsheet built
from the previous run's metrics. The fix is one line and had **no observable at
all** until the parity rule shipped with it — so it did, in one commit, with the
intermediate RED observed live.

## What Was Built

### Task 1 — D-07: record-and-continue instead of raise

`_resolve_name` and the payload-shape arm of `_collect_write_sites_in_text` now
append to a `skipped: list[str]` and return `None`. Six raise sites became six
skip records (multiple dict bindings, non-dict binding, `*args`/`**kwargs` param,
param with no default, unsupported default expression, zero bindings anywhere) plus
the two in the collector (no positional payload, non-Dict/non-Name payload).

The policy paragraph was rewritten to say where the invariant actually lives: the
`BEFORE UPDATE` trigger function `strategy_analytics_stamp_computing_started`
(migration `20260803120000_strategy_analytics_stamp_trigger_null_stamp_clock_start.sql`),
proven by Part 6 of the SQL gate. Both names are the cross-plan contract values from
plan 142.1-05 and are cited verbatim (prose only — 5 occurrences, all docstrings).

**Counters re-derived from a live scan, not assumed** — `kept=12`, `n1=2`, `n2=1`,
`skipped=0`. Unchanged, as the plan predicted, but measured:

```
kept 12
n1   2
n2   1
skip 0 []
```

A third pinned counter `EXPECTED_SKIPPED_UNRESOLVED = 0` is what keeps the softening
honest: a refactor that moves a site kept→skipped reddens a COUNT (visible,
decidable, one-line acknowledgement) instead of aborting the run with a demand to
grow AST arms in a 1000-line test file.

`_collect_write_sites_in_text(source, *, label)` was split out of
`_collect_write_sites(path)` — the `_count_in_text` / `_count` precedent — so the
resolver can be driven against synthetic in-memory source. That is what makes
SC-07 a standing observable rather than a one-off manual check.

### Task 2 — D-04: the whole `src/` write surface

`_ts_scan_files` now walks `src/**/*.ts` ∪ `src/**/*.tsx`, excluding `.d.ts`,
`*.test.*`, `*.spec.*` and any `__tests__/` segment. **684 non-test files**, up from
the API-route corner. Exclusions are shape-based, never name-based, so a new
directory is covered the day it lands.

The tree has **17 raw key matches**. Two mechanisms separate them:

| Mechanism | Drops | How |
|---|---|---|
| 1 — value-token | 10 | a payload key is followed by a VALUE (quoted literal or `null`); a type member is followed by a TYPE. `queries.ts:414,452`, `AdminTabs.tsx:82`, `types.ts:299,1345,1381,1392`, all three `database.types.ts` members. None named, none by file. |
| 2 — two-tier count-pinned census | 3 | the remaining benign shapes are quoted literals in non-DB positions, so they are classified explicitly with an exact count. |

Tier B (`_TS_BENIGN_FILES`), each justified in the module docstring:

- `src/app/(dashboard)/portfolios/[id]/page.tsx` ×1 — `chooseAnalytics`'s fallback
  row, the **wrong table** (`portfolio_analytics`). The TS twin of the
  `routers/portfolio.py` trap.
- `src/lib/utils.ts` ×1 — `EMPTY_ANALYTICS`, an in-memory placeholder. It *does*
  carry `computing_started_at: null`, so it would have passed the stamp rule — for
  the wrong reason. Classified rather than counted.
- `src/lib/types.ts` ×1 — a string-literal **type** (`a is T & { … : "complete" }`).
  ⚠️ Not in the plan's three-shape ledger; see Deviations #2.

Tier A (`_TS_PAYLOAD_FILES`) is the unchanged 4: finalize-wizard ×2, csv-finalize ×1,
keys/sync ×1. Both totals are separate literal ints (`4` and `3`) rather than
`len(...)` of the dicts — double-entry bookkeeping, so a one-sided edit cannot pass.
The unknown-file arm is kept and now covers both tiers.

A positive control was added: the scan must reach `src/lib/utils.ts` **and** a `.tsx`
component, else every assertion above would hold vacuously over the old surface.

The `:29-54` docstring was rewritten in the same commit — it stated the boundary was
not widened, which the shipped code now contradicts. It also records **why** the
allowlist beat proximity scoping (see Decisions).

### Task 3 — D-03: the parity rule and the one-line fix, one commit

`_TsHit` gained a `value` field captured at scan time; `_ts_terminal_status` reads it
and returns the terminal status or `None`. New
`test_typescript_terminal_writers_carry_computation_warned` asserts that every
tier-A literal writing a terminal status carries `computation_warned` in the same

The fix is exactly one line in `writeFailedStrategyAnalyticsPlaceholder`, copying

## Deviations from Plan

### 1. [Judgment] Reused `_TERMINAL_STATUSES` instead of a TS-side mirror frozenset

- **Found during:** Task 3, STEP 1.
- **Plan text:** *"declare a TS-side frozenset mirroring the Python `_TERMINAL_STATUSES`"*.
- **What I did:** `_ts_terminal_status` reads the existing module-level
  `_TERMINAL_STATUSES` directly.
- **Why:** two hand-maintained copies of one closed set, in one file, is the exact
  divergence class D-10 was raised about and plan 142.1-02 just spent a commit
  closing. The terminal-status set is a property of the `strategy_analytics`
  column — it is not Python's and not TypeScript's. PATTERNS §7(b) frames the task
  as "port the concept across the language boundary", and sharing the definition is
  the stronger port. The reason is written into the helper's docstring so the next
  reader does not re-fork it.
- **Files modified:** `analytics-service/tests/test_computing_started_at_stamp.py`
- **Commit:** `bfeb69a2`

### 2. [Rule 2 — Missing critical] The benign-shape ledger was incomplete: a FOURTH class

- **Found during:** Task 2, deriving the widened census.
- **Issue:** the docstring ledger (and PATTERNS §7(a), which quotes it) names three
  benign shapes and asserts the third class is *type-annotation members*, killable
  by telling a type name from a value. `src/lib/types.ts:1382` is
  `a is T & { computation_status: "complete" } {` — a **string-literal type** inside
  a type predicate. It is a type, but its token is a quoted literal, so value-token
  discrimination does **not** drop it. Had I implemented only the two mechanisms the
  ledger implies, the gate would have reddened on correct code at the first run.
- **Fix:** classified in `_TS_BENIGN_FILES` with a written reason, counted, and named
  in the rewritten module docstring as a fourth class alongside the three.
- **Files modified:** `analytics-service/tests/test_computing_started_at_stamp.py`
- **Commit:** `929782b6`

### 3. [Judgment] `EXPECTED_PER_FILE` is now an alias of a module-level census

Task 2's acceptance criterion says *"EXPECTED_TOTAL / EXPECTED_PER_FILE are literal
values re-derived from the widened scan, with csv-finalize still listed"*. The literal
values moved to module scope as `_TS_PAYLOAD_FILES` / `_TS_BENIGN_FILES`, because the
scanner needs the same mapping to separate tiers, and
`EXPECTED_PER_FILE = _TS_PAYLOAD_FILES` inside the census test.

Stating the objection so it is not hidden: the oracle and the tiering key are now the
same object. It does not make the census self-referential — the dict is a
hand-written census, never derived from a scan, and `actual` is measured
independently over all 684 files — but `EXPECTED_TOTAL = 4` and
`EXPECTED_BENIGN_TOTAL = 3` are kept as separate inline literals precisely so a
one-sided edit to the dict cannot slide through. csv-finalize is still listed.

### 4. [Rule 1 — Bug in my own edit] A census docstring outlived its own truth

`test_python_writer_census_counts`'s docstring said *"Without this arm the gate
FAILS LOUD on that correct, deliberately-untouched partial upsert"* about the n2 arm.
After Task 1 that is false — without n2 the site moves into the **skipped** count.
Caught by running `grep -c 'FAILS LOUD'` over the whole file rather than only over
the paragraph the acceptance criterion names. Reworded in the same commit.

This is the third instance in this phase of prose contradicting or tripping the gate
it describes (plan 01 deviation #3, plan 02 deviation #5). It is worth saying plainly:
in a phase where every gate is a string search, **the file's own documentation is
inside the blast radius**, and the check is to run the greps over the whole file
before committing, not over the region you edited.

### 5. [Rule 3 — Blocking] Worktree base correction at startup

The worktree spawned on merge commit `34127316` — the same default-branch fork the
three prior spawns in this phase hit — an **ancestor** of the plan's
`EXPECTED_BASE` `b086aad6`. `git merge-base HEAD b086aad6` returned `34127316`, not
`b086aad6`. Corrected with `git reset --hard b086aad6` per `<worktree_branch_check>`,
only after the HEAD/namespace assertions passed
(`worktree-agent-a7fb4a53670af4e35`, not a protected ref). Working tree was clean;
nothing was discarded. **4 of 4 spawns in this phase have now landed on the wrong
base** — the reset block is not a defensive nicety here, it is load-bearing.
