- ISO-day math over `YYYY-MM-DD` strings; interval/containment is LEXICOGRAPHIC string comparison (`a.date >= b.date`), never `Date` objects (Date objects reintroduce the UTC/local off-by-one dateday.ts exists to kill).
- `daily_returns` arrays are already ascending-sorted by date (portfolio-math-utils guarantee) — but do NOT assume it for `coverageSpanOf`; scan for min/max defensively.

Design intent (from ADR-001:89-91 and 55-RESEARCH § Supporting):
- `coverageSpanOf(dailyReturns) → { first: string; last: string } | null` — first/last date WITH data (ignore leading/trailing absence). `null` for an empty series.
- `defaultWindowFor(spans) → { start: string; end: string } | null` — intersection = `max(firsts) / min(lasts)` over the given spans; `null` when the intersection is empty (`max(firsts) > min(lasts)`) or `spans` is empty.
- `intersectionOf(spans) → { start: string; end: string } | null` — the generic intersection primitive `defaultWindowFor` delegates to (same math; keep one implementation, have `defaultWindowFor` call it).
- `covers(span, window) → boolean` — inclusive-closed containment: `span.first <= window.start && span.last >= window.end`.
