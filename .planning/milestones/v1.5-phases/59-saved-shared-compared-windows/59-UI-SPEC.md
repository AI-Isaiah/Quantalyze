# Phase 59 — UI Design Contract

> Visual and interaction contract for **Saved / Shared / Compared Windows** — making the coverage
> window durable across the three ways a scenario leaves the composer (saved, shared, compared).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a DATA-CENTRIC phase.** The bulk of PERSIST-01/02/03 is non-visual: a `ScenarioDraft`
> schema-version bump (2→3, code-level non-destructive upgrade — NO SQL migration), save/load
> hydration threading `draft.window` into `state.window`, share-resolve threading the same window
> before `computeScenario`, and the compare engine passing each scenario's own `draft.window` into
> `computeMetricsForDraft`. **`scenario.ts` and `scenario-window.ts` stay FROZEN.** Reopen / share /
> compare all recompute TODAY's numbers at the owner's saved window — never replay stored series
> (no-invented-data lock).
>
> **The net-new UI surface is SMALL and mostly REUSE.** This phase adds exactly **two** genuinely-new
> visual contracts (locked below). Every token, font, spacing value, and interaction pattern is
> INHERITED verbatim from `58-UI-SPEC.md` and `DESIGN.md` — this document introduces **no new token,
> no new dependency, no new copy string** beyond the one provenance-note copy variant and the
> per-column window-label format string that `59-CONTEXT.md` locked. All four grey areas were resolved
> in `59-CONTEXT.md` and are treated as LOCKED — this document translates them into a 6-dimension
> contract; it does not re-open them.

## Inheritance Statement (read first)

For **every** dimension below, the default is: **inherited from `58-UI-SPEC.md` and `DESIGN.md`,
unchanged.** Phase 59 does not author a new design system, spacing ladder, type scale, or color
budget. It reserves and reuses the already-approved Phase-58 tokens. Only the **two new UI contracts**
add anything, and even they reuse existing components/tokens:

| # | New UI contract | Requirement | Reuses | What is genuinely new |
|---|-----------------|-------------|--------|------------------------|
| 1 | **Provenance / upgrade note** | PERSIST-01 | `DefaultChangeNote` inline info-note pattern (`role="status"`, dismissible `×`, `bg-surface-subtle`, `text-fixed-13`) | One copy variant + **ephemeral per-open dismissal** (NOT the localStorage one-time global) |
| 2 | **Per-column compare window label** | PERSIST-03 | `BlendHeader` typography/tokens (`font-mono tabular-nums`, `text-fixed-11`, en-dash date convention) | The `· {start}–{end}` effective-window date-range label per compare column |

Everything else in this phase is non-visual. The recipient share-resolve view already renders through
existing components — no new visual contract there beyond the numbers recomputing at the owner's window.

**Accent (`#1B6B5A`) reserved for — explicit list, nothing else:**
1. The **"Show full range"** inline text action inside the provenance note (Contract 1) — the only
   interactive text affordance this phase adds, verbatim from the reused `DefaultChangeNote`.

**Per-column window label color (Contract 2):** `text-text-muted` `#64748B` (AA-shifted 2026-04-30
value, 4.85:1 on white). The label is a neutral honesty caption — **never accent, never warning,
never a winner color.** The compare table's winner-`✓` accent stays on the metric cells only; the
window label is deliberately quiet so heterogeneous windows read as informational, not alarming.

(`{start}–{end}`); heterogeneous windows are legible by reading the dates, not by any color contrast.
The provenance note carries its full sentence; the `×` has `aria-label="Dismiss"`.

## Copywriting Contract

string are authored beyond the inherited Phase-58 copy.

| Element | Copy |
|---------|------|

| **Per-column compare window label** (Contract 2, PERSIST-03) — LOCKED format | `· {start}–{end}` per compare column, where `{start}` = `effective_start` and `{end}` = `effective_end` from that column's `computeMetricsForDraft` output; en-dash `–`, `YYYY-MM-DD` bounds in `font-mono tabular-nums` (BlendHeader convention). ## Interaction & State Contract (phase-specific — consumed by planner + executor)

| Behavior | Contract |
|----------|----------|
| **Provenance note trigger** (Contract 1) | Shown ONLY when a hydrated/decoded draft is a **pre-v1.5 v2 draft with no `window` field** that has been defaulted to the intersection via `defaultWindowFor()` on open. The trigger is a **transient provenance marker set on the hydrate/decode result** (Claude's-discretion representation, NOT persisted into `ScenarioDraft`) — not the general "intersection truncates union" condition `DefaultChangeNote` uses for POLISH-03. A fresh v3 draft (window present) NEVER shows it. |
| **Provenance note placement** | Above the coverage-window control (`ScenarioComposer.tsx` ~2828) — the same slot the Phase-58 POLISH-03 `DefaultChangeNote` occupies. `role="status"` + `aria-live="polite"` + dismissible `×` with `aria-label="Dismiss"` (verbatim from the reused shell). Never `role="alert"` — this is informational, not blocking. |
| **Provenance note dismissal (KEY divergence from POLISH-03)** | **Ephemeral per-open.** Dismissal is component-local (`useState`) and re-shows if ANOTHER old draft is reopened — it is a per-scenario provenance signal, NOT a one-time global. Do **NOT** reuse `DefaultChangeNote`'s `useCrossTabStorage` `composer.coverageDefaultChangeNoteDismissed` localStorage flag (that is the POLISH-03 education artifact; this is a per-scenario data-provenance signal that must recur). |
| **Provenance note "Show full range" action** | One click applies the existing Full-range preset (`onShowFullRange`) — widens to the union, auto-dropping non-covering members via the Phase-57 state machine. Immediate + reversible. No modal. Same affordance the POLISH-03 note offers. |
| **Reopen recompute** (PERSIST-01) | On hydrate, `draft.window` (if present, v3) is applied into `state.window`, then `computeScenario` re-derives TODAY's numbers at that window. A v2 (windowless) draft loads fine (non-destructive 2→3 upgrade — NEVER reset/dropped), defaults window to intersection, and sets the provenance marker. No stored series is replayed (no-invented-data). |
| **Share-resolve recompute** (PERSIST-02) | The recipient reads the owner's saved `draft.window` VERBATIM (rides in the returned `draft` JSONB) and threads it into `state.window` before `computeScenario`. Recipient view == owner view (deterministic; do NOT re-derive a fresh intersection recipient-side). A v2 shared draft defaults to intersection, same rule. **No new visual contract on the recipient** — it renders through the existing share-resolve components; the numbers simply recompute at the owner's window. Leak safety unchanged (the window is two ISO date strings; no tenant data). |
| **Per-column window label source of truth** (Contract 2) | Reads each column's `effective_start` / `effective_end` from `computeMetricsForDraft` ONLY — never re-derives the window from the draft. Each compared scenario is computed at **its own persisted `draft.window`** (heterogeneous windows are honest). The live-book column stays **windowless** (Phase-55 lock — own-book callers keep union behavior); its label shows the union-derived effective window it already computes, consistent with the other columns' effective-window semantics. |
| **Per-column window label placement (augment, don't duplicate)** | Lands in `ScenarioCompareTable`'s existing `<tfoot>` "Window" row. That row TODAY stamps `methodologyLine(n)` (a trading-day-**count** caption). Contract 2 adds the **effective `{start}–{end}` date-range** to the same per-column stamp so the user sees both *how many days* and *over which window*. Preserve the existing sample-floor gate: a whole below-floor column shows the neutral sample-floor copy (heading + body), and an `undecodable` column shows the older-format stamp — in those two cases the date-range label is suppressed (there is no honest window to show). Only the `verdict.ok` columns carry the new `{start}–{end}` label. |
| **A11y live regions** | Provenance note = `role="status"` `aria-live="polite"` (inherited from `DefaultChangeNote`). The per-column window label is static caption text inside a `<td>` — no live region; it is read as part of the table's `<tfoot>` "Window" row (which is already labeled). No new tab stop except the note's "Show full range" + `×` buttons (both inherited, both operable). |
| **Keyboard / focus** | The note's "Show full range" action and `×` are real `<button>`s in DOM order, Enter/Space activate, `focus-visible:ring-2 focus-visible:ring-accent/50` — verbatim from `DefaultChangeNote`. The per-column window label is non-interactive text (no new tab stop). |
| **Motion** | None new. The note's appearance and the compare table are static; if the reused `DefaultChangeNote` shell carries any transition it is inherited unchanged, honoring `motion-reduce:transition-none`. |
| **Focal point / visual hierarchy** | Unchanged from Phase 58: the always-visible `BlendHeader` remains the composer's primary anchor. The provenance note is a transient, dismissible secondary signal above the window control (subordinate to the header). In the compare panel, the metric grid is primary; the per-column window label is a tertiary honesty caption in the `<tfoot>` — it must not out-weight the metric values or the winner `✓`. |
