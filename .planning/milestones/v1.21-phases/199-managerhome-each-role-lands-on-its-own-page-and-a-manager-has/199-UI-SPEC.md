## Health column (D-03, CD-04)

### Placement and cell

- Header `Health`, emitted directly after `Status` (column order: `#` | Strategy | Status | Health | Created | Return % | CAGR | Sharpe | Max DD | Volatility | 6 Month | AUM | Return | Underwater | Actions). Not sortable: no button, no `aria-sort`, same shape as the Status header. Not pinned.
- Cell: `px-4 py-3 whitespace-nowrap group-hover:bg-page/50 transition-colors`, then the word as `<span class="text-caption font-semibold {tone}">`. Plain text, not a chip (a chip would add a fourth chip family). No dot, no glyph.
- Placeholder rows: `—` in `text-text-muted`, matching their Status and Created cells.
- The empty-row `colSpan` grows by one with the new column (`emptyRowColSpan`); the note row spans every header.

### Derivation (one pure function, first match wins)

One pure function (e.g. `strategyHealthOf`) in `src/lib/`, read by the cell, the legend and the tests. It reads only existing signals and existing constants (CD-04). No new threshold.

| Order | Condition | Word |
|-------|-----------|------|
| 0 | Status is `archived` | `—` |
| 1 | Any feeding key (`api_key_id` plus `strategy_keys` members, the page's existing `feedingKeyIdsByStrategy`) is untrusted by `isUntrustedKeySyncStatus` | `Key problem` |
| 2 | Analytics `computation_status` is `failed` (the row's `rowChipStatus`) | `Analytics failed` |
| 3 | A run is queued or computing: `deriveEmptySeriesState(...) === "computing"`, or the shaped row carries `analytics_updating === true` | `Updating` |
| 4 | Computed (`isComputedAnalytics`) and the Phase 197 list verdict is `stale`: `listSeriesVerdict(series_end, asset_class, now)`, more than `SERIES_STALE_DAYS` days for a crypto strategy and more than `SERIES_STALE_DAYS_TRADITIONAL` for any other asset class, null included. This is the same predicate the Discovery list ranks on (REVIEWS R-05, 2026-11-10). | `Stale (no data since {day})` |
| 5 | Not computed and nothing running (`deriveEmptySeriesState(...) === "empty"`) | `Stale (no data yet)` |
| 6 | Computed and the list verdict is `unknown`: a missing, unparseable or calendar-impossible series end, or one more than 2 days ahead | `—` |
| 7 | Computed and the list verdict is `current` (a series end up to 2 days ahead included) | `Healthy` |

Rules:
- `{day}` is the series end (`series_end`) through `formatCloseDay`, e.g. `Stale (no data since Oct 3, 2026)`. Never a client clock, never a guessed date.
- Key-status read failed (`keyStatusUnreadable`): Key problem cannot be ruled out, so a row that would read `Healthy` reads `—` instead. Every other word is still a true fact and still renders. The page-level `KEY_STATUS_UNREADABLE_NOTE` explains it.
- `failed` with a stored earlier result still reads `Analytics failed` (a failed row is never admitted as displayed, `isDisplayedRow`).
- `Stale (no data yet)` is the dateless form of the founder's `Stale (no data since <date>)`: the parenthetical says honestly that no date exists (DESIGN.md: never a fabricated value). See OQ-1.
- The in-row `Syncing` / `No data` data-state chips stay (D-02 keeps everything). The legend explains both the chip and the word.

### Row note — the Health detail (D-03: "the row note carries the detail")

Every row whose Health is not `Healthy`, `Updating` or `—` gets one detail line in its existing note row, placed after review feedback and before the share note. Each detail line is a registered degrade warning (next section).

| Health | Detail line (template) | Action source |
|--------|------------------------|---------------|
| `Key problem` | The existing key line, with the caption naming the key: `Exchange key · {key label}` (or `Exchange keys · {label A}, {label B}`), then the shipped `AllocatorSyncStatus` pill (`Key revoked` / `Sign-in failed`) and its shipped helper (`Re-add a read-only key from your exchange.` / `Update this account's credentials — they may have changed.`). | Shipped helper. The caption change needs `label` added to the page's `KEY_STATUS_COLUMNS` allowlist (never an encrypted column). |
| `Analytics failed` | `The last computation, on {day}, did not produce figures. {remedy}` | `ownerRemedy(...)` for the row's compute state and shape (existing KCS09 remedies). `{day}` is the failed job's day from the page's existing compute-state read. |
| `Stale (no data since {day})` | `No new data since {day}. {action}` | By shape and role: CSV → `Upload a newer CSV to extend the record.` with the link `upload a new CSV strategy` (shipped shape-remedy link). API or composite, manager or `both` → `If it still trades, check its key on the edit page.` (shipped `edit page` link). API or composite, allocator only → `If it still trades, check its key on the Exchanges page.` (`ExchangesPageLink`; the edit route is manager-guarded). |
| `Stale (no data yet)` | `No figures yet, and no computation is running. {remedy}` | The never-started shape remedy from `ownerRemedy` (manager, `both`), or `Check its key on the Exchanges page.` (allocator only). |

- `{key label}` is set at 600 weight in `text-text-primary`; the rest of the line is `text-caption text-text-muted`, matching the shipped note lines.
- When the failed job's day cannot be read, the line is the shipped `KCS09-UNREADABLE` sentence with its reload remedy, registered as a read failure (it is a fact about this read, not about the data).
- One fact, one sentence: a key named by the Key problem line is not named again by another detail line in the same note.

## Degrade-warning copy contract (D-04, CD-05, SC-4)

### What counts

A **degrade warning** is any user-visible sentence saying that figures on the surface are missing, partial, excluded, held back or stale because of a data, key or computation condition.

Not degrade warnings, and why (each still gets a registry id with its class, so the scan sees every hit):

| Class | Example at HEAD | Why it is not a degrade warning |
|-------|-----------------|--------------------------------|
| `read_failure` | `STRATEGIES_LIST_UNREADABLE`, `KEY_STATUS_UNREADABLE_NOTE`, 198's `history_read_failed` line, `KCS09-UNREADABLE` | Nothing is known about the data; this request failed. Must carry an action (reload, or open the strategy). No day or key is possible. |
| `in_progress` | `ANALYTICS_UPDATING_LINE` (founder wording, Phase 190 D-06), KCS09 queued/running lines, Scenario "Loading returns…" | Work is running; the figures shown are complete for the last computation. |
| `composition` | Scenario "No common period across the selected strategies", "Auto-excluded (outside window)" | Caused by the user's own selection; the copy already names the strategy and the fix. |
| `share_status` | KCS12 share notes on a list row | Describes what a link's recipient sees, not data missing here. |
| `provenance` | `ReconstructedRangeLines` | Discloses how days were built; nothing is missing. |
| `empty` | "No strategies yet." | Honest empty account, not a degrade. |
| `field_error`, `ErrorEnvelope` | form validation, request failures | Own contracts (DESIGN.md Error Envelope). |

### The rule for every degrade warning

1. **It names its scope.** One of: a key (`{key label}` by the one key-label rule), a day or day range (`{day}`, `{day range}`, `since {day}`), or both.
2. **It names one action.** One sentence from the action vocabulary below: one place to go, or one named wait.
3. **A dead key's warning names only that key** (founder rule, CD-05). Never "your keys" or "your book" for a fault on one key; figures from other keys are never withheld because of it.
4. **Book-wide reasons with no key cause** (198's `awaiting_derivation`, `derivation_rejected`, `shared_account_history_truncated`) have scope `whole-history`: the copy states the range as `for your whole history` (with `since {first day}` when the payload has the book's first day). `whole-history` ids are an explicit, count-pinned allowlist; no other entry may use it. See OQ-2.
5. **Recipient- and public-facing notices** (share page, public factsheet) never name an owner's key (privacy). They carry an action, and a day where the public payload has one. Scope `recipient`. See OQ-3.
6. **Copy lives in one registry** (a module of entries `{ id, surface, class, scope, template, action }`), never inline. Surfaces render the registry entry.
