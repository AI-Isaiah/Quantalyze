# Phase 194.2 Plan 01: Strict day check and interior-date helper Summary

TS now reads an impossible calendar day as unreadable exactly as Python `_read_day` and SQL do, and one helper, `firstUnreadableDate`, lets the factsheet builder (all three axes) and the Scenario payload withhold annualised figures on a malformed interior date.

## What changed

- `src/lib/figure-gate.ts`: `isReadableDay` is the anchored `^\d{4}-\d{2}-\d{2}$` shape plus the `toISOString().slice(0, 10)` round trip. New exported `firstUnreadableDate(...axes)` returns `{ axis, index, date } | null`.
- `analytics-service/services/metrics.py`: docstring only; the impossible-day divergence is recorded as closed (194.2).
- `src/lib/factsheet/build-payload.ts`: `mtmClipped` / `smoothedClipped` are normalised once before `totalRecord`; the bundle arms reuse them. `totalRecord` uses `firstUnreadableDate(dates, mtmDates, smoothedDates)` (an axis under two points, which builds no bundle, contributes no dates). The Sentry `extra` gains `firstBadAxis` (`cash | mark_to_market | smoothed_mtm | null`).
- `scenario-factsheet-payload.ts`: `record` is `{ ...endsRecord, unreadable: true }` when `firstUnreadableDate(datesR)` hits. No Sentry report (client re-derive, R6 WR-01).
