## Observations (not threats, no action required)

- Attestation read precedes the limiter by design (T-194.2-12), so an approved allocator's refused POSTs cost two
  indexed reads and no limiter token. The profile read already preceded the limiter before this phase.
- `RequestIntroButton` still renders the route's `error` string for non-attestation failures (pre-existing; the
  base test `a non-ok response with a JSON error string shows that string` predates this phase). Those strings
  are fixed server-authored text, and the 400 `issues` array is never rendered.
- `reportedUnreadable` is bounded by key count (1000), not key length. The keys are built from stored producer
  dates, so this is not attacker-reachable from a non-admin path today.
- The R3 review's three figure-integrity survivors (WR-01 to WR-03) sit on T-194.2-01's component (the USD view's source-date scan and the stress-window withheld form). This audit verified L1 presence of the declared mitigations; the edge behaviour of those survivors is routed to a follow-up phase and was not re-measured here.
