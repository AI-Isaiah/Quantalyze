<decisions>
## Implementation Decisions

### Carried forward (not re-asked)
- **D-01: Phase 194's rules govern every figure item.** "Unreadable" means withheld, with its reason. The total-record gate is 194 D-15: 60 observations or 90 days for crypto. Notes use the muted-note style. Items 1-6 close on their `TODOS.md` "Closed when" wording, and each closing change carries a test that goes RED when the fix is neutered (repo testing rule).
- **D-02: The record length is 194 D-20 `coveredDays` (founder, 2026-11-08, "Count returns").** It runs from the first to the last return date with both ends counted, via `coveredDays` in `src/lib/figure-gate.ts`, its Python twin `_index_span_days` and the SQL span arm of `get_verified_cohort_rank`. "193 days" is correct. The factsheet reader that printed 192 is using the gap (`spanDays`) where a length is meant, and it moves to `coveredDays`. The fix is to find every "days of record / overlap" producer and route it through the one helper, not to patch the one string. A parity test pins the same strategy's count on discovery, factsheet and tearsheet.

### Intro attestation (item 9)
- **D-03: Enforce the attestation in `/api/intro` (founder, 2026-11-10, "Enforce in /api/intro").** An approved allocator without an `investor_attestations` row is refused with a named error code. A direct POST no longer bypasses the gate. — **Reversibility:** costly — every intro caller and its tests depend on the new refusal shape.
- **D-04: Every intro entry point shows the attest step (founder, 2026-11-10, "Here, with an attest prompt").** This covers the Bridge ReplacementCard on `/allocations` (the path that broke when Phase 196 round 1 enforced the route, R2-02) and the factsheet (whose unattested allocator today sees no actions and no hint, 196 round-2 silent-failure M6). Each shows an unattested allocator an "attest to request introductions" step, reusing `/discovery`'s existing gate (`src/components/legal/AccreditedInvestorGate.tsx`), never a dead or hidden button. After attesting, the original action completes without leaving the page if the existing gate supports that. Otherwise it returns to the same page.

### Zoomed benchmark coverage (item 5)
- **D-05: A muted note names the benchmark's covered span (founder, 2026-11-10, "Muted note naming the span").** On a narrowed range, when the benchmark series starts after the window start or ends before its end, the vs-benchmark figures stay computed on the overlap. A muted note in the 194 style names the covered span, for example "BTC compared over Mar 3 – Nov 9 (its data starts after this range)". This phase adds no withholding for a short benchmark overlap.

- **D-06 (founder, 2026-11-10, UI-SPEC OQ-1): the attest step's lead sentence reads "Before requesting an introduction" inside the intro modal.** Founder pick: "'Before requesting an introduction'". This changes the lawyer-reviewed gate text in the intro modal only; /discovery keeps "Before viewing, please confirm…" word for word.
- **D-07 (founder, 2026-11-10, UI-SPEC OQ-2): "Add to my allocation" stays hidden on the factsheet until the allocator has attested.** Founder pick: "Keep hidden until attested". Today's behaviour is unchanged; D-04's attest step covers intro entry points only.

### Claude's Discretion
- How the Sentry dedup is done (item 6): once per record per process, or a stable fingerprint so Sentry groups the reports. Either is acceptable if a test pins the count.
- The exact copy of the attest step and of the zoom note, within DESIGN.md and 194's muted-note conventions.
- How the equity-curve fit is done (item 7): a responsive width from the container, not a fixed 620px SVG.
- How items are grouped into plans.
