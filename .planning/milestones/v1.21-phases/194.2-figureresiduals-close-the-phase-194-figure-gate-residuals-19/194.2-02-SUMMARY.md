# Phase 194.2 Plan 02: Unreadable flag, verbatim list dates, one Sentry report per record

An unreadable record is now withheld with its reason in Holdings and on a book-held Scenario leg. A malformed list date reads unreadable, and one Sentry report is sent per bad record per process.

`commits: 3` counts the production commits. The SUMMARY commit comes after it.

## What changed

- **Task 1.** `figureRecordScalars` returns `figure_unreadable: record.unreadable === true`. `OwnCapitalStrategy` and the book inline type carry it. The empty-record call site gets `false` through the same function. Fixtures that build `OwnCapitalStrategy` gained `figure_unreadable: false`: `strategies-row-adapter.test.ts`, `HoldingsTable.figure-gate.test.tsx` and `makeMarked`.
- **Task 2.** `shapedRecordScalars` no longer uses the prefix regex or the earliest-valid scan.
  - `series_start` and `headline_since` are the stored string, or null when absent or empty.
  - The owner arm reads `returns_series[0].date`, as the alias does.
  - `series_end` is added only when the alias was not projected and the last element's date is present but fails `isReadableDay`. A readable series keeps `seriesEndOf`'s value.
  - `figureRecordScalars` passes `headline_since` verbatim.
- **Task 3.** `reportUnreadableOnce(key, send)` uses a Set capped at 1000 keys, cleared on overflow. The key is `op|strategyId|seriesStart|seriesEnd|headlineSince`. The doc comment states the limit: once per record per process, and a record that is repaired and then broken again reports again only after a clear.

## Deviations from Plan

**1. [Rule 1 - Bug] `src/lib/queries.test.ts` encoded the old behaviour.**
- Two assertions in `shapeRowAnalytics — the D-15 record scalars` contradicted D-01: the "earliest date, not slot 0" test, and the "null for a malformed date" test.
- They now assert slot 0 verbatim and a malformed date kept verbatim.
- I added an absent-stays-null case and an owner-arm unreadable-`series_end` case.

**2. [Rule 3] Fixtures needed the new required field.** `strategies-row-adapter.test.ts` and `HoldingsTable.figure-gate.test.tsx` failed typecheck without it. The plan's grep step for strict-equality fixtures found no strict-equality assertions that needed changing.

**3. Parity test: the factsheet arm covers malformed last only.**
- The plan asked for first, last and headline through `fetchAndBuildPayload`. Two of those cannot be asserted there.
- A malformed first date never reaches the gate. `readFactsheetBenchmark` throws a `RangeError` first (see Deferred).
- The factsheet reads a malformed headline through the composite path, which already treats it as `headlineWithheld`. `composite-read-path.headline-basis` case (d) pins that, so the test header says so.
- All three cases run through the owner list arm, the anon alias arm and `getPercentiles`.
- The parity test header states that SQL and lists judge first, last and headline, while the factsheet also judges interior dates.

**4. Test fixtures use `x`-suffixed dates** (`2023-02-28x`, `2026-02-28x`). The prefix-regex neuter reads them as valid days, so the cases fail when the fix is removed. They do not depend on plan 01's tightening of `isReadableDay`. I did not assert the `2026-02-31` case from the plan's behaviour list: current `isReadableDay` accepts it because `Date.parse` rolls the day over. It becomes testable once plan 01 lands.

**5. The queries report test loads a fresh module per case** (`vi.resetModules`, dynamic imports), as the plan asked, because the dedup state is module-scoped.
