D-07 (SC-7): debug the composer opening on `Selected range: <d> – <same d>` to its root cause, and fix it if real or record it as a seed/headless artifact with evidence.

Purpose: the 2026-11-12 UAT saw the composer open on a one-day selected range with dashes in the KPI strip until "Reset to full history" was pressed, reproducing at `4a65c8843`. This plan proves or disproves H1 with a deterministic jsdom rerender test before any fix is written.

The trace RESEARCH already made (orientation only, re-read by symbol): `ScenarioComposer` passes `portfolioDaily={scenarioMetrics.portfolio_daily_returns ?? []}` to `ScenarioFactsheetChart`, which mounts `FactsheetProvider payload={synthPayload} persist={false}` with no key. `buildReturnsBody` returns `dates: []` for fewer than 2 points. In `FactsheetProvider`, `fullRange` is `[0, max(0, dates.length - 1)]` and `xRange` is `useState(fullRange)`; nothing re-seeds it, and only `resetXRange` re-reads `fullRange`. `resolveRangeScope` returns kind `full` only when the start is 0 and the end reaches the last index, so a stale `[0, 0]` over a longer axis reads as a one-day `selected` scope with the Reset control. `setXRange` clamps every gesture to `MIN_VISIBLE_SAMPLES` samples, so no gesture produces a one-day range.
