## Top 3 Priority Fixes

1. **WARNING — remaining "→" date ranges and raw-ISO gap titles (O-2)** — users see two range forms on one factsheet (`StressWindowsPanel.tsx:135`, `BatchDPanels.tsx:77` twice, `SyncPreviewStep` gap line, and `No data YYYY-MM-DD → YYYY-MM-DD` `<title>`s in `TimeSeriesChart.tsx` / `chart-gaps.tsx`) — replace `→` with ` – ` and route the `<title>` dates through `formatDay`; needs a founder booking since CONTEXT routed only the Coverage window.
2. **WARNING — `userRange` stored as indices (factsheet-context.tsx:562-572)** — if the series grows at the front (back-filled history), a pan/zoom the user set now points at different dates with no signal; the guard only catches `userRange[1] > maxIdx` — store the user's range as ISO date bounds and re-resolve to indices against the current axis, or reset `userRange` when `dates[0]` changes. Booked for founder decision (conflicts with the pinned append-growth contract).
3. **WARNING — stale/false comment in ScenarioFooter.tsx:524-527** — says the actions "still share the line from `md` up"; plan 14 measured 768px as two rows (bar 396px, one row needs ~482px). Future readers will treat 768px two-row as a regression — reword to "from about an 860px viewport".

Further findings:

4. **WARNING — CoverageTimeline 320px spill** (`CoverageTimeline.tsx:171-191`): the end label overflows its track leftwards over the `w-32` spacer. It stays inside the section (no horizontal overflow, tested), but the label no longer sits under the bar it annotates. Human judgement: accept, or drop the endpoint row to `formatMonth` below ~402px.
5. **WARNING — 320px KpiStrip 7px overflow** pre-existing, booked in `deferred-items-201.1-14.md`; still visible on the composer at the same width this phase polished.
6. **WARNING — matrix at 320px grew 758 → 766px** (`DistributionPanels.tsx:565`). Inside its scroll region (out of scope), but every phone user now scrolls 8px more. Acceptable trade for D-05; noted.
7. **INFO — 1440px wrapped status-helper backstop** (UI-SPEC UI Considerations, "orphaned pill" row) has no visual evidence in the summaries; the e2e asserts widths only.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- `ScenarioComposer.tsx:5936` — `→` replaced with U+2013 in the Coverage window value; "All history" fallback unchanged. Meets D-03.
- `CoverageTimeline.tsx:195-198` and `CompareEquityOverlay.tsx:232-258` — ISO dates removed from endpoints, ticks and hover label (`formatTooltipDay`). Meets D-02 and U-05.
- No new or reworded strings: matches the Copywriting Contract.
- Deduction: O-2 sites still print `→` between dates and raw ISO in gap `<title>`s, so the product still shows two range forms. Out of the locked scope, which is why this is 3, not 2.

### Pillar 2: Visuals (3/4)
- `AllocatorExchangeManager.tsx:1821` and `:1953` — both row sites get `@4xl:basis-[12.5rem]`; failed-row floor tested at 1280/1440/1920 per VERIFICATION. Meets D-01.
- `CompareEquityOverlay.tsx:236-243` — `EdgeFitXTick` clamps edge labels inside the svg without rotate/shrink/hide; tested at 320/390/1280.
- Matrix: re-baked 320 golden human-checked: first column header clears `BTC` (201.1-16-SUMMARY:47). Note that check was on `Phase 47 svg…`, not `My allocation`; the latter is proven only arithmetically and by unit arms.
- Deduction: the 320px endpoint spill (finding 4) contradicts the contract text.

### Pillar 3: Color (4/4)
- No class, token or hex added in the diff. `LINE_COLORS` hex literals in `CompareEquityOverlay.tsx:34` predate this phase (not scored here; candidates for chart tokens later).

### Pillar 4: Typography (3/4)
- `utils.ts:140-194` — `NBSP` in `formatDay`, `formatMonth`, `formatDayTime` (one U+0020 after the year's comma, per U-07). Unit test asserts code points and was neutered RED (plan 12).
- No size/weight change; edited elements keep `text-fixed-11/13` mono and `text-sm font-semibold`.
- Deduction: desktop/2560 matrix goldens stayed byte-identical inside `maxDiffPixelRatio` though the seed label gained a glyph, so the visual suite does not actually witness the desktop label change. Also the `formatDayTime` break-opportunity behaviour is asserted on strings only, never on a rendered narrow box.

### Pillar 5: Spacing (3/4)
- `basis-[12.5rem]`, `basis-[14rem]`, `LABEL_W 136`, `gap-x-2`: all on the 4px ladder; arbitrary-value brackets are the documented mechanism.
- Deduction: `ScenarioFooter.tsx:524-527` comment misstates the breakpoint (finding 3). The bar is two rows on tablets (768px) — pre-existing, but a human should decide whether a two-row sticky bar on tablet is acceptable chrome height.

### Pillar 6: Experience Design (3/4)
- `factsheet-context.tsx:556-591` — real root cause found: `useState(fullRange)` froze the opening range at the first render's 1-point axis. Derived `xRange` + `resetXRange → setUserRange(null)` fixes it; RED-then-green provider test exists. Meets D-07 with a fix, not an artifact claim.
- Shrunk-axis fallback is present (`userRange[1] <= maxIdx`).
- Deduction: front-growth index shift (fix 2) is a silent wrong-range risk; and the 320 KpiStrip overflow remains deferred.
