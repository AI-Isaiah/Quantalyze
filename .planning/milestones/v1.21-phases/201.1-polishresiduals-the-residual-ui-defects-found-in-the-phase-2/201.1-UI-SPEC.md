## Interaction contract 1: the key row's label floor (D-01, WR-13)

**Sites (by symbol):** `AllocatorExchangeManager`, the active key row (`data-testid="allocator-key-row"`, label column at about `:1817`) and the disconnected key row (label column at about `:1948`). Both carry `flex-1 min-w-0 basis-[calc(100%_-_3.5rem)] @4xl:basis-0` at HEAD.

**Root cause (from `200-REVIEW.md` WR-13, attributed there as older than Phase 200).** In the single-line layout the label column's basis is 0. In a `flex-wrap` row the line-breaker then counts it as 0px, so every sibling whose max-content fits joins line one, and the label gets the leftover. A failed row's status helper is one unwrapped sentence, so the leftover was 20.2px at 1440px in the UAT.

**Contract.**

| Row width | Label column | Siblings (Last sync, status block, actions) |
|-----------|--------------|---------------------------------------------|
| below 56rem (wrapped layout) | unchanged: takes the whole first line beside the 40px venue tag | unchanged: wrap below |
| 56rem and up (single-line layout) | flex basis **12.5rem (200px)**, grows into free space, `min-w-0` kept so the label still truncates with an ellipsis | fill line one in DOM order (Last sync, then the status block, then the actions) only while each fits beside a 200px label column. The first sibling that does not fit starts the next line, and every sibling after it follows it there. In practice the trailing siblings wrap first: the actions, or the status block and the actions together |

- Both row sites carry the same class. The recommended form is the reviewer's: `basis-[calc(100%_-_3.5rem)] @4xl:basis-[12.5rem]`. The planner may choose another mechanism with the same geometry.
- A healthy row is unchanged at 1280px. Its siblings fit beside a 200px column, so Last sync still shares line one with the label column (the existing 1280 test keeps passing as written).
- The label stays one line with `truncate`. A 60-character label in a 200px column shows its start and an ellipsis. That is the readable width D-01 asks for.
- The status block, when it wraps, keeps its own layout (`flex flex-col items-end`). A 150-character helper wraps inside the row's width. Nothing overflows the row.

**Test contract (extends `e2e/manager-keys.spec.ts`, the 1280 floor test).**
- Add one failed-state row: a key whose `sync_status` is `error`, with a `sync_error` of about 150 characters and a label of 60 characters. That is the UAT case. An allocator row is preferred because the UAT ran on the allocator profile. The row markup is shared, and `AllocatorSyncStatus` renders `sync_error` as the helper for either role, so a manager row with the same status is equivalent if the seed helper only seeds managers.
- At viewports 1280, 1440 and 1920:
  - the label column is at least **199px** wide (the 200px floor less the 1px sub-pixel tolerance the spec already uses in its other assertions; U-01);
  - the helper's right edge is not past the row's content-box right edge;
  - `assertNoReflow` passes on `[data-testid="allocator-key-row"]`.
- The failed-state assertion is shown RED against `@4xl:basis-0` on a byte copy, at 1440px at least (UAT: 20.2px), then restored with `cp`.

## Interaction contract 4: no year orphans (D-04)

The visible format is unchanged (`201-UI-SPEC.md` Interaction contract 5). Only the space characters inside a date change. Code points are named here, and no invisible literal is used in this file.

| Helper | Output | Spaces | Break opportunities |
|--------|--------|--------|---------------------|
| `formatDay` | `Oct 9, 2026` | between month and day: **U+00A0**; between comma and year: **U+00A0** | none |
| `formatMonth` | `Oct 2026` | between month and year: **U+00A0** | none |
| `formatDayTime` | `Oct 9, 2026, 14:05 UTC` | the `formatDay` part as above; after the year's comma: **U+0020**; between time and zone: **U+00A0** | one, after `2026,` |
| null, empty, unparseable | `—` | none | none |
| Day range (call sites) | `Oct 9, 2026 – Nov 3, 2026` | each date as above; the separator stays U+0020 U+2013 U+0020 (U-08) | the two separator spaces only |

- U+00A0, not U+202F. U+202F would visibly narrow the gap and change every date's width.
- The helpers return strings, which also feed attributes and SVG text. So the fix lives in the helpers, not in `whitespace-nowrap` wrappers at call sites.
- `isoToMonthDay` and every call site inherit the change with no edit.
- **Test contract.** A unit test asserts exact code points:
  - `formatDay("2026-11-11")` equals `"Nov\u00a011,\u00a02026"` (written with the escape in the test source) and contains no U+0020;
  - the matching assertions for `formatMonth` and `formatDayTime`, with `formatDayTime`'s single U+0020 after the comma.
  - It is shown RED by putting U+0020 back in one helper on a byte copy, then restored with `cp`.
- **What the change does to other tests (for the planner).** Testing Library's default normalizer and Playwright's text matchers collapse `\s+`, and JavaScript's `\s` includes U+00A0. So `getByText`, `toHaveText`, `toContainText` and `toHaveTextContent` keep matching. Exact comparisons do change: `toBe` or `toEqual` on helper output, `toHaveAttribute` on an `aria-label` or `title` holding a date, `textContent ===`, and `String.includes`. The planner enumerates them by running the suites, not from this sentence.
- **Machine paths.** The helpers' output must not feed a machine value (CSV, file name, URL, a parsed comparison). Seen at HEAD: `src/app/api/cron/founder-lp-report/route.ts` passes `formatMonth` output into an email as `monthLabel`. U+00A0 is valid in an HTML email body and a UTF-8 subject. The planner confirms that no consumer parses helper output back.
- This amends `201-UI-SPEC.md` Interaction contract 5's "Day", "Month" and "Day with time" rows in their spaces only.

## Interaction contract 6: the composer sticky bar at 390px (D-06)

**Site:** `ScenarioFooter` (`role="region"`, `aria-label="Scenario draft summary and actions"`). Its summary group is `flex min-w-0 flex-1 flex-wrap …`, and its action group is `ml-auto flex shrink-0 items-center gap-3`.

**Root cause (hypothesis, the executor confirms by measurement).** This is the WR-13 mechanism. `flex-1` is `flex: 1 1 0%`, so in the bar's `flex-wrap` row the line-breaker counts the summary group as 0px. The action group ("Reset" plus "Commit scenario", about 210px) therefore always shares line one, and at 390px the summary is left with about 100px or less. A `whitespace-nowrap` on the sentence alone would push it into the buttons, so the group needs a real floor.

**Contract.**

| Bar content width | Layout |
|-------------------|--------|
| at least about 460px (the summary floor plus the actions plus the gap) | unchanged: one row, summary left, actions right |
| below that (390px and 320px viewports) | **two rows.** Row 1: the count chip and the summary. Row 2: "Reset" and "Commit scenario", right-aligned (`ml-auto`) |

- Mechanism: the summary group gets a flex basis of **14rem (224px)**. `min-w-0` and `flex-1` stay, and the action group is unchanged. The planner may choose another mechanism with the same layout.
- "No material change yet." renders on **one line** at 390px and at 320px. At 13px Geist Mono it is about 180px. At 320px the chip and the sentence may sit on two lines inside the summary group, but the sentence itself never wraps.
- Non-muted summaries ("+0.3 Sharpe · −4% Max DD" and so on) keep their behaviour: each item is `whitespace-nowrap`, and wrapping happens only between items.
- Buttons keep `min-h-[44px]`. The bar's `min-h-[56px]` grows to fit two rows. The sticky offsets `bottom-16 md:bottom-0` are unchanged, and the bar stays above the mobile bottom nav.
- From about an 860px viewport the bar is one row. CORRECTED 2026-11-13 (plan 201.1-14, measured): at 768px the bar is 396px wide and a one-row bar needs about 482px, so 768px is a two-row width, as it already was at HEAD; the e2e asserts the shared line at 1280px only. The earlier claim "at 768px and wider the bar is one row, as at HEAD" was false.
- **Test contract.** An e2e check at 390px and 320px, with a draft whose deltas are all muted:
  - the sentence's box height is at most 1.5 times its computed line height, so it is one line;
  - the action group's top is at or below the summary group's bottom;
  - both buttons measure at least 44px tall;
  - `assertNoReflow` passes.
  - At 768px and 1280px the action group shares the summary's line.

## Interaction contract 7: the composer's opening range (D-07)

D-07 is a debugging criterion. This contract states the **expected opening state** and the **evidence** that closes the criterion either way. It prescribes no fix.

**Expected opening state.** This applies to a selected set whose strategies share more than one day of returns.
- The range eyebrow reads `Full history: <first day> – <last day>` over the scenario's full axis, in the `formatDay` form.
- No "Reset to full history" control renders.
- The KPI strip shows finite figures wherever they are computable. Per the Numbers Contract, a figure is `—` only when it truly cannot be computed.

**Observed (UAT 2026-11-12, local stack, reproduces at `4a65c8843`).** The composer opened on `SELECTED RANGE: <d> – <same d>`, a one-day range, with dashes in the KPIs until "Reset to full history" was pressed.

| Outcome of the root-cause debug | UI result | Evidence recorded (plan SUMMARY and the phase VERIFICATION) |
|---------------------------------|-----------|---------------------------------------------------------------|
| A product defect (the opening range is set from the wrong input) | the expected opening state above, pinned by a test that is shown RED on the defect | the root cause by symbol, the RED-then-green test |
| A seed or headless artifact (the seeded set really shares one day, or the headless run only) | no UI change | the seeded spans and the computed window, plus the same flow run on data shaped like the founder's (headed browser or a non-seeded set) opening on full history |

- Either way there is no new copy. A truly one-day common window stays honest: the eyebrow names that one day, and the KPIs show `—`. That is not a defect.

## Decisions taken in this contract

Each item is taken within "Claude's Discretion" in `201.1-CONTEXT.md`. Each is the option most consistent with DESIGN.md and the code at HEAD, and the founder may overturn any of them.

- **U-01 The D-01 floor is 12.5rem, asserted at 199px.** This is the reviewer's measured value: in the WR-13 harness it keeps every failed-state cell at 213px or more. The assertion allows the same 1px sub-pixel tolerance the spec already uses, because a column that lands exactly on its basis could otherwise fail by rounding.
- **U-02 The status helper's width is not bounded.** D-01 is about the label. Bounding the helper (a max width, right-aligned text) would change the status block on every row for a layout D-01 does not ask about. Recorded as a backstop row rather than added.
- **U-03 CoverageTimeline endpoints print the day (`formatDay`), not the month.** The Coverage window value directly above them prints days, so the axis and the window can be read against each other. The narrow-width wrap rule handles the extra length.
- **U-04 Compare ticks print the day (`formatDay`), not `formatMonth`.** On a short record, month labels would repeat on adjacent ticks ("Nov 2026", "Nov 2026"). `EdgeFitXTick` is the repo's existing primitive for keeping an edge label whole, so it is preferred over relying on Recharts' own edge handling.
- **U-05 The compare chart's hover label also takes `formatDay`.** It is the same chart D-02 names, under the same "No ISO dates in UI" criterion, and it costs one prop on `TouchTooltip` with the frozen file itself unedited. `201-UI-SPEC.md` U-15 already puts chart hover tooltips inside the date rule. **Flagged:** this is the one element this contract adds beyond the literal wording of D-02, which names the ticks. The planner may drop it if the founder reads D-02 narrowly.
- **U-06 Rule C reads an unformatted date x-axis, and nothing more.** The form reports a Recharts `XAxis` with a date `dataKey` and no formatter or tick renderer, which is a syntax-level fact the scanner can see. Judging a formatter's output would need run-time knowledge the scanner deliberately lacks, and it would contradict 201 D-21's exemption for the formatted ticks listed in O-1.
- **U-07 U+00A0 in the helpers, with one break opportunity in `formatDayTime`.** A 22-character day-with-time may still need to wrap. It wraps after `2026,`, never inside the date and never before `UTC`.
- **U-08 The range separator keeps ordinary spaces.** Binding the en dash to the first date with U+00A0 would stop a line starting with "–". But it would mean editing about 12 inline range sites (`MasterBrush`, `RangeEyebrow`, the wizard steps, `CustomRangePicker` and others) that are outside the seven criteria. D-04 is about the year, and the year is kept by the helpers. The rest is not done here.
- **U-09 D-05 is met by both a cap change and a label-width change.** The cap alone clips the mobile row label (measured 4.81px at V390). The width alone leaves "My allocati…". 13 characters is the smallest cap that prints "My allocation" whole, and 136 is the smallest 4px step that clears 124.8px plus the 8px gap.
- **U-10 The sticky bar goes to two rows at narrow widths.** At 390px the bar has about 326px of content width. That cannot hold the chip, the sentence (about 180px) and the buttons (about 210px) on one row. So the contract is a two-row layout, made by a real floor on the summary group, the same fix shape as D-01.
- **U-11 D-07 gets a target state and an evidence rule, not a fix.** CONTEXT leaves the method and the outcome open. Prescribing a fix before the root cause is known would be the guess Rule 1 forbids.
