<objective>
D-05 (SC-5), golden half: re-bake exactly the svg-chart-parity goldens the phase's final render changes, through the dispatch-only `bake_svg_goldens` workflow on the Linux runner.

Purpose: widening the mobile `LABEL_W` from 128 to 136 changes the 320px matrix golden's element width (758 to 766), and a size mismatch always fails `toHaveScreenshot`. The cap change may also move the desktop and 2560 matrix goldens (UI-SPEC O-3: the parity seed is named `Phase 47 svg-parity`, 19 characters), but they may stay inside `maxDiffPixelRatio` and not be rewritten. Playwright's bare `--update-snapshots` rewrites only failing snapshots, so the bake artifact's sha diff against the committed PNGs IS the re-bake set (RESEARCH Pitfall 3).

Output: the measured set of PNGs committed with the mechanism named, before the ship's single CI run.

This plan is run by the orchestrator, not dispatched to a plan executor: it pushes a branch and dispatches a workflow, and executors never push. It runs after every other plan of the phase is merged, because plans 201.1-01 (date text) and 201.1-04 (the provider the factsheet shares) also touch what the goldens photograph, so the diff must be taken on the final tree.
</objective>
