## Decision notes (recorded for the founder)

- **Throw, not an in-page card (UI-SPEC).** A read error or an empty persona throws to the existing root `src/app/error.tsx`. That boundary says "return to the dashboard" and offers "Go to Discovery", copy written for a signed-in user, and it replaces the marketing shell. Accepted for an outage path (UI-SPEC "UI Considerations", unresolved row); recorded here as a planner assumption, booked by plan 192-10. In production Next masks the thrown message to a digest (`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/error.md`), so the real reason goes to `console.error` and Sentry first.
- **Consequence for PROD, and the gate that holds it.** On PROD this code renders the root error page for any persona whose book is empty or whose labels cannot resolve, where HEAD renders the loading card. It does not ship in that state. Plan 192-10's Task 1 precondition halts the phase before it can verify, and so before `/gsd-ship`, unless 192-EVIDENCE.md reads `D-08 repair: applied` or `D-08 repair: not needed (...)` and `D-10 unresolvable labels: 0`. The deployed code is then proven by the post-deploy PROD probe that 192-VALIDATION.md's Manual-Only table assigns to the `/land-and-deploy` run (booked by plan 192-10 as `[192-DEMO-POSTDEPLOY-PROBE]`). The throw itself stays unconditional: a guard is not weakened to make a deploy safe.
- **BTC cells (D-08, RESEARCH).** The full-app seeder stores the benchmark under keys the reader does not read, with a hard-coded value. That value is never displayed. The BTC TWR shows only from a stored `benchmark_twr`; the BTC drawdown is not persisted, so it stays null and its cell is removed (plan 192-02). Computing BTC from `benchmark_prices` at read time is not planned; the founder can ask for it.
- **Batch date (UI-SPEC row, Claude's choice of when).** "Showing the batch computed {date}" uses `formatAbsoluteDate` as the UI-SPEC says, and renders whenever recommendations render, not only on fallback (DESIGN.md: every surface is a dated document). The counterfactual window uses `formatIsoDay` because a window start without a year would be ambiguous; the UI-SPEC names no formatter for it.
- **Persona copy (UI-SPEC).** The counts change ("Six strategies", "Two strategies" become counts read from the holdings list). The active descriptor's "with manager recommendations" now renders only when at least one recommendation renders, because PROD has no recommendation batch. This applies the UI-SPEC's own active-persona rule ("the claim must be true of the cells that render") and D-08's rule that a claim goes with content that cannot render. The UI-SPEC's "leave the rest alone" row covers cold and stalled only. The rest of the persona copy is unchanged.
- **Edge probe (specless fallback).** ROUTE-03's probe came back `unclassified`. Planner assumption, flagged for manual review: the edge that matters is the data state of each persona (rows present, rows missing, read error); the throw rule and plan 192-06 cover it.
- **D-09 precondition.** This plan removes the footer link only because plan 192-01 records `D-09 outcome: remove`.
