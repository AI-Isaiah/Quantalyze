## Decision notes (recorded for the founder)

- **EXCHANGE_LIST needs no map (orchestrator resolution 7 premise does not hold at HEAD).** `EXCHANGES` is `readonly ExchangeDisplay[]` and `ExchangeDisplay` is the union of label strings ("Binance", "OKX", ...): `src/lib/closed-sets.ts` maps each code through `EXCHANGE_DISPLAY` when it builds the array. So `Intl.ListFormat(...).format(EXCHANGES)` is correct as written; PATTERNS' "objects" note was wrong. At HEAD with sFOX off it reads "Binance, OKX, Bybit, or Deribit".
- **Flag caveat, not unified here.** `EXCHANGES` follows `NEXT_PUBLIC_SFOX_ENABLED` (build time); /security's sFOX guide follows `SFOX_ENABLED` (runtime). Two flags; the copy and its pins use `EXCHANGES` only. Booked by plan 192-10.
- **/for-quants visibility copy deviates from the UI-SPEC verbatim text (orchestrator resolution 6).** The UI-SPEC body adds "your firm name stays hidden until you accept an intro". The tearsheet shows an institutional-tier manager's identity to an attested signed-in allocator with no accepted intro (`src/app/factsheet/[id]/tearsheet/page.tsx`, `effectiveManager`), so that clause is false for some viewers. The D-01/D-04 truth rule beats verbatim copy: the sentence is scoped to what a signed-out request returns. The same scoping applies to the "Codename anonymization" row and the factsheet-sample sentence, which the UI-SPEC change list did not cover but which carry the same false clause.
- **Codename claims rest on a measured title (RESEARCH A8).** The factsheet titles a strategy `name ?? codename` (`src/lib/factsheet/fetch-and-build-payload.ts`, `factsheetName`). The wizard writes a preset codename into `name`, but other creation paths may write a free-text name. So the three new sentences that say a reader sees the codename (the "Public by link, under your codename" row title, the "Codename anonymization" body, step 03's body) ship only when plan 192-01 recorded `title=codename` and `non-codename-titles=0`. Any other reading contradicts the "behind its codename" part of D-04, so the executor stops and the founder decides. The alternative it shows him is to delete each codename clause and keep the no-firm-name clause.
- **Trust-row link (PATTERNS issue 2).** `TRUST_ATOMS` gains an optional `link` field instead of widening `body` to a React node, so every other row stays a plain string.
- **Orphaned form line (orchestrator resolution 7).** `src/components/landing/VerificationForm.tsx` keeps its false "never stored" line because the component is no longer rendered anywhere after this plan; the home assertions are render-scoped, and plan 192-10 books the orphaned components. Its import leaves the home page here.
- **Signed-in wizard steps stay false after this phase (orchestrator resolution 4).** `ConnectKeyStep.tsx` and `MultiKeyConnectStep.tsx` still show a signed-in manager the old cipher and Vault sentence. CONTEXT D-02 gives manager surfaces to Phase 200 LEAN-04; plan 192-10 routes them there. They are named here so the founder sees it.
- **CTA wording (Claude's discretion).** "Verify your track record" and "Create an account", from the UI-SPEC, sentence case per DESIGN.md Voice.
