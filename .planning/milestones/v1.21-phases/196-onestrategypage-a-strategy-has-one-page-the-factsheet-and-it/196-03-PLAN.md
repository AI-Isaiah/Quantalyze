<objective>
Build the origin contract for the factsheet back link (D-01): a closed map from `from` (plus `cat` for discovery and browse) to a label and href, the one href builder every in-app link will use, and the client `BackLink` that renders a named link, a history "Back", or "Go to Discovery".

Purpose: ROUTE-04 "a signed-in user can go back to where they came from". This plan is library plus one presentational component; plan 05 mounts it in the viewer bar and plans 06 and 07 make every link site carry the origin.
Output: `origin.ts`, `BackLink.tsx` and their tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query (`from`, `cat`) → back-link href | attacker-crafted links can carry any value |
| `document.referrer` → history fallback | referrer is client-controlled and can be off-site |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-196-06 | Spoofing / Tampering (open redirect) | `parseOrigin`, `backTargetFor` | high | mitigate | exact hasOwnProperty membership in `FACTSHEET_ORIGINS` and `DISCOVERY_CATEGORIES`; hrefs come only from the map; adversarial arms (absolute, protocol-relative, `__proto__`, traversal, arrays) with neuter evidence |
| T-196-07 | Spoofing | `BackLink` history branch | medium | mitigate | `history.back()` only when the referrer origin equals `window.location.origin`; otherwise a fixed same-origin link |
| T-196-SC | Tampering | npm/pip/cargo installs | low | accept | no package installs in this plan |
</threat_model>
