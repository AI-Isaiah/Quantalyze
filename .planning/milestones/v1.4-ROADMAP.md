## 🚧 v1.4 — Frontend Excellence — Phases 49–54

## Overview

v1.4 is a **quality milestone, not a feature build** — every surface already exists; the goal is
best-in-class rendering across the full resolution range: **fluid typography that never clips**, an
**evolved design system** (DESIGN.md refreshed via design-consultation), a **restructured
information architecture**, and **React/Next-16 best practices applied app-wide** — while the scenario
math engine, the `compute.ts`/factsheet parity, and the WCAG-AA floor stay locked. All four research
agents converged on the same dependency order: **design-system spine first → surfaces second →
verification last** (doing them out of order double-touches every surface and blurs visual vs routing
failure classes).

Net-new technical footprint is deliberately minimal: fluid type = pure CSS `clamp()` in a **plain
`@theme`** block (no dep; `@theme inline` flattens the variable chain), container queries = Tailwind v4
core (no dep), motion = CSS transitions + native View Transitions (no dep), visual regression =
Playwright `toHaveScreenshot()` (already installed), design-lint = extend the local
`eslint-plugin-quantalyze`. The ONE justified new prod dep is **`radix-ui@1.6.0`**, scoped to
hand-rolled widgets with no native HTML equivalent (native `<dialog>`/`<select>` stay native).

**LOCKED (presentation-layer milestone):** `scenario.ts` SCENARIO-05 zero-diff · `compute.ts` parity ·
`FactsheetBody` math (BODY-02) · no-invented-data · no-peer-rank-a-hypothetical-blend (its one audited
aggregate `scenarioPeer` override aside) · the v1.3 WCAG-AA floor must not regress. Desktop
byte-identity (v1.3's invariant) is **LIFTED** — the visual layer is free to change.
