# Phase 21 — UI Design Contract

> Visual and interaction contract for Phase 21 (Surfacing, Correlation & Honest Projection). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Brownfield phase.** This contract does NOT introduce a new visual language. It surfaces an already-shipped scenario engine, extracts a presentational correlation heatmap, and adds honesty framing — all using existing DESIGN.md tokens and existing components. Where a contract value below is already realized in shipped code, the spec PINS it (do not redesign); where this phase adds a surface, the spec PRESCRIBES the exact tokens/copy to use.

## Spacing Scale

Declared values (DESIGN.md base unit 4px). This phase uses the existing ladder verbatim:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| 0.5 | 2px | Heatmap cell grid gap (`gap-px` = 1px hairline between cells over `bg-border`) and badge `py-0.5` |
| 1 | 4px | Badge/cell inline padding; border radius `sm` |
| 2 | 8px | Compact gaps (tab `gap` between buttons, KPI strip cell gap) |
| 3 | 12px | Heatmap header→grid gap; card inner row spacing |
| 4 | 16px | Card padding (`Card padding="sm"` = `p-4`); panel-to-panel default |
| 6 | 24px | Section gaps between projection sub-panels |
| 8 | 32px | Major section breaks (`mt-8` between composer sections — matches shipped `ScenarioComposer`) |
| 12 | 48px | — (not needed this phase) |
| 16 | 64px | — (not needed this phase) |

Exceptions:
- **Heatmap cell minimum:** cells floor at `minmax(48px, 1fr)` width and ~36px height (existing `CorrelationHeatmap` uses `py-2` + `text-xs`). This is a data-density floor, NOT a spacing-ladder token — it keeps de-aliased labels and the 2-decimal ρ value legible. Do not shrink below 48px even at large N; scroll instead (see Component Contracts §3).
- **Table row height** stays at DESIGN.md's ~44px touch-target convention where rows are interactive.
- `--space-grid-gap` (10px, designer-bundle origin) is NOT used by any Phase 21 surface — do not introduce it here.

## Color

60 / 30 / 10 split is the institutional light-mode contract from DESIGN.md. Color is rare and meaningful.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8F9FA` page (`--color-page`) + `#FFFFFF` surface (`--color-surface`) | Page background, all cards/panels |
| Secondary (30%) | `#0F172A` sidebar (`--color-sidebar`), `#E2E8F0` borders (`--color-border`), `#F1F5F9` track / heatmap-neutral midpoint | Sidebar nav (Strategy Sandbox link lives here), hairline dividers, zero-correlation cells |
| Accent (10%) | `#1B6B5A` (`--color-accent`), hover `#155A4B` | See reserved-for list below |
| Destructive | `#DC2626` (`--color-negative`) | `commitError` alert only (existing); NOT used by any Phase 21 net-new surface |
| Warning | `#B45309` (`--color-warning`) on `#FEF3C7`/`#FDE68A` | Fingerprint-mismatch banner (existing). The PROJECTED honesty badge does NOT use warning — see Honesty contract rationale. |

**Accent (`#1B6B5A`) reserved for — explicit list (never "all interactive elements"):**
- The active Scenario tab indicator (`border-accent text-accent` — PINNED, matches the 5 existing tablist buttons).
- Primary CTAs already on these surfaces (`+ Allocation`, `Browse strategies`, `Open Bridge` — all existing `bg-accent text-white`).
- The strong-diversification end of the correlation scale (teal), which intentionally echoes — but does not equal — accent (see Heatmap palette note).
- Focus rings (`focus-visible:outline-accent`) and focused-input borders (`--color-border-focus` = accent).

Accent is NOT used for: the "Example universe" badge (neutral outline — accent means "verified/action", which would mislead on an illustrative surface), the PROJECTED badge, or correlation cell text.

### Heatmap palette — RECONCILIATION (planner: resolve before build)

CONTEXT.md says "reuse the WCAG-audited `palette.ts`" (the factsheet heatmap palette). Codebase scout found that the correlation surface already ships a **different** WCAG-audited palette, in `src/components/portfolio/CorrelationHeatmap.tsx`:
- Diverging **teal (negative ρ = diversifying) → `#F1F5F9` neutral (ρ≈0) → burnt-orange (positive ρ = concentration)**.
- Self-audited for deuteranopia/protanopia; CI contrast sweep (`CorrelationHeatmap.test.tsx`) locks min ratio ≥ ~3.75:1 (SC 1.4.11 non-text 3:1 floor) across ρ ∈ [−1, 1], with per-cell dark/white text auto-picked by luminance.
- Deliberately NOT equal to accent `#1B6B5A` so a correlation cell can't be confused with a verified/positive badge.

`palette.ts` (factsheet) is a DIFFERENT semantic: accent-teal = POSITIVE return, negative-red = NEGATIVE return, near-white at zero — a *return-magnitude* scale, not a *correlation-sign* scale. Applying it to correlation would invert the institutional reading (red would mean "negative correlation = good diversification", which is backwards and alarming).

**Decision recorded for the planner:** Keep the existing `CorrelationHeatmap` correlation palette (teal-diversifying / orange-concentrated) as the shared component's scale. It is the palette already in front of allocators on the correlation surface, it is the one whose semantic matches "correlation", and it is independently WCAG-audited with a CI lock. Treat the CONTEXT "reuse palette.ts" instruction as satisfied-in-spirit by reusing an *existing WCAG-audited heatmap palette* rather than inventing a new scale — but flag the literal-instruction divergence in the plan and get it ratified. Do NOT import `palette.ts`'s return-scale into the correlation component. (This is a genuine surfaced conflict per Rule 7 — pick the more-tested, semantically-correct one; document the other.)

### 2. Strategy Sandbox sidebar link (SURF-02 / SURF-03) — `Sidebar.tsx`
- Add a `NavItem` `{ label: "Strategy Sandbox", href: "/scenarios", icon: <BeakerIcon> }` to `workspaceItems`, rendered ONLY when `showsAllocatorWorkspace` is gated to **allocator-only** — i.e. `isAllocator` true, and NOT shown to manager-only or admin-only via the allocator path. (Distinct from "My Allocation", which today also shows to admins.) Plan must decide admin visibility explicitly: per CONTEXT "managers and admins see no Sandbox entry" → gate on `isAllocator` ONLY (exclude admin-only). Server already enforces the gate at the `/scenarios` route (`isAllocator = role IN ('allocator','both')` → else `redirect("/")`), so the sidebar hide is defense-in-depth, not the security boundary.
- Place it in the `MY WORKSPACE` section, BELOW "My Allocation" (and below Discovery is not literal — Discovery is its own section; "below Allocations/Discovery" from CONTEXT means: after the allocator's primary workspace links, before ADMIN/ACCOUNT). Recommended position: directly under "My Allocation" in `MY WORKSPACE`.
- Reuse the existing `NavItemLink` render (active-state `bg-sidebar-active`, `hover:bg-sidebar-hover`). New icon must match the existing inline-SVG convention (16px viewBox, 1.5px stroke, `currentColor`).
- Provide a new `BeakerIcon` (or `FlaskIcon`) following the existing icon factory pattern — a simple lab-flask/beaker outline signals "sandbox/experiment". No icon dependency.

### 3. Shared `<CorrelationHeatmap>` presentational component (CORR-01, CORR-02, CORR-04-superseded)
**Starting point:** `src/components/portfolio/CorrelationHeatmap.tsx` ALREADY EXISTS and is already consumed by the `/scenarios` Sandbox (`ScenarioBuilder.tsx`). This phase makes it the shared presentational component and adds the scenario-tab consumer. **Presentational extraction only** — matrix + de-aliased labels + legend; data computation stays per-surface (do NOT touch the Risk-tab matrix or `/scenarios` data paths — parallel-agent collision risk flagged in PROJECT.md).

Pinned visual contract (already shipped, keep):
- Grid: `display:grid`, `gap-px` over `bg-border` (1px hairlines), `gridTemplateColumns: "80px repeat(N, minmax(48px,1fr))"`, top-left empty corner `bg-surface`.
- Axis labels: de-aliased strategy name (CORR-01 — wire `strategyNames` from `scenario-dealias`), `text-[10px] uppercase tracking-wider text-text-muted text-center truncate`.
- Cells: `font-metric text-xs` (Geist Mono), value `v.toFixed(2)`, `backgroundColor = correlationBg(v)`, `color = pickTextColor(bg)` (luminance-driven). Diagonal cell `#F1F5F9` neutral; missing cell `#F8F9FA` with `—`.
- Per-cell `role="img"` + `aria-label` "{rowLabel} and {colLabel}: {v} correlation"; figure-level `role="figure"` + descriptive `aria-label` (PINNED — keep the screen-reader contract).

Required CHANGES this phase:
- **Remove `pickTopTenByAvgCorr` truncation (lines 128–143 + the `useMemo` at 146–149).** Per locked decision, **show ALL strategies, scrollable** — this SUPERSEDES CORR-04. Render every id from the matrix. Keep `className="overflow-x-auto"` on the figure wrapper AND add vertical scroll affordance for large N (e.g. wrap in a `max-h`-bounded scroll container at, say, ~70vh so a 20-strategy grid scrolls both axes instead of pushing the page). Cells stay ≥48px wide / labels stay legible.
- **CORR-04 reconciliation (document in plan):** with show-all there is no truncation, so the "shows the 10 most-correlated" disclosure is moot and must NOT be rendered. Do not add a "showing top 10" caption. The requirement is satisfied by removal, not by a disclosure string.
- **"Avg |ρ|" caption (CORR-03):** the component (or its host) renders a single caption "Avg |ρ| {value}" where value = mean of off-diagonal **absolute** pairwise correlations, computed ONCE and reused by the KPI strip (see §5). Caption typography: label `text-[11px] text-text-muted`, number `font-metric` 12px.

Empty state (CORR-02 — never a 1×1 grid, never a fabricated number):
- Trigger: `< 2` active strategies OR `< 10` overlapping days. (The current component only guards `ids.length === 0`; extend the gate.)
- Render the existing empty-state shell shape: `rounded-lg border border-border bg-surface px-4 py-8 text-center text-text-muted text-sm`.
- Copy MUST name the reason (see Copywriting). Never render a 1×1 grid; never show an "Avg |ρ|" number in the empty state.

### 4. Honesty framing on the projection (IMPACT-01) — both ScenarioComposer AND `/scenarios` ScenarioBuilder
- **Persistent PROJECTED badge** at the top of the projection panel header (always rendered, NOT a hover tooltip). Sits next to / under the "Scenario" `text-2xl` title in `ScenarioComposer`, and next to the equivalent title block in `ScenarioBuilder`.
  - Label: `PROJECTED — hypothetical, not your live book` (see Copywriting).
  - Token: neutral-outline pill per DESIGN.md badge ladder — `inline-flex items-center rounded-sm border px-2 py-0.5 text-[10px] uppercase tracking-wide font-semibold`, `border-text-muted text-text-muted` (mirrors the `csv_uploaded` trust-tier "outline, no fill" pattern). **Not** `bg-accent` (accent = verified/action, wrong signal) and **not** warning-amber (warning = transient recoverable state; a projection is not an error state). A calm neutral outline reads as "label/metadata", which is the honest signal.
- **Coverage caveat** directly under the badge or under the KPI strip: a single `text-[11px] text-text-muted` line naming **N overlapping days AND the shortest-history strategy name** (see Copywriting). This reuses the existing caveat slot pattern (`scenario-leverage-caveat` already renders a `text-[11px] text-text-muted` line in the same region — place the coverage caveat alongside it).
- ARIA: the badge is informative, not an alert — plain text, no `role="alert"`. The caveat is `role="status"`-free static copy (it doesn't change reactively in a way that needs announcing on every recompute; if planner wants it announced, use `aria-live="polite"`, never `assertive`).

### 5. "Avg |ρ|" single-source reconciliation (CORR-03) — `KpiStrip.tsx`
- The KPI strip already renders a cell `label: "Avg ρ"` (line ~416) sourced from `avg_pairwise_correlation`. **Reconcile the label to "Avg |ρ|"** so there is exactly one correlation number with one definition (off-diagonal absolute mean) across the scenario surface.
- The heatmap caption and the KPI cell MUST read the SAME computed value (compute once at the composer level, pass to both). Do not let the heatmap compute its own average independent of the strip.
- Keep the existing honest-pending behavior (`AVG_RHO_PENDING_SUB` / stale → null) — this phase changes the LABEL and single-sources the value, not the pending semantics.

### 6. Neuter-check regression test (IMPACT-02) — durable lock, not a visual
- Not a UI element, but it is the contract that protects the honesty surface. Assert: on a hypothetical blend, (a) no builder runs with `ingestSource: "api"`, and (b) no peer / allocator-percentile panel renders in the scenario projection (search the rendered tree for `PercentileRankBadge` / peer-percentile panels and assert ABSENT). The test MUST FAIL if a peer panel is ever wired into the scenario projection. Model on the project's existing "prove it fails when neutered" guard convention (e.g. `ScenarioComposer.test.tsx`, `KpiStrip.scenario.test.tsx`).
