## Worker lifecycle (load-bearing)
- Spawn `new Worker(new URL("../lib/montecarlo.worker.ts", import.meta.url))` only after gates 1–2 pass.
- `useEffect` keyed on the debounced `(portfolioDaily, n, horizon, paths)`; on change: terminate any prior worker, spawn, set computing, `postMessage(req)`; `onmessage` → set bands (only if this effect's run is still current — a ref/epoch guard against a stale late post); `onerror`/empty → error state. Cleanup: `worker.terminate()`.
- Debounce ~250–300ms so weight-scrub doesn't spawn a worker per keystroke.

## States (UI-SPEC) — guard order
1. `portfolioDaily.length === 0` → `EmptyStateCard` (scenario-side).
2. `evaluateSampleFloor(n, SAMPLE_FLOOR_OVERLAPPING_DAYS)` not ok → `SampleFloorEmptyState feature="Monte-Carlo" strategyCount`.
3. worker in flight → `Skeleton` + "Simulating forward paths…".
4. worker error / empty → `EmptyStateCard` (worker-error).
5. ok → `MonteCarloBandChart` + terminal summary + disclosure line (`methodologyLine(n)` + paths + block + "not a Normal model · not a forecast.") + honest-to-N note when n just above floor.

## Honesty invariants (test-pinned)

- Disclosure never a bare band; paths + block + N + "not a forecast" always present in state 5.
- Heading-matches-body (#509) for states 1 & 4; em-dash (not 0) on any null terminal value.
- Own-book composer only; Sandbox untouched; PROJECTED framing intact.
- No new color; band fill is `--color-chart-strategy` low-opacity; no number colored.
