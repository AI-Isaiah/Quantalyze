# Phase 26 — UI Design Contract: Stress Testing & VaR

> Visual and interaction contract for the new **"Stress & VaR"** section mounted in the own-book `ScenarioComposer` after `ScenarioBenchmarkSection`. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a heavy-reuse, conformance-only contract — NOT net-new visual design.** The section copies the visual language of the already-shipped `ScenarioBenchmarkSection.tsx` (heading + MetricRow + methodology caption + `EmptyStateCard`) and `SampleFloorEmptyState.tsx` verbatim. DESIGN.md owns every token; this file does NOT re-declare tokens — it pins which existing tokens the section uses and the states/copy it must render. No new visual language; no new primitive; ≤ 4 font sizes; ≤ 2 weights.

---

## Section Focal Point (declared)

The section's single focal point is the **shock-control row + the headline projected portfolio impact directly beneath it**. The accent color appears in exactly one place in this section: the *active* shock-preset segment (`border-accent text-accent`) — the affirmative selection the allocator is steering. Every downside number (VaR / CVaR, including losses) is neutral data type (`text-text-secondary`, Geist Mono), never colored. A loss is honest data, not an error — `#DC2626` is NOT used to paint a loss number.

## Typography

Conforms to the strategy-family **4-size / 2-weight** contract (DESIGN.md Decisions Log 2026-04-29). Exactly 4 sizes, exactly 2 weights (400 regular, 600 semibold). Sub-labels differentiate by color/transform, never a third weight.

| Role | Size | Weight | Font | Token (verbatim) |
|------|------|--------|------|------------------|
| Section heading (H3) | 16px | 600 semibold | DM Sans | `text-base font-semibold text-text-primary` |
| Headline impact value + metric values | 12px | 600 semibold (headline) / 400 (rows) | Geist Mono `tabular-nums` | `text-xs font-metric` — headline `font-semibold`, rows regular |
| Metric / control labels | 12px | 400 regular | DM Sans | `text-xs text-text-muted` (label) / `text-xs font-normal` (segment) |
| Methodology + empty-state body caption | 11px | 400 regular | DM Sans | `text-[11px] text-text-muted` |

Heading line-height: default (~1.2, Tailwind `text-base`). Body/caption line-height: default (~1.5, `text-xs`/`text-[11px]`). No `line-height` override — inherits the same as the benchmark section.

**Hard constraint honored:** 4 sizes (16 / 12 / 12 / 11 — the two 12px roles share the size, differing only by font-family and weight), 2 weights. No 5th size. No `font-medium` (500) in this section — the 16px heading is the only semibold-heading, the active segment uses `font-semibold` at 12px (both inside the 2-weight set).

## Color

DESIGN.md 60 / 30 / 10. This section adds zero new colors.

| Role | Value | Usage in this section |
|------|-------|----------------------|
| Dominant (60%) | `#F8F9FA` page / `#FFFFFF` surface | Section sits on page; `EmptyStateCard` is `bg-surface` |
| Secondary (30%) | `#E2E8F0` border / `#64748B` text-muted / `#4A5568` text-secondary | Hairline row dividers (`border-border/50`), labels, metric values |
| Accent (10%) | `#1B6B5A` | See reserved list below |
| Destructive | `#DC2626` | **NOT used in this section.** Losses are honest data, not errors. |

**Accent reserved for (explicit — never "all interactive"):**
1. The **active** shock-preset segment of the `SegmentedControl` (`border-accent` + `text-accent`) — the one affirmative selection.
2. The keyboard **focus ring** on interactive controls (`focus:ring-accent/50`, inherited from `Button`/segment focus).

That is the complete accent allowlist for this section. The accent is NOT used to color any number, any heading, any positive/negative impact, or the methodology caption.

**Loss-sign / color discipline (load-bearing):** a negative projected impact or a VaR loss renders as a neutral Geist Mono number (`text-text-secondary`), with the sign and percent format carrying the meaning. Do not apply `text-negative` / `#DC2626` to loss figures — that color is reserved for genuine errors/permanent failures (DESIGN.md), and a stress loss is an expected, honest output. Do not apply `text-positive` either. Numbers are monochrome data here.

## States (the contract the checker + executor verify)

The section is a pure presentational component fed resolved props (`portfolioDaily`, `btcDaily`, `btcAvailable`, leverage-aware metrics, `n`, `strategyCount`). It renders exactly one of:

| # | Condition (checked in this order) | Render | Copy source |
|---|-----------------------------------|--------|-------------|
| 1 | `portfolioDaily.length === 0` (scenario produced no returns — degenerate active set) | `EmptyStateCard` | heading + scenario-side body (see Copywriting) |
| 2 | `!btcAvailable` (BTC fetch failed/empty — mirrors `benchmarkAvailable=false`) | `EmptyStateCard` | "Stress testing unavailable" heading + body |
| 3 | `evaluateSampleFloor(n, 60)` is not `ok` (no-usable-n FIRST, then below-floor) | `SampleFloorEmptyState feature={…} strategyCount={…}` | `@/lib/sample-floor` builders (never re-authored) |
| 4 | ok | Shock control + headline impact + VaR/CVaR rows + mandatory disclosure line | below |

Guard order is non-negotiable and mirrors `ScenarioBenchmarkSection`: scenario-side absence first (never misattribute to BTC), then BTC unavailability, then the floor gate (which itself guards no-usable-n before below-floor). The empty-state **heading must match its body** (the #509 invariant) — a degenerate scenario must not be blamed on BTC coverage, and vice-versa.

**Degenerate → em-dash, never 0.** Every value in the ok state flows through `formatPercent` / `formatNumber`; a null / non-finite metric renders "—". Never fabricate a `0` impact or a `0` VaR.

**Mandatory inline disclosure line (per the VaR/CVaR rows — never a bare VaR):**
`Historical · {N} overlapping days · 95% · not a forecast.`
Built on `methodologyLine(n)` and extended with the confidence level, exactly as `ScenarioBenchmarkSection` extends it ("Metrics are 252-day annualized active returns."). Rendered once, `text-[11px] text-text-muted`, immediately below the metric rows. If a 99% level is shown (planner discretion), it must be disclosed in the same line. The N is the floor-gated overlap N actually used for the estimate, not a union window.

**Shock-control disclosure (inline, mandatory):** a short caption states the shock assumptions — single-factor (BTC only), linear β propagation, historical β over the same N overlapping days, point-in-time (no regime change), ending in the "not a forecast" framing. Same `text-[11px] text-text-muted` caption tier; may share the disclosure line with the VaR method line if layout keeps both legible.

**Visual layout (ok state), mirroring the benchmark section verbatim:**
- `<h3 className="text-base font-semibold text-text-primary">` — the section heading naming the shock + window (e.g. "BTC shock & downside risk over {N} overlapping days").
- `SegmentedControl` row of preset magnitudes (default −30% active).
- Headline projected impact: one `MetricRow`-shaped row (`flex justify-between border-b border-border/50 py-2`), label `text-xs text-text-muted`, value `text-xs font-metric` (headline value may be `font-semibold`).
- VaR (95%) row + CVaR / Expected Shortfall row, same `MetricRow` shape.
- Optional per-strategy β breakdown (planner discretion) uses the same MetricRow shape if built.
- Disclosure caption `<p className="mt-2 text-[11px] text-text-muted">`.
