<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → allocator generate/revoke routes | Authenticated allocator; `withAllocatorAuth` is the gate; created_by must come from auth, never the body |
| generate response → clipboard | The raw token is externalized exactly once (the URL in the 200 body); never logged, never re-fetched |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-08 | Spoofing / Elevation | created_by sourced from request body | mitigate | `created_by: user.id` from `withAllocatorAuth`, never the body; RLS WITH CHECK (`created_by = auth.uid()`) is the structural backstop. Proven by the generate route test. |
| T-25-09 | Information Disclosure | DB error text echoed to the client | mitigate | Redacted envelope: `console.error` + `captureToSentry`; client sees a stable "Couldn't create a share link. Try again." (F5a/F5b). Never echo `error.message`. |
| T-25-10 | DoS | unrestrained generate/revoke | mitigate | `userActionLimiter` (5/60s/user) AFTER zod validation (B15 ordering, so a 400 never burns a token); misconfig → 503 not a misleading 429. |
| T-25-11 | Information Disclosure (oracle) | revoke of non-owned share leaks existence | mitigate | 0-rows → 404 (NOT 403); identical response whether the scenario doesn't exist or isn't owned — no existence oracle (T-23-10 precedent). |
| T-25-12 | Tampering | raw token persisted / logged | mitigate | Only `hashShareToken(raw)` is inserted (`token_hash`); the audit log carries no token/draft content; the raw appears only in the response body. Proven: the generate test asserts the insert payload key is `token_hash` not `raw`. |
| T-25-SC | Tampering | npm/pip/cargo installs | accept | No package installs — all imports are in-tree (RESEARCH Package Legitimacy Audit = N/A). No legitimacy checkpoint required. |
</threat_model>
