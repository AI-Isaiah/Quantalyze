<objective>
Build the pure, dependency-light token primitive: `mintShareToken()` (256-bit `randomBytes` → base64url raw + its sha256 hex hash) and `hashShareToken(raw)` (the single digest source-of-truth the generate route and the public page both call). The raw token lives ONLY in the URL; only its sha256 hex is ever persisted (`scenario_shares.token_hash`) or passed to the RPC (`get_shared_scenario(p_token_hash)`).

Purpose: this is the leaf both Wave-2 plans depend on. Per the Plan 25-01 hash-in-Node decision (pgcrypto `digest` is not enabled in any migration), THIS file is the only place the sha256 algorithm is defined — the RPC matches against the hash this produces, so they cannot drift.
Output: one tiny pure lib + its unit test.

This is a security-critical phase, so the strong token (256-bit random + stored-hash) is the "don't simplify away security" exception, NOT gold-plating: a DB-read leak must expose no usable live links, and the stored-hash model is what makes SHARE-03 revocation possible (an HMAC-stateless token cannot be revoked without a denylist).
</objective>
