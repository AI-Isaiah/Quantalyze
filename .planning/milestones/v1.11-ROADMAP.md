### Phase 109: ROLE — predicate unification + page guards

**Goal**: One predicate (`profiles.role` = marketplace persona; `is_admin` = ops overlay only) drives nav, page access, and APIs, so an account only ever sees its own workspace — with staff access preserved via `role='both'`.
**Depends on**: Nothing (first v1.11 phase; unblocks the 403-blocked allocator QA)
**Requirements**: ROLE-01, ROLE-02, ROLE-03, ROLE-04, ROLE-05, ROLE-06
**Success Criteria** (what must be TRUE):

  1. A manager-role account sees no allocator workspace (My Allocation, Scenario, Recommendations, Compare, Decks) or Discovery catalog in nav; an allocator-role account sees ZERO sell-side surfaces (Strategies, Portfolios) at 109 close — the scoped "Add a Strategy" entry (arrives Phase 110) is the only permitted future exception (ROLE-02).
  2. `is_admin` adds only the Admin section and grants no marketplace-persona surface — an `is_admin`+`manager` account does NOT see the allocator workspace.
  3. Direct navigation (bookmark/URL) to a route the role doesn't own is server-side redirected to the role's home surface — never a 403 or a half-rendered page — using a three-branch failure model where a transient DB error does NOT redirect (mirrors `withAllocatorAuth`); the full `role × is_admin` matrix is enumerated and proven redirect-loop-free.
  4. **[GATE]** The `role='both'` staff backfill lands atomically (same PR/deploy) with the `|| isAdmin` drop, proven by a pre-merge SQL assertion that `is_admin=true AND role NOT IN ('both')` returns the empty set — no staff member loses access.
  5. A role-denied action shows honest copy naming the role requirement, never a retry that cannot succeed.

**Plans**: 3 plans (all complete)
