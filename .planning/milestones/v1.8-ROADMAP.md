## Overview

v1.8 makes every track record's *return magnitude* honest on every exchange. Anchor-to-today
silently over/under-states flow-heavy accounts (a live Deribit account onboarded at +458% cum /
229,214% CAGR, founder-confirmed inflated); this milestone replaces it with true time-weighted
returns computed from a **daily NAV series that dates every external cash flow**:
`r_t = (NAV_t − NAV_{t-1} − F_t)/NAV_{t-1}` (Wikipedia TTWROR Formula 1 = GIPS true-TWR).

Root cause pinned: `services/transforms.py:trades_to_daily_returns_with_status` sets
`initial_capital = account_balance − total_pnl`; when ≤ 0 (profits withdrawn) it silently falls
back to today's tiny equity as the return base with no DQ flag — cross-exchange, not
Deribit-specific. The spine is **shared-core-first / parity-gates-last**: build the pure NAV/TWR
core (73), wire both callers with a byte-identical zero-flow pin (74), land the Deribit dated-flow
adapter (75, RISKY inverse valuation), the Binance/Bybit/OKX adapters + reconciliation gate (76),
the uPnL basis reconciliation (77), and finally the golden old-vs-new parity + P72 acceptance HARD
GATE (78). No new dependencies (`ccxt==4.5.59` / `pandas==2.2.3` / `numpy==2.4.6`). Frontend /
factsheet UI is untouched — this is an analytics-service return-math correction.

Two Key Decisions (PROJECT.md, 2026-07-05): (1) **SPLIT annualization** — RETURN/CAGR (and Calmar)
on the 365/calendar clock, RISK (Sharpe/vol/Sortino/rolling_*) stays 252 (TWR-05). (2) **uPnL basis
= realized-basis intra-window NAV + `unrealized_pnl_in_anchor` DQ flag when material**; per-day
true-up only if Phase 77 confirms historical marks are retrievable on read-only keys.

## Phase Details

### Phase 73: Pure NAV/TWR Core

**Goal**: A pure, I/O-free `services/nav_twr.py` reconstructs the daily NAV backward from the real exchange anchor and chain-links a true daily TWR, with fail-loud DQ guards at every NAV denominator and the split (365-return / 252-risk) annualization basis — reproducing today's output byte-for-byte at zero flow
**Depends on**: Nothing (first phase of v1.8; the shared foundation everything else builds on)
**Requirements**: TWR-01, TWR-02, TWR-05, DQ-01
**Success Criteria** (what must be TRUE):

  1. `services/nav_twr.py` reconstructs `NAV_{t-1} = NAV_t − pnl_t − F_t` from the real anchor and chain-links `r_t = (NAV_t − NAV_{t-1} − F_t)/NAV_{t-1}`, cumulative `Π(1+r)−1`, stdlib/pandas/numpy only, with revert-proof numpy-pinned parity tests
  2. Every NAV denominator is guarded — dust-floor ($1000), negative reconstructed NAV, and flow-dominated capital each break the chain-link for that day and flag `complete_with_warnings`, never a fabricated number or synthetic base (DQ-01); no `clamp`/`floor`/`replace(0,…)` on a denominator
  3. The annualization basis is split in `metrics.py` — RETURN/CAGR (and Calmar) on the 365/calendar clock, Sharpe/volatility/Sortino/rolling_* stay 252 (TWR-05), mutation-verified falsifiable both ways
  4. The ACC-01 golden-parity delta-bucket classifier primitive exists (the panel + live run gate in Phase 78)

**Plans**: 3 plans (complete)

### Phase 77: uPnL Basis Reconciliation
**Goal**: The realized-vs-mark-to-market basis wedge between the anchor (incl. open uPnL) and the realized-only daily pnl stream is made explicit — the backward roll is realized-basis, uPnL is re-added only to the reported current NAV, and a material wedge fails loud rather than silently drifting every intra-window NAV.
**Depends on**: Phase 76
**Requirements**: FLOW-04
**Research flag**: Whether historical open-position marks are retrievable on read-only keys per venue is MEDIUM confidence — resolve at plan time; a per-day uPnL true-up is pursued ONLY if they prove retrievable.
**Success Criteria** (what must be TRUE):
  1. `exchange.py` gains a companion open-uPnL read alongside the equity anchor (the one genuinely new upstream data dependency)
  2. The core holds a realized-basis terminal NAV (`anchor − open_unrealized_usd`) for the backward roll so the roll and the increments share one basis, and re-adds uPnL only to the reported *current* NAV — no silent mark-to-market/realized blend; an account with a large open position across the window-end reconstructs with no step discontinuity at the anchor day
  3. `unrealized_pnl_in_anchor` (`complete_with_warnings`) is raised when `|open_unrealized_usd| / anchor_equity` exceeds the materiality threshold — honest surfacing over false precision
  4. Historical-mark availability on read-only keys is resolved per venue and documented in the core docstring — a per-day true-up lands only if marks are retrievable; otherwise the realized-basis-intraday / mark-to-market-at-endpoint invariant stands, documented and flagged
