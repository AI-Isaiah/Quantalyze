## Overview

Close the Bridge feedback loop. Five phases, one per task from the autoplan plan file (`~/.claude/plans/splendid-riding-whisper.md`). Phases 1 and 2 are independent foundations. Phase 3 consumes Phase 2 (scoring reads mandate columns). Phases 4 and 5 consume Phase 1 (feedback + dashboard read `bridge_outcomes`); Phase 4 additionally depends on Phase 3 so the scoring pipeline that will consume `scoring_weight_overrides` exists before the feedback engine writes to it. Success for the sprint = first allocator records an outcome, Bridge scoring incorporates mandate constraints, Outcomes widget shows at least one realized delta.

### Phase 4: Feedback Loop
**Goal**: `feedback_engine.py` reads `bridge_outcomes` history and adjusts per-dimension scoring weights per allocator. Rule-based v1: floor 0.5×, ceiling 1.5×, minimum 5 outcomes.
**Depends on**: Phase 1 (needs `bridge_outcomes` data) AND Phase 3 (scoring consumes `scoring_weight_overrides`)
**UI hint**: no
**Requirements**: FEEDBACK-01, FEEDBACK-02, FEEDBACK-03, FEEDBACK-04, FEEDBACK-05, FEEDBACK-06
**Success Criteria** (what must be TRUE):
  1. After 5+ positive outcomes tied to `W_PORTFOLIO_FIT`, the next scoring run pushes `W_PORTFOLIO_FIT` toward 1.5× default (capped).
  2. After 5+ negative outcomes, `W_PORTFOLIO_FIT` pushes toward 0.5× default floor.
  3. Fewer than 5 outcomes → defaults unchanged.
  4. Dimensions adjust independently (`W_TRACK_RECORD` unaffected by `W_PORTFOLIO_FIT` history).
  5. `allocator_preferences.scoring_weight_overrides` JSONB reflects the adjusted weights; `match_batches.effective_preferences` snapshots them at scoring time.
