<objective>
Make the final email-change confirmation link land on the Account tab even when Supabase's PKCE flow state has expired, instead of on /login and from there (through the proxy's signed-in bounce) on the role home page (GD-03).

Gap closed (219-VERIFICATION `gaps:` entry 3, first `missing` item): "emailRedirectTo next carries email_change=confirmed; callback code branch redirects to safeNext on exchange failure only when that marker is present; route test RED without the fix". The `emailRedirectTo` half is built by plan 219-06; the Account-tab half (the "Your sign-in email is now X." note) by plan 219-07.

Root cause, measured on PROD auth logs 2026-11-20 (219-CONTEXT GD-03): the completing link's `POST /token grant_type=pkce` failed 422 `flow_state_expired`, because GoTrue's PKCE flow state, created by the change request, lives only minutes and the link was clicked 18 minutes later. src/app/auth/callback/route.ts then redirected to /login?error, and src/proxy.ts bounces any signed-in user off /login to ROLE_HOME_ROUTE (/home), which redirects an admin to the admin dashboard. Auth had already completed the change. The same failure hits the single link after GD-01 whenever it is clicked late, so the fix is needed for the target flow too.

Why the fix is safe (GD-03): the failed exchange minted no session; the target is the same-origin path safeNextPath already allows; a signed-out user is sent to /login by the proxy as before; the Account tab reads the truth from auth.getUser() and never trusts the marker by itself (GD-04).

Output: a narrow edit to the code branch of src/app/auth/callback/route.ts and its route tests.
</objective>
