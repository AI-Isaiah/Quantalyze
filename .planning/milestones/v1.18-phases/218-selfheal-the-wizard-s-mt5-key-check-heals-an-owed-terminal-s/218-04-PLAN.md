Mechanics at HEAD, verified in source. Locate by symbol.
- In `WizardClient.tsx`, the `draftResumeStep` const is `"csv_upload"` for a CSV draft and `"sync_preview"` otherwise. The `useState` step initializer mounts it (or `connect_key` under a preselect) synchronously when `initialDraft` is set.
- `showResumeBanner` and `hydrated` both start false. The async hydration effect calls `loadWizardState()` (never throws) and `deriveWizardResumeOverrides(...)`, calls `setShowResumeBanner(true)` when the overrides say so, then calls `setHydrated(true)`.
- `deriveWizardResumeOverrides` (`src/lib/wizard/localStorage.ts`) shows the banner when no payload exists and a draft id is present, or when the payload's `strategyId` differs from the draft. A matching pointer resumes silently.
- `handleResume` clears the banner and sets `draftResumeStep`. `handleStartFresh` opens the confirm dialog; the confirmed delete sets the first step and clears the banner.
- The `wizard_step_view_N` effect is gated on `hydrated`.
- `InitialDraft.supported_exchanges` (`src/lib/wizard/draft-query.ts`) holds the draft's venue. MT5 is not a user chip, so `venueSecretIsVerbatim` (`src/lib/closed-sets.ts`, true only for mt5) identifies an MT5 key (RESEARCH A1).
- `SyncPreviewStep.tsx` has no secret input (RESEARCH A3).

This plan touches a client component only, not routing, config or APIs (AGENTS.md: no Next.js API change here).
