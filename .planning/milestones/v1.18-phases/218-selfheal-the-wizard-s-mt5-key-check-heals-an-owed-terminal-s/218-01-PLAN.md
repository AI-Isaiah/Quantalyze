<objective>
Make the wizard's MT5 key check heal an owed validation terminal itself. At the owed gate in `_validate_mt5_key_probe` (`analytics-service/routers/exchange.py`), instead of refusing with `MT5_TERMINAL_BUSY` and scheduling a scrub, pay the scrub inline under the lease already held, then run the check in the same request. Every non-`scrubbed` kind refuses before any client is built, with a code that names the real cause.

This reverses Phase 164.6.6.1 D-08's accepted cost ("the first validation after each analytics deploy is refused") and its Decision 6, per the ROADMAP Phase 218 goal and 218-CONTEXT.md (`### Inline scrub inside the wizard request`, `### The answer when the inline scrub does not come to scrubbed`, and the `### Amended after research` block, which supersedes the earlier bullets it names).

Purpose: the founder's 2026-11-19 13:14Z session showed "Our MetaTrader terminal is briefly busy" on the first wizard validation after a deploy. The scrub took about 6 s and a manual Retry passed. The user should never see that card for an owed scrub.

Output: the new never-raises sibling plus `budget_s` plumbing in `services/mt5_terminal_scrub.py`; the rewritten owed gate in `routers/exchange.py`; `MT5_TERMINAL_NOT_READY_DETAIL` in `services/closed_sets.py`; the park and wire-parity tests rewritten for heal semantics; the guards that pin the new sibling.
