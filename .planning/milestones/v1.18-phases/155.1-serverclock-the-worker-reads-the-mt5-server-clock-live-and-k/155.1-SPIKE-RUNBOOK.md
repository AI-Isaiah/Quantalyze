# Phase 155.1 — live tick spike: founder runbook

**When:** Monday 2026-11-16, in market hours, supervised. **Run by:** the founder. The agent
never touches the gateway.
**What it measures:** the five spike items in `155.1-CONTEXT.md` `<spike>`, using
`python -m scripts.mt5_spike --leg tick`. The command logs in once with the investor password,
makes read-only calls (symbol list, tick times, 30 days of deals), and prints counts, offsets,
ages and verdicts. It prints no symbol name, login, server or amount.

## Timing rule (all three must hold)

1. **Outside the derive window.** Not between 00:30 and 07:30 UTC. Key syncs land around
   01:00 UTC and the allocator derive fans out at 05:30 UTC. Any time 10:00–16:00 UTC on Monday is
   good. Just before you start, ask Claude to confirm over the Supabase MCP that no `mt5` job is
   in flight (`compute_jobs` with status `running`). The worker's lease covers its
   own process only. A spike login during a derive switches the shared terminal's account, and
   that derive then fails with `Mt5AccountMismatchError`.
2. **Away from the session-monitor tick.** In the analytics service logs, wait for a
   `mt5 validation liveness:` line. Start about 60 s after it, so the next tick is minutes away.
3. **Before the 157 rotation** of `MT5_SPIKE_INVESTOR_PASSWORD`. That rotation comes after this run.

## Clock leg (post-deploy live proof)

**When:** AFTER this phase is deployed to the analytics service. **Run by:** the founder. The
agent never touches the gateway and no test runs this leg against one.
**What it proves:** the leg calls the PRODUCTION `Mt5Client.server_tick_times`, so it runs the
exact committed remote expression (`_REMOTE_SERVER_TICK_TIMES_SRC`) on the live bridge. That
string has never run live. This is its first live proof, taken right after the deploy instead of
waiting for the nightly derive. It then assesses the reading under both rules with
`assess_server_clock_reading` and prints counts, offsets, the residual, verdicts and the
crossing's elapsed seconds. It prints no symbol name, login, server or amount.

**Why after the deploy, not before:** the leg imports `Mt5Client.server_tick_times` and
`assess_server_clock_reading`, which the container only carries once the phase deploys. The
single-file copy used for runs 1-3 is not enough. Running after the deploy is safe. Until the
expression is proven, a failing one only records `tick_read_failed` and never refuses a derive
(D-20(b)).

### What to paste back

Paste only the JSON block and the `exit=` line. The fields to read:

| Field | Answers |
|---|---|
| `server_clock_live.verdict_us` / `verdict_eu` | does the live clock match each rule. On a weekday outside a DST divergence week both read `match`. |
| `server_clock_live.measured_offset_s`, `raw_offset_s`, `residual_s` | the rounded offset (7200 or 10800 for this broker), the raw reading, and the rounding residual (the bound is 5 s) |
| `server_clock_live.symbols_total` / `symbols_visible` / `symbols_answered` | the expression ran: the listing size, the Market Watch subset and how many answered |
| `server_clock_live.reason` | `null` on a match; `tick_read_failed` means the committed expression failed live, so every derive reading would degrade to `unmeasured` |
| `server_clock_live.crossing_elapsed_s` | see below |
| `verdict` | the leg's call: `GO` on a us-rule match, `INCONCLUSIVE` on an unmeasured reading other than a failed read, `NO-GO` on a mismatch, a failed read or a login mismatch |

**`crossing_elapsed_s` is the reading that confirms or reopens the decision not to widen the
derive read bound (Plan 03).** It is the monotonic wall time of the one `server_tick_times()`
call: far-side `symbols_get` over the whole symbol list, the visible-symbol tick loop and the
rpyc round trip. No earlier run measured it. The 0.043-0.252 s spike figure timed a 14-symbol tick
loop only, and the 4.7-7.3 s listing figure was client-side netref iteration. Compare it with
`_MT5_DERIVE_READ_TIMEOUT_S` in `analytics-service/services/mt5_concurrency.py` (read the
constant by symbol, not from a number restated here). A figure well under that bound confirms
the no-widening decision. A figure near or over it reopens it. It never changes the verdict: it
is evidence for a human decision, not a threshold.

Exit codes: 0 report printed, 3 a variable missing, 1 another failure (the message is scrubbed).
