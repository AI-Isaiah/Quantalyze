# Phase 155.1 Plan 02: SERVERCLOCK oracle tests and founder-run clock leg Summary

**The assessment is now pinned by 35 independent hand-literal tests (the three live readings, wrong rule, fixed clock, stale tick, every unmeasured reason, the 5.0 s edge, check order, criterion 5's constructed near-midnight time), and the founder has a one-command `--leg clock` that runs the production `server_tick_times` bytes live and reports the crossing's elapsed seconds.**

## Accomplishments

- `test_mt5_server_clock_reading.py` (35 tests). Expected values are the recorded readings in `155.1-SPIKE-READINGS.md` (residuals 0.165, 0.164, 0.292) or DST facts derived by hand in a comment. A repeated hour (eu 2026-10-25 03:30) and a skipped hour (eu 2026-03-29 03:30) are fixture-checked with `candidates()` lengths 2 and 0, with the residual held at 0.1 s so the unassertable branch is the one reached. The five unmeasured reasons all occur among the cases of the reason-invariant test. `format_offset_hours`, the mismatch text (no run of five digits) and `server_label_hash` (case/whitespace equal, `hashlib` oracle, None for blank and non-string) are pinned.
- Criterion 5, as ruled 2026-11-17: `test_near_midnight_constructed_deal_time_anchored_to_2026_10_30_lands_on_the_us_rule_day` uses the CONSTRUCTED wall time 2026-10-30 02:30:00 (labelled constructed in the name, docstring and comment, never a real deal, no ticket/symbol/amount/login/server). Us gives 2026-10-29 (23:30Z), eu 2026-10-30 (00:30Z). `..._real_mm2_boundary_deal_2026_10_30_0300_agrees_under_both_rules` pins MM2's real 03:00:00 deal as the agreeing boundary. `-k near_midnight` selects exactly these 2.
- `run_clock_spike` / `_leg_clock` and `--leg clock`: one login, `assert_expected_login` on `account_info`, one call to the PRODUCTION `client.server_tick_times()`, `monotonic_fn` read immediately before and in a `finally` right after that call only, `utc_now_fn()` after it, assessment under both rules, `_safe_close` always. Overall verdict: GO on a us match, INCONCLUSIVE on unmeasured other than `tick_read_failed`, NO-GO on mismatch, `tick_read_failed` or a login mismatch. `crossing_elapsed_s` (3 decimals) does not move the verdict.
- `test_mt5_spike_clock.py` (13 tests): healthy GO, an hour-off clock NO-GO, timer bracketing (event order login, account_info, monotonic, server_tick_times, monotonic, close), slow crossing still GO, elapsed reported on a raise, failed read NO-GO/`tick_read_failed`, redaction, `no_tick` INCONCLUSIVE, login mismatch NO-GO with no tick call and neither login in the report, login error INCONCLUSIVE, exact key set, `main(["--leg","clock"])` runs only the clock leg.
- Runbook section "Clock leg (post-deploy live proof)": same timing rule and one-command shape, runs AFTER deploy (the single-file copy of runs 1-3 is not enough), paste back only the JSON block and `exit=`, with the field table naming `crossing_elapsed_s` as the reading that confirms or reopens the no-widening decision against `_MT5_DERIVE_READ_TIMEOUT_S` (by symbol).
