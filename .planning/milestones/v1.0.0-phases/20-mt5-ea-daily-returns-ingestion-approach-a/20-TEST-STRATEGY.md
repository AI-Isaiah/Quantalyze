# Test Plan — MT5 EA → daily-returns ingestion (Approach A, as written)

Generated by /autoplan (Phase 3 Eng) on 2026-06-14
Branch: chore/dep-security-hygiene | Repo: quantalyze

Constraint: the daily-return math lives in MQL5 (Wine) and has **no CI harness**.
Strategy: pin the EA's *output contract* with checked-in golden CSV fixtures, test the
*ingestion + KPI interpretation* in the existing Python suite, and gate first live KPIs
on a one-time manual demo-account reconcile. Tests below map 1:1 to Eng findings.

## A. Golden CSV fixtures → Python ingestion/KPI tests (CI)
Place fixtures next to the EA; assert via `run_csv_strategy_analytics` / `compute_all_metrics`
and `csv_validator.validate_csv(fmt="daily_returns")`. Each is a `date,daily_return` file
(fractional, no `currency` column) + an expected-KPI assertion.

| # | Fixture | Asserts | Covers finding |
|---|---------|---------|----------------|
| T1 | no-flow steady series | Sharpe/vol/CAGR/maxDD match hand-computed | baseline |
| T2 | **deposit-day** (deposit + same-day trading) | day shows trading return, NOT a cash spike | E4/E5 — the #1 test |
| T3 | withdrawal-day | return excludes the outflow | E5 |
| T4 | intraday-flow (deposit 09:00 then trades) | matches chosen convention; day flagged if approx | E4 (taste) |
| T5 | gap series (missing week) | rejected OR dense via zero-fill; vol on dense calendar | E2 |
| T6 | overnight open position across day boundary | return tracks equity (incl floating PnL), not balance | E8 |
| T7 | realistic fractional series | `info_flags == []` (auto-÷100 did NOT fire) | E7 |
| T8 | blank-currency file | validates OK | E1 |
| T9 | `currency=EUR` file | HARD-FAILS (documents the deliberate USD-only choice) | E1 |
| T10 | swap/commission days | included in return, NOT netted as flows | E5 |
| T11 | CREDIT/CHARGE/CORRECTION day | classified per table (excluded vs included), documented | E5 |
| T12 | overlapping/partial re-upload | full-replace semantics; no stale rows; history not truncated | E9 |
| T13 | DST boundary day | exactly one row, correct label, no dup/skip | E3 |

## B. EA-side checks (not CI, but mandatory)
- **T14 — manual demo-account acceptance reconcile** (gates first live KPI): on a demo
  account, open an overnight position, do a deposit and a withdrawal, restart the terminal,
  sleep the laptop past the snapshot cutoff. Then reconcile the EA's `daily_return` rows +
  audit sidecar against the MT5 account history by hand. This is the ONLY validation of the
  MQL5 balance-deal classification (E5) and restart-state (A1) — they can't run in CI.
- **T15 — restart-state test**: kill + relaunch the terminal between two days; assert the
  next day's return uses the persisted `prior_close_equity` (not a fresh/zero base).

## C. Security (CI)
- **T16 — read-only static check**: grep the `.mq5` source; FAIL if it contains
  `OrderSend|CTrade|PositionClose|PositionModify|OrderModify|OrderDelete|trade\.`. Wire as a
  tiny CI step on `tools/mt5/*.mq5`.

## Must-pass before any KPI is shown on a page
T2 (deposit-day), T5 (gap), T14 (manual reconcile). Without these three, a plausible-but-
wrong Sharpe can reach an allocator-facing page.
