<objective>
Add the T16 read-only security static-check to CI: a step that recursively greps `tools/mt5/**/*.mq5` AND `tools/mt5/**/*.mqh` (included headers) and FAILS the build on any order/trade-mutation API — the low-level surface, the CTrade method surface (`.Buy(`/`.Sell(`/`.PositionOpen(`/`.PositionClose(`/…), and `OrderSendAsync`. This is Phase 20's distinctive security control — it guarantees the recording EA can never place, close, or modify a trade on the user's account.

This is the M4 red-team hardening: the original denylist scanned only top-level `*.mq5` and missed the most common way an MQL5 EA places a trade — a `CTrade` instance named anything other than `trade` calling `.Buy(`/`.Sell(`, and trade calls hidden in an `#include`d `.mqh`.

Purpose: A recording EA with account access is a Tampering/Elevation risk; the denylist makes "read-only" a CI-enforced invariant, not a code-review hope.
Output: A new step in `.github/workflows/ci.yml` mirroring the existing banned-packages step.

Wave 2: depends on Plan 02 so the step greps a real EA file (and the legitimate read-only EA proves the denylist does not false-positive).
</objective>
