## Phase-Specific Contracts

### Contract A — Scenario KPI strip: remove AUM, reflow to 4 cells (PRESENT-01/02)

**File:** `src/app/(dashboard)/allocations/components/KpiStrip.tsx`
**Sole production mount:** `ScenarioComposer.tsx:3533` (always `mode="scenario"`).
Verified: the two other `<KpiStrip>` sites (`FactsheetView.tsx:196`,
`OutcomesWidget.tsx:910`) are DIFFERENT components with a `kpis` prop — they do not
import `components/KpiStrip.tsx`. So this edit touches the scenario tab only; there
is no live-dashboard collateral.

Contract:
- **Remove the AUM cell** — the first entry (`label: "AUM"`) in the `cells[]` array
  (currently `KpiStrip.tsx:373–389`). Nothing replaces it (no-invented-data; NO new KPI).
- **Remaining cells, left → right (4, all return-form):** `YTD TWR` · `Sharpe` ·
  `Max DD 12m` · `Avg |ρ|`. Order unchanged; this is the scenario-tab analog of the
  share page's existing "No USD, no AUM" strip.
- **Grid reflow (the ONE layout token change):** the inner grid at `KpiStrip.tsx:469`
  goes `@lg:grid-cols-5` → `@lg:grid-cols-4`. Keep `grid-cols-1 gap-3 @sm:grid-cols-2`
  exactly as-is (1-up mobile, 2-up small, now 4-up large). The `@container` host
  wrapper and every cell's `font-mono … tabular-nums` are preserved BYTE-for-byte
  (Phase 52 container-query + tabular-nums invariants).
- **PRESENT-02 guard:** `scenarioAum` computation stays. It still feeds the commit
  diff modal (weight × AUM sizing at the COMMIT boundary) unchanged. Only the KPI-strip
  *consumer* of the AUM number is removed. Whether the executor also drops the now-unused
  `aum` prop from the `<KpiStrip>` mount is an implementation detail — the visual
  contract is simply: the strip shows 4 return-form KPIs and no dollar figure.
- **Degenerate state unchanged:** all-excluded → null KPIs → em-dash "—" per the
  existing convention; the `scenario-data-sources-empty` honest card is untouched.

Executor freedom (within DESIGN.md): may implement removal as a straight `cells[]`
splice (preferred — single mount, `mode="scenario"` only) rather than a mode-gated
branch. Either way the rendered scenario strip is 4 cells at `@lg`.

### Contract B — Public share page: mixed-draft caption (PRESENT-03)

**File:** `src/app/scenario-share/[token]/page.tsx` (render) +
`src/app/scenario-share/[token]/share-resolve.ts` (the data the render reads).

**Render condition (LOCKED):** the caption renders iff the shared draft is MIXED —
`memberKeyIds` non-empty **AND** `addedStrategies` non-empty.
- At the render point the page is already on the `resolved.kind === "ok"` branch,
  which `share-resolve.ts` only reaches when `strategies.length > 0` (a book-only /
  zero-added draft returns `honest-absence "book-only"` at `share-resolve.ts:214`).
  So **"addedStrategies non-empty" is guaranteed by construction** at render time.
- The remaining live gate is therefore **`draft.memberKeyIds?.length > 0`** (book
  series ARE members of this mixed draft). This is the F3 red-team case: a draft that
  blends the owner's book keys with catalog adds, where only the catalog legs are
  publicly computable.
- **Pre-v4 shares** (upgraded v2/v3, `memberKeyIds` undefined) → `?? []` → falsy →
  **NO caption** (honest-absence-of-membership path unchanged; never invent a caption
  for a draft whose membership is unknown).

**Data threading note for the planner/executor (not a UI choice, but load-bearing):**
`ResolvedOk` does NOT currently expose draft membership — the page cannot see
`memberKeyIds`. The executor must surface a boolean (e.g. `isMixed:
draft.memberKeyIds?.length ? draft.memberKeyIds.length > 0 : false`, computed inside
the existing `kind:"ok"` return at `share-resolve.ts:267`) so the page renders the
caption without re-reading the draft. This reads ONLY the already-decoded draft JSONB
(zero private data, no RPC/SQL change — SECURITY BOUNDARY at the top of `page.tsx`
stays intact).

**DOM placement (LOCKED to the note register):** render the caption as a sibling
`<p>` **immediately after** the `methodologyLine` paragraph inside `<header>` (after
`page.tsx:214`), so the two honesty notes sit together directly under the PROJECTED
framing. Do not place it in the KPI grid, the chart section, or the correlation card.

**Styling (exact):**
```jsx
<p data-testid="scenario-mixed-caption" className="mt-1 text-xs text-text-muted">
  computed from this scenario&apos;s catalog strategies only
</p>
```
- `text-xs text-text-muted` = the exact classes of its `methodologyLine` sibling —
  quiet 12px DM Sans in muted register. `mt-1` matches the register's 4px rhythm.
- Escape the apostrophe (`&apos;`) per the surrounding JSX prose convention.
- `data-testid="scenario-mixed-caption"` for the public-role e2e (memory: cover the
  public/share user group). Keep the copy VERBATIM so grep-style assertions match.
- Never accent/warning/positive/negative; no `role`; static text node only.
