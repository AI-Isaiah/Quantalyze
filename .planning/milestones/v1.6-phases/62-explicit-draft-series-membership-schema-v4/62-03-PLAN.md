<objective>
Unify the "book-only" definition across the share surface: the mint gate and share-resolve
read the SAME null-safe `isBookOnlyDraft` predicate (membership contains per-key ids AND
addedStrategies is empty), and `memberKeyIds` rides the existing whole-draft jsonb through
`get_shared_scenario` with no RPC/SQL change. This is MEMBER-03.

Purpose: One definition of book-only across mint/resolve/compare (no per-surface drift),
and a security-critical proof that the new field round-trips without leaking through the
public share payload. Because the codec-decode schema is tolerant (plan 01), a pre-v4 share
arrives with membership undefined — share-resolve must keep its primary book-only detection
on the resolved `strategies.length` and rely only on the NULL-SAFE predicate for the reason,
so it never throws on the common pre-v4 share path (the checker's key_links warning).

Output: `share/route.ts` mint gate via null-safe `isBookOnlyDraft`; `share-resolve.ts`
book-only reason via the same predicate with strategies.length as the primary detector
(Open Question 1 recommendation a — no RPC expansion); the additive `memberKeyIds`
round-trip assertion in the RLS SQL with the over-return guard byte-intact.
</objective>
