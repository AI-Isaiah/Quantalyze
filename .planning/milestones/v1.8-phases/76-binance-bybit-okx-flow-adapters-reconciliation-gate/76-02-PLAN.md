  <behavior>
    ccxt_rows_to_dated_flows(rows, *, venue, price_index) → sorted list[ExternalFlow]:

    OWN-TRANSFER FILTER (per venue, on already-fetched rows):
      - binance: drop rows where row['internal'] is True; keep row['internal'] is False.
      - bybit: keep ONLY rows whose raw info.withdrawType == '0' (on-chain withdrawals);
        deposit rows are on-chain by nature and kept; drop off-chain/internal.
      - okx: rows are already structurally external (deposit/withdraw-history) → keep all.
      - Test (per venue): a real deposit + an internal own-transfer → ONLY the deposit
        survives to an ExternalFlow. MUTATION: neutering the filter lets the own-transfer
        through → RED.

    EVENT-TIME VALUATION (surviving rows):
      - currency ∈ STABLECOINS → usd = amount * 1.0.
      - else → usd = amount * price_index[(utc_day, currency_upper)] (same-UTC-day close).
        No same-day price → raise NavReconstructionError (fail loud). MUTATION: valuing a
        BTC flow at 1.0, or at a cross-day/current price, → the event-time test REDs.
      - SIGN: deposit rows → +amount, withdrawal rows → −amount. Trust ONE source (the
        deposit/withdrawal kind, or ccxt row['amount'] sign) — never re-derive after signing.
      - Same-UTC-day multi-flow collapses to one summed ExternalFlow (dict-by-day, like
        the Deribit producer). Day key via the shared _row_utc_day helper (import from
        deribit_txn — do NOT fork a date helper; Pitfall #11).
      - A missing/blank amount fails loud (schema drift → dropped capital), mirroring the
        Deribit _MISSING guard (deribit_txn.py:629-650). A numeric 0.0 amount is a no-op skip.

    PURITY: stdlib + typing + the imported ExternalFlow/_row_utc_day/STABLECOINS only.
    NO ccxt, NO network, NO pandas — the injected price_index is the ONLY price source.
  </behavior>
