<objective>
Add a SMALL, ADDITIVE, BACKWARD-COMPATIBLE `persist?: boolean` prop (default `true`) to
`FactsheetProvider` that gates its two view-state write effects (the URL `history.replaceState`
half and the localStorage `setStoredView` half). The factsheet itself never passes the prop, so
its behavior is byte-identical and its tests stay green; the composer mount (Plan 03) passes
`persist={false}` so scenario pans never rewrite the allocator's dashboard URL or write a
`factsheet-v2:` localStorage blob.

Purpose: This is the no-clean-analog risk flagged by PATTERNS.md. `FactsheetProvider` was built for
a factsheet page where URL/storage round-trip is desired (link-sharing); the composer is a dashboard
tab where it must not leak. The synthesize-payload seam (Plan 01/03) keeps every OTHER factsheet file
byte-identical; this one provider needs an opt-out because the write effects always run. An
additive default-`true` prop is the minimal way to honor "don't change the factsheet's behavior" —
it's an opt-out the factsheet never exercises.

Output: the gated `FactsheetProvider` + a test pinning both directions (default persists; opt-out
writes nothing).
</objective>
