<decisions_locked_by_planner>
- **D-P4 (replace, not coexist):** DROP the existing non-unique `idx_portfolio_analytics_computing (portfolio_id, computed_at DESC) WHERE computation_status='computing'` (mig `20260516170400`) and replace it with the single-column partial UNIQUE index. Verified: no query orders by `computed_at DESC` within the `computing` partition — the reaper (`reset_stalled_portfolio_analytics`) filters by age, and both in-flight checks are `.eq(portfolio_id).eq(status).limit(1)`. Two overlapping partial indexes would be pure write overhead.
- **D-P5 (plain build in ONE transaction, not CONCURRENTLY):** `BEGIN; SET LOCAL lock_timeout='5s'; LOCK TABLE public.portfolio_analytics IN ACCESS EXCLUSIVE MODE; <dedupe UPDATE>; <DROP old index>; <CREATE UNIQUE INDEX>; <verify DO block>; COMMIT;`. Rationale: a CONCURRENTLY unique build cannot share a transaction with the dedupe, leaving a window where a fresh duplicate aborts the build and strands an INVALID index. The atomic single-tx approach has ZERO dedupe->build race window. The HIGH-3 audit precedent (mig 20260516170400) objected to an UNGUARDED blocking build; here `lock_timeout='5s'` aborts cleanly if the lock is contended, and `portfolio_analytics` write volume is recompute-cadence (low), so the post-acquisition build is sub-second-to-seconds. Explicit ACCESS EXCLUSIVE up front (rather than letting DROP INDEX escalate mid-tx) avoids lock-escalation deadlock.
- **Dedupe survivor rule:** keep the row with the greatest `computed_at` (tiebreak: greatest `id`) per `portfolio_id`; set all others to `computation_status='failed'`, `computation_error='PI-07 dedupe: superseded duplicate computing row (migration 20260714090000)'`. `failed` is a valid enum value per the CHECK constraint (`20260407075303_portfolio_intelligence.sql`, `computation_status IN ('pending','computing','complete','failed')`) and is what the reaper itself uses.
- No new SQL function is introduced => no SECDEF hardening needed (research A3). If the executor finds itself writing a function, STOP — that violates this plan's contract.
- Test filename per 98-VALIDATION.md (the phase contract): `test_portfolio_recompute_inflight_unique.sql` (RESEARCH's alternate name is superseded).
</decisions_locked_by_planner>

Dedupe shape (ranked-CTE, mirrors the repo's rn=1 dedupe convention):
```sql
WITH ranked AS (
  SELECT id,
         ROW_NUMBER() OVER (
           PARTITION BY portfolio_id
           ORDER BY computed_at DESC NULLS LAST, id DESC
         ) AS rn
    FROM public.portfolio_analytics
   WHERE computation_status = 'computing'
)
UPDATE public.portfolio_analytics pa
   SET computation_status = 'failed',
       computation_error  = 'PI-07 dedupe: superseded duplicate computing row (migration 20260714090000)'
  FROM ranked r
 WHERE pa.id = r.id AND r.rn > 1;
```
