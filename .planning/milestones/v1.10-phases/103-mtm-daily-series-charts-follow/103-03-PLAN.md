<objective>
Thread the persisted MTM daily series through the ONE common downstream: a shared server-side reader for the `mtm_daily_returns` row, and a per-basis series bundle emitted by `buildFactsheetPayload` (`payload.seriesByBasis.mark_to_market`) derived by the SAME code path as the cash series. Charts consume it in Plan 103-04.

Why a server-side bundle (planned-through assumption): the basis toggle is EPHEMERAL CLIENT state (basis-context.tsx, GUARD-04) while the payload is a user-agnostic cached RSC blob (`${id}::${computedAt}`) — the server cannot know the toggle. So "the toggle swaps the daily SERIES feeding the one downstream" is honored at the derivation seam: buildFactsheetPayload derives BOTH bundles from their respective DailyReturn[] with the same function; the client picks the active one. Dailies-canonical holds: every MTM chart value traces to the persisted MTM dailies.

SCOPE (coordinator 2026-07-12, settles warning-5): the bundle reaches beyond the three chart tracks to EVERY statistics panel that is a pure function of the strategy's own daily return series. See the panel classification block below.

Purpose: MTM-04 payload half.
Output: types + reader + bundle emission + SC-4 byte-identity pins.
</objective>
