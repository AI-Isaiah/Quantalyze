## Phase Boundary

Phase 105.1 unifies the **onboarding sync-teaser compute** onto the one backbone route. The teaser arm (`analytics-service/routers/process_key.py:854-948`) today computes its public landing-preview scalars OFF the backbone (via `EquityCurveBuilder` on a synthetic 100k-NAV curve at √252 with bespoke fixups) and never touches `derive_basis_series`. 105.1 routes the **return-based** scalars through `derive_basis_series → compute_all_metrics` (one compute path) while persisting **no new series row** (user-chosen Option c).

**IN SCOPE:** route the sync-flow return-based scalars (`twr/sharpe/return_ytd/max_drawdown`) through `derive_basis_series`; keep writing the (now-derived) `metrics_snapshot`; re-source its `equity_curve` from the same derived series; a no-anchor-persist regression guard; the documented permanent preview-only exception in the invariant docstring + `.planning/BACKBONE-BYPASS-INVENTORY.md`; an advisory golden on teaser scalars.

**CENTRAL FACTS (fable-corrected — the research undersold these):**
- **No SC-4 byte-identity gate here.** The teaser is an explicitly-throwaway preview (`trust_tier='self_reported'`, heuristic capital documented as degrading 5-10×, 90-day expiry). "On the backbone" = STRUCTURAL unification, not byte-identity. The public preview numbers WILL shift (different input series than today's `EquityCurveBuilder`) — accepted.
- **Only the sync-teaser arm is a permanent bypass.** The async-onboard arm (`long_fetch.py:474-489`) already closes its window via a real tail job (`sync_trades`/`derive_broker_dailies → compute_analytics`) that persists a real series under the real `strategy_id`. Do NOT touch it.

**CARVED / DEFERRED:** `metrics_snapshot` store retirement + its 3 reader repoints → Phase 106. The dormant TS teaser twin (`src/app/api/verify-strategy/route.ts`, legacy arm, runs only when `isUnifiedBackboneActive()` is false — prod flag is ON) → delete in 106; a kill-switch rollback reverting the teaser off-backbone is acceptable (rollback = legacy by definition).

## Implementation Decisions (LOCKED — do not re-open in planning)

### D1 — SC1 reworded: compute-unified, persist-nothing (USER DECISION 2026-07-14)
- Route the teaser return-based scalars through `derive_basis_series` (the ONE compute path — kills the Phase-101 second-derivation class) but persist **NO series row**. Zero DDL / SECDEF / RLS.
- **SC1 is reworded** from "persists a daily series so no scalar-without-series window exists" → **"no teaser scalar is computed off the backbone; the teaser is a documented permanent preview-only exception to the persisted-series half of the invariant."** The teaser's scalar-without-persisted-series state is PERMANENT (survives Phase 106) — there is no series reader, and the shared archived sentinel anchor (`00000…0001`, `status='archived'`, user-less) makes any persisted row unreadable by construction (`fetch_strategy_lazy_metrics` requires published-OR-owner) and PK-collides across concurrent teasers.
- **Honesty conditions (MUST land in 105.1):** (a) document the exception in `basis_series.py`'s invariant docstring AND `.planning/BACKBONE-BYPASS-INVENTORY.md` ("teaser: derive-only, persist-none — no reader, anchor unreadable, permanent"); (b) a regression test asserting NO `upsert_strategy_analytics_series_batch` call under the `00000…0001` anchor; (c) the snapshot `equity_curve` re-sourced from the SAME derived series so the persisted artifact is internally coherent (today it's a separate `(1+r).cumprod()`).
- Option (a) (verification-scoped series table) REJECTED: prod DDL + RLS + SECDEF + 90-day cleanup tail for rows no reader can read. If ever wanted, it rides 106's fold migration.

### D2 — Conventions: crypto √365 per #597 (USER DECISION 2026-07-14)
- The teaser annualizes by asset_class per [[project_597_asset_class_annualization]] (crypto √365 / traditional √252). This RESOLVES the Rule-7 conflict: Phase-34/ANNUAL-05 "√252 everywhere" (2026-06-24) is SUPERSEDED for the teaser — its rationale is cross-strategy comparability on the discovery surface, which does NOT apply to a single-strategy self-preview. Flag Phase-34 as the not-chosen pattern (still governs cross-strategy discovery ranking; unchanged there).
- Accept the resulting public-preview number shift (~+20% Sharpe for crypto vs the old √252 builder, plus the capital-base/fixup delta from the input-series change). **Advisory golden** on teaser scalars = YES (shift-detector for future unintended drift; advisory, not a gate).

### D3 — Input series (Claude's decision)
- `trades_to_daily_returns(account_balance=None)` (`services/transforms.py:125-205`) — the same transforms family the finalize path uses, closest to the eventual canonical dailies. tz-aware `[us]` DatetimeIndex, survives `derive_basis_series`'s index math; can emit interior NaN (negative-NAV guard) which derive handles BETTER than today (`_drop_nonfinite` + `gap_spans` vs today's cumprod NaN-propagation).

### D4 — Flow scope: flow-agnostic swap (Claude's decision)

The csv/internal_report wizard previews shift too — ACCEPTED (same D2 convention). NOT a teaser-only fork.
- The CSV *finalize* path is a different branch (`finalize_csv_strategy`) and already routed (Phase 105) — untouched here.

### D5 — Shape: 4-key map, builder kept for trade-level stats (Claude's decision)
- The return-based scalars (`twr/sharpe/return_ytd/max_drawdown`) map from `result.metrics_json` (keys `cumulative_return/sharpe/ytd/...`) into the fixed `MetricsSnapshot` shape (`adapter.py:150-164`) via a **4-key map** — NOT a wholesale spread (a spread pushes ~50 keys through the public H-04 sanitizer to unauthenticated browsers — an avoidable public-surface growth).
- `EquityCurveBuilder` KEEPS running: `total_pnl/trade_count/win_rate` are trade-level, inherently NOT derivable from a daily-return series — a documented NON-exception (trade-level stats are trade-derived by nature). `compute_fingerprint(trades, metrics)` still needs the `MetricsSnapshot`.
