Make the allocator history probe take its raw OKX fills-history ordering read on every arm whose forced pass read OKX trades, and turn the OKX ordering gate into a code-derived token.

D-01, verbatim from CONTEXT: "The probe also takes its raw OKX fills-order read when the member is refused, so 173 measures OKX ordering on a4 now. Rebuilding a4 still waits on the bills-chain follow-up (OKXBILLSCHAIN)."
SC-1, verbatim from ROADMAP `### Phase 173`: "A multi-page OKX read records at least one ordering reading, so the TRADEPAGES gate reads `okx-order: ok` or `violated`, never `unmeasured`."

Root cause (CONTEXT, RESEARCH Q1): the raw `private_get_trade_fills_history` read lives in `_read_member` AFTER `er._fetch_and_price_window(..., require_anchor=True)`, and a refusal raises out of that function first. The refusal is raised at the END of `_fetch_and_price_window`, so the refusal arm's call snapshot already holds the whole forced OKX pass; the busiest instrument type is available from it.

Purpose: SC-1 can be met on a4 (refused `anchor_skipped_implausible`) on the next deployed probe run. Output: the probe and its tests changed, the runbook's P4 sentence reworded. Plan 02 (Bybit half) edits the same two code files and runs after this one.
