## New finding

### N1 - MEDIUM (user-facing if reached, low probability): the malformed-flag promise is false, and the failure direction is the harmful one

**Where:** `supabase/migrations/20261030120000_ledger_fanout_marks_paused_weekly.sql:534`, mirrored in `supabase/schema/functions/enqueue_ledger_refresh_for_strategies.sql:369-370`. The claim is made at migration header line 31, at the in-function comment (migration `:523`), in `docs/runbooks/ledger-refresh-go-live.md:684` ("a malformed value keep[s] the 20-hour cooldown"), and in CONTEXT D-04.

**Mechanism:** the fix compares the flag as raw text and drops the `~ '^\d{4}-\d{2}-\d{2}$'` guard that round 1 recommended. Text comparison against `'2026-10-24'` puts every string that sorts before it on the weekly side. Measured on the lane with `CURRENT_DATE - 3` as the cutoff:

| `marks_trailing_since` value | `weekly` |
|---|---|
| `""`, `"0"`, `0`, `"2026"`, `"2026-10"` | true (7 days) |
| `"abc"`, `true`, `"2026-13-45"`, a future date | false (20 hours) |
| `null`, key missing, `[]`, `"x"`, `{}` | NULL, so false (20 hours) |

So "never raises" holds, but "malformed falls to 20 hours" does not, and the failures go toward the 7-day freeze that D-04 exists to prevent. No gate arm seeds a malformed value, so the claim is unpinned.

**Reachability:** low. The two writers validate first: `job_worker.py` emits `.isoformat()` of a `date` (`:7720`), and `analytics_runner._read_navmtm_flags` drops anything that is not a real `YYYY-MM-DD` before publishing (`:1381-1437`). Reaching it needs an out-of-band write or a future writer that skips the validator. Treat it as the weakest MEDIUM here. The cost to fix is one line.

**Hidden errors:** a hand-edited or imported `data_quality_flags` (a restore, an SQL fix-up, a future writer) carrying an empty string or a truncated date silently gives the public chart a 7-day freeze, with no log or instrument row.

**Recommendation:** re-add the shape guard ahead of the compare, as round 1 sketched, and make arms P2 or P4 seed an empty-string flag so the claim is pinned:

```sql
AND (sa.data_quality_flags ->> 'marks_trailing_since') ~ '^\d{4}-\d{2}-\d{2}$'
AND (sa.data_quality_flags ->> 'marks_trailing_since') <= to_char(CURRENT_DATE - 3, 'YYYY-MM-DD')
```

`~` on text never raises, so the "cannot raise inside the tick" property is kept. The `v_age_needle` (`CURRENT_DATE - 3`) is untouched, so the verify block still holds. Update the P2 `RED-UNDER-M` find string if the predicate text changes.

- **Recorder and clearer:** `except Exception` does not catch `CancelledError`, so cancellation propagates. Every call site (`job_worker.py:7167`, `7234`, `7256`) is in the shared seam, and a swallowed failure cannot change the derive's outcome (now pinned for both directions).
- **Public leak:** `test_no_refusal_token_reaches_public_flags` is parametrised over the whole closed set. Unchanged by the fixes.
- **The loosened `others` filter** in `test_derive_broker_dailies_dualmode.py` excludes only the `nav_mark_refusal:` kind on `allocator_equity_derived`, so a stray write to any other table still fails the test.
- **Frozen forever?** No. The CASE only lengthens the attempt window and is keyed on `compute_jobs.created_at`; arm P3 (8-day attempt, 12-day pause) is admitted.
- **Flag age measures marks missing, not refusals:** after a gap with no derives, the first refused derive stamps an already-old `last_applied + 1`, so it goes weekly at once. That follows from D-04 as written ("the flag's own first trailing day"), so I recorded it as a limit, not a defect.
