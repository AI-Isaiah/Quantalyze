# Phase 164.9 Plan 08 — Ledger Round: an execution ledger that makes the live-DB lane's red mean something

**`frontend-live-db-lane` is GREEN on this tree for the first time since it was
built — not by relaxing anything, but because its 18 known-bad arms are now a
DATED, SHRINK-ONLY LEDGER and the job is green only when the failing set MATCHES
it. An unledgered failure reddens it; a ledger entry that stops failing reddens it
too. Both were observed, one of them end-to-end against a real neutered assertion.**

## The decision this implements

The founder chose the ledger explicitly over two alternatives, and both refusals
are kept in the artefact's own header so nobody re-litigates them:

| option | verdict |
|---|---|
| make the aggregator row advisory | ⛔ a forbidden closure |
| block the phase on a production baseline re-dump | someone else's work, on someone else's schedule |
| **a dated, shrink-only execution ledger** | **taken** |

One thing had changed since the decision was framed, and it is recorded rather
than smoothed over: the decision spoke of ~14 F1 entries. The real residue is
**18**, and it is **three kinds, not one**.

## Reproduction first, ledger second

Nothing was written until the tree had been measured. The stack was booted and the
lane run BEFORE any file was created:

## What was built

### 1. `scripts/live-db-execution-reporter.mjs` — the measurement

A vitest reporter that writes one machine-readable record of what the lane did.

⭐ **It exists because the built-in `json` reporter loses the fact the ledger turns
on.** MEASURED: for all six `wizard-rpcs-live-db` arms the built-in reporter's only
failure text is `expected { code: '42501', details: null, …(2) } to be null` — the
serializer has ELIDED the `message` field, and that field is the entire difference
between *"PostgreSQL withheld EXECUTE"* (K1, closed by a re-dump) and *"the
function body's own role gate answered"* (K2, which a re-dump may not close). A
ledger generated from the built-in reporter would have filed six entries under the
wrong kind — reproducing, mechanically, the exact misclassification plan 08 made by
hand and its fix round corrected.

⛔ The reporter observes the run at its end. It selects no test, skips no test and
cannot change an outcome. That is the property that lets the gate claim every test
still executes. Its artifact is **gitignored**: it carries verbatim failure text,
and the ledger carries verdicts only.

### 2. `scripts/live-db-execution-ledger.txt` — the ledger

**ENTRY_COUNT = 18**, beside a dated `MEASURED` block carrying the run it is a
picture of. Generated by `--generate` from that run's artifact; **not one entry was
typed by hand**.

Fields, TAB-separated: `<module>  <kind>  <signature class>  <arm>  # <destination>`

⭐ **Parsed BY TAB, never by stripping from `#` onward** — a deliberate divergence
from the sibling ledgers' `sed` idiom, which is safe for a migration basename and
would corrupt an arm name containing a `#`.

### 3. `scripts/live-db-execution-ledger.mjs` — the gate

Spawns `npm run test:live-db` **verbatim**, streams its output, then compares.
GREEN iff the failing set is EXACTLY the ledger. Beyond the two-direction set
comparison it refuses:

| guard | why |
|---|---|
| zero collected / zero executed | a run that could not have failed must never pass |
| fewer files than the derived corpus | the corpus must never be narrowed |
| unhandled errors | not arm-keyed, so never ledgerable |
| a lane exit that is neither 0 nor 1 | a crash is not a test failure |
| `ENTRY_COUNT` disagreeing with the list | a list with no recorded cardinality can be emptied without a red |
| a missing `ENTRY_COUNT` line | same |

`--self-test` ships **10 cases, a red and a green for each direction**, and CI runs
it as its own step BEFORE the lane — the `sql-gate-lint` discipline: the gate proves
it can fail before anyone is asked to trust it passing.

### 4. `src/__tests__/live-db-execution-ledger.contract.test.ts` — a gate for the gate

The ledger's own gate only runs inside `frontend-live-db-lane`, which needs Docker.
That is the right place to compare the ledger against a RUN and the wrong place to
be the ONLY thing standing between a public repository and a malformed or
specimen-bearing ledger. So the structural invariants are asserted in the ordinary
sharded suite, with no stack and no network: the self-test is EXECUTED, `ENTRY_COUNT`
agrees, every entry is well-formed with a known kind and class, and ⛔ **no entry
carries a specimen** — no absolute path, URL, DSN, JWT-shaped literal or long opaque
token.

⚠️ It deliberately does NOT pin the 9/6/3 tally. That is a measurement expected to
shrink, and restating it would make a correct shrink red — the "prose beside a
constant" defect `CLAUDE.md` records four separate times.

## The 18, as three kinds

| kind | n | closed by |
|---|---|---|
| `K1-baseline-privilege-state-absent` | **9** | a baseline RE-DUMP. `BASELINE.md` makes that a human-run command against production; no agent closes it alone. |
| `K2-function-body-role-gate` | **6** | a SEPARATE investigation. ⛔ NOT more K1. |
| `K3-migration-or-invariant-decision` | **3** | a migration against a production catalogue, or an invariant decision. |

**K2 is the correction that matters.** All six are in `wizard-rpcs-live-db`, and the
MEASURED failure is the function body's own role gate answering with SQLSTATE 42501
— the body was REACHED. The baseline DOES carry the REVOKE/GRANT pair for that
function, so **a re-dump may not close these six**; reaching the body at all points
at the `pg_default_acl` re-grant the column comment itself warns about. The arms
additionally assert a *"happy path (as `authenticated` — grant withdrawn by
20260814120000)"*, which is self-contradictory on its face. Plan 08's SUMMARY read
these as more K1; the fix round corrected it and this round keeps the correction —
in a machine-checked field, not only in prose.

⭐ **And the K2 routing rule is EVIDENCE-KEYED, not a hand-written list**: it fires
on the measured body-gate message, so an arm that stops answering that way stops
being K2 and reddens the gate.

**K3, one line each:** g10b P12 — a REAL production defect the lane surfaced (the
public wrapper routes to an internal overload whose INSERT omits `status`, so a job
enqueued WITH parents never enters the fan-in state); `match-decisions-xor-rls` —
asserts a unique index migration 081 REPLACED, so the repair is an intent decision;
`request-allocator-holdings-sync-queued` — the Queued shape is returned only from an
exception handler the RPC's own optimistic look-up prevents from firing.

⚠️ **What is MEASURED and what is JUDGED is stated in the artefact, not implied.**
Module, arm and signature class are measured and re-derived every run. The KIND is a
recorded judgement — *"a re-dump will close this"* is not something a test run can
observe. Two of the three routing rules are nonetheless evidence-keyed; the third is
the explicit three-arm list above, each with the fix round's derivation beside it.
