<objective>
ROADMAP criterion 11 asked for the shared-TEST flakiness to be MEASURED before a remedy was
prescribed. It now is: three attempts of one run at one commit, two different failure signatures on
two different test sets, then green on identical code. Non-deterministic victims across attempts is
the proof that this is TRANSPORT, not logic — and the deliverable is a bounded retry at the
transport boundary, observed to EXHAUST.

⚠️ RESEARCH found the Python half has NO analog in this repo: a grep of the Python tree for retry
and backoff idioms returns zero hits, and the exact call sites were UNMEASURED. ⭐ **This plan
measures the boundary first and then wraps it, rather than guessing where to put a decorator.**

⛔ The bash half of the same criterion is NOT here. It belongs with the advisory-key work (plan 06)
because it shares that root, and CONTEXT Area 3 locks those as one unit.

Purpose: keep an unreadable transport from being reported either as a clean run or as a defect in
the code under test.

Output: a hand-written bounded-retry helper with an injected clock, threaded at all four live-DB
client factories, with exhaustion and discrimination both observed.
</objective>

    - Test 1 (recovery): a fake execution that raises a transient transport fault on its first
      attempts and then succeeds returns the underlying result, and the recorded attempt count
