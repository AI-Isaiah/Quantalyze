    CORPUS DISCOVERY — walk `src/` with node's own `fs`, not a shell glob and not `grep`. Two
    reasons, both measured in this repo: a static filename glob misses the corpus (only a handful of
    the live-DB-gated files follow any naming convention), and at least one file under `src/`

    source paths must be overridable by CLI flag so the self-test can point at stub fixtures.

    CALL-SITE EXTRACTION — for each corpus file, find chained PostgREST call sites and record:
    the relation named by a string-literal `.from(...)`, the schema named by a string-literal
    `.schema(...)`, the function named by a string-literal `.rpc(...)`, and the object keys of an
    object-literal payload passed to `.insert(...)`, `.update(...)` or `.upsert(...)` on the same
    chain. ⛔ Anything not statically resolvable — a computed relation name, a spread payload, a
    variable — is recorded as `unresolved` and counted. It is never recorded as `ok`. The census
    must be honest about its own coverage; a tool that silently passes what it cannot read is the
    vacuity this repo's discipline exists to prevent.

    CLASSIFICATION — emit one finding per defect with a class of exactly `absent-table`,
    `absent-column`, `unexposed-schema` or `ambiguous-overload`, each naming the file, the relation
    or function, and the offending identifier. `ambiguous-overload` fires when the catalogue
    declares the called function more than once and the call site does not supply enough named
    arguments to select one — the shape a REST layer reports as an unresolvable overload.

    OUTPUT AND EXIT — print a summary line carrying the corpus size, the per-class counts and the
    unresolved count, every count DERIVED from the scan. Exit 1 when any finding is not present in
    the lineage allowlist; exit 1 when the corpus is empty; exit 0 otherwise.

    GREEN fixture under `scripts/live-db-fixture-drift-fixtures/`, against stub catalogue and stub

    `live-db-fixture-drift self-test OK (N rules, red+green each.)` with `N` derived from the rule
    table rather than restated. Fixture filenames follow this repo's existing convention:
    `<class>.red.ts` and `<class>.green.ts`.
  </action>
