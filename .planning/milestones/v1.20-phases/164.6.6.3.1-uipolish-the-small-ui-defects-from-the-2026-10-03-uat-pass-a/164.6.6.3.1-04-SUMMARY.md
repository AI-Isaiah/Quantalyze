# Phase 164.6.6.3.1 Plan 04: The alpha eyebrow keeps its glyph, and the page doubles learn strategy_shares Summary

The factsheet's alpha KPI eyebrow now renders "α VS BTC" (lower-case α under the uppercase) through a first-letter class gated on the alpha label, with both polarities pinned and neuter-proven; the three /strategies page doubles accept a `strategy_shares` read ahead of plan 05.

## What changed

`src/app/factsheet/[id]/v2/FactsheetView.tsx`
- The `factsheet-kpi-label` `<p>` className is now a template literal: the unchanged class set followed by `${it.label.startsWith("α") ? " first-letter:normal-case" : ""}`. The label string (`α vs ${cn}`), the element, its other classes and its style are untouched. A JSX comment cites D-09 and the measured reason the span form was not used. `grep -c 'startsWith("α")'` prints 1.
- Gating matters: applied to every label, "Sharpe" would render "sHARPE" (neuter proof (a) below pins this).

`src/app/factsheet/[id]/v2/FactsheetView.kpistrip.test.tsx` (+2 tests, new describe)
- Fixture: a 30-day record paired with BTC benchmark prices through `buildFactsheetPayload` and `activeComparator: "btc"`, mounted through the real `FactsheetBody` (the way `FactsheetBody.joint-floor.test.tsx` does). The existing scenario fixture in this file uses `benchmark: null` and so has no alpha cell.
- Test 1: the label found by `getByText("α vs BTC")` is the `factsheet-kpi-label` element, its class tokens include `first-letter:normal-case`, `uppercase`, `whitespace-nowrap`, `text-ellipsis`, and its `textContent` is exactly "α vs BTC".
- Test 2: the "Sharpe" label's tokens do not include `first-letter:normal-case` and still include `uppercase`.
- Tokens are compared by splitting on whitespace, so a substring match cannot pass.

`src/app/(dashboard)/strategies/page.share-affordance.test.tsx`
- `strategy_shares` added to the server double's allow-list. Hoisted `shares` and `sharesError` state, reset in `beforeEach`. The arm answers `{ data: shares, error: sharesError }`: with an error seeded it returns the seeded rows TOGETHER with the error (poisoned by design, documented in the double's comment). The `ShareableLink` probe's props type gains `hasActiveShare?: boolean` and each `shareProps` entry records it.

`src/app/(dashboard)/strategies/page.wizard-draft-banner.test.tsx`: `strategy_shares` added to the allow-list; the existing default empty answer is what this file wants.

`src/app/(dashboard)/strategies/page.key-pill.test.tsx`: an `else if (table === "strategy_shares")` arm before the throw, mirroring the `strategy_keys` arm (error answers `data: null`, as that file's other arms do), backed by new hoisted `shares` / `sharesError` reset in `beforeEach`. `state.calls` already records per table, so existing table-filtered call-count assertions are untouched.

Every change carries a comment citing Phase 164.6.6.3.1 D-05/D-06 Wave 0. No test asserts the new read; plan 05 owns those.
