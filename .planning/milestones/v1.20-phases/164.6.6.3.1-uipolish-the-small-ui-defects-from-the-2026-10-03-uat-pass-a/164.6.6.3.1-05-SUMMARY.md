# Phase 164.6.6.3.1 Plan 05: The /strategies row manages a live private link Summary

An unpublished /strategies row with a server-confirmed live private link now reads "Manage private link" and opens the existing share panel in a "Private link" Modal; the live flag comes from one two-column RLS-scoped read that fails closed and loud, and the row and the panel can never disagree about whether the link is live.

## What changed

`src/app/(dashboard)/strategies/page.tsx`
- After `const strategyIds`, `unpublishedIds` is the listed rows where `!isPublishedStatus(s.status)`. `liveShareIds` starts as an empty `Set` (the fail-closed value). Only when there are unpublished ids, ONE read on the request-scoped client (cast through `unknown as SupabaseClient`, as for `strategy_keys`): `.from("strategy_shares").select("strategy_id, revoked_at").in("strategy_id", unpublishedIds)`. Never `nonce` or `generation`.
- On an error, or when the data is not an array, `console.error("[strategies/page] active-share read failed", message)` and `captureToSentry(new Error(message), { tags: { route: "strategies/page", stage: "active-share" } })` (a fixed message for the non-array case); the set stays empty and no visible note is shown. Otherwise the set is filled in code by `revoked_at === null`, the factsheet's own rule, not in the query.
- The row mount passes `hasActiveShare={liveShareIds.has(s.id)}`. Only a boolean crosses to the client.

`src/components/strategy/ShareableLink.tsx`
- New optional `hasActiveShare`; state `shareLive` (seeded once from `hasActiveShare === true`, commented), `modalMounted`, `panelOpen`; `managing = !published && shareLive`.
- Idle label `published ? "Share Factsheet" : managing ? "Manage private link" : "Get private link"`; `onClick` opens the Modal when managing; `aria-haspopup="dialog"` only when managing. Variant, size and className untouched (sm/md class pins still green).
- Module-scope `dynamic(() => import(".../FactsheetView").then((m) => ({ default: m.OwnerUnpublishedPanel })), { ssr: false, loading: <div className="h-24" aria-hidden /> })`. A static import would be a cycle and pull the whole factsheet module into /strategies and discovery detail.
- Returns a fragment: the Button, then `{modalMounted && <Modal open={panelOpen} title="Private link">{panelOpen && <OwnerUnpublishedPanel strategyId hasActiveShare={shareLive} onShareLiveChange=... />}</Modal>}`.
- `handleCopy`'s unpublished arm calls `setShareLive(true)` right after `mintShareUrl` resolves and before the clipboard write; a failed mint returns earlier and never sets it.
- The Button block was not re-indented inside the new fragment, to keep the diff surgical (the repo has no prettier config).

`src/app/factsheet/[id]/v2/FactsheetView.tsx`
- `OwnerUnpublishedPanel` gains optional `onShareLiveChange?: (live: boolean) => void`. The state setter is renamed `setShareLiveState`; a `React.useCallback` `setShareLive` sets state then calls the host, and is passed to BOTH children. The callback runs on the event path only (mint success, revoke 2xx/404), never at mount and never on a failed revoke. Existing callers pass nothing and are unchanged (pinned byte-identical).

Tests (four files plus the key-pill double):
- `ShareableLink.test.tsx`: dialog polyfill, sentry and next/navigation stubs, new describe with: live row reads Manage and opens the Modal with no fetch; published ignores the prop; absent prop stays Get private link with no popup and no dialog; Close goes through the native close; revoke 200 and 404 close and flip the row; revoke 500 keeps Modal and Manage; successful mint flips to Manage after "Link copied!" clears; failed mint never claims a live link.
- `FactsheetView.share-affordance.test.tsx`: panel callback fires once with true on mint, once with false on revoke 200 and 404, not on revoke 500; absent prop is byte-identical.
- `page.share-affordance.test.tsx`: `hasActiveShare` reaches each row from one read (A live, B revoked, C none, published P false); a poisoned failed read leaves every row false and is logged. Added an inert `@/lib/sentry-capture` mock.
- `page.key-pill.test.tsx`: `sharesAnswer` override on the double; guards for one batched read of exactly the unpublished ids with a single `"strategy_id, revoked_at"` select, no read with zero unpublished rows, tags-only log and capture for an error and for a non-array answer (neither message nor context carries a strategy id), and nothing captured on a healthy read.
