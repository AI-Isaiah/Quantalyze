<decisions>
## Implementation Decisions

### Behaviour (founder, 2026-10-06, smart discuss Area 1, "Discuss deeper")
- **D-01 (item 1).** The edit page keeps the name picker, and it always includes and preselects
  the strategy's OWN name. A name outside `STRATEGY_NAMES` (e.g. "MM-2x") is no longer replaced by
  "Alpha Centauri".
- **D-02 (item 1, Claude's discretion by founder "You decide").** The edit-mode update payload
  carries `name` ONLY when the user changed the picker. A deliberate pick still renames; an
  unrelated save never does.
  - Test: an off-list name survives an unrelated save.
  - Test: a changed pick sends the new name.
- **D-03 (item 6e).** Until the first key read settles, the key card shows a single caption line,
  "Loading keys…", never "No API keys connected." A load error keeps its existing error state.
- **D-04 (item 6e).** This phase fixes only the misleading empty state. The ~20 s key-list read is
  measured (PROD, read-only); if it is real, it is booked as a `TODOS.md` entry. It is not fixed
  here.
- **D-05 (item 6f).** When a live (non-revoked) private link exists, the /strategies button reads
  **"Manage private link"** and opens the existing share panel/dialog, showing the live link with
  copy and revoke. Live links are found by ONE batched read of the owner's non-revoked shares for
  the listed strategies, not one read per row.
  - **Clarified (founder, 2026-10-06, after the UI-SPEC):** `ShareableLink` opens no panel at HEAD.
    The modal reuses `OwnerUnpublishedPanel` (from `FactsheetView.tsx`) inside the existing `Modal`,
    titled "Private link". It states that the link is live and offers copy and revoke. It does NOT
    print the URL, so opening it makes no mint-or-reuse call.
- **D-06 (item 6f).** If that read fails, the button falls back to today's "Get private link" and
  the failure is logged. It never claims a live link that was not confirmed.

### Visual and copy (founder, 2026-10-06, smart discuss Area 2, "Accept all")
- **D-07 (item 6a and 170.6's disclaimer item).** Remove the page-level `Disclaimer` from
  `recommendations/page.tsx`, since `DashboardChrome` already renders it, and check
  `portfolios/[id]/page.tsx` for the same doubling. The "Batch: Fresh" chip shows the batch date,
  for example "Batch: Fresh · 6 Oct", through the shared date formatter.
- **D-08 (item 6c).** The "My Allocation" bottom-nav label may wrap to two lines (`min-w-0`,
  centred, no ellipsis), so the product name stays whole at 320px.
- **D-09 (item 6d).** Keep the α glyph and exempt it from the CSS uppercase (`normal-case` on the
  glyph), so the label reads "α VS BTC".
- **D-10 (item 8).** The venue label comes from `src/lib/api-key-label.ts` ("MT5", matching the
  allocator card).
  - The key card's left block gets `min-w-0` and its actions `shrink-0`.
  - When space runs out, the actions wrap as a whole row, never one word per line.
  - 164.5.3 closes only after a founder re-read.

- Exact skeleton and caption styling within DESIGN.md.
- The batched-share-read query shape, which follows existing share-row reads (the factsheet's
