<objective>
Item 6f of 164.6.6.3 (D-05, D-06): the /strategies row knows whether a private link is live, says
"Manage private link" when it is, and manages it in the existing share panel inside a Modal.

Recorded choices (Claude's discretion under CONTEXT, set by the orchestrator, or measured):
- **D-05 clarified 2026-10-06:** the Modal reuses `OwnerUnpublishedPanel`, titled "Private link".
  It states the link is live and offers copy and revoke. It does NOT print the URL, so opening it
  makes no mint-or-reuse call. A test pins "no fetch on open".
- **Decision 1 (orchestrator, RESEARCH Q2):** the Modal closes on a live-to-not-live transition
  after a successful revoke, and stays open on a failed revoke.
- **Decision 2 (orchestrator, RESEARCH A3):** after a successful row mint, `ShareableLink` calls
  `setShareLive(true)`, so the row never reads "Get private link" over a live link. Consistent with
  D-06: the mint itself confirmed the link.
- **Dynamic import uses the repo idiom** `.then((m) => ({ default: m.OwnerUnpublishedPanel }))`
  with `{ ssr: false }` at module scope (every other `next/dynamic` site in `src/` wraps in
  `{ default }`). A static import would create a cycle (`FactsheetView.tsx` already imports from
  `ShareableLink`) and pull the whole factsheet module into /strategies and discovery detail.
- **The Modal mounts on the row's first open and then stays mounted; the panel mounts only while
  open** (`modalMounted && <Modal open={panelOpen}>{panelOpen && <Panel/>}</Modal>`). This is
  narrower than RESEARCH's `shareLive || panelOpen`: `Modal` always renders its title and a Close
  button inside the `<dialog>`, so mounting it on every live row would add a dialog and a button per
  row and could make existing `getByRole("button")` queries ambiguous. A row that was never opened
  keeps today's DOM plus at most `aria-haspopup`. Keeping the Modal mounted after the first open
  (plan-check A2) is what lets every close path, Close button, Esc and a successful revoke, go
  through `Modal`'s `open={false}` effect, which calls the native `dialog.close()`. The browser then
  returns focus to the row button. Unmounting an open dialog would skip that and drop focus to the
  body. jsdom does not implement that focus return, so the tests pin the `close()` call, and a
  keyboard focus check joins the human 320 px / 1440 px re-read.
- **The dynamic panel has a minimal `loading` fallback** (plan-check A2), as every other
  `next/dynamic` site in the repo does: an `aria-hidden` block of fixed height, no copy and no
  spinner (DESIGN.md Motion), so the Modal does not jump when the chunk arrives.
- **Log prefix** `[strategies/page] active-share read failed` matches the page's own read
  failures (the UI-SPEC's `[strategies]` line is an "e.g."). Tags-only capture, stage
  `active-share`.
- The panel's inner share button fires `trackFactsheetEvent("factsheet_v2_share_copy")` from
  /strategies too, carrying `strategy_id` only. Accepted and noted, not changed.

Output: the batched page read; the extended `ShareableLink`; the panel's optional callback; tests in
four files.
</objective>
