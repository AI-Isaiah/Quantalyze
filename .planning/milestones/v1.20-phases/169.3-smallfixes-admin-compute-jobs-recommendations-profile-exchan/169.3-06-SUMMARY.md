# Phase 169.3 Plan 06: Credential inputs opt out of autofill and strip pasted whitespace Summary

One pure helper, `src/lib/credential-input.ts`, now holds D-76's paste rule and attribute sets, and six credential surfaces use it. Masked inputs carry `autocomplete="new-password"` and every credential input carries the 1Password, Bitwarden, LastPass and Dashlane ignore attributes. Key and secret strip pasted leading/trailing whitespace (including U+200B and U+FEFF). Typed keystrokes and the OKX passphrase are never stripped. The MT5 Update password gets the attributes and no strip.

## Decisions and recorded limits

- **MT5 Update password: attributes only, no strip** (D-76, 2026-09-30 line). The rotate path never trims: the route uses `.trim()` only as a presence check and forwards the raw `body.new_secret`, and `internal.py` passes it straight to validation and encryption. A client strip would change the stored password. The component's CREDENTIAL HANDLING docblock now says so.
- **Create-versus-rotate asymmetry, left as it is:** the MT5 investor password is trimmed at creation (the wizard secret slot, `create-with-key` → `validateKey` → `trimCredential`) and not trimmed at rotation. This predates the phase, and both server paths are unchanged (routed to Phase 164.6.6 by `c7d47efe3`).
- **Landing form's route does not trim and was left unchanged** (D-76, plan-check round 1 line). `/api/verify-strategy` forwards `api_key` raw. On that surface the client strip changes what is posted, deliberately, so what is posted equals what the field shows. The posted-body test pins this.
- **Keystroke exception (D-76):** leading/trailing whitespace a user TYPES stays in the field. Only bulk-arriving input is normalized (paste, drop, autofill, programmatic change, or no inputType).
- **jsdom observation:** a single-line `<input>` sanitizes CR/LF out of a pasted value before `onChange` runs. This follows the HTML value-sanitization algorithm for single-line inputs, which real browsers also apply; that part is sourced, not observed here. So on the DOM surfaces the line-break part of each paste case is stripped by the input itself. U+200B, U+FEFF and spaces reach the rule, and they are what the surface paste cases pin. The rule's own CR/LF handling is pinned in `credential-input.test.ts`.
- The MultiKeyConnectStep docblock sentence that claimed `autoComplete="off"` was replicated VERBATIM was rewritten. It now says the attributes and paste rule come from `src/lib/credential-input.ts` (169.3 D-76). The rest of the docblock is untouched.
