### CR-01 = SFH-01 [HIGH]: A failed preferences read shows "No mandate is set yet" and hides every recommendation

**Files modified:** `src/app/(dashboard)/recommendations/page.tsx`, `src/app/(dashboard)/recommendations/page.mandate-gate.test.tsx`
**Commit:** `56ddcedc8`
**Applied fix:** The preferences read now takes `error`. On an error it logs `[recommendations] allocator_preferences read failed:` with the code and message, following the attestation read above it. The mandate is `set`, `unset` or `unknown`. `unknown` renders a neutral header ("Strategies from the daily match engine."), a "We couldn't load your mandate" notice, and then whatever the batch holds. It never renders the set-mandate call to action or "No mandate is set yet", and it never withholds the list.
**Test:** ER1 (the read fails and a 3-candidate batch exists): the list renders, no CTA, no "No mandate is set yet", no mandate-fit header, the notice renders, and the breadcrumb is logged. ER2: a missing row with no error is still `unset`.
**Neuter → RED → restore:** the page was replaced with its pre-fix version (`git show HEAD:page.tsx`, with the new test in place). ER1 went RED (`1 failed | 14 passed`). After restoring from a byte backup, `cmp` matched and the suite was green.

### WR-01 [MEDIUM]: An allocator whose engine-consumed mandate lies outside the two gated fields sees no recommendations

**Files modified:** `src/app/(dashboard)/recommendations/page.tsx`, `src/app/(dashboard)/recommendations/page.mandate-gate.test.tsx`, `169.3-CONTEXT.md` (new decision D-73), `.planning/ROADMAP.md` (a dated line under `### Phase 169.3`)
**Commit:** `074b5c788`
**Status:** fixed: requires human verification. This is a behaviour change decided by a founder ruling, so a person should confirm the field set.
**Founder ruling (2026-09-30, AskUserQuestion, "Hide only if no field set"), recorded as D-73:** D-03's `deriveMandateIsSet` keeps deciding the mandate wording here and on `/allocations`, unchanged. The list is withheld only when no preference the engine reads is saved.
**Applied fix:** The page defines `ENGINE_PREFERENCE_FIELDS`, the fields the match engine reads, measured in `analytics-service/services/match_engine.py` and `routers/match.py` against the `AllocatorPreferences` TypedDict in `services/match_defaults.py`:
- `max_weight`
- `preferred_strategy_types`
- `excluded_exchanges`
- `max_drawdown_tolerance`
- `correlation_ceiling`
- `liquidity_preference`
- `style_exclusions`
- `target_ticket_size_usd`
- `min_sharpe`
- `min_track_record_days`
- `max_aum_concentration`

Left out on purpose:
- `mandate_archetype` and `preferred_markets`: both are in the TypedDict, but the engine never reads them.
- `scoring_weight_overrides`: this is the feedback engine's output, not a saved preference.

The page selects exactly these columns. `hasEngineUsedPreference` counts a non-null scalar as saved (a saved 0 counts, as in D-03) and a list only when it is non-empty. The withhold fires only when the mandate is not `unknown` and the row has no engine-read preference.

Checked before relying on this:
- The table grants SELECT to `authenticated` at table level, and there are no column-level revokes in migrations. The own-row RLS policy is `allocator_prefs_self_read`. So widening the select cannot 42501.
- The self-edit RPC `update_allocator_mandates` inserts NULL for any field that was not passed, so no engine field gets a default value. The "nothing saved" state can therefore still be reached.

**Tests:**
- EP1 (drawdown tolerance only): the list renders, there is no CTA, and the header reads "No mandate is set yet" per D-03.
- EP2 (only empty lists): the list is still withheld.
- MP5 now compares the header wording with `deriveMandateIsSet`, and DRAWDOWN_ONLY was added to its cases. After D-73, the header wording is where D-03 applies.
- The `ARCHETYPE_ONLY` fixture's `target_ticket_size_usd` changed from `1` to `null`. The page used not to select that field, so the `1` was invisible before. Now that ticket size is an engine-read field, keeping the `1` would make the fixture a scored mandate and contradict its name.

**Neuter → RED → restore (two neuters):**
- (A) Withhold driven by the old D-03 rule: EP1 went RED (`1 failed | 19 passed`).
- (B) Select narrowed back to `max_weight, preferred_strategy_types`, which the projection-honest mock catches: EP1 went RED (`1 failed | 19 passed`).
- Restored from a byte backup; `cmp` matched.
