## Warnings

### WR-01: MEDIUM. Every inputType outside the keystroke list normalizes the whole field, so undo and redo can delete an interior space that was typed

**File:** `src/lib/credential-input.ts:39-46` (`isKeystrokeInputType`) and `:59-63`
(`readCredentialInput`). Reached from the wizard secret slot at
`src/app/(dashboard)/strategies/new/wizard/steps/ConnectKeyStep.tsx`
(`setApiSecret(readCredentialInput(e))`) and from
`src/app/(dashboard)/strategies/new/wizard/steps/MultiKeyConnectStep.tsx`
(`onUpdate(index, { apiSecret: readCredentialInput(e) })`). Those two slots carry the MT5
investor password.

**Issue:** `isKeystrokeInputType` is a denylist. It returns raw only for `insertText`,
`insertCompositionText` and `delete*`. Every other inputType goes to
`normalizeCredentialInput`, which strips the edges of the WHOLE current field, not the
edges of the inserted text. D-76 names four intended bulk cases: paste, drop, autofill
and a change with no inputType. The denylist also sends inputTypes D-76 never
considered through the strip: `historyUndo`, `historyRedo`, `insertFromYank` and
`insertTranspose`.

These events do not insert bulk text. They restore or move text the user typed, and that
text can end on the very space the keystroke guard exists to keep. The helper's own
docblock says "Interior characters are left alone" (`:28`). For these types that is
false.

Failing scenario, wizard, MT5 selected, investor password `pass word` (D-76 itself
says an MT5 password may legitimately contain spaces):

1. Type `pass`, a space, then `w`. Every event is `insertText`, so the field holds
   `pass w`.
2. Press Cmd/Ctrl+Z. The DOM becomes `pass ` and the event's inputType is `historyUndo`.
   The helper strips the value to `pass`, and React writes `pass` back into the input.
   That write also discards the input's native undo stack, so Cmd+Shift+Z cannot restore
   the space.
3. Type `word`. The field holds `password`. The input is masked, so the user cannot see
   the lost space.
4. Submit. `password` is posted, and it is what the field holds. The server trim cannot
   restore the space, so the broker rejects the login as a wrong password. The user has
   no way to see why.

A second route to the same loss: type `word`, move the caret to position 0 and paste
`pass `. The field becomes `pass word`, with no edge whitespace, so nothing is lost.
Now reverse it. Type `pass ` (the trailing space is kept raw), move the caret to
position 0 and paste anything. The whole-field strip removes the typed trailing space
that the user was about to follow with more text.

Impact is bounded. The broker validates before anything is stored, so a wrong password
is rejected, not persisted, and no data-integrity risk follows. The harm is user-facing:
a credential is changed silently, in a masked field, with no signal. That is the exact
failure the keystroke guard was written to prevent. Exchange API keys and secrets do not
contain interior whitespace in practice, so the MT5 secret slot is where this bites.
None of the plan's tests covers a `history*` inputType or a paste into a non-empty
field. `src/lib/credential-input.test.ts:57-77` covers only
`insertFromPaste`/`insertFromDrop`/absent against `insertText`/composition/delete.

**Fix:** Invert the rule. Normalize only the bulk-insertion types D-76 named, and return
everything else raw, the way `history*` and any unknown or future inputType should be
treated. The server trims the typed edge case anyway.

```ts
const BULK_INPUT_TYPES = new Set([
  "insertFromPaste",
  "insertFromPasteAsQuotation",
  "insertFromDrop",
  "insertReplacementText", // autofill / password-manager replace
]);

function isBulkInputType(inputType: string | undefined): boolean {
  // Absent inputType = autofill or a programmatic change (D-76's stated intent).
  return inputType === undefined || inputType === "" || BULK_INPUT_TYPES.has(inputType);
}

export function readCredentialInput(event: React.ChangeEvent<HTMLInputElement>): string {
  const value = event.target.value;
  const inputType = (event.nativeEvent as InputEvent | undefined)?.inputType;
  return isBulkInputType(inputType) ? normalizeCredentialInput(value) : value;
}
```

Add `historyUndo` and `historyRedo` raw-return cases to `credential-input.test.ts`. Also
add a component test on a wizard secret slot: type `pass w`, fire a `historyUndo` change
to `pass `, and assert the controlled value is still `pass `. Optionally, narrow the
paste case too, so it strips only when the pre-event value was empty or the paste
replaced the whole field. Then a paste into a non-empty field cannot strip whitespace
the user typed. The residual case is a user who pastes a chunk that itself ends in a
space and then types the rest. That case is inherent to D-76's "strip the pasted edges"
rule and is not claimed here.
