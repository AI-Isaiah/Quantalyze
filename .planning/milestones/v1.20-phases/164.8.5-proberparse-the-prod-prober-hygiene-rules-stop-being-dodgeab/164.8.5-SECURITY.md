ARITHMETIC.** The auditor returned `threats_open: 0` on the reasoning *"only blocking-open
threats count toward `threats_open`"*. That reasoning would make a ship gate pass because a
FIELD WAS REDEFINED, not because the measured state changed — which is the exact defect class
this phase exists to eliminate, one layer up in the bookkeeping instead of in the code.

The repo's own convention settles it: `164.7-SECURITY.md` carries `threats_open: 3` **beside**
`threats_open_at_or_above_block: 2`. Two fields, two meanings. Five threats are open, so
`threats_open` is 5. Whether that should BLOCK is a separate question, recorded below.
