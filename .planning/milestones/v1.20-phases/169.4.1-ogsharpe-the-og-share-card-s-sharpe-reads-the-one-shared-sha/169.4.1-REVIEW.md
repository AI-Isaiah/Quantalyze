## Critical Issues

### CR-01 (HIGH): On a chain-broken row the card shows a stored CAGR annualized over a short suffix, because its 0.95-year gate measures the full series

**File:** `src/lib/factsheet/og-metrics.ts:98-106` (gate plus stored read), wired from
`src/app/api/og/factsheet/[id]/route.tsx:145-151`

**Issue:** The phase goal says the card applies its own policy to the persisted value: "CAGR hidden under
0.95 calendar years". The code checks that gate against `times`, which is the calendar span of the card's
resolved series. For a service-computed row, that series comes from differencing `returns_series`, and
`returns_series` covers the WHOLE record. Python builds it from `returns.fillna(0)`
(`analytics-service/services/metrics.py:1743`, `:2048`).

The stored `cagr` is annualized over something else. On a geometric row it covers only the suffix after
the last interior chain break: `_cagr_index = _last_interior_break_suffix(returns).index`, then
`(1 + total_return) ** (365 / _elapsed_days) - 1` (`metrics.py:1848-1861`). Python stores that value
however short the suffix is. It only flags it through `data_quality_flags.insufficient_window` (suffix
under `MIN_ANNUALIZATION_DAYS = 90`).

Failure scenario: a published broker strategy has a 2-year record and a TWR chain break 45 days ago, and
the account gained 6% since the break. Python stores `cagr ≈ 1.06^(365/45) − 1 ≈ +60%`. The card's gate
sees about 2.0 calendar years and positive `cum`, so `storedFigure(stored.cagr)` renders **"+60.0%"** on
the social card.

The factsheet shows the same number, but it also says why. It prints "headline covers from <date>"
(`composite-read-path.ts:806-824`, `headlineCoversFrom`) and the amber "Track record under 90 days —
annualized metrics are flagged…" caveat (`FactsheetView.tsx:1624-1633`). The card has neither. Before
this phase, the card compounded over the full 2-year span, so it could not produce this figure.

This breaks the card's stated policy and SC4's "or a surface that must differ says why". It is a
user-facing number on a public image cached `s-maxage=86400, stale-while-revalidate=604800`, and every
unfurl cache keeps its own copy (the route's own STALE-01 comment at `route.tsx:121-126` explains why that
matters most on this surface).

The unit tests miss it. Every persisted-arm case uses `alternating(n)`, a clean series with no break and
no DQ flags, so the stored CAGR and the gate always cover the same span.

**Fix:** Pass the row's data-quality signal to the gate, so the stored CAGR shows only when the span it
was annualized over passes the card's policy. The smallest root-cause fix is to project
`data_quality_flags` in the embed and hide the stored CAGR on a chain-broken or short-window row. The
card cannot name the covered span the way the factsheet can.

```ts
// route.tsx — embed select
"... strategy_analytics ( daily_returns, returns_series, computation_status, cagr, sharpe, max_drawdown, data_quality_flags )"

// route.tsx — pass it through
computeOgHeadline(rows, data?.asset_class, {
  cagr: analytics?.cagr,
  sharpe: analytics?.sharpe,
  max_drawdown: analytics?.max_drawdown,
  computation_status: computationStatus,
  data_quality_flags: analytics?.data_quality_flags,
});

// og-metrics.ts — the stored CAGR's own span may be a suffix the card's
// full-series gate cannot see; hide rather than show an unexplained figure.
const dqf = stored?.data_quality_flags as { twr_chain_broken?: unknown; insufficient_window?: unknown } | null | undefined;
const storedCagrSpanUnknown = dqf?.twr_chain_broken === true || dqf?.insufficient_window === true;
...
if (years >= 0.95) {
  cagr = stored?.cagr !== undefined
    ? (storedCagrSpanUnknown ? NaN : storedFigure(stored.cagr))
    : Math.pow(cum, 1 / years) - 1;
}
```

The `twr_chain_broken` clause is the one that closes the gap. A clean record under 90 days already
fails the full-span `years >= 0.95` gate, so `insufficient_window` is defence in depth only. Add
`data_quality_flags?: unknown` to `OgPersistedScalars`, and add the new hide rule to the CAGR-gate
docblock, so the card's policy states why it differs from the factsheet here, as SC4 requires.

Add a unit case with a 400-day series, a stored `cagr: 0.6`, status `complete` and
`data_quality_flags: { twr_chain_broken: true }` that expects `cagr` to be NaN. Add a route case asserting
that `data_quality_flags` is projected and forwarded. Neuter the new guard and confirm the unit case goes
RED (SC9).

Alternative, if the founder wants the figure shown: thread `headlineCoversFrom` into the card and gate on
`calendarYears(coversFrom, lastDate) >= 0.95`. That costs one more read on every unfurl
(`readHeadlineCoversFrom` uses the service-role client).
