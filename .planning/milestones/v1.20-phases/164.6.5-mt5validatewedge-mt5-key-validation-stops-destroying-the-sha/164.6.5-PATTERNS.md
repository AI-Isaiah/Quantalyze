**Analog:** itself — `_heal_blocking`'s branch table, `_not_healed`, `_VERDICT_NOT_HEALED_PREFIX`.

**Imports pattern:**

    ...

**Verdict-construction pattern (`_not_healed`)** — every verdict is a composed
string prefixed by a module-level `Final[str]` constant, redacted BY VALUE:
```python
_VERDICT_NOT_HEALED_PREFIX: Final[str] = "not_healed:"

def _not_healed(
    reason: str, err: Mt5ClientError, login: int, password: str, server: str
) -> str:
    detail = _redact_credential_values(str(err), login, password, server)
    return f"{_VERDICT_NOT_HEALED_PREFIX}{reason}:{detail}"
```

**The branch table D-08's escalation extends** (`_heal_blocking`):
```python
client = Mt5Client(host, port)
try:
    try:
        client.assert_session_authorized()
    except Mt5ClientError as err:
        if err.code != _MT5_NO_AUTHORIZED_ACCOUNT_CODE:
            return HealOutcome(
                verdict=_not_healed(
                    f"{KIND_IPC_FAULT}:code={err.code}",
                    err, login, password, server,
                ),
                first_kind=KIND_IPC_FAULT,
                ...
            )
```
D-08's escalation reads `outcome.final_kind == KIND_IPC_FAULT` (or
`outcome.verdict.startswith(_VERDICT_NOT_HEALED_PREFIX)`) on the STRUCTURED
`HealOutcome` the caller already has — never re-parses the verdict string.
This is Pattern 1 from RESEARCH.md, confirmed by direct read this session.

**Error handling pattern:** every branch that cannot heal returns a
`HealOutcome`, never raises for an ordinary fault; `Mt5SessionAbandoned` is the
ONE exception deliberately left un-absorbed (propagates to the entry's
catch-all). A new escalation trigger should follow this shape — return a
`HealOutcome` variant / call a new escalation function, do not raise a new
exception type into the existing catch-all.

### 2. `analytics-service/services/mt5_session_episodes.py` (model, event-driven) — D-08

**Analog:** itself — the `KIND_*` constant block and `HealOutcome` NamedTuple.

**The closed vocabulary pattern (add a new `KIND_*` here, never inline a string
elsewhere):**
```python
KIND_ALREADY_AUTHORIZED: Final[str] = "already_authorized"
KIND_HEALED: Final[str] = "healed"
KIND_NO_AUTHORIZED_ACCOUNT: Final[str] = "no_authorized_account"
KIND_IPC_FAULT: Final[str] = "ipc_fault"
KIND_CREDENTIAL_REFUSED: Final[str] = "credential_refused"
KIND_HEAL_SENT_IPC_FAULT_ON_REPROBE: Final[str] = "heal_sent_ipc_fault_on_reprobe"
KIND_STILL_UNAUTHORIZED: Final[str] = "still_unauthorized"
KIND_BUSY_SKIP: Final[str] = "busy_skip"
KIND_BUDGET_ABANDONED: Final[str] = "budget_abandoned"
...
KIND_SUPERSEDED: Final[str] = "superseded"
```
Each new kind ships with a doc-comment explaining WHY it is distinct from its
neighbors (see `KIND_CREDENTIALS_NOT_CONFIGURED` vs `KIND_GATEWAY_NOT_CONFIGURED`
as the worked example of "two genuinely different operator faults sharing one
class broke the pin"). D-08's escalation-outcome kind (e.g. "escalated to
supervision") should follow this exact shape — a new `Final[str]` with a
comment naming which existing kind it is a sibling of and why it cannot reuse
that kind.

**The structured-outcome pattern (`HealOutcome`):**
```python
class HealOutcome(NamedTuple):
    """... ``verdict`` IS THE COMPOSED STRING, BYTE-UNCHANGED. ... The other
    fields exist so the recorder never has to PARSE it — string-shape
    dependency is exactly what plan 01 removed ...
    """
    verdict: str
    first_kind: str
    first_code: int | None
    final_kind: str | None
    final_code: int | None
```
Per RESEARCH.md's "Don't Hand-Roll" table: extend THIS tuple / THIS
vocabulary for the escalation outcome — do not build a second
`HealOutcome`-shaped record. If the escalation needs a field `HealOutcome`
does not carry (e.g. "escalation attempted: bool"), add it here as a new
field with a sensible default-safe meaning, following the `final_kind: str |
None` precedent for "None means this step never ran."

  code: WizardErrorCode;
  status: number;

⚠️ **RESEARCH.md's Open Question 3 asked where D-15's "fails loudly" check
should live (prober vs. validate path) — this session found the validate path
ALREADY HAS a working, judged version of exactly this signal**, which the
prober's `classifyProbe` deliberately does NOT have (its header states
`connected`/`trade_allowed` are "printed and NEVER JUDGED").

**Analog:** `classify_trade_capability` / `terminal_trade_permission_off`:
```python
def terminal_trade_permission_off(terminal_info: dict[str, Any] | None) -> bool:
    """True iff the terminal WAS read, IS connected, and its OWN trade
    permission is off ...
      * True  -> a setting in OUR gateway terminal. No retry can clear it;
        the remedy is an operator changing that setting ...
      * False -> the terminal was unreadable, malformed, or detached from the
        trade server. That is our bridge blipping and it clears on retry.
    """
    if not isinstance(terminal_info, Mapping) or "trade_allowed" not in terminal_info:
        return False  # unreadable / malformed shape -> transient, not operator
    if not terminal_info.get("connected"):
        return False  # detached from the trade server -> transient
    return not terminal_info.get("trade_allowed")
```
This function already judges `trade_allowed` immediately post-validate, with
the exact fail-safe shape D-15 needs (unreadable/disconnected → transient, not
a false alarm; connected + `trade_allowed=false` → the real landmine signal).
D-15's "assertion that fails loudly" can be built as a NEW caller of this
EXISTING predicate at the validate call site (an account-change event, which
is precisely when the landmine trips), rather than adding judgment logic to
the prober's deliberately-unjudged branch. ⛔ Do not duplicate this
four-condition shape test elsewhere — the module's own comment says a copy
"drifts, and the drift would be silent."
