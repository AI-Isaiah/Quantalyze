# Phase 164.6.5 Plan 05: The heal acts on ipc_fault Summary

When the credential-free detector reads `-10005` (the bridge answered and the terminal did not), the heal now escalates. It logs the wedge evidence first, then recycles the terminal process through plan 02's verb. It does this once per run of consecutive readings, inside the one existing lease and budget, with no credential, and nothing it raises can get out of the heal. The `not_healed:ipc_fault:...` verdict string is byte-identical to before.

## What was built

**Task 1: vocabulary, field and gate (`mt5_session_episodes.py`), commit `7037055cf`**
- Four new kinds, each commented as a sibling of `KIND_IPC_FAULT` and not a reuse of it: `ipc_fault_recycled`, `ipc_fault_recycled_no_account`, `ipc_fault_recycled_still_faulted`, `ipc_fault_recycle_failed`. Passed to `classify_reading`, each one maps to `not_measured`, and a gate checks that.
- `HealOutcome.escalation_kind: str | None = None` is appended with a default, so every existing construction site (6 in `_heal_blocking`) and the tests' positional constructions are unchanged.
- The gate is `claim_ipc_fault_escalation()`, which returns True once and then disarms, and `rearm_ipc_fault_escalation()`. Its tradeoff is written in its own terms: a deploy re-arms it, which costs at most one extra recycle per deploy.
- `_reset_session_episode_state_for_tests()` re-arms the gate. `tests/test_mt5_session_episodes.py`'s `_DECLARED_MUTABLE_MODULE_GLOBALS` registry now names the new bool and gives the reason it is not episode state. That gate required the entry; it is Deviation 2.

**Task 2: the escalation (`mt5_relogin.py`), commit `87123dbfc`**
- `_escalate_ipc_fault(client, code, env_server)` is called from `_heal_blocking`'s ipc_fault branch, after the verdict is composed. Its steps, in order:
  1. The code gate.
  2. The debounce. A suppressed attempt logs an INFO line saying so.
  3. Evidence capture, logged at WARNING.
  4. `client.recycle_terminal_process()`.
  5. Classification from the verb's structured keys.
  6. Its own log line: INFO when recycled, WARNING for recycled_no_account, ERROR for still_faulted or failed.
- The placement reasoning (the caller logs after the lease has released, and a second lease is refused) is written at the site.
- `_RECYCLE_REACHABLE_IPC_CODES = frozenset(_IPC_TRANSPORT_CODES) - {-10004}`.
- The already-authorized and `-6` first-probe arms call `rearm_ipc_fault_escalation()`.

**Task 3: the gates (`test_mt5_relogin.py`), commit `a50569376`**
- `_FakeRpycConn` now carries `execute` and `namespace`, so the real plan-02 verb runs: its fence, `_guarded_read`, JSON parse and relaunch probe. Only the Win32 body is faked. `_FakeMt5` gained `terminal_info`, `account_info`, and post-recycle scenario keys.
- The autouse fixture resets episode state, which re-arms the gate before and after every test.
- The existing `test_an_ipc_fault_is_not_healed_and_the_verdict_names_the_code[-10005]` was extended rather than replaced. Its expected call order for `-10005` is now `initialize, terminal_info, recycle, initialize`.
- 22 new test cases: every gate the plan listed, plus the evidence gates the orchestrator added.

## Orchestrator addition: capture before recycle (MT5-SWITCH-WEDGE-CAUSE-01)

`_capture_wedge_evidence` runs before the recycle and is logged on its own WARNING line.
- It reads `terminal_info()` (build, connected) and then `account_info()` (server), both credential-free. No login is ever made.
- A failing `terminal_info()` records all fields as `not_captured (terminal_info failed: exc_class=... code=...; account_info skipped)`. The skip is what keeps the budget bounded.
- ⚠️ **Deviation from the literal ask:** the broker server is recorded as `session_server_matches_env=True|False`, never as a name. This module's rule T-164.6.2-12 says a value never reaches a log line, and `MT5_SERVER` is one of the three values `_not_healed` redacts by value. `TODOS.md` MT5-SWITCH-WEDGE-CAUSE-01 also says to keep server names private and bring in only the verdicts. The comparison answers "is the terminal on the environment account's server?". It does not name the server on each side of a switch. If the orchestrator wants the name in the private Railway log despite T-164.6.2-12, that is a founder call, and the change is one line.
- No account number is read into the line. The login field is never touched.
- This plan writes no episode record, so the log line is the only record.

## Known limits / unmeasured

- **The escalation has not run live, and nothing here claims it works live.**
  - It is the first caller of the plan-02 verb, whose over-the-bridge terminate is still unmeasured (`.planning/WINDOWS.md` entry 68).
  - The first live `-10005` after deploy will be the first measurement. Its log lines are the pre-recycle evidence line, then `escalated to a terminal-process recycle ... (matched=.. terminated=.. exited=.. authorized=.. relaunch_code=..)`.
- **Capture reads against a wedged terminal are unmeasured.** Whether `terminal_info()` answers at all during a `-10005` is not known. If it does not, the line records `not_captured` with the reason, which still tells MT5-SWITCH-WEDGE-CAUSE-01 that the build could not be read in-process.
- **The relaunched terminal's account is not assumed.** It comes up on whichever account the last call logged in to. `ipc_fault_recycled` means the detector found some authorized session, not the environment account (the module's `ATTRIBUTION_LIMIT`).
- **The debounce state lives in memory.** Two analytics containers overlapping during a deploy could each recycle once. That is bounded and documented at the gate.
- **Still owed before phase close: `/gsd-secure-phase` for 164.6.5.** T-164.6.5-22 through -27 are mitigated as planned. The new surface (two credential-free reads before the recycle) adds no endpoint and no new remote payload.
