# Phase 167.2.1.1.1 Plan 13: NAV twin in the Deribit ledger builder Summary

One Deribit crawl now yields the allocated ledger exactly as before and, on request (`nav_twin=True`), a NAV twin that keeps the net-extraction spot legs, reusing the allocated marks, flows and wedge, with no venue call.

## What changed

- `CompletenessReport` gains `nav_twin_ledger: NativeLedger | None = None` and `nav_twin_error: str | None = None` (additive, D-14).
- `build_deribit_native_ledger` gains keyword `nav_twin: bool = False`. `True` is only valid with `exclude_spot_extraction=True` (otherwise `ValueError` before any crawl). After the allocated ledger is built exactly as before, the twin re-aggregates the crawl's own raw rows with `exclude_spot_extraction=False`, merges the same smoothed delta-MTM book when that basis is on, runs `assert_balance_identity` in NAV mode (a twin-only currency gets its own tolerance floor by the allocated rule), and stores `dataclasses.replace(ledger, native_pnl=<twin series>)`.
- W1: only the twin steps sit in `try/except LedgerValuationError`; the class name goes to `report.nav_twin_error` and one log line `build_deribit_native_ledger: nav twin unbuildable (error=<class>)`. The allocated steps are outside the wrapper.
