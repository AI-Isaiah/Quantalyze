# Phase 167.2.1.1.1 Plan 06: NAVMTM writer Summary

Every derive of an OKX, Deribit, MT5 (USD or BTC unit) or sFOX key now stores the key's marked NAV, open profit, read time and native figures in `api_key_nav_marks` (write-once, first writer of the closed UTC day wins), from the read the derive already made, and keeps the row the database holds instead of its own read.

## What was built

- `services/nav_marks.py`: the interface the plan fixed, plus `read_stored_mark`, `deribit_native_detail`, `UNIFORM_READ_VENUES` (okx, deribit, mt5, sfox: Bybit and Binance stay plan 15's) and `PRICED_NATIVE_UNIT` (pinned equal to `job_worker._BTC_PRICED_UNIT` by a test). `build_mark_read` is pure and returns a `MarkRead` or one token of the closed set of ten. Ladder: `native_unit`, `native_unpriced`, `balance_error`, `upnl_unreadable`, the caller's token (plan 15's positions/wallet tokens), `nonfinite`, `nonpositive`, `dust`. A non-finite native amount is `nonfinite`, judged before pricing.
- `run_derive_broker_dailies_job`: `_mark_read_at`, `_stored_nav_mark`, `_nav_mark_refusal` defined before the venue branches; `_mark_read_at = _utc_now()` stamped right after each equity read (ccxt `fetch_account_equity_and_upnl_usd`, Deribit `account_state`, sFOX balance-history crawl, MT5 `read_mt5_deal_ledger`); one `await _write_nav_mark_for_this_derive()` at the convergence point, after the `finally: aclose_exchange` and before the ccxt combine and noise guard. It covers both modes and the key-mode `<2`-day short-circuit. A refusal logs `nav mark refused (token=... venue=... api_key=...)` and never fails the derive; a database error bubbles (the job retries).
- Key-mode `key_inputs` payload gains additive `nav_mark` (`mark_day`, `nav_usd`, `open_pnl_usd`, `marked_at`, from the STORED row) and `nav_mark_refusal`.

## Per venue: what is stored, and the identity pinned (Pitfall 6)

| Venue | nav_usd | open_pnl_usd | native fields | identity `nav - open ==` realized terminal |
|---|---|---|---|---|
| OKX | totalEq | upl | unit USD, native = USD, no price_day | pinned: 1050 - 50 == 1000 == `realized_terminal_usd` |
| Deribit | collapsed USD equity | collapsed USD uPnL | unit/nav_native/open_native NULL; `native_detail` = {equity, upnl per currency, usd_basis "venue_index_at_marked_at"}; price_day NULL | NOT asserted (see caveat) |
| MT5 USD unit | equity | equity - balance | unit USD | pinned: 110600 - 100 == 110500 == balance == `realized_terminal_usd` |
| MT5 BTC unit | native equity x the mark day's close | native open x same close | unit BTC, native amounts, price_day = the mark day; missing close -> `native_unpriced`; other native unit -> `native_unit` | priced at the one close; not the USD identity |
| sFOX | last observed usd_value | 0.0 | unit USD | pinned: nav - open == 1030 == the series' last point == anchor_usd |
| Bybit, Binance | plan 15 | | | plan 15 |

Deribit caveat (stated in `test_nav_marks_reads.py`): its realized terminal is the native balance at the mark of the last ledger day less the terminal uPnL, while the mark is today's collapsed equity, so the D-04 step there also contains the coin's mark move since that ledger day (real MTM profit). The test asserts only `nav_usd == 2000.0` (the collapsed equity the venue priced).

## Deviations from Plan

**1. [Rule 3 - Blocking] `tests/conftest.py` default stand-in for the writer (file not in the plan's list)**
- **Found during:** Task 1. 20 existing OKX derive tests failed: their supabase is a `MagicMock`, so the re-select finds no row and `write_nav_mark` correctly raises.
- **Fix:** a module-scoped autouse fixture patches `services.job_worker.write_nav_mark` with "this derive's read won the day" (no database call). The first version was function-scoped and left 29 module-scoped-fixture errors in `test_allocator_equity_writer_basis.py`; it became module-scoped. The two marks suites re-bind the real writer in a function-scoped autouse fixture (the repo's existing "test's own patch wins" idiom).
- **Commits:** 88b5ac2ee, 020b5c24f.

**2. [Rule 1 - Bug] Deribit native detail computed at the convergence helper, not at the read stamp**
- **Found during:** Task 2. Building it at the stamp raised `AttributeError` for three hang/early-failure tests whose `account_state` is a `SimpleNamespace`. Moved into the helper, which those derives never reach. Production `account_state` is always the frozen dataclass.

**3. sFOX read time is stamped right after the balance-history crawl, before the transactions crawl** (the plan said "sFOX's terminal"): the NAV series is the equity read; the transactions crawl can run for minutes and is not part of it.

**4. Branch**: committed on `feat/167.2.1.1.1-p06` as instructed (the plan text names `feat/167.2.1.1.1-navmtm`).

**5.** Extra module constants `UNIFORM_READ_VENUES` and `PRICED_NATIVE_UNIT` (the plan's interface list did not include them); the venue gate and the single source of "BTC" need a name.
