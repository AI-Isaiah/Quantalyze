# Phase 167.2.1.1.1 Plan 20: Deribit open profit is NAV minus wallet Summary

A Deribit mark now stores `equity - balance` per currency at the read's own index as its open profit, so the option book's value and the accrued session RPL are inside it, and on the first marked day the D-04 step is exactly that amount.

## The definitions

**Old:** `open_pnl_usd = collapsed_upnl_usd`, the combined session uPnL (futures plus options session UPL, each currency at its index). For the read in the test module that is `(0.1 + 0.02) x 60000 = 7200`.

**New (D-21):** `open_pnl_usd = sum over currencies of _cash_basis_wedge(state, ccy) x index`, `_cash_basis_wedge` being `equity - balance` when the balance was read, else the component form `native_upnl - options_session_upl + options_value`. A USD-family currency is counted at 1.0 (already dollars, as in `deribit_equity_to_usd`). Same read: `0.6 x 60000 = 36000`.

**Doc identity (D-18, Deribit), quoted in the helper's docstring** from https://docs.deribit.com/api-reference/account-management/private-get_account_summary: `equity` is "balance + futures (session UPL + RPL) + options mark value". So `nav_usd` (collapsed `equity`) already holds the option value, and `equity - balance` holds it too. `nav_usd - open_pnl_usd` is the cash wallet the ledger rolls its realized series from.

**`native_detail` keys:** `equity` and `upnl` (unchanged: per-currency equity and session uPnL), `open_profit` (new: per-currency `equity - balance`, native units, sorted), `usd_basis` (unchanged). `sum(open_profit x index) == open_pnl_usd`; no reader should take `upnl` for the stored open profit.

## Deviations from Plan

**1. [Rule 3 - ordering] Task 2's RED is shown by drill, not by a failing first run.** The plan's Task 1 helper already returns `None` for an unindexed wedge currency and the worker already turns that into `upnl_unreadable`, so the Task 2 tests passed on their first run. Shipping a deliberately wrong intermediate helper to manufacture a RED would have been worse; the D-IX drill (priced at 0.0) is the RED evidence (`drill-ix.log`, copied to `red2.log`). Task 2 therefore has one commit (tests only) and no source change.

**2. [Rule 3 - blocking] The set of wedge currencies was extracted into `_cash_wedge_currencies`.** The plan says the new sum runs over "the same set the cash terminal builds"; calling one helper from both places is how "the same" stays true. `build_deribit_native_ledger` now calls it; its output is unchanged (full suite green).

**3. Branch.** The plan text names `feat/167.2.1.1.1-navmtm`; the orchestrator's brief assigned `feat/167.2.1.1.1-p20` in a dedicated linked worktree, which is where every commit went. Nothing was committed to main or the phase branch.

## Known limits

- The legacy `upnl_unreadable` flag (a garbled or absent session-uPnL field on every summary, or an open option book with an absent `options_session_upl`) still refuses a Deribit mark, although the `equity - balance` path does not read session uPnL when the balance was read. Kept deliberately: the component-form fallback (no `balance`) does depend on it, and a refused day costs nothing (D-05).
- Module docstring of `tests/test_nav_marks_reads.py` still describes Deribit as an exception to the `nav - open == terminal` identity. Under D-21 the identity holds when the index has not moved since the last ledger day (the new D-04 test); with a moved index the step still also contains the coin's mark move, as before. The docstring was left (the plan allows only the named fixtures and asserts).
- The D-04 proof is for an unchanged index, as the must-have states; with a moved index the step is open profit plus the wallet's mark move, which is real marked-to-market profit.
- The derive-apply Deribit test's own mark loses to its seeded marks (first writer wins, D-06), so its fixture edit keeps the derive's own mark storable rather than asserting on it; the open-profit assertions live in the new module and the reads test.
- Nothing reads `native_detail["upnl"]` as an open profit anywhere in `src/` or `analytics-service/` today (grep: `native_detail` appears only in the migration, the generated types, `nav_marks.py` and `job_worker.py`).
- OKX is unchanged (D-21's orchestrator note: D-19 refuses every account holding an option, so `upl` and NAV minus wallet coincide for the accounts that are marked); re-check when D-19's refusal is lifted.
- No live exchange call was made; the Deribit field names and identity come from the documentation and the existing fixtures.
