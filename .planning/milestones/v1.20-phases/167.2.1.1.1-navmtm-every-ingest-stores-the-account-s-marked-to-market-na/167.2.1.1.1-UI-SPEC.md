# Phase 167.2.1.1.1 NAVMTM — UI Design Contract (D-08: start-of-marks note)

> Visual and interaction contract for D-08 only. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Founder decision quoted from CONTEXT D-08: "Small note on charts (Recommended)". A small marker or note on the
> factsheet and on My Allocation wherever the start date falls inside the drawn range. This needs a UI-SPEC and a
> DESIGN.md check.

Everything else in the phase (storage, cron move, return rules, the D-05 gap days, MARKSOURCE's price rule) has no
visual surface in this contract. See "Out of scope" at the end.

---

## What is drawn (summary)

On each host chart, when the marks-start date lies inside the range the chart currently draws:

1. **A marker line:** one solid 1 px vertical line at the start day, the full plot height, in `--color-text-secondary`.
2. **A short label in the chart:** `Recorded equity from {date}`, Geist Mono, uppercase and letter-tracked (`tracking-wider`, 0.05em) per DESIGN.md, placed beside the line
   only where it fits inside the plot. Otherwise it is left out.
3. **A caption under the chart:** one to three plain sentences in HTML (copy below) that name the date and explain the
   step. It wraps at any width and is the text alternative.

When the start date is outside the drawn range, absent or malformed, none of the three renders. No placeholder is shown,
no em-dash, and no space is reserved.

## Visibility rule (one rule, both surfaces)

Let `start` be the parsed start date (`parseMarksStart`, `src/lib/nav-marks-start.ts`). Let `first` and `last` be the
first and last dates **the chart is drawing right now**:
- Factsheet: `dates[xStart]` and `dates[xEnd]` of the chart's current zoom window, so the note follows pan, zoom and reset.
- My Allocation: the first and last points of the period-sliced `visible` series (1M / 3M / 6M / YTD / 1Y / ALL / CUSTOM).

Show the note iff `first < start <= last` (`marksStartInRange`). Then:
- `start == first` hides it. No earlier day is drawn, so no step is on screen to name.
- `start == last` shows it. The line sits at the right edge and the label flips left.
- The marker's x is the first drawn index whose date is `>= start`.

Two further conditions apply. Each comes from the ACCTREBUILD OQ-1 warning: a note on a curve that does not contain the
step is wrong.
- **Factsheet basis.** The note shows only while the chart draws the **cash-settlement series**. That covers basis
  `cash_settlement`, and also `mark_to_market` / `smoothed_mtm` when their series bundle is absent, because the charts
  then fall back to cash (the same three-state logic as the existing caption "Charts show the cash-settlement series…"
  in `FactsheetView.tsx`). When a mark-to-market or smoothed bundle is drawn, the note is hidden, because marks change
  only the cash-settlement series (plans 07, 08, 09, 16).
- **My Allocation curve.** `EquityChart` mounts only in the "ready" state, where the drawn curve is always the derived
  curve (see the `equityCurveSource` comment in `getMyAllocationDashboard`, `src/lib/queries.ts`). No extra source gate
  is added. Per that same comment, do not add one.

### The label placement rule (one pure helper, both hosts)

`placeMarksStartLabel(x, label, fontSize, plotLeft, plotRight): { x: number; textAnchor: "start" | "end" } | null`,
exported from `src/lib/nav-marks-start.ts`, with the width taken from `estLabelWidth` (`src/lib/chart-ticks.ts`):

1. If `x + 4 + w <= plotRight`, return `{ x: x + 4, textAnchor: "start" }`. The label reads to the right of the line,
   over the recorded days.
2. Otherwise, if `x - 4 - w >= plotLeft`, return `{ x: x - 4, textAnchor: "end" }`.
3. Otherwise return `null` and draw **no label**. The line and the caption remain.

Because the label names its own date ("from {date}"), it stays true on either side of the line. The label is never
truncated, shrunk or wrapped. This is the NARROWCHARTS rule (Phase 170.1.3): no SVG text is drawn past its bound.
Rule 3 is the expected path for My Allocation at 390 px whenever the line sits mid-plot. There the plot is about 260 px
and the 12 px label about 240 px, so it fits only near an edge. The factsheet viewBox plot is about 800 units and the
label about 200, so the factsheet label always fits on one side.

### Caption placement

| Host | Element and position | Classes |
|------|---------------------|---------|
| `TimeSeriesChart` | `<figcaption data-testid="marks-start-note">`, the last child of the chart's existing `<figure>` after `ResponsiveChartFrame`. The figure's `gap-2` gives the 8 px above it. Rendered only when the note is visible. | `text-caption text-text-secondary` |
| `EquityChart` | `<p data-testid="marks-start-note">` directly after the chart's `position: relative` container (svg plus tooltip), inside `EquityChart` itself, because only `EquityChart` knows the `visible` range. | `mt-2 text-caption text-text-secondary` |

Plain wrapping text: no `whitespace-nowrap`, no `truncate` and no fixed width. It is not a live region (`role="status"`
or `aria-live`), because a pan or zoom would otherwise announce it on every step. It is plain document text that
appears and disappears with the range.

## Typography

DESIGN.md "Three voices, fixed roles". The label is a data micro-label beside data, so it uses Geist Mono, uppercase and
letter-tracked (`tracking-wider`, 0.05em), as DESIGN.md requires and as the chart's own existing labels in
`TimeSeriesChart.tsx` already are (orchestrator correction 2026-10-26 after the UI check's typography FLAG: the earlier
sentence-case choice claimed a precedent the file does not have). The copy strings below are written in sentence case;
the uppercase is applied in rendering. Label placement (`placeMarksStartLabel`) measures the rendered string, uppercase
and tracked, so the right-else-left-else-omit rule and the 390 px fit hold for what is drawn. The caption is prose the reader reads, so it uses DM Sans like the sibling caption lines.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Caption (both hosts) | `text-caption` token, 12 to 13 px fluid | 400 | 1.5, inherited from the page (`--text-caption` in `globals.css` sets no line-height; do not add `leading-*`, matching the sibling caption lines) | DM Sans |
| In-chart label, factsheet | 10 svg units (the chart's existing annotation size, scaled by the viewBox like every other label in that SVG) | 400 | single line, n/a | Geist Mono |
| In-chart label, My Allocation | 12 px (the chart's existing tick size) | 400 | single line, n/a | Geist Mono |

Weights: 400 for everything this phase adds. The only other weight on these cards is 600, on the existing chart titles
("Cumulative Returns", "Equity curve"), which stay unchanged. No new size, weight or font is introduced, and no raw
`text-[Npx]` is added in HTML.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF surface / #F8F9FA page | Existing chart surfaces, unchanged |
| Secondary (30%) | #E2E8F0 border / #F1F5F9 track | Existing hairlines and grid, unchanged |
| Accent (10%) | #1B6B5A | **Not used by the note.** On these charts it stays reserved for the strategy / portfolio series line, the crosshair price-label background and focus outlines. |
| Destructive | #DC2626 | Not used |
| Marker line, label and caption | #4A5568 (`--color-text-secondary`) | The only colour this phase adds to the charts |

Accent reserved for (on the host charts): the strategy / portfolio series stroke and area fill, the crosshair label
background, and focus-visible outlines. The marks-start note never uses it.

**Why neutral, and not amber or red** (DESIGN.md "Semantic-color gates"). The note states a fact about the record and
reports no failure, so it is not red. Nothing about it is recoverable, so it is not amber. It is steady-state, so it is
neutral. The `text-secondary` step over `text-muted` is chosen so that the line separates from the muted dashed FS-01
markers by both pattern and weight.

**Contrast, measured** (WCAG sRGB formula, 2026-10-26):

| Pair | Ratio | Requirement |
|------|-------|-------------|
| #4A5568 on #FFFFFF | 7.53:1 | caption text 4.5:1 (AA); line 3:1 non-text (1.4.11): pass |
| #4A5568 on #F8F9FA | 7.14:1 | same: pass |

## Copywriting Contract

Voice: DESIGN.md "Voice / microcopy". Declarative and sentence case, the limit stated with its date, no adjectives, no
glyph. The copy names no number the data does not hold and never says "mark-to-market". The factsheet already offers a
basis called "Mark-to-market", and this note sits on the **Cash settlement** chart, so that word would contradict the
basis control.

`{date}` is `formatIsoDate(start)` from `src/app/factsheet/[id]/trade-fetch-lines.tsx` ("Mar 6, 2026", UTC). It is the
factsheet's one date formatter and is used on both surfaces, so the same day reads identically everywhere.

| Element | Copy |
|---------|------|
| In-chart label (both hosts) | `Recorded equity from {date}` |
| Caption S1 (always) | `Recorded equity, including unrealized P&L, begins on {date}.` |
| Caption S2 (always) | `Earlier days are rebuilt from trade and balance history and can leave out unrealized P&L, so the curve may step on that day.` |
| Caption S3 (multi-account charts only) | `An account whose recording began later may step on its own first recorded day.` |
| `<title>` in the marker group | S1, verbatim |
| Primary CTA | None. The note has no action. |
| Empty state heading / body | None. With no start date, an out-of-range date or a malformed value, nothing renders. No placeholder, no em-dash: the em-dash rule is for a metric that cannot be computed, and this is a note with nothing to say. |
| Error state | None shown. A failed My Allocation read or a malformed published value yields `null` (reason-only `console.warn` from the parser) and the chart renders exactly as today. A note must never cost the chart. |
| Destructive confirmation | None. This phase has no destructive action in the UI. |

**When S3 is shown.** S3 is shown on the My Allocation equity widget and on its embedded portfolio factsheet chart
(payload `types` includes `allocator_portfolio`), and on a composite strategy factsheet (`payload.dataQuality.composite === true`).
On those charts the start date is the earliest start among several accounts (CONTEXT D-12 and plan 09, "the earliest
member marks_since"; plan 10 Task 2, "the earliest mark_day across the owner's keys"). S1 alone would wrongly imply that
every account is recorded from that day. A single-strategy factsheet has one account and omits S3.

**Why each sentence is true on every venue:**
- S1 names only where recorded equity begins.
- S2 says "can leave out", not "leaves out". For OKX, Bybit, Binance, MT5 and Deribit, the earlier days are realized-basis
  (L1, CONTEXT `code_context`). For sFOX the earlier NAV is observed with zero open profit (RESEARCH 5.3), so no step
  occurs. "May step" covers both. The step itself is L2 / D-04: the open profit at the boundary is booked as that day's
  return.
- S3 is phrased the same way.

The copy strings live once in `src/lib/nav-marks-start.ts` as functions of the formatted date (and of the multi-account
flag for the caption), so both hosts render the same words, as `RECONSTRUCTED_SENTENCE` does for OKXHISTORY.

## Narrow width (390 px) and print

- **390 px.** The caption wraps inside its card. In-chart text obeys `placeMarksStartLabel`, so every drawn label box
  lies inside its plot, and therefore inside its SVG. This meets the NARROWCHARTS SC-2 test, "each measured label box
  lies inside its SVG box", which `e2e/layout-narrow.spec.ts` already measures on `/allocations`. The factsheet label
  scales with the viewBox like every other label in that SVG.
- **Print.** Nothing is `print:hidden`. A printed factsheet or dashboard carries the line, the label and the caption
  for the range on screen when printed. This follows DESIGN.md's five-second test: a step on paper with no date
  attached would fail it. The printed tear sheet (`tearsheet/page.tsx`, a sparkline) is out of scope (see below).

## Data the visuals read (contract for plan 10)

Plan 10 owns the data path. This section only fixes the field shape the visuals depend on.

- **Factsheet.** `payload.marksSince: string | null`, parsed once by `parseMarksStart` from
  `data_quality_flags.marks_since` in `fetch-and-build-payload.ts` (D-12). `TimeSeriesChart` reads it from the basis
  view, like `segmentBoundaries`.
- **My Allocation, equity widget.** `marksStart: string | null` on the `getMyAllocationDashboard` payload. In
  `equityChartWidgetDataSchema` (`src/app/(dashboard)/allocations/widgets/lib/widget-data.ts`) it is declared
  `z.unknown().optional()`, and the widget passes it through `parseMarksStart` before `EquityChart` sees it. A strict
  `z.string()` would send a malformed value into the boundary's `onInvalid="empty"` path and blank the whole card (see
  `EquityChart.boundary.test.tsx`).
- **My Allocation, embedded factsheet.** `AllocationDashboardV2` passes the same `marksStart` to
  `buildAllocatorPortfolioFactsheetPayload` as a new optional meta field, which sets `payload.marksSince`.
- **Planner check (not a visual decision).** The note must name a step the drawn curve contains. If the "earliest
  `mark_day` across the owner's keys" could belong to a key whose history the drawn curve leaves out (for example the
  `departed_history_unavailable` case behind `DepartedHistoryNote`), the read should take the earliest start over the
  keys the curve includes. Today every active key's marks begin on the deploy day (D-02, D-09), so the two answers agree
  at ship time.
