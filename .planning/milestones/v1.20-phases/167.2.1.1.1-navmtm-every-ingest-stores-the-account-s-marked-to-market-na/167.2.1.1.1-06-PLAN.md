## The interface this plan fixes (plans 07, 09, 12, 15, 16 and 17 read it; do not rename)

`services/nav_marks.py`:
- `MARK_REFUSAL_TOKENS: Final[frozenset[str]]` = the ten tokens in the must-haves.
- `@dataclass(frozen=True) class MarkRead`: venue, mark_day (date), marked_at (aware UTC datetime), nav_usd, open_pnl_usd,
  nav_native, open_pnl_native, native_unit, price_day (date | None), native_detail (dict | None). Its `to_row(api_key_id,
  allocator_id)` returns the insert dict (ISO strings; floats checked finite).
- `class StoredMark(NamedTuple)`: mark_day (str ISO), marked_at (str), venue, nav_usd (float), open_pnl_usd (float),
  nav_native (float | None), native_unit (str | None).
- `def mark_day_for(marked_at: datetime) -> date`: UTC date of `marked_at` minus one day (D-03/D-11).
- `def build_mark_read(...) -> MarkRead | str`: pure; returns a MarkRead or a refusal token.
- `def write_nav_mark(supabase, read: MarkRead, *, api_key_id: str, allocator_id: str) -> StoredMark`: sync (callers
  wrap it in `db_execute`); upsert with `on_conflict="api_key_id,mark_day", ignore_duplicates=True`, then select the
  row for (api_key_id, mark_day) and return it parsed. A missing row after the insert raises (it cannot be absent).
- `def read_key_marks(supabase, api_key_id: str) -> list[StoredMark]`: every stored mark of the key, ascending by
  mark_day, keyset-paginated like `_load_strategy_daily_returns`.
- `def read_stored_mark(supabase, api_key_id: str, mark_day: date) -> StoredMark | None`: the one row for (key, day)
  or None; `write_nav_mark`'s re-select uses it, and plan 15's derive calls it before the Bybit/Binance read (W3).

In `run_derive_broker_dailies_job` the stored row is kept in the local `_stored_nav_mark: StoredMark | None` and the
refusal in `_nav_mark_refusal: str | None`, both defined before the venue branches.
