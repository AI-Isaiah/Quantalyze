Planner decision PD-06 (CONTEXT discretion: the record's shape): key `__pnl_missing__` (lowercase dunder,
so it cannot collide with the upper-cased symbol keys or the `:PERP` keys), value
`{"count": perp_upnl_missing_total, "symbols": perp_upnl_missing_symbols}` (the two values the audit event
already carries), set only when the count is above 0. The TS type `breakdown: Record<string, number> | null`
in src/lib/queries.ts is left unchanged: nothing in `src/` reads `.breakdown` (the precedent
`__truncated__: true` is already non-numeric), and adding a TS reader is out of scope.

Measured by the planner at the phase base (by symbol, inside `refresh_allocator_equity_daily`):
- The loop declares `breakdown: dict[str, float]`, skips a Deribit row first, and for a derivative with
  `unrealized_pnl_usd is None` increments `perp_upnl_missing_total`, appends to `perp_upnl_missing_symbols`
  (bounded at 50) and continues. After the loop it emits `allocator.equity.perp_upnl_missing` once.
- Then `book_emptied` is computed and `if not breakdown and not book_emptied:` returns without writing.
- Then `capped_bd = _cap_breakdown(breakdown)` and the row uses `value_usd: round(total, 2)`.
- `_cap_breakdown` returns early at or under `_BREAKDOWN_TOP_N` (20) or under the byte cap; otherwise it
  pops `_BREAKDOWN_PROTECTED_KEYS`, sorts the rest by `abs(float(kv[1] or 0))` (a dict value raises
  TypeError there), keeps 20, re-adds the protected keys and sets `__truncated__`.
- mypy strict is the CI gate for `services/`: a dict value cannot be stored into `dict[str, float]`.
