### P0 — the sentence (one builder, both surfaces)

```
{N} derivative without reported P&L left out.     (N = 1)
{N} derivatives without reported P&L left out.    (N ≥ 2)
```

- Founder's words, verbatim (CONTEXT D-06, Q5). DESIGN.md requires only the terminal period,
  because the sentence stands as its own sentence everywhere it renders, and the singular for
  N = 1. Nothing else is adjusted. See U-02 for why the participle fragment stays and is not
  recast into an active-voice "We left out …".
- `{N}` is the count as a plain integer, interpolated raw, as `buildKeyTrustClause` interpolates
  `part.count`. DESIGN.md's thousands-separator rule is unreachable in practice: PROD held 288
  current derivative rows across all books on 2026-10-20 (CONTEXT D-10). Using raw interpolation
  keeps the two builders in this module on one convention.
- `P&L` is written `P&amp;L` in JSX, or as the literal string from the builder. The ampersand
  renders as `&`.
- ⛔ No symbol, venue, key label or amount is interpolated. The sentence names a count and a
  constant phrase. The rows themselves stay visible on P2 with their `—`. On P1 the reader can
  find them on the Holdings tab.
- ⭐ **Test oracles type the expected string literally** (e.g. `"2 derivatives without reported
  P&L left out."`). They never call the builder to produce the expectation. This is the
  composer test file's stated rule, carried by 167.1-UI-SPEC.

### What is counted (binds both surfaces)

1. **A derivative row whose P&L was not reported** (`holdingEquityIsReported(h) === false`: null
   or non-finite `unrealized_pnl_usd`), **among the rows the qualified total would otherwise
   have summed.** A null P&L is D-06's case. A non-finite P&L keeps contributing 0 (D-06's
   second bullet), and adding 0 leaves the total exactly as leaving the row out does. So the
   sentence is true for both, and one predicate covers both (U-04).
2. **Per row, not per symbol.** Since 170.4 D-08 the composer keeps every key's row under a scope
   ref, and P2 lists one row per position. Two keys holding the same perp with no reported P&L
   count as 2 on both surfaces.
3. **Spot rows are never counted.** A spot row with a non-finite `value_usd` keeps its existing
   disclosure, the key-trust clause's `(value unavailable for N holdings)` sub-clause, where its
   key is in a disclosed part. This phase does not change that.
4. **A left-out row is named once, by this sentence only (U-05).** It is not in the total, so it
   is **not** counted in any "includes $X from …" key-trust part of that total. An "includes"
   part must be a strict subset of the total it qualifies (167.1 D-04). The rendered effect:
   a left-out derivative on a key needing attention keeps its row chip and strike-through, adds
   1 to this sentence, and no longer opens or extends "Includes … from keys needing attention".
   On P2 the key-trust clause's `(P&L unavailable for N positions)` sub-clause therefore stops
   rendering, because every row it counted is now left out. The builder keeps that branch, since
   the composer's spot path still reaches it.
5. **Rows the composer's modelled-book narrowing already dropped are not counted (P1).** They are
   not in `liveHoldingsSum` for an independent reason, and their existing "excludes $Y from …"
   part names them. An unreported derivative there keeps that part's existing
   `(value unavailable for N holdings)` sub-clause. This phase changes no wording in
   `buildKeyTrustClause`.

**Test id:** `scenario-aum-pnl-missing-note`, on exactly ONE element in every state where it
renders. Book mode only (`entryMode === "book"`). In blank mode `holdingsSummary` is `[]`, so the
count is 0 by construction.

The sentence follows the live-holdings total wherever that total is on screen, using the same
state machine as the key-trust marker (167.1-UI-SPEC § 1, the three mutually exclusive flags).
It never sits where it would read as qualifying the allocator's own typed number.

**State A** (field shows 50,000; 2 left out):


| Untrusted marker | Rendered row text after the input |
|---|---|
| absent | `2 derivatives without reported P&L left out.` |
| present | `Includes $12,345 from keys needing attention.` then `2 derivatives without reported P&L left out.` (two flex items) |

No subject is needed, for the same reason as the sibling "Includes …": in State A the field's

**State B** (manual 40,000, live 39,963, 1 left out). The host's existing text is unchanged, and

| Untrusted marker | `scenario-aum-override-note` textContent |
|---|---|

read as being about that total, not about the manual value in the field.

**State C** (live total 0 because every derivative is left out, or −4,000). Today the hint names
the live total only when the key-trust marker shows. ⭐ **Widened:** it names the live total when

|---|---|---|

- `The live-holdings total is {formatUsd(liveHoldingsSum)}` reuses the shipped 167.1 State C
  phrase and renderer. When the marker is absent it ends in `.` instead of `, which …`.
  `formatUsd` prints `$0` and the U+002D hyphen-minus for a negative total (167.1 measured this).
  Neither is post-processed.
- Nested spans carry no class. They inherit the host's `text-xs text-text-muted` (167.1 D-09).

**`aria-describedby` on `scenario-aum-input`** (the WR-02 rule: the note that qualifies the
field's value is its description):
- State A: add `scenario-aum-pnl-missing-note` to the list, after `scenario-aum-untrusted-note`
  when both render. The input then names up to two ids. Both qualify the number the field shows.
- State B: unchanged. `scenario-aum-override-note` is already named, and the sentence is inside it.
- State C: name `scenario-aum-required-note` when the marker shows **or** the count is ≥ 1, the
  same widening as the hint. A plain hint stays undescribed, as before.
- No `role`, no `aria-live`. The sentence changes only when toggles or the payload change, and the
  existing notes in this row are silent too (167.1 D-09).

**Placement follows the committed state** (`sanitizedManualAum`), never the per-keystroke input
text. The state moves on blur or Enter, exactly as the override note's does (167.1 Pitfall 3).
