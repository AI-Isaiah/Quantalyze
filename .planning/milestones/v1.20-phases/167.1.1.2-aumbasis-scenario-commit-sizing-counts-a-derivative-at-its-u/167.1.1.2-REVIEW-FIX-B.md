# 167.1.1.2 AUMBASIS - review fix B (scenario commit route)

**Finding:** WR-01 (MEDIUM, data-integrity). The commit route's holdings projection comment said
`unrealized_pnl_usd` was selected "for the EQUITY-basis comparison figure only". After D-04 that
column is the only input that sizes a derivative (equity AUM, D-02 remove size, D-03 left-out test).
The route test harnesses mock `select: () => chain` and ignore the column list, so dropping the
column would turn every derivative into "P&L not reported" with CI green.

## Change (minimal)

1. `src/app/api/allocator/scenario/commit/route.ts`: the comment above the `fetchLatestHoldingsPerKey`
   projection now says the column sizes a derivative and that a test pins it. No code change.
2. `src/app/api/allocator/scenario/commit/route.per-key-aum.test.ts`: the existing harness's `query()`
   takes an optional select log; the `allocator_holdings` mock logs every `select()` argument. One new
   test asserts that at least one logged projection includes `unrealized_pnl_usd`. (The reader also
   calls `select("asof")` alone to find the latest day, so the assertion is `some`, not `every`.)

## Evidence the test can fail

- Green before: `vitest run src/app/api/allocator/scenario/commit` = 3 files passed, 106 passed, 1 skipped.
- Neutered: removed `unrealized_pnl_usd, ` from the projection string in `route.ts` (byte backup taken
  with `cp`). Result: 1 failed (the new test only), 105 passed. This also shows the existing tests
  were blind to the column, which is the finding.
- Restored from the byte backup and confirmed with `cmp`; rerun = 106 passed, 1 skipped.
- `npm run typecheck` green. `src/__tests__/holding-scope-key-census.test.ts` = 53 passed.
