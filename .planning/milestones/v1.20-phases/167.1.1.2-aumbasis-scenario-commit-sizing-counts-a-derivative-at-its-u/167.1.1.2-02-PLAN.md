<objective>
Stop the derivative writers from manufacturing 0.0 when a venue reports no unrealized P&L (SC-2,
D-05). One helper decides "reported or not" for every venue string, four normaliser sites in
positions.py use it, and the allocator row builder passes None through instead of coercing it.

Purpose: after this, NULL in `allocator_holdings.unrealized_pnl_usd` (and in
`position_snapshots.unrealized_pnl`) means "the venue said nothing", which every reader in plans 01, 03
and 04 then handles by name. Both columns are already nullable, so there is no migration (D-09).
Output: `reported_pnl`, five changed sites, a per-site test matrix, a RED-on-coercion drill.
</objective>

Measured by the planner at the phase base (by symbol):
- `_parse_bybit_v5_positions`: P&L is read with a default of 0 when the key is absent, and an empty
  string raises ValueError today (aborting the whole batch).
- `_normalize_deribit_position`: coin-settled branch multiplies the zero-defaulted `floating_profit_loss`
  by `rate`; linear branch reads it zero-defaulted.
- `_normalize_ccxt_position`: zero-defaulted `unrealizedPnl`.
- `_fetch_derivative_rows`: zero-defaulted `unrealized_pnl` from the snapshot dict. Spot rows in the same
  file already write `unrealized_pnl_usd: None`, so the persist path already carries NULL.
- ccxt 4.5.85: Bybit unified nulls an exact-zero P&L (`omit_zero`); OKX / Binance keep a reported 0 and
  give None for absent or unparseable. Deribit documents `floating_profit_loss` as required.
- `value_usd`, `mark_price`, `entry_price` coercions on the same lines are OUT of scope (D-05 names P&L only).
- Existing harness: `TestFetchPositionsBybitFallback` with `BYBIT_CCXT_INCOMPLETE` and `BYBIT_V5_RAW_RESPONSE`;
  `TestFetchPositionsDeribit` with `_deribit_ccxt_position(info, ccxt_symbol)`; `TestFetchPositionsBinance`
