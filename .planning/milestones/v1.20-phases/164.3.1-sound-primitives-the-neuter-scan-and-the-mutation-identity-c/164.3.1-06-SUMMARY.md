## Decisions Made

- **Inline return type over a named interface.** `unmatchedBlockOpen` returns `{ open: number; quoteAtEnd: string | null }` written inline. The plan-03 instrument lifts this declaration by name and evaluates it through `ts.transpileModule`, which strips types without resolving them — so a named interface would have worked, but an inline type makes the extracted declaration self-contained and keeps the instrument's guarantee structural rather than dependent on a transpiler detail.
- **Null-forcing scoped to `'` and `"`.** Carrying an unterminated single/double quote across a newline would swallow every subsequent `/*` and produce the same blindness from the opposite direction. The rationale is stated in a comment beside the forcing, naming [AUDCOV-01].
- **Header comment appended, not rewritten.** The SP-I01 paragraph's final claim ("a `/*` inside … a template literal cannot open a block") was too strong, but it records what Phase 164.3 measured. The supersession names exactly which claim failed and why the shipped single-line arms stayed green while the detector went blind.
- **The block-exit path documented rather than silently changed.** After a `*/`, the tail is not re-scanned for a further opener — pre-existing scope. Carried quote is reset to null there with the reason given (a block comment cannot begin inside a string), instead of leaving a stale value to be discovered later.
