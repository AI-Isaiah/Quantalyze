Planner findings this plan acts on (measured at planning, re-measure before writing):
- `bridge_outcomes_allocated_at_check` is `allocated_at IS NULL OR (allocated_at <= CURRENT_DATE AND
  allocated_at >= CURRENT_DATE - '365 days'::interval)` (supabase/schema/baseline.sql, table DDL). PostgreSQL
  evaluates every CHECK on every UPDATE, so the holding_updated UPDATE of a row aged past 365 days raises 23514
  and aborts the whole function. A reset that NULLs deltas turns rows into candidates that can age into it.
- `allocator_equity_derived` carries FORCE ROW LEVEL SECURITY; the bridge function is SECURITY DEFINER and runs
  as the table owner (BYPASSRLS on PROD; superuser on the pg-lane), so a SECURITY INVOKER helper called from it
  reads the row. B1 proves the helper sees the row inside the batch.
- The derived payload is written by services/allocator_equity_compose.py: `returns` rows are `{date, r}` over
  the union of dense calendar-daily per-key days; a day the writer left out has no row (D-05: NULL).
