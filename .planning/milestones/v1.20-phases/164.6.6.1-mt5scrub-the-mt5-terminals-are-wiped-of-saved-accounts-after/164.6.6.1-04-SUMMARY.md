# Phase 164.6.6.1 Plan 04: relaunch debt paid on any tick, and the D-09 boot relaunch Summary

The jobs terminal can no longer be left account-less with nothing acting on it. Within one process, a tick that finds relaunch debt skips the bare probe and sends one credentialed house relaunch. The debt clears only when the house-equality check verifies that relaunch (CONTEXT D-10). Across a process restart, the boot heal treats the unattributed code `0` as the account-less signature and relaunches with the house credentials (CONTEXT D-09).

## What was built

- **`_settle_relaunch_debt(client, login, password, server, deadline)`.** `_heal_blocking` calls it right after the client is built, inside the `try` and before the bare probe, whenever `mt5_relaunch_debt(client.terminal_key)` is true, from any source. It works as follows:
  - It makes one `initialize_with_credentials` call with no poll, in the bare probe's two-crossing slot.
  - **Verified:** it clears the debt, calls `end_ipc_fault_run()`, logs "relaunch debt paid" at WARNING, and returns `_VERDICT_HEALED`, `first_kind=relaunch_debt`, `final_kind=healed`, `escalation_kind=relaunch_debt_settled`.
  - **A raised `-10005`:** it falls through to `_escalate_ipc_fault(..., env_login, env_password)`, subject to the existing debounce and cap. The escalation kind is returned, or `relaunch_debt_outstanding` when the call was debounced.
  - **Any other raised code:** `_not_healed("relaunch_debt_outstanding:code=N", err, ...)`. This is redacted by value. A `-6` also ends the fault run (CR-01: the terminal answered).
  - **Authorized but degraded or unverified:** the same `not_healed:` prefix, and the value-free check fragment run through `_redact_credential_values`. This also ends the fault run, and the debt is kept.
  - **While the debt stays set at return,** `_log_relaunch_debt_outstanding` logs an ERROR on every tick. The message says the terminal this service ended has not been seen authorized as house, that MT5 jobs on it fail until it is, and that an operator is needed if this persists.
- **`_boot_accountless_relaunch` (D-09).** It runs from the first-probe `except Mt5ClientError` arm, before the ipc_fault return, when `source == HEAL_SOURCE_BOOT and err.code == _MT5_UNATTRIBUTED_CODE`.
  - It calls `_relaunch_as_house`, with polls gated by `_affordable`, then `_read_post_relaunch_state`.
  - **Verified:** it clears the debt, calls `end_ipc_fault_run()`, logs at WARNING, and returns `boot_accountless_relaunched`.
  - **Otherwise:** it logs at ERROR and returns `boot_accountless_relaunch_failed`.
  - The verdict is the byte-identical `not_healed:ipc_fault:code=0:...`, with `first_kind=ipc_fault` and `first_code=0`. It never scrubs, recycles or claims, and it never touches the cap.
- **`_heal_blocking` gained `source: str | None = None`.** `heal_mt5_terminal_session`'s `to_thread` call passes `source=source`. Every existing `_heal_blocking` stub in the tests accepts `**kwargs`, which was checked before the change.
- **"THE BRANCH" docstring.** A dated 164.6.6.1 paragraph names the two exceptions to "a credential only on -6": (a) relaunch debt, citing D-10, and (b) D-09 at boot only. It qualifies the "disclosure surface opened for nothing" sentence, and (c) says every other reading keeps the original asymmetry.
- **Five kinds in `mt5_session_episodes`,** with a comment block. None is a positive class, so `classify_reading` degrades each to `not_measured`. The four escalation-shaped kinds were added to the test's `_ESCALATION_KINDS`, and `KIND_RELAUNCH_DEBT` has its own NOT_MEASURED test.

`_RECYCLE_REACHABLE_IPC_CODES` and `test_the_escalation_gate_is_exactly_the_ipc_timeout_code` are unchanged:

2. **[Plan-internal conflict, resolved by measurement] D-09's crossing count.** Task 2's action allows polls under `_affordable`, but its behaviour bullet says "at most 4 crossings". The action was kept.
   - With every crossing at its ceiling, a boot code-0 relaunch that verifies on the first call makes exactly 4 crossings.
   - One that never authorizes makes 6: the probe 2, the credentialed reading 2, then one affordable poll of 2, after which the settle window ends it. That is about 190 s of the 250 s budget, derived from the constants.

3. **[Rule 2] D-09 budget guard.** `_boot_accountless_relaunch` skips the credentialed call (`relaunch=not_read`) when one credentialed reading no longer fits. Without the guard, a `MT5_RELOGIN_BUDGET_S` below its default could abandon a credentialed call mid-flight against the shared terminal.
4. **[Rule 1 - Bug, own code] A debt relaunch the terminal answered did not end the fault run.**
   - **Found during:** the pre-handback review.
   - **Issue:** `_settle_relaunch_debt` called `end_ipc_fault_run()` only on a verified result. `initialize_with_credentials` does not move `mt5_terminal_answer_count`, and a debt tick never sends a bare probe. So after a still-faulted scrub (gate disarmed), a debt tick that read `-6` or authorized-but-unverified left the run open, and a re-wedge's `-10005` stayed debounced on every later tick, with no second scrub. That contradicts the module's CR-01 rule that an authorized reading or `-6` ends the run.
   - **Fix:** end the run on those two arms. The debt is still kept.
   - **Gate:** `test_RELAUNCH_DEBT_a_debt_relaunch_the_terminal_ANSWERED_ends_the_run_so_the_next_wedge_is_scrubbed` covers the `-6` arm and the authorized-unverified arm. Both were **RED** before the fix ("…left the escalation disarmed, so the re-wedge was debounced instead of scrubbed") and GREEN after.
   - **Commit:** df5270d1b.
5. **[Design choice inside the plan's latitude] The debt tick's verdicts.** The `-10005` fall-through's verdict names `relaunch_debt`, not `ipc_fault`. `first_code` is `None` on every debt outcome, so a credentialed `-6` can never classify as `dark`. The plan did not specify either.

## For the founder / reviewer

- **An unpaid debt is ERROR on every tick,** as the plan's truth and T-164.6.6.1-15 require. That is a different cadence from SFH-03's hourly persistence alarm. A terminal that stays account-less for a day on a ten-minute cadence produces about 144 debt ERRORs, beside the hourly persistence alarm.
- **D-09 fires on every cause of the code-0 sentinel at boot.** The causes are an unknown `last_error`, a malformed one, and a transport raise. D-09 is decided on "code 0", so a boot whose probe hit a dropped bridge now also sends one credentialed `initialize`, to the private-network gateway only. If the bridge is down, that call fails the same way and the outcome is `boot_accountless_relaunch_failed` at ERROR.
