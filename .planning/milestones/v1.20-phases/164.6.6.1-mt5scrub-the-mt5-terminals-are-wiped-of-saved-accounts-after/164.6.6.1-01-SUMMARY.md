# Phase 164.6.6.1 Plan 01: terminal scrub verb Summary

This plan adds one narrow verb, `Mt5Client.scrub_terminal_account_data(*, delete_trades: int)`, that ends every `terminal64.exe` in the bridge. If every matched process terminated and exited, it then deletes `Config/accounts.dat`; behind the int flag it also deletes the `Bases/<x>/trades` children. Its remote body is one committed literal, it never relaunches, and it records a relaunch debt before anything crosses. A scrub-owed registry for D-08 sits beside that debt registry.

## What was built

- **`_REMOTE_TERMINAL_SCRUB_SRC`** (`services/mt5_client.py`). The process half is copied verbatim from the recycle body: the walk, the terminate, the bounded wait, file versions and every refusal code. It then decides `refused` in this order:
  - 4: the process walk failed;
  - 1: no terminal matched;
  - 2: not every match was terminated;
  - 3: not every match exited;
  - 0: none of the above, the only value that allows a delete.

  Only at 0 does it delete `accounts.dat`, and the `trades` children only when `delete_trades == 1`. Whatever `refused` is, it counts `accounts.dat` files in the APPDATA profile one and two levels down, matching `os.listdir` names exactly so a case-insensitive filesystem cannot double-count. It deletes nothing there. It returns ints, int lists and class names, never a path. The install directory appears exactly once, as `root = "C:/Program Files/MetaTrader 5"`.
- **The verb.** It runs, in order:
  1. the fence;
  2. the transport check;
  3. strict int-flag validation (a bool is refused);
  4. `note_mt5_relaunch_debt`;
  5. `_guarded_read(stage="terminal_scrub")`;
  6. a strict parse of `matched`, `terminated`, `exited` and `refused`;
  7. the tolerant `_parse_scrub_diagnostics`;
  8. one WARNING naming the refusal (`_SCRUB_REFUSAL_REASONS`; an unknown int reads `unrecognised`);
  9. the `HOLDER_UNKNOWN` stamp when `terminated >= 1`.

  It issues no `initialize()`.
- **Registries.** `_MT5_TERMINAL_RELAUNCH_DEBT` and `_MT5_TERMINAL_SCRUB_OWED` each have note, clear and read functions. Both are cleared in `_reset_mt5_epochs_for_tests`, which `mt5_concurrency.reset_terminal_state_for_tests()` calls. Their comments say they live only in this process and name what covers each terminal after a restart: D-09's boot widening (plan 04) for the jobs terminal, and `mark_validation_terminal_owed_at_boot` (plan 06, not yet shipped) for the validation terminal.
- **Recycle amendments.** The recycle's comment block and docstring now carry a dated D-03 note. `_REMOTE_TERMINAL_RECYCLE_SRC` is byte-identical: an AST read of the constant at base `7cac3365` and at HEAD gave equal strings, 7506 chars each.
- **Runbook.** A new section, `## ⚠️ T-134-03 POSTURE CHANGE — file deletion under the volume (Phase 164.6.6.1, terminal_scrub)`, follows the three-part shape of the 164.6.5 section. It records counts and yes/no only.
- **Tests.** 23 `def test_TERMINAL_SCRUB_*` functions (32 cases once parametrised):
  - the tracer;
  - literal, allowlist and forbidden-target checks, with logs, mail and history matched as whole words;
  - the signature pin;
  - flag refusal, including bool, 2 and str;
  - the fence;
  - the absent transport;
  - a malformed essential count (the debt is kept);
  - a remote traceback;
  - a malformed diagnostic field;
  - the refusal name on the log line, including `unrecognised`;
  - no `initialize()`;
  - offline refusals 1 to 4, each confirming every file survives;
  - `trades` deletion limited to its children;
  - `common.ini`, `servers.dat`, the Journal and the profile kept;
  - an already-absent `accounts.dat`;
  - the IN-01 twin;
  - the credential roster excluding the verb;
  - the two registry tests.
