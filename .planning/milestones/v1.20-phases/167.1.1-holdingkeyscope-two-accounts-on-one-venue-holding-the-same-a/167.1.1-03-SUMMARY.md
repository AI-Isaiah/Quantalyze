# Phase 167.1.1 Plan 03: Compare per-holding metrics from the daily mark price Summary

**`/compare` now computes a crypto spot holding's return, Sharpe, max drawdown and vol from `allocator_holdings.mark_price` (one price per day, adjacent-day returns only), so buying more of an asset at a constant mark reads 0% where the retired dollar-ratio read gave +100%.**

## Accomplishments

- The adapter reads `allocator_holdings` only (user-scoped client, explicit `allocator_id` filter, the four columns `asof, mark_price, updated_at, api_key_id`), paged with `.range()` under a total order (`asof`, `id`) and a 50-page ceiling that throws `HoldingCompareLoadError` instead of returning a partial series. `allocator_equity_snapshots` is no longer read.
- `dailyMarkPrices` skips any mark that is not a finite number above 0 BEFORE the per-day pick, then keeps the row with the latest `writtenAtMicros(updated_at)`, ties to the smallest lowercase `api_key_id`. `analyzePriceSeries` reads cumulative return and max drawdown from the price level series and vol/Sharpe from true one-day returns only (a missing calendar day breaks the chain). Annualization is `annualizationPeriods("crypto")` (365); Sharpe and dispersion come from `@/lib/return-stats`.
- Per-type state: crypto spot with rows is always `"ready"` (four null metrics below 30 priced days, `priced_days` always carried), derivative with rows is `"rebuilding"`, an unknown `holding_type` and a spot holding on a non-crypto venue return null, zero rows return the D-15 null. The global history-state switch and its test seam are gone.
- Every compile-dependent fixture was updated (`priced_days` only, no assertion change in the factsheet and signed-zero tests), the page test now routes `allocator_holdings` and asserts the ready grid for a spot holding, sites T1 runs through `analyzePriceSeries`, and the live RLS test is reseeded on `allocator_holdings`.

## Decisions Made

- MIN gates on priced days (30), not returns: it is the unit the founder measured and the unit the approved UI-SPEC caption names, so the caption stays true. Vol and Sharpe additionally need at least two usable adjacent-day returns and are null on their own otherwise.
- Page ceiling of 50 pages (50000 rows) throws rather than truncating; the full-page-forever stub is the proof.
- The derivative branch is decided before the venue check, so a derivative on any venue with rows is `"rebuilding"` and never numbers.

## Known limits recorded, not fixed

- **Deferred Python twin (SC 4):** `reconstruct_symbol_returns` in `analytics-service/routers/match.py` is the Python twin of the retired dollar-ratio read, and the Bridge matcher still uses it. Not touched; to be booked.
- **Sampling-instant noise:** a mark is a ticker `last` at poll time, so the copy must say "daily price", never close-to-close.
- **MT5 reading, flagged for the founder:** a spot holding on a venue `isCryptoExchange` rejects (MT5 `ACCOUNT-<hex>` rows) returns null ("not available"), never a confident 0%. This is an orchestrator reading, not a founder decision; if the founder wants non-crypto spot handled differently it is a follow-up.
- **MIN-on-priced-days choice:** see Decisions Made; it is deliberately not reconciled with the Python warm-up gate, which counts returns.
- **Holding ids reach `/compare` by URL only today** (no in-app control adds one), so the ready state is reachable by a pasted `holding:` id.
