## Focus checks

- **Misleading figures.** Simulator `dd_delta` (`simulator_scoring.py:206`, surfaced at `:245`) is positive when the drawdown is shallower. The same holds for the optimizer `dd_improvement`, for `raw.dd_improvement` in the match engine, and for the bridge. The match engine's reasons are built from `max_drawdown_pct` magnitudes (`match_engine.py:811`), not from the signed improvement, so no reason carries the old sign. `AllocatorMatchQueue.tsx` only types the field. `ReplacementCard`, `PortfolioImpactPanel`, `simulatorSchema` and `analytics-schemas` pass the value through. No renderer negates it or takes its absolute value.
- **Stale persisted rows.** The only persisted `dd_improvement` and `dd_delta` store is `portfolio_analytics.optimizer_suggestions`. No migration or SQL function computes the sign, and no simulator result is persisted. PROD holds 0 non-empty rows and 0 match candidates carrying `dd_improvement`, so D-04 holds and nothing needs a backfill. The 119 v2.1.0 batches are re-scored on the first cron after deploy (`routers/match.py:1424`). `scripts/seed-demo-data.ts` seeds an empty `optimizer_suggestions`. The `complete.json` fixture holds positive values and is test data only.
