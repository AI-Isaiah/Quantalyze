## Warnings

### WR-01: New D-03 test pins "diversify the portfolio" for a candidate whose only measured effect is to worsen drawdown

**File:** `src/components/portfolio/WhatWedDoCard.test.tsx:106-122` (behaviour in `src/components/portfolio/WhatWedDoCard.tsx:19-55`)
**Severity:** WARNING (MEDIUM, confidence 6/10)

**Issue:**
1. Before this phase, `dd_improvement` was inverted, so the card could not act on it.
2. With the sign now correct, `dd_improvement < 0` means the suggested strategy makes the book's drawdown worse.
3. The card's own guard (`:21-38`) says "Don't recommend a strategy that would make the portfolio worse", but it hides the card only on a negative `sharpe_lift` or a non-finite score.
4. A top suggestion with `sharpe_lift: null`, `corr_with_portfolio: null` and `dd_improvement: -0.0087` therefore still renders, with the generic fallback "diversify the portfolio".

The new test asserts `expect(text).toContain("diversify the portfolio")` for exactly that input. That turns a user-facing claim with no support in any measured axis into pinned, intended behaviour. The phase itself books it as a known defect: plan 03's CHANGELOG brief lists "the What-we'd-do card's thin fallback for a constant-yield book" as out of scope.

So the test now pins a behaviour that is known to be wrong. Whoever fixes the fallback later has to flip an assertion that reads as a D-03 regression guard. The test's actual purpose is that the sentence "improve drawdown by" must not come back. Rule 9 applies: a test should encode why the behaviour matters.

The underlying card behaviour predates this phase. What this phase adds is the assertion.

**Fix:** Keep the two negative assertions, which are the real D-03 pin. Drop the positive pin on the fallback copy, or mark it explicitly as booked:

```tsx
const text = container.textContent ?? "";
expect(text).not.toContain("improve drawdown by");
expect(text).not.toContain("0.87%");
// The fallback copy for a suggestion with no measured win is a booked,
// out-of-scope defect (166.1.1 plan 03 Notes); do not pin it here.
```

Optionally, a later phase could make the card's "don't recommend a worse portfolio" guard also hide the card on `Number.isFinite(top.dd_improvement) && top.dd_improvement < 0` when no other axis shows a win. That is a product decision, so it is not proposed for this phase.
