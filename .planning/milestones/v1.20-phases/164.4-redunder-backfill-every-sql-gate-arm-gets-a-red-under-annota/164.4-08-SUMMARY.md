### Part 1 — the founder decision (commit `029ba435`)

`test_get_published_trust_signals.sql` assertion 5 asserts `has_function_privilege('anon', …,
'EXECUTE')`. It sat ~90 lines BEHIND assertions 1-3, which call the function AS anon. The only
change that reddens it is anon losing EXECUTE — and that killed assertion 1 first with a raw
`ERROR: 42501: permission denied for function get_published_trust_signals`, emitting no
`TEST FAILED (…)` at all. It was escalated as a waiver candidate.

The founder chose the root-cause fix. The assertion is a **precondition**, so it now runs before
`SET LOCAL ROLE anon;`, ahead of its dependents. `has_function_privilege` takes the role as an
argument, so it needs no anon context and is correct in that position.

- The six executable lines were relocated **byte-identically** — proved by diffing the removed

  `REVOKE EXECUTE ON FUNCTION public.get_published_trust_signals(uuid[]) FROM anon`.

## The timeout decision

**Measured ubuntu `sql-mutation` wall clocks, SHA-bound:**

| Arms | Wall clock | Run | Per-lane mean |
|---|---|---|---|
| 45 | 119 s | 33751634051 | 1.0s |
| 86 | 171 s | 33774615747 | 1.0s |
| 134 | 232 s | 33785233457 | 1.0s |
| 163 | 278 s | 33794810067 | 1.0s |
| 189 | **458 s** | 33804312706 (2026-09-03) | **1.7s** |

The old comment's linear fit over ARM COUNT (1.35 s/arm + ~58 s fixed) projected 313 s for 189
arms. The job took 458 s — **46% over**. The cause, read off the job's own log, is per-LANE cost:
`mean 1.7s`, where every earlier ubuntu run and both local runs printed `1.0s`. One observation
cannot separate CI-host variance from a real ubuntu-only per-lane cost, so the rewritten comment
projects from the WORST observed per-lane cost and cites **both** observations, dated.

**Arithmetic**, using the fixed non-lane overhead that same run implies (`458 − 189 × 1.7 ≈ 137 s`):

- this batch, 219 arms: `219 × 1.7 + 137 ≈ 509 s ≈ 8.5 min` — PROJECTION
- phase end, ~265 arms: `265 × 1.7 + 137 ≈ 587 s ≈ 9.8 min` — PROJECTION

**Decision: `timeout-minutes` STAYS 15.** The plan's rule is applied literally — raise only when a
MEASURED run is ≥ 10 min. The largest measured ubuntu run is 458 s = **7.6 min**, and even the
worst-case projection for the phase END is 9.8 min. Both are under 10, so there is nothing to
raise, and the comment says so beside the measurement.

The 20-minute CEILING is restated in the comment as a hard STOP, not the next rung; the split mode
was **not** built. The 219-arm PROJECTION line is marked `⬆ ONE-LINE SWAP` so the orchestrator can
replace it with the measured wall clock after the PR's first ubuntu run. The comment no longer
contains the `30 arms x ~2.0s` claim (asserted by the verify block).
