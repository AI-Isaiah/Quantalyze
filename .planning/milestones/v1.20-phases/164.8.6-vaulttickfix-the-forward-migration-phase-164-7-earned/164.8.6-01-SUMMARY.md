## Decisions Made

- **Count form over `INTO STRICT`** (CONTEXT "Claude's Discretion", RESEARCH §Q3 Pitfall 8). STRICT raises `NO_DATA_FOUND` on zero rows, which replaces V1's by-name message with a bare P0002; recovering the name needs the handler shape `20260907130000:243-245` keeps out of source and lint R1 flags in the corpus. The count form adds one RAISE by name and leaves V1's message byte-identical.
- **The `btrim` residual is recorded, not closed.** `btrim` with no character set trims SPACES ONLY; a key of tabs or newlines still passes. Criterion 3's text is `btrim(v_key) = ''` and it is matched verbatim; widening it to `E' \t\r\n'` is a decision with its own evidence, noted in a comment beside the guard.
- **The cardinality guard is shape-only.** Neither the lane stand-in (`name TEXT PRIMARY KEY`) nor hosted Vault (a VIEW) lets a gate insert two rows of one name, so no arm mutates `IF v_cnt > 1 THEN` and the migration asserts it by needle. Recorded in the header and here.
- **This file does NOT re-run 20260907120000's check 7** (the allow-list literal appearing identically in the CHECK constraint and the body). That check ran at that migration's apply and is not weakened; the body comment referring to it is kept byte-for-byte under the re-base discipline. Recorded as a residual in the header.
- **Assumption A3 stated, not assumed away:** no out-of-repo caller invokes the tick as `service_role`. A repo-wide grep at HEAD finds only the two migrations, the snapshot, the gate and the prober manifest — an Edge Function or a dashboard SQL snippet is outside what a grep of this repository can see and would begin failing on 42501 at the merge. Written into the REVOKE's comment.

### 2. [Rule 3 - Blocking] The three needles had to be ASSEMBLED BY CONCATENATION, which the plan did not name

- **Found during:** Task 1
- **Issue:** Task 1's acceptance criterion requires exactly ONE non-comment occurrence of `FROM vault.decrypted_secrets` and of `FROM public.system_settings` in the file ("the needles are falsifiable: deleting the read removes its only occurrence"). `grep -c` counts LINES. A needle written whole — `v_vault_needle TEXT := 'FROM vault.decrypted_secrets';` — is a SECOND non-comment line carrying that string, so the whole-literal form and the acceptance criterion cannot both hold.
- **Fix:** all three needles are assembled by concatenation (`'FROM vault.' || 'decrypted_secrets'`), which yields the identical runtime value and leaves the body read as the only occurrence. This is the repo's own idiom and its own argument — `20260907130000:776-783` concatenates its `v_guc_needle` for exactly this reason ("Written whole, the needle would itself be an occurrence"). The DECLARE carries that derivation.
- **Verification:** both counts measure 1; the DO block executed on the lane and printed its NOTICE.
- **Committed in:** `96590464`

### 3. [Rule 3 - Blocking] The disjointness table's gate-`find` column could NOT be pasted verbatim

- **Found during:** Task 1 (caught by measurement before the commit — `WHERE s.key = 'analytics_service_url'` read **2** occurrences on the first draft)
- **Issue:** The plan says to paste BOTH disjointness lists "verbatim from PATTERNS". But the mutation runner measures `occurrences` over the **RAW file text**, comments included (`countOccurrences` / `applyFileStep`, `scripts/mutation-runner/run.mjs:1930-1977`). Every re-pointed arm claims `occurrences: 1`; a verbatim gate-`find` string in the migration header is a second occurrence, and the run would report `MEASURE_FAIL … mutation NOT applied, so this arm was NOT tested`. `WAIVED_CEILING` is 0, so it is not waivable.
- **Fix:** the MIGRATION-NEEDLE column is verbatim (no arm mutates those). The GATE-`find` column is printed with each string's tail elided as `⟦…⟧`, with a loud ⛔ note naming the elided tails and the exact reason — which is itself the trap the table exists to warn about. A first draft that quoted C1's find verbatim inside the `v_settings_needle` comment was caught by the same measurement and rewritten.
- **Verification:** raw occurrence counts of all five find strings = 1 each (table above); `--parse-only` clean; all 13 arms bit first on the lane.
- **Committed in:** `96590464`
