### WR-02: the staging step prints two CONTRADICTORY `::error::` lines on the commonest abort (fix-or-drop)

**File:** `.github/workflows/test-restore-from-baseline.yml:2015` vs `:2029`

**Issue.** Line 2015 (the `scan_ok` deny, written for WR2-03) ends:

> `... The backup (ledger.csv, schema-before.sql) IS staged.`

Line 2029 (the `backup_ok` deny, added later for C1) says of the same two files:

> `... ledger.csv and schema-before.sql are therefore UNSCANNED and are NOT staged ...`

**Failure scenario.** Any run that aborts before the backup step's own scan — a `\copy` killed by
its `timeout 120`, a failed `supabase db dump`, an abort in the activity gate after `mkdir -p`
— leaves BOTH verdict files absent, so `scan_ok=0` AND `backup_ok=0`, and **both** annotations
print. The operator reading the Actions summary is told in one line that the backup IS in the
artifact and in the next that it is NOT. This is precisely the "control weaker than the sentence
beside it" class the phase exists to remove, reintroduced by the second half of its own fix.

**No test covers it.** The WR2-03 arm seeds `REAL_NAMES.filter(f => f !== "credential-scan.ok")`
(so `backup_ok=1`) and the C1 arm seeds `... f !== "backup-scan.ok"` (so `scan_ok=1`). Neither
exercises both-missing.

**Fix.** Make the first message conditional on the second verdict, e.g. move the backup sentence
out of line 2015 and print one combined line after both guards:
```bash
if [ "${backup_ok}" -eq 1 ]; then
  echo "::notice::the backup (ledger.csv, schema-before.sql) IS staged — its own scan cleared."
fi
```
and add a third arm to `src/__tests__/test-restore-workflow-wiring.test.ts` seeding
`REAL_NAMES.filter(f => f !== "credential-scan.ok" && f !== "backup-scan.ok")`, asserting the log
does not contain both "IS staged" and "NOT staged" about the same two names.

### WR-03: the backup step's verdict write is UNGUARDED, unlike its twin in the script (fix-or-drop)

**File:** `.github/workflows/test-restore-from-baseline.yml:1592`

**Issue.** The script's half carries an explicit failure narration
(`scripts/restore-test-from-baseline.sh:1727-1728`):
```bash
printf '%s\n' "$verdict" > "$RESTORE_OUT_DIR/credential-scan.ok" \
  || fail "MEASURE_FAIL: the scan CLEARED all … but its verdict could not be written … which is the opposite diagnosis."
```
The workflow's half has none:
```bash
printf '%s\n' "the backup files carry no credential shape …" > "${outdir}/backup-scan.ok"
```

**Failure scenario.** `${outdir}` full (ENOSPC), remounted read-only, or replaced under the job →
under `set -euo pipefail` the step dies at line 1592 **with no annotation at all**, and the
`if: always()` staging step then prints *"the backup step did not reach its secret scan, or that
scan did not clear"*. Both halves of that sentence are FALSE: the scan ran and cleared. The
direction is safe (deny), but the diagnosis sends the operator to the wrong step — the exact
"opposite diagnosis" the script's own comment says the guard exists to prevent. Two halves of one
mechanism, one guarded and one not, is the half-class fix this phase's own standard forbids.

**Fix.** Mirror the script:
```bash
printf '%s\n' "the backup files carry no credential shape in any scanned class (read: ${scanned_set})" \
  > "${outdir}/backup-scan.ok" \
  || { echo "::error::MEASURE_FAIL: the secret scan CLEARED '${scanned_set}' but its verdict could not be written to ${outdir}/backup-scan.ok. The staging step stages ledger.csv and schema-before.sql only on that file, so this run would read as though the scan had failed — the opposite diagnosis."; exit 1; }
```

### WR-04: the walk traverses BLANK lines, so the window is not "the contiguous comment block immediately above" (fix-or-drop)

**File:** `src/__tests__/gate-family-meta.test.ts:642-648`

**Issue.** The regex `/^\s*(?:\*|\/\*|\/\/|#|$)/` admits a blank line via its `$` alternative, so
the walk crosses any number of blank lines (up to 80) into an unrelated comment block. Measured
with a standalone reproduction of the function:

| fixture | result |
|---|---|
| `// MEASURED …` / `const A_FLOOR` / blank / `const B_FLOOR` | `B_FLOOR` **unjustified** ✅ |
| `// MEASURED …` / blank / blank / `const B_FLOOR` | `B_FLOOR` **JUSTIFIED** ❌ |
| code directly above, no comment | unjustified ✅ (terminates correctly) |
| site on line 1 | unjustified ✅ (terminates at file start) |

So the narrower version of the defect the fix was written for — evidence about a *different*
constant satisfying this site — survives whenever the two are separated only by blank lines.
Termination at file start and at a bare site is correct; no site is silently *dropped* (the walk
only affects `justified`, never whether a site is found), so coverage cannot be lost invisibly.

**Fix.** Stop at the first blank line that is not inside the block:
```ts
const isComment = (s: string) => /^\s*(?:\*|\/\*|\/\/|#)/.test(s);
let blockStart = idx;
while (blockStart > 0 && idx - blockStart < JUSTIFICATION_WINDOW && isComment(lines[blockStart - 1])) {
  blockStart -= 1;
}
```
(allowing at most ONE blank between the block and the site if the repo's formatting needs it —
but then say so in the comment rather than admitting unbounded blanks).

### WR-05: on an UNREADABLE backup file the operator is handed the wrong MEASURE_FAIL (fix-or-drop)

**File:** `.github/workflows/test-restore-from-baseline.yml:1544-1552`, `:1570`

**Issue.** `scan_for_secrets` returns from the `rc > 1` branch (line 1548) **before** recording the
basename in `seen` (line 1552). That is deliberate — an unopened file is not a read one — but the
consequence is that the *set* floor fires and its text is the one the operator reads:

> `MEASURE_FAIL — the secret scan READ 'schema-before.sql', expected 'ledger.csv schema-before.sql'.
> A count would have been satisfied by scanning one file twice; this is the set it actually opened.`

For an unreadable `ledger.csv` that sentence names the wrong cause ("a call was … aimed twice at the
same file"). The per-file `::error::` at line 1547 does print above it, so the information is
present — but the last and loudest line is a false diagnosis, and `hits` is never reported because
line 1569 exits first.

**No falsifier.** The new `describe("I1/I2/L1 — the backup step's secret scan, EXECUTED")` covers
clean, DIRTY (both flagged), double-aim (L1) and unwithholdable (I1). It does **not** cover
`grep` rc > 1 — a path that round 2 restructured (`exit 1` → `hits` + `return 0`).

**Fix.** Discriminate the two, and add the arm:
```bash
if [ "${scanned_set}" != "${SECRET_SCAN_EXPECTED}" ]; then
  if [ "${hits}" -ne 0 ]; then
    echo "::error::MEASURE_FAIL — the secret scan READ '${scanned_set}' of '${SECRET_SCAN_EXPECTED}'; the missing name(s) are the file(s) named in the unreadable-file error(s) above, not a mis-aimed call."
  else
    echo "::error::MEASURE_FAIL — the secret scan READ '${scanned_set}', expected '${SECRET_SCAN_EXPECTED}' …"
  fi
  exit 1
fi
```
Test arm: seed `ledger.csv` as a directory (or `chmod 000`) and assert the log names the unreadable
file and does NOT say "aimed twice".

### IN-01: `hits` double-counts an unwithholdable file
**File:** `.github/workflows/test-restore-from-baseline.yml:1545-1546`, `:1554-1555`
`hits` is incremented once for the finding and again when `withhold` fails, so one flagged file
that could not be removed reports `flagged 2 finding(s)`. Use a separate `unwithheld` counter, or
drop the second increment and let the named `::error::` carry it.

### IN-02: `withhold()`'s second arm is effectively unreachable and uncalibrated
**File:** `.github/workflows/test-restore-from-baseline.yml:1535-1538`
`rm -f` on an existing regular file either removes it or returns non-zero; the `[ -e "$1" ]`
post-check can only fire under exotic conditions (immutable attribute, a racing writer). The I1
test exercises the *first* arm (read-only directory), not this one. Keep it if the defensive
intent is wanted, but say in the comment that it is a belt-and-braces arm with no observed red,
rather than presenting it as the measured half of the guard.

### IN-03: `printf '%s\n' ${seen}` is unquoted
**File:** `.github/workflows/test-restore-from-baseline.yml:1568`
Word splitting is intended, but pathname expansion is also enabled and IFS is inherited. Safe for
the two literal basenames in use today; a future file whose name carries a glob character, or a
step that touches IFS, silently changes what the identity floor compares. `IFS=' ' read -r -a _n <<<"${seen}"`
or `set -f` around the line removes the latency.

### IN-04: stray double blank line
**File:** `.github/workflows/test-restore-from-baseline.yml:1593-1594`
Two consecutive blank lines introduced by the diff between the verdict write and the counts block.

### IN-05: the per-file hit message asserts withholding unconditionally
**File:** `.github/workflows/test-restore-from-baseline.yml:1547`, `:1556`
Both say *"The file has been WITHHELD from the … artifact"* even when `withhold` just printed
`COULD NOT WITHHOLD IT`. The tally at line 1574 hedges correctly ("unless an error above says
otherwise"); the per-file lines do not. Move the claim after the `withhold` result, or soften it to
"was withheld (see any error above)".

  removed trailing blank line does not break the byte-identity pin (`.trimEnd()`).
- **Default-DENY is complete.** The workflow has exactly one `upload-artifact`, and its `path:` is
  the staged directory, never `${outdir}`. Twenty names reach `${outdir}`; at most 13 can be staged
  (7 content, gated on the two verdicts; 6 channels, gated on `steps.redact.outcome`). Both verdict
  files are in neither allowlist and the wiring test seeds them into `REAL_NAMES` precisely so the
  "exactly the allowlist" arm requires them OUT.
- **Neither verdict file can be forged, substituted or inherited.** They are content-checked
  (`grep -aq 'carry no credential shape'`), not existence-checked, and the WR2-03 arm proves that
  by rewriting the grep pattern; the C1 arm proves the two gates are independent in both
  directions; each is written only after its own positive floor (`scanned N of N` in the script,
  `SECRET_SCAN_EXPECTED` + `hits -ne 0` in the workflow) — and the wiring test pins the ordering by
  index comparison. A re-run gets a fresh `RUNNER_TEMP`, so no stale verdict can survive.
- **Empty/unset `outdir` / `RESTORE_OUT_DIR` fails closed.** The workflow derives `outdir` from
  `${RUNNER_TEMP}` under `set -u`; the script falls back to `mktemp -d`, which puts
  `credential-scan.ok` somewhere the staging step will never look — deny, not admit.
- **`gutBranch()` and the two-line anchors fail LOUD, not silently.** Each anchor is asserted with
  `toContain(branch)` before substitution, so a reworded echo throws with "the branch … was not
  found". If `gutBranch`'s `/^if \[[^\]]*\]; then/` ever stopped matching, the replace would be a
  no-op, the branch would stay armed, and the "every fixture must go green" assertion below would
  red. The two `if [ "${rc}" -gt 1 ]` MEASURE_FAIL anchors are disambiguated by their echo heads,
  which is the right fix for the four-`rc`-branch problem the comment describes.
- **`findThresholdSites()` cannot silently LOSE a site.** The walk only affects `justified`; site
  discovery is unchanged, and an unjustified site is a red. Termination at file start and at a
  comment-less site is correct (verified).
- **F-R2-04 / F-R2-05 preserve semantics and are calibrated.** `grep_rc` is `local`-declared at
  `scripts/test-ledger-drift-check.sh:358`; the `set +e`/`set -e` idiom matches six existing sites
  in the same function; `check()` runs in its own `bash "$0" --run-check` subprocess so the
  restore of errexit cannot leak. Both carry a RED arm and a CONTROL arm in
  `drift-check-scripts.test.ts`, and both new softening sites are registered in the B3 allowlist.
- **F-R2-01's identity floor does what it claims.** `printf '%s\n' ${seen} | sort` over the two
  basenames yields exactly `SECRET_SCAN_EXPECTED`, and the L1 arm proves a double-aimed call reds.
- **`scripts/restore-test-from-baseline.sh` really carries 0 threshold sites** (independently
  re-derived with the two site regexes: no `*FLOOR|MIN|CEILING|MAX|LIMIT=` constant, no
  `[ "$x" -ge <2+ digits> ]` comparison), so listing it costs nothing today and is a real
  forward guard.
