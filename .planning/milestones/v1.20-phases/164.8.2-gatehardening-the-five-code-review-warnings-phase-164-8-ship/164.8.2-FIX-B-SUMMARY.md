### The exact transcript shapes the floor REDS on

All three are `exit 0` from the CLI's point of view — the live path F1 names — and all three are
executed against **both** blocks by the new arm
`EXECUTED (BOTH): the C-0331 floor REFUSES an empty, header-only or reshaped migration list (F1)`:

| Shape | Fixture text | Verdict with the floor |
|---|---|---|
| **EMPTY** | `""` | exit 1, `MEASURE_FAIL … printed no migration version at all` |
| **HEADER-ONLY** | `        Local      \| Remote     \| Time (UTC)\n  ---------------\|---------------\|---------------------\n` | exit 1, same message |
| **RESHAPED / REWORDED (no version rows)** | `No migrations found.\n` | exit 1, same message |
| **CONTROL — a valid list with one version and no reverted row** | header + `   20260101000000 \| 20260101000000 \| 2026-01-01 00:00:00` | exit **0**, no `MEASURE_FAIL` |
| **grep cannot READ the list (rc 2)** | valid list, `grep()` stubbed to `return 2` | exit 1, `could not read the migration list` |

⚠️ **THE RESIDUAL, stated rather than papered over.** The floor does **not** catch a CLI that keeps
printing version rows but **renames the status word** (`reverted` → some other word) while leaving
the table otherwise intact. No check can, without a *measured* replacement wording, and inventing
one and pinning it would risk reddening the PROD gate for a reason that has nothing to do with the
database. Re-**casing** is already covered by the existing `-i`. This limit is written into the
workflow comment itself, not only into this file.

### The falsifier, and the RED observed

finds exactly 2, and prints every removed line. It reported `NEUTER APPLIED at 2 site(s)` with both
blocks echoed back.

The floor-presence guard fires first, so it was bypassed transiently (`).toContain("grep -ac …")`

### ⭐ The repo's own stub WAS the defect

`SUPABASE_STUB`'s `migration list` printed the header and **nothing else**. The hermetic model of
the CLI in this repo was already the header-only shape, and every executed arm driving it green-lit
a C-0331 check that read no version at all. Adding the floor reddened three arms at once:

```

```

The stub now emits a version row via `${STUB_LIST_VERSIONS-…}` (no colon), so a test can request the
header-only transcript **deliberately** rather than getting it by omission.

## WR-05 — IN-04's job bound no longer degrades to slice-to-EOF

### What changed

Two things, matching the IN-03 discipline nine lines away in the sibling file (`suffix()` throws
rather than degrading to `slice(-1)`):

1. `NEXT_JOB_RE` widened to `/\n {2}[A-Za-z_][\w-]*:[^\S\n]*(#[^\n]*)?\n/` — trailing horizontal
   whitespace and a trailing comment are admitted.
2. `applyJobBlock` now **THROWS** when a permissive 2-space job key follows `apply:` that the bound
   did not match, instead of silently returning the slice to end-of-file. The real file, where
   `apply` genuinely IS the last job, must not throw — that control is asserted.

The calibration seeded a **bare** key only, which is exactly why the degradation shipped: a bare key
is the one shape the old bound matched. It now loops all three shapes, and a second arm proves the
throw fires on an unrecognised successor.

the last job in the file (`apply:` at line 1036, nothing at 2-space indent after it). That is what
makes the permissive detector safe here, and it is cited by command in the code comment.
