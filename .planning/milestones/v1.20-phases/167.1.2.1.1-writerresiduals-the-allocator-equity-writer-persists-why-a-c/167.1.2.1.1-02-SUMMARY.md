## Accomplishments

- **SC-2.** `DegradeReason.FAILING_KEY_SERIES_ENDED`. In `run_derive_allocator_equity_job`, after the no-capital exit rule, `failing_series_ended_keys` counts groups with exactly one eligible member that is counted, not in `departed_end_by_key`, not `working_holder_predicate`, and whose last return day is before the max last return day over the counted keys. A key with no return day is not flagged (the compose already blocks it as `dropped_key`). Reader and census read it as `shared_account_no_working_key`, in that token's precedence slot.
- **SC-3.** `_stitch_owned_window(firsts, index)` is the one ownership rule; `stitch_shared_account` now calls it for series values and flows (every pre-existing stitch test passes unmodified), and `stitch_flow_disagreement_days(links)` compares an owner's per-day flow total with every later member that LISTS the day under `math.isclose(rel_tol=1e-9, abs_tol=0.01)`. `SHARED_ACCOUNT_FLOWS_DISAGREE` reads `shared_account_history_truncated`.
- **SC-6.** `identity_pending_venues(key_rows, stamping_venues)` counts venues holding two or more eligible working keys whose `account_identity_tokens` entry is `None`. `ACCOUNT_IDENTITY_PENDING` reads the existing `account_identity_pending` line, after a duplicate and before the truncated-history line. `MissingSeriesReason` gained the existing member. Plan 03 calls the same helper.
- **SC-7.** When `departed_unavailable` is non-empty the payload `inputs` gains `departed_history_unavailable_keys`, `..._no_inputs_keys` and `..._no_anchor_keys`, and ONE `capture_message` at warning level fires (static message, tags `compute_job_id` and `derive_outcome` only). The benign flag the reader reads is unchanged. A healthy payload has none of the keys and fires no event.
- One cross-runtime table, `writer_residual_resolution.json` (6 cells: SC-2 positive and negative, SC-6 two-unknown, one-unknown, MT5 pair, one-failing), is run by the derive in Python and by the reader in TS. `derive_refusal_rows.json` gained a `blocking` row per new token and `precedence` rows, so plan 01's completeness pins keep every new member honest.
