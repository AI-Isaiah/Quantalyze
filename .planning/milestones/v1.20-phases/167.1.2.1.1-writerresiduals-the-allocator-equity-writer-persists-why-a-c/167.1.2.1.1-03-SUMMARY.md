# Phase 167.1.2.1.1 Plan 03: WRITERRESIDUALS SC-4, SC-5, SC-6 (refresh half) Summary

## For the orchestrator to book

- **Sentry volume.** The hold event fires once per allocator per day the hold persists (leader job only), so an allocator with a working key that never polls raises one warning a day until the key polls. That is the plan's design (D-14); no throttle was added.
- **A frozen book.** A working key that never produces a `sync_completed` event or a row (a broken poller) holds that allocator's legacy snapshot every day, by decision D-01. The audit row and the Sentry event are the signal; the same account clears the day it polls once.
- **The left-out Sentry events fire only when the day is written.** A book whose only account is a never-polled failing key takes the existing `no_holdings_today` branch (counts in the audit, no event), because nothing was left out of a total.
