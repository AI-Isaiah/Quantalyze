## Summary

Today three different pairings feed the benchmark-relative metrics. Alpha, beta, correlation, `info_ratio`, treynor, `btc_rolling_correlation_90d` and the rolling greeks all use M1's daily inner join (`returns.align(benchmark, join="inner")`), which pairs a Monday return of a weekday-only strategy with BTC's Sunday→Monday move. r² alone goes through `_align_benchmark_like_qs`'s reindex branch, which already produces the Friday→Monday compounded move but zero-fills the first strategy date, back-fills BTC across any missing date, and zero-fills the strategy's own NaN days. That is why r² ≠ correlation² and why r² did not move when beta flipped sign. [VERIFIED: analytics-service/services/metrics.py::compute_all_metrics, ::_rolling_alpha_beta, ::_r_squared, ::_align_benchmark_like_qs]

The only production path that hands the engine a sparse calendar is a **user-CSV** strategy (`api_key_id IS NULL`) through `analytics_runner.run_csv_strategy_analytics`. Broker-sourced strategies are reindexed to a dense daily span (NaN at guard days) before compute, and every `stitch_composite` basis goes through `gap_fill_daily_returns` (dense, 0.0 on absent days). With the benchmark always a contiguous 7-day BTC series from `get_benchmark_returns`, the interval-matched pairing reduces to the daily inner join bit-for-bit on those paths. A prototype of the one helper, wired into a scratch copy of the service, moved **exactly 4 of 7,064 analytics tests**, all four being pins of the old pairing on calendar-mismatched fixtures. The golden 252-day parity fixture, the TypeScript cross-runtime parity file and every other test stayed green.

**Primary recommendation:** add ONE helper that returns, for each strategy date, the benchmark return over (t_{k-1}, t_k] (a single return verbatim, several compounded, NaN when a close is missing at either endpoint). Build ONE `(strategy, benchmark)` pair from it in `compute_all_metrics`, and feed that pair to `_greeks_no_guess`, correlation, `info_ratio`, treynor, `_rolling_correlation`, `_rolling_alpha_beta` and `_r_squared`. Retire the reindex branch of `_align_benchmark_like_qs`, and keep the three mirror symbol names the quantstats gate maps. Three conventions are not covered by D-A and go to the orchestrator/founder before the planner locks SC2 and SC4 wording (DC-1, DC-2, DC-3 below).

**"Gap" and "skip", defined for what the metrics actually receive:**

- A **benchmark close exists at date d** iff d carries a finite benchmark return, or d is the base close of the first return (see the base-close convention in Q3). A NaN or ±inf benchmark return means no close at d.
- A **benchmark gap** is a strategy date t that is not a benchmark close.
- **Skip**: interval k is excluded from the pair when t_k or t_{k-1} is not a benchmark close. By the D-58 amendment rule this excludes BOTH the interval ending on a missing close and the interval that starts on it. Nothing is filled.
- A strategy-side NaN (broker guard day, composite member guard) is NOT a benchmark gap. Its date stays in the strategy index, so the NEXT interval is still one day long and pairs normally. Each metric keeps its own existing strategy-NaN convention (pairwise drop for scalars, `fillna(0)` for rolling greeks). That is what keeps broker and composite series bit-identical.

**The three fills in `_align_benchmark_like_qs`, verbatim** [VERIFIED: analytics-service/services/metrics.py::_align_benchmark_like_qs]:

```python

...
benchmark_prices.reindex(new_index, method="bfill")
    .reindex(period)
    .pct_change(fill_method=None)
    .fillna(0)
```

| Fill | Fires on real inputs? | When |
|---|---|---|
| #1 `fillna(0)` before `cumprod` | **No** | `prices_to_returns` ends in `.dropna()`, so production BTC returns carry no NaN |
| #2 `reindex(..., method="bfill")` | **Yes** | (a) every strategy date BEFORE BTC's first return (a strategy history longer than the ~1000-day window) takes BTC's first rebuilt price, so those strategy returns pair with 0; (b) a BTC gap (stale fallback) takes the next close |
| #3 `.fillna(0)` after `pct_change` | **Yes, on every benchmarked strategy** | the first strategy date always pairs with a benchmark return of 0. Also any strategy date after BTC's last completed day (bfill finds no later close, NaN, then 0) |

## Q3. The interval-matched pairing, defined

**One helper, recommended signature** (names are discretion):

```python
def _interval_matched_benchmark(index: pd.DatetimeIndex, benchmark: pd.Series) -> pd.Series:
    """For each strategy date t_k, the benchmark return over (t_{k-1}, t_k] (166.4 D-A); NaN = unpaired.

    Paired ONLY when the benchmark has a close dated t_{k-1} AND a close dated t_k (the pairing
    rule of Phase 169.5 BENCHCOMPARE's D-58 amendment; its TypeScript twin is
    src/lib/factsheet/align.ts). One benchmark return in the interval is used VERBATIM;
    two or more are compounded, prod(1 + b) - 1. Never filled.
    """

def _benchmark_pair(returns: pd.Series, benchmark: pd.Series) -> tuple[pd.Series, pd.Series]:
    """The ONE (strategy, benchmark) pair every benchmark-relative metric reads.

    Refuses mismatched day labels (_refuse_mismatched_day_labels), tz-normalises the strategy
    (_tz_naive_like_qs), and restricts both legs to the paired dates. Strategy NaN is retained;
    each metric keeps its own existing NaN convention.
    """
```

**Rules:**

1. k ≥ 1: paired iff `t_k` and `t_{k-1}` are benchmark closes and no benchmark value in (t_{k-1}, t_k] is NaN. Value = the single return verbatim if exactly one benchmark date lies in the interval, else `prod(1 + b) − 1`.
2. k = 0: the one-period convention, DC-2 option (i). Paired with the benchmark return dated t_0 when t_0 carries one.
3. **Base close** of the benchmark: `benchmark.index[0] − 1 day` is treated as a close. Rationale: `prices_to_returns` drops the first price date, so a strategy date that equals BTC's first return date would otherwise be unpaired, and dense strategies older than the BTC window would lose one pair (breaking SC4). This rests on BTC's first two closes being one day apart, which the cache path's contiguity check guarantees. [ASSUMED] for the fresh-fetch and stale-fallback paths.

**Vectorisation** (measured 0.022 s for 975 strategy dates × 1000 BTC dates): assign each benchmark date its interval with `np.searchsorted(index.values, benchmark.index.values, side="left")`, then group by that id for count / first / compounded product / any-NaN.

**Dense reduction to the inner join (SC4), measured on the prototype:**

| Fixture | inner-join pairs | D-A pairs | benchmark leg bit-identical to inner join? |
|---|---|---|---|
| dense daily, 400 d inside BTC coverage | 400 | 400 | **yes** (`np.array_equal`) |
| dense daily, starts before BTC window, ends 1 day after | 1000 | 1000 | **yes** (needs the base-close convention) |
| dense daily, 3 NaN strategy guard days | 400 | 400 benchmark-paired (397 complete) | **yes**; alpha/beta/corr equal today's |
| golden: `golden_returns` + `benchmark_returns` (same bdate calendar) | 500 | 500 | **yes** |
| committed `golden_252d_input.parquet` (both legs one weekday calendar) | 252 | 252 | yes. `test_metrics_parity.py` stayed green on the prototype |
| dense daily with ONE missing BTC close (stale-fallback shape) | 399 | 398 | **no, by design**: the date after the gap is a 2-day BTC move against a 1-day strategy move |

**SC4 therefore holds under two stated preconditions:** the benchmark is contiguous (true for the cache path), and DC-2 option (i) plus the base-close convention.

def test_benchalign_weekday_beta_is_the_friday_to_monday_regression():
    strategy, benchmark = _q166_calendar_mismatch()          # committed builder
    price = (1.0 + benchmark).cumprod()                      # the benchmark's own closes

    b_interval = pd.Series(
        [benchmark[s[0]]] + [price[s[k]] / price[s[k - 1]] - 1.0 for k in range(1, len(s))],

### Anti-Patterns to Avoid

- **A price-ratio or `(1 + x) − 1` implementation of a one-day interval.** Not bit-identical to the stored return; breaks SC4 at 1e-16. Use the single return verbatim.
- **Fixing r² alone** (for example `r_squared = correlation**2` computed from the inner join). Satisfies "r² = corr²" while leaving the M1 pairing that flips beta.
- **Aligning twice.** `_rolling_alpha_beta` today does its own `returns.align`. Two independently built pairs is how the metrics diverged in the first place.
- **Filling a benchmark gap with 0 or a neighbour** anywhere in the new path (D-A, D-58).

## Common Pitfalls

1. **Verbatim single return.** See Anti-Patterns. Warning sign: the dense parity test fails at ~1e-16.
2. **The tz refusal leaving the `try`.** `_rolling_alpha_beta` today refuses a mismatched-zone pair inside `_rolling_greeks`, within its `try`, degrading to `([], [])` with a WARNING. Calling `_benchmark_pair` BEFORE that `try` makes the refusal propagate, and `compute_all_metrics` calls `_rolling_alpha_beta` unguarded. `test_q166r2_a_pair_labelled_in_different_zones_is_refused_not_shifted` stayed green on the prototype, but the planner must keep the refusal inside the existing handler. Better still, build the pair ONCE inside the benchmark fan-out's `try` and pass it down.
3. **The base-close convention** (`benchmark.index[0] − 1 day`). [ASSUMED] contiguity. Without it, a dense strategy older than the BTC window loses one pair and SC4 fails for it.
4. **A BTC gap breaks dense bit-identity by design** (1 extra unpaired date per gap). The SC4 parity test must use a contiguous benchmark and state the precondition. Add a separate SC2 test with a missing BTC close asserting BOTH adjacent intervals are unpaired.
5. **r² tolerance.** `linregress` r² vs `corr()**2` differ by ~1e-16. Assert `rel=1e-12`.
6. **Guards counting the wrong length.** `len(aligned_returns) > 1`, `>= 90` and `_rolling_alpha_beta`'s `aligned_n < window` must count PAIRED rows. With the pair restricted to paired dates this is automatic; a mask-based design would silently count unpaired rows.
7. **Rolling window semantics on a sparse series.** The 90-row window is 90 paired intervals (about 126 calendar days for weekday data), exactly as today's inner join on the same dates. Unchanged convention; say so in the docstring.
8. **Hygiene.** `.planning/` is public: no strategy id, name, or home path in SUMMARY or tests. Fixtures are synthetic and seeded.
