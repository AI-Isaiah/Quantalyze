# Phase 166.4 Plan 01: One interval-matched benchmark pair Summary

**Every benchmark-relative metric (alpha, beta, correlation, info_ratio, treynor, r_squared, btc_rolling_correlation_90d, rolling alpha/beta) now reads one `_benchmark_pair` that pairs each strategy return with BTC's compounded return over the same holding interval, only when BTC has a close at both endpoints. The weekday fixture's beta flips from +0.012560995909126458 to -0.007423918641620668, and r_squared equals correlation squared again.**

## Decisions Made

- The one-day verbatim rule uses `np.where(count == 1, first, compounded)`, so dense series keep the stored return bit-for-bit and never go through `(1 + x) - 1`.
- The searchsorted inputs are cast to `datetime64[ns]` on both sides, so interval ids never depend on each index's resolution.
- `_r_squared_pair_varies` keeps its four conjuncts, now evaluated on the same pairwise-complete pair that `_r_squared` regresses.
- The index-0 D-05 value is looked up directly, so benchmark dates before t_0 (which fall in interval 0) are ignored.
