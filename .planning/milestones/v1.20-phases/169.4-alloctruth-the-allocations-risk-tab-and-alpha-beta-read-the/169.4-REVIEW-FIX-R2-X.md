## Fixed Issues

### R2 CR-01 + SFH-R2 MEDIUM-1: the signature sections labelled BTC data with the active comparator's name

**Files modified:** `src/app/factsheet/[id]/v2/SignaturePanels.tsx`,
`src/app/factsheet/[id]/v2/CrossSignaturePanels.tsx`, `src/app/factsheet/[id]/v2/SignaturePanels.cr01.test.tsx`
**Commit:** `dc1abccaf`

**Applied fix** (orchestrator decision: the panels always say BTC, and the empty state names the real cause):

- `SIG_BENCH = "BTC"` (exported from `SignaturePanels.tsx`) is the label for every title, per-panel
  count, legend entry, subtitle and em-dash reason in both files. The `useActiveComparator()` read and
  the `benchName` prop plumbing are removed from both files. `FactsheetView.tsx:469,472` mounts
  `<SignaturesSection />` and `<CrossSignaturesSection />` with no props, so no caller carries a
  now-dead prop and nothing is left for topic Y to clean up.
- `btcPricesUnavailable(payload)` separates the two causes using only the payload the component already
  reads. It is the predicate the allocator portfolios use (`build-payload.ts`, `btcUnavailable =
  "unavailable" in benchmarkPrices`), read off `payload.benchmarkPrices`, which the builder attaches.
  An absent `benchmarkPrices` counts as unavailable, which is how `types.ts` documents the browser
  re-derive reading it.
  - **Outage:** each missing BTC view reads *"Not measurable: BTC prices are unavailable right now."*,
    the allocator panel's wording. In the cross section this also covers the "of Accumulated Capital"
    panels, whose missing side during an outage is BTC's own events. Before the fix they read
    "no BTC event has a complete ±14-day window of returns", which is the wrong cause.
  - **BTC available but no complete window:** *"no win/loss event has a complete ±14-day window of BTC
    prices"*, now always naming BTC.
- **Why not `comparators.btc.through === null`** (the reviewer's suggested marker):
  `buildComparatorBlock` passes `aligned.through` through unchanged, so a BTC series that was read but
  has no return on the strategy's axis also gives `through: null`. That is the window cause, not an
  outage. With `benchmarkPrices`, the signature panels and `BatchDPanels` agree on the cause by
  construction.
- The two causes are told apart from props and context alone, so the "true in both cases" fallback
  wording was not needed.

**Status: fixed.** This is a copy and label defect, not a logic change to any figure. Every plotted
series is unchanged.
