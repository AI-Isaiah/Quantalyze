## Deviations from Plan

**1. [Rule 2 - currency] Two comments in `build-payload.ts` rewritten, one local added.** The plan's scope line says only the two calls and the function change. The comment above the D-65 locals and the `nullAsZero` docblock both said the event signatures take the 0-filled series; after this change that was false, so both now say the event signatures read the null-honest returns (169.4-05) and the allocator portfolios remain 169.4-06's. The `btcAligned` local is how the calls receive the alignment. `nullAsZero` itself is deleted by 169.4-06 (D-70(5)). Commit `5303c6188`.

**2. D-70(1) window reading.** D-70(1) says a trace "whose 29-day window touches a null" is dropped. Implemented as: the trace reads a null among the 28 returns it compounds, indices eventIdx-13 .. eventIdx+14. The point at offset -14 is the close ending day eventIdx-14; the return dated eventIdx-14 (the move INTO that close) is read by no trace, so a null there invents no 0 and dropping for it would lose a real event. A dropped close at eventIdx-14 nulls eventIdx-13 too, which is read, so that case is dropped. This matches the pre-existing `buildReturnTrace` span.

**3. node_modules.** The plan says remove the `node_modules` symlink before every commit; the orchestrator brief says never remove or stage it (it is gitignored). The brief was followed; `git status` was clean at each commit.

## For the orchestrator / verifier

- **Header count vs equity population (pre-existing, out of scope).** In the strategy-driven set `winCount`/`lossCount` count the BTC traces; the "of Accumulated Capital" panels aggregate every window-eligible event. With a mid-series BTC null, SignaturePanels' title can read 24 while the equity panels aggregate 52. The plan's behaviour keeps equity traces unchanged, and the divergence already existed (the -100% guard caused it). The must-have "count and draw only events whose windows hold real BTC data" holds for the BTC panels; the equity panels never read BTC.
- **An empty trace set draws a flat 0% line (pre-existing, panels out of scope).** `aggregate([])` returns all-zero arrays, so a BTC panel with 0 events (BTC unavailable, or every window touching a null) draws mean and bands at 0% under a "0 wins · 0 losses" title. Before this plan the same inputs drew 0-filled traces with FULL counts, so this plan does not worsen it, but it is a user-facing render of no data as a 0% path. It lives in the panels / `aggregate`, which this plan may not edit; routing is the orchestrator's call.
