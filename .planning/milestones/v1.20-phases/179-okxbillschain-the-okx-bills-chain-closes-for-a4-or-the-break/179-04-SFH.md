## Findings

### SFH-179-04-01 — MEDIUM — data-integrity (not user-facing) — okx_opening_balance.py:`close_agrees` / `bal_places` (~lines 300-335)
The forgiven residual is half a unit of `max(-exponent)` over the printed `bal` strings, and the
precision is INFERRED from the print, not known. D-06's premise is that OKX prints fixed places, but
`bal_places` itself documents that "a print that dropped its trailing zeros" exists, and guards only
the `places == 0` case. A chain whose bills all print short (a dust or low-activity currency, a
single-bill chain, `"100.5"`) gets `places == 1` and a 0.05 absolute allowance: a missing 0.04 of that
currency passes the close as "agreed" and the forced rebuild anchors on an unproven opening. Bounded
in value for the common case (dust), but unbounded in relative terms: 0.05 on a 0.5 balance is 10%.
The 1e-12 arm is tight; the precision arm is the loose one and has no relative cap.
Hidden errors: a missing bill/withdrawal/fee of up to half a last-place unit on any currency whose
bills happen to print few places.
Minimal fix: cap the precision arm by a relative bound as well, i.e. accept on the precision arm only
when `residual <= max(half_ulp_bound, ...)` is replaced by `half_ulp_bound` AND
`residual <= <founder-decided relative cap> * max(|bal|, |cash|)`; or require `places >= <floor>` (for
example the 16 a4 prints) before the precision arm applies, so a short print falls to the exact/1e-12
arms. Needs a founder number (D-06 says bounds change only by a founder decision), so route as a
question, not a silent edit. Add a test world: single bill `("100.5","0")`, cash `"100.54"` must refuse.
Today's tests pin `100.5000`/`100.3` shapes but no world where the whole chain prints one place.

## Orchestrator disposition (2026-10-28)

SFH-179-04-01 is not fixed in this round. It does not find a defect in how D-06 was implemented: a chain that prints one decimal place and a cash balance that rounds to the same value at that place is the case D-06 describes ("agree to the bill's own decimal places"). Narrowing that arm needs a new number, and CONTEXT D-06 and `CLOSE_RESIDUAL_REL_BOUND`'s comment make a bound change a founder decision. A fixer round cannot choose one ("For fix rounds minimal fix only, no new abstractions or defensive checks").

The parallel code review (179-04-REVIEW.md) found that the close allowance never enters the opening's value: the opening stays the oldest bill's `bal - balChg`, so a forgiven close residual cannot move it. The exposure is a weaker proof that no bill newer than the walk was missed, not a wrong opening.

Routed to the founder as a decision, recommended option first:
1. Keep D-06 as written (Recommended). a4 passes on the 1e-12 arm either way.
2. Add a floor on printed places before the precision arm applies, or a relative cap on it. This is a new bound, so it would be decided first and then planned.

## Founder decision (2026-10-28, supersedes the routing above)

The founder chose "Trillionth bound only (Recommended)" (179-CONTEXT D-07): the decimal-places rule is deleted and the close check passes only within 1e-12 of the larger balance. SFH-179-04-01 is fixed in one fixer round, with a test that refuses the one-place 0.5 vs 0.54 case.
