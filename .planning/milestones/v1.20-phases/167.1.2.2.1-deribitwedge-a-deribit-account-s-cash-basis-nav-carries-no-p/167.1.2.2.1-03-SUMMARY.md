# Phase 167.1.2.2.1 Plan 03: Cash-basis wedge, derive determinism, refusal capture Summary

**The Deribit cash_settlement wedge is now `equity - balance`, so the open option book's session move is counted once and an accrued `session_rpl` no longer moves the rolled terminal; two derives over one ledger are byte-equal whatever the live state does, a derive can be replayed from its stored `account_summary`, and a derive that refuses after its read now stores that read on a `key_capture` row.**

`PLAN_BASE` (HEAD before the first edit) is `ed334abe10720231e6f7b77b2e9b8ac59ae46041`. `commits: 7` is measured with `git rev-list --count`; `plan_head_after` is the code HEAD before this SUMMARY's own commit. Nothing is shipped; this plan's code goes in PR-2 after plan 05 records `identity-verdict: confirmed`.

## What was built

- **Task 1 (tracer, SC-1 / D-18).** `_cash_basis_wedge(state, ccy)` in `deribit_ingest.py`: `equity - balance` when `balance` was read (present-only map from plan 01), else `native_upnl - options_session_upl + options_value`. The cash arm of `build_deribit_native_ledger` keeps its `if/else`, adds the `native_balance` currencies to the `_wedge_ccys` union and replaces only the `else` dict body. The block comment states the documented identity and names Phase 131 REVIEW "Residual #2" as lifted. The MTM/smoothed arm, `_combined_session_upl` and the `native_upnl` map are untouched.
- **Task 2 (SC-6 / D-03).** `_state_from_summaries(summaries, index_prices, *, read_at_iso)` is the pure half of `fetch_deribit_native_account_state` (no I/O, no clock); the fetch keeps its I/O, retry behaviour and failed-read returns and calls it. `DeribitNativeAccountState.from_stored(stored)` runs the same code over the dict `read_account_summary` returns; a missing key raises `KeyError`. New `tests/test_derive_determinism.py`: perturbation matrix A-D, stored-snapshot replay, `from_stored` round trip for a valuable and an unvaluable-collapse state, corrupt-row `KeyError`, identical-stub control (9 tests).
- **Task 3 (MD-01, MD-02, LO-06).**
  - MD-01: the `account_summary` capture now runs right after the account read is validated; the ledger digest and inception diagnostics run right after `assert_ledger_complete` and before the C2 floor and `combine_native_ledger`. The diagnostics are gated on `native_ledger.full_history` only (no longer on the "reconciled" verdict). Module-level `_persist_refused_key_capture` upserts `kind = "key_capture:" + api_key_id` with `outcome: "refused"`, `refusal_class`, `captured_at`, `venue` and whichever captures exist; it never raises (one class-name-only WARNING). A branch closure `_record_refusal` calls it from the completeness-class handler, the `LedgerValuationError` handler, the `NavReconstructionError` handler and the C2 empty-ledger return (`refusal_class: "EmptyLedgerRefusal"`). A refused derive writes no `key_inputs`; a success writes no `key_capture`.
  - MD-02: `_account_identity` uses `_DERIBIT_FIELD_PLACES = 8` with five terms: `tol = max(2.5e-8, 1e-9 * |equity|)`, exact `Decimal` residual kept. Stores `identity_resid_native` (signed) and `identity_places` (8). `read_account_summary` parses both strictly (finite float or null; non-bool int) and accepts old rows. `_decimal_places`, `_IDENTITY_PLACES_CAP`, `_IDENTITY_TOL_UNITS` removed (`git grep` showed no other user). IN-03 recorded in the `_account_identity` docstring.
  - LO-06: a derive test runs the REAL `native_ledger_inception_diagnostics` through `job_worker` on a ledger with marks and round-trips the output through `read_native_inception_diagnostics`; the mocked-wrapper test now asserts the wrapper received the very ledger object and the indexable set the combine received.

I checked the substance instead: HEAD is attached, on a per-plan branch, not on `main` or any protected name, in a linked worktree (`.git` is a file).

**3. [Rule 3 - blocking] Two existing test files outside `files_modified` needed an update.** Both were forced by this plan's change and are the intended consequence:
- `tests/test_broker_dailies.py`: five key-mode refusal pins asserted `capture["upserts"] == []`. A refusal now writes exactly one `key_capture` row, so they assert `_non_capture_upserts(capture) == []`, a helper that lets only that row through; they still forbid any `csv_daily_returns` or `key_inputs` write.
- `tests/test_job_worker_deribit.py::test_no_per_account_dispatch_flag_source_scan`: it looked for `combine_native_ledger(` inside the first 200 lines of the deribit branch; the refusal-capture code now sits before that call (about 240 lines in). The window is 400 lines. The pin is "present and unconditional", not a distance.

**4. [Test update, intended] Two PR-1 identity tests changed their basis.** `test_identity_breaks_by_the_residual_over_the_precision_tolerance` (25 tolerances at 4e-8) and `test_identity_tolerates_a_half_unit_of_the_last_place` (3e-8 inside 4e-8) restated the old rule. They are renamed and restated for the new one (1e-6 is 40 tolerances of 2.5e-8; 2e-8 is inside, 3e-8 is outside). `test_identity_falls_back_to_session_upl...` gained the 1.8 case it could not fail before.

**5. [Design] Order of operations in the fetch split.** Parsing the native maps moved from before the index probes to after them (they are one pure function now). A summary with a garbled non-numeric `equity` string used to raise `ValueError` before any probe; it now raises after the probes ran. Every value and every successful-path order is identical, the suites are green, and the probes are read-only.

**6. [Design] `identity_places` is validated as a non-boolean int, not pinned to 8.** The plan said "int 8"; pinning the reader to a constant would break reading old rows the day the constant changes. The writer always stores `_DERIBIT_FIELD_PLACES`.

**7. [Design] `_run_deribit_key_mode_derive` gained optional `ledger=` and `trace=` parameters** (existing callers unchanged) so the LO-06 tests can hand it a ledger with marks and see what the combine received.

No other deviations.
