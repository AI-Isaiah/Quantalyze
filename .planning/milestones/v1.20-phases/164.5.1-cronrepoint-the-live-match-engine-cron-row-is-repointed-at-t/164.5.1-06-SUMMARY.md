# Phase 164.5.1 Plan 06: CRONREPOINT Batching Summary

**`cron_recompute()` now stops at a batch boundary (count bound OR elapsed-time bound, whichever first) instead of doing its whole unit of work inside one gateway-bounded request — persisting a resumable keyset cursor in `public.system_settings` (the FIRST Python read/write path against that table) and returning `status="partial"` + `next_cursor` until the set is exhausted.**

## Accomplishments

- `analytics-service/routers/match.py`: `MATCH_ENGINE_CURSOR_KEY`, `CRON_BATCH_SIZE` (default 10, floor 1, env-overridable), `CRON_BATCH_BUDGET_S` (default 25.0s, strictly below plan 03's 45s `statement_timeout`, env-overridable), `_read_cron_cursor`/`_write_cron_cursor` — the FIRST Python read/write path against `public.system_settings` in this service.
- The allocator query in `cron_recompute()` became a keyset page (`.gt("id", cursor).order("id").limit(CRON_BATCH_SIZE + 1)`), fetching one extra row to learn whether more remain without a second count query.
- Three return outcomes, cleanly separated: a batch boundary (`status="partial"` + `next_cursor` at the last COMPLETED allocator — never mid-allocator, since the budget check runs strictly between allocators); the set exhausted (cursor wraps to the empty-string marker, existing `ok`/`degraded`/`total_failure` discriminator untouched, `partial` never enters it); a mid-run kill-switch flip (returns the kill-switch status, cursor left completely unwritten so the next tick re-attempts the same slice).
- `docs/runbooks/match-engine.md`: `partial` and `kill_switch_unavailable` added to the only documented status vocabulary, plus a troubleshooting subsection distinguishing normal batching progress (advancing cursor) from a genuine stall (stuck cursor or `partial` persisting a full day).
- A contract test (`TestRunbookStatusVocabulary`) AST-derives `cron_recompute`'s actual status vocabulary from its own source plus the `KILL_SWITCH_*` module constants — never a hand-typed list — and asserts every value is documented, with an anti-vacuity character floor and a calibration case proving the check can fail.
