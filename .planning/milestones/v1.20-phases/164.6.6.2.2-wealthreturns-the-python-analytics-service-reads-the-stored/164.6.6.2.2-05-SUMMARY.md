## Behaviour changes (intended)

1. A published strategy whose stored curve LEVELS track the target's returns but whose derived daily returns do not is no longer reported as a match (verify_strategy and the process-key duplicate matcher). Measured on the fixture: levels correlate with the target at > 0.999, the derived returns at about 0.71.
2. The parser behind the portfolio reads now sorts and dedupes (last record on a date wins); the removed router copy did neither. Retargeted tests carry a comment naming this change; none of the old tests in `test_portfolio_router_audit_2026_05_07.py` pinned "does not dedupe", so nothing flipped, and a new test pins sort + dedupe keep-last.
3. A malformed record with a non-finite value is dropped by the shared parser, where the old copy dropped only `None`.

## Hand-computed pins

- Curve fixtures read back as: USD `[0.0, 0.02, 0.01, 0.03]` -> daily returns 0.02, 0.01, 0.03 on 2026-02-03..05; candidate `[0.0, -0.01, 0.04, 0.02]` -> -0.01, 0.04, 0.02.
- BTC leg, closes +10% a day: native readable 0.10, 0.10, 0.04; the converter drops the first readable day (no prior priced value), so d2 = 1.10 * 1.10 - 1 = 0.21 and d3 = 1.04 * 1.10 - 1 = 0.144 (raw read would be 0.10).
- Trim: cap 40 over a 60-day curve -> 39 rows (day 0 of the trimmed 40 levels dropped), first row dated `idx[21]`, last `idx[59]`; cap 40 over a 60-record `daily_returns` -> 40 rows from `idx[20]`.
- Levels-track-target negative: levels `1 + t_k`, derived `(t_k - t_{k-1}) / (1 + t_{k-1})`, correlation with an independent-noise target about 1/sqrt(2) = 0.707, asserted `< 0.95` as a precondition.
