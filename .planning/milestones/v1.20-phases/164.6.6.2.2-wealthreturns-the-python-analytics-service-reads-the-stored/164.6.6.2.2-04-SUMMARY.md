# Phase 164.6.6.2.2 Plan 04: Portfolio analytics on real columns, boundary-derived returns, allocation AUM Summary

`_compute_portfolio_analytics` now selects only columns `strategy_analytics` has, blends each strategy's daily returns read through `daily_returns_from_row` (then the BTC to USD converter), derives every TWR over the same days 1..n, and reports `total_aum` as the sum of `portfolio_strategies.allocated_amount`; a schema-parsed strict fake means a select naming a missing column can no longer hide behind canned rows.

## What changed in `_compute_portfolio_analytics`

- Select: `strategy_analytics` -> `strategy_id, returns_series, daily_returns, data_quality_flags` (the old select named `equity_curve` and `total_aum`, neither exists); `portfolio_strategies` -> adds `allocated_amount`.
- Per strategy: `daily_returns_from_row(row, name=sid)`, then `UsdSeriesConverter.convert`, then the weighted blend. The `equity_curve` branch and the native-only equity rebuild are gone; every strategy's TWR equity is `equity_from_daily_returns(<its blend series>)`.
- `portfolio_twr` = `total_return_from_equity(equity_from_daily_returns(portfolio_returns_series))` (was `(1 + p).cumprod()`, which dropped the first blended day).
- `btc_twr` = same construction over `b_aligned` (was `(1 + b).cumprod()`).
- `total_aum` = sum of `allocated_amount` over every `portfolio_strategies` row, None if any is null, 0 counts, filled before the analytics loop so an allocation without an analytics row (or without usable returns) still counts.
- `missing_equity_sids`: key kept, always `[]` from this producer (comment explains); `partial_data` and the narrative payload wiring unchanged.
- `usd_equity_from_converted_returns` removed (grep over `analytics-service/`, `src/`, `scripts/`: no other caller). Its docstring carried the stale "stored equity_curve" sentence, so that went with it.

## Behaviour changes (intended, for the orchestrator)

1. The displayed `total_return_twr` (portfolio) and `benchmark_comparison.benchmark_twr` now INCLUDE the first day. This is a deliberate departure from the Phase-114 day-0-exclusion convention described in `total_return_from_equity`'s docstring; that convention applies to stored equity curves and the function is left unchanged.
2. `total_aum` changed source (analytics `total_aum` did not exist; PROD has 0 `portfolio_strategies` rows, so nothing stored changes meaning).
3. The persisted `portfolio_equity_curve` (`cumulative = (1 + portfolio_returns_series).cumprod()`) is a charted curve, not a TWR, and is deliberately unchanged.

## Findings for the orchestrator (recorded, not fixed here)

- `portfolio_twr` spans EVERY blended day, while `benchmark_twr` spans only the benchmark-aligned days (`aligned`/`b_aligned`). Both now include their first day, but the two windows still differ in date RANGE whenever the benchmark lacks a portfolio date. `BenchmarkComparison.tsx` shows them as a delta.
- A BTC-native leg loses its first TWO stored days: stored day 0 (no predecessor, at the boundary) and the first readable day (the converter has no prior priced value, RESEARCH Pitfall 7). In the blend that day is absent for the leg and `fillna(0)` reads it as flat. This is existing converter behaviour surfaced by the boundary, not introduced here; it is why the BTC blend literals below use four stored days.
- `routers/portfolio.py::_records_to_series` is still used by the optimizer, bridge, verify-strategy and the simulator-adjacent paths (lines for `portfolio_optimizer`, `portfolio_bridge`, `verify_strategy`); those are plan 05. `_recs` (return-shaped) in `test_portfolio_router_logic.py` was kept for exactly those fixtures.
- Pre-commit guard note: the generic step-0 allow-list wants an `agent-*` branch name; this worktree branch is `wt/164.6.6.2.2-p04`, so I used the orchestrator's pin script (exit 0 before every commit) plus a protected-branch check instead of the namespace regex.
