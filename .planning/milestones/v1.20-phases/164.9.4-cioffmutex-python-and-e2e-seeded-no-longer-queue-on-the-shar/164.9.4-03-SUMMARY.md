# Phase 164.9.4 Plan 03: `run.sh --assert-local-handoff` reuses the lane's loopback guards (D-04) Summary

`scripts/local-stack/run.sh --assert-local-handoff [FILE]` reads a lane handoff (default: the lane's own `.stack-env`). It passes `API_URL` through the lane's existing `assert_local` and `DB_URL` through the WR-08 `capability-probe.mjs --refuse-nonlocal-dsn` call, byte-identical to the one `load_baseline` makes. It exits 0 only when both are loopback, and it never prints a URL, DSN or key. Plans 07 and 08 can now assert D-04 as the first command of each job's lane-handoff step without adding a guard.

## What the seam does

- `assert_local_handoff` sits next to `write_env_handoff`. It takes the handoff path and reads `API_URL` and `DB_URL` with the same `sed -n … | head -1` idiom `write_env_handoff` uses.
- A missing or unreadable file, or a missing line, prints a `FATAL` that names the path only, then exits 1.
- `API_URL` goes to `assert_local "$api_url"`, the lane's one API guard. No new glob and no copied `case`.
- `DB_URL` goes to `LOOPBACK_DSN="$db_url" node "${LANE_DIR}/capability-probe.mjs" --refuse-nonlocal-dsn >/dev/null`. That line is byte-identical across all three callers: `sort | uniq -c` of the probe line counts `3`.
- On success it logs exactly `handoff is loopback (API_URL and DB_URL), values not printed`.
- The dispatcher arm `--assert-local-handoff) shift; assert_local_handoff "${1:-$ENV_FILE}" ;;` carries a comment in the style of `--check-currency`'s that gives the reason (reuse, D-04) and the callers (the `python` and `e2e-seeded` lane-handoff steps).
- The INVOCATIONS block lists `scripts/local-stack/run.sh --assert-local-handoff [FILE]` under "Diagnostic / assertion seams". `bash scripts/local-stack/run.sh | grep -c -- '--assert-local-handoff'` prints `1`.
