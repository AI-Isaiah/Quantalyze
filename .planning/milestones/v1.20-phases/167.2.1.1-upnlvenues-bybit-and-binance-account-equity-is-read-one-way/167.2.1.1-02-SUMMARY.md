## Ruling on ROADMAP evidence (2)

The founder-booked evidence, quoted verbatim from the plan's must_haves: "Binance: the derive sets uPnL 0 (`exchange.py` ~3133) but the reconstruct anchor adds position uPnL on top (`equity_reconstruction.py` ~3093-3101)".

**Ruling: the observation is accurate; the inference that it is a double count is not.** The derive anchor is the spot wallet, which embeds no uPnL, so its wedge is structurally 0.0 and `terminal_nav = anchor - wedge` is exact. The reconstruct anchor is the mark-to-market level of a replay that marks open perps daily, so it must add the position uPnL exactly once. Neither counts uPnL twice on the spot wallet the repo reads. The executable form of this ruling is `test_cross_path_binance_reconstruct_equals_derive_plus_upnl_equals_holdings` (R == D + U == H == O) and `test_binance_tripwire_repo_reads_the_spot_wallet_only`, which marks the one configuration (a futures-type read, whose `total` already carries uPnL) where it would become a double count.

ROADMAP.md was not edited by this plan, so the orchestrator surfaces this ruling to the founder. No executor unified the two bases.
