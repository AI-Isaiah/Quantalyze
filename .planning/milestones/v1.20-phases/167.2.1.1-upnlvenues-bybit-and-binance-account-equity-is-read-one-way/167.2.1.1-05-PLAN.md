<objective>
Make the forced recompute unable to re-bake the defect. A forced rebuild (plan 04) replaces a SOLE-key allocator's
stored curve in one atomic write, and D-02's recompute is that one-way step. Under plan 01's decision PD-B a failed
Bybit `fetch_positions()` anchors at the wallet figure with only a WARNING, which on a forced rebuild would rewrite
the curve with exactly the wallet-only anchor this phase removes, and nothing downstream could tell. Per the
orchestrator's guidance (2026-10-22) and the plan-checker's required property ("a curve that silently kept the
wallet-only anchor is never recorded as recomputed"), the forced path now REFUSES: it fails the job loudly and
writes nothing unless the curve is anchored to today's venue equity including the open uPnL. The unforced path is
unchanged.

Purpose: D-02 ("re-run the derive and the reconstruct for every Bybit-backed strategy and allocator") and SC-3
("recomputed or recorded"): a forced job now either recomputes correctly or fails with a named reason the
handoff (plan 06) records.
Output: the refusal in `services/equity_reconstruction.py`; tests appended to `tests/test_reconstruct_force_rebuild.py`.
</objective>

Measured by the planner at the phase base (2026-10-22; cite by symbol, never by line):
- The anchor is fetched inside `_fetch_and_price_window` (`anchor, anchor_partial_symbols = await
  _fetch_current_equity(exchange, venue)`), after the replay and BEFORE anything is persisted. The handler awaits
  that crawl under `asyncio.wait_for(..., timeout=_RECONSTRUCT_CRAWL_TIMEOUT_S)` inside a try whose arms are, in
  order, `ccxt.RateLimitExceeded`, `asyncio.TimeoutError` and a generic `except Exception` that emits
  `reconstruct_failed` and returns FAILED; its `finally` closes the exchange. Every FAILED return there happens
  before the persist half and before the marker writer, so a refusal raised in the crawl writes nothing.
- `_fetch_current_equity` wraps everything after the OKX branch in one try whose blanket `except Exception`
  returns `(None, set())`; a refusal raised inside it would be swallowed into anchor None unless a dedicated
  `except ForcedRebuildRefusedError: raise` precedes the blanket arm.
- The anchor block applies the offset only in its final `else` branch; the skip branches set
  `_anchor_skipped_partial_ticker`, `_anchor_skipped_unreliable_replay`, `_anchor_skipped_implausible`, and the
  terminus branch only logs (`hit_terminus` is the signal). With `anchor is None` the block is not entered and no
  telemetry flag is set, so an anchor that could not be read is INVISIBLE in the completion audit today.
- Fixed-signature fakes exist and must keep working: tests/test_ana_recon_audit.py `fake_anchor(exchange, venue)`
  and `fake_fetch_and_price(exchange, venue, start_ms, now_ms, supabase=None, strategy_id=None)`;
  tests/test_job_worker_flipretry.py patches `_fetch_and_price_window` with an AsyncMock; tests/test_equity_reconstruction.py
  installs a `_landmine` for it. Passing a new keyword on the unforced path would break the first two with a
  TypeError, so the keyword is passed ONLY when forced.
- `ErrorKind` is `Literal["transient", "permanent", "unknown"]` (services/job_worker.py); "permanent" ends the
  job `failed_final` with no automatic re-claim.

Planner decisions:
- PD-H (forced path: anchored or nothing). A forced rebuild exists to re-anchor a stored curve, and on a SOLE-key
  allocator it replaces that curve atomically. It therefore writes only a curve anchored to today's venue equity
  including open-position uPnL; any other outcome fails the job and leaves the stored curve as it was. Covered:
  positions read failed or non-list on an additive venue (not in `_UNIFIED_MARGIN_VENUES`), anchor None, and each
  existing anchor skip. Not covered by design: the mt5 branch (it reads the full deal ledger and has no anchor) and
  an empty replay (no rows: the existing empty-replace refusal already writes nothing). Recorded consequence: a
  forced rebuild of an account whose replay is deterministically unanchorable (for example OKX past its 90-day
  terminus) always refuses; this phase forces Bybit keys only, and a future need to force such an account needs
  its own explicit decision.
- PD-I (no auto-retry). Every refusal returns error_kind "permanent": a transient retry would re-crawl up to
  `BACKFILL_CAP_DAYS` of venue history per attempt with no human looking. Plan 06's handoff re-enqueues once for the
  venue-read reasons (positions_unreadable, anchor_unreadable, anchor_skipped_partial_ticker) and records the rest.
- PD-J (default byte-identical in arguments). The new keywords are keyword-only with default False and are passed
  only on the forced branch, so the unforced call shape is exactly today's.
- PD-B (plan 01) is unchanged for the unforced path; TODOS [167.2.1.1-ANCHOR-POSITIONS-READ-FAILURE] (plan 06)
  records both halves.
