# Phase 167.2.1.1 Plan 01: Bybit total is the wallet balance, and the reconstruct anchor now adds the open uPnL

**The Bybit reconstruct anchor no longer drops the open-position uPnL: ccxt's real `bybit.parse_balance` sets `total` from the coin `walletBalance`, and `_UNIFIED_MARGIN_VENUES` now holds `okx` only, with all three Bybit paths pinned to that one reading by tests that feed ccxt's real parser.**

## Performance

- **Duration:** about 25 min
- **Completed:** 2026-10-22
- **Tasks:** 3
- **Files modified:** 3 (1 created, 2 modified)

## Accomplishments

- SC-1: a UNIFIED and a CONTRACT payload through ccxt's REAL `parse_balance` (no network) give `total['USDT']` equal to the coin `walletBalance` (1000) and not the coin `equity` (1250.5). Every failure message carries `ccxt.__version__`.
- SC-2: the reconstruct anchor `_fetch_current_equity(exchange, "bybit")` now returns 1250.5 (wallet 1000 + position uPnL 250.5). The derive anchor still returns `(1000.0, False, 0.0, False)` and the holdings poll still writes a USDT spot row of 1000 plus a derivative row with `unrealized_pnl_usd` 250.5.
- One test (`test_cross_path_bybit_reconstruct_equals_derive_plus_upnl_equals_holdings`) asserts reconstruct == derive + open uPnL == holdings spot value + derivative uPnL == the payload's coin `equity`, and that the wedge stays 0.0.
- The positions-failure WARNING now names the venue and exception class and logs `scrub_freeform_string(str(exc))` instead of the raw message. The test proves a `signature=deadbeef` in the ccxt error text never reaches the log; at the plan base that raw text did.
- Pin guard: `requirements.txt`'s `ccxt==` line must equal `CCXT_PIN_READ = "4.5.88"`, so a pin bump goes RED until the semantics are re-read.
