### Informational (recorded, not counted)

- **Plain-`complete` retry gap (WR-01), T-05 family.** On `failed_retry`, the SQL bridge rewrites a plain `complete` row to `computing`, so the transient retry protects only `complete_with_warnings` or warned rows. When the gap bites, the result is a loud failure, never a silent one. It is routed to Phase 164.5.2 and documented above `MarkerLiveState` and in runbook items 2 and 4.
- **`_read_existing_failed_row` reads through bare `db_execute`.** If it raises, nothing is written and the exception reaches `dispatch`. Nothing is suppressed and no protection is granted.
- **Sentry volume.** A failed re-read emits up to 3 events per attempt, so at most 9 per job. The runbook's alert-volume bullet records this. It is not a disclosure issue.
- **01-SUMMARY has no `## Threat Flags` section.** The section is missing rather than declared "None". 02 and 03 declare "None".

### Surfaces re-audited (all under T-164.6.7-03 unless noted)

1. **`_read_failure_text`: closed.** It scrubs with `scrub_freeform_string` first and only then cuts to 120 characters, prefixed by the exception class name. The auditor swept every added line that turns an exception into text. Each one goes through this helper: `_refresh_marker_live_state` (both arms), `_stamp_io` (both error arms and the `StampIOUnavailable` text), the entry publish-state read (both arms and the `RefreshMarkerRereadUnavailable` text), the heal-delete ERROR line, and the chain edge. The only raw `str(exc)` among the added lines is the one inside the helper. The removed code logged raw exception text at three sites, so this is a net improvement.
2. **Sentry tags: closed.** `_capture_read_failure` and the capture in `_flags_object_or_dropped` each set one scoped tag, `compute_job_id`, which is an internal id. The `capture_message` text carries only the site and a type name. `init_sentry` still sets `send_default_pii=False`, `include_local_variables=False` and `before_send=_redact_before_send`.
3. **Malformed-flags drop (`_flags_object_or_dropped`): residual R-1 is open, low and non-blocking.** The scrub runs before the 120-character cut, so the cut cannot expose an unscrubbed fragment. But `scrub_freeform_string`'s key/value pattern requires the separator right after the key. In a Python `repr` or a JSON string the key is quoted before the colon, so a credential-keyed value inside a list or string repr passes unredacted. The orchestrator reproduced this with a fake value: a list holding a dict with a quoted key came back unredacted, and the `key=value` form was redacted. **Why it is low:** the helper logs only when the value is not a dict and not None. The column is written by our own service and holds flag names. The sink is the operator log and an ERROR breadcrumb, and the Sentry message itself carries only the type name. The limitation is not new to this phase. It applies wherever `scrub_freeform_string` sees a dict-shaped repr, including PostgREST error text. **Suggested fix, outside this phase's files:** allow an optional closing quote after the key in `services/redact.py`, or have this helper log only the type and length.
4. **Heal's cause line: closed.** The heal-delete ERROR line appends the stamp's `cause`. Its only source is `_cause`, which is the scrubbed message plus the scrubbed detail. The heal's own exception goes through `_read_failure_text`.
5. **No new network path: closed.** The new imports are `collections.abc` (`Awaitable`, `Callable`), `typing.TypeVar` and a local `services.redact` import. Every added database call goes through the existing `db_execute` / `db_read_with_retry` helpers. The diff adds no HTTP client, venue call, subprocess, socket, RPC or enqueue.

The register rows still hold at HEAD. T-05's transient mapping now covers `StampIOUnavailable` through the common parent `HandlerIOUnavailable`. T-08: the worktree was clean, with no tracked backup files. T-09: runbook items 6 and 7 are still BLOCKING. T-10: the lines added to the runbook and TODOS.md contain 0 uuid shapes and 0 home paths.
