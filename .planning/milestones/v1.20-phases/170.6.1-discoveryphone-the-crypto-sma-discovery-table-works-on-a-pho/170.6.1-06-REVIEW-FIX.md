### Share-link feedback: a successful "Get private link" mint could end with no message and no URL

**Files modified:** `src/components/strategy/ShareableLink.tsx`, `src/components/strategy/ShareableLink.test.tsx`
**Commit:** `ddcd0bfe4`
**Defect (read from the code, then pinned RED):** after the mint created a live capability URL, the only feedback was the 2-second clipboard flash. A `writeText` that rejected fell to `execCommand`, and when that failed the button said "Copy failed — copy the URL manually" about a URL shown nowhere. A `writeText` that never settled (an unanswered permission prompt) left the UI silent: the button returned to its idle label and no message appeared. The Private link dialog is no help, since it prints no URL (its own Copy button re-mints and copies).
**Applied fix:**
- The clipboard wait is bounded to 3 s (`CLIPBOARD_WAIT_MS`) with `Promise.race`, and a timeout is treated as a rejection, so the synchronous `execCommand` fallback still runs.
- When neither path copies on the unpublished lane, the existing Private link dialog opens with the minted URL in the existing `Input` primitive: read-only, labelled "Private link URL", focused and fully selected, with a sentence saying the link is live and the browser would not copy it.
- The URL is kept in component state so "Manage private link" shows it again, and it is cleared when the link is revoked, so a later clean mint cannot resurrect a dead URL.
- A clean copy is unchanged: the flash and no dialog. The published lane gets only the bounded wait; its message is unchanged and it still shows no URL (its URL is the public id URL; there is no owner dialog for a published strategy). That is a known limit, recorded, not fixed.

**Tests (all hand-typed):** clipboard rejected and fallback failed (dialog, URL, read-only, focus, full selection, the row message); clipboard never settling (fake timers: nothing shown at 500 ms, no premature "Link copied!", the URL after the bound); a hang rescued by the fallback (flash, no dialog); clean copy (no dialog); failed mint (no dialog); the manage and revoke lifecycle (URL reachable through Manage, gone after revoke, not resurrected by a later clean mint). RED before the change: 4 of the 6 failed (the other two were the controls that pass either way). GREEN after, three consecutive runs. Each new mechanism was neutered once: bare `writeText` instead of the bounded call turned 3 tests RED; removing the clear-on-revoke turned the lifecycle test RED (`6050 ms`, timing out on the stale URL).
**Earlier tests kept green:** the v0.131.5.3 tests that `await waitFor` the Modal's native close are untouched and pass. One existing test changed: "keeps the sm classes when the copy fails" used `getByRole("button")` for the row button, which now finds two buttons because the dialog opens beside it, so it names the row button (`findByRole("button", { name: /Copy failed.../ })`). It asserts the same classes.
