## How the Task 1 verify command was adjusted, and why

The plan's `<verify>` opens:

```
test "$(grep -c 'GATED ON WIZFORM-02 CLOSING' TODOS.md)" = "0" \
  && grep -c 'GATE OPEN 2026-09-06' TODOS.md | grep -qx 1 && …
```

It asserts the marker is **gone** and a `GATE OPEN` note is **present**. Under
the founder decision, both of those are the wrong outcome. Forcing the marker
down to make the command exit 0 would be shipping a false attestation to satisfy
a shell command — precisely what the plan's own `<fails_when>` calls the honest
failure.

**The original command was run anyway, and it failed, as it should:**

```
ORIGINAL_VERIFY_EXIT=1  (whole-file 'GATED ON WIZFORM-02 CLOSING' count = 4)
```

(The whole-file count is 4, not 1: the marker plus three prose references,
including the two this plan added. The plan's `<fails_when>` predicted exactly
this whole-file-count weakness.)

**The adjustment — the two marker conjuncts INVERTED, the deciding precondition
added as a third, the three bookings unchanged:**

```bash
test "$(grep -c 'GATED ON WIZFORM-02 CLOSING. Do not pick this up before that gate opens' TODOS.md)" = "1" \
  && test "$(grep -c 'GATE OPEN 2026-09-06' TODOS.md)" = "0" \
  && test "$(grep -c '^## Surfaces not rendered' "$S")" = "1" \
  && grep -q '164.5-BASELINE-PROVENANCE-COLS' TODOS.md \
  && grep -q '164.2-TYPES-REGEN-CHECK' TODOS.md \
  && grep -q '164.2-TEST-APPLY-PROVENANCE' TODOS.md
```

Output:

```
marker sentence count      = 1
GATE OPEN 2026-09-06 count = 0
Surfaces-not-rendered      = 1
roster-render skip count   = 0
ADJUSTED_VERIFY_EXIT=0
```

Two properties of the adjustment worth stating, because a loosened gate is worse
than a failing one:

1. It is **stricter**, not looser, in the dimension that matters. The original
   counted the marker phrase across the whole file (which its own `<fails_when>`
   flags as trippable by any prose mention). The adjusted version pins the
   marker's **own sentence** — `GATED ON WIZFORM-02 CLOSING. Do not pick this up
   before that gate opens` — at exactly 1. Prose references cannot satisfy it and
   cannot break it.
2. It asserts the **reason**, not just the effect. The third conjunct re-checks
   the precondition that produced the decision, so if a future author deletes
   `## Surfaces not rendered` from plan 09's SUMMARY without doing the wiring,
   this command goes red rather than silently continuing to bless a marker that
   no longer has a justification.

## WR-01 — why option (b), with a measurement the review did not have

The review offered two options and called (a) — apply the 161.1 F1 remedy, return `FAILED`/`permanent` so the bridge takes a branch that consults the markers — the root-cause fix. **Measured, F1's safety property does not transfer to this handler, and the review's fix note does not say so.**

F1 is applied at a `derive_broker_dailies` job. That kind is IN the bridge's `is_protected` predicate, whose kind list is exactly `derive_broker_dailies`, `compute_analytics_from_csv`, `stitch_composite` (`supabase/schema/functions/sync_strategy_analytics_status.sql:258-263`). So on a MARKED recurring refresh over a still-healthy published row, F1's FAILED lands on branch **(b-prime)**, which preserves the publish state and records the error.

`sync_trades` is not in that list and can never be protected. The same edit here always lands on the LOUD branch **(b)**: `computation_status = 'failed'` over whatever was published. The consequences are asymmetric and correlated —

* a transient `enqueue_compute_job` hiccup on a routine cron sync would unpublish a live funded factsheet until the next tick's `done` supersedes the `failed_final`;
* a SYSTEMATIC enqueue fault (a bad kind, an RLS change) fires on every strategy, so every live factsheet on the platform goes dark within one cron tick.

Today's behaviour in that same systematic case is over-optimistic, not dark. Trading a false-fresh `complete` for a platform-wide blackout is not a fix a review pass should ship without the founder, and the correct version — scope the FAILED return to the case with nothing published to lose — is a behaviour decision with its own design. It is booked in `TODOS.md` as `[SYNCTRADES-ENQUEUE-DONE]` with the measurement above.

So: **(b)**. The stamp is removed, the writer's comment now carries the branch-(c) trace instead of a claimed protection, and every overclaim is corrected in place —

* `164.2-08-SUMMARY.md` — the `provides` line ("10 of 11"), the census floors line ("10/1/2"), the P1 row of "The eleven writers, as measured", and a dated `## ⚠️ CORRECTION` section carrying the full trace. T-164.2-17's "mitigate" is corrected in the same section (see WR-02).
* the census docstring — a new paragraph stating that a green there does NOT mean these sentences survive, only that each carries a well-formed pair; whether a marker is READ is a property of `main_worker`'s outcome mapping. **P1 is the site where those two came apart, and that sentence is the finding's real lesson.**

**The review under-costed (b).** It reads "reclassify P1 out of `EXPECTED_STAMPED_SITES` (10 → 9)". A decrement alone reddens: Rule A is TOTAL over sentence-writing literals, so an unstamped P1 lands in its defect list. (b) therefore required a third classified class — INERT — carved out by exact key set **and** file, with its own hand-typed `EXPECTED_INERT_SITES = 1`. It is self-expiring in the direction that matters: re-stamping P1 takes that count to 0 and reddens, so the carve-out cannot outlive its cause.
