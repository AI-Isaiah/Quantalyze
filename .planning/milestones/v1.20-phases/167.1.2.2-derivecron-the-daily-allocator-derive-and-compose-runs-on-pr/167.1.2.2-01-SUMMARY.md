## Notes for plan 02 (found while writing the forms)

- In key-mode, a derive with fewer than two interpretable days ends `done` (`run_derive_broker_dailies_job` takes the key-mode insufficient-history branch, runs the compose epilogue and returns DONE), so E1 failures appear as `failed_final` only for strategy-mode-style text. The SQL classes in `final-readings` are a first pass over `last_error`; the rule is the closed list, applied after reading `final-detail`.
- `reset_stalled_compute_jobs` sets `last_error = 'worker_stalled'` and clears `claimed_at`, but does not touch `reclaim_count` there; `mark_compute_job_done` does not clear `last_error`. So a reclaimed-then-done row still shows `worker_stalled`, and `reclaimed` counts either marker. The reset TIME is not stored on the row: it comes from the backfill logs.
- On a row that later succeeded, `last_error` still names a crawl-bound or login-mismatch attempt only if no later attempt overwrote it, so the backfill logs are the second source (stated in the runbook).
- Pipe-through caution: stderr carries a "Using workdir ..." line with a home path when output is merged (`2>&1`); never paste CLI output into tracked files.
