# 170.6 DISPLAYPOLISH - silent-failure review

Scope: `git diff origin/main...HEAD -- . ':!.planning'` (110 files) in worktree `quantalyze-170.6`, branch `feat/170.6-displaypolish`. MEDIUM and above only.

## What held up (no finding)

- `display-sign.ts` fails closed. `roundForDisplay` returns null for null, undefined, NaN and Infinity. `formatFixedSigned` then prints "—", and `signTone`, `percentTone`, `ratioTone` and `drawdownTone` return `undefined`. A non-finite input never gets a confident number or a tone.
- Every `metricColor` caller (11 files) now passes a `unit`, and its tone `dp` matches the printed `dp` (2 on both sides). A NaN input used to fall to "text-negative" and is now muted.
- The paired-floor sentence change (D-08) leaves the old sentence unchanged when `comparatorThrough` is null.
- The comparator overlap computation has no try/catch and swallows nothing. A malformed date gives `Date.parse` NaN, `NaN >= 90` is false, and the five fields become NaN. It fails closed, not open.
- The new tests I read hand-type their expected strings. The 5-day SPX fixture and the 89/90-day boundary tests can fail on a regression.

## Findings

### 1. MEDIUM, confidence 6: withheld comparator Sharpe, Sortino, Calmar, CAGR and volatility print a bare "—" with no stated reason

Location: `src/lib/factsheet/comparator-block.ts:112-135` (`summaryOf`, `annualizes`), read at `src/app/factsheet/[id]/v2/MetricsColumn.tsx:331-335` (`bench={ratio(hb?.sharpe)}` and the rows around it).

The withheld values are computable. The founder chose to suppress them (D-07), and "—" is the sanctioned form. But the rail gives no cue. `COMPARATOR_ANNUALIZATION_FLOOR_DAYS` is imported by no reader; only `comparator-block.ts` uses it (grep over `src`). The code comment says "every reader imports it" and that is not true. The neighbouring joint figures get a `pairedFloorReason` sentence. The rail's SPX or BTC column gets nothing.

Failure scenario: a strategy with 400 days of history is compared with an SPX series that has 60 days of overlap. The rail shows SPX Cumulative Return, Max DD and Win Rate, then "—" for CAGR, Sharpe, Sortino, Calmar and Ann. Volatility. The strategy beside it shows full figures. The reader cannot tell "SPX has no data" from "SPX is too short to annualize" from a bug. The same blank appears in a selected range under 90 days: the windowed view re-derives each comparator on the slice, so the SPX column goes dash while the strategy's own annualized figures stay.

Recommendation: add a one-line note under the Main Metrics bench column when a comparator is selected and `summary.sharpe` is NaN while `summary.cum_ret` is finite. For example: "SPX annualized figures need 90 days of overlap; this has N." Export a predicate from `comparator-block.ts` and call it in `MetricsColumn`. Alternatively state in CONTEXT that the bare dash is accepted.

### 2. MEDIUM, confidence 5: the payload cache key was not bumped although the comparator summary values changed

Location: `src/app/factsheet/[id]/v2/page.tsx:264` (`"factsheet-v2-payload-v17"`, `revalidate: 3600`); the value change is in `comparator-block.ts` `summaryOf`.

The file's own history bumps the key whenever a stored payload would show stale figures "for the 1 h TTL drain". This phase changes the values inside `comparators.*.summary` and `summarySince` without changing their shape. The key parts (`computedAt`, `tradesFetchedAt`, provenance, status) do not move at deploy.

Failure scenario: a v17 entry built before the deploy holds the 10.24 SPX Sharpe. It keeps serving that figure for up to one hour after the floor ships, while a fresh build serves "—". The founder's own verification of the fix on PROD can read the old number. The server-rendered rail, the OG card and the tearsheet can disagree during the drain.

Recommendation: bump to v18 with a dated comment in the established style, or record in the ship note that one hour of stale comparator figures is accepted.

### 3. MEDIUM, confidence 4: the allocations KPI strip "Max DD 12m" cell tones through the generic sign rule, so a positive value goes green (D-04 not applied here)

Location: `src/app/(dashboard)/allocations/components/KpiStrip.tsx:194-205` (`valueColorClass`) and `:522-526` (call site, `metricKey === "max_drawdown"` shares the generic path).

D-04 says Max drawdown is never green. The phase adds `drawdownTone` for this and uses it on the other max-DD surfaces. The KPI strip's max-DD cell still goes through `signTone`, whose `positive` branch returns "text-positive". `maxDdValue` comes from `analytics?.max_drawdown_12m ?? metrics?.max_drawdown`, and nothing normalises its sign.

Failure scenario: a scenario or analytics value arrives as a positive magnitude (a convention flip, or a bad write). The cell prints "+4.20%" in green on a "worst peak-to-trough" label. The single-source guard cannot catch this. R1-R3 and R7 look for raw comparisons with zero. R5 and R8 count constant red tones. A `signTone`-based green passes all of them.

Recommendation: in `valueColorClass`, accept a `kind` and use `drawdownTone` when `metricKey === "max_drawdown"`. Add one test with `max_drawdown_12m: 0.04` that asserts no `text-positive`.

## Below threshold (noted, not counted)

- `formatFixedSigned` checks finiteness on `v`, not on `v * scale`. A finite value near 1e307 with scale 100 would print "+Infinity%". It is unreachable with real data.
- Recharts tooltip formatters call `Number(v)`, so a null value prints "0.00%" instead of "—". The old code did the same. NaN and undefined now correctly print "—".

Verdict: 3 findings (MEDIUM and above)
