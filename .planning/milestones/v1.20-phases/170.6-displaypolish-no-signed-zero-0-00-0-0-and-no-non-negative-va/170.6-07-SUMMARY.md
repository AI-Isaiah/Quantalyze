## Deviations from Plan

**1. [Rule 3 - Blocking] Outcomes widget stops calling `utils.formatPercent` for its two figures.** The plan's behaviour list requires the average-realized KPI to render `0.0%` and the row cell to print no sign, but both strings came from `formatPercent`, which lives in `utils.ts` (plan 02's file, not in this plan's `files_modified`). In this worktree it still prints `-0.0%` / `+0.0%`, so the plan's own behaviour could not be met without either touching plan 02's file or calling display-sign directly. Chose the latter: a file-local `formatDeltaPercent` over `formatFixedSigned` (`dp 1, scale 100, "%", plus`). Non-zero output is identical (`+4.0%`, `-3.0%`, existing tests unchanged); non-finite stays `—`. The `formatPercent` import is gone from that file. After plan 02 merges nothing conflicts: that file no longer imports `formatPercent`.

**2. [Plan fallback, recorded as the plan asked] The composer delta summary has no render test.** Rendering `ScenarioComposer` to reach `deltaSummary` is not cheap, and it would not reach the changed line anyway: `ScenarioFooter` filters out every `muted` entry (`deltaSummary.filter((d) => d.tier !== "muted")`), and each of the three metrics' noise floor is 0.01, so any entry that renders has |delta| >= 0.01 and prints at least `0.01` (Sharpe) or `1.0%` (Max DD, TWR). A printed zero never reaches the footer today. The `pushDelta` edit is therefore defensive (the census row names it, O-7), its tier logic is untouched, and it is covered only by the 430 existing composer cases staying green plus the 6-line bound. If a noise floor is ever lowered below the printed precision, the guard becomes live and has no test; that is worth a case then.
