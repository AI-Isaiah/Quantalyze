### `analytics-service/services/mt5_deals.py` (new `deal_utc_instant_ms`)

**Analog:** `deal_utc_day`, same file. Copy its validation prologue verbatim, then return the instant instead of a date string:
```python
def deal_utc_day(time_value: Any, server_utc_offset_s: int) -> str:
    if isinstance(server_utc_offset_s, bool) or not isinstance(server_utc_offset_s, int):
        raise Mt5DealClassificationError(
            "MT5 server_utc_offset_s must be an int (seconds) — fail loud"
        )
    if isinstance(time_value, datetime):
        aware = (time_value if time_value.tzinfo is not None
                 else time_value.replace(tzinfo=timezone.utc))
        epoch = aware.timestamp()
    elif isinstance(time_value, bool) or not isinstance(time_value, (int, float)):
        raise Mt5DealClassificationError(
            f"MT5 deal time={time_value!r} is not a datable epoch/datetime — fail loud"
        )
    else:
        if not math.isfinite(time_value):
            raise Mt5DealClassificationError(
                "MT5 deal time is non-finite (NaN/Inf) — fail loud"
            )
        epoch = float(time_value)
    try:
        utc_epoch = epoch - server_utc_offset_s
        return datetime.fromtimestamp(utc_epoch, tz=timezone.utc).date().isoformat()
    except (OverflowError, OSError, ValueError) as exc:
        raise Mt5DealClassificationError(
            "MT5 deal time is out of the datable epoch range — fail loud"
        ) from exc
```
Rules (research "Reading the instant", D-08, D-09): use the SAME `server_utc_offset_s` argument, never a second offset (Pitfall 3, one fixed integer, DST limit is a Note not a defect); prefer `time_msc` (ms) when it is a finite non-bool int, else `time * 1000`; errors name the FIELD, never the value (the module's leak-safety convention, T-136-03). Note the existing `deal_utc_day` error text interpolates `time={time_value!r}` for a non-datable time; a timestamp is not an account amount, but keep the new helper's messages field-only. Order ties by `(utc_ms, kind_rank, ticket)` with flow rank 0, trading rank 1.

The `entry` code needs a constant table in this module in the style of `_MT5_TRADING_DEAL_TYPES` / `_MT5_EXTERNAL_FLOW_DEAL_TYPES` (frozenset of ints with an import-time disjointness `assert`, the `deribit_txn.py` precedent): `IN` / `OUT` / `INOUT` / `OUT_BY` codes. Research assumption A1 says IN=0, OUT=1, INOUT=2, OUT_BY=3 is UNPINNED (only the fixture value `entry: 1` for a closing deal is in-repo). Wave 0 must pin it from a live dump; until then label it `[ASSUMED]` exactly like the module header does for the unconfirmed DEAL_TYPE codes, and make an unknown `entry` code resolve to day-level, never to a default.

## Shared Patterns

### Fail-loud, never-substitute (applies to every new numeric path)
**Source:** `nav_twr._coerce_float`, `mt5_deals._coerce_money`, the `NavReconstructionError` / `Mt5DealClassificationError` split.
```python
    if not np.isfinite(result):
        raise NavReconstructionError(
            f"nav_twr non-finite {field}={value!r} (row={dict(row)!r})"

```
Rules: bool rejected; NaN/Inf rejected; error text names the FIELD and day-index, never a USD/BTC amount (T-73-02, T-136-02/03). `NavReconstructionError` and `Mt5DealClassificationError` are both `ValueError` subclasses so the worker dispositions them PERMANENT (the MT5 `try:` block in `run_derive_broker_dailies_job` already catches both with scrubbed stamps; a new raise inherits that for free).

### Annotation vs guard separation (flag lifecycle)
**Source:** `NAV_TWR_GUARD_KEYS` vs `NAV_TWR_ANNOTATION_KEYS`.
**Apply to:** `flow_timing_day_level` in `nav_twr`, `_prestamp_flags`, `analytics_runner`, TS readers. Membership in `NAV_TWR_GUARD_KEYS` is the single switch that promotes `computation_status` to `complete_with_warnings` (which the publish gate PASSES) and sets `computation_warned`; an informational key must stay outside it and travel on its own present-only carry. Every registry that promotes/lifts iterates the tuple, so removing `flow_dominated_guard` from it propagates by construction (that is why the tuple exists, "SHOULD-1").

### Additive keyword with a byte-identical default
**Source:** `chain_linked_twr(..., prev0: float | None = None, floors: UnitFloors = USD_FLOORS)`.
**Apply to:** `timing=`, `full_history=` on `chain_linked_twr`, `reconstruct_nav_and_twr`, `combine_mt5_deal_ledger`, `reconstruct_mt5_nav_levels`; `instant_ms` on `ExternalFlow`.
