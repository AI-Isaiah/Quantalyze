### test_allocator_equity_writer_basis.py: the re-pinned sha256

`test_a_stitched_account_without_the_fields_composes_as_today[all|key-A|key-B|key-M]`: `_FIELDLESS_STITCHED_SHA256` `f0b6dda4...` -> `4ab9c409...`.

Why the new value is right, not copied:
1. **The only input that changed is one return.** The fixture account (`_btc_book`) deposits 9 BTC on day 2 against ~4 BTC held. The writer used to drop that day (no return row, its P&L a `dropped_day_pnl` row); under D-05 it is measured and `dropped_day_pnl` keeps only the funding day.
2. **That is proven, not argued.** New test `test_the_fieldless_pin_moved_only_by_the_measured_deposit_day[all|key-A|key-B|key-M]` withdraws the day-2 return and restores its dropped row, runs the real compose, and reproduces the OLD sha `f0b6dda4...` byte for byte in all four shapes. The old constant is kept as `_FIELDLESS_STITCHED_SHA256_BEFORE_FLOWTIMING`.
3. **The new content is checked against an independent oracle.** The re-pinned test additionally asserts (a) the stored day-2 return equals `(NAV2 - NAV1 - F2) / NAV1` from the exact `Fraction` book and (b) every curve level except the live-anchor day equals the oracle NAV (measured worst relative error 8e-16), via `_assert_curve_is_the_oracle`. Then the sha pins the rest of the payload.
