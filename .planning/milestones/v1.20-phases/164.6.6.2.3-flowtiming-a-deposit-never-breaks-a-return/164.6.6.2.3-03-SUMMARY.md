# Phase 164.6.6.2.3 Plan 03: FLOWTIMING MT5 instant and DEAL_ENTRY seam Summary

`deal_utc_instant_ms` gives each MT5 deal a UTC epoch-millisecond instant that shares `deal_utc_day`'s offset and `time` parser, so the two cannot disagree. The DEAL_ENTRY codes are pinned from the vendor package, with `deal_entry_code` and `deal_position_id` resolvers for the fold in plan 05.

`commits:` counts the two code commits (measured from the ledger base to `plan_head_after`). The commit that adds this SUMMARY comes after `plan_head_after`.

## What changed

- `analytics-service/services/mt5_deals.py`
  - `deal_utc_day` was split into three private helpers, written once: `_require_offset_seconds`, `_server_epoch_seconds` (the `time` parse) and `_utc_day_of_server_epoch`. Its behaviour and messages are byte-identical; the existing `deal_utc_day` tests pass unchanged.
  - `deal_utc_instant_ms(deal, server_utc_offset_s)`:
    - It returns `time_msc - offset*1000` when `time_msc` is a non-bool int (or an integral finite float) in the same second as the deal's `time`.
    - Without `time_msc` it returns the deal's own `time` in milliseconds minus the offset. Fractional times use an exact floor, and the offset is never applied twice.
    - It returns `None` for a bool, fractional, non-finite or non-numeric `time_msc`, and for a `time_msc` in another second than `time` (D-07).
    - It never falls back to `time` after an anomalous `time_msc`, and never to midnight or noon.
    - The only raise is the shared `time` parse plus the shared out-of-range check, with the same class and message `deal_utc_day` gives. No derive that succeeds today can fail on the instant.
    - Final guard: the instant's UTC day, computed by exact integer arithmetic, must equal `deal_utc_day`'s day; otherwise `None`. This covers a float `time` of 86399.9999996, which `datetime.fromtimestamp` rounds onto the next day.
    - The docstring records the DST limit of the one fixed offset (Pitfall 3) as a known limit, not fixed here.
  - `MT5_DEAL_ENTRY_IN/OUT/INOUT/OUT_BY = 0/1/2/3` and `_MT5_KNOWN_DEAL_ENTRIES`, with a module-header entry marked VERIFIED that cites wheel 5.0.6231 and its sha256.
  - `deal_entry_code` returns `None` for an absent, bool, non-int or unknown code.
  - `deal_position_id` returns `None` for an absent, bool, non-int, zero or negative id.
  - Error text names fields and never values or amounts.
- `analytics-service/tests/test_mt5_deal_timing.py` (new, 55 tests).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan said the fallback instant is `int(round(epoch * 1000)) - offset*1000`**
- **Issue:** `round` can push a sub-millisecond-below-midnight float time onto the next UTC day while `deal_utc_day` keeps it on the previous one, so the instant would disagree with the day.
- **Fix:** exact floor via `Fraction` for fractional epochs (`int * 1000` for integral ones), plus the final day-agreement guard that answers `None` on any disagreement.
- **Files modified:** analytics-service/services/mt5_deals.py
- **Commit:** c27d128fb
