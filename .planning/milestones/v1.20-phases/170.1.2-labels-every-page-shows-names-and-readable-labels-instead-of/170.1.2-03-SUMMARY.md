# Phase 170.1.2 Plan 03: Admin user, intro and partner-pilot labels Summary

Four admin pages now show words and names where they showed raw roles, statuses, sources and id fragments, all through `src/lib/display-labels.ts` and the Badge status labels. No local label map was added.

## What changed

- **/admin/users/[id]**: "Profile role" via `profileRoleLabel` (manager reads "Asset Manager"), allocator and manager status via `profileStatusLabel`, the row "Legacy is_admin true/false" is now "Legacy admin flag" Yes/No, the badge reads "Legacy admin". The "User ID" row keeps the id (the field is the id). The `generateMetadata` export from TITLES is untouched.
- **/admin/users**: profile role cell via `profileRoleLabel`, app-role badges via `appRoleLabel` ("Quant manager"), badge "Legacy admin".
- **/admin/intros**: allocator fallback `row.allocator_id` became "Unknown allocator"; strategy and replacement fallbacks became "Unnamed strategy"; source via `introSourceLabel`, snapshot status via `introSnapshotStatusLabel`. The existing `uppercase` micro-label CSS on those two cells was left alone (DESIGN.md data-annotation voice); the underlying text is the label.
- **/admin/partner-pilot/[partner_tag]**: both allocator id slices (text and `title`) became "Unknown allocator". Strategy managers come from one new `profiles` read (`.select("id, display_name").in("id", managerIds)`, error checked) with "Unknown manager" on a miss; this replaces the lookup in the partner-tagged profile list, which missed any manager not tagged to the pilot. Status renders through `<Badge type="status">`, disclosure tier through `disclosureTierLabel`. The now-unused `MANAGER_ROLES` and `managers` were removed.
