## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] AllocationOverTime tooltip would have lost its USD figure**
- **Found during:** Task 2
- **Issue:** The tooltip formatter looked up the per-venue gross USD with `usdByAsofMs.get(asof)?.[String(name)]`, where `name` is the `<Area name>`. That map is keyed by the raw venue code. Setting `name` to the display label ("OKX") would make the lookup miss and render the dollar amount as missing for every venue (and collide for several unlisted venues all labelled "Other venue"). jsdom does not render recharts tooltips, so no existing test could catch it.
- **Fix:** the lookup now derives the raw code from the series `item.dataKey` (`v:<venue>`, sliced by `VENUE_KEY_PREFIX.length`). Legend and series `name` use `venueLabel`; dataKeys and the stack order are unchanged.
- **Files modified:** `src/app/(dashboard)/allocations/widgets/allocation/AllocationOverTime.tsx`
- **Commit:** `057572e9c`
- **Limit:** the tooltip itself is not exercisable under jsdom, so this lookup is verified by `tsc` and by reading, not by a test.

**2. [Scope note] Test file added beyond the plan's list**
- The plan lists no OpenPositionsTable test file; `OpenPositionsTable.all-columns.test.tsx` exists and renders the table directly, so the OKX case was added there instead of stating "no test file" (`ee47fab48`).

### Other

- The plan's `<behavior>` says to compute the display name "once per key"; the component calls `venueLabel(key.exchange)` at each site (a pure lookup, nine call sites) rather than adding a per-row variable, to keep the diff minimal. Output is identical.
- Behavior change to note: an empty venue string used to render "" in the two tables and now reads "Other venue"; `venue` is a required non-empty string on both row types.
- Existing pins re-pointed outside the Task 3 files: `HoldingFactsheet.test.tsx` `/binance/` to `/Binance/`; `AllocationOverTime.test.tsx` `getByText("binance")` to `"Binance"`.
