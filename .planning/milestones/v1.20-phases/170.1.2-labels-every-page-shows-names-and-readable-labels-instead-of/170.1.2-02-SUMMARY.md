# Phase 170.1.2 Plan 02: Compute jobs and CSV submissions labels Summary

Operators now read compute jobs and CSV submissions in words and names: "Trade sync", "Retrying", "Temporary error: boom", "Alpha" or "Unnamed strategy", "Metrics captured" and the trust-tier pill, with no raw column value and no id fragment on either surface.

## What changed

- `/admin/compute-jobs` (`page.tsx`): the jobs read moved from `compute_jobs` to the `compute_jobs_admin` view with an explicit column list that includes `strategy_name` and `portfolio_name` and omits the owner email and `claim_token`. The read's `error` is now checked: a failure logs `[admin/compute-jobs] jobs query failed` and throws to `error.tsx` instead of rendering an empty queue. Kind, Status (inside `StatusBadge`), Error and Exchange render through `computeJobKindLabel`, `computeJobStatusLabel`, `computeJobErrorKindLabel` and `venueLabel`. A null `error_kind` renders the bare excerpt, with no prefix and no colon. Target is the strategy name, else the portfolio name, else "Unnamed strategy" / "Unnamed portfolio", else a dash. The "Recent jobs" description is `{status label}: {count}` joined by commas. "Position metrics failed" reads "Analytics rows whose position metrics did not compute", and an unknown "Strategies missing fills" count reads a dash instead of "N/A".
- `ComputeJobsTable.tsx`: Status filter options are built through `computeJobStatusLabel` (`failed_retry` now reads "Retrying"); Kind filter options keep the raw `value` and use `computeJobKindLabel` for the label; the kind and status cells use the same helpers; the Target fallback chain no longer reaches the raw strategy and portfolio ids and feeds both the cell text and its `title`.
- `/admin/csv-status` (`page.tsx`): status through `verificationStatusLabel`, trust tier through `<TrustTierLabel>`, description "Track-record uploads from quant teams, most recent first." The doc comment no longer spells the filter text either, so `grep -ac "flow_type='csv'"` prints 0.
- The PageHeader titles and metadata exports were not touched (Phase 170.1.1).

### Choices inside the plan's wording

**1. [Rule 2 - missing critical functionality] jobs read now checks `error`**
- **Found during:** Task 1
- **Issue:** The old read used `jobsResult.data ?? []`, so a failed read (for example the view missing a column) would have read as "No compute jobs found." The plan says new Supabase reads check `error`.
- **Fix:** log with the query name and throw, the same idiom as `admin/page.tsx`. Pinned by a test.
- **Commit:** `30b9a9ba5`

**2. Target rule duplicated, not shared.** The page and the table each carry the name / Unnamed strategy / Unnamed portfolio / dash expression. A helper would have meant editing `display-labels.ts`, which other wave-2 plans import from and may touch, and the plan forbids new abstractions. If a third surface needs the rule, a helper becomes worth it.

**3. Security comment reworded.** The claim_token warning comment on the jobs read was kept, but the plan's acceptance check (`grep -ac 'user_email'` prints 0) forced the owner-email mention to be spelled without the column name.
