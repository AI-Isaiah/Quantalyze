  selected zero strategies) before the diff.
- A `SCOPE BOUNDARY` section naming the sibling site that is deliberately NOT touched

  excluded) and WHY, so a future reader does not "complete" the change.
- A `BLAST RADIUS` section enumerating what the widening turns on, downstream —
  directly mirrored by CONTEXT.md's own Area 3.

**Check 8 / Check 9+10 — the exact ask from the brief, verified line-by-line in the
DO block (`v_life_needle`, `v_draft_needle`, `v_arch_needle`):**
- **Check 8** (`position(v_life_needle IN v_def) = 0` — needle `'AND s.' || 'status IN ('`)
  pins the lifecycle conjunct's own **shape** (the column name + the `IN (` form),
  never the widened value set. Comment: "bound to a shape every form of the set
  preserves" — this is deliberately not a positive check on `'private'` because the
  gate file's own header (DISJOINTNESS section) explains why: the private-admits

  against exactly the naive move this phase's title tempts ("just copy the Python

- ⚠️ Note the header prose ("check 8 holds the shape... check 9 holds the two values")
  is a SIMPLIFICATION of the DO block's actual numbering — the two "never admit"
  values are really checks **9 and 10**, one value each, not one check holding both.

### 2. `analytics-service/tests/test_ledger_refresh_gates.py` — SQL gate shape (does NOT transfer wholesale)

- **Shape:** static/source-scan gates over `pg_get_functiondef`-extracted, regex-
  comment-stripped regions, each behind an anti-vacuity floor (`_assert_region`,
  `test_every_sentinel_lies_beyond_its_own_floor`) so a broken extraction can't make
  a positive AND a negative assertion agree by accident.
- **Gate `10c`** (`TestGate10CompositeArm::test_10c_composite_function_name_appears_in_exactly_the_named_migrations`,
  the twin of gate `3b`) asserts a function's name appears in **EXACTLY** the named
  set of migrations (`{original, *superseded, live}`) via `pathlib.Path.glob("*.sql")`
  + `path.read_text()` + `assert hits == expected` — an **exact-set**, not a count,
  specifically so a silent extra definition and a silent disappearance are both
  distinguishable failures. This is a reusable IDIOM (exact-set-over-a-scan,
  never a count) but the FILE itself guards SQL migrations that this phase does not
  touch — it transfers as a technique, not as a file to extend.
- **Which shape would transfer to `cron.py`:** the exact-set idiom is the right
  shape IF this phase adds a source-scan gate at all (e.g. "the string `'private'`
  appears in `ALLOWED_STRATEGY_STATUSES`'s own declaration and nowhere else" or an
  ordering-gate reading 164.5.1.4's resume-marker symbol). But the **stronger,
  already-established idiom in THIS repo for a Python constant is behavioural, not
  source-scan** — see Pattern 3/4 below, which is the one to prefer per this repo's
  own anti-vacuity rule (a name-presence check over source is satisfied by the name
  as a string literal; a behavioural drive is not).

### 3. `analytics-service/tests/test_cron_router.py::TestStrategyLifecycleFilter` — THE template

**This is the closest possible analog and should be copied near-verbatim in shape.**

```python
class TestStrategyLifecycleFilter:
    """C-0200: only sync into strategies whose status is one of
    {draft, pending_review, published}. Archived/suspended/deleted
    strategies must NOT receive a sync_trades RPC.
    """

    @pytest.mark.asyncio
    async def test_only_live_statuses_receive_sync_trades_rpc(self):
        """Behavioural: drive `cron_sync` end-to-end with a single key
        whose embedded strategies span every lifecycle status. Assert
        the resulting `sync_trades` RPC fan-out only fires for the
        three live statuses — the rest are silently dropped.

        Replaces the prior local-replay test that re-implemented the
        filter inline (a refactor that dropped the cron.py filter would
        have left that test green).
        """
```
(`analytics-service/tests/test_cron_router.py`, class `TestStrategyLifecycleFilter`)

- **Naming convention:** `TestStrategyLifecycleFilter` names the CONCERN, not a ticket
  number, but its class docstring cites the originating ticket (`C-0200`). Sibling
  classes in the same file (`TestC0198CursorOnlyAdvancesWhenStored`,
  `TestC0193ValidationCache`, `TestC0195AllocatorProtectedKeyNotDeactivated`,
  `TestC0197CronTriggersAnalyticsRecompute`) use a `TestC0NNN<Concern>` prefix when the
  work traces to a numbered legacy ticket; `TestStrategyLifecycleFilter` and
  `TestHeldStatusBucketForStalledKeys` (no numeric prefix) are the newer style,
  naming the concern only and citing the TODOS/phase id in the docstring instead.
  **Prefer the newer, no-numeric-prefix style** for this phase — it is more recently
  used (`TestHeldStatusBucketForStalledKeys` cites `FANOUT-COHORT-SYNC-CONSTANT-01`,
  the direct predecessor TODOS entry to this phase) and matches this repo's own rule
  to prefer the more recently established convention.
- **Assertion idiom — MEMBERSHIP, not just counts.** `test_only_live_statuses_receive_sync_trades_rpc`
  builds `mixed_strategies` spanning every real status
  (`published, draft, pending_review, archived, suspended, deleted`), drives
  `cron_mod.cron_sync()` end-to-end through the full mock-Supabase harness, and
  asserts:
  ```python
  rpc_strategy_ids = sorted(
      call.args[1]["p_strategy_id"]
      for call in mock_supabase.rpc.call_args_list
      if call.args and call.args[0] == "sync_trades"
  )
  assert rpc_strategy_ids == ["s-draft", "s-pub", "s-review"]
  result_strategy_ids = sorted(response["results"][0]["strategy_ids"])
  assert result_strategy_ids == ["s-draft", "s-pub", "s-review"]
  ```
  This is a **CONSEQUENCE gate**: it names which strategy IDs reached the RPC by ID,
  not merely how many. Adding a `private` strategy to `mixed_strategies` and asserting
  it now DOES (post-widening) or does NOT (pre-widening / on the ordering gate) appear
  in `rpc_strategy_ids` is the direct, minimal extension this phase needs.
- **`test_strategy_missing_status_field_is_dropped`** is the fail-closed sibling test —
  same class, same harness, asserts an entry with no `status` key at all is dropped,
  not admitted. Model: any edit to `ALLOWED_STRATEGY_STATUSES` should keep this
  fail-closed test passing unchanged (it is a good "did I break something adjacent"
  regression check, not something this phase needs to touch).
- ⚠️ **This class does NOT use `_make_key_row`.** It hand-builds the `keys_data` dict
  because it needs a `"strategies"` list of `{"id", "status"}` dicts embedded on the
  key row — `_make_key_row` (below) only accepts a flat `strategy_ids: list[str]`
  and cannot express per-strategy status. Any new test in this shape must hand-build
  the key dict the same way `TestStrategyLifecycleFilter` does, NOT reach for
  `_make_key_row`.

### 4. `_make_key_row` helper (`test_cron_router.py:94-133`) — for tests that do NOT need per-strategy status

```python
def _make_key_row(
    *,
    key_id: str = "key-1",
    exchange: str = "binance",
    strategy_ids: list[str] | None = None,
    last_sync_at: str | None = None,
    strategy_cursors: dict[str, str | None] | None = None,
) -> dict[str, Any]:
```
- Kwargs default conventions: `key_id="key-1"`, `exchange="binance"` are the
  house defaults nearly every call site in the file relies on; `strategy_ids`
  defaults to `None` and is coalesced to `[]` inside the body
  (`strategy_ids or []`), never passed as `[]` directly by callers who want the
  default. `strategy_cursors=None` **omits the key from the returned dict entirely**
  rather than writing `{}` — a documented three-state marker convention (key absent /
  strategy absent from mapping / strategy present with null) that any new call site
  touching the 164.5.1.4 cursor machinery must preserve.
- Use this helper only when the test does not need per-strategy status fan-out
  (e.g. a test about the `held` bucket, the cursor, or RPC failure isolation, where
  every strategy is already known to be admitted). For anything that varies
  status across strategies — which is what this phase's own tests will need — use
  `TestStrategyLifecycleFilter`'s hand-built `keys_data` shape instead (Pattern 3).

## Shared Patterns

### Constant-widening test discipline (this repo's answer to "not vacuous")
**Source:** `test_cron_router.py::TestStrategyLifecycleFilter` (behavioural, drives
`cron_sync()`) vs. `test_ledger_refresh_gates.py` (source-scan with anti-vacuity
floors, for SQL bodies that have no import path).
**Apply to:** any new/edited test in this phase.
**Rule, stated once so it isn't relitigated per test:** a test asserting
`"private" in ALLOWED_STRATEGY_STATUSES` directly is vacuous (nothing reads that
membership except the one line already in `cron.py`, which the test would be
restating). The calibrated shape in THIS codebase for a Python-side constant with
exactly one reader is **drive the reader** (`cron_sync()`) with fixture data that
exercises the boundary and assert on the RESULTING side effect (which strategy IDs
reached the `sync_trades` RPC / which bucket the response landed in) — never assert
on the constant's contents in isolation. `TestStrategyLifecycleFilter`'s own docstring
states this exact reasoning: it *"[r]eplaces the prior local-replay test that
re-implemented the filter inline (a refactor that dropped the cron.py filter would
have left that test green)"* — i.e. the prior, discarded test WAS the vacuous shape
this rule now forbids, and this repo has already made that mistake once and fixed it
at this exact call site.

### Two-value exclusion, stated by name, tied to the sibling constant
**Source:** `supabase/migrations/20260917120000_ledger_fanout_admit_private.sql`
checks 9 and 10, and their exception messages.
**Apply to:** any docstring/comment this phase writes justifying the widening's
boundary (admit `private` only, never `rejected`/`archived`).
**Excerpt (the reasoning to mirror, not the SQL mechanism):**
> "This phase's decision record admits the owner-only terminal status AND NOTHING
> ELSE; mirroring `ALLOWED_STRATEGY_STATUSES` (analytics-service/routers/cron.py)

The inverse direction applies here: this phase's own docstrings/comments should state,

and neither site's set is a template for the other's, by design (CONTEXT.md Area 1).

## Contradiction Surfaced

**Two analogs disagree on HOW to prove a lifecycle-set widening is not vacuous, and
this repo's own rule (surface, don't blend) requires picking one:**

- `test_ledger_refresh_gates.py` (SQL side, 2026-09-07 through 2026-09-17, most
  recently touched) proves it via **apply-time source-scan needles over
  `pg_get_functiondef`**, comment-stripped, anti-vacuity-floored — because a SQL
  function body has no import path and no test runner can call it without hitting
  real Postgres.
- `test_cron_router.py::TestStrategyLifecycleFilter` (Python side, same general
  vintage, actively exercised) proves the identical CLASS of change via **driving
  the actual function end-to-end and asserting on its output** — because the
  Python constant IS importable and callable in a plain pytest run.

**Pick the second (behavioural) for this phase, and flag the first for what it is —
not for cleanup, but for scope:** `ALLOWED_STRATEGY_STATUSES` lives in Python with a
single, directly-testable reader in the same process; none of the constraints that
forced the SQL file into apply-time text-probing (no import path, must not invoke
real Postgres at migration-apply time, mutation-runner lane concerns) apply here.
Porting the source-scan/DO-block idiom onto a Python constant would be reaching for
heavier, SQL-specific machinery to solve a problem this repo already solves more
simply and more strongly (a consequence gate beats a text-presence gate under this
repo's own stated anti-vacuity rule). The SQL file is not "wrong" — it is the right
tool for a body with no import path — it is simply the wrong analog to copy here.
