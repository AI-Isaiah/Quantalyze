## Accomplishments

1. **`realSqlRunner(env)` in `seams.mjs`** — spawns `psql` with the pooler URL as an argv element and the password ONLY as `PGPASSWORD` in a child env built from scratch (`PATH`, `PGPASSWORD`, `PGCONNECT_TIMEOUT`), plus `-X -v ON_ERROR_STOP=1 -At` and a 60 s timeout. `ENOENT`, timeout, spawn error and non-zero exit all become `measureFail` with the first stderr line redacted (`<pooler-url>`). An empty stdout at status 0 stays a legitimate zero-row answer the seam refuses to interpret — that judgement belongs to the arm, and the docblock says so.

2. **`arms/cron-obs.mjs`** — `TTL_SQL` and `CRON_OBS_SQL` (one `WITH` statement, a `probe` CTE guaranteeing one row even with no runs so "not scheduled" stays distinguishable from "scheduled and silent"), plus the PURE `judgeCronObs`. Never selects `headers`. Never selects `job_run_details.status`. Three boundaries, each calibrated: the 120 s in-flight grace, the 3 h scan window, and the window's clamp to `pg_net.ttl`.

3. **`arms/cron-drift.mjs`** — `DB_MARKER_SQL` (CLAUDE.md's `COMMENT ON DATABASE` rule made mechanical) and `CRON_JOB_SQL` over ALL rows, compared by a jobname MAP so PROD row order is irrelevant by construction. Ten hygiene rules run on BOTH sides independently of equality; `compareManifest` validates the oracle before comparing against it; every drift defect carries D-15's two readings verbatim.

4. **`captureManifest` and `--capture-manifest --out <path>`** — three refusals that each write nothing, and a success path that writes only text every one of the ten rules cleared.

5. **Twenty fixtures**, including a ten-row hygiene RED set where each row fires its own rule and ONLY its own rule, and a five-row GREEN calibration that includes the exact Vault-backed body jobid 1 was re-scheduled onto on 2026-09-01.

### The exact separators chosen for the multi-line command query

`CRON_JOB_SEPARATORS = { fieldSep: "", recordSep: "" }` — ASCII **0x1F (unit separator)** and **0x1E (record separator)**, passed to psql as `-F` and `-R` for `CRON_JOB_SQL` ONLY. `cron.job.command` is a multi-line `DO $$ … $$` block containing newlines and, inside `jsonb_build_object` argument lists, tabs; psql's default tab/newline separators turn one job's body into several malformed rows. They are written as `` / `` escapes rather than raw bytes — `grep -rlP '[\x1e\x1f]' scripts/prod-prober/` returns nothing, so no invisible control character is committed.

The same separators are threaded through `createSeams({ sqlRunner }).sql(arm, query, opts)` and the fixture runner renders its answer with them, which is what makes the cron-drift fixtures exercise the PARSER and not just the judgement.
