## Deviations from Plan

None to the rules or the allow-list contents. Two small judgment calls, both inside the plan's wording:

- **Fixture host choice.** The plan allows `example.com` for fixtures where `VERCEL_ENV` is unset and the host is irrelevant. In the pdf and tearsheet tests every remaining .com fixture moved to `https://quantalyze.xyz/...` (valid in both production and non-production tests), so no fixture needed `example.com` there; existing `quantalyze.example.com` fixtures were left alone.
- **Spoof host in the shape test.** The suffix-spoof case uses `quantalyze-rho.vercel.app.evil.example` rather than an `evil.com` host, so no real domain appears in the test. The match behaviour is identical.

## Known Limits

- The shape test anchors the host value as `^(?:value)$` (case-insensitive) to model Next's matching. That Next anchors it that way (RESEARCH A2) was measured on a local server only; plan 13's live `curl -sI` host matrix (rho 308, per-deployment host 200, spoof hosts) is the real gate. This plan does not prove the live 308.
- Reversibility: a 308 is browser-cached, so reverting the rule does not reach visitors who already followed it (RESEARCH Pitfall 7). Accepted by the plan.
- The `next.config.ts` PostToolUse validator printed `headers() is async` errors; those are false positives (the `headers()` there is the next.config method, not `next/headers`). Not touched, out of scope.
