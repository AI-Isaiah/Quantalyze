Rules for the lane (orchestrator brief, binding):
- The lane is SHARED with other worktrees. Before any `scripts/local-stack/run.sh` call, take the lock: `until mkdir "$LANE_LOCK" 2>/dev/null; do sleep 20; done; echo "164.9.8.1-04 executor" > "$LANE_LOCK/owner"`. Release with `rm -rf "$LANE_LOCK"`. `LANE_LOCK` and `SCRATCH` are passed at dispatch; refer to them only by these env var names, never write their values into tracked text.
- `up` on a running stack fails: run `down` first. Release the lock between batches.
- If `up` fails on Logflare / analytics health: inside the lock, `cp supabase/config.toml "$SCRATCH/config.toml.bak"`, set `enabled = false` under `[analytics]` only, `down`, `up`, then immediately restore with `cp "$SCRATCH/config.toml.bak" supabase/config.toml` and `cmp` (exit 0) before any test runs. Never commit it. Record in the ledger that the batch ran with analytics disabled.
- Run in THIS worktree, never the main checkout (the main checkout's `analytics-service/` carries dotenv files that `main.py` / `main_worker.py` load at import; RESEARCH "Local soak loop").
- The tool shell is zsh: put loops in a scratch `.sh` under `$SCRATCH` and run them with `bash`.

Facts from RESEARCH ("Local soak loop", Pitfalls 3, 4, 6) that constrain this plan:
- CI exports exactly `API_URL` -> `SUPABASE_TEST_URL` and `SERVICE_ROLE_KEY` -> `SUPABASE_TEST_SERVICE_KEY` from the handoff file `scripts/local-stack/.stack-env`, and sets `CI=true`. Run pytest under `env -i` with only `PATH`, `HOME`, `TMPDIR`, `CI=true` and those two values, so no stray `TEST_SUPABASE_DB_URL`, `HAS_LIVE_DB` or `SUPABASE_URL` from the shell can un-skip a module against shared TEST.
- The lane shape is about 10027 passed / 70 skipped / 2 xpassed in CI; the offline shape is about 10009 passed / 90 skipped. A run that shows the offline shape did not receive the lane values and does not count.
- `rm -f .coverage .coverage.*` before every run.
- `PYTEST_XDIST_AUTO_NUM_WORKERS=4` changes the `-n auto` worker count without changing the argument string (the runner-shaped figure). Do not install `psutil`.
- Do NOT measure or enable `COVERAGE_CORE=sysmon`; it is outside the locked command (D-06) and is a founder question.
