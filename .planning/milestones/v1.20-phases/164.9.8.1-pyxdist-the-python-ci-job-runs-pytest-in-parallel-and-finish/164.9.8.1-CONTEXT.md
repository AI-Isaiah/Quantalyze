<domain>
## Phase Boundary

The `python` CI job (`.github/workflows/ci.yml`, job key `python`) and the analytics-service
Makefile `test:` target run pytest as
`-n auto --dist loadgroup` with the existing coverage flags, byte-identical argument strings,
with `--cov-fail-under=80` still enforced on the combined (all-worker) coverage. The Phase 97
"global-claim fence tests flake under xdist ordering" and the limiter-identity flake
(`tests/test_limiter_identity.py::TestClassClosure::test_every_router_limiter_is_the_one_singleton`)
are each reproduced or ruled out by measurement, and any reproduced flake is fixed at its root
cause. A soak of ≥20 consecutive green runs of the CI command precedes the release commit. Wall
time is measured before and after.

Out of scope: the other CI jobs, the vitest shards, any change to which tests run, any change to
the coverage floor or its `--cov` path set.

<decisions>
## Implementation Decisions

### D-01..D-04 Flake investigation (SC-1)
- **D-01:** Phase 97 fence flake. Reproduce-or-rule-out by measurement on the local-stack lane
  (the same DB the CI job uses since Phase 164.9.4): (a) the exact new CI command repeated (the
  soak counts), and (b) the `shared_test_db` group alone (`test_compute_jobs_fencing.py` and every
  module the conftest sentinels pin) under `-n auto --dist loadgroup`, repeated ≥20 times. Also
  record the MECHANISM: Phase 97's failure was against the SHARED TEST project, where other CI
  runs' rows also lived; the lane is private to the run now. In addition, audit for any test
  module that writes to the lane database (compute_jobs or any other table the global claim
  reads) WITHOUT carrying one of `_DB_MODULE_SENTINELS`. Such a module would run concurrently on
  another worker and is the one way the Phase 97 class could survive under xdist. Any module
  found is a root-cause defect: fix the grouping (sentinel or explicit group), not the assertion.
- **D-02:** Limiter-identity flake. Reproduce deterministically before fixing. The suspected class
  is order-dependent module pollution: several test modules pop/replace `sys.modules` entries for
  `routers.*` / `slowapi` (e.g. `tests/limiter_stub.py`, `test_routers_audit_emission*.py`,
  `test_correlation_residue_sites.py`, `test_computation_error_curated.py`,
  `test_portfolio_compute_integration.py`, `test_routers_audit_2026_05_17.py`,
  `test_c19_portfolio_fixes.py`). Under xdist, a different set of modules shares a worker
  process before `test_limiter_identity.py`. Bisect by running `test_limiter_identity.py` in ONE
  process after each candidate (`-p no:xdist`, explicit file order), and also try the full suite
  under CPU load. The fix goes in the POLLUTER, so that it restores the module state it changed.
  The victim's assertion stays exactly as strict. If it does not reproduce, rule it out with the
  same ≥20-run evidence and a stated mechanism.
- **D-03:** "Ruled out" standard. ≥20 consecutive green runs of the relevant command plus a
  written mechanism for why the recorded cause no longer applies. A bare "it passed" is not a
  rule-out.
- **D-04:** No hiding. No retry plugin, no `@pytest.mark.flaky`, no skip, no new xdist_group used
  only to dodge a flake, no `-p no:xdist` carve-out. A reproduced flake whose root cause is not
  found inside the phase STOPS the phase for a founder decision (accepting a residual flake is
  the founder's call).

### D-05..D-08 Command and wiring (SC-2)
- **D-05:** `-n auto`, not a fixed count, per the ROADMAP SC-2 text. On the 4-vCPU
  `ubuntu-latest` runner that is 4 workers.
- **D-06:** The command. CI: `pytest -n auto --dist loadgroup --cov=services --cov=routers --cov=main_worker --cov-report=term-missing --cov-fail-under=80`.
  Makefile: `$(PYTEST) ` + the same argument string. "Byte-identical" means the argument string
  after the executable, which is the only part the two can share (`$(PYTEST)` is the venv path).
- **D-07:** A gate for byte-identity. Today "keep byte-identical with Makefile `test:`" is only a
  comment. Add a vitest pin (in `src/__tests__/local-stack-lane-wiring.test.ts`, beside the
  existing python-job pins) asserting that the CI `python` job's pytest argument string equals the
  Makefile `test:` argument string, and that it contains `-n auto --dist loadgroup` and
  `--cov-fail-under=80`. Move the D-04 row's `firstDbStep` (`"pytest --cov=services"`)
  deliberately to the new command with a dated comment. Every new or changed pin is seen RED
  (neuter → RED → restore from a byte backup → `cmp`).
- **D-08:** Comments and ledgers. Replace the SERIAL deferral comments in `ci.yml` and the Makefile
  with a dated 164.9.8.1 note, keeping the old text as lineage in the repo's house style. Update
  the TODOS entries for the Phase-97 parallelization deferral and the `ci/pytest-xdist-parallel`
  branch to say what this phase measured.

### D-09..D-10 Coverage (SC-2)
- **D-09:** pytest-cov combines xdist worker data natively. Measure the TOTAL under serial and
  under `-n auto` on the same tree. A difference larger than 1 point is investigated (for
  example, a subprocess or fork path that is lost under xdist) before the phase continues.
- **D-10:** The 80 floor is proven still ENFORCED under xdist: a run with the floor neutered
  upward (e.g. `--cov-fail-under=99`) must exit non-zero under `-n auto`. The floor itself is not
  changed (changing it is a founder decision).

### D-11..D-13 Soak and timing (SC-3, SC-4)
- **D-11:** Soak. ≥20 CONSECUTIVE green runs of the exact CI command
  (`CI=true`, from `analytics-service/`, against the local-stack lane with the handoff values the
  CI job exports). A red run resets the count and routes to root cause per D-04. Record each
  run's pass/fail counts and wall time. The lane is booted fresh at least once per batch (CI
  always runs on a freshly booted lane), and batches release the shared lane lock in between.
- **D-12:** Wall time. "Before": the cited CI runs (job 18-20 min, pytest step ~15 min) plus a
  local serial measurement of the same command on the same tree. "After": local `-n auto`
  measurement, plus `-n 4` locally as the runner-shaped figure. The PR's CI timing (SC-4 "on
  the PR") is taken at ship by the orchestrator, because this phase does not push.
- **D-13:** Release: CI/infra change → last-digit version bump, re-picked from a freshly fetched
  origin/main; no push, no PR.

### D-14 Founder decision 2026-10-15: the full soak and SC-4 move to CI
- **D-14:** The founder chose "Fix bound, soak in CI" (AskUserQuestion, 2026-10-15), after the second local lane soak stopped on a RED. (1) `tests/test_feedback_engine.py::test_lazy_import_not_triggered_at_module_load` is fixed at its root. It checks the lazy-import property by the module set, not by elapsed time: seen RED with the lazy import neutered, GREEN after. Other wall-clock subprocess bounds of the same class in `analytics-service/tests` are audited and listed, and any that would fail under CPU starvation are fixed the same way. (2) Plan 04's full soak (Task 2b), required by D-11, moves to CI: at least 20 consecutive green `python` job runs on the PR branch's head. The SC-4 wall-time before/after reading (D-12) is taken from the PR's CI. Reason: the local box is shared by other phase agents (load average 50 to 63), so a local soak measures this laptop, not the change. The two local stops stay as lineage in plan 04's SUMMARY. This supersedes D-11's "equivalent local loop" and D-12's local "after" measurement as the gate.

### D-15 Founder decision 2026-10-15: coverage measures with the sysmon core
- **D-15:** The founder chose "Switch to sysmon" (AskUserQuestion, 2026-10-15) after the first CI soak run MISSED SC-4. That run's `python` job took 942 s, against a 1190 s before median and a 654.5 s threshold, with pytest alone at 727 s on 4 workers. The cause was RESEARCH Open Question 1: under coverage's default settrace core, the AST-heavy `test_qstats_gate.py` tests take 37-89 s each, and they form the parallel critical path. `analytics-service/pyproject.toml` gains `[tool.coverage.run] core = "sysmon"`. This **deviates from D-06 in effect, not in letter.** The pinned pytest argument string is unchanged and still byte-identical in CI and the Makefile, but both now read a coverage setting that D-06 did not cover. Measured locally with the exact CI command: 10135 passed, 93.61% (93.60% under settrace), 81 s (5m13s under settrace). Cost: no branch coverage before Python 3.14, and this suite measures none. The CI soak restarts from zero on this head, and SC-4 is re-read from it.
