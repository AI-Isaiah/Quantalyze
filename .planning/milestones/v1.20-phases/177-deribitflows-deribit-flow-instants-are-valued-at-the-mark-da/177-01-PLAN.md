Deribit's public 1-minute `BTC_USDC-PERPETUAL` candle at the flow's minute, valued at that candle's `open`, counted in
the mark day, and the derive's stored return reads 22.92 / 1171.0 where today's code stores 22.42 / 1171.0. Then pin the

CONTEXT decisions carried verbatim (the authority is `177-CONTEXT.md`, not this summary):
- D-02 revisited: "Fetch index at flow time", chosen over the recommended "Day-D ledger mark".
- D-03: "Fix anyway (Recommended)". Ship the fix with a test that is RED on own-day pricing.
- D-04: "Perpetual 1-min candle (Recommended)". Price = the open of the {CCY}_USDC-PERPETUAL 1-minute candle that
  contains the flow (public `get_tradingview_chart_data`, `resolution=1`).
- D-05: "Refuse + store prices". No fallback: a structural no-data read refuses as `mark_flow_index_unavailable`; a
  transient read retries; a 429 re-raises to `_stamp_429`. (The store is plan 03; the derive's refusal split, the
  capture that keeps the mark and the 429 stamp are plan 04.)

Design choices recorded here (Claude's discretion in CONTEXT: "where the at-instant index is attached"):
- The price is attached as `FlowInstant.amount_prior_day` inside `native_flow_instants` (the single choke point every
  call site already uses), through a keyword `at_instant_index` keyed `(CCY, at_ms)`.
- The read runs inside the Deribit branch while the exchange is open, against a PREDICTED mark set (the key's stored
  marks plus this derive's own `_mark_read_at`), because the exchange is closed before the apply seam and the derive's
  own mark is written after the close (RESEARCH Pattern 3). A coverage check on the FINAL marks at the seam turns any
  prediction miss into a loud failure, never an own-day price (RESEARCH Pitfall 3).
- The read is one request per (currency, read day) group, window 00:00Z of the read day through the latest instant
  plus 60 s (the probe verified the end is inclusive and a tick is the candle start).

Output: the shared predicate, the valuation keyword, the minute reader, the new `deribit_flow_prices` module, the
key-mode wiring, and the RED-first oracle.
