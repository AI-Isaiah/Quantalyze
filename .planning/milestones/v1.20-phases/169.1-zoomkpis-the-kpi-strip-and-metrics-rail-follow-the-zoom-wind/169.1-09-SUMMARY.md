# Phase 169.1 Plan 09: The Rolling Sharpe strategy line is continuous across the days the active basis excluded Summary

On a strategy computed on the active day basis, the Rolling Sharpe chart now draws its
strategy line as one path across the zero-return days the basis excluded. The values are
still null on those days, as the engine's are. Only the drawn path changes. The bridge is
an opt-in on the `rollingSharpe` chart config. It applies to the strategy series only, and
only at the indices `metricsBasisSeries` excludes (D-84). The leading warm-up, any
no-dispersion (D7) window and every comparator null stay gaps.

## Scoping

- **Config opt-in.** `bridgeBasisExcludedDays` is set on `CHART_CONFIGS.rollingSharpe`
  only. A test pins the opted-in list to exactly `["rollingSharpe"]`.
- **Strategy series only.** `resolveSeries` sets `bridgeAt` on the strategy `ResolvedSeries`
  only. The comparator series never carries it, so the rolling Sharpe comparator line still
  breaks at an interior null and draws nothing past its last finite index (pinned).
  `TimeSeriesChart.coverage-gap.test.tsx` (the 169.5-02 break past `through`) passes
  unedited.
- **Basis-excluded days only (D-84).** The mask comes from `metricsBasisSeries`, the same
  helper that made the exclusion. A null on a non-zero day stays a gap under the active basis
  (pinned). That is the no-dispersion window (founder D7). On the calendar basis the helper
  excludes no day, so the mask is all false and the line is byte-identical (pinned: the same
  nulls give two segments). The Scenario payload carries no `dayBasis`, so it is in the
  calendar case.
- **Every other chart.** For each line config with a strategy series other than
  `rollingSharpe`, an interior null on an excluded day gives two segments. The configs are
  cumulative, volMatched, rollingVol, rollingSortino, worstDDs and underwaterAcc. This case
  was green on arrival because the default is the old behaviour. Neuter C shows it can fail.
- **Values unchanged (D-27).** Each render case asserts that the payload's
  `strategyRollingSharpe` is the same object after render and is deep-equal to its contents
  before render. The average line, the Y-domain scan, the crosshair and the Rolling Metrics
  table read `values`, not the path, and none of them were edited.
- **Not edited:** `rolling.ts`, `build-payload.ts`, `compute.ts`,
  `TimeSeriesChart.coverage-gap.test.tsx`, `TimeSeriesChart.markers.test.tsx`,
  `MetricsColumn.tsx`, any Scenario file and any Python file. The plan's acceptance command
  over those paths printed nothing (exit 0).

## Expected rendering (169.1-08, step 3)

On a published active-basis strategy, the Rolling Sharpe chart's accent (strategy) line is
continuous across the excluded zero-return days. A straight segment joins the last value
before each excluded run to the next value after it. No point is drawn on an excluded day.
The only gaps are:

- the leading warm-up;
- any no-dispersion window;
- nothing after the last finite value.

The comparator (muted) line breaks exactly as before. "Now", min, max and average in the
Rolling Metrics table are unchanged.
