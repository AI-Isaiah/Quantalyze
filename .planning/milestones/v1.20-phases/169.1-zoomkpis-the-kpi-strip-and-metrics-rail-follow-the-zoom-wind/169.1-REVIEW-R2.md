## Paths checked for new defects (none at MEDIUM+)

- **HIGH-1: is there a second public cache?** The only `unstable_cache` around a factsheet build is `buildFactsheetPayloadCached`, and `v2/page.tsx:543` is its only call site. The share page is `force-dynamic` and has no data cache. The OG route (`api/og/factsheet/[id]/route.tsx`) is CDN-cached, but it never reaches `fetchAndBuildPayload` or the conventions read: it computes its card from `computeOgHeadline` over `resolveDailyReturnSeries`. So dropping `conventionsDegraded` in `fetchAndBuildPayload` leaks nothing into a cache. Owner, share and discovery are uncached; they render the degraded build, and the resolve stage captures it once.
- **HIGH-1: no sibling caller drops the failure.** Two non-test call sites exist. `readCompositeFactsheet` is called only at `fetch-and-build-payload.ts:450`, which copies `conventionsReadFailure`. `readCashConventions` is called only at `:561` (single-key) and `composite-read-path.ts:420` (the composite read). No other path can discard the new optional field and skip the capture or the marker.
- **HIGH-1: capture count.** A sibling `read_error` exits before the success-exit capture, so a failed build sends one event and not two. Neither the probe (`caller !== "build"`) nor an absent row (`failed: false`) captures. Each has a test.
- **MD-03: readers of a NaN `ann_vol`.** Every displayed reader formats through a non-finite-to-"—" `pct` / `pct1`. Of the code that does arithmetic on `compute()`: `allocator.ts` does not read its `ann_vol`, and `style-drift.ts` and the comparator bench summary run on the calendar basis with n ≥ 2. The single arithmetic reader is the vol-match, which is now guarded. After the `unstable_cache` JSON round-trip, a NaN becomes `null`, and `Number.isFinite(null)` is false, so the guard covers that shape as well.
- **MD-02: the new `dense` call.** For an active-basis composite it now runs the calendar-dense path, which previously only the calendar basis ran. It is the same composite series that round 1 proved cannot reach the `metricsBasisSeries` throw: `readCsvDailyReturns` rejects a non-increasing date with `page_order`. Exposure is unchanged. Non-composites get identity positions, so they are byte-identical, and the snapshot did not move.
- **MD-01: can the hold get stuck?** I traced every begin to a matching end.
  - The brush has four branches (left, right, pan, select). All four set `dragRef`, so `onPointerUp` always ends the hold.
  - The chart releases on up, cancel, lost capture and unmount, and a wheel burst releases on its timer.
  - A drag that starts during a wheel burst clears that timer and inherits the hold.
  - A double-click is two balanced down/up pairs.
  - When holders overlap, the outcome is an early release (a per-event derive), never a stuck hold. That is the accepted perf-only LOW.
- **MD-01: can caption and figures split?** The hold replaces `range` before `resolveRangeScope`, so `scope` and `view` come from the same range for every `useWindowedView` consumer: the strip, the rail, Main Metrics, the rail tables, and `AnalyticalPanels:288`. Neither the strip nor the rail reads `useXRange` for a figure. `FactsheetView.tsx:2115` reads only `resetXRange`, and `AnalyticalPanels.tsx:105` is a tap-pin index, not a scope. This closes fixer B's merge-hazard note 3.
- **SFH MED-2: basis agreement.** The strip's `basis` is `useBasisOrCash()` (`FactsheetView.tsx:1433`), the same hook the rail uses, so the two surfaces gate the caveat identically.
- **The out-of-list test edit (FIX-A Decisions).** The `page.pending-fallback.test.tsx` double now answers the conventions read as an empty, successful read.
