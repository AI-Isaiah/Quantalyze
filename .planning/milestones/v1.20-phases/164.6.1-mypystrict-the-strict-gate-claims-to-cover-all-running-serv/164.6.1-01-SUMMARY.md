### `-> Any` justification (Task 2, verbatim from the plan)

`_claim_priority`, `_claim_legacy`, `_reset`, `_enqueue` and `_query` gain `-> Any`, for four reasons:
- This matches the repo convention for Supabase-call closures. RESEARCH counted 21 `-> Any` against 7 concrete returns in services/+routers/, e.g. `services/equity_reconstruction.py` `_upsert`/`_sel`.
- It equals the return type mypy already infers for an unannotated def.
- It is an explicit return type rather than a cast.
- The concrete `SingleAPIResponse`/`APIResponse` types were MEASURED to cascade into 7 new errors: the `jobs: list[ClaimedJob]` assignment, and the `rows[0].get("created_at")` freshness check. Those could only be cleared by editing runtime code, which D-04 forbids.
