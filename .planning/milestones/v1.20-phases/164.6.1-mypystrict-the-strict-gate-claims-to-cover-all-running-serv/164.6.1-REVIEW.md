## Warnings

### WR-01: Quoted or spaced YAML keys switch the gate step off with every pin green

**EXECUTION STATUS: EXECUTED.** The real `surfaceProblems` was run on mutated in-memory copies of ci.yml. PyYAML confirmed that both spellings parse to the same keys GitHub reads.

**Files:**
- `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts`, function `gateStepKeys` (regex `^([A-Za-z0-9_-]+):` on the trimmed line);
- same file, function `stepSwitchProblems` (`keyBlock(job, 4, "continue-on-error")`, which matches with `startsWith(\`${key}:\`)`).

**Issue:** WR-04 was closed on the premise that "the step may set only `name` and `run`". The key reader only recognises a bare, unquoted key followed directly by `:`. YAML allows other spellings of the same key, and GitHub treats them identically. Each of these mutations returned **no problem at all**:

| Mutation (inserted after the gate's `- name:` line, or under `  python:`) | Result |
|---|---|
| `        "if": false` | GREEN (silent) |
| `        'continue-on-error': true` | GREEN (silent) |
| `        if : false` | GREEN (silent) |
| `    "continue-on-error": true` (job level) | GREEN (silent) |
| `    continue-on-error : true` (job level) | GREEN (silent) |
| `        if: false` (control) | RED, as expected |

`yaml.safe_load('a:\n  "if": false\n  continue-on-error : true\n')` gives `{'a': {'if': False, 'continue-on-error': True}}`. So these are the real keys, not malformed YAML. The test docstring still states that the step carries "no `if:`, `continue-on-error:`, `shell:` or `env:` that could switch it off". The round-1 fix already took on one syntactic variant (the flow-mapping `defaults:`) and missed these ones.

**Fix:** fail closed on any content line at the step's key indentation that is not literally `run:`. Do not try to recognise the bad keys by name:
```ts
function gateStepKeyProblems(ymlText: string): string[] {
  const step = gateStepLines(ymlText);
  const keyIndent = indentOf(step[0]) + 2;
  return step.slice(1)
    .filter((l) => isContent(l) && indentOf(l) === keyIndent && !/^run:\s/.test(l.trimStart()))
    .map((l) => `ci.yml: step "${STEP_NAME}" carries ${JSON.stringify(l.trim())}; only name and run are allowed.`);
}
```
For the job level, normalise the key before comparing: strip the quotes, then trim before the colon (`/^["']?continue-on-error["']?\s*:/`). Add calibration legs for `"if": false` and `if : false`.

### WR-02: Seven new assertion arms have no calibration leg, including two that REVIEW-FIX says are covered

**EXECUTION STATUS: EXECUTED.** Each arm was fired by hand on a mutated in-memory copy, and each goes RED today. No test in the file does this.

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts`, in functions `mypyConfigProblems`, `stepSwitchProblems` and `surfaceProblems`.

**Issue:** these arms are reached only by the main assertion, which passes on the real tree. Nothing proves they can fail, so a later refactor could neuter any of them silently. That is the defect class this phase's own "CALIBRATION" block exists to prevent.

| Arm | What I fired | Leg in file? |
|---|---|---|
| mypy config outside `[tool.mypy]`/overrides | `tool.mypy.ignore_errors = true` at root; `[tool]` + `mypy = { ignore_errors = true }` | none |
| `main.length !== 1` | a second `[tool.mypy]` | none |
| `lost the key` | `strict = true` deleted | none |
| `THIRD_PARTY_OVERRIDES` removal direction (REVIEW-FIX: "set equality means a removal also goes red") | the `pandera.*` override deleted | none |
| `.mypy.ini` tracked | `.mypy.ini` added to the listing | none ((t) covers only `mypy.ini`) |
| workflow-level `defaults: shell:`, and the flow-mapping form (REVIEW-FIX: "The check also catches the flow-mapping form") | top-level `defaults: run: shell:`; job `defaults: {run: {…, shell: 'bash {0}'}}` | none ((m) covers only the job-level block form) |
| Makefile has no `ci:` target | `ci: typecheck test` deleted | none ((v) covers only "present, but missing typecheck") |

The root-dotted and inline-table arm matters most. It is the only thing that catches mypy settings written as TOML dotted keys or inline tables, which are exactly the constructs the narrow reader was built to refuse.

**Fix:** add one leg per row. Each leg should use `mutate`/`insertAfter` so that the mutation is proven to have applied, and should assert that the named problem is present. For example:
```ts
it("(w) mypy config as a root dotted key → an outside-table problem", () => {
  const added = "tool.mypy.ignore_errors = true\n";
  expect(REAL_PYPROJECT.includes(added)).toBe(false);
  expect(has(cfg(added + REAL_PYPROJECT), "[(root)] carries mypy configuration")).toBe(true);
});
```
Then update the REGISTRY row and the registry `invariant` leg list, (a)–(v), to match.

### IN-01: The invocation counter still misses common invocation shapes, and flags two harmless ones

**EXECUTION STATUS: EXECUTED.** The real `surfaceProblems` was run with a second step inserted after the gate.

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts`, constant `MYPY_COMMAND` and function `mypyInvocationCount`.

**Issue:** commit `b2b3591b9` is titled "count every mypy invocation", and the REGISTRY row says "exactly ONE mypy invocation in the job". The regex only accepts `mypy` at the start of a command or directly after `; & | ( $(`. Two kinds of error follow:
- **Missed (GREEN with 2 invocations):** `run: uv run mypy services/`, `if mypy services/; then …`, `timeout 60 mypy services/`, `"$VENV/bin/mypy" services/`.
- **Flagged wrongly (RED with 1 real invocation):** a step named `Lint check (mypy)`, and `run: echo "done; mypy next"`.

The impact is low. The gate step's own path set and flag set are pinned exactly, so a second, missed invocation cannot shrink coverage. The false positives fail loud. The issue is that the prose claims more than the code does.

**Fix:** either scope the prose to what the regex does ("`mypy`/`python -m mypy` at a command start"), or allow wrapper words (`(?:uv run|poetry run|timeout \S+|if|!|time|exec|env(?: \w+=\S+)*)\s+`) and strip YAML `name:` values before matching.

### IN-02: Any multi-line TOML construct in an unrelated tool table reds the mypy contract

**EXECUTION STATUS: EXECUTED.**

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts`, function `parseTomlTables`.

**Issue:** the reader reports every line it cannot parse, in any table. Appending a routine `[tool.ruff]` with `select = [\n  "E",\n  "F",\n]` produces three `pyproject.toml: line N … is neither a table header nor a single-line key = value` problems. The mypy-surface contract goes red over a linter config change. This fails loud, not silently, and it is a deliberate fail-closed choice. But the next person to add ruff or pytest config to this file will hit it.

**Fix:** track bracket depth and triple-quote state, so that a multi-line array or string is read as one value. Then report unparseable content only inside tables that `mypyTables` selects. A header cannot occur inside an array, so this keeps the fail-closed property for mypy tables.

### IN-03: Job-level `if:` and job- or workflow-level `env:` are not pinned, although job-level `continue-on-error` and step `env:` are

**EXECUTION STATUS: EXECUTED.** The probes stayed GREEN. The indirect catch described below was established by reading ci.yml, not by running it on GitHub.

**File:** `src/__tests__/contracts/ci-mypy-strict-surface.contract.test.ts`, function `stepSwitchProblems`.

**Issue:** these two mutations both return no problem:
- `    if: false` under `  python:` (a second `if:`; replacing the existing `if:` value behaves the same);
- job `env: PATH: /tmp/stub`.

The docstring bans step `env:` because it can "repoint mypy", and job-level env can do the same. A skipped `python` job is caught indirectly: `sql-tests` has `needs: [python]`, and the `frontend` aggregator reddens a `sql-tests` skip on a trusted event. It is not caught on a fork PR or a `workflow_dispatch`, and it is not caught by this contract.

**Fix:** pin the job's `if:` to its current expression (`needs.changed-paths.outputs.docs_only != 'true'`). Either ban job-level and workflow-level `env:` keys that name `PATH` or `MYPY*`, or document them as a declared limit in the docstring and the REGISTRY row.
