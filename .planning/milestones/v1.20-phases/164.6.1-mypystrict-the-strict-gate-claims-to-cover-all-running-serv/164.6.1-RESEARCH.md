## Summary

The 15 strict errors under the D-01 invocation are real and cheap to fix, and every fix has been measured. Applying the annotations below to a scratch copy of `analytics-service/` takes the widened invocation from `Found 15 errors in 3 files (checked 100 source files)` to `Success: no issues found in 100 source files`. `mypy --strict main.py` alone reports `Success: no issues found in 1 source file`. The full-app OpenAPI document is byte-identical before and after (sha256 prefix `8103da730102c4fc` both sides). The seven test files that exercise these modules (`test_health`, `test_main_worker`, `test_sentry_init`, `test_verify_service_key_middleware`, `test_service_key_log_companion`, `test_local_worker_prod_guard`, `test_correlation_middleware`) pass against the annotated copy with `125 passed`.

Three findings change what the planner must write.
- **`health()` cannot simply gain a return annotation.** FastAPI 0.139 infers `response_model` from the return annotation. `-> JSONResponse | dict[str, Any]` without `response_model=None` raises `FastAPIError: Invalid args for response field!` at route registration, so the service would fail to boot on deploy. With `@app.get("/health", response_model=None)`, the responses (200 and 503 bodies, content-type) and the OpenAPI entry are byte-identical to today. The repo already uses exactly this shape on `routers/process_key.py`'s `process_key` endpoint.
- **The sentry fix needs one local binding, not only a signature change.** With `Event`/`Hint` types, the breadcrumbs branch fails `union-attr`, because the SDK types `breadcrumbs` as `Annotated[...]`, a union that includes `AnnotatedValue`. mypy cannot narrow `event["breadcrumbs"]` from an `isinstance(event.get("breadcrumbs"), dict)` test. Binding `breadcrumbs = event.get("breadcrumbs")` once and testing that is behaviour-identical and clears it. No `# type: ignore` is needed anywhere.
- **The five Supabase-call closures in `main_worker.py` should be `-> Any`**, matching the repo's dominant convention (21 `def _x() -> Any:` closures vs 7 concrete ones in `services/`+`routers/`). Concrete `SingleAPIResponse`/`APIResponse` annotations were measured too. They cascade into 7 NEW errors at `claim_result.data` (the `jobs: list[ClaimedJob]` assignment) and at `rows[0].get(...)` in the daily-enqueue freshness check, and clearing those would change runtime code.

**Primary recommendation:** Build one plan with two tasks: (1) annotations + CI step + Makefile + comment corrections + local neuter proof; (2) the contract test + registry row + floor bump 60 → 61. Use the annotations verbatim from Code Examples, add `response_model=None` on `/health`, and carry D-06b as an explicit OPEN ship step.

### Pattern 1: Line-based extraction of a `ci.yml` step (repo convention)

**What:** The existing `ci.yml` readers do NOT use a YAML library. `package.json` has no `yaml`/`js-yaml` dependency, and no test imports one. They split the text into lines, find a step by its exact `- name:` line, and slice the `run:` body by indentation. [VERIFIED: `src/__tests__/contracts/ci-anti-skip-gate.contract.test.ts` function `extractRunScript`]

**Recommendation:** Give the mypy step a `name:` so the test can anchor on it. Today it is a bare `- run: mypy ...` line. Renaming or naming a step does not change any required-check name, because checks are per-job. Then parse the single-line `run:` value.
- Scope the search to the `python:` job block: from `^  python:$` to the next `^  [a-z0-9-]+:$` line. [VERIFIED: `ci.yml` has `  python:` as a top-level job key, and the next job key follows the same two-space shape]
- Assert that EXACTLY ONE mypy invocation exists in that block, so a second, partial one cannot satisfy the pin.

### Pattern 2: In-test calibration on a mutated COPY (repo convention)

**What:** `ci-docs-path-filter.contract.test.ts` has a `CALIBRATION` describe block with three parts. [VERIFIED: that file's `describe("[164.6.3 / CI-DOCSPATH-01] CALIBRATION — ...")` block]
1. A NON-VACUITY CONTROL: the unmutated input passes through the same harness.
2. Two neuter legs. Each one first asserts the mutation target exists, the mutated text differs, and the original no longer survives. Then it asserts the RED.
3. A final "byte-unchanged on disk" assertion.

**Apply here:** Write the check as a PURE function, e.g. `surfaceProblems(ciYmlText, makefileText, diskSurface): string[]`.
- The real arm asserts `[]`.
- Calibration legs:
  - (a) remove ` main.py` from the extracted ci.yml text: expect a problem naming `main.py`;
  - (b) add a phantom `newmod.py` to the disk surface: expect a problem naming `newmod.py` (the "new top-level module added without widening" case D-03 exists for);
  - (c) drop `main_worker.py` from the Makefile text: expect a problem naming the Makefile.
- The non-vacuity control asserts the real inputs yield `[]` through the same function, and that the disk surface contains `main.py` plus at least three packages.
- Mutate strings only. Never write to `ci.yml` or the Makefile.

### Pattern 3: Disk derivation of "the service surface"

- **Top-level modules:** `readdirSync("analytics-service", { withFileTypes: true })`, keeping `isFile()` and a `.py` suffix. Today that is exactly `main.py`, `main_worker.py`, `main_worker_healthz.py`, `sentry_init.py`. [VERIFIED: `git ls-files 'analytics-service/*.py'` at depth 1 and `ls analytics-service/*.py` agree on these four; there is no top-level `conftest.py`, since `conftest` lives under `tests/`]
- **Packages:** every directory directly under `analytics-service/` that contains an `__init__.py`, minus a HAND-TYPED exclusion set `{tests, scripts}`, each with its reason. Today there are five such directories: `models, routers, scripts, services, tests`. `docs/` has none. [VERIFIED: `ls analytics-service/*/__init__.py`]
  - Deriving the packages as well as the top-level files means a new package also reds. That is a strict superset of D-03's wording.
  - Assert that the exclusions still exist on disk, so a stale exclusion is loud.
  - This is D-03's intent. The planner may keep the package list hand-typed if they prefer the literal wording.
- **Pitfall:** an untracked stray `.py` in a developer's checkout reddens the test locally. That is acceptable and loud. CI checkouts carry only tracked files. The alternative is `git ls-files` via `spawnSync`, which works in CI (checkout has git) but adds a subprocess.

### Anti-Patterns to Avoid

- **Annotating `health()` without `response_model=None`.** It is an import-time crash, and the service fails to boot. Measured; see Pitfall 1.
- **`# type: ignore[arg-type]` on `before_send=`.** Not needed; the real types work with one local binding. D-04 permits the ignore only if a real type is impossible, and it is not.
- **Concrete `APIResponse` return types on the claim/query closures.** They produce a 7-error cascade that needs runtime edits. See Pitfall 3.
- **Restoring a neutered file with `git checkout --`.** Use a scratch copy (preferred) or a byte backup.
- **A grep-only pin of the YAML** (e.g. `expect(yml).toContain("main.py")`). It passes if `main.py` appears in the comment while the command drops it. Parse the command line itself.

## Common Pitfalls

### Pitfall 1: FastAPI turns a return annotation into a `response_model`
**What goes wrong:** `@app.get("/health")` + `async def health() -> JSONResponse | dict[str, Any]` raises `FastAPIError: Invalid args for response field! Hint: check that starlette.responses.JSONResponse | dict[str, typing.Any] is a valid Pydantic field type` at route registration, i.e. at `import main`. On Railway that is a boot failure, and the healthcheck never goes green.
**Why:** In `fastapi/routing.py` (0.139.0), when `response_model` is the default placeholder, `get_typed_return_annotation(endpoint)` is used. The code only skips inference when `lenient_issubclass(return_annotation, Response)` holds, and a Union is not a subclass. [VERIFIED: installed `fastapi/routing.py` block beginning `if isinstance(response_model, DefaultPlaceholder):`, which reads `if lenient_issubclass(return_annotation, Response): response_model = None … else: response_model = return_annotation`]
**Avoid:** Use `@app.get("/health", response_model=None)`. A probe app measured byte-identical 200/503 responses (body and `application/json` content-type) and an identical OpenAPI path entry. The full `main.app.openapi()` sha256 is identical before and after the full annotation set. [VERIFIED: measured this session]
**Warning sign:** Any test that imports `main` errors at collection.

### Pitfall 2: `sentry_sdk` `Event["breadcrumbs"]` is a union mypy cannot narrow through `.get()`
**What goes wrong:** After re-typing to `Event`, mypy reports `sentry_init.py: error: Item "AnnotatedValue" of "AnnotatedValue | dict[Literal['values'], list[dict[str, Any]]]" has no attribute "get" [union-attr]`.
**Avoid:** Bind once: `breadcrumbs = event.get("breadcrumbs")`, then `if isinstance(breadcrumbs, dict): crumbs = breadcrumbs.get("values")`. This is the same object, the same mutations and the same control flow. `test_sentry_init.py`: `30 passed` on the annotated copy. [VERIFIED: measured]

### Pitfall 3: Concrete Supabase return types cascade
**What goes wrong:** Annotating `_claim_priority`/`_claim_legacy`/`_query` with `SingleAPIResponse`/`APIResponse` produced 7 new errors. One `assignment` error is at the `jobs: list[ClaimedJob] = claim_result.data or []` line, and six `union-attr` errors are at `rows[0].get("created_at")`. Fixing them needs runtime edits (`rows()`/casts). [VERIFIED: measured]
**Avoid:** Use `-> Any` for the five Supabase closures. It is the repo convention (21 vs 7 in `services/`+`routers/`), and it equals what mypy infers today for an unannotated def's return. It is an explicit return type, not a cast.

### Pitfall 4: `--follow-imports=silent` makes "reached" look like "checked"
