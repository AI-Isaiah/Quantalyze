# Phase 164.6.6.2 Plan 09: server seams convert a BTC series to USD Summary

**The allocator dashboard payload, the lazy returns route and the portfolio page all call the one `convertNativeReturnsToUsd` on stored BTC closes, so a BTC account is blended and plotted as USD (the 0.21 oracle) and the raw `data_quality_flags` blob never crosses to the client.**

## What was built

- `getMyAllocationDashboard`: before the per-row `flatMap`, a scan of the rows' `data_quality_flags.native_unit` through `parseReturnsUnit`; `readBtcCloses(supabase)` runs once, only if some row has a unit, and a `null` result logs one `console.error` and converts every native row to `[]`. Per row, `daily_returns` is `convertNativeReturnsToUsd(resolvedDailyReturns, returns_unit, btcCloses)` (same array reference for USD) and `returns_unit` is emitted on `strategy`. `series_state` still derives from the pre-conversion series. The scalar metrics beside it stay the strategy's own; the comment records that the table's MTD for a BTC strategy is now a USD MTD (D-13) and the list-surface chip is Phase 164.6.6.2.1 (D-19).
- Returns route: `returns_unit` (strict `parseReturnsUnit`) and `daily_returns_usd` (`convertNativeReturnsToUsd` on `readBtcCloses(supabase)` for a native unit; `null` for USD; `[]` when native but unpriced or series empty). `daily_returns` is unchanged. Each field carries a JSDoc with the D-18/D-22/D-23 reasoning and the no-new-disclosure argument.
- Portfolio page: `getPortfolioStrategies` embeds `data_quality_flags`; `buildEquityCurveSeries(strategies, btc = null)` takes the native branch (`buildUsdWealthPoints`: resolve daily, convert, cumprod, empty is `null`); `hasNativeUnitConstituent` gates the page's single closes read; `stripConstituentSeries` drops `data_quality_flags`. The other two `getPortfolioStrategies` callers (manage, documents) project names only, so the widened select ships nothing new there.
