## Warnings

### WR-01: In the "ready" branch the warm-up note's two-day promise is off by one, and the new arm pins it while mocking the builder that decides it

**File:** `src/app/(dashboard)/allocations/AllocationDashboardV2.tsx:235-241` (JSDoc), `:252-256` (copy), `:215-230` (branch); `src/app/(dashboard)/allocations/AllocationDashboardV2.rebuilding.test.tsx:391-411`

**Issue:** Plan 14's truth D2, and the JSDoc it rewrote, say the note renders "before two days have accrued ... so its timer is true". Three facts in the real code contradict that:

1. **"Ready" needs at least one return.** `extractTrustworthyDerivedSeries` returns null for `returns.length === 0` (`src/lib/queries.ts`, the `returns` guard), and `equityHistoryReadiness` is "ready" only with a series.
2. **Returns come one day behind the curve.** The writer's `portfolio_returns` (`analytics-service/services/allocator_equity_compose.py`) treats a key's first day as a join, not a return. An N-day curve therefore yields at most N−1 returns.
3. **Panels need two returns.** `buildAllocatorPortfolioFactsheetPayload` returns null when `dailyReturns.length < 2`. With `equityDailyReturns` passed as `dailyReturns`, that null is the only way into the warm-up branch.

So under "ready", `FactsheetWarmupNote` renders exactly when there is one return, which means a curve of at least 2 days is already on screen above it. Its sentence, "Aggregated factsheet panels appear once at least two days of blended equity history are available", is false every time it renders. The panels actually need 3 days. The promise does come true a day later, so this is not the indefinite false timer that D-15 removed from "rebuilding". It is still the "promise the data cannot keep" class this plan was meant to close, and the JSDoc now says the opposite.

The new arm (`rebuilding.test.tsx:391`) cannot catch it. It forces `buildPayloadSpy.mockReturnValueOnce(null)` and passes a 2-point curve with no returns, a combination the producer never emits for "ready" (fact 1). It then asserts the two-day sentence verbatim (`:403-405`), which makes the wrong threshold harder to correct.

Plan 14's hard constraint forbade editing `FactsheetWarmupNote`'s copy, so this goes back as a copy call, not an executor fix.

**Fix:** Ask the founder to make the copy call (DESIGN.md Voice). Two options:
```tsx
// Either state the true threshold:
Aggregated factsheet panels appear once at least three days of
blended equity history are available.
// or name the unit the builder actually counts:
Aggregated factsheet panels appear once your history has at least two
daily returns.
```
Then:
- correct the JSDoc (`:235-241`) to say the note renders when the book has exactly one return;
- rewrite the arm so its fixture is a real "ready" shape (`equityDailyReturns` with one point, a curve with 2 points);
- let the real builder, or a spy that delegates to it, decide null, so a later change to the builder's threshold or to the copy fails the arm.

### IN-04: The blank-mode `it.each` title fills its placeholders from the wrong columns

**File:** `src/app/(dashboard)/allocations/components/ScenarioComposer.test.tsx:17083-17090`

**Issue:** The rows are `[label, state, snapshotCount, source]` and the title is `"blank mode + equityHistoryState %s (%s snapshots, %s source)"`. ### IN-05: Conditional reachability question. A trustworthy v2 row with a single-point curve would show a new book "did not pass its checks"

**File:** `src/lib/queries.ts`: `extractTrustworthyDerivedSeries` (the `returns.length === 0` guard), `derivedPayloadRejection` (falls through to `"malformed"`), and the `missingSeriesReason` mapping in `derivePhase07Fields`

**Issue:** The writer (`job_worker.py` derive) deletes only EMPTY curves. It upserts any non-empty v2 payload. `portfolio_returns` gives a 1-day curve zero returns. If the compose ever emits a 1-point curve, the reader rejects it as `"malformed"` and the Overview shows a brand-new book the `derivation_rejected` line: "The latest rebuild of your history did not pass its checks". That would be a false alarm on exactly the book D-15 is about. I could not prove this path is reachable. A key with an anchor and no returns is classed `DROPPED_KEY`, which may empty the curve and delete the row, and the reader then correctly shows `awaiting_derivation`. That is why this is Info and not a Warning. The reader code is C2's, not plan 14's.

**Fix:** Add a Python compose test pinning what a single-day book produces (no row, or a curve of at least 2 days). If a 1-point trustworthy row is possible, map "v2, trustworthy, curve present, returns empty" to `awaiting_derivation` in `derivedPayloadRejection` and the producer mapping, with a `queries.test.ts` arm.
