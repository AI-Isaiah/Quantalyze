# Phase 167.1.2 Plan 05: Flow-Neutral Book Returns Summary

**The allocator equity payload is version 2 and carries flow-neutral book returns, and the derive job deletes the curve when an account would be counted twice.**

## Accomplishments

- `portfolio_returns` computes D-06 returns from replayed per-key equity. A deposit steps the dollar curve and does not enter the return. A join is not a return. A carried key keeps its last level with r = 0, never $0.
- The derive job upserts that payload unchanged (`version` 2, `returns` as `{date, r}` in ascending ISO order).
- `account_identity_collisions` refuses an overlapping known account over the counted set. A `duplicate` marker deletes the curve only while its holder is working. A `composite_member` non-holder is excluded and the payload stays trustworthy.

## Decisions Made

- Carry follows the dollar curve's seam rule. `segment_coverage` marks only a disjoint handoff as rotated out. A key that ends while another key continues is still held, so its last level carries with r = 0. A rotated-out key contributes nothing after its last day.
- Plan 09 cannot rely on clipping alone. If a departed key's window still overlaps another counted key, `portfolio_returns` will carry it. Plan 09 has to classify those keys as rotated out inside `portfolio_returns`, not only in the seams it passes to `allocator_equity_curve`.
- The counted set for this plan is the eligible live keys as open intervals (`first_counted_day` and `last_counted_day` both None). Two open intervals on one known account always overlap.
- SC-3 is not checked off in REQUIREMENTS.md. Plans 09, 10 and 11 declare it too.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Composite non-holders stay eligible so their key_inputs rows are not deleted**
- **Found during:** Task 2 (identity gate)
- **Issue:** Removing a composite member from `eligible_ids` before the loaders would also mark its `key_inputs` row as an orphan. The key is still eligible; only the compose must skip it.
- **Fix:** The counted set is `eligible_ids` minus those members. Orphan cleanup still uses eligibility. The member's row is asserted to survive.
- **Files modified:** `analytics-service/services/job_worker.py`, `analytics-service/tests/test_derive_allocator_equity_job.py`
- **Verification:** `test_composite_member_counted_once_and_trustworthy` passed
- **Committed in:** `138222506`

**2. [Rule 2 - Missing Critical] A blank venue id is unknown, not a shared account**
- **Found during:** Task 2 (collision helper)
- **Issue:** The plan says NULL ids do not collide. A blank or whitespace id is non-NULL and would group every unstamped key into one collision and delete their curves.
- **Fix:** `account_identity_collisions` skips a venue id that is not a non-blank string. Two blanks do not collide.
- **Files modified:** `analytics-service/services/job_worker.py`, `analytics-service/tests/test_derive_allocator_equity_job.py`
- **Verification:** `test_account_identity_collisions_intervals` passed
- **Committed in:** `75b1ebca1` (the assertion); the skip itself is in `138222506`
