# 167.1.2-01 (HIDE, PR A): silent-failure review, round 1

Scope: the 14 non-planning files in `git diff origin/main...HEAD` at `fb24fb49d`. I read the
producer gate (`derivePhase07Fields`), both consumers (`AllocationDashboardV2`,
`ScenarioComposer`), the new panel, every changed test, and the e2e gate. I then traced every
other reader of the allocator equity stores in `src/` and `analytics-service/`.

**What holds.** The producer gate is real. `equityDailyPoints` is `[]` for every allocator, and
both payload branches spread the same `phase07` object. The Overview's `isRebuilding` branch is
checked BEFORE the warm-up fallback. The factsheet memo returns `null`, so no KPI is computed.
`scenarioOwnBookDelta` goes undefined through the existing `< 2` guard and is not duplicated.
The Scenario disclosure is pinned by a test. The new tests carry positive controls: the `"ready"`
case renders the curve and the Sharpe label with the same mocks, and the derived-row fixture
asserts `equityCurveSource === "derived"` so the empty series is the gate, not an absent input.
`ScenarioFactsheetChart` never drew an own-book line from `equityDailyPoints` (it is accepted for
call-site symmetry only), so the only own-book number that reached the user was the delta, and
that is gone.

## SFH-01 (HIGH): the "fail-closed" default is fail-OPEN for any value other than the literal `"rebuilding"`

**Location:** `AllocationDashboardV2` (the destructure default `equityHistoryState = "rebuilding"`
and `const isRebuilding = equityHistoryState === "rebuilding"`). `ScenarioComposer` has the same
pair (`equityHistoryState = "rebuilding"`, `isOwnBookRebuilding = equityHistoryState === "rebuilding"`).

**Issue.** A destructuring default fires only on `undefined`. The gate then tests equality with
the one literal `"rebuilding"`, so every other value shows the curve:

- `null`. This is the likeliest future shape, because plan 11 reads DB-backed readiness. A
  nullable column or RPC field serialises to `null`, the default does not fire, `null !==
  "rebuilding"`, and the curve and factsheet render.
- Any new state plan 11 adds (it already names reasons such as `duplicate_account` and
  `account_identity_pending`). If one of them ever lands in this field instead of the separate
  reason field, it shows the curve.
- A casing or typo drift across the RSC boundary (`"Rebuilding"`).

The interface comment and the test name both say "fail-closed", but the code only fails closed
for a missing key. The test (`a payload WITHOUT equityHistoryState is treated as rebuilding`)
covers `undefined` only, so it cannot catch this.

**Hidden errors:** a producer regression that emits `null`, an unrecognised state, or a
mis-cased string. Each one silently re-exposes the double-counted curve and every KPI built on it,
which is the exact number D-02 exists to hide.

**Recommendation.** Gate on the ONE value that permits display, in both consumers:

```ts
// fail-closed: only an explicit "ready" may show the curve
const isRebuilding = equityHistoryState !== "ready";
```

Keep the destructure default or drop it; either works once the comparison is inverted. Add one
case to each consumer's test that passes `equityHistoryState: null as never` (and an unknown
string) and asserts the rebuilding panel or disclosure renders. Neuter check: revert to
`=== "rebuilding"` and the new case goes RED.

## SFH-02 (HIGH, needs a scope decision): `/compare` still shows per-holding return, Sharpe, max DD and vol built from the same `allocator_equity_snapshots` store

**Location:** `src/app/(dashboard)/compare/lib/holding-compare-adapter.ts` (`fetchHoldingCompareItem`
and `reconstructAndAnalyze`), rendered by `CompareTable` and `HoldingFactsheet`.

**Issue.** D-02 hides "the curve and every number derived from it" because the snapshot store
can count one exchange account twice and reads $-level changes as returns. The `/compare` holding
item reads `allocator_equity_snapshots.breakdown[symbol]` and computes
`values[i] / values[i-1] - 1`, then cumulative return, Sharpe, vol and a running-peak max DD.
It skips `$0` rows, so the no-sync-day defect does not reach it. The account-identity defect does:
a second key on the same account, or a key joining or leaving, doubles or halves a symbol's
breakdown value, which reads as a +100% or -50% day. Level ratios also read deposits as returns.
The code even documents itself as "a SECOND read boundary on allocator_equity_snapshots".

The plan's success criterion is scoped to "My Allocation", so this is not a defect against the
plan's letter. It is the same wrong-number-the-allocator-can-act-on class that D-02's reason
names, on another surface, and nothing in plan 01 or plan 11 mentions it.

**User impact.** An allocator who opens `/compare` on a holding still sees a Sharpe and drawdown
built from the store the Overview now calls "not reliable", with no disclosure.

**Recommendation.** Take one of these explicitly rather than leaving it silent:
(a) extend the D-02 gate to the holding compare item: return a "being rebuilt" state instead of
the analytics while the history is rebuilding; or (b) record in CONTEXT that the `/compare`
per-holding analytics are out of D-02 scope, with the reason, and name the plan that owns them.
Related, INFO only: `analytics-service/routers/match.py` (`_load_holding_portfolio_context`)
builds per-symbol returns from the same `breakdown` for the correlation-ceiling holding flags,
which feed `flaggedCount` in the InsightStrip. That signal is indirect and server-side, but it
belongs in the same decision.

## SFH-03 (MEDIUM): the raw withheld series still ships to the browser on every payload

**Location:** `derivePhase07Fields` still returns `equitySnapshots` (`asof`, `value_usd`,
`breakdown`, `source`, `history_depth_months`) untouched. The payload is spread into the client
tab shell and re-sent on the 30s `router.refresh()` poll.

**Issue.** The gate comment says the curve "is withheld here, at its one producer". But the raw
per-day `value_usd` levels the curve was built from, and the per-symbol breakdown, still cross
the RSC boundary to the client in full. No client component reads them today (a grep of `src/`
outside `queries.ts` and tests finds none), so nothing renders. However:

- The "one producer" invariant is false. The payload carries two representations of the withheld
  history, and only one of them is gated. A future widget, a debug panel, or a CSV/export
  affordance that reaches for `equitySnapshots` bypasses D-02 with no test failing.
- The unused array is serialised on every poll, so each 30s refresh re-sends up to the full
  snapshot history.

**Recommendation.** Compute `snapshotCount` and `minHistoryDepthMonths` from the snapshots first
(already the case), then return `equitySnapshots: []` while rebuilding, under the same
`equityHistoryState` switch. Plan 11 says "Keep `equitySnapshots` on the payload for its other
readers". Before plan 11 relies on that, name those readers: none exist in `src/` today. Add a
producer test asserting `equitySnapshots` is `[]` while rebuilding. If the field must stay for a
reason I did not find, record that reason beside the gate.

## SFH-04 (MEDIUM): the 115.1 safety pins now assert a constant, so the fallback logic they guarded is unguarded until plan 11

**Location:** `src/lib/queries.my-allocation.test.ts` (`115.1 equity display-repoint`: the
MALFORMED T-115.1-18 cases, "never NaN", B2 empty curve) and `src/lib/queries.test.ts`
(`derivePhase07Fields — is_trustworthy → equityCurveSource flip`).

**Issue.** Before this PR, those cases pinned the CONTENT of the display series: the derived curve
is mapped directly with no forward-fill, a malformed row falls back to the byte-identical legacy
render, and there is never a NaN. They now assert `equityDailyPoints` is `[]`, which the gate makes
true for every input. The `equityCurveSource` assertions survive, so the source-selection decision
is still pinned. What is no longer pinned is the content of `candidateEquityDailyPoints`: the
no-NaN guarantee, the direct mapping, and the legacy adapter output. A regression in
`extractTrustworthyDerivedCurve` or in the candidate computation now passes every test, and it
surfaces only when plan 11 flips the state to `"ready"`.

This is the "a test that cannot fail is worse than none" class, scoped to a data-integrity gate.
Plan 11 says it will "keep the existing malformed-shape tests, moved to the new name". That covers
the extractor, not the legacy-adapter content pins, which plan 11 deletes together with the
branch.

**Recommendation.** Pick one and say which in the SUMMARY:
(a) keep the content pins alive by asserting on `extractTrustworthyDerivedCurve(...)` directly
(it is already a named function), so the NaN, malformed and empty-curve cases still bite; or
(b) state in the test comment that the legacy content pins are retired with the legacy branch in
plan 11 and that the extractor pins move there, rather than "plan 11 restores the content pin",
which plan 11's text does not promise for the legacy half.

## SFH-05 (MEDIUM): two messages about the same history contradict each other, and the panel's copy is wrong for a new allocator

**Location:** `EquityHistoryRebuilding` body copy; `BaselineUnknownBanner` in
`AllocationDashboardV2`; the Scenario disclosure line.

**Issues.**

1. `BaselineUnknownBanner` still renders above the rebuilding panel when
   `equityBaselineUnknown`. It says "a full performance history builds up from here as daily
   snapshots accrue". Directly below it, the panel says the history is withheld because it is not
   reliable. The banner promises a curve that accrues with time, while D-02 withholds the curve
   regardless of how many snapshots accrue. The founder criticised this same wrong-reason class in
   the warm-up copy, and plan 01 fixed it there but not here.
2. The panel opens "The earlier chart added up snapshots from several keys." It also renders for
   an allocator who never had a chart: a first-connect allocator with `hasSyncing` true and no
   holdings yet passes the `holdingsEmpty && !hasSyncing` guard, and so does a single-key
   allocator. For them "the earlier chart" and "from several keys" are false statements.
3. The Scenario disclosure ("Your book's own history is being rebuilt …") renders in book mode for
   every allocator, including one with no connected book, because the producer now sends `[]`
   unconditionally and the client cannot tell "withheld" from "none".

**Recommendation.** (1) While rebuilding, suppress `BaselineUnknownBanner`'s history promise, or
give it a variant that does not promise accrual. (2) Make the panel copy true for every recipient,
e.g. "The equity chart could count one exchange account twice or read a day with no sync as zero,
so it is hidden while we rebuild it. Holdings and AUM on this page are current." (3) Gate the
disclosure on the allocator having a book (non-empty `holdingsSummary`) as well as rebuilding.
Each is a copy or condition change and needs no new data.
