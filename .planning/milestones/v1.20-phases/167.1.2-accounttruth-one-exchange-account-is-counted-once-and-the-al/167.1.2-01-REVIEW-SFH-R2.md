## SFH-R2-01 (MEDIUM, user-facing, regression introduced in this round): the Scenario disclosure is now silent for an allocator whose own book came from the derived curve

**Location:** `ScenarioComposer.tsx`, the `scenario-ownbook-rebuilding` condition
`isOwnBookRebuilding && !isBlankMode && snapshotCount > 0`. The comment says: "with no snapshot
there is no own-book history to withhold".

**Issue.** That premise is false for one real input. `snapshotCount` counts TRUSTWORTHY
`allocator_equity_snapshots` rows. The own-book series the composer used before D-02 is
`candidateEquityDailyPoints = derivedCurve ?? legacy`, and `derivedCurve` comes from the
`allocator_equity_derived` row (`extractTrustworthyDerivedCurve`). It does not come from the
snapshots. So an allocator with a trustworthy derived row and zero trustworthy snapshots had an
own-book comparison (`scenarioOwnBookDelta`) before PR A. One example is a terminus-clamped book,
where every historical row is flagged `pre_terminus_balance_unknown`, before a daily-refresh row
has landed. D-02 withholds that comparison, and this round's new condition hides the sentence
that explains why. The comparison just disappears.

This is the same "cannot tell withheld from none" problem SFH-05(3) raised, answered with a
proxy that misses one of the two sources. The case is rare today, because the per-key backfill
has not run for most keys. It becomes common exactly when plan 10/11's derived rows land, and
that is before the flip to `"ready"`.

**Hidden error:** a withheld own-book comparison with no explanation, on the surface D-02 says
must "say so rather than leave a silent gap".

**Recommendation.** Plan 11 must see this. Key the disclosure on what the producer would have
shown, not on one of its two inputs. `equityCurveSource` is already on the payload and is
`"derived"` exactly when `derivedCurve !== null`:

```tsx
const hadOwnBookHistory =
  snapshotCount > 0 || payload.equityCurveSource === "derived";
{isOwnBookRebuilding && !isBlankMode && hadOwnBookHistory && ( ... )}
```

Fix the comment to name both sources. Add one case: `snapshotCount: 0` with
`equityCurveSource: "derived"` shows the disclosure. Neuter check: drop the `||` arm, and the
case goes RED.

## SFH-R2-02 (pre-existing, user-facing, NOT a regression, noted because the brief asked "still swallowed elsewhere"): `/compare` turns query failures into "not available"

**Location:** `compare/page.tsx`. The strategies read,
`((strategiesRes as { data }).data ?? [])`, never inspects `strategiesRes.error`. The holding
read now logs its error (INFO-02) but still returns `null`.

**Issue.** When either query fails (RLS regression, PostgREST outage, timeout), the page shows
the generic "not available" state. The allocator is told the strategy or holding does not exist,
or is not theirs. The strategies error is not even logged. D-15 does not need this: a query
error happens whatever the ownership is, so throwing to the route's error boundary leaks
nothing. It would also give the allocator a retry instead of a false "not available".

**Recommendation.** Plan 01 does not need to fix this. It predates the phase (last touched in
Phase 159), and the fix round only added the holding log. Book it as fix-or-drop. Check
`strategiesRes.error` and throw. Have the adapter throw on `error` rather than return `null`,
and keep `null` for "no rows / unowned".
