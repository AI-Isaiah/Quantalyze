### WR-02 / SFH-C3R2-03: two reasons that are holds were classed as waits

**Files modified:** `src/app/(dashboard)/allocations/components/EquityHistoryRebuilding.tsx`, `src/app/(dashboard)/allocations/components/ScenarioComposer.tsx`, `src/app/(dashboard)/allocations/components/ScenarioComposer.test.tsx`
**Commit:** `47609db3b`
**Status:** fixed: requires human verification. The fix adds one new user-facing sentence (DESIGN.md Voice), and the founder has not reviewed it yet.

**The rule applied** (from the orchestrator's brief): a reason stays "rebuilding" only if the Overview's OWN line for it promises a daily run. If that line says the history is held back or not shown, and names no run that heals it, the reason moves to a fourth class, `held_back`.

**Decision per reason, quoting the Overview line (`REASON_LINE`, unchanged):**

| Reason | Overview line | Class | Why |
|---|---|---|---|
| `account_identity_pending` | "We are confirming which exchange account each key reads. Each daily sync checks it again." | `rebuilding` (unchanged) | The line names a daily run that retries it. |
| `awaiting_derivation` | "Your history is recomputed from each account's returns and cash flows once a day." | `rebuilding` (unchanged) | The line promises the daily recompute. `queries.ts` (`MissingSeriesReason` doc) agrees: "Only `awaiting_derivation` is answered by the daily recompute". |
| `derivation_rejected` | "The latest rebuild of your history did not pass its checks, so it is not shown." | **`held_back`** (moved) | The line promises no recompute and says the history "is not shown". The comment above it reads "is not a wait on the daily recompute, so neither line names one", and `queries.ts` says a rejected v2 row "must not be shown as a wait". |
| `shared_account_history_truncated` | "One of your exchange accounts changed keys, and we cannot join its history from before the change to the new key's yet, so your history is not shown." | **`held_back`** (moved) | The line says "not shown". Its comment reads "No action is named because none heals it in this release". Nothing is being rebuilt. |

**The reviewers disagreed on `derivation_rejected`.** The SFH reviewer (SFH-C3R2-04) said the compose reruns on every key refresh, so "being rebuilt" is fair. The code reviewer (WR-02) cited the C2 rule that a rejected row is not a wait. The brief's tie-break is the Overview's own line. That line promises no recompute, so the reason is `held_back`. The SFH argument is still true about the machinery: a rerun does happen, and it may be rejected again. But the Overview deliberately does not tell the owner to wait, so the Scenario must not either.

**What changed:**
- `REBUILD_REASON_CLASS` gains `held_back` and moves both rows into it. It stays the one place a reason is classed, and it still carries its `satisfies Record<EquityHistoryRebuildReason, …>` exhaustiveness.
- The class doc no longer claims "being rebuilt" is true for a hold. It defines each class by what the reason's own Overview line says, and it quotes those lines.
- `OWN_BOOK_REBUILDING_LINE` (typed `Record<EquityHistoryRebuildClass, ReactNode>`) gains the `held_back` sentence:
  > We are holding back your book's own history, so the comparison with your current book is not shown.

  The sentence uses active voice (DESIGN.md Voice). It has no em dash, no wait, no date or day count, and no "appear once". It carries the Overview's meaning ("so it is not shown") and makes no new claim. It is one sentence, like the other three classes, and it does not point at the Overview. The class doc's fail-closed arm is unchanged: an unknown or absent reason still reads as the generic `rebuilding` wait, never as `held_back`.

**Test changes (hand-written table, not read from the classifier):**
- `REASON_CLASSES` moves both rows to `held_back`, and its type union gains `held_back`. The compile-time "every reason listed" check is unchanged.
- `SCENARIO_LINE_BY_CLASS` gains the `held_back` sentence as a literal.
- The parity arm gains two assertions tied to the rule itself. The Scenario says "being rebuilt" exactly when the class is `rebuilding`. The Overview panel's text names a daily run (`/\bdaily\b|once a day/i`) exactly when the class is `rebuilding`. The panel's heading and body name no daily run, so that match comes from the reason line alone. A misclassed reason fails this arm. So does an Overview line that starts or stops promising a daily run while its class stays put.
- `held_back` asserts no Exchanges link and no "reload" on either surface. That comes from the existing assertions (`needsAction` and `readFailed` are both false).

### IN-01 (R2): the Overview's `REASON_LINE[reason]` lookup had no guard

**Files modified:** `src/app/(dashboard)/allocations/components/EquityHistoryRebuilding.tsx`, `src/app/(dashboard)/allocations/components/ScenarioComposer.test.tsx`

**Status:** fixed

- A single guard, `isKnownRebuildReason` (`reason != null && Object.hasOwn(REBUILD_REASON_CLASS, reason)`), now feeds both `equityHistoryRebuildClass` and the Overview panel. The panel computes `knownReason` once and branches on it. An unknown reason or a prototype key fails closed to the generic line: exactly the no-reason panel (heading and body, no reason line).

The count assertion catches the empty `<p>`. The console-error assertion catches the function passed to React as a child.
