## Warnings

### WR-01: The twin test silently pins against a stale body when a later migration redefines the fan-out in a form its regex does not match

**Severity:** MEDIUM · **Confidence:** 6/10
**File:** `src/__tests__/history-reconstruct-note-predicate-twins.test.ts:54-55` (`FN_RE`) and `:66-80` (`newestFanoutBody`). The Python twin has the same selection logic: `analytics-service/tests/test_fanout_owed_predicate_twins.py:57-80`. It predates this diff.

**Issue:** `newestFanoutBody` sorts the migrations and takes the last body that matches `FN_RE` **and** contains `v_reconstruct_attempt_cap`. `FN_RE` matches only one exact form: `CREATE OR REPLACE FUNCTION public.enqueue_refresh_allocator_equity_for_all()` with an unnamed `AS $$ ... \n$$;` delimiter.

A later redefinition is skipped without any message, and the test pins against `20261018120000`'s body instead, if it does any of these:

- uses a named dollar tag (`AS $fn$`, `$function$`). 37 migrations in this tree already use named tags.
- omits the `public.` qualifier.
- writes the closing `$$;` on a line with leading whitespace.
- renames the cap constant.

The test's own "loud failure, never a vacuous pass" guard only fires when **no** file matches. Because `20261018120000` always matches, that guard can never fire once a newer definition exists.

**Scenario:** A later phase adds a term to the fan-out's `ck` and `rk` counts, for example a new non-retryable `sync_status`, in a migration that uses `AS $fn$`.

- Both twins keep classifying the 20261018120000 body and stay green.
- The Overview note keeps naming keys in the new state, which the fan-out no longer counts.
- That is the round-1 WR-02 false "could not be rebuilt" note, re-entered through exactly the drift event this test exists to catch.

The same applies to the Python refresh hold's owed predicate.

**Fix:** Bind the parsed body to the real newest definition, not to the newest body the regex can read. Either of these works:

```ts
// (a) Fail when any later migration mentions a CREATE of the function that FN_RE did not parse.
const DEF_ANY = /CREATE\s+(OR\s+REPLACE\s+)?FUNCTION\s+(public\.)?enqueue_refresh_allocator_equity_for_all\s*\(/i;
const newestDefFile = files.filter((f) => DEF_ANY.test(stripSqlComments(read(f)))).at(-1);
expect(parsed.file, `newest definition ${newestDefFile} was not parsed by FN_RE`).toBe(newestDefFile);
```

```ts
// (b) Assert against the generated snapshot's provenance line.
// supabase/schema/functions/enqueue_refresh_allocator_equity_for_all.sql carries
// "-- source migration: <file>".
expect(parsed.file).toBe(sourceMigrationFromSnapshot);
```

Also loosen `FN_RE` to accept any dollar tag (`AS\s+\$(\w*)\$([\s\S]*?)\$\1\$`). Apply the same change to `_newest_fanout_body` in the Python twin.
