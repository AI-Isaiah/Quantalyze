## The data-integrity core: a marker is never stamped on a failed or partial reconstruct

The only call to `_mark_api_key_history_reconstructed` is at the normal completion ladder, guarded by `audit_kind != reconstruct_unexpected_noop`, immediately before that exit's `_emit_audit`. Every earlier exit (preflight failure, Deribit, rate limit, crawl timeout, any crawl exception, the persist-phase exception, the MT5 failure arm) returns before it, so none can mark. The short-circuit never reaches it and performs no UPDATE on `api_keys` (Test 3b asserts the fake recorded none). The `EmptyReplaceRefusedError` and `purge_refused` paths fall through to the ladder as `reconstruct_no_data` and are marked, as the plan specifies. Grep: `grep -a -c "_mark_api_key_history_reconstructed("` is 2 (definition and the one call).

## Deviations from Plan

### Auto-fixed / judgment calls

**1. [Rule 3 - Blocking] Existing reconstruct tests needed an `api_keys` row for the key under reconstruction.**
- **Found during:** Task 1, first run after the writer landed (about 14 existing tests went FAILED).
- **Issue:** the writer correctly fails the job when its UPDATE matches no row, and most existing reconstruct tests never seeded an `api_keys` row (the preflight is faked).
- **Fix:** `_install_fake_preflight` (in `tests/test_equity_reconstruction.py`) now `setdefault`s the requested key's row, for `reconstruct_allocator_history` jobs only (a refresh job would gain a phantom eligible key) and never over a row a test seeded. The sibling count excludes the key itself, so no sole-key semantics changed. Separately, the head-request shim `_head_request_without_count_header` replaced the whole `api_keys` table and now answers only `select(..., head=True)`; other calls go to the real fake.
- **Files:** `analytics-service/tests/test_equity_reconstruction.py`. **Commit:** `9a48006a7`.

**2. [Plan wording] Neuter (a) of Task 2 does not turn Test 7 RED.** The plan says dropping the `attempts >= 1` term turns Test 7 RED; it does not (Test 7's key has attempts 1, which satisfies both bounds). Dropping that term turns the never-attempted case (Test 10) and the eight in-flight cases RED (N7a). Test 7's own neuter is removing the retryable branch (N7b). Both are recorded above.

**3. [Rule 2] A failed marker write emits a `reconstruct_failed` audit.** The plan said only "returns FAILED/transient", and "no completion audit". Every other failure exit emits `reconstruct_failed`, and M1's `newest_outcome` filters on success actions plus `unexpected_noop` only, so a failed event cannot mark or unmark a key. The static message names no id.

**4. [Plan wording] "after closing the exchange".** The exchange is already closed by the crawl's `finally` before the persist phase, so the failure branch has nothing to close.

**5. [Convention] Existing tests updated, none deleted.** `test_m076_reconstruct_short_circuits_when_same_api_key_already_done` now seeds the marker instead of a `done` row (docstring cites B1 and the inverse test); `test_reconstruct_idempotent` no longer seeds a `done` row, it asserts the first run set the marker and lets the second short-circuit on it.

**6. [Naming] Hold audit count key** renamed `inflight_reconstructs` to `owed_reconstructs` (it counts the union of owed keys now). `git grep` shows no reader of either key.

**7. [Convention] Pre-commit branch allow-list.** The generic executor guard expects an `agent-*` branch; this worktree's branch is the orchestrator-provisioned `wt/167.1.2.1-p05`. Not detached, not protected, cwd matches the worktree toplevel, and the instruction named the branch. Same convention as plans 01-03. Commits went on it with explicit paths.
