## What was built

- `_utc_now()` in `job_worker.py`: aware-UTC clock seam.
- `_btc_closes`: declared beside `_mt5_unit`; loaded by one `await get_btc_closes()` per derive, only when the unit is BTC, before either `_persist_account_unit` call (key mode and strategy mode share it).
- `_persist_account_unit`: for a native unit writes `account_balance_native = equity`, `account_balance_usdt = priced[0]` and `account_balance_usdt_close_date = priced[1].date().isoformat()` from `price_live_balance(equity, code, _btc_closes, _utc_now())`, else both None. The PGRST204 log text now names the close-date column. The info log carries the unit code and a priced flag, never an amount.
- `_fetch_mt5_account_balance`: unchanged behaviour; a comment names this plan and the COALESCE reason.

## Deviations from Plan

**1. [Rule 1 - Bug] A non-BTC native key-mode code would have been priced with BTC closes**
- **Found during:** Task 2 (wider regression run of key-mode tests)
- **Issue:** key-mode wraps a floorless currency (EUR, ETH) as `AccountUnit(native=True)`. The plan's "for a native unit" branch would have priced 12345.67 EUR with a BTC close (764,814,256.5 in the neuter run), a confident wrong USD figure (T-164.6.6.2.1-17).
- **Fix:** `_BTC_PRICED_UNIT = "BTC"` gates both the closes load and the pricing call; any other native code stores the NULL pair and never reads the closes.
- **Files modified:** `analytics-service/services/job_worker.py`
- **Commit:** `cf25b0b16`
