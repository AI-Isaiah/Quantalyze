Accent reserved for: the alpha line, the net-exposure line, the gross-exposure area (opacity 0.2), the turnover line and the correlation line. Nothing else this phase adds is accent-coloured.

The header "Verified" chip is **not** accent: `VerifiedBadge` renders `text-positive`, i.e. `#15803D` (positive green, 5.12:1 on white), the DESIGN.md colour for "gains, verified status, success". It is unchanged; this phase only makes it appear for an `api_verified` strategy (Defect 5).

Text colour rules for this phase:
- Say-why lines and captions: `text-text-muted` (`#64748B`, 4.85:1 on white).
- Sub-section eyebrows: `text-text-secondary` (existing).
- An em dash: `text-text-primary`, never `text-negative` (DESIGN Semantic-color gates: a dash is colourless). `MetricCell` already gets this right because `isNeg` is false for null and non-finite values; keep it.
- Chart text fills: only `CHART_TICK_STYLE` (`#64748B`).
- **Recorded deviation, not changed:** the header chip `VerifiedBadge` renders `text-xs font-medium` (weight 500). The v2 contract allows weights 400 and 600 only, but the chip lives in `src/components/ui/VerifiedBadge.tsx`, outside `strategy-v2/**`, so the type-scale gate does not walk it, and it is shared with other surfaces. Defect 5 makes it visible on v2 for the first time for API-verified strategies. 170.5 does not edit it (PATTERNS: do not edit `VerifiedBadge`); route the weight to 170.6 DISPLAYPOLISH. `#94A3B8` and `#718096` are forbidden as a text fill (`tests/a11y/chart-contrast.test.ts`).

**Tone and sign come from the rounded value** (DESIGN.md Numbers Contract: "the sign taken from the ROUNDED value, so a value that rounds to zero shows no sign and the neutral colour"). For the five greek cells, which this phase reformats anyway:
- the formatter rounds first (to 2 dp, or to 2 dp of the percent for alpha) and normalises `-0` to `0`;
- `negative` is true only when the **rounded** value is below zero. `-0.004` prints `0.00` in `text-text-primary`, never `-0.00` in red; `-0.005` prints `-0.01` in red; alpha `-0.00004` prints `0.00%`, neutral.
- The tone flag is computed from the same rounded number the cell prints, in `strategy-v2/format.ts`, so text and colour cannot disagree.

**Collision note (170.6 DISPLAYPOLISH):** 170.6 owns signed zero and red-for-non-negative everywhere else on the page (`MetricCell` consumers in other panels). 170.5 applies the rounded-value rule only to the five cells it reformats; 170.6 rebases onto it and must not reintroduce `isNeg` on the raw value for these cells.

## Panel contracts

### 1. Rolling alpha and beta (Defect 1, D-01)

**Primary anchor (Panel 5, this sub-section):** the chart, or in its place the 250px say-why block. Either one occupies the same box, so the reader's eye lands in the same place whether the figure exists or not; the caption above it is secondary.

**Placement:** the fourth sub-section of Panel 5 "Rolling metrics", after Rolling Sortino. Title unchanged: `Rolling alpha & beta` (pinned by `RollingMetricsPanel.test.tsx:356`). The 3M / 6M / 12M toggle stays (D-01).

**Rolling-window caption (always shown, chart or say-why):**

> `90-day rolling window, paired with BTC. The 3M / 6M / 12M toggle sets the charts above, not this one.`

- Rendered by `SubChartSection` through a new optional `caption` prop. When `caption` is set, the `h3` uses `mb-1` instead of `mb-4` and the caption is `<p className="mb-4 text-xs font-normal text-text-muted">`. Sections without a caption render exactly as today.
- Only the alpha and beta section passes a caption. The volatility, Sortino and Sharpe sections are unchanged (window-label mismatch is Q7, routed to 170.1).

**Draw rule:** draw `RollingAlphaBetaChart` only when the merged series holds **at least 2 points with a finite value** (alpha or beta). Otherwise render the say-why body. A 1-point series (exactly 90 paired intervals) says why; it is never a blank chart (RESEARCH Pitfall 2). When it draws, the panel passes `data?.rolling_alpha` and `data?.rolling_beta` by reference, unchanged (Test 15).

**Say-why body (fixed height):**

```tsx
<div className="flex items-center" style={{ minHeight: 250 }} data-testid="rolling-alpha-beta-why">
  <p className="text-xs font-normal text-text-muted">{message}</p>
</div>
```

Left-aligned (DESIGN: a report is left-anchored), vertically centred in a 250px block, no border, no icon, not focusable, no `aria-live` (the text does not change on toggle, so it is not a status change).

**Reason ladder (first match wins, same text at 3M, 6M and 12M):**

| # | Condition | Exact copy |
|---|-----------|------------|
| 1 | `parseReturnsUnit(data_quality_flags.native_unit)` returns a unit `{unit}` | `Not paired with BTC: returns are in {unit}.` (composes `nativeUnitReason(unit)`) |
| 2 | `data_quality_flags.benchmark_unavailable === true` | `BTC benchmark prices were unavailable when this strategy was last computed.` |
| 3 | `history_days < 91` | `Not enough history for the 90-day rolling window: needs 91 days paired with BTC; this strategy has {M} days of history.` where `{M}` is `history_days` |
| 4 | otherwise | `Rolling alpha and beta are not computed for this strategy.` |

Why "days of history" and not "paired days": `history_days` is an upper bound on the paired count (RESEARCH A6), so the sentence names what `{M}` measures. No rung says "yet": none of them can promise the figure will arrive. Why 91 in rung 3: the series is one point per day after the first 90 paired intervals, and a line needs 2 points, so 91 days is the true threshold to draw. The caption carries the window (90); the reason carries the threshold (91). `{M}` is printed as an integer with no separator below 1,000 and a thousands separator from 1,000 (DESIGN Numbers Contract, integers).

Constants: `BENCHMARK_ROLLING_WINDOW_DAYS = 90` in `src/lib/min-history.ts`; the 91 is derived as `BENCHMARK_ROLLING_WINDOW_DAYS + 1`, never typed as a literal in copy.

### 2. Benchmark greeks (Defect 2, D-07)

**Source:** the factsheet's live TypeScript joint (`jointMetrics` over the BTC-paired daily returns, the composition PATTERNS.md section D-07 names). Stored Python greeks are not displayed. The five figures equal the factsheet's §IV "Joint Metrics" rows for the same strategy at the default view (cash basis, leverage 1x).

**Primary anchor (Panel 7):** the five 18px Geist Mono semibold greek figures (`MetricCell` values, `text-lg font-semibold`). They are the only 18px text in the panel; charts, captions and every say-why line sit at 12px below them in emphasis.

**Layout decision: correlation becomes a fifth cell in the greeks strip.** It does not go into the "Correlation with BTC" sub-section.

Reasons:
1. The factsheet groups correlation with alpha, beta, IR and Treynor in one block computed from the same paired days and withheld by the same causes. One strip means one reason line covers all five, exactly as the factsheet's one `withheldReason` covers its block.
2. The "Correlation with BTC" sub-section draws the **90-day rolling** series, a different quantity from the full-record correlation scalar. Putting the scalar on top of it would invite reading one as the other.

**Grid:** `grid grid-cols-5 gap-3 max-md:grid-cols-3`. This replaces `grid grid-cols-4 gap-3`. The `max-md:grid-cols-3` step copies the existing v2 strip idiom (`HeadlineMetricsPanel.tsx:220`, `OverviewPanel.tsx:59`: `grid-cols-6 gap-3 max-md:grid-cols-3`), so five 18px mono figures never squeeze below `md`. `BenchmarkGreeksTable.test.tsx` Test 1 (the `grid-cols-4` pin) is edited with a dated comment naming D-07 and this spec; the assertion moves to the new class string and the five labels. It is not loosened to "any grid".

**Cells, in factsheet order:**

| # | Label (verbatim) | Value format | Negative tone |
|---|------------------|--------------|---------------|
| 1 | `alpha (ann)` | signed percent, 2 dp: `+12.34%`, `-3.10%`; a value that rounds to zero prints `0.00%` with no sign | yes, when the rounded value is below zero |
| 2 | `beta` | 2 dp: `0.38`; `-0.004` prints `0.00` | yes, when the rounded value is below zero |
| 3 | `correlation` | 2 dp: `0.40` | yes, when the rounded value is below zero |
| 4 | `IR` | 2 dp | no (existing rule: IR is never sign-flagged) |
| 5 | `Treynor` | 2 dp | yes, when the rounded value is below zero |

Label casing follows the existing convention (lowercase Greek letters and common nouns, `IR` acronym, `Treynor` proper noun). `alpha (ann)` carries the factsheet's annualisation qualifier because the value is now the factsheet's annualised alpha.

**Formatting module:** the two formatters live once, in a v2 formatter module `src/components/strategy-v2/format.ts` (`fmtSignedPct2`, `fmtNum2`), each returning `null` for a non-finite input so `MetricCell` prints the em dash. Their digits and decimal places are the factsheet's `pct(v, true)` and `num(v)` (`MetricsColumn.tsx`, module-private there), so a non-zero figure prints the same string on both pages; they add the DESIGN.md rounded-sign rule (a value that rounds to zero prints unsigned, `0.00` / `0.00%`). Each returns `{ text, negative }` with `negative` computed from the rounded number. A unit test pins: `0.123456` -> `+12.35%`; `0.38412` -> `0.38`; `-0.004` -> `0.00`, not negative; `-0.005` -> `-0.01`, negative; `NaN` -> `null`. Do not inline `toFixed` in `BenchmarkGreeksTable` (DESIGN: one formatter module per surface family).

**Reason line:** a sibling `<p className="mt-2 text-xs font-normal text-text-muted" data-testid="greeks-reason">` directly under the strip, rendered only when at least one of the five cells is an em dash. Exactly one line. When several per-cell causes apply, join them with a space in the order of the table below.

**Withheld-joint ladder (all five cells "—", first match wins):**

| # | Condition | Exact copy |
|---|-----------|------------|
| 1 | native unit `{unit}` | `Not measurable: returns are in {unit}. A BTC benchmark measured in {unit} is a flat line.` (the factsheet's sentence, `MetricsColumn.tsx`, verbatim) |
| 2 | the BTC benchmark read returned its unavailable marker | `BTC benchmark prices are unavailable for this record.` |
| 3 | paired days below `MIN_PAIRED_OBSERVATIONS` (10) | `pairedFloorReason("BTC", paired, "record")`, which reads `Alpha and beta need at least 10 days paired with BTC; this record has {paired}.` (the factsheet's sentence, verbatim) |
| 4 | analytics not in a computed state, or any other cause | `Benchmark greeks are not computed for this strategy.` |

**No composite rung.** A composite strategy (`data_quality_flags.composite === true`) takes the builder path (`fetchAndBuildPayloadWithReason`, called from the page, PATTERNS "Alternative path"), because D-07 requires v2's greeks to be the factsheet's, and the light path cannot read a composite's series. Its cells and reasons therefore follow this same ladder; there is no composite-specific copy and no composite is withheld.

**Failure is not absence.** If the builder path (composite) or the light path's admin read fails (the call throws, or returns a not-buildable result whose reason is an error rather than a data condition), the Benchmark greeks sub-section does **not** show five dashes with rung 4. It renders the existing error state instead of the strip:

```tsx
<PartialDataBanner heading="Couldn’t load this section" body="Refresh the page to retry. The other panels still work." />
```

so a transient failure never reads as a permanent fact. Rung 4 is only for a strategy whose analytics are genuinely not in a computed state. A failed BTC price read is not this case: it returns the unavailable marker and reads rung 2.

**Per-cell causes (the joint was computed but a single ratio is undefined, `NaN` mapped to null):**

| Cell is "—" because | Exact copy |
|---------------------|------------|
| one leg has no dispersion (flat record; FACTSHEETTRUTH D-04) | `No dispersion in this record.` (replaces every per-cell line below when it applies) |
| `correlation` undefined | `Correlation reads — when either return series is flat.` |
| `IR` undefined | `IR reads — when tracking error is zero.` |
| `Treynor` undefined | `Treynor reads — when beta is zero.` |

The em dash in these sentences is U+2014, the same glyph the cell shows.

### 5. Turnover (Defect 4, D-04)

**Draw gate:** draw `TurnoverChart` only for an array of at least 2 points, each `{ date: string, value: finite number }`. The chart itself is unchanged (percent of NAV). Legacy `{ date, turnover }` rows fail the gate. Never map `turnover` to `value`.

**Say-why** (existing `SubBanner`, `text-xs font-normal text-text-muted`, replaces `Turnover unavailable for this strategy.`). The ladder runs only when the draw gate fails; data-shape rungs come first, first match wins:

| # | Condition (draw gate failed) | Exact copy |
|---|-----------|------------|
| 1 | the array holds legacy rows (any entry carries a `turnover` key and no finite `value`) | `Turnover isn’t available for this strategy: the stored turnover figures are not on a percent-of-NAV scale, so they are not shown.` |
| 2 | the array has entries (any other shape, including `{date, value}` rows and malformed entries) but fewer than 2 pass the gate | `Turnover isn’t available for this strategy: the stored series has fewer than 2 valid points.` |
| 3 | `turnover_series` absent or empty **and** `exposure_series` absent or empty **and** `data_quality_flags.csv_source === true` | `Turnover isn’t available for this strategy: it was uploaded as a CSV file, and no position-level series is stored for it.` |
| 4 | `turnover_series` absent or empty | `Turnover isn’t available for this strategy: no turnover series is computed for it.` |

Not a fixed-height block: the sub-section has no toggle, so its height does not change while the reader is on it.

## NaN to "—" rule (D-06, DESIGN Numbers Contract)

Applies to every figure, tick, tooltip value and series point on the panels this phase touches.

1. **Cells:** `null`, `undefined`, `NaN`, `Infinity` and `-Infinity` render `—` (U+2014). Never `0`, `0.00`, `NaN`, `Infinity`, `-` or blank.
2. **Boundary:** the D-07 helper maps every `NaN` from `jointMetrics` to `null` before the value leaves the server (`BenchmarkGreeks` stays `number | null`). The formatters in `strategy-v2/format.ts` return `null` for any non-finite input as a second line of defence.
3. **Tone:** a `—` is never coloured (`text-text-primary`); `negative` is true only when the **rounded, printed** value is below zero, so a value that rounds to zero is neutral and unsigned.
4. **Every `—` on these panels has a reason line within its sub-section** (greeks reason line, rolling and correlation say-why, turnover say-why). A dash without a derivable cause uses the "not computed for this strategy" rung; it never stands alone.
5. **Series:** a point with a non-finite value is dropped before charting; a series left with fewer than 2 points says why instead of drawing.
6. **Tooltips:** a non-finite hovered value reads `—`.
