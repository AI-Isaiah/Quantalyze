# Phase 170.5 Plan 04: v2 benchmark joint (D-07) Summary

`src/lib/factsheet/v2-joint.ts` computes v2's alpha, beta, correlation, IR and Treynor through the factsheet's own TypeScript chain, with a parity oracle that fails if it drifts from `buildFactsheetPayload`'s BTC joint. No caller yet; plan 06 wires it.

## What was done

**Task 1, commit `2b1d81ff8`.** `computeV2Joint(dailyReturns, benchmarkPrices, assetClass)`: `normalizeDailyReturns`, then `alignCoveredReturns` with `COMPARATOR_CALENDARS.btc`, paired indices collected as `buildComparatorBlock` collects them, the `MIN_PAIRED_OBSERVATIONS` floor, then `jointMetrics(..., 0, annualizationPeriods(assetClass))`. A NaN ratio leaves as `null`. `flatLeg` is `dispersion(...).sd === 0` on either paired leg and is a reason input only.

**Task 2, commit `93bad9db3`.** `readV2BenchmarkJoint(admin, strategyId)`: one `withPublishedOnly` read of `asset_class` plus the four series columns, then G1 (`isComputedAnalytics`), composite -> `needs_builder`, native unit -> `native_unit`, `resolveDailyReturnSeries` with `curveMethodFromFlags`, `hasBuildableSeries`, `readFactsheetBenchmark(admin, series, undefined, id)`, `computeV2Joint`. A returned or thrown admin error, and an absent row, are `error` (logged `[v2-joint] admin read failed`, captured with tags `{ stage: "v2-joint", strategy_id }`, no row data). `v2JointFromBuildResult` maps a `fetchAndBuildPayloadWithReason` result to the same status and takes the five values from the payload's own `comparators.btc.joint`.

**Task 3, commit `6e31c3370`.** One stored row (equity-curve-only `returns_series`, `cumulative_method: "simple"`) through `readV2BenchmarkJoint` and through `fetchAndBuildPayloadWithReason` + `v2JointFromBuildResult`: five figures `toBe`-equal, same paired count, and both equal the payload's own joint.
