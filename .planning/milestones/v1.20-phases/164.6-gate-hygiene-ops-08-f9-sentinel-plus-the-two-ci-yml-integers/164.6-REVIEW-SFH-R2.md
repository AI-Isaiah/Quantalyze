## New findings

- **N1 (High)**: cron-obs step (4) counts only failures whose message names the function. Missed: pg_cron startup timeouts, errors re-thrown unchanged by the outer handler (cooldown subquery, 42P01/42703, 57014, 55P03), a PROD message shape without CONTEXT, zero runs in the window, and a hung run that holds the advisory lock so every later tick skips and records `succeeded`. Fix: count by the success shape (`end_time IS NOT NULL AND return_message NOT IN ('1 row','SELECT 1')`), keep the name match as a classification column, add a `stuck` count, and raise a defect when fewer than 2 runs appear in the 3 h window.
- **N2 (High)**: the partial-failure `cron_runs` row has no reader. Fix: count-only read of `candidate_enqueue_failed` rows in the last 21 h; never read `metadata`. Preferred root fix (shared with REVIEW-R2 WR-01): drop the all-fail RAISE so the failure row always commits and the cooldown always engages; keep the raise only when the failure row itself cannot be written.
- **N3 (Medium)**: the `cron-ledger-fanout-failed` remedy sends the operator to rows the all-fail RAISE rolled back; the runbook says the opposite. Closed by the N2 root fix; otherwise add distinct SQLSTATEs to the raise message and rewrite the remedy. (Also raised as the migration-reviewer MEDIUM.)
- **N4 (Medium)**: step (4) is skipped when an earlier cron-obs step measure-fails. Fix: always run it, collect defects from every step. (REVIEW-R2 IN-02.)
- **N5 (Medium)**: no self-test drives `parseLedgerFanoutRow` to null or the step's measure-fail branch. Fix: fixtures for an unparsable answer, a psql failure and `runs:0`, each observed red when the guard is neutered. (REVIEW-R2 IN-03.)
- **L1 (Low)**: a failed failure-row write on a tick that did enqueue is silent. Two independent faults; record it.
- **L2 (Low)**: a late rejection after the 5 s retraction timeout in `keys/sync` is discarded. Fix: `.catch` on the retraction promise logging `retractionFailureCode` under a `_late` tag.
- **L3 (Low)**: 40P01 is counted as a lost race; a recurring deadlock is silent. Fix: count only 40001 as a lost race; 40P01 falls to the failure path. (REVIEW-R2 IN-05.)
