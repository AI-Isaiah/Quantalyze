# Phase 164.6 Plan 02: TS composite refresh-marker retraction Summary

**keys/sync and finalize-wizard now retract an inherited ledger-refresh marker from the `stitch_composite` job the enqueue dedup handed them, using a shared helper whose marker set is parity-pinned to Python's `LEDGER_REFRESH_JOB_SOURCES`. A failed retraction is logged and sent to Sentry under its own tag, and never fails the request.**

## Accomplishments

- `retractInheritedRefreshMarker` follows Python's `_retract_refresh_marker_on_reuse` step by step. With no job id it returns. Otherwise it reads the row with maybe-single and returns unless `metadata.source` is a marker. When it is, it writes the metadata back without `source`, adding `refresh_marker_retracted` and `correlation_id`. The JSDoc explains why the write targets `metadata->>'source'` (it has two readers, the Python honour sites and the SQL `is_protected` predicate). It also explains why the union of markers is the safe choice, and states the 161.1-D12 read-modify-write residual.
- Parity pin: `ledger-refresh-marker.test.ts` parses both `Final[str]` literals out of `job_worker.py`. It also checks that the frozenset declaration names both symbols, and throws at module scope if any part is missing. The parsed set's size and both values are pinned before the TS set is compared against it.
- keys/sync: the retraction is awaited between the enqueue log and the `sync.start` audit, inside its own try/catch. The 202 body does not change.
- finalize-wizard: the composite enqueue destructures `data: jobId`. `correlationId` is resolved before `after()` is scheduled. The retraction's own try/catch means a failure can never reject the `enqueue_sync_trades_job` side effect (RESEARCH Pitfall 15).

## Decisions Made

- The union of both markers, per D-15 and Pitfall 16. Each marker gets its own positive case, and neuter (iii) shows why: a single-marker check leaves every composite case green.
- Success logging lives at the call sites (`console.warn` with the route prefix), mirroring Python's `log.warning("…refresh_marker_retracted")`. The helper does no logging, which keeps D-18's "the caller owns error reporting" contract symmetrical.
- The finalize-wizard composite enqueue's `p_metadata` stays `{ source: "finalize-wizard" }`. Adding `correlation_id` there is not part of D-17 and was left alone.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Log a successful retraction**
- **Found during:** Task 1
- **Issue:** The plan's call-site action only covers the failure path. Python logs every retraction (`log.warning`). Without a log, the TS path would give operators no sign that a user request deduped onto a refresh job.
- **Fix:** Each site now emits `console.warn` naming the marker, the job and the strategy when the helper returns `{ retracted: true }`.
- **Files modified:** `src/app/api/keys/sync/route.ts`, `src/app/api/strategies/finalize-wizard/route.ts`
- **Verification:** The positive cases silence `console.warn` but do NOT assert the log line. The log is operator telemetry, not a data-integrity or user-facing gate, so it is not pinned; the retraction itself is.
- **Committed in:** `5bc613962`, `f0d48e0df`

**2. [Neuter form] "Comment out the call" was done as "replace the call with `{ retracted: false }`"**
- **Found during:** Task 3
- **Issue:** Commenting out the call leaves `retraction` undefined. The resulting ReferenceError would land in the new catch, so the RED would come from a crash instead of from the missing behaviour.
- **Fix:** The call expression was replaced by the value the helper returns for "nothing to do". That is the behaviour-removal the plan intends, with no crash.
- **Verification:** The tallies above. Each restore passed a silent `cmp`.

**3. [Rule 3] The parity regex spans the frozenset's multi-line declaration**
- **Found during:** Task 1
- **Issue:** The plan says "the frozenset line". In `job_worker.py` the `LEDGER_REFRESH_JOB_SOURCES` declaration spans three lines, with the symbols on the second.
- **Fix:** The regex captures everything from `frozenset(` to the closing `)`, then requires both symbol names inside that capture.
