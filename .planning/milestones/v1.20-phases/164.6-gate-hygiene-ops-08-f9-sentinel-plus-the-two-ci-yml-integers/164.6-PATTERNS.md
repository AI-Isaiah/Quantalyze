## Pattern Assignments

### 1. `src/lib/supabase/retry-serialization-failure.ts` (utility, NEW)

**Analog:** `src/lib/supabase/cast.ts`. It is a pure module with no `server-only` import and no runtime deps: a file-level JSDoc, then one exported function per concern, each with its own JSDoc. Copy that SHAPE. The body comes from RESEARCH Code Example 1:

```ts
type PgResult = { error: { code?: string | null } | null };
export async function retryOnceOnSerializationFailure<T extends PgResult>(
  call: () => PromiseLike<T>,
  onRetry: (first: T) => void, // caller console.warns (D-06); never Sentry
): Promise<T> {
  const first = await call();
  if (first.error?.code !== "40001") return first;
  onRetry(first);
  return call(); // exactly once, no sleep (D-03)
}
```

- It takes a FACTORY, never a builder. A supabase-js builder is a thenable, so re-awaiting it is not a second request (Pitfall 3).
- ⛔ Do NOT put it in `src/lib/retry/`. That directory's index documents it as the *client* retry/backoff primitives. `src/lib/seam-retry-registry.ts` governs Railway HTTP seams, not Supabase RPCs.
- `knip` gate: export only the function the two routes import.

### Fail-loud best-effort side effect (TS)
**Source:** csv-finalize `enqueueCsvAnalyticsAfter` (`console.warn` + `captureToSentry(err, { tags: { surface, step }, extra: { strategy_id, correlation_id } })`); finalize-wizard `keyLinkErr` capture (`tags: { surface: "finalize-wizard-after", side_effect: <label> }`); keys/sync `assetClassErr` capture (`tags: { op: "keys-sync.<thing>" }`).
**Apply to:** items 3, 9 and 11. Use the local file's tag vocabulary (`surface`/`step` in csv-finalize, `surface`/`side_effect` in finalize-wizard, `op` in keys/sync). Pass errors through `scrubSeamError` before logging.

### Audit-coverage pragma
**Source:** csv-finalize's `// @audit-skip: see helper-level audit-skip block above. …` sitting directly above `admin.rpc("enqueue_compute_job", …)`; finalize-wizard's `// @audit-skip: denormalization timestamp — see outer comment. (Pragma kept within 8 lines of the .update chain so the audit-coverage grep sees it.)`.
**Apply to:** every wrapped RPC (3, 5) and every retraction call site and helper `.update(` (7, 9, 11). Keep the pragma within 8 lines above the chain start.

### Hoisted-mock harness
**Source:** `vi.hoisted(() => ({ mockRpc: vi.fn(), … }))` plus a module-level `vi.mock(...)` (holdings, keys/sync), or a `STATE` object reset in `beforeEach` (finalize-wizard).
**Apply to:** items 4, 6, 10 and 12. Extend the existing harness; never add a second one.

### Neuter → RED → restore (D-07, D-13, D-20)
**Source:** the `⭐ RED DEMO` docblock at the end of csv-finalize's `[WR-07]` describe (dated, names the neuter, quotes the observed AssertionError, records the restored pass count).
**Apply to:** every TS guard and every new SQL arm. Take a byte backup plus `cmp`, never `git checkout --`, and re-take the backup after every edit.

### SQL: assignments in handlers, writes outside
**Source:** the dormancy instrument in both fan-out snapshots (locals set in the handler; the `INSERT INTO public.cron_runs` wrapped in its own `BEGIN … EXCEPTION WHEN OTHERS THEN RAISE WARNING … END;`).
**Apply to:** item 13 (the failure row) and items 16/17 (the gate arms obey lint R1 the same way).

### SQL: concatenated needles and a comment-stripped definition

## Anti-Patterns (from the analogs themselves)

- Counting ALL `cron_runs` failure rows in a gate. Arm R's all-poisoned tick now writes one too, so narrow by your own target id.
- Placing the failure `INSERT` inside the outer lock-holding `BEGIN … EXCEPTION WHEN OTHERS … RAISE` block. An INSERT error would roll back the successful enqueues (D-10).
- Copying 20260917120000's OPS sentence about a "Production environment's human reviewer gate". That text is stale per project memory.
- Letting finalize-wizard's retraction error reject the `enqueue_sync_trades_job` side effect. It would then be captured under the enqueue's tag (Pitfall 15).
