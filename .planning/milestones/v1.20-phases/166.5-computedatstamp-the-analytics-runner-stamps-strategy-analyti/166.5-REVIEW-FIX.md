### SFH-3a (root part): the column default `now()` writes a false date

**File:** `supabase/schema/baseline.sql:12824` area (`strategy_analytics.computed_at ... DEFAULT now() NOT NULL`), bridge `INSERT` arms in `supabase/migrations/20261023120000_sync_status_runner_stamps_computed_at.sql`
**Reason:** needs a migration; not made, as instructed. What was found by reading every reader of the column:
- The freshness chip cannot read "fresh" on a never-completed row. `FreshnessChip` is fed only by `fetchAndBuildPayload`, which returns `notBuildable("not_computed")` unless `isComputedAnalytics(status)` (`src/lib/factsheet/fetch-and-build-payload.ts:418`), and the existing PARITY fixtures ("status computing", "status failed") already pin it. The tearsheet badge (`isRankableAnalyticsRow` gate, `tearsheet/page.tsx:424`), the ranked lists and SyncBadge (`shapeRowAnalytics` blanks the date for non-success rows, `queries.ts:735`) and the wizard's fresh-skip (`SyncPreviewStep.tsx:929`, `isComplete &&`) all key on status too. So the review's chip claim does not hold; the one raw reader found was the admin review card (fixed above).
- Still reading the raw date for a never-completed row, left alone: `src/app/(dashboard)/portfolios/[id]/page.tsx:222` and `:660` (donut slice tooltip date and the `staleConstituents` warning). Gating them on status would also blank a published constituent under recompute, whose date is honest, and "no figures" is not available there without widening the embed. The exposure is a missing stale warning, not a false fresh chip.
- The exact schema change that closes it at the root, for the orchestrator to book: `ALTER TABLE public.strategy_analytics ALTER COLUMN computed_at DROP DEFAULT, ALTER COLUMN computed_at DROP NOT NULL;`, then a one-off `UPDATE ... SET computed_at = NULL` for rows that never completed (status not in `complete`, `complete_with_warnings` and all of `cagr`, `sharpe`, `max_drawdown`, `daily_returns` NULL), plus: `StrategyAnalytics.computed_at` in `src/lib/types.ts` becomes `string | null`; the readers that assume a string (`fetch-and-build-payload.ts:870` already sentinels, `portfolios/[id]/page.tsx:222` already `|| null`, `computeFreshness(null)` already returns stale) need a typecheck sweep; the NAVBREACH hold trigger already keeps a NULL old value, which is the "never completed" signal; the bridge `INSERT` arms then omit the column with no other change. It is a CREATE-OR-REPLACE-free `ALTER` but it touches the baseline snapshot, the VAC-04/baseline-content-drift gates and the rollback file, so it is its own reviewed migration, not part of this round.
