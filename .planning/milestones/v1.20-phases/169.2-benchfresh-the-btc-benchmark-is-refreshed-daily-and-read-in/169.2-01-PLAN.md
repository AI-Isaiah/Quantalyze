<objective>
Make the BTC benchmark feed current and readable (SC3, the feed half). Today the only writer of
`benchmark_prices` is a lazy refetch during an analytics compute, nothing refreshes it on a schedule,
and the one TypeScript reader returns the OLDEST 1000 rows because PostgREST caps an unranged read
(RESEARCH root cause B). This plan adds one paged reader, points the Scenario BTC route at it, and
adds the analytics-service endpoint that runs the existing Python fetcher. Plan 169.2-02 (same wave) adds
the daily Vercel cron and the analytics-client seam that call this endpoint.

Purpose: Phase 169 plans 169-02 / 169-03 make every factsheet read BTC from this reader and date its coverage.
Output: `benchmark-source.ts` (+test), the paged `/api/benchmark/btc`, and a Python refresh endpoint
(+pytest) that fails with 500, never 503.
</objective>
