## Summary

`_fetch_trades_paginated_one_pass` (`analytics-service/services/equity_reconstruction.py:638`) asks `fetch_my_trades` for 500 rows and breaks on `len(page) < limit_per_call`. OKX and Bybit both cap a page at 100 rows, so every pass stops after its first page. On Bybit the call also carries only `startTime`, which Bybit answers as `[startTime, startTime + 7 days]`, so a quiet first week returns an empty page and the loop ends with nothing. On OKX the endpoint answers the NEWEST 100 fills of `[begin, end]`, so the existing forward cursor (`max_ts + 1`) is wrong even if the short-page break is removed: it has to walk backward with `end`. These are three different defects under one symptom; one stopping sentence ("empty page, cursor that does not advance, window end, never a short page") has three venue implementations.

The fix is contained in two functions (`_fetch_trades_with_pagination`, `_fetch_trades_paginated_one_pass`) plus the window arithmetic in two places (`_account_rebuild_window` for the forced account path, and `start_date = end_date - timedelta(days=BACKFILL_CAP_DAYS)` at line 4750 for the unforced single-key path, which would hit the same Bybit rejection). The OKX 89-day window is untouched. The test suite has one big hazard: most reconstruct tests use `AsyncMock(side_effect=[trades, []])` list fakes, which raise `StopAsyncIteration` on the third call, and a Bybit loop makes about 105 window calls. One shared callable fake that behaves like the venue (100-row cap, `since`/`until`, newest-first on OKX, 7-day answer and `nextPageCursor` on Bybit) is the fix for tests and also the RED-on-100-rows / RED-on-quiet-window proof.

D-03 and D-04 are operational. The probe must reuse `_fetch_and_price_window` (reads only, plus a CoinGecko cache upsert that a read-only Supabase wrapper must refuse) and `_sum_account_rows`, and must NOT call `_crawl_account_key` / `_crawl_whole_account` (rate-limit stamping and the circuit-breaker preflight write to `api_keys`). On the ACCTREBUILD SC-3 record, only account a2 was rebuildable; the other four refuse `account_key_not_working` while their Bybit key stays revoked, so D-04 will most likely record one rebuild and four named refusals, to be re-measured at execution time.

**Primary recommendation:** Replace the one-pass loop with three venue strategies behind one stopping contract (OKX: backward `until` walk per instType with id-dedupe; Bybit: 7-day windows, `limit=100`, `cursor` inside each window, window start at 729 days back; everything else: forward walk that stops only on an empty page or a non-advancing cursor), add one venue-faithful test fake, change `_account_rebuild_window` and the single-key `start_date` for Bybit, then ship a read-only probe before any forced rebuild.

### Q2. How ccxt 4.5.88 implements `fetch_my_trades`

Exercised this session against a real `ccxt.async_support.bybit({})` / `okx({})` with the raw private endpoint stubbed (no network). Results below are `[VERIFIED: local run of ccxt 4.5.85, whose okx/bybit fetch_my_trades bodies are identical to the pinned 4.5.88]`.

**Bybit** (`bybit.py:5570`, `GET /v5/execution/list`):
- Request built: `{'execType': 'Trade', 'category': 'linear', 'limit': 100, 'startTime': 1700000000000, 'endTime': 1700000600000, 'cursor': 'ABC'}` for the call `fetch_my_trades(None, 1700000000000, 100, {"until": 1700000600000, "cursor": "ABC"})`. So `since` maps to `startTime`, `params["until"]` to `endTime` (`handle_until_option('endTime', ...)`), and an unknown extra key such as `cursor` passes straight through.
- `category` defaults to `linear` (`options defaultType 'swap'`, `defaultSubType 'linear'` at `bybit.py:1209-1210`; `get_bybit_type` returns the sub type). **The rebuild reads Bybit linear executions only**; spot, inverse and option fills are never read. The strategy sync is the same (`_BYBIT_FILL_CATEGORIES: frozenset[str] = frozenset({"linear"})`, `services/exchange.py:370`). Out of scope; record as a known limit.
- Page size: the vendor documents `limit` as `[1, 100]`, default 50 `[CITED: https://bybit-exchange.github.io/docs/v5/order/execution]`. The loop sends 500. Whether Bybit clamps or rejects 500 is **not shown by any source I could read**; the PROD probe saw 100 rows from a 500 request, which suggests a clamp `[CITED: ROADMAP evidence, 2026-10-23]`. Send `100` explicitly and stop depending on it.
- Window rule `[CITED: same page, quoted]`: "Only startTime is passed, return range between startTime and startTime+7 days"; "Only endTime is passed, return range between endTime-7 days and endTime"; "If both are passed, the rule is endTime - startTime <= 7 days". This is the quiet-first-window defect: a `startTime`-only request is a 7-day request.
- Order: "sorted by `execTime` in descending order" and "Response items will have sorting issues when 'execTime' is the same" `[CITED: same page]`. ccxt re-sorts the page ascending by `(timestamp, id)` (`parse_trades_helper -> sort_by_2(result, 'timestamp', 'id')`), so the order the venue used is not visible to the caller.
- Cursor: `nextPageCursor` is attached by ccxt to the first RAW item; after ccxt's ascending sort it lands on the NEWEST trade of the page: local run printed `cursor-on [('e1', None), ('e2', 'CUR1')]`, where `e2` is the newer execution. Read it as `next((t["info"].get("nextPageCursor") for t in page if t.get("info", {}).get("nextPageCursor")), None)`. An empty string cursor is falsy; treat it as "no cursor" `[ASSUMED: Bybit returns "" on the last page]`.
- Two-year limit: the doc page's title reads "Get Trade History (2 years)" but its body states no limit (the fetch returned no 2-year sentence). The rejection (retCode 10001 for a start older than two years) is PROD evidence `[CITED: ROADMAP evidence, 167.2.1.1.2-VERIFICATION.md SC-3 record]`, not something I can reproduce offline. Exactly how Bybit measures "two years" (730 x 24 h, or calendar-based) is `[ASSUMED]`; 729 days back from UTC midnight is inside both readings (see Q3).

**OKX** (`okx.py:4872` in 4.5.88, `GET /api/v5/trade/fills-history`):
- Request built for `fetch_my_trades(None, 1700000000000, 100, {"type":"swap","until":1700000600000})`: `{'begin': 1700000000000, 'end': 1700000600000, 'instType': 'SWAP'}`. `limit` is **not sent when `since` is set** (ccxt: "let limit = n, okx will return the n most recent results, instead of the n results after limit, so limit should only be sent when since is undefined", `okx.py:4909`). So the 500 the loop passes is ignored on OKX, and the venue's own default page applies. The same file's `params={"type": inst_type.lower()}` convention in `_fetch_trades_with_pagination` is what makes ccxt send `instType` (confirmed: `'instType': 'SWAP'`).
- Page size 100 `[VERIFIED: okx.py comment "# 'limit': limit, // default 100, max 100"]`, and the strategy sync sends `"limit": "100"` explicitly (`services/exchange.py:2415`).
- Order: newest first. Evidence: ccxt's own comment above ("the n most recent results"), the repo's `services/exchange.py:2415-2420` comment "OKX fills-history returns DESC-sorted data; ``after=<tradeId>`` fetches records OLDER than the cursor (H-0665 ...)", and the PROD probe (two accounts returned exactly 100 over 89 days). I could not load OKX's own reference page (the fetched copy was truncated before the endpoint), so the sort order is `[CITED: ccxt okx.py comment + services/exchange.py comment]`, not vendor-confirmed in this session. The consequence is large: with `begin` set and the newest 100 returned, advancing `since = max_ts + 1` (the current cursor) returns the same newest rows or nothing; paging must walk BACKWARD by lowering `end`.
- Cursor options: `end` (via `params["until"]`, shown working above) is a timestamp bound and needs only documented parameters. `after` takes a record id (the strategy sync passes `tradeId`; OKX's reference says billId `[ASSUMED: from training knowledge, not verified]`). ccxt re-sorts the page by `(timestamp, id)`, so "the oldest row of the page" by ccxt's order may differ from the venue's last row among same-millisecond ties; an id cursor taken from the ccxt-sorted page could skip a tie. Use the timestamp bound plus id-dedupe.
- Endpoint depth: `fills-history` is the last-3-months endpoint (ccxt docstring link "...transaction-details-last-3-months", `okx.py:4846` in 4.5.85); the existing 90-day terminus clamp matches.

**Stopping rule per venue (the answer to "reads every page without looping forever"):**

| Venue | Walk | Page request | Stop when (any) |
|-------|------|--------------|-----------------|
| OKX, per instType (5 passes) | backward from now | `fetch_my_trades(None, effective_since_ms, 100, {"type": <inst>.lower(), "until": <oldest_ts_seen>})`, no `until` on the first call | page empty; page has no row whose `id` is unseen (cursor did not advance); oldest `timestamp` in the page <= `effective_since_ms` (window start reached) |
| Bybit | forward in 7-day windows from `since_ms` to `now_ms`; inside a window, cursor pages | `fetch_my_trades(None, w_start, 100, {"until": w_end, "cursor": <c>})`, `w_end = min(w_start + 7 d - 1 ms, now_ms)`, `cursor` omitted on the first page | window: page empty; no `nextPageCursor`; `nextPageCursor` equals the previous one. Whole read: `w_start > now_ms` |
| Any other venue (binance) | forward `since = max_ts + 1` (today's rule) | as today | page empty; `max_ts <= cursor_ms`. Never a short page |

Safety ceiling (keep, but make loud): the current 500-iteration `for` silently ends. Use `for ... else` with a WARNING that carries counts only, as `services/ccxt_flow_fetch.py` does for transfers (the `else:` branch "NIT-1": "TRUNCATED ... investigate"). Per Bybit window a ceiling of about 100 pages; per OKX pass 500.

Same-millisecond hazard (OKX): if more than a full page of fills share one millisecond, `until = oldest_ts` returns the same rows, no unseen id appears, and the walk stops with rows missing. Log a WARNING in that exit (counts only), never swallow it.

### Anti-Patterns to Avoid
- **Breaking on `len(page) < limit`** where `limit` is the REQUESTED limit and not the venue cap (the defect itself). Also do not replace it with `len(page) < 100`: the venue cap is not measured for every endpoint, and OKX ignores `limit`.
- **Forward cursor `since = max_ts + 1` on OKX.** The venue answers the newest rows, so the walk must be backward.
- **A Bybit request with `startTime` only.** Always send `endTime`; never let the venue pick the 7-day answer.
- **Dedupe on a fabricated key.** Only `id` when present.
- **Venue error text in a log line or audit** (signed URLs). Class and closed-vocabulary tokens only.
- **A code clamp that silently shortens the trade window** below the curve window (breaks the replay's start balance). Refuse instead.
- **Writing from the probe.** No `.insert(`, `.update(`, `.upsert(`, `.delete(`, `.rpc(`, no preflight.

## Common Pitfalls

### Pitfall 1: List `side_effect` fakes exhausting
**What goes wrong:** forced-path tests with a Bybit fake raise `StopAsyncIteration` after the second call and fail for an unrelated reason.
**Why:** `AsyncMock(side_effect=[trades, []])` (`tests/test_reconstruct_marker_writer.py:154`) predates multi-call loops.
**How to avoid:** replace at the `_crawl_exchange` seam with the shared callable fake; keep the positional call signature.
**Warning signs:** `StopAsyncIteration` in a reconstruct test after the loop change.

### Pitfall 2: OKX returns the newest page
**What goes wrong:** forward `since` advancing re-reads or skips; a "fixed" loop that only deletes the short-page break still returns 100 rows.
**How to avoid:** backward `until` walk, id-dedupe, stop on no unseen id; test with a fake that returns the newest 100 of `[begin, end]`.

### Pitfall 3: Bybit `startTime`-only reads 7 days
**What goes wrong:** a quiet first week yields 0 rows and the loop ends; ten weeks of data are invisible.
**How to avoid:** always windowed with `endTime`; RED test with an empty first window.

### Pitfall 4: Two-year edge at midnight
**What goes wrong:** a job that computes `end_date` before 00:00 UTC and requests after it sends a start older than two years.
**How to avoid:** 729 days, the 30-minute rule extended to Bybit in the handoff, and a refusal (not a clamp) if Bybit still rejects.

### Pitfall 5: Probe writes through a shared helper
**What goes wrong:** `_crawl_account_key` stamps a 429 on `api_keys`; `_fetch_and_price_window` can upsert a price cache.
**How to avoid:** call `_fetch_and_price_window` directly with a select-only Supabase wrapper; never `_crawl_*`; keep the static no-write pin.

### Pitfall 6: Comparing a mixed account to stored rows
**What goes wrong:** an account with an MT5 member is compared to a stored sum that includes MT5 -> a false "differs".
**How to avoid:** `comparable=false` unless every contributing member is read.

### Pitfall 7: Census drift
**What goes wrong:** acting on ACCTREBUILD's a1..a5 table from 2026-10-23 as if current (keys can be reconnected, rows written by the daily run).
**How to avoid:** re-run B'1 at execution; treat ledger claims as claims.

### Bybit windowed read (shape)
```python
# Source: this research, Q2 (Bybit rule and ccxt mapping); pattern: services/ccxt_flow_fetch.py window loop
_DAY_MS = 24 * 60 * 60 * 1000
_BYBIT_WINDOW_MS = 7 * _DAY_MS
_BYBIT_PAGE = 100

async def _fetch_bybit_trades(exchange: Any, since_ms: int, now_ms: int) -> list[dict[str, Any]]:
    trades: list[dict[str, Any]] = []
    seen: set[Any] = set()
    w_start = since_ms
    while w_start <= now_ms:
        w_end = min(w_start + _BYBIT_WINDOW_MS - 1, now_ms)
        cursor: str | None = None
        for _ in range(_BYBIT_WINDOW_PAGE_CEILING):
            params: dict[str, Any] = {"until": w_end}
            if cursor:
                params["cursor"] = cursor
            try:
                page = await exchange.fetch_my_trades(None, w_start, _BYBIT_PAGE, params)
            except ccxt.NotSupported:
                return trades
            page = page or []
            if not page:
                break
            _extend_unseen(trades, seen, page)
            nxt = next((t["info"].get("nextPageCursor") for t in page
                        if isinstance(t.get("info"), dict) and t["info"].get("nextPageCursor")), None)
            if not nxt or nxt == cursor:
                break
            cursor = nxt
            await _rate_limit_sleep(exchange)
        else:
            logger.warning("bybit trade window hit the page ceiling window_start_ms=%d rows=%d", w_start, len(trades))
        w_start = w_end + 1
        await _rate_limit_sleep(exchange)
    return trades
```

### OKX backward walk per instType (shape)
```python
# Source: this research, Q2 (OKX answers the newest rows of [begin, end]); params {"type": ...} per equity_reconstruction.py:628
async def _fetch_okx_inst_type(exchange: Any, since_ms: int, inst_type: str) -> list[dict[str, Any]]:
    trades: list[dict[str, Any]] = []
    seen: set[Any] = set()
    until_ms: int | None = None
    for _ in range(500):
        params: dict[str, Any] = {"type": inst_type.lower()}
        if until_ms is not None:
            params["until"] = until_ms
        try:
            page = await exchange.fetch_my_trades(None, since_ms, 100, params)
        except ccxt.NotSupported:
            return trades
        page = page or []
        if not page:
            break
        if not _extend_unseen(trades, seen, page):      # nothing new: cursor did not advance
            break
        oldest = min(int(t.get("timestamp") or 0) for t in page)
        if oldest <= since_ms:
            break                                         # window start reached
        until_ms = oldest
        await _rate_limit_sleep(exchange)
    else:
        logger.warning("okx trade pass hit the page ceiling inst_type=%s rows=%d", inst_type, len(trades))
    return trades
```
`_extend_unseen` returns whether any row was new; rows with `id is None` always count as new.

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Signed URL / HMAC in an exception message reaching logs or audit | Information disclosure | Exception CLASS only in the new WARNINGs; keep the existing `LEAKED_SIGNATURE` caplog assertion |
| Probe output pasted into a public repo leaks amounts/ids | Information disclosure | `emit_record` whitelist + `assert_sanitized` + `sig3`; account labels only; logging disabled |
| Probe or helper writes to PROD | Tampering | Static no-write pin, select-only Supabase wrapper, no preflight/`_stamp_429`; B'0 marker query before any SQL |
| Unbounded loop on a misbehaving venue (non-advancing cursor) | Denial of service | Non-advancing-cursor stop plus page ceilings, loud WARNING, `asyncio.wait_for(_RECONSTRUCT_CRAWL_TIMEOUT_S)` already wraps the crawl |
| Forced rebuild overwrites history with a wrong curve | Tampering | Existing ACCTREBUILD guards (window-only replace, `history_days_unreproduced`, anchor refusals); probe BEFORE rebuild; one forced job per account |
