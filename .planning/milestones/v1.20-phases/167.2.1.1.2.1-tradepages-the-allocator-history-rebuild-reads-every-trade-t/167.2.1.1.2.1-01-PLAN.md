Facts measured at HEAD 6796b4f34 (cite by symbol, never by line):
- `_fetch_trades_with_pagination` has one caller, `_fetch_and_price_window`, which computes `now_ms` from the wall
  clock at call time and passes `start_ms` (UTC midnight of `start_date`) as `since_ms`. The loop sees okx, bybit and
  binance; deribit returns before any crawl and mt5 never reaches it.
- ccxt 4.5.88: bybit `fetch_my_trades(None, since, 100, {"until": u, "cursor": c})` sends `startTime`, `endTime`,
  `limit` and passes `cursor` through; category defaults to linear. ccxt re-sorts every page ascending by
  (timestamp, id), so the bybit `nextPageCursor` lands in the `info` of the NEWEST row of the page.
- Bybit's documented rule: a request with only a start answers start to start plus 7 days; with both, end minus start
  must be at most 7 days; rows come newest first; `limit` is 1 to 100, default 50.
- `_rate_limit_sleep` returns at once for a non-numeric or non-positive `rateLimit`; set `rateLimit = 0` on real ccxt
  fakes.
- `_crawl_exchange` (marker-writer tests) builds every forced-path test exchange with a LIST `side_effect`, which raises
  `StopAsyncIteration` on a third call; a Bybit walk makes over a hundred calls. `_mutate_on_first_trades_call` reads
  that list as an iterator with `next(...)`. `_first_call_trades` is a callable and survives.
- ccxt bybit trades always carry `id` (`execId`); `_make_trade` fixtures carry none.
