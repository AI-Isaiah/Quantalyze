# Phase 167.2.1.1.2.1 TRADEPAGES - Context

**Gathered:** 2026-10-23
**Status:** Ready for planning

<domain>
## Phase Boundary

The allocator history rebuild (`reconstruct_allocator_history`, single-key and whole-account paths) reads every trade the venue holds for its window, not just the first page. Then the ACCTREBUILD account that refused `account_key_read_failed` is re-run, the stored OKX- and Bybit-backed allocator histories are measured against a correct re-read, and the accounts that can be rebuilt are rebuilt in this phase (D-04). The strategy trade sync in `analytics-service/services/exchange.py` has its own loops and is not in scope.

</domain>

<decisions>
## Implementation Decisions

### Carried from ACCTREBUILD 167.2.1.1.2 (founder 2026-10-22)
- D-01 "Keep them as they are (Recommended)": stored days older than the rebuilt window keep their values.
- D-02 "Refuse that account (Recommended)": a stored in-window day the rebuild does not reproduce refuses that account and writes nothing.
- D-03 "Allow the step, mark the date (Recommended)": the seam date is stored; no values are invented.
- ACCTREBUILD SC-3 founder close 2026-10-23, "Accept as recorded (Recommended)": the four accounts whose only Bybit key is revoked keep their stored histories.

### D-01 Bybit two-year edge: shorten the window
Founder 2026-10-23, AskUserQuestion: "Shorten the window (Recommended)". An account holding a Bybit key starts its window at the first whole UTC day Bybit still serves (729 days instead of 730). Older stored days stay as they are (ACCTREBUILD D-01) and the seam date is recorded (ACCTREBUILD D-03). No new refusal token.

### D-02 Read scope: every venue the rebuild reads
Founder 2026-10-23: "All rebuild venues (Recommended)". The rebuild's trade loop stops only on an empty page or when the read reaches the end of its window, never on a page shorter than the requested limit. Bybit is read in 7-day windows with an explicit end time. One rule for every venue the rebuild reads.

### D-03 Measuring stored history: read-only probe
Founder 2026-10-23: "Read-only probe (Recommended)". A probe script run on the worker (the `analytics-service/scripts/bybit_upnl_probe.py` pattern) re-reads each OKX- or Bybit-backed account's window through the fixed loop and prints counts and sizes only: trades read, days compared, days that differ, largest relative difference. It never writes. No ids or amounts in its output.

### D-04 Rebuild within this phase
Founder 2026-10-23: "Rebuild within this phase". After the fix ships and the measurement is recorded, this phase runs the existing forced whole-account rebuild (ACCTREBUILD D-01..D-03) for every OKX- or Bybit-backed account that can be rebuilt, and records each outcome (recomputed, or refused with a named reason). This replaces the ROADMAP's original SC-3 wording "whether to rebuild them is a founder decision"; the ROADMAP entry is updated in the same commit.

### D-05 Post-deploy outcome: rebuild none (deviation from D-04, founder 2026-10-26)
Founder 2026-10-26, AskUserQuestion: "Rebuild none, book follow-ups (Recommended)". The post-deploy probe (plan 06 Task 1) read 128753 trades live but compared no stored history: four of six accounts have no working key, a4 was refused `anchor_skipped_implausible`, a6 was truncated at the read ceiling, and both gates (`okx-order`, `bybit-transfers`) read `unmeasured`. D-04's rebuild is therefore not run: no forced job was enqueued, stored histories stay as recorded ("Accept as recorded"), and plan 06 Tasks 2 and 3 are not run. Follow-ups booked in TODOS.md: `167.2.1.1.2.1-READ-CEILING-STRANDS-ACCOUNT` (a6), `167.2.1.1.2.1-OKX-ANCHOR-IMPLAUSIBLE`, `167.2.1.1.2.1-OKX-ORDER-UNMEASURED`, `167.2.1.1.2.1-BYBIT-TRANSFER-DEPTH-UNMEASURED`. This amends D-04; D-04 is kept as lineage.

### Claude's Discretion

- How the Bybit 7-day windows and the two-year start are computed and pinned in tests.
- Which accounts count as "can be rebuilt" for D-04: the ACCTREBUILD key-selection rules decide; accounts it refuses are recorded with the token.

## Evidence and starting points

- `analytics-service/services/equity_reconstruction.py`: `_fetch_trades_with_pagination` (OKX instType fan-out, 90-day terminus) and `_fetch_trades_paginated_one_pass` (asks `fetch_my_trades` for 500 rows; breaks on `len(page) < limit_per_call`). In use since 2026-04-22.
- `_fetch_and_price_window` calls the trade read, then `fetch_ccxt_transfers` (deposits, withdrawals). `analytics-service/services/ccxt_flow_fetch.py` already pages transfers in venue-sized windows with an explicit end time (Bybit 30 days), the pattern the trade read lacks.
- `_crawl_whole_account` / `_crawl_account_key` (whole-account path) and the single-key path both reach the same read.
- PROD probes 2026-10-23 (read-only, analytics service, counts only): Bybit 89 days, one pass returned 100 trades on one day; 7-day windows with an explicit `endTime` found 1300 trades over 15 days. A 365-day pass returned 0 (quiet first 7 days). Two OKX accounts returned exactly 100 trades each over 89 days. Bybit rejects a trade query starting earlier than two years (retCode 10001); the 730-day window from UTC midnight crosses it.
- TODOS `[167.2.1.1.2-ACCOUNT-CRAWL-DIAGNOSTICS]` is routed here: a failed member crawl should name the member key, venue and exception class in its WARNING (the gather loop already logs venue and class).
- Post-deploy procedure to reuse: ACCTREBUILD plan 09 SUMMARY handoff B'0-B'6 (marker query first, one forced job per account, audit read-back).
