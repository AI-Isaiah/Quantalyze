## What the probe does

- Groups the active okx/bybit keys by allocator, labels accounts a1..aN by earliest key, picks the job key (earliest working Bybit, else earliest working OKX, else earliest active), and chooses members and window by calling `_read_account_keys`, `_select_account_crawl_keys` and `_account_rebuild_window` as a forced rebuild would. A selection refusal is printed as its closed-vocabulary token before any decrypt for that account.
- Reads each selected OKX/Bybit member with `_fetch_and_price_window(..., require_anchor=True)` under `_RECONSTRUCT_CRAWL_TIMEOUT_S`, with a recorder on `fetch_my_trades` (call count, distinct ids, first-page rows, oldest timestamp, in memory only).
- Compares with the stored history only when every selected member is OKX/Bybit and all were read (Deribit counts as $0); otherwise `comparable` is false with the read counts (RESEARCH Pitfall 6). Differing day: absolute difference above 0.005.
- Per OKX member that read a row: one raw `private_get_trade_fills_history` on the busiest instrument type, `okx_newest_first` over the answer; counts OKX passes whose last page was full while its oldest row is newer than that call's `since`.
- Exit codes 0 / 1 / 2 as documented in the module docstring; `EXIT_OK`, `EXIT_FAILED`, `EXIT_REFUSED` are module constants (plan 06's worker import check prints `EXIT_OK`).

## Behaviours plan 06 needs to know

- `okx_order_readings` counts OKX members whose raw answer was decisive. If an OKX member read rows but its reading is indeterminate (`field-absent`), `okx_order_readings` is lower than the OKX member count and `okx_order_violations` stays 0: plan 06's gate should require readings equal to the number of OKX members that read trades, not merely "violations is 0".
- A failed raw ordering read fails the whole member (class recorded, exit 1) because RESEARCH A1 would otherwise be unmeasured.
- A selection refusal alone exits 0 (it is a recorded measurement). A member refusal such as an anchor token exits 1 and is printed in `member_refusal`.
- For a non-comparable account `stored_days`, `rebuilt_days`, `days_compared`, `days_differing` and `days_incomplete` print 0 and `max_rel_diff` prints `field-absent`; `comparable` false is the disambiguator.
- Censuses: `git grep -la bybit_upnl_probe -- ':!.planning' ':!CHANGELOG.md'` lists only the existing probe, its tests and the new probe (which imports `sig3`, `classify_failure`, `FAILURE_CLASSES`, `FIELD_ABSENT` from it).
