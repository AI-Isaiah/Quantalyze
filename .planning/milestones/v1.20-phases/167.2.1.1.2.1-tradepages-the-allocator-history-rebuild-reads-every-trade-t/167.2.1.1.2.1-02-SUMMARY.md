# Phase 167.2.1.1.2.1 Plan 02: OKX trade read walked backward Summary

**The allocator history rebuild now reads every OKX fill of its window, one instrument type at a time, newest first with an explicit end one millisecond past the oldest fill seen, so it is correct whether OKX's end bound is inclusive or exclusive.**

## What changed

- `services/equity_reconstruction.py`: new `_fetch_okx_inst_type_trades(exchange, since_ms, inst_type)`. First page has no end; each later page sends `params["until"] = oldest_seen + 1`; rows added with `_extend_unseen`. Stops on an empty page, a page with no new fill, a next end that is not lower than the current one, or the oldest fill at or before `since_ms`. One counts-only WARNING (venue okx, instrument type, row counts) after a full page (at least `_TRADE_PAGE_LIMIT` rows) that cannot advance, and on the `for ... else` ceiling exit; a short or empty last page ends quietly. `ccxt.NotSupported` returns what was read. The OKX branch of `_fetch_trades_with_pagination` calls it for each `OKX_INSTRUMENT_TYPES` entry after the unchanged terminus clamp and the unchanged "OKX trade history capped at 3 months" INFO line. OKX no longer calls `_fetch_trades_paginated_one_pass`.
- `tests/_trade_pages.py`: `okx_select` (OKX's newest-100-in-`[begin, end]` rule), `VenueTradeBook(..., end_exclusive=)`, `real_ccxt_client("okx", ..., end_exclusive=)` (real `ccxt.async_support.okx`, `privateGetTradeFillsHistory` stubbed on the RAW request `begin`/`end`/`instType`, `limit` ignored, requests on `.raw_requests`).
- `tests/test_trade_pages.py`: the OKX tracer plus 7 further cases (6 functions; the tie test is parametrized inclusive / exclusive). File total 18 tests, 0 skipped.

## Deviations from Plan

None that change scope. Choices made inside the plan:

1. **Existing fakes needed no fix.** The plan allowed fixing `tests/test_equity_reconstruction.py` fakes that cannot express a later page carrying `until`; none failed, so that file is untouched.
2. **`okx_select` factored out** in `_trade_pages.py` so `VenueTradeBook` and the real-ccxt stub share one OKX rule; plan 01's `VenueTradeBook._okx` body was replaced with a call to it (behaviour for the default inclusive bound unchanged).
3. **Window-start check order.** The "oldest fill at or before `since_ms`" stop is evaluated right after the page is added and before the no-new-fill check, so a pass that ends by reaching the window start is always quiet. A fill group sitting exactly on `since_ms` and split at the page edge would not be re-asked; this is the plan's stated stop rule, noted as a residual of negligible width (one millisecond).
4. **Branch namespace.** Worktree branch is `feat/167.2.1.1.2.1-p02`, not `agent-*`; treated as the orchestrator-assigned sequential case, as in plan 01. It is not a protected branch.
5. **Ceiling test sizing.** The ceiling test runs 500 pages of 100 rows (50,000 rows held); it completes in about a second because `_rate_limit_sleep` is a no-op on the test double.
