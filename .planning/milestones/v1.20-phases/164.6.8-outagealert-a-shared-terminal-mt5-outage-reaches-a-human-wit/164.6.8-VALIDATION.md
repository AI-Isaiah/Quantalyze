# Phase 164.6.8 — Validation Strategy

> Per-phase validation contract for OUTAGEALERT: a shared-terminal outage reaches a human without one clicking a
> button. Every reader or alert has a test that fails first when the reader is removed; RED is proven by
> neuter-and-restore from a byte backup (`cp`, then `cmp`), never by git checkout, restore or stash.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest (analytics-service), vitest (Next.js and scripts), the SQL gate corpus on the pg lane via `scripts/mutation-runner/run.mjs` |
| **Config file** | `analytics-service/pytest.ini` or `pyproject.toml` (existing), `vitest.config.ts`, `scripts/mutation-runner/GRAMMAR.md` |
| **Quick run command** | `(cd analytics-service && .venv/bin/python -m pytest tests/<file> -q)` or `npx vitest run <one file>` (one file per invocation) |
| **Full suite command** | `(cd analytics-service && .venv/bin/python -m pytest -q)`; vitest one file per invocation over the phase's files; `node scripts/mutation-runner/run.mjs` (FULL corpus, once, plan 05) |
| **Estimated runtime** | quick < 60 s per file; the full mutation corpus is minutes and runs once |

## Sampling Rate

- **After every task commit:** the task's own `<automated>` command.
- **After every plan wave:** the union of that wave's test files.
- **Before `/gsd-verify-work`:** every command in the map below green, plus plan 05's full mutation run quoted in its SUMMARY.
- **Max feedback latency:** 60 s per task command (the full mutation run is the one exception, run once in plan 05).
