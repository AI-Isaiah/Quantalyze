## Deviations from Plan

### [Rule 1 — Bug] The plan's permanent-header text about PR #750 was factually wrong

- **Found during:** Task 1 §A, while grounding the header's measured incident.
- **Issue:** the plan instructs the header to say PR #750's "diff was four `.planning/`
  markdown files and zero code". **Measured from `gh pr view 750 --json files`: false.**
  #750 also changed `CHANGELOG.md`, `TODOS.md`, `VERSION` and `package.json` — four files
  outside the allow-list. Under this phase's own predicate **PR #750 classifies as CODE and
  would still run the entire corpus.** Writing the plan's sentence would have seeded a false
  fact into a permanent script header — the precise `[164.7-CITATION-DRIFT-01]`-adjacent
  defect class the same paragraph of the plan forbids.
- **Also corrected:** the plan attributes `23 check rows / ~4,760 job-seconds` to PR #750.
  That census is from run **`34717952454`**, a *different*, later PR (`headBranch:
  docs/close-v1.20-verification`, head `c1262aff`) — verified by `gh run view`. The header now
  binds each figure to its own run: `21 jobs / ~50 job-minutes` → PR #750 (run `34062196456`),
  `23 rows / 4,760 s` → run `34717952454`, with the by-job-key vs by-check-row reconciliation
  the plan asked for.
- **Fix:** header states the measured truth in both cases, and explicitly tells the reader that
  the motivating PR would not itself be filtered, so a future reader does not see a full corpus
  on #750 and conclude the filter is broken. ⛔ The allow-list was NOT widened to make #750 fit
  — `CHANGELOG.md`/`VERSION` moving IS a release, and a release must run every gate.
- **Files:** `scripts/classify-changed-paths.mjs` · **Commit:** `668b8e08`

### [Rule 3 — Blocking] The analog's bare `process.exit(main())` made the module unimportable

- **Issue:** `check-version-bump.mjs` ends with `process.exit(main());`, which runs at import.

- **Fix:** adopted `scripts/lint-app-guc.mjs`'s realpath-safe `invokedDirectly()` guard (the

- **Files:** `scripts/classify-changed-paths.mjs` · **Commit:** `668b8e08`

### [Rule 1 — Bug] My `needs:` comment reddened an existing gate

- **Found during:** Task 1 §B(iii) verification — `npx vitest run src/__tests__/critical-regressions.test.ts`.
- **Issue:** I placed the `changed-paths` rationale as a comment INSIDE the aggregator's
  `needs:` list. `critical-regressions.test.ts` parses that list with
  `/^ {4}needs:\n(?: {6}- [\w-]+\n)+/m`, so the interleaved comment produced
  `AssertionError: ci.yml frontend aggregator: no needs: list found` — a RED on the gate that
  pins `sql-tests` into the aggregator.
- **Fix:** moved the prose into the aggregator's HEADER (the file's own convention for per-job
  rationale) and left `needs:` a contiguous run of bare entries. Added a `⚠️` line in that
  header recording the parser constraint, so the next person does not repeat it.
- **Files:** `.github/workflows/ci.yml` · **Commit:** `668b8e08`

## ⛔ BLOCKER FOR WAVE 2 — `[164.6.3-MW02-DOCSONLY-BLIND]`

**This phase's own failure mode, found inside this phase: a gate that silently stopped covering
what it exists to cover.** Full write-up in `deferred-items.md` §1.

`src/__tests__/lint-sql-gates.test.ts`'s MW02 executed-tolerance oracle asserts *"the jobs whose
SKIP is tolerated are exactly `TOLERANCE_BEARING_JOBS`"*, justified as *"A job gaining tolerance
means branch protection now passes on its skip."* **Eleven jobs just gained that tolerance and
the oracle reported no change** — it stayed green.

Cause, measured: `extractResultLoopBlock()` slices only `for r in \` … `done`. This plan hoists
`docs_only` and `ALWAYS_ON` ABOVE the loop (the placement RESEARCH Pattern 4 requires and which
is necessary for correctness), so the extracted block **references** `$docs_only` but never
**defines** it — bash sees an empty string, the new arm is dead, and the oracle measures the
pre-change posture. Its own green diagnostic prints `sql-gate-lint=0`, which is false at HEAD.

**Not fixed here, deliberately:** `lint-sql-gates.test.ts` is outside this plan's
`files_modified`, and the repair is a semantic decision about an existing VAC-03 oracle
(widening the slice takes guard combinations 2³→2⁴ and reclassifies eleven jobs as
tolerance-bearing, which the exact-set assertion will reject until `TOLERANCE_BEARING_JOBS` is
redefined; and the sibling *"every tolerated skip is CONDITIONED on the event"* assertion does
not fit a diff classification). That is Rule 4 — surfaced, not improvised.

**Why it blocks wave 2:** plan 02 adds the `if:` to fifteen more job keys, widening this blind
spot fifteenfold, in the very oracle whose job is to notice a job gaining skip-tolerance.
⛔ Do not close it by weakening or deleting the exact-set assertion.
