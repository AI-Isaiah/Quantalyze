Repair the MW02 executed-tolerance oracle so it measures the aggregator that exists at HEAD
instead of the one that existed before wave 1.

nothing changed. Wave 3 adds the docs-only conjunct to fifteen more job keys; every one of them
widens this blind spot. The oracle is repaired BEFORE the filter is widened, not after.

DOCS-ONLY FILTER excuses, a shell hardening that turns the whole defect class into a loud
MEASURE_FAIL, a standing proof that the repaired oracle catches a mutation the pre-repair one
could not, and a re-engaged fixture-fidelity coupling.

**Hermetic rows under a real fault, all 16 combinations:** `sql-gate-lint=failure` tolerated
0/16, `=cancelled` 0/16; `sql-mutation=failure` 0/16, `=cancelled` 0/16. The docs-only arm

**The root-cause experiment.** Re-running the same four files with the shell's unset-variable
check enabled:

```
CI/narrow-slice : ABORTS, status 1, `bash: line 18: ALWAYS_ON: unbound variable`
CI/script-slice : runs to a verdict
MW02 alternate-spelling red fixture : runs to a verdict under BOTH slices
MW02 case-spelling red fixture      : runs to a verdict under BOTH slices
MW02 green fixture                  : runs to a verdict under BOTH slices
```

⭐ This is why the repair is two layers and not one. Widening the slice fixes the instance; the
unset-variable check fixes the CLASS — the next person who hoists a variable out of the slice
gets an abort with the variable's name in it, not a green run reporting yesterday's world.

**Why `fail=0` is a safe slice anchor.** All three MW02 fixtures already carry `fail=0` on the
line immediately above their `for r in \`, so the widened slice adds exactly one line to each
and changes none of their postures (verified). In `ci.yml` the same anchor picks up the
prologue. The case-spelling fixture also contains the characters `fail=0` inside a prose
comment; a whole-line anchor does not match it.
