**Rule 7 conflict inside the UI-SPEC, resolved here (D-06 outranks the P-1 class strings).** P-1
sets rank to `min-w-14` (56 px) and star to `w-11 min-w-11 px-0` (44 px, Strategy offset 100). RESEARCH
measured neither width at desktop: the star cell renders about 60 px (the 44 px `StarToggle` plus
`px-2`; a table cell never renders below its content's minimum), and the stack measured about 339 px at
V1280 (rank + star + a 235 px Strategy column), which puts the rank column near 44 px, not 56. Forcing
either P-1 width would move every column to its right, breaking P-5 and the founder's locked D-06 ("no
visible desktop change"). Fixing them at px values measured on the executor's machine would bake a
literal that CI's fonts can contradict. So no width changes at all, and the offsets follow the widths.

**Rule (no measured literal in code).** The rank and star cells keep exactly their plan-07 classes
(natural, unconstrained widths; no `min-w-*`, no `w-[Npx]`, star keeps `px-2`). `StrategyTable` measures
the rank `th` and star `th` widths at runtime (a `ResizeObserver` on the two header cells, attached in a
layout effect, disconnected on unmount) and writes two CSS custom properties on the
`[data-strategy-table]` frame: `--pin-star-left` = rank width, and `--pin-strategy-left` = rank width +
star width when the star column shows, else rank width. The offsets read them: star cells
`@3xl:left-(--pin-star-left)`, Strategy cells `@3xl:left-(--pin-strategy-left)` (header, body and
placeholder: all nine strings keep the `@3xl:` gate from plan 07; rank stays `@3xl:left-0`). The frame's
initial inline values are the plan-07 offsets (`3.5rem`; `6.25rem` with the star column, `3.5rem`
without), so the server render and the pre-measure first paint are exactly plan 07's. Confirm the
Tailwind 4.3.3 build emits `left: var(--pin-star-left)` for the `@3xl:left-(--pin-star-left)` form
(read the compiled CSS once and record it); if this Tailwind does not support the `(--var)` form, use
the equivalent arbitrary value `@3xl:left-[var(--pin-star-left)]`.

**STOP rule.** If, with the runtime offsets, the P-1 edge equalities or the P-5 comparison fail at
V1100 or V1280 beyond 1 px, do not change a width and do not widen the tolerance: STOP and report the
measured deltas at both widths in the SUMMARY as a named D-06 conflict ("D-06 conflict: pinned stack vs
desktop geometry") for the founder to decide.

**Why P-5 compares in-page, not against px constants.** `playwright.config.ts` notes that font
hinting shifts between macOS dev runners and Linux CI runners, and the Strategy column is
content-sized, so px literals measured on the executor's machine could be red on CI for no defect. The
spec instead reverts the pinned cells' box CSS to the plan-07 values inside the same page and compares
the two measurements at V1100 and V1280, which fails exactly when any width change (this plan's or a
later one's) moves a desktop column. The plan-07 head's absolute readings are also recorded in the
SUMMARY.
