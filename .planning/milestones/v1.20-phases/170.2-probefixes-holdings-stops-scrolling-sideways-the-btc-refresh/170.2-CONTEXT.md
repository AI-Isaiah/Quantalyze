<decisions>
## Implementation Decisions

### Discovery table on phones (SC-6)
- **D-01:** Below tablet width, the Strategy column is **not pinned**: the whole row scrolls sideways together. Founder choice (AskUserQuestion, 2026-10-09: "Unpin on phones"), preferred over a narrowed pinned column and over a card list.
  - At tablet width and above, the pinned column stays, but each pinned body cell must be exactly as wide as the pinned header cell above it and must never cover a metric column (SC-6's second half applies at every width where pinning is active).
  - The page itself still has no horizontal scroll at 360, 375 and 390 px. The table scrolls inside its own scroller and its "Columns" hint stays visible.
  - The breakpoint follows DESIGN.md's tablet breakpoint.

### Carried from the ROADMAP (locked)
- **D-02:** Each criterion ships with a test that fails on the current code (SC-1 to SC-6).
- **D-03:** The restoring recompute for SC-5 runs through the normal compute-job path, inside the Wave 5 consolidated PROD recompute, so no row is recomputed twice. This phase names it and does not run it.
- **D-04:** SC-6 is re-checked on a phone after deploy. The founder or the orchestrator does this in a signed-in browser.


### Founder decisions after the UI-SPEC check (2026-10-09)
- **D-05 (refines D-01's "tablet width"):** pinning keys on the **table's own width**, not the viewport. The Strategy column pins only when the `StrategyTable` container is at least `@3xl` (~768 px of table, about a 1090 px window with the sidebar). It matches the table's existing `@max-3xl` column-collapse idiom. Below that, phones, tablets and narrow laptop windows scroll the whole row together. Founder choice (Recommended) over pinning from a 768 px viewport.
- **D-06:** desktop Strategy names stay **content-sized** as today. A fixed width applies only where pinning is tight, if at all. No visible desktop change. Founder choice (Recommended) over a fixed 160/224 px column everywhere.
- **D-07 (SC-3 /compare):** the overlay draws each strategy over **the same span its headline cumulative return uses** (the post-break suffix), with "Measured since {date}" under the legend when that span is shorter than the history. Chart and table always agree. Consistent with FACTSHEETTRUTH D-01. Founder choice (Recommended) over the full bridged curve plus a note.

### After research (2026-10-09)
- **D-08 (orchestrator call; reversible, one-line `vercel.json` edit):** move the BTC refresh cron from `10 0 * * *` to `30 0 * * *`. CoinGecko publishes the last completed day at 00:10 UTC, and the cron fires at the same minute (research Q-3).
- **D-09 (supersedes UI-SPEC M-3's earlier marker):** the CSV marker is `strategies.source = 'csv'` (27 PROD rows), carried as a new payload field. `ingestSource` is NULL-derived on PROD and unusable. The factsheet payload cache key moves v12 → v13.
- Research resolutions adopted:
  - SC-1 needs `grid-cols-1` on the root and on all three nested section grids.
  - SC-2: shift CoinGecko stamps back one day, drop non-midnight points, clamp `days` to 365, the cache wins on merge, and upsert only new dates.
  - SC-5: add a `since` keyword with keyset reads, plus a one-time Binance backfill to the oldest strategy start. Fix the 12 `_fake_benchmark(symbol)` fakes.
  - SC-6: prefix the nine `left-*` offsets with `@3xl:` and add `min-w-*`. The page-overflow offender is measured red-first by the executor (Q-5).

### Claude's Discretion
- **SC-2 fallback source:** either CoinGecko within the free-tier window merged with cached history, or another free source. Research measures and picks.
- **SC-5 benchmark read shape:** for example, read from the strategy's first date instead of using a fixed trailing count. The cache read limit has to change with it.
- **Re-measure 169.2:** check whether Phase 169.2 BENCHFRESH's "read in full" claim holds at HEAD before relying on it. The ROADMAP flags it as unverified.

### Established Patterns
- **Overflow (SC-1):** grid-item ancestors keep `min-width: auto`, which lets `overflow-x-auto` scrollers grow with their tables. The fix class is `min-w-0` on the track or item. SC-6 is likely the same class.
- **Analytics freshness:** read from `strategy_analytics.computed_at`. The benchmark cache lives in `benchmark_prices`.
