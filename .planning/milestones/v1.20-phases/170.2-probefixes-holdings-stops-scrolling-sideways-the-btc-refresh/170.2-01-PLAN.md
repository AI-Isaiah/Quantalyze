<objective>
SC-2 first (orchestrator priority): when Binance fails, the daily BTC refresh still lands yesterday's
close. PROD's stored BTC series is two days stale today, so this plan is self-contained and can ship
as its own PR ahead of the rest of the phase if the founder chooses a split.

Purpose: the CoinGecko fallback requests `days=1001`, which the free tier refuses (365 answers 200,
366 answers 401, measured), so any Binance failure loses that day. The fallback is also one day off
against Binance (CoinGecko's `D 00:00` stamp is the close of `D-1`, measured), so making it reachable
without the shift would write wrong closes into the cache every metric reads.

Output: the clamped and shifted CoinGecko parser, a cache-wins merge that writes only new dates, the
00:30 UTC cron (D-08), and route-level tests that fail on the old code.
</objective>
