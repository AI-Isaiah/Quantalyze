# Phase 170.2 Plan 11: One-time BTC benchmark backfill script (SC-5) Summary

A tested `python -m scripts.backfill_btc_benchmark` that writes BTC closes older than the cache once, through the product's own fetch-merge-upsert path, exits 1 when the result is stale or the stored history still starts too late, and is held by the plan-03 census. It was written and tested only: it was NOT run against PROD or shared TEST (D-03; plan 10 runs it post-merge).

## What changed

- **`scripts/backfill_btc_benchmark.py` (new).** `main(argv) -> int`, shaped like `phase35_backfill_enqueue.py`. It reads the oldest `csv_daily_returns.date` among rows with a non-null `strategy_id` (or takes `--since`), reads the BTC cache's oldest / newest / row count from `benchmark_prices` (three small queries; the count uses `CountMethod.exact`), prints `before:` and `plan:`, and with `--dry-run` stops there (no fetch, no write). Otherwise it awaits `get_benchmark_returns("BTC", since=since, require_persist=True)`, re-reads the cache, prints `after:`, and exits 1 on: no series, a stale flag, or stored oldest later than `max(since - 1 day, BTC_FIRST_DAY)`; exit 0 prints an `ok:` line. A lost cache write raises `BenchmarkCacheWriteError` through (require_persist) and is not caught. Docstring carries the run forms (`railway ssh` form, and the documented `railway run` alternative from a machine that can reach Binance when Railway egress cannot) and the idempotency note (cache wins, re-run writes nothing new).
- **`tests/test_backfill_btc_benchmark.py` (new, 15 tests).** Stateful fake client (an "after" read reflects what the patched `get_benchmark_returns` stored; any write verb on the fake is recorded so "no write" is assertable). Covers: the tracer (reads, kwargs `{"since": date, "require_persist": True}`, one `before:` and one `after:` line with oldest/newest/rows), dry-run, stale -> 1 naming the stored range, fresh-flag-but-short -> 1, no series -> 1, already-covered cache -> 0 (idempotent), since before `BTC_FIRST_DAY`, `--since` override, per-key (`strategy_id` NULL) rows ignored, empty strategy read / empty cache / absent count each raise, a failed write propagates, a bad `--since` rejected, and an output-hygiene test (no `http`, no `supabase`, no key or id values; every line carries a fixed prefix).
- **`tests/test_benchmark_since_census.py`.** `("backfill_btc_benchmark.py", "main"): 1` added to `EXPECTED_SINCE_SITES` (in the same commit as the script, so no commit has a red census) and the "PLAN 11" docstring paragraph now says it was added.
