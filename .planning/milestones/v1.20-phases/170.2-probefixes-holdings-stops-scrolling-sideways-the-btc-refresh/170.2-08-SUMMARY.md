# Phase 170.2 Plan 08: Pinned Strategy stack (SC-6, second half) Summary

Where the Discovery table pins its name column (the table at `@3xl` and up), the rank, star and Strategy cells now line up edge to edge, the pinned Strategy header is no longer painted over by the headers scrolling under it, and nothing about the desktop table moved. The occlusion case was RED on the plan-07 head at V1100 and V1280 and is GREEN now, on the local lane.

## What changed

- **Component** (`StrategyTable.tsx`). The Strategy `th` is `z-30` (was `z-20`), level with the rank and star headers; every other header stays `z-20`, pinned body cells stay `z-10`. A `usePinnedStackOffsets` hook measures the rank `th` and star `th` (`getBoundingClientRect().width`, `ResizeObserver` attached in a `useLayoutEffect`, disconnected on cleanup) and writes `--pin-star-left` (= rank width) and `--pin-strategy-left` (= rank + star width, or rank width without the star column) on the `[data-strategy-table]` frame. The star cells read `@3xl:left-(--pin-star-left)`, the Strategy header, data cell and placeholder cell read `@3xl:left-(--pin-strategy-left)`; rank stays `@3xl:left-0`. A zero width (jsdom, not laid out) keeps the fallbacks. No width class was added or changed anywhere.
- **Helper** (`geometry.ts`). `assertPinnedStackDoesNotCover(page, region, label, { metrics })` probes `elementFromPoint` at the centre of each metric cell's visible interval right of the pinned stack, at scrollLeft 0/60/150/300/max; skips intervals under 4 px; names the covering element, column, row and scroll position; throws on a zero-element region, a missing header, no rows, or any (column, row) pair that never had a probeable interval (W-02).
- **Spec** (`layout-narrow.spec.ts`). `"/discovery — SC6-DISCOVERY pinned"`, `HAS_SEED_ENV`-gated, local viewports V1100 (1100x800) and V1280 (1280x800), same seed and `finally` teardown as the unpinned describe, signed in so the star column shows. Cases collect rather than throw: X-1, the occlusion probe, P-1 (rank right = star left, star right = Strategy left, at scrollLeft 0 and max), P-1b (the Strategy header's right edge does not cover Return % at rest), P-2 (every pinned td matches its th in width and right edge, per row, at 0 and max), P-3 (no descendant or text past the pinned cell), P-4 (room right of the pinned edge >= the widest of Return %, CAGR, Sharpe), and P-5. P-5 measures every header cell, applies the hand-typed `PLAN_07_PINNED_BOX_CSS` inline to the rank and star cells (th and td), re-measures, restores the cells' own `style`, and fails above 1 px (non-pinned cells: left and right edge; pinned: width). It compares in the page, not against px literals, because font hinting differs between macOS dev and Linux CI.
- **Unit tests** (`StrategyTable.test.tsx`). Strategy header asserts `z-30` (dated comment `// 2026-10-09 Phase 170.2 UI-SPEC P-1 / X-1 / D-06: ...`) and no `z-20`; CAGR asserts `z-20`; rank/star header and cells assert their plan-07 width classes unchanged (`w-14`/`w-11`, `px-2`, no `min-w-`, no `w-[`); star cells assert `@3xl:left-(--pin-star-left)`, Strategy cells `@3xl:left-(--pin-strategy-left)`; the frame carries `3.5rem`/`3.5rem` (no star) and `3.5rem`/`6.25rem` (star) before any measurement. The plan-07 source census now asserts exactly nine pinned strings (three per column) and that the placeholder star and Strategy cells carry the same width and offset classes as the data row.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in my own spec] The pinned readings moved while the page settled.** Found during: Task 1, first runs. The rank cell read 38.5 px and the region's scrollWidth 1338 early, then 31.0 px and 1184 settled, on the same page (fonts and sparklines land late). The first RED run therefore mixed two layouts. Fix: the describe waits for `document.fonts.ready` and then for every header width and the region's scrollWidth to hold still for 500 ms, plus two frames so the table's `ResizeObserver` has applied, before reading anything. This is what makes the readings above stable and repeatable across six runs. File: `e2e/layout-narrow.spec.ts`. Commit: 0f19ee0e2.

**2. [Rule 2 - Missing critical check] P-1b added.** The plan's occlusion probe skips the interval of a metric cell that lies under the stack (RESEARCH design), so it is GREEN on the plan-07 head even though the Strategy cell visibly covers the first 9 px of Return % at rest (the founder's symptom). I added P-1b (the Strategy header's right edge must not exceed Return %'s left edge at scrollLeft 0). It is RED on the head (`covers the first 9.2 px of Return %`) and GREEN now. The occlusion probe stays as designed and is still the proof for the scrolled positions. File: `e2e/layout-narrow.spec.ts`. Commit: 0f19ee0e2.

**3. [Design] Direct DOM writes instead of state for the measured offsets.** The plan describes "writes two CSS custom properties"; I implemented it without React state so a window resize does not re-render the whole table. The consequence is that React's style prop only owns the fallbacks, and the effect re-measures when the star column toggles (`showStarColumn` is a dependency). Commit: 7a12298e2.

**4. [Design] The Strategy header's two `stickyLeft` arms merged.** Both arms now read the same variable, so one string remains (the plan said `z-30` "on both pinned arms"). The source census floor changed from 12 to 9, with an added exact-count test (3 rank, 3 star, 3 Strategy) that is stricter than the old floor. File: `StrategyTable.test.tsx`. Commit: 2419c8bc4.

**5. Commit-time branch assertion.** The worktree-mode allow-list expects an `agent-*` branch; this worktree's branch is `wt/170.2-p08`, named by the orchestrator and not a protected branch. Committed there, as plan 07 did.

**Total deviations:** 2 auto-fixed in my own test code (1, 2), 2 design choices inside the plan's intent (3, 4), 1 protocol note (5). **Impact:** none on scope; the desktop table is unchanged (P-5 max delta 0.000 px at both widths).
