# Phase 167.2.1 Plan 03: /strategies share note tells the truth about an unbuildable factsheet Summary

The `/strategies` share note now asks the builder's own resolve stage (`probeFactsheetBuildable`, under `withPublishedOrOwner(q, user.id)`) about every row the analytics embed calls computed. A computed row the builder refuses now gets the precise D-02 line, for example KCS12-UNBUILDABLE-SHORT for a one-point single-key row. Before this change it showed no note, which implied a working factsheet.

## What changed

- **Copy (`status-surface-copy.ts`):** adds `UnbuildableNoteKind` and `unbuildableNoteKindOf` (`too_few_points` → `too_short`, `composite_unbuildable` → `cannot_build`, anything else → null). `NotBuildableReason` is a type-only import. The module-private `MINT_UNBUILDABLE_NOTES` and `PUBLIC_UNBUILDABLE_NOTES` hold exactly the four D-02 strings. `recipientShareNoteFor(mode, arm, kind)` applies the D-02 selection rule. The doc comment on `recipientShareNote` names the four new ids. No existing KCS-12 string changed.
- **Page (`strategies/page.tsx`):**
  - Every listed row maps to `[id, note | null]`, and the nulls are dropped afterwards. `Promise.all` is kept.
  - Uncomputed rows keep today's path through the shared `armOf` and `uncomputedNote` helpers, and are never probed.
  - Computed rows run `probeFactsheetBuildable(s.id, (q) => withPublishedOrOwner(q, user.id))` inside a try/catch:
    - buildable → no note;
    - a throw, `read_error` or `not_visible` → `recipientShareNote(mode, "unreadable")`, plus `console.error` and `captureToSentry` with `{ route: "strategies/page", stage: "factsheet-probe" }` tags only;
    - `not_computed` → the uncomputed path;
    - otherwise → `recipientShareNoteFor(mode, arm, kind)`. A `public-url` row needs no RPC (the arm helper short-circuits, per 167.2 IN-04).
  - The "Known limit" sentences are replaced by a lineage comment saying WR-02 is closed by 167.2.1 D-04 and D-08.
  - No builder gate was re-implemented, no `daily_returns` select was added, and no cache was used.
- **Tests:** see the case list below. The sibling suites got a default-buildable admin double and a UUID-shaped session id. `grep` confirmed `u-test` appeared exactly once in each of the three files before the switch.
