## Fixed Issues

### L-3: The route's Sentry events drop the error code

**Files modified:** `src/app/api/keys/[id]/memberships/route.ts`, `route.test.ts`
**Commit:** `d3b4557e1`
**Applied fix:** A new `errorCodeTag` helper feeds a `code` tag to both the `ownership` and the
`memberships` captures. The tag carries the PostgREST or SQLSTATE code, `"none"` when the error
has no code, and `"no_error"` when the read returned no rows array and no error. The console
lines carry the code too. The raw message still stays out of the event and the response body.
**Neuter:** I restored the pre-fix route. Four cases went RED (`4 failed | 8 passed (12)`), and
the restore passed `12 passed (12)`.

### M-4: The membership route's defence-in-depth tripwire fires silently

**Files modified:** `src/app/api/keys/[id]/memberships/route.ts`, `route.test.ts`
**Commit:** `46c9c9b37`
**Applied fix:** The `rows.map` branch now counts `ownerMismatches` (a strategy whose `user_id`
is not the caller's) and `danglingEmbeds` (no strategy embed) separately. If either count is
non-zero, `console.error` logs the counts and `captureToSentry` records
`"key memberships: strategy owner mismatch or dangling embed"`. The capture has the tags
`{ route, stage: "coherence" }` and puts the counts in `extra`. It contains no key, user or
strategy id and no name. The response does not change: the row is still listed with a null name
and status, so the confirm still warns. `COHERENCE-QUIET` pins that an all-own list captures
nothing and logs nothing.
**Neuter:** I restored the pre-M-4 route, and `COHERENCE-TRIPWIRE-LOUD` went RED
(`1 failed | 13 passed (14)`). The restore passed `14 passed (14)`.

### L-2: The membership fetch is not aborted when the bound wins

**Files modified:** `src/components/strategy/ApiKeyManager.tsx`, `ApiKeyManager.test.tsx`
**Commit:** `4a23ca769`
**Applied fix:** `readKeyCompositeMemberships` now creates an `AbortController`, passes its
`signal` to `fetch`, and calls `abort()` in the `finally`. Aborting a request that has already
settled does nothing. The late rejection was already handled by `Promise.race`, so the owner sees
the same behaviour as before. `UNCHECKED-TIMEOUT` now asserts that the membership request's
signal is aborted after the bound fires. `R2-WR02-WARNING-NAMES` now expects the fetch init to
contain `signal: expect.any(AbortSignal)`.
**Neuter:** I removed only `abort.abort();`. `UNCHECKED-TIMEOUT` went RED with
`AssertionError: expected false to be true`, and the restore passed.

### M-6: The client-side "unreadable" causes of the membership read never reach Sentry

**Files modified:** `src/app/api/keys/[id]/memberships/route.ts`, `route.test.ts`,
`src/components/strategy/ApiKeyManager.tsx`
**Commit:** `8fa8e8cfa`
**Applied fix:**
- I corrected the `readKeyCompositeMemberships` docstring. It claimed that every "unreadable"
  cause was captured, but the component is `"use client"` and Sentry is server-only, so the
  capture is a browser no-op. The docstring now lists the causes that are recorded server-side:
  the route's 500s, captured with the error code, and a limiter deny. It also lists the causes
  that reach only the browser console: the bound, 401, 404, a non-JSON body, a malformed
  `memberships` and a rejected fetch. The capture is kept so it starts reporting if a client init
  lands, and that init must adopt `scrubSentryEvent` first.
- The route now logs a limiter deny with `console.warn`. The log carries only the status (429, or
  503 when the limiter is misconfigured) and no user or key id. A confirm that warned because of
  a deny now leaves a server-side trace.

**Neuter:** I restored the pre-M-6 route, and `RATE-LIMITED` went RED
(`1 failed | 13 passed (14)`). The restore passed.

**Not fixed here (a class, outside this fixer's files), routed to the orchestrator:** every
`captureToSentry` in `ApiKeyManager.tsx`, and in any other `"use client"` component, does nothing
in the browser. The root fix is a client `Sentry.init` that adopts `scrubSentryEvent`, which is a
security decision because it reopens the browser channel that `src/instrumentation.ts` warns
about. `TODOS.md` has no entry for it (checked by grep). The orchestrator needs to book it.
