## The pattern, and what was actually done about it

The brief named the recurring defect: **a control is built correctly and then
measured by an instrument that agrees with it by construction.** Five of this
round's six criticals are that shape, and each was closed by making the two
sides different things rather than by adding another assertion:

| Finding | The instrument that agreed by construction | What it was replaced with |
|---|---|---|
| SP-C05 | the PROD name index and the body fetcher were the **same function over the same dump** | a **second derivation** (`sql-function-names-naive.mjs`) that imports nothing from the normalizer; the two are UNIONED, so absence needs both to miss |
| SP-C01 | a five-row "ORACLE" whose values **never reached the subject** | the spelling table now goes through the **real parser** (3a), and 3c's table generates **lane outputs** — its actual input axis |
| SP-C03 | `naive >= parsed`, true for **every possible input**, with neither side from the implementation | `parseFile`'s count, asserted **strictly below** the naive count |
| SP-C04 | assertions about a **string literal defined two lines above** | the **real `usage()` text**, mutilated, with both needles applied to the result |
| SP-C02 | the corpus run is **green by construction at 30/30**; the only proof-of-firing was unwired | `--self-test` wired into `sql-mutation`, pinned, and its coverage ranged over the runner's **own** `DEFECT_KINDS` |

Every fix was observed **RED before and GREEN after**, and the RED was produced
from **outside the subject** — a stub `git`, a stub `grep`, a chmod-000
directory, a node-less `PATH`, a signal from the injected query, or a neuter of
the implementation. Verbatim failure text is recorded per finding.

⚠️ **Byte backups only; `git checkout --` was never used.** Every restore was
verified by `shasum -a 256` against a backup re-taken after each edit. Before
every commit the staged diff was scanned for NUL, C0/C1 controls, NBSP, the
space separators, zero-width and bidi marks, `U+2028/9`, the interlinear block
and the astral tag block, with a detector written in **numeric code points
only** and calibrated on a planted sample each run (0 offenders, 18/18 files at
HEAD).

* the PR's function list: `--function-names` ∪ the naive reader;
* PROD's index: `BODY_NAME_INDEX_CMD` ∪ **`BODY_NAME_INDEX_XCHECK_CMD`** (new,
  **required** — optional would reinstate the hole, the SKIP-01 shape).

readings that share an implementation agree by construction."*

**AFTER, the same input, PROD holding the function:**

```
::warning::…the independent cross-check index found 1 function name(s) the primary index did not:
::warning::  sanitize_user$v2
::error::…: 'sanitize_user$v2' IS in the PROD source's function-name index, but the
::error::fetcher extracted no body for it. That is an extraction failure, not a new function.
GATE EXIT=1
```

and with PROD **not** holding it: `Functions defined or replaced by this PR: 1`
→ `measured absent` → exit 0. Both honest; neither is the old silent pass.

**Refuses nothing that exists.** MEASURED across all **380** `.sql` files under

definitions**): the two readings return **identical name sets, 0 disagreements**.
