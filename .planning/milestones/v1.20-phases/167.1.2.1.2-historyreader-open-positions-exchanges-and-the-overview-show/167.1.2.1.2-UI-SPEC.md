# Phase 167.1.2.1.2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds no component, no token, no colour and no layout. It changes two existing
surfaces, and both changes reuse patterns already shipped:

| Surface | Decision | Change |
|---------|----------|--------|
| Overview of the allocator dashboard (`AllocationDashboardV2.tsx`, via `historyGate` in `lib/history-gate.ts`) | D-04 | A book whose equity history is `ready` and whose positions are all closed renders the existing curve and factsheet render path, not the connected-but-empty card. No new copy, no new line (D-08). |
| Exchanges holdings panel, `Exchange Positions` section (`HoldingsTabPanel.tsx`) | D-05 | One muted line per stale key directly under the spot `Holdings` table, in the form and by the dating rule of the existing Open Positions read-day note (`openPositionReadDayNotes`). |

Items with no visual surface: item (1) and item (3) are closed by decision (D-01, D-03, no code). Item (2) (D-02, same-day empty clean poll) only removes rows from the existing tables. It adds no element, and the tables' existing empty forms ("No spot holdings." / "No holdings to display.", and the Open Positions table's own empty state) apply unchanged.

## Copywriting Contract

### D-05 stale-key spot line (the only new copy in the phase)

**Pinned template:**

```
Spot holdings from {keyPhrase} are as last read on {asof}: {symbols}.
```

- `{keyPhrase}` is the existing `keyPhrase(apiKey, venue)` output: `the Bybit key Main` when labelled, `the Bybit key` when the label is blank, `a Bybit key` when the key is not in `apiKeys`. Venue names come from the existing `venueName` (`OKX`, `MT5`, `sFOX`, otherwise capitalised).
- `{asof}` is the row's raw `asof` (`YYYY-MM-DD`, UTC), unformatted, as in the Open Positions note.
- `{symbols}` is the key's dated spot symbols joined with `", "`, in the order the rows arrive in `holdingsSummary`.

**Rendered examples:**

| Case | Rendered |
|------|----------|
| Labelled key, two symbols | `Spot holdings from the Bybit key Main are as last read on 2026-10-15: BTC, USDT.` |
| Unlabelled key | `Spot holdings from the Bybit key are as last read on 2026-10-15: BTC.` |
| Key not in the list | `Spot holdings from a Bybit key are as last read on 2026-10-15: USDT.` |

**Why "Spot holdings", not the "Balances" in the CONTEXT D-05 example** (the example is marked "for example", so the noun was open; Claude's choice):
1. The line sits under a table headed `Holdings`, whose own copy says "No spot holdings." and "Show holdings from …". "Balances" appears nowhere on this panel, and a new noun would make the reader wonder whether it means something other than the rows above it.
2. The Open Positions note names its own table's noun ("Positions from …"). The parallel for the Holdings table is "holdings". "Spot" keeps the two lines apart, since they sit in the same section a few rows apart.
3. The sentence form is otherwise the read-day sentence word for word (D-05, D-08): "{Noun} from {keyPhrase} are as last read on {asof}: {list}."

**Checked against DESIGN.md `## Voice / microcopy`:**
- Declarative, sentence case, no exclamation: yes.
- States the limit with its threshold: yes. The date is the threshold; the reader learns how old the figures are.
- No adjectives where a number exists: yes. No "stale", "old" or "outdated"; the date carries it.
- Active voice: the clause "are as last read on" is not active. This is a known tension. It is kept because D-05 and D-08 lock this phase to the existing read-day sentence form, and two dated lines in one section must read alike (CLAUDE.md Rule 7: the locked, shipped form wins). An active rewrite of both sentences is a separate copy change, not this phase's.
- Five-second test (would it survive print): yes. It names the source key, the date and the rows.

## Interaction and Render Contract

### D-04: Overview for a ready, all-closed book

The gate order stays fail-closed, and the precedence is pinned:

| # | Condition (evaluated in this order) | Overview renders | Risk renders |
|---|-------------------------------------|------------------|--------------|
| 1 | Book empty, nothing syncing, no eligible key (`hasConnectedKeys !== true`) | Connect-a-key `EmptyState` (unchanged, 170.4 D-09) | Connect-a-key `EmptyState` (unchanged) |
| 2 | `equityHistoryState !== "ready"` (missing, null, unknown, mis-cased) | `EquityHistoryRebuilding` panel (unchanged) | Rebuilding panel (unchanged) |
| 3 | History `ready`, book empty (all positions closed), eligible key | **The full Overview render: banners as their own conditions decide, `InsightStrip`, then the curve plus `FactsheetBody` when a factsheet payload builds, else the curve plus `FactsheetWarmupNote`. Same tree as row 4** | Its widgets (unchanged; it already renders here) |
| 4 | History `ready`, book not empty | Full Overview render (unchanged) | Widgets (unchanged) |

Rules:
- Row 3's focal point is the equity curve (`overview-equity-curve`), as in row 4.
- Row 3 adds no element, no line and no banner (D-04, D-08). Any widget that reads holdings shows its own existing empty form.
- In row 3 the Overview and the Risk tab agree: both show figures (the 170.4 D-04 goal this decision serves).
- Whether `connected_empty` stays a member of `HistoryGate` or is removed is the planner's call. Either way the Overview must not return `EmptyState` for a `ready` history while an eligible key exists, and Risk's behaviour must not change.
- The `BaselineUnknownBanner`, `DepartedHistoryNote`, `HistoryReconstructFailedNote` and `UnpricedAccountNote` render in row 3 under their existing conditions. They are not suppressed for an empty book.

### D-05: placement and markup of the stale-key spot line

- **Position:** inside the `Exchange Positions` `<section>`, directly after the spot `<HoldingsTable … />` and before `<OpenPositionsTable … />`, one `<p>` per key. It is a sibling in the section's grid, outside the Holdings card's border.
- **Markup:** `<p data-testid="holdings-read-day-note" className="text-xs text-text-muted [overflow-wrap:anywhere]">`. The testid is distinct from `open-positions-read-day-note`, so tests can tell the two notes apart.
- **Wrap:** `[overflow-wrap:anywhere]` is required. It is the repo's precedent for long unbroken spot symbols (v0.132.0.1, the MT5 `ACCOUNT-<hex>` symbol that ran 160px past its card at 375px). No `truncate`, no `whitespace-nowrap`, no `overflow-x-hidden`, no px `max-w`.
- **Dating rule:** identical to `openPositionReadDayNotes`. A spot row is dated when its `asof` is earlier than the later of (a) yesterday UTC relative to the tab's `today`, and (b) the newest `asof` across ALL rows in the book (spot and derivative). Both notes use the same reference, so the spot and derivative lines can never date the same key's read differently. Rows without `asof` say nothing.
- **Grouping:** one line per `api_key_id`. The date is that key's spot rows' `asof`. Under D-16 a key's rows share one read day.
- **Toggle independence:** the line is computed over all spot rows, whatever the `Show holdings from …` toggle says, as the Open Positions note is. When the toggle hides a key's rows, the existing hidden-count footer already discloses them.
- **Order of lines:** by the key's first appearance in `holdingsSummary`, as the existing note orders its keys.
- **No table change:** no column, chip or row style is added (D-05). Strike-through and the disconnected chip on departed keys' rows stay as they are.
