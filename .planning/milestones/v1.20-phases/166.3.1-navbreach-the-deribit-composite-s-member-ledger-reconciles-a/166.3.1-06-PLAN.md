<objective>
Implement half (b) of the founder's D-05 decision (2026-10-07, "Add status to cache key"): the
public factsheet cache key carries `computation_status` alongside `computed_at`. Plan 02 makes
`computed_at` move only on a successful write. The cache key used to rely on the job-start and
failure stamps to move ("so the key moves when a compute starts AND when it completes"). Without
this plan, a complete payload cached under `computed_at = t0` would keep being served while the
row is `computing` or `failed` under the same t0, for up to the 3600 s TTL. That would undo
STALE-01's withholding gate.

Purpose: the status change, not a timestamp side effect, invalidates the entry.
Output: the key change, a test shown RED on today's key, updated censuses and invariant comments.
</objective>
