## Deviations from Plan

**1. [Rule 1 - the plan's falsifier premise was false] Removing the sort alone does NOT turn arm 33 RED**
- **Found during:** Task 2 (d).
- **Issue:** the plan's truth reads: "neutering the emit sort … turns arm 33 RED, because the fixture allowlist lists the `update:` line ABOVE the INSERT line". `modeEmit` pushes blocks in two passes: every INSERT entry first, then every C5 pair. With the sort line deleted, the fixture still emits INSERT, INSERT, UPDATE. I measured this rather than assumed it. With the sort-deleted copy in the seam the run printed `ok 33 …` and `self-test OK (34/34 arms`.
- **Fix:** the copy was neutered the way the plan's action text says, "push blocks in entry order". Each block is ordered by its allowlist `lineNo`, which puts the UPDATE first. That turned arm 33 RED (table above).
- **What this means for coverage:** arm 33 falsifies emission in allowlist-line order. It does not falsify deleting the sort alone. The real-corpus order pin from plan 01 catches that: with the sort line removed, plan 01 measured a cross-file UPDATE moving after a later file's INSERT. A fixture that made sort-removal alone bite would need a second fixture migration file, and the plan forbids that (RESEARCH Pitfall 9, the ledger arms pin 3 files).
