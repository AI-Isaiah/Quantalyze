## What this phase ships, and why that shapes the threat model

`git diff <merge-base with origin/main>..HEAD`, excluding `.planning/`: the
reference-data extractor (`scripts/extract-reference-inserts.mjs`) gains a C5
class (top-level literal UPDATEs on replayed `public` tables, replayed in
migration order; non-literal writes accounted for by `decline:` lines), its
allowlist and fixtures, the restore script's replay bracket and C5 trailer
checks (`scripts/restore-test-from-baseline.sh`), two C5 census steps in CI,
and vitest harnesses. **No migration, no route, no RLS policy, no grant, no
dependency manifest change, no user-facing surface.**

⭐ **The dominant threat is TAMPERING of shared TEST through replayed SQL.**
Statement bytes from applied migrations execute inside the restore transaction
that COMMITs on a database other people's CI uses. Every C5 control exists to
keep what reaches that transaction literal, in order, accounted for and
resolved against built-ins.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| migration corpus → replayed SQL | applied migrations' original bytes run inside the restore transaction | literal UPDATE / INSERT statements only |
| allowlist → classifier | a human-edited file decides which statements run | `update:` / `decline:` / INSERT pins |
| extractor output → restore transaction | emitted SQL is concatenated (not heredoc-expanded) into the transaction | statements plus `-- refdata*` trailers |
| audit output → CI verdict | workflows decide pass/fail from printed census lines | counts only |
| local lane → developer machine | this checkout's CLI is linked to PRODUCTION | nothing; loopback-only lane |
| Actions → shared TEST | the restore rebuilds a shared database | gated by ref guard, environment, marker, mutex, activity gate |

### The C5 trailer-vs-pin checks fail before any write (T-04 / T-05 / T-13 support)

Two independent comparisons, both before `run_transaction` opens a session:
`refuse_bad_refdata_allowlist` compares the preflight emission's
`-- refdata-update:` / `-- refdata-decline:` counts against the allowlist's
`update:` / `decline:` sums, and `build_transaction` repeats the comparison on
the REPLAYED emission (`REFDATA_UPDATE_PINNED` / `REFDATA_DECLINE_PINNED`).
Self-test arms 24 (d)/(e) and 36 drive each direction.

### The replay bracket (T-02 support)

`build_transaction` wraps the emission in `SET LOCAL search_path = pg_catalog,
public` and restores `pg_catalog` right after. With `pg_catalog` listed first,
built-in functions, operators and cast types win over any `public` twin.
Arm 35 plants a `public` `now()` and `=` and measures both orders. ⚠️ Residual,
informational: an operator whose EXACT argument types exist only in `public`
(for example an operator on a user enum) still resolves there. That matches
PROD's own resolution when the migration ran, which is what the replay must
reproduce, so it is not a gap in this control.

### Post-merge obligation — T-164.9.2-17 and the procedural half of T-16

The act T-17 guards (a `mode=restore` dispatch on shared TEST) does not exist
