# Phase 164.8.1 Plan 03: the seeder's false inference, and the PROD-compute hazard booked — Summary

The e2e seeder stopped telling readers that a missing `crypto-sma` row means a migration
never ran — it did run, is ledgered, and only its DML is gone — and the hazard the founder
chose to replay faithfully rather than normalise away is now a dated finding with a phase.

## What changed

### 1. `scripts/seed-demo-data.ts` — the message (commit `1a3f556e`)

Removed, because it is measurably false after a schema-only restore:

> `The initial schema migration (20260405061911_initial_schema.sql) seeds this row — if it's missing the migration didn't run.`

The restore seeds the ledger from the repo file set, so all 266 migrations read as applied and
`supabase db push` skips them. The migration ran. What is absent is its DML. A reader who
believed the old sentence would go hunting a migration that never failed — the exact time this
session spent. The replacement:

```
[seed] discovery_categories row for slug='crypto-sma' not found.
20260405061911_initial_schema.sql seeds it and the TEST restore replays it
(scripts/restore-test-from-baseline.sh, Phase 164.8.1). A ledger row for that
migration does NOT prove the row exists: the restore loads a schema-only dump, so it
reseeds the ledger but replays no DML of its own. On TEST, read the
refdata:public.discovery_categories census row from the last
test-restore-from-baseline run — a 0 there is a restore defect to NAME, not a reason
to hand-seed shared TEST (Phase 164.8 Plan 06). Error: <catErr>
```

The query, the `.single()`, the `throw`, and the `Error: ${catErr?.message ?? "no rows"}` tail
are byte-unchanged. Diff is `+8 −2`, entirely inside the one template string.

⚠️ **Stated honestly — one forward reference.** `refdata:public.discovery_categories` is the
census row **Plan 02 (wave 2) emits**; `grep -n refdata scripts/restore-test-from-baseline.sh`
returns nothing at this commit. The message is true the moment Plan 02 lands and is wrong for
nobody in between, because the only way to reach this throw is a TEST run that Plan 02's gate
would already have reddened. It is named here so it is a known dependency, not a discovery.
