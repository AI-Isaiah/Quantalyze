## Warnings

### WR-01 (MEDIUM, data truth, regression introduced by 3194279bf): any zoom un-dashes the last EOY and Calmar year, which still show the whole-record figure

**Files:**
- `src/app/factsheet/[id]/v2/MetricsColumn.tsx:266` (the gate includes `!selected`), `:403` and `:441` (the gate is passed to `EoyReturnsPanel` and `CalmarByYearPanel`), `:1144` (`useBasisSeriesView`, not windowed) and `:1186`.
- `src/app/factsheet/[id]/v2/AnalyticalPanels.tsx:287-290` (`view = useBasisSeriesView(payload)`, and the comment "per-calendar-year figures stay full history") and `:326`.

**Issue:** `wholeRecordWithheld` is scoped to D-78's window exemption, "a selected window keeps its slice figures". That scope is right for the panels that read `useWindowedView`: Rolling, Extended, Bootstrap and Best/Worst all switch to the slice. EOY Returns and Calmar by Year do not switch. Inside a zoom they keep rendering `useBasisSeriesView`, which is the whole record, under the "Full history" scope note (`MetricsColumn.tsx:403`, `AnalyticalPanels.tsx:305-308`).

So inside any zoom the gate is false, `dashed` is false, and the last row prints `stratYearly[lastYear]` again. That value is the withheld whole-record Year-to-date return (identity pinned by the new WR-01 test). The Calmar row prints its Return, Max DD and Calmar. None of these is a slice figure, so D-78 does not cover them. The same panel label "Full history" then sits over the number the full-history page hides.

**Failure scenario:**
1. A Withheld api strategy's record runs into 2026. At full history, EOY 2026 reads "—".
2. The user drags the master brush over any range, for example 2023 only.
3. EOY Returns ("Full history") › 2026 › Strategy reads, for example, "+3.84%". Calmar by Year › 2026 reads its Return, Max DD and Calmar.
4. Nothing else on the page prints that whole-record YTD at that moment. The Returns panel's Year-to-date is the 2023 slice's.

**Test gap:** no test renders EOY or Calmar on a Withheld row inside a zoom. The 62-case window exemption does not include these cells, so CI stays green.

**Fix:** dash these two panels on their own scope, not the slice-aware gate. Pass a second boolean computed without `!selected`, for example `const fullHistoryWithheld = !railLeverageApplied && isHeadlineWithheld(payload.dataQuality, railBasis);`. Then:
- Pass `wholeRecordWithheld={fullHistoryWithheld}` to `EoyReturnsPanel` and `CalmarByYearPanel` only.
- Add a test that renders the Withheld payload with a selected range (the window-exemption harness) and asserts the last EOY and Calmar rows read "—".
- Run it RED once against the current code.

### WR-02 (MEDIUM, data truth): `EndOfYearBarsPanel` prints the dashed Year-to-date figure, and the benchmark's, as SVG text, not only as a bar height

**File:** `src/app/factsheet/[id]/v2/DistributionPanels.tsx:51` (`stratByYear = view.strategyMetrics.yearly`), `:181-191` (strategy value label `{pctSigned(r.strat)}`), `:196-207` (benchmark label `{pctSigned(r.bench)}`).

**Issue:** this answers the brief's question directly. The panel draws a bar and also writes a right-edge `<text>` label for every year, at 1 dp (`PCT_DEFAULT_DP = 1`, `format.ts:31`). On a Withheld row its last row prints the whole-record current-year return, which is the dashed Year-to-date figure. When a comparator is selected it also prints the benchmark's current-year return, which the Returns panel dashes through `headlineBenchSource`.

- The labels are DOM text, so screen readers and copy-paste get them too.
- There is no tooltip. The `aria-label` is generic (`:121`) and carries no value.
- The scale caption `±{maxAbs}%` (`:107`) can also be set by that year.

After 3194279bf, the EOY table two columns away reads "—" for the same year while this chart labels it. The fix made the contradiction easier to see.

**Why the TODOS booking does not cover it:**
- `TODOS.md:1535` files it under founder item 2. That item, quoting CONTEXT's "Plan 15 residue" line, is about "the EOY Returns and Calmar by Year rows for the break year". The TODOS text defines it as "a break year that is NOT the Year-to-date year". This bar is the Year-to-date year, the case WR-01 already decided to dash.
- The booking's rationale, "Charts show the whole record by design (the Withheld note says so for the strip)", is wrong for a Withheld row. The Withheld note text (`MetricsColumn.tsx:105-108`) has no chart clause. Only the Dated variants say "the chart shows the whole record" (`:117`, `:122`, `:127`).

**Failure scenario:** on a Withheld row at full history, Returns › Year-to-date and EOY Returns › 2026 read "—". End-of-Year Returns › 2026 prints "+3.8%" next to the bar, and the benchmark's "+12.1%" beneath it.

**Fix:** decide this with the gate, not a footnote. The gate lives in `MetricsColumn`, so compute the same full-history predicate as WR-01 in `EndOfYearBarsPanel`, or lift it into a shared hook that both read. Under that predicate, drop the last year's strategy and benchmark `<text>` labels, the same scope as the table. Either drop that year's bars too, or keep them and exclude them from `maxAbs`, so the scale caption does not encode them. Add a render test that asserts no last-year label text on Withheld and that the label is present on Dated. If the founder prefers to keep the bar, correct `TODOS.md:1535` so the entry says the chart prints the YTD-year figure as text, not "a bar", and that the Withheld note does not mention charts.

### WR-03 (MEDIUM, data truth, unbooked): the Monthly Returns heatmap's "YTD" column prints the dashed Year-to-date figure under a header that says YTD

The per-month cells are per-period entries (class d) and are not in question. Only the last row's YTD cell is.

**Failure scenario:** Withheld row, full history. Returns › Year-to-date reads "—". Monthly Returns › 2026 › YTD reads "+3.8%", green.

**Fix:** under the same full-history Withheld predicate as WR-01 and WR-02, render the last row's YTD cell as "—" with no tone. Leave every earlier row's total and every month cell as they are. ### WR-04 (MEDIUM, data truth, plan 15 residue missed by round 1): the rolling charts print an "avg" label equal to the rail's dashed Rolling Avg

**File:** `src/app/factsheet/[id]/v2/TimeSeriesChart.tsx:969-1003` (`showStratAverage`, `<text>avg {…}</text>`). The configs are `src/app/factsheet/[id]/v2/chart-configs.ts:196-226` (`rollingVol`, `rollingSharpe`, `rollingSortino`, all `showStratAverage: true`).

**Issue:** plan 15 dashes Rolling Metrics Avg (A23, A26, A29) because it "aggregate[s] every warm window of the whole record" (`MetricsColumn.tsx:860-861`). The three rolling charts in Performance read the same `strategyRolling*` series. At full history their `xRange` covers the whole axis. They sum the finite values over it and print `avg 1.23` (ratio, 2 dp) or `avg 11.1%` (vol, 1 dp). Hover is interactive, so that part is lower weight. The static "avg" label is printed unprompted.

This predates the round-2 diff. It falls under the brief's "a still-printed copy of a dashed figure", and no record books it.

**Failure scenario:** Withheld row, full history. Rolling Metrics › Sharpe › Avg reads "—". Rolling Sharpe (6mo) chart, directly left, reads "avg 1.87".
