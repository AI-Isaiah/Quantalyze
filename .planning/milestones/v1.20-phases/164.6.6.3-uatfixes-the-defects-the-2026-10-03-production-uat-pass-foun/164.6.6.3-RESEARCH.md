## Summary

**Item 0 is a small, well-bounded change with one real design hazard.** `read_mt5_deal_ledger` is one synchronous block (`login` → `account_info` → PRE bracket → `history_deals_get(0, now+1d)` → POST bracket), run by two callers through `asyncio.to_thread` under `asyncio.wait_for(..., 40 s)` and the per-terminal lease. The wait belongs inside that helper, between the first deal read and the POST bracket, as a deadline-based poll using module-level `_clock`/`_sleep` (the `mt5_relogin` precedent). The helper must keep deciding nothing about what a failure means: it raises one NEW plain-`Exception` subclass on expiry and each caller maps it (transient, no stamp, no restart, ERROR). The hazard is the freshness test: `Mt5Client.login` stamps the prior-holder registry on success, so the test has to run BEFORE `login()`, and "previous holder == this key" is not enough, because a transient expiry makes the retry look cached and read a partial history. Add a per-(terminal, holder) "history settled" record and treat "stable at zero while equity is material" as NOT settled. The Journal evidence (`synchronized` at 10:38:27.2, bad read at 10:38:27.9) proves the "synchronized" line is not a history-complete signal.

**D-06's "own `error_kind`" is a schema change if taken literally.** `compute_jobs.error_kind` is DB-checked and the RPC rejects anything outside three values. The cheap, repo-conformant reading is `error_kind="transient"` plus a distinct named message key (the `_MT5_BACKFILL_MESSAGES` pattern). Both options are costed under Open Question 1; the recommendation is the message key.

**The flip is bigger than the pin test.** Flipping `_JOB_TERMINAL_DELETE_TRADES` to 1 turns four other jobs-path assertions red, leaves a fail-loud gap (`_escalate_ipc_fault` never reads `faults.trades_errored`, so a failed trades delete would log at INFO), and strands about seven prose sites. The `TODOS.md` gate's live reading (trades count falls, next derive succeeds) is still owed, so the entry becomes `human_needed`, not closed.

**Item 9: no reliable known-server source exists, and the repo already decided against the one candidate.** `servers.dat` is binary, undocumented, disputed on encryption, and flagged by MQL5 as not for third-party use; `TODOS.md` (~7330) and `153-EVIDENCE` B8 already rejected reading it ("not a route we should take"). That conflicts with D-09's example, so under Rule 7 this research picks one and flags the other: **a repo-owned curated known-server list, failing closed into a new recoverable wire code**, coupled by the runbook to the operator act of adding the server to both terminals. My attempt to read `servers.dat` on the live gateway was denied by the permission classifier, so there is NO observation of its format; that measurement is a founder checkpoint (D-03). The check belongs in the shared `mt5_probe` mechanics before `client.login`, with dispositions left at the two validate sites (PARITY-01), and the TypeScript wiring follows commit `ea4167a3f` (`MT5_TERMINAL_UNRESPONSIVE`) file for file.

**Primary recommendation:** Ship item 0 as three commits in this order — (1) failing-first race test + helper wait + both callers + the new exception arms, (2) the ONE flip commit (ledger line + constant + the four stale assertions + the `trades_errored` ladder arm), (3) item 9 plumbing with a curated-list source — and make the `servers.dat` measurement an optional founder-led task that can only change the detection SOURCE, never the wire code, copy or runbook.

### Pattern 1: the read helper decides nothing (leaf-module doctrine)
**What:** `mt5_read.py` performs the read and lets typed exceptions out; the lease, the `wait_for` bound and every disposition stay at each call site. Its docstring lists five reachable exceptions; the new one is a sixth.
**Evidence:** `services/mt5_read.py:12-39` — "⛔ THIS MODULE DECIDES NOTHING ABOUT WHAT A FAILURE MEANS." The derive caller restarts on timeout but not on a fence refusal; the backfill caller answers some differently.
**Rule for the new exception:** a plain `Exception` subclass, NOT `asyncio.TimeoutError` (the timeout arm restarts the terminal) and NOT `Mt5ClientError` (`classify_mt5_login_error` can turn it into a credential verdict). Same discipline as `_Mt5PostReadVerificationError` and `Mt5SessionAbandoned`. Carry counts only (deal count, materiality boolean), never a login, server or amount.

### Pattern 2: injectable clock and sleep as module attributes
**Evidence:** `services/mt5_relogin.py` carries `_clock: Callable[[], float] = time.monotonic` and `_sleep: Callable[[float], None] = time.sleep` with the comment "A module attribute, not a bare `time.monotonic` call, only so the budget-gated paths can be driven against a clock whose every crossing costs its full ceiling" (`mt5_relogin.py` ~490-498, read this session). `tests/test_mt5_relogin.py` has a `_fake_clock`/`_FakeClock` fixture. Copy the shape into `mt5_read.py`.

### Pattern 3: one derived outer bound, read at call time
Keep `_MT5_DERIVE_READ_TIMEOUT_S` untouched. Add `_MT5_HISTORY_WAIT_S` beside it in `mt5_concurrency.py` and compute `base + wait` AT THE CALL SITE from module attributes, so existing tests that `monkeypatch.setattr(jw, "_MT5_DERIVE_READ_TIMEOUT_S", 0.1)` keep biting. A value computed once at import would freeze the sum and silently stop those tests from moving the bound.

### Anti-Patterns to Avoid
- **Editing `_MT5_DERIVE_READ_TIMEOUT_S`.** The holdings arm (`allocator_positions.py:811`) and the balance arm (`job_worker.py:424`) share it, and `tests/test_mt5_concurrency.py::test_timeout_constants_survived_the_move` pins `read_s == MT5_REQUEST_TIMEOUT_S + 10.0`.
- **Letting the expiry arrive as `asyncio.TimeoutError`.** It would restart a healthy terminal (`_mt5_bounded_restart`) in the middle of its own history download.
- **Importing `job_worker` into `mt5_read`.** `mt5_read` is a leaf (`job_worker` imports it). Pass the material-equity floor in as a parameter; callers already see `_DERIBIT_EMPTY_LEDGER_FLOOR_USD` (`equity_reconstruction.py` already imports from `services.job_worker`, `equity_reconstruction.py:67-76`).
- **Deciding freshness after `login()`.** `Mt5Client.login` ends with `_note_terminal_holder(self.terminal_key, stage="login")`, which overwrites the very record the test needs.

## Item 0 — findings, with evidence

### 0.1 `read_mt5_deal_ledger` and its callers [VERIFIED: services/mt5_read.py:83-138]
One synchronous block: `session.client.login(...)` → `info = session.client.account_info()` → `assert_expected_login(info, login=session.login)` (PRE) → `deals = session.client.history_deals_get(0, int(now.timestamp()) + _MT5_DEAL_FETCH_MARGIN_S)` → POST `account_info()` (wrapped so a transport blip becomes `_Mt5PostReadVerificationError`) → `assert_expected_login(post_info, ...)` → `return info, deals`. The new loop goes between the first `history_deals_get` and the POST bracket, so the POST bracket also covers the poll window (another actor switching the terminal during up to 30 s is caught, and its deals discarded).

| Caller | Evidence | Bound used |
|---|---|---|
| derive | `job_worker.py:4955-4960`: `asyncio.wait_for(asyncio.to_thread(read_mt5_deal_ledger, _mt5_session, now=_mt5_now), timeout=_MT5_DERIVE_READ_TIMEOUT_S)`, inside `async with mt5_terminal_lease(..., holder=ctx.key_row.get("id"), site=SITE_DERIVE)` | the job_worker module alias |
| backfill | `equity_reconstruction.py:3048-3057`: same shape, `holder=api_key_id`, `site=SITE_BACKFILL`, `timeout=_mt5_conc._MT5_DERIVE_READ_TIMEOUT_S` ("Read through the module so the bound stays ONE constant") | read through `_mt5_conc` |

Both run the read with `asyncio.to_thread`, so the helper is plain blocking code: `time.sleep` is correct, no `await`, no event-loop implication. The lease is held for the whole poll (the one shared terminal serialises every MT5 job), so a fresh account costs up to 30 s of every other job's queue time. That is the price D-04/D-05 chose; it is paid only on a fresh login.

### 0.2 The bound [VERIFIED: services/mt5_concurrency.py:91-93]
```
_MT5_DERIVE_READ_TIMEOUT_S: Final[float] = float(
    os.getenv("MT5_DERIVE_READ_TIMEOUT_S", str(_MT5_REQUEST_TIMEOUT_S + 10.0))
)
```
with `MT5_REQUEST_TIMEOUT_S = float(os.getenv("MT5_REQUEST_TIMEOUT_S", "30"))` [VERIFIED: services/mt5_client.py:262]. So 40 s by default. The restart arm on expiry is `_mt5_bounded_restart` (`mt5_concurrency.py`, ~10 s cap).

**Derivation (D-05).** `outer = _MT5_DERIVE_READ_TIMEOUT_S + _MT5_HISTORY_WAIT_S` = 40 + 30 = 70 s, computed at the call site. The loop is deadline-based (`deadline = _clock() + _MT5_HISTORY_WAIT_S`, no read starts at or after the deadline), so the only overshoot is one in-flight read, which "the read's own budget" (the 40 s base) already covers. Raise the helper's own expiry BEFORE the outer bound: the helper's deadline fires at wait-budget, the outer at wait-budget plus the read budget, so a healthy-but-slow history download can never reach the restart arm. 70 s is under the ~90 s healthz budget cited at `mt5_client.py:260` and far under `TIMEOUT_PER_KIND` (`"reconstruct_allocator_history": 30 * 60`, `"derive_broker_dailies": 15 * 60`, [VERIFIED: services/job_worker.py:524,527]).

**Decision for the planner (pre-decide vs always-raise).** Recommended: the caller computes `fresh` once before spawning the thread and passes it as `settle_history=fresh`, and uses `+ wait` only when `fresh`. That keeps the 40 s wedge detector for cached accounts (D-04 "pays no wait") and is deterministic to test. The alternative (always raise the bound at these two sites) is simpler but delays real-wedge restarts by 30 s on every cached read.

### 0.3 Fresh-login detection [VERIFIED: services/mt5_client.py:706-718 and 740-793]
The registry: `_MT5_TERMINAL_HOLDERS: dict[str, str] = {}`, with the literals
```
HOLDER_HOUSE: Final[str] = "house"
HOLDER_VALIDATION: Final[str] = "validation"
HOLDER_UNKNOWN: Final[str] = "unknown"
HOLDER_UNATTRIBUTED: Final[str] = "unattributed"
```
`mt5_terminal_holder(terminal_key)` reads it; `Mt5Client.login` stamps it AFTER a successful login (`_note_terminal_holder(self.terminal_key, stage="login")`); `recycle_terminal_process` and the scrub stamp `HOLDER_UNKNOWN` (`mt5_client.py:3474`, `:3619`). The lease context carries the holder in `_MT5_LEASE_HOLDER` (a `ContextVar`), which `asyncio.to_thread` copies into the thread. It is in-process memory only: a restart empties it, which reads as "fresh" (safe direction: the poll is cheap when the history is already cached).

Three traps, each needing a decision in the plan:

1. **Read the prior holder before `login()`.** After it, the registry names this key. Compute `previous = mt5_terminal_holder(terminal_key)` and `holder_now` from the call site (derive: `ctx.key_row.get("id")`, backfill: `api_key_id`) BEFORE spawning the thread. 2. **The retry hole.** After a transient expiry, this key's retry sees itself as the previous holder, skips the wait and can read a partial history: either a permanent stamp again or, worse, a plausible-looking but wrong series (breaks "never invent data"). ## Common Pitfalls

### Pitfall 1: every existing derive/backfill test is "fresh" and will start polling
`reset_terminal_state_for_tests` (autouse in `tests/conftest.py`) empties `_MT5_TERMINAL_HOLDERS`, so every legacy test that drives the derive or backfill path now takes the poll path. **Prevent:** an autouse conftest fixture setting `mt5_read._sleep` to a no-op (a fake that returns the same deals settles at the second read, so no spin); the three timeout tests that move the bound (`test_mt5_derive_branch.py:852,916` set `jw._MT5_DERIVE_READ_TIMEOUT_S = 0.1`; `test_equity_reconstruction.py:6028` sets `_mt5_conc._MT5_DERIVE_READ_TIMEOUT_S = 0.05`; `test_allocator_positions_non_ccxt.py:1059` is the holdings arm and is unaffected) must also set `_MT5_HISTORY_WAIT_S` to ~0, or the freshly-added 30 s turns each into a 30 s test. Never-settling tests inject a fake clock that advances per sleep instead of using the real clock.

### Pitfall 2: the retry reads a partial history
Covered in 0.3(2). **Warning sign:** a retry log shows no wait and a `<2 usable days` or a short series.

### Pitfall 3: the expiry reaching the restart arm
If the helper's expiry is implemented with `wait_for` inside the thread, or raised as `TimeoutError`, `_mt5_bounded_restart` fires on a healthy terminal. **Verify:** a test asserts `connects == 1` and no `shutdown` in `transport.calls` on the unsettled path (the derive fake already records both).

### Pitfall 4: the new message is classifier-matchable
`compute_jobs.error_message` is re-classifiable. See 0.4.

### Pitfall 5: the trades flip silently logs at INFO
See the ladder row in 0.6.

### Pitfall 6: the pin test goes red on the ledger line alone
The line and the constant flip must be one commit, failing-first (write the failing assertion first, see RED against 0, then flip).

### Pitfall 7: `login_attempted` ordering at the validate sites

### The settle loop (sketch; names are suggestions)
```python
# services/mt5_read.py — Source: derived from the in-tree read helper and the
# mt5_relogin _clock/_sleep precedent; not copied from any external source.
import math
import time
from collections.abc import Callable

_clock: Callable[[], float] = time.monotonic
_sleep: Callable[[float], None] = time.sleep


class Mt5HistoryUnsettledError(Exception):
    """The wait budget expired before the deal count settled. A PLAIN Exception:
    never an Mt5ClientError (the credential classify arm) and never a
    TimeoutError (the terminal-restart arm). Counts only."""

    def __init__(self, deal_count: int, material: bool) -> None:
        super().__init__("mt5 deal history did not settle within its wait budget")
        self.deal_count = deal_count
        self.material = material


def _settle(read, info, first, *, floor: float) -> list[dict]:
    try:
        equity = float(info["equity"])
    except (KeyError, TypeError, ValueError):
        return first                     # the callers' guards fail loud on it
    if not math.isfinite(equity):
        return first
    material = abs(equity) > floor
    deadline = _clock() + _MT5_HISTORY_WAIT_S        # from mt5_concurrency
    previous, deals = len(first), first
    while True:
        remaining = deadline - _clock()
        if remaining <= 0:
            raise Mt5HistoryUnsettledError(previous, material)
        _sleep(min(_MT5_HISTORY_POLL_S, remaining))
        deals = read()
        count = len(deals)
        if count == previous and (count > 0 or not material):
            return deals                 # then: record (terminal, holder) as settled
        previous = count
```
