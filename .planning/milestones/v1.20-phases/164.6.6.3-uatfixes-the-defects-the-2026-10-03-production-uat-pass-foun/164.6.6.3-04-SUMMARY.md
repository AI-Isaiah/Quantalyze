# Phase 164.6.6.3 Plan 04: the shared known-server pre-check Summary

One shared `assert_mt5_server_known(server, *, site)` decides whether a broker server is on the curated list
(`MT5_KNOWN_SERVERS` plus the house `MT5_SERVER`, trim and case-fold), raises a typed plain-Exception refusal
on a miss or on an empty list, logs ERROR on every miss with a sanitised server, and captures to Sentry at most
once per server per hour. It emits no wire code and is wired into no validate site yet.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's `MT5_SERVER_UNKNOWN_DETAIL` text collides with a real cascade needle**
- **Found during:** Task 1, while writing the needle-sweep test
- **Issue:** The plan's text says "this broker server". `src/lib/wizardErrors.ts::classifyKeyValidationError`
  has a `lower.includes("broker server")` branch (it is what classifies `MT5_WRONG_SERVER_DETAIL`), so the
  plan's string would classify as `KEY_MT5_WRONG_SERVER` wherever the cascade is reached. The `closed_sets.py`
  STRING-SAFETY comment the plan told the test to take its needles from omits three real branches:
  `master password`, `broker server`, `etimedout`.
- **Fix:** Reworded to "Our MetaTrader terminals do not recognise this server yet. Check the spelling of the
  name; if it is right, we have been notified and will add it." The sweep test carries the full needle list,
  including those three, plus the `ip` and `allow` pair. The stale comment's needle list was not rewritten
  (surgical); the new comment line points at the test, which is the executable list.
- **Files modified:** `analytics-service/services/closed_sets.py`, `analytics-service/tests/test_mt5_server_known.py`
- **Commit:** `e96f95e09`

**2. [Rule 2 - Missing critical] Bounded dedupe table**
- **Found during:** Task 1
- **Issue:** The plan keys the capture window on the sanitised server, which is user input. An unbounded dict
  is a memory sink for a flood of distinct junk, the same hazard T-164.6.6.3-16 names for Sentry.
- **Fix:** `_SERVER_UNKNOWN_ALERT_MAX_KEYS = 256`; stale entries swept at the bound, capture skipped if still
  full (the ERROR line is never skipped). Keys are prefixed (`server:` and `cause:`) so a user server cannot
  collide with the unconfigured cause. Pinned by a test and a neuter.
- **Commit:** `e96f95e09`
