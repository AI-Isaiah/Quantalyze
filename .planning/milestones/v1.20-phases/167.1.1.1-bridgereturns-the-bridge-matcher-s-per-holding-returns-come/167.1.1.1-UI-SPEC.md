### What disappears

1. **State D is removed.** `DERIVATIVE_NOTE` ("Return, Sharpe, max drawdown and volatility are not
   shown for derivative holdings yet. A price rise is a gain on a long position and a loss on a
   short one, and these figures wait until that direction is defined for each day.") is deleted.
   Its premise is gone: this phase defines the direction per day (D-02, which SUPERSEDES 167.1.1
   D-03's "Derivative holdings stay `"rebuilding"`").
2. **The `"rebuilding"` history state has no producer left.** `holdingCompareHistoryState` returned
   `"rebuilding"` only for derivatives. After this phase both `spot` and `derivative` reach the
   price rule, so the `{ historyState: "rebuilding" }` variant of `HoldingCompareItem` and the
   `"rebuilding"` return of `holdingCompareHistoryState` are removed rather than left as dead
   union members. The planner greps every reader of `"rebuilding"` on the `/compare` path before
   removing it, and names each one it changes.
3. **The note slot keeps its test id.** `data-testid="holding-factsheet-rebuilding"` stays on the
   note `<p>`. It now hosts only withheld notes and State X. Renaming it would churn
   `HoldingFactsheet.test.tsx` and `compare/page.test.tsx` for no reader-visible gain (Rule 3). A
   test asserting a DERIVATIVE item renders that test id is rewritten to assert the grid instead.
4. The header comment of `HoldingFactsheet.tsx` that says "Derivatives stay withheld until a signed
   basis is defined (State D)" is rewritten to name State RD.

### State RD — derivative, ready (NEW; replaces State D)

The existing ready `<dl>` grid renders byte-for-byte: labels `Cumulative return`, `Sharpe`,
`Max drawdown`, `Vol (annualized)`; values through the existing `fmtPct` / `fmtNum`; annualization
365 (D-06), as for spot. Below the grid, in the existing `holding-factsheet-price-basis` `<p>`
(`max-w-prose text-sm text-text-muted`), the derivative caption replaces the spot one:

> `Computed from {N} days of {SYMBOL}'s daily mark price. A price rise counts as a gain while the position was long and as a loss while it was short, so opening, closing or resizing the position does not count as a gain or loss.`

- **This is how the card says the series is direction-signed.** The caption names the rule in
  the reader's terms (long gain, short loss) and the consequence that matters (trading does not
  read as return). No label suffix, chip or icon is added.
- `{N}` = `analytics.priced_days` through the existing `dayCount` (`1 day` / `{N} days`, thousands
  separators). For a derivative it counts only days that carry BOTH a positive mark and an
  established direction. ⛔ Never render the caption without `{N}`.
- `{SYMBOL}` = `item.symbol` as the heading renders it.
- "while" is deliberately neutral about which day's direction governs an interval. The planner
  owns that rule (CONTEXT, Claude's Discretion: candidate "day i-1's direction governs the move
  from i-1 to i"), and this sentence stays true under either choice.
- ⛔ The spot caption ("…so buying, selling or moving more of it does not count…") must NOT render
  for a derivative, and the derivative caption must NOT render for spot. A test pins both
  directions.
- **Gap clause (binds to the planner's return rule).** If derivative cumulative return and max
  drawdown are compounded from signed adjacent-day returns only (so a price move across a missing
  calendar day is dropped, unlike spot's level ratio), append one sentence to the same `<p>`:
  `A price move across a missing day is not counted.` If the planner's rule DOES count a move
  across a gap, the sentence is omitted. The plan must state which rule it chose and which caption
  form follows; an executor never picks this alone. (Rationale: for spot, `last / first - 1` over
  the price level spans gaps; a signed series cannot use a level ratio once the sign changes, so
  the two types may legitimately differ, and the reader must be told when they do.)

### State RD0 — derivative, ready, too few priced days

Identical to 167.1.1 State R0, same copy, same slot, em-dashes `—` in all four values:

> `Only {N} priced {day|days} of {SYMBOL} so far. These four figures need at least {MIN} priced days.`

`{MIN}` = `HOLDING_COMPARE_MIN_PRICED_DAYS`, read by symbol. "so far" is true here: 1 to `MIN - 1`
usable days means the history is filling.

**`too_few_priced_days` on `/compare` is rendered as State R0 / RD0, not as a withheld note.**
D-03 names `too_few_priced_days` as the withheld reason on the MATCHER side (Python
`holding_flags`), and the shared fixture pins that string. On `/compare` the same condition already
has a better rendering: the grid with em-dashes plus the threshold sentence, which names `{N}` and
`{MIN}`. The adapter keeps returning `"ready"` with null metrics below `MIN`, and the fixture maps
`too_few_priced_days` to that outcome. ⚠️ If the planner nevertheless adds `too_few_priced_days` to
the TypeScript `HoldingWithheldReason` union (for example so both languages share one closed set),
its `withheldNote` case reads:
`Return, Sharpe, max drawdown and volatility are not shown for {SYMBOL}: fewer than {MIN} usable priced days have been recorded.`
and the R0 grid path stays the one the adapter actually produces. One rendering per condition;
never both.

### State RD2 — derivative, ready, at or above the minimum, vol null

Identical to 167.1.1 State R2: the existing `holding-factsheet-adjacency-note` renders
`Volatility and Sharpe need at least two pairs of consecutive priced days.` after the RD caption,
keyed on `vol === null` (unchanged rule).

### State ND — derivative, withheld because no direction is recorded (NEW)

A derivative holding with rows and priced days, but on which NO day carries an established long or
short direction (a `flat` side on a derivative, or a day whose rows disagree on side), is returned
with `historyState: "withheld"` and a new reason. Recommended string: **`no_direction`** (the
planner fixes the final string under CONTEXT's vocabulary discretion; it must be identical in
TypeScript, Python and the fixture). The note slot renders:

> `Return, Sharpe, max drawdown and volatility are not shown for {SYMBOL}: its long or short direction could not be established from the recorded positions.`

- `<p data-testid="holding-factsheet-rebuilding" className="max-w-prose text-sm text-text-secondary">`,
  the 167.1.1 State F element and classes, unchanged. No metric label, value, em-dash or
  price-basis caption renders. The header stays.
- No time word ("yet", "so far"): the note states the cause, as State N does.
- D-02: "Never guess a sign, and never zero-fill." A day without an established direction is a
  GAP in the signed series, exactly like a non-positive mark (D-03). It is not counted in `{N}`, so
  a holding with only some unsigned days falls to RD / RD0 / RD2 by its usable-day count. State ND
  is reached only when the usable-day count is zero because of direction, not price.
- Precedence with `no_price`: zero days with a positive mark is State N (`no_price`, 167.1.1 copy
  unchanged, now reachable for derivatives too, for example a Deribit holding whose every mark is
  `<= 0`). State ND applies only when priced days exist and none of them is signed.
- Measured context (CONTEXT D-02, PROD 2026-10-15): no derivative row is `flat` and 0 of 16 771
  derivative holding-days carry both sides. State ND is therefore expected to be unreachable on
  today's data. It is a fail-loud path, and a unit test drives it from a fixture.

### State OP — derivative option, conditional on an open question

CONTEXT D-02 leaves the Deribit options question open: their mark is a premium whose unit (USD or
coin) is unmeasured, and whether a signed premium return is what D-02 intends goes back to the
founder if research cannot settle it. The UI contract covers both outcomes:

- **If options are priced under the signed rule:** they render States RD / RD0 / RD2 with the RD
  caption unchanged. The caption says "mark price", which is the premium for an option; that is
  accurate only if the rule's series is in USD, which is the researcher's measurement to make.
- **If options are withheld** — **Orchestrator default — founder may override:** withheld with a
  new reason, recommended string `option_premium`, and this note in the State ND slot:

  > `Return, Sharpe, max drawdown and volatility are not shown for {SYMBOL}: it is an option, and these figures are not computed from option premiums.`

  Same element, classes, test id and "no metric, em-dash or basis line" rule as State ND.

The plan states which outcome it built. Only one ships.
