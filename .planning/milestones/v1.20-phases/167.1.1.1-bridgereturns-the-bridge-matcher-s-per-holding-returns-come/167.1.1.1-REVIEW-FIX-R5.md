## M1: a personalized candidate with no returns series got a null fit with no named reason

Fixed, using the orchestrator's decisions.

- `services/match_engine.py`: new `_no_candidate_returns_components()` returns the empty components
  with `fit_unavailable_reason: "no_candidate_returns"`, `fit_overlap_days: 0` and
  `fit_min_overlap_days: PORTFOLIO_FIT_MIN_OVERLAP_DAYS` (true facts, uniform with `overlap_below_min`).
  - `score_candidates`: a new `elif mode == "personalized" and not portfolio_returns_series.empty`
    branch (candidate has no entry in `candidate_returns`) uses it. Screening mode and an empty book
    series still take the plain empty components, so screening rows carry none of the keys.
  - `_compute_portfolio_fit_components`: the combined early return is split. A book-side empty
    returns the plain empty components first; an empty candidate series then returns the marker.
  - The existing conditional raw write carries the three keys unchanged. `data_completeness` stays
    `None` on the path. `reasons` (allocator-facing) is untouched.
- Book-side empties (`portfolio_returns_series.empty`, `port_df.empty`) stay unnamed per candidate,
  with a comment that the batch-level D-22 `book_join_marker` names them.
- v2.4.0 comment paragraph: one clause naming `no_candidate_returns`; the `_empty_pf_components`
  docstring notes the second setter.
- `src/components/admin/CandidateDetail.tsx`: for reason `no_candidate_returns` renders
  `Portfolio fit not computed: this strategy has no daily returns to compare with the book.` with the
  same classes as the `overlap_below_min` line. Unknown reasons still render nothing.

Tests added:

  `candidate_returns`: null components, the three keys, overlap 0, min 30, `data_completeness` None, no
