# Phase 167.1.1.1 Plan 05: Matcher AUM basis, withheld spot in holding_flags, D-20 Summary

**The matcher now sizes on the AUM the allocator sees (spot value plus each derivative's signed unrealized P&L, never notional), names every withheld spot holding in holding_flags without changing the dashboard, and withholds from the return join by name any spot holding with fewer than 30 adjacent one-day returns so it cannot empty the join.**

## Accomplishments

- Task 1 (tracer): the per-key select gained `unrealized_pnl_usd`. Each counted row goes through `holding_equity_contribution`; the collapsed row carries `aum_contribution_usd` (sum of the contributions that exist, `None` when none did) and `pnl_missing`. Derivative rows go to the new `holdings_rows_derivative` list (returned by every return dict) and add their P&L to the AUM; they never enter the weights, the returns, the strategies or the eligible list. The in-memory AUM sum skips a `None` explicitly. `_load_allocator_context` weighs spot on `aum_contribution_usd` over strategy AUM plus this holdings AUM.
- `compute_holding_flags` takes `holdings_rows_withheld` and appends, per withheld spot row, `{holding_ref, value_usd, weight, breach_reasons, top_candidate_strategy_id: None, top_candidate_composite: None, flagged: False, withheld_reason}`. The max-weight test runs; no correlation test and no candidate pick. `_score_one_allocator` passes `ctx["_holdings_rows_withheld"]`. A queries arm proves the dashboard reader ignores such an entry (no change to `src/lib/queries.ts`).
- Task 2 (D-20): `_MATCHER_MIN_ADJACENT_RETURNS = 30`. An admitted spot holding (30+ priced days) with fewer adjacent returns is withheld `too_few_adjacent_returns`, stays in AUM, weights and the max-weight test, and is absent from `portfolio_returns`/`portfolio_strategies`. The price rule's reasons keep precedence below 30 priced days. The reason is in the matcher docstrings only; the shared price-rule module, its fixture and the /compare adapter carry 0 occurrences.
- `tests/test_match_book_join_overlap.py` (6 tests) builds each book through the real `_load_allocator_context`, scores with the real `score_candidates` and runs the real `compute_holding_flags`: control (BTC+ETH, 119-day join, ceiling breach recorded), gappy (30 alternating days: withheld, join stays 119, all four fit values floats, ceiling and max-weight flags intact), 30 adjacent days (withheld), 31 adjacent days (eligible with exactly 30 returns), 29 days (`too_few_priced_days` precedence), and a with/without comparison of BTC's ceiling breach.

## Deviations from Plan

- **[Rule 1 - Bug, test strength]** The plan's third Task 1 neuter was not RED against the allocator-context assertions alone, because `_load_allocator_context` rebuilds its weights from the spot rows. The tracer test now also asserts on `_load_holding_portfolio_context`'s own weights, returns, strategies and eligible/withheld rows; the neuter was re-run and is RED (table above).
- **[Rule 2 - Correctness]** `compute_holding_flags` reads a spot row's dollar figure from `aum_contribution_usd` when present (new private helper `_flag_value_usd`), falling back to `value_usd`. Without it a NaN `value_usd` would give a NaN flag weight and a NaN in the persisted JSON while the context weight is 0. Rows without the field behave exactly as before (the unchanged phase-09 tests and a without-withheld equality test prove it).
- No neighbouring test fed an eligible spot holding with fewer than 30 adjacent returns, so none was moved to 31+ days or to the D-20 meaning.
- The plan's verify command uses `/tmp` backup paths; the byte backups lived in the session scratchpad instead (same `cp` / `cmp` protocol).
