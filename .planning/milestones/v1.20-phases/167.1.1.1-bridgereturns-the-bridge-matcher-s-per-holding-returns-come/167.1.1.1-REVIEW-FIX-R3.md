## The shared fix

The round-2 entry was built before scoring from the context alone. It is now decided AFTER
`score_candidates` returns, by `add_weight_fallback_entry(ctx, result, allocator_id=...)`, from
the engine's own `result["mode"]` and `result["candidates"]`. The pre-scoring step keeps only
the sizing seam: the 1e-6 scoring AUM (`_AUM_NOT_POSITIVE_SCORING_AUM`) is handed to the engine
when `ctx["aum_not_positive"]` and the effective ticket is positive. In screening mode the
engine never reads it, so it is harmless there; whether it was USED is decided from the result.
`_engine_ticket_is_positive` is the shared ticket check (the preference merged with its default
through `merge_with_defaults`, as the engine reads it).

| Case (candidates returned) | Entry | `add_weight` |
|---|---|---|
| personalized, AUM <= 0, ticket > 0 | `aum_not_positive_ceiling_0_5` (D-23) | 0.5 |
| screening, AUM <= 0 (ticket plays no part) | `aum_not_positive_screening_default_0_10` (D-25) | 0.1 |
| personalized, AUM unknown, ticket > 0 | `aum_unknown_default_0_10` (D-24) | 0.1 |
| no candidate returned | none | n/a |

Every entry keeps the shape `{kind: "book", holding_ref: null, add_weight_fallback, add_weight,
flagged: false}`, appended beside the D-22 marker. Each has its own named WARNING
(`match: add_weight_fallback: <name>: allocator <id> ...`), emitted only when the entry is
recorded. The context-time `aum_not_positive` WARNING no longer asserts any sizing (it said "a
ticket is sized at the 0.5 ceiling" unconditionally); it still states the null weights and the
skipped max-weight test. This also closes the LOW in SFH-R3: the sizing WARNING can no longer
precede a scoring failure.

## Item 2 (D-25): screening-mode AUM <= 0 names the 0.10 sizing

## Item 3 (D-24): unknown AUM names the kept default

Fixed. A strategies-only book with every `allocated_amount` missing keeps the engine's 0.10
default (scores unchanged: the engine is still handed `portfolio_aum=None`, pinned by a spy on
the `score_candidates` call) and records `aum_unknown_default_0_10`, `add_weight` 0.1, plus a
named WARNING. Test: `test_d24_an_unknown_aum_keeps_the_default_sizing_and_names_it`.

**Decision made here, as the brief asked:** D-24 applies only when the engine actually sized at
the default, which means personalized mode, candidates returned, and a positive effective ticket.
- Candidates required: no candidate, no sizing, no entry (never claim a sizing that did not
  happen).
- Personalized required: in screening mode the AUM is never an input, so a book with no portfolio
  at all (unknown AUM, nothing to size against) records nothing. A screening book is named only
  through D-25, which needs AUM <= 0 for a book of holdings.
- Positive ticket required: with an explicit zero ticket the engine sizes at 0.10 whatever the
  AUM, so the unknown AUM changed nothing.
- `test_d24_records_nothing_when_nothing_was_defaulted` pins a known AUM, a zero ticket, an empty
  candidate list and a no-portfolio screening book.

Consequence worth knowing: D-24 fires for every personalized batch of a strategies-only allocator
with no allocated amounts, each with one WARNING per batch. No existing test moved (the 1,258
round-2 tests all still pass), so no fixture relied on the absence of the entry. The reader in
`src/lib/queries.ts` keeps only flagged entries that carry a candidate, so it ignores all three
entries.
