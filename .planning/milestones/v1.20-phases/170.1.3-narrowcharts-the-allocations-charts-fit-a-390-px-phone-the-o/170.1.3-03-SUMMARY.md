# Phase 170.1.3 Plan 03: EdgeFitXTick Summary

One shared Recharts tick renderer anchors an x tick whose estimated box crosses the chart's right edge with `text-anchor="end"`, and the three rolling charts (volatility, Sortino, Sharpe) use it, so the composer and the strategy pages draw the "10-20" end-date label whole.

## What was built

- `EdgeFitXTick` reads the chart width from Recharts' `useChartWidth()`, the label from the axis `tickFormatter`, the font size from its own `fontSize` prop (spread from `CHART_TICK_STYLE`), and calls `fitTickLabel(x, label, fontSize, 0, width, textAnchor)`. It renders Recharts' `Text` with every other prop unchanged. An `undefined` width or a non-finite `x` keeps the caller's anchor (T-170.1.3-07). No DOM read, no `style` prop.
- `tick={<EdgeFitXTick {...CHART_TICK_STYLE} />}` replaces `tick={CHART_TICK_STYLE}` in `RollingVolatilityChart`, `RollingSortinoChart` and `RollingMetrics`. `tickFormatter`, `interval`, `margin`, the y axis, tooltip and legend are untouched.

## Decisions and notes for plan 04

- Real Recharts in jsdom does not measure text, so `preserveStartEnd` keeps every tick and the last few sit in the edge band. The real-render cases therefore pin the rule per tick (a tick whose centred box, from its rendered x and `estLabelWidth`, stays inside the chart is `middle`; one that crosses the right edge is `end`) plus hand-typed values for the end-date tick ("10-20" is `end` at 390 and at 1280, the first tick is `middle`). At 1280 a plain-tick control chart is rendered beside the fitted one: same tick strings, control all `middle`, fitted differs only where the box crosses.
- The tick text stays inside Recharts' `g.recharts-xAxis-tick-labels` layer (plan 01 deviation 1), because the renderer returns Recharts' own `Text` from the tick slot. Plan 04's browser reading can keep that selector.
- The browser proof (composer: no svg text clipped at 390 and 640, 1280 AFTER reading) is plan 04's. No e2e was run here, so no local stack was started.
