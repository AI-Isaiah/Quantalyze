# Phase 164.6.6 Plan 07: MT5 password is never trimmed (D-08) Summary

**An MT5 investor password now reaches validate and encrypt exactly as entered, on every path. The exemption is a `secretVerbatim` venue capability read by one shared `secretForVenue` helper and by both wizard secret inputs. Every other venue's key and secret, and the MT5 login, are trimmed as before.**

## Performance

- **Duration:** about 17 min (14:22Z to 14:39Z, 2026-10-03)

## Accomplishments

- `src/lib/closed-sets.ts` gained the optional field `VenueCapabilities.secretVerbatim`. Only the `mt5` row sets it. A new predicate `venueSecretIsVerbatim` returns `false` for null, undefined, empty and unknown venues, so unresolved venues keep the trim. The sFOX row still asserts no capability.
- `src/lib/analytics-client.ts` gained `secretForVenue(exchange, apiSecret)`, a top-level, unexported function. It feeds `api_secret` in both `validateKey` and `encryptKey`. `api_key: trimCredential(apiKey)` is unchanged in both, and the passphrase is untouched. The `trimCredential` docblock gained a dated D-08 sentence.
- `ConnectKeyStep` and every `MultiKeyConnectStep` panel now take the raw `e.target.value` in the secret `onChange` when the venue is a verbatim-secret venue, and `readCredentialInput(e)` otherwise. The API key and passphrase handlers and `credential-input.ts` are unchanged.
- Docstring-only edit: `parse_mt5_credentials` no longer claims that the wizard client trims at submit.
- New D-08 pins on paths whose source was not edited: the rotate route test, the rotate handler test, and the new `test_mt5_password_verbatim.py` (covering `parse_mt5_credentials` and `encrypt_key`, the latter built through `EncryptKeyRequest`).
