<objective>
Add the two modes the `redump-pr` job calls after compose. `--check-bot-branch` protects human
commits on the bot branch, names the pull request they sit on, and hands the push a lease.
`--open-or-edit-pr` creates or reuses the one PR and never merges. The gate-dump no-op notice
gains the bot-PR status RESEARCH Open Question 3 asked for.

Purpose: D-24 says a human edit on the bot branch is never discarded silently and the refusal
names the PR. A reviewer told "a PR exists somewhere" has to go looking; a reviewer told "#N"
does not.

Output: `scripts/baseline-redump.mjs` with the two modes and the notice status, and observed-RED
evidence per arm.
</objective>

<interfaces>
Modes implemented here (names frozen in plan 01; plan 04's workflow calls them verbatim):
- `--check-bot-branch --remote <name>`: ONE `git ls-remote <remote> refs/heads/<BOT_BRANCH>
  'refs/pull/*/head'` call. When the branch is absent, it emits `lease=` (empty) and prints
  `baseline-redump bot-branch: absent`. When present, it fetches it into
  `refs/remotes/<remote>/<BOT_BRANCH>` and lists `git log --format='%H%x09%an%x09%ae'
  <remote>/main..<remote>/<BOT_BRANCH>`. If every author is `BOT_NAME`/`BOT_EMAIL`, it prints
  `baseline-redump bot-branch: present tip=<sha8> prs=<#n,…|none>` and emits `lease=<sha>`.
  Otherwise it REFUSES with exit 1 (see Task 1).
- `--open-or-edit-pr --title-file <f> --body-file <f>`: needs `GH_TOKEN` in the environment. It
  runs `gh pr list --repo $GITHUB_REPOSITORY --head <BOT_BRANCH> --base main --state open --json
  number`, parses the JSON in node, and dispatches on the count: 0 means create, 1 means edit,
  more than 1 refuses. It runs `judgeSkipTokens` (plan 03) over the title and body again before
  the call.
- `$GITHUB_OUTPUT` keys: `lease` (check-bot-branch), `pr_number` (open-or-edit-pr).

Measured at plan time: anonymous `git ls-remote origin 'refs/pull/86*/head'` against this public
repository returned `refs/pull/<n>/head` lines (for example `refs/pull/861/head`) with no
credential. Only `/head` refs are matched; `/merge` refs are ignored.

Assumption, recorded so a reader can check it: GitHub updates `refs/pull/<n>/head` while PR
`<n>` is open and freezes it when the PR closes. So a human commit pushed to the bot branch while
its PR is open moves that PR's head ref to the new tip, and the tip-sha match names the open PR.
A tip that no pull ref points at means the commit was pushed after every PR on the branch
closed, and the refusal says exactly that.
