## The four threats that carry this phase

**1. Credential disclosure into a PUBLIC repo with Sentry attached (T-134-01, criterion 5) —
genuinely mitigated.** `Mt5Client._raise_last` takes a keyword-only `credentials` triple and **all
three** raise points route through `_redact_with_optional_credentials`, which **delegates** to
`_redact_credential_values` rather than carrying a second copy of the loop. The SHAPE scrub is NOT
lost on the credentialed arm — `scrub_freeform_string` runs first, then the escape-aware by-value
pass covering raw / `repr` / `ascii` / `json.dumps` renderings in one longest-first pass. ⭐ The MT5
code is parsed out at `code, text = int(err[0]), str(err[1])` **before** the text is rewritten and
is raised as an `int`, so `-6` survives by construction.

**2. No credential, account number, gateway host, port or terminal free text in any row
(T-164.6.2-12) — the closed set is TOTAL over every writer.** The module has exactly four
`.execute()` sites — one select, three writers — and all three writers are walked
(`_OPEN_ROW_METADATA_KEYS` / `_CLOSE_METADATA_KEYS` / `_CONFIRM_METADATA_KEYS`). Probes A/B/C each
produced a named RED. `record_mt5_heal_outcome` passes `outcome.first_kind`/`final_kind` only and
**never `outcome.verdict`** — the one field carrying terminal free text.

**3. The service-role write to `public.cron_runs` — posture inherited, not weakened.**
`git diff --name-only bedb00d7..HEAD -- supabase/` is **empty**: no migration, so
`cron_runs_service_role` and `cron_runs_admin_read` are untouched. Writes use `get_supabase()`,
never `get_user_scoped_supabase`. ⛔ Verified **statically only** — nothing was run against PROD or
shared TEST.

**4. Availability / DoS-on-self — structurally held.** A background-task exception would reach
`main.lifespan`'s `_crash_handler` → `SHUTDOWN.set()` → dispatch, watchdog and enqueue stop behind
a green `/health`. Both new symbols keep their whole body inside one top-level `except Exception`
with a nested `except BaseException` fallback wrapping no `await`; the loop is guarded twice
(outer containment + per-tick survival that can neither `break` nor `raise`); the only `break` is
`SHUTDOWN`'s. Enforced by the ONE shared `_heal_guard_defects` (imported, never copied) plus
`_loop_survival_defects`, both with calibrated mutant tables, and backed behaviourally.

**5. Terminal contention — one lease, bounded, six sites.** The tick delegates; the only
acquisition is the heal's bounded `mt5_terminal_lease(...)`, so a busy terminal becomes
`Mt5TerminalBusyError` → `KIND_BUSY_SKIP` and never queues ahead of an unbounded job acquire.
`_PRODUCTION_LEASE_SITES` is a six-element frozenset pinned with `==`.
