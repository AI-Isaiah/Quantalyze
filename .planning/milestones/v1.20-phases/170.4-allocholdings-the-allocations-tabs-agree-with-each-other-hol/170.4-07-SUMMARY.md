## Known limits (recorded, NOT fixed here)

- **Persisted identifiers stay venue:symbol:type**: the draft's `toggleByScopeRef` / `weightOverrides` keys, note `scope_ref`s, `match_batches.holding_flags` refs and `match_decisions.original_holding_ref`. Two keys' rows of one symbol share one Scenario toggle line, one note and one bridge flag; no dollars are dropped.
- **`native_unpriced`** (predates this phase): the RPC's `contributing` CTE has no `native_unpriced` handling, while the TS reader drops a key whose newest poll left it unpriced. For such a key the client fingerprint lacks tokens the server recompute still carries, so a book-mode commit can be refused as `portfolio_fingerprint_stale` until the key's next priced poll. Closing it needs a migration, which PR 1 does not carry.
- **`ScenarioComparePanel`** `defaultDraftFromHoldings(payload.holdingsSummary)` is left unchanged: it is a decode fallback with no commit path, so its fingerprint is never sent to the RPC.
- **The composer wiring has no direct test.** Neutering `payload.holdingsFingerprintRows ?? rawHoldingsSummary` to `rawHoldingsSummary` in `ScenarioComposer.tsx` leaves all 485 composer tests green (measured, restored with `cmp`). The hook, the helpers and the payload are each pinned; the one line that joins the payload field to the hook is pinned only by `tsc` and the acceptance grep. A composer case would live in `ScenarioComposer.test.tsx`, which is not in this plan's `files_modified`. Flagged for the orchestrator.
- The fingerprint set equals the RPC's `contributing` token set by construction (the reader and the CTE are twins, per the migration's own comment); this was established by reading the CTE, not by running the SQL gate `supabase/tests/test_commit_scenario_batch_fingerprint_precondition.sql`.
