# Phase 170.4 Plan 04: One history gate for Overview and Risk Summary

Overview and Risk now choose their state through a single pure function, `historyGate(payload)`, so an allocator with a connected key and an empty book sees the same rebuilding panel (same reason line, same named key) on both tabs; the 2026-10-03 disagreement cannot recur.

## What changed

- `lib/history-gate.ts`: `historyGate` returns `no_eligible_key | rebuilding | connected_empty | ready`. Order: empty and unsynced book with `hasConnectedKeys !== true` is `no_eligible_key`; else `equityHistoryState !== "ready"` is `rebuilding` (fail-closed: missing, null, "", unknown, mis-cased); else empty and unsynced is `connected_empty`; else `ready`. `resolveNotSyncingKeys` moved verbatim out of `RiskTabPanel.tsx` (the Overview's inline copy is gone too).
- `AllocationDashboardV2.tsx`: the early return now runs for `no_eligible_key` and `connected_empty` only, so `rebuilding` falls through to the existing `isRebuilding` branch. The BaselineUnknownBanner stays in the early return. `isRebuilding` is kept as the fail-closed flag the banners read. Unused destructured props (`holdingsSummary`, `hasConnectedKeys`, `equityHistoryNotSyncingKeyIds`, `apiKeys`) were removed; the DOGFOOD-1 comment now records the D-04 precedence.
- `RiskTabPanel.tsx`: routes through the gate; `no_eligible_key` renders `<EmptyState hasSyncing={false} hasConnectedKeys={false} />` inside `data-tab-panel="risk"`; `rebuilding` as before; `connected_empty` and `ready` render the widget grid as today.
