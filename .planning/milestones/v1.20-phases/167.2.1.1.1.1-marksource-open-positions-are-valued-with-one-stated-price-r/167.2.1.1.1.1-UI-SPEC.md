Accent reserved for: nothing in this phase.

**Tone: MUTED, not amber and not red.** DESIGN.md § Semantic-color gates: "A `—` cell never
carries a semantic color"; red is "never for absence"; amber is a recoverable disclosure "that a
one-click action reverses". The allocator has no action that makes a venue quote a price, so the
gap is a steady-state fact ("muted = honest-empty"). It also matches the 167.1.1.2 sibling
sentence in the same AUM row; two tones for two qualifiers of one figure would rank one above the
other for no stated reason. On an untrusted-key row the P1 cell keeps that row's existing
`line-through text-text-muted` treatment, and the caption inherits it (one row, one treatment).

Contrast: `#64748B` on `#FFFFFF` is 4.85:1 (AA for 12px), the shipped pairing of every sibling
note in all three hosts.

### P1 — the Value (USD) cell of a price-gap row

| Row | Visible cell text | Accessible text |
|-----|-------------------|-----------------|
| priced (unchanged) | `$12,345` | `$12,345` (+ the existing `sr-only` native basis when present) |
| **price gap** | `—` on line 1, `No price` on line 2 | `No price` |

```tsx
<td className={numericCell}>
  <span aria-hidden="true">{formatUsd(null)}</span>
  <span data-testid="holding-price-gap-label"
        className="block font-sans text-caption text-text-muted">No price</span>
</td>
```

- The dash comes from `formatUsd(null)` (DESIGN.md Numbers Contract: "Null / non-finite: em-dash
  `—`. Never `0`"). It is `aria-hidden` so a screen reader hears the words, not "em dash".
- `No price` is the founder's own phrase from the D-07 option label, sentence case, no period (a
  cell label, like `Spot` / `Derivative` in the Type column).
- **No `title` and no native-basis `sr-only` span on a gap row.** `nativeValueBasis` would print
  `× $0.00` for a finite 0 mark, which states a fabricated price. Gate it at the call site:
  `const valueBasis = holdingIsPriceGap(h) ? null : nativeValueBasis(h, nativeUnit);`.
- ⛔ Test oracles type the expected strings literally (`"—"`, `"No price"`), never via the
  predicate or `formatUsd`.

### P0 — what is counted

1. **P2 (composer):** a toggled-on row that **would have entered `total`** and for which
   `holdingIsPriceGap(h)` is true. Such a row is counted in `priceGap` and is in neither `total`
   nor any includes part (`untrusted`, `unknownStatus`), exactly as `pnlMissing` is (167.1.1.2
   U-05: an includes part must be a strict subset of the total it qualifies). The total does not
   move: the row's equity was 0.
2. **P2, narrowed-out rows:** a gap row the modelled-book narrowing already dropped stays in its
   `excluded*` part and is **not** counted in `priceGap`. Its part's `unavailable` is incremented
   (`addTo` treats `!holdingEquityIsReported(h) || holdingIsPriceGap(h)` as unavailable), so the
   existing "excludes $Y … (value unavailable for N holdings)" clause stops presenting its $0 as
   a known figure (the module's WR-03 rule). No wording in `buildKeyTrustClause` changes.
3. **P3 (Holdings tab):** every spot row in `spotHoldings` for which `holdingIsPriceGap` is true,
   counted over ALL spot rows, not the rows left after the show-revoked toggle (the
   `spotReadDayNotes` rule). Counted per row, not per symbol.
4. **Derivatives are never counted** (the predicate is spot only). Blank mode: count 0 by
   construction.

## Accessibility

- The disclosure is carried in words, not colour or icon (WCAG 1.4.1).
- P1: the dash is `aria-hidden`, so the cell's accessible text is "No price". No `sr-only`
  duplicate is added (a visible label plus an `sr-only` copy would read twice).

  hears it with the number (167.1 WR-02). States B and C sit inside notes already described.
- No `role`, no `aria-live` on any new text: it changes only when toggles or the payload change,
  and every sibling note in these hosts is silent too. The axe matrix covers the dashboard.
