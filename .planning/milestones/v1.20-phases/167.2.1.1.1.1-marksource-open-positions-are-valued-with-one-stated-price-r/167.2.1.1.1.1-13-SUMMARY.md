- `rowdiff.mjs` (embedded): counts-only before/after row diff with `older_rows_changed` (EXPECTED 0) and `max_rel` to 3 significant figures; the double-count estimate and the row diff are reported side by side, never the estimate as the change.

- **Files modified:** `src/__tests__/marksource-okx-census-sql.test.ts`
- **Committed in:** `a4ecc8725`

**2. [Rule 2 - Missing critical] `enqueue` skips an account that already has a reconstruct job open or created at or after `MS_T0`.** The plan requires "never a second forced job per account"; a plain `DISTINCT ON` select would queue a second one on a retry after an ambiguous CLI error. The skip is a compare-and-set in the style of the NAVMTM move form and uses `__T0__`, which the plan already supplies. Pinned by the guard.

**3. Interpretation, not a change of intent:**
- "The `okx_account` CTE ... in every form" is applied to the five forms that select accounts (`pollafter`, `inflight`, `enqueue`, `newjob`, `audit`). `marker` and `rebuildfn` read no account; an unused CTE there would be dead code. The guard pins all five by substring equality with `okx-snapshot-census.sql`.
- `inflight` prints `t0` as `to_char(now() AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')` instead of a bare `now()`, so it exports unchanged as `MS_T0` (the renderer accepts only that shape). It also prints `accounts_selected`.
- `pollafter` filters by `MS_LABELS` (the plan's bad-labels check renders it and expects exit 2, which needs it to use the placeholder). P2 says to export every a-label for it.
- The guard additionally spawns the runbook's renderer (not asked for): it keeps the plan's T-167.2.1.1.1.1-34 mitigation (validated placeholders, exit 2) failing in CI rather than only shown once by hand.

**Total deviations:** 1 auto-fixed bug (own test source), 1 added safety clause, 1 set of interpretations. **Impact:** none on scope; all inside the three planned files.
