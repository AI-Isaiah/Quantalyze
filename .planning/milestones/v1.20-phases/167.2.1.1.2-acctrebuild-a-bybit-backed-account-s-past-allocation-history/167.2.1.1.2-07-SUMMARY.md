## Defect found by a pin and fixed

`test_a_failed_sibling_crawl_refuses_the_account_without_its_text` was RED against plan 06's code. The gather converter in `_crawl_whole_account` logged `scrubbed=<scrub_freeform_string(str(exc))>` for a failed sibling crawl, although plan 06 and T-167.2.1.1.2-24 say it records the exception class only. `scrub_freeform_string` redacts a keyed `signature=<hex>` but leaves a bare word in place, so a venue message carrying one reached the worker log (`... scrubbed=fixture failure deadbeef`). Fix: the WARNING now logs `exc_class` only (`services/equity_reconstruction.py`, one log call, comment added). No token and no message changed. The pin plants the bare word on purpose: the keyed form passed against the unfixed code and would have hidden the defect.
