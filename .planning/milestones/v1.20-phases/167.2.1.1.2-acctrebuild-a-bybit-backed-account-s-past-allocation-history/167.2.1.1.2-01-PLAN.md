The tracer for Phase 167.2.1.1.2 ACCTREBUILD: the one new write path, proven end to end at the persistence
boundary before any account logic is built on it.

CONTEXT D-01: "Only the rebuilt window is replaced. Stored days older than the window (90 days for accounts holding
OKX keys, 730 days otherwise) keep their current values, and the boundary date is recorded." D-02: "If a stored day
inside the window is not reproduced by the rebuild ..., that account's rebuild writes nothing and records why, counts
only." D-03: "Leave the jump, store the boundary date so charts and returns can name it, and invent no values."
Carried UPNLVENUES D-04: "replaces that account's history in one atomic step, or refuses and writes nothing."

The existing replace_allocator_equity_snapshots deletes every row of the allocator, so it cannot honour D-01
(RESEARCH Q2). This plan adds one new SECURITY DEFINER function that replaces only the window, refuses an
unreproduced stored day inside its own transaction (D-02, RESEARCH Q4), and records the seam (D-03, RESEARCH Q3).
It also adds the worker wrapper that calls it and maps its refusal, and proves the whole slice on the local-stack
lane through the real PostgREST.

Purpose: SC-1 (one atomic call), SC-2 (older days left as they are, boundary stated), SC-4 (a stored day the rebuild
would drop is refused in the transaction, never silently deleted).
Output: the migration, its rollback, the worker wrapper, an offline test module and a lane probe module.
</objective>

## Decisions recorded by this plan (orchestrator resolutions of the open questions; the founder may revisit)

- **AR-1 (new SECURITY DEFINER function, PATTERNS conflict 1).** A NEW function
  `replace_allocator_equity_snapshots_window(p_allocator_id, p_rows, p_depth_months, p_window_start)`, a new name and
  never an overload (PostgREST resolves RPCs by name and argument names). Same advisory lock key, `search_path` and
  `lock_timeout` as the latest `replace_allocator_equity_snapshots` (migration 20260602183000). SECURITY DEFINER to
  match the function it stands beside, not SECURITY INVOKER as the okx_archive_rebuild precedent chose. The cost of
  that choice is RESEARCH assumption A2: a definer write to the FORCE-RLS `allocator_equity_derived` must succeed on
  the service-role call path. Task 1's lane probe proves it through PostgREST, and plan 03's gate proves it in SQL.
  **If that proof fails, STOP and report. Do not switch to SECURITY INVOKER silently.**
- **AR-2 (the D-02 check moves into the transaction).** `WITH del AS (DELETE ... RETURNING asof)` compared with the
  payload's days; any deleted day missing from the payload raises `RAISE EXCEPTION 'history_days_unreproduced' USING
  ERRCODE = 'P0001', DETAIL = <count>`. The message is the BARE token: no prefix, no id, no amount (the
  account_identity convention, PATTERNS conflict 2). The worker maps by APIError class, `code == "P0001"` and
  `message == "history_days_unreproduced"`, never by `details`. The Python pre-read (`_allocator_snapshot_asofs`) is
  retired by plan 06, not here.
- **AR-3 (the seam record, D-03).** One `allocator_equity_derived` row, `kind = 'snapshot_rebuild_boundary'`, payload
  `{"boundary_date": "YYYY-MM-DD"}`, written by the function in the same transaction when an older row is kept and
  deleted otherwise. The table's `kind` has no CHECK ("Add a new family = INSERT a new row; no ALTER TABLE"), and the
  compose job's orphan sweep only selects `key_inputs:%`, so no other writer touches the new kind.
- **AR-8 (schema-gate override).** No `supabase db push` task exists in this phase. This checkout's Supabase CLI is
  linked to PRODUCTION, and executors have no TEST or PROD access. The migration is applied locally only by the
  local-stack lane (`bash scripts/local-stack/run.sh up` replays every migration newer than the dump, D-F), and to
  TEST then PROD only by CI on merge. That is the replacement for the schema push.
