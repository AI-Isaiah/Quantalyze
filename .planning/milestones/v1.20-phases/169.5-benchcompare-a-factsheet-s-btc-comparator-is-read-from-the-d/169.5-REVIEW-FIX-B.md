## Fixed Issues

### WR-01: past coverage ignored the comparator's own calendar

**Files modified:** `src/lib/factsheet/align.ts`, `src/lib/factsheet/comparator-block.ts`,
`src/app/factsheet/[id]/v2/ComparatorPicker.tsx`, plus the tests `align.test.ts`,
`comparator-block.coverage.test.ts` and `ComparatorPicker.test.tsx`
**Commit:** `deb0497ba`
**Applied fix:** `align.ts` now owns one rule, `isPastCoverage(through, lastDate, calendar)`. A comparator is
past its coverage when `through` is null, or when a date on the comparator's OWN calendar lies in
(`through`, `lastDate`]. It also exports the calendar masks `CALENDAR_7D` and `CALENDAR_WEEKDAY`, and
`COMPARATOR_CALENDARS` (btc/eth 7-day; spx/gld/ief Monday to Friday). `alignCoveredReturns` exposes the rule
as `coveredToEnd` on `CoveredAlignment`. `buildComparatorBlock` sets `pastThrough = aligned.coveredToEnd !== true`,
and the picker caption calls the same `isPastCoverage` with `COMPARATOR_CALENDARS[key]`.

- `coveredToEnd` is OPTIONAL on `CoveredAlignment`. `build-payload.ts` hand-builds two alignments
  (`unavailableAlignment`, and the correlation's strategy leg). Both have `through: null`, and this group may not
  edit that file. When the field is absent it reads as NOT covered, which is the safe direction, and for those two
  literals it is exactly today's behaviour. Once WR-02 lands, the owner of `build-payload.ts` can make the field
  required and add `coveredToEnd: false` to both literals.
- `toAlignment` (a plain `number[]` handed to the block, D-21) sets `coveredToEnd` to "the last entry is non-null".
  That is byte-equivalent to the old `lastDate > through` rule for that path.
- **Interim state until WR-02 lands:** the block's `coveredToEnd` still uses the calendar that `alignCoveredReturns`
  infers from the prices it is given. The caption uses the explicit `COMPARATOR_CALENDARS`. The four fixture
  comparators are aligned on their full series, so the inferred calendar equals the explicit one, and the measured
  WR-01 scenario (SPX) is fully fixed. BTC's bounded window can in principle infer a smaller calendar (the WR-02
  mechanism), and in that edge case the block and the caption could disagree. They converge when WR-02 passes
  explicit calendars.

**Tests (each neutered, observed RED, then restored):**

| pin | neuter | observed |
|---|---|---|
| `comparator-block.coverage.test.ts` "SPX through Friday covers a 7-day strategy ending that Sunday" (real SPX fixture, 2024-03-01..2025-03-16; `through = 2025-03-14`, `coveredToEnd` true, all five windows numeric) | block `pastThrough` put back to the raw-date `lastDate > through` | RED, 1 failed / 6 passed |
| same file, "a real gap (SPX cut at Friday, strategy ends the next Tuesday)" | none. It is the counter-pin: it shows the rule is not a blanket "covered" (windows null, `coveredToEnd` false) | GREEN under the fix |

| `align.test.ts` "isPastCoverage reads the gap on the benchmark's own calendar" | `isPastCoverage` reduced to `lastDate > through` | RED, 1 failed / 7 passed |

- **An existing test was changed, and the change is intended.** `ComparatorPicker.test.tsx` used to pin
  "SPX prices through Aug 2, 2024" for a strategy ending Sunday 2024-08-04. That assertion pinned the bug
  itself. It is replaced by the no-caption case above, plus the real-gap case.

### SFH-M-07: the coverage caption read the cash comparator, not the active basis

**Files modified:** `src/app/factsheet/[id]/v2/ComparatorPicker.tsx`, `src/app/factsheet/[id]/v2/ComparatorPicker.test.tsx`
**Commit:** `6946ce12b`
**Applied fix:** the picker reads `useBasisSeriesView(payload)` and takes `view.comparators[comparator].through`
and `view.dates` at the end. That is the view the windows and chart lines come from. `basis-context.tsx` is
unchanged. The chips' titles still read `payload`, since a name does not depend on basis.
**Test:** in the new describe block "coverage caption follows the active basis", the cash axis ends on Sunday
2024-08-04 and BTC covers it. The MTM axis runs two days further, to 2024-08-06. Under cash the picker shows no
caption. After switching to MTM through `useBasis().setBasis` it shows "BTC prices through Aug 4, 2024". With the
two reads put back to `payload.*`, the test went RED (1 failed / 11 passed), and it passed again after the restore.

## Skipped Issues

### WR-02 = SFH-M-03: the benchmark calendar is inferred from the bounded window

**File:** `src/lib/factsheet/align.ts:115-116` (at the base commit)
**Reason:** blocked by the file boundary. The brief says: "If build-payload.ts … must change, STOP and report
instead." Fixing this means passing each comparator's calendar explicitly. Every production caller that would
pass it is in a file this group does not own:
- `src/lib/factsheet/build-payload.ts` `alignComparators` (BTC at `:133`, SPX/ETH/GLD/IEF at `:136-139`)
- `src/lib/factsheet/fetch-and-build-payload.ts:769`, the route's `anyCovered` probe, which aligns BTC

No single default for a new `calendar` parameter is right for both BTC and the weekday fixtures. An optional
parameter that falls back to inference keeps the exact code path the review wants removed. So no half-fix was
committed.

**Re-measured at this branch's HEAD** (tsx, the SFH-M-03 case): a weekday strategy
`[2025-01-02 Thu, 01-03 Fri, 01-06 Mon, 01-07 Tue]` against daily BTC closes with Saturday 2025-01-04 missing.
- Window from 2025-01-01, which holds only that one Saturday: `paired = [true,true,true,true]`. This is the bug.
- Window from 2024-12-27: `paired = [true,true,false,true]`. This is the engine's answer.

**Proposed follow-up. One fixer should own all three files:**
1. `align.ts`: `alignCoveredReturns(prices, dropped, dates, calendar: WeekdayCalendar)`, with the parameter
   required. Delete the inference at `const calendar = …; for (const d of closeDates) …`. The masks
   (`CALENDAR_7D`, `CALENDAR_WEEKDAY`, `COMPARATOR_CALENDARS`) already exist from WR-01, so the block and
   the caption then read the same calendar by construction. Update the D-64(2) sentence "The benchmark's
   calendar is the set of weekdays on which the price series handed to the helper carries a close" in
   CONTEXT, because that sentence records the inference as the decision.
2. `build-payload.ts` `alignComparators`: BTC and ETH take `COMPARATOR_CALENDARS.btc` / `.eth`, and SPX, GLD
   and IEF take their weekday masks. Make `coveredToEnd` required, and add `coveredToEnd: false` to the two
   hand-built literals.
3. `fetch-and-build-payload.ts:769`: pass `COMPARATOR_CALENDARS.btc`.
4. Pin: the SFH-M-03 short-window case above, where index 2 should be unpaired. Neuter it by restoring the
   window inference and observe RED. The ~20 existing test call sites of `alignCoveredReturns`
   (`align.test.ts`, `build-payload.benchmark-opt.test.ts`, `comparator-block.coverage.test.ts`,
   `EoyComparatorCoverage.test.tsx`, `TimeSeriesChart.coverage-gap.test.tsx`,
   `fetch-and-build-payload.benchmark.test.ts`) will need the new argument.
