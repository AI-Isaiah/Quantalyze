# Phase 169.5 Plan 02: the payload carries its BTC series, the discovery page reads it the route's way, and comparator chart lines stop where the prices stop. Summary

**The factsheet payload now carries the exact BTC closes, `through` and `dropped` list its comparators were computed from. The browser leverage re-derive aligns BTC from that field, never from the bundled fixture. The discovery detail page reads BTC through the route's one read function, and a LOCKSTEP test pins the two paths together. A comparator's cumulative, cumVsBench and vol-matched lines are null where there is no price, so the chart breaks the line there. Rolling vol, Sharpe and Sortino use the comparator's basis over non-null window points, and rolling beta uses paired intervals only.**

## Accomplishments

- `types.ts`:
  - `BenchmarkPricesOpt` now lives here. `build-payload.ts` re-exports it, so wave 1's importers compile unchanged.
  - `FactsheetCommon.benchmarkPrices?` is optional, per D-21. Its comment says both builders always set it, and that an absent field means BTC is unavailable.
- `build-payload.ts`:
  - `alignComparators` and `deriveSeriesBundle` take the BTC input as a required argument.
  - `buildFromBuildableSeries` resolves the input once. It uses the route's opt verbatim, or `fixtureBenchmarkPrices([cash, mtm, smoothed])` when no opt was passed. That one value feeds the api arm, all three bundles and the payload field.
  - `BTC_DAILY` has exactly one non-import use, inside `fixtureBenchmarkPrices`.
- `basis-context.tsx`: the leverage re-derive passes `base.benchmarkPrices ?? { unavailable: true }`. The unity short-circuit and the shared memo are unchanged.
- The discovery page calls `readFactsheetBenchmark(createAdminClient(), dailyReturns, buildOpts)` once both arms have assembled `buildOpts`, and passes the result as the opt.
  - The call is unconditional. On the failure arms every axis is empty, so the function returns the unavailable marker without a query.
  - The page has no second copy of the read logic (`mergeWithFixture` count: 0).
- `comparator-block.ts`:
  - `cumulative` and `volMatched` are `cumEq` over the covered returns, placed back on the axis with null at uncovered indices. `cumVsBench` is null wherever `cumulative` is.
  - Rolling vol, Sharpe and Sortino compact each window to its non-null points and call the `rolling.ts` helper on `benchPeriodsPerYear`.
  - Rolling beta compacts both legs over the window's paired indices and calls `rolling.ts` `rollingBeta`.
  - `rolling.ts` is untouched.
  - The 169.5-01 interim comment is replaced by a `dailyReturns` note naming 169.5-04.
- `TimeSeriesChart.tsx` is unedited. The change there is test-only: the chart case passes against the unchanged `buildPath`. The same case fails when the pre-Task-3 `comparator-block.ts` is swapped in, because that version emits no nulls.

## Known limits (recorded, not fixed)

- **D-21:** a hand-built payload without the field shows BTC as unavailable under leverage. No production surface reaches that path today (deviation 3).
- **Rolling series near coverage edges:** a comparator window with fewer than 2 non-null (or paired) points is a gap. For a weekday comparator against a 7-day strategy, the rolling beta therefore has no value on Mondays.
- **`dailyReturns`** still enters an uncovered day as 0. 169.5-04 owns it (D-21).
- **Comparator series are not rebased on zoom:** `resolveSeries` does not rebase them. This is pre-existing and out of scope. A null does not affect it.
