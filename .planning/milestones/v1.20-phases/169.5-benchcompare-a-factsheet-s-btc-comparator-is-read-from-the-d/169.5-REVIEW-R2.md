## Warnings

### MR-01: The comparator-coverage disclosure uses a raw-date rule, so a 7-day strategy ending on a weekend labels SPX, GLD and IEF as truncated while the caption and windows on the same page say they are covered (MEDIUM, regression from fix D `fc6472d92`)

**File:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx:393-400` (`comparatorPartialThrough`) and `:408-415` (`comparatorPartialYear`). The results are used at `:107-108`, `:139`, `:169`, `:191` (bench headers), `:738`/`:792-796` (EoY table note) and `DistributionPanels.tsx:44`/`:106-108` (EoY bars subtitle).

**Issue:** `comparatorPartialThrough` returns `through` whenever `through < lastDate` as ISO strings. Its docblock says it uses "the ISO-string comparison `buildComparatorBlock` uses for its `pastThrough` windows". That stopped being true when fix B (WR-01) moved `pastThrough` onto `isPastCoverage` and the comparator's own calendar. B and D were built in parallel off `3be596e40`, so D kept the rule B removed. A weekday comparator never has a close on Saturday or Sunday. So for a 7-day strategy whose last date is a weekend, SPX, GLD and IEF are always "partial" under D's rule, even though nothing is missing.

**Failure scenario, measured** (tsx at HEAD, `buildFactsheetPayload` on a crypto strategy from 2025-01-01 to Sunday 2025-03-16, inside the SPX fixture's range):
- `spx.through = "2025-03-14"`, and `spx.summary.mtd = -0.0530` (numeric).
- `isPastCoverage("2025-03-14", "2025-03-16", COMPARATOR_CALENDARS.spx)` is `false`. So the picker shows **no** caption, and all five windows are numeric.
- `comparatorPartialThrough("2025-03-14", "2025-03-16")` is `"2025-03-14"`.

With SPX selected, the same page therefore shows:
- "vs SPX to Mar 14, 2025" on the **Main Metrics** and **Returns** headers.
- A **Max Drawdown** bench header that did not exist before fix D. It appears only because `benchThrough != null`.
- The EoY table note "SPX 2025: prices through Mar 14, 2025 only."
- The EoY bars subtitle "· SPX 2025 through Mar 14, 2025 only".

The picker is silent and the windows are full, so the page contradicts itself. It tells an allocator that SPX data is missing for a period where SPX's record is complete.

This is the WR-01 defect, moved to five different surfaces. It hits every weekend-ending 7-day strategy (about 2 in 7 crypto records) whenever a weekday comparator is selected. When SPX gets a live feed, it will hit every weekend view. BTC and ETH are unaffected, because for a 7-day calendar the raw compare and the calendar compare agree.

`MetricsColumn.comparator-through.test.tsx` has no weekday-comparator or weekend case (grep: no SPX, Sat or Sun), so no existing test pins the wrong rule, and no test catches it either.

**Fix:** use the one rule. Pass the comparator key (or its calendar) and delegate to `isPastCoverage`, so the block, the caption and the disclosure cannot drift apart:

```ts
import { COMPARATOR_CALENDARS, isPastCoverage, type WeekdayCalendar } from "@/lib/factsheet/align";

export function comparatorPartialThrough(
  through: string | null | undefined,
  lastDate: string | undefined,
  calendar: WeekdayCalendar,
): string | null {
  if (typeof through !== "string" || lastDate === undefined) return null;
  return isPastCoverage(through, lastDate, calendar) ? through : null;
}

// comparatorPartialYear: take `calendar` too, and count only dates d > t in t's
// year that fall on the calendar, e.g. by testing
// isPastCoverage(t, lastDateOfThatYearInDates, calendar).
```

The callers pass `COMPARATOR_CALENDARS[cmpKey]`. They already guard `cmpKey !== "none"` (`hasBench`, and `bn` being defined), so index only under that guard. Fix the docblock above `:393` so it names `isPastCoverage`. Pin it with a 7-day strategy ending Sunday 2025-03-16 with SPX active: no dated header, no Max Drawdown header, no EoY note and no bars subtitle. Add a counter-pin with SPX cut at a Friday and the strategy ending the next Tuesday, where the dated header appears. Add a neuter that restores the raw `through < lastDate` compare and observe RED.
