## Fixed Issues

### MR-01 = SFH-R2-M-01: the partial-coverage note used the raw-date rule, so a weekday comparator looked truncated across the strategy's weekend

**Files modified:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx`, `src/app/factsheet/[id]/v2/DistributionPanels.tsx`, `src/app/factsheet/[id]/v2/MetricsColumn.comparator-through.test.tsx`
**Commit:** `d046b1701`
**Applied fix:**
- `comparatorPartialThrough(through, lastDate, calendar)` now delegates to `isPastCoverage`. This is the rule the `pastThrough` windows in `buildComparatorBlock` and the picker caption already use. The `typeof through !== "string"` guard still runs first, because `isPastCoverage(null, …)` is `true` and would put a date on an unavailable comparator.
- `comparatorPartialYear(through, dates, calendar)` finds the strategy's last date in `through`'s year and tests it with the same rule. Before, it checked `d > through` on raw dates, which carried the same defect into the year check. For example, SPX through Fri 2024-12-27 with a 2024 tail of Sat/Sun is a complete year.
- The callers pass `COMPARATOR_CALENDARS[cmpKey]`: the MetricsColumn bench header (behind a `cmpKey === "none"` guard), the EoY table and the EoY bars (both behind the existing `hasBench` narrowing). The docblocks now name `isPastCoverage`.

**Tests added:** a 7-day strategy 2025-01-01..Sun 2025-03-16 with SPX active, and SPX `through` 2025-03-14 is asserted as a precondition. It shows "vs SPX" on Main Metrics and Returns, no Max Drawdown header, no EoY note, and no "through" in the bars subtitle. The control sets SPX `through` to Wed 2025-03-12, and the dated header, EoY note and bars subtitle all appear. There are helper pins for the weekday and 7-day calendars, and a year-rule pin (2024-12-27 → null, 2024-12-26 → "2024"). The existing BTC helper pins now pass `CALENDAR_7D`.

**Neuter → RED → restore:**
- Putting `through < lastDate` back in `comparatorPartialThrough` makes 3 of 12 tests fail. The rail test reports `Expected: "vs SPX"`, `Received: "vs SPX to Mar 14, 2025"`. The helper pin and the year pin also fail. After the restore, 12/12 pass.
- Putting back the old raw `d > through` year rule makes 1 of 12 tests fail (the year pin). After the restore, 12/12 pass.

**Gates, all run in `quantalyze-169.5`:** `npx tsc --noEmit -p .` exits 0. `eslint` on the 3 files exits 0. `npx vitest run src/app/factsheet` passes: 65 files, 638 tests.

**Known limit, not new:** `isPastCoverage` counts every Monday to Friday as an SPX trading day. A US market holiday between `through` and the last date therefore still puts a date on the header. WR-01 accepted this when it made that rule, and this fix only brings these surfaces onto it.
