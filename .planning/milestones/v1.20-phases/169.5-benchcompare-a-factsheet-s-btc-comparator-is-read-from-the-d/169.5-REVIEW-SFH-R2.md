# Phase 169.5 BENCHCOMPARE: confirmation silent-failure review (round 2)

Recorded limits, not re-reported: D-65 (the api arm's allocator and event-signature panels take
a comparator null as 0, owned by 169.4) and D-52 (the unavailable form may be cached for the TTL).
No source was changed by this review. The two probes below ran as throwaway files and were
deleted; `git status --short src` was clean afterwards.

## Round-1 findings

### SFH-H-01: stress windows showed BTC +0.00% / DD 0.00% when BTC was unavailable. CLOSED

- `build-payload.ts:457` passes `btcAl.returns` (null-honest). `nullAsZero` no longer feeds it.
- `stress-windows.ts`: any null bench day in a window sets `benchCovered = false`, and the window
  then gets `benchReturn: null` and `benchMaxDD: null`. The strategy fields are still computed.
- `StressWindowsPanel.tsx`: `pctSigned` / `pct` render "—" for null, and `benchColor` makes the
  cell muted, so the old `null >= 0` true, green 0% path is gone.
- The only other caller, `scenario-factsheet-payload.ts:403`, passes a `number[]` and its values
  are unchanged. There are no other `benchReturn` / `benchMaxDD` readers in `src`. A payload that
  round-trips JSON through `unstable_cache` keeps null as null.
- The browser leverage re-derive (`basis-context.tsx` → `deriveSeriesBundle`) takes the same call.
- A null now reaches this panel as "—", never 0. One dropped or missing BTC close inside a window
  blanks that window's bench columns. That is a conservative and honest outcome, not a silent one.

### SFH-M-01: the wide `try`, and a log line with no context. CLOSED

- Only `readBenchmarkPrices` and the first-date probe sit inside `try`
  (`readBtcWithFirstStoredDate`). The merge, trim and align code runs outside it.
- `benchmarkReadFailed` logs `{ id, from, to, code, message }`. Both callers now pass the strategy
  id: the route passes `id`, and discovery passes `strategy.id` (fix E).
- **A thrown build does not cache and does not render a blank page silently.** v2 public lane:
  the `unstable_cache` callback throws, so nothing is stored (see the measured note at
  `page.tsx:126-135`). At `page.tsx:~520` anything that is not a `FactsheetReadError` is rethrown
  to `factsheet/[id]/v2/error.tsx`. The owner lane and discovery await directly, with no enclosing
  catch, so the throw reaches `v2/error.tsx` or `(dashboard)/error.tsx`. The share page falls to
  `src/app/error.tsx`, which captures to Sentry. Server-side, `src/instrumentation.ts` exports
  `onRequestError`, so the render error is captured for every surface.

### SFH-M-02: the two data-driven unavailable exits logged nothing. CLOSED

Both exits go through `unavailableData(reason)`, which logs `console.warn(BENCHMARK_UNAVAILABLE_MESSAGE,
{ reason, id, from, to, firstStored, readCount, readThrough })`. `reason` is `no_prices_in_window`
or `no_covered_interval`. The line is separate from the read-failure `console.error`. The only
remaining silent exit is the "no date on any axis" return, which issues no query and is reached
only on the resolve failure arms, where the page already shows its own fallback. It is outside
the finding.

### SFH-M-03 (= WR-02): the calendar was inferred from the bounded window. CLOSED

- `alignCoveredReturns(prices, dropped, dates, calendar)`: `calendar` is required, and the
  inference loop is deleted.
- Every production caller passes an explicit mask: `alignComparators` (all five comparators) and
  the route's `anyCovered` probe (`COMPARATOR_CALENDARS.btc`). `grep` finds no other production
  caller.
- The masks match the fixtures' real cadence. Measured on this HEAD: BTC has 1113 rows and ETH
  1112 over 2023-04-26..2026-05-1x, which is daily, so 7-day is right. SPX, GLD and IEF have 762
  rows each over 2023-04-26..2026-05-08, which is weekdays, so Monday to Friday is right.
- The measured short-window pin (`paired = [true,true,false,true]`) is in `align.test.ts`, and
  fix E recorded its neuter.
- Market holidays count as expected days on the weekday mask. For pairing, the engine does the
  same with `count == expected`. The coverage rule already had this behaviour before round 1, so
  it is not new.

### SFH-M-04: the correlation strip dropped the BTC row. CLOSED

The filter is gone. A non-finite rho (including NaN serialized as `null` by the cache) keeps its
row, reads "—" through `signedNum`, and draws no `<rect>`.

### SFH-M-05: partly covered comparator figures had no disclosure beside them. PARTLY CLOSED, see SFH-R2-M-01

The dated header, the EoY note and the bars subtitle exist, and they read the active basis view.
The rule deciding when they show is the problem, reported below.

### SFH-M-06: the regime band ran past the comparator's last close. CLOSED

The final segment ends at `lastNonNull`. If every value is null, no segment is pushed. Interior
nulls are still bridged. That is fix D's recorded decision: breaking on a null would split SPX
shading into weekday islands. A multi-day interior BTC gap therefore stays shaded across the gap.
The band is a regime hint and no figure depends on it, so this is not raised.

### SFH-M-07: the coverage caption read the cash view. CLOSED

`ComparatorPicker` reads `useBasisSeriesView(payload)` for both `through` and the last date, and
calls `isPastCoverage` with `COMPARATOR_CALENDARS[comparator]`. The hook falls back to cash when
no provider is mounted, so it cannot throw.

## New finding

### SFH-R2-M-01 (MEDIUM): the SFH-M-05 disclosure uses the raw-date rule that WR-01 removed, so SPX, GLD and IEF are wrongly labelled as stopping early whenever a 7-day strategy ends on a weekend

- **Location:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx:393-415` (`comparatorPartialThrough`,
  `comparatorPartialYear`), consumed at `MetricsColumn.tsx:107-108` (the Main Metrics, Returns and
  Max Drawdown headers), `MetricsColumn.tsx:738` (the EoY table note) and
  `DistributionPanels.tsx:44` (the EoY bars subtitle).
- **Cause:** fixes B (WR-01) and D (SFH-M-05) were written in parallel off `3be596e40`. Fix B
  replaced the raw-date check `lastDate > through` with the calendar rule `isPastCoverage` in
  `buildComparatorBlock` (`pastThrough = !coveredToEnd`) and in the picker caption. Fix D's helper
  kept the raw check (`through < lastDate`). Its docblock still says it is "the ISO-string one
  `buildComparatorBlock` uses for its `pastThrough` windows", which stopped being true after the
  merge.
- **Measured on HEAD 5c31c4e9f** (real exports, vitest probe): a 7-day strategy
  2025-03-01..2025-03-16 (last date Sunday), aligned through `alignCoveredReturns` with each
  comparator's own mask:

  | comparator | through | coveredToEnd | comparatorPartialThrough | comparatorPartialYear |
  |---|---|---|---|---|
  | spx | 2025-03-14 | true | 2025-03-14 | 2025 |
  | gld | 2025-03-14 | true | 2025-03-14 | 2025 |
  | ief | 2025-03-14 | true | 2025-03-14 | 2025 |

- **What the user sees on one page:** the picker shows no caption, and every SPX window
  (MTD/YTD/3M/6M/1Y) is numeric, because the comparator is covered. Yet the Main Metrics and
  Returns headers read "vs SPX to Mar 14, 2025". Max Drawdown gains a header it does not have at
  full coverage. Under the EoY table: "SPX 2025: prices through Mar 14, 2025 only." The EoY bars
  subtitle says the same. The disclosure tells the reader that SPX prices are missing after
  Friday, which the page's own coverage rule says is false. This is the partial-coverage note
  showing a date when none is due, and it contradicts the caption beside it.
- **Exposure:** SPX, GLD or IEF selected, a 7-day strategy (or any strategy) whose last date is a
  Saturday or Sunday, and that last date on or before the fixtures' end (2026-05-08). For a live
  strategy ending after 2026-05-08, the weekday fixtures really are past coverage, and the dated
  note is then correct. So this hits historical and stopped strategies, not every live factsheet.
  That limit, and the fact that the stated date is itself accurate (only the implication of
  missing prices is false), is why this is MEDIUM and not HIGH. BTC and ETH are unaffected,
  because on a 7-day calendar the raw rule and the calendar rule agree.
- **Why the tests missed it:** `MetricsColumn.comparator-through.test.tsx` only pins BTC, the 7-day
  case. No test puts a weekday comparator next to a weekend last date on these helpers, while
  `ComparatorPicker.test.tsx` pins exactly that case for the caption ("shows no SPX caption when
  SPX's Friday close covers a strategy ending that weekend").
- **Recommendation (not applied):** decide "partial" with the same rule as the windows and the
  caption. Give both helpers a `calendar` argument, and return `through` only when
  `isPastCoverage(through, lastDate, calendar)` is true. Callers pass
  `COMPARATOR_CALENDARS[cmpKey]`, and `cmpKey` is already in scope in `MetricsColumn`,
  `EoyReturnsPanel` and `EndOfYearBarsPanel`. Fix the docblock in the same change. Pin it with the
  SPX weekend case from the table: no dated header and no EoY note. Neuter the fix back to
  `through < lastDate` and observe RED.

  ```ts
  export function comparatorPartialThrough(through, lastDate, calendar: WeekdayCalendar) {
    if (typeof through !== "string" || lastDate === undefined) return null;
    return isPastCoverage(through, lastDate, calendar) ? through : null;
  }
  ```

  `comparatorPartialYear` must also test a later strategy date in that year that falls on the
  comparator's own calendar, not just any later date. Otherwise a strategy ending Sunday still
  raises the year note.
