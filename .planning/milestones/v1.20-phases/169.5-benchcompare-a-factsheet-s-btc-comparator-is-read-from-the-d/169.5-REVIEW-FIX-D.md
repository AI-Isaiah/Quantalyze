## Fixed Issues

### SFH-M-04: the correlation strip drops the BTC row without a trace

**Files modified:** `src/app/factsheet/[id]/v2/DistributionPanels.tsx`, `src/app/factsheet/[id]/v2/CorrelationStrip.unavailable-row.test.tsx` (new)
**Commit:** `2182c8521`
**Applied fix:** `CorrelationStripPanel` no longer filters rows with a non-finite `rho`. Such a row keeps its name, reads "—" (via the existing `signedNum`), and draws no bar, the matrix's own form for the same cell.
**Neuter → RED → restore:** reinstating `.filter(r => Number.isFinite(r.rho))` fails 2 of 3 tests (row list, and the "—" / no-bar row). Restored, 3/3 GREEN. The fixture uses real `buildFactsheetPayload` with two BTC closes, so `pairedCorr` returns NaN. A precondition test asserts that.

### SFH-M-06: regime shading paints a band past the comparator's last close

**Files modified:** `src/app/factsheet/[id]/v2/TimeSeriesChart.tsx`, `src/app/factsheet/[id]/v2/TimeSeriesChart.regime-tail.test.tsx` (new)
**Commit:** `a048601bf`
**Applied fix:** the regime walk tracks the last index with a rolling Sharpe and closes the final segment there, not at `length - 1`.
**Decision recorded:** interior nulls are still bridged. `rollingOverCovered` (`comparator-block.ts`) makes a weekday comparator's rolling Sharpe null on weekends against a 7-day strategy. The review's "treat a null as the end of a segment" would therefore split SPX shading into weekday islands. Only the tail is fixed, which is what the brief asked for.
**Neuter → RED → restore:** reverting the end to `cmp.rollingSharpe.length - 1` fails the "BTC through index 59 of 80" case. Restored, 2/2 GREEN. The full-coverage case asserts the band still reaches the plot's right edge.
**Known behaviour change:** SPX shading on a strategy whose last date is a weekend now stops at the last weekday with a close, not the weekend. This is correct under the same rule.

### SFH-M-05: a partly covered BTC's truncated figures are not disclosed next to the numbers

**Files modified:** `src/app/factsheet/[id]/v2/MetricsColumn.tsx`, `src/app/factsheet/[id]/v2/DistributionPanels.tsx`, `src/app/factsheet/[id]/v2/MetricsColumn.comparator-through.test.tsx` (new)
**Commit:** `fc6472d92`
**Applied fix (keeps D-54; this is a disclosure change and does not touch the rule):**
- New exported helpers `comparatorPartialThrough` (through as a string strictly before the last date, else null) and `comparatorPartialYear` (the year of `through` when the strategy has a later date in that year). They use the same ISO-string comparison as `pastThrough`.
- Main Metrics and Returns bench header: "vs BTC to Jan 20, 2025" when partial. Max Drawdown has no bench header at full coverage, so it gains the dated header only in the partial case. This asymmetry is deliberate: full coverage stays byte-identical.
- EoY table: a muted italic `text-fixed-10` note "BTC 2025: prices through Jan 20, 2025 only." The column header is not dated, because that would imply the earlier full years are truncated too. The EoY bars subtitle carries the same fact.
- Coverage is read from the active basis view (`view.comparators[key].through`, `view.dates`), which is where the figures come from.
- The colour is muted, not warning, per DESIGN.md: "Muted = honest-empty". This is a disclosure, not a fault.
- Unchanged: full coverage, `through: null` (every figure is already "—"), and an absent `through` (D-21).
**Neuter → RED → restore:** forcing `comparatorPartialThrough` to return null fails 5 of 7 tests (the three headers, the EoY note, the bars subtitle, and both helper cases). Restored, 7/7 GREEN.

## svg-chart-parity goldens

These were not run locally. They are Playwright chromium-linux goldens against a seeded route. Every change is conditional on a non-finite rho, a `through` before the last date, or the regimes toggle being on (default off). If the seeded lane's BTC covers the seeded window, no golden moves. If the lane's stored BTC stops early or yields a NaN rho, these may move:
- `correlation-strip-*`
- `end-of-year-bars-*` (the subtitle)
- `full-page-*` (the MetricsColumn headers and the EoY note)

`master-brush-*` and the time-series charts do not move, because regimes are off by default.
