# Phase 169.5 Plan 04: comparator dailyReturns null where uncovered Summary

The comparator's per-day `dailyReturns` now carries the coverage-aware helper's series as it stands, null wherever the comparator has no price and never 0. A calendar year with no covered comparator day now reads as missing (the table's em-dash, no bar and no label in the bars) instead of "+0.00%".

## Tests (EoyComparatorCoverage.test.tsx, 9 cases)

Each figure is computed by hand from typed closes (close = 100 + i on consecutive calendar days). The strategy is a 7-day series running 2024-12-20 → 2025-01-31.

| Case | Asserts |
|---|---|
| prices ending 10 days before the strategy | `dailyReturns` equals the helper's `returns`; the last 10 entries are null; the rest are numbers; day one is 0.01 (101/100 - 1, D-64) |
| no close before the first strategy date | `dailyReturns[0]` is null, in its own `expect` (D-64) |
| a dropped close | that day is null, the array equals the helper's, the next day is a number (D-58) |
| full coverage | no null anywhere, length = strategy length |
| EoY table, no 2024 comparator day | the 2024 BTC cell is "—" |
| EoY bars, no 2024 comparator day | the 2024 row has one label and one bar (the strategy's own) |
| covered year under late prices | 2025 = 126/100 - 1: table "+26.00%", bars "+26.0%" |
| first year compounds day one | 2024 = 112/100 - 1: "+12.00%", "+12.0%" |
| last year over covered days only | 2025 = 132/112 - 1: "+17.86%", "+17.9%" |

**RED first at `7da46ed64`, before the fix:** 5 of 9 failed for the intended reason. The three comparator-block cases failed with `expected +0 to be null`, and the deep-equal failed. The table case failed with `expected '+0.00%' to be '—'`, and the bars case with `expected [ '-0.3%', '+0.0%' ] to have a length of 1 but got 2`. The other four pin figures that are already true: 0 and a skipped day compound to the same value.
