## Decisions Made

1. **The vitest stays.** `baseline-wiring-claim.test.ts`'s second `it` keeps its assertion. Different sampling rates (full-suite vs. every `supabase/schema/**` PR including forks); the measured gap was CI placement. The overlap is stated in the gate's header rather than resolved by deleting one side.
2. **One spelling for the recorded-hash extraction**, proven byte-identical by comparison rather than asserted.
3. **Steps run before `npm ci`.** Zero dependencies means the gate can report even when the install flakes.
4. **`judge()` returns early on an unmeasurable dump.** Comparison against nothing is not a comparison.
5. **Unknown CLI args are rejected.** A typo'd `--self-tset` would otherwise fall through to a corpus run and print `✅ No defects` — a defanged invocation reading green, which is the exact failure this gate exists to prevent one level up.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality / message honesty] An empty dump printed sha256("") in the `actual=` slot as though it were a measurement**

- **Found during:** Task 2, mutation arm 4 (the extra end-to-end arm).
- **Issue:** With `baseline.sql` truncated to zero bytes, the gate correctly fired `baseline-sql-unreadable`, but its summary line read `actual=e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` — the sha256 of *no bytes*, a real, stable hex string — printed directly beside `recorded=514ba9…`, while the defect detail simultaneously claimed the hash "could not be computed".
