## Implementation Decisions

### Area 1 — What the sweep sweeps over (the unit)

- **The unit is the CHANNEL, not the psql invocation.** Re-measured at HEAD 2026-09-19: the three
  named files hold ~100 psql lines, of which 8 carry a connection URL — but the stderr redirect
  lives at the CALL SITE, not at the psql site. In `scripts/test-ledger-drift-check.sh` the five
  url-bearing psql lines are four arms of ONE `ledger_query()` case plus `default_body_fetch()`,
  and four of the five callers are already safe. Counting sites would have planned five fixes for
  one defect — which is exactly the "half-class twice" failure the ROADMAP entry warns about.
- **`[164.8.2-LEDGER-STDERR-PUBLIC-LOG]` is ONE channel:** `test-ledger-drift-check.sh:348`,
  `run_ledger_query missing "$names_csv" > "$missing_file"` — stdout redirected, stderr bare. ⭐ Its
  own `|| fail` message already says *"output withheld — it can carry connection detail"*, so the
  defect is literally this phase's declared class: a control narrower than the sentence beside it.
  The correct capture-count-WITHHOLD idiom is in the same file at `:414`; REUSE it, do not invent one.
- **`[164.8.2-REDACT-HOSTNAME-01]` is 8 blocks with SIX distinct expressions, and NO block carries
  all six.** ⛔ **CORRECTED 2026-09-19, same day, by the phase researcher — this entry first said
  "12 blocks, 11 of 12 missing one expression" and that was WRONG.** The 12 came from counting
  LINES matching `server at `, which includes prose comments; the researcher's independent byte-read
  said 8, and a re-measure by `sed -E` invocation confirmed the researcher. ⚠️ Recorded rather than
  silently overwritten because a restated claim is this phase's own declared defect class, and this
  one was restated by the orchestrator inside the very document that forbids it.
  **MEASURED at HEAD** — 3 blocks in `.github/workflows/ci.yml`, 5 in
  `.github/workflows/test-restore-from-baseline.yml`, and the union is six expressions:

  | expression | blocks carrying it |
  |---|---|
  | `postgres(ql)?://…@` | 8 / 8 |
  | `server at "…"` | 8 / 8 |
  | `for user "…"` | 8 / 8 |
  | `host=…` | **2 / 8** |
  | `user=…` | **2 / 8** |
  | `could not translate host name "…"` | **1 / 8** |

  ⭐ **THE CORRECTED READING IS STRICTLY WORSE AND IT SHARPENS THE FIX.** The defect is not "one
  expression missing from most blocks"; it is that EVERY block is incomplete, in TWO OPPOSITE
  directions — the one DNS-aware block lacks `host=`/`user=`, and the two `host=`/`user=` blocks
  lack DNS. Maximum coverage anywhere is 5 of 6. ⛔ So "copy the correct block" has no referent:
  there IS no correct block. The shared definition must be the UNION of all six, and adopting any
  existing block as the target form ships a known gap.

- **A THIRD leak shape was found in this sweep and is IN SCOPE:** `ci.yml:3394` and `ci.yml:3422`
  do `> "$out" 2>&1` and then `cat "$out"` UNCONDITIONALLY — psql's connect/auth stderr is echoed
  verbatim to a public log through no redaction at all. It is the same defect class, in one of the
  two files group (a) already owns, and found by the one-sweep method the entry mandates. Excluding
  it because no TODOS id names it would reproduce the exact half-class this phase exists to end.

### Area 2 — The fix SHAPE for redaction

- **ONE definition, referenced 12 times — not 12 corrected copies.** A hand-copied regex set that
  drifted to 11-of-12 will drift again; correcting each copy fixes today's instances and leaves the
  class open. This is the repo's own recorded preference (cite by symbol, derive rather than
  restate) applied to a regex set.
- **⚠️ The two files cannot share a bash function across workflow boundaries**, so the durable
  carrier is a repo-owned script (e.g. `scripts/redact-psql-stderr.sed` or a tiny `.sh` filter)
  that both workflows invoke, plus a gate asserting no in-line `sed -E … server at …` block
  survives outside it. The gate is the deliverable; the de-duplication is how it is satisfied.
- **The gate must FAIL on a NEW unredirected/unredacted site**, per success criterion 1 — not
  assert today's count of 12. A count-pinning arm is the "widened count over an unwidened scan"
  overclaim this phase's own criterion 9 names as forbidden.
- **⛔ No specimen in any artifact.** A proof-of-absence that quotes the pattern publishes what it
  proves absent. Calibration records a VERDICT and a redacted-form assertion, never a real host.

### Area 3 — `[164.8.2-EVIDENCE-DOTENV-LEAK]`: where the fix can durably live

- **The booked location is NOT repo-fixable, and this is the material re-measurement.**
  `gstack-evidence` carries `#!/usr/bin/env bun` and lives ONLY at
  `~/.claude/skills/gstack/bin/gstack-evidence` — there is no repo-local copy, and
  `/gstack-upgrade` overwrites it. A fix there is wiped by the next upgrade, the same
  non-durability class this repo already records for `/gsd-update` overwriting global workflows.
- **Upstream has moved since the 2026-09-10 booking:** the wrapper now has a `childEnv()` scrubber
  that deletes bun-injected dotenv keys from the child env and reports the KEY NAMES only. Two
  fail-open holes are documented in its own comments and remain: bun EXPANDS `${VAR}` inside dotenv
  values while the reader compares raw file text (an expanded key survives), and multi-line values
  are not parsed (that key survives).
- **DECISION: the repo-owned remedy is a REPO-SIDE guard, not a wrapper edit.** `HAS_LIVE_DB` is
  `Boolean(NEXT_PUBLIC_SUPABASE_URL && SUPABASE_SERVICE_ROLE_KEY)` (`src/lib/test-helpers/live-db.ts`).
  The durable fix asserts, inside the repo's own test bootstrap, that live-DB credentials were not
  INHERITED from a dotenv file the runner did not intend — failing loud rather than silently
  running 16 suites against shared TEST.
- **⛔ Not closable by editing the skip gates.** `it.skipIf(!HAS_LIVE_DB)` is correct; the defect is
  that `HAS_LIVE_DB` became true by accident. (Carried verbatim from the TODOS entry.)
- **Criterion 2's proof stands as written:** a run whose skip counts match a plain `npx vitest run`
  at the same commit. That measurement has NOT been taken at HEAD and is a plan task, not an
  assumption. ⚠️ Full vitest must not share the box with another suite.

### Area 4 — `[164.8.2-CHANNEL-ALLOWLIST-STALE]`: derive, and what "derive" means here

- **Premise CONFIRMED live at HEAD, and confirmed clean — which is the point.** The staged list is
  `census.err ledger.err marker.err refdata.err dump.log transaction.out` at
  `test-restore-from-baseline.yml`. Deriving the writer set across BOTH producers (the workflow
  writes `dump.log`, `ledger.err`; `scripts/restore-test-from-baseline.sh` writes `census.err`,
  `marker.err`, `refdata.err`, `transaction.out`) yields exactly those six. It agrees TODAY by
  coincidence of two lists holding the same names, not by construction — which is precisely the
  state the entry says this defect passes through on its way to disagreeing.
- **DERIVE means: the stager enumerates what the producers can write**, not a second hand-kept
  list. ⛔ The 2026-09-10 fix replaced a glob with an enumeration deliberately (default-DENY, after
  a glob published a file nobody had named) — so the derivation must stay default-DENY. Deriving
  back to a glob would re-open `[164.8.2-REFUSAL-STILL-PUBLISHES]`, which is CLOSED.
- **Calibration:** a NEWLY written channel reaches the artifact with no list edited, and an
  UNDECLARED file still does not. Both arms, or the derivation has only moved the hazard.
