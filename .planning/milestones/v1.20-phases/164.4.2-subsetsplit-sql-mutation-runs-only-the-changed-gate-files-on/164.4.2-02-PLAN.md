    - baseline timestamp empty -> defect `baseline-epoch-unreadable`, exit 1 — an unreadable timestamp is not a fresh one
    - baseline timestamp non-numeric -> same defect kind, exit 1
    - migrations timestamp empty or non-numeric -> defect `migrations-epoch-unreadable`, exit 1
    - every kind `judge()` can emit is named in `DEFECTS`, asserted by iterating the kinds observed
  </behavior>
  <action>
Write the new gate following the shape named in `<context>`.

`judge({ baselineEpoch, migrationsEpoch })` is PURE — it takes two already-read strings and
returns a defect array. Refuse a non-numeric or empty epoch BY NAME *before* any numeric
comparison runs, mirroring the `case "$b_ts" in ''|*[!0-9]*)` guards the bash comparator
already has: a timestamp that could not be read is never fresh, and that is the whole reason
this check survives a shallow CI clone honestly instead of passing vacuously.

`main()` does the I/O: read `BASELINE_FILE`, `MIGRATIONS_DIR` and `FRESHNESS_TS_CMD` from the
environment with the SAME defaults the restore script uses, invoke the freshness command once
per path, take the first line, strip whitespace, hand the two strings to `judge()`.

⛔ Invoke the freshness command through an argv ARRAY (`execFileSync`), never a shell string:
split `FRESHNESS_TS_CMD` on whitespace, use element 0 as the binary and the remainder plus the
path as the argv tail. That reproduces what bash's unquoted `$FRESHNESS_TS_CMD "$path"`
expansion does today, with no shell in the middle. A non-zero exit or a throw from that call
is an UNREADABLE epoch (its own defect kind), never a fresh one.

The stale message MUST contain the phrase `the baseline dump is STALE`, naming both paths and
both epochs and telling the reader to regenerate the dump first. That phrase is load-bearing:
`scripts/restore-test-from-baseline.sh`'s self-test arm 5 asserts the refusal it observes is
the staleness one by matching on it, and task 2 re-points that arm at this script.

Print one always-on line on the clean path, e.g.
`baseline-currency: baseline=<epoch> migrations=<epoch> defects=0`.

Add `--self-test` driving `judge()` directly over the seven arms in `<behavior>`, with
`EXPECTED_ASSERTIONS` pinned and checked at the end.

⛔ PROVE IT CAN FAIL. Take a byte backup first (`cp scripts/check-baseline-currency.mjs
<scratch>/currency.bak`), then neuter the `-lt`-equivalent comparison so a stale pair returns
no defect, run `--self-test`, OBSERVE RED, record the RED message VERBATIM for the SUMMARY, and
restore from the backup verifying with `cmp`. ⛔ Never `git checkout --`, `git restore` or
`git stash`: those restore to HEAD and silently destroy uncommitted work. Re-take the backup
after every subsequent edit — a stale backup makes `cmp` pass on a corrupt restore.
