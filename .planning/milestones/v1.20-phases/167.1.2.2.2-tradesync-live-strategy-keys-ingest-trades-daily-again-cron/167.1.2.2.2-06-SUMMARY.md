# Phase 167.1.2.2.2 Plan 06: selector filter, cron_runs heartbeat, timeout budget Summary

**The tick now reads only connected keys that back an eligible strategy (4 on the PROD census, not 42), reports how many it skipped, leaves one closed counter-only `cron_runs` row per run for the future staleness alarm, and a test pins the filtered worst case (120 s) against the migration's 180 s timeout and Railway's 300 s idle cut-off.**

## What was built

`analytics-service/routers/cron.py`
- **Task 1 (D-13).** `.is_("disconnected_at", "null")` follows `.eq("is_active", True)` in the `api_keys` select. After the flatten loop, keys with an empty `strategy_ids` are dropped before `create_exchange`, `validate_key_permissions` or `fetch_usdt_balance`; the count is logged once at INFO (no ids). `skipped_no_strategy` rides on the no-keys early return and the final response. The excluded classes and their reasons are commented (counts only). A revoked key that backs a strategy keeps today's path.
- **Task 2 (SC-6).** `CRON_SYNC_CRON_NAME`, the module-level frozenset `_CRON_SYNC_HEARTBEAT_METADATA_KEYS` (`total_keys, skipped_no_strategy, synced, held, failed, timed_out, revoked, duration_s, stamped`), `_record_cron_sync_run` (5 s `asyncio.wait_for`, `except Exception` plus a nested `BaseException` guard on the log call, modelled on `mt5_terminal_scrub`), and the `_heartbeat_cron_sync` decorator on the route. `status` is `error` when `failed`, `timed_out` or `revoked` is above 0, or any top-level `*_error` field is set, or the run aborted.

`analytics-service/tests/test_cron_sync_timeout_budget.py` (new, 6 tests)
- Reads exactly one `*_cron_sync_tick.sql` and one `timeout_milliseconds := N` (currently 180000, in `20261010140000_cron_sync_tick.sql`); imports `BATCH_SIZE` (5), `KEY_SYNC_TIMEOUT` (60), `EXCHANGE_BATCH_DELAY` (2.0) from the route.
- Filtered census `{okx 3, bybit 1}` (2026-10-09): one batch per exchange, 60 + 60 = **120 s**, under 180 s and under 300 s. The runbook rehearsal ceiling (90 s) is under the timeout.

## Deviations from Plan

**1. [Rule 2 - Missing critical functionality] Autouse refusing sink for `get_supabase` in `test_cron_router.py`**
- **Found during:** Task 2
- **Issue:** the recorder runs on every exit, including runs that abort before the route builds its own client; a test that did not patch `routers.cron.get_supabase` would reach the real client, which WRITES a `cron_runs` row to a real project whenever `SUPABASE_URL` is set (any test importing `main` loads the TEST project's env file).
- **Fix:** autouse fixture that makes `get_supabase` raise; the never-raise contract turns it into one warning. Tests that want rows patch it themselves.
- **Commit:** 8e3417447

**2. [Rule 3 - Blocking] Route wrapped by a decorator instead of editing each return**
- The plan said to "wrap the body so the early return and the final return both pass through one recording point". The wrapper also covers the two HTTP 500 exits and cancellation, which a hand-edited pair of returns would miss. Behavior of the wrapped function is unchanged (return value and exceptions pass through).
- **Commit:** 8e3417447

**3. [Rule 1 - Test re-basing] Held-bucket tests re-fed**
- Some existing held-bucket tests used a strategy-less key to reach their branch; D-13 now drops such keys before the branch. They were re-fed with a strategy that stores zero rows, preserving what each asserts.
- **Commit:** 668062d1a

**4. [Addition] `trades_fetched_at_stamped` response field**
- The plan's metadata set includes `stamped`; the route did not yet expose a tick-wide stamped count (plan 05 only exposes it per key). Added as a sum over the uncapped `all_results`.
- **Commit:** 8e3417447
