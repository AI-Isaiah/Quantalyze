### The describe

`"/strategies — MYSTRATTABLE phones"`, `HAS_SEED_ENV`-gated, V360 360x780, V375 375x667, V390 390x844 (a local array; the shared `VIEWPORTS` is untouched). One case per viewport seeds a manager (`seedTestAllocator({ role: "manager" })`) owning: a published row WITH computed analytics (`ownerUserId`), a private row and a pending_review row with none, and a draft with a review note and the name `Long-Short-Momentum-Mean-Reversion-Statistical-Arbitrage Sleeve`. It signs in, opens `/strategies`, waits for `[data-strategy-table]`, asserts all four rows are present (precondition), then collects:

1. `assertNoReflow(page, "[data-strategy-table]")` (main and document).
2. `assertScrollsInside(region)` and the region's right edge inside the viewport.
3. Unpinned: Strategy header and every Strategy body cell moved left by the scroll amount within 1 px at max scroll, with guards that the container is below 768 px and the region really scrolled (>= 40 px), so the check cannot pass vacuously. No 170.2 helper exists for unpinned movement (`geometry.ts` exports only the pinned-stack check), so this is a local evaluate, same logic as SC6-DISCOVERY unpinned.
4. Each of the four names links to `/factsheet/<id>` and its text equals the seeded name (private and pending_review included).
5. Private and pending_review rows read `—` in Return %, CAGR, Sharpe and Max DD (found by header index); the published row's four cells contain a digit, so the dash check is not passing on an all-empty table.
6. The draft's note row has `data-testid="strategy-row-note"` and contains `Review feedback:`; at scrollLeft 0 and at max: block left = region left (1 px), block right <= region right + 1, first element left = region left + 16 (1 px).

Failures are collected and asserted once per viewport (named, `MYSTRATTABLE <vp> FAILED ...` lines), so a RED run names every broken contract. Rows are removed in a `finally` through `cleanupStrategiesByNamePrefix` under the per-worker `NAME_PREFIX`.

## Task 2: MYSTRATTABLE focus return

`"/strategies — MYSTRATTABLE focus return"`, V1280 and V390, `test.use({ permissions: ["clipboard-read", "clipboard-write"] })`. Seeds a manager with one private row, signs in, locates the button inside the row's last cell (`getByRole("button", { name: /private link/ })`), clicks `Get private link` (the mint) and waits for `Manage private link`. Then:

- (a) click it, a `dialog[open]` appears; click the dialog's `Close`; no dialog open and `button.evaluate(el => el === document.activeElement)` is true.
- (b) reopen, `Escape`: same.
- (c) reopen, wait for the lazily loaded panel's `Revoke link`, click it, click `Revoke`: dialog closed, the button reads `Get private link`, and it is the active element.

Rows (and their cascading `strategy_shares`) are removed in the `finally`. The mint needs `SHARE_TOKEN_SECRET` in the shell that runs Playwright, per the plan's lane recipe.

The post-deploy PROD reading of the same behaviour is the manual line in `170.7-VALIDATION.md` ("Private-link modal focus return on PROD after Close, Escape and a revoke", D-01); the Playwright describe does not replace it.
