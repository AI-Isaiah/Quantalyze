# Phase 166.2 COMPUTEONCE: silent-failure review, round 1

Scope: every `src/` change on the branch against its merge-base with `origin/main`. Cited by
symbol only.

**Frame.** `@/lib/return-stats` returns `null` for "no dispersion" (an exact constant or float
residue), a non-finite input, or n < 2. CONTEXT D-07 is a locked, reversible decision: each
calling site maps `null` to the value it already emits for an exactly constant input. This review
does not re-argue D-07. It names the places where that mapping puts a number on screen while a
sibling surface shows "—" for the same input, or where a `null`/gap path already exists and the
site still draws 0.

**What is sound.** The module itself (`dispersion`, `sharpe`, `pearson`, `residueFloor`), the
`og-metrics.ts` `computeOgHeadline` hide path (`?? NaN`, "—" in the OG route's `fmtNum`),
`build-payload.ts` `pearsonCorr` (`?? NaN`, and `DistributionPanels` renders non-finite ρ as "—"
and filters it from the bar chart), `CompareCorrelationMatrix` (null renders "—"),
`sample-basis-ratios.ts` `sampleBasisRatios`, `scenario.ts` `computeScenario` Sharpe (null),
`scenario-benchmark.ts` `computeScenarioBenchmark` (IR, beta, alpha and correlation all null),
`diversification.ts` `diversificationRatio` (null on residue or NaN), and
`holding-compare-adapter.ts` `reconstructAndAnalyze` (Sharpe null). There are no empty catch
blocks, no new try/catch, and no new broad catches in the diff. The cross-language pin in
`return-stats.test.ts` can fail: it requires exactly one literal definition across the two Python
files, so a missing or renamed constant goes red and cannot pass empty.

**Measured, not argued.** A temporary vitest probe, deleted afterwards and never committed, ran
every `CONSTANT_YIELDS` fixture (7 of 7) through `compute`, `computeOgHeadline`, `jointMetrics`,
`rollingSharpe` and `rollingBeta`. A second probe checked `beta` on a NaN `y` leg. The results
are quoted in each finding.

## HIGH

### SFH-H1: the factsheet shows Sharpe "0.00" where the OG card for the same series shows "—"

- **Location:** `src/lib/factsheet/compute.ts` `compute` (`sharpeRatio(...) ?? 0`);
  `src/lib/factsheet/og-metrics.ts` `computeOgHeadline` (`?? NaN`); rendered by
  `MetricsColumn` `num(m.sharpe)` (Main Metrics, "Sharpe" row, and the bench column via
  `b?.sharpe`). The same 0 also feeds `build-payload.ts` `computePeerPercentile(strategyMetrics.sharpe, …)`
  on the api arm, and `bootstrap.ts` `headlineStats` (`?? 0` per resample), whose output
  `AnalyticalPanels` renders as the Sharpe point, its CI and its histogram.
- **Measured:** 7 of 7 constant-yield fixtures give `compute(...).sharpe === 0` and
  `ann_vol === 0`, and `computeOgHeadline(...).sharpe` is `NaN` ("—").
- **When it reaches the screen:** `overlayBasisScalars` replaces the TS Sharpe with the persisted
  `cash_settlement` scalar when that object exists, and a persisted null reads NaN, shown as "—".
  The TS 0 is what renders whenever `metricsByBasis.cash_settlement` is absent (the overlay returns
  `base` unchanged). The bootstrap panel and the benchmark column always use the TS value.
- **Issue:** this is the population the phase targets: a compounding constant-yield book. Before
  the phase the factsheet showed a Sharpe of about 1e13. It now shows `0.00`, a well-formed
  number that says "no risk-adjusted return". The social card for the same strategy says "—", which
  means "cannot be measured". Two public surfaces now give different answers for one series. The
  peer percentile ranks the strategy on the fabricated 0, and the bootstrap panel draws a CI of
  `[0.00, 0.00]` with a histogram spike at 0, which looks like a very precise estimate of zero.
- **Pre-existing part:** an exactly flat series already rendered `0.00` here (D-07 keeps that).
  The new part is that residue books, which this phase exists for, now land on it as well.
- **Hidden errors:** NaN inside `rets` also becomes 0, because `sharpe` returns null on
  non-finite input and `?? 0` absorbs it. That was 0 before the phase too (`s > 0` was false on NaN).
- **Recommendation:** make `compute`'s Sharpe `sharpeRatio(...) ?? NaN`. `num()` in
  `MetricsColumn` already renders a non-finite value as "—", and that matches the OG card. In
  `headlineStats`, let a null Sharpe drop the resample from the histogram (the histogram builder
  already `continue`s on non-finite values) rather than count it as 0. Guard `computePeerPercentile`
  on a finite Sharpe. That is a D-07 reversal for one field, so it needs an explicit decision and
  must not be slipped into a fixer round. If D-07 stands, record the OG/factsheet split as an
  accepted, user-visible divergence in CONTEXT.

```ts
// compute.ts
const sharpe = sharpeRatio(rets, { periodsPerYear, ddof: 0, rf }) ?? NaN; // "—", as the OG card
```

### SFH-H2: the allocator Risk-tab CorrelationMatrix paints "0.00" where CompareCorrelationMatrix shows "—", and the new test pins "0.00" as intended

- **Location:** `src/app/(dashboard)/allocations/widgets/risk/CorrelationMatrix.tsx`
  `CorrelationMatrixInner` (`pearson(av, bv) ?? 0`); test
  `CorrelationMatrix.residue.test.tsx` case "reference: the all-zero leg's pair cells read 0.00 in
  the neutral colour".
- **Issue:** `pearson`'s own contract (audit G11.E.5, quoted in `return-stats.ts`) says "no
  correlation" and "correlation cannot be measured" are different answers. The retired local
  `pearson` in this widget returned 0 on a zero denominator, and the phase kept that by mapping
  null to 0. `CompareCorrelationMatrix` receives the same null from the same function and renders
  "—". An allocator who looks at a flat or constant-yield leg on the Risk tab reads "0.00
  (uncorrelated)", a claim the data cannot support, and the compare page says the opposite for
  the same pair.
- **Test intent (Rule 9):** the residue test checks that constant-yield equals all-zero, which is
  a real D-07 invariant and can fail. Its reference case also asserts the literal `"0.00"`, which
  makes the misleading shape a requirement. A later fix to "—" would turn that case red for the
  right change.
- **Recommendation:** type the matrix `number | null`, render null as "—" with the neutral
  background (as `CompareCorrelationMatrix` `cellBg(null)` does), and change the reference case to
  assert "—". The D-07 equality between constant-yield and all-zero stays intact because both legs
  move together.

## MEDIUM

### SFH-M1: rolling Sharpe and rolling beta draw 0 through undefined windows, although the gap path already exists

- **Location:** `src/lib/factsheet/rolling.ts` `rollingSharpe` and `rollingBeta` (`?? 0`).
  Consumers: `scenario-blend-adapter.ts` (`zipDrop`, which already drops `null`),
  `build-payload.ts` `strategyRollingSharpe`, `comparator-block.ts` `rollingSharpe`/`rollingBeta`,
  `scenario-factsheet-payload.ts`.
- **Measured:** both functions return `0` in every window for 7 of 7 constant-yield fixtures.
- **Issue:** the return type is already `Array<number | null>` (warm-up windows are null), and
  `zipDrop` drops nulls, so a chart would show a gap. `?? 0` draws a flat line at 0 instead: a
  "Sharpe 0" and "beta 0" regime the data cannot support. NaN in a window is absorbed to 0 in the
  same way. For `rollingBeta` that changed: before the phase a NaN window gave `cov / varB` = NaN.
- **Recommendation:** `out[i] = sharpe(...)` and `out[i] = beta(...)` with no `?? 0`, so the
  undefined window becomes the null the type and `zipDrop` already handle. This is D-07-scoped, so
  it needs the same decision as H1.

### SFH-M2: `computeScenario`'s average |corr| counts undefined pairs as real zeros

- **Location:** `src/lib/scenario.ts` `computeScenario`, correlation loop
  (`pearson(...) ?? 0`, then `absCorrSum += Math.abs(corr); corrCount += 1`).
- **Issue:** a pair whose correlation is undefined adds 0 to the numerator and 1 to the
  denominator of the displayed "Avg |corr|". A book with one flat or constant-yield leg reads as
  better diversified than it is. The matrix cell shows 0.000 for the same pair.
- **Recommendation:** on null, skip both `absCorrSum` and `corrCount`. Separately, decide whether
  the matrix cell should carry null. The avg change alone does not alter any exact-constant output
  shape except the average's value, so it may need its own decision under D-07.

### SFH-M3: `jointMetrics` shows 0 for five ratios on a residue benchmark, and D-07 is asserted for only two of its fields

- **Location:** `src/lib/factsheet/joint.ts` `jointMetrics` (`beta ?? 0`, `corr ?? 0`, so
  `r2 = 0` and `treynor = 0`, and `infoRatio ?? 0`); test `return-stats.sites-joint.test.ts`
  "T16 beta and corr against a constant-yield bench equal the all-zero bench".
- **Measured:** on a constant-yield benchmark, `beta`, `corr`, `r2` and `treynor` are all 0, but
  `up_capture` runs from -0.012 to -4.47 across the fixtures. On an all-zero benchmark `up_capture`
  is 0 (no up days). Every day of a constant-yield benchmark is an "up day" with a tiny real sum,
  so the capture ratio divides by it.
- **Issue:** the D-07 invariant ("constant-yield gives exactly the all-zero output") is violated at
  `up_capture`. The T16 test compares only `beta` and `corr`, so it cannot catch this. The capture
  ratio is not a dispersion ratio, so it may fall outside the phase's formula scope, but it is the
  same benchmark the phase has just declared to have no dispersion, and it is rendered next to the
  zeroed beta.
- **Recommendation:** either extend T16 to a full-object `toEqual` against the all-zero bench and
  fix `up_capture` (for example, guard it on the benchmark's dispersion), or record `up_capture`
  in CONTEXT as an explicit out-of-scope exception. The 0-for-undefined mapping of the five ratios
  is the same D-07 question as H1.

### SFH-M4: `buildAllocatorMetrics` computes vol and correlation over possibly different windows

- **Location:** `src/lib/factsheet/allocator.ts` `buildAllocatorMetrics`
  (`mmS = dispersion(mmRets.length === n ? mmRets : mmRets.slice(0, n), 0).sd`, then
  `corr = pearson(rets, mmRets) ?? 0`).
- **Issue:** if `mmRets` is shorter than `rets`, `pearson` silently uses `min(n, mmRets.length)`
  points while `annVol` uses n. Before the phase that case produced NaN (reads past the end),
  which at least surfaced. Now it produces a finite correlation over a truncated window. `jointMetrics`
  throws on unequal lengths, and this function has no such assertion. Callers pass equal-length
  arrays today, so this is latent. `corr ?? 0` also shows 0.00 for an undefined correlation (the
  same class as H2).
- **Recommendation:** assert `mmRets.length === rets.length` at entry (throw, as `jointMetrics`
  does), then drop the `slice` branch.

### SFH-M5: `beta()` returns NaN, not null, for a NaN in the `y` leg, and `?? 0` does not catch NaN

- **Location:** `src/lib/return-stats.ts` `beta`; callers `portfolio-stats.ts` `computeAlphaBeta`,
  `joint.ts` `jointMetrics`, `rolling.ts` `rollingBeta`.
- **Measured:** `beta([1, NaN, 3], [1, 2, 3])` is `NaN`, and so is
  `computeAlphaBeta([1, NaN, 3], [1, 2, 3]).beta`.
- **Issue:** the docstring says null "when the variance is not positive (a NaN leg)", but only the
  `x` leg is guarded. `sharpe` rejects non-finite input explicitly, and `pearson` catches both legs
  through `denom`. `beta` is the only one of the three that lets NaN through, and every caller's
  `?? 0` passes NaN on, so `alpha` becomes NaN too. The behavior predates the phase (the old local
  `varB > 0` guard had the same gap). It is flagged because the module now claims a single contract.
- **Recommendation:** at the top of `beta`, add
  `if (y.some((v) => !Number.isFinite(v)) || x.some((v) => !Number.isFinite(v))) return null;`,
  with a unit case per leg.

### SFH-M6: `diversification.ts` now judges σ_p with two different floors

- **Location:** `src/lib/diversification.ts` `diversificationRatio` (the shared
  `dispersionIsReal(sigmaP, 0)`, so sd above 1e-12) and `percentContributionToRisk`
  (`portVar > 1e-15`, so sd above about 3.2e-8, untouched by this diff); also
  `portfolio-stats.ts` `computeRiskDecomposition`, which moved to the shared floor.
- **Issue:** for σ_p in (1e-12, about 3.2e-8] the panel shows a diversification ratio while PCR and
  ENB read "—". `computeRiskDecomposition` and `percentContributionToRisk` both answer "whose risk
  is this" but now use different floors. It is a surviving local floor of the kind D-17 set out to
  remove. The window is narrow, and real books sit far above it.
- **Recommendation:** move `percentContributionToRisk` to
  `dispersionIsReal(Math.sqrt(Math.max(portVar, 0)), 0)`, or record why a looser floor is kept.

### SFH-M7: dispersion is still computed locally in several places, so D-07 reads 0 in one field and residue in the next

- **Location:** `src/lib/scenario.ts` `computeScenario` (`variance`, `volDaily`, `volatility`
  computed locally); `src/lib/factsheet/rolling.ts` `rollingVol` (`stdDev(w, false)`, not
  `dispersion`); `src/lib/portfolio-stats.ts` `computeTrackingError` (`stdDev(diff, true)`, used by
  `computeScenarioBenchmark.trackingError`); `scenario-benchmark.ts` `varB` and
  `scenario-stress.ts` `varSeries` (local population variance, now judged by the shared floor).
- **Issue:** on a residue series, `compute` reports `ann_vol === 0` (measured), while `rollingVol`,
  the scenario `volatility` and the benchmark `trackingError` report about 1e-15, which formats as
  0.00% and so does no visible harm today. The IR is null while its own tracking error is a
  positive residue. None of these is a ratio, so the single-source gate by design does not match
  them. The risk is a future ratio built on one of these local sds, where it would divide by
  residue again.
- **Recommendation:** route these through `dispersion(...).sd` (so residue reads exactly 0, as in
  `compute`) or record them in the single-source gate's rationale as deliberately raw.
