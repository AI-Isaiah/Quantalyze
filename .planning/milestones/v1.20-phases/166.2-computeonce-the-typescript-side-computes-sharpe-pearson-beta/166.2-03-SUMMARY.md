## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] T10 uses the NaN-safe complement of the plan's predicate**
- **Found during:** Task 1
- **Issue:** The plan's expression was `dispersionIsResidue(Math.sqrt(Math.max(totalVariance, 0)), 0) ? 0 : share`. `Math.max(NaN, 0)` is NaN, and `dispersionIsResidue(NaN, 0)` is false. So a NaN total variance would have produced NaN percentages, where the old strict-positive guard produced 0. `RiskDecomposition.tsx` rounds the percentage for the chart, so the NaN would reach it.
- **Fix:** `dispersionIsReal(Math.sqrt(Math.max(totalVariance, 0)), 0) ? share : 0`. On a finite total this is the exact complement of the plan's form. On NaN it reads 0 as before. Plan 01 used the same reasoning for T5. A test pins it: "a NaN covariance still reads 0 per strategy".
- **Files modified:** src/lib/portfolio-stats.ts, src/lib/return-stats.sites-risk.test.ts
- **Commit:** dc0e63d19

**2. [Rule 1 - Plan text] T11's information-ratio invariant is tested on the excess series, not on a single constant leg**
- **Found during:** Task 2
- **Issue:** The plan's behavior lines say a constant-yield benchmark, or a constant-yield portfolio, gives a null IR "as an all-zero benchmark gives today". That is not what the all-zero leg gives: with one leg constant, `p - b` is the other leg's noise, so the IR is a finite number for the all-zero leg and for the constant-yield leg alike. The D-07 invariant applies to the series the ratio is computed over, and for the IR that is the excess.
- **Fix:** The IR is tested with portfolio = benchmark + a constant yield against portfolio = benchmark, for all 11 ids. With a constant-yield single leg the tests assert beta, alpha and correlation (benchmark leg) and correlation (portfolio leg), which is where D-07 does apply. The plan's other IR behaviours are tested as written: null on a constant excess, bitwise today's value on noisy input, and equal to the shared `sharpe`.
- **Commit:** 02b522b47

**3. [Rule 3 - Necessary edit] Import line and header comment in portfolio-stats**
- The `computeRollingMetric` import line in `portfolio-stats.test.ts` had to go with the describe block. The header docblock of `portfolio-stats.ts` no longer says "15 quantitative functions ... rolling metrics", and it now names `@/lib/return-stats` as the source of the beta and the floor. Section numbers of the remaining functions are unchanged (section 3 is simply absent).

## Behaviour notes (recorded, not changed)

- **NaN legs at T11.** On a NaN in either leg, `informationRatio` and `correlation` are now null where they used to be NaN, because the shared `sharpe` and `pearson` return null on non-finite input. Both are "no number". Null is the em-dash path, and NaN was never a shape this site promised. `scenario-stress.ts` still guards a non-finite BTC feed separately for beta. `beta` and `alpha` behave as before on NaN.
- **Constant-yield portfolio beta at T11.** With a constant-yield PORTFOLIO against a noisy benchmark, `beta` is about 1e-14 rather than the all-zero portfolio's exact 0. The shared `beta(y, x)` floors only `x`, the benchmark, which is the correct regressor test. A 1e-14 beta renders as 0.00. Making `beta` treat a residue `y` as 0 would change `return-stats.ts`, which this plan must not edit. If the phase wants that exactness, it is plan 01's module to change.
- **The noisy correlation was already bitwise equal** to `pearson` on the test's input on the old code, so that identity check is a pin, not a red test. The noisy IR identity is bitwise by construction (the plan's D-20 B1 argument), so it is a pin too.
- **Flaky UI tests under load.** The full `allocations` run printed `Test timed out in 5000ms` for `ScenarioCommitDrawer.test.tsx` (1 test) and `ScenarioComposer.save.test.tsx` (4 tests) at load averages of 40 to 63, with three sibling executors running.
