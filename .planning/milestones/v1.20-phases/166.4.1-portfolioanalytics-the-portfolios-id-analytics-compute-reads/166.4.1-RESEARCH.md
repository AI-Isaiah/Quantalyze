### Anti-Patterns to Avoid
- **Writing `str(exc)` into the flag/note.** `benchmark_error` already does that into `data_quality`; the new user-facing note must be a fixed sentence (HONEST-01 / D-162-4, `portfolio.py:711-717`).
- **Making stale/thin flip `partial_data`.** `tests/test_portfolio_compute_integration.py:226-234` runs the stale path (`return None, True`) and asserts `data_quality["partial_data"] is False`. Keep `partial_data`'s inputs exactly as they are (`portfolio.py:1146-1149`); the new flag is a separate field.
- **Duplicating `_interval_matched_benchmark` in the router.** Locked out by D-02.
- **Gating the 30-day floor on the pre-pairing overlap.** Count the PAIRED rows (`len(aligned)` after the helper), otherwise a weekday portfolio is gated on a different count than the metric it feeds.

## Common Pitfalls

### Pitfall 1: D-06 turns most of the existing compute tests RED
**What goes wrong:** the shared fake returns `MagicMock(data=[])` for the final update (`test_portfolio_compute_integration.py:104`), and so does `_c6_supabase` (`test_correlation_residue_sites.py:384`) and the curated-error fake (`test_computation_error_curated.py:78`). Today the code logs and continues, which is why they pass; the prototype run printed that very `ERROR ... analytics update returned no data` line.
**How to avoid:** change the shared helper's default to a one-row result (`data=[{"id": insert_returns_id}]`), add an opt-in parameter to return `[]` for the D-06 test, and do the same in `_c6_supabase`. The test files that reach the final update through the shared helper: `test_portfolio_compute_integration.py`, `test_c19_portfolio_fixes.py`, `test_status_contract_match_sim_portfolio.py`, `test_portfolio_router_logic.py`; with their own fakes: `test_correlation_residue_sites.py`. `test_computation_error_curated.py` explodes before the final update, so it is unaffected. Verify by running the full `analytics-service` suite, not only the four files.
**Warning signs:** `HTTPException 500` in a test that previously asserted a result.

### Pitfall 2: weekday-only portfolio, first and last day semantics
**What goes wrong:** index 0 is paired with the BTC return dated `t_0` (166.4 D-05) and every later date with the compounded return over `(t_{k-1}, t_k]`. A Monday needs BTC returns for Saturday and Sunday (the BTC calendar is seven days), else the interval is unpaired. `benchmark_twr` is then `price[t_last] / price[t_0 - 1] - 1` over PAIRED intervals only.
**How to avoid:** the oracle in the tests is built from price ratios, never from the helper (see Code Examples).

### Pitfall 3: windows can still differ between the two TWRs
**What goes wrong:** `portfolio_twr` covers every blended day; the BTC TWR covers paired intervals only. A portfolio older than BTC's stored window, or a BTC gap, makes the "Alpha" delta on screen (`BenchmarkComparison.tsx`: `portfolio_twr - benchmark_twr`) span different windows. This is pre-existing (the old inner join had it too) and is NOT introduced here. See Open Question 1.

### Pitfall 4: the persisted `stale` flag is dead today
`"stale": benchmark_stale` sits inside the `not benchmark_stale` guard, so it is always `False` in stored rows and the "Stale" badge in `BenchmarkComparison.tsx` can never render. The flagged-empty object on the stale path should write `stale: True` (when `benchmark_rets` is not `None` the stale series exists, when `None` write `True` as well: `(None, True)` is what `get_benchmark_returns` returns on total failure).

### Pitfall 5: adapter `toEqual` pin
`src/lib/portfolio-analytics-adapter.test.ts:59-65` asserts the parsed comparison with `toEqual({symbol, correlation, benchmark_twr, portfolio_twr, stale})`. A parser that always emits `note: null` breaks it. Emit the key only when the stored object carries a string `note` (or update that test deliberately).

### Pitfall 6: `data_quality` is invisible to the page
Persisting a flag only in `data_quality` satisfies D-04 literally ("writes a NAMED flag") but nothing on `/portfolios/[id]` reads that column. That is why the recommended carrier is the comparison object.

### Failing-first test B (D-02): correlation is the interval correlation
Prototyped and run RED against HEAD (`correlation = 0.9383379914861462`):
```python
def test_portfolio_correlation_is_the_interval_correlation():
    wd = pd.bdate_range("2026-01-05", periods=40)
    rng = np.random.default_rng(11)
    cal = pd.date_range(wd[0] - pd.Timedelta(days=14), wd[-1] + pd.Timedelta(days=3), freq="D")
    btc = pd.Series(rng.normal(0.0, 0.03, len(cal)), index=cal)
    price = (1 + btc).cumprod()                      # the oracle is the benchmark's own closes
    interval = [float(btc[wd[0]])] + [float(price[wd[k]] / price[wd[k - 1]] - 1) for k in range(1, len(wd))]
    strat = pd.Series([0.5 * v for v in interval], index=wd)   # a book that tracks BTC over each HOLDING interval
    bc = _run_with_btc(strat, btc)["benchmark_comparison"]
    assert bc["correlation"] == pytest.approx(1.0, abs=1e-9)
```
