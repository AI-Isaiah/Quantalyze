Close the NULL-population gap RESEARCH.md identifies as the actual defect D-02-PRIME's original
"no backfill needed" framing did not anticipate: `venue_account_id` is populated ONLY by the wizard's
`create_wizard_strategy` RPC today. `keys/validate-and-encrypt/route.ts` — the route BOTH founder-visible

key connected outside the wizard stays permanently unidentifiable on the card Plan 01 just taught to
render the value, which defeats the phase's own goal for its most common entry point.

own migration comment (TWIN-7) records that MT5 cannot be a composite member, so it has nothing to
stamp. Do not touch that file in this plan.

Purpose: make the identifier populate at every LIVE, MT5-capable create chokepoint, per the phase's
explicit instruction to either populate everywhere or record why a path stays NULL — this plan is the
"populate" half for the one path that genuinely needs it.

Output: one route edit (derive + stamp `venue_account_id`, mirroring `create-with-key/route.ts`'s exact
derivation) plus a new, previously-unreachable 23505 discrimination arm on this route's INSERT, since
writing the column for the first time here makes the venue-identity unique index reachable on a path
that has never hit it before.
