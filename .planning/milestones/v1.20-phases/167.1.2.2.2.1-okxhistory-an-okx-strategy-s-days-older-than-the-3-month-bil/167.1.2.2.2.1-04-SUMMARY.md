# Phase 167.1.2.2.2.1 Plan 04: Rebuild core and survival pins Summary

**A pure module that runs the live NAV/TWR core over live inputs with OKX archive days prepended, proves the live days are bit-for-bit unmoved, and slices the result to exactly the covered, in-gap, finite, not-yet-present days; plus tests pinning that the derive never reaches older rows and the runner counts them.**

## Accomplishments

- `rebuild_union` calls `combine_realized_and_funding` twice with the derive's own keyword shape (live-only, then archive days in `[from_day, live_first_day)` prepended) and refuses with `identity_violation` if any live day after the first differs by more than 1e-9. The first live day is recorded in `first_live_day_differs`, not failed. An unusable anchor (`balance_error`, `equity` None or non-finite, `abs(equity) <= DUST_NAV_FLOOR`, or no live day) raises `live_anchor_unusable` before the first core call. `apply_flow_coverage_terminus` is never called, and a test reads the module source to pin that.
- `rows_for_strategy` returns `[{date, daily_return}]` for days in covered ∩ stored gap, finite, not already present, strictly before `live_first_day`, and the narrowed gaps `subtract_ranges(gaps, inserted ∪ (existing ∩ gap days))`.
- A covered quiet day is an explicit zero-P&L record (a real 0.0); an uncovered day never gets a record, a row or a 0.0, even when the core's own gap fill puts a 0.0 into the union index between two covered days.
- Hand-computed oracle (independent literals): anchor 10000, live 08-02 +100 / 08-03 -50, archive 08-01 +200 gives 200/9750, 100/9950 and -50/10050.
- Pins over existing code: the derive's span-bounded delete cannot reach older rows (T-CLOBBER-1a), a span starting inside a rebuilt range overwrites those days (T-CLOBBER-1b), and the runner's dense reindex plus segmenter close the break inside rebuilt rows and move `headline_since` (D-07).
