- **Whole-day gating.** All three sum sites in `aggregate_archive` are gated on `covered`:
  NON_EXTERNAL after its non-USD handling, REALIZED outside the live instTypes before
  `excluded_by_month`, and the final branch before `summed.add`. The three classification
  counters (`map_drift`, `unknown_nonzero`, `non_usd_rows`) and `excluded_non_usd` still read

- **Edge-day adjacency and the `bal` seam chain.** `quarter_edge_days` and `_adjacent_runs` both
  use the same rule: one file's tail edge equals another file's head edge. A probe over Q4 2025
  plus Q1 2026 plus Q3 2026 behaved as follows:
  - The year boundary joins: whole is `{2025-12-31}`.
  - The Q2 hole stays split: runs `[[Q4, Q1], [Q3]]`, and the missing set is
    `{2025-09-30, 2026-03-31, 2026-06-30, 2026-09-30}`.
  - `_windows` returns two separate windows.

  `verify_bal_chain` chains edge-day bills too, so the seam is still proven.
- **Fail-closed if the cut is not exactly 8 hours.** The 2026-10-22 reading proves only that the
  Q2 file starts before 04-01 00:00Z. It does not pin 16:00Z, and it says nothing about the Q2
  end cut, because `observed_max_day` read 06-07. Under any other consistent offset, a bill on the
  wrong side of 16:00Z falls outside the UTC+8 bounds and stops `quarter_range_mismatch`. A bill
  that sits in neither file breaks the seam chain whenever it moved the balance. So a wrong offset
  produces a stop, never a partial "whole" 06-30.
- **D-10 window from `covered_days`.** `_windows` clips each island of `days_to_ranges(covered_days)`.
  The merge rule only joins islands whose days are consecutive (`first <= last + 1 day`), so a
  missing day between two islands is never compared. Plan 19's N1 neuter confirms that 09-30 is
  never compared.
- **No NAV-roll hole from a missing tail edge.** `rebuild_union` does not refuse a hole in
  `covered_in`. A hole at the latest file's tail edge would need the live P&L to start the day
  after that edge, and in that case no window remains: the covered set ends the day before the
  edge, so the stop is `reconcile_miss window=none`. With `MIN_COMPARED_DAYS` at 14, every run
  that passes reconcile has the live side owning the tail edge day.
- **`census.edge_days`.** The value is sorted ISO dates computed from the requested quarter labels,

  its four keys, and the `Q3_CENSUS_COUNTS` split pins that. No TS or SQL reader parses

- **A partial edge day can never be written.** `rows_for_strategy` and `_plan_target` both require

  outside them. The RPC derives `reconstructed_ranges` from the inserted dates. The one-file
  end-to-end test asserts `p_rows`, `p_expected_gaps_after`, `csv_days`, the stored
