## Evidence by criterion

### SC-1: the durable job (VERIFIED, code side)

- **Kind and scope.** `20261026120000_okx_archive_rebuild.sql` admits `okx_archive_rebuild` at all three sites (registry row, `compute_jobs_kind_check`, `compute_jobs_kind_target_coherence`), api_key-scoped only, so a published strategy is never flipped to `computing` during the multi-hour wait. The re-base keeps the `derive_broker_dailies` and `derive_allocator_equity` arms. No newer migration on `origin/main` redeclares either CHECK (grepped).
- **Worker wiring.** `job_worker.dispatch` has the `okx_archive_rebuild` arm, `TIMEOUT_PER_KIND` is 15 minutes, `WATCHDOG_PER_KIND_OVERRIDES` is 30 minutes (strictly greater), and the kind is not in the backfill set.
- **Statelessness.** `_quarter_step` re-applies (idempotent), re-reads OKX's own request state and decides ready, wait, re-apply once, or give up. `_defer_job` uses `defer_compute_job` (claim-token fenced, attempts untouched, at most one hour). The give-up bound comes from OKX's request `ts` (8 h) and a second backstop from the job's own `created_at` (24 h). No link or `ts` is stored between claims. There is no state table.
- **Link expiry.** `_download_quarter` answers a 403/410 with exactly one fresh status read and one retry on the new link; a second expiry or a read with no link is the transient `link_expired`. `finished` with no link is never treated as success.
- **Test that fails on a lost link.** `TestLostOrExpiredLink` and `TestWaitIsADeferNeverAFailure` in `tests/test_okx_archive_job.py`. I neutered a copy of `okx_archive_job.py` (outside the repo) two ways and re-ran the file:
  - second-expiry path returns an empty file instead of the transient stop: `test_a_second_403_is_transient_link_expired_not_a_third_try` goes RED (1 failed, 116 passed);
  - `finished` accepted without a link: `test_finished_with_an_empty_link_never_reaches_done[calibrate|preflight]` and `test_an_empty_link_that_the_reapply_replaces_is_ingested` go RED.
  The assertion that nothing but `set_compute_job_progress` and `defer_compute_job` is ever written on a lost link (`_assert_no_other_writes`) is what makes "a lost link never yields a partial result" a checked property.
- **Restart.** `test_a_calibrate_job_defers_then_a_restarted_claim_ingests_the_quarter` and `test_after_a_lost_link_a_restarted_claim_gets_a_fresh_link_and_reuses_nothing` run the second claim on fresh fakes.
- **SSRF and bombs.** `okx_archive_download.py` is https-only, exact-host allow-list, private-address refusal, size and ratio caps. `ARCHIVE_ALLOWED_HOSTS` is deliberately EMPTY in PR-A (`frozenset()`); every real download is refused until plan 13 fills it from a measured host. This is by design and is recorded as pending, not as a gap.

### SC-2: provenance and the public line (VERIFIED, code side)

- **Write side.** `public.apply_okx_archive_rebuild` (SECURITY INVOKER, service_role only) inserts rows `ON CONFLICT DO NOTHING` and, in the same transaction, narrows `unrecovered_gaps` and appends `{from, to, source, recorded_at}` to `series_provenance.reconstructed_ranges`. The appended ranges are built from the rows the INSERT actually returned, never from the caller's claim. `source` is a literal inside the function. A refusal raises and rolls the whole call back.
- **SQL gate.** I ran `node scripts/mutation-runner/run.mjs --file supabase/tests/test_okx_archive_rebuild.sql` on the disposable local lane (no shared database touched): `arms: 15/15/0`, `biting: 15`, every arm RED under its own neuter with identity ok, baseline and restore legs green, "No defects in the narrowed scope".
- **Read side.** `readReconstructedRanges` is the only reader; it voids a malformed record rather than rendering a partial claim, and the callers report the malformed case to Sentry and print an "unavailable" line instead of silence. `RECONSTRUCTED_SOURCE` is pinned across SQL and TS by `okx-archive-literal-pin.test.ts` (green).
- **Public text.** `ReconstructedRangeLines` renders `{from} – {to}: rebuilt from OKX's quarterly account statement, not the live feed.` which is the CONTEXT D-06 sentence character for character. It is wired in `FactsheetView` (header) and the tear sheet page, shown to every viewer, no chart marking. The payload cache key is bumped to v19 in `v2/page.tsx`. Rebuilt days are not excluded from headline metrics (D-07).
- **Run:** `FactsheetView.reconstructed-range.test.tsx`, `page.trade-fetch.test.tsx`, `trade-fetch-provenance.test.ts`, `fetch-and-build-payload.test.ts`, and all of `src/app/factsheet`: green.

### SC-3: the one-cent reconciliation (VERIFIED, code side; calibration pending)

- `okx_archive_reconcile.TOLERANCE_USD = Decimal("0.01")` is a module constant with no parameter. `reconcile_leg` requires every day AND the window total within it; a day present on one side only compares against zero, so truncation surfaces as a miss. `MIN_COMPARED_DAYS` and `MIN_ACTIVE_DAYS` stop an empty or quiet window from authenticating a file (an evidence floor, not a tolerance).
- `_reconcile` raises the permanent `reconcile_miss` (date range plus both totals) and `_run_evaluation` runs before the fingerprint gate and before any RPC, so a miss writes nothing (D-11). Live days win (D-12) both in `rebuild_union` and in the RPC (`ON CONFLICT DO NOTHING`). The identity assertion (`IDENTITY_ATOL = 1e-9`, permanent `identity_violation`) proves prepending archive days cannot move a live day.
- The units for the cent bound are in `tests/test_okx_archive_reconcile.py` (green, part of the 612-test Python run). The seam, completeness and bill-class guards (`verify_bal_chain`, `MIN_CHAINED_PAIRS`, unknown subtype fails loud, non-USD fails loud) are in `okx_archive_classify.py` and `okx_archive_files.py`.
- **Not provable here:** whether the real Q2/Q3 files reconcile to one cent. That is plan 14, and per D-10 a miss STOPS for the founder; the tolerance is never widened. D-13 seam readings (`realized_balance_vs_rolled_nav`, `flow_seam`) are readings, not gates, as decided.

### SC-4: unrecovered days stay named (VERIFIED, code side)

- `rows_for_strategy` emits a row only for a day that is inside a verified ingested quarter, inside a stored gap, finite, not already present, and before the first live day. A day in a quarter that was not ingested gets no row and no 0.0.
- The RPC recomputes the narrowed gaps itself (stored gap days that still have no row, collapsed to islands) and refuses unless they equal the caller's `p_expected_gaps_after` (`gaps_after_mismatch`, INSERT rolled back). SQL arm 14 covers a two-quarter gap with rows for only the later part: the earlier part stays named with no row and no 0.0.
- The factsheet and tear sheet render the gap lines and the reconstructed lines side by side, so a partly rebuilt gap shows both (covered by the factsheet and tear-sheet tests above).
