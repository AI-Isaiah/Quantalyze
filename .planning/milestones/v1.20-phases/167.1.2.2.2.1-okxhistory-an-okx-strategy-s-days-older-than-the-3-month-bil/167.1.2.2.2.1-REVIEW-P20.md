## Summary

The D-16 code does what CONTEXT D-16 asks, and the skip is safe for the bal-chain completeness proof. The two
MEDIUM findings are a test gap on the multi-file path, which is the shape of the real Q2+Q3 calibrate re-run,
and a crash path that the skip now opens to a bill that used to stop cleanly.

**Answers to the brief's focus questions:**

- **Is the skip safe for the completeness proof? Yes.** A bill is skipped only when its `ccy` is blank, its
  `billId` passes `isdigit()`, and `bal_chg`, `pnl` and `fee` are all `== 0`. Bills that stop are counted
  first and raise before `_adjacent_runs`. Only then does the chaining loop's `if not row.ccy: continue` run.
  At that point every blank-ccy bill left is a skip candidate, and the per-run `unique` de-duplication and
  conflict check have already seen it. No `""` entry is created and `previous` is never set from a skipped
  bill. The chain proves each currency's `bal == prior.bal + balChg`. A bill with `balChg == 0` leaves its
  real currency's balance unchanged, so that currency's neighbours chain the same with or without it.
- **Can a skipped bill hide a real balance move? No.** A balance move with `balChg == 0` (a `bal` jump) still
  breaks the next bill of that currency, skipped or not. A blank-ccy bill with any nonzero `balChg`, `pnl` or
  `fee` still stops as `blank_ccy`. The proof was already blind to a missing zero-`balChg` bill of a named
  currency, so the skip does not weaken it. One residual effect, below the reporting threshold:
  `longest_billless_run` counts a day whose only bills were skipped as billed. Step 3's go/no-go rule rests on
  `ccys.<ccy>.first_day` / `last_day` and `gaps_before`, which skipped bills never extend, so the founder's
  head/tail judgment is unaffected.
- **Does the census still count the skipped bill? Yes.** `_census_of` runs `aggregate_archive` before
  `verify_bal_chain` over every row, and that function is unchanged. The bill lands in `by_ccy` `(blank)`,
  `by_inst_type`, `by_sub_type` and `row_count`, and is never summed: blank is outside `ARCHIVE_USD_FAMILY`,
  and zero effect keeps it out of `summed_ccys`. The fingerprint hashes `aggregate.census`. Within-file
  identical duplicates are dropped at parse, and the quarters' ts ranges are disjoint, so the per-file
  `skipped` tally equals the de-duplicated `(blank)` census on a clean run. The end-to-end test pins
  `by_ccy == {"(blank)": 2, "USDT": 11}` and `row_count` 13.
- **Do the `last_error` tokens carry amounts or ids? No.** `_unchainable_tokens` reads only fixed keys. A
  count must be a non-bool, non-negative `int` and a day must pass `_iso_day`; anything else reads
  `unreadable`. Tags come from `_quarter_tag` on the validated job input. No ccy label, `billId` or amount is
  read. `_bal_chain_info` passes counts and days through unvalidated, but the job computes every one of them
  (`row.day` is `_ms_to_day` on an int `ts`), as the plan accepts in T-56.
- **Runbook reading: correct.** `blank_ccy_skipped == census.by_ccy (blank)` on a clean calibrate holds. The
  pair arithmetic (sum of `row_count` − `blank_ccy_skipped` − one per currency) matches the end-to-end
  numbers: 13 − 2 − 1 = 10 = `total_pairs`.
- **Can the tests fail? Mostly yes, but not on the multi-file path** (WR-01). I re-ran the seven OKX files on
  a scratch copy at HEAD: `669 passed`. Three more neuters, none in the plan's N1–N13 list, all leave
  `669 passed`.

### WR-02: A zero-effect blank-ccy bill with a non-ASCII digit `billId` now crashes the chain with the `billId` in `last_error`. Before D-16 it stopped cleanly.

**File:** `analytics-service/services/okx_archive_classify.py:228` (`row_nondigit = not row.bill_id.isdigit()`),
`:145` (`_bill_order_key`), `:278` (the sort)

**Issue:** `str.isdigit()` is true for characters that `int()` rejects, such as the superscript `²`.
`_bill_order_key` calls `int(row.bill_id)` whenever `isdigit()` is true. At `bb83337db` a blank-ccy bill
always raised the named `unchainable_row` stop before the sort. Under D-16, a blank-ccy, zero-effect bill
whose `billId` passes `isdigit()` but not `int()` is classed as skippable. It reaches
`sorted(..., key=_bill_order_key)` and raises a bare `ValueError`. Probed on a scratch copy:
`_interleaved_q3(_blank("2005²", ...))` makes `verify_bal_chain` raise
`ValueError: invalid literal for int() with base 10: '2005²'`, with no `stop_class`.
`okx_archive_job.dispatch` does not catch it, so `job_worker`'s catch-all classifies it as
`("unknown", str(exc)[:500])`. The job is retried rather than stopped permanently, and the `billId` text from
the file is written to `last_error`. That breaks two rules this plan's own tests state in their docstrings:
"a stop must never turn into a crash", and the `last_error` never-file-text rule (T-167.1.2.2.2.1-52).

The same crash already existed at `bb83337db` for a non-blank bill with such a `billId`, so the root defect
predates D-16. D-16 widens it to a bill class that previously failed closed. OKX `billId`s are ASCII digits
in every observed file, so the likelihood is low. The fix is one predicate, and it closes both the old and
the new path.

**Fix:** Use an ASCII-decimal test wherever "all digits" is decided, so the tally, the skip and the sort key
agree with `int()`:
```python
def _is_bill_digits(bill_id: str) -> bool:
    return bill_id.isascii() and bill_id.isdigit()

def _bill_order_key(row: ArchiveRow) -> tuple[bool, int, str]:
    digits = _is_bill_digits(row.bill_id)
    return (not digits, int(row.bill_id) if digits else 0, row.bill_id)

# in verify_bal_chain's tally
row_nondigit = not _is_bill_digits(row.bill_id)
```
Add a parse test: a zero-effect blank-ccy bill with `billId` `"2005²"` stops `unchainable_row` with
`nondigit_bill_id=1`, and the same for a USDT bill. Show it RED on the current code, where it raises a
`ValueError`.
