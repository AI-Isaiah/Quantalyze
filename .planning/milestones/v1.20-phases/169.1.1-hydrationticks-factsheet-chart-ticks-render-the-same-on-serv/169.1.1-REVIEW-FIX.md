### WR-01: The placement pin false-passes when the step is neutralised inside its own `run:` line or by a non-literal `continue-on-error`

**Files modified:** `src/__tests__/e2e-seeded-hydration-guard.test.ts` (only this file; `ci.yml` and `CHANGELOG.md` are untouched)
**Commit:** 017fadb6e
**Applied fix:**
- **Exact command.** A new constant, `SELF_TEST_COMMAND`, holds the step's exact command: `npx playwright test e2e/hydration-guard.self-test.spec.ts --retries 0 --reporter=list`.
  - `selfTestPlacements` now flags a step unless one of its lines matches `^ {6}(?:- | {2})run:[ \t]+<SELF_TEST_COMMAND>[ \t]*$`. The command must be the whole value of a single-line `run:`, in either the `- run:` or the `  run:` form. Only surrounding spaces or tabs are allowed.
  - These all fail that match, which fails closed: a shell wrapper, an extra or missing flag, `|| true`, an echo, a block scalar, or a trailing `# comment`.
  - Each one reports `its step's run: is not exactly the self-test command on one line …`.
- **`continue-on-error`.** A `continue-on-error:` key of any value is now advisory, whether it sits on the step or on the job. The old regexes required the literal `true`.
- **Detection is unchanged.** The broad `invocation` regex still decides whether a step is a placement at all. So a disarmed step is reported as a flagged placement and does not disappear. If it did disappear, the only red would be the "is not run by any line" message, which points to the wrong cause.
- **Red cases on the real `ci.yml`.** All six of the reviewer's disarming edits are now `it.each` cases that mutate the real `ci.yml` text:
  - `|| true`
  - an expression-valued step `continue-on-error`
  - `--list`
  - `--grep NOMATCH --pass-with-no-tests`
  - an `if false; then …; fi` wrapper
  - `echo npx playwright test <spec> --retries 0`

  Each case asserts three things: the mutated text differs from the original, at least one placement is found, and the specific reason is reported.
- **Sentinel case.** One case asserts that the real `run:` line appears in `ci.yml` exactly once. If a future reflow of `ci.yml` turned `replace()` into a no-op, the six cases would otherwise test unchanged text and pass vacuously.
- **Synthetic cases.**
  - The green fixture `blockingStep`, and the step-level `continue-on-error` and `if:` cases, now use the exact command. So each case still isolates exactly one reason (`toEqual([reason])`), rather than being loosened to `toContain`.
  - New: the exact command passes in both the `- run:` form and with trailing whitespace.
  - New: a block scalar, the bare command without flags, and the command with an extra spec each report exactly `NOT_EXACT_RUN`.
  - New: a job-level `continue-on-error` is flagged whether its value is literal or an expression.
- **Test name.** The line-362 test is renamed to what it covers: *"…or its path is echoed without the command"*. A comment points to the real-`ci.yml` `echoed` case, which covers `echo npx playwright test <spec>`.
