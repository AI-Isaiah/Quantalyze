<objective>
The second half of layer 2 on the unforced path (the first half is plan 07; the two were one plan, split for the
per-plan context budget): prove the resumed read replays exactly as a single pass across claims and days, stop a read
that makes no progress by name with its progress kept, and make sure kept progress is physically removed once it
expires even when no claim ever touches the key again.

D-02 verbatim from CONTEXT: "The read position and what has been read are kept between runs so a book of any size
eventually completes; each run reads within the existing crawl bound and defers (`defer_compute_job`) instead of
refusing. Nothing is written to the allocator's history until the read is complete (ACCTREBUILD D-02). Persisted trade
data needs a migration with owner/service-role RLS and an expiry ..."

Claude's discretion from CONTEXT, decided here: "How a job that keeps making no progress is stopped by name (a stall
still refuses loud; a resumable read never loops forever)": the pessimistic stalled-claims count (plan 04) and the 24 h
job-age backstop at the defer point, both ending FAILED permanent with the windows kept; the forced side's closed token
is plan 10's.

Retention (revised after the plan check): the stall keeps windows, so an abandoned key's rows must not depend on a
further claim to be removed. The sweep runs from the worker's existing recurring path (`watchdog_loop`, the
`report_orphaned_capped_reconstructs` precedent of Phase 167.1.2.1), never from a database-scheduled job.

Purpose: SC-1. Output: the stall arm, the job-age check, the sweep, the oracle and stall tests.
