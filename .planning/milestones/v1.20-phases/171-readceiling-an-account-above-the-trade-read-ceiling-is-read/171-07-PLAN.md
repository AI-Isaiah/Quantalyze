## The resumable read contract (names are load-bearing: plans 08 to 10 build on them)

- `_fetch_bybit_trades` keeps its signature and its two-year guard first. Then: when `store.current_trade_read_scope()`
  returns a scope whose `api_key_id` AND `job_id` are both set, it returns `await _read_bybit_trades_resumable(exchange,
  since_ms, now_ms, scope)`; otherwise it runs plan 02's layer 1 unchanged.
- `_read_bybit_trades_resumable`: `state = await store.begin_claim(scope.supabase, scope.api_key_id, venue="bybit",
  since_ms=since_ms, job_id=scope.job_id)` (it may raise TradeReadStalled; plan 08 handles that). When `state` is None
  (plan 04: a store fault, already logged once by the store), return plan 02's layer-1 read of `[since_ms, now_ms]`
  with no budget, no store call and no extra log line: the job then ends exactly as it would have before the store
  existed (a book too big for the hard bound ends on the existing timeout arm, transient). The grid is `origin + k *
  _BYBIT_TRADE_WINDOW_MS` with `origin = state.grid_origin_ms`; each grid window is `[ws, ws + _BYBIT_TRADE_WINDOW_MS -
  1]`; only windows overlapping `[since_ms, now_ms]` are visited, oldest first. Per window:
  (1) stored and `load_window` returns rows: use them;
  (2) else it is STORABLE when `ws >= since_ms` and its grid end is before `now_ms - _STORE_SETTLE_MS` (one hour): if
  `store.deadline_passed(scope)`, raise `TradeReadDeferred(windows_done, windows_total, trades_stored)` (plan 08 puts the
  job-age check in front of this raise); otherwise read it with `_read_bybit_window` over `[ws, grid end]`, then
  `store.save_window(...)`, and on the first successful save of the claim `store.record_progress`; a save that returns
  False leaves the window unstored and its trades in this claim's output;
  (3) else (the window holding now, or a grid window starting before `since_ms`) read it live over
  `[max(ws, since_ms), min(grid end, now_ms)]`, never stored, never subject to the budget.
  Every window's trades go into the output as `store.unproject_trade(store.project_trade(t))`, in window order and read
  order, filtered to `timestamp >= since_ms`. When every window is covered, `store.record_progress` (completion is
  progress) and return. NotSupported keeps plan 02's meaning: an empty book only when nothing at all was read (a stored
  window counts as read); otherwise a typed truncation.
- Constants beside `_RECONSTRUCT_CRAWL_TIMEOUT_S`: `_TRADE_READ_CLAIM_BUDGET_S` from a pure
  `_validated_claim_budget(raw, hard_bound) -> float` called at import (raises ValueError unless 0 < budget < hard bound;
  the env-validated-at-import precedent), `_TRADE_READ_DEFER_S: Final[int] = 120`, `_STORE_SETTLE_MS: Final[int] =
  3_600_000`.
- Handler, unforced non-MT5 branch: build `TradeReadScope(supabase=ctx.supabase, api_key_id=str(api_key_id),
  deadline=store.claim_deadline(_TRADE_READ_CLAIM_BUDGET_S), job_id=<the job's id as str, or None>,
  job_created_at=job.get("created_at"))` immediately before the crawl, and enclose the existing `asyncio.wait_for(_crawl,
  ...)` in `with store.trade_read_scope(scope):`. The crawl call itself is unchanged (five positional arguments, PD-J).
- Handler arm, in the inner try, BEFORE `except Exception` (Pitfall 4): `except store.TradeReadDeferred as exc: return
  await _defer_reconstruct(ctx.supabase, job, exc, allocator_id, api_key_id, venue)`. (Plan 08 adds the
  `TradeReadStalled` arm beside it; plan 10 adds its forced side.)
- `_defer_reconstruct`: `defer_compute_job` through `db_execute` with `p_job_id`, `p_defer_seconds` =
  `_TRADE_READ_DEFER_S`, `p_reason` = a static class plus the three counts, `p_claim_token` = `job.get("claim_token")`;
  `asyncio.CancelledError` re-raised; `_defer_lost_ownership(exc)` (add it to the existing `from services.job_worker
  import (...)` list) -> DEFERRED; any other RPC failure re-raised (dispatch classifies it); one counts-only log line;
  no audit (no new audit action: `test_action_literal_matches_ts_union`).
- Purge on DONE: immediately before the handler's final `return DispatchResult(outcome=DispatchOutcome.DONE)`, `await
  store.purge_keys(ctx.supabase, <every key id of the rebuilt account when account is set, else the job key>)`
  (best-effort by construction). Not on the early already-reconstructed DONE.
