## Warnings

### WR-01: The fix turns the e2e "hydrated default" settle gate into a no-op in two blocking seeded specs, and the specs' comments now state something false

**Severity:** WARNING. **Confidence:** 8 that the fence is now vacuous; the flake rate is unmeasured.
**Files:**
- `e2e/full-flow.spec.ts:89-109`
- `e2e/discovery-hide-examples-default.spec.ts:159-206`
- cause: `src/components/strategy/StrategyTable.tsx:510-512`

**Issue:** Both specs run in CI's blocking `e2e-seeded` list (`.github/workflows/ci.yml`
`npx playwright test …` list: `discovery-hide-examples-default.spec.ts` and `full-flow.spec.ts`).
Both use `expect(hideExamplesCheckbox).toBeChecked()` as the deterministic proof that React
has hydrated. Only then do they press Space on the checkbox. The comments say so
explicitly:

- full-flow `:94-96`: "wait for the hydrated default first (checkbox checked …) … Toggling
  before that settle would race the mount effect again".
- discovery spec `:174-180` and `:203-205`: "StrategyTable renders with showExamples=true … on
  first paint, then the prefsHydrated effect … flips … checked=true once hydration commits.
  This is the deterministic settle signal".

Before this phase the box was unchecked in the SSR HTML and became checked only in a
post-hydration effect commit, so the gate proved hydration. Under D-06 the SSR HTML already
carries `checked=""`, which is the very fixture change this phase pinned. `toBeChecked()` now
passes on the server markup before any JS runs, and the gate proves nothing.

The next step is `focus()` + Space. If it lands before React hydrates the input, the native
default action flips the DOM `checked`, and `not.toBeChecked()` passes on the DOM alone. In
the bundled React (`next/dist/compiled/react-dom`, 19.3.0-canary), hydration's `initInput`
keeps `element.checked` as found when `isHydrating` (`react-dom-client.development.js:1885`)
and then calls `track(element)` with that already-flipped value. No `onChange` fires, so
`showExamples` stays `false` while the DOM box reads unchecked. The examples never appear:

- In full-flow, the seeded `crypto-sma` category holds only `is_example` rows (`:90`), so
  `firstLink` never becomes visible and the public-funnel test fails.
- In the discovery spec, the "seed names appear" poll fails.

This is the exact race class both specs document as a past CI flake. The phase removed its
fence without replacing it. The plan only noted that the e2e "runs in CI, not locally"
(`170.6.2-02-SUMMARY.md:87`). It never re-checked whether the spec's settle signal still
holds.

**Fix:** Give the specs a real post-hydration signal and correct the comments. For example,
expose an attribute that only a client effect sets, and wait on it before toggling:

```tsx
// StrategyTable.tsx — set once after the prefs-mirror effect has run
const [prefsApplied, setPrefsApplied] = useState(false);
useEffect(() => {
  if (!prefsHydrated) return;
  /* existing mirror … */
  setPrefsApplied(true);
}, [prefsHydrated]);
// on the table root:  data-prefs-applied={prefsApplied ? "true" : undefined}
```

```ts
// both specs, replacing the toBeChecked() settle gate
await expect(page.locator('[data-prefs-applied="true"]').first()).toBeVisible();
await expect(hideExamplesCheckbox).toBeChecked();
```

⚠️ The attribute changes the root markup, so `strategy-table-default-mounts.json` would need
a third dated surgical edit. If you would rather leave the markup alone, the alternative is a
wait-for-hydration helper the seeded lane already trusts. Either way, rewrite the stale
"renders with showExamples=true on first paint" comments in both specs. As written they tell
the next investigator the opposite of what the code does.
