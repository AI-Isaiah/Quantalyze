# 170.6.1.1 plan 03 (PR-A) - Silent-failure review

Scope: `git diff 1dd7fee0..HEAD -- . ':!.planning'`. Goal under review: every anonymous strategies reader projects a key-free list, so PR-B's revoke cannot become a silent empty page.

What is sound: the three projections are key-free and template-built; `getStrategyDetailV2`, `getStrategyDetail`, `getPercentiles`, `getPopulatedCategorySlugs` and `readPublicVerificationSignals` already split error from empty and report to Sentry. The live probe fails (not skips) when `HAS_LIVE_DB` is true and the anon key is absent, and its `strategiesSelectLiterals` arms fail on zero or multiple matches. The `?? null` on `api_key_id` at the two owner pages is type-only: both owner reads are `select("*")` on the authenticated session, so the value is present; no finding.

## Findings

### F1 - HIGH (confidence 9) - `getStrategiesByCategory` turns any query error into an empty ranked list, with no Sentry
`src/lib/queries.ts:397` (error arm just after the `withPublishedOnly(...)` select, ~line 421).
`if (error) { console.error(...); return []; }`. After the PR-B revoke, a missed wildcard, a column added to `STRATEGY_PUBLIC_COLUMNS_ARR` without a grant, or a column dropped from the grant answers 42501. `/browse/[slug]` then renders "no strategies" for every category. Only a console line is emitted (no `captureToSentry`, unlike every sibling reader), so nothing pages. This is exactly the failure the phase exists to prevent, and PR-A leaves the swallow in place.
Fix: capture to Sentry and either throw (so the route error boundary engages, as `getStrategyDetailV2` does for non-PGRST116) or return a distinguishable failed-read result the page renders as an error.

### F2 - HIGH (confidence 9) - `getPublicStrategyDetail` and `getFactsheetDetail` collapse 42501 / transport errors into `null` (404), unlogged
`src/lib/queries.ts:1281` and `src/lib/queries.ts:1336`: `if (error || !strategy) return null;`.
`.single()` signals "no row" as PGRST116; everything else (42501 after the revoke, 401 on a column-grant mismatch, timeout, 5xx) takes the same arm, with no log and no Sentry. Callers render not-found: `/strategy/[id]`, `/browse/[slug]/[id]`, `/factsheet/[id]/tearsheet` all 404, and `generateMetadata` (shared via `React.cache`) emits not-found metadata that third parties cache. The sibling `getStrategyDetailV2` (~line 1715, M-1159) and `getStrategyDetail` (~line 1478, F-07) already do the right split; these two were edited in this PR and were left on the old idiom.
Hidden errors: 42501, PGRST301 (JWT), 57014 timeout, network failure, a malformed projection (PGRST100/204).
Fix: copy the V2 idiom: `if (error && error.code !== "PGRST116") throw/captureToSentry`, then `if (!strategy) return null`.

### F3 - MEDIUM (confidence 8) - Landing page social-proof counts ignore every Supabase `error` and the `catch` is silent
`src/app/(marketing)/page.tsx:12-24` (the changed `select("id", { count: "exact", head: true })` line is inside it).
All three `Promise.all` results are destructured to `{ count }` / `{ data }` with `error` dropped, and `catch {` (line 23) logs nothing (supabase-js does not throw on query errors, so the catch is also nearly dead). After the revoke, any wildcard regression here makes `count = null` -> `strategies: 0`, `aum: 0` and the page shows "0 strategies / —" to the public with no signal. Probe arm (f) only protects against the specific `"*"` regression in source text.
Fix: read `error` on each result, `console.error` + `captureToSentry`, and either omit the stat tiles or surface an error state instead of a plausible zero.

### F4 - MEDIUM (confidence 6) - The static census can go stale silently on three axes
`src/lib/anon-strategies-projection.test.ts` (`ANON_ROUTE_DIRS`, `ANON_READERS`, `ANON_ROUTE_EXEMPTIONS`).
(a) `ANON_ROUTE_DIRS` is a hand-copied subset of `PUBLIC_ROUTES` in `src/proxy.ts:18`. Public prefixes absent from it: `/demo`, `/for-quants`, `/legal`, `/security`, `/contact`, `/api/demo`, `/api/for-quants-lead`, `/api/verify-strategy`, `/api/alert-digest`, `/api/benchmark/btc`, `/api/keys`, `/api/trades`. Nothing asserts that a new `PUBLIC_ROUTES` entry is added here, so a future anon strategies read under one is unscanned and reads as clean (the "> 20 files" guard only catches a wrong root).
(b) `ANON_READERS` is a closed list of three `queries.ts` functions. A new exported helper called from an anon page is not scanned. Concrete evidence of the blind spot: `getStrategyDetail` (`src/lib/queries.ts` ~line 1450) still uses `baseSelect = "*, ..."`; it is authenticated-only today (discovery page), so it is correctly out of scope, but nothing records that exclusion, so the day it gains an anon caller the pin stays green.
(c) Exemptions are keyed by file plus an exact hit count only. `v2/page.tsx` "hits: 1" (Lane B) would still pass if Lane B were deleted and an anon wildcard added elsewhere in the same file, and the stated reason (runs after `auth.getUser()` returned a user) is never checked.
Fix: derive `ANON_ROUTE_DIRS` from, or cross-check it against, `PUBLIC_ROUTES`; pin Lane B by its select literal/position rather than a bare count; list non-scanned authenticated `*` readers (`getStrategyDetail`, `getMyStrategies`) in a named allowlist with a reason so omission is a decision.

### F5 - MEDIUM (confidence 5) - `Strategy.api_key_id` made optional removes the compiler's only guard on owner-surface reads
`src/lib/types.ts:~159`.
Every consumer that truth-tests `strategy.api_key_id` (`strategies/page.tsx:550,851-852`, `edit/page.tsx:74,175`) now compiles against rows that may be a public projection and would silently read "no key" (offers key-connect UI, reports `hasApiKey=false`). Today those pages use `select("*")`, so it is latent, but the `?? null` additions at the two owner call sites make the absent case look intentional. Weak guard; a dedicated `PublicStrategy = Omit<Strategy, "api_key_id">` for the three public readers (keeping `Strategy.api_key_id` required) would keep the owner path type-checked.
