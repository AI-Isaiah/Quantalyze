## Verdict: no MEDIUM, HIGH or CRITICAL findings. Worst finding: none at MEDIUM or above.

## What was checked, and why each candidate did not become a finding

- Skip on missing env (probe). Every arm is `it.skipIf(!HAS_ANON_PROBE)`, but the closing test
  fails when `HAS_LIVE_DB` is true and the anon key is absent, so a lane with the service key and
  no anon key goes red instead of green-with-skips. The unit shards (no credentials) skip by
  design. beforeAll throws on any seed failure, so a failed seed cannot leave arms running with
  null ids.
- Caught error read as the expected 42501 (probe). The arms do not catch. They assert
  `error.code === "42501"` AND the message `permission denied for table strategies`; the write arms
  additionally reject `row-level security`, so an RLS refusal cannot stand in for the grant
  refusal, and a no-error result (RLS-filtered UPDATE/DELETE) fails `not.toBeNull()`.
- Wrong role (probe). The client is built from the anon key with no session. A service/authenticated
  key would make arm (a) read the column and go red, not green.
- Empty result as denial (probe). Arm (a) requires `data` null and an error; column privilege is
  checked at statement start whatever the row count, so zero visible rows cannot mimic a refusal.
- Exception handlers in the SQL gate (GRANT 4). Both handlers are `WHEN OTHERS` but record only
  state, SQLSTATE and SQLERRM; the assertions run after `RESET ROLE`. The key read must be exactly
  42501 with a message naming `strategies`, so 42703, schema-level denial (message names `public`),
  a missing role or any other SQLSTATE fails with the actual SQLSTATE printed. The second read
  (id, name, status) flags any error at all. An unhandled `SET LOCAL ROLE anon` failure aborts the
  file loudly.
- Vacuity of the catalogue arms. GRANT 3 refuses an empty column set (3-SETUP); no
  skip-when-unapplied branch; GRANT 1/2/4 and WRITE 1/2 use `has_*_privilege`, which counts PUBLIC
  grants and inheritance, and `has_column_privilege` raises on a missing column rather than
  returning false. KEEP 1 reads the same functions for the retained roles.
- Migration self-check. REVOKE and GRANT sit in one DO block with the proof, so a silent grantor
  mismatch aborts the apply. The column list is derived from pg_attribute, with a NULL guard.
  No data is read, so an empty TEST cannot refuse.
