## Fixed

### WR-01 / SFH-1: `getStrategiesByCategory` returned `[]` on any error

**File:** `src/lib/queries.ts`
**Commit:** abafdb13c
**Fix:** the error arm now calls a module-private `failAnonRead(op, subject, error)`: `console.error`, `captureToSentry` with tags `{ op, code }` at level `error`, then THROWS `getStrategiesByCategory(<slug>) failed: <message>`. It no longer returns `[]`. Convention chosen after reading the sibling and the pages: `getPopulatedCategorySlugs` captures and degrades to `[]`, but there `[]` makes `/browse` show ALL categories (a safe fallback). Here `[]` renders "no strategies", which is the fake empty state the brief rules out, so the throw matches `getStrategyDetailV2` instead. `/browse/[slug]` falls to the root `error.tsx`; the authenticated `/discovery/[slug]` caller falls to its dashboard boundary.

### WR-01 / SFH-2: `getPublicStrategyDetail` and `getFactsheetDetail` collapsed every error into `null`

**File:** `src/lib/queries.ts`
**Commit:** abafdb13c
**Fix:** `if (error || !strategy) return null` became `if (error && error.code !== "PGRST116") failAnonRead(...)` followed by `if (!strategy) return null`. A genuine no-row (PGRST116) is still a quiet null and so still a 404. Every other error is captured and thrown, so `/strategy/[id]` (including `generateMetadata`, which shares the `React.cache` alias), `/browse/[slug]/[strategyId]` and `/factsheet/[id]/tearsheet` engage their error boundary instead of emitting not-found metadata that third parties cache. Column list, static pin scope and types untouched.

### SFH-3: landing `getSocialProofStats` ignored `error` on all three queries

**File:** `src/app/(marketing)/page.tsx`
**Commit:** d99279b8c
**Fix:** each result's `error` is read. An errored stat is logged, captured (`{ op: "getSocialProofStats", stat, code }`) and returned as `null`; a thrown read is captured once (`stat: "all"`) and returns all `null`. `null` renders as the page's existing dash (`formatAum` gained a `null` arm; the two `> 0` count checks became truthiness checks). The page keeps rendering. The three query expressions are unchanged, so the static census pin and live probe arm (f) still match them.
**Known limit:** the page already printed a dash for a genuine 0, so the rendered output of `null` and `0` is identical. The `null` is a semantic honesty fix in the data shape (an errored stat is no longer indistinguishable from a counted zero); the user-visible gain is the Sentry signal. Neuter N5 below shows this and is expected to stay GREEN.
