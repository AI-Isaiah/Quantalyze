<objective>
Make the single-key connect step wait honestly: a card after 300 ms, an escalation ladder, a
`Stop waiting` that costs nothing, and a stated verdict when the budget is spent (D-05).

Purpose: `ConnectKeyStep.tsx:782` renders a disabled button reading `Validating...` and nothing
else. Against the 120 000 ms serialized budget this plan's predecessors granted, that is a
two-minute silent spinner — which D-05 names as a worse product than a fast wrong answer.

Output: an abortable validate with a mounted card, a neutral cancelled state, and a client-side
deadline that turns the minted `SEAM_DEADLINE_EXCEEDED` copy into a reachable state.
</objective>

  <action>
    **State.** Add: `waitStartedAt: number | null`, `elapsedMs: number`, `cancelled: boolean`, and
    two refs — `abortRef: AbortController | null` and `abortReasonRef: "user" | "deadline" | null`.
    Do not thread anything through `WizardClient`; this state is local to the step.

    **On submit.** Alongside the existing resets, clear `cancelled`, stamp `waitStartedAt` from
    `Date.now()`, zero `elapsedMs`, create an `AbortController`, store it in `abortRef`, clear
    `abortReasonRef`, and pass `signal: controller.signal` in the `wizardFetch` init. `wizardFetch`
    spreads `init`, so no change is needed there.

    **The tick.** One `useEffect` keyed on `waitStartedAt`: while it is non-null, set `elapsedMs`
    every 1 000 ms from `Date.now() - waitStartedAt`. Clear the interval on unmount and when
    `waitStartedAt` returns to null. ⛔ Do not tick faster than 1 s — the counter is whole seconds
    and a faster tick buys nothing but renders.

    **The mount gate.** The card renders only when `submitting && elapsedMs >= 0 && waitStartedAt !==
    null && Date.now() - waitStartedAt >= WAIT_CARD_MOUNT_DELAY_MS`. Implement it as a boolean state
    flipped by a `setTimeout(WAIT_CARD_MOUNT_DELAY_MS)` armed in the same effect, so a sub-300 ms
    answer never flashes a card. Clear the timeout on completion and on unmount.

    **The client deadline backstop.** In the same effect, arm a
    `setTimeout(validateBudgetMsFor(exchange) + WAIT_ABORT_GRACE_MS)`. On fire: set
    `abortReasonRef.current = "deadline"` and `abortRef.current?.abort()`.
    WHY the grace exists — write it in a comment: the 120 000 ms deadline is the SEAM's, enforced
    inside our own route; the browser→route hop is not free, so aborting at exactly the budget could
    cut off a verdict already on the wire. The grace makes the browser the LAST thing to give up,
    never the first. The advertised figure in copy stays the budget (what we grant the broker), not
    the grace.

    **The catch arm.** `AbortError` is not a transport failure and must not be classified as one.
    Branch FIRST on `abortRef.current?.signal.aborted`:
    - `abortReasonRef.current === "user"` → set `cancelled: true`, leave `errorCode` null, ⛔ do not
      `console.error`, ⛔ do not fire a `wizard_error` funnel event (the user chose this; recording
      it as an error would tell an operator the seam is failing when it is not).
    - `abortReasonRef.current === "deadline"` → `setErrorCode("SEAM_DEADLINE_EXCEEDED")` and fire
      the `wizard_error` funnel event with that code (a real failure, and the funnel must agree with
      the screen — the 140.5-03 rule).
    - otherwise → the existing `SERVICE_UNREACHABLE` path, byte-unchanged.
    Always clear `waitStartedAt`, the card gate and `setSubmitting(false)` in a path that runs on
    every outcome.

    **The envelope context.** Extend the `buildEnvelope` call at `:608-614` with
    `budgetSeconds: errorCode === "SEAM_DEADLINE_EXCEEDED" ? validateBudgetSecondsFor(exchange) :
    undefined`. ⚠️ `undefined`, not `null` and not `0` — 140.3-10's rule, inherited: ABSENCE IS NOT
    ZERO, and a `0` there is a budget we never granted (TRAP-3).

    **Render.** Above the submit row (and above `footerSlot`), render:
    - `{showWaitCard && <ValidateWaitCard exchange={exchange} elapsedMs={elapsedMs}
      onStopWaiting={handleStopWaiting} />}`
    - `{cancelled && !submitting && <p className="text-caption text-text-secondary">We stopped
      waiting. Nothing was saved and your key details are still on this page.</p>}` — ⛔ not an
      `ErrorEnvelope`, ⛔ not `text-negative`. Clear `cancelled` the moment the user edits any field
      or resubmits, so a stale line cannot sit under a fresh attempt (the same discipline the
      140.5-03 comment applies to `retryAfterSeconds`).
    - `aria-busy={submitting ? "true" : undefined}` on the `<form>`.

    **`handleStopWaiting`.** Set `abortReasonRef.current = "user"`, call `abortRef.current?.abort()`,
    and move focus to the submit button (add a ref to it). ⛔ No confirmation dialog: `validate-key`
    is strictly pre-encrypt / pre-RPC and nothing is persisted server-side.

    **Do NOT change:** the submit button's label (`Validating...`, ASCII — D-21) or its mounted
    state while in flight; `KNOWN_CREATE_WITH_KEY_CODES`; the `!res.ok` translate-then-membership
    arm; the TRAP-1 comment block in the catch (re-check its claim still holds now that a `signal`
    is passed — an `AbortError` carries no credential either; say so in one added sentence rather
    than rewriting the block).
