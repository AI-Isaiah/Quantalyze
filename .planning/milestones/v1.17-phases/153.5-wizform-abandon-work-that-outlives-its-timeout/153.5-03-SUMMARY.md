## Decisions Made

- **The bump no-op targets `services.mt5_concurrency.bump_mt5_terminal_epoch`, not `services.mt5_client.…` as the plan's text specified.** `mt5_concurrency` does `from services.mt5_client import bump_mt5_terminal_epoch` at module scope, so the lease's `finally` resolves the name from `mt5_concurrency`'s own globals. Measured rather than reasoned about: an isolated one-hold lease shows an epoch delta of `1` unpatched, `1` with `services.mt5_client.bump_mt5_terminal_epoch` patched (a silent no-op), and `0` with `services.mt5_concurrency.bump_mt5_terminal_epoch` patched. The plan's own subject is this trap, so following its letter here would have been the defect.
- **The minimal neuter-arm re-point shipped in Task 1's commit** rather than Task 2's, even though the plan assigns test files to Task 2. Task 1's verify block requires both worker suites green, and the conversion breaks that control by construction. Splitting it would have committed a knowingly-red test. Task 2 kept every genuinely new behavior.
- **`_mt5_terminal_lock_for` stays imported in both modules** despite nothing reading it any more. Removing it would red `test_registry_object_is_shared_across_modules` and `test_mt5_holdings_branch_shares_the_one_terminal_lock_registry`, which assert the ONE-registry invariant through those bindings.
- **The `mt5_concurrency.py` exemption in the ast pin is belt-and-braces, and says so.** The lease reaches the registry as a plain call, not an async-with, so it would not be reported anyway; the exemption is written down so a future refactor of the lease into an async-with cannot silently inherit an exemption it was never granted.
