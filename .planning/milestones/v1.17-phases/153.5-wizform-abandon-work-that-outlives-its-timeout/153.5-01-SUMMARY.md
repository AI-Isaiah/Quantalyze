# Phase 153.5 Plan 01: The abandoned-session fence at the sink Summary

**A `terminal_key`-keyed generation counter in `mt5_client.py` that `mt5_terminal_lease` bumps on every release path, plus a lazily-binding `_assert_live` fence on six session-touching methods and a lease-occupancy ContextVar for plan 02's construction fence — so a `to_thread` zombie that outlived its `wait_for` is refused loudly instead of driving the next holder's MT5 terminal.**

## Accomplishments

- **The sink exists.** `_MT5_TERMINAL_EPOCHS` / `_mt5_epoch_for` / `bump_mt5_terminal_epoch` live in `services/mt5_client.py` — the leaf — because the import edge to `mt5_concurrency` is strictly one-way and `mt5_terminal_lease(terminal_key: str, ...)` structurally cannot bump an instance attribute.
- **The fence is armed on exactly six methods** (`login`, `account_info`, `terminal_info`, `history_deals_get`, `order_check`, `_raise_last`), each ahead of `_guarded_read` and `_timed` so a refusal can neither be rewritten into a scrubbed `Mt5ClientError` nor pollute the D-32 `duration_ms` population. `restart`, `__init__`, `close`, `release` and `_teardown_transport` carry none.
- **The lease drives it** on every exit path — normal return, raising body, cancelled holder — and on none of the failed ones: a timed-out acquisition raises above the `try` and therefore bumps nothing and stamps nothing.
- **The construction half is staged** for plan 02: `_MT5_LEASE_OCCUPANCY`, `begin_mt5_lease_occupancy`, `end_mt5_lease_occupancy`, with the frozen-`Context` property `to_thread` rests on re-verified in-repo rather than trusted from a research note.
- **Nine falsifications observed**, not predicted (table below).
- One shared `reset_terminal_state_for_tests()` now serves all five previously hand-rolled fixtures.

## Decisions Made

- **`begin_mt5_lease_occupancy` is called once, after the acquisition `if/else`, not once per arm.** The plan's wording said "both arms". The single call is reached only when one of the two arms succeeded (the bounded arm's expiry raises rather than falling through), so it is behaviourally identical and cannot drift between two copies. Documented at the call site.
- **The refusal message wording** is `"MT5 session abandoned: the lease under which it operated has ended"` (Claude's Discretion per CONTEXT). Verified disjoint from both live token tables for all eight stage names.
- **`_reset_mt5_epochs_for_tests()` was added as a sibling in `mt5_client`** and called by `mt5_concurrency.reset_terminal_state_for_tests()`, rather than reaching into the dict through the module object — the plan explicitly allowed either.
- **`test_mt5_derive_branch.py`'s fixture was re-pointed via `mt5_conc`, not `jw`.** `jw._MT5_TERMINAL_LOCKS` is the same dict object, so nothing is lost — and the epoch registry is deliberately not re-exported into `jw`, so no `jw` name could reach it.
