# Phase 153.3 Plan 01: MT5 gateway honesty — close the read-only fail-open Summary

**One-liner:** `is_trade_capable`'s two-negative investor rule is deleted and replaced by a
tri-state `classify_trade_capability` gated on a new `Mt5Client.terminal_info()` read, so a
MASTER password presented under MetaQuotes' default-ON *"Disable automatic trading through the
external Python API"* is now REFUSED on both the router and the adapter path instead of being
persisted stamped `read_only: true`.

## Deviations from Plan

**1. [Plan-directed] Tasks 2 and 3 landed in ONE commit (`fd20052f`).**
- **Reason:** the plan's own `must_haves.artifacts` requires `services/ingestion/mt5.py` to be
  "the SECOND call site, fixed **in the same commit as the seam**", and Task 2 deletes
  `is_trade_capable` — which makes both call sites a hard `ImportError` until Task 3 lands. A
  separate Task-2 commit would have been a knowingly broken tree. Each task's acceptance criteria
  were still run and evidenced independently (above).

**2. [Rule 2 — missing critical functionality] Added `terminal_trade_permission_off()` to the seam.**
- **Found during:** Task 3, wiring the `undetermined` cause split.
- **Issue:** the plan says to distinguish the two `undetermined` arms by re-reading the same
  `terminal` dict. That test is four conditions (is-a-mapping, has `trade_allowed`, `connected`
  truthy, `trade_allowed` falsy), and copying it into both call sites is exactly the drift this
  plan exists to delete — a copy that silently diverged would route a network blip to the
  permanent operator arm (paging a human for something a retry fixes) or vice versa.
- **Fix:** one predicate at the seam (`mt5_validation.py:230-253`), consumed by both sites.
  `classify_trade_capability` remains the named artifact and is unchanged in signature.

**3. [Rule 1 — bug] `terminal_info()` errors must not reach `classify_mt5_login_error`.**
- **Found during:** Task 3, reasoning about where a raising `terminal_info()` lands.
- **Issue:** left inside `_probe`, an `Mt5ClientError` from `terminal_info()` would fall into the
  existing `except Mt5ClientError` arm, and `_WRONG_SERVER_TOKENS` contains `"terminal"`, `"ipc"`
  and `"connect"` — so a gateway-side terminal failure would answer `MT5_WRONG_SERVER_DETAIL` and
  tell the user their **broker server** is wrong. That is a user-blame mis-attribution the plan's
  fail-closed posture forbids.
- **Fix:** the terminal read is wrapped at its own call site (`_read_terminal`) on both paths and
  degraded to "no signal" → `undetermined` → the transient arm.
  `test_mt5_unreadable_terminal_is_transient_never_readonly` asserts the detail is
  `NETWORK_ERROR_DETAIL` and explicitly `!= MT5_WRONG_SERVER_DETAIL`. On the adapter,
  `test_validate_unreadable_terminal_propagates_transient_never_readonly` asserts
  `classify_mt5_login_error(exc) == "transient"`, which is why the propagated message deliberately
  avoids every token in that table.

**4. [Rule 3 — blocking] `tests/test_raw_5xx_census.py` pin 7 → 8.**
- **Found during:** the full-suite run.
- **Issue:** the census pins the number of in-tree `HTTPException`-subclass construction sites; the
  new (existing-arm) `VenueTransientHTTPException(424)` refusal makes it 8.
- **Fix:** constant updated **with the reason recorded at the constant** — it reuses an existing
  arm, mints no new code, and is a 4xx, so blind spot (b) stays latent rather than live.

**5. [Cosmetic, own-mess cleanup] `8591f5de` reflows the Task-1 docstring bullet.**
- Task 1's edit orphaned "Read-only is a" on its own line and shifted every anchor below it by one
  line. The follow-up commit reflows the paragraph to its **original line count**, so
  `MT5_REQUEST_TIMEOUT_S` is back at `:82`, the ordering guard at `:213-219` and `initialize()` at
  `:306` — all cited verbatim by the 153.3-02/03 plans — are line-stable. Verified by diffing those
  line numbers against the pre-153.3 file.

## What stays UNVERIFIABLE offline — owner Phase 155 (MT5-VERIFY)

CI never installs `mt5linux`; everything above runs through the injected `_connect` /
`Mt5Client` doubles. Three claims are therefore **unproven against a real terminal**:

1. **Whether a real `terminal_info()` actually reports `trade_allowed: False` while "Disable
   automatic trading through the external Python API" is on.** The MetaQuotes docs describe the
   option and the terminal AutoTrading flag; that the flag reflects the option is [DOC]-implied,
   not [DOC]-explicit. If it does NOT, this plan refuses nothing extra but also proves nothing
   extra — the rule would still be strictly safer than the deleted one, but the security claim
   would be unearned.
2. **Which retcode a real investor session yields.** `10017` is the documented value and is now
   the fixture, but it is `[ASSUMED]` until observed live.
3. **The rule-6 residual** — an `order_check` rejected for an unrelated reason (e.g. no `EURUSD`
   at that broker) is still classified `read_only`. Resolving it needs a live master AND investor
   login on a real broker.

All three are recorded at the code that depends on them (`mt5_validation.py:47-61`) and belong to
**Phase 155**, which is already live-gated.
