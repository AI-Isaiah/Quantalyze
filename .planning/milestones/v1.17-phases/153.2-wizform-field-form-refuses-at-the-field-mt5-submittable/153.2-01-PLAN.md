<objective>
Close the defect that cost the founder three submits: the 10–5000 character description bound
refuses **at the field**, and the dead submit button that hid *which* field was wrong is deleted
together with the guard widening that keeps it honest.

Purpose: **WIZFORM-01 / D-11** — the client already knows the rule, so it must refuse at the field.
Today `MetadataStep` checks `!description.trim()` in three places
(the error derivation `:214`, the `handleSubmit` early return `:230`, the `disabled` gate `:491`)
and the server checks `10 ≤ len ≤ 5000`. A 2-character description satisfies every client check,
POSTs, and dies at submit as a full-page envelope that names no field — which is what sent the
founder to change the supported-exchanges chips (D-13).

Output: one client mirror of the server rule, read from `MAGNITUDE_CAPS`, driving both the inline
message and the submit predicate; no `disabled` for a validation reason; the weak focus ring at
`:334` upgraded in the same edit.

`MAGNITUDE_CAPS.MIN_DESCRIPTION_CHARS` (153.1-02) and the
`METADATA_DESCRIPTION_TOO_SHORT` / `METADATA_DESCRIPTION_TOO_LONG` copy members (153.1-04). This
plan **consumes** them and must not re-create either. If `MIN_DESCRIPTION_CHARS` is absent from
`src/lib/closed-sets.ts`, STOP and report the missing dependency — do not type `10`.

⛔ Scope fence: this plan touches the DESCRIPTION field and the submit predicate only. Category,
AUM and capacity mirrors plus the submit-with-errors focus orchestration are 153.2-02. The
supported-exchanges chips are 153.2-04. Do not touch the budget row,
