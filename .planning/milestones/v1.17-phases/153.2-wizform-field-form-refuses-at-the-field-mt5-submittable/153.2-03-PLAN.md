<objective>
Hold Phase 150's allocation-amount form to the same bar this sub-phase sets for the wizard
(**D-12**, at **D-13**'s behavioural bar — a prettier-but-still-ambiguous error does not pass):
the red border **derives from ARIA** instead of a JS ternary, and an amount the user has already
fixed stops reading red the moment it becomes valid.

Purpose: `AllocateDialog` is the BEHAVIOURAL precedent this whole surface copies — client mirror,
inline refusal, focus the field, never disable the CTA. But it is not the STYLING precedent
(UI-SPEC FLAG-1): `:354-357` colours the border with `fieldError ? "border-negative" :
"border-border"`. It is correct today only because `fieldError` happens to also feed `Field`'s
`error` prop — so the invariant "a red control without `aria-invalid` is structurally impossible"
is not yet true here. And `fieldError` is set on save and cleared only on the NEXT save, so a
corrected amount keeps its red until the user clicks again.

Output: one class-string change, one live re-evaluation, and the two test rows that can tell the
difference.

⚠️ **The two files swap fixes in opposite directions.** This file already carries the CORRECT focus
ring (`focus-visible:ring-inset focus-visible:ring-accent`, no alpha) that `MetadataStep.tsx:334`
lacks; `MetadataStep` already carries the CORRECT aria-derived border that this file lacks. Copy
the border mechanism FROM `MetadataStep` TO here; 153.2-01 copies the ring FROM here TO there.
⛔ Do not "fix" `ui/Button.tsx:35` or `ui/Modal.tsx:33` — `AllocateDialog.test.tsx:523-555` exempts
them BY IDENTITY and asserts they still carry `focus-visible:ring-accent/50`.
