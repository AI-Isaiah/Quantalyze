### ⭐ The cross-check earned its keep — it found a real matcher bug

The first run disagreed on `error_contract.py`: **TS said 3 sites, `ast` said 2.**

The extra was `class VenueTransientHTTPException(HTTPException):` — a **class-definition head**
being read as a call. `ast` reports no `Call` node there. The research's 9-false-positive census
enumerated `def` sites but could not have enumerated `class`, because that census was run over the
three `service_error*` **function** names, where `class` can never precede. Adding a **class**
callee added a hazard class with it.

Two properties of this bug are worth recording, because they are the reason the cross-check was
made mandatory rather than advisory:

1. **It was silent.** The site yields no code literal, so it landed in `dynamicishByFile` and read
   as an honest dynamic emitter. No assertion in the file would have named it.
2. **It would have frozen into a pin in the same commit.** The exclusion count pin was about to be
   written as 3 — after which the two derivations' disagreement would have read as *agreement*.

Fixed by widening the guard to `/\b(?:def|class)\s+$/`, with a SELF-TEST asserting the class head
yields nothing. After the fix the derivations agree exactly on every number above.

## Decisions Made

- **The `class` guard.** See the reconciliation report — a measured bug fix, not a preference.
- **`stringMask` is a real expression-position check.** RESEARCH offered a cheaper route: rely on
  the `error_contract.py` + `tests/` exclusions, which happen to remove all six in-tree in-string
  cases. Rejected. That would make the guard correct by coincidence, and the next root widening
  would re-open the class silently. The SELF-TEST deliberately fixes the *mask*, not the exclusion,
  as the thing being relied on, and says so in its comment.
- **The code argument must be the WHOLE argument.** `service_error(500, "REAL_CODE",
  detail="not a DECOY_CODE here")` yields one code, not two. A substring reader would mint fiction
  out of prose — which is the failure this whole milestone is about.
- **Ends RED, committed RED.** Constraint 7 of the plan, and the reason the phase is three plans.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] The widened root reads ~7,600 third-party `.py` files under `.venv`**

- **Found during:** Task 1 (before any edit — measured while inspecting the tree).
- **Issue:** The plan names exactly two exclusions (`tests`, `services/error_contract.py`).
  `analytics-service/` contains **8,010** `.py` files, of which ~7,660 live in the gitignored
  `.venv`, plus `.mypy_cache` / `.pytest_cache` / `.ruff_cache`. RESEARCH's own AST scan excluded
  `.venv` and the plan inherited that silently. Without an exclusion the walk reads the entire
  virtualenv, and — worse than slow — **the derived population becomes machine-dependent**: green
  on CI (no venv) and red on any developer machine that has run `pip install`. A hand-typed roster
  cannot survive that.
- **Fix:** A third `SCAN_EXCLUSIONS` entry with the same discipline as the other two — a >80-char
  reason, and a hand-typed `LOCAL_ARTEFACT_DIRS` name list rather than a `startsWith(".")` rule, so
  a NEW artefact directory is **scanned** and reds the roster instead of vanishing. Its count pin is
  explicitly `null`, because the count is machine-dependent *by construction* — which is itself the
  reason for the exclusion, and is stated in the reason rather than hidden. The `null` case is
  asserted (half-pinned entries red).
- **Files modified:** `src/lib/seam-venue-vocabulary.invariant.test.ts`
- **Verification:** Scan completes in ~0.5 s; derived population identical on a machine with and
  without `.venv` populated.
- **Committed in:** `8116af4f`

**2. [Rule 1 — Bug] The call matcher read a `class` definition head as a call**

- **Found during:** Task 2, by the mandatory AST cross-check (3 vs 2 on `error_contract.py`).
- **Issue:** `class VenueTransientHTTPException(HTTPException):` matched the callee needle. The
  `def` guard did not cover it. Silent: the site yields no literal, so it presented as a legitimate
  dynamic emitter.
- **Fix:** Guard widened to `/\b(?:def|class)\s+$/`, plus a SELF-TEST asserting the class head
  yields nothing, with a comment recording that the case came from the cross-check and not from the
  research census.
- **Files modified:** `src/lib/seam-venue-vocabulary.invariant.test.ts`
- **Verification:** The two derivations now agree exactly on all four metrics and on the per-file
  table.
