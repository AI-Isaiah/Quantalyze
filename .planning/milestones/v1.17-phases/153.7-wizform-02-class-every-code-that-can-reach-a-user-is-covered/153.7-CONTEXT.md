# Phase 153.7: WIZFORM-02-CLASS — every code that can reach a user is covered - Context

**Gathered:** 2026-08-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Close the **class** behind WIZFORM-02 — the one requirement the Phase 153 span failed
(`153-VERIFICATION.md`, status `failed`, 5/6).

A server-classified failure currently reaches the user as `code: UNKNOWN`. The derived-roster
coverage law that was supposed to prevent this **works**, but its *reach* is wrong: its population
is scoped by directory and by syntactic shape rather than by "can this code reach a user".

This phase widens the population to every user-reachable code, and — the headline fix — makes a
code that is missing from **both halves** of the coverage law a **CI failure by name** instead of
a silent gap.

**IN:** the two scanner widenings (root + shape), the pinned-table re-cut, the both-halves
coverage assertion, the falsifiability proof, dispositions for the two known mt5-gateway codes,
the three code-less `finalize-wizard` rejections, and the `create-with-key` terminal arm that
discards the honest machine code.

**OUT:** WIZFORM-05 / the validate budget (explicitly — see decisions). Re-verifying 153.6.
Adding the two known codes as rows *without* the mechanism.

</domain>

<decisions>
## Implementation Decisions

### Boundary (LOCKED — the crux; reverse only with founder sign-off)
- The coverage law's boundary is **"every code that can reach a user-facing surface"**, NOT
  "codes emitted in a particular directory in a particular syntactic shape".
- Rationale, recorded: the present boundary is an artifact of *how the scanners were written*, not
  of any product rule. No one decided a 500 from `routers/` deserves less honesty than a 400 from a
  Next route, and the user cannot tell the difference. Both scanners already prove the mechanism
  works; only their reach is wrong.

### Scanner reach — root AND shape, but NOT for the reason first written
⭐ **CORRECTED 2026-08-14 by `153.7-RESEARCH.md` (measured).** The original framing — "two
independent misses, either sufficient alone" — describes why one *file* is invisible. It does NOT
describe where the population comes from. Measured:
- Widening the root to `analytics-service/**` discovers **ZERO new codes** (30 assignment sites,
  the same 17 codes; both new sites — `routers/cron.py:238`, `routers/process_key.py:833` — are
  literal-less forwards).
- **All 20 new codes come from the SHAPE widening.**
- Both changes are still required: the shape scan must be rooted somewhere that contains
  `routers/` and `main.py`. But a plan must not expect the root change to move the count.

Concretely:
- Widen the Python scanner root from `analytics-service/services/**` to `analytics-service/**`
  (`seam-venue-vocabulary.invariant.test.ts`, `SERVICES_ROOT`).
- Teach it the **positional** shape `service_error(<status>, "<CODE>", …)` in addition to
  `error_code = "<CODE>"` assignments (`ASSIGNMENT_RE`).

### The both-halves assertion — ⛔ ALREADY EXISTS. DO NOT REBUILD IT.
⭐ **CORRECTED 2026-08-14 by `153.7-RESEARCH.md`.** The PRD called this "the headline fix". It is
not: `seam-venue-vocabulary.invariant.test.ts:222-240` **already** filters exactly
`!VENUE_WIRE_CODE_TO_VERDICT.has(code) && !VENUE_WIRE_CODES_WITHOUT_VERDICT.has(code)` and asserts
`[]`, by name. The assertion is correct today.
- **The entire defect is the `derived` set that assertion runs over.**
- ⛔ A plan that writes a NEW both-halves assertion has shipped a **duplicate that passes for the
  same reason the original does** — and it will read as progress in the diff. Do not do this.
- The work is to widen `derived`, not to add an assertion.

### Pinned tables
- Re-cut the 153.1 `EXPECTED_TABLE_SIZE` family. **Never delete them.** The re-cut is the
  deliberate act that records the widening.

### Dispositions — ⭐ TWENTY codes, not two
⭐ **CORRECTED 2026-08-14 by `153.7-RESEARCH.md` (measured).** Widened population = **37 codes**
(17 → 37). **20 are new and all 20 are currently undisposed in BOTH halves.** The scope is the 20,
not the 2 the PRD named. It splits cleanly and the split is what keeps it out of "blanket sweep"
territory:
- **8 codes reach `classifyKeyValidationError`** → a **verdict row is REQUIRED**. For these, "no
  verdict" IS the defect. All 8 probed through the real classifier answer
  `{ code: "UNKNOWN", status: 500 }` today. This is the live user-facing harm — 8, not 2. It
  includes the 424 `EXCHANGE_PROBE_FAILED`, which is **venue-agnostic and ordinary**, so the harm
  is not MT5-specific.
- **12 codes reach a different classifier** → a `WITHOUT_VERDICT` row is the **correct** answer.
  ⚠️ These are twelve **individually measured** facts, each with its own reason. That is NOT the
  forbidden blanket sweep — but writing them without individual reasons WOULD be.

The two originally-named codes remain in scope, with corrected anchors:
- `MT5_GATEWAY_UNCONFIGURED` — permanent, operator-directed, not retryable.
- `MT5_GATEWAY_UNREACHABLE` — transient, retryable. ⚠️ **TWO emitters (`:537`, `:629`), not one.**
- ⚠️ The mt5-gateway family is **SIX** emitters, not five. `resilient-fetch.ts`'s own census already
  recorded `(×2)` correctly — the phase docs were the stale record, not the code.

### Also in scope (from the verification's `missing` list)
- Three code-less `finalize-wizard` rejections (D-153.2-D: 500 draft-load, 500 finalize-RPC,
  502 upstream-shape) each need a copy member; `KNOWN_CODELESS_FINALIZE_REJECTIONS = 3`
  (`wizardErrors.invariant.test.ts:516`) moves accordingly.
- `src/app/api/strategies/create-with-key/route.ts` — ⭐ **ANCHOR CORRECTED 2026-08-14 by
  `153.7-PATTERNS.md` (symbol wins over line hint):** the terminal arm is `classifyKeyValidationError`
  at **:1145**, the UNKNOWN Sentry at **:1169**, the wire body at **:1186**. The `:1057` / `:1094`
  hints written earlier were WRONG — `:1057` is the RPC-contract arm and `:1094` is a non-blocking
  `console.warn`. The terminal arm discards the honest machine
  code: `classifyKeyValidationError(err)` reads `err.seamCode` only through
  `VENUE_WIRE_CODE_TO_VERDICT`, falls through to a substring cascade over the human sentence, and
  answers `{ code: "UNKNOWN", status: 500 }`.
- ⭐ **CORRECTED 2026-08-14: the twin is `composite/add-key`, NOT `finalize-wizard`.**
  `finalize-wizard` never calls `classifyKeyValidationError`. Because the loss happens inside
  shared `wizardErrors.ts`, a **verdict row fixes both key routes at once** — but a route-local
  fix at `create-with-key` alone would be the twin-path defect in its purest form, which is this
  milestone's single most repeated mistake. Fix it in the shared table; regression-test both routes.

### Falsifiability (the phase's own gate)
- Add a new `service_error(...)` code in `routers/` with no verdict row and prove the gate **reds**.
- ⛔ **A fix that cannot fail this way has not closed the class.**

### The call-shape matcher — ⚠️ HIGHEST-RISK TASK IN THE PHASE
⭐ **Measured 2026-08-14:** regex vs Python-AST over the same population gives **41 vs 32 sites —
22% false positives**, in three live classes: `def` sites; matches inside string literals (which
`stripCommentsPreserveLines` deliberately preserves); and `service_error_body`, which takes the
code **first**, so any "second positional argument" rule mis-reads it.
- ⚠️ A too-narrow matcher **satisfies every absence assertion in the file** — it fails open.
- ⚠️ A matcher bug gets frozen into `EXPECTED_EMITTED_CODES` in the same commit, where it
  thereafter reads as *agreement*.
- **Mitigation (required):** cross-check the matcher's output against the independent Python AST
  census recorded in RESEARCH.md Q2 (32 sites / 21 codes, per-file table). The two must agree.
- Convention already exists in-repo — follow it, do not invent: `analytics-service/tests/test_raw_5xx_census.py`
  uses AST over `routers/**` + `services/**` + `main.py`, skips any path containing a `tests`
  segment, and keys on symbols never line numbers.

### Claude's Discretion
- Whether the two scanners converge into one shared discovery helper or stay separate with a
  shared matcher — as long as both roots and both shapes are covered and neither guard silently
  loses reach.
- Plan/wave decomposition and file-level task ordering.
- Copy wording for the new members, within DESIGN.md and the established wizard error voice.

<specifics>
## Specific Ideas

- ⭐ The mechanism is **proven**: mutating an emitted code literal in `finalize-wizard/route.ts`
  reds two assertions by name. This phase changes *reach*, not *design*. Do not rebuild the roster.
- ⚠️ **Do not blanket-sweep newly discovered codes into `WITHOUT_VERDICT` to make CI green.** Each
  newly discovered code needs a real disposition. A sweep reproduces the defect in its most general
  form: the law would cover everything and assert nothing.
- ⚠️ `analytics-service/**` is a wider root and may pull in test fixtures or scripts that mint
  codes no user can reach. Excluding them is legitimate; excluding them **silently** is not. Every
  exclusion is recorded with its reason.
- Live-relevance note: the code actually measured on PROD was `MT5_GATEWAY_UNCONFIGURED`, now less
  likely to fire since MT5 is configured. Its sibling `MT5_GATEWAY_UNREACHABLE` is exactly what the
  documented gateway wedges produce (three in one day), so the user-facing impact is live and
  recurring, not historical.

</specifics>
