## Non-negotiable

1. ⛔ **No Group-A code may take a WITHOUT_VERDICT row.** For a code that reaches
   `classifyKeyValidationError`, "no verdict" IS the defect being fixed (CONTEXT locked).
2. ⛔ **No blanket sweep.** Do NOT write the 12 Group-B rows as copies of
   `CSV_FORMAT_UNSUPPORTED`'s back-referencing one-liner (PATTERNS flags it as the model NOT to
   copy — twelve rows of that shape IS the forbidden sweep). Each row is its own measured fact
   naming its own rendering path.
3. ⛔ **Symbol anchors only, in comments AND in reason strings.** `wizardErrors.ts` is on
   `SEAM_CITATION_SURFACE`, and PATTERNS §4.3 confirmed at source that a `file.py:NNN` inside a
   reason STRING evades the citation guard (the guard scans comments only, with a self-test
   asserting exactly that is not an offence). A line-number citation there would ship with the
   guard's own self-test as its alibi. Anchor on symbols: `_connect_and_probe in
   routers/exchange.py`, machine codes, function names — never `path:NNN`.
4. **The SERVICE_UNAVAILABLE_RETRY trap** (written in-file near the transport-verdict comment,
   quoted in PATTERNS §1.3a): its copy asserts "Nothing was submitted" — knowable for a breaker
   that DECLINED to send, false-by-construction for a request that WAS issued.
   `MT5_GATEWAY_UNREACHABLE` fires after the request was issued → it maps to
   `SERVICE_UNREACHABLE`, never `SERVICE_UNAVAILABLE_RETRY`. The same test applies to ANY member
   whose copy makes a nothing-was-submitted or nothing-changed claim — including
   `SEAM_MISCONFIGURED`, whose copy says "we stopped before sending the request. Nothing was
   submitted and nothing was changed." Adopt such a member ONLY where that claim is measured TRUE
   at the emitter (the failure fires before any venue request and before any state change).
5. **Any new lookup structure must be a `Map`, never a `Record`** — the key arrives over the
   wire; a plain object resolves `constructor`/`__proto__` to inherited members (in-file security
   property, PATTERNS §1.3d).
6. **Verdict `code` values must be members of BOTH key rosters** (`KNOWN_CREATE_WITH_KEY_CODES`
   in ConnectKeyStep.tsx, `KNOWN_ADD_KEY_CODES` in MultiKeyConnectStep.tsx) or be added to both —
   otherwise the step roster-rejects the code and renders UNKNOWN anyway. Measured free members
   (in both rosters already): SERVICE_UNREACHABLE, SERVICE_UNAVAILABLE_RETRY,
   KEY_VENUE_TRANSIENT, KEY_PROBE_FAILED. SEAM_MISCONFIGURED is NOT in either key roster (2
   roster additions if adopted, no new copy).
7. **Dispositions are rendering decisions only** — the `UNAUTHENTICATED` / `SERVICE_KEY_UNCONFIGURED`
   rows must not weaken any auth gate, and copy must name a remedy, not a subsystem (DESIGN.md
   voice: every surface is a dated document that states its own limits; no infra detail leaks).
8. **Do not touch either route file.** The fix lives in the shared table (PATTERNS §1.4 verdict:
   both routes are read-only for this phase except regression tests, which are Plan 03's).
</constraints>
