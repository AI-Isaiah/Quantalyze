### M2-01 (MEDIUM, confidence 9) — the census pin is now structurally un-recuttable

**Line:** 572

The MIG-01 fix made `v_sig` an equality target (`v_sig <> c_pin_mt5`). The moment PROD's
mt5 rows span more than one creation date, **no choice of the three literals can satisfy
it** — and the block's own comment forbids softening the comparison.

**Fix:** decouple the count from the single date. Either
(a) make the date a set — `c_pin_dates CONSTANT DATE[] := ARRAY[DATE '2026-08-04']`, with
`v_sig` counted via `(created_at AT TIME ZONE 'UTC')::date = ANY(c_pin_dates)`, so a re-cut
appends a date; or
(b) abort on `v_mt5 <> v_sig OR v_mt5 <> c_pin_mt5` with the same `DATE[]` signature.
Then update the re-cut instruction at line 530 to say WHICH literals to re-cut for a
multi-date population.
