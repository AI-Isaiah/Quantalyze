<objective>
Make `finalize-wizard` honest on the wire: every rejection carries a `code`, and every coded
rejection is written in the shape the coverage scanner can read.

Purpose: D-09(b) — all `validatePayload` 400 arms are code-less, so the arm that cost the founder
three submits ("description must be 10-5000 characters") renders as "We could not classify this
failure". D-34 — the arms that DO carry codes are written `{ error, code }`, which the emitter

would go blind on them rather than fail.

`KNOWN_FINALIZE_CODES` roster that admits the whole vocabulary **in this same commit**.

(plus one lowercase→uppercase literal) of existing emitters — **nothing else**. The
`runScopeBroadeningProbe` gate, the `KEY_NETWORK_TIMEOUT` catch-all and every probe decision are
Phase 153.2's. No status code, no condition, no control flow changes. In `SubmitStep.tsx` this
plan touches the roster ONLY — field-level routing is 153.2's.

`KNOWN_CREATE_WITH_KEY_CODES` (`ConnectKeyStep.tsx:265-315`) and `KNOWN_ADD_KEY_CODES`
(`MultiKeyConnectStep.tsx:214+`) BOTH already contain `SERVICE_UNREACHABLE`,

sets are identical (24 members each; D-08's "22" is a regex artefact, RESEARCH Finding 10).
