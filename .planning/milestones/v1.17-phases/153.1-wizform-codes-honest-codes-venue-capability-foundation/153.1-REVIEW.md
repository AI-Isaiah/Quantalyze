## Critical Issues

### CR-01: `METADATA_DESCRIPTION_REQUIRED` renders a Retry control on the submit surface

**File:** `src/lib/wizardErrors.ts:1167-1176`, `src/app/(dashboard)/strategies/new/wizard/steps/SubmitStep.tsx:335`, `src/app/api/strategies/finalize-wizard/route.ts:448`

**Issue:** 153.1-05 made `finalize-wizard` emit `METADATA_DESCRIPTION_REQUIRED`
(route.ts:448, the `typeof description !== "string"` arm) and 153.1 admitted it to
`KNOWN_FINALIZE_CODES` (SubmitStep.tsx:335). But its copy entry is the **pre-existing
Phase 53 one**, which carries `actions: ["clear_and_retry"]`.
`clear_and_retry` is a member of `RECOVERABLE_ACTIONS` (`src/lib/envelope.ts:54-57`),
so `buildEnvelope` derives `recoverable: true` (`envelope.ts:88`) and `SubmitStep`
renders a Retry control wired to `onRetry={() => setErrorCode(null)}`
(`SubmitStep.tsx:559`). Pressing it re-POSTs the identical payload against the same
server rule and is refused identically.

This is the exact defect the phase's own class docblock forbids, in writing:

> `wizardErrors.ts:1181-1199` — *"RECOVERABILITY IS DECIDED ONCE, FOR THE CLASS, AND
> THE DECISION IS 'NOT RECOVERABLE' … ⛔ Specifically NOT `clear_and_retry`: it wipes
> what the user typed, which for a description they spent minutes on is the worst
> possible answer to 'it is nine characters long'."*

And the roster comment two lines above the offending entry asserts the property that
does not hold:

> `SubmitStep.tsx:307-309` — *"the **SEVEN** `METADATA_*` members are deliberately
> NON-recoverable and render NO Retry control."*

**EIGHT** `METADATA_*` codes are in that list (`SubmitStep.tsx:333-341`). The eighth is
this one, and it is recoverable. The count of "seven" comes from the union comment
(`wizardErrors.ts:187-207`), which enumerates the seven codes 153.1-04 minted and does
not include the Phase-53 code the route was newly pointed at.

**Honest scoping:** this is **not a regression** — before 153.1 the same arm fell to
`UNKNOWN`, which is also recoverable, so the Retry button was already there. It is an
**incomplete fix**: ten of the eleven newly-wired arms got the class treatment and one
did not, and the artefacts assert that all of them did. `wizardErrors.test.ts` cannot
catch it (its sweeps cover table size, destructive actions and `fixRequires` alignment
— none asserts `recoverable === false` for this class), and `SubmitStep.test.tsx` has
no case for any of the eleven new codes (see WR-03).

**Fix:** the change is one line and has no blast radius — the only other consumer of
this entry is `MetadataStep.tsx:215`, which reads `.cause` and never `.actions`.

```ts
// src/lib/wizardErrors.ts — METADATA_DESCRIPTION_REQUIRED
  METADATA_DESCRIPTION_REQUIRED: {
    title: "Add a description.",
    cause:
      "Allocators need a short description to evaluate the strategy. A description is required before you can continue.",
    fix: [
      "Write one paragraph describing the strategy, its edge, and how you frame risk.",
    ],
    docsHref: "/security",
    // 153.1 review CR-01 — joins the field-level refusal class. Carries no
    // member of RECOVERABLE_ACTIONS, so `buildEnvelope` derives
    // `recoverable: false` and no Retry control renders: the server compared a
    // value against a fixed rule and will refuse an identical resubmit
    // identically. The remedy is on the FORM. `MetadataStep.tsx:215` reads only
    // `.cause` from this entry, so the inline field guard is unaffected.
    actions: ["expand_log"],
  },
```

and correct the roster comment (`SubmitStep.tsx:307`) from "SEVEN" to "EIGHT". Add the
class assertion described in WR-03 in the same commit, or the next author reopens it.

### WR-01: the `EMITTER_BODY_MAX_CHARS` self-test cannot fail across the range that matters (measured)

**File:** `src/lib/wizardErrors.invariant.test.ts:1041-1065`

**Issue:** The self-test claims to be *"the cap's own falsifier"* and states
*"It reds for any cap at or above ~230 and stays green at 160."* **Measured, by
executing the file's own `emitterRe` + fixture against a sweep of cap values: it
reds only at cap ≥ ~305.**

```
cap=160 → ["SECOND_CODE"]   cap=250 → ["SECOND_CODE"]   cap=304 → ["SECOND_CODE"]
cap=200 → ["SECOND_CODE"]   cap=300 → ["SECOND_CODE"]   cap=320 → ["FIRST_CODE"]  ← first red
```

The cause is that the filler was sized at 200 to model the measured 202-character
real-world neighbour distance (`:140`), but the regex run is measured from `error:` to
the next `}`, and the fixture inserts ~104 characters of scaffolding into that span
that the sizing did not account for: 26 chars of the first body, the newline-plus-
`return NextResponse.json(` line (31), and 45 chars of the second body before its
closing brace. Total span = 304, not 200.

**Consequence.** The file's stated safety property is that the cap must stay **under
202**, or one emitter's code is reported against the next emitter's status on the real
sources. A cap of 250 — genuinely unsafe by that measure — passes this self-test green.
The guard is ~100 characters weaker than its prose, in exactly the "a guard which
cannot fail is worse than no guard" shape this phase was convened around.

**Fix:** stop modelling the distance through scaffolding and assert the bound directly,
beside a shrunk fixture:

```ts
// The measured shortest distance from any `error:` to the NEXT emitter's
// `status:` is 202 characters. A cap at or above that can cross-report, so the
// bound is asserted DIRECTLY rather than inferred from a fixture whose
// scaffolding adds ~104 characters to the span the regex actually measures.
expect(
  EMITTER_BODY_MAX_CHARS,
  "The lazy body run can now reach past a malformed emitter's own close and " +
    "report its code against the FOLLOWING emitter's status. 202 is the " +
    "measured neighbour distance on the real sources; the cap must stay under it.",
).toBeLessThan(202);

// …and shrink the filler so the fixture's real span is ~205, not 304:
"      ".padEnd(100, "x"),
```

### WR-02: `METADATA_DESCRIPTION_TOO_LONG`'s title is off by one against the rule it describes

**File:** `src/lib/wizardErrors.ts:475-477` (via `DESCRIPTION_BOUND_TITLE`), `src/app/api/strategies/finalize-wizard/route.ts:466`

**Issue:** The server rejects on `description.length > MAGNITUDE_CAPS.MAX_DESCRIPTION_CHARS`,
so a description of exactly 5,000 characters is **accepted**. The title reads
*"Keep this under 5,000 characters."* — which asserts a ceiling of 4,999. The `cause`
one line down is correct (*"longer than the 5,000 characters we store"*), so the entry
contradicts itself. Same class as the phase's other copy-honesty findings: a surface
naming a bound the server does not enforce. (The `TOO_SHORT` sibling is correct —
`< 10` rejects, "at least 10" is true.)

**Fix:**

```ts
const DESCRIPTION_BOUND_TITLE = {
  METADATA_DESCRIPTION_TOO_SHORT: `Add at least ${MAGNITUDE_CAPS.MIN_DESCRIPTION_CHARS} characters`,
  // "under N" asserts N-1. The server accepts exactly N (`length > N` rejects),
  // so the inclusive form is the true one.
  METADATA_DESCRIPTION_TOO_LONG: `Keep this to ${MAGNITUDE_CAPS.MAX_DESCRIPTION_CHARS.toLocaleString(
    "en-US",
  )} characters or fewer`,
} as const;
```

### WR-05: `venueCapabilities` indexes a plain `Record` with an externally-sourced key

**File:** `src/lib/closed-sets.ts:159-166`

**Issue:** `venueCapabilities` does
`(VENUE_CAPABILITIES as Record<string, VenueCapabilities | undefined>)[venue.toLowerCase()]`.
A plain-object index resolves `constructor`, `toString` and `__proto__` to inherited
members, so those keys return a truthy object rather than `undefined`. This is the
precise pattern the sibling module refuses, twice, in writing:

> `wizardErrors.ts:2450-2456` — *"WHY A `Map` AND NOT A `Record`, restated because it is
> a security property, not a style choice: the key arrives OVER THE WIRE. A plain-object
> index resolves `"constructor"`, `"toString"` and `"__proto__"` to inherited members…"*
> (repeated at `:2812-2818`)

**Current impact is nil and the reason is accidental**: `Object.prototype` carries none
of `scopeProbeSupported` / `substitutable` / `serialized`, so all three predicates fall
to their declared defaults (`?? true`, `?? true`, `?? false`) — the safe directions.
That safety is a property of today's three capability names, not of the lookup.
`venueSupportsScopeProbe` gates an ASVS V4 control and will be fed a venue read off the
`api_keys` row by 153.2, so a fourth capability whose safe default is the *other*
polarity would be silently subverted for those three keys.

**Fix:** one line, no behaviour change for any real venue:

```ts
function venueCapabilities(
  venue: string | null | undefined,
): VenueCapabilities | undefined {
  if (!venue) return undefined;
  const key = venue.toLowerCase();
  // OWN-property only. `constructor` / `toString` / `__proto__` otherwise
  // resolve to inherited members and hand back a truthy object typed as a
  // capability row — the Record-vs-Map rule wizardErrors.ts states twice.
  return Object.hasOwn(VENUE_CAPABILITIES, key)
    ? (VENUE_CAPABILITIES as Record<string, VenueCapabilities>)[key]
    : undefined;
}
```

### WR-06: the "two populations reconcile" assertion reconciles literals, not predicates

**File:** `src/lib/wizardErrors.invariant.test.ts:760-765`

**Issue:** The assertion is
`expect.soft(sites.length - codeless.length).toBe(d.expectedSites)` — i.e. `30 - 5 === 25`
— and its message claims *"the CODED rejections this scan sees and the emitters
`deriveEmittedCodes` sees have diverged."* It never reads `deriveEmittedCodes` output.
Both operands come from `deriveRejectionSites`, and both are already pinned by the two
`expect.soft` assertions immediately above (`toBe(30)`, `toBe(5)`), so whenever those
pass this one is arithmetically forced.

**Consequence:** the divergence it exists to catch is invisible. Break `emitterRe` so
`deriveEmittedCodes` returns 20 for finalize-wizard: the per-route count assertion reds
(correctly), `deriveRejectionSites` still reports 30/5, and this assertion passes green
while claiming the two predicates agree.

**Fix:** compare the two derivations directly.

```ts
expect.soft(
  sites.length - codeless.length,
  "the CODED rejections `deriveRejectionSites` sees and the emitters " +
    "`deriveEmittedCodes` sees have diverged — one predicate changed and the " +
    "other did not.",
).toBe(d.codes.length);          // ← the OTHER scanner's output, not a third literal
```
