### ⭐ The comment that argued for the defect — and its twin in the test suite

card — it GUARANTEES it, for every rejection on the path, forever. The paragraph
is deleted (not softened), the reasoning that is still true is kept (hard 400
never a silent coercion; the mark is data not privilege), and the inversion is
written in so the next reader cannot restore the bug.

**3. [Rule 2 — scope addition, +1 file] `SubmitStep.test.tsx` was modified
although it is NOT in `files_modified`.**
Its `[140.3-G2]` case reddened unprompted the moment the roster admitted
`COMPOSITE_UNSUPPORTED_UNIFIED`, and its failure message — authored for exactly
this moment — instructed: *"IF YOU ARE READING THIS BECAUSE YOU JUST ADMITTED
THE CODE: that is the right fix and this test is doing its job … THEN update
this case to assert the new code. Do not delete it."* Its sibling
(`draft_state_invalid` → UNKNOWN) had the same broken premise. **Both residuals
are now CLOSED**, and a NEW case keeps the OLD lowercase literal resolving to
UNKNOWN so the rename cannot be satisfied by a case-insensitive "fix".

**4. [Obligation discharged, not assumed] TRAP-4 was checked before proceeding,
because that failure message demanded it.**
It warns that admitting a NON-recoverable code can leave 'Try another key' →
`handleDeleteDraft()` as the sole affordance and **destroy the user's composite
draft**. Checked at source rather than reasoned about:

- `DESTRUCTIVE_CONTROL_IS_WRONG_FOR` **does not exist anywhere in `src/`** — its
  only hit is that message's own prose. Logged as DEF-153.1-05-B.
- The destructive control comes from the `try_another_key` action, and **not one
  of the eleven carries it** — checked through `buildEnvelope`, not by reading
  the table's own `actions`.
- `SubmitStep.tsx` has no `handleDeleteDraft` and no destructive affordance;
  that control lives on `SyncPreviewStep`.

The result is written into the test file so the next reader does not repeat it,
**and the obligation is explicitly NOT retired** for a future plan admitting a
`try_another_key`-carrying code.

**5. [Scope addition, +2 permanent guards] The class sweep and the lower-boundary
case.** The plan owed eleven per-arm assertions. A per-instance table cannot see
an arm added later without a code, and the constant-vs-condition drift D-23
names is an off-by-one away in either direction.
