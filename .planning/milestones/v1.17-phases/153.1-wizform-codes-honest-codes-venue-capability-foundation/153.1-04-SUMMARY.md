### The reasoning, re-run per site (not copied between them)

The two guards scan **different populations**, so each docblock got the clause its own
site needs.

**Site 1 — `[140.3-10 / TRAP-4]`**, whose population is entries carrying a DESTRUCTIVE
action (`DESTRUCTIVE_ACTIONS = ["start_fresh"]`):

- the seven metadata refusals carry `["expand_log"]` alone;
- `SEAM_DEADLINE_EXCEEDED` and `COMPOSITE_UNSUPPORTED_UNIFIED` carry `request_call` + `expand_log`;
- `DRAFT_STATE_INVALID` carries `leave_and_return` + `expand_log`.

None carries `start_fresh`, so **all ten are outside the scanned population by
construction** and the destructive class stays at four — which the `toEqual([...])`
receipt two `it`s down asserts independently rather than by this reasoning. ⭐ The
exclusion is load-bearing rather than incidental on `DRAFT_STATE_INVALID` and on the
seven: their whole point is that the user's work survives the refusal, so a control that
deletes the draft would answer them by destroying the thing the copy tells the user to go
and fix.

**Site 2 — `[140.3-12 / SEAMUX-04]`**, the copy-honesty scan. All ten read against the
four FORBIDDEN fragments by hand. None mentions notification, trade fetching or a session
field name, so the fragment needing care is `"data is unchanged"` — and nine of the ten
DO make a server-state claim. Taken in **three groups, because the GROUND differs**:

| Group | Claim | Ground — why it is OBSERVABLE, not asserted |
|---|---|---|
| the seven metadata refusals | "Nothing was saved" | raised inside `validatePayload`, which returns its 400 BEFORE `finalize_wizard_strategy`, before `postProcessKey`, before any write. A control-flow property. They also claim "everything you typed is still on the form" — a statement about the client's own DOM, the weakest possible claim and the one the user needs |
| `COMPOSITE_UNSUPPORTED_UNIFIED` | deliberately claims the OPPOSITE | the failed-stamp is written one statement above the 409, so "nothing changed" would have been the CSV lie. It says "we marked the strategy as failed" and narrows the untouched-claim to the keys |
| `DRAFT_STATE_INVALID` | "This attempt saved nothing" | SQLSTATE 22023 means the RPC itself raised, so Postgres rolls the function's transaction back. Stronger than the returns-before-write kind, not weaker |
| ⚠️ `SEAM_DEADLINE_EXCEEDED` | "your key was not stored" | the ONE whose ground is an **obligation on a future emitter** rather than a property of code that exists. Recorded at the entry AND in the docblock so 153.4 inherits it |

### The new guard: the two pins cannot silently diverge

`describe("[153.1-04 / WIZFORM-02] the two EXPECTED_TABLE_SIZE pins cannot silently
diverge")` at `:3010`, one `it`. The subject is **this test file's own source**, which is
the only vantage point from which both declarations are visible at once — the two `const`s
live in separate function scopes, so nothing has ever stopped a plan from moving one and
leaving the other. The file already reads a sibling module's source for the copy-marker
hand-off, so the technique is its own.

Three assertions, in order:
1. ⭐ **positive control** — exactly **2** hand-typed declarations found (hand-typed `2`).
   A matcher that stops matching gives `0` and reds HERE, instead of letting a
   "they all agree" check pass over an empty list.
2. the two literals are **one** value, and the failure message prints both.
3. that value still equals the measured table size.

The regex matches a **numeric literal only**, so an `EXPECTED_TABLE_SIZE =
Object.keys(...).length` would fail assertion 1 rather than sneak past as agreement —
which is where the two docblocks' prohibition on a derived value becomes enforceable
across both sites at once.
