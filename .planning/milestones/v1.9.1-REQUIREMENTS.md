## v1 Requirements (this milestone)

### HARD — Composite analytics & data correctness
- [x] **HARD-01** — A composite factsheet never renders absurd metrics (per-key contribution in the thousands/millions of %, CAGR/Cumulative 0.0% while the curve rises). Root-cause and fix the inverse-Deribit per-key daily-return scale blow-up (near-zero-equity denominator family, P72-adjacent) so the stitched series and every dependent KPI are finite and correct on the live repro.
- [x] **HARD-02** — The first member key's data window is captured and persisted (never `window "–" / Days 0` when the user entered one): the window flows ConnectKeyStep/MultiKeyConnectStep → `/api/keys/sync` → `strategy_keys.window_start/window_end`, with a regression test that fails without the fix.
- [x] **HARD-03** — A composite persists `cumulative_method` in `data_quality_flags` at stitch time so the factsheet chart prefers the persisted method over a live-config re-derive; editing config without re-stitching can never make the chart disagree with the headline scalars. (Closes #69 / Phase-90 LEV carry-forward.)
- [ ] **HARD-04** — A short-lived / flow-heavy composite window is flagged (`insufficient_window` DQ) instead of silently over-annualizing CAGR; the flag is stamped at the CAGR site without changing the underlying value. (Closes #67; likely shares root with HARD-01.)
- [x] **HARD-05** — A composite whose members span Bybit/OKX/Binance reconstructs honestly (or degrades with an explicit DQ reason) rather than fail-loud PERMANENT; only-Deribit-composites-work is removed as a limitation. (Closes #78; the largest composite functional gap.)

### WIZ — Composite wizard resumability (dogfooding C–F)
- [x] **WIZ-01** — A server read returns a composite draft's existing member keys (exchange, nickname, active window, verified status) WITHOUT secrets (ciphertext stays server-side), so the wizard can rehydrate them.
- [x] **WIZ-02** — `MultiKeyConnectStep` rehydrates State B from the server on re-entry: already-stored keys appear pre-filled and marked verified (no re-validation, empty secret field is acceptable for an unchanged key), so navigating back never shows a blank form.
- [x] **WIZ-03** — "Review your keys" is non-destructive: it navigates back to the populated key step and never deletes the draft or its member keys.
- [x] **WIZ-04** — The wizard stepper supports free back/forward navigation (clickable steps); after going back and changing nothing, the user can return forward to any later step without redoing work.
- [x] **WIZ-05** — Returning to the crawled/verify step shows the cached stitch snapshot instead of re-triggering a crawl/stitch.

### PROG — Stitch progress transparency
- [ ] **PROG-01** — The in-progress copy is user-facing ("Trades are being downloaded and processed", phase-aware if cheap), not the internal "Stitching composite…".
- [ ] **PROG-02** — The progress panel shows per-key status (e.g. Key 1: Successful / Key 2: In process / Key 3: Waiting) instead of the debug `strategy_id / status=pending / elapsed` block: the worker writes per-member progress to `compute_jobs.metadata`, the poll route surfaces it, the frontend renders it.
- [ ] **PROG-03** — An interrupted/stalled stitch is visible and recoverable within the wizard's patience window: close the 30-min stall-watchdog vs 15-min wizard-patience gap (faster reclaim for `stitch_composite`, or surface a genuine stall distinctly from "still working") so a worker restart/OOM never presents as an indefinite hang.

### CLEAN — Draft & key hygiene
- [ ] **CLEAN-01** — A cron atomically deletes stale wizard drafts (`source='wizard' AND status='draft' AND created_at < now() - 24h`) as a single DELETE (no SELECT-then-DELETE race with a concurrent finalize). (Closes #35.)
- [ ] **CLEAN-02** — After draft cleanup, an `api_keys` sweep removes rows not referenced by any surviving strategy. (Closes #36.)

### CI — Test & schema infra for the composite path
- [ ] **CI-01** — The analytics-service pytest suite runs in parallel WITHOUT red-lining `test_compute_jobs_fencing.py`: make the shared-DB claim/fence tests parallelism-safe (scope their claims to a per-run tag, or run the shared-DB file in a dedicated serial lane), so `-n auto` is green and #610 can land. Tie in re-enabling the 3 deferred P97 flaky live-DB fence tests (#165) where the same fix applies.
- [ ] **CI-02** — The composite finalize/publish path is fully green in CI: instrument the `stitch_composite` enqueue mutation (`finalize-wizard/route.ts:907`) for `audit-coverage.test.ts`, add the `strategy_keys` mock to `audit-fanout-integration.test.ts`, and land the owed SQL-fn snapshots (`enforce_strategy_keys_owner_coherence`, `sync_strategy_analytics_status`) so `schema:functions:check` is green.
