# Phase 51 — UI Design Contract

> Visual and interaction contract for the shell + information-architecture
> restructure (NAV-01..04). Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. This phase **evolves the existing shell onto the Phase-50
> token/focus conventions** — it does NOT rebuild it. Every value below is
> pre-populated from DESIGN.md (the SoT), 51-CONTEXT.md (locked user decisions),
> and the live shell components; defaults are recorded where DESIGN.md is silent.

## Typography

Shell/nav/breadcrumb surfaces draw from the fixed px scale (DESIGN.md §Typography)
and its Phase-49 fluid `--text-*` mirror. The shell uses a tight subset:

| Role | Size | Weight | Line Height | Token / class |
|------|------|--------|-------------|---------------|
| Page title (H1 in PageHeader) | 32px Instrument Serif | 400 | 1.1 (display) | `font-display text-[32px]` → migrate to `text-page-title` (24→32 fluid) in 52/53; **keep `text-[32px]` this phase** to avoid visual churn |
| Section heading (sidebar group label) | 10px DM Sans | 600 semibold | 1.4 | `text-[10px] font-semibold uppercase tracking-widest` |
| Sub-group label (Discovery buckets) | 10px DM Sans | 500 medium | 1.4 | `text-[10px] font-medium uppercase tracking-wider` |
| Nav item label | 14px DM Sans | 500 medium | 1.5 | `text-sm` (→ `text-body` 14→16 in 52/53) |
| Breadcrumb label | 14px DM Sans | 400 / 500 on current | 1.5 | `text-sm`; current crumb `font-medium` |
| Marketing nav link | 14px DM Sans | 500 medium | 1.5 | `text-sm font-medium` |
| Badge / micro | 10px DM Sans | 500 medium | 1 | `text-[10px] font-medium` |

**Weights this phase: exactly 2 — regular (400) + medium/semibold (500/600).**
Hierarchy on the dark sidebar is carried by `font-semibold` + tracking, NOT a
third weight or an opacity modifier (opacity collapses fg+bg → AA failure; see
the PR #108 note baked into `Sidebar.tsx`).

**Migration posture:** this phase keeps the existing raw `text-sm`/`text-[10px]`
/`text-[32px]` classes (additive, no app-wide type churn — the per-surface
`--text-*` migration is Phase 52/53 per DESIGN.md §"Migration posture"). New
breadcrumb/marketing markup MAY use the named tiers (`text-body`/`text-small`)
where it introduces fresh class strings.

## Color

Light mode only (FROZEN). Tokens are `--color-*`-prefixed CSS custom properties
(DESIGN.md §Color; sidebar family in `globals.css`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8F9FA` page / `#FFFFFF` surface | App background, content panels, marketing surface |
| Secondary (30%) | `#0F172A` sidebar (`--color-sidebar`) | The dark navy authed nav rail (desktop + drawer) |
| Accent (10%) | `#1B6B5A` (`--color-accent`), hover `#155A4B` | See reserved-for list below |
| Destructive | `#DC2626` (`--color-negative`) | Permanent failures / errors only — **no destructive actions exist in this phase** |

**Sidebar state palette (the dark-rail nav contract — already AA-blessed):**

| Role | Value | Token |
|------|-------|-------|
| Rail background | `#0F172A` | `--color-sidebar` |
| Item hover background | `#1E293B` | `--color-sidebar-hover` |
| Active item background | `#334155` | `--color-sidebar-active` |
| Default item / label text | `#94A3B8` | `--color-sidebar-text` (6.75:1 on rail — AA) |
| Hover / active item text | `#FFFFFF` | `--color-sidebar-text-active` |

**Accent (`#1B6B5A`) is reserved EXCLUSIVELY for, this phase:**
- The active/current-route indicator in the **light** navs (mobile bottom-nav active cell `text-accent`; marketing-header CTA).
- The **focus-visible** ring/outline on every interactive nav/breadcrumb/link element (keyboard focus affordance).
- The "My Allocation" flagged-count badge (`bg-accent`, white text) — pre-existing.
- The marketing-header primary CTA ("Sign up" → `bg-accent text-white`, Button `primary`).
- Inline prose links inside marketing body copy (`text-accent underline underline-offset-4` — WCAG 1.4.1 persistent underline, per the 2026-06-28 DESIGN.md decision).

Accent is **NOT** used for: the dark-sidebar active state (that uses
`--color-sidebar-active` slate, by design — accent on navy fails contrast and
breaks the rail's restraint), generic hover backgrounds, breadcrumb separators,
or any decorative purpose.

**Contrast floor:** every nav/breadcrumb/link text-on-bg pair MUST pass WCAG-AA
(≥4.5:1 normal text). The v1.3 AA floor is LOCKED — the design conforms to the
gate, never the reverse. Breadcrumb muted text `#64748B` on `#F8F9FA`/`#FFFFFF`
is AA (4.85:1 on white, per the 2026-04-30 muted-text shift).

## Role-Scoped Nav Contract

The role OR-logic in `Sidebar.buildNavSections` / `buildPrimaryMobileNav` is the
**security-relevant SoT (T-45-01 info-disclosure mitigation) — DO NOT REGRESS
it.** This phase brings it to *completeness* + evolves the visual states onto the
Phase-50 conventions. It does NOT change which roles see which sections.

### Nav section grouping (existing — preserve)
`MY WORKSPACE` → `DISCOVERY` (allocator/admin only, sub-grouped Digital Assets →
TradFi) → `ADMIN` (admin only) → `ACCOUNT`. Section headings: 10px DM Sans
semibold uppercase `tracking-widest`, `--color-sidebar-text`.

### Item state contract (desktop rail + drawer)

| State | Treatment | Class contract |
|-------|-----------|----------------|
| Default | `--color-sidebar-text` (#94A3B8) on rail; 14px medium; `rounded-lg px-3 py-2` | `text-sm` + `gap-3`, 16×16 icon |
| Hover | `bg-sidebar-hover` (#1E293B) + `text-sidebar-text-active` (#FFFFFF) | `hover:bg-sidebar-hover hover:text-sidebar-text-active` |
| **Focus-visible (NEW — gap to close)** | Accent ring, keyboard-only | **`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent`** — the sidebar `<Link>` currently has NO focus-visible affordance; ADD it to match Button/Tabs/MobileNav. Use `focus-visible:` (keyboard), never bare `focus:`. |
| Active / current page | `bg-sidebar-active` (#334155) + `text-sidebar-text-active` (#FFFFFF) | `bg-sidebar-active text-sidebar-text-active` (existing) |
| Current-page semantics (NEW — gap to close) | The active item MUST also expose `aria-current="page"` for AT (desktop rail currently sets visual active but no `aria-current`; MobileNav already does). | `aria-current={active ? "page" : undefined}` |
| Transition | `transition-colors` 150ms ease-out (DESIGN.md hover spec) | existing |

Active rule stays the existing pathname match:
`pathname === href || pathname.startsWith(href + "/")` (SSR-safe, no
`useSearchParams` CSR-bailout — keep the documented tradeoff in `MobileNav`).

### "You are here" current-route indicator
1. The active **nav item** (slate-filled + white text + `aria-current="page"`).
2. App-wide **breadcrumb** in `PageHeader` (the primary "where am I" affordance).
3. The **PageHeader H1** (the leaf label) echoes the active surface name.

### Role-scoped nav COMPLETENESS (NAV-01 — surface the orphans)
Audit every role-owned surface and ensure it is reachable from its role's nav
(no orphan/dead-end). Known orphan candidates from 51-CONTEXT.md to resolve in
planning (UI contract: each gets a labeled, role-gated nav entry OR is reachable
via a parent surface + breadcrumb back-path — never a dead end):
`/scenarios`, `/preferences`, `/referral`, `/recommendations`, `/security`,
`/compare`, `/decks`. Where a surface is a *child* of a workspace destination
(reached by an in-page control), it is "reachable" via that parent + a
breadcrumb back-path rather than a top-level nav item — that is acceptable and
explicitly NOT an orphan. The planner picks per-surface; this spec fixes the
*states*, not the per-route placement.

### Mobile parity (structurally unchanged — LOCKED v1.3 shell)
`MobileNav` (≤5 primary cells, `min-h-[44px]`, active `text-accent`,
`focus-visible:outline-2 outline-accent`, `aria-current="page"`) and
`MobileSidebarDrawer` (full nav, focus-trap, Escape, body-scroll-lock,
focus-restoration) are the LOCKED v1.3 baseline. Apply the SAME new
focus-visible + `aria-current` contract additively; do NOT restructure the
drawer/bottom-nav, do NOT regress TouchTooltip/useTapPin or the
mobile-drawer-keyboard e2e.

## Breadcrumb Contract

App-wide on dashboard surfaces, rendered inside/above `PageHeader`. Evolves the
existing `Breadcrumb.tsx` — does NOT rebuild it.

### Structure & a11y (existing — preserve + extend)
- `<nav aria-label="Breadcrumb">` wrapper (already present).
- Separator: the 14×3.5 chevron SVG (`M6 4l4 4-4 4`), `text-text-muted`,
  decorative (no `aria-label`) — existing.
- Crumb links: `text-sm text-text-muted`, `hover:text-text-primary
  transition-colors` — existing.
- Current (last) crumb: `text-text-primary font-medium`, rendered as plain
  `<span>` (no link) — existing — **PLUS add `aria-current="page"` (gap to
  close: it is currently a styled span with no `aria-current`).**
- **Focus-visible (NEW — gap to close):** linked crumbs MUST get
  `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent`
  (the current `<Link>` has hover only). Keyboard, not bare `focus:`.

### Hierarchy derivation
Breadcrumbs are derived from the route hierarchy, shallow-to-deep:
`{workspace root} → {section} → {current page}`. Depth is typically 2–3 crumbs;
the root crumb links to the role's workspace landing (allocator → `/allocations`,
manager → `/strategies`, admin → `/admin`), labeled by that surface's name.
Keep it shallow — do NOT mirror every URL segment; collapse intermediate
non-navigable segments.

### Truncation of long labels (ties to the Phase-49 truncation audit)
Long crumb labels (e.g. a strategy name) use **legitimate truncation only**:
single-line `truncate max-w-[…]` with recovery — `title={fullLabel}` on the
element AND the full string available to AT (the visible text is the source).
Accidental clipping is a defect (TYPE-01 classifies clip sites). Never truncate
the **current/leaf** crumb so aggressively that the page identity is unreadable;
prefer truncating the middle crumbs. The separators and the leaf must always
remain visible at 320px (no horizontal scroll).

## Back-Path Convention (every deep surface answers "how do I get back")

Every surface below the top nav level MUST provide at least ONE unambiguous
back-path. Priority order (a surface satisfies the contract with any one, but
the breadcrumb is the default app-wide answer):

1. **Breadcrumb** (default, app-wide): the root + section crumbs are live links —
   the primary, always-present back affordance in `PageHeader`.
2. **Active nav item** stays highlighted so the rail itself shows the parent.
3. **Explicit "← Back to {parent}" link** for deep leaf surfaces that have NO
   meaningful breadcrumb parent in the nav tree (e.g. a `/strategies/[id]/edit`
   returning to the strategy). Style: `text-small text-text-muted
   hover:text-text-primary`, with a 16×16 chevron-left glyph,
   `focus-visible:ring-2 focus-visible:ring-accent`, `min-h-[44px]` tap target.
   Label names the destination ("Back to {parent}"), never bare "Back".

**No dead ends:** a surface that has neither a nav highlight, a breadcrumb
parent, nor an explicit back link is a defect. Modal/drawer surfaces close back
to their opener (existing focus-restoration pattern) — that counts as the
back-path for overlay surfaces.

## Unified Active / Hover / Focus State Contract

ONE contract across nav + breadcrumbs + links + the marketing shell. AA-passing,
keyboard-aware. Matches the Phase-50 primitives (Button/Tabs).

| Surface | Default | Hover | Focus-visible (keyboard) | Active / current |
|---------|---------|-------|--------------------------|------------------|
| Dark sidebar nav item | `--color-sidebar-text` #94A3B8 | `bg-sidebar-hover` + white text | `ring-2 ring-accent` (NEW) | `bg-sidebar-active` + white + `aria-current="page"` |
| Mobile bottom-nav cell | `text-text-muted` | (tap) | `outline-2 outline-accent` (live) | `text-accent` + `aria-current="page"` |
| Breadcrumb link | `text-text-muted` | `text-text-primary` | `ring-2 ring-accent` (NEW) | leaf: `text-text-primary font-medium` + `aria-current="page"` |
| Marketing nav link | `text-text-secondary` | `bg-page text-text-primary` | `ring-2 ring-accent` (NEW) | n/a (top-level marketing) |
| Marketing primary CTA | `bg-accent text-white` (Button primary) | `bg-accent-hover` | `ring-2 ring-accent/50` (Button live) | n/a |
| Inline prose link (marketing) | `text-accent underline underline-offset-4` | `text-accent-hover` | `ring-2 ring-accent` | n/a |

**Hard rules:**
- **`focus-visible:`, never bare `focus:`** for keyboard rings (so a mouse click
  on a nav item does not paint a ring) — matches Button/Tabs/MobileNav. Field
  controls keep the soft `focus:` glow (Phase-50 50-02 decision); nav/links use
  `focus-visible:`.
- Ring token: `ring-2 ring-accent` (`#1B6B5A`) on light surfaces;
  `outline-2 outline-accent` where the element already uses outline (MobileNav).
  Buttons keep their existing `ring-accent/50`.
- Transition: `transition-colors`, 150ms ease-out (DESIGN.md hover spec). No new
  motion, no decorative transition (anti-decoration invariant).
- Every state pair passes WCAG-AA (LOCKED v1.3 floor).

### Footer

### SEO / chrome safety (NON-NEGOTIABLE — NAV-04)

## Route-Contract Notes (UI-resolvability only)

Enforcement (the by-construction CI guard, `proxy.ts` allowlist, redirect map)
is **out of UI-SPEC scope** (51-CONTEXT.md decision 3). The only UI obligation:
**every nav/breadcrumb/back-path link MUST resolve to real content — never a
307→login (the #512 class) or a 404.** Specifically:
- The mobile Discovery filler links to the canonical slug
  (`/discovery/crypto-sma`), not bare `/discovery` (which 404s — no `page.tsx`).
  Any new nav link to a `[slug]`-only route MUST target a concrete landing slug.
- Any route a MOVE relocates keeps a 301/308 redirect so existing nav/share/deep
  links still resolve; the nav points at the NEW canonical path.
- Never add a nav link to a share-token / in-the-wild route as a "move" target
  (`/scenario-share/[token]`, `/factsheet/[id]`, `/strategy/[id]`,
  `/portfolio-pdf/[id]` are not moved — 51-CONTEXT.md).
