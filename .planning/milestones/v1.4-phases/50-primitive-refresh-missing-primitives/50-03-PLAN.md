## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer-supplied content -> Table/Field render | Table cells and Field labels/hints/errors render content supplied by the consuming surface (admin data, user-entered form values); an injection sink here would be app-wide. |
| npm dependency -> Tabs runtime | @radix-ui/react-tabs executes in the client bundle as the first runtime UI-widget dep. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-50-04 | Tampering (XSS / HTML injection) | Table cells + Field label/hint/error | mitigate | All cell/label/hint/error content renders as React children (escaped). The plan forbids `dangerouslySetInnerHTML` in Table.tsx and Field.tsx (acceptance-criteria gated). No `innerHTML` sink is introduced. |
| T-50-SC | Tampering (supply chain) | @radix-ui/react-tabs import in Tabs.tsx | mitigate | The package was legitimacy-gated + exact-pinned in Plan 01 (T-50-SC). This plan only imports it; no new install. Tabs is the ONLY Radix import (UI-04) — Table/Field use semantic/native HTML, gated by the no-@radix-ui acceptance criteria. |
| V5 Input Validation | Field primitive | accept | mitigate | Field renders `aria-invalid`/error visuals but does NOT itself validate — validation stays in the consuming form (no new input-parsing/sanitization surface). This is the documented ASVS V5 (low) posture. |
| V2/V3/V4/V6 ASVS | — | n/a | n/a (not applicable) | New presentational primitives; no auth/session/access-control/crypto. Marked non-applicable explicitly. |
</threat_model>
