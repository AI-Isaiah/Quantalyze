# Phase 47 — UI Design Contract

> Visual and interaction contract for the hand-rolled SVG charts. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **RETROFIT over a LOCKED design system.** This phase introduces ZERO new aesthetic direction. Every
> token (color / typography / spacing / radius / motion) is already locked in `DESIGN.md` and is treated as
> immutable here. The phase adds three things to the *already-shipped* hand-rolled `<svg>` charts: (1)
> touch tap-to-reveal/pin parity where a desktop hover already exists, (2) 320px legibility (the
> viewBox-downscale trap), and (3) portrait density/aspect tuning — all while the frozen `scenario.ts` /
> `compute.ts` math stays byte-identical. The reference is the existing
> `src/app/factsheet/[id]/v2/TimeSeriesChart.tsx`; the contract is to propagate ITS interaction/legibility
> behavior, never to invent a new one.

**Phase-47 spacing exceptions (touch-target only, NOT visual-rhythm changes):**

## Typography

**LOCKED `DESIGN.md` v2 chart-text contract (4-size / 2-weight superset already grep-enforced by
`tests/visual/strategy-v2-type-scale.test.ts`).** This phase changes **only the effective rendered size of
chart axis/label text at 320px** (the legibility fix), never the type *system*:

| Role | Size | Weight | Family / Notes |
|------|------|--------|----------------|
| Panel H2 (chart titles) | 16px | 600 semibold | DM Sans — unchanged |
| KPI metric values | 18px | 600 semibold | Geist Mono `tabular-nums` — unchanged |
| Chart axis ticks / cell labels / caption | 12px | 400 regular | Geist Mono `tabular-nums`, `#64748B` on `#FFFFFF` (4.85:1 AA). The shipped Recharts token is `CHART_TICK_STYLE` (`src/components/charts/chart-tokens.ts`, `fontSize:12`). Hand-rolled SVG `<text>` MUST match this **effective** size. |
| Sub-heading | 12px base | 400 | differentiated by `uppercase tracking-wider`, **never a third weight** |

**The legibility contract (CHART-02) — the load-bearing change of this phase:**

- **Problem (measured, not hypothetical):** in-scope SVG panels declare viewBox `fontSize` of **8–11px**
  (`AnalyticalPanels` 9px, `HeatmapPanels` 8–9px, `MasterBrush` 9px, `SignaturePanels`/`CrossSignaturePanels`/`HistogramChart` 10px,
  `DistributionPanels` 9–12px). Those scale with the SVG: at 320px against a viewBox width like
  `VB_W=440` the chart renders at ≈0.66×, so a 9–10px label lands at **≈5–7px effective** — the
  WCAG 1.4.4 viewBox-downscale trap.
- **Floor:** effective rendered axis/label text **≥ ~12px** (the `DESIGN.md` caption / "body-small" tier)
  at a 320px CSS viewport. This is the falsifiable bar a portrait snapshot verifies.
- **Default technique (CSS-first, no overlay machinery):** at the mobile breakpoint **reduce tick density**
  (fewer ticks) **and bump the viewBox font** so the *effective* px clears the floor. Trigger is
  **breakpoint-driven via `useBreakpoint`** (mobile → fewer ticks / larger viewBox font), consistent with
  the Phase-44 primitive.
- **HTML-overlay real-px labels** are the fallback technique, used **only** where the viewBox downscale
  still wins after the font bump (real CSS-px `<div>`/`<span>` positioned over the SVG, in DM Sans/Geist
  Mono at the literal 12px). Executor discretion which panels need overlay vs font-bump.
- **Data is never touched** — ticks/labels only. **Never downsample data points** (banned anti-feature;
  frozen-math guard).

## Interaction Contract (CHART-01a — touch tap-reveal/pin)

**Focal point (per-chart, locked by DESIGN.md — not invented here):** the data series itself is the primary
visual anchor — on equity/line charts the strategy stroke `#1B6B5A` (`CHART_ACCENT`); on heatmaps the baked
cell ramp; on box/histogram the bars. The tap-pin crosshair/tooltip is **subordinate** and inherits the
existing `TimeSeriesChart` styling — it never out-weights the series it reads from.

The defining work of this phase. **Parity-only**: add tap-to-reveal/pin **only where a desktop hover
exists today** (SC#1 = "a tap reveals the value that hover gives on desktop"). Charts with no desktop hover
get **legibility + portrait only** — do NOT invent a new interaction surface for them.

**Reference gesture (verbatim from `TimeSeriesChart`, to be reused via the shared hook):**

| Aspect | Contract |
|--------|----------|
| Tap detection | pointer never moved beyond **~8px** (TAP_SLOP) AND gesture lasted **< 350ms** → treat as a tap, not a drag |
| Tap action | reveal the value the desktop tooltip shows AND **pin** it (stays visible after the finger lifts) |
| Re-tap | a re-tap within ~10px of the pin **toggles the pin off**; a tap elsewhere **moves** the pin |
| `pointerleave` | a **pinned** reveal **survives** `pointerleave` (touch users lift their finger); an unpinned reveal clears |
| Auto-dismiss | **none** — no timer |
| Hit target | the tap target's hit rectangle measures **≥ 44 × 44 CSS px** under `pointer-coarse:` |

**Per-chart-type tap target — the tapped element shows the SAME value the desktop tooltip shows (NOT a
literal crosshair line on non-line charts):**
