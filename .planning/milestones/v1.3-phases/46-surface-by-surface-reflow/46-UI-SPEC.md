# Phase 46 — UI Design Contract

> Visual and interaction contract for the surface-by-surface reflow (CSS-first, no charts). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **RETROFIT contract.** DESIGN.md is the LOCKED source of truth. This spec invents NO new aesthetic — it pins exact existing tokens, utilities, and primitives to the three reflow jobs (honest table reshape, wizard de-block, honest states across breakpoints) plus the all-route reflow sweep, so the planner and executor implement without guessing. Every token below traces to DESIGN.md or to an existing component cited inline. CSS-first work with ZERO risk of crossing the frozen `scenario.ts` / `compute.ts` math boundary; charts are explicitly OUT of scope (phases 47–48).
>

## Design System

| Property | Value |
|----------|-------|
| Tool | none (existing hand-rolled system; DESIGN.md is SoT) |
| Preset | not applicable |
| Component library | none (Tailwind v4 utilities + `--color-*` tokens; no `components.json`, no `tailwind.config.*` — CSS-first `@theme inline` in `globals.css`) |
| Icon library | In-repo inline SVGs (reuse existing — this phase adds NO icons) |
| Font | DM Sans (body/labels), Instrument Serif (display), Geist Mono / `font-metric` (numeric cells) — via `next/font`, already loaded |

**No new dependencies. No shadcn (project is not shadcn-based).** Breakpoints are Tailwind v4 defaults — **`sm = 640px`, `lg = 1024px`** — with NO custom `--breakpoint-*` tokens. The wizard de-block targets the same `640px` boundary `DesktopGate.tsx` uses today (`(max-width: 639px)` = `<sm`). Any unavoidable JS viewport branch routes through the single SSR-safe two-pass `useBreakpoint` / `useMediaQuery` (server snapshot `'desktop'`); this phase introduces NO new `matchMedia` site.

**Canonical reshape primitive:** `ResponsiveTable` (`src/components/ResponsiveTable.tsx`) — a Server Component that wraps a table in `<div className="overflow-x-auto" role="region" aria-label={hint} tabIndex={0}>`. It adds ONLY the scroll affordance + a11y region (no table restyle, no row-height change). **Do NOT reinvent per-table scroll wrappers** — every protected/migrated table routes through this one component.

## Spacing Scale

DESIGN.md base unit is **4px**; ladder `2 4 8 12 16 24 32 48 64`. This phase is CSS-first reflow — it adds almost no new spacing, it preserves existing table/card padding and applies scroll/stack utilities. Declared subset:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| 0.5 | 2px | (preserve only — `py-0.5` on existing badges; do not introduce new) |
| 1 | 4px | Tab/inline gaps already present; CorrelationMatrix `p-1` cells (unchanged) |
| 2 | 8px | Existing table cell `px-2`/`py-2` (unchanged) |
| 3 | 12px | Existing `px-3`/`py-3` header padding (unchanged) |
| 4 | 16px | Card padding (16–20px sm) + table `px-4` cell padding (preserve verbatim) |
| 6 | 24px | Card padding (md) + section gaps (preserve) |
| 8 | 32px | `EmptyStateCard` `py-8` (32px) vertical breathing room (preserve) |

**Touch-target floor (intentional, WCAG 2.5.8):** table rows are already `~44px` (DESIGN.md §Spacing "Table row height ~44px"; `HoldingsTable` rows carry `style={{ minHeight: 44 }}`). Any interactive control surfaced by reflow work (wizard step nav/footer buttons, sort headers, row toggles) MUST measure **≥44px** in both axes on `pointer: coarse`. **44px is NOT on the 4-ladder** — it is the WCAG floor and the only sanctioned off-ladder value, matching `e2e/helpers/reflow.ts:30` (`MIN_TARGET_PX = 44`) and the phase-44/45 precedent. **Do not lower it to pass a gate** — scope the selector instead, never weaken the bar.

**Exceptions:** `--space-grid-gap` (10px, designer-bundle WidgetGrid/Bridge origin) is preserved verbatim wherever it already lives — do NOT snap it to 12px (DESIGN.md 2026-04-27 decision: snapping shifts the 4-col grid 6px and regresses the 980px/640px breakpoints). This phase introduces NO new `--space-grid-gap` site.

## Component Contracts

### 1. Table Reshape — horizontal scroll via `ResponsiveTable` (TABLE-01)

**The contract:** every wide financial table stays usable at 320px by **horizontal scroll inside a `ResponsiveTable` region — NEVER by dropping or hiding a column.** Column-drop on a financial table is a no-invented-data violation (a hidden Sharpe or Max-DD silently changes what the allocator sees). CSS-first, zero math risk. **No sticky first column** (simplest, matches the existing `ScenarioCompareTable` pattern); the cut-off column edge peeking past the right edge IS the scroll affordance.

**1a. Wrap the 3 currently-UNPROTECTED raw `<table>`s** (no scroll wrapper today) in `ResponsiveTable`:

| Table | File | Modes / column count |
|-------|------|---------------------|
| `HoldingsTable` (NEW row mode) | `src/app/(dashboard)/allocations/components/HoldingsTable.tsx:~378` | `TOTAL_COLUMNS = 7`: Venue/Symbol · Type · Quantity · Entry price · Value (USD) · Unrealized PnL · Notes |
| `HoldingsTable` (legacy/DESIGN mode) | `…/HoldingsTable.tsx:~551` | `DESIGN_TOTAL_COLUMNS = 9`: Status · Strategy · Symbol · Weight · Allocation · MTD · Sharpe · Max DD · Age |
| `HoldingsTable` (StrategyRows mode) | `…/HoldingsTable.tsx:~223` | 8 cols: Strategy · Manager · Weight · Allocation · MTD · Sharpe · Max DD · Age |
| `OpenPositionsTable` | `src/app/(dashboard)/allocations/components/OpenPositionsTable.tsx` | wrap raw `<table>` in `ResponsiveTable` |

**1b. Migrate the 2 highest-stakes already-scrolling tables** (today a raw `<div className="overflow-x-auto">` with NO a11y region) onto `ResponsiveTable` so they gain the `role="region"` + focusable + sr-only-hint contract:

| Table | File | Today | Migrate to |
|-------|------|-------|-----------|
| `ScenarioCompareTable` | `…/components/ScenarioCompareTable.tsx:185` | raw `<div className="overflow-x-auto">` | `<ResponsiveTable>` (drop the raw div) |
| `CorrelationMatrix` | `…/widgets/risk/CorrelationMatrix.tsx:173` | raw `<div className="overflow-auto">` | `<ResponsiveTable>` (keep N×N symmetric structure) |

**1c. Admin tables** (`ComputeJobsTable`, `csv-status`, `usage`, `compute-jobs`, `deletion-requests`, `intros`, `users`): scroll-wrap with `ResponsiveTable` only (internal, lower-stakes) — no deep restructure, no all-columns guard.

**1d. Low-stakes tables that already have a raw `overflow-x-auto`** (`StrategyBreakdownTable`, `CompareTable`, `StrategyTable`, factsheet tables) MAY stay as-is — this is NOT a forced 30-file migration. The executor may opportunistically migrate trivial ones at discretion (CONTEXT §Claude's Discretion), but doing so is not required for SC compliance.

**Scroll-hint copy (the `ResponsiveTable` `aria-label`):** the component default —
> "Table scrolls horizontally. Swipe or use arrow keys to see more columns."
— is the canonical hint. Pass a table-specific `hint` only if a clearer affordance is warranted; otherwise rely on the default (it is the region's accessible name, announced once on focus — do NOT add a duplicate `sr-only` node, which double-announces).

**All-columns-present fail-loud guard (SC#2) — highest-stakes tables ONLY:**

| Table | Material set the guard asserts (and fails if any is hidden/truncated/dropped) | Anchor |
|-------|------------------------------------------------------------------------------|--------|
| `HoldingsTable` (NEW mode) | all 7: Venue/Symbol, Type, Quantity, Entry price, Value (USD), Unrealized PnL, Notes | `TOTAL_COLUMNS === 7` + `<th>` label set |
| `HoldingsTable` (legacy/DESIGN mode) | all 9: Status, Strategy, Symbol, Weight, Allocation, MTD, Sharpe, Max DD, Age | `DESIGN_TOTAL_COLUMNS === 9` + `<th>` label set |
| `ScenarioCompareTable` | the "Metric" axis column + every scenario column (`data-testid="scenario-col-{name}"`) + every `METRICS` row | per-column `data-testid` + `METRICS` length |
| `CorrelationMatrix` | the full N×N symmetric set — every strategy name appears as BOTH a column header and a row label | header `<th>` count === row-label count === N |

The guard **fails when a future `hidden` / `hidden md:table-cell` / column-`truncate` / column-drop edit removes a material metric or status** from a highest-stakes table. Baseline (verified 2026-06-27): these tables currently carry NO `hidden md:table-cell` and NO material-column `truncate` — the only `hidden` strings are the "{n} holdings hidden from view" expand-copy (NOT a column drop) and `CorrelationMatrix`'s `truncate` on the long name LABEL (the name stays present via `title=` tooltip and is reachable — the guard polices column PRESENCE, not label ellipsis). The guard must assert presence of the FULL set, and must FAIL (be falsifiable) when a column is neutered — verify it fails when a column is deleted, then restore.

### 2. Wizard De-Block (WIZARD-01)

**The contract:** below 640px, render the REAL wizard. Delete the desktop-only hard-block and its email-capture fallback; reflow the wizard's own layout CSS-first so it is usable on a phone.

**Surgical changes (locked in CONTEXT):**
- **Keep the two-pass `isNarrow === null` hydration-safe pattern** is NOT the framing — the de-block REMOVES the narrow branch entirely. Concretely: in `DesktopGate.tsx` today the render tail is `if (isNarrow === null) return children; if (!isNarrow) return children; return <email-capture form>`. After de-block, the component renders `children` at ALL widths — so the `matchMedia` measurement, the `isNarrow` state, and the email-capture branch (`DesktopGate.tsx:77–114`) become dead.
- **Remove `DesktopGate` from the wizard tree and DELETE the component** (`src/app/(dashboard)/strategies/new/wizard/DesktopGate.tsx`) — cleaner than a pass-through stub. Update `wizard/page.tsx:92,122` to render the `<Suspense key={source}>…<WizardClient/>` subtree directly (the Suspense boundary + `key={source}` MUST be preserved — it is the Next-16/React-19 CSR-bailout fix documented at `page.tsx:93–119`; removing it re-introduces the empty-CsvUploadStep hydration bug). Delete `DesktopGate.test.tsx` (its subject is gone).
- **No hydration mismatch (SC#5):** because the wizard already SSR-renders `children` (the `isNarrow === null` server pass returned `children`), removing the narrow branch makes SSR and the first client paint render the SAME tree at every width — this REMOVES a viewport branch rather than adding one, so it cannot introduce a new hydration warning. This phase adds NO new `matchMedia`/JS viewport branch to the wizard.
- **The email-capture "resume on desktop" form is removed** — the `/api/for-quants-lead` route stays (other callers use it), but the wizard no longer posts the `wizard_context: { wizard_session_id: "desktop-gate" }` payload.

**Reflow the wizard's own layout CSS-first (no new JS branching):**
- Stack fields vertically and make inputs full-width at `<sm` (`w-full`, single-column); the multi-column step grids collapse to one column below `sm` via existing Tailwind responsive utilities (`grid-cols-1 sm:grid-cols-2`-style — apply the project's existing pattern, do not invent a custom breakpoint).
- The broker-selector grid (DESIGN.md §Broker Selector Grid: `3-cols × 1-row`) stacks to a single column at `<sm`; each broker card keeps its white surface / 1px `#E2E8F0` border / 8px radius / `border-accent bg-accent/5` active state verbatim.
- The CSV escape-hatch card (DESIGN.md §CSV Escape-Hatch Card) stays full-width and reflows naturally — verify it does not overflow at 320px.
- **Step nav / footer reachable and usable at 320px:** the stepper and the footer Back/Next/Submit controls must be visible and tappable (≥44px) at 320px with NO horizontal page overflow. The wizard's `Button` primary CTA stays `bg-accent`; step-transition focus management (DESIGN.md §9-State Matrix a11y: "on step transition, focus moves to the first interactive control of the new step") and `aria-current="step"` on the active step are PRESERVED.
- **Honor the wizard's existing 9-state matrix + a11y minimums** (DESIGN.md §9-State Matrix): `role="alert"` blocking errors, `role="status" aria-live="polite"` non-blocking changes, Tab/Shift+Tab DOM-order keyboard nav — none of this regresses; the reflow is layout-only.

### 3. Honest States Across Breakpoints (REFLOW-03)

**The contract:** loading / empty / error / partial states stay honest AND unbroken at every viewport. Degenerate inputs (0/1 strategy, <10 overlapping days, non-finite returns) keep their honest empty states with no fabricated data and no broken layout. **Verify-and-fix-only — no new empty-state components.**

| Component | File | Reflow status (verified 2026-06-27) | Action |
|-----------|------|-------------------------------------|--------|
| `EmptyStateCard` | `src/components/ui/EmptyStateCard.tsx` | Fluid by construction — `rounded-lg border bg-surface px-4 py-8 text-center`; no fixed width | Verify at 320px; fix ONLY if it overflows |
| `SampleFloorEmptyState` | `src/components/scenarios/SampleFloorEmptyState.tsx` | Copies the `CorrelationHeatmap` shell; renders `EmptyStateCard` tokens | Verify at 320px; fix only on overflow |
| allocations `EmptyState` | `src/app/(dashboard)/allocations/EmptyState.tsx` | Simple card | Verify at 320px; fix only on overflow |
| `Skeleton` / `SkeletonText` / `SkeletonCard` | `src/components/ui/Skeleton.tsx` | Fluid — fractional widths only (`w-full`, `w-2/3`, `w-1/3`, `w-1/3`, `h-4`/`h-5`); `aria-hidden` | Verify at 320px; change ONLY on overflow |

**Honest-absence visual rules (DESIGN.md, must hold at every width):**
- Empty states are **neutral muted cards** — `text-text-muted` body, `text-text-secondary` heading, `bg-surface`, NO `role="alert"`, NO red/warning color. A below-threshold/degenerate state is honest absence, not an error.
- Em-dash (`—`) is the canonical "no real value" placeholder in cells (never `0`, never a fabricated number) — preserve at every width.
- **Extend the phase-44 reflow e2e to cover ≥1 degenerate-state route at 320px** so a regression that breaks an honest-empty layout fails LOUDLY (e.g. a 0-strategy or <10-overlapping-day composer/correlation surface). Wire per FLOW-01 (below).

### 4. All-Route Reflow Sweep + Verification (REFLOW-01 / REFLOW-02)

**The contract:** prove "every authed + public route passes" with a **parametrized reflow spec** iterating a curated route list at 320px CSS width + 400% browser zoom, extending the phase-44 `assertNoReflow` helper (`e2e/helpers/reflow.ts`).

**Reflow assertion (verbatim from phase-44 helper — do not re-derive):**
- `document.documentElement.scrollWidth - clientWidth <= 1px` at a 320px viewport (`clientWidth`, not `innerWidth`, to exclude the scrollbar gutter; `≤1px` slop for sub-pixel font hinting).
- Anchored on a VISIBLE content element per route so a blank/404/unhydrated page fails LOUD instead of false-greening (the `assertNoReflow` fail-loud guard).
- **Zoom never disabled** at 400% (WCAG 1.4.4) — the phase-44 root-layout zoom-permissive viewport export (no `maximum-scale` / `user-scalable=no`) already enforces this; the sweep verifies routes remain usable (no two-axis PAGE scroll) at 400%.

**Curated route list (Claude's discretion per CONTEXT — the SC#1 authed + public surface set is the floor):**
- **Authed:** `/allocations` (+ each tab: Overview / Holdings / Outcomes / Mandate / Risk / Scenario), Scenario composer, factsheets (`/factsheet/[id]`, `/factsheet/[id]/v2`), Bridge, Risk, Discovery, Single-Strategy, manager onboarding wizard (`/strategies/new/wizard`), `/portfolios`, `/security`, admin routes.
- **Public/marketing:** every public route (landing, `/demo`, `/discovery`, public factsheet/share, `/security`, `/for-quants`).
- The exact curated list + which authed routes need seeding is at executor discretion within this floor; admin routes are scroll-wrapped not deep-restructured.

**FLOW-01 dual-wiring (the twice-burned trap — MANDATORY):** every new e2e gate (the parametrized reflow sweep + the degenerate-state reflow spec) MUST be wired into BOTH:
1. the appropriate Playwright list in `.github/workflows/ci.yml` (place 1 — unseeded routes go in the unseeded `auth.spec.ts e2e/smoke.spec.ts …` line like `reflow.spec.ts`; seeded authed routes go in the seed-gated MA-8 list), AND
2. its `HAS_SEED_ENV` self-skip guard (place 2 — seeded specs `test.skip(!process.env.TEST_SUPABASE_*)`; unseeded specs carry NO env guard, matching `reflow.spec.ts`).
Both places together guarantee the gate actually executes — a gate added to only one silently never runs (false-green by omission, burned twice). The phase-44 `reflow.spec.ts` is the unseeded precedent; the phase-45 `mobile-drawer-keyboard.spec.ts` is the seeded precedent.

## States

Applies to all surfaces touched by this phase.

| State | Behavior |
|-------|----------|
| **320px viewport (smallest target, SC#1)** | Every authed + public route: `scrollWidth - clientWidth <= 1px` (no horizontal PAGE scroll, WCAG 1.4.10). | **Error** | Wizard inline errors keep `text-negative role="alert"`; the canonical `ErrorEnvelope` (DESIGN.md §Error Envelope) reflows fluidly (it is full-width `rounded-md` with no fixed width). This phase adds NO new error surface. |

| **Focus** | Every interactive control surfaced by reflow (sort headers, row toggles, wizard nav/footer, scroll regions) shows `focus-visible:outline outline-2 outline-accent`. Existing rings preserved; none stripped. |
| **Reduced motion (`prefers-reduced-motion: reduce`)** | This phase adds no animation. `Skeleton`'s `animate-pulse` is the only motion on a touched surface and is a pre-existing decorative pulse (unchanged). Any incidental transition uses the existing `motion-reduce:transition-none` convention. |
