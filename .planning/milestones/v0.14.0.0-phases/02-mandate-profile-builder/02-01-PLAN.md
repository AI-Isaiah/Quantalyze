<objective>
Ship the database + data-access foundation for the Mandate Profile Builder. Migration 061 adds five mandate columns (`max_weight`, `correlation_ceiling`, `liquidity_preference`, `style_exclusions`, `mandate_edited_at`) to `allocator_preferences`, **drops the `allocator_prefs_self_update` RLS policy** so MANDATE-06 is enforced at the DB (ROADMAP SC4 Option A — allocators can no longer direct-UPDATE), and creates the `update_allocator_mandates(...)` SECURITY DEFINER RPC with named parameters + a `p_clear_fields text[]` escape hatch for the Reset affordance (D-11). Extend `AuditAction`/`AuditEntityType` unions + ADR-0023, export `ALLOCATOR_PREFERENCES_COLUMNS` from `src/lib/admin/match.ts`, expand `SELF_EDITABLE_PREFERENCE_FIELDS` + `validateSelfEditableInput` in `src/lib/preferences.ts`, rewrite `PUT /api/preferences` to call the RPC (dropping the direct upsert + profiles denorm write), extend the admin PreferencesPanel + admin route for parity, and ship three live-DB test files. Migration is applied via a `[BLOCKING]` `supabase db push` task so Wave 2 executes against the real schema.

Purpose: The RPC is the only allocator write path (MANDATE-05 / MANDATE-06). Without the live schema, Wave 2's `MandateForm` POSTs would compile against stale types and silently diverge from the DB. Without `p_clear_fields`, the Reset affordance (D-11) cannot set a previously-set field back to NULL through the same auto-save path. Without the `ALLOCATOR_PREFERENCES_COLUMNS` sync, the admin match queue payload silently drops new columns from the PreferencesPanel. Dropping `allocator_prefs_self_update` is what MAKES ROADMAP SC4 literally true; previously MANDATE-06 was API-convention-only, now it's a DB-level invariant.

Output: Wave 0 test scaffolds (Task 0), live migration 061 applied with self-update policy removed, audit union + ADR-0023 updated, preferences lib + tests extended, route handler + its unit test rewritten, admin panel parity wired, three live-DB integration tests committed. No client UI yet — Plan 02-02 consumes this contract.
</objective>

Existing RLS policies on allocator_preferences (from migration 011:240-253):
```
allocator_prefs_self_read    FOR SELECT USING (user_id = auth.uid())                   -- KEEP
allocator_prefs_self_insert  FOR INSERT WITH CHECK (user_id = auth.uid())              -- KEEP
allocator_prefs_self_update  FOR UPDATE USING (user_id = auth.uid())                   -- DROP in 061 (MANDATE-06 Option A)
allocator_prefs_admin_read   FOR SELECT USING (<is_admin>)                              -- KEEP
allocator_prefs_admin_all    FOR ALL    USING/WITH CHECK (<is_admin>)                   -- KEEP — admin direct UPDATE path
allocator_prefs_service_all  FOR ALL    USING/WITH CHECK (auth.role() = 'service_role') -- KEEP
```
The SECURITY DEFINER RPC bypasses RLS via `prosecdef = TRUE` — it runs as the function owner (postgres/table-owner role) and its INSERT/UPDATE inside the function body is authorized by that role, not by the caller's RLS context. Dropping `allocator_prefs_self_update` only removes the direct-UPDATE escape hatch for the authenticated allocator role; the RPC continues to upsert successfully. Admin direct UPDATE remains via `allocator_prefs_admin_all`.

  p_max_weight                NUMERIC DEFAULT NULL,
  p_preferred_strategy_types  TEXT[]  DEFAULT NULL,
  p_excluded_exchanges        TEXT[]  DEFAULT NULL,
  p_target_ticket_size_usd    NUMERIC DEFAULT NULL,
  p_mandate_archetype         TEXT    DEFAULT NULL,
  p_correlation_ceiling       NUMERIC DEFAULT NULL,
  p_max_drawdown_tolerance    NUMERIC DEFAULT NULL,
  p_liquidity_preference      TEXT    DEFAULT NULL,
  p_style_exclusions          TEXT[]  DEFAULT NULL,
  p_clear_fields              TEXT[]  DEFAULT '{}'
)
RETURNS VOID
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_catalog
AS $$
DECLARE
  v_auth_uid UUID := auth.uid();
  v_allowed_clear_fields CONSTANT TEXT[] := ARRAY[
    'max_weight','preferred_strategy_types','excluded_exchanges',
    'target_ticket_size_usd','mandate_archetype','correlation_ceiling',
    'max_drawdown_tolerance','liquidity_preference','style_exclusions'
  ];
  v_bad_field TEXT;
BEGIN
  -- 1. Auth guard (SQLSTATE 28000 maps to HTTP 401 in route handler)
  IF v_auth_uid IS NULL THEN
    RAISE EXCEPTION 'update_allocator_mandates: no auth session'
      USING ERRCODE = 'insufficient_privilege';
  END IF;

  -- 2. Bounds validation (SQLSTATE 22023 maps to HTTP 400).
  --    Mirrors TypeScript validateSelfEditableInput (D-18 double-check).
  IF p_max_weight IS NOT NULL AND (p_max_weight < 0.05 OR p_max_weight > 0.50) THEN
    RAISE EXCEPTION 'max_weight must be between 0.05 and 0.50'
      USING ERRCODE = 'invalid_parameter_value';
  END IF;
  IF p_correlation_ceiling IS NOT NULL AND (p_correlation_ceiling < 0 OR p_correlation_ceiling > 1) THEN
    RAISE EXCEPTION 'correlation_ceiling must be between 0 and 1'
      USING ERRCODE = 'invalid_parameter_value';
  END IF;
  IF p_max_drawdown_tolerance IS NOT NULL AND (p_max_drawdown_tolerance < 0 OR p_max_drawdown_tolerance > 1) THEN
    RAISE EXCEPTION 'max_drawdown_tolerance must be between 0 and 1'
      USING ERRCODE = 'invalid_parameter_value';
  END IF;

    RAISE EXCEPTION 'liquidity_preference must be high, medium, or low'
      USING ERRCODE = 'invalid_parameter_value';
  END IF;
  IF p_mandate_archetype IS NOT NULL AND length(p_mandate_archetype) > 500 THEN
    RAISE EXCEPTION 'mandate_archetype must be 500 characters or less'
      USING ERRCODE = 'invalid_parameter_value';

    p_correlation_ceiling, p_max_drawdown_tolerance, p_liquidity_preference,
    p_style_exclusions, NULL, now(), now()

    excluded_exchanges        = CASE WHEN 'excluded_exchanges' = ANY (p_clear_fields) THEN NULL
                                     ELSE COALESCE(EXCLUDED.excluded_exchanges, allocator_preferences.excluded_exchanges) END,
    target_ticket_size_usd    = CASE WHEN 'target_ticket_size_usd' = ANY (p_clear_fields) THEN NULL
                                     ELSE COALESCE(EXCLUDED.target_ticket_size_usd, allocator_preferences.target_ticket_size_usd) END,
    mandate_archetype         = CASE WHEN 'mandate_archetype' = ANY (p_clear_fields) THEN NULL
                                     ELSE COALESCE(EXCLUDED.mandate_archetype, allocator_preferences.mandate_archetype) END,
    correlation_ceiling       = CASE WHEN 'correlation_ceiling' = ANY (p_clear_fields) THEN NULL
                                     ELSE COALESCE(EXCLUDED.correlation_ceiling, allocator_preferences.correlation_ceiling) END,
    max_drawdown_tolerance    = CASE WHEN 'max_drawdown_tolerance' = ANY (p_clear_fields) THEN NULL
                                     ELSE COALESCE(EXCLUDED.max_drawdown_tolerance, allocator_preferences.max_drawdown_tolerance) END,
    liquidity_preference      = CASE WHEN 'liquidity_preference' = ANY (p_clear_fields) THEN NULL

    style_exclusions          = CASE WHEN 'style_exclusions' = ANY (p_clear_fields) THEN NULL

    edited_by_user_id         = NULL,  -- allocator self-edit marker (D-14)

    updated_at                = now();
END;
$$;
