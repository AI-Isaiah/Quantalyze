## Spacing Scale

Declared values (4px base, per DESIGN.md):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside the banner strip; button content gaps |
| sm | 8px | Button-to-button gaps in the banner action row; compact form field spacing |
| md | 16px | Default inline padding of the banner strip (`px-4 py-3`); form field vertical rhythm; card padding (sm variant) |
| lg | 24px | Vertical separation between the banner strip and the Holdings row above it; card padding (md variant); section gaps |
| xl | 32px | Layout gaps between major sections of the allocations widget |
| 2xl | 48px | Major section breaks (not used in Phase 1 banner/forms; declared for completeness) |
| 3xl | 64px | Page-level spacing (not used in Phase 1) |

**Exceptions (phase-specific):**
- **Table row height:** ~44px (touch-target compliant) per DESIGN.md Spacing. The banner strip sits below an eligible Holdings row and MUST NOT compress the 44px row above it — banner renders as a full-width strip appended beneath the row using `border-t border-border`.
- **Dismiss [×] hit-target:** button min-height 32px (`h-8 w-8`) to keep `&times;` tap-target ≥ 32px without forcing the strip to 44px+. Icon-only controls follow WCAG 2.5.5 (target ≥ 24×24) — 32×32 clears this with padding.

Source: DESIGN.md Spacing § base unit + scale; RESEARCH.md Banner component shell.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (DM Sans regular) | 1.5 |
| Label | 13px | 500 (DM Sans medium) | 1.4 |
| Heading | 16px | 600 (DM Sans semibold) | 1.3 |
| Display | 32px | 400 (Instrument Serif regular) | 1.15 |

**Phase 1 role mapping:**
- **Body (14px DM Sans 400, 1.5):** banner prompt "Did you act on this Bridge suggestion?"; form helper/validation text; inline Recorded status line.
- **Label (13px DM Sans 500, 1.4):** form field labels ("Percent allocated", "Allocated on", "Note (optional)", "Why not?"); button labels on [Allocated] / [Rejected] / "Record allocation" / "Record rejection" / "Cancel".
- **Heading (16px DM Sans 600, 1.3):** form section heading if a form needs one (Phase 1 forms inline-replace the banner strip — a heading is not strictly required; if used, reserve for "Record allocation" / "Record rejection" as a visible form title).
- **Display (32px Instrument Serif 400, 1.15):** NOT used in Phase 1 banner/forms. Declared to keep the contract aligned with DESIGN.md page-title usage elsewhere in the app.

**Metric / numeric content (footnote — not a template row):** All numeric content in the banner/form uses **Geist Mono 13px, `font-variant-numeric: tabular-nums`** via the `.font-metric` utility in `globals.css`. This covers:
- Percent-allocated input value suffix (`12%`) and the echoed value in the Recorded status line
- `allocated_at` date (`2026-04-17`)
- Delta values (`+1.2%`, `−3.4%`, etc.)
- Day counter in Estimated label (`3d`, `29d`)

Source: DESIGN.md Typography § scale + Data/Tables; `src/app/globals.css` `.font-metric` (lines 109–113); RESEARCH.md D-01 ("DM Sans body, Geist Mono for numeric labels").

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8F9FA` (`--color-page`) | Page background; banner strip background (strip inherits page bg to read as row-integrated, not card-on-card) |
| Secondary (30%) | `#FFFFFF` (`--color-surface`) | Holdings widget card surface (the card that contains the Holdings rows the banner sits beneath); form input backgrounds |
| Accent (10%) | `#1B6B5A` (`--color-accent`) | See "Accent reserved for" list below |
| Destructive | `#DC2626` (`--color-negative`) | Submit button fill on RejectedForm (records a rejection; semantic alignment with "negative outcome"); realized-window negative delta text (`30-day: −X.X%`, `90-day: −X.X%`, `180-day: −X.X%`); inline form error copy. NOT used on the [Rejected] *trigger* button on the banner strip (that's Secondary, per DESIGN.md Button pattern) |

**Accent reserved for** (explicit list — never "all interactive elements"):
1. **Primary CTA button fill** — the `[Allocated]` trigger button on the banner strip (opens `AllocatedForm`). Background `--color-accent`, text `#FFFFFF`, hover `--color-accent-hover` (`#155A4B`). Follows DESIGN.md Buttons § Primary.
2. **AllocatedForm submit button fill** — "Record allocation" button (same Primary treatment as #1).
3. **Input/textarea focus border** on both forms — `--color-border-focus` which maps to `--color-accent`. Fields in idle state use `--color-border` (`#E2E8F0`); on `:focus-visible`, border upgrades to `--color-accent`.
4. **`OutcomeRecordedRow` leading glyph** — a subtle accent-tinted checkmark (ASCII `✓` or a single-char glyph; project has no icon library so use `✓` at `text-accent`) rendered before the "Recorded: …" text to confirm the commit.

**Not accent** (explicit non-uses to prevent drift):
- `[Rejected]` trigger button on the banner strip → Secondary style (transparent fill, 1px `--color-border`, text `--color-text-primary`, hover background `#F1F5F9` or the muted hover token used elsewhere in the widget).
- `[×]` dismiss button → Ghost style (transparent, no border, text `--color-text-muted`, hover text `--color-text-secondary`).
- Form "Cancel" button → Ghost style.
- Inline validation error text → `--color-negative` (not accent).
- Plain text links inside form helper copy (if any) → body color; no accent underline unless DESIGN.md says otherwise for the surrounding context.

**Semantic colors beyond destructive:**
- **Positive `#16A34A` (`--color-positive`):** realized-window positive delta text (`30-day: +X.X%`, `90-day: +X.X%`, `180-day: +X.X%`). Per D-13, applied ONLY to 30d/90d/180d realized windows.
- **Warning `#D97706` (`--color-warning`):** NOT used in Phase 1 (reserved per DESIGN.md 2026-04-11 update for transient recoverable states; Phase 1 has no such state — cron failures surface as `Pending` per D-14, not as warning).
- **Neutral (default `--color-text-primary` `#1A1A2E`):** `Pending` label and `Estimated: +X.X% (Nd)` label use default text color per D-13 (avoids over-reading short-window noise).

Source: DESIGN.md Color; `src/app/globals.css` lines 7–27; CONTEXT.md D-13 (color treatment); RESEARCH.md D-13 + Pattern 1.

| Day 180+ (realized 180d) | `180-day: +X.X%` / `180-day: −X.X%` | `--color-positive` / `--color-negative` per D-13 |

Notes on delta labels:
- Numeric values (`X.X`, `N`) render in Geist Mono tabular-nums via `.font-metric`; label prefix (`Pending`, `Estimated:`, `30-day:`, …) renders in DM Sans 14px body.
- Sign glyph is ASCII `+` for positive and the minus glyph `−` (U+2212) for negative to keep widths consistent in tabular-nums.
- Values render to one decimal place (`%.1f`) per D-11/D-12 example `+1.2%`.

## Interaction States & Motion

**State transitions** (banner lifecycle for a single eligible row):

| From → To | Trigger | Visual / Motion |
|-----------|---------|-----------------|
| `hidden` → `banner visible` | Server returns `eligible_for_outcome: true` for the row (page SSR) | No entry animation (SSR already paints; avoid motion on first render). |
| `banner` → `AllocatedForm` | Click `[Allocated]` | Inline replace on the same row strip. No cross-fade; immediate swap (`setState`). Total time ≤ 50ms (micro per DESIGN.md Motion). |
| `banner` → `RejectedForm` | Click `[Rejected]` | Same as above. |
| `form` → `banner` | Click `Cancel` | Same immediate swap. |
| `form` → `submitting` | Click `Record allocation` / `Record rejection` | Submit button text → `Recording…`, `disabled` + `aria-busy="true"`; other fields become `readonly` (not disabled — preserves screen-reader ability to re-read values). |
| `submitting` → `OutcomeRecordedRow` + toast | POST 2xx | Replace banner strip with status line (immediate swap). Toast slides up from bottom using existing `UndoToast` keyframes (`@keyframes slide-up`, 250ms ease-out — matches DESIGN.md Motion medium). Toast auto-dismisses at 10s (existing `UndoToast` TTL). |
| `submitting` → `form + error` | POST 4xx/5xx (other than 429) | Form stays visible; submit button re-enables; inline error copy appears above submit row (`role="alert"`, `aria-live="polite"`); error toast fires. No form fields cleared. |
| `submitting` → `form + rate-limit` | POST 429 | Same as generic error, with copy variant: `Too many submissions — try again in a moment`. |
| `banner` → `hidden` (dismissed) | Click `[×]` | 150ms `ease-out` opacity fade-out on the strip (DESIGN.md Motion § short / hover states). On transition-end, remove from DOM. Server-side dismissal insert fires optimistically in parallel; on dismiss-route failure, the banner reappears on next page load (TTL takes over — no rollback animation needed). |
| `OutcomeRecordedRow` → `OutcomeRecordedRow (label upgraded)` | Next-day cron populates `delta_30d`/`90d`/`180d` | No transition — the upgrade is visible on next SSR render. No polling, no client-side label swap animation. |

**Focus management:**
- Opening a form (banner → form) moves focus to the first form field (`percent_allocated` for Allocated, `rejection_reason` radio group for Rejected).
- Closing a form via `Cancel` returns focus to the originating trigger button (`[Allocated]` or `[Rejected]`).
- After successful record, focus moves to `OutcomeRecordedRow`'s container (`tabindex="-1"` + programmatic `.focus()`) so screen readers announce the status line.
- `prefers-reduced-motion: reduce` disables the dismiss fade-out (strip is removed immediately) and the toast slide-up (toast appears without translate). The `animate-pulse` override in `globals.css` (lines 57–62) sets the precedent.

**Keyboard:**
- `[Allocated]`, `[Rejected]`, `[×]` are native `<button>` elements — `Enter` / `Space` activate. Tab order is left-to-right: prompt text → `[Allocated]` → `[Rejected]` → `[×]`.
- Inside forms: `Tab` traverses fields top-to-bottom; `Enter` inside a single-line input submits if the form is valid (standard HTML form behavior); `Escape` invokes Cancel (matches modal-dismiss convention elsewhere in the app).

Source: DESIGN.md Motion (50/150/250/400ms scale, reduced-motion respect); CONTEXT.md D-05/D-07/D-11; RESEARCH.md Pattern 2 + `UndoToast.tsx`.
