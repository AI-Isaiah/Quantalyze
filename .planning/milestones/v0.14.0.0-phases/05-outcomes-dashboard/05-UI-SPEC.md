- Table row height: exactly **44px** (`style={{ height: 44 }}`) — matches PositionsTable.tsx row height; touch-target compliant.

- Sparkline cell vertical padding: `py-2` (8px) above/below chart; horizontal `px-0` (0px — full column width).

### 2. OutcomesKPIStrip

**Layout:** 3-column horizontal flex with `justify-around`. Vertical hairline dividers between columns (`border-r border-[#E2E8F0]` on first two columns). Source: CustomKpiStrip.tsx pattern (`flex h-full items-center justify-around`).

**KPI columns (left to right):**

| Column | Label | Value font | Color logic |
|--------|-------|-----------|-------------|
| Total Outcomes | `"TOTAL"` | Geist Mono 13px medium | `#1A1A2E` always (neutral count) |
| Win Rate | `"WIN RATE"` | Geist Mono 13px medium | `#16A34A` if > 50%, `#DC2626` if < 50%, `#1A1A2E` if = 50% or null |
| Avg Delta | `"AVG DELTA"` | Geist Mono 13px medium | `#16A34A` positive, `#DC2626` negative, `#718096` null |

**Sub-label under Avg Delta:** `"Avg realized delta: +2.3% · 3 pending"` — DM Sans 12px medium `#718096`. The main Geist Mono value is the number alone (`+2.3%`); the sub-label carries the contextual string. Separator is the Unicode middle-dot `·` (U+00B7). Source: CONTEXT.md D-14.

**KPI semantic rules (D-11, D-12, D-13):**
- Total = `COUNT(*)` all rows for allocator (reconciles 1:1 with visible timeline rows below).
- Win rate numerator = allocated rows where most-mature non-NULL delta > 0 AND `percent_allocated >= 1.0`.
- Win rate denominator = allocated rows with ≥1 non-NULL delta AND `percent_allocated >= 1.0`. Pending-only allocated and all rejected rows excluded.
- Avg delta = mean of most-mature non-NULL delta per row, same inclusion set as win rate denominator.

### 3. OutcomesTimeline (table)

**Structure:** plain HTML `<table>` with `border-collapse` — mirrors PositionsTable.tsx. No TanStack Table (no sorting, column visibility, or resizing needed; sort order is fixed newest-first per D-01).

**Column definitions:**

| Column | Width | Content | Font |
|--------|-------|---------|------|
| Caret (expand toggle) | 32px fixed | `<button>` with chevron icon | — |
| Original Strategy | flex | Strategy name as `<a href="/strategies/[id]">` | DM Sans 14px medium text-primary |
| Replacement Strategy | flex | Strategy name as `<a href="/strategies/[id]">` | DM Sans 14px medium text-primary |
| Date Recorded | 100px | `"Apr 18, 2026"` format | DM Sans 14px medium text-muted `#718096` |
| Status | 140px | Status pill (see pill anatomy below) | DM Sans 11px badge |
| Best Available Delta | 120px | Derived via `deriveOutcomeLabel()`; em-dash for rejected | Geist Mono 13px tone-colored |

**Table header row:** `bg-[#F8F9FA]`, `border-b border-[#E2E8F0]`, text `text-[11px] font-medium uppercase tracking-wider text-[#718096]`. `px-3 py-2` per header cell. Matches PositionsTable `th` styling exactly.

**Table body rows:**

- Hover: `hover:bg-[#F8F9FA] transition-colors` (150ms ease-out per DESIGN.md motion).
- Cell padding: `px-3 py-2`.

**Sort order:** `ORDER BY created_at DESC` (newest first, D-01). No column-sort controls.

**Strategy name links:** `<a>` tag with `href="/strategies/[id]"`, `className="text-[#1A1A2E] hover:text-[#1B6B5A] transition-colors hover:underline truncate block"`. Full-row click does NOT navigate; only the strategy name text is a link (D-04).

### 4. Status Pill Anatomy

Four states. Border-radius 4px (`rounded`). No border. Uppercase 11px DM Sans medium. Inline-block with `px-2 py-0.5`.

| State | Copy | Text color | Background |
|-------|------|-----------|------------|
| Allocated win | `"Allocated 12% — win"` | `#16A34A` | `rgba(22,163,74,0.10)` |
| Allocated loss | `"Allocated 12% — loss"` | `#DC2626` | `rgba(220,38,38,0.08)` |

**Win/loss determination:** resolved from most-mature non-NULL delta sign (D-02). If all deltas NULL, show pending state.
**"Allocated X%"** — X is `percent_allocated` rendered as `{value}%` in Geist Mono within the pill (matches OutcomeRecordedRow.tsx `font-metric tabular-nums` pattern). Pill text is: DM Sans for "Allocated " and "— win" portions; Geist Mono for the percentage number.

### 5. Caret / Expand Toggle

Renders as a `<tr><td colSpan={6}>` beneath the parent row — matches BannerSubRow pattern in PositionsTable.tsx.

**Layout:** 3-column CSS grid (`grid grid-cols-3 gap-4`) with `border-b border-[#E2E8F0] bg-[#F8F9FA] px-3 py-4`.

**Per column (30d / 90d / 180d):**
```
┌─────────────────────┐
│  30d               │  ← DM Sans 11px semibold uppercase header
│  +4.3%             │  ← Geist Mono 13px semibold, tone-colored (prominence via tone color + bold weight + placement)
│  [sparkline chart]  │  ← 48px height, full column width
│   ▬ Original        │  ← legend: muted (#94A3B8) dot + DM Sans 11px
```

**Pending column:** Delta number replaced by `"Pending"` pill (same DM Sans 11px medium, muted `#718096`, `bg-[#F8F9FA]` with border `border border-[#E2E8F0]`). Sparkline replaced by grey placeholder rectangle `h-[48px] rounded bg-[#E2E8F0] animate-pulse`.

### 7. OutcomesSparkline

**Recharts `<LineChart>`** with hidden axes and tight margins — mirrors existing DrawdownChart.tsx / EquityCurve.tsx sparkline-variant pattern (D-07).

```tsx
<ResponsiveContainer width="100%" height={48}>
  <LineChart data={points} margin={{ top: 2, right: 0, bottom: 2, left: 0 }}>
    <Line
      type="monotone"
      dataKey="original"
      stroke="#94A3B8"
      strokeWidth={1.5}
      dot={false}
      isAnimationActive={false}
    />
    <Line
      type="monotone"
      dataKey="replacement"
      stroke="#1B6B5A"
      strokeWidth={1.5}
      dot={false}
      isAnimationActive={false}
    />
    {/* NO XAxis, NO YAxis, NO Tooltip, NO Legend — sparkline style */}
```

**Exact pixel dimensions:** height `48px`, full column width (responsive via `ResponsiveContainer`). Stroke width `1.5px`. No dots. No animation (`isAnimationActive={false}` — data loaded lazily on expand, animation would flash). Source: DESIGN.md data-density principle; DrawdownChart.tsx `strokeWidth={1.5}` precedent.

**Data shape:** both series rebased to 100 at `allocated_at` (D-09). Array of `{ date: string; original: number; replacement: number }` objects.

**Lazy load:** sparkline data fetched only on expand from `GET /api/bridge/outcome/[id]/curves`. Loading state shows `animate-pulse` grey rectangle while fetch is in flight.

## State Matrix

Every state must be fully specified. Source: DASHBOARD-05, DASHBOARD-06, CONTEXT.md D-10.

### State 1: Loading

**Trigger:** Initial widget data fetch in flight (server component hydration or client refetch).

**Visual treatment:**

- KPI strip: three grey `animate-pulse` rectangles replacing the values. `h-4 w-12 rounded bg-[#E2E8F0]` per KPI number; `h-2.5 w-8 rounded bg-[#E2E8F0]` per KPI label.
- Timeline: **5 skeleton rows** (chosen to fill `defaultH: 5` grid height plausibly). Each row `h-[44px] border-b border-[#E2E8F0]`. Inner: `animate-pulse` rectangles at ~25%, 20%, 15%, 20%, 15% widths per column, `bg-[#E2E8F0] rounded h-3`.
- No text copy in loading state.

**Reuse:** `animate-pulse` class from Tailwind — same as existing widget skeleton convention (no external skeleton library). No dedicated `<Skeleton>` component; inline `animate-pulse` divs.

### State 2: Error

**Trigger:** Supabase query throws or returns error code; network failure.

**Visual treatment:**

- Widget body centered: `flex h-full items-center justify-center flex-col gap-3 p-4 text-center`
- Error icon: `⚠` (U+26A0) at 20px, color `#D97706` (warning amber — error is potentially transient / retryable).
- Primary copy: `"Could not load outcomes"` — DM Sans 14px medium, color `#DC2626`.
- Secondary copy: `"Check your connection and try again"` — DM Sans 12px medium, color `#718096`.
- Retry CTA: `<button>` labeled `"Try again"` — Secondary button style: transparent background, `border border-[#1B6B5A]`, text `#1B6B5A`, `text-sm font-medium`, `rounded-md px-3 py-1.5`. On click: re-trigger the data fetch. Source: TileWrapper WidgetErrorBoundary pattern (wraps all widgets); this widget adds its own data-level error state within the boundary.

**Note:** TileWrapper's `WidgetErrorBoundary` catches render-time JS errors (`"Widget error — try removing and re-adding."`). This data error state is distinct — it handles fetch failures at the data layer and offers a retry.

### State 3: Empty

**Trigger:** Fetch succeeds but `bridge_outcomes` table has zero rows for this allocator.

**Visual treatment:**

- Widget body centered: `flex h-full items-center justify-center flex-col gap-3 p-4 text-center`
- Icon: `◈` glyph or simple inline SVG of a clock/sparkle (8×8 grid, muted tone). Keep it minimal — no colored circles (DESIGN.md anti-pattern).
- Primary copy: `"Your Bridge outcomes will appear here after you act on one"` — DM Sans 14px medium, color `#718096`. (Literal from CONTEXT.md §Specifics — locked verbatim.)
- CTA: `"View Holdings"` — Primary button: `bg-[#1B6B5A] text-white`, `hover:bg-[#155A4B]`, `text-sm font-medium`, `rounded-md px-4 py-2`. Links to `/holdings` anchor (the Holdings table widget where the BridgeOutcomeBanner appears). Source: Claude's Discretion resolved to `/holdings` anchor — most direct path to the action.

### State 4: Partial (pending-delta)

**Trigger:** Rows exist but some or all have NULL deltas (cron has not yet run or allocation is < 30 days old).

**Visual treatment:** Normal table renders. No degraded widget state. Per-row handling:

- **Best Available Delta cell:** `deriveOutcomeLabel()` returns `"Pending"` or `"Estimated: +2.1% (3d)"` — rendered in Geist Mono 13px medium, tone = neutral → muted `#718096`.
- **Status pill:** `"Allocated 12% — pending"` (neutral muted pill, as defined in Status Pill Anatomy above).
- **Expanded row, pending window:** grey `animate-pulse` placeholder rectangle for the sparkline; `"Pending"` pill for the delta number. Layout remains 3-column (D-10 — symmetric layout preserved).
- **KPI sub-label:** `"Avg realized delta: +2.3% · 3 pending"` — "3 pending" count = count of allocated rows with zero non-NULL deltas included in the total count but excluded from avg delta calculation (D-14).

## Interaction Contract

### Expand / Collapse Row

1. User clicks caret button on a collapsed row.
2. `aria-expanded` toggles from `false` to `true` on the button.
3. Expanded panel `<tr>` is inserted below the row via `useState<string | null>(expandedId)` — one expanded row at a time (closing previous if another is clicked).
4. Animation: `transition-all duration-150 ease-out` on the expanded panel's height.
5. If sparkline data not yet fetched for this `id`, a client-side fetch to `GET /api/bridge/outcome/[id]/curves` fires immediately on expand.
6. While fetch is in flight: grey `animate-pulse` placeholder in all three sparkline cells.
7. On fetch success: sparklines render. Result cached in a `useRef<Map<string, CurveData>>` per widget mount (session-level in-memory cache — no SWR/react-query; plain ref map matches existing widget conventions for minimal deps).
8. On fetch error: sparkline cells show `"—"` in muted text + `"Retry"` microlink that refires fetch.
9. Clicking the same row's caret again collapses the panel.

### Strategy Name Link

- `<a href="/strategies/[id]">` — opens in same tab.
- Hover: `text-[#1B6B5A] underline transition-colors`.
- Does NOT trigger row expand (D-04 — unambiguous affordances).

### Row Hover

- `hover:bg-[#F8F9FA]` on the `<tr>` — 150ms ease-out transition. Matches PositionsTable row hover exactly.
- Caret button brightens: `#1A1A2E` on row hover.

### Empty State CTA

- `"View Holdings"` button navigates to `/holdings` page anchor. Uses Next.js `<Link>` component (no native `<a>` in App Router pages).

### Retry Button (error state)

- Triggers re-fetch by calling the widget's data-load function (planner picks the exact mechanism; could be `router.refresh()` or a `useState` trigger).

```ts
{
  outcomes: Array<{

    kind: "allocated" | "rejected";
    percent_allocated: number | null;
    allocated_at: string | null;   // YYYY-MM-DD
    rejection_reason: string | null;
    delta_30d: number | null;
    delta_90d: number | null;
    delta_180d: number | null;
    estimated_delta_bps: number | null;
    estimated_days: number | null;
    needs_recompute: boolean;
    created_at: string;
    original_strategy: { id: string; name: string } | null;   // from match_decision_id join
    replacement_strategy: { id: string; name: string } | null;
  }>;
}
```

### `GET /api/bridge/outcome/[id]/curves` response:

```ts
{
  original: Array<{ date: string; nav: number }>;   // rebased to 100 at allocated_at
  replacement: Array<{ date: string; nav: number }>;
}
```

The merged `{ date, original, replacement }` array for Recharts is assembled client-side after the lazy fetch.
