### Phase 62: Explicit Draft Series Membership (schema v4)
**Goal**: Saved scenario drafts are self-describing about which series they blend — membership is a persisted per-key id list, not inferred from the runtime gate or the ephemeral `entryMode`.
**Depends on**: Nothing (first phase of the milestone; pure additive — must land before Phase 63 so the deletion has a persisted selector)
**Requirements**: MEMBER-01, MEMBER-02, MEMBER-03, MEMBER-04
**Success Criteria** (what must be TRUE):
  1. A saved draft round-trips an explicit per-key series-id membership list alongside `addedStrategies`, at `SCENARIO_SCHEMA_VERSION` 4.
  2. Reopening a v3 draft upgrades NON-destructively — membership derived from today's gate rule on open, no saved scenario dropped (same pattern as v1.5's `upgraded_v2_windowless` codec branch).
  3. Compare distinguishes blank-authored drafts from book drafts by persisted membership — a blank draft NEVER has the live book merged into its column (closes red-team F5); `entryMode` stops being load-bearing for saved drafts.
  4. Share mint and share-resolve read the SAME membership field — "book-only" is defined once (membership containing only per-key ids) across mint/resolve/compare.
  5. Reopening a draft whose persisted member key is no longer eligible DISCLOSES the drop via provenance-note mechanics — never a silent recompute over a different member set.
