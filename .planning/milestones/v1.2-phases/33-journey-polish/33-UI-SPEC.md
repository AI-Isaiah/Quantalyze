>

This contract specifies **interaction contracts** (JOURNEY-01), **a consistency target over 4 inventoried surfaces** (JOURNEY-02), and **acceptance criteria for an a11y verification** (JOURNEY-03). ## Interaction Contracts (Phase-33 specifics)

### JOURNEY-01 — Bridge → composer continuity (VERIFY the existing seam; wire at root ONLY if proven dead)

- **The seam already exists and is structurally wired:** `BridgeDrawer.onAddToScenario(holdingScopeRef, candidate)` → `scenario.addStrategyBridge(...)` (pure mutator: the swapped holding keeps its weight, the candidate takes it, others renormalize to 1.0) → composer handler at `ScenarioComposer.tsx:2328–2347`, which also lazy-fetches the candidate's returns so the projection moves on add (UNIFY-04).
- **The reachability hinge (the FLOW-01 / shipped-but-dead risk):** ONLY the composer-owned `BridgeDrawer` (`ScenarioComposer.tsx:2328`) passes `onAddToScenario`. `BridgeWidget`'s own `BridgeDrawer` instances do NOT pass it (BridgeWidget.tsx:278-283/317-322/377-382), so they cannot seed the draft. **The contract is: prove the user-reachable path delivers the candidate into the draft AND updates the projection.** If the live `/allocations?tab=scenario` surface cannot reach the seeding drawer, fix the wiring at root (Rule 6 — no bandaid).
- **Interaction contract for the affordance:** per-candidate add via the drawer confirm stage only — **no batch-add** (sprawl / BRIDGE-02 v2). CTA label "Add to scenario" sits alongside "Send intro" in the confirm stage. One click adds one candidate; the drawer may stay open or close per existing behavior — do not change the dismissal contract (Esc / backdrop / × → `onClose`).
- **Confirmation feedback contract:** a non-blocking `role="status" aria-live="polite"` confirmation ("Added to your portfolio.", muted neutral, transient) AND the candidate visibly appears in the composition list AND the projection recomputes. The visible draft change is the load-bearing proof; the toast is reinforcement.
- **No new persistence:** the added candidate lands in the in-memory draft and saves via the existing `scenarios` path. No migration, no schema change, no new callback type, no new state machine.
- **Proof (downstream-planner contract):** a NON-VACUOUS regression test that fails if the seam is neutered (candidate must appear in the draft + the projection must reflect it), plus end-to-end reachability coverage. A test that only asserts the callback type exists is vacuous and does not satisfy this gate.
