# Phase 30 — UI Design Contract

> Visual and interaction contract for **Factsheet Graphs on the Blend**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a reuse-first unification phase, not a redesign.** Phase 30 adds three factsheet-grade graph surfaces to the BLENDED portfolio inside the Phase-29 unified composer (`ScenarioComposer` at `/allocations?tab=scenario`): a returns-distribution view (GRAPH-02), rolling Sharpe / volatility / Sortino (GRAPH-03), and a visual-identity alignment of the already-shipped equity + drawdown charts to the DESIGN.md factsheet chart stack (GRAPH-01). Every new panel self-discloses its method / overlap-N / horizon and shows an honest empty state below the sample floor (GRAPH-04). All series come from ONE new pure-TS adapter `src/lib/scenario-blend-panels.ts` off the frozen engine's `portfolio_daily_returns`.
>
> **Every token below is sourced from `DESIGN.md` (LOCKED), `src/components/charts/chart-tokens.ts` (the shared factsheet chart-stack visual contract), and `29-UI-SPEC.md` (the composer chrome contract this builds on).** Do NOT invent new chart styles, new tokens, or new layouts. Reuse the factsheet LEAF charts (plain-prop) and their existing DESIGN.md chart-stack treatment.
>
> **Out of scope for Phase 30 (do NOT spec or build here):** the graphs-lead / collapsible layout (Phase 31 — Phase 30 just ADDS the panels in a reasonable position in the projection region; it does NOT reorder to graphs-lead or add collapsibility), `/scenarios` retirement (Phase 32), Bridge→composer continuity + full WCAG-AA audit (Phase 33), exposure / turnover on the blend (v2 — EXPO-01). **Peer / percentile / signature ranking of the blend is a LOCKED honesty invariant — never shown on any panel.**

**Accent reserved for (explicit — never "all chart elements"):**
1. The blended-portfolio series stroke in the rolling charts (`RollingVolatilityChart`, `RollingSortinoChart` strokes = `CHART_ACCENT`; the 365d Sharpe line = `CHART_ACCENT` via `STROKE_BY_KEY`) — the blend IS the verified-engine-derived primary series, so the accent identity holds.

## Adapter contract — `src/lib/scenario-blend-panels.ts` (the one new file)

Pure TS, zero deps, zero fetch, zero DOM/time reads. Consumes `scenarioMetrics.portfolio_daily_returns` (full-res, UNROUNDED — never the rounded `equity_curve`). This is a derivation contract, not a visual one, but it is load-bearing for the honesty invariant and is pinned by `scenario-blend-panels.test.ts`.

**Convention pins (LOCKED exit gate — must match the frozen engine, 252-day annualization product-wide):**
- Rolling volatility = sample-std × √252.
- Rolling Sortino = windowed mean × 252 ÷ (downside-RMS over the TOTAL window n × √252) — divide the downside RMS by the total window n, mirroring the engine.
- Rolling Sharpe = windowed mean × 252 ÷ windowed annualized vol.
- **NO `√365` / `*365` / `√250` anywhere.** 252-day annualization only.
- Histogram buckets + quantile set defaults: mirror the factsheet leaf charts' existing defaults (`ReturnHistogram` `bins = 20`; quantile periods follow the leaf `ReturnQuantiles` 5-number-summary `[q0, q25, q50, q75, q100]` shape).
- **Degenerate windows return `[]`** — `series.length < window`, fewer than 10 usable points, or any non-finite value → empty series (drives the honest empty branch, never a fabricated flat line).
- The adapter reads `portfolio_daily_returns` only; it never imports the engine internals, never edits `scenario.ts`, never calls a Python endpoint.

**Rolling window default (Claude's discretion, resolved):** default the rolling window to **63 trading days (≈ one quarter)**, with the 3M/6M/12M `SegmentedControl` offering 63 / 126 / 252-day windows. 63d yields a non-trivial series above the sample floor for typical `portfolio_daily_returns` lengths while staying on the 252-annualization basis. Final window-day mapping is the planner/executor's to confirm against the measured typical series length; this default stands unless that pass surfaces a shorter typical history.
