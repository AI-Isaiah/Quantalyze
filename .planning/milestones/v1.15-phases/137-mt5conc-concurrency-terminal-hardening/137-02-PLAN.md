<objective>
MT5CONC-02 — the trust-integrity core of the phase: cross-account contamination on the
ONE shared terminal is made structurally impossible. Two deltas: (1) a MODULE-LEVEL
per-terminal `asyncio.Lock` registry (keyed `host:port`, mirroring
`position_reconstruction.py:308-317`) serializing every terminal-IPC region in-process;
(2) an `account_info().login == expected_login` bracket asserted pre+post the read —
a mismatch fails loud, restarts the terminal (bounded, per resolved decision A3),
classifies transient, and persists NOTHING. This is the structural guarantee that
`api_verified` is never stamped on the wrong account's numbers — the whole point of
the phase.

list, PLUS (from 137-01, this plan's dependency): `Mt5Client.restart()`,
`_MT5_RESTART_TIMEOUT_S`, and the module-level `_mt5_bounded_restart(client)` helper —
the mismatch branch REUSES that helper, it never re-implements the bounded restart.

Locked decisions honored here: lock is MODULE-LEVEL keyed by host:port, never
Session-attached (each job builds a fresh Mt5Session — a Session lock serializes
nothing); mismatch disposition = TRANSIENT + restart + persist-NOTHING, no user-blame
stamp (A3); expected_login = Mt5Session.login (the parsed api_key slot,
mt5_validation.py:75); the offline double gains a "login" field (A2 — live field name
confirmed in Phase 139); cross-replica serialization is a documented v1 gap with the
bracket as the cross-process net.

Purpose: MT5CONC-02 — one-terminal-one-account cross-bleed impossible.

```python
_RECONSTRUCT_LOCKS: dict[str, asyncio.Lock] = {}

def _lock_for(strategy_id: str) -> asyncio.Lock:
    # setdefault is atomic across coroutine resumption — no await between
    # lookup and insert, so two simultaneous first-callers cannot end up
    # with two different Lock objects for the same key. Single-event-loop safe.
    return _RECONSTRUCT_LOCKS.setdefault(strategy_id, asyncio.Lock())
```
