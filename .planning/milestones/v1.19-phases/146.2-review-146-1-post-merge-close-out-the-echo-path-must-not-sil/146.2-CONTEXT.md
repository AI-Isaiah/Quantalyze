## Roster

### R1 — BLOCKER. The echo path drops classification on the recovery A3 instructs
`src/app/api/strategies/csv-finalize/route.ts:1923`

Found by **both** reviewers independently. Orchestrator-verified: `applyCsvMetadataUpdate` runs
AFTER the fold commits and returns **400** on a parse failure (`:1430-1445`); the call is gated
on `outcome.fresh` (`:1923`).

Chain:
1. Fold RPC commits → connection dies before `:1923` (A3 CLASS 2 `{error:{code:""},status:0}`)
   or the lost-id 2xx (CLASS 3). Strategy is committed with **zero** metadata applied.
2. A3's new copy tells the user: *"submit the same file again — an unchanged resubmit from this
   wizard resolves to the strategy you already started."*
3. They do. 23505 → resolve arm → name/status/count/boundaries all match → echo, `fresh:false`,
   **200 "saved"**.
4. `:1923` skips the UPDATE. `:1938` **still enqueues the compute.**

Permanent consequence — this is the part that makes it a blocker:
- `asset_class` stays at the column default. `20260709130000_strategies_asset_class.sql:26` is
  `NOT NULL DEFAULT 'traditional'`, and `services/metrics.py:45` returns **252** for anything
  ≠ `'crypto'` (`services/analytics_runner.py:1214,1399-1400` read it).
  ⇒ **a crypto CSV track record is annualized √252 and published as "Verified".**
- **No post-creation editor for `asset_class` exists** ⇒ irreversible by the user.
- `category_id = NULL` additionally leaves it invisible to discovery (route's own WR-04 docblock).

Pre-A4 the echo re-applied metadata and **healed** this.

⭐ **Why A4's own suite could not catch it:** every arm in
`csv-finalize-cross-submission-merge.test.ts:1098-1177` echoes against a row **assumed already
classified**. The sibling test at `:1163` deliberately KEEPS the enqueue on echoes for exactly
the "first attempt lost its side effect" reason — that argument was never applied to metadata.

Proposed forward fix (from the review; validate at plan time): extend the resolve arm's existing
`.select()` to carry `category_id, asset_class`; **FILL** when the committed classification is
absent; **REFUSE** (409, existing `CSV_SESSION_REUSED`) when a present one conflicts. That is
A2's own logic applied to the second identity field. A4's original intent (don't honour a
mutation the user never asked for) is preserved by the refuse arm.

## ⭐ THE CRUX — orchestrator-verified before planning (2026-08-19)

**R1 is NOT "delete the `outcome.fresh` gate".** A4's gate exists for a real economic reason
that is pinned by a test the fix must not break. Two constraints are in tension:

- **A (R1):** a row committed with NO classification must receive the user's classification on
  the recovery resubmit, else a crypto record is annualized √252 and published "Verified".
- **B (A4's economic oracle, `src/__tests__/csv-finalize-cross-submission-merge.test.ts:1132`):**
  an echo must NOT overwrite a PRESENT-and-different `asset_class` — the committed row's stored
  Sharpe/Sortino/CAGR were computed on the OLD convention and nothing recomputes them.

FILL-when-absent / REFUSE-when-conflicting satisfies both **only if "absent" is decidable.**

**MEASURED against PROD `information_schema`:**

    strategies.asset_class : NOT NULL DEFAULT 'traditional'   ← "never classified" is
    strategies.category_id : nullable                            INDISTINGUISHABLE from
                                                                 "user chose traditional"

⇒ Filling on `asset_class='traditional'` would overwrite a LEGITIMATE traditional
classification — precisely what B forbids. The research recommends `category_id IS NULL` as the
never-classified discriminator (the two fields are written by ONE atomic UPDATE, and the wizard
always sends `category_id`). **Ratify or replace that discriminator deliberately — it is the
load-bearing choice of this phase.**

### ⚠️ Refinement the orchestrator verified — the FILL-safety argument has a hole

RESEARCH argues FILL is safe because the echo path already re-enqueues, so KPIs recompute under
the filled clock. **Verified TRUE — but not universally.** `route.ts:1938` gates the enqueue on
`args.dailyReturnsSeries.length > 0`, and `fmt='trades'` produces **no series**
(`route.ts:1652-1655`: "fmt='trades' currently produces no series … and is intentionally
exempt"). So on a `trades` echo the clock would change with **no recompute following it** —
reintroducing the exact hazard B guards.

**Governing principle for the plan: never change the annualization clock without guaranteeing
the recompute that reconciles it.** Whether `trades` strategies carry stored KPIs at all is the
open question that decides whether this is a live hazard or a vacuous one — the planner must
settle it with evidence, not assume it either way.

### Test-suite consequence — do not miss

`csv-finalize-cross-submission-merge.test.ts:1115` ("an ECHO issues NO metadata UPDATE at all")

The economic-oracle arm at `:1132` must **SURVIVE UNCHANGED** — it is the guard on constraint B.
