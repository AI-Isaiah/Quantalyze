## Decisions Made

- **Structural over literal.** Adding `body.passphrase` to the array would have closed today's instance and left the mechanism — two hand-maintained lists over one set — intact. The tuple removes the mechanism. This is the plan's own must-have truth #2.
- **Filter over per-member conditional.** The old `if (body.passphrase !== undefined)` is generalised to `Object.entries(...).filter(([, v]) => v !== undefined)`, so the omission rule is not re-typed per credential. Wire bytes are unchanged: `process-key-client` `JSON.stringify`s the context and JSON drops `undefined` either way (verified at `src/lib/process-key-client.ts:517`).
- **PR-X5 preserved and restated.** The spread is over an object whose keys are literals written in the route, never keys taken from the caller's body — it cannot widen the allowlist. The new WIRE SIDE case asserts the exact five-key context, so a future widening reds.
- **No sweep.** Exactly two `perRequestSecrets` sites exist in `src/`; the sibling `keys/validate-and-encrypt/route.ts:401` already names all three credentials. Scope held to the instance.
