**THE CRUX — discriminator RATIFIED: `category_id IS NULL` is the never-classified marker.**
Justification (all verified at HEAD): `asset_class` is `NOT NULL DEFAULT 'traditional'`
(`supabase/migrations/20260709130000_strategies_asset_class.sql:26-27`), so on that column
"never classified" and "user chose traditional" are the SAME stored value — filling on
`asset_class='traditional'` would overwrite a legitimate user choice, which is exactly what the
economic oracle forbids. `category_id` has no default, the fold's INSERT never writes it,
`applyCsvMetadataUpdate` writes both fields in ONE atomic UPDATE (`route.ts:1455-1459`), and the
wizard always sends `category_id` (an explicit null is 400-refused pre-create, `route.ts:353-359`).
Therefore `category_id IS NULL` on the committed row is observable proof the metadata UPDATE
never ran. The plan MUST NOT key FILL on `asset_class`.

   writer writes status/error/flags but NO KPI columns (`:1283-1291`).
   ⇒ stored KPIs on a zero-dailies row are a HISTORICAL, per-row-MEASURABLE fact — not a
   structural impossibility. KPI absence must be measured, never assumed.
2. The resolve arm's series-equality check (`route.ts:1060-1135`) guarantees payload ≡ committed
   series, and an empty payload echoes only when the committed series is empty too
   (`:1076-1080`). ⇒ enqueue fires on the echo ⟺ committed dailies exist.

Therefore FILL is clock-safe in two DIFFERENT ways, one per arm:
- **Series-bearing echo → unconditional FILL** (as before): the enqueue at `:1938` fires after
  the awaited UPDATE, so stored KPIs recompute under the filled clock.
- **Empty-series (trades) echo → THE CLOCK-SAFETY GUARD** (chosen rule: plan-check option (i),
  REFUSE variant): one owner-scoped read of the strategy's `strategy_analytics` row selecting
  the seven ranked KPI columns — `cagr, sharpe, sortino, calmar, max_drawdown, volatility,
  cumulative_return`, the exact set `PERCENTILE_ANALYTICS_COLUMNS` folds into rankings
  (`queries.ts:126-127`). Row absent, or present with all seven null → FILL both fields, no
  enqueue: nothing exists that the missing recompute could leave stale, and that absence was
  MEASURED on this request. ANY of the seven non-null → REFUSE 409 via `refuse()` with an
  arm-specific sentence: ZERO metadata writes — the clock does not move over unreconciled
  stored KPIs, and the row is not promoted into discovery (a `category_id` write would make its
  stale sqrt(252) numbers reachable in listings and percentile ranks). Guard-read ERROR →
  failClosed: unconfirmable clock-safety is not a license to write.

Why (i)-REFUSE and not option (ii) (`category_id`-only FILL on empty series): (ii) permanently
drops the user's `asset_class` on EVERY trades echo — no post-creation editor exists — which
reintroduces the R1 defect family on that arm for all users, and it still promotes the
historical failed-with-KPIs rows into rankings. (i) preserves the full R1 remedy for every case
reachable under current code (placeholder rows carry no KPI values, so the guard measures
absence and FILLs) and is fail-loud on exactly the measured 7-row historical class, at the cost
of one owner-scoped read on a rare arm. Why REFUSE rather than a `category_id`-only partial
fill on the KPI-present arm: the partial write would CREATE the discovery visibility that makes
a stale failed-computation KPI reachable in rankings, and half-applying a classification is a
silent partial drop — this phase's charter is that the echo path must not silently drop
anything. Governing principle unchanged and extended: **never change the annualization clock
without guaranteeing the recompute that reconciles it — and never promote a row into a ranking
surface whose stored KPIs were computed under a different clock.**
