## R6 — what was actually broken

146.1 / C1 attached `human_message` to the 23505 resolve echo: the founder-chosen sentence
that states **what the route compared** (the saved track record's row count and its first and
last dates) and **what it did not** (the individual daily values), then instructs the user to
open the strategy and check. `CsvSubmitStep` read `human_message` inside `if (!res.ok && …)`
only. A 200 with `ok: true` fell straight through to `onSubmitted(strategy_id)`, which
`WizardClient` hooks to `clearWizardState()` + `router.push('/strategies')`.

So the sentence was computed server-side, serialised, sent over the wire — and rendered
nowhere, on every echo, since 146.1. A mitigation the user cannot read is not a mitigation.
It was a **non-regression**: no test could have caught it, because no test asserted a
success-path consumer existed.

### The discriminator, and why it is not `res.ok`

```ts
if (data.ok === true &&
    typeof data.human_message === "string" &&
    data.human_message.trim().length > 0)
```

Control only reaches this point on a success — every error arm returned above — so
re-testing `res.ok` buys nothing and would **exclude** the legacy 409-with-`ok:true`
idempotent shape (`isIdempotentSuccess`, NEW-C14-01), which is also a success. A success that
carries a sentence must show it; that is the whole requirement. The route spreads
`human_message` in **only** when `resolveExistingCsvStrategy` supplies it, so a fresh create
carries no such key and falls through to the unchanged auto-continue.

### The product call, taken and stated

The plan pre-decided option (a) — render in-step. Executed as specified, plus the two
consequences the plan did not spell out:

- **The step HOLDS.** `onSubmitted` is deferred to an explicit Continue. Auto-navigating on
  the one response whose copy says *"open the strategy to check it holds the numbers you
  meant to upload"* would tear the wizard down before the user finished the sentence.
- **The submit CTA is RETIRED, not disabled.** Leaving `submitting = true` would have left a
  dead `Submitting…` button on screen — a lie (the submit is done) and a banned disabled
  button (v1.11 UAT direction). Leaving it *live* would put a second, contradictory primary
  affordance beside a sentence saying the strategy is already saved, inviting a resubmit that
  can only echo again. So while the notice stands the footer is `[Back] [Continue]`.
- **`wizard_step_complete_3` still fires at response time on both arms.** Step 3 completed
  either way; only the navigation defers. Gating it on the notice would have silently dropped
  a completion event for every echoed submit.

### The render vehicle — DESIGN.md, applied

The pattern-mapper found no existing success-path `human_message` consumer anywhere, so this
is a genuinely new surface. DESIGN.md **does** settle it; the reasoning is recorded verbatim
at the render site:

| Question | DESIGN.md rule | Resolution |
|---|---|---|
| Error envelope? | *"every error path MUST call `buildEnvelope`"* governs **error** paths; `ErrorEnvelope`'s shell is `role="alert"` + `border-negative/30 bg-negative/5` | **No.** This is a 200. Red is *"permanent / negative only"* and the strategy IS saved — red would be a false statement about the user's data, in the phase whose subject is false statements |
| Which tone? | Semantic-color gates, as widened 2026-07-02: amber = *"transient/recoverable — whether the system or a disclosed one-click user action performs the recovery"* | **Amber.** The residual uncertainty is resolved by exactly such a disclosed action (open the strategy and check). Muted would say "nothing to flag" (false); red would say "broken" (false) |
| Which shell? | Cards vs data panels; no colored-left-border (AI-Slop Ban row); no decorative icon/emoji | `rounded-md border border-warning/30 bg-warning/5 px-4 py-3` — **verbatim from the nearest existing pattern**: `WizardIpAllowlistHint`, `WithdrawalWarningStrip` and `/security`'s banner all use exactly this |
| Which ARIA? | DESIGN-05 a11y minimums: `role="alert"` on **blocking errors**; `role="status"` + `aria-live="polite"` on **non-blocking state changes** | `role="status"` + `aria-live="polite"` — announced without stealing focus |
| Copy? | Voice: declarative, states the fact | The wire sentence **verbatim**, no client-authored heading. The SEAMUX-04 register lives server-side; re-voicing it here would fork the copy |
| Body colour | DESIGN.md measures amber-700 at 4.56:1 on `bg-warning/5` | `text-text-primary` (near-black), not the strips' `text-text-secondary` — this is the response's primary content and the a11y floor should not rest on the tinted fill |

**No deviation from DESIGN.md was needed.** `WarningBanner` (`src/components/ui/WarningBanner.tsx`)
was considered and NOT used: it forwards no `role`/`aria-live`/`data-testid`, and widening it
would touch a shared component outside this plan's ownership for a one-call-site need.

## The declined option, recorded as instructed

A static gate coupling the two files — grep `route.ts` for each constant and red if absent —
would make the provenance claim mechanical instead of documentary. **Not added**, per the
plan's explicit instruction and the stopping rule (prose/provenance findings are logged, not
forced). Two honest costs of declining: (1) the pair can drift a third time silently; (2) the
mechanical check exists only as a scratchpad script run once, recorded above. If it drifts
again, that gate is the fix to reach for — and the file now says that too.

## Decisions Made

- **In-step render with an explicit Continue** (the plan's pre-taken product call), plus the
  two consequences above: the step holds, and the submit CTA is retired rather than disabled.
- **Amber, not red**, per the semantic-color gates as widened 2026-07-02. Stated at the render
  site with the reasoning, so the next editor does not "fix" it into an error panel.
- **The discriminator is the body, not the status**, so the legacy 409-with-`ok:true` success
  shape is included rather than silently excluded.
- **W1's constants stay hand-typed**, and the file now states what that choice does and does
  not buy.
