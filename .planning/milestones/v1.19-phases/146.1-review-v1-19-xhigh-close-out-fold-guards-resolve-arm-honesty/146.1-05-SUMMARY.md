# Phase 146.1 Plan 05: route.ts serial cluster, second half (A4 → A3 → C2) Summary

Three corrections to what the CSV finalize route DOES and what it SAYS: an
echoed submission no longer rewrites the committed strategy's annualization
clock, the failure arm stops asserting a rollback it did not observe, and the
two token-identical handlers become one. Every changed gate was observed RED
under a named neuter, with the failure text captured verbatim.

## What changed

### A4 — the metadata UPDATE belongs to the create, never to its echo (`a4d0a26e`)

`FinalizeAtomicOutcome`'s ok-arm gained a **required** `fresh: boolean`, set
`true` at the fold's create return and `false` at the 23505 resolve echo. Both
handlers now call `applyCsvMetadataUpdate` only when `fresh`.

**The economic argument, which is why this is the money-math half of the
roster.** `buildMetadataUpdatePayload` copies `asset_class` verbatim, and
`asset_class` IS the annualization clock — √365 for crypto, √252 for
traditional (#597 part 2). The KPIs (Sharpe, Sortino, Calmar, CAGR) are
computed by the analytics worker from the dailies the FIRST submission
committed, under the clock THAT submission declared. A same-series retry with a
flipped picker value therefore relabelled the row while every persisted number
kept the old convention: a Sharpe computed on 252, displayed as a 365 crypto
track record. Nothing reconciles the two, and for `fmt='trades'` the enqueue
gate (`dailyReturnsSeries.length > 0`) means no recompute is even scheduled, so
the mismatch is permanent.

**Required, not optional** — the plan's F-05-2 is an inverted neuter and it was
run: with `fresh` optional and the create-path construction site DELETED,
`npm run typecheck` stays **GREEN**. That silence is exactly what requiredness
prevents.

**Skip, not "re-enqueue after".** `enqueueCsvAnalyticsAfter` and its
`length > 0` gate are untouched; both fresh and echo paths still enqueue. The
`fmt='trades'` no-enqueue behaviour is pre-existing and was not touched.

⚠️ **Two pre-existing echo positives changed from `updateCalls` length 1 to 0.**
Those lines encoded the defect. Both are annotated in place with the reason.
The A2 positive counterparts still assert 200 + echoed id + echoed status, so
they still discriminate a refuse-everything arm.

**Harness change:** the test file's `after()` mock was a no-op, so the enqueue
side effect was invisible to every case in it. It now RECORDS callbacks
(behaviourally identical by default) and the admin `rpc` is a hoisted stable
mock, so "was the compute job actually enqueued?" is assertable — which is what
lets A4 prove it gated ONE side effect and not the fan-out.

## Deviations from Plan

### 1. [Rule 1 — Bug] F-05-4's named neuter did not RED, and the gap was real

- **Found during:** Task 2 verification.
- **Issue:** the plan predicts that replacing the length check with
  `if (error?.code)` flips the class-2 fixture into class 1's copy. It does
  not, against the shape I wrote: this arm's SECOND branch tests `error`
  PRESENCE, not `error.code`, so an empty-string code still lands on
  `transport-unknown`. **The neuter ran GREEN.** The plan assumed a two-way
  branch; I had written a three-way one that happens to be robust to exactly
  that collapse.
- **But the coverage gap was genuine.** A **non-empty, non-5-character** code
  discriminates the two implementations: PostgREST emits its own `PGRST301` /
  `PGRST116` / `PGRST002`, which are **not SQLSTATEs** — they mean PostgREST
  itself refused or failed, so we were never told the fold ran and raised.
  Under truthiness those get "nothing was saved — the submission rolled back
  completely", the same fabricated observation A3 exists to delete.
- **Fix:** added the `PGRST301` fixture. Re-ran A3-TRUTHY → **RED**. The
  reasoning is written into the test, including the fact that the class-2
  fixture alone measured GREEN.
- **This is recorded rather than quietly reported as "F-05-4 observed".**
