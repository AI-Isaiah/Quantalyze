Copy, in order:

**(a) Header block — the delta-list style.** `20260819120000:1-147` is the canonical shape: `Why this migration exists` → `RE-BASE ENUMERATION (house law, 20260728120000:186-195)` → `EXACT delta list from the parent body` (numbered, each item citing `file:line` of the source it copies/adapts/drops) → `>>> READ THIS BEFORE SIMPLIFYING <<<` → `ERRCODE map` → PROD auto-apply warning → `Gates (all in this same commit — the 144-§8 rule)` → `Manual rollback`.
The re-base sentence to imitate verbatim in form (`20260728120000:186-195`):

```sql

-- ...
-- EXACTLY ONE change from that body: ...
-- Unchanged: the terminal-status guard, both auth-identity guards, the fmt
```

For 146.1 the LATEST body is `20260819120000:204-342` and the delta is: add a NULL guard on `p_rows`, and scope the empty-array allowance to `p_fmt = 'trades'`. The header must state that `20260819120000:283-285`'s "NOTE the parents' empty-array raise is deliberately ABSENT" comment is being *narrowed, not reverted*, or the next reader re-litigates it.

**(b) `BEGIN; SET lock_timeout = '3s';`** — `20260819120000:149-151`. (Cron migrations use `'5s'`; `20260816140000:597`. Match the neighbour, not the other family.)

**(c) STEP 0 pre-flight DO block** — `20260819120000:164-199`. Fail-loud arity/state check with an **honesty paragraph** naming what the pre-flight canNOT prove (`:157-163`). Message form: `'145 FOLD ABORT (STEP 0): expected exactly one 6-arg …, found % - this database is not in the <ts> state this migration was authored against …', v_cnt`.

**(d) The guard statements themselves** — `20260819120000:225-281`. Each guard is `IF <cond> THEN RAISE EXCEPTION '<fn_name>: <what> %', <val> USING ERRCODE = '22023'; END IF;` with a `-- (parent: <file>:<lines>, verbatim)` provenance comment. Auth guards use `'42501'`. Note `:236-237`: message literals pinned by a SQL gate carry "change both together or not at all".

The two new A1 guards therefore read (shape, not final text):

```sql

  -- comparison, so a NULL argument passed all of them and committed a
  -- zero-dailies strategy the 143 sweep structurally cannot heal
  -- (its EXISTS(csv_daily_returns) conjunct, 20260816140000:723-727).
  IF p_rows IS NULL THEN

  -- 20260522111839:166-168, re-admitted for every non-trades fmt).
  IF jsonb_array_length(p_rows) = 0 AND p_fmt <> 'trades' THEN
    RAISE EXCEPTION '…' USING ERRCODE = '22023';
  END IF;
```

**(e) GRANT/REVOKE re-assertion after `CREATE OR REPLACE`.** `20260728120000:311-315` states the rule and `20260819120000:352-353` restates it after DROP:

```sql
-- Grants restated verbatim from <parent>:<lines>. CREATE OR REPLACE
-- [preserves ACLs, but restating keeps this file] self-contained and keeps the
-- anon REVOKE auditable at this file.
REVOKE ALL ON FUNCTION public.finalize_csv_strategy_with_returns(UUID, UUID, TEXT, TEXT, JSONB, TEXT) FROM PUBLIC, anon;
GRANT EXECUTE ON FUNCTION public.finalize_csv_strategy_with_returns(UUID, UUID, TEXT, TEXT, JSONB, TEXT) TO authenticated;
```

⚠️ `CREATE OR REPLACE` **keeps** ACLs (unlike DROP+CREATE, `20260601120000:32`) — restate anyway for auditability, but do not write the fold's DROP-specific "DROP FUNCTION loses ACLs" justification, which would be false here. `20260813150106:69` is the house citation for "CREATE OR REPLACE, never DROP+CREATE".

**(f) `COMMENT ON FUNCTION` upkeep.** `20260819120000:355-369` — the comment carries the full ERRCODE map, the grant rationale and the gate list. A1 changes the ERRCODE map (`22023` gains "NULL p_rows / empty rows for a non-trades fmt"), so the COMMENT must be re-issued in the same migration; a stale COMMENT is the documented drift hazard.

**(g) STEP N self-verify DO block — COMMENT-STRIPPED BOUNDED REGEX, the new house rule.** `20260819120000:375-495`. Checks (a)–(g): overload count / `prosecdef` / `pronargs`; `has_function_privilege('authenticated'…)` present and `('anon'…)` absent; then `pg_get_functiondef(...::regprocedure)` into `v_fn_src`.

The rule, stated at `:444-454` and re-proven on TEST 2026-08-18:

```sql
  v_code := regexp_replace(v_fn_src, '--[^\n]*', '', 'g');
  IF v_code !~ 'jsonb_array_length\(p_rows\)\s*>\s*5000\M' THEN
    RAISE EXCEPTION '145 FOLD: the guard statement "…" is gone (deleted or widened) - …';
  END IF;
```

Do **not** use `v_fn_src NOT LIKE '%…%'`: a substring gate false-PASSes on a widened literal and on a deleted guard whose comment still names it. The `\M` (end-of-word) or a `([^0-9]|$)` alternation is mandatory on any numeric literal — see `20260816140000:876` `IF v_command !~ 'LIMIT[[:space:]]+25([^0-9]|$)'` and its "the `|$` arm is required, not decorative" note. Two of the fold's checks ((c), (g) at `:431-442`, `:481-492`) still use fragment-scoped `strpos` + `LIKE`; that is acceptable **only** because the fragment is anchored between two `strpos` anchors and the anchor-drift case RAISEs ("FIX THE ANCHORS rather than deleting this check"). New checks should prefer the regex form.

Every self-verify RAISE **names the consequence**, not the missing token (`20260816140000:778-780` states this as law).

Close with `RAISE NOTICE '<tag>: … is live (…)';` (`20260819120000:494`).
