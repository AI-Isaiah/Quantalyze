## Overview

v1.2.1 unified every exchange API key's stats through the ONE CSV → `compute_all_metrics`
path (per-key dailies, 252-unified annualization) so Overview, Scenario, and factsheets read
the same honest source, and finished the scenario composer's convergence onto the factsheet.
The journey: make the annualization basis **explicit at the call site** (default 252 unified,
the `equity_reconstruction`@365 vs `compute_all_metrics`@252 ×1.20 mismatch resolved by
converging to 252) (34); stand up a **per-key dailies foundation** (`csv_daily_returns` gains
an `api_key_id` axis, the derive job generalizes to allocator-key-scoped realized+funding
dailies, existing keys backfilled, RLS-reviewed) (35); **repoint the stats reads** so the
Overview equity curve + KPIs blend the per-key dailies through the frozen `computeScenario`
engine while live HOLDINGS stay on the poll/snapshot path (36); surface an **honest
per-data-source toggle** in the composer (per-`api_key` projection units; excluding a key
honestly recomputes the curve + KPIs from the remaining per-key series, never a cosmetic hide)
(37); and bring the composer to **factsheet parity** (the scenario equity + drawdown reuse the
real factsheet `TimeSeriesChart` + `MasterBrush` under one `persist={false}` provider at 1440
width) **+ a blank-mode fix** (blank-slate renders the scenario overlay) (38).

Additive client-TS/TSX + Python over the **frozen** `src/lib/scenario.ts` engine. Phase 35
shipped the milestone's one storage migration (per-key `api_key_id` axis with an RLS review);
every other phase is zero-DDL. The no-invented-data and no-peer-ranking-a-hypothetical-blend
invariants stayed LOCKED throughout.

## Phases

### Phase 34: Asset-class-aware annualization

**Goal:** `compute_all_metrics` makes the annualization basis explicit at the call site (default
252 unified), and the `equity_reconstruction`@365 vs `compute_all_metrics`@252 ×1.20 mismatch is
resolved by converging to 252.
**Depends on:** Nothing (first phase of this milestone)
**Requirements:** ANNUAL-01..05
**Plans:** 2 · **Status:** Complete (2026-06-24)

Threaded an explicit `periods_per_year: int = 252` (one `DEFAULT_PERIODS_PER_YEAR` constant)
through every genuine annualization site in `metrics.py` — the explicit `np.sqrt(252)`/`*252`
sites AND the quantstats sharpe/sortino/volatility/cagr calls — keeping default-252 output
byte-identical, with a mutation-verified `periods_per_year=365` rescale-by-≈√(365/252) proof that
fails CI on any silent threading hole. The ×1.20 mismatch resolved by converging
`equity_reconstruction` down to 252; all displayed/ranking metrics stay apples-to-apples on 252.

### Phase 35: Per-key dailies foundation

**Goal:** A per-key dailies store (`api_key_id` axis) exists, fed by an allocator-key-scoped derive
job, backfilled for existing keys, RLS-scoped to the owning allocator.
**Depends on:** Phase 34
**Requirements:** DAILIES-01..04
**Plans:** 3 · **Status:** Complete (2026-06-24)

`csv_daily_returns` became a dual-axis store (strategy XOR `api_key_id`) with a per-key owner RLS
policy + owner-coherence trigger (committed live SQL/RLS tests for NULLs-distinct coexistence,
both upsert arbiters, CHECK rejections, cross-tenant content isolation). `run_derive_broker_dailies_job`

`phase35_backfill_enqueue.py` enqueues exactly one api_key-scoped derive job per active connected
exchange key (idempotent, 23505-safe, fail-loud).

### Phase 36: Repoint stats reads

**Goal:** Overview stats read persisted per-key dailies blended through the compute path (converging

poll/snapshot path.
**Depends on:** Phase 35
**Requirements:** UNIFY-01..03

### Phase 37: Honest per-data-source toggle

**Goal:** The composer lets an allocator include/exclude each API key from the projection, and
excluding a key honestly recomputes the curve + KPIs from the remaining per-key series.
**Depends on:** Phase 36
**Requirements:** DSRC-01..03
**Plans:** 3 · **Status:** Complete (2026-06-25)

real). The eligibility predicate is a single SSR-side SoT the composer mirrors (`eligibleApiKeyIds` /
`perKeyDailiesGateSatisfied`) — no divergence from Overview. Mutation-falsifiable DSRC-03 honesty oracle.

## Milestone Summary

**Decimal Phases:** none.

**Key Decisions:**

- **252 stays the universal annualization basis** (user decision 2026-06-24) — ANNUAL-02/03/04/05
  redefined away from asset-class-divergent (crypto 365) to keep displayed/ranking metrics
  apples-to-apples; the `periods_per_year` param ships so the basis is explicit and a future
  per-asset divergence is a one-line call-site change, not a function rewrite.
- **Per-key axis on the existing `csv_daily_returns` store** (dual-axis strategy XOR `api_key_id`),
  not a new table — resolves the `strategy_id NOT NULL FK→strategies` blocker without inventing
  synthetic strategy rows.
- **All-or-nothing per-key blend gate** with snapshot fallback — Overview only repoints onto per-key
  dailies when every active key has a series; otherwise it falls back to the existing reconstruction
  (no half-honest blend).
- **Composer factsheet parity = chart reuse, not a fork** — the composer mounts the REAL factsheet
  `TimeSeriesChart`/`MasterBrush` under an additive `persist={false}` provider so the factsheet stays
  byte-identical and the composer gets full interaction parity, scope-bounded (Overview untouched).

**Issues Resolved:**

- The `equity_reconstruction`@365 vs `compute_all_metrics`@252 ×1.20 scale mismatch (the two paths
  now agree at 252 with no residual factor).
- The `csv_daily_returns.strategy_id NOT NULL FK→strategies` blocker on per-key dailies.
- /ship red-team caught + fixed two issues the gsd-audit passed: RT1 — per-key blend now filtered to
  `eligibleApiKeyIds` (soft-disconnected keys had ridden the blend untoggleably); RT2 — `persist={false}`
  now gates the hydration READ too (Overview factsheet `?range`/`?cmp`/`?dark` had bled cross-tab via
  the shared `/allocations` URL).

**Issues Deferred (deferred-by-construction, not code gaps):**

  post-deploy + post-backfill + an authed Chromium session (headless can't hydrate authed pages). Code

- 38-HUMAN-UAT.md (2 scenarios): factsheet-grade interaction feel (wheel-zoom/drag-pan/brush/keyboard +
  shared window) and blank-slate overlay end-to-end — only verifiable in a deployed authed Chromium
  session (JSDOM has no layout/D3-zoom). Code paths proven incl. the shared-window + PARITY-03 cases.
