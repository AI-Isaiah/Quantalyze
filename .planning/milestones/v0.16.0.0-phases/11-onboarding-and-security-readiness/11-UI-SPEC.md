## Spacing Scale

Project base unit is 4px (DESIGN.md). All values used by Phase 11 surfaces MUST be one of the locked tokens below — no off-grid values, no `m-3.5`, no fractional rems.

| Token | Value | Tailwind | Phase 11 usage |
|-------|-------|----------|----------------|
| 1 | 4px | `1` / `gap-1` | Icon gap inside chip / pill, sub-row dot offset. |
| 2 | 8px | `2` / `gap-2` | Inline element rhythm (label → input gap; gap between S5 strip and S7 hint). |
| 3 | 12px | `3` / `py-3` | Banner vertical padding inherited from `<WarningBanner>` defaults (S1, S5, S7). Status pill padding x. |
| 4 | 16px | `4` / `p-4` | Section spacing inside Quick-Set card (S2). Banner horizontal padding inherited from `<WarningBanner>` (S1, S5, S7). |
| 5 | 20px | `5` / `p-5` | Audit-log subsection internal gap (S6) — between header, copy, and CTA button. |
| 6 | 24px | `6` / `p-6` | Default `<Card>` primitive padding (S2 inherits `padding="md"` → `p-6` automatically; do NOT override). Section gaps inside `/security` Compliance Posture content. |
| 8 | 32px | `8` / `mb-8` | Top-of-tab spacing for new Audit log subsection (S6). |
| 12 | 48px | `12` / `mt-12` | Existing pattern in `/security` — preserve when adding D-06 banner (do NOT collapse). Phase 11 does not introduce new 48px gaps inside Phase 11-owned cards. |
| 16 | 64px | `16` | Page-level top/bottom margin (existing). Phase 11 adds NO new 64px gaps. |

**Vertical rhythm inside Phase 11 cards (S2, S6):** the executor follows the project's standard 8-point grid for vertical spacing between heading, body, and CTA buttons. Specific gaps (8 / 12 / 16 / 24 px) are at planner discretion within the locked scale; the contract requires only that every gap is a token from the table above. No off-grid values.

**Exceptions (none):** every Phase 11 surface fits the 4px scale. If the executor needs a value not in this table, the executor MUST stop and re-enter discuss; do not introduce off-grid spacing.

**Touch target (S1 dismiss `×`):** the icon-only dismiss `×` button on the S1 banner has a **32×32px visible square** with an **extended 44×44px tap area** via CSS hit-area expansion (e.g. `relative` with a `before:absolute before:inset-[-6px]` pseudo-element making the click target 44×44 while the visible glyph stays 32×32). This satisfies WCAG 2.5.5 (Target Size — Enhanced) without enlarging the visible glyph to compete with the primary CTA. Pattern reference: any existing project icon-only button; if none exists, executor uses `before:absolute before:inset-[-6px] before:content-['']`.

## Typography

> **Display sizes (24px Instrument Serif) are NOT used in Phase 11** — see DESIGN.md for the project's full scale (Hero 48/32px, H2 24px). Phase 11 stays within the institutional-minimalist body/heading scope.

The deployed-in-Phase-11 typography scale is exactly four roles:

| Role | Size | Weight | Line height | Family | Phase 11 usage |
|------|------|--------|-------------|--------|----------------|
| Heading | 18px (`text-lg`) | semibold (600) | 1.3 (`leading-snug`) | DM Sans | S2 card heading "Mandate quick-set". S6 subsection heading "Audit log". S1 banner leading sentence "Connect your exchange to see real performance". |
| Body | 14px (`text-sm`) | regular (400) | 1.5 (`leading-relaxed`) | DM Sans | All copy in S1, S2, S5, S6, S7. `/security` paragraph copy in D-06 and D-07 patches. |
| Caption | 12px (`text-xs`) | regular (400) | 1.4 | DM Sans | Helper line beneath S5 strip. Status pill copy in S3 partial mode. S6 "Last 90 days" qualifier. |
| Numeric / data | inherited size | regular (400), tabular | 1.4 | Geist Mono (`font-mono tabular-nums`) | IP addresses in `/security` D-07 patch. Date timestamps. NOT used for prose. |

**Buttons and labels at 16px:** if a button or input label uses `font-size: 16px`, that's the base font size of the existing `<Button>` / `<Input>` primitives — NOT a new typography role. Phase 11 does not introduce a "body emphasis" or any other 16px role; Phase 11 surfaces inherit primitive defaults.

**Display headings (Instrument Serif) reserved for:** hero / landing / page-title surfaces only (DESIGN.md). **Phase 11 introduces zero display headings** — S1, S2, and S6 use DM Sans 18px semibold to stay within DESIGN.md's institutional-minimalist scope. **All Phase 11 text is DM Sans except Geist Mono for numerics.**

**Weight rule:** only regular (400) and semibold (600). No 500-medium, no 700-bold. Where the existing project mixes `font-medium` (500), Phase 11 surfaces conform to the 400/600 contract regardless of nearby code.

**Tabular nums rule:** any number in S6 (timestamps, row counts, IP octets in S4 D-07) MUST use `font-mono tabular-nums`. Prose numbers ("90 days") may stay in DM Sans.

### S3 — `<WidgetState>` primitive (D-09 / D-10 / D-11)

The primitive's strings are PER-WIDGET (the widget owner picks the strings). The contract below specifies the SHAPE of strings at each mode — executors implement widgets to match this shape.

**Mode union (LOCKED):** `'loading' | 'empty' | 'partial' | 'error' | 'success'`. The `mode` prop accepts ONLY these five values; **no `category` prop on the primitive.** If the planner decides a per-widget loading-shape discriminator is needed, that would be a separate optional prop (e.g. `loadingShape?: 'kpi' | 'chart' | 'table' | 'sparkline' | 'card'`) added at planner discretion — not part of this contract.

| Mode | Visible UI shape | Strings the widget owner provides | Default fallback |
|------|------------------|-----------------------------------|------------------|
| `loading` | Centered animate-pulse skeleton matching the widget's natural height. | (none — widget owner may pass an optional shape discriminator if planner adds one) | Generic skeleton card |
| `empty` | Reuses existing `EmptyState.tsx` (Card variant) | `empty: { title: string, description?: string, ctaHref?: string, ctaLabel?: string }` | Default fallback strings provided by the widget owner; if not provided, the primitive renders a generic message — exact wording at planner discretion. |
| `partial` | Renders `partial.children` PLUS a small `Pill` in the widget header (top-right) with `partial.pill` text, warning-tinted. | `partial: { pill: string, children: ReactNode }` | Pill = generic "Partial data" string at planner discretion. |
| `error` | Card with negative-tint border, error glyph, message, optional Retry button. | `error: { message: string, onRetry?: () => void }` | Default fallback strings provided by the widget owner; if not provided, the primitive renders a generic error message — exact wording at planner discretion. NEVER show stack trace or error code. |
| `success` | Renders `children` directly with no chrome. | `children: ReactNode` | (must be present — `success` mode without children is a bug) |

**Partial-pill copy patterns (D-11):**
- Sync-state partials: `"Syncing N of M venues"` (reads `api_keys.sync_status` from Phase 06 D-07).
- Warmup partials: `"Awaiting <metric> — needs <threshold> <unit> history"` (e.g., `"Awaiting Sharpe — needs 30 days history"`).
- Staleness partials: `"Stale — last sync <relative> ago"` (e.g., `"Stale — last sync 26h ago"`). Triggered when last sync > 24h.

**Error-state Retry rule:** Retry button appears ONLY if `onRetry` is passed. Default error UI has no Retry. `aria-live="polite"` on the error region so screen-readers announce the failure.

## Interaction Contract

### S1 / S2 visibility predicate

**Source-of-truth for `apiKeysCount` is server-side, per CONTEXT D-02 (locked):**
- `apiKeysCount` is rendered into the page payload (`MyAllocationDashboardPayload` or equivalent) on every request via server-side `SELECT count(*) FROM api_keys WHERE user_id = auth.uid()`.
- **NO client-side caching** of `apiKeysCount`. NO localStorage. The value is fresh on every page load.
- Re-evaluated on every page load. After a key connects in another tab, the next request to `/allocations` returns the updated count.

**sessionStorage is per-tab dismissal only (CONTEXT D-03):**
- `sessionStorage["allocations.onboarding_banner_dismissed"]` and `sessionStorage["allocations.mandate_card_dismissed"]` are scoped to a single tab session. Tabs do NOT see each other's dismissal. This is intentional per D-03 — the surfaces re-surface on the next page load in any new tab until the server-side count flips.

**Visibility predicate (verbatim — executor matches this exactly):**

```
visible_S1 = (apiKeysCount === 0) && !sessionStorage["allocations.onboarding_banner_dismissed"]
visible_S2 = (apiKeysCount === 0) && !mandate.is_set && !sessionStorage["allocations.mandate_card_dismissed"]
```

- `apiKeysCount` is read from the server-rendered page payload prop, NOT computed client-side.
- `mandate.is_set` is read from the server-rendered page payload (existing field on the mandate select for that user).
- The sessionStorage check is the ONLY client-side input; it gates dismissal within a single tab session.
- The server-side count + mandate flag is the **gating source**.

**Layout:** when both visible, render S1 above S2, both above the `<AllocationsTabs>`. Spacing: page top → S1 → 12px gap → S2 → 24px gap → tabs.

**Dismissal independence:** dismissing S1 does NOT dismiss S2 (and vice versa). Each surface owns its own sessionStorage key.

**Auto-hide on key connect:** when `apiKeysCount > 0` on a subsequent page load, neither surface renders, regardless of sessionStorage state.

### S2 save / skip flow

| Trigger | Behavior |
|---------|----------|
| User edits `max_weight` field, clicks `Save mandate` | Call `update_allocator_mandates({ max_weight: <value/100> })` (Phase 02 RPC). On success, S2 unmounts permanently for this session; toast `"Mandate saved"` (matches Phase 02 toast copy). On failure, render inline error beneath the field using Phase 02 error pattern; field value preserved. |
| User clicks `Save mandate` without editing | Same RPC call with the suggested defaults (`max_weight: 0.15, preferred_strategy_types: []`). This is an explicit user act — Phase 02 D-09 forbids SILENT default save, NOT explicit user save of suggested values. |
| User clicks `Skip for now` | Set `sessionStorage["allocations.mandate_card_dismissed"]="1"`. S2 unmounts for this session. Re-surfaces on next page load until (a) user saves a mandate via S2 or `/preferences`, or (b) any `first_sync_success` has occurred. |
| User clears a field then saves | Saves NULL via RPC (allowed per Phase 02 D-10). Phase 03 scoring engine returns `mandate_fit_score = 1.0` graceful fallback. |

### S3 `WidgetState` lifecycle

```
Initial mount:        mode="loading"  → skeleton
Data resolves:        mode="success"  → renders children directly
                  OR  mode="empty"    → EmptyState card + optional CTA
                  OR  mode="partial"  → children + pill in top-right
                  OR  mode="error"    → Card + message + optional Retry
On Retry click:       parent re-fetches; primitive returns to mode="loading"
```

Mode transitions are managed by the widget owner (NOT the primitive). The primitive is stateless. NO internal `useState` for mode.

**Hook order rule:** the primitive consumes ONLY props. Widget owners that read `useEffect`/`useState` must place those hooks ABOVE the primitive's render — same pattern as Phase 09.1 D-08's `holdingsEmpty && !hasSyncing` short-circuit (hooks above the early return).
