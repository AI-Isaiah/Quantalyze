<objective>
Ship the self-serve audit-log CSV download infrastructure: a new authenticated route handler `GET /api/me/audit-log/export` that returns the caller's last 90 days of audit_log rows as CSV (capped at 10,000 rows), plus the supporting serializer at `src/lib/audit-log-csv.ts`. Per CONTEXT D-05, this lives on the authenticated `/profile?tab=security` surface (UI lands in Plan 06), NOT on the public `/security` page.

Purpose: Institutional LPs evaluating Quantalyze under diligence need a way to retrieve their own audit trail without emailing support. The audit_log table already has the right RLS policy (`audit_log_owner_read` from migration 010) — this plan ships the route handler that reads it and the CSV serializer that formats it. Existing `src/lib/csv.ts` only exports parsing helpers; serialization is greenfield (RESEARCH Open Question #2 confirmed via `grep -n '^export' src/lib/csv.ts`).

Per BLOCK-1 review feedback: the SELECT applies a hard `.limit(10000)` cap so a pathological caller (huge audit_log) cannot OOM the serverless function via an unbounded in-memory `rows.join("\n")` string build. The serializer also prepends a caption line that documents the cap so LP recipients know what they're looking at.

Streaming via ReadableStream is a future optimization (Phase 11+1+) when an active LP genuinely exceeds 10K log rows per 90 days. Today's PII-light, low-write audit_log makes the bounded-rows approach the right shape: simpler code, no streaming complexity, hard ceiling on memory.

Output: Two new TypeScript modules (route + serializer) and their tests. The route handler verifies via a unit test for header/auth shape, a live-DB integration test for RLS isolation (allocator A cannot see allocator B's rows), and a regression test that >10K seeded rows still return ≤ 10001 data rows + 1 caption + 1 header.
</objective>

```typescript
export async function GET(req: NextRequest) {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

  const ninetyDaysAgo = new Date(Date.now() - 90 * 24 * 60 * 60 * 1000).toISOString();
  // @audit-skip: read-only export of caller's own audit_log rows. The download
  //   itself does not mutate state; an audit emission for the download would
  //   create an audit-log-of-audit-logs feedback loop. Out of scope per D-05.
  const { data: rows, error } = await supabase
    .from("audit_log")
    .select("created_at, action, entity_type, entity_id, metadata")
    .gte("created_at", ninetyDaysAgo)
    .order("created_at", { ascending: false })
    .limit(10000);  // BLOCK-1 cap — bounds in-memory CSV string build to ~2 MB
  if (error) return NextResponse.json({ error: "Failed to read audit log" }, { status: 500 });

  const csv = serializeAuditLogCsv(rows ?? []);
  const filename = `quantalyze-audit-log-${new Date().toISOString().slice(0, 10)}.csv`;
  return new NextResponse(csv, {
    status: 200,
    headers: {
      "Content-Type": "text/csv; charset=utf-8",
      "Content-Disposition": `attachment; filename="${filename}"`,
      "Cache-Control": "no-store",
    },
  });
}
```

    ```typescript
    /**
     * Phase 11 / D-05 — Audit-log CSV serializer.
     *
     * Why a new module:
     *   - src/lib/csv.ts only exports parse-side helpers (sanitizeCsvValue,
     *     parseCsvLine, parseCsv, parseCsvWithSchema). Export-side
     *     serialization is greenfield.
     *
     * RFC 4180 escape rules:
     *   - If value contains comma, double-quote, CR, or LF → wrap entire
     *     value in double-quotes and double-up internal double-quotes.
     *   - Otherwise emit as-is.
     *
     * BLOCK-1 (review feedback): the route handler caps SELECT at 10,000
     *   rows so the rows.join("\n") string build is bounded at ~2 MB
     *   (10000 × ~200 bytes + caption + header). Streaming via ReadableStream
     *   is a future optimization (Phase 11+1+) if an active LP genuinely
     *   exceeds 10K log rows per 90 days.
     *
     * CSV injection (formula start chars =, +, -, @, TAB, CR) is handled
     * at PARSE time by sanitizeCsvValue in csv.ts. Export side only
     * conforms to RFC 4180 — the receiver decides whether to sanitize.
     */

    /** Caption line prepended to every export — documents the 10K cap to recipients. */
    export const AUDIT_LOG_CSV_CAPTION =
      "# Quantalyze audit log export — most recent 10,000 entries within 90-day window";

    export interface AuditLogRow {
      created_at: string;
      action: string;
      entity_type: string;
      entity_id: string | null;
      metadata: Record<string, unknown> | null;
    }

    /** RFC 4180 escape; quote if value contains , " \r \n. */
    export function escapeCsvValue(value: string): string {
      if (/[,"\n\r]/.test(value)) {
        return `"${value.replace(/"/g, '""')}"`;
      }
      return value;
    }

    /**
     * Serialize audit_log rows to RFC 4180 CSV with caption + header.
     *
     * Output structure:
     *   line 1: AUDIT_LOG_CSV_CAPTION (recipient-readable provenance)
     *   line 2: column header
     *   line 3+: data rows
     */
    export function serializeAuditLogCsv(rows: AuditLogRow[]): string {
      const caption = `${AUDIT_LOG_CSV_CAPTION}\n`;
      const header = "occurred_at,action,entity_type,entity_id,metadata_summary\n";
      const body = rows.map((r) => {
        const summary = r.metadata ? JSON.stringify(r.metadata) : "";
        return [
          r.created_at,
          escapeCsvValue(r.action),
          escapeCsvValue(r.entity_type),
          r.entity_id ?? "",
          escapeCsvValue(summary),
        ].join(",");
      }).join("\n");
      return rows.length === 0 ? `${caption}${header}` : `${caption}${header}${body}\n`;
    }
    ```
