## THE META-QUESTION: where the boundary of protection is

The seam **core** is genuinely well-guarded — 10/10 semantic mutations caught, and the census
above bears that out: budgets, breaker constants, the discriminator table, redaction, the
purity of all three leaves, the copy bytes, and the tick-scoped retry-storm fence all have real
teeth.

**Every one of those guards derives its population from one of exactly two needles:**

1. `/resilientFetch\s*\(/` — the core call (`wiring.test.ts:627`, `budgets.invariant.test.ts:755`); or
2. the ESLint rule's `process.env.ANALYTICS_SERVICE_URL` taint — the raw fetch.

**What lies just outside is the middle tier: a new consumer of an existing seam wrapper.**

A route that calls `computePortfolioAnalytics()` — or `postProcessKey()`, or any of the nine
`analytics-client` exports — makes a real, budgeted, breaker-feeding, credential-bearing seam call
while matching *neither* needle. It gets:

- no `SEAM_ROUTE_BUDGETS` row → its `maxDuration` is never checked against its worst case (F-2);
- no `SEAM_FILES` membership → its `catch` blocks are never scanned (F-1);
- no lint error, no wiring-test failure, no SSR-exposure failure.

Today all 9 wrapper consumers and all 5 `postProcessKey` callers happen to be inside the 15-row
table:

```
$ grep -rnE "\b(validateKey|encryptKey|optimizeScenarioWeights|computePortfolioAnalytics| \
  runPortfolioOptimizer|findReplacementCandidates|simulateAddCandidate|recomputeMatch|evalMatch)\s*\(" \
  src --include='*.ts' --include='*.tsx' | grep -v test | sed 's/:.*//' | sort -u
→ 9 route files, all present in EXPECTED_ROUTE_BUDGETS
```

That agreement is **coincidence maintained by discipline, not by any assertion.** It is the same

## Sub-audit B — the ESLint rule, the three leaf-purity guards, redaction / Sentry

### F-14 — HIGH. A **dynamic `import()`** escapes all four needles in all three leaf-purity guards — and `sentry-capture.ts:144` proves it is this repo's own idiom for exactly the concern the guards exist for.

The stripper and the four patterns are byte-identical across
`seam-errors.purity.test.ts:56-62`, `seam-discriminator.purity.test.ts:57-63`,
`seam-copy.purity.test.ts:55-61` and `seam-redaction.test.ts:514-520`. Measured against crafted
sources:

```
CAUGHT   import { Redis } from "@upstash/redis";                    (control)
CAUGHT   /* outer /* inner */ + import      ← nested block comments: NOT a defeat
CAUGHT   const R = /\/\*/;  + import        ← regex literal: NOT a defeat
ESCAPES  const { Redis } = await import("@upstash/redis");          ← DYNAMIC IMPORT
ESCAPES  import{Redis}from"@upstash/redis";                         ← no space after `import`
ESCAPES  const PAT = "/*"; import …; const END = "*/";              ← `/*` in a string literal swallows the import
```

`/^\s*import\s/m` requires whitespace; `/\brequire\s*\(/` does not match `import(`; there is no
fourth pattern. And the escape is not exotic — `src/lib/sentry-capture.ts:144` already spells

rationale these leaves cite. A `void import("@upstash/redis")` inside a leaf function passes every
assertion in all three purity files while violating both stated rationales (browser-bundle edge;
module-load failure evaluated inside a `catch`).

The no-space escape is not blocked by formatting either: **prettier is not installed and is not a
CI gate** (`grep -rn prettier package.json .github/workflows/*.yml` → no matches; `ls
node_modules/.bin | grep prettier` → empty).

**Fix is one line per file:** add `/\bimport\s*\(/` to the pattern set, and relax
`/^\s*import\s/m` to `/^\s*import[\s{"']/m`.

*Refuted, and worth recording:* a `//` inside a template literal only removes a line from the scan
and cannot conceal a top-level import — the files' own comment (`seam-copy.purity.test.ts:53-55`)
correctly calls that the safe direction.
