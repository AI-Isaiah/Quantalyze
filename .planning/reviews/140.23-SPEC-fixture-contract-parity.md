## Ground truth: the service emits exactly SIX body shapes

Verified in `analytics-service/services/error_contract.py`, `main.py`, and every `raise` site in `routers/`.

| # | Shape | Where |
|---|---|---|
| A | `{detail:{code, dependency, retryable, detail[, correlation_id]}}` — first four **always** present | `service_error()` / `service_error_response()`; 31 sites |
| B | `{detail:<str>, code, recoverable}` — **exactly 3 keys**, always **424** | `VenueTransientHTTPException`, 7 sites |
| C | `{ok:false, code:"VALIDATION_FAILED", human_message, detail:<str>, correlation_id, recoverable:false}` @422 | `main.py:409` app-global |
| D | `{ok:false, code:"RATE_LIMITED", human_message, detail:<str>, correlation_id, recoverable:true, retry_after_seconds}` @429 + `Retry-After` | `main.py:516` app-global, **slowapi-decorated routes ONLY** |
| E | `{ok:false, code, human_message, debug_context, correlation_id, recoverable}` — `/process-key`'s own; statuses **401/403/422/424 only** | `process_key.py:_envelope_error` |
| F | `{detail:"Unauthorized"}` @401 / bodyless `500 text/plain` | `main.py:806` / Starlette |

**Constraints `_validate` enforces at construction:** 500 ⇒ `retryable:false` · 503 ⇒ dependency ∈ {mt5-gateway, kek, supabase, egress-proxy} AND `retry_after` ∈ {30, 15} exactly · 424 ⇒ dependency is a venue, never one of ours · 429 ⇒ no dependency, `retry_after` required.
**`/process-key` has no 202** (`@router.post("", response_model=None)`, no `status_code=`).

## Findings, ranked by blast radius

### 1. `/api/keys/[id]/permissions` — all six 429 fixtures use the WRONG one of the two 429 shapes
`src/app/api/keys/[id]/permissions/route.test.ts:655, 709, 745, 772, 802, 820, 1214`

Every fixture uses **flat shape D** (top-level `code`). But the upstream `POST /internal/keys/{key_id}/permissions` has **no slowapi decorator** (`routers/internal.py:184`; `:130` says the decorator dimension is wrong so it rolls its own). Its only 429 is `routers/internal.py:246` → **nested shape A**, header `Retry-After: 60`.

**Why it matters:** TS-34 (`route.ts:471-500`) exists *specifically* for this throttle, and **zero tests drive it against the body it will actually receive.** It survives only because it gates on `seamFailure?.status === 429` and pulls the code via `seamErrorCode` (which handles both shapes). Narrow that to a top-level `body.code` read — the obvious "simplification" — and **all six tests stay green while the real per-key throttle regresses to `PROBE_FAILED`/502.**
`:1214`'s two-key `{detail:"per-key throttle", code:"RATE_LIMITED"}` matches **no** Python shape at all.

### 2. `PortfolioImpactPanel` — a nested envelope at a boundary that provably flattens it
`src/components/portfolio/PortfolioImpactPanel.test.tsx:1478-1494`; same claim in prose at `PortfolioImpactPanel.tsx:80-84`

Test mocks `/api/simulator` → 500 + shape A and asserts the panel renders `body.detail.detail`. But `src/app/api/simulator/route.ts:224-226` returns a **static** `{error:"Portfolio impact simulation failed."}` on every `status >= 500`, and `:202-205` flattens 4xx to `{error: err.message}`. The panel has exactly one `fetch` (`:56`).
⇒ **The nested envelope cannot reach this component.** The `seamErrorCode(raw)`/`seamHumanMessage(raw)` branch added by 140.3-01 is **unreachable in production**; deleting it breaks only this test, while a real Railway 500 still renders the static sentence.

Same file `:1529-1548` mocks a 429 as shape D. `/api/simulator`'s own limiter emits `{error, retryAfter}` (`route.ts:125-134`); an upstream 429 forwards as `{error: err.message}` **with `Retry-After` dropped**. Test asserts `body.detail`; production reads `body.error`.

### 3. A body `_validate` REFUSES to construct: 500 + `retryable:true`
`src/app/api/keys/[id]/permissions/route.test.ts:607-616` · `src/lib/analytics-client.test.ts:1729-1737` · `src/components/portfolio/PortfolioImpactPanel.test.tsx:1478-1494`

These are the **canonical CONTRACT-A fixtures in three separate suites** — the shape of record for the nested reader is one the emitter cannot produce.

### 4. `analytics-client.test.ts` venue-transient bodies pinned at the PRE-REMAP status
`src/lib/analytics-client.test.ts:1832` and `:1866` — both `{status: 400}`, with a comment claiming byte-identity to `validate_key_venue_transient_contract.json`. That fixture says **424** at all fourteen cases, and `routers/exchange.py:185,200,393,409,431,620` are all `status_code=424` at HEAD (140.3-06, commit `1f8ad052`). The comment's excuse — "140.3-06 remaps 400 → 424 **in the next wave**" — is **stale; that wave landed.**
400 and 424 are *different verdicts* in `seamBreakerVerdict` (`caller` vs `caller-exchange`), and the status isn't asserted, so the drift is **silent**.

### 5. `/process-key` answers **200**, not 202 — encoded in three doubles and one source comment
`src/app/api/keys/sync/route.seam.test.ts:406-416` (real-wire `new Response(…, {status:202})`) · `keys/sync/route.test.ts:988, 1049` · `src/lib/process-key-client.ts:628` documents `"202 enqueue → {ok:true, status:202, body}"`.
Python's enqueue arm (`process_key.py:1397-1403`) returns a bare dict ⇒ **200**. Tests pass because `keys/sync/route.ts:611` **mints its own 202**.
⚠️ `src/app/api/strategies/csv-finalize/route.ts:1300` forwards `result.status` **verbatim** — so upstream status IS load-bearing on the seam, and nothing would catch a `keys/sync` change that started forwarding it.

### 6. Nested-500-with-`correlation_id` at wizard routes that cannot produce it
`SubmitStep.test.tsx:756-780` (`EVAL_FAILED`, a `routers/match.py` code, on `/api/strategies/finalize-wizard`) · `SyncPreviewStep.render.test.tsx:1331-1352` (`SCORING_FAILED`, also `match.py`, on `/api/keys/sync`).

⇒ the nested `correlation_id` reader is proven against the one nested-500 variant that **cannot arrive**.

### 7. Code-vocabulary drift (LOW — the mechanism under test doesn't read `code`)
`src/lib/resilient-fetch.test.ts:1485` `KEK_NOT_CONFIGURED` (real: `KEK_UNAVAILABLE`); `:1520` `DB_UNAVAILABLE` (not in the vocabulary). Structure, polarity, dependency and breaker-key expectations are all **correct**; only the string is invented.
