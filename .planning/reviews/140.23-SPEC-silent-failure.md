## Headline

The diff's *discrimination* work is genuinely strong. `seam-discriminator.ts`,
`error_contract._validate`, `seam-redaction.ts` and the `finalize-wizard` publish gate
were each probed for the collapse shapes named in the brief and each held. What the diff
did not close is the layer *underneath* the discrimination:

1. the **breaker's own observability is console-only**, so a breaker that has stopped

3. the **424 remap over-asserts venue fault** for conditions that are permanent, or ours
   (S3/S4) — which is simultaneously a lie to the user and a hole in the breaker.

### H1 — Every SEAMUX-08 capture is a floating promise started on the tick the response returns, on a runtime that is not Sentry-wrapped and never flushes
`src/lib/sentry-capture.ts:144-158`. Confidence: **high**. Severity: **HIGH**.

```ts
void import("@sentry/nextjs")
  .then((Sentry) => { try { Sentry.captureException(payload, {...}); } catch {} })
  .catch(() => {});
```

- `captureToSentry` returns synchronously, before the dynamic `import()` resolves.
- Every call site returns immediately after — e.g.
  `src/app/api/strategies/create-with-key/route.ts:582-599`,
  `src/app/api/admin/match/eval/route.ts:241-249`,
  `src/app/api/portfolio-optimizer/route.ts:232-247`,
  `src/app/api/verify-strategy/route.ts:379-388`. No `await`, no `after()`.
- `grep -n "Sentry\|sentry" next.config.ts` → **no hits**. There is no `withSentryConfig`,
  so route handlers get none of `@sentry/nextjs`'s serverless instrumentation and none of
  its end-of-invocation `Sentry.flush()`. `grep -rn "flush("` across `sentry-capture.ts`,
  `src/instrumentation.ts`, `src/app/api/` → **zero**.

**Scenario.** An allocator's key connect throws an unclassified error. `create-with-key`
classifies UNKNOWN, calls `captureToSentry`, returns 500. The response is complete; Vercel
freezes the instance. `import("@sentry/nextjs")` — a module load with real I/O on a cold
instance — never resolves, or resolves and hands the event to a transport with no tick to
send it. Three separate `catch {}` swallow the loss. The only other trace is `console.error`.

This is the pattern the brief calls out by name: *empty catches around observability make
"no event arrived" indistinguishable from "no capture was attempted"*. The
`void import()` shape is pre-existing (`git show 4b59fb31^:src/lib/sentry-capture.ts:29`),
but this diff took the number of sites depending on it from 83 to 115 and made it the
sole reporting mechanism for the seam.

Asymmetry that makes it easy to miss: `src/instrumentation.ts:38 onRequestError` **is**
awaited by the framework, so errors that *escape* a handler do report. The 15 seam routes
are exactly the ones that catch their own errors and therefore rely on the un-awaited path.

**Fix.** Make `captureToSentry` return the promise and `await` it (or `after()` it) at the
route arms, and add `withSentryConfig` to `next.config.ts` so the runtime flushes.
