## Findings

### LOW-1 — IN-02 residual: perp-only native composites permanently render the smoothed "has not been computed" line
**Seam:** 132 gate (`stitch_composite.py:326` `mark_to_market_available` returns True for perp-only native) → 133 render (`FactsheetView.tsx` ~:1350 `!smoothedAvailable && (mtmAvailable || reason === "unsmoothed_options_book")`).
**Scenario:** a perp-only all-Deribit composite has MTM AVAILABLE → the IN-02 suppression (built for the MTM-also-disabled case, i.e. ccxt-venue books) does not apply → the disabled smoothed segment renders WITH the stacked line "Smoothed mark-to-market unavailable: this basis has not been computed for this strategy." — permanently, for a pass that will never run (no option activity ⇒ smoothed ≡ cash). This is the exact "reads as pending" harm IN-02's own rationale names, missed for the perp-only-native book class. The copy is factually true and no money number is mislabeled, hence LOW not MEDIUM.
**Fix suggestion (post-land polish):** suppress the stacked line additionally when `mtmAvailable && smoothedReason` is the closed-set default AND the book shows no options signal — or reuse the IN-02 pattern: keep the line only when `payload.mtmGate?.reason === "unsmoothed_options_book"` (the one state where smoothed is the specific remedy).

### LOW-2 — TS basis chain has no exhaustiveness enforcement for a future 4th basis
**Seam:** TS `Basis` union (basis-context.tsx:33) vs the if/ternary chains at `useBasisMetrics` (:110), `useBasisSeriesView` bundle pick (:239), FactsheetView caption (:521) and eyebrows (:868).
**Scenario:** a future `Basis` member added to the union + SegmentedControl but missed at one consumer compiles clean and falls through to CASH data — with the mitigating property that the labels also fall through to cash/blank (data and label stay consistent; no money mislabel), but the active segment highlight would lie. Python's side fails loud (kind-map pin + `_PNL_BASES` raise); TS's does not.
**Fix suggestion:** a `switch (basis) { … default: basis satisfies never }` (or an exhaustive record keyed on `Basis`) at the 3-4 pick sites, so adding a union member is a compile error.

### LOW-3 — Cross-language contract is convention-pinned, not fixture-pinned
**Seam:** `basis_series.py` payload writer ↔ `parseSmoothedSeriesPayload`/`SmoothedMtmDailyReturnsSeriesPayload`.
Both sides are independently well-tested and currently byte-equal (verified by inspection this review), but nothing executable would catch a Python-side payload-shape change (`schema` bump, rows rename) until production render degrades to cash-with-caption. Same pre-existing exposure as `mtm_daily_returns` — v1.14 doubles the surface without adding the shared golden fixture.
**Fix suggestion (backlog):** one TS test consuming a checked-in Python-emitted payload fixture (generate from `test_smoothed_persist_roundtrips_via_batch_rpc`'s asserted dict).
